パイプラインの構造

Source ステージソースアクションだけ（最初のステージにしか置けない）
↓ トランジション（無効にすると入らない）
Build ステージ単体テスト・静的解析・メトリクスを並列（runOrder が同じ）
↓ 出力アーティファクト → 入力アーティファクト
Staging ステージdeploy → test
↓
Prod ステージapproval（SNS で通知・7 日で失敗）→ deploy
決まり
ステージは 2 つ以上
アクションは source・build・test・deploy・approval・invoke
ステージは 1 度に 1 つの実行（ロック）
アーティファクトは S3 のアーティファクトバケット（ソースの S3 とは別）
変数は #{namespace.variable_key}
本番を止めたいだけならトランジションの無効化。承認の流れを作るなら承認アクション。

AWS DevOps #01 CI/CDパイプラインとCodePipelineタスク 1.1

実行モード

モード動き
SUPERSEDED（既定）ロックの前で待つ古い実行を、新しい実行が置きかえる
QUEUED（V2）入った順に 1 つずつ。とばさない
PARALLEL（V2）独立して同時に。キューなし。ロールバック不可
止め方：停止して待機（進行中のアクションは終える）／停止して中止。止める前にトランジションを無効に。
失敗したら中身
ステージの再試行最初のアクションから。最初からやり直さない
失敗したアクションの再試行失敗したものだけ
ロールバック（V2）以前に成功した実行へ。新しい実行として始まる。ソースステージは不可

AWS DevOps #01 CI/CDパイプラインとCodePipelineタスク 1.1

クロスアカウントとクロスリージョン

アカウント A（パイプライン）カスタマーマネージドの KMS キー・アーティファクトバケット
↓ キーポリシー・バケットポリシーで B に許可
アカウント B（デプロイ先）A が引き受けるロール・EC2 のインスタンスロールにバケットとキーの権限
既定の AWS マネージドキーは B が使えない。キーは ID か ARN で（エイリアスは作ったアカウントでしか通じない）。
B と C のどちらもパイプラインのアカウントでなければ、B→C で直接アーティファクトは渡せない。
us-east-1（パイプライン）アーティファクトバケット
↓ コピーは CodePipeline が行う
eu-west-1（アクション）リージョンごとにアーティファクトバケットと暗号化キー
バケットとキーは「アクションと同じリージョン」「パイプラインと同じアカウント」。
