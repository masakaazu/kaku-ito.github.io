第1章

フレームと MAC アドレス

スイッチが読むのは、先頭の 12 バイト。

CCNA #06 スイッチの動作1.13

イーサネットフレームの形

欄役目
プリアンブル1・0 のくり返しで「フレームが来る」と知らせる
SFD（SOF）宛先の直前の 1 バイト。最後が 1 1 で始まりを示す
タイプ上の層のプロトコル（802.3 の形では長さ）
データ最小 64 バイトのフレームになるよう、足りなければ埋める
宛先が先：イーサネットは宛先 → 送信元の順。IP ヘッダーの「送信元 → 宛先」と逆なので注意。
アドレスの種類：送信元はいつもユニキャスト。宛先はユニキャスト・マルチキャスト・ブロードキャストのどれにもなる。
出典：Cisco Internetworking Troubleshooting Handbook「Troubleshooting Ethernet」（tr1904）（Figure 4-2 Preamble 7, SOF 1, Destination address 6, Source address 6, Type 2, Data 46-1500, FCS 4／The preamble tells receiving stations that a frame is coming／This byte ends with 2 consecutive 1 bits／The source address is always a unicast (single node) address, whereas the destination address may be unicast, multicast (group), or broadcast／padding bytes are inserted to ensure at least a 64-byte frame／4-byte frame check sequence (FCS) field containing a cyclic redundancy check (CRC) value）

MAC アドレスの読み方

48 ビット＝前 24（OUI）＋後ろ 24
早わかり（Claude）：最初のオクテットが奇数ならグループあて（マルチキャストかブロードキャスト）。01・33・FF は奇数。
種類例スイッチの扱い
ユニキャストfc58.9a02.7382表にあれば 1 ポートへ
ブロードキャストffff.ffff.ffffVLAN の全ポートへ
IPv4 マルチキャスト0100.5exx.xxxx基本は全ポートへ
IPv6 マルチキャスト3333.xxxx.xxxx基本は全ポートへ
01-00-5E は IPv4 の下位 23 ビット（RFC 1112）、33-33 は IPv6 の下位 32 ビット（RFC 2464）をつける。例：224.0.0.5 → 0100.5e00.0005（Claude が計算）。
#05 との関係：EUI-64 で反転するのは U/L（下から 2 ビット目）。I/G（いちばん下）ではない。
出典：tr1904（The first 3 bytes of the addresses are specified by the IEEE on a vendor-dependent basis, and the last 3 bytes are specified by the … vendor）／RFC 9542 2.1.1（M bit … "group" or "multicast" bit. If it is zero, the MAC address is unicast. If it is a one, the address is groupcast (multicast or broadcast)／X bit … "universal/local" bit）／RFC 1112 6.4（01-00-5E-00-00-00）／RFC 2464 7（first two octets are the value 3333）／Doc 10543（Broadcasts and multicasts are also flooded）
第2章

学習とエージング

送信元を見て覚え、使わなければ忘れる。

CCNA #06 スイッチの動作1.13

表ができるまで

  1. 表は空。A（Gi1/0/1）が B あてに送る
  2. 学習：送信元 A → Gi1/0/1
  3. B は表にない → フラッディング（Gi1/0/2・Gi1/0/3）
  4. B（Gi1/0/2）が返事 → 学習：B → Gi1/0/2
  5. A は表にある → Gi1/0/1 だけへ転送。C には届かない
A・B・C とポートは Claude の例。
出典：Cisco Doc 10543「Troubleshooting Transparent Bridging Environments」（they learn the topology of the network by analysis of the source address of inbound frames／If … a bridge sees a frame arrive on Line 1 from Host A, the bridge concludes that Host A can be reached through the network connected to Line 1／If no map is found, the frame is flooded to all outbound ports）／Doc 23563（Limited flooding is part of the normal switching process）／tr1904（Each station must examine received frames to determine whether the station is a destination）

エージングと加速エージング

最後に使われてからの時間（Claude が作成）
なぜ消す：機器が外れたり別のポートに移ったりしても、表が古いままにならないように。
設定意味
aging-time 300初期値
10〜1000000変えられる範囲（秒）
aging-time 0エージングしない
… vlan 2VLAN ごとに指定
加速エージングSTP の再構成で多くの機器の場所が変わりうる。5 分待つと届かない時間が長いので、forward delay の値まで短くして学習しなおす。VLAN ごと（#09）。
静的アドレスはエージングされない。消えたあとの宛先は、次に学習するまで未知ユニキャスト。
出典：9300 Sys Mgmt CG 17.9（As devices are added or removed … aging out those that are not in use／The range is 10 to 1000000 seconds. The default is 300. You can also enter 0, which disables aging. Static address entries are never aged）／STP Configuration Guide IOS XE 17「Accelerated aging」（The accelerated aging is the same as the forward-delay parameter value／the switch accelerates aging on a per-VLAN basis）／Cisco Doc 19120（The forward delay is the time spent in the listen and learn state. This time is equal to 15 seconds by default）

第4章

フラッディングが続くとき

少しはふつう、続くのは原因がある。

CCNA #06 スイッチの動作1.13

ユニキャストのフラッディングが続く 3 つの原因

原因なぜ宛先が表にない対策の例
非対称ルーティング行きと帰りの道がちがい、相手を送信元とするフレームが届かないARP タイムアウトとエージングを近づける
STP の TCNエージングが短くなり表が消える。ポートのフラップでくり返す端末ポートに PortFast（#09）
表のあふれ表がいっぱいで学習できない（MAC フラッディング攻撃）ポートセキュリティ（#23）
見つけ方：PC でパケットを取り込み、その PC あてでないユニキャストが何度も見えたらフラッディングを疑う。
非対称ルーティング（Doc 23563 の例を簡単にした）
ルーターをこえると送信元 MAC は書きかわるので、スイッチ A は S2 の MAC を学習できない。
出典：Cisco Doc 23563「Unicast Flooding in Switched Campus Networks」（Cause 1: Asymmetric Routing … switch A will not "see" traffic from the S2 MAC address … since the source MAC address will be rewritten by router B／bring the router's ARP timeout and the switches' forwarding table-aging time close to each other／Cause 2 … TCN operates by shortening the forwarding table aging time … Ports with the STP portfast feature enabled will not cause TCNs／Cause 3 … one host starts generating frames each sourced with different MAC address … limiting the number of MAC addresses learned on untrusted ports by using the port security feature／unicast packets not involving the workstation should not be seen repeatedly on the port）

問われ方とまちがえやすい点

こう聞かれたら答えの考え方
何を見て学習する送信元 MAC と受け取ったポート（宛先ではない）
宛先が表にない同じ VLAN の受け取ったポート以外へフラッディング
宛先が同じポートの先フィルタリング（捨てる）
別の VLAN で学習済みこの VLAN では未知 → フラッディング

静的アドレスエージングしない・再起動でも残る・clear … dynamic で消えない
CRC を調べてから送るストアアンドフォワード（カットスルーは宛先を読んだらすぐ）
フラッディングが止まらない非対称ルーティング・TCN（PortFast）・表のあふれ（ポートセキュリティ）

まとめ

フレーム宛先 → 送信元 → タイプ → データ → FCS。送信元はいつもユニキャスト。最初のオクテットが奇数ならグループあて
学習とエージング送信元で学ぶ。表は VLAN ごと。300 秒で消える。静的は消えない。STP 再構成中は短縮
転送の判断表にある→転送、同じポート→フィルタリング、ない・全員あて→フラッディング
続くフラッディングと IOS非対称ルーティング・TCN・表のあふれ。show mac address-table で確かめる
数字・値中身
6・6・2・4宛先・送信元・タイプ・FCS（バイト）
ffff.ffff.ffffブロードキャスト
0100.5e・3333IPv4・IPv6 マルチキャスト
300 秒エージングの初期値
15 秒forward delay の初期値（加速エージング）
この分野で 1.0 ネットワークの基礎（#01〜#06）がそろった。VLAN とトランク（#07）から先は、表を VLAN ごとに分ける話へ進む。
