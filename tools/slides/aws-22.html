スポットの中断：いつ、何が届くか

中断の理由：主にキャパシティの回収。ホストのメンテナンスやハードウェアの使用停止のこともある。上限料金を決めた場合は、スポット料金がそれを超えたとき。
ひっかけ：中断動作を休止にすると、通知は出るがすぐに休止が始まり、2 分の猶予はない。上限料金を決めると、決めないときより中断が増える。
出典：スポットインスタンスの中断通知（「スポットインスタンスの中断通知はAmazon EC2 がスポットインスタンスを停止または終了する 2 分前に発行される警告です。」）／スポットインスタンスの中断の動作（「デフォルトの動作ではAmazon EC2 は中断時にスポットインスタンスを終了します。」）／スポットインスタンスの中断（「ただし、上限料金を指定すると、指定しなかった場合に比べ、インスタンスの中断が増えます。」）

T インスタンスと CPU クレジット

クレジットがなくなったらスタンダードモードUnlimited モード

Aurora serverless と Database Savings Plans

Aurora serverless：最小と最大の容量（ACU）を決めると、その範囲で自動で増減する。0 ACU から 256 ACU まで。最小を 0 ACU にすると、ワークロードがないときは 0 まで下がる。負荷の差が大きい・読めない・開発やテストに向く。安定した負荷はプロビジョン済みのクラスター。
Database Savings Plans：Aurora・RDS・DynamoDB・ElastiCache などをまとめて最大 35% 割り引く。エンジン・ファミリー・サイズ・AZ・リージョンに関係なく適用され、RDS for Oracle から Aurora PostgreSQL 互換エディションへ移しても続く。
出典：Aurora serverless の仕組み（「Aurora serverless は、0 ACU から 256 ACU までの容量を提供します。」「最小容量が 0 ACU の場合、ワークロードが実行されていないときは、クラスターは 0 にスケールされます。」）／Savings Plans のタイプ（「Database Savings Plans は、Aurora、RDS、DynamoDB、ElastiCache、DocumentDB、Timestream、Neptune、Keyspaces、DMS、Amazon OpenSearch Service のコストを最大 35% 削減しながら、 AWS データベースサービスを使用する柔軟性を提供します。」）
