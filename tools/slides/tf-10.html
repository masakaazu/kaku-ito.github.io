しくみCLI・UI の表示ステート・プランバージョン

variable "api_token" { type = string sensitive = true ephemeral = true } provider "example" { api_token = var.api_token # OK：provider ブロック } # 子モジュールの出力（ルートには付けられない） output "session_token" { value = ephemeral.auth_provider.main.token ephemeral = true sensitive = true }

provider ブロック

ephemeral ブロックと write-only 引数

ephemeral "random_password" "db_password" { length = 16 override_special = "!#$%&*()-_=+[]{}<>:?" } resource "aws_secretsmanager_secret_version" "db_password" { secret_id = aws_secretsmanager_secret.db_password.id secret_string_wo = ephemeral.random_password.db_password.result secret_string_wo_version = 1 } resource "aws_db_instance" "example" { # … password_wo = ephemeral.random_password.db_password.result password_wo_version = 1 # 変えるときは 2 に上げる }
open結果が必要になったら開く
↓
renew期限より長く使うなら延長
↓
close依存するプロバイダーの作業が済んだら閉じる
入力が計画で分からなければ apply まで遅らせる。
write-only はふつうの値も受け付けるが、ephemeral な値を渡すのがおすすめ。差分は出せない。

Vault プロバイダー

provider "vault" {} # VAULT_ADDR・VAULT_TOKEN で渡す data "vault_aws_access_credentials" "creds" { backend = vault_aws_secret_backend.aws.path role = vault_aws_secret_backend_role.role.name } provider "aws" { access_key = data.vault_aws_access_credentials.creds.access_key secret_key = data.vault_aws_access_credentials.creds.secret_key }
使いみちは 2 つ：① Vault を設定してシークレットを入れる ② Vault から資格情報を借りてほかのプロバイダーに使う。
『Interacting with Vault from Terraform causes any secrets that you read and write to be persisted in both Terraform's state file and in any generated plan files』
子トークン（既定 約 20 分）期限で Vault が資格情報を取り消す。plan から時間をおくと apply が失敗しうる
AWS 用の資格情報は renew 不可Terraform が終わるまでもつリースに
ephemeral "vault_kv_secret_v2"ステートに残さず読み、write-only 引数へ

HCP Terraform の動的な資格情報

1. HCP Terraform が OIDC のワークロード ID トークンを作る組織・ワークスペース・実行の段階を含む
↓
2. plan・apply の開始時にクラウドへ送る
↓
3. クラウドが HCP Terraform の公開鍵で確かめる
↓
4. 一時的な資格情報を返し、実行環境に設定
↓
5. 実行が終わると環境ごと捨てる
『Dynamic provider credentials improve your security posture by letting you provision new, temporary credentials for each run.』
静的な資格情報をワークスペースに置かない。ローテーションの手間もない。
クラウド側の信頼関係のルールで、ワークスペースや実行の段階ごとに権限を絞れる。
出典：Dynamic provider credentials
