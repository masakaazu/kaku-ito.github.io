Terraform のしくみ

Write・Plan・Apply とステート。

Terraform #01 IaCとTerraformのしくみ目標 1a・1b・1c

基本のワークフロー

Writeリソースを定義する（複数のクラウドにまたがってよい）
↓
Plan今のインフラと設定から、作る・変える・消すものの実行計画
↓ 承認
Apply依存関係を守った順番で、計画どおりに実行
# 一人で使うとき $ git init my-infra && cd my-infra $ vim main.tf $ terraform init $ terraform plan # 書きながらくり返す $ terraform apply
計画と実行を分けるので、『they know exactly what will happen beforehand』。
依存しないリソースは、リソースグラフで並列に作る。
出典：Core Terraform Workflow Overview／What is Terraform?／Terraform versus CloudFormation

構成要素

要素役割
Terraform 言語（HCL）ブロック・引数・式で書く。主な目的はリソースの宣言
プロバイダーAPI のあるプラットフォーム・サービスを扱うプラグイン
Terraform Registry公開されたプロバイダーとモジュールを探す（registry.terraform.io）
ステートファイル実際のインフラの記録。『a source of truth for your environment』
リソースグラフ依存関係から順番を決め、依存しないものは並列に
モジュール設定を部品にして再利用。組織の標準をセルフサービスに

第3章

マルチクラウドとエディション

同じワークフローで、どこにでも。

Terraform #01 IaCとTerraformのしくみ目標 1a・1b・1c

いろいろな環境を同じやり方で

言葉意味
マルチクラウド複数のクラウド（AWS＋Azure など）
ハイブリッドクラウドオンプレミス＋パブリッククラウド
サービス非依存DNS・CDN・監視・SaaS も同じワークフロー
並行環境開発・テスト・本番を作っては消す
『Terraform lets you use the same workflow to manage multiple providers and handle cross-cloud dependencies.』
CloudFormationAWS の中だけ
Terraform『both cloud-agnostic and enabling multiple providers and services to be combined and composed』
例：AWS と OpenStack のクラスタ、Cloudflare の CDN、DNSimple の DNS を 1 つの設定で。
出典：Terraform Use Cases／Terraform versus CloudFormation, Heat／What is Terraform?

3 つのエディション

エディション形特徴
Terraform Community Edition無料・ダウンロードして CLI で使う設定・プラグイン・インフラ・ステートを管理。最新の設定は自分で pull
HCP TerraformHashiCorp の SaaSリモート実行・ステートとシークレットの保管・RBAC・プライベート・レジストリ・VCS 連携・Sentinel
Terraform Enterpriseセルフホストの HCP Terraformリソースの上限を変えられる。厳しいセキュリティ・コンプライアンスの要件向け
Sentinel：『a policy-as-code framework, to automatically enforce compliance and governance policies before Terraform makes infrastructure changes』（HCP Terraform と Enterprise）
出典：Terraform Editions Overview／Terraform Use Cases（Policy Compliance and Management）

ねらい見るところ
