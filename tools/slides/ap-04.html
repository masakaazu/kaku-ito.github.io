4-1 システムの構成処理の形と構成

クライアントサーバシステムClient Server System
依頼する側（クライアント）と処理する側（サーバ）に役割を分けたシステム
3層クライアントサーバ3-tier Client Server
プレゼンテーション層・ファンクション層（アプリケーション）・データベース層の3つに分けた構成
ポイント層ごとに変更しやすい
デュプレックスシステムDuplex System
主系と待機系の2つを用意し、主系が故障したら待機系に切り替える構成
ポイントホットスタンバイ（待機系を動かしておく）とコールドスタンバイがある
デュアルシステムDual System
2つのシステムで同じ処理を同時に行い、結果を照合する構成
ポイント信頼性が高い
クラスタ構成Cluster
複数のサーバをまとめて1つのシステムのように動かす構成
ポイントHAクラスタ（可用性）と負荷分散クラスタがある
ロードバランサLoad Balancer
複数のサーバに処理を振り分ける装置

4-1 システムの構成処理の形と構成

スケールアウト・スケールアップScale-out / Scale-up
スケールアウトはサーバの台数を増やすこと、スケールアップはサーバ1台の性能を上げること
仮想化Virtualization
1台の物理サーバの上で、複数の仮想的なサーバを動かす技術
ポイントハイパーバイザ型・ホスト型・コンテナ型がある
コンテナ型仮想化Container
OSのカーネルを共有し、アプリの実行環境だけを分ける仮想化
ポイント軽くて起動が速い
ライブマイグレーションLive Migration
動いている仮想マシンを、止めずに別の物理サーバに移すこと
RAIDれいど / Redundant Arrays of Independent Disks
複数のディスクを組み合わせ、速さや信頼性を高める技術
Redundant＝冗長な／Arrays＝並び／Independent＝独立した／Disks＝ディスク
NAS・SANNetwork Attached Storage / Storage Area Network
NASはLANにつなぐファイルサーバ型の記憶装置、SANはサーバと記憶装置を専用のネットワークでつなぐ方式
Attached＝接続された／Storage＝記憶装置／Area＝領域

4-2 システムの評価指標性能・信頼性

スループットThroughput
単位時間あたりに処理できる仕事の量
レスポンスタイムResponse Time
要求を出し終えてから、最初の応答が返ってくるまでの時間
ターンアラウンドタイムTurnaround Time
仕事を出してから、結果をすべて受け取るまでの時間
ベンチマークBenchmark
決まったプログラムを動かして性能を比べる方法
ポイントSPECやTPCがある
キャパシティプランニングCapacity Planning
将来の負荷を予測し、必要な性能や台数を計画すること
RASISらしす
信頼性を評価する5つの観点
Reliability＝信頼性／Availability＝可用性／Serviceability＝保守性／Integrity＝完全性／Security＝安全性
応用情報 システム構成要素8

4-2 システムの評価指標信頼性

MTBFえむてぃーびーえふ / Mean Time Between Failures
故障から次の故障までの平均の時間（平均故障間隔）。長いほど信頼性が高い
Mean＝平均の／Time Between＝間の時間／Failures＝故障
MTTRえむてぃーてぃーあーる / Mean Time To Repair
故障してから直るまでの平均の時間（平均修復時間）。短いほど保守性が高い
Mean＝平均の／Time To＝〜までの時間／Repair＝修理
稼働率Availability
システムが使える状態にある時間の割合
ポイントMTBF÷(MTBF＋MTTR)
バスタブ曲線Bathtub Curve
故障率が時間とともに「初期故障期→偶発故障期→摩耗故障期」と変わる様子を表した曲線
フォールトトレラントFault Tolerant
故障が起きても、システム全体としては機能を続ける考え方
ポイントフェールセーフ・フェールソフト・フールプルーフなどの設計がある
フェールセーフFail Safe
故障したとき、安全な側に止まるようにする設計
例故障したら信号を赤にする

4-2 システムの評価指標信頼性

フェールソフトFail Soft

フールプルーフFool Proof
人が誤った操作をしても、危険にならないようにする設計
