main の形を分解する

JLS 12.1.4：main は public・static・void で、型が「String の配列」の引数を 1 つ持つ。String[] args と String... args（可変長引数）のどちらでもよい。
修飾子の順番は自由：static public でもよい。final を足してもよい。ただし大文字の Main は別の名前で、入口にならない（Java は大文字と小文字を区別する）。
出典：JLS 12.1.4 Invoke Test.main（The method main must be declared public, static, and void. It must specify a formal parameter whose declared type is array of String／public static void main(String... args)）／java ドキュメント（JDK 17） Description（it must not return any value, and it must accept a String array as a parameter）

起動できる main・できない main

A.java の main の宣言javacjava AJDK 17 の表示・理由
public static void main(String[] args)OK起動標準の形
static public void main(String args[])OK起動順番と [] の位置は自由
public static final void main(final String... a)OK起動final・可変長引数・名前の変更は OK
public void main(String[] args)OK失敗Main method is not static in class A
static void main(String[] args)OK失敗Main method not found in class A（public がない）
public static int main(String[] args)OK※失敗Main method must return a value of type void
public static void main(String args)OK失敗Main method not found（配列でない）
public static void Main(String[] args)OK失敗Main method not found（名前がちがう）
ポイント：形のちがう main もふつうのメソッドとしては正しいので、コンパイルは通る。止まるのは java で起動したとき。※ int を返すなら return 0; が必要（ないと missing return statement）。
出典：JLS 12.1.4／java ドキュメント Description（The method must be declared public and static, it must not return any value）／表示は JDK 17（Temurin 17.0.21）で 1 つずつ確かめたもの

道具渡すもの

javaクラス名（.class は付けない）。パッケージがあれば完全修飾名

パッケージはディレクトリになる

src/com/example/app/Main.java（Claude が作成）

                src/com/example/app/Main.java

out/

出典：javac ドキュメント -d（javac puts the class file in a subdirectory that reflects the … package name／If the -d option is not specified, then javac puts each class file in the same directory as the source file）／Arrangement of Source Code（The package p.q … is represented as the subdirectory q of directory p）／結果は JDK 17 で確かめたもの

ソースファイルの並び順

1 つのソースファイル（コンパイル単位）の形
コメント・空白どこに書いてもよい（宣言ではない）
① package 宣言（0 か 1 つ）なければ無名パッケージ
② import 宣言（0 個以上）効くのはこのファイルの中だけ
③ クラス・インタフェースの宣言（0 個以上）public なものは 1 つまで
JLS 7.3：[PackageDeclaration] {ImportDeclaration} {TopLevelClassOrInterfaceDeclaration}。3 つとも省けるが、順番は変えられない。
NG の例と JDK 17 の表示
import java.util.*;
package p;           // import のあとに package
error: class, interface, enum, or record expected
package p;
package q;           // 2 つ目の package
error: class, interface, enum, or record expected
OK の例
/* メモ */
// コメントは package の前でもよい
package p;
import java.util.*;
public class T { }
出典：JLS 7.3 Compilation Units（OrdinaryCompilationUnit: [PackageDeclaration] {ImportDeclaration} {TopLevelClassOrInterfaceDeclaration}／A compilation unit that has no package declaration is part of an unnamed package）／JLS 3.2（after white space and comments are discarded）

public クラスとファイル名・トップレベルの修飾子

ファイルと中身javac の結果説明
T.java に public class TOK・T.classpublic なクラスはクラス名＋.java のファイルに書く
Main.java に public class Tエラーclass T is public, should be declared in a file named T.java
T.java に public class T と public class Uエラーpublic は 1 ファイルに 1 つまで。U でも同じエラー
T.java に public class T と class UOK・T.class と U.classpublic でないクラスは足してよい。main があれば java U も動く
Main.java に class T と class MainOK・T.class と Main.classpublic でなければファイル名と合っていなくてよい
final class A {}・abstract class A {}OKfinal・abstract はトップレベルに付けられる（#11）
private・protected・static class A {}エラーmodifier private not allowed here（protected・static も同じ）
JLS 7.6：ファイル名の決まりは「ファイルシステムを使う処理系が課してよい制約」で、javac は守らせる。トップレベルのクラスのアクセスは public か、何も書かない（同じパッケージだけ）の 2 通り。
出典：JLS 7.6 Top Level Class and Interface Declarations（It is a compile-time error if a top level class or interface declaration contains any one of the following access modifiers: protected, private, or static／The class or interface is declared public … there must be at most one such class or interface per compilation unit）／結果は JDK 17 で確かめたもの

無名パッケージとサブパッケージ

無名パッケージ
// Util.java（package を書かない）
public class Util { }

// p/T.java
package p;
import Util;          // error: '.' expected
public class T { }
名前付きパッケージから、無名パッケージの型は使えない。インポートできるのは名前付きパッケージの型だけ（JLS 7.5.1）。import を書かずに Util と書いても cannot find symbol。無名パッケージは「小さなプログラムや学習の始め」のための便利な仕組み（JLS 7.4.2）。
サブパッケージは別のパッケージ
* はサブパッケージを含まない。import java.util.*; のあと concurrent.ConcurrentHashMap と書くと package concurrent does not exist。パッケージそのもの（import java.util;）もインポートできない。

インポート

短い名前で書くための宣言。中身を取り込むわけではない。

Java Silver #01 プログラムの実行とパッケージ試験内容 1

インポートの 4 種類と java.lang

書き方種類使えるようになるもの
import java.util.List;単一型List という 1 つの型
import java.util.*;オンデマンドjava.util の型すべて（使った分だけ。サブパッケージは含まない）
import static java.lang.Math.max;単一 staticMath の static メンバー max（同じ名前のオーバーロードすべて）
import static java.lang.Math.*;static オンデマンドMath の static メンバーすべて（max(3, abs(-5))・PI）
（書かない）自動java.lang の型すべて：String・Math・System・StringBuilder・Integer など
まちがえやすい書き方（JDK 17 の表示）
static import java.lang.Math.max;  // 語順が逆
  → class, interface, enum, or record expected
import static java.lang.Math;      // クラス名で終わる
  → cannot find symbol
import java.lang.Math.*;            // static がない
  → max(1, 2) が cannot find symbol
import の正体：型や static メンバーを短い名前で書けるようにするだけ。クラスの中身はコピーしない。効くのは書いたファイルの中だけで、同じパッケージのほかのファイルには効かない。import しなくても完全修飾名（java.util.ArrayList）で書けば使える。
出典：JLS 7.5（makes classes, interfaces, or members available by their simple names only within the compilation unit that actually contains the import declaration）／7.5.1〜7.5.4（import TypeName ;／import PackageOrTypeName . * ;／import static TypeName . Identifier ;／import static TypeName . * ;）／7.3（Every compilation unit implicitly imports every public class or interface declared in the predefined package java.lang）

名前がぶつかったとき ― Date の例

import の組み合わせDate を使うとJDK 17 の結果・理由
import java.util.*;
import java.sql.*;		エラーreference to Date is ambiguous。使わなければエラーにならない
import java.util.Date;
import java.sql.*;		java.util.Date単一型インポートが * のインポートを隠す（シャドウイング）
import java.util.Date;
import java.sql.Date;		エラーa type with the same simple name is already defined by the single-type-import of Date。使わなくてもエラー
import java.util.*; と自分の class Vector {}自分の Vector同じファイル・同じパッケージの型が * のインポートより優先（JLS 7.6 の例）
強い順：① 自分のファイル・単一型インポート　② 同じパッケージの型　③ * のインポート（java.lang も ③ と同じ扱い）。①どうし・③どうしで同じ名前が並ぶと、決められずエラーになる。
直し方：どちらかを単一型インポートにする。もう片方は java.sql.Date のように完全修飾名で書く。
出典：JLS 7.5.1（If two single-type-import declarations in the same compilation unit attempt to import classes or interfaces with the same simple name, then a compile-time error occurs）／7.5.2 Example 7.5.2-1（might be shadowed by a single-type-import declaration … by a class or interface named Vector and declared in the package to which the compilation unit belongs）／7.6 Example 7.6-1／結果は JDK 17 で確かめたもの
