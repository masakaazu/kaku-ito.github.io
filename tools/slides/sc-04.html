第1章

なりすましと信頼の悪用

「送り主」「宛先」「見慣れたサイト」を偽る。

支援士 #04 ネットワーク・DNS・DoSの攻撃23-2

IP スプーフィングと ARP スプーフィング

IP スプーフィング：送信元アドレスを偽る
プロトコル偽装の通りやすさ
UDP・ICMP応答を待たないので、そのまま通る → 反射・増幅に使われる
TCP3ウェイハンドシェイクが完了しない → SYN フラッドに使われる
対策：境界で送信元を検査（イングレスフィルタリング、BCP 38）。外から来たのに送信元が内部のパケットは捨てる。
ARP スプーフィング（ARP ポイズニング）
PCGW の MAC は？
→
攻撃者「GW は私（偽の MAC）」
→
本物の GW攻撃者が中継
LAN の中だけで起きる。ゲートウェイになりすますと外へ出る通信をすべて盗聴・改ざん（中間者攻撃、#02）。
対策：スイッチの DHCP スヌーピング＋DAI（ダイナミック ARP インスペクション）、静的 ARP。
出典：RFC 2827（BCP 38）Network Ingress Filtering／Cisco「Configuring Dynamic ARP Inspection」／IPA「支援士試験 シラバス（案）」中分類25「DHCP スヌーピング」

第三者中継とフィッシングの仲間

第三者中継（オープンリレー）
社外の送信者迷惑メール業者
→
自社のメールサーバ制限なしで中継
→
社外の宛先大量の受信者
踏み台にされ、IP がブラックリスト入り → 自社の正規メールも届かない。
対策：中継する送信元を自組織に限る、SMTP-AUTH、OP25B（#14）。
攻撃入口特徴
フィッシングメール本物そっくりの偽サイトで資格情報を入力させる
スミッシングSMS不在通知などを装う。偽アプリを入れさせる手口も
標的型攻撃業務に見せたメール事前に偵察。長期に潜伏（APT）
水飲み場型標的がよく見る正規サイト標的の IP のときだけ攻撃コード
SEO ポイズニング検索結果話題の言葉で罠のサイトを上位に
出典：IPA「支援士試験 シラバス（案）」用語例「第三者中継（オープンリレー）」「フィッシング（スミッシング）」「標的型攻撃」「SEO ポイズニング」
第2章

DNS への攻撃

正しいドメイン名を入れても、偽のサイトへ連れて行かれる。

支援士 #04 ネットワーク・DNS・DoSの攻撃23-2

DNS キャッシュポイズニング：答えより先に偽の答えを届ける

① 利用者www.bank.example の IP は？
→
② キャッシュ DNS権威サーバに問い合わせ中
→
③ 権威 DNS正しい答え（遅れて届く）
攻撃者偽の答えを大量に送る
→
キャッシュに偽の IP利用者全員が偽サイトへ
偽の答えが受け入れられる条件対策
DNS ヘッダの ID（16 ビット）が一致ID をランダムに
宛先ポート（＝問い合わせの送信元ポート）が一致ポートをランダムに
正しい答えより先に届く—
内容の正しさを確かめていないDNSSEC で署名（#16）
H31春 問11：正解は「ID をランダムに変更」。「送信元ポート番号を 53 に固定」は逆効果のひっかけ。
出典：RFC 5452 Measures for Making DNS More Resilient against Forged Answers／IPA 午前Ⅱ 平成31年度春期 問11

カミンスキー攻撃：何度でも試せるようにした

従来の攻撃カミンスキー攻撃（2008）
問い合わせる名前www.bank.examplea1.bank.example、a2…（存在しない）
失敗したら正しい答えがキャッシュされ TTL の間は再挑戦できない次の名前ですぐ再挑戦
偽の答えの中身その名前の IPbank.example 全体の権威サーバを偽サーバに
当たる確率の目安
ID だけ：216 ≒ 6.5万通り　→　ID×ポート：約 6.5万 × 約6万 ≒ 約40億通り
R7春 問4（R5春 問5 と同じ）：正解は「問合せ時の送信元ポート番号をランダム化」。
誤りの選択肢本当は何の対策か
計2台の冗長構成過負荷・故障
SPF でレコードを認証メールの送信元（#14）
プレースホルダSQL インジェクション（#03）
出典：CERT/CC VU#800113（2008）／RFC 5452／IPA 午前Ⅱ 令和7年度春期 問4・令和5年度春期 問5。確率の数字は Claude の概算

ドメイン名ハイジャックとオープンリゾルバ

ドメイン名ハイジャック
キャッシュをだますのではなく、登録情報や権威 DNS そのものを書き換える。だれが引いても偽サーバに着く。
入口対策
レジストラのアカウントの乗っ取りMFA、レジストリロック
権威 DNS への侵入登録情報・NS の監視
残ったサブドメインの CNAME（テイクオーバー）使わない DNS レコードを消す
オープンリゾルバ
だれからの再帰問い合わせにも答えるキャッシュ DNS サーバ。
DNS アンプ攻撃の踏み台送信元を偽った問い合わせに大きな応答を返す
キャッシュポイズニングの的外部から問い合わせを起こさせやすい
対策：再帰問い合わせを自組織の利用者に限る。権威 DNS とキャッシュ DNS を分ける。
出典：JPCERT/CC「オープンリゾルバに関する注意喚起」／IPA「支援士試験 シラバス（案）」中分類23 用語例
第3章

サービス妨害（DoS・DDoS）

何を使い切らせるのか（回線・接続・処理）で分ける。

支援士 #04 ネットワーク・DNS・DoSの攻撃23-2

SYN フラッドとバックスキャッタ

3ウェイハンドシェイクを途中で止める
正常SYN フラッド
① SYN →① SYN →（送信元は偽）×大量
② ← SYN/ACK② ← SYN/ACK（偽の送信元へ）
③ ACK →（接続完了）③ 来ない → 待ち行列が満杯
SYN cookie：SYN では待ち行列を使わず、情報を SYN/ACK のシーケンス番号に埋め込む。正しい ACK が来たら接続（RFC 4987）。
R7秋 問7（R4秋・R6春 と同じ）
送信元 A : 80/tcp → 未使用アドレス 種類 SYN/ACK × 大量
  • A は SYN/ACK（応答）を返している側
  • 宛先が未使用 → だれかが送信元を偽って A に SYN を送った
  • だから A を攻撃先とするサービス妨害（ア）
    • 未使用のアドレス（ダークネット）に届くこうした応答をバックスキャッタという。NICTER などが観測に使う。
    出典：RFC 4987 TCP SYN Flooding Attacks and Common Mitigations／IPA 午前Ⅱ 令和7年度秋期 問7／NICT「NICTER 観測レポート」

    Smurf 攻撃：ブロードキャストで増やす

    攻撃者ICMP エコー要求
    送信元＝標的・宛先＝ブロードキャスト
    →
    踏み台のネットワーク全機器がエコー応答を返す
    →
    標的大量の ICMP エコー応答
    R6秋 問6 の選択肢正体
    ICMP エコー要求・送信元＝標的・宛先＝ブロードキャストSmurf（正解）
    受信可能範囲を超える大きなパケットPing of Death など
    偽の送信元の SYN を大量、ACK を返さないSYN フラッド
    ボットネットで大量のなりすましメールメール爆弾
    H31春・R3春 の版では「ICMP の応答パケットを大量に発生させ…攻撃対象に送られる」、R4秋 では「偽装した ICMP の要求パケットを送って、大量の応答パケットが攻撃対象に」が正解。
    対策：ルータでダイレクテッドブロードキャストを転送しない。
    出典：IPA 午前Ⅱ 令和6年度秋期 問6・平成31年度春期 問6・令和3年度春期 問4・令和4年度秋期 問4

    アプリケーション層の DoS：HTTP フラッドと Slow HTTP

    HTTP フラッドSlow HTTP
    量大量の GET・POST少ない
    使い切らせるもの処理能力（アプリ・DB）同時接続数
    手口重い検索などを連打ヘッダ・本文を数秒おきに少しずつ
    気付き方要求数の急増量は普段どおりで接続が埋まる
    対策レート制限・Bot 判定・WAF・CDN受信タイムアウト短縮・IP ごとの同時接続数制限
    Slowloris の送り方（イメージ）
    GET / HTTP/1.1 Host: www.example.jp （10秒待つ） X-a: 1 （10秒待つ） X-b: 2 …空行を送らず終わらせない
    R7春 問1：「多数の HTTP リクエストを長期間掛けて送信し続け、セッションを占有」は DRDoS ではなく Slow HTTP。
    出典：Apache HTTP Server ドキュメント「Security Tips」Denial of Service (DoS) attacks・mod_reqtimeout／IPA 午前Ⅱ 令和7年度春期 問1

    リフレクション（DRDoS）と増幅率

    攻撃者小さな要求 × 多数
    送信元＝標的
    →
    第三者のサーバDNS・NTP・Memcached…
    →
    標的大きな応答が集中
    プロトコル増幅率（CISA）使われる要求
    DNS28〜54ANY 型、署名付き応答
    NTP556.9monlist（最大600件の一覧）
    SSDP30.8M-SEARCH
    SNMPv26.3GetBulk
    Memcached10,000〜51,000stats など（UDP 11211）
    R3春 問1：悪用されやすいのは「DNS, Memcached, NTP」。DKIM・DNSSEC・SPF や IPsec・TLS は違う。
    R6秋 問4：NTP サーバは踏み台。「送信元を偽って、レスポンスが大きくなるリクエストを送る」が正解。「NTP サーバに echo request」は ICMP なので誤り。
    出典：CISA「Alert TA14-017A UDP-Based Amplification Attacks」（増幅率の表）／IPA 午前Ⅱ 令和3年度春期 問1・令和6年度秋期 問4

    DDoS とマルチベクトル型

    R1秋 問13：マルチベクトル型はどれか
    選択肢攻撃の種類
    DNS リフレクタで DNS を止める1種類
    SYN Flood と HTTP POST Flood を同時に2種類（L4＋L7）
    IoT 機器から UDP Flood1種類（台数は多い）
    FW の送信順序を操作して枯渇1種類
    「多数の機器から」は DDoS の条件で、マルチベクトルの条件ではない。
    DDoS への備え（詳しくは #13）
    CDN・Anycast大容量の回線と多数の拠点で受け止めて分散
    スクラビングセンター通信を引き込み、攻撃の通信だけ取り除いて返す
    レート制限・Bot 対策L7 の攻撃を見分けて絞る
    送信元検証（BCP 38）自分のネットワークから偽装パケットを出さない
    出典：IPA 午前Ⅱ 令和元年度秋期 問13／IPA「支援士試験 シラバス（案）」中分類25「DDoS 対策（CDN，スクラビングセンター，Anycast，レート制限）」

    過去問の問われ方のまとめ

    パケットの向きを読む：応答（SYN/ACK・エコー応答）を出している側は被害者か踏み台。送信元を偽った要求が先にある。
    DNS は「ランダム化」：ID と送信元ポート番号をランダムに。固定するのは逆。根本的には DNSSEC。
    リフレクションの条件：UDP・送信元を偽れる・応答が大きい。DNS・NTP・Memcached。
