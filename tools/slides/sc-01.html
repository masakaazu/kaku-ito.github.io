第1章

脅威の種類と動向

攻撃の「入口」と「種類」を整理する。設計の段階で脅威を洗い出すのが脅威モデリング。

支援士 #01 脅威と脆弱性23-1

攻撃ベクトルと攻撃対象領域：「道」と「入口の総和」

攻撃ベクトル：「どこから・何を使って」入るかという個々の経路。CVSS の基本評価基準にも「攻撃元区分（AV）」として出てくる（ネットワーク・隣接・ローカル・物理）。
攻撃対象領域の最小化：使わないサービスを止め、公開範囲を絞り、不要なアカウントを消す。外部から見える資産を継続的に把握するのが ASM／EASM（#12）。
出典：IPA「支援士試験 シラバス（案）」中分類23 小分類1 用語例「攻撃ベクトル，攻撃対象領域（アタックサーフェス）」、中分類24 小分類1「攻撃対象領域の最小化」、中分類25 小分類5「ASM／EASM」

STRIDE：脅威の6種類は「守りたい性質」の裏返し

STRIDE損なわれる性質例主な対策
S なりすまし
Spoofing		真正性（認証）盗んだパスワードで他人としてログインする多要素認証・パスキー
T 改ざん
Tampering		完全性通信途中や DB の金額を書き換えるMAC・デジタル署名・アクセス制御
R 否認
Repudiation		否認防止「その注文は自分ではない」と言い逃れるデジタル署名・改ざんできないログ
I 情報漏えい
Information disclosure		機密性エラーメッセージに内部情報が出る暗号化・最小権限
D サービス妨害
Denial of service		可用性大量のリクエストでサービスを止めるレート制限・冗長化・CDN
E 権限昇格
Elevation of privilege		認可一般利用者が管理者の操作を行うサーバ側での認可の確認
区別：STRIDE は脅威の種類の分け方。サイバーキルチェーンや MITRE ATT&CK は攻撃の段階・手口の分け方（#02）。問題文が「設計時に脅威を網羅的に洗い出す」なら STRIDE。
出典：Microsoft「Threat Modeling Tool の脅威」（STRIDE の6分類）／IPA「支援士試験 シラバス（案）」用語例「脅威モデリング（STRIDE など）」

脅威モデリングの進め方：作る前に脅威を洗い出す

データフロー図（DFD）。境界をまたぐ流れが、脅威を当てはめる場所。図は Claude が作った例。
  1. 図にする：データの流れ・保存場所・外部の相手・信頼境界を DFD に描く
  2. 洗い出す：境界をまたぐ流れと要素ごとに STRIDE を当てはめる
  3. 評価する：起こりやすさと影響で優先順位を付ける（リスク評価は #06）
  4. 対策を決める：要件に落とし込む（認証・暗号化・入力検証・ログなど）
  5. 確かめる：実装後のレビューやテストで、対策が効いているかを検証する
セキュリティ・バイ・デザイン：脆弱性は作ったあとで直すほど費用がかかる。だから要件定義・設計の段階で脅威モデリングを行う。科目Bでも「設計書を読んで不足している対策を指摘する」形で問われる。
出典：IPA「支援士試験 シラバス（案）」中分類23 用語例「脅威モデリング」「脅威シナリオ」、中分類24 小分類1「セキュリティ・バイ・デザイン」、目標とする技能 2-1「脅威分析の結果からセキュリティ要件を定義する能力」

ビジネスメール詐欺（BEC）の典型的な流れ
① 侵入・盗み見取引先や自社のメールアカウントを乗っ取る
→
② 観察請求のタイミングや文面のくせを学ぶ
→
③ なりすまし似たドメインや乗っ取った本物のアカウントから送る
→
④ 送金「口座が変わった」と攻撃者の口座へ
手口中身
ソーシャルエンジニアリング権威・緊急性・親切心につけこむ。電話、のぞき見（ショルダーハッキング）、ごみあさり（トラッシング）

第2章

マルウェア・不正プログラム

何をするか（目的）と、どう隠れるか（ステルス技術）の2つの軸で整理する。

支援士 #01 脅威と脆弱性23-1

C&C とコネクトバック：なぜ「内から外」が危ないか

コネクトバック＝侵害したシステムから攻撃者のサーバへ通信を始めること（令和7年度春期 問8）。リバースシェルやボットの C&C 通信がこの形。
対策：出口（外向き通信）を絞る。プロキシ経由だけを許し、認証を求める。宛先の評判（脅威インテリジェンス、#09）で不審な通信先を止め、ログで定期的な通信（ビーコン）を探す。
出典：IPA 午前Ⅱ 令和7年度春期 問8（コネクトバック）／IPA「支援士試験 シラバス（案）」中分類23 用語例「リバースシェル」「C2（Command and Control）」

ステルス技術：見つからないための工夫

技術何が変わる・何が残らない対抗する検知
ポリモーフィック型感染のたびに暗号化の鍵や復号部を変える。復号後の本体は同じビヘイビア法（振る舞い）、メモリ上での検査
メタモーフィック型感染のたびに本体のコードそのものを書き換える（命令の並べ替え、無意味な命令の挿入）ビヘイビア法、ヒューリスティック法
ファイルレス実行ファイルをディスクに残さず、PowerShell・WMI など正規ツールでメモリ上だけで動くEDR、PowerShell のログ、メモリフォレンジック
ルートキット侵入後のツールやプロセス・ログを隠す（OS のカーネルやコマンドを改変）別の起動媒体からの検査、OS の再インストール
パッカー・難読化圧縮や暗号化でコードを読みにくくし、静的解析を妨げるアンパックしてから解析（#19）
パターンマッチング（定義ファイルと照合）は、見た目が変わる・ファイルがない相手に弱い。だから振る舞いで見る方式（#12）と組み合わせる。
ひっかけ：「メモリ上だけで動く」はファイルレス、「痕跡を隠す」はルートキット。ポリモーフィックとメタモーフィックの違いは「本体まで変えるか」。
出典：IPA「支援士試験 シラバス（案）」中分類23 用語例「ステルス技術（ポリモーフィック型，メタモーフィック型 など），ファイルレスマルウェア」、中分類26 小分類2「解析やセキュリティ検知を回避する技術（パッカー，難読化…）」

いまのランサムウェア攻撃：侵入してから暗号化する

① 侵入VPN 機器の脆弱性・盗んだ認証情報（IAB から購入）
→
② 権限昇格・横展開管理者権限を奪い、AD やサーバに広がる
→
③ 持ち出し機密データを外部へ送る
→
④ 妨害バックアップを消す・セキュリティ製品を止める
→
⑤ 暗号化と脅迫復号と非公開の両方で身代金
段階止める対策の例
①VPN 機器のパッチ、多要素認証、公開範囲の最小化
②特権アカウントの管理（PAM）、ネットワークの分離、EDR
③外向き通信の監視、DLP
④⑤オフライン・イミュータブルなバックアップ、3-2-1 ルール（#12）、復旧手順の訓練
二重恐喝：③で盗んでいるので、バックアップから戻せても「公開する」という脅しは残る。
クリプトジャッキングとの違い：あちらはデータを壊さず、計算資源だけを盗む（令和7年度春期 問5）。
出典：IPA「情報セキュリティ10大脅威 2026」1位 ランサム攻撃による被害／IPA「支援士試験 シラバス（案）」中分類25 小分類5〔ランサムウェア対策〕（バックアップ分離，3-2-1 ルール，イミュータブルバックアップ など）

Mirai：初期パスワードの IoT 機器をボットにする

  1. 探す：ランダムな宛先 IP アドレスに、Telnet（TCP 23番など）で接続を試みる
  2. ログインする：よくある初期設定の ID・パスワードの一覧を順に試す
  3. 感染する：ログインできた機器に本体を送り込み、ボットにする
  4. 増える：感染した機器がさらに①から繰り返す
  5. 攻撃する：C&C サーバの指令で、標的に一斉に DDoS 攻撃
午前Ⅱの選択肢の見分け方（令和7年度春期 問7）
選択肢の特徴判定
ランダムな宛先・C&C の指令で DDoSMirai
Web サーバの脆弱性・決められた日時に DDoS別物
Web ページに JavaScript を挿入して誘導改ざん
ファイル共有ソフトで情報を公開暴露ウイルス
対策：初期パスワードの変更、Telnet など不要なポートを閉じる、ファームウェアの更新。総務省・NICT の NOTICE（#07）は、こうした機器を調べて注意喚起する取組。
出典：IPA 午前Ⅱ 令和7年度春期 問7（令和5年度秋期 問6）・令和3年度秋期 問11（TCP 23番への攻撃）
第3章

脆弱性

作り方の不備（技術）と、人・組織の不備。どれも CWE や OWASP の分類で名前が付いている。

支援士 #01 脅威と脆弱性23-1

シラバス案に並ぶ脆弱性と、その正体

脆弱性どんな不備かCWE根本的な対策
認可・アクセス制御の不備ログイン後に他人のデータや管理機能に手が届く（ID の書き換え＝IDOR）CWE-862 ほか要求のたびにサーバ側で権限を確認
認証バイパス認証そのものを経ずに機能に到達できるCWE-306すべての入口で認証を確認
不適切な入力確認想定外の入力をそのまま処理に使うCWE-20入力検証＋出力先に合わせたエスケープ
パスワードのハードコード認証情報をコードに書き込む。全製品で共通・変更不可になりがちCWE-798シークレットストアで管理
平文での保存・送信重要情報を暗号化せずに保存・通信するCWE-312／319TLS、保存時の暗号化、パスワードはハッシュ
レースコンディション処理の順序やタイミングのずれをつかれるCWE-362／367確認と使用を不可分にする
認証と認可：認証＝「あなたはだれか」、認可＝「あなたはそれをしてよいか」。ログインしているのに他人の注文が見えるのは認可の不備。ログイン画面を飛ばせるのは認証バイパス。
出典：IPA「支援士試験 シラバス（案）」中分類23 小分類1 用語例（脆弱性）／MITRE「CWE」（CWE-20・306・312・319・362・367・798・862）

レースコンディション（TOCTOU）：確認と使用のすきま

TOCTOU（Time of Check to Time of Use）＝確認した時点と使う時点のずれ。間に対象を差し替えられると、確認の意味がなくなる。
Web での例：クーポンの「使用済みか確認」と「使用済みにする」の間に同じ要求を同時に大量に送り、何度も使う。対策は DB のトランザクションやロックで、確認と更新を1つの不可分な処理にする（#21）。
出典：MITRE「CWE-367 Time-of-check Time-of-use (TOCTOU) Race Condition」／IPA「支援士試験 シラバス（案）」用語例「レースコンディション」。図は Claude が作った例

人と組織の脆弱性

人的脆弱性
不注意・知識不足・心理的な弱さ。添付を確認せず開く、パスワードを付箋に書く。
対策：教育・訓練（標的型メール訓練、#09）、一人の判断に頼らない手順
シャドーIT
情報システム部門が把握していないクラウドや機器を業務に使う。生成 AI への機密の入力も。
対策：CASB で見える化（#13）、使ってよいサービスと規程を用意（#08）
内部統制の不備
職務の分離・承認・ログの確認がない。一人で申請も承認もできる。
対策：職務の分離、アクセス権の定期的な見直し、ログの監視
なぜ「脆弱性」に入っているか：リスクは「脅威が脆弱性につけこんで資産に損害を与える可能性」。技術の穴をふさいでも、人と組織の穴が残れば同じように攻撃される。支援士は技術だけでなく、規程・教育・体制の指導・助言も役割（科目Bの技能 1-8 人的管理）。
出典：IPA「支援士試験 シラバス（案）」中分類23 用語例「人的脆弱性，内部統制の不備，シャドーIT」、目標とする技能 1-8「人的管理」
