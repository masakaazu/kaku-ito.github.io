第1章

VLANとアクセスポート

1台のスイッチを、配線を変えずに論理的に分ける。端末をつなぐポートは「アクセスポート」で、VLANを1つだけ持つ。

CCNA #07 VLANとトランク2.1

VLAN＝ブロードキャストが届く範囲を、ポート単位で切ったもの

VLAN（Virtual LAN）
スイッチのポートを、配線と関係なく論理的なグループに分けたもの。1つのVLAN＝1つのブロードキャストドメイン。
ユニキャスト・ブロードキャスト・マルチキャスト
どれも同じVLANの中にしか流れない（構成ガイド「forwarded and flooded only to end stations in the VLAN」）。
VLANどうしの通信
スイッチだけでは届かない。ルーティングが必要（第3章）。
VLANとサブネット
1つのVLANに1つのIPサブネットを割り当てるのが基本。VLAN 10＝192.168.10.0/24 のように番号をそろえると読みやすい。
スタティックVLAN：ポートごとに手でVLANを決める方式（構成ガイドでは interface-based / static membership）。PCをつなぎ替えるとVLANも変わる。
出典：Cisco VLAN Configuration Guide, IOS XE 17.9.x (Catalyst 9300)「Configuring VLANs」Logical Networks

ブロードキャストドメインと衝突ドメインの数え方

数え方の手順
  1. ブロードキャストドメインはルータ（L3）とVLANで切れる。
    → ルータのポートの数、またはスイッチのVLANの数を数える
  2. 衝突ドメインはスイッチとルータのポートごとに切れる。
    → スイッチ・ルータの使っているポートを数える
  3. ハブは何も切らない。ハブにつながった全体で衝突ドメイン1つ
  4. 全二重ならコリジョンは起きないが、数える問題では「ポートごとに1つ」と数える
例題24ポートのスイッチ1台。VLAN 10に12ポート、VLAN 20に12ポートを割り当て、全ポートに端末をつないだ。
数えるもの答え理由
ブロードキャストドメイン2VLANの数
衝突ドメイン24スイッチのポートの数。VLANでは変わらない
引っかけ：「VLANを分けたら衝突ドメインも2つ」「ポートごとにブロードキャストドメインが分かれる」はどちらも誤り。VLAN→ブロードキャスト、ポート→衝突と対で覚える。
出典：Cisco VLAN Configuration Guide 17.9.x「Configuring VLANs」（VLANとブロードキャストの範囲）。例題はClaudeが作成

VLAN番号は4つの範囲。消せないのは1と1002〜1005

範囲名前ポイント
1デフォルトVLAN最初から全ポートが入っている。削除・名前の変更はできない
2〜1001標準範囲自由に作れる。vlan.dat に保存。VTPで伝わる
1002〜1005予約トークンリング・FDDI用。最初からあり削除できない
1006〜4094拡張範囲VTPバージョン1・2では伝わらない（v3なら伝わる）
12ビット：802.1QのVLAN IDは12ビットなので0〜4095。使うのは1〜4094（0と4095は使わない）。「4096個作れる」は誤り。
覚えておきたい動き
存在しないVLANを switchport access vlan 30VLAN 30が自動で作られる（名前は VLAN0030）
VLANを no vlan 40 で削除VLAN 40のポートは使えない状態（inactive）のまま。別のVLANに入れ直すまで通信できない
名前を付けないVLAN0004 のように「VLAN＋0で埋めた番号」
write erase で初期化vlan.dat は消えない。delete flash:vlan.dat も必要

アクセスポートの設定は3行。確かめるのは show vlan brief

設定（VLANを作ってポートに割り当てる）
SW1(config)# vlan 10
SW1(config-vlan)# name SALES
SW1(config-vlan)# exit
SW1(config)# interface g1/0/1
SW1(config-if)# switchport mode access
SW1(config-if)# switchport access vlan 10
SW1(config-if)# end
SW1# copy running-config startup-config
  • switchport mode access：相手が何でもトランクにしない（DTPの交渉も非トランクにする）
  • switchport access vlan：アクセスポートが入るVLANは1つだけ
  • まとめて設定するなら interface range g1/0/1 - 12
確認（show vlan brief）
SW1# show vlan brief
VLAN Name           Status    Ports
---- -------------- --------- -----------------
1    default        active    Gi1/0/13, Gi1/0/14
10   SALES          active    Gi1/0/1, Gi1/0/2
20   ENG            active
1002 fddi-default   act/unsup
  • Ports に並ぶのはアクセスポートだけ。トランクのポートは出ない
  • VLAN 20 は作られているが、所属するポートがない
  • 1002〜1005 は act/unsup（存在するが、この機器では使えない）
  • 1ポートを詳しく見るなら show interfaces g1/0/1 switchport

音声VLAN：アクセスポート1つで、電話の音声とPCを分ける

SW1(config)# interface g1/0/5
SW1(config-if)# switchport mode access
SW1(config-if)# switchport access vlan 10
SW1(config-if)# switchport voice vlan 20
  • トランクにしなくてよい（アクセスポートのまま2つのVLANを運ぶ）
  • Cisco IP電話は音声に CoS 5（IP precedence も5）を付けるのが初期値
  • 音声VLANを設定すると PortFast が自動で有効になる（外しても自動では無効にならない）
  • 確認：show interfaces g1/0/5 switchport の Access Mode VLAN と Voice VLAN
  • ほかの書き方：voice vlan dot1p＝VLAN 0（優先度だけのタグ）、untagged、none

第2章

トランクと802.1Q

複数のVLANを1本のリンクで運ぶ。どのVLANのフレームかはタグで区別する。トランクにするかはDTPで交渉できる。

CCNA #07 VLANとトランク2.2

トランク＝タグを付けて、複数のVLANを1本で運ぶリンク

トランクがないと（VLANの数だけケーブル）
トランクがあると（1本で全部）
トランク
2台の機器を結ぶポイントツーポイントのリンクで、複数のVLANのトラフィックを運ぶ。つなぐ相手はスイッチ・ルータ・コントローラなど。
タグ
送る側がフレームにVLANの番号を付け、受け取った側がタグを外して、そのVLANに転送する。
初期状態で通るVLAN
VLAN 1〜4094の全部。許可リストで絞れる（このあと）。
アクセスポートとの違い
アクセス＝VLAN 1つ・タグなし。トランク＝VLAN複数・タグ付き（ネイティブVLANだけタグなし）。
出典：Cisco VLAN Configuration Guide 17.9.x「Configuring VLAN Trunks」 Trunking Overview・Allowed VLANs on a Trunk

802.1Qタグは4バイト。送信元MACの後ろに入れて、FCSを計算し直す

TPID0x8100。普通ならタイプ（IPv4は0x0800）がある位置に来るので、受け取った側はタグ付きとわかる
PCPIEEE 802.1p の優先度（CoS）。3ビットで8段階。音声はCoS 5がよく使われる
VID12ビット。使えるのは1〜4094。VID 0 は「優先度だけのタグ」（voice vlan dot1p）
出典：Cisco「Inter-Switch Link and IEEE 802.1Q Frame Format」（IEEE 802.1Q Frame Fields）／ Configuring Voice VLANs（dot1p＝VLAN ID 0）。CFIは新しい版の規格ではDEIと呼ぶ

802.1Q と ISL：「中に挿入」か「外から包む」か

比べる点IEEE 802.1QISL（Inter-Switch Link）
作ったところIEEE の標準。他社の機器ともつながるCisco 独自。古い方式
付け方元のフレームの中（送信元MACの後ろ）に4バイトのタグを挿入元のフレームを26バイトのヘッダーと4バイトのFCSで丸ごと包む
FCSフレームが変わるので計算し直す外側に新しいFCSを付ける（元のFCSも残る）
VLANの数VID 12ビット（4096通り。使うのは1〜4094）1024
ネイティブVLANある（タグなしで送るVLAN）ない（全部包む）
いまの機器Catalyst 9300 などは802.1Qだけ使わない。古い機種で使えても802.1Qへ移すのが推奨
設定の注意：ISLも使える古い機種では、switchport mode trunk の前に switchport trunk encapsulation dot1q でカプセル化を決める。802.1Qだけの機種にはこのコマンドがない。
出典：Cisco「Inter-Switch Link and IEEE 802.1Q Frame Format」 ／ Cisco「Best Practices for Catalyst 6500/6000 and 4500/4000 Series Switches Running Cisco IOS」（Encapsulation Type）

ネイティブVLAN：トランクの中で、タグを付けないVLAN

SW1(config-if)# switchport trunk native vlan 99
決まりごと中身
初期値VLAN 1。1〜4094のどれにでも変えられる
送るとき出ていくフレームのVLANがネイティブVLANならタグなし、それ以外はタグ付き
受け取るときタグなしのフレームはネイティブVLANのものとして転送
両端同じ番号にそろえる。違うとスパニングツリーのループが起こりうる
推奨ユーザーが使わない番号（例：999）にする。VLANホッピング対策
VLAN 1の特別扱い：許可リストからVLAN 1を外しても、CDP・DTP・VTP・PAgP・LACPなどの制御フレームはVLAN 1で送受信を続ける。止まるのはユーザーのデータだけ。
出典：Cisco VLAN Configuration Guide 17.9.x「Configuring VLAN Trunks」 Configuring the Native VLAN for Untagged Traffic・Prerequisites・Allowed VLANs on a Trunk

ネイティブVLANの不一致とVLANホッピング

不一致（SW1 native 10 ／ SW2 native 20）
  • トランクは上がるので気づきにくい
  • 構成ガイド：「両端のネイティブVLANが違うとスパニングツリーのループになりうる」
  • 確認：両側で show interfaces trunk の Native vlan を比べる
VLANホッピング（ダブルタギング）の流れ
  1. 攻撃者はアクセスVLAN＝トランクのネイティブVLAN（例：VLAN 1）にいる
  2. 外側にVLAN 1、内側にVLAN 20の2つのタグを付けて送る
  3. SW1は外側のタグ（ネイティブVLAN）を外し、タグなしの扱いでトランクへ出す
  4. SW2は残った内側のタグを見て、VLAN 20に届けてしまう
対策：ネイティブVLANを端末に使わない番号にする／端末用ポートは switchport mode access にしてDTPを止める（DTPでトランクを結ばれる「スイッチスプーフィング」も防ぐ）。
出典：Configuring VLAN Trunks Prerequisites ／ Cisco Best Practices for Catalyst 6500/4500（802.1Q Operational Overview：ネイティブVLANの暗黙のタグとセキュリティ、使わない番号にする対策）。手順の図はClaudeが整理

DTP：トランクにするかを隣と交渉する。モードは5つ

モード（コマンド）動きDTPを送るトランクになる相手
switchport mode access常に非トランク。相手が何でもアクセス送らない（変更時の通知だけ）なし
dynamic auto待つだけ。持ちかけられたら応じる。Catalystの初期値送るtrunk・desirable
dynamic desirable自分から持ちかける送るtrunk・desirable・auto
switchport mode trunk常にトランク。相手にも持ちかける送る（自分は常にトランク）
trunk＋nonegotiate常にトランク。DTPを止める。相手も手で trunk にする送らない（相手も trunk が必要）
DTPの条件：Cisco独自。交渉には両方のVTPドメイン名が一致している必要がある。nonegotiate は access か trunk のときだけ使える（dynamic ではエラー）。
勧められる使い方：DTPを話さない機器（他社のスイッチなど）とは、トランクなら trunk＋nonegotiate、トランクにしないなら access に固定する。
出典：Configuring VLAN Trunks Layer 2 Interface Modes ／ Command Reference「switchport mode」「switchport nonegotiate」 ／ Best Practices for Catalyst 6500/4500（DTP Frames Transmitted?）

組み合わせ表：トランクにならないのは「auto どうし」と「access がいる」とき

自分＼相手accessdynamic autodynamic desirabletrunk
accessアクセスアクセスアクセス不一致
dynamic autoアクセスアクセストランクトランク
dynamic desirableアクセストランクトランクトランク
trunk不一致トランクトランクトランク
不一致＝片方だけがトランクとして動く。通信できないVLANが出る
考え方「誰か1人でも持ちかける（desirable か trunk）」かつ「誰も拒否しない（access がいない）」ならトランク。
  1. 初期設定のスイッチどうし＝auto＋auto → アクセス（よく出る）
  2. trunk＋auto → トランク（trunk はDTPで持ちかける）
  3. trunk＋nonegotiate＋相手 auto → 相手はDTPを受け取れずアクセス → 不一致
  4. DTPで交渉した結果は、必ず両側で同じになる
出典：Configuring VLAN Trunks Layer 2 Interface Modes（各モードがどの相手でトランクになるか）。表はその記述からClaudeが組み合わせた

トランクの設定と、許可VLANリストの「置き換え」の罠

設定の例
SW1(config)# interface g1/0/24
SW1(config-if)# switchport trunk encapsulation dot1q  ! 古い機種だけ
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk native vlan 99
SW1(config-if)# switchport trunk allowed vlan 10,20,99
SW1(config-if)# switchport nonegotiate          ! 必要なら
allowed vlan の書き方意味
10,20（番号だけ）一覧を置き換える
add 30今の一覧に足す
remove 2今の一覧から外す
except 100-200指定以外の全部
all ／ none全部（初期値）／空
例題許可リストが 10,20,30 のトランクに、VLAN 40も通したい。
入れたコマンド結果の一覧
allowed vlan 4040 だけ（10・20・30が止まる）
allowed vlan add 4010,20,30,40（正しい）
allowed vlan except 4040以外の全部（逆）
本番でも実務でも：add の付け忘れで、動いていたVLANを止めてしまうミスが多い。コマンドリファレンスの説明「add adds … instead of replacing the list」が根拠。
出典：Cisco Command Reference 17.9.x「switchport trunk」 Usage Guidelines ／ Configuring VLAN Trunks Defining the Allowed VLANs on a Trunk

show interfaces trunk は4つのかたまりを上から読む

SW1# show interfaces trunk

Port      Mode   Encapsulation  Status    Native vlan
Gi1/0/24  on     802.1q         trunking  99

Port      Vlans allowed on trunk
Gi1/0/24  10,20,30,99

Port      Vlans allowed and active in management domain
Gi1/0/24  10,20,99

Port      Vlans in spanning tree forwarding state and not pruned
Gi1/0/24  10,20,99
  1. Mode・Status・Native vlan：on＝mode trunk（desirable／auto なら交渉で上がった）。ネイティブVLANは両側で比べる
  2. Vlans allowed on trunk：許可リスト。allowed vlan の設定そのもの
  3. allowed and active：許可されていて、このスイッチに存在するVLAN。VLAN 30はここにない → スイッチにVLAN 30がない
  4. forwarding state and not pruned：STPで転送中で、プルーニングもされていないVLAN。ここにあるVLANだけが実際に流れる
つながらないときの切り分け：②にない→許可リストの問題／③にない→VLANを作っていない／④にない→STPでブロックかプルーニング。
出典：Cisco Command Reference 17.9.x「show interfaces」（trunk の出力例）／ Configuring VLAN Trunks（A trunk port can become a member of a VLAN if the VLAN is enabled … and in the allowed list）

第3章

VLAN間ルーティング

VLANが違えばサブネットも違う。間をつなぐのはルータのサブインタフェースか、レイヤ3スイッチのSVI。

CCNA #07 VLANとトランク2.1.c

VLAN間ルーティングは3つの方法。いまの主流はSVI

① VLANごとに物理ポート
ルータのポートとケーブルがVLANの数だけ要る。わかりやすいが広げられない
② ルータオンアスティック
サブインタフェース＋encapsulation dot1Q。ケーブル1本で済むが、VLAN間の通信が全部そのリンクを往復する
③ SVI（レイヤ3スイッチ）
interface vlan 10 にIPアドレス。スイッチの中でハードウェアで中継するので速い
どの方法でも：端末のデフォルトゲートウェイ＝自分のVLANを受け持つサブインタフェースかSVIのアドレス。VLAN 10の端末に VLAN 20 側のアドレスを入れると、VLANの外へ出られない。
出典：Configuring Layer 3 Subinterfaces ／ IP Routing Configuration Guide 17.9.x「Configuring IP Unicast Routing」（SVI・routed port）

ルータオンアスティック：サブインタフェースにVLANを1つずつ受け持たせる

ルータ R1
R1(config)# interface g0/0
R1(config-if)# no shutdown          ! 親の物理ポート
R1(config)# interface g0/0.10
R1(config-subif)# encapsulation dot1Q 10
R1(config-subif)# ip address 192.168.10.1 255.255.255.0
R1(config)# interface g0/0.20
R1(config-subif)# encapsulation dot1Q 20
R1(config-subif)# ip address 192.168.20.1 255.255.255.0
R1(config)# interface g0/0.99
R1(config-subif)# encapsulation dot1Q 99 native
スイッチ SW1（R1につなぐポート）
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk native vlan 99
  • .10 の番号は名前だけ。どのVLANかを決めるのは encapsulation dot1Q 10（番号をそろえるのは読みやすさのため）
  • サブインタフェースどうしは別のサブネットにする（構成ガイド）
  • ネイティブVLANを受け持つときは native を必ず付ける。付けないとタグなしのフレームを受け取れない
  • ルータのサブインタフェースに switchport 系のコマンドはない。switchport はスイッチ側
  • 物理ポート（g0/0）を shutdown するとサブインタフェースも全部止まる。サブインタフェースだけを止めるなら、そのサブインタフェースで shutdown
確認show ip interface brief でサブインタフェースが up/up か、show interfaces trunk（SW1側）で許可VLANに10・20があるかを見る。
出典：Cisco VLAN Configuration Guide 17.9.x「Configuring Layer 3 Subinterfaces」（Restrictions：native キーワード、Information About：別のサブネット、encapsulation dot1q vlan-id [native]）

SVI と ip routing：レイヤ3スイッチの中でVLAN間を中継する

L3SW(config)# ip routing                 ! 初期値は無効
L3SW(config)# vlan 10
L3SW(config)# vlan 20
L3SW(config)# interface vlan 10
L3SW(config-if)# ip address 192.168.10.1 255.255.255.0
L3SW(config-if)# no shutdown
L3SW(config)# interface vlan 20
L3SW(config-if)# ip address 192.168.20.1 255.255.255.0
L3SW(config-if)# no shutdown
L3SW(config)# interface g1/0/24          ! 上位ルータ向け
L3SW(config-if)# no switchport
L3SW(config-if)# ip address 10.0.0.1 255.255.255.252
つまずきどころ理由
SVIにIPを付けたのにVLAN間で届かないip routing がない。Catalystのレイヤ3スイッチでは IP routing の初期値は Disabled
SVIが up にならないそのVLANにupしているポートがない（「物理ポートと結び付くまで active にならない」）。VLAN自体がない場合も
1つのVLANにSVIを2つできない。SVIはVLANに1つ
interface vlan 1 を消したいVLAN 1のSVIは最初からあり、削除できない
ルーテッドポートno switchport でL3にした物理ポート。VLANに属さない
SVIとルーテッドポート：SVI＝「VLANの代表のL3インタフェース」、ルーテッドポート＝「そのポートだけのL3インタフェース」。
出典：IP Routing Configuration Guide 17.9.x「Configuring IP Unicast Routing」（By default, IP routing is disabled）／ Interface and Hardware Components Configuration Guide「Configuring Interface Characteristics」（Switch Virtual Interfaces）

「VLAN間で通信できない」ときに確かめる順番

  1. 端末：IPアドレス・マスク・デフォルトゲートウェイが自分のVLANのサブネットか（ipconfig）
  2. アクセスポート：正しいVLANに入っているか（show vlan brief）。VLANを消していないか
  3. トランク：トランクになっているか、許可リストとネイティブVLANは正しいか（show interfaces trunk）
  4. VLANの存在：途中のスイッチ全部にVLANがあるか（③のかたまり）
  5. ルーティング：サブインタフェースの encapsulation の番号、SVIの up/up、ip routing
症状から逆引き
症状まず疑うところ
同じVLAN内も、別のスイッチだと届かないトランク（auto＋auto、許可リスト、VLANがない）
同じVLAN内は届く。別のVLANだけ届かないデフォルトゲートウェイ、ip routing、encapsulation の番号
1台だけ別のVLANの通信が混ざるネイティブVLANの不一致
設定を足したら他のVLANが止まったallowed vlan の add の付け忘れ
ポートがどのVLANにも出てこないトランクになっている（show vlan brief に出ない）、または削除したVLANのまま inactive
