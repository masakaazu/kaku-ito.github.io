偽の DHCP サーバーと信頼ポート

信頼ポート信頼しないポート
つなぐもの本物のサーバー・上流利用者の端末
既定―すべてのポート
サーバーのメッセージ通す捨てる
表への記録しないする
偽の DHCP サーバーはうその既定ゲートウェイや DNS を配って通信を横取りする。DHCP スヌーピングは、信頼しないポートに来た DHCPOFFER・DHCPACK・DHCPNAK を捨てて防ぐ。
落とし穴：上流（サーバー側）を trust にし忘れると、本物の応答まで捨てられて誰もアドレスをもらえない。
出典：IP Addressing Services CG 17.9（9300）「Configuring DHCP」（DHCP snooping acts like a firewall between untrusted hosts and DHCP servers／By default, the switch considers all interfaces untrusted／all DHCP servers must be connected to the switch through trusted interfaces）／Cisco Doc 217055（This prevents a rogue DHCP server …）

何を捨て、何を記録するか

送信元 MAC ≠ クライアントのハードウェアアドレス（chaddr）MAC を変えた大量の要求（DoS）
表とちがうポートから来た RELEASE・DECLINE他人のアドレスを勝手に返す
giaddr が 0.0.0.0 でない／オプション 82 付き端末がリレーを装う
MAC の照合は既定で有効。オプション 82 は、スイッチが「どのポートから来たか」を書き足す欄。

DAI と IP ソースガード

バインディングテーブルと比べて、なりすましの ARP と IP を止める。

CCNA #23 レイヤ2と無線のセキュリティ5.7

ARP スプーフィング（ARP キャッシュポイズニング）

なぜ成り立つか
ARP は頼んでいない応答（gratuitous ARP）でも受け取って ARP キャッシュを書き換える。攻撃者がうその応答を流すと、ほかの機器はその IP の宛先 MAC を攻撃者のものと覚えてしまう。
DAI の考え方
  1. 信頼しないポートの ARP（要求と応答）をすべて受け止める
  2. 送信者の IP と MAC の組をバインディングテーブルと比べる
  3. 合えば転送、合わなければ捨ててログに残す
攻撃は同じブロードキャストドメイン（VLAN）の中で起きる。
出典：Security CG 17.9（9300）「Dynamic ARP Inspection」（ARP allows a gratuitous reply from a host even if an ARP request was not received …／Figure 1. ARP Cache Poisoning（Host C … broadcasting forged ARP responses with bindings for a host with an IP address of IA (or IB) and a MAC address of MC）／It intercepts, logs, and discards ARP packets with invalid IP-to-MAC address bindings）。図は Cisco の図をもとに Claude が書き直した

DAI の設定と既定値

ip dhcp snooping
ip dhcp snooping vlan 10
ip arp inspection vlan 10                ! VLAN ごとに有効
ip arp inspection validate src-mac dst-mac ip
!
interface g1/0/1                         ! 隣のスイッチ
 ip arp inspection trust
!
arp access-list SRV                      ! 固定 IP の機器
 permit ip host 10.2.2.2 mac host 0018.bad8.3fbd
ip arp inspection filter SRV vlan 10
ARP ACL はバインディングテーブルより先に調べられる。ACL で deny なら、表に正しい組があっても捨てる。
項目既定
DAIどの VLAN でも無効
ポートの信頼すべて信頼しない
レート制限信頼しない 15 pps／信頼は制限なし。超えたら err-disabled
validate追加のチェックなし
validate の3つ
src-macヘッダーの送信元 MAC ＝ ARP の送信者 MAC か
dst-mac（応答）ヘッダーの宛先 MAC ＝ ARP のターゲット MAC か
ip0.0.0.0・255.255.255.255・マルチキャストを捨てる
出典：Security CG 17.9（9300）「Dynamic ARP Inspection」（Default Dynamic ARP Inspection Configuration／ip arp inspection validate {[src-mac] [dst-mac] [ip]}／permit ip host 10.2.2.2 mac host 0018.bad8.3fbd／ARP ACLs take precedence over entries in the DHCP snooping binding database）

ポートセキュリティ

このポートで使ってよい MAC アドレスを決める。

CCNA #23 レイヤ2と無線のセキュリティ5.7

ポートセキュリティの設定

interface g1/0/1
 switchport mode access                 ! 先に固定する
 switchport port-security               ! 有効にする
 switchport port-security maximum 2
 switchport port-security violation restrict
 switchport port-security mac-address sticky
 switchport port-security aging time 120
 switchport port-security aging type inactivity
既定値
ポートセキュリティ無効
最大数1
違反モードshutdown
スティッキー学習・エージング無効
セキュア MAC アドレスの3種類
種類覚え方running-config再起動後
静的手で書く入る保存すれば残る
動的自動入らない消える
スティッキー自動（手でも可）入る保存すれば残る
前提：既定の dynamic auto のポートには設定できない（アクセスかトランクに固定）。EtherChannel のポートでは使えない。
IP 電話の先に PC をつなぐポートは最大数 2（電話1・PC1）。
出典：Security CG 17.9（9300）「Port Security」（Types of Secure MAC Addresses／Default Port Security Configuration／an interface in the default mode (dynamic auto) cannot be configured as a secure port／Port Security is not supported on EtherChanel interfaces／set the maximum allowed secure addresses on the port to two／The sticky secure MAC addresses do not automatically become part of the configuration file）

違反モードと err-disabled

違反になるとき
  1. 最大数まで覚えたあと、知らない MAC の機器が来た
  2. あるセキュアポートで覚えた MAC が、同じ VLAN の別のセキュアポートに現れた
モード知らない送信元知らせるカウンターポート
protect捨てる××動く
restrict捨てるsyslog・トラップ○動く
shutdown全部止まる―○err-disabled
shutdown vlanその VLAN が止まる―○VLAN だけ
err-disabled からの戻し方
interface g1/0/1
 shutdown
 no shutdown                ! 手で戻す
!
errdisable recovery cause psecure-violation  ! 自動で戻す
原因自動復旧の cause
ポートセキュリティの違反psecure-violation
DHCP のレート超えdhcp-rate-limit
見分け方：気づけないのは protect。知らせるがポートを止めないのは restrict。止めるのが shutdown（既定）。
確かめる：show port-security interface g1/0/1（最大数・今の数・違反の回数・違反モード）
出典：Security CG 17.9（9300）「Port Security」（Security Violations／Security Violation Mode Actions の表／errdisable recovery cause psecure-violation … or … shutdown and no shut down／Monitoring Port Security）／Catalyst 4500 CG IOS XE 3.11.0E（errdisable recovery cause dhcp-rate-limit）。「知らせる」の列の「―」は、Cisco の表と手順の説明で書き方が分かれているので空けた
第4章

WPA2 PSK の無線 LAN

Catalyst 9800 の GUI で作る（無線のしくみは #10）。

CCNA #23 レイヤ2と無線のセキュリティ5.9・5.10

9800 の GUI で WPA2 PSK の WLAN を作る

  1. Configuration > Tags & Profiles > WLANs で Add
  2. General タブ：Profile Name・SSID・WLAN ID を入れ、Status を有効にする
  3. Security > Layer2 タブ：Layer 2 Security Mode ＝ WPA + WPA2、WPA2 Policy にチェック、暗号は AES
  4. 同じタブの認証キーの管理（AKM）：802.1X を外し、PSK にチェック。PSK Format（ASCII／Hex）と鍵を入れる
  5. Apply to Device で反映（端末に出すには、ポリシータグで AP に付ける：#10）
落とし穴：WPA・WPA2 の既定の AKM は 802.1X。PSK に変え忘れると RADIUS を探しに行き、鍵を入れてもつながらない。
同じ設定を CLI で（Cisco の例をもとに）
wlan SHOP 1 SHOP
 no security wpa akm dot1x
 security wpa wpa2
 security wpa wpa2 ciphers aes
 security wpa akm psk
 security wpa psk set-key ascii 0 Cisco123
 no shutdown
項目決まり
鍵（ASCII）8〜63 文字（% は避ける）
鍵（Hex）64 けた
SSID32 文字まで
鍵の使われ方端末との間の PMK になる
出典：Catalyst 9800 CG 17.9「WLAN Security」（click Security > Layer2. From Layer 2 Security Mode drop-down menu, select WPA + WPA2／By default, both WPA1 and WPA2 use the 802.1X for authenticated key management／This key is used as the Pairwise Master Key (PMK)／WPA preshared keys must contain 8 to 63 ASCII text characters or 64 hexadecimal characters）／同「WLANs」（Configuration > Tags & Profiles > WLANs page, click Add／A valid SSID can be up to 32 characters）／同「WPA3」（no security wpa akm dot1x／security wpa wpa2 ciphers aes／security wpa psk set-key ascii 0 Cisco123）。CLI の並びは Claude が WPA2 PSK だけに組み直した

WPA・WPA2・WPA3 をおさらいくわしくは #10 無線LAN

暗号化（既定）個人向け（Personal）会社向け（Enterprise）9800 の Layer 2 Security Mode
WPATKIP（古い）PSK802.1XWPA + WPA2 の中の WPA Policy
WPA2AES-CCMPPSK802.1X（RADIUS）WPA + WPA2 の中の WPA2 Policy

WPA2 Personal と Enterprise：Personal（PSK）は全員で同じ鍵を使い、利用者を区別できない。Enterprise（802.1X）は利用者ごとに RADIUS で認証する。会社では Enterprise。
WPA3 の決まり：WPA3 では PMF（管理フレームの保護）が必須。WPA2 と WPA3 を同じ WLAN で出す（SAE と PSK を両方）ときは PMF は任意だが、無効にはできない。

よくあるひっかけ

よくある思い込み正しくは
DHCP スヌーピングでは端末のポートを trust にするtrust にするのはサーバー側・上流。端末は既定の信頼しないまま
ip dhcp snooping だけで働くip dhcp snooping vlan も要る
DAI は MAC アドレステーブルと比べるDHCP スヌーピングのバインディングテーブル（固定 IP は ARP ACL）
DAI のレート制限の既定は制限なし信頼しないポートは 15 pps。信頼ポートが制限なし
ポートセキュリティの違反モードの既定は restrict既定は shutdown（最大数は 1）
protect でも違反カウンターは増えるprotect は何も知らせず、カウンターも増えない
スティッキーは自動で startup-config に残るrunning-config だけ。保存しないと再起動で消える
err-disabled は時間がたてば自動で戻る自動復旧は既定で無効。shutdown → no shutdown か errdisable recovery
WPA2 の WLAN は作れば PSK になる既定の AKM は 802.1X。PSK に変える

まとめ

DHCP スヌーピング全体＋VLAN で有効。サーバー側だけ trust。信頼しないポートでサーバーのメッセージを捨て、バインディングテーブルを作る。レート超えで err-disabled
DAI と IP ソースガード表（固定 IP は ARP ACL）と比べてなりすましを捨てる。DAI は VLAN ごと、信頼しないポートは 15 pps
ポートセキュリティアクセスかトランクに固定して有効に。既定は最大数 1・shutdown。protect／restrict／shutdown、スティッキー、エージング
WPA2 PSK の WLANWLANs > Add → General → Security > Layer2（WPA + WPA2・WPA2 Policy・AES・PSK）→ Apply to Device
