第1章

暗号方式と鍵交換

速さの共通鍵、配りやすさの公開鍵。

支援士 #15 暗号技術25-7

ハイブリッド暗号のしくみ

① 送信者が使い捨ての共通鍵 K を作る
→
② データ本体を K で暗号化速い（AES-GCM）
→
③ K を受信者の公開鍵で暗号化遅いが短い
→
④ 受信者は秘密鍵で K を取り出し、本体を復号
共通鍵暗号公開鍵暗号
鍵同じ鍵公開鍵と秘密鍵
n 人の鍵の数n(n-1)/22n（1人1組）
速さ速い遅い
安全性の根拠総当たりの計算量素因数分解・離散対数
RSA：素因数分解。2048 ビット以上。
楕円曲線：短い鍵で同じ強さ。署名の ECDSA は署名ごとの乱数が漏れる・使い回すと秘密鍵が計算される。
出典：IPA「支援士試験 シラバス（案）」用語例〔暗号方式の種類〕／CRYPTREC 暗号リスト

鍵交換と前方秘匿性（R4秋 問8）

Diffie-Hellman 鍵交換
A：秘密 ag^a を送る
⇄
B：秘密 bg^b を送る
両者とも g^ab を計算できる。盗聴者は g^a と g^b からは求められない（離散対数問題）。
相手を認証しない → 中間者攻撃。TLS は証明書と署名で確かめる。
鍵の決め方サーバ秘密鍵の漏えい後
RSA で共通鍵を送る過去の通信も解読される
使い捨ての DHE・ECDHE過去は解読されない＝PFS
TLS 1.3 は ECDHE などだけ → 常に前方秘匿性。
R4秋 問8 の誤りの選択肢：チェーンで共有＝ブロックチェーン、片方の鍵で暗号化＝公開鍵暗号、ハッシュから推測できない＝一方向性。
出典：IPA 午前Ⅱ 令和4年度秋期 問8／RFC 8446 TLS 1.3

第2章

ハッシュ関数と共通鍵暗号

3つの「困難性」と、ブロックのつなぎ方。

支援士 #15 暗号技術25-7

ハッシュ関数の3つの性質（H31春・R3春・R5春）

性質与えられるもの → 探すものSHA-256 での目安
原像計算困難性
（一方向性）		ハッシュ値 h → h になる元のメッセージ2 の 256 乗
第二原像発見困難性メッセージ M → M と同じハッシュ値の別の M'2 の 256 乗
衝突発見困難性何もなし → ハッシュ値が一致する二つのメッセージ2 の 128 乗（誕生日攻撃）
過去問の誤りの選択肢：「256 の 2 乗」（数が小さすぎ）、「元のメッセージの発見に 2 の 256 乗」（原像の話）、「ハッシュ値が与えられたとき」（原像の説明）。
危殆化：MD5（2004年 衝突）、SHA-1（2017年 SHAttered）。
SHA-512/256（R7春）：SHA-512 を1回 → 256 ビットに切り詰め。SHA-3 はスポンジ構造の別系統。
出典：IPA 午前Ⅱ 令和5年度春期 問4・令和7年度春期 問3／NIST FIPS 180-4・FIPS 202

AES と暗号利用モード（R3春 問7・R5春 問7）

AES：ブロック長 128 ビット固定、鍵長は 128・192・256 から選ぶ。
CBC と CTR
CBC：C_i ＝ E(P_i ⊕ C_(i-1))暗号化は順番に、復号は並列に
CTR：C_i ＝ P_i ⊕ E(カウンタ＋i)暗号化も復号も鍵ストリームとの XOR
性質CBCCTR
暗号化の並列できないできる
復号の並列できるできる
パディング要る不要
1ビットの誤りブロック全体＋次の1ビットその1ビット
R5春 問7 の誤りの選択肢ウ・エは CBC の性質。ECB は同じ平文→同じ暗号文で使わない。
出典：NIST FIPS 197（AES）・SP 800-38A（Modes of Operation）／IPA 午前Ⅱ 令和3年度春期 問7・令和5年度春期 問7

ストリーム暗号・認証付き暗号・軽量暗号

種類しくみ例
ストリーム暗号鍵ストリームと平文を少しずつ XOR。同じ鍵ストリームの再利用は厳禁KCipher-2（電子政府推奨暗号）、ChaCha20
認証付き暗号 AEAD暗号化＋改ざん検出を一度に。関連データ（ヘッダ）も守るAES-GCM・AES-CCM・ChaCha20-Poly1305
軽量暗号回路規模・電力を小さく。IoT のセンサー向けAscon（NIST が 2023年に選定）
日本のブロック暗号 Camellia（NTT・三菱電機）も電子政府推奨暗号。
「軽量」は安全性を下げてよいという意味ではない。
出典：CRYPTREC 暗号リスト／IPA「支援士試験 シラバス（案）」用語例〔共通鍵暗号〕／NIST Lightweight Cryptography Project

「量子」の付く言葉を区別する

言葉正体過去問の正解の言い方
PQC 耐量子計算機暗号従来のコンピュータで動き、量子コンピュータの攻撃にも耐える暗号（格子など）。NIST FIPS 203〜205（2024年）量子コンピュータを使った攻撃に対しても安全（R3秋・R6秋・R7秋）
量子暗号（QKD）量子通信路で乱数を共有し、使い捨ての鍵に。盗聴すると気付ける原理的に第三者に解読されない（R4春・R6秋）
Shor のアルゴリズム量子コンピュータで素因数分解・離散対数を解くPQC の誤りの選択肢
ワンタイムパッド平文と同じ長さの真の乱数の鍵を一度だけ情報理論的安全性（R7秋 問9）
RSA・DH・楕円曲線は「計算量的安全性」。今の通信を記録して将来解読する Harvest Now, Decrypt Later に備えて PQC へ移行する。
出典：NIST FIPS 203・204・205（2024）／IPA 午前Ⅱ 令和7年度秋期 問3・問9、令和6年度秋期 問5・問9

まとめ：本番での問われ方

方式：本体は共通鍵、鍵の配送は公開鍵（ハイブリッド）。DH は認証しない → 中間者。
前方秘匿性：使い捨ての DH 鍵 → 秘密鍵が後で漏れても過去は解読されない。
ハッシュ：衝突＝一致する二つを探す（2 の n/2 乗）、原像＝ハッシュ値から元を、第二原像＝決まった M と同じ値の別の M'。
AES：鍵 128・192・256。CTR：鍵ストリームと XOR、並列・パディング不要。CBC：暗号化は直列。
量子：PQC＝従来機で動く耐性のある暗号、量子暗号＝量子通信路で鍵を共有、ワンタイムパッド＝情報理論的安全性。
ブロックチェーン：必須はハッシュ関数（改ざん検出）。
