見出しの行：is subnetted と is variably subnetted

      172.16.0.0/24 is subnetted, 2 subnets
O        172.16.1.0 [110/2] via 10.1.12.2, ...
O        172.16.2.0 [110/2] via 10.1.12.2, ...

C        10.1.12.0/24 is directly connected, Gi0/1
L        10.1.12.1/32 is directly connected, Gi0/1
S        10.2.0.0/16 [1/0] via 10.1.12.2
見出しから分かること
見出し意味
/24 is subnetted, 2 subnets下に経路が2本。マスクは全部 /24（行には /24 を書かない）
variably subnetted, 3 subnets, 3 masks下に経路が3本。マスクは3種類（/24・/32・/16）なので、各行に /nn が付く
読み方の手順
  1. コードの付いていない字下げの浅い行は見出し。経路として数えない
  2. subnets の数＝下に並ぶ経路の本数
  3. subnetted（マスク1種類）なら、各行のマスクは見出しのマスク
  4. variably subnetted なら、各行に /nn が書かれる
ひっかけ：「10.0.0.0/8 への経路がある」と読むのは誤り。見出しの /8 はクラスAのまとまりを示すだけで、10.0.0.0/8 宛ての経路は入っていない。
出典：show ip route（10.89.0.0 is subnetted (mask is 255.255.255.0), 3 subnets の例）／ Route Selection in Cisco Routers（172.30.0.0/16 is variably subnetted, 2 subnets, 2 masks の例）

ネクストホップと出口：再帰検索で「どこから出すか」を決める

ネクストホップ（via の後ろ）
次に渡す隣のルーターのアドレス。ふつうは自分の C のネットワークの中にある
出口のインタフェース（行の最後）
パケットを出す自分のインタフェース。ダイナミックルートでは両方が表示される
再帰検索
ネクストホップだけの経路は、そのアドレスへ行く経路をもう一度引いて出口を決める
確かめ方：show ip route 10.2.5.9 のように宛先を付けると、その宛先に使われる経路の詳しい情報が出る。
出典：What Is Administrative Distance?（ネクストホップに届かない経路はテーブルに入らない旨）／ show ip route（ip-address を付けた表示）。図はClaudeが作った例

経路の選び方

入れるときは AD とメトリック、送るときは最長一致。2つの段階を混ぜないのがコツ。

段階比べる相手使う値この例では
① 入れる同じ宛先・同じ長さの経路プロトコルが違う → AD が小さいほう／同じプロトコル → メトリックが小さいほう/24 は EIGRP（90）が OSPF（110）に勝つ
② 送る宛先に当てはまる全部の経路プレフィックスの長さだけ。AD もメトリックも見ない宛先 10.1.30.7 は /24 の D で送る（/16 の S ではない）
いちばんのわな：/16 と /24 は「違う宛先」なので、AD で比べられることはない。両方テーブルに入り、送るときに長いほうが使われる。
出典：Route Selection in Cisco Routers（routing protocols・routing table・forwarding decisions の3つのプロセス／prefix length が違えば別の宛先として全部入る）

AD の初期値：小さいほど信用する

覚える4つ（本番によく出る）
出どころAD
EIGRP（内部）90
OSPF110
RIP120
スタティック1
並び：EIGRP 90 → OSPF 110 → RIP 120。同じ宛先を3つとも覚えたら、テーブルに入るのは EIGRP の経路。
255：「信用しない」。この AD の経路はテーブルに入らない。予備にしたいときは 255 ではなく、本物より少し大きい値にする。
性質AD はそのルーターの中だけの値。ほかのルーターには伝わらない
出典：What Is Administrative Distance?（Default Distance Value Table：0/1/5/20/90/110/115/120/170/200/255・255 は信用しないためテーブルに入らない）。棒の長さは AD の値に比例

AD による選択：同じ宛先を2つのプロトコルから覚えたら

  1. 宛先とプレフィックスの長さが同じかを確かめる（違えば比べない）
  2. プロトコルが違えば AD が小さいほうを入れる
  3. 入らなかった経路は捨てられず、入った経路が消えると代わりに入る
この性質を使う：フローティングスタティック
ip route 10.1.30.0 255.255.255.0 10.1.99.2 115
OSPF（110）が生きている間は OSPF の経路が入り、OSPF が消えたら AD 115 のスタティックが入る。本物より大きく 255 より小さい値にする（設定は #13）。
出典：What Is Administrative Distance?（EIGRP 90 と OSPF 110 の例・floating static routes）／ Route Selection in Cisco Routers（Backup Routes）

メトリック：同じプロトコルの中で、道の良さを比べる

上の道下の道選ぶ道
RIP（ホップ数）23上（遅い）
OSPF（コスト）10＋10＝201＋1＋1＝3下（速い）
プロトコルメトリック特徴
RIPホップ数（通るルーターの数）速さを見ない。16 は「届かない」
OSPFコストの合計。コスト＝基準の帯域÷インタフェースの帯域基準の初期値は 100 Mbps
EIGRP道のいちばん細い帯域と、遅延の合計から計算初期の K 値は 1,0,1,0,0（帯域と遅延だけ使う）
比べられない：RIP の 2 と OSPF の 20 は単位が違う。プロトコルどうしは AD で比べる。
出典：RIP Configuration Guide（hop count・16 は unreachable）／ OSPF Configuration Guide（auto-cost reference-bandwidth）／ EIGRP Configuration Guide（metric weights 0 1 0 1 0 0）。図の数値はClaudeが作った例

ECMP：メトリックが同じなら、両方入れて分けて送る

O    10.1.30.0/24 [110/3] via 10.1.12.2, 00:01:10, Gi0/1
                  [110/3] via 10.1.13.3, 00:01:10, Gi0/2
  • 宛先の行の下に via の行が何行も並ぶ → ECMP
  • 2本とも AD もメトリックも同じ。片方でも違えば、小さいほう1本だけ
  • 何本まで入れるかは、プロトコルの設定 maximum-paths で変えられる
  • プロトコルが違う経路どうしは ECMP にならない（AD で1つに決まる）
語ECMP＝Equal-Cost Multi-Path（同じコストの複数の道）
出典：Route Selection in Cisco Routers（equal metrics なら load balancing）／ EIGRP Configuration Guide（maximum-paths）

計算手順：宛先がどの経路に当てはまるかを2進数で確かめる

宛先 192.168.32.100 と /26 の経路
第4オクテット
宛先 .10001100100
経路 .0 /2600000000
判定前の2ビット（25・26ビット目）が違う → 外
宛先 192.168.33.5 と /19 の経路
第3オクテット
宛先 3300100001
経路 32 /1900100000
判定前の3ビット（17〜19ビット目）が同じ → 当てはまる
  1. 経路のマスクが切れるオクテットを見つける（/26 なら第4、/19 なら第3）
  2. ブロックの大きさ＝256 −（そのオクテットのマスクの値）。/26 は 256−192＝64、/19 は 256−224＝32
  3. 経路の範囲＝ネットワークアドレスから「ブロック−1」まで。/26 は .0〜.63、/19 は 32〜63
  4. 宛先が範囲の中なら当てはまる。当てはまる中で一番長いものを選ぶ
  5. どれにも当てはまらなければデフォルトルート。それもなければ捨てる
2進数を書かなくてよい：本番は手順2〜3の「ブロックの大きさ」で範囲を出すと速い。

よくあるひっかけ

よくある思い込み正しくは
AD が小さい経路で必ず送るAD はテーブルに入れるときだけ。送るときは最長一致。長さが違えば AD は比べない
[110/3] の 3 が AD[ ] の左（110）が AD、右（3）がメトリック
RIP の 2 と OSPF の 20 なら RIP が良いメトリックは同じプロトコルの中だけで比べる。違うプロトコルは AD で決まる
「10.0.0.0/8 is variably subnetted」は経路見出しの行。経路は下に字下げされた行
via の後ろは最終の宛先次に渡す隣のルーター（ネクストホップ）
予備のスタティックは AD 255 にする255 はテーブルに入らない。本物より大きく 255 より小さい値にする
Gateway of last resort is not set でも届くデフォルトルートがないので、どの経路にも当てはまらない宛先は捨てる
EIGRP のコードは ED（外部は D EX）
