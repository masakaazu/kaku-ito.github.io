ブラウザが備える防御機構と指示

ヘッダと属性で、ブラウザに守らせる。

支援士 #17 セキュア開発とWebの防御26-1

cookie の属性（R1秋・R2・R3秋）

Set-Cookie: SID=4f9a...; Secure; HttpOnly; SameSite=Lax; Path=/; Max-Age=1800
属性動作防ぐもの
Secureスキームが https のときだけ送る。値はもたない平文の通信での盗聴
HttpOnlyJavaScript から読めないXSS での cookie 盗用
SameSite他サイト発の要求で送らない（Strict・Lax）CSRF
Path・Domain送るパス・ホストを決めるー
Expires・Max-Age有効期限。なければブラウザ終了で消えるー
過去問の誤りの選択肢：有効期間で無効化＝Expires、JavaScript の読出し禁止＝HttpOnly、パスのプレフィックス＝Path、「Secure=時間」「Secure=ホスト名」は存在しない書き方。
出典：RFC 6265 HTTP State Management Mechanism 4.1.2／IPA 午前Ⅱ 令和3年度秋期 問10・令和2年度 問12

同一オリジンポリシーと CORS

オリジン＝スキーム＋ホスト＋ポート
https://app.example.jp と比べて同一？
https://app.example.jp/x同一
http://app.example.jp別（スキーム）
https://api.example.jp別（ホスト）
https://app.example.jp:8443別（ポート）
CORS で読取りを許可する
Access-Control-Allow-Origin: https://app.example.jp Access-Control-Allow-Credentials: true
「*」や、要求の Origin をそのまま返すのは危険。認証情報つきでは「*」は使えない。
CORS は「読める相手」を広げる仕組み。CSRF の対策ではない。
出典：RFC 6454 The Web Origin Concept／WHATWG「Fetch Standard」CORS protocol

HSTS・CSP・SRI・Cache-Control

指示書き方の例効果
HSTSStrict-Transport-Security: max-age=31536000; includeSubDomains; preload以降の期間、全て HTTPS で接続（R3春・R4春・R6春）
CSPContent-Security-Policy: script-src 'self' 'nonce-r4nd0m'; frame-ancestors 'none'許可外のスクリプトを実行させない、枠表示を禁止
SRIscript src="https://cdn…/lib.js" integrity="sha384-…"改ざんされた外部ファイルを実行しない
no-storeCache-Control: no-storeどのキャッシュにも保存させない（R6春 問20）
HSTS の誤りの選択肢：他のオリジンにアクセスさせない＝同一オリジン、EV 証明書の表示、秘密情報を判定できない圧縮、再ハンドシェイク。
no-cache は「保存してよいが毎回確認」、private はブラウザだけ保存可。混同に注意。
出典：RFC 6797（HSTS）・RFC 9111（HTTP Caching）／W3C「CSP Level 3」「Subresource Integrity」／IPA 午前Ⅱ 令和6年度春期 問13・問20

まとめ：本番での問われ方

検査：SAST＝動かさずコード、DAST＝動かして外から、ファジング＝異常な入力を大量に。
根本対策：SQLi＝プレースホルダ、XSS＝出力時のエスケープ、CSRF＝トークン、BOF＝長さの確認、パスワード＝ソルト＋ストレッチング。
サプライチェーン：シークレットのハードコード禁止、署名付きコミット、成果物の署名、SLSA、要塞化。
cookie：Secure＝https のときだけ送る、HttpOnly＝JS から読めない、SameSite＝他サイト発では送らない。
HSTS：以降の指定期間、全て HTTPS で接続。no-store：どのキャッシュにも保存させない。
CSP＝実行してよいスクリプト、SRI＝外部ファイルのハッシュ、CORS＝読ませてよいオリジン。
