チームとワークスペースの権限

権限できること
Read実行・変数・ステートを読む
Plan＋ plan を始める（apply は承認が必要な人向け）
Write＋ apply、変数・ステートの読み書き、ロック（日々の構築）
Admin＋ 設定（run trigger など）・チームの権限・削除
custom で細かく選べる。ステートは「出力だけ読む」にも絞れる。
チーム組織の中のユーザーのグループ。権限は自分の組織のワークスペースだけ
ユーザー複数の組織の複数のチームに入れる
owners チーム組織の全権。削除も空にもできない
チームの API トークン：特定のユーザーに結びつかない。

ポリシーと強制レベル

Sentinel失敗したとき
advisory止めない（知らせるだけ）
soft mandatory止める。許された人は override で続行
hard mandatory直すまで apply しない（セットで許せば上書き可）
OPA（Rego）失敗したとき
advisory止めない
mandatory止める。Manage Policy Overrides の人は上書き可
ポリシーセット組織全体・プロジェクト・ワークスペースに付ける。1 つのセットに 1 つのフレームワーク
実行ごとに plan を照らすスペキュラティブプランとリモートの apply
ポリシーは VCS に置く（標準化・セキュリティ・監査）。
CLI 駆動の実行で結果が端末に出るのは Sentinel だけ。
出典：Policy enforcement overview／Manage policy sets／The CLI-driven remote run workflow
