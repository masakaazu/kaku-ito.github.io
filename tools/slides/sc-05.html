AI を悪用する攻撃と AI への攻撃

「いつ」（学習時か推論時か）と「何を」（判定・データ・モデル）で分ける。

支援士 #05 AI・サプライチェーン・特殊な攻撃23-2

AI への攻撃の地図：学習時か、推論時か

学習データ集めたデータ・公開モデル
→
学習モデルを作る
→
AI モデル公開 API・アプリ
→
推論入力 → 出力
時期攻撃何をする奪われるもの
学習時データポイズニング悪いデータを混ぜる。合図で誤らせるバックドアもモデルの正しさ
推論時敵対的サンプル人に分からないノイズで誤認識させる（回避攻撃）判定結果
推論時モデルインバージョン入力を変えて出力をくり返し調べる学習に使ったデータ
推論時メンバーシップ推測確信度の高さから推測学習に使われたか
推論時モデル窃取大量に問い合わせ、出力で真似たモデルを作るモデルそのもの
R7秋 問5：モデルインバージョン＝「学習に用いた元のデータを推測」。「模倣し同等のモデルを得る」はモデル窃取、「悪意あるデータを混入」はデータポイズニング。
出典：NIST AI 100-2 E2025「Adversarial Machine Learning」／MITRE ATLAS／IPA 午前Ⅱ 令和7年度秋期 問5

敵対的サンプル（Adversarial Examples）

元の画像AI：「一時停止」
＋
小さなノイズ人には見えない
＝
細工した画像AI：「速度制限」
人の目には同じでも、モデルの判定の境界のすぐ向こうに押し出す。学習データには手を出さない。
対策：敵対的サンプルも混ぜて学習する（敵対的学習）、入力の前処理、複数のモデルで判定。
R6秋 問2（R3秋 問1 とほぼ同じ）の選択肢
選択肢正体
Adaptively Chosen Message 攻撃署名の安全性評価のモデル
Adversarial Examples 攻撃正解
Distributed Reflection DoS 攻撃反射型 DDoS（#04）
Model Inversion 攻撃学習データの推測
頭文字の A どうしを並べるひっかけ。Adaptively は署名、Adversarial は AI。
出典：IPA 午前Ⅱ 令和6年度秋期 問2・令和3年度秋期 問1／NIST AI 100-2 E2025（Evasion attacks）。画像の例は Claude が単純化

依存関係混同とタイポスクワッティング

依存関係混同（Dependency Confusion）
社内リポジトリ acme-utils 1.2.0 公開リポジトリ acme-utils 99.0.0 ← 攻撃者が登録 ツール：「両方を探して新しい版を選ぶ」→ 99.0.0 を取得
対策
社内パッケージの取得先を固定する
名前空間（スコープ、例 @acme/utils）を使う
ロックファイルで版とハッシュを固定する
タイポスクワッティング
本物偽物の例
requestsreqeusts・request
example-bank.jpexamp1e-bank.jp
インストール時に動くスクリプトで認証情報を盗むことが多い。名前は似ている（依存関係混同は名前が同じ）。
対策：入れる前に名前・公開者・ダウンロード数を確認、社内で許可した部品だけを使う。
出典：IPA「支援士試験 シラバス（案）」用語例「依存関係混同（Dependency Confusion），タイポスクワッティング」。パッケージ名の例は Claude が作った

ビルド環境・CI/CD とメンテナを守る

ねらわれる点対策
CI が持つクラウドの認証情報・署名鍵権限の最小化、短期間だけ使える認証情報（OIDC 連携）
ビルドの途中での混入再現可能なビルド、来歴（provenance）の署名（SLSA）
CI が取り込む外部のスクリプト・アクションハッシュで版を固定、取り込む前の検証
メンテナのアカウントMFA、公開権限を複数人で
何が入っているか分からないSBOM（部品表）で把握（#17）
xz utils の教訓：攻撃は技術ではなく人の信頼から入った。疲れた1人のメンテナに「手伝う」と近づき、時間をかけて権限を得た。
見つかったきっかけは、別の開発者が気付いた SSH のログインが約0.5秒遅いという小さな異常だった。
出典：CISA「Defending Against Software Supply Chain Attacks」／SLSA（Supply-chain Levels for Software Artifacts）v1.0／Andres Freund の oss-security への投稿（2024-03-29）
第3章

サイドチャネルと特殊な攻撃

暗号は数学的に強くても、実装した装置から秘密が漏れる。

支援士 #05 AI・サプライチェーン・特殊な攻撃23-2

サイドチャネル攻撃：数学ではなく物理量で解く

分類手法サイドチャネル？
物理量を測る処理時間・消費電力・電磁波・音はい
数学的な解読線形解読法・差分解読法・選択平文攻撃いいえ
しらみつぶし総当たり（全ての鍵を試す）いいえ
人をのぞくショルダーハッキング・トラッシングいいえ
通信に割り込む中間者攻撃・不正なアクセスポイントいいえ
5年で5回出た定番。正解の言い回しは「暗号化処理時の消費電力などの測定や統計処理」「機器が発する電磁波を測定」「物理量（処理時間や消費電力など）やエラーメッセージ」。
R3春 問5 のひっかけ：「アクセスポイントを不正に設置し、チャネル間の干渉」は無線 LAN の妨害。
出典：IPA 午前Ⅱ 平成31年度春期 問7・令和元年度秋期 問2・令和2年度 問4・令和3年度春期 問5・令和4年度春期 問3

タイミング攻撃：途中で抜けると時間で分かる

// 危ない：違った文字ですぐ終わる for (i = 0; i < n; i++) if (a[i] != b[i]) return false; return true; // 安全：最後まで比べて時間を一定に diff = 0; for (i = 0; i < n; i++) diff |= a[i] ^ b[i]; return diff == 0;
先頭から合っている文字が多いほど時間が長い → 1文字ずつ当てられる。
R7春 問14（R5春 問11 と同じ）の選択肢
選択肢何の対策
処理時間に差異が出ないようにタイミング（正解）
コンデンサで電力消費を均一に電力解析
故障を検出したら秘密情報を破壊故障利用攻撃
保護層で書換えを防ぐプロービング・改ざん
出典：IPA 午前Ⅱ 令和7年度春期 問14・令和5年度春期 問11。比較のコードは Claude が作った（C 言語風の擬似コード）

耐タンパ性をおびやかす5つの攻撃

攻撃何をするか装置を壊すか対策
タイミング攻撃処理時間の差を測る壊さない処理時間を一定に
電力解析（SPA・DPA）消費電力の波形を測る・統計処理壊さない電力の均一化・マスキング
テンペスト漏れる電磁波を離れた所で受信壊さない電磁シールド
故障利用（フォールト）電圧・クロック・レーザで誤動作させ差を解析壊さない〜半分異常検出 → 秘密を消去
プロービングチップを開け、信号線に探針を当てる壊す（侵襲型）保護層・開封の検知
R3秋 問13：テンペスト＝「処理中に機器から放射される電磁波を観測」。ア 故意に誤動作＝故障利用、イ 処理時間の差＝タイミング、エ 探針＝プロービング。
出典：IPA 午前Ⅱ 令和3年度秋期 問13／IPA「IoT 開発 セキュリティ手引き」耐タンパ性。表は Claude がまとめた

隔離・機能・交渉を逆手にとる

エアギャップに対する攻撃
切り離しても、USB メモリ・保守用 PCが橋になる。Stuxnet（2010）は USB 経由で制御システムへ。電磁波・音・光で外へ出す研究もある。
機能の悪用
脆弱性ではなく正しい機能を使う。オープンリゾルバの悪用（#04）、正規の管理ツールでの活動（Living off the Land）。パッチでは防げない。
ダウングレード攻撃
交渉に介入して弱い版・弱い暗号を選ばせる。POODLE（2014、SSL 3.0）。TLS 1.3 はサーバの乱数の末尾に印を入れて格下げを検知。
バージョンロールバック攻撃
対策防げるか
署名の検証防げない（古い版も正規の署名）
HTTPS で配信防げない
版の番号のカウンタ（アンチロールバック）防げる
共通点：脆弱性そのものではなく、信頼・機能・互換性を利用する。だから設定と運用で防ぐ。
出典：IPA「支援士試験 シラバス（案）」用語例「エアギャップに対する攻撃」「サービス及びソフトウェアの機能の悪用」「ダウングレード攻撃（バージョンロールバック攻撃）」／RFC 8446 4.1.3

過去問の問われ方のまとめ

サイドチャネル：「物理量（時間・電力・電磁波）を測る」が正解。数学的解読・総当たり・のぞき見は不正解。
対策の取り違え：時間→一定に、電力→均一に、故障→検出して消去、探針→保護層。
AI：学習時か推論時か、何が奪われるか。英語名のまま出るので Adversarial・Inversion・Extraction・Poisoning を覚える。
新シラバスで増えた用語：プロンプトインジェクション（直接・間接）、ジェイルブレイク、メンバーシップ推測、モデル窃取、システムプロンプトの窃取、依存関係混同、タイポスクワッティング、OSS メンテナの乗っ取り、エアギャップ、ダウングレード。
守る側（AI のガードレール、SBOM、SLSA、セキュアブート）は #17・#18 で。
