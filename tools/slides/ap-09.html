9-1 データベース方式方式

関係データベースRelational Database
データを表（関係）で表すデータベース
ポイント行をタプル、列を属性、属性がとりうる値の集合をドメインという
3層スキーマThree-schema Architecture
外部・概念・内部の3つに分けて定義する構造
ポイントデータの独立性を高める
NoSQLのーえすきゅーえる / Not only SQL
表の形にとらわれないデータベース
ポイントキーバリュー・ドキュメント・列指向・グラフ型。整合性より拡張性を優先するBASE特性
Not only＝〜だけではない／SQL＝関係DBの言語
CAP定理CAP Theorem
分散データベースでは、一貫性・可用性・分断耐性の3つを同時にすべて満たすことはできないという定理
Consistency＝一貫性／Availability＝可用性／Partition tolerance＝分断耐性

9-2 データベース設計設計

E-R図Entity Relationship Diagram
実体と実体どうしの関連を表した図
ポイント1対多・多対多などのカーディナリティを表す。多対多は連関エンティティで分解する
主キー・外部キーPrimary / Foreign Key
主キーは行を1つに決める列、外部キーはほかの表の主キーを参照する列
ポイント外部キーで参照制約を守る
候補キーCandidate Key
行を1つに決められる最小の列の組合せ
ポイント主キーは候補キーから1つ選ぶ
正規化Normalization
重複をなくすように表を分けること
ポイント更新時の矛盾（更新時異状）を防ぐ
部分関数従属Partial Functional Dependency
複合主キーの一部の列だけで、ほかの列が決まる関係
ポイントなくすと第2正規形
推移的関数従属Transitive Functional Dependency
主キー → 非キー列 → 別の非キー列 と、間接的に決まる関係
ポイントなくすと第3正規形

9-3 データ操作関係演算とSQL

選択・射影・結合Selection / Projection / Join
選択は行を取り出す、射影は列を取り出す、結合は共通の列で表をつなぐ
和・差・積Union / Difference / Intersection
和は両方の行を合わせる、差は片方にだけある行、積は両方にある行
直積Cartesian Product
2つの表のすべての行の組合せ
ポイント行数は両方の行数の積
SELECT文SELECT Statement
表からデータを取り出すSQL
ポイント実行の順は FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
内部結合・外部結合Inner / Outer Join
内部結合は両方に一致する行だけ、外部結合は一致しない行もNULLで補って残す
副問合せSubquery
SQLの中に入れた別のSELECT文
ポイントIN・EXISTSと組み合わせる。外側の値を使うのが相関副問合せ

9-4 トランザクション処理同時実行と回復

ACID特性ACID Properties
トランザクションが守るべき4つの性質
Atomicity＝原子性／Consistency＝一貫性／Isolation＝独立性／Durability＝耐久性
排他制御Exclusive Control
同時の更新で矛盾が起きないよう、ロックをかける制御
ポイント共有ロックどうしは同時にかけられるが、専有ロックはほかと同時にかけられない
2相ロックTwo-phase Locking
ロックをかけていく段階と外していく段階に分け、外し始めたら新しくかけない方式
ポイント直列化可能性を保証する
隔離性水準Isolation Level
トランザクションをどれだけ独立させるかの段階
ポイントダーティリード・反復不能読取り・ファントムを防ぐ程度が違う
デッドロックDeadlock
トランザクションがお互いのロックの解除を待ち合う状態
ポイント待ちグラフで検出し、どちらかをロールバックする
ロールバック・ロールフォワードRollback / Rollforward
ロールバックは更新前ログで取り消すこと、ロールフォワードはバックアップに更新後ログを当て直すこと
