variable ブロックの引数

引数意味覚えどころ
type型の制約書かなければ any
default既定値なければ必須（plan の前に入力を求める）。リテラルだけ、参照不可
description使う人向けの説明保守のメモはコメントに
validationcondition・error_message計画を作るときに評価、false で止まる
sensitiveCLI の出力で隠す使った式も sensitive。ステートには残る
nullablenull を入れてよいか既定 true。false なら null 不可
ephemeralステート・プランに残さない#10
変数名に使えない：source・version・providers・count・for_each・lifecycle・depends_on・locals
出典：variable block reference

値の渡し方と優先順位

1. -var・-var-file（書いた順）・HCP Terraformいちばん強い
2. *.auto.tfvars・*.auto.tfvars.json名前の順
3. terraform.tfvars.json
4. terraform.tfvars
5. 環境変数 TF_VAR_name
6. defaultいちばん弱い
$ terraform apply -var="instance_type=t3.medium" $ terraform apply -var-file="prod.tfvars" # 自動では読まれない名前 $ export TF_VAR_environment=staging $ export TF_VAR_cfg='{"key": "value", "list": ["a", "b"]}'
自動で読まれる：terraform.tfvars・terraform.tfvars.json・*.auto.tfvars・*.auto.tfvars.json
子モジュールの変数は、親の module ブロックの引数で渡す。
秘密の値が入った tfvars は VCS に入れない。
出典：Use input variables to add module arguments（Assign values to variables）

output と terraform output

output の引数意味
value（必須）返す値。ステートに保存
description使う人向けの説明
sensitiveplan・apply で (sensitive value)
ephemeralステートに残さない（子モジュールの出力）
depends_on・precondition明示の依存・事前の条件
$ terraform output # 全部（sensitive は隠す） $ terraform output lb_address # 1 つ $ terraform output -json | jq # JSON $ terraform output -raw lb_address # 文字列そのまま（string・number・bool だけ）
-json・-raw では sensitive も平文で出る。
sensitive な属性を value に使うと、output にも sensitive = true が必要。
出典：output block reference／Command: output
第2章

型

同じ型の集まりか、ちがう型の組か。

Terraform #07 変数・出力と型目標 4c・4d

型の全体像

種類型特徴
プリミティブstring・number・boolnumber は整数も小数も。15 ⇔ "15"、true ⇔ "true" は自動変換
コレクションlist(T)0 からの番号。同じ型の要素
コレクションmap(T)文字列のキー。同じ型の値
コレクションset(T)順番もキーもなく、重複しない
構造object({k = T, …})名前付きの属性ごとに型。キーは全部必要（多い分は捨てる）
構造tuple([T, …])位置ごとに型。数はぴったり
動的any型ではなく置き場所。『very rarely the correct type constraint』
list・map だけ書くと list(any)・map(any)。新しいコードは完全な形で。
出典：Type Constraints

型の変換と optional

渡した値 → 型結果
["a", 15, true] → list(string)["a", "15", "true"]
["b", "a", "b"] → set(string)重複が消え、順番もなくなる
["a", 1, "b"] → list(any)list(string)：["a", "1", "b"]
["a", [], "b"] → list(any)エラー（そろう型がない）
{name = [...], age = 12} → map(string)エラー（リストは文字列にならない）
variable "with_optional_attribute" { type = object({ a = string # 必須 b = optional(string) # 省くと null c = optional(number, 127) # 省くと 127 }) }
null でない既定値は、省いても null を渡しても既定値になる。
any を使ってよいのは、中を見ずに jsonencode などでそのまま渡すときだけ。
出典：Type Constraints（Conversion of Complex Types／any／Optional Object Type Attributes）
