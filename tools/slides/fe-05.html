5-1 オペレーティングシステムOSの役割・タスク管理

OSおーえす / Operating System
ハードウェアを管理し、アプリケーションが動く土台になる基本ソフトウェア
Operating＝動かす・運用する／System＝仕組み
ソフトウェアの分類Software Classification
システムソフトウェア（OS・ミドルウェア）と応用ソフトウェア（業務ソフト・表計算など）に分かれる
ポイント表計算やワープロは応用ソフトウェア
カーネルKernel
OSの中核部分。タスク管理・記憶管理・入出力管理などを行う
スプーリングSpooling
プリンタなど遅い装置への出力をいったん補助記憶にためて、CPUを早く解放する仕組み
タスクプロセス / Task, Process
OSから見た処理の単位
ポイント実行可能・実行・待機の3つの状態を行き来する
ディスパッチャDispatcher
実行可能状態のタスクに、実際にCPUを割り当てる機能

5-1 オペレーティングシステムタスク管理

到着順方式FCFS / First Come First Served
実行可能になった順にCPUを割り当てる方式
First Come＝先に来た／First Served＝先に扱われる
優先度順方式Priority Scheduling
優先度の高いタスクからCPUを割り当てる方式
ポイント低い優先度のタスクがずっと待たされることがある
ラウンドロビン方式Round Robin
一定の時間（タイムクウォンタム）ずつ順番にCPUを割り当てる方式
ポイント時間切れになると実行可能状態の最後に並び直す
処理時間順方式SPT / Shortest Processing Time First
処理時間の短いタスクから実行する方式
ポイント平均の待ち時間が短くなる
Shortest＝最も短い／Processing Time＝処理時間／First＝先に
プリエンプティブ方式Preemptive
実行中のタスクを途中で止めて、ほかのタスクにCPUを渡せる方式
ポイント止められないのはノンプリエンプティブ方式
マルチタスクMultitask
複数のタスクを切り替えながら、同時に動いているように処理すること
基本情報 ソフトウェア5

5-1 オペレーティングシステムタスク管理・記憶管理

デッドロックDeadlock
複数のタスクがお互いに相手の持つ資源を待って、どれも進めなくなる状態
ポイント資源を確保する順序をそろえると防げる
固定区画方式Fixed Partition
主記憶をあらかじめ決めた大きさの区画に分けて割り当てる方式
ポイント区画内の使われない部分（内部断片化）が生じる
可変区画方式Variable Partition
プログラムの大きさに合わせて区画を割り当てる方式
ポイント空きが細切れになる（外部断片化）ので、詰め直す（コンパクション）
オーバレイ方式Overlay
主記憶より大きいプログラムを部分に分け、必要な部分を入れ替えながら実行する方式
スワッピングSwapping
実行していないタスクを丸ごと補助記憶へ退避（スワップアウト）し、必要なときに戻す（スワップイン）方式
仮想記憶かそうきおく / Virtual Memory
補助記憶を使って、主記憶より大きな記憶空間があるように見せる仕組み
基本情報 ソフトウェア6

5-1 オペレーティングシステム記憶管理

ページング方式Paging
仮想記憶を一定の大きさのページに分け、ページ単位で主記憶と補助記憶を入れ替える方式
ポイント必要なページが主記憶にないことをページフォールトという
ページイン・ページアウトPage In, Page Out
ページインは補助記憶から主記憶へ読み込むこと、ページアウトは主記憶から補助記憶へ追い出すこと
スラッシングThrashing
ページインとページアウトが頻繁に起きて、処理がほとんど進まなくなる状態
ポイント主記憶を増やす、同時に動かすタスクを減らすなどで防ぐ
LRUえるあーるゆー / Least Recently Used
最も長い間使われていないページを追い出す方式
Least＝最も少なく／Recently＝最近／Used＝使われた
LFUえるえふゆー / Least Frequently Used
使われた回数が最も少ないページを追い出す方式
Least＝最も少なく／Frequently＝頻繁に／Used＝使われた
メモリリークMemory Leak
使い終わったメモリが解放されず、使える量がだんだん減っていく現象
ポイントガーベジコレクションは使わなくなった領域を自動で回収する

5-2 ミドルウェアOSとアプリの間

ミドルウェアMiddleware
OSとアプリケーションの間で、多くのアプリが使う共通の機能を提供するソフトウェア
例DBMS、Webサーバソフト
APIえーぴーあい / Application Programming Interface
ソフトウェアの機能をほかのプログラムから呼び出すための窓口
Application＝アプリケーション／Programming＝プログラムから使う／Interface＝窓口
シェルShell
利用者が入力したコマンドを解釈して、OSに伝えるプログラム

5-3 ファイルシステムファイルの管理

ディレクトリDirectory
ファイルを分類して入れておく入れ物。階層（木構造）にできる
ポイントいちばん上がルートディレクトリ
絶対パス・相対パスAbsolute / Relative Path
絶対パスはルートから、相対パスは今いる場所（カレントディレクトリ）からファイルの場所を示す
ポイント..は1つ上の階層を表す
アクセス権Access Right
ファイルを読む・書く・実行する権限を、利用者ごとに設定するもの

5-4 開発ツール言語処理

コンパイラCompiler
ソースプログラムを実行前にまとめて機械語（目的プログラム）に翻訳するプログラム
ポイント翻訳後は直接実行できるので速い
インタプリタInterpreter
ソースプログラムを1行ずつ解釈しながら実行するプログラム
ポイントすぐ試せるが、実行は遅め
リンカLinker
複数の目的プログラム（オブジェクトファイル）やライブラリを結合して、実行できる形にするプログラム
ポイント結合することをリンクという
ローダLoader
実行できるプログラムを主記憶に読み込むプログラム
IDEあいでぃーいー / Integrated Development Environment
エディタ・コンパイラ・デバッガなどを1つにまとめた開発環境
Integrated＝統合された／Development＝開発／Environment＝環境
デバッガDebugger
プログラムを止めながら変数の値を見るなどして、誤り（バグ）を探す道具

5-5 オープンソースソフトウェアOSS

OSSおーえすえす / Open Source Software
ソースコードが公開され、決まったライセンスのもとで自由に使い・変え・配れるソフトウェア
例Linux、Apache、MySQL
Open＝公開された／Source＝ソースコード／Software＝ソフトウェア
GPLじーぴーえる / GNU General Public License
OSSの代表的なライセンス。改変したものを配るときもソースを公開する必要がある（コピーレフト）
GNU＝プロジェクト名／General Public＝一般に公開する／License＝利用許諾
