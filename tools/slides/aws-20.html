Kinesis Data Streams の設定 4 つ

設定決まり本番で狙われる点
パーティションキーレコードの行き先のシャードを決める。同じキーは同じシャードで順番が付く偏ったキーは 1 つのシャードの上限を超えて例外になる。値が散らばるキーを使う
容量モードオンデマンド：シャードを自動で管理し、使った分に課金。プロビジョンド：シャード数を自分で決め、時間料金予測できない・変動が大きい → オンデマンド
保持期間既定 24 時間、最大 8,760 時間（365 日）。24 時間を超えると追加料金「過去のデータを読み直したい」→ 保持期間を延ばす
拡張ファンアウトコンシューマーごとにシャードあたり毎秒 2 MB を専用に。HTTP/2 でプッシュ。平均 70 ミリ秒共有だと 2 MB を分け合い、5 つで平均約 1,000 ミリ秒まで遅くなる
ひっかけ：シャードを増やしても保持期間は変わらない。拡張ファンアウトは読み取り側の話で、書き込みの偏りは直らない。暗号化は KMS キーによるサーバー側の暗号化。
出典：適切なストリームモードを選ぶ（「オンデマンドモードは、予測不能で変動性の高いトラフィックパターンを持つワークロードに適しています。」）／データ保持期間を変更する（「Kinesis data stream は、デフォルトでは 24 時間レコードを保持し、最大値は 8,760 時間 (365 日) です。」）／専用スループットを備えた拡張ファンアウトを開発する（「この機能により、コンシューマーは、シャードあたり 1 秒間に最大 2 MB のデータのスループットで、ストリームからレコードを受け取ることができます。」）

Data Firehose：アプリを書かずに宛先へ

形式変換：Parquet と ORC は列指向で、容量が減り、JSON よりクエリが速い。CSV などは先に Lambda で JSON にする。Lambda の呼び出しは最大 5 分。
ひっかけ：Firehose は「届いたら配る」サービスで、複数のアプリが読み直すしくみはない。配信は最低 1 回で、重複することがある。
出典：Amazon Data Firehose とは何ですか?（「Amazon Data Firehose を使用すると、アプリケーションを記述したり、リソースを管理したりする必要はありません。」）／Amazon Data Firehose で入力データ形式を変換する（「Parquet と ORC は列指向のデータ形式であり、容量を節約するだけでなく、JSON のような行指向の形式と比較してより高速なクエリを可能にします。」）／Amazon Data Firehose のストリーミングデータのパーティショニング（「データをパーティショニングすることで、スキャンされるデータ量が最小限に抑えられ、パフォーマンスが最適化され、Amazon S3 での分析クエリのコストが削減されます。」）

Amazon EMR：Spark・Hadoop を自由に

項目内容
向く処理カスタムのコード・機械学習・グラフ分析・データ変換・ストリーミング

Athena：スキャン量を減らすと速く安くなる

方法効果注意

Athena の便利な機能と使いどころ

機能何をするか選ぶ言葉
ふつうのクエリ標準 SQL で S3 のデータを直接分析。サーバーレス、実行したクエリにだけ課金。CSV・JSON・Parquet・ORCときどき・アドホック・インフラなし
CTASSELECT の結果から新しいテーブルを作り、データを S3 に書く。Parquet・ORC にも変換できるAthena だけで形式を変換・必要なデータだけのコピー
フェデレーティッドクエリS3 以外のリレーショナル・非リレーショナルなどのデータソースに、コネクタ（多くは Lambda）で SQLデータを移さずに結合
Glue Data Catalogテーブル定義（メタデータ）の置き場所クローラーで登録してクエリ
Athena が向かない場面：多くのソースを共通の形にまとめて長く持ち、複雑なレポートを作る → Redshift。独自の Spark のプログラムや細かいフレームワークの設定 → EMR。
出典：Amazon Athena とは（「Amazon Athena は、標準的な[ SQL](ddl-sql-reference.md) を使用して Amazon Simple Storage Service (Amazon S3) 内のデータを直接分析することを容易にするインタラクティブなクエリサービスです。」）／クエリ結果からテーブルを作成する (CTAS)（「クエリ結果を Parquet や ORC などのストレージ形式に変換する。」）／Amazon Athena フェデレーティッドクエリを使用する（「Athena のフェデレーティッドクエリでは、リレーショナル、非リレーショナル、オブジェクト、およびカスタムデータソースに保存されているデータの全体で SQL クエリを実行することができます。」）

Amazon Redshift：データウェアハウス

機能選ぶ言葉
Redshift多くのソースを共通の形で長く保存・履歴から高度なレポート
Redshift Spectrumロードせずに S3 のデータも一緒にクエリ

同時実行スケーリング数千の同時ユーザー・同時クエリの集中に自動で容量を足す
出典：Amazon Redshift とは（「Amazon Redshift は、クラウド内でのフルマネージド型、ペタバイトスケールのデータウェアハウスサービスです。」）／Amazon Redshift Spectrum（「Amazon Redshift Spectrum を使用すると、効率的にクエリを実行し、Amazon Redshift テーブルにデータをロードすることなく、Amazon S3 のファイルから構造化および半構造化されたデータを取得できます。」）／同時実行スケーリング（「同時実行スケーリング機能を使用すると、一貫した高速のクエリパフォーマンスで、数千の同時ユーザーと同時クエリをサポートできます。」）／列指向ストレージ（「データベーステーブルの列指向ストレージは、ディスク全体の必要な I/O を大幅に減らすため、分析クエリのパフォーマンスの最適化の重要な要因となっています。」）
