パブリックサブネットとプライベートサブネット

確かめることパブリックにするにはひっかけ

ルートテーブルとルートの優先順位

メインルートテーブルVPC を作ると自動でできる。明示的に関連付けていないサブネットは、すべてこれを使う。ここに IGW へのルートを書くと、新しいサブネットが意図せずパブリックになる
カスタムルートテーブル自分で作り、サブネットに明示的に関連付ける。パブリック用・AZ ごとのプライベート用などに分ける
ローカルルートすべてのルートテーブルに入っている、VPC の中の通信のルート。同じ VPC のサブネットどうしは追加の設定なしでつながる
ルートテーブルは「行き先」だけ許可・拒否はセキュリティグループとネットワーク ACL（#03）の仕事
出典：ルートテーブルの概念（「これは、他のルートテーブルに明示的に関連付けられていないすべてのサブネットのルーティングを制御します。」「各ルートテーブルには、VPC 内で通信を有効にするローカルルートが含まれます。」）／ルーティングオプションの例（「最も具体的なルートが優先され、ルートが一致する場合は、伝達されたルートよりも静的ルートが優先されます。」）

インターネットゲートウェイ・Elastic IP・デフォルト VPC・DNS

しくみ内容本番で狙われる点
インターネットゲートウェイVPC とインターネットの間の通信を可能にする。冗長・高可用・水平にスケール。IPv4 と IPv6料金なし・帯域の制約なし。「IGW がボトルネック」は誤り
Elastic IP アドレス静的なパブリック IPv4。障害のとき別のインスタンスに付け替えて障害を隠せる。外部の DNS やファイアウォールに登録できる自動割り当てのパブリック IP は、関連付けを解除するとプールに戻り二度と使えない
デフォルト VPC2013-12-04 以降のアカウントの各リージョンにある。各 AZ のデフォルトサブネット・アタッチ済みの IGW・IGW へのルート・DNS の設定デフォルトサブネットの EC2 はすぐインターネットにつながる。NAT GW は最初からはない
Amazon DNS サーバーRoute 53 Resolver。VPC の範囲のベース＋2、または 169.254.169.253。独自の DNS サーバーは DHCP オプションセットでVPC の外やピア VPC からは直接使えない
出典：インターネットゲートウェイを使用して VPC のインターネットアクセスを有効にする（「インターネットゲートウェイは、VPC とインターネットとの間の通信を可能にする VPC コンポーネントであり、冗長性と高い可用性を備えており、水平スケーリングが可能です。」）／Elastic IP アドレスを VPC 内のリソースに関連付ける（「Elastic IP アドレスは、動的なクラウドコンピューティング専用に設計された静的なパブリック IPv4 アドレスです。」）／VPC とサブネットの IP アドレス指定（「パブリック IP アドレスとインスタンスの関連付けを解除すると、アドレスが解放されてプールに戻され、そのアドレスを使用することができなくなります。」）／Amazon VPC の仕組み（「アカウントが 2013 年 12 月 4 日以降に作成された場合、各リージョンにデフォルトの VPC があります。」）

NAT ゲートウェイ：外へは出るが、入れない

置き場所：パブリック NAT ゲートウェイはパブリックサブネットに作り、Elastic IP を関連付ける。プライベートサブネットのルートテーブルで 0.0.0.0/0 を NAT ゲートウェイに向ける。応答はもとの送信元に戻る。
性能と制御：5 Gbps から 100 Gbps まで自動で拡張。それ以上はサブネットを分けて NAT GW を増やす。セキュリティグループは付けられない → 後ろのインスタンスの SG と、NAT GW のサブネットの NACL で制御。
出典：NAT ゲートウェイ（「NAT ゲートウェイを使用すると、プライベートサブネット内のインスタンスは VPC 外のサービスに接続できますが、外部サービスはそれらのインスタンスとの接続を開始できません。」「パブリックサブネット内にパブリック NAT ゲートウェイを作成します。作成時に Elastic IP アドレスを NAT ゲートウェイに関連付ける必要があります。」）／NAT ゲートウェイの基本（「NAT ゲートウェイは 5 Gbps の帯域幅をサポートし、100 Gbps まで自動的に拡張します。」「NAT ゲートウェイにセキュリティグループを関連付けることはできません。」）

NAT ゲートウェイは AZ ごとに作る

設定のしかた：AZ-a のプライベートサブネット用と AZ-c のプライベートサブネット用に、ルートテーブルを分ける。それぞれ 0.0.0.0/0 を同じ AZ の NAT ゲートウェイに向ける。NAT ゲートウェイ自体は AZ の中で冗長化されているが、AZ の障害には AZ ごとに作って備える。
出典：NAT ゲートウェイの基本（「複数のアベイラビリティーゾーンにリソースがあって、1 つの NAT ゲートウェイを共有している場合、その NAT ゲートウェイが属するアベイラビリティーゾーンがダウンすると、その他のアベイラビリティーゾーンのリソースはインターネットにアクセスできなくなります。」「耐障害性を高めるには、各アベイラビリティーゾーンに NAT ゲートウェイを作成し、同じアベイラビリティーゾーンに属する NAT ゲートウェイがリソースで使用されるようにルーティングを設定します。」）

ゲートウェイエンドポイントの細かい決まり

項目決まりひっかけ
ルート選んだルートテーブルに「プレフィックスリスト → エンドポイント」が自動で入る。変更・削除はできない関連付けていないサブネットはパブリックのエンドポイントを使う
優先順位0.0.0.0/0 → IGW があっても、同じリージョンの S3・DynamoDB 宛てはエンドポイントへほかのリージョンの S3 宛ては IGW へ行く
届く範囲作ったリージョンの、その VPC の中だけVPN・ピアリング・TGW・Direct Connect の向こうからは使えない
SG と NACLSG はプレフィックスリストを参照できる。NACL は参照できないので IP 範囲で書く通信を許可しないとエンドポイントがあっても届かない
バケットポリシーエンドポイント経由では aws:SourceIp は使えない。aws:VpcSourceIp を使う送信元がパブリックからプライベートのアドレスに変わる
エンドポイントポリシーIAM のリソースポリシー。既定はすべてを許可。自社のバケットだけに絞れるデータの持ち出し対策はこれ。SG ではバケットを区別できない
出典：ゲートウェイエンドポイント（「プレフィックスリストはリージョンに固有であるため、別のリージョンのサービス (Amazon S3 または DynamoDB) 宛てのトラフィックはインターネットゲートウェイに送信されます。」）／Amazon S3 のゲートウェイエンドポイント（「VPN 接続、VPC ピアリング接続、トランジットゲートウェイ、または VPC 内の Direct Connect 接続の反対側にあるリソースは、ゲートウェイエンドポイントを使用して Amazon S3 と通信することはできません。」）／AWS PrivateLink の概念（「デフォルトの VPC エンドポイントポリシーでは、すべてのリソースに対して、VPC エンドポイント経由でのすべてのプリンシパルによるすべてのアクションが許可されます。」）

PrivateLink で自分のサービスを公開する

作り方：サービスの前に Network Load Balancer を置き、それを選んでエンドポイントサービスを作る。既定ではだれも使えないので、特定のアカウントなどに許可を足す。少なくとも 2 つの AZ で使えるようにする。
ピアリングとの違い：ピアリングは VPC 全体を双方向につなぎ、CIDR が重なると作れない。PrivateLink は特定のサービスだけを単方向に公開し、コンシューマー側の ENI を使うので IP が競合しない。
出典：AWS PrivateLink を通じてサービスを共有する（「サービスプロバイダーとして、サービスのフロントエンドとして VPC で Network Load Balancer を作成します。」）／AWS PrivateLink の概念（「デフォルトでは、サービスコンシューマーはエンドポイントサービスを使用できません。」）／AWS PrivateLink（ホワイトペーパー）（「コンシューマー VPC でアクセス権を持つクライアントのみが、サービスプロバイダー VPC またはサービス内の AWS サービスへの接続を開始できます。」）

VPC ピアリング：1 対 1 で、推移しない

できないこと（エッジツーエッジの制限）
相手の VPC のインターネットゲートウェイで外に出る
相手の VPC の NAT ゲートウェイで外に出る
相手の VPC の VPN・Direct Connect で社内に行く
相手の VPC のゲートウェイエンドポイントで S3 に行く
CIDR が重なる VPC どうしをつなぐ（重ならない CIDR を足してもだめ）
作り方と料金：リクエスタが申請 → アクセプタが承認 → 両方の VPC のルートテーブルに相手の CIDR へのルートを手動で追加。別のアカウント・別のリージョンともつなげる。作るのは無料、同じ AZ の中の転送も無料、AZ やリージョンをまたぐ転送は有料。たくさんの VPC は Transit Gateway（#18）で。
出典：VPC ピアリング接続の仕組み（「VPC ピアリングでは、推移的なピアリング関係がサポートされません。」「VPC A にインターネットゲートウェイがある場合、VPC B のリソースは VPC A のインターネットゲートウェイを使用してインターネットにアクセスすることはできません。」）／VPC ピア機能とは（「VPC ピアリング接続の確立に料金はかかりません。」）
