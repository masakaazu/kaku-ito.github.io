Terraform #12 バックエンドとロック目標 6a〜6c

backend ブロックの決まり

terraform { backend "s3" { bucket = "mybucket" key = "path/to/my/key" region = "us-east-1" use_lockfile = true # S3 のロックファイル encrypt = true # 保存時の暗号化 } }
書かなければ local（ルートモジュールの terraform.tfstate）。
決まり
1 つの構成に 1 つだけ
cloud ブロックとは同時に書けない（HCP は cloud）
変数・ローカル値・データソースは参照できない
backend の値をほかで参照できない
組みこみの種類だけ（プラグインで追加不可）
変えたら terraform init
資格情報は書かない。設定や -backend-config に書くと .terraform とプランファイルに平文で残る → 環境変数で。

local バックエンドと移行

terraform { backend "local" { path = "relative/path/to/terraform.tfstate" workspace_dir = "states" # 既定は terraform.tfstate.d } }
local（Enhanced）ファイルに保存・OS の API でロック・処理もローカル
-state・-state-out・-backup は古い機能（すすめない）。-backup=- でバックアップなし。
init のオプション意味
-migrate-state今のステートを新しいバックエンドへコピー
-force-copy確認せずに移す（-migrate-state も有効）
-reconfigure今の設定を無視し、移さない
-backend=falseバックエンドの設定をとばす
移す前に terraform.tfstate を手でバックアップ（強くすすめ）。
出典：Backend Type: local／Backend block configuration overview／Command: init

部分設定と .terraform

# backend.tf（種類だけ） terraform { backend "s3" {} } # config.s3.tfbackend（中身をトップレベルに） bucket = "your-bucket" key = "your-state.tfstate" region = "eu-central-1" $ terraform init -backend-config="./config.s3.tfbackend" $ terraform init -backend-config="key=prod.tfstate"
渡し方注意
ファイル*.<バックエンド名>.tfbackend がすすめ
KEY=VALUEシェルの履歴に残る → 秘密には向かない
対話必須の値だけ聞かれる
.terraform/terraform.tfstateバックエンドの設定（資格情報も入りうる）。インフラのステートとは別物。Git に入れない
保存したプランを apply するときは、プランの中のバックエンドの設定を使う（期限つきの資格情報は切れうる）。

ステートのロック

同時に書かせない。

Terraform #12 バックエンドとロック目標 6a〜6c

ロックのしくみとオプション

自動でロックステートに書きこむおそれのあるすべての操作。メッセージは出ない
取れなければ止まる長引けばステータスのメッセージ
対応はバックエンドごとlocal は OS の API、S3 は use_lockfile
S3 の DynamoDB ロック（dynamodb_table・LockID）は非推奨。バケットのバージョニングを強くすすめ。
$ terraform plan -lock-timeout=5m # 5 分まで取りなおす $ terraform apply -lock=false # 危険。すすめない $ terraform force-unlock 6638e010-8fb0-46cf-966d-21e806602f3a
force-unlock
ロック ID が必須（失敗時に表示される一意の ID）
インフラは変えない。-force で確認なし
自分のロックが自動で外れなかったときだけ
ローカルのロックはほかのプロセスから外せない

data "terraform_remote_state" "vpc" { backend = "s3" config = { bucket = "mybucket" key = "network/terraform.tfstate" region = "us-east-1" } } resource "aws_instance" "app" { subnet_id = data.terraform_remote_state.vpc.outputs.subnet_id }
組みこみ（terraform.io/builtin/terraform）。読めるのはルートモジュールの出力だけ。

CLI のワークスペース

$ terraform workspace list * default $ terraform workspace new feature-x $ terraform workspace select default $ terraform workspace show resource "aws_instance" "example" { count = terraform.workspace == "default" ? 5 : 1 tags = { Name = "web - ${terraform.workspace}" } }
1 つの構成・1 つのバックエンド・複数のステートdefault は削除できない。local は terraform.tfstate.d
向く：機能ブランチ用の一時的なコピー
向かない：資格情報・アクセス制御を分けたい環境ルートモジュールやバックエンドを分ける
新しいワークスペースの plan は、ほかのワークスペースのリソースを見ない（実物は残る）。
HCP Terraform のワークスペースとは別物（#16）。
