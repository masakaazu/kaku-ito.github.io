設定の2つの書き方：network コマンドと ip ospf area

計算手順：network コマンドのワイルドカードを読む

  1. 各オクテットを 255 から引くとサブネットマスクに戻る：0.0.0.255 ＝ /24、0.0.0.3 ＝ /30、0.0.0.0 ＝ 1つのアドレス
  2. ワイルドカードの 0 の部分だけを比べる（1 の部分は見ない）
  3. インタフェースのプライマリのアドレスが当てはまれば、そのインタフェースで OSPF が動き、指定したエリアに入る
  4. 何行書いてもよい。範囲が重なったら先に当てはまった行のエリア
サブネットマスクを書かない：network 10.1.1.0 255.255.255.0 area 0 は誤り。OSPF の network はワイルドカード。

passive-interface と default-information originate

passive-interface
  • 指定したインタフェースから Hello を送らない → ネイバーはできない
  • そのネットワークは OSPF で広告される（network が当てはまっていれば）
  • PC だけの LAN に付ける。ルーターどうしのリンクに付けるとネイバーが消える
default-information originate
R1(config)#ip route 0.0.0.0 0.0.0.0 203.0.113.1
R1(config)#router ospf 1
R1(config-router)#default-information originate

R2#show ip route ospf
O*E2  0.0.0.0/0 [110/1] via 10.1.12.1, 00:00:12, Gi0/0
  • R1 が自分のデフォルトルートを OSPF で配る（ないときは配らない。always を付けると無くても配る）
  • 受け取った側は O*E2（OSPF の外から入れた種類2、* はデフォルトの候補）
  • E2 の経路は、途中のリンクのコストを足さない（CCNA では表示の読み方を覚える）
出典：OSPF Configuration Guide（passive-interface：Suppresses the sending of hello packets）／ 「default-information originate (OSPF)」（always・default is type 2 external route）。出力はClaudeが作った例

ネイバーと隣接

Hello で互いを見つけ（ネイバー）、LSDB をそろえて隣接（Full）になる。どこで止まったかで原因が分かる。

CCNA #14 OSPF3.4.a

Hello の中身：これが合わないとネイバーにならない

ネットワークマスク必要（同じサブネット）

止まった状態考えられる原因

第3章

ネットワークタイプと DR・BDR

イーサネット（broadcast）は代表を選んでまとめる。2台だけのリンク（point-to-point）は代表を選ばない。

CCNA #14 OSPF3.4.b・c

なぜ DR を選ぶのか：隣接の数を減らす

  1. 1つのセグメントに n 台いると、全員どうしで隣接になれば n(n−1)/2 本。5台で 10 本、10台で 45 本
  2. DR と BDR を決め、ほかのルーターは DR・BDR とだけ隣接になる
  3. DROTHER は変化を 224.0.0.6（DR・BDR 宛て）に送り、DR が 224.0.0.5（全員）に配り直す
  4. DR が落ちたら、すでに全員と隣接の BDR がすぐ DR になる
DR はセグメントごと：「ルーター全体の DR」ではなく、インタフェース（セグメント）ごとに選ぶ。同じルーターが、ある LAN では DR、別の LAN では DROTHER ということもある。
出典：RFC 2328 7.3 The Designated Router（becomes adjacent to all other routers on the network）・7.4 The Backup Designated Router・A.1（AllSPFRouters・AllDRouters）／ Doc 13685。本数の計算はClaudeが書いた

broadcast と point-to-point：DR を選ぶか選ばないか

broadcastpoint-to-point
初期値になる線イーサネットシリアル（HDLC・PPP）
DR・BDR選ぶ選ばない
隣接の相手DR・BDR とだけ相手と必ず
Hello／Dead10／40 秒10／40 秒
State の表示FULL/DR などFULL/-
優先度使う使わない
ルーター2台だけをつなぐイーサネット
R1(config)#interface Gi0/0
R1(config-if)#ip ospf network point-to-point
R2(config)#interface Gi0/0
R2(config-if)#ip ospf network point-to-point
  • 相手が1台しかいないので、DR を選ぶ意味がない
  • point-to-point にすると選出を省き、相手と直接 Full になる
  • 両側で同じタイプにする。片側だけ変えると問題が起きる
確認show ip ospf interface Gi0/0 の Network Type
出典：OSPF Configuration Guide（Broadcast networks (Ethernet…)・Point-to-point networks (HDLC and PPP)）／ ip ospf network・ip ospf priority（not to point-to-point networks）／ Doc 13699（network-type mismatch）

計算手順：DR と BDR を当てる

  1. 優先度 0 のルーターを外す（DR にも BDR にもならない）
  2. 残りで優先度がいちばん大きいものが DR、2番目が BDR
  3. 優先度が同じなら、ルーター ID が大きいほう
  4. ただし、すでに DR・BDR がいるなら交代しない（あとから来たルーターは DROTHER）
インタフェースの IP アドレスでは比べない：同点の決め手はルーター ID。
ルータールーター ID優先度結果
R11.1.1.1200DR
R22.2.2.21DROTHER
R33.3.3.31DROTHER
R44.4.4.41BDR
R59.9.9.90DROTHER（選ばれない）
考え方R5 は ID が最大でも優先度 0。R1 は優先度で勝つ。残り（R2〜R4）は優先度 1 で同じなので ID が最大の R4 が BDR
出典：OSPF Command Reference「ip ospf priority」（higher router priority takes precedence. If there is a tie, the router with the higher router ID・priority set to zero is ineligible・Priority of 1・range 0 to 255）。表はClaudeが作った練習（全部が同時に起動した場合）

DR は交代しない：先に起動したルーターが DR のまま

RFC 2328 の考え方：インタフェースが動き出したとき、すでに DR がいれば優先度に関係なくそれを受け入れる。DR が変わると LSA を作り直し、一時的に通信が乱れるので、なるべく変わらないようにしている。
したいことやり方
今すぐ DR を変えたい優先度を変えたあと clear ip ospf process
DR にしないip ospf priority 0
DR を選ばないip ospf network point-to-point（2台のとき）
本番のわな：優先度や ID だけを見て「いちばん大きいのが DR」と答えると、起動の順番が書かれた問題で間違える。
出典：RFC 2328 7.3（If there is, it accepts that Designated Router, regardless of its Router Priority … ensures that the Designated Router changes less often）・7.4（BDR becomes DR when the previous DR fails）。時系列の例はClaudeが作った

第4章

ルーター ID

OSPF の中でルーターを見分ける名札。手で決める → ループバック → 物理の順に決まる。

CCNA #14 OSPF3.4.d

ルーター ID の決まり方と、変えるときの注意

① router-id コマンドの値インタフェースのアドレスでなくてもよい（1.1.1.1 など）
② up しているループバックの最大のアドレスループバックは down しないので安定する
③ up している物理インタフェースの最大のアドレスそのインタフェースが落ちると ID を選び直すことになる
例Gi0/0＝192.168.1.1、Lo0＝1.1.1.1、Lo1＝2.2.2.2、router-id なし → 2.2.2.2（物理の 192.168.1.1 より、ループバックが先）
R1(config)#router ospf 1
R1(config-router)#router-id 1.1.1.1
% OSPF: Reload or use "clear ip ospf process" command,
  for this to take effect
R1#clear ip ospf process
Reset ALL OSPF processes? [no]: yes
R1#show ip ospf | include ID
 Routing Process "ospf 1" with ID 1.1.1.1
  • ネイバーがいる OSPF で変えると、再起動か clear ip ospf process のあとで使われる
  • ルーター ID は一意でなければならない。同じ ID どうしは Hello を無視し、隣接にならない
  • ExStart の主と従、DR の同点の決め手にも使う
出典：OSPF Configuration Guide（OSPF automatically prefers a loopback interface … highest IP address among all loopback interfaces. If no loopback interfaces are present, the highest IP address）／ router-id（next reload or manual OSPF process restart）／ Doc 13699（duplicate Router IDs）。出力はClaudeが作った例
