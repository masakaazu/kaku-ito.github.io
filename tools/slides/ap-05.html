5-1 オペレーティングシステムタスクの管理

タスクプロセス）の状態（Task States
実行状態・実行可能状態・待ち状態の3つ
ポイント入出力を待つと待ち状態、終わると実行可能状態に戻る
ディスパッチDispatch
実行可能状態のタスクに、CPUを割り当てること
スケジューリング方式Scheduling
どのタスクにCPUを渡すかの決め方
ポイント到着順・優先度順・ラウンドロビン（一定時間ずつ順番に）など
ラウンドロビンRound Robin
決まった時間（タイムクウォンタム）ずつ順番にCPUを割り当てる方式
プリエンプションPreemption
実行中のタスクからCPUを取り上げ、別のタスクに渡すこと
スレッドThread
プロセスの中の処理の流れの単位
ポイント同じプロセスのスレッドはメモリを共有する

5-1 オペレーティングシステムタスクの管理・記憶の管理

セマフォSemaphore
共有する資源を使えるかを、数（カウンタ）で管理するしくみ
ポイントP操作で減らし、V操作で増やす
デッドロックDeadlock
複数のタスクがお互いの持つ資源を待ち合って、どれも進めなくなる状態
ポイント資源を取る順番をそろえると防げる
仮想記憶Virtual Memory
補助記憶を使って、主記憶より大きな記憶空間があるように見せるしくみ
ページング方式Paging
仮想記憶を決まった大きさのページに分けて管理する方式
ポイント主記憶にないページを使うとページフォールトが起きる
ページフォールトPage Fault
必要なページが主記憶にないときに起きる割込み
スラッシングThrashing
ページの入れ替えが多くなりすぎて、処理がほとんど進まなくなる状態
ポイント主記憶が足りないと起きる

5-1 オペレーティングシステム記憶の管理・いろいろなOS

LRUえるあーるゆー / Least Recently Used
最後に使われてから最も長い時間がたったページを追い出す方式
Least＝最も少なく／Recently＝最近／Used＝使われた
フラグメンテーションFragmentation
空き領域が細かく分かれ、まとまった領域が取れなくなること
ポイントコンパクションで空きをまとめる
メモリリークMemory Leak
使い終わったメモリが解放されず、使える領域が少しずつ減ること
ポイントガーベジコレクションで回収する
リアルタイムOSReal-time OS
決められた時間内に処理を終えることを保証するOS
ポイント組込みシステムに使う
カーネルKernel
OSの中心部分。タスク・メモリ・入出力などを管理する
ポイントマイクロカーネルは最小限の機能だけを持つ

5-3 ファイルシステムファイルの管理

絶対パス・相対パスAbsolute / Relative Path
絶対パスはルートからの道順、相対パスは今いるディレクトリ（カレント）からの道順

5-4 開発ツール言語処理

コンパイラCompiler
高水準言語のプログラムを、まとめて機械語に翻訳するソフトウェア
ポイント字句解析→構文解析→意味解析→最適化→コード生成の順
インタプリタInterpreter
プログラムを1行ずつ解釈しながら実行するソフトウェア
リンカLinker
複数の目的プログラムやライブラリを結合して、実行できる形にするソフトウェア
ポイント実行時に結合するのが動的リンク
最適化Optimization
コンパイラが、実行が速くなるように命令を整理すること
JIT コンパイラJust-In-Time Compiler
実行するときに中間コードを機械語に翻訳する方式
例Javaの仮想マシン
IDEあいでぃーいー / Integrated Development Environment
編集・コンパイル・デバッグなどを1つにまとめた開発ツール
Integrated＝統合された／Development＝開発／Environment＝環境

5-5 オープンソースソフトウェアOSS

OSSおーえすえす / Open Source Software
ソースコードが公開され、決まった条件のもとで誰でも使ったり変えたりできるソフトウェア
Open＝公開された／Source＝ソースコード／Software＝ソフトウェア
GPLじーぴーえる / GNU General Public License
改変したものを配布するときも、同じGPLでソースコードを公開する必要があるライセンス（コピーレフト）
GNU＝プロジェクト名／General Public＝一般公衆向けの／License＝利用許諾
BSDライセンス・MITライセンスBSD / MIT License
著作権の表示などを守れば、改変したものを非公開にしてもよいライセンス
