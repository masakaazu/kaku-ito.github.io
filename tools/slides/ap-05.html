互換性は2段階。POSIXはソースの約束、ABIは機械語の約束

用語意味
POSIXUNIX系OSのAPI（関数・コマンド・シェル）の標準。IEEE と The Open Group が定める。従えばソースのまま他のOSへ移しやすい
ABI機械語の段階の約束（呼出し規約・データの並べ方・システムコール番号）。同じなら再コンパイルなしで動く
OSEOpen Systems Environment。標準に従い、異なるメーカーの機器・ソフトを組み合わせられる環境
The Open GroupPOSIX を含む UNIX の標準（Single UNIX Specification）を管理する団体
例：Linux 用の C プログラムは、POSIX の範囲で書けば FreeBSD でもコンパイルし直して動く。だが Linux の実行ファイルをそのまま FreeBSD で動かすには、Linux の ABI をまねる仕組みが要る。

ファイルを1つ読むだけでも、アプリは何度もシステムコールでOSに頼む

Linux で「cat memo.txt」を実行したときの流れ（概略）
  1. openat：「memo.txt を読みたい」→ OSが権限を調べ、ファイル記述子（番号）を返す
  2. read：記述子の番号で中身を読む。OSがディスク（またはキャッシュ）からアプリの領域へ写す
  3. write：読んだ内容を、標準出力（記述子1番）へ書く
  4. close：記述子を返す。最後に exit_group で終了を伝える
アプリは装置を直接さわれない（ユーザーモード）。すべてシステムコール（SVC割込み）でカーネルモードの OS に代わりにやってもらう。
システムコールの例頼む内容
fork・execveプロセスを複製する・別のプログラムに入れ替える
openat・read・writeファイルや装置を開く・読む・書く
mmap・brkメモリ（仮想アドレス空間）を割り当てる
socket・connectネットワークの通信口を作る・つなぐ
kill他のプロセスにシグナルを送る
数の目安Linux の man ページ syscalls(2) には数百のシステムコールが並ぶ。アプリは普通、C ライブラリの関数（fopen など）経由で呼ぶので、自分で番号を書くことはない。

使用率は「装置が動いていた時間÷全体の時間」。時間の線を引いて数える

H21春 問17：A・Bの順に実行。CPUの後にディスク。装置は1つずつ処理
ジョブCPUディスク
A3秒7秒
B12秒10秒
  1. CPU：Aが0〜3秒、Bが3〜15秒
  2. ディスク：Aは3秒から7秒で10秒まで。BはCPUが終わる15秒から10秒で25秒まで
  3. CPUの使用率＝(3＋12)÷25＝0.60
  4. ディスクの使用率＝(7＋10)÷25＝0.68（正解 イ）
全体の時間を「CPUの合計＋ディスクの合計＝32秒」としない。AのディスクとBのCPUが重なる（3〜10秒）ので、全体は25秒。この重なりがマルチプログラミングの効果。

空きがないときのフォールト処理は「決める→追い出す→読み込む」の順

  1. ページフォールト：主記憶にないページを参照した（プログラム割込み）
  2. 置換え対象ページの決定：FIFO・LRU などで、追い出すページを選ぶ
  3. ページアウト：選んだページが更新されていれば補助記憶へ書き戻す
  4. ページイン：空いた枠に、必要なページを補助記憶から読み込む
  5. ページテーブルを書き換え、止まっていた命令をやり直す

フォールト→決定→ページイン→ページアウト枠が空く前に読み込むことはできない
追い出すページが更新されていなければ、補助記憶に同じ内容が残っているので書き戻し（ページアウト）は要らない。だから「ページアウトの回数 ≦ ページインの回数」になる。

サポートメーカーの保証がない。有償サポート契約や社内の技術者で補う
