第1章

組織とアカウント

アカウントは、権限・セキュリティ・コストの境界。分けて、束ねる。

AWS SAA #02 マルチアカウントとフェデレーションタスク 1.1

Organizations の木の形

部品決まり
ルート組織に1つ。自動でできる。#01 のルートユーザーとは別物
OUアカウントのグループ。入れ子にできる。付けたポリシーは下のアカウントすべてに効く
メンバーアカウント一度に1つの組織にだけ入れる。新しく作るか、招待して入れる
出典：AWS Organizations の概念と用語（組織構造・「ルートは 1 つのみ持つことができます。」「メンバーアカウントは、一度に 1 つの組織のみに所属できます。」）

管理アカウントは「組織の管理だけ」に使う

管理アカウントメンバーアカウント
役割組織を作る・アカウントを作る／招待する・ポリシーを付けるワークロードを動かす
料金全員分を払う（支払者）管理アカウントにまとまる
SCP効かない効く（ルートユーザーも）
ほかに変更できない―
SCP で守れないので、管理アカウントに作業用のリソースを置かない。リソースはメンバーアカウントに分けるのが AWS のおすすめ。
機能のセット使えること
すべての機能（既定・推奨）一括請求に加えて、SCP などのポリシー、ほかのサービスとの統合、委任
一括請求だけ請求をまとめるだけ。SCP は使えない
一括請求だけ → すべての機能に変えるには、招待で入ったメンバーアカウントすべての承認が要る。
委任管理者中身
Organizations の組織のポリシーの管理を任せる
AWS サービスのGuardDuty など統合したサービスの管理を任せる
委任管理者はメンバーアカウントなので SCP が効く。
出典：AWS Organizations の概念と用語（管理アカウント・利用可能な機能セット・委任された管理者）／サービスコントロールポリシー (SCP)（「SCP は、管理アカウントのユーザーやロールには影響を与えません。」）

アカウントをまたいで「そろえる」「分け合う」

AWS RAM（Resource Access Manager）
リソースごとにリソースベースのポリシーを書かなくても、アカウント・OU・組織全体と共有できる。代表例は VPC のサブネット、Transit Gateway、Route 53 Resolver のルール。
タグポリシー
そろえる前タグポリシーで
costcenter / Cost-Center / CostCenterCostCenter に統一
組織のアカウントのリソースに付けるタグを標準化する（キーや値の大文字・小文字など）。コスト配分タグ（#23）の集計がずれない。
似たものの見分け：そろえる＝タグポリシー、止める＝SCP、分け合う＝RAM、アカウントを束ねる＝Organizations。
出典：AWS RAM とは／ポリシーとアクセス許可（AWS RAM リソース共有の一般的なユースケース）／タグポリシー
第2章

ガードレール：SCP・RCP・Control Tower

アカウントの管理者でも外せない「上限」を、上の階層からかける。

AWS SAA #02 マルチアカウントとフェデレーションタスク 1.1

SCP：権限は与えない。上限だけ

実際の権限＝SCP（と RCP）が許す範囲と、ID ベース・リソースベースのポリシーが許す範囲の共通部分。図は Claude が作った模式図。
だれに効くかSCP
メンバーアカウントの IAM ユーザー・ロール効く
メンバーアカウントのルートユーザー効く
委任管理者のアカウント効く
管理アカウント効かない
サービスにリンクされたロール効かない
組織の外のユーザー・ロール効かない（→ RCP）
IAM のポリシーがないユーザーは、SCP がすべてを許していても何もできない。SCP は「開ける」ものではない。
出典：サービスコントロールポリシー (SCP)（「SCP は、組織内の IAM ユーザーと IAM ロールにアクセス許可を付与しません。」「SCP はサービスにリンクされたロールに影響しません。」）

SCP の評価：Allow は全階層、Deny はどこか1つ

FullAWSAccess：組織を作ると、すべてのルート・OU・アカウントに自動で付く「全部許可」の SCP。外して代わりの許可を付けないと、メンバーアカウントのすべての操作が失敗する。
2つの書き方：FullAWSAccess を残して Deny を足す（拒否リスト）か、FullAWSAccess を外して必要なサービスだけ Allow する（許可リスト）。
出典：SCP 評価（SCP と Allow の連携の仕組み・SCP と Deny の連携の仕組み・SCP の使用戦略）。図の組織とポリシーは Claude が作った例

SCP と RCP：守る向きがちがう

SCPRCP
縛るもの自分の組織のプリンシパルが「何をできるか」（相手のリソースがどこにあっても）自分の組織のリソースに「だれが何をできるか」（組織の外の人も含む）
こんなとき社員が使えるリージョンやサービスを限る組織の外からバケットに触らせない
共通権限は与えない。管理アカウントには効かない。Organizations の「すべての機能」で使う
出典：リソースコントロールポリシー (RCP)（「組織のメンバーアカウント内の IAM プリンシパルのアクセス許可を制限する必要がある場合は、SCP を使用します。」）

Control Tower：安全なマルチアカウント環境をすぐ作る

機能中身
ランディングゾーンベストプラクティスに沿って設計された複数アカウントの環境（OU・アカウント・ユーザーなど）
コントロール環境全体を統制するルール（ガードレールとも呼ぶ）。OU 単位で効く
Account Factory承認済みの設定で新しいアカウントを作るテンプレート（Service Catalog の上に作られている）
ダッシュボードアカウント・有効なコントロール・違反の状況を見る
Control Tower は Organizations・Service Catalog・IAM Identity Center などを組み合わせて動かす。
コントロールのふるまい
種類何をする実装
予防違反になる操作を許さないSCP・RCP・宣言型ポリシー
検出違反を見つけて知らせるAWS Config ルール
プロアクティブ作る前に調べ、違反なら作らせないCloudFormation フック
指針（ガイダンス）は別の分類で、必須・強く推奨・選択の3つ。
本番の言い回し：「最小の運用の手間で、ガバナンスの効いた複数アカウントの環境を用意」→ Control Tower。
出典：AWS Control Tower とは（機能）／Control behavior and guidance（「The detective controls are implemented using AWS Config rules.」）

責任共有モデル：どこまでが AWS で、どこからが自分か

範囲はサービスで変わる：EC2 のようにサーバーを借りる形ほどお客様の範囲が広く、マネージドサービスほど AWS が多くを受け持つ（運用の負担が減る）。
ひっかけ：「EC2 の OS のパッチは AWS が当てる」は誤り。ゲスト OS はお客様の責任。
出典：AWS ホワイトペーパー「責任共有モデル」（「お客様の責任範囲は、使用するサービス、IT 環境へのサービス統合、および関係法令に応じて異なります。」）

IAM Identity Center と権限セット

用語決まり
権限セットIAM ポリシーをまとめたテンプレート。AWS 管理・カスタマー管理・インライン・職務機能のポリシーを入れられ、境界も付けられる。1人に複数を割り当てられる
ID ソース組織に1つ。外部 IdP（Okta・Entra ID など）、Active Directory（オンプレミスか AWS Managed Microsoft AD）、Identity Center ディレクトリ（既定）。Simple AD は不可
出典：権限セットを使用して AWS アカウントを管理する／ID ソースを管理する（「ID ソースは AWS Organizations で組織あたり 1 つのみ持つことができます。」）

Active Directory を AWS で使う3つの形

AWS Managed Microsoft ADAD ConnectorSimple AD
中身AWS が管理する本物の Microsoft ADオンプレミスの AD へ問い合わせを転送するゲートウェイSamba 4 の AD 互換ディレクトリ
ユーザーの置き場所AWS の中のドメインオンプレミスの AD のまま（キャッシュしない）AWS の中
配置VPC の複数の AZ にドメインコントローラーのペアオンプレミスのドメインと1対1―
オンプレミスとの信頼関係結べる（AD そのものに転送する）―
ほかのアカウントと共有できるできない―
向いている場面SharePoint・.NET・SQL Server など AD 対応アプリを AWS で動かす今の AD のアカウントのまま AWS にサインイン新しい顧客には提供されていない
選び方：「AWS の中に AD のドメインが要る」→ Managed Microsoft AD。「ユーザー情報を AWS に置かずに今の AD を使う」→ AD Connector。
出典：AWS Managed Microsoft AD／AD Connector（「AD Connector を他の AWS アカウントと共有することはできません。」）／Simple AD（「Simple AD は新規顧客に公開されなくなりました。」）
