第1章

ルートブリッジとルートポートの選び方

経路が二重でもループにならないように、根（ルート）を1台決め、そこへの一番良い道だけを残す。

CCNA #09 スパニングツリー2.5.a

なぜSTPが要るのか：レイヤ2のループは止まらない

ループで起きること中身
ブロードキャストストームフレームが回り続け、増え続けて帯域とCPUを使い切る
同じフレームが何度も届く端末に重複したフレームが届く
MACアドレステーブルの不安定同じMACアドレスを、あちこちのポートで学習し直す
STPの答え：二重の経路は残したまま（予備として）、一部のポートを止めて木の形にする。使っている道が切れたら、止めていたポートを使う。
BPDU：STPのスイッチが2秒ごとに交換する情報（ルートのID・ルートまでのコスト・自分のID・ポートID・タイマー）。受け取っても中継はしない。
出典：Cisco Layer 2 Configuration Guide 17.9.x (Catalyst 9300)「Configuring Spanning Tree Protocol」（Spanning Tree Protocol・Spanning-Tree Topology and BPDUs）

ブリッジID＝プライオリティ＋VLAN番号＋MACアドレス。小さいほうがルート

SW1# show spanning-tree vlan 20
VLAN0020
  Spanning tree enabled protocol rstp
  Root ID    Priority    24596
             Address     0050.0f00.0001
  Bridge ID  Priority    32788  (priority 32768 sys-id-ext 20)
             Address     0050.0f00.0005
  • 32788 ＝ 設定した 32768 ＋ VLAN番号 20
  • ルート（Root ID）は 24596－20 ＝ 24576（root primary の値）
  • 設定できるのは 0〜61440 の4096の倍数だけ（30000 はエラー）
  • 全部初期値なら MACアドレスが一番小さいスイッチがルート。古い機種がルートになりやすいので、コアを明示的にルートにする
出典：Configuring Spanning Tree Protocol（Bridge ID, Device Priority, and Extended System ID・Configuring the Device Priority of a VLAN・Restrictions）。出力は Command Reference「show spanning-tree」の書式に沿ってClaudeが書いた例

パスコスト：速いリンクほど小さい。値は2つの方式がある

パスコスト
ポートの速度から決まる「遠さ」。管理者が spanning-tree cost で変えることもできる。
ルートパスコスト
ルートから自分までに通る受信側のポートのコストの合計。ルート自身は0。

本番の注意：参考書や問題の多くは短い方式（1G＝4、100M＝19）。比べ方はどちらでも同じなので、問題文や図に書かれた値で計算する。
出典：Configuring Spanning Tree Protocol（Default Spanning-Tree Configuration・Note：The long path cost method is the default）／ Catalyst 2960 Software Configuration Guide 12.2(55)SE「Configuring STP」（1000 Mb/s: 4・100 Mb/s: 19・10 Mb/s: 100）／ Command Reference「spanning-tree pathcost method」

選ぶ順番は4段。比べ方はどれも「小さいほうが勝ち」

  1. ルートブリッジを1台（VLANごと）：ブリッジIDが一番小さいスイッチ
  2. ルートポートをルート以外の各スイッチに1つ：
    ① ルートパスコストが小さい → ② 相手（送り主）のブリッジIDが小さい → ③ 相手のポートIDが小さい
  3. 指定ポートをリンクごとに1つ：そのリンクからルートまでのコストが小さいスイッチ側（同じならブリッジIDが小さい側）
  4. どれにも選ばれなかったポートはブロック（RSTPでは代替ポート）
よくある勘違い正しくは
直接つながっているポートがルートポートホップ数ではなくコストの合計で決まる
同じコストなら自分のポート番号が小さいほう比べるのは相手（送り主）のブリッジID・ポートID
プライオリティが大きいほど優先小さいほど優先（初期値32768）
ルートブリッジにもルートポートがあるない。ルートのポートは全部指定ポート
リンクの両端とも指定ポート指定ポートはリンクに1つ
出典：Configuring Spanning Tree Protocol（Spanning-Tree Topology and BPDUs・Port Priority Versus Path Cost）／ Catalyst 2960「Configuring STP」（root port を選ぶ順番：lowest root bridge ID → path cost → designated bridge ID → … → port ID）

計算の例：3台のスイッチで、どのポートが止まるか

  1. ルート：プライオリティが一番小さいSW1
  2. SW1のポート：ルートなので全部D（指定）
  3. SW2のルートポート：SW1へ直接＝4、SW3経由＝8 → SW1側がR
  4. SW3のルートポート：同じくSW1側がR（4）
  5. SW2–SW3のリンク：両方ともルートまで4で同じ → ブリッジIDが小さいSW2側がD、SW3側がA（ブロック）
止まるのはSW3のSW2向きのポート1つだけ。SW1–SW3 のリンクが切れると、このポートがすぐ新しいルートポートになる（RSTP）。
出典：Configuring Spanning Tree Protocol（選び方の規則）。例の構成と計算はClaudeが作成

ルートを決める設定：root primary／secondary と priority

CORE1(config)# spanning-tree vlan 10 root primary
! VLAN 10 のプライオリティを 24576 に（足りなければさらに下げる）
CORE2(config)# spanning-tree vlan 10 root secondary
! 28672 に。CORE1 が壊れたら次のルート

CORE1(config)# spanning-tree vlan 20 priority 4096
! 値を直接書く（4096 の倍数）

SW1(config-if)# spanning-tree vlan 10 cost 10
SW1(config-if)# spanning-tree port-priority 64
! インタフェースでコストとポートプライオリティ（16刻み）
コマンド決まる値
root primaryふつう 24576
root secondary28672
初期値32768
VLANで分ける：VLAN 10 は CORE1、VLAN 20 は CORE2 をルートにすると、VLANごとに止めるリンクが変わり、両方のリンクを使える（PVST+ の負荷分散）。
構成ガイドの注意：アクセスのスイッチをルートにしない。ルートはバックボーンかディストリビューションに置く。
出典：Configuring Spanning Tree Protocol（Configuring the Root Device：24576・Configuring a Secondary Root Device：28672・Configuring Port Priority / Path Cost・Restrictions・Spanning-Tree Modes and Protocols）
第2章

ポートの役割と状態（Rapid PVST+）

役割（Root・Desg・Altn・Back）と状態（転送するか）を分けて読む。RSTPはタイマーを待たずに切り替わる。

CCNA #09 スパニングツリー2.5.b

STPの種類：VLANごとか、まとめるか。速いか、遅いか

モードもとの規格ツリーの数収束コマンド
STPIEEE 802.1D全部のVLANで1つ遅い（最大50秒）―
PVST+802.1D＋Cisco独自VLANごと遅いspanning-tree mode pvst
Rapid PVST+802.1w（RSTP）VLANごと速い（1秒未満も）spanning-tree mode rapid-pvst
MSTPIEEE 802.1sVLANをまとめたインスタンスごと速い（RSTPの上で動く）spanning-tree mode mst
Catalyst 9300 の既定値は Rapid PVST+。show では「Spanning tree enabled protocol rstp」と出る（PVST+ なら ieee、MSTPなら mstp）。コマンドは rapid-pvst で、rstp ではない。
混ぜたとき：Rapid PVST+ と PVST+ の機器がつながると、そのつながりはPVST+（遅いほう）で動く。Rapid PVST+ の設定はほぼPVST+と同じ。
出典：Configuring Spanning Tree Protocol（Spanning-Tree Modes and Protocols・Interoperability・Default Configuration・Changing the Spanning-Tree Mode）／ Configuring Multiple Spanning-Tree Protocol（RSTP Overview）

ポートの役割は4つ。転送するのは Root と Desg だけ

役割（表示）中身状態
ルート（Root）ルートへの一番良い道。ルート以外の各スイッチに1つ転送
指定（Desg）リンクの代表。ルートのポートは全部これ転送
代替（Altn）ルートポートの予備（別のスイッチ経由でルートへ）止める
バックアップ（Back）指定ポートの予備（自分の2つのポートが同じリンクにある）止める
ディセーブルリンクダウンや shutdown で役割なし―
代替とバックアップの見分け方：止めているポートの先に別のスイッチの指定ポートがあれば代替、自分の指定ポートがあればバックアップ。
出典：Configuring Multiple Spanning-Tree Protocol（Port Roles and the Active Topology）／ Configuring Spanning Tree Protocol（Root・Designated・Alternate・Backup）

ポートの状態：802.1D は5つ、RSTP は3つ

Ciscoの show は RSTP でも BLK（blocking）と表示する。FWD／LRN／LIS／BLK／DIS
802.1D の遅さ（初期値のタイマー）
Hello タイム2秒（BPDUを送る間隔）

出典：Configuring Spanning Tree Protocol（Spanning-Tree Interface States・Default Configuration）／ Configuring MSTP（Port State Comparison・RSTP Overview：50 seconds）／ Command Reference「show spanning-tree」（port states）

RSTPが速い理由：待たずに切り替える3つの仕組み

① エッジポート
PortFast のポート＝エッジポート。リンクが上がるとすぐ転送。リンクの上下はトポロジーの変化として扱わない。
② 新しいルートポート
ルートポートが切れたら、古いルートポートを止めて、代替ポートをすぐ転送にする。
③ 提案と合意
ポイントツーポイント（全二重）のリンクで、BPDUの proposal／agreement を交わしてすぐ転送。
リンクタイプ：全二重＝P2p、半二重＝Shr（共有）。提案と合意が使えるのは P2p だけ。show spanning-tree の Type 列で見る（P2p Edge＝PortFast）。
出典：Configuring Multiple Spanning-Tree Protocol（Rapid Convergence・Synchronization of Port Roles・Topology Changes）

第3章

PortFastと保護機能

端末用のポートはすぐ使えるように。でも、そこにスイッチがつながれたり、ルートが乗っ取られたりしないように守る。

CCNA #09 スパニングツリー2.5.c・2.5.d

PortFast：端末用のポートを、リンクが上がったらすぐ転送に

SW1(config)# interface g1/0/5
SW1(config-if)# switchport mode access
SW1(config-if)# spanning-tree portfast

SW1(config)# interface g1/0/40       ! 仮想化サーバ
SW1(config-if)# switchport mode trunk
SW1(config-if)# spanning-tree portfast trunk

SW1(config)# spanning-tree portfast default
! トランクでない全部のポートに付ける
トランクには portfast だけでは効かない。portfast trunk が必要（構成ガイドの Note）。
PortFastなしPortFastあり
Blocking→Listening 15秒→Learning 15秒→転送（約30秒）すぐ転送
リンクの上下でトポロジー変化（TC）エッジポートなのでTCにならない
  • 使うのは端末1台（PC・サーバ・プリンタ）のポートだけ
  • 初期値は無効
  • PortFastでもBPDUは送る（止めるのはBPDUフィルタ）
  • スイッチがつながれる心配 → BPDUガードと組み合わせる
  • 30秒待つと、DHCPで住所をもらう前にPCがあきらめることがある → PortFastで解決
出典：Cisco Layer 2 Configuration Guide 17.9.x「Configuring Optional Spanning-Tree Features」（PortFast・Enabling PortFast）／ Configuring MSTP（Edge ports・Topology Changes）。DHCPの例はClaudeの補足

BPDUガードとBPDUフィルタ：「止める」か「無視する」か

BPDUガード
SW1(config)# spanning-tree portfast bpduguard default
! PortFastのポート全部に
SW1(config-if)# spanning-tree bpduguard enable
! このポートに（PortFastでなくても効く）
  • BPDUを受け取ったら err-disabled（ポートを止める）
  • 勝手につながれたスイッチによるループやルートの乗っ取りを防ぐ
  • 戻すのは手で：shutdown→no shutdown（または errdisable recovery cause bpduguard）
BPDUフィルタ
設定する場所動き
グローバル
spanning-tree portfast bpdufilter default		PortFastのポートからBPDUを送らない。BPDUを受け取るとPortFastが外れ、フィルタも外れる（ふつうのSTPに戻る）
インタフェース
spanning-tree bpdufilter enable		BPDUを送りも受けもしない＝そのポートのSTPを止めたのと同じ。ループの危険
構成ガイドの注意：インタフェースでBPDUフィルタを有効にするのは、STPを止めるのと同じで、ループの原因になりうる。
出典：Configuring Optional Spanning-Tree Features（Bridge Protocol Data Unit Guard・Bridge Protocol Data Unit Filtering・Enabling BPDU Guard / Filtering）

ルートガードとループガード：どちらも自動で戻る「止め方」

ルートガード spanning-tree guard root
  • 付ける場所：ルートが来てはいけない向きの指定ポート
ループガード spanning-tree guard loop
  • 付ける場所：ルートポート・代替ポート（全体なら spanning-tree loopguard default）
  • 片方向だけ通らないリンク（単方向リンク）のループを防ぐ
ルートガードとループガードは同じポートに同時には付けられない（構成ガイドの Note）。
出典：Configuring Optional Spanning-Tree Features（Root Guard・Loop Guard・Enabling Root Guard の Note）／ Cisco「Enhance STP with Root Guard」（Recovery is automatic）／ Cisco「Understand STP Loop Guard and UDLD Features」

4つのガードを1枚で比べる

機能付ける場所きっかけ結果（状態）戻し方
BPDUガード端末用（PortFast）BPDUが来たerr-disabled手で（shutdown→no shutdown、errdisable recovery）
BPDUフィルタ端末用（PortFast）―BPDUを送らないグローバル：BPDUが来ると外れる
ルートガードルートが来てはいけない向き（指定ポート）より良いBPDUが来たroot-inconsistent自動（来なくなれば）
ループガードルートポート・代替ポートBPDUが来なくなったloop-inconsistent自動（また来れば）
場面→答え会議室のポートに持ち込みスイッチ → BPDUガード／アクセス側にルートを作らせない → ルートガード／光ファイバーの片方向障害 → ループガード／PCをすぐ使えるように → PortFast
ひっかけ「BPDUガードは自動で戻る」×（手で戻す）。「ルートガードは err-disabled にする」×（root-inconsistent）。「BPDUフィルタは安全」×（インタフェースではSTPを止めたのと同じ）。
出典：Configuring Optional Spanning-Tree Features ／ Cisco「Enhance STP with Root Guard」／「Understand STP Loop Guard and UDLD Features」。表はそれらからClaudeがまとめた
