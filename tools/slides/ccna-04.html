論理積（AND）でネットワークを出す
172.16.17.30  = 10101100.00010000.00010001.00011110
255.255.240.0 = 11111111.11111111.11110000.00000000
AND           = 10101100.00010000.00010000.00000000
              = 172.16.16.0
規則：マスクが 1 の所はアドレスのビットをそのまま、0 の所は 0 にする。結果がネットワークアドレス。
プレフィックス長 ＝ マスクの 1 の数。255.255.240.0 は 8＋8＋4＝/20。
出典：Cisco Doc 13788（Any address bits which have corresponding mask bits set to 1 represent the network ID／Sample Exercise 1: subnet = … = 172.16.16.0 … equivalent to when you perform a logical AND between the mask and address）／RFC 4632 3.1（followed by the "/" (slash) character, followed by a decimal value between 0 and 32 that describes the number of significant bits）

クラスと CIDR

クラス最初のオクテット既定のマスク
A1〜127255.0.0.0（/8）

C192〜223255.255.255.0（/24）

表は Doc 13788 の範囲から作った。127 はループバック（第 2 章）。
今は CIDR：クラスという言葉は、CIDR の導入でほとんど使われなくなった（Doc 13788 の注）。マスクはプレフィックス長で自由に決める。
CIDR（Classless Inter-Domain Routing）クラスにしばられず、好きな長さのプレフィックスで割り当てる。目的はアドレスの無駄を減らすことと、インターネットの経路表を小さくすること。
172.16.0.0 255.255.0.0 ＝ 172.16.0.0/16
2 の累乗の大きさなら、1 個から 2^32 個まで、どんな大きさのブロックも表せる（RFC 4632）。
出典：Cisco Doc 13788（Class A … 1.0.0.x - 127.255.255.x／Class B … 128.0.0.x - 191.255.255.x／Class C … 192.0.0.x - 223.255.255.x／Class A: 255.0.0.0 Class B: 255.255.0.0 Class C: 255.255.255.0／These terms are rarely used in the industry anymore because of the introduction of classless interdomain routing (CIDR)／CIDR was introduced in order to improve both address space utilization and routing scalability）／RFC 4632 3.1（any power of two-sized block of between one and 2^32 end system addresses）
第2章

サブネットの切り方

ブロックの大きさで区切る。

CCNA #04 IPv4 アドレスとサブネット1.6

アドレスから「範囲」を出す手順

  1. マスクが 255 でない最後のオクテットを見る（/27 → 4 つめ、224）
  2. ブロックの大きさ ＝ 256 − 224 ＝ 32
  3. そのオクテットの値（37）を超えない、32 の倍数 → 32＝ネットワーク
  4. 次のブロック（64）の 1 つ前 → 63＝ブロードキャスト
  5. その間 → 33〜62 が使える（30 台）
192.168.5.37/27 → .32〜.63（使えるのは .33〜.62）
ブロックの大きさで区切るやり方は、Doc 13788 のサブネットの一覧を早く出すための近道として Claude がまとめた。
使えない 2 つ：ホスト部が全部 0（ネットワークアドレス）と全部 1（ブロードキャスト）。10.255.255.255 あては 10.0.0.0 の全員が受け取る。
出典：Cisco Doc 13788（192.168.5.0 255.255.255.224 host address range 1 to 30 … 192.168.5.32 … 33 to 62 … 192.168.5.224 … 225 to 254）／IP Addressing CG IOS XE 17.x「Configuring IPv4 Addresses」（The all 0's host address cannot be used because it is the same as the network address／The all 1's address is a broadcast address … addressed to 10.255.255.255 will be accepted by every host on network 10.0.0.0）

「5 つ、最大 28 台」を /24 から切る（Doc 13788 の練習）
  1. 5 つ必要 → 2^2＝4 では足りない → s＝3（8 つ）
  2. ホスト部は 8−3＝5 ビット → 2^5−2＝30 台 ≥ 28
  3. マスクは /27（255.255.255.224）
トレードオフ：借りるビットを増やすほどサブネットは増え、1 つのサブネットの台数は減る。
サブネットゼロ（借りたビットが全部 0）は、Cisco では ip subnet-zero で使える。
出典：Cisco Doc 13788（With these three bits, it is possible to create eight subnets. With the other five host ID bits … 30 of which can actually be assigned／16 subnets, each of which can have up to 16 host addresses (14 …)／32 subnets (2 5 ) … 2046 of which could be assigned／Sample Exercise 2: you would need to use three bits … Two bits would only allow you four subnets／The more host bits you use for a subnet mask, the more subnets you have available. 第3章

プライベートアドレス

なぜ、組織の中だけのアドレスが要るのか。

CCNA #04 IPv4 アドレスとサブネット1.7

RFC 1918 の 3 つのブロック

範囲プレフィックス昔のクラスでは
10.0.0.0〜10.255.255.25510/8A が 1 つ
172.16.0.0〜172.31.255.255172.16/12B が 16 個
192.168.0.0〜192.168.255.255192.168/16C が 256 個
いちばん取り違えやすいのは 172：/12 なので 2 つめのオクテットは 16〜31。172.15.x.x・172.32.x.x はプライベートではない。169.254 や 100.64 も RFC 1918 ではない。
なぜ必要か（RFC 1918 2・3）① 世界で一意のアドレスがなくなる心配　② インターネットの経路が増えすぎる心配。外と直接つながらない機器は、一意のアドレスを使わなくてよい。
使い方IANA や登録機関に頼まずに、どの組織でも使える。そのかわり一意なのは組織の中だけ。外とつなぐためにこの範囲が割り当てられることはない。
出典：RFC 1918 2（a concern within the community that globally unique address space will be exhausted. A separate and far more pressing concern is that the amount of routing overhead will grow）・3（10.0.0.0 - 10.255.255.255 (10/8 prefix) … 172.16.0.0 - 172.31.255.255 (172.16/12 prefix) … 192.168.0.0 - 192.168.255.255 (192.168/16 prefix)／a single class A network number … a set of 16 contiguous class B … a set of 256 contiguous class C／without any coordination with IANA or an Internet registry／will never be assigned addresses from the blocks defined above）

プライベートアドレスと外の世界

図は RFC 1918 の説明をもとに Claude が作成。
プライベートグローバル
一意な範囲組織の中だけインターネット全体
もらい方自由に使う登録機関から
外と IP で直接はつながれないつながれる
外のサービスを使うには：中継するゲートウェイを通す（RFC 1918）。今はふつう NAT でグローバルアドレスに変える。
経路の決まり：プライベートの経路は組織の間に広告しない。送信元・宛先がプライベートのパケットも転送しない。
出典：RFC 1918 3（Addresses within this private address space will only be unique within the enterprise／Private hosts … cannot have IP connectivity to any host outside of the enterprise … can still have access to external services via mediating gateways／routing information about private networks shall not be propagated on inter-enterprise links … Routers … of Internet service providers, are expected to be configured to reject (filter out) routing information about private networks）
