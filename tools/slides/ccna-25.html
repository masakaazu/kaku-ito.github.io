部品中身
メソッド何をしたいか（GET・POST・PUT・PATCH・DELETE）
URIどのリソースに（エンドポイント）

URI の読み方と RESTCONF

URI を分けて読む（Cisco の資料の例）
RESTCONF の要点中身
何かHTTPS で、YANG で決めたデータ（設定・状態）を CRUD する（RFC 8040）
データの形式application/yang-data+json か +xml
NETCONF との違いNETCONF は SSH の上で XML。データの考え方は同じ

CRUD と HTTP のメソッド

CRUDメソッド安全べき等
CreatePOST（PUT でも作れる）××
ReadGET○○
UpdatePUT（置き換え）
PATCH（一部）		×PUT ○
PATCH 決まりなし
DeleteDELETE×○
RESTCONF の表：GET＝Read、PATCH＝Update、PUT＝Create or Replace、POST＝Create、DELETE＝消す。
安全（safe）：サーバーの状態を変えない。GET・HEAD・OPTIONS・TRACE。
べき等（idempotent）：同じ要求を何回送っても、1回と同じ結果。PUT・DELETEと安全なメソッド。
落とし穴：POST はべき等ではない。同じ POST を2回送ると、2つ作られることがある。送り直しで安心なのは PUT・DELETE。
出典：RFC 9110 9.2.1・9.2.2（the GET, HEAD, OPTIONS, and TRACE methods are defined to be safe／PUT, DELETE, and safe request methods are idempotent）／RFC 5789（PATCH）／Cisco IOS XE 17.9 Programmability CG「RESTCONF Protocol」（GET Read／PATCH Update／PUT Create or Replace／POST Create or Operations／DELETE Deletes the targeted resource）

PUT と PATCH の違い

PUTPATCH
すること送った内容で作る・まるごと置き換える送った変更だけを当てる
送らなかった部分置き換わるそのまま
べき等○決まりなし
定義RFC 9110RFC 5789
使い分け：「説明だけ変えたい」→ PATCH。「この内容にそっくりそろえたい」→ PUT。
出典：RFC 9110 9.3.4（The PUT method requests that the state of the target resource be created or replaced with the state defined by the representation enclosed in the request message content）／RFC 5789 2.（The PATCH method requests that a set of changes described in the request entity be applied to the resource）

ステータスコード

1けた目種類
1xx情報（続けて処理中）
2xx成功
3xxリダイレクト（別の場所へ）
4xxクライアントの誤り
5xxサーバーの誤り
落とし穴：4xx は要求を送ったこちら側の問題、5xx はサーバー側の問題。
コード意味よくある場面
200 OK成功GET で返った
201 Created成功して新しくできたPOST で作った
204 No Content成功、返す中身なしDELETE のあと
400 Bad Request要求の書き方がおかしいJSON の文法の誤り
401 Unauthorized正しい認証の情報がないトークンの期限切れ
403 Forbidden分かったが断る権限が足りない
404 Not Foundリソースが見つからないURI の打ち間違い
500サーバーの中で思わぬ問題サーバーの不具合
「よくある場面」は Claude が書いた例。
出典：RFC 9110 15.（1xx (Informational) … 2xx (Successful) … 3xx (Redirection) … 4xx (Client Error) … 5xx (Server Error)）・15.3.1 200・15.3.2 201（resulted in one or more new resources being created）・15.3.5 204・15.5.1 400・15.5.2 401（lacks valid authentication credentials）・15.5.4 403（understood the request but refuses to fulfill it）・15.5.5 404・15.6.1 500

REST API の認証

方式送るもの注意
Basic「ユーザー名:パスワード」を Base64暗号化ではない。HTTPS と使う
トークン先にもらったトークン（Bearer・X-Auth-Token）持つ人なら誰でも使える。期限あり
API キー前もって発行した鍵パスワードと同じに扱う。ソースに書かない
OAuth 2.0持ち主が許可した範囲の権限アプリにパスワードを渡さない
Meraki のダッシュボード API は、API キー（管理者の権限で動く）と OAuth（アプリの連携）の2つ。どちらも Authorization: Bearer で送る。
Catalyst Center のトークン認証
出典：RFC 7617（credentials as user-id/password pairs, encoded using Base64／not considered to be a secure method … unless used in conjunction with … TLS）／RFC 6750（any party in possession of a bearer token … can use it）／RFC 6749（enables a third-party application to obtain limited access to an HTTP service）／Cisco DevNet「Catalyst Center API: Authentication」（POST /dna/system/api/v1/auth/token／X-Auth-Token／The lifetime of a token is 60 minutes … returns a 401 UNAUTHORIZED）／Meraki Dashboard API v1「Authorization」（Admin-scoped access - Uses API keys／OAuth／Bearer Auth using the standard Authorization header）

JSON の部品を読む

Claude が作成した例。
部品決まり
オブジェクト{ } の中に「名前: 値」を , で並べる。順番に意味はない
配列[ ] の中に値を , で並べる。順番に意味がある

組み立てる型オブジェクト・配列の2つ
空白・改行意味はない（読みやすくするため）
出典：RFC 8259（JSON can represent four primitive types (strings, numbers, booleans, and null) and two structured types (objects and arrays)／An object is an unordered collection of zero or more name/value pairs, where a name is a string／An array is an ordered sequence of zero or more values／Insignificant whitespace is allowed／The names within an object SHOULD be unique）

よくある JSON の誤りと、XML・YAML

誤り正しくは
'hostname'"hostname"（ダブルクォート）
True・NULLtrue・null（小文字だけ）
[10, 20, 30,]最後の値のあとに , を付けない
"mtu" 1500名前と値の間に :
"mtu": 01500数値の頭に余計な 0 を付けない
落とし穴："10" は文字列、10 は数値。"true" も文字列。
同じ「VLAN 10・名前 SALES」を3つの形式で（Claude が作成）
形式書き方
JSON{"vlan": {"id": 10, "name": "SALES"}}
XML<vlan><id>10</id><name>SALES</name></vlan>
YAMLvlan:
  id: 10
  name: SALES
見分け方：{ } と [ ] → JSON、<タグ> → XML、字下げと「名前: 値」 → YAML（Ansible のプレイブック）。RESTCONF は JSON か XML。
出典：RFC 8259（A string begins and ends with quotation marks／The literal names MUST be lowercase／array = begin-array [ value *( value-separator value ) ] end-array／name-separator = ws %x3A ws ; : colon／Leading zeros are not allowed）／Ansible「YAML Syntax」（A dictionary is represented in a simple key: value form）／IOS XE 17.9 Programmability CG「RESTCONF Protocol」（Application/YANG-Data+XML OR Application/YANG-Data+JSON）
