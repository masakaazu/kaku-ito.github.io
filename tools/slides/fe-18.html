18-1 システム化計画計画を立てる

システム化構想System Concept
経営の課題をもとに、どの業務をどうシステム化するかの全体像を描くこと
システム化計画System Planning
システム化の範囲・スケジュール・費用・体制などを決めること
投資対効果ROI / Return On Investment
投資した金額に対して、どれだけの利益が得られたかを表す指標
ポイント利益 ÷ 投資額 × 100（％）
費用対効果分析Cost-Effectiveness Analysis
かかる費用と得られる効果を比べて、投資するかを判断すること

18-2 要件定義要件を決める

業務要件Business Requirements
システム化する業務の内容や手順など、業務の面から求められること
要件定義Requirements Definition
利用者の要望を整理し、システムが満たすべき機能や性能を決めること
ポイント発注者と開発者が合意する
機能要件Functional Requirements
システムが「何をするか」についての要件
例注文を登録できる
非機能要件Non-functional Requirements
性能・信頼性・セキュリティなど、機能以外の要件
例応答時間、稼働率
利害関係者要件Stakeholder Requirements
利用者や発注者など、関係する人たちが求めること

18-3 調達計画・実施調達

ベンダVendor
システムやサービスを開発・提供する側の企業
ポイント発注する側はユーザ企業という
RFIあーるえふあい / Request For Information
ベンダに、製品や技術、実績などの情報の提供を頼む文書。情報提供依頼書
Request＝依頼／For＝〜のための／Information＝情報
RFPあーるえふぴー / Request For Proposal
ベンダに、システムの要件を示して具体的な提案を頼む文書。提案依頼書
Request＝依頼／For＝〜のための／Proposal＝提案
RFQあーるえふきゅー / Request For Quotation
ベンダに見積りを頼む文書。見積依頼書
Request＝依頼／Quotation＝見積り
提案書Proposal
RFPを受けたベンダが作る、システムの具体案をまとめた文書
評価基準Evaluation Criteria
提案を公平に比べるための基準
ポイントRFPを出す前に決めておく
