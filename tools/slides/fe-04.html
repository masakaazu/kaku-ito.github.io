4-1 システムの構成処理形態

集中処理しゅうちゅうしょり / Centralized Processing
1台の大きなコンピュータですべて処理する形態
ポイント管理しやすいが、止まると全体が止まる
分散処理ぶんさんしょり / Distributed Processing
複数のコンピュータで処理を分け合う形態
ポイント一部が止まっても続けやすいが、管理が複雑
バッチ処理一括処理 / Batch Processing
データを一定期間ためて、まとめて処理する方式
例月末の給与計算
リアルタイム処理Real-time Processing
データが発生したらすぐに処理する方式
例座席予約、銀行ATM
クライアントサーバシステムClient Server System
サービスを頼む側（クライアント）と提供する側（サーバ）に役割を分けたシステム
ポイント2層はクライアントがアプリの処理も持つ。3層はプレゼンテーション層・アプリケーション層・データ層に分ける
3層クライアントサーバシステム3-tier Client Server
画面（プレゼンテーション層）、業務処理（アプリケーション層）、データ管理（データ層）の3つに分けた構成
ポイント業務処理はアプリケーションサーバが担当する。修正の影響を小さくできる
基本情報 システム構成要素4

4-1 システムの構成処理形態・システムの構成方式

シンクライアントThin Client
端末には画面表示と入力だけをさせ、処理やデータはサーバに置く方式
ポイント端末にデータが残らないので情報漏えいを防ぎやすい
VDIぶいでぃーあい / Virtual Desktop Infrastructure
サーバ上の仮想マシンでデスクトップ環境を動かし、端末に画面だけ送る仕組み
ポイントクラウド事業者が提供する形態はDaaS
Virtual＝仮想の／Desktop＝デスクトップ環境／Infrastructure＝基盤
ピアツーピアPeer to Peer
対等な関係のコンピュータどうしが直接データをやり取りする形態
ポイントサーバを置かない
プル型・プッシュ型Pull, Push
プル型は受け手が自分から情報を取りに行く方式、プッシュ型は送り手が受け手に届ける方式
例Webページの閲覧はプル型、通知はプッシュ型
デュアルシステムDual System
2組のシステムで同じ処理を同時に行い、結果を照合する方式
ポイント信頼性は高いが費用もかかる
デュプレックスシステムDuplex System
1組を本番で動かし、もう1組を障害に備えた予備にする方式
ポイント予備の待ち方でホットスタンバイ・コールドスタンバイに分かれる
基本情報 システム構成要素5

4-1 システムの構成システムの構成方式

クラスタCluster
複数のコンピュータをつないで、1台のシステムのように動かす構成
ポイント負荷分散や、障害時の切替え（フェールオーバ）に使う
スケールアウトScale Out
サーバの台数を増やして処理能力を上げる方法
ポイント負荷分散しやすい処理に向く
スケールアップScale Up
1台のサーバのCPUやメモリを強くして処理能力を上げる方法
仮想化かそうか / Virtualization
1台の物理的なコンピュータの上で、複数の仮想的なコンピュータを動かす技術
ポイントライブマイグレーションは、動いたまま別の物理サーバへ移すこと
コンテナ型仮想化Container
OSを共有して、アプリごとに分けた実行環境（コンテナ）を動かす方式
ポイント仮想マシンより軽く、すぐ起動する
マイクロサービスMicroservices
システムの機能を、小さく独立したサービスに分けて組み合わせる構成
ポイント1つにまとめた構成はモノリシック。マイクロサービスは部分ごとに変更しやすい

4-1 システムの構成システムの構成方式・クラウドサービス

RAIDれいど / Redundant Arrays of Inexpensive Disks
複数のディスクを組み合わせて、速さや信頼性を高める技術
ポイントRAID 0＝ストライピング（分散して速く、冗長なし）、RAID 1＝ミラーリング（同じデータを複数に）、RAID 5＝データとパリティを分散
Redundant＝冗長な／Arrays＝並べたもの／Inexpensive Disks＝安価なディスク
NASなす / Network Attached Storage
ネットワークに直接つなぐファイルサーバ専用の記憶装置
Network＝ネットワーク／Attached＝接続された／Storage＝記憶装置
クラウドコンピューティングCloud Computing
サーバやソフトウェアを、インターネット経由で必要な分だけ使う形態
ポイント自社で持つのはオンプレミス
SaaSさーす / Software as a Service
アプリケーションまでを事業者が用意し、利用者はそのまま使うサービス
例Webメール、オンライン表計算
Software＝ソフトウェア／as a Service＝サービスとして

4-1 システムの構成クラウドサービス

PaaSぱーす / Platform as a Service
OSやミドルウェアなど、アプリを動かす基盤を提供するサービス
ポイント利用者はアプリを作って載せる
Platform＝実行基盤／as a Service＝サービスとして
IaaSいあーす / Infrastructure as a Service
サーバ・ストレージ・ネットワークなどの設備を提供するサービス
ポイントOSから上は利用者が管理する
Infrastructure＝基盤設備／as a Service＝サービスとして
DaaSだーす / Desktop as a Service
仮想デスクトップ環境をクラウドで提供するサービス
Desktop＝デスクトップ環境／as a Service＝サービスとして
エッジコンピューティングEdge Computing
利用者や機器の近くにサーバを置いて処理する方式
ポイント遅延を減らし、通信量を抑えられる

4-2 システムの評価指標性能・信頼性

スループットThroughput
単位時間あたりに処理できる仕事の量
例1秒あたりの処理件数
レスポンスタイム応答時間 / Response Time
要求を出し終えてから、最初の応答が返ってくるまでの時間
ポイント主にオンライン処理で使う
ターンアラウンドタイムTurnaround Time
処理を依頼してから、すべての結果を受け取るまでの時間
ポイント主にバッチ処理で使う
ベンチマークBenchmark
標準的なプログラムを実行して、性能を比べる方法
例SPEC、TPC
キャパシティプランニングCapacity Planning
将来の利用量を見込んで、必要な処理能力や設備を計画すること
RASISらしす
システムを評価する5つの観点。信頼性・可用性・保守性・保全性（完全性）・安全性
Reliability＝信頼性／Availability＝可用性／Serviceability＝保守性／Integrity＝保全性／Security＝安全性

4-2 システムの評価指標信頼性・信頼性設計

MTBFえむてぃーびーえふ / Mean Time Between Failures
故障してから次に故障するまでの平均時間。平均故障間隔
ポイント長いほど信頼性が高い。稼働時間の合計 ÷ 故障回数
Mean Time＝平均時間／Between Failures＝故障と故障の間の
MTTRえむてぃーてぃーあーる / Mean Time To Repair
故障してから修理が終わるまでの平均時間。平均修復時間
ポイント短いほど保守性が高い
Mean Time＝平均時間／To Repair＝修理までの
稼働率かどうりつ / Availability
システムが使える状態にある時間の割合
例MTBF 3,600時間・MTTR 900時間なら 3,600÷4,500＝0.8
故障率こしょうりつ / Failure Rate
単位時間あたりに故障する割合。1 ÷ MTBF
バスタブ曲線Bathtub Curve
時間と故障率の関係を表す、浴槽の形の曲線
ポイント初期故障期（だんだん減る）→ 偶発故障期（一定）→ 摩耗故障期（増える）
フォールトアボイダンスFault Avoidance
品質の高い部品を使うなどして、故障そのものが起きないようにする考え方

4-2 システムの評価指標信頼性設計

フォールトトレランスFault Tolerance
故障が起きても、システム全体としては動き続けるようにする考え方
ポイント冗長化が代表的な方法
フェールセーフFail Safe
故障したときに、安全な側に止まるようにする設計
例信号機の故障時はすべて赤にする
フェールソフトFail Soft
故障した部分を切り離し、機能を落としてでも動き続ける設計
フールプルーフFool Proof
人が誤った操作をしても、危険が起きないようにする設計
例ドアが閉まらないと動かない電子レンジ
フォールトマスキングFault Masking
故障の影響を、冗長な部分で打ち消して外に見せない仕組み
バックアップBackup
障害に備えてデータを複製しておくこと
ポイントフル＝全部、差分＝最後のフルバックアップ以降の変更、増分＝直前のバックアップ以降の変更
