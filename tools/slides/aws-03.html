セキュリティグループとネットワーク ACL

特性セキュリティグループネットワーク ACL
効く単位インスタンス（リソース）レベルサブネットレベル
ルール許可だけ許可と拒否
評価のしかたすべてのルールを見てから決める番号の小さい順に見て、最初に一致したもので決める
戻りの通信自動で許可（ステートフル）明示的に許可が必要（ステートレス）
付け方1つのリソースに複数付けられる1つのサブネットに一度に1つだけ（1つの ACL は複数のサブネットに付けられる）
AWS の位置づけ主な手段きめの粗い補助の制御。特定の通信を拒否する、サブネットのガードレール
覚え方：SG は「人ごとの名札チェック（許可リスト）」、NACL は「建物の入口の番号順の関所」。両方を通らないと届かない。
どちらでも止められない通信：Route 53 Resolver（VPC＋2 のアドレス）との DNS や、インスタンスメタデータなど。DNS の問い合わせを絞るなら Route 53 Resolver DNS Firewall。
出典：Amazon VPC のインフラストラクチャセキュリティ（比較表・「ステートレスできめの粗いネットワーク制御を行うことができます」）／ネットワーク ACL（「サブネットは一度に 1 つのネットワーク ACL にのみ関連付けることができます。」）

ルール番号：小さい順、最初の一致で決まる

例：Web サーバーのサブネットのインバウンド
番号種類・ポート送信元動作
90すべて198.51.100.0/24拒否
100TCP 4430.0.0.0/0許可
110TCP 1024-655350.0.0.0/0許可
*すべて0.0.0.0/0拒否
ルールは Claude が作った例。110 は、サーバーが外へ始めた通信の戻り（一時ポートあて）を通すためのもの。
届いた通信結果
198.51.100.9 から 44390 で拒否（100 は見ない）
203.0.113.5 から 443100 で許可
203.0.113.5 から 22どれにも一致せず * で拒否
拒否は小さい番号に。許可 100・拒否 200 の順だと、100 に先に一致して拒否が効かない。IAM の「明示的な Deny が勝つ」とは考え方が違う。
番号は 1～32,766。後から間に挟めるよう、10 や 100 おきに付けるのが AWS のおすすめ。* のルールは消せない。
出典：ネットワーク ACL ルール（「ルールは、最も低い番号のルールから評価されます。ルールがトラフィックに一致すると、それと相反するより高い数値のルールの有無にかかわらず、すぐに適用されます。」）

ステートレスと一時ポート

一時ポートを使う側範囲
多くの Linux カーネル32768～61000

Firewall Manager・Network Firewall・DNS Firewall

サービス何をするか本番の言い回し
AWS Firewall ManagerWAF・Shield Advanced・セキュリティグループ・ネットワーク ACL・Network Firewall・DNS Firewall のルールを、組織の複数のアカウントとリソースにまとめて適用。新しいアカウントやリソースにも自動で付ける「組織の全アカウントで」「新しいリソースにも自動で」
AWS Network FirewallVPC のための、ステートフルなマネージドのファイアウォール兼 IDS/IPS。VPC の境界で通信をフィルター。Suricata 互換のルール・ドメイン名のリスト・ディープパケットインスペクション「VPC から出る通信を許可したドメインだけに」「VPC の出入りを中身まで検査」
Route 53 Resolver DNS FirewallVPC の中から Route 53 Resolver に送る DNS の問い合わせをフィルター「悪いドメインの名前解決を止める」
WAF との違い：WAF は CloudFront・ALB などに届く HTTP(S) を見る。Network Firewall は VPC の出入りの通信全般（HTTP 以外も）を見る。
Firewall Manager は「配る係」：自分では通信を調べない。実際に止めるのは WAF や SG など。
出典：AWS Firewall Manager（「アカウントに追加されたリソースへの保護を自動的に追加します」）／What is AWS Network Firewall?（「Use custom lists of known bad domains to limit the types of domain names that your applications can access.」）
