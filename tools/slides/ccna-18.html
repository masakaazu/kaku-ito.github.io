第1章

SNMP

マネージャーが機器の値を読み書きし、機器は異変を自分から知らせる。

CCNA #18 SNMP・syslog・TFTP/FTP4.4

登場人物：マネージャー・エージェント・MIB

名前役目
マネージャー機器に問い合わせて値を集め、グラフや警告にする（NMS）
エージェント機器の中で動き、MIB の値で答える・値を変える・通知を送る
MIB管理できる情報の一覧。木の形で、各変数を OID（例 1.3.6.1.2.1.1.5＝sysName）で指す
初期値：Cisco の機器では SNMP エージェントは無効。snmp-server community・host・user などを1つ入れると有効になり、UDP 161・162 が開く。
出典：Network Management CG IOS XE 17.9（Catalyst 9300）「Configuring SNMP」（The SNMP system consists of an SNMP manager, an SNMP agent, and a MIB／Default SNMP Configuration：SNMP agent Disabled／one of the following … to open SNMP UDP ports 161 and 162）／RFC 3417（3.2：UDP port 161・162）。図はClaudeが作った例

操作と通知：だれが、どちらへ

操作向き何をするか
get-requestM → A指定した変数の値を読む
get-next-requestM → A次の変数を読む（名前を知らなくても順にたどれる）
get-bulk-requestM → A表などをまとめて読む。v2c 以降
set-requestM → A値を書き換える（RW が要る）
responseA → Mget・set への答え
trapA → M異変を自分から知らせる。返事なし
informA → M異変を知らせ、マネージャーが返事。v2c 以降
略M＝マネージャー、A＝エージェント
trap と inform
trapinform
受け取った返事なしあり（response）
届かなかったらわからない送り直す
機器の負荷小さい大きい（返事までメモリに残る）
SNMPv1あるない
通知の例：ポートのアップ・ダウン、スパニングツリーの変化、認証の失敗、再起動。
出典：IOS XE 17.9「Configuring SNMP」SNMP Manager Functions・SNMP Notifications（get-request … get-next-request … get-bulk-request … set-request … trap／The get-bulk command only works with SNMPv2 or later／informs are more likely than traps to reach … consume more resources／SNMPv1 does not support informs）／RFC 3416

バージョンとセキュリティ：v2c はコミュニティ名、v3 はユーザー

版レベル認証暗号化
v1noAuthNoPrivコミュニティ名なし
v2cnoAuthNoPrivコミュニティ名なし
v3noAuthNoPrivユーザー名だけなし
v3authNoPrivHMAC-SHA などなし
v3authPrivHMAC-SHA などAES など
語auth＝authentication（認証）、priv＝privacy（中身を隠す＝暗号化）
コミュニティ名（v1・v2c）
snmp-server community MyRO123 RO   ! 読むだけ
snmp-server community MyRW456 RW   ! 読み書き
  • コミュニティ名は合言葉。マネージャーと同じ文字列ならアクセスできる
  • 暗号化されずに流れるので、のぞかれると読まれる。public・private のような初期値の名前は使わない
  • v2c の c は community。v1 に get-bulk・inform・細かいエラーを加えた版
  • 安全にしたいなら v3 の authPriv
出典：IOS XE 17.9「Configuring SNMP」（SNMP Versions の表：noAuthNoPriv・authNoPriv・authPriv／community strings … function as embedded passwords／Read-only (RO)・Read-write (RW)）／Cisco「Configure SNMP Community Strings」（snmp-server community public RO／private RW）

SNMP の設定例

! v2c：読むだけのコミュニティと通知の宛先
R1(config)#snmp-server community MyRO123 RO
R1(config)#snmp-server location Tokyo-DC1 Rack3
R1(config)#snmp-server contact noc@example.com
R1(config)#snmp-server enable traps
R1(config)#snmp-server host 10.1.99.20 version 2c MyRO123

! v3：authPriv のグループとユーザー
R1(config)#snmp-server group ADMIN v3 priv
R1(config)#snmp-server user nms1 ADMIN v3 auth sha AuthPass1 priv aes 128 PrivPass1
snmp-server communityv1・v2c の合言葉と RO／RW
snmp-server location／contact機器の場所と連絡先（MIB の値になる）
snmp-server enable traps送る通知の種類を有効にする
snmp-server host通知の宛先・版・コミュニティ名（ポートを省略すると 162）
snmp-server group … v3 privv3 の authPriv のグループ
読み方のコツ：「community＝v2c の合言葉」「host＝通知の宛先」「enable traps＝何を送るか」の3つに分ける。
出典：IOS XE 17.9「Configuring SNMP」（snmp-server contact・location／snmp-server enable traps／snmp-server host 192.180.1.27 version 2c public／udp-port … The default is 162／snmp-server group … v3 … priv／snmp-server user）。設定はClaudeが作った例

syslog

機器のログを、重大度とファシリティを付けて、画面・メモリ・サーバーへ送る。

CCNA #18 SNMP・syslog・TFTP/FTP4.5

重大度レベル 0〜7：数字が小さいほど重大

#キーワード意味
0emergencies機器が使えない
1alertsすぐ対処が要る
2critical重大な状態
3errorsエラー
4warnings警告
5notifications正常だが大事なこと
6informational情報
7debuggingデバッグ
logging trap 4 で送られる範囲
コンソール・vty の初期値debugging（7 まで全部）
syslog サーバーの初期値informational（6 まで）
サーバーへのファシリティlocal7
名前で書いても数字でも同じ：logging trap warnings ＝ logging trap 4。
出典：RFC 5424（Table 2 Syslog Message Severities：0 Emergency … 7 Debug）／System Management CG IOS XE 17.9「Configuring System Message Logs」（Console severity Debugging／Server facility Local7／Server severity Informational／numerically lower levels）

ログの形を読む：%ファシリティ-レベル-ニーモニック

000123: *Nov  7 10:15:03.158: %LINEPROTO-5-UPDOWN: Line protocol on Interface GigabitEthernet0/1, changed state to down
部分意味付ける設定
000123連番service sequence-numbers
*Nov 7 10:15:03.158時刻（* は時計が NTP で合っていない印）service timestamps
LINEPROTOファシリティ：何に関するログか―
5重大度（notifications）―
UPDOWNニーモニック：メッセージの短い名前―
よく見るログ
%LINK-3-UPDOWN物理リンクの up／down（errors）
%LINEPROTO-5-UPDOWN回線プロトコルの up／down
%SYS-5-CONFIG_Iだれかが設定を変えた
2つの軸：ファシリティ＝何のログか、重大度＝どれだけ重大か。
出典：IOS XE 17.9「Configuring System Message Logs」System Log Message Format（seq no:timestamp: %facility-severity-MNEMONIC:description／%LINK-3-UPDOWN・%LINEPROTO-5-UPDOWN・%SYS-5-CONFIG_I の例）／Basic System Management CR（show clock：* Time is not authoritative）。ログはその形式にそろえてClaudeが作った例

送り先と設定：画面・メモリ・サーバー

送り先レベルを決めるポイント
コンソールlogging console初期値で出る（debugging）
Telnet・SSHlogging monitor見るには terminal monitor（セッションごと）
メモリlogging bufferedshow logging で見る。再起動で消える
syslog サーバーlogging trap宛先は logging host。UDP 514。初期値 informational
R1(config)#service timestamps log datetime msec
R1(config)#logging buffered 16384
R1(config)#logging host 10.1.99.30
R1(config)#logging trap warnings
R1(config)#line console 0
R1(config-line)#logging synchronous
R1#terminal monitor
  • logging trap は syslog サーバーへのレベル。SNMP の trap とは別物
  • logging synchronous：ログが出ても打ちかけのコマンドを出し直す
  • 時刻をそろえるには NTP（#16）も要る
出典：IOS XE 17.9「Configuring System Message Logs」（logging buffered … default 102400 bytes … lost unless … saved to flash／logging host … UNIX syslog server／terminal monitor … for each session／logging console・monitor・trap の初期値／logging synchronous）／RFC 3164（UDP port … 514）。設定はClaudeが作った例
第3章

TFTP と FTP

設定や OS のファイルを運ぶ。簡単な TFTP と、ログインして操作する FTP。

CCNA #18 SNMP・syslog・TFTP/FTP4.9

TFTP と FTP を比べる

項目TFTPFTP
運ぶものUDP 69TCP 21（制御）＋データ
認証なしユーザー名・パスワード
暗号化なしなし（パスワードも平文）
できること読む・書くだけ一覧・削除・名前の変更なども
抜けの直し方512 バイトごとに ACKTCP にまかせる
向く用途小さなファイル・機器の設定の保存大きなファイル・いろいろな操作
TFTP の lock step（Claudeが作った例）
出典：RFC 1350（It cannot list directories, and currently has no provisions for user authentication／fixed length blocks of 512 bytes … must be acknowledged … before the next packet／A data packet of less than 512 bytes signals termination／TID 69）／RFC 959（port 21）

FTP は2本のコネクション：アクティブとパッシブ

  • 制御のコネクション（TCP 21）でログインやコマンドをやりとりし、つないだまま
  • データのコネクションで、ファイルや一覧を運ぶ。運ぶたびに張る
  • アクティブはサーバーから張るので、クライアント側のファイアウォールや NAT で止められやすい
  • パッシブはいつもクライアントから張るので、越えやすい
症状で見分ける：ログインはできるのに一覧や転送だけ失敗する ― データのコネクションが止められている。パッシブにすると直ることが多い。
出典：RFC 959（3.2：server-process default data port … L-1／4.1.2：PASSIVE (PASV) … "listen" on a data port … wait for a connection rather than initiate one／5.2：The server … shall "listen" on Port L／service port 21）。図はClaudeが作った例

機器でファイルを運ぶ：copy 元 先

! 今の設定を TFTP サーバーへ保存
R1#copy running-config tftp://10.1.99.40/r1-confg

! OS を FTP サーバーからフラッシュへ
R1#copy ftp://admin:Pass1@10.1.99.40/c9300.bin flash:

! 同じことを SCP で（認証＋暗号化）
R1#copy scp://admin@10.1.99.40/c9300.bin flash:
tftp:tftp://場所/ファイル（ユーザー名なし）
ftp:ftp://ユーザー:パスワード@場所/ファイル
scp:scp://ユーザー@場所/ファイル（SSH の上）
3つを比べる
認証暗号化
TFTPなしなし
FTPありなし
SCPありあり
順番：copy は「元 → 先」。copy tftp: running-config は逆向き（サーバーの設定を読み込む）。
関連SCP には SSH の設定が要る（#11）
出典：System Management CG IOS XE 17.9「Working with the Flash File System」Copying Files（copy source-url destination-url／FTP—ftp:[[//username [:password]@location]/directory]/filename／TFTP—tftp:[[//location]/directory]/filename／SCP—scp:…）。設定はClaudeが作った例

よくあるひっかけ

よくある思い込み正しくは
trap はマネージャーからエージェントへ送るエージェント → マネージャー。返事なし
trap と inform は同じinform は返事あり・送り直しあり。v1 にはない
SNMP は TCP 161／162UDP。問い合わせ 161、通知 162
v2c のコミュニティ名は暗号化される平文。暗号化は v3 の authPriv
syslog のレベルは数字が大きいほど重大小さいほど重大。0 emergencies、7 debugging
logging trap 4 は 4〜7 を送る0〜4 を送る
SSH で入れば自動でログが流れるterminal monitor が要る
TFTP はユーザー名とパスワードで認証するTFTP は認証なし・UDP 69。認証するのは FTP
FTP は暗号化して安全FTP は平文。安全に運ぶなら SCP（や SFTP）
