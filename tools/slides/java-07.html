第1章

while 文と do-while 文

先に調べれば 0 回もありうる。後で調べれば必ず 1 回。

Java Silver #07 繰り返し試験内容 3

前判定と後判定

流れの図（Claude が作成）
i = 5 のとき（Claude が作成）
int i = 5;
while (i < 3) {
  System.out.print("w ");   // 0 回
}
do {
  System.out.print("d ");   // 1 回
} while (i < 3);
d
コード（i は 0 から）結果（JDK 17）
while (i++ < 3) print(i);1 2 3、あとの i は 4
do print(i); while (++i < 3);0 1 2、あとの i は 3
i++ < 3 は増やす前の値で比べる。比べた結果が false の回も i++ は実行されるので、最後に 1 つ多くなる。
出典：JLS 14.12 The while Statement（executes an Expression and a Statement repeatedly until the value of the Expression is false）・14.13 The do Statement（DoStatement: do Statement while ( Expression ) ;）／結果は JDK 17 で確かめたもの

範囲は { } で決まる ― 無限ループ

字下げにだまされる例（Claude が作成）
int i = 0;
while (i < 3)
  System.out.print(i);
  i++;          // ループの外！
000000000000000000 …（止まらない）
コンパイラから見た形
while (i < 3) { System.out.print(i); }
i++;             // ここには来ない
わざと終わらないループ抜け方
while (true) { … }中で break・return
for (;;) { … }中で break・return
do { … } while (true);中で break・return
無限ループもコンパイルはできる。i < 3 は定数式ではないので、コンパイラは「いつか false になるかもしれない」と扱う。問題では「無限ループになる」が答えの選択肢になる。
条件の型：boolean か Boolean だけ。while (1) や while (x = 1)（x は int）はコンパイルエラー（#06 の if と同じ）。
出典：JLS 14.12（WhileStatement: while ( Expression ) Statement／The Expression must have type boolean or Boolean, or a compile-time error occurs）・14.14.1（If the Expression is not present … the contained Statement is executed）／結果は JDK 17 で確かめたもの

到達できない文はコンパイルエラー

コード結果（JDK 17）
while (false) { x++; }unreachable statement
for (int i = 0; false; i++) { }unreachable statement
while (true) { } のあとの文unreachable statement
break; の直後の文unreachable statement
final boolean F = false; while (F)unreachable statement
if (false) { x++; }OK（if は例外）
boolean b = false; while (b)OK（b は定数でない）
for (int i = 0; i < 0; i++)OK（0 回まわるだけ）
while (true) { if (…) break; } のあとOK（break で抜けられる）
判断に使うのは「定数式」だけ。true・false のリテラルや、final で定数に初期化した変数の値を見る。ふつうの変数は値を追いかけない。
if (false) が許される理由：JLS は「デバッグ用の切りかえ」に使えるよう、if だけはわざと到達できるものとして扱うと説明している。
static final boolean DEBUG = false;
if (DEBUG) { System.out.println("x = " + x); }  // OK
「定数の true の while で、到達できる break がない」ときは、while 文そのものが正常に終わらないので、そのあとの文が到達不能になる。
出典：JLS 14.22 Unreachable Statements（It is a compile-time error if a statement cannot be executed because it is unreachable／The contained statement is reachable iff the while statement is reachable and the condition expression is not a constant expression whose value is false／if (false) { x=3; } does not result in a compile-time error）／JLS 15.29 Constant Expressions／結果は JDK 17 で確かめたもの
第2章

for 文

初期化は 1 回、更新は本体のあと毎回。

Java Silver #07 繰り返し試験内容 3

for 文の実行の順番

for (初期化; 条件; 更新) 本体（Claude が作成）
順番を表示で確かめる（Claude が作成）
int i = 0;
for (System.out.print("init ");
     i < 2;
     System.out.print("upd ")) {
  System.out.print("body" + i + " ");
  i++;
}
init body0 upd body1 upd
最後の本体のあとも更新は実行される。そのあと条件で false になって終わる。だから「for の前で宣言した i」は、終わったとき条件が false になった値（例では 2）。
出典：JLS 14.14.1.1 Initialization of for Statement・14.14.1.2 Iteration of for Statement（If execution of the Statement completes normally, then … the ForUpdate … are evaluated in sequence from left to right … Second, another for iteration step is performed）／結果は JDK 17 で確かめたもの

ループ変数のスコープと入れ子のループ

コード結果（JDK 17）

スコープ：初期化部で宣言した変数は、条件・更新・本体の中だけで使える。ループのあとで値を使いたいなら、for の前で宣言する。
内側は外側の 1 回ごとに最初から（Claude が作成）

拡張 for 文

配列か Iterable を、先頭から 1 つずつ。

Java Silver #07 繰り返し試験内容 3

拡張 for のしくみと使える型

配列の拡張 for は、次の基本の for と同じ意味（JLS 14.14.2 の説明を Claude が書き直した）
for (int x : a) { … }
// ↓ と同じ
for (int #i = 0; #i < a.length; #i++) {
  int x = a[#i];     // 要素のコピー
  …
}
#i はプログラムからは見えない名前。List なら iterator() の hasNext()・next() で同じことをする。
ループ変数は毎回新しく宣言される。だから final や var を付けられる。代入しても元の配列やリストは変わらない（#04）。

Stringfor-each not applicable to expression type
StringBuilder・intfor-each not applicable
s.toCharArray()OK（char[]）
: の左結果（JDK 17）
var x・final int xOK
int n（List<Integer> から）OK（アンボクシング）
宣言済みの x だけbad initializer for for-loop
出典：JLS 14.14.2 The enhanced for statement（The type of the Expression must be an array type or a subtype of the raw type Iterable, or a compile-time error occurs）／Java SE 17 API java.lang.Iterable（Implementing this interface allows an object to be the target of the enhanced for statement）／結果は JDK 17 で確かめたもの
第4章

break・continue・ラベル

ラベルなしはいちばん内側。外へ行くならラベル。

Java Silver #07 繰り返し試験内容 3

break と continue の行き先

飛ぶ先（Claude が作成）
for (int i = 0; i < 5; i++) {
  if (i == 1) continue;   // 1 を飛ばす
  if (i == 3) break;      // 3 で抜ける
  System.out.print(i + " ");
}
0 2
こんなとき結果（JDK 17）
入れ子の内側で break;内側だけ抜け、外側は続く
ループの中の switch で break;switch だけ抜ける
while で更新が continue の後ろ無限ループになりうる
break; の直後の文unreachable statement
出典：JLS 14.15 The break Statement（A break statement with no label attempts to transfer control to the innermost enclosing switch, while, do, or for statement）・14.16 The continue Statement（the continue target … immediately ends the current iteration and begins a new one）／結果は JDK 17 で確かめたもの

ラベル付き break と continue

outer:
for (int i = 0; i < 3; i++) {
  for (int j = 0; j < 3; j++) {
    if (j == 1) continue outer;
    if (i == 2) break outer;
    System.out.print(i + "" + j + " ");
  }
}
00 10
ij起きること
0000 を表示
01continue outer → i++ へ
1010 を表示
11continue outer → i++ へ
20break outer → 全部を抜ける
コード結果（JDK 17）
loop: if (true) { … break loop; }OK（if を抜ける）
loop: if (true) { continue loop; }not a loop label: loop
ループの中の switch で break a;（a は for）for ごと抜ける
break ラベル：ラベルの付いた文を抜ける。その文はループでなくてもよい。
continue ラベル：ラベルの付いたループの次の回へ。ラベルはループ（while・do・for）に付いていなければならない。
Java に goto はない。ラベルを使うのは break と continue だけ。ラベル名は変数名と同じでもよい。
出典：JLS 14.7 Labeled Statements（Unlike C and C++, the Java programming language has no goto statement）・14.15（In this case, the break target need not be a switch, while, do, or for statement）・14.16（the continue target must be a while, do, or for statement, or a compile-time error occurs）／結果は JDK 17 で確かめたもの

問われ方とまちがえやすい点

こう聞かれたら答えの考え方
ループの表示結果変数の値を 1 回ずつ表に書く。条件で比べる値（i++ か ++i か）と、ループ後の値を分けて考える
while と do-while の差最初から false なら while は 0 回、do-while は 1 回。do-while の最後の ;
字下げした 2 行{ } がなければ 1 文目だけがループの中。無限ループの選択肢を疑う
コンパイルできるか到達できない文（定数の false・true、break の直後）、for の宣言は 1 つの型、ループ変数のスコープ、拡張 for の右は配列か Iterable
for の終わったときの値更新のあとに条件で終わるので、条件が false になった値
break・continue の結果ラベルなしはいちばん内側（switch の中の break は switch だけ）。ラベル付きはそのラベルの文
