try-with-resources

try (R x = new R("1"); R y = new R("2")) { print("body "); throw new RuntimeException(); } catch (RuntimeException e) { print("catch "); } finally { println("finally"); } // open1 open2 body close2 close1 catch finally try (R r = new R()) { throw new IOException("body"); } // close も例外 → 投げられるのは body // getSuppressed() に close の例外が 1 つ
StringReader r = new StringReader("a"); r = new StringReader("b"); try (r) { } // × variable r used as a try-with-resources // resource neither final nor effectively final try (Writer w = new StringWriter()) { w.write("a"); } // × unreported exception IOException // exception thrown from implicit call to close()

コンストラクタは呼ばれるか

class P { int p = 1; P() { print("P() "); } } class C extends P implements Serializable { int c = 2; transient int t = 3; static int s = 4; C() { print("C() "); } } x.p = 10; x.c = 20; x.t = 30; // 書く C.s = 40; // 読み戻すと：P() 1 20 0 40
record Pt(int x, int y) implements Serializable { Pt { print("ctor "); } } // 読み戻すと：ctor Pt[x=1, y=2]
クラス読み戻すとき
Serializable なクラスコンストラクタは呼ばれない
Serializable でない親いちばん近いものの引数なしコンストラクタ（ないと InvalidClassException: no valid constructor）
レコード標準コンストラクタが呼ばれる
Externalizablepublic の引数なしコンストラクタ → readExternal
出典：API Serializable・Externalizable、Java Object Serialization Specification 1.13・3.1／JDK 17 での実行結果

細かいしくみ

class V implements Serializable { private static final long serialVersionUID = 1L; private void writeObject(ObjectOutputStream o) throws IOException { print("w "); o.defaultWriteObject(); } private void readObject(ObjectInputStream i) throws IOException, ClassNotFoundException { print("r "); i.defaultReadObject(); } } o.writeObject(v); o.writeObject(v); o.writeObject("s"); // 読むと：w r true s（2 回目は参照だけ） in.readObject(); // 4 回目は EOFException
serialVersionUID書いたときと読むときで番号がちがうと InvalidClassException。書かなければ自動計算
writeObject・readObjectprivate で書くと、方法を変えられる
ExternalizablewriteExternal・readExternal で全部自分で書く
