実行計画を作って読む

変える前に、見る。

Terraform #05 plan・apply・destroy目標 3d・3e・3f

terraform plan がすること

① 実物を読むステートを最新にする（refresh）
↓
② 設定と前のステートを比べるちがいを見つける
↓
③ 変更を提案する実物を設定に合わせるための作る・変える・消す
『The plan command alone does not actually carry out the proposed changes』
書き方計画
terraform plan投機的プラン。見るだけ（『without any intent to actually apply it』）
plan -out=tfplan保存した計画。apply tfplan でそのとおり実行（自動化向け）
plan -detailed-exitcode0＝変更なし・1＝エラー・2＝変更あり
プランファイルには設定全体・変数・sensitive な値が平文で入る。名前は tfplan（.tf で終わらせない）。中身は terraform show tfplan。
出典：Command: plan（Introduction／Other Options）／Command: apply

計画の読み方

Resource actions are indicated with the following symbols: -/+ destroy and then create replacement # module.hello.random_pet.server must be replaced -/+ resource "random_pet" "server" { ~ id = "more-swan" -> (known after apply) ~ keepers = { # forces replacement ~ "secret_key" = (sensitive value) } } Plan: 1 to add, 0 to change, 1 to destroy.
記号意味
+作る
-消す
~その場で変える
-/+消してから作り直す
+/-作ってから消す（create_before_destroy）
<=データソースを読む
(known after apply)＝適用まで分からない値。# forces replacement＝作り直しの原因。
出典：チュートリアル Create a Terraform plan
第2章

モードとオプション

何を目ざすか、どこまでやるか。

Terraform #05 plan・apply・destroy目標 3d・3e・3f

3 つのモードと主なオプションplan と apply で共通

ノーマル（指定なし）実物を設定に合わせる
-destroy管理しているもの全部を消す（＝ terraform destroy）
-refresh-only外での変更に合わせてステートと出力値だけ更新（#13）
モードは『mutually-exclusive』。同時に 2 つは選べない。
オプション何をするか・注意
-refresh=false速いが外の変更を無視 → 不完全な計画のおそれ
-replace=ADDRこわれた実物を同じ設定で作り直す（taint の代わり）
-target=ADDRそのインスタンス＋依存先だけ。例外のときだけ
-var 'n=v'= の前後に空白を入れない
-var-file=x.tfvars多くの場合こちらがおすすめ
-parallelism=n同時に処理する数（既定 10）
出典：Command: plan（Planning Modes／Planning Options／Resource Targeting）

-target はなぜ例外だけ？

書き方選ばれるもの
aws_instance.web[0]そのインスタンスだけ
aws_instance.webcount・for_each の全インスタンス
module.vpcそのモジュールと子モジュールの全部
（どれでも）＋直接・間接に依存するもの
『It is not recommended to use -target for routine operations, since this can lead to undetected configuration drift』
こうする大きな設定は小さな設定に分け、データソースで情報をやりとりする
使ってよい場面まちがいからの復旧・Terraform の制限の回避
出典：Command: plan（Resource Targeting）

第3章

apply と destroy

承認して、作る。終わったら、片づける。

Terraform #05 plan・apply・destroy目標 3d・3e・3f

apply の 2 つの動き

terraform applyterraform apply tfplan
計画その場で新しく作る（automatic plan mode）保存した計画をそのまま（saved plan mode）
承認yes を入力（-auto-approve で省略）聞かれない（ファイルを渡すことが承認）
モード・オプション-destroy・-refresh-only・-replace・-var など使える付けられない（もう決まっている）
-auto-approve承認を省く無視される
-auto-approve を使うなら、Terraform の外で変更できないようにする（ドリフト対策）。
-input=false だけだと承認を聞けず『assume that you do not wish to apply the plan』→ 失敗。
出典：Command: apply（Automatic Plan Mode／Saved Plan Mode／Apply Options）

terraform destroy

$ terraform destroy # ＝ terraform apply -destroy $ terraform plan -destroy # 消す計画を見るだけ $ terraform destroy -target aws_instance.example # そのリソースと依存するもの
開発用の一時的な環境を、作業のあとにまとめて片づける。
やりたいこと使うもの
全部消すterraform destroy
1 つを作り直すapply -replace
1 つを消す設定から消して apply（例外なら destroy -target）
管理から外すだけstate rm・removed ブロック（#13・#14）
消す順番は、作るときの逆。設定から消したものは orphan として消す計画になる。
出典：Command: destroy／Dependency Graph
