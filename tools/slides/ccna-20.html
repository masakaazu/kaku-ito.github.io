脅威・脆弱性・エクスプロイト・リスク・対策

図は RFC 4949 の定義から Claude が作った
CIA の3要素（守るもの）
要素意味破る攻撃の例
機密性 C許された人だけが見られる盗み見・中間者
完全性 I勝手に変えられていない改ざん・中間者
可用性 A使いたいときに使えるDoS・ランサムウェア
ゼロデイ：ベンダーがまだ知らない（パッチのない）穴を突く攻撃。パッチだけでは防げないので、不審な動きの検知と組み合わせる。
出典：RFC 4949（threat・vulnerability・risk・countermeasure・data confidentiality・data integrity・availability）／Cisco「What Is an Exploit?」（An exploit is not malware itself／zero-day exploits）／Cisco「What Is a Cyberattack?」（CIA Triad）／NIST CSRC Glossary「zero day attack」

使えなくする：DoS・DDoS とリフレクション・増幅

攻撃しくみ
DoS正規の利用をできなくする・遅らせる。例：SYN フラッド（偽の送信元から SYN を大量に送り、返事待ちで埋める）
DDoSたくさんの機器（乗っ取られたボット）から一斉に
リフレクション・増幅送信元を被害者に偽り、第三者のサーバーに問い合わせて、大きな応答を被害者へ
根本の対策：送信元を偽ったパケットを自分のネットワークから出さない入口フィルタリング（BCP 38／RFC 2827）。DNS は外の人に再帰の問い合わせを許さない。
出典：RFC 5358（reflector attacks … small query-large response … amplification factor … could be around 80／the only real solution: … ingress filtering）／RFC 2827／RFC 4949（denial of service・SYN flood・distributed attack・zombie）／Cisco「What Is a DDoS Attack?」（botnets）。図はClaudeが作った例

偽る・割り込む・調べる・突く・当てる

攻撃何をする主な対策
スプーフィング送信元の IP・MAC などを偽ってなりすます。ほかの攻撃の土台入口フィルタリング、DHCP スヌーピング・DAI（#23）
中間者攻撃（MITM）2者の間に割り込み、盗み見・書き換え。LAN ではうその ARP でルーターになりすます方法がある暗号化と相手の認証（証明書）、DAI
偵察攻撃の前に、機器・ソフトの版・開いたポート・人の情報を集める不要なサービスを止める、出す情報を減らす
バッファオーバーフロー書き込みの範囲を確かめない不具合を突き、長いデータで動きを乗っ取る・止めるパッチ（修正）
パスワード攻撃辞書攻撃（一覧を順に試す）・総当たり・ほかで漏れた組を試す（クレデンシャルスタッフィング）長いパスワード、失敗回数の制限、MFA
見分け方：「間に入る」なら中間者、「偽の送信元」ならスプーフィング、「攻撃の前の下調べ」なら偵察、「一覧を試す」なら辞書攻撃。
出典：RFC 4949（masquerade／spoof・man-in-the-middle attack・buffer overflow・dictionary attack・brute force）／Cisco「What Is a Cyberattack?」（Reconnaissance・Brute force attacks・credential stuffing）／Cisco Guide to Harden Cisco IOS Devices（ARP poisoning … man-in-the-middle）

手口中身

第3章

パスワードとその代わり

長さとブロックリストで守り、パスワード以外の要素と組み合わせる。

CCNA #20 セキュリティの基本と AAA5.4

パスワードの決まり：NIST SP 800-63B-4

項目よくある古い決まりNIST SP 800-63B-4
長さ8文字以上1要素だけで使うなら 15文字以上（MFA の一部なら 8 以上）。64文字以上まで入れられる
組み合わせ大文字・数字・記号を必ずそうした決まりは課さない
定期変更90日ごと求めない。漏れた証拠があれば変えさせる
弱いもの―よく使われる・漏れたもののブロックリストで拒む
入力貼り付け禁止パスワードマネージャー・貼り付けを許す
失敗―失敗回数を制限する
なぜ組み合わせの決まりをやめたか
決まりを課すと、人は予想しやすい形で応じる（「password」→「Password1」）。強さはあまり増えず、使いにくくなるだけ。
機器では
初期パスワード最初に使う前に変える
保存平文で残さない（enable secret など、#11）
出典：NIST SP 800-63B-4 3.1.1.2（minimum of 15 characters … minimum of eight characters／maximum password length of at least 64／SHALL NOT impose other composition rules／SHALL NOT require subscribers to change passwords periodically／blocklist／password managers … paste／rate-limiting）・Appendix A（users respond in very predictable ways … "Password1"）／NIST SP 800-53 Rev. 5 IA-5（Changing default authenticators prior to first use）

多要素認証（MFA）：違う種類を2つ以上

組み合わせMFA？理由
パスワード＋スマホに出る6桁の数字○知っている＋持っている
スマートカード＋PIN○持っている＋知っている
パスワード＋秘密の質問×どちらも知っているもの
パスワードを2回×同じ要素の繰り返し
出典：NIST SP 800-53 Rev. 5 IA-2(1)（two or more different factors … something you know …, something you have …, or something you are）／NIST CSRC Glossary「multi-factor authentication」（CNSSI 4009-2022）／NIST SP 800-63B-4 3.1.4（Single-factor OTP … as few as six decimal digits）。表の例はClaudeが作った

証明書と生体認証

証明書（X.509）のしくみ
証明書生体認証
要素持っているもの（秘密鍵の入った機器）本人の特徴
よさパスワードを送らない覚えなくてよい
気をつけること秘密鍵を守る、期限と失効確率で判定（誤って合う・合わない）、漏れても取り替えにくい
NIST：生体認証は単独の認証手段とは認めない。持っているもの（機器）と組み合わせた MFA の一部としてだけ使い、生体以外の方法も用意する。
出典：RFC 4949（public-key certificate：binds a system entity's identifier to a public key value … digitally signed・certification authority）／RFC 5280 4.1（issuer・validity・subject・subjectPublicKeyInfo）／NIST SP 800-63B-4 3.2.3（Biometrics SHALL only be used as part of multi-factor authentication with a physical authenticator … An alternative non-biometric authentication option SHALL always be provided／Biometric comparison is probabilistic）。図はClaudeが作った例

ローカルとサーバー
ローカルサーバー（TACACS+・RADIUS）
ユーザー機器ごとに username一か所にまとめる
記録機器ごとにばらばらサーバーに集まる

TACACS+RADIUS
運ぶTCP 49UDP 1812・1813

802.1X：ポートにつないだ人を、使わせる前に確かめる

よくあるひっかけ

よくある思い込み正しくは
脆弱性と脅威は同じ脆弱性は穴、脅威は害を与えうるもの、エクスプロイトは穴を突く道具
エクスプロイトはマルウェアの一種Cisco の説明では、マルウェアを送り込む方法でマルウェアそのものではない
トロイの木馬は自分で増える増えない。自分で広がるのはワーム
フィッシングはメールだけ電話（ビッシング）・SMS（スミッシング）もある
パスワード＋秘密の質問は MFAどちらも知っているもの。違う種類が要る
パスワードは記号を混ぜ、定期的に変えるのが NIST の決まりSP 800-63B-4 はどちらも求めない。長さ・ブロックリスト・失敗回数の制限
意識向上とトレーニングは同じ意識向上は全員に注意、トレーニングは役割ごとの技能
認可は「本人か確かめる」それは認証。認可は「何をしてよい」
802.1X でスイッチが合否を決める決めるのは認証サーバー（RADIUS）。スイッチは中継
