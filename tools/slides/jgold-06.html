遅延評価と、要素の流れる順

終端操作なし
Stream.of("a","bb","ccc") .filter(x -> { print("f"+x); return x.length() > 1; }) .map(x -> { print("m"+x); return x; }); println("end"); // end だけ（filter も map も動かない）
終端操作あり：要素ごとに縦に流れる
Stream.of("a","bb","ccc") .peek(x -> print("p"+x)) .filter(x -> x.length() > 1) .forEach(x -> print("F"+x)); // pa pbb Fbb pccc Fccc
要素peekfilterforEach
"a"pa落ちる―
"bb"pbb通るFbb
"ccc"pccc通るFccc
「全部 peek → 全部 filter」ではなく、1 要素ずつ最後まで流れる。
出典：API java.util.stream パッケージの説明「Laziness」、Stream.peek／JDK 17 での実行結果

短絡操作と、状態を持つ操作

Stream.of(1,2,3,4) .filter(n -> { print("f"+n); return n % 2 == 0; }) .map(n -> { print("m"+n); return n; }) .findFirst(); // f1f2m2 → 3 と 4 は触らない
Stream.of("b","a","c").sorted() .peek(System.out::print).limit(1).forEach(...); // a! sorted が全部集めて並べ、先頭だけ流す Stream.of("b","a","c") .peek(System.out::print).limit(1).forEach(...); // b!
分類中間操作
状態を持たないfilter・map・flatMap・peek
状態を持つdistinct・sorted・limit・skip
短絡（中間）limit・takeWhile
短絡（終端）findFirst・findAny・anyMatch・allMatch・noneMatch
無限ストリーム＋sorted は、終端操作を呼ぶと終わらない（組み立てるだけなら何も起きない）。
出典：API java.util.stream パッケージの説明「Stateless behaviors」「Short-circuiting」／JDK 17 での実行結果

使用済みのストリーム

Stream<String> s = Stream.of("a","b"); s.forEach(System.out::print); // ab s.forEach(System.out::print); // IllegalStateException
Stream<String> s = Stream.of("a","b"); s.map(String::toUpperCase); // 戻り値を捨てた s.forEach(System.out::print); // IllegalStateException
Stream<Integer> t = s.filter(n -> n > 1); t.count(); // ○ s.count(); // × s は filter した時点で使用済み
遅延バインディング
List<String> src = new ArrayList<>(List.of("a","b")); Stream<String> s = src.stream(); src.add("c"); s.count(); // 3（終端操作の開始時点の中身）
終端操作の途中でソースを変えるのは干渉（non-interference 違反）で、ConcurrentModificationException などになりうる。
出典：API java.util.stream パッケージの説明「Non-interference」、Stream／JDK 17 での実行結果

選別：distinct・limit・skip・takeWhile・dropWhile
