第1章

電波とチャネル・SSID

同じ周波数を、となりのAPと取り合わないように配る。名前（SSID）とAP（BSSID）を区別する。

CCNA #10 無線LAN1.11.a〜c

2.4GHz：チャネルは5MHzおき、幅は約22MHz → 重ならないのは 1・6・11

帯重ならないチャネル特徴
2.4GHz1・6・11 の3つだけ遠くまで届くが混む。電子レンジ・Bluetooth・コードレス電話も同じ帯。802.11b/g/n/ax
5GHz20以上（36〜165。52〜144 は DFS）20MHz どうしは重ならない。40/80/160MHz に束ねられる。802.11a/n/ac/ax
出典：Catalyst 9800 Configuration Guide 17.9「Radio Resource Management」（Use only nonoverlapping channels (1, 6, 11…)）／ Enterprise Mobility 8.5 Design Guide（22 MHz・5 GHz Band Channels・2412/2462 MHz）。図はClaudeが作図

チャネルの配り方：となりは違うチャネル、同じチャネルは遠くで再利用

干渉何が起きるか
同一チャネル干渉（CCI）近くのAPと同じチャネル。電波を出す順番を待ち合って遅くなる
隣接チャネル干渉1と2のように少しずれて重なるチャネル。相手の電波が雑音になる
Wi-Fi 以外電子レンジ・Bluetooth など（2.4GHz）
チャネルボンディング
20MHz を束ねて 40/80/160MHz にし、速くする（802.11n 以降）。束ねるほどチャネルの数は減る。Cisco は2.4GHz では束ねない（3つしかないので）。
RRM（自動の調整）
WLCが、チャネル（DCA）と出力（TPC）を自動で決める。DCA は重ならないチャネルだけを使う。
出典：Catalyst 9800 Configuration Guide 17.9「RRM」（Channel reuse・Adjacent channel separation・DCA supports only 20-MHz channels in the 2.4-GHz band）／ Enterprise Mobility 8.5 Design Guide（802.11n：We do not support bonding of channels in 2.4 GHz・Overlap should be 10-15%）

SSID は名前、BSSID はAPの番号。同じSSIDのAPの集まりが ESS

用語意味注意
SSIDネットワークの名前（最大32文字）。ビーコンで知らせる隠しても（Broadcast SSID を切っても）安全にはならない
BSS／BSSIDAP1台（の無線）とその端末／それを見分けるMACアドレス1台のAPで複数SSIDなら、SSIDごとにBSSIDも別
出典：Enterprise Mobility 8.5 Design Guide「Split MAC Architecture」（BSSID・ESS・ESSID commonly referred to as an SSID）／ Wireless Controller Configuration Guide 8.10「WLANs」（SSID up to 32 characters）

電波の強さ：RSSI は「0に近いほど強い」、SNR は「信号－雑音」

まちがえやすい：-67dBm は -80dBm より強い（マイナスの小さいほうが強い）。電波が強くても、雑音も強ければ SNR は小さく、速度は出ない。

第2章

暗号化と認証

暗号化の方式（WEP→WPA→WPA2→WPA3）と、だれを入れるか（全員同じ鍵か、1人ずつか）を分けて考える。

CCNA #10 無線LAN1.11.d

方式は4世代。WPA2＝AES、WPA3＝SAEとPMF

方式暗号化パーソナル（家庭・小規模）エンタープライズ（会社）今の扱い
WEPRC4・固定の鍵全員同じ固定の鍵―破られている。使わない
WPATKIP（RC4）PSK802.1XWEPからのつなぎ。使わない
WPA2AES-CCMPPSK802.1X今も多い（9800 の既定）
WPA3AES（CCMP/GCMP）SAE802.1X（192ビットモード）PMF が必須。新しい標準
PSK のパスフレーズ：ASCII 8〜63文字か、16進数64文字。全員同じ鍵なので、1人が辞めたら全員の鍵を変える。
ひっかけ：「WPA2 の暗号化は？」→ AES（TKIP ではない）。「SAE は暗号化の方式？」→ いいえ、鍵を作る認証の手順。
出典：Catalyst 9800 Configuration Guide 17.9「WLAN Security」（WPA1 using TKIP and WPA2 using AES-CCMP・802.1X is default AKM）／ Wireless Controller Configuration Guide 8.10「WLAN Security」（8 to 63 ASCII text characters or 64 hexadecimal characters・Static WEP not supported on Wave 2 APs）／ 「Wi-Fi Protected Access 3」

PSK と 802.1X：鍵が「全員共通」か「1人ずつ」か

PSK（WPA2-Personal）
802.1X（WPA2-Enterprise）
PSK802.1X
認証に使うもの全員共通のパスフレーズ1人ずつのアカウント・証明書
サーバーいらないRADIUS（WLCがそのクライアント）
辞めた人全員の鍵を変えるその人のアカウントを止める
画面の選び方AKM の PSK にチェック・PSK FormatAKM の 802.1X にチェック・AAA Servers で RADIUS
Web認証（Layer 3）との違い：来客用のログインページは「つないだ後」の認証で、無線の通信は暗号化しない。暗号化は Layer 2 の WPA2/WPA3 がする。
出典：Wireless Controller Configuration Guide 8.10「WLAN Security」（Layer 2 Security・Authentication Key Management・Layer 3 Security／Web Authentication）。パスフレーズの例はClaudeが書いた

WPA3 の3つの道具：SAE・OWE・PMF

SAE（WPA3-Personal）

PSK のかわり。パスワードそのものを流さず、同じパスワードを知っていることを確かめ合って強い鍵を作る。

  • 盗み見たデータで家からパスワードを試すオフラインの辞書攻撃に強い
  • 1つの鍵が破られても、ほかの通信は安全（前方秘匿性）
OWE（Enhanced Open）

パスワードのないオープンなWLANでも、端末ごとに鍵を作って暗号化だけする。

  • 認証はしない（だれでもつながる）
  • カフェ・来客用で、盗み見を防ぐ
  • Diffie-Hellman で鍵を作る
PMF（802.11w）

切断などの管理フレームにも保護をかける。

  • にせの切断フレームで端末を追い出す攻撃を防ぐ
  • WPA3 では必須（切れない）
  • オープン・WEP・TKIP のWLANでは使えない
やりたいこと選ぶもの
家庭の WPA2-PSK を強くしたいWPA3-Personal（SAE）。古い端末があるうちは WPA2+WPA3 の移行モード
来客にパスワードなしで、でも暗号化してOWE（Web認証は暗号化しない）
出典：Catalyst 9800 Configuration Guide 17.9「Wi-Fi Protected Access 3」（Simultaneous Authentication of Equals・Opportunistic Wireless Encryption・you cannot disable PMF）／ Configuration Guide 8.10「WLAN Security」（802.11w cannot be applied on an open WLAN, WEP-encrypted WLAN, or a TKIP-encrypted WLAN）

アーキテクチャとAPのモード

APを1台ずつ管理するか、WLCやクラウドでまとめて管理するか。端末のデータをどこで有線に出すか。

CCNA #10 無線LAN2.6

4つのアーキテクチャ：違いは「管理する場所」と「データの出口」

もう1つ：組み込み型（EWC／Mobility Express）＝1台のAPの中でコントローラを動かし、ほかのAPを管理する。小さな拠点で、WLCの機械を買わずに済む。
出典：Enterprise Mobility 8.5 Design Guide（CAPWAP・autonomous AP）／ Configuration Guide 8.10「FlexConnect」／ Cisco Meraki「Meraki Cloud Architecture」（User data does not flow through the Meraki cloud）／ 8.10「Cisco Wireless Solution Overview」（Mobility Express）

スプリットMAC：急ぐ仕事はAP、考える仕事はWLC。間は CAPWAP

AP（時間にきびしい）WLC（時間にゆるい）

第4章

APとWLCのつなぎ方

どの機器を、スイッチのアクセスポート・トランク・LAGのどれにつなぐか。理由は「そのポートに何VLAN流れるか」。

CCNA #10 無線LAN2.7

ポートの選び方：VLANが1つならアクセス、いくつも流れるならトランク

! ローカルモードのAP
interface Gi1/0/1
 switchport mode access
 switchport access vlan 100
 spanning-tree portfast
! FlexConnect のAP（管理＝ネイティブ）
interface Gi1/0/37
 switchport mode trunk
 switchport trunk native vlan 10
 switchport trunk allowed vlan 10,20,30
! WLC（ディストリビューションシステムポート）
interface range Gi1/0/47 - 48
 switchport mode trunk
 channel-group 1 mode on
  • ローカルの AP：端末のデータは CAPWAP の中 → VLAN は管理の1つだけ
  • WLC：WLANごとのVLANを運ぶのでトランク（アクセスモードは非対応）
  • サービスポート：タグを扱えない → アクセスポート
出典：Enterprise Mobility 8.5 Design Guide（AP Switch Configuration・Configuring switch ports）／ Configuration Guide 8.10「Ports and Interfaces」（Controller configuration in access mode is not supported・Service Port）／ 「FlexConnect」（FlexConnect VLANs and ACLs）

変えたあとすぐ再起動―

WLCのインタフェース：WLAN → ダイナミックインタフェース → VLAN

インタフェース役目

Client Exclusion認証に何度も失敗した端末を、決めた時間だけ入れないパスワードの総当たりを遅らせる
P2P Blocking同じWLANの端末どうしの通信を止める（マルチキャストには効かない）来客用で、ほかの客のPCを守る
Coverage Hole Detection電波が弱い場所（カバレッジホール）を見つけるRRM に出力を上げさせる
Maximum Allowed ClientsWLAN（AP・無線）ごとの端末数の上限1台のAPへの集中を防ぐ
FlexConnect Local SwitchingFlexConnect の AP で、このWLANをローカルスイッチングにする支店で直接出したいWLAN
まちがえやすい組：Client Exclusion（失敗した端末を締め出す）／P2P Blocking（端末どうしを分ける）／AAA Override（RADIUS の指示で上書き）。
