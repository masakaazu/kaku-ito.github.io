12-1 要件定義要件のまとめ方

システム要件定義System Requirements Definition
システムに求める機能や性能などを決めて文書にすること
ポイント利用者の要望を「何を作るか」に落とし込む
機能要件・非機能要件Functional / Non-functional Requirements
機能要件は「何ができるか」、非機能要件は性能・信頼性・セキュリティ・使いやすさなど「どれくらいうまくできるか」
例応答時間3秒以内は非機能要件
ヒアリングHearing
利用者に話を聞いて、要望を集めること
ユースケース図Use Case Diagram
利用者（アクタ）とシステムの機能（ユースケース）の関係を表すUMLの図
ポイント要件を整理するときに使う

12-2 設計設計の手法

DFDでぃーえふでぃー / Data Flow Diagram
データの流れに注目して、処理・データストア・外部実体のつながりを表した図
ポイント処理の順序や条件分岐は表さない
Data＝データ／Flow＝流れ／Diagram＝図
E-R図Entity Relationship Diagram
実体と、実体どうしの関連を表した図
ポイントデータベースの設計に使う
UMLゆーえむえる / Unified Modeling Language
オブジェクト指向の分析・設計で使う、図の書き方の標準
ポイントクラス図・ユースケース図・シーケンス図・アクティビティ図・状態マシン図など
Unified＝統一された／Modeling＝モデルを描く／Language＝言語
クラス図Class Diagram
クラスの属性・操作と、クラスどうしの関係を表すUMLの図
シーケンス図Sequence Diagram
オブジェクトどうしのメッセージのやり取りを、時間の順に表すUMLの図
状態遷移図じょうたいせんいず / State Transition Diagram
状態と、状態が変わるきっかけ（イベント）を表した図
例自動販売機の動き
基本情報 システム開発技術5

12-2 設計設計の手法

汎化・特化はんか・とっか / Generalization, Specialization
汎化は複数のクラスの共通点をまとめて上位クラスを作ること、特化はその逆
ポイント「is-a」の関係。例: 犬は動物である
集約しゅうやく / Aggregation
全体と部分の関係
ポイント「part-of」の関係。例: 車はエンジンを持つ
カプセル化Encapsulation
データとそれを扱う処理をまとめ、外から中身を直接さわれないようにすること
継承けいしょう / Inheritance
上位クラスの性質を、下位クラスが引き継ぐこと
ポリモーフィズム多相性 / Polymorphism
同じ命令でも、受け取るオブジェクトによって違う動きをすること
モジュールModule
プログラムを機能ごとに分けた部品

12-2 設計設計の手法

モジュール結合度Module Coupling
モジュールどうしの依存の強さ
ポイント弱いほど修正の影響が広がらない。データ結合が最も弱く望ましい
モジュール凝集度Module Cohesion
1つのモジュールの中の機能のまとまりの強さ
ポイント強いほどよい。機能的強度が最も強い
構造化設計Structured Design
システムを機能ごとに上から下へ段階的に分けていく設計
ポイントSTS分割・TR分割・共通機能分割がある

12-4 統合・テストテストの方法

ブラックボックステストBlack Box Test
中の作りを見ずに、入力と出力が仕様どおりかを確かめるテスト
ポイント同値分割・限界値分析でテストデータを作る
ホワイトボックステストWhite Box Test
プログラムの中の作り（命令や分岐）を見て、通り道を確かめるテスト
ポイント命令網羅・判定条件網羅などの基準がある
同値分割どうちぶんかつ / Equivalence Partitioning
入力を、同じように処理されるグループに分け、各グループから代表の値を選ぶ方法
限界値分析げんかいちぶんせき / Boundary Value Analysis
グループの境目の値と、その前後の値をテストする方法
ポイント境目は間違いが起きやすい
単体テストUnit Test
モジュールを1つずつ確かめるテスト
結合テストIntegration Test
モジュールを組み合わせて、データの受け渡しや呼出しを確かめるテスト
ポイントトップダウンテストとボトムアップテストがある
基本情報 システム開発技術10

12-4 統合・テストテストの方法

スタブStub
トップダウンテストで、まだできていない下位のモジュールの代わりに使う仮のモジュール
ドライバDriver
ボトムアップテストで、まだできていない上位のモジュールの代わりに使う仮のモジュール
リグレッションテスト回帰テスト / Regression Test
プログラムを直したことで、ほかの部分に新しい不具合が出ていないかを確かめるテスト
バグ管理図信頼度成長曲線 / Reliability Growth Curve
テストの時間と、見つかったバグの累計の関係を表すグラフ
ポイントゴンペルツ曲線のようにS字になり、増え方が落ち着けば品質が安定してきたとみなす
