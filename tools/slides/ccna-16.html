第1章

NAT の4つのアドレス

同じパケットのアドレスが、ルーターの内側と外側で違う名前になる。

CCNA #16 NAT と NTP4.1

なぜ NAT：プライベートアドレスはインターネットで使えない

RFC 1918 のプライベートアドレス
範囲書き方
10.0.0.0〜10.255.255.25510.0.0.0/8
172.16.0.0〜172.31.255.255172.16.0.0/12（172.32 は外）
192.168.0.0〜192.168.255.255192.168.0.0/16
  1. 組織の中ではプライベートアドレスを自由に使う
  2. インターネットではプライベートアドレスの経路が流れない
  3. 出口のルーターが、送信元を正規アドレスに書き換える＝NAT
語NAT＝Network Address Translation（ネットワークのアドレス変換）
出典：RFC 1918（3. Private Address Space）／IOS XE「Configuring NAT for IP Address Conservation」（NAT enables private IP internetworks that use nonregistered IP addresses to connect to the Internet）。図はClaudeが作った例

4つのアドレス：行きのパケットで見る

local（内側で見える形）global（外側で見える形）
inside（内側のホストのアドレス）inside local：PC に設定した 192.168.1.10inside global：外に見せる 203.0.113.5
outside（外側のホストのアドレス）outside local：内側から見たサーバー 198.51.100.7outside global：サーバーの本物 198.51.100.7
出典：Cisco「NAT: Local and Global Definitions」（Packets sourced on the inside portion of the network have an inside local address as the source address and an outside local address as the destination address … When that same packet gets switched to the outside network, the source … inside global … destination … outside global）。図はClaudeが作った例

帰りのパケット：宛先を inside global から inside local に戻す

  1. PC が送る：送信元 192.168.1.10（inside local）
  2. R1 が G0/0（inside）から G0/1（outside）へ送るとき、送信元を 203.0.113.5（inside global）に書き換え、変換表に1行残す
  3. サーバーは PC を 203.0.113.5 だと思い、宛先 203.0.113.5 で返事を送る
  4. R1 は変換表を引き、宛先を 192.168.1.10 に戻して PC に届ける
outside local と outside global：inside source NAT では外側のアドレスを変えないので同じ値。違う値になるのは ip nat outside source で外側のアドレスも変換するときだけ。
インタフェースに「内」と「外」を付ける
interface GigabitEthernet0/0
 ip address 192.168.1.1 255.255.255.0
 ip nat inside
interface GigabitEthernet0/1
 ip address 203.0.113.5 255.255.255.0
 ip nat outside
  • NAT は inside と outside の間を通るパケットだけを変換する
  • 片方でも付け忘れると変換されない。向きを逆にしてもねらいどおりにならない
  • inside＝変換したい組織のネットワーク側。アドレスの種類ではなく、側を表す
出典：Cisco「NAT: Local and Global Definitions」（The destination of the packet is known as the inside global address. When the same packet gets switched to the inside network … the destination … inside local）／Cisco「Configure Network Address Translation」（The first step to deploy NAT is to define NAT inside and outside interfaces）
第2章

NAT の種類と設定

1対1で固定するスタティック、プールから貸すダイナミック、ポート番号で多数をまとめる PAT。

CCNA #16 NAT と NTP4.1

3つの種類を比べる

スタティック NAT1対1・固定
  • 設定した時点から変換表に常に載る
  • 外から通信を始められる＝サーバーの公開
  • 1台ごとに1行
ダイナミック NAT1対1・プールから貸す
  • 内側が通信を始めたときに変換表へ
  • 同時に変換できるのはプールの数まで
  • しばらく使わないと消える
PAT（overload）多対1・ポート番号で区別
  • 1つの正規アドレスを多数で共有
  • TCP・UDP のポート番号で見分ける
  • RFC 3022 では NAPT と呼ぶ
出典：IOS XE「Configuring NAT for IP Address Conservation」Types of NAT（Static … one-to-one … Dynamic … from a pool … Overloading … many to one … by using different ports）／RFC 3022（Basic NAT と NAPT）。図はClaudeが作った例

スタティック NAT：「内側の実アドレス → 外に見せるアドレス」の順に書く

R1(config)#ip nat inside source static 192.168.1.20 203.0.113.20
R1(config)#interface g0/0
R1(config-if)#ip nat inside
R1(config-if)#interface g0/1
R1(config-if)#ip nat outside

R1#show ip nat translations
Pro Inside global      Inside local       Outside local      Outside global
--- 203.0.113.20       192.168.1.20       ---                ---
ip nat inside source static inside local inside global
  • Pro が「---」の行がスタティック。通信がなくてもいつも出る
  • 外のホストは 203.0.113.20 宛てに送れば、R1 が宛先を 192.168.1.20 に戻す＝外から始められる
  • ダイナミックや PAT は、内側が通信を始めるまで行がないので、外からは始められない
順番のひっかけ：static 203.0.113.20 192.168.1.20 と逆に書くと、203.0.113.20 を内側のホストとして扱ってしまう。
例メールサーバー・Web サーバーを外に公開するときに使う
出典：IOS XE「Configuring NAT for IP Address Conservation」Configuring Static Translation of Inside Source Addresses（ip nat inside source static local-ip global-ip … useful when a host on the inside must be accessible by a fixed address from the outside）／Doc 13772（permanent entry … enables both inside and outside hosts to initiate a connection）

ダイナミック NAT：プール＋ACL＋list … pool の3行

! 1. 貸し出す正規アドレスの範囲
R1(config)#ip nat pool POOL1 203.0.113.10 203.0.113.14 netmask 255.255.255.0
! 2. 変換する送信元を選ぶ
R1(config)#access-list 1 permit 192.168.1.0 0.0.0.255
! 3. 1 と 2 を結ぶ
R1(config)#ip nat inside source list 1 pool POOL1
ip nat pool名前・最初 最後・netmask か prefix-length（どちらか）
access-listパケットを止めるためでなく変換する相手を選ぶ。最後に暗黙の deny
list N pool 名「ACL N に合った送信元を、プールのアドレスに変える」
  1. 変換表は最初は空
  2. 192.168.1.10 が外へ送る → ACL 1 に合う → プールから空きの 203.0.113.10 を1対1で割り当て
  3. プールは 5 個（.10〜.14）→ 同時に変換できるのは 5 台まで
  4. 使われなくなった行はタイムアウトで消え、アドレスはプールに戻る
ACL のひっかけ：permit に入らない送信元は変換されない。Cisco は広すぎる ACL（permit any など）を NAT に使わないよう注意している。
出典：IOS XE「Configuring NAT for IP Address Conservation」Configuring Dynamic Translation of Inside Source Addresses（ip nat pool name start-ip end-ip { netmask | prefix-length }／The access list must permit only those addresses that are to be translated … implicit "deny all"）／Doc 13772（translation table … initially empty）

PAT：overload を付けると、1つのアドレスを多数で共有する

変換表（Claudeが作った例）
Inside localInside global
192.168.1.10:51000203.0.113.5:1024
192.168.1.11:51000203.0.113.5:1025
192.168.1.12:49152203.0.113.5:1026
要返事の宛先ポート（1024 など）で、どの PC に戻すかを決める
書き方は2つ
! A. outside のインタフェースのアドレスを使う
ip nat inside source list 1 interface g0/1 overload

! B. プールのアドレスを使う（1個でもよい）
ip nat pool ONE 203.0.113.5 203.0.113.5 netmask 255.255.255.0
ip nat inside source list 1 pool ONE overload
  • overload がなければ1対1のダイナミック NAT
  • 多数のホストを外へ出す設定＝PAT。変換表の行はアドレス:ポートの形になる（extended エントリー）
  • list の後ろが「interface 名」か「pool 名」かの違い
出典：IOS XE「Configuring NAT for IP Address Conservation」Overloading of Inside Global Addresses（the TCP or UDP port numbers of each inside host distinguish between local addresses … extended entry）／Doc 13772（ip nat inside source list 7 interface serial 0 overload／the NAT pool ovrld only has a range of one address）

第3章

NTP

正確な時計から段々に時刻を受け渡し、ネットワークの全機器の時計をそろえる。

CCNA #16 NAT と NTP4.2

NTP とストラタム：時刻源から何段目か

項目内容
運ぶものUDP 123（今の版は NTPv4、RFC 5905）
ストラタム 1原子時計・GPS などに直結したサーバー
ストラタム 2〜15NTP で上から受け取った機器（相手＋1）
ストラタム 16同期していない
選び方通信できる中でいちばん小さいストラタム
目的：時刻がずれていると、機器ごとのログを並べても順番がわからない。同期していない機器には、だれも同期しない。
出典：System Management CG IOS XE 17.9（Catalyst 9300）「Administering the Device」NTP Stratum（A stratum 1 time server has a radio or atomic clock directly attached … chooses … the lowest stratum number … never synchronizing to a device that is not synchronized）／RFC 5905（PORT 123／Figure 11：16 unsynchronized）。図はClaudeが作った例

クライアントとサーバー：ntp server を書いた側がクライアント

コマンド入れた機器の役関係
ntp server アドレスクライアント：そのサーバーから時刻をもらうもらうだけ（client mode）
ntp master [1〜15]外の時刻源なしで時刻を配る権威のあるサーバー。省略時ストラタム 8配る側
ntp peer アドレス対等に合わせ合うおたがい（symmetric active）
ntp master の注意：小さいストラタムを付けると正しい時刻源より優先されてしまう。何台にも入れると時刻が乱れる。Cisco の機器は原子時計を直結できないので、本当のストラタム1にはならない。
組み合わせの例（Claudeが作った例）
! R1：上流 10.0.0.1 のクライアント
R1(config)#ntp server 10.0.0.1 prefer
R1(config)#ntp server 10.0.0.2
R1(config)#ntp source Loopback0

! SW1：R1（Loopback0＝1.1.1.1）のクライアント
SW1(config)#ntp server 1.1.1.1
  • R1 は上流にはクライアント、SW1 にはサーバー。同期できた機器は、指定してきた相手に時刻を返す
  • prefer：優先するサーバー。切り替えを減らす
  • ntp source：送信元を Loopback0 に固定（初期値は出ていくインタフェース）
出典：IOS XE 17.9「Administering the Device」Poll-Based NTP Associations・Authoritative NTP Server（ntp server … client mode／ntp peer … symmetric active mode／ntp master … Use … with caution）／Basic System Management CR（ntp master：stratum 1 to 15, default 8／ntp server：prefer／ntp source：Source address is determined by the outgoing interface）

show clock の先頭の記号

.正しかったが、NTP の相手と連絡が取れなくなった

よくあるひっかけ

よくある思い込み正しくは
inside global は内側の PC に設定したアドレスPC に設定したのは inside local。inside global は外に見せる変換後のアドレス
show ip nat translations の左の列は Inside local左が Inside global、その右が Inside local

ダイナミック NAT で外から通信を始められる行は内側が始めたときにできる。外から始めるならスタティック

ntp server を入れた機器が NTP サーバーになる入れた機器はクライアント。サーバーは後ろに書いた相手
ストラタムは大きいほど正確、0 は未同期小さいほど時刻源に近い。未同期は 16
NTP は TCP 123UDP 123（SNMP は UDP 161、Syslog は UDP 514）
