Executors で作る

メソッドスレッド使いどころ
newSingleThreadExecutor()1 つ出した順に 1 つずつ実行
newFixedThreadPool(n)n 個で固定同時に n 個まで、残りはキューで待つ
newCachedThreadPool()必要なだけ作る空いたスレッドを再利用（60 秒使わないと消える）
newScheduledThreadPool(n)n 個遅らせて・くり返し実行
スレッド名は「pool-プール番号-thread-番号」（例：pool-2-thread-1）。
プールのスレッドはデーモンでない。shutdown しないと main が終わっても JVM が終わらない。

Future で結果を受け取る

Future<Integer> f = es.submit(() -> { throw new IllegalStateException("bad"); }); try { f.get(); } catch (ExecutionException e) { e.getCause() // IllegalStateException: bad } Future<String> s = es.submit(() -> { Thread.sleep(2000); return "done"; }); s.get(100, TimeUnit.MILLISECONDS); // TimeoutException s.cancel(true); // true（実行中なら割り込み） s.isCancelled(); // true s.isDone(); // true s.get(); // CancellationException

終わらせ方と時間指定

メソッド中身
shutdown()新しいタスクを断る。受け付け済みは最後まで実行。待たない
shutdownNow()実行中に割り込み、始まっていないタスクを List<Runnable> で返す
awaitTermination(t, 単位)終わるまで待つ（終われば true、時間切れは false）
isShutdown()shutdown を呼んだら true
isTerminated()shutdown のあと全タスクが終わったら true
shutdown のあとの execute・submit は RejectedExecutionException。
ScheduledExecutorService s = Executors.newScheduledThreadPool(1); s.schedule(() -> "later", 50, MILLISECONDS) .get(); // later（1 回だけ） s.scheduleAtFixedRate(r, 0, 10, MILLISECONDS); // 開始から開始までを一定に s.scheduleWithFixedDelay(r, 0, 10, MILLISECONDS); // 終わりから次の開始までを一定に // くり返しの 2 つは Runnable だけ

CopyOnWriteArrayList

List<String> l = new ArrayList<>(List.of("a","b","c")); for (String s : l) if (s.equals("a")) l.add("d"); // ConcurrentModificationException List<String> c = new CopyOnWriteArrayList<>(List.of("a","b","c")); for (String s : c) if (s.equals("a")) c.add("d"); c // [a, b, c, d]（d は走査に出ない） Iterator<Integer> it = list123.iterator(); list123.add(4); // it で数えると 3、size は 4 list123.iterator().remove(); // UnsupportedOperationException
書き込みのたびに配列をコピーadd・set・remove は重い
イテレータはスナップショット作ったときの配列を見る。例外にならない
読み込みが多く、書き込みが少ないときに向く。CopyOnWriteArraySet もある。
Collections.synchronizedList は各メソッドを同期するだけ。拡張 for の途中で add すると ConcurrentModificationException。
出典：API CopyOnWriteArrayList・Collections.synchronizedList／JDK 17 での実行結果

ConcurrentHashMap

ConcurrentMap<String,Integer> m = new ConcurrentHashMap<>(); // 4 スレッド × 1 万回 m.merge("k", 1, Integer::sum); m.get("k") // 40000（原子的） m.putIfAbsent("k", 0) // 40000（変えない） m.putIfAbsent("z", 9) // null（入れた） m.put(null, 1); // NullPointerException m.put("a", null); // NullPointerException new HashMap<>().put(null, null); // OK
メソッドキーがないキーがある
putIfAbsent入れて null今の値を返す
computeIfAbsent関数で入れる何もしない
computeIfPresent何もしない関数で更新
computev は null関数で更新
merge値を入れる関数で合わせる
走査中に put しても例外にならない。

CountDownLatch と CyclicBarrier

CountDownLatch(3)countDown で 1 ずつ減らす。0 になるまで await で待つ
CountDownLatch l = new CountDownLatch(3); // 3 つのタスクが l.countDown() l.await(1, TimeUnit.SECONDS) // true l.getCount() // 0
0 になったら戻せない（1 回きり）。
CyclicBarrier(2, action)2 つのスレッドが await でそろうまで待つ
CyclicBarrier b = new CyclicBarrier(2, () -> println("all arrived")); // 2 つのタスクが b.await() // → all arrived（1 回）→ 両方が進む
そろうたびに使い回せる（cyclic）。
出典：API CountDownLatch・CyclicBarrier／JDK 17 での実行結果

Flow のしくみ

Publisher<T>subscribe(subscriber)
↓ onSubscribe(subscription)（1 回）
Subscriber<T>subscription.request(n)「n 個まで受けられる」
↓ onNext(item)（要求した数まで）
onComplete() か onError(t)どちらか 1 回
インタフェース役割
Publisherデータを出す
Subscriberデータを受ける
Subscriptionrequest(n)・cancel()
Processor<T,R>受けて変換して出す（両方）
受ける側が量を決める＝背圧（back pressure）。request しなければ onNext は来ない。
出典：API Flow・Flow.Publisher・Subscriber・Subscription・Processor

SubmissionPublisher

try (SubmissionPublisher<Integer> p = new SubmissionPublisher<>()) { p.subscribe(new Flow.Subscriber<>() { Flow.Subscription sub; public void onSubscribe(Flow.Subscription s) { sub = s; print("sub "); s.request(1); } public void onNext(Integer i) { got.add(i); sub.request(1); } public void onError(Throwable t) {} public void onComplete() { print("complete "); done.countDown(); } }); p.submit(1); p.submit(2); p.submit(3); } // close → 残りが届いてから onComplete done.await(); // sub complete [1, 2, 3]
submit で出す・close で終わりAutoCloseable なので try-with-resources
配信は別スレッド既定は ForkJoinPool.commonPool()
onSubscribe で request(2) だけなら、5 個 submit しても届くのは [1, 2]。
出典：API SubmissionPublisher・Flow.Subscription.request／JDK 17 での実行結果
