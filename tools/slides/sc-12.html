マルウェアの検出手法（R3春 問13）

手法何を見るか実行未知
パターンマッチング法定義ファイルの特徴的なコードと一致するかしない×
コンペア法安全な場所の原本（ハッシュ値）と比べるしない改変は分かる
チェックサム法事前に付けた「感染していない保証」と不整合かしない改変は分かる
ヒューリスティック法コードの怪しい命令・構造を経験則でしない（静的）○
ビヘイビア法読込み・書込み・通信などの動作を監視する○
静的解析：動かさずにハッシュ・文字列・逆アセンブル。難読化に弱い。
動的解析：サンドボックスで動かして観察。仮想環境を見抜いて黙るマルウェアに注意。
出典：IPA 午前Ⅱ 令和3年度春期 問13／IPA「支援士試験 シラバス（案）」用語例「ビヘイビア法，ヒューリスティック法，動的解析，静的解析」

ランサムウェアに負けないバックアップ

3-2-1 ルール
3コピーを3つ
（元データ含む）
22種類の媒体
11つは離れた場所
拡張の 3-2-1-1-0：もう1つはオフラインか変更不可、復元テストでエラー0。
攻撃者は管理者権限を奪うと、まずバックアップを消す。同じ権限で届く場所は危ない。
対策しくみ
バックアップ分離ネットワーク・アカウントから切り離す
WORM一度書いたら期間中は変更・削除不可（ワームではない）
イミュータブル管理者でも消せないバックアップ
カナリアファイルおとりファイルが触られたら警報
暗号化挙動検知大量の書換え・エントロピー上昇・拡張子の一斉変更
出典：IPA「支援士試験 シラバス（案）」用語例〔ランサムウェア対策〕／NISC・警察庁・IPA ほか「ランサムウェア被害防止対策」／US-CERT「Data Backup Options」

脆弱性の優先順位の付け方

指標組織分かること
CVEMITRE識別番号
CVSSFIRST深刻度 0.0〜10.0（v4.0 は 2023年）
EPSSFIRST30日以内に悪用される確率の予測
KEVCISA実際に悪用が確認された一覧
JVNJPCERT/CC・IPA国内製品を含む対策情報
判断の流れ
情報を集めるベンダ・JVN・KEV
影響のある資産を特定資産インベントリと照合
優先順位深刻度×悪用状況×公開か×重要度
検証 → 段階適用 → 確認当てられない機器は仮想パッチ・通信制限
CVSS 基本値は深刻度であり、自組織のリスクそのものではない。
出典：FIRST「CVSS v4.0 Specification」「EPSS」／CISA「KEV Catalog」／NIST SP 800-40 Rev.4 Guide to Enterprise Patch Management Planning

ASM：攻撃者の目で外から見る

① 発見ドメイン・IP・公開サーバ・VPN 機器・クラウド
② 情報収集ソフトの版数・開いているポート
③ リスク評価既知の脆弱性・設定の不備
④ 継続的に繰り返す
EASM（External）＝インターネット側に絞った ASM。
見つかるのは、管理部門が知らない資産：海外子会社のサーバ、キャンペーン用に作って放置したサイト、廃止し忘れた VPN 装置。
経済産業省「ASM 導入ガイダンス」（2023年5月）が、手順と注意点（他人の資産を誤って調べない）をまとめた。
出典：経済産業省「ASM（Attack Surface Management）導入ガイダンス〜外部から把握出来る情報を用いて自組織の IT 資産を発見し管理する〜」2023年

データを守る：DLP・Web 分離・マスキング・削除

対策しくみ効く場面
DLPデータの内容（番号の形式・キーワード）を識別して持ち出しを止める読む権限がある人の誤送信・持ち出し
Web 分離隔離した環境のブラウザで閲覧し、端末には画面だけ送る悪意のある Web での感染
データマスキング伏せ字・置換。静的（テスト用の複製）と動的（表示時）テスト環境・権限の低い閲覧者
情報の削除SP 800-88 の Clear・Purge・Destroy媒体の廃棄・再利用
アクセス制御は「だれが読めるか」。DLP は「読めた人が外に出すのを止める」。
SSD は上書きで消しきれない領域がある → 暗号消去（鍵を消す）や Purge コマンド。
出典：IPA「支援士試験 シラバス（案）」用語例「DLP，Web 分離，情報の削除及びデータマスキングの実装」／NIST SP 800-88 Rev.1 Guidelines for Media Sanitization

ログ設計と相関分析

決めること例
取得範囲認証の成否、管理者の操作、通信の許可・拒否
保存期間調査・法令・契約の要件から決める
改ざん防止WORM・追記のみ・別サーバへ即転送
時刻同期NTP で全機器を同じ時刻源に。タイムゾーンも統一
攻撃者は手元のログを消す → 別の場所へ送っておく。
相関分析の例（時刻がそろっていれば）
02:10 VPN：海外 IP から失敗×100
02:14 VPN：同じ ID で成功
02:20 認証サーバ：ファイルサーバへログオン
02:25 FW：外部へ 3GB 送信
単独では見逃す事象を、一つの事案としてつなげる。
出典：IPA「支援士試験 シラバス（案）」用語例〔ログの管理〕／NIST SP 800-92 Guide to Computer Security Log Management。例は Claude が作った

まとめ：本番での問われ方

検出手法の当てっこ：動作を監視＝ビヘイビア、定義と一致＝パターンマッチング、原本と比較＝コンペア、事前の保証情報＝チェックサム。
ランサムウェア：3-2-1、分離、WORM／イミュータブル。管理者権限でも消せないことが鍵。
脆弱性：深刻度（CVSS）に悪用状況（KEV・EPSS）と資産の状況を加える。ASM で知らない資産を見つける。
2×2 の4択：インライン／ミラー × シグネチャ（異常を定義）／アノマリ（通常を定義）。
偽陽性・偽陰性：正常を止めた＝フォールスポジティブ、攻撃を通した＝フォールスネガティブ。
製品：SIEM＝集約と相関、SOAR＝自動対応、EDR＝端末、NDR＝通信、XDR＝横断。
