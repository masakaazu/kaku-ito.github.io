terraform init

まず最初に、何回でも。

Terraform #04 ワークフローとinit・validate・fmt目標 3a・3b・3c・3g

init がすること『the first command you should run』

① バックエンドの初期化ルートの backend 設定を読む
↓
② 子モジュールのインストールmodule の source から取ってくる
↓
③ プラグインのインストール直接・間接に参照するプロバイダー → ロックファイルに記録
『always safe to run multiple times』『will never delete your existing configuration or state』
. ├── main.tf ├── .terraform/ # プロバイダー・モジュール（コミットしない） └── .terraform.lock.hcl # コミットする
リソースは作らない（作るのは apply）。
出典：Command: init

init のオプション

オプション段階何をするか
-migrate-stateバックエンド今のステートを新しいバックエンドへコピー（-force-copy で確認なし）
-reconfigureバックエンド今の設定を無視。ステートは移さない
-backend-config=…バックエンド部分設定。秘密・動的な値を外から渡す
-backend=falseバックエンドバックエンドを飛ばす（validate の準備など）
-upgradeモジュール・プラグイン制約に合う最新へ。ロックファイルを無視
-get=falseモジュール子モジュールのインストールを飛ばす
-lockfile=readonlyプラグインロックファイルを変えず照合だけ（-upgrade と併用不可）
-plugin-dir=PATHプラグインそのディレクトリからだけ入れる（開発中のプロバイダーなど）
もう一度 init：新しいモジュールだけ入る。入っているものは -upgrade まで変わらない。
出典：Command: init（Backend Initialization／Child Module Installation／Plugin Installation）

validate と fmt

正しさと、見た目。

Terraform #04 ワークフローとinit・validate・fmt目標 3a・3b・3c・3g

terraform validate

見る見ない
文法（syntactically valid）リモートのステート
中の整合性（internally consistent）プロバイダーの API
属性名・値の型値がプロバイダーにとって正しいか
参照先があるか変数の値・今のステート
『safe to run automatically』：エディタの保存時・CI・pre-commit。
$ terraform init -backend=false # バックエンドなしで準備 $ terraform validate Success! The configuration is valid. $ terraform validate -json { "valid": true, "error_count": 0, "warning_count": 2, "diagnostics": [ … ] }
警告だけなら valid は true。
特定の変数・ワークスペースで確かめるなら plan（validate をふくむ）。
出典：Command: validate／Style Guide（Code validation）

terraform fmt とスタイル

オプション動き
（なし）今のディレクトリを整えて上書き
-check書きかえず確認。整っていなければ終了コード 0 以外
-diff差分を表示
-recursiveサブディレクトリも
-write=false上書きしない
『intentionally opinionated and has no customization options』。版を上げたら fmt をかけ直す。
resource "aws_instance" "example" { count = 2 # メタ引数が最初 ami = "abc123" # = をそろえる instance_type = "t2.micro" # 2 スペース network_interface { # 引数のあとにブロック # ... } lifecycle { # メタ引数のブロックは最後 create_before_destroy = true } }
コミット前に fmt と validate。組織の規則は TFLint。
出典：Command: fmt／Style Guide（Code style／Code formatting）
