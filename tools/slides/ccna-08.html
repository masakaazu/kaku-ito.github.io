第1章

CDPとLLDP

直接つながった隣の機器に、自分の名前・機種・ポート・アドレスを定期的に知らせる。CDPはCisco独自、LLDPは標準。

CCNA #08 CDP・LLDPとEtherChannel2.3

CDP：隣の機器だけに、60秒ごとに自己紹介を送る

CDP（Cisco Discovery Protocol）
Cisco機器が、直接つながった隣の機器を知るためのレイヤ2のプロトコル。Cisco独自。
IPがなくても動く
データリンク層で動くので、IPアドレスを設定していない機器どうしでも隣がわかる。配線の確認に便利。
送る中身（TLV）
機器名（Device ID）・送ったポート・IPアドレス・機能（ルータ／スイッチ）・IOSのバージョン・機種。CDPv2ではネイティブVLAN・デュプレックス・VTPドメイン名・音声VLANなども。
既定値（Catalyst 9300）
全体も全ポートも有効。送る間隔60秒、ホールドタイム180秒、v2で送る。
出典：Cisco Network Management Configuration Guide 17.9.x「Configuring Cisco Discovery Protocol」（Overview・Default Configuration）／ Cisco Best Practices for Catalyst 6500/4500（CDP：SNAP type 2000・01-00-0c-cc-cc-cc・CDPv2 TLV）

CDPとLLDP：目的は同じ。違いは「誰の規格か」と「最初から動くか」

比べる点CDPLLDP
規格Cisco独自IEEE 802.1AB（標準。他社の機器とも話せる）
初期状態（Catalyst 9300）有効（全体・全ポート）無効（lldp run が必要）
送る間隔／ホールドタイム60秒／180秒30秒／120秒（初期化の遅延 2秒）
全体で止める・動かすno cdp run／cdp runno lldp run／lldp run
ポートで止めるno cdp enable（送受信まとめて）no lldp transmit・no lldp receive（送信と受信が別）
隣を見るshow cdp neighbors [detail]show lldp neighbors [detail]
電話向けの拡張CDPで音声VLANを伝えるLLDP-MED（ネットワークポリシーTLVでVLAN・CoSを伝える）
数字の取り違えに注意：CDP 60/180、LLDP 30/120。どちらも「ホールドタイムは送る間隔の数倍」（CDPは3倍、LLDPは4倍）で、通知が数回届かなかったら隣を消す考え方。
出典：Configuring Cisco Discovery Protocol ／ Interface and Hardware Components Configuration Guide 17.9.x「Configuring LLDP, LLDP-MED, and Wired Location Service」（Default LLDP Configuration・Enabling LLDP）

止める設定は「全体」と「ポート」の2段。LLDPは送信と受信が別

CDP
R1(config)# no cdp run            ! 全体で止める
R1(config)# interface g0/0/1
R1(config-if)# no cdp enable       ! このポートだけ
R1(config)# cdp timer 30              ! 送る間隔（5〜254）
R1(config)# cdp holdtime 90           ! 保持時間（10〜255）
LLDP
SW1(config)# lldp run             ! 全体で動かす
SW1(config)# interface g1/0/10
SW1(config-if)# no lldp transmit   ! 送らない
SW1(config-if)# no lldp receive    ! 受け取らない
やりたいことコマンド
全部のポートでCDPを止めるno cdp run（グローバル）
1ポートだけCDPを止めるno cdp enable（インタフェース）
LLDPを使い始めるlldp run（初期値は無効）
LLDPで自分を見せないno lldp transmit（受信は続く）
なぜ止めるのか：CDP・LLDPは機種・バージョン・IPアドレスを暗号化せずに送る。Ciscoの堅牢化ガイドは「信頼できないネットワークにつながるポートでは止める」としている。社内では切り分けに役立つので動かしておくのが普通。
書けない組み合わせ：インタフェースで cdp run、グローバルで cdp enable は使えない。
出典：Configuring Cisco Discovery Protocol（Disabling … on an Interface・Characteristics）／ Command Reference「lldp (interface configuration)」 ／ Cisco Guide to Harden Cisco IOS Devices（CDP・LLDP）

第2章

EtherChannelとLACP・PAgP

何本かのイーサネットのリンクを、1本の論理的なリンクに束ねる。STPから見ても1本なので、全部のリンクを使える。

CCNA #08 CDP・LLDPとEtherChannel2.4

束ねないと1本はSTPでブロック。束ねると全部使える

束ねないとき
EtherChannel（Po1）にしたとき
帯域束ねた本数ぶん増える。ただし1つの通信は1本を通る（第3章の負荷分散）
冗長1本切れたら残りのリンクへ自動で移る。管理者の操作はいらない
本数1つのEtherChannelで動くのは最大8本。LACPは16本まで入れて8本を待機にできる
出典：Cisco Layer 2 Configuration Guide 17.9.x (Catalyst 9300)「Configuring EtherChannels」（EtherChannel Overview・LACP：adds the group to the spanning tree as a single device port）

物理ポート → チャネルグループ → ポートチャネル（Po）

チャネルグループ
物理ポートで channel-group 1 mode active と書いて、どのPoに束ねるかを決める。1つのポートは1つのグループだけ。
ポートチャネル（Po）
EtherChannelを表す論理インタフェース。レイヤ2では channel-group を入れると同じ番号のPoが自動で作られる。
レイヤ3のとき
interface port-channel を作って no switchport にし、そこにIPアドレスを付けるのが構成ガイドの手順。
設定の置き場所
トランク・許可VLAN・ネイティブVLANは Po で設定すると、全部の物理ポートにそろって入る。
出典：Configuring EtherChannels（Channel Groups and Port-Channel Interfaces・EtherChannel Configuration Guidelines）

LACP と PAgP：どちらも「自動で束ねる」ための交渉のプロトコル

比べる点LACPPAgP
規格IEEE 802.3ad（標準。サーバや他社スイッチとも束ねられる）Cisco独自
自分から持ちかけるactivedesirable
来たら応じるだけpassiveauto
入れられる本数16本（動くのは8本、残り8本は待機＝ホットスタンバイ）8本
パケットの宛先01-80-C2-00-00-02（タイプ 0x8809）01-00-0C-CC-CC-CC（CDPと同じアドレス）
確かめること速度・デュプレックス・ネイティブVLAN・VLANの範囲・トランクかどうか がそろっているか
そのほか全二重のポートだけ。サイレントモードはないauto／desirable にサイレントモード（non-silent を付けなければサイレント）
混ぜられない：1つのEtherChannelはLACPかPAgPのどちらか。active と desirable は話が通じない。on はどちらも使わない3つ目の方法（次のページ）。
出典：Configuring EtherChannels（PAgP・LACP・Modes・Configuration Guidelines）／ Cisco Best Practices for Catalyst 6500/4500（PAgP・LACP：アドレスとタイプ、全二重のみ）

組み合わせ表：束ねられるのは「誰かが持ちかけ、プロトコルが同じ」とき

自分＼相手activepassivedesirableautoon
active○○×××
passive○××××
desirable××○○×
auto××○××
on××××○
オレンジ＝本番でよく狙われる「待つだけどうし」
  1. プロトコルが同じか：LACP（active・passive）どうし、PAgP（desirable・auto）どうし
  2. 誰かが持ちかけるか：passive＋passive、auto＋auto は誰も始めないので×
  3. on は on とだけ：on は交渉のパケットを送らない
DTPと似ている：dynamic desirable／dynamic auto（トランクの交渉）と同じ考え方。ただしDTPの auto＋auto はアクセスポートになり、PAgPの auto＋auto は「束ねない」。
出典：Configuring EtherChannels（PAgP Modes・LACP Modes・EtherChannel On Mode）。表はその記述からClaudeが組み合わせた

on モード：交渉しないぶん、間違いに気づけない

片側だけ on にしてしまったら
  • on：LACPもPAgPも使わず、強制的に束ねる。相手も on のときだけ使える
  • 構成ガイドの注意：「両端を同じ設定にする。間違えるとパケットの消失やスパニングツリーのループが起こりうる」
  • on でも、速度やデュプレックスがそろわないポートは suspended（一時停止）になる
  • 使いどころ：相手がLACPもPAgPも話せないとき
おすすめ：相手がLACPを話せるなら、両側 active。Best Practicesの推奨も「LACPなら両端 active」。交渉があれば、相手が束ねていないときに束ねずに済む。
出典：Configuring EtherChannels（EtherChannel On Mode・Caution）／ Cisco Best Practices for Catalyst 6500/4500（LACP active on both ends）

LACPのくわしい動き：待機・優先度・タイマー・本数

項目中身コマンドと初期値
ホットスタンバイ8本を超えたポートは待機。動いているリンクが切れると代わりに入る。summary では H16本まで設定できる
システムプライオリティどちらのスイッチが「使うポート」を決めるか。小さいほうが優先。MACアドレスと合わせてシステムIDlacp system-priority　32768
ポートプライオリティどのポートを束ね、どれを待機にするか。小さいほうが優先して束ねられるlacp port-priority（インタフェース）
lacp rateLACPのパケットの間隔。fast＝1秒、normal＝30秒。タイムアウトはその3倍（3秒／90秒）lacp rate fast　normal
max-bundle束ねる本数の上限。超えたポートは待機lacp max-bundle 3
min-links束ねた本数がこれより少ないとPo全体を止める（帯域不足のPoを使わせない）port-channel min-links 2
「小さいほうが勝つ」でそろえて覚える：LACPのシステム／ポートプライオリティとSTPのブリッジプライオリティは小さいほうが優先。OSPFのDRの選出（プライオリティもルータIDも大きいほうが勝つ）は逆なので注意。
出典：Configuring EtherChannels（LACP and Link Redundancy・Default EtherChannel Configuration・Configuring the LACP System Priority / Hot-Standby Ports）／ Command Reference「lacp rate」「lacp port-priority」
第3章

EtherChannelの設定と確認

レイヤ2ならスイッチポートのまま、レイヤ3なら no switchport にしてPoにIPアドレス。確認は show etherchannel summary。

CCNA #08 CDP・LLDPとEtherChannel2.4

レイヤ2 EtherChannel とレイヤ3 EtherChannel の設定

レイヤ2（トランクとして使う）
SW1(config)# interface range g1/0/1 - 2
SW1(config-if-range)# channel-group 1 mode active
! Po1 が自動で作られる
SW1(config)# interface port-channel 1
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk native vlan 99
SW1(config-if)# switchport trunk allowed vlan 10,20,99
  • トランクの設定は Po に入れる → 全メンバーにそろう
  • 束ねるポートは全部アクセス（同じVLAN）か全部トランク
レイヤ3（ルーティングに使う）
L3SW(config)# interface port-channel 10
L3SW(config-if)# no switchport
L3SW(config-if)# ip address 10.0.0.1 255.255.255.252
L3SW(config)# interface range g1/0/23 - 24
L3SW(config-if-range)# no switchport
L3SW(config-if-range)# no ip address
L3SW(config-if-range)# channel-group 10 mode active
  • IPアドレスはPoに付ける。物理ポートには付けない
  • 物理ポートも no switchport（レイヤをそろえる）
  • show etherchannel summary で Po10(RU)：R＝レイヤ3
出典：Configuring EtherChannels（Configuring Layer 2 EtherChannels・Configuring Layer 3 EtherChannels・Layer 3 EtherChannel Configuration Guidelines）

束ねるには設定をそろえる。そろわないポートは外される

そろえるものそろわないと
速度・デュプレックス束ねられない（on でも suspended）
アクセスかトランクか束ねられない
アクセスVLAN違うVLANのポートは束ねられない
ネイティブVLAN違うと束ねられない（構成ガイド）
許可VLANの範囲違うと、PAgP・LACPでも束ねられない
レイヤ2かレイヤ3か混ぜられない
ほかの決まりごと
  • 1つのポートは1つのグループだけ
  • 1つのグループで LACP と PAgP を混ぜない
  • STPのパスコストが違うだけなら束ねられる
  • グループを作ったときは、最初に入れたポートの設定にそろう。あとで変えるなら全ポート（またはPo）で変える
  • メンバーを shutdown するとリンクの障害と同じ扱い。通信は残りのポートへ移る
  • Catalyst 9300 では1台（スタック）で最大128個のEtherChannel
実務のコツ：まず物理ポートを default interface で初期化してから束ね、細かい設定は Po で入れる。食い違いが起きにくい。
出典：Configuring EtherChannels（Restrictions・EtherChannel Configuration Guidelines・Layer 2 EtherChannel Configuration Guidelines）。「実務のコツ」はClaudeの補足

負荷分散：アドレスから計算して、通すリンクを決める

方式（例）何で決めるか
src-mac送信元MAC。Catalyst 9300 の初期値
dst-mac宛先MAC
src-dst-mac送信元と宛先のMAC
src-ip／dst-ip／src-dst-ipIPアドレス
src-dst-port などTCP・UDPのポート番号
SW1(config)# port-channel load-balance src-dst-ip
SW1# show etherchannel load-balance
グローバル設定：方式はその機器の全部のEtherChannelに効く。相手のスイッチと同じにする必要はない（それぞれが自分の送る向きを決める）。
出典：Configuring EtherChannels（Load-Balancing and Forwarding Methods・Default EtherChannel Configuration・Configuring EtherChannel Load-Balancing）／ Best Practices for Catalyst 6500/4500（no misordering of frames）

負荷分散の選び方：「いろいろな値になるアドレス」で振り分ける

  1. その方向に流れる通信で、値がばらつくアドレスはどれか考える
  2. 宛先が1台に集まる → 送信元で分ける
  3. 送信元が1台に集まる → 宛先で分ける
  4. どちらとも言えない → 送信元と宛先の両方（src-dst-ip など）
  5. 端末どうしが1対1でも、TCP・UDPのポート番号まで使うと分かれやすい
本番の引っかけ：「EtherChannelにすれば1台のPCからの1つの転送も4倍速くなる」は誤り。
出典：Configuring EtherChannels（Load-Balancing Advantages：ルータの例と「宛先が1つのMACなら dst-mac は常に同じリンク」）。図はその説明からClaudeが描いた

EtherChannelができないときに確かめる順番

  1. show etherchannel summary：Po は U か D か、各ポートは P・I・s・H のどれか
  2. 相手側の設定：channel-group が入っているか。モードの組み合わせ（passive＋passive、auto＋auto、on＋active、LACP＋PAgP）
  3. ポートの設定：速度・デュプレックス・アクセスVLAN・ネイティブVLAN・許可VLANがそろっているか（show interfaces trunk、show running-config）
  4. 物理：リンクが up か。CDP・LLDPで、つながっている相手のポートが想定どおりか
  5. 相手から見て：show lacp neighbor で相手のLACPが見えているか
症状から逆引き
症状まず疑うところ
