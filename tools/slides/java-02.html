範囲をこえると回りこむ（オーバーフロー）

int の数直線は輪になっている（Claude が作成）
int x = 2147483647;
long y = x + 1;     // int で計算してから long へ
long z = x + 1L;    // long で計算
System.out.println(y + " " + z);
-2147483648 2147483648
エラーにも例外にもならない。整数の計算が範囲をこえると、静かに反対の端へ回りこむ。
代入先は関係ない：計算の型は右辺の式で決まる。x + 1 は int どうしなので int で回りこみ、そのあと long に広がる。片方を 1L にすれば long で計算される。

拡大変換 ― 自動で広がる向き

代入（キャストなし）結果
long l = i;（i は int）OK
float f = l;（l は long）OK（精度が落ちることあり）
int n = 'A';OK → 65
char c = b;（b は byte の変数）lossy conversion from byte to char
char c = s;（s は short の変数）lossy conversion from short to char
矢印の向きなら、代入するだけで変わる。float は 32 ビットだが、long（64 ビット）からも矢印がある（範囲が広いので）。ただし int・long → float、long → double は下の桁が丸められることがある。例外にはならない。
出典：JLS 5.1.2 Widening Primitive Conversion（byte to short, int, long, float, or double／short to int, long, float, or double／char to int, long, float, or double／int to long, float, or double／long to float or double／float to double／may result in loss of precision／never results in a run-time exception）／結果は JDK 17 で確かめたもの

縮小変換とキャスト

(byte) 200 が -56 になるわけ（Claude が作成）
System.out.println((byte) 200 + " " + (int) 3.99
                   + " " + (int) -3.99);
-56 3 -3
縮める変換動き
整数 → 小さい整数下位のビットだけ残す（符号が変わることも）
小数 → 整数小数部分を捨てる（0 の方向へ）。3.99 → 3、-3.99 → -3。四捨五入ではない
double → float近い float に丸める
キャストなしの縮小はコンパイルエラー（possible lossy conversion）。キャストを書けばコンパイルは通り、範囲外の値は黙って変わる（例外にはならない）。
特別ルール：byte b = 10; のように、範囲内の int の定数は byte・short・char にキャストなしで入る。final int i = 10; byte b = i; も OK。int i = 10; byte b = i; は NG。
出典：JLS 5.1.3 Narrowing Primitive Conversion（simply discards all but the n lowest order bits／the floating-point value is rounded to an integer value V using the round toward zero rounding policy）／5.2 Assignment Contexts（if the expression is a constant expression of type byte, short, char, or int: A narrowing primitive conversion may be used … byte theAnswer = 42; is allowed）／結果は JDK 17 で確かめたもの

計算の型と複合代入

計算の前に型をそろえる（数値の昇格）
式に含まれる型計算する型
double があればdouble
なければ float があればfloat
なければ long があればlong
それ以外（byte・short・char・int）int
byte + byte も int。char + char も int（'A' + 'B' は 131）。だから b = b + 1;（b は byte）は int を byte に入れることになり、エラー。
byte b = 10;
b = b + 1;       // lossy conversion from int to byte
b += 1;          // OK：b = (byte)(b + 1) と同じ
b++;             // OK
System.out.println(b);    // 12
byte c = 127;
c += 1;
System.out.println(c);    // -128（回りこむ）
複合代入（+= -= *= /= など）は、左辺の型へのキャストが自動で入る。E1 op= E2 は E1 = (T)((E1) op (E2))。
整数どうしの割り算は整数（5 / 2 は 2）。くわしくは #05 演算子。
出典：JLS 5.6 Numeric Contexts（If any expression is of type double, then the promoted type is double … In a numeric arithmetic context … the promoted type is int）／JLS 15.26.2 Compound Assignment Operators（E1 op= E2 is equivalent to E1 = (T) ((E1) op (E2)), where T is the type of E1）／結果は JDK 17 で確かめたもの

問われ方とまちがえやすい点

こう聞かれたら答えの考え方
