内部統制

全般統制が土台、業務処理統制が個々の処理を守る。

支援士 #23 サービスマネジメントとシステム監査4・12

内部統制の枠組み

四つの目的
業務の有効性・効率性／報告の信頼性／法令等の遵守／資産の保全
六つの基本的要素
統制環境リスクの評価と対応統制活動
情報と伝達モニタリングIT への対応
内部統制の限界
共謀で無効になりうる
経営者が無視・無効化しうる
想定外の事態・判断の誤り
→ 保証は「合理的」で、絶対ではない
J-SOX：上場企業の経営者が財務報告に係る内部統制を評価し、監査を受ける。
出典：金融庁「財務報告に係る内部統制の評価及び監査の基準（令和5年）」Ⅰ 1〜3

IT 全般統制と業務処理統制

IT 全般統制（土台）システムの開発・保守に係る管理（R6春）／運用・管理／アクセスなどの安全性の確保／外部委託の管理
IT 業務処理統制（個々の処理）入力情報の完全性・正確性・正当性／エラーの修正と再処理／マスタデータの維持管理／アプリの利用者認証と権限（R4春・R6秋）
規程・方針の策定や教育は、IT の統制ではなく全社的な統制の選択肢。
IT の統制目標
有効性・効率性業務に役立ち、無駄なく
準拠性法令・規程に従う
信頼性正確・完全。取引に漏れ・重複がない（R7春）
可用性必要なときに使える
機密性権限のない者に開示しない
出典：金融庁「財務報告に係る内部統制の評価及び監査に関する実施基準（令和5年）」／IPA 午前Ⅱ R4春 問25・R6春 問25・R6秋 問25・R7春 問25

監査の流れ

監査計画リスクアプローチ
→
予備調査概要把握・手続書
→
本調査証拠の入手と評価

用語意味
監査調書監査人が実施した監査のプロセスを記録したもの。結論の根拠（H31）
監査証拠運用・保守の記録、アクセスログ、トランザクションログ、監査証跡
保証型／助言型適切であることを保証する／問題を指摘し改善を助言する
CSA担当者が自らの統制を評価。監査人は参考にできる
出典：経済産業省「システム監査基準（令和5年）」／IPA 平成31年度春期 午前Ⅱ 問25

リスクアプローチ

監査リスク ＝ 固有リスク × 統制リスク × 発見リスク
固有リスク統制がないとした場合の誤りの起きやすさ
統制リスク統制で防げない・見つけられない
発見リスク監査手続で見逃す（監査人が調整できる）
R5春・R7秋で問われた考え方
リスクは変化する → 変化と影響に留意し、計画を見直す ← 正解
監査リスクを完全に回避 → できない
全対象に一律・均等に資源 → リスクに応じて配分
「統制リスクと残存リスク」の二つに大別 → 基準にない
出典：経済産業省「システム監査基準（令和5年）」／IPA 午前Ⅱ R5春 問25・R7秋 問25

指摘事項になるもの

場面指摘事項適切な管理（指摘しない）
DB の直接修正（R5秋）ログ上はアプリ経由の更新として記録事前・事後の承認、作業後に特権 ID を無効化
個人情報管理台帳（R2）見直しは新たな取得のときだけ概数での記載、保管場所・期限の記載
本番移行（R1秋）—役割と責任を明確にした移行計画がチェックポイント
クラウド導入（R3秋）—情報の保全には事業者の信頼性・継続性を確認
SaaS（R4秋）—利用者が評価できるのはアプリの利用者 ID
「記録が実態と違う」「定期的でない」「責任がない」は指摘。チェックポイントは、そのリスクに直接効くコントロールを選ぶ。
