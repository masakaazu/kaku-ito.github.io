第1章

書き方と構造

128 ビットを、短く正しく書く。

CCNA #05 IPv61.8

128 ビットの書き方と 2 つの省略

16 ビットずつ 8 つ（16 進 1 けた＝4 ビット）
省略決まり
① 先頭の 0各フィールドの左側の 0 は省ける。右側は省けない。0000 は 0
② ::0 だけのフィールドが続く所をまとめる。1 つのアドレスで 1 回だけ
RFC 4291 の例
2001:DB8:0:0:8:800:200C:417A → 2001:DB8::8:800:200C:417A
FF01:0:0:0:0:0:0:101         → FF01::101
0:0:0:0:0:0:0:1              → ::1   ループバック
0:0:0:0:0:0:0:0              → ::    未指定
:: が 2 回はだめ：2001:DB8::1::2 は、前と後ろの :: にそれぞれ何個の 0 が入るか決まらない。
右の 0 は残す：0800 → 800（○）、0800 → 08（×、0008 になる）。
英字の A〜F は大文字でも小文字でもよい（IPv6 Basic CG）。
出典：RFC 4291 2.2（x:x:x:x:x:x:x:x, where the 'x's are one to four hexadecimal digits of the eight 16-bit pieces／it is not necessary to write the leading zeros in an individual field／The "::" can only appear once in an address／2001:DB8::8:800:200C:417A … FF01::101 … ::1 … ::）・2.3（may drop leading zeros, but not trailing zeros）／IPv6 Basic CG（The hexadecimal letters in IPv6 addresses are not case-sensitive）

推奨表記（RFC 5952）と、プレフィックスの書き方

1 つのアドレスを 1 通りに書くための推奨
決まり例
先頭の 0 は必ず省く2001:0db8::0001 → 2001:db8::1
:: はできるだけ長く2001:db8::0:1 → 2001:db8::1
0 が 1 つなら :: にしない2001:db8:0:1:1:1:1:1 のまま
一番長い 0 の並びを ::2001:0:0:1:0:0:0:1 → 2001:0:0:1::1
同じ長さなら前を ::2001:db8:0:0:1:0:0:1 → 2001:db8::1:0:0:1
英字は小文字2001:DB8::1 → 2001:db8::1
読む側は、どの正しい書き方も受け付けなければならない。Cisco の出力は大文字で出る。
60 ビットのプレフィックス 2001:0DB8:0000:CD3
書き方判定
2001:0DB8:0000:CD30:0000:0000:0000:0000/60○
2001:0DB8::CD30:0:0:0:0/60○
2001:0DB8:0:CD30::/60○
2001:0DB8:0:CD3/60× 右の 0 を消した
2001:0DB8::CD30/60× CD30 が末尾になる
プレフィックス長：「アドレス/10 進」で、左から何ビットがプレフィックスかを表す。IPv4 のような点区切りのマスクは使わない。
出典：RFC 5952 4（all implementations MUST accept and be able to handle any legitimate [RFC4291] format／4.1 Leading zeros MUST be suppressed／4.2.1 MUST be used to its maximum capability／4.2.2 MUST NOT be used to shorten just one 16-bit 0 field／4.2.3 the longest run … the first sequence of zero bits MUST be shortened／4.3 MUST be represented in lowercase）／RFC 4291 2.3（ipv6-address/prefix-length／the following are legal representations of the 60-bit prefix 20010DB80000CD3／The following are NOT legal representations）

CCNA #05 IPv61.9

修正 EUI-64 の手順

  1. 分ける：48 ビットの MAC を前 24・後ろ 24 ビットに
  2. 挟む：間に FFFE を入れて 64 ビットに
  3. 反転：先頭オクテットの左から 7 ビット目（U/L ビット）を反転
  4. つける：プレフィックス（FE80:: や RA の /64）の後ろへ
反転の早わかり：先頭オクテットの値に 2 を足すか引く。00→02、3C→3E、02→00、A8→AA（Claude の言い方）。
U/L ビットは MAC では 0＝世界で 1 つ。修正 EUI-64 では反転するので 1＝世界で 1 つになる。
出典：RFC 4291 付録 A（insert two octets, with hexadecimal values of 0xFF and 0xFE … in the middle of the 48-bit MAC (between the company_id and vendor-supplied id)／The only change is inverting the value of the universal/local bit）・2.5.1（the "u" bit is set to one (1) to indicate universal scope）／9300 CR 17.8「show ipv6 neighbors」（FE80::203:A0FF:FED6:141E 0 0003.a0d6.141e REACH Ethernet2）。手順の計算は Claude

SLAAC と DAD

ホストがアドレスを作る流れ（Claude が作成）
  1. リンクローカル（FE80::＋インタフェース ID）を作り、DAD
  2. RS を送る（FF02::2 へ）
  3. ルーターが RA を返す（プレフィックス 2001:DB8:1:10::/64）
  4. プレフィックス 64＋インタフェース ID 64 ＝ グローバルアドレス
  5. そのアドレスも DAD。重ならなければ使う。RA のルーターを既定ルーターの候補に
ステートレス：だれにどのアドレスを渡したかをだれも覚えていない。きっちり管理したいなら DHCPv6（#17）。両方同時も可。
DAD（重複アドレス検出）アドレスを付ける前に、同じリンクで使われていないか NS で確かめる。SLAAC・DHCPv6・手動のどれでも、ユニキャストに行う。

答えが来たら重なり → そのアドレスは使えない
