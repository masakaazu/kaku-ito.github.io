第1章

管理アクセスの方法

コンソールで直接つなぐか、ネットワーク越しに入るか。ネットワーク越しなら、暗号化するものを選ぶ。

CCNA #11 機器の管理アクセス2.8

入り口は2つ：コンソール（直接）と VTY（ネットワーク越し）

方法ポート暗号化メモ
コンソール――直接つなぐ。ネットワークが壊れても使える
TelnetTCP 23なしパスワードも丸見え
SSHTCP 22ありTelnet のかわり。鍵が必要
HTTPTCP 80なしip http server
HTTPSTCP 443ありip http secure-server
クラウド―あり管理のデータだけがクラウドへ
VTY：Telnet と SSH のログイン口（仮想のライン）。設定は 全部の VTY に同じように入れる（0〜4 だけ設定して 5〜15 を忘れるのがよくあるミス）。
出典：Security Configuration Guide 17.9 (Catalyst 9300)「Controlling Switch Access with Passwords and Privilege Levels」（console 9600, 8, 1, no parity・line vty）／ 「Configuring Secure Socket Layer HTTP」／ RFC 854・RFC 4253（ポート）／ Meraki Cloud Architecture

Telnet と SSH：同じ「ログイン」でも、途中で見えるものが違う

Telnet（TCP 23）を途中で盗み見ると
User Access Verification
Username: netadmin
Password: Adm1n!
R1>enable
Password: Str0ngPass!
R1#show running-config
ユーザー名・パスワード・入れたコマンドが全部そのまま読める。
SSH（TCP 22）を途中で盗み見ると
SSH-2.0-Cisco-1.25
(鍵の交換)
8f 3a c1 0e 77 d2 9b 41 5e a0 ...
c4 19 6b f2 03 88 de 7a 21 90 ...
(暗号化されていて読めない)
鍵を交換したあとは中身が暗号化される。だからネットワーク越しのログインは SSH、Web は HTTPS にする。
Cisco の手引き中身
VTYTelnet や rlogin のかわりに transport input ssh で、暗号化した接続だけを受け付ける
HTTP使わないなら no ip http server・no ip http secure-server で止める
出典：Cisco Guide to Harden Cisco IOS Devices（Control Session Timeouts／use transport input ssh instead of clear-text protocols／The HTTP server can be disabled…）／ Security Configuration Guide 17.9「Configuring Secure Shell」。画面はClaudeが書いた例

レイヤ2スイッチに入るには：管理用 SVI と ip default-gateway

interface vlan 99
 ip address 10.1.99.11 255.255.255.0
 no shutdown
!
ip default-gateway 10.1.99.1
  • レイヤ2スイッチのポートには IP を付けない → VLAN のインタフェース（SVI）に付ける
  • SVI は、その VLAN のポートが up でないと up にならない
  • 別のサブネットへの返事は ip default-gateway のルーターに渡す。同じサブネットの PC からは、なくても入れる
  • スイッチが ip routing でルーティングしているなら、default-gateway は要らない（ルートで決める）
出典：Catalyst 2960 Software Configuration Guide 12.2(55)SE「Assigning the Switch IP Address and Default Gateway」（interface vlan・ip default-gateway…When your switch is configured to route with IP, it does not need to have a default gateway set）。アドレスはClaudeが書いた例
第2章

パスワードと特権レベル

「ラインに入るとき」と「特権EXECに上がるとき」の2か所で守る。保存のしかた（タイプ）にも気をつける。

CCNA #11 機器の管理アクセス5.3

パスワードを聞かれる場所は2か所

接続コンソール／VTY
→
① ラインのログインline の password ＋ login
または username ＋ login local
→
R1>ユーザーEXEC（レベル1）
→
② enableenable secret（または enable password）
→
R1#特権EXEC（レベル15）
! ① ラインのログイン
line console 0
 password C0nsole
 login
 exec-timeout 5 0
line vty 0 15
 login local
 transport input ssh
username netadmin secret Adm1n!
! ② 特権EXEC
enable secret Str0ngPass!
  • username … privilege 15 にすると、①のあとすぐ R1# になる（②を飛ばす）
  • 初期の特権レベルは2つだけ：1（>）と 15（#）。0〜15 の16段階まで分けられる
  • exec-timeout：何もしないで切れるまでの時間（初期10分）。0 0 は切れない
  • banner motd：ログイン前の警告。機器の名前や機種は書かない
「パスワードを決めたのに聞かれない」→ login が抜けている。「login を入れたら入れない」→ password が抜けている。
出典：Security Configuration Guide 17.9「Controlling Switch Access with Passwords and Privilege Levels」（Privilege Levels・Configuring Username and Password Pairs）／ Guide to Harden Cisco IOS Devices（exec-timeout・Warning Banners）

ラインの3つの書き方：何を聞かれるか

VTY の設定Telnet でつなぐと説明
login
（password なし）		Password required, but none set で切られるlogin を入れたとき「password を設定するまで無効」と警告が出る。パスワードのないVTYには入れない
password letmein
login		Password: だけ聞かれる全員が同じパスワード。だれが入ったかわからない
login local
（username あり）		Username: と Password:line の password は使われない。1人ずつ認証し、記録に名前が残る。SSH はこれ（か AAA）が必要
R2(config)# line vty 0 4
R2(config-line)# login
% Login disabled on line 66, until 'password' is set
...
R1# telnet 10.3.3.1
Password required, but none set
[Connection to 10.3.3.1 closed by foreign host]
出典：Cisco「Configure a Telnet Password on a Cisco Router」（Password required, but none set・Login disabled on line…until 'password' is set）／ Security Configuration Guide 17.9「Configuring Local Authentication and Authorization」

enable は secret を使う。保存のタイプは「戻せるか」で見る

R1(config)# enable password Cisco123
R1(config)# enable secret Str0ngPass!
R1(config)# service password-encryption
R1# show running-config | include enable|password
enable secret 9 $9$sMLBsTFXLnnHTk$0L82...
enable password 7 0822455D0A16
line con 0
 password 7 045802150C2E
  • 両方あれば enable secret が勝つ（同時には効かない）
  • IOS XE 16.10 以降、タイプを書かない secret は自動でタイプ9
  • service password-encryption は平文をタイプ7にするだけ。のぞき見よけ
タイプ中身戻せる？
0平文見える
7ヴィジュネル暗号すぐ戻せる
5MD5戻せない（古い）
6AES（マスターキー）鍵で戻せる
8PBKDF2（SHA-256）戻せない
9scrypt戻せない（推奨）
Cisco の手引き：タイプ7 は道具ですぐ戻せるので使わない。できるだけタイプ9（scrypt）：username admin algorithm-type scrypt secret …
出典：Security Configuration Guide 17.9「Controlling Switch Access…」（enable secret takes precedence・auto converted to type 9・type 0, 5, 8, and 9・type 6）／ Guide to Harden Cisco IOS Devices（simple Vigenère cipher・Use type 9 (scrypt) whenever possible）。出力はClaudeが書いた例

そのほかの守り：時間・警告・パスワードリカバリー

exec-timeout
line vty 0 15
 exec-timeout 5 0
  • 書き方は「分 秒」
  • 初期は10分
  • 0 0 は切れない（危ない）
  • SSH の交渉の待ち時間（ip ssh time-out）とは別
banner motd
banner motd #
Authorized access only.
#
  • 同じ区切り文字（#）で囲む
  • 「許可のない利用は禁止」を知らせる
  • 機器の名前・機種・持ち主は書かない（攻撃のヒント）
パスワードリカバリー
  • 起動を途中で止めて、パスワードを設定し直す手順
  • コンソールにさわれる人ならだれでもできる → 機器は鍵のかかる部屋に
  • 止めると（system disable password recovery switch all）、起動を止めたとき設定が消える
特権レベルを分ける例：privilege exec level 5 clear counters ＋ enable secret level 5 … → レベル5 に上がった人は clear counters も使える。今のレベルは show privilege。
出典：Guide to Harden Cisco IOS Devices（By default, sessions are disconnected after ten minutes of inactivity・Warning Banners）／ Security Configuration Guide 17.9「Controlling Switch Access…」（Password Recovery・Setting the Privilege Level for a Command）
第3章

SSHの設定

名前とドメイン → 鍵 → バージョン2 → ユーザー → VTY。抜けた手順ごとに、何が起きるかを覚える。

CCNA #11 機器の管理アクセス4.8

SSH の設定は7行。順番に意味がある

1hostname R1
2ip domain name example.com
3crypto key generate rsa modulus 2048
   The name for the keys will be: R1.example.com
   %SSH-5-ENABLED: SSH 1.99 has been enabled
4ip ssh version 2
5username netadmin secret Adm1n!
   line vty 0 15
6 login local
7 transport input ssh
#なぜ要るか
1・2鍵の名前は「ホスト名.ドメイン名」。初期の名前（Switch・Router）やドメインなしでは鍵を作れない
3鍵を作ると SSH が自動で動き出す。SSHv2 は 768ビット以上、Cisco の推奨は1024ビット以上
4弱い v1 を使わない（1.99＝v1とv2の両方 → 2.0）
5・6SSH の認証はユーザー名とパスワード（ローカル・RADIUS・TACACS+）
7VTY で受け付けるのを SSH だけにする（Telnet を止める）
鍵を消す crypto key zeroize rsa をすると、SSH のサーバーも止まる。
出典：Security Configuration Guide 17.9「Configuring Secure Shell」（Prerequisites・Setting Up the Device to Run SSH・We recommend that a minimum modulus size of 1024 bits）／ 「Secure Shell Version 2 Support」（at least 768 bits）。表示の行はClaudeが書いた例

抜けた手順で起きること（トラブルの読み方）

抜けている／まちがい起きること
hostname が初期のままcrypto key generate rsa で No host name specified。鍵ができず SSH は動かない
ip domain name がないNo domain specified。鍵ができない
鍵を作っていないshow ip ssh が SSH Disabled。SSH でつなぐと拒否される
username がない（login local）ユーザー名を聞かれても、だれも認証できない
transport input telnet ssh のままSSH も使えるが、Telnet でも入れてしまう
vty 0 4 だけ設定5本目以降のセッションは別の設定のまま（入れない、または Telnet で入れる）
SVI か default-gateway がない（スイッチ）そもそも IP で届かない／別のサブネットから入れない
出典：Security Configuration Guide 17.9「Configuring Secure Shell」（SSH Configuration Guidelines：No host name specified／No domain specified）／ Guide to Harden Cisco IOS Devices（transport input）／ Catalyst 2960 Configuration Guide（ip default-gateway）

確かめる：show ip ssh と transport input

R1# show ip ssh
SSH Enabled - version 1.99
Authentication timeout: 120 secs; Authentication retries: 3

R1(config)# ip ssh version 2
R1# show ip ssh
SSH Enabled - version 2.0
Authentication timeout: 120 secs; Authentication retries: 3
  • 1.99＝v1 と v2 の両方を受け付ける／2.0＝v2 だけ
  • timeout と retries は ip ssh time-out・ip ssh authentication-retries で変える
  • show ssh は「今つながっているセッション」の一覧（別のコマンド）
transport input の書き方
設定SSHTelnet
transport input ssh○×
transport input telnet×○
transport input telnet ssh○○
transport input none××
transport output は、その機器から外へつなぐときのプロトコル。入ってくるのを決めるのは input。
出典：Security Configuration Guide 17.9「Secure Shell Version 2 Support」（Verifying the Secure Shell Version 2 Status：SSH Enabled - version 1.99／2.0）／ Guide to Harden Cisco IOS Devices（transport input ssh・transport input none）

どこから入れるか：VTY には access-class

access-list 10 permit 10.1.50.0 0.0.0.255
!
line vty 0 15
 access-class 10 in
 login local
 transport input ssh
コマンドかける場所
access-class … inライン（VTY）：ログインしてよい送信元を絞る
ip access-group … inインタフェース：そこを通る全部の通信にかかる
最後に見えない「全部拒否」があるので、許す送信元だけ permit を書けばよい（ACL は #22 で詳しく）。
出典：Guide to Harden Cisco IOS Devices（Other forms of vty and tty access controls can be enforced with the transport input or access-class configuration commands）。アドレスはClaudeが書いた例
第4章

AAAとTACACS+・RADIUS

ユーザーを機器ごとに作らず、サーバーにまとめる。だれか・何をしてよいか・何をしたか、の3つ。

CCNA #11 機器の管理アクセス2.8

AAA：だれ？ → 何をしてよい？ → 何をした？

Authentication（認証）だれ？ 本人か確かめる
ユーザー名・パスワード・証明書
→
Authorization（認可）何をしてよい？
特権レベル・使えるコマンド・VLAN
→
Accounting（アカウンティング）何をした？
ログインの時間・入れたコマンドの記録
aaa new-model
!
tacacs server TAC1
 address ipv4 10.1.50.5
 key T@cKey
!
aaa authentication login default group tacacs+ local
aaa authorization exec default group tacacs+ local
aaa accounting commands 15 default start-stop group tacacs+
!
username backup privilege 15 secret B@ckup1
  • aaa new-model で AAA を有効にする
  • key（共有の鍵）は機器とサーバーで同じにする。違うと認証できない
  • サーバーが落ちたときのために、ローカルのユーザー（backup）も残す
  • サーバーを使うと、管理者ごとのアカウント・退職者の停止・記録が1か所でできる
出典：Security Configuration Guide 17.9「Configuring TACACS+」（separate and modular authentication, authorization, and accounting）／ Guide to Harden Cisco IOS Devices（TACACS+ Authentication・Command Authorization・Command Accounting・fallback）

TACACS+ と RADIUS：機器の管理には TACACS+、利用者の接続には RADIUS

TACACS+RADIUS
生まれCisco（今は RFC 8907）IETF の標準（RFC 2865）
運び方TCP 49UDP 1812（認証）・1813（アカウンティング）
Cisco の古い初期値は1645・1646
暗号化パケットの中身全部パスワードだけ（ユーザー名などは見える）
認証と認可分けられるいっしょ（Access-Accept に認可の情報が入る）
コマンドごとの許可できるできない
主な使い道ルーター・スイッチの管理者のログイン802.1X・無線・VPN など利用者の接続
覚え方：TACACS+ は TCP・全部暗号化・コマンドの許可 → 管理者向け。RADIUS は UDP・パスワードだけ・標準 → 利用者のネットワーク接続向け。Cisco の手引きも、使えるなら機器の管理は TACACS+ をすすめている。
出典：Cisco「TACACS+ and RADIUS Comparison」（UDP and TCP・Packet Encryption・Authentication and Authorization・Router Management）／ RFC 8907（TCP port 49）・RFC 2865（1812）／ 「Configuring RADIUS」（auth-port 1812／1645）／ Guide to Harden

メソッドリスト：次へ進むのは「エラー」のときだけ

方法何で認証するか
group tacacs+／group radiusサーバー
local機器の username
enableenable のパスワード
lineline の password
none認証しない（入れてしまう）
