OSINT・脅威ハンティング・テイクダウン

OSINT
報道・SNS・公開レポート・CT ログ・WHOIS。防御側は自組織の漏えいや攻撃予告を探す。攻撃者は偵察に使う（#02）。
脅威ハンティング
潜んでいる前提で、仮説を立てて能動的に探す。アラートを待つ通常の監視と違う。見つけた手口は検知ルールへ。
テイクダウン
フィッシングサイト・配布サイト・C2 の停止を、ホスティング事業者や登録事業者に依頼。証拠を残してから。

インシデント対応の4つの段階（SP 800-61 Rev.2）

準備体制・IRP・連絡先・ツール・訓練
→
検知・分析兆候の発見・トリアージ・範囲の特定・記録
→
封じ込め・根絶・復旧隔離 → 原因除去 → 戻して監視
→
事後対応事後レビュー・再発防止
よくある誤り正しくは
感染 PC の電源をすぐ切るネットワークから切り離し、電源は入れたまま（メモリの証拠）
原因を除く前に復旧する根絶してから。でないと再侵入される
確かめてから報告するまず報告。記録は最初から
担当者の責任を追及する仕組みの改善に目を向ける
トリアージ：インシデントか、範囲内か、影響と緊急度は → 優先順位。
2025年の Rev.3 は CSF 2.0 の6つの機能（統治・識別・防御・検知・対応・復旧）に合わせて組み直した。Rev.2 の4段階も引き続き基本。

報告・通知・公表：個人データの漏えいのとき

個人情報保護委員会への報告と本人通知が義務になる事態

②財産的被害のおそれ（カード番号など）

④1,000人を超える漏えい

時間の軸で見る

まとめ：本番での問われ方

言葉の定義：IoC＝侵害の痕跡、UEBA＝異常なふるまいの検知、STIX＝形式、TAXII＝手順、TLP＝共有範囲。
順番：準備 → 検知・分析 → 封じ込め → 根絶 → 復旧 → 事後対応。
数字：漏えい報告の速報（3〜5日）・確報（30日／不正目的は60日）。RTO は時間、RPO は時点。
科目B（午後）の定番：ログから感染端末を特定 → 隔離の判断 → 影響範囲の調査 → 報告先と期限 → 再発防止。「電源を切る」「確かめてから報告」は誤り。
SIEM・SOAR・EDR などの監視の製品は #12、証拠の保全とフォレンジックは #19。
