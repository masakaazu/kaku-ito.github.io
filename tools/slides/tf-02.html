宣言とバージョン

どこから、どの版を。

Terraform #02 プロバイダー目標 2a・2b・2c

required_providers とソースアドレス

terraform { required_version = ">= 1.12" # 本体 required_providers { aws = { # ← ローカル名 source = "hashicorp/aws" # ← ソースアドレス version = "~> 5.0" # ← バージョン制約 } } }
各モジュールが自分で書く。子は親の source・version を受け継がない。
部分意味
HOSTNAME（省略可）省くと registry.terraform.io
NAMESPACE配布する組織（hashicorp など）
TYPE短い名前（aws など）
hashicorp/aws ＝ registry.terraform.io/hashicorp/aws
source を省くと registry.terraform.io/hashicorp/<ローカル名> とみなす（明示がおすすめ）
出典：Provider Requirements（Requiring Providers／Source Addresses／Local Names）

バージョン制約と ~>

書き方選べる版
= 1.2.0（演算子なしも）1.2.0 だけ
!= 1.2.01.2.0 以外
>= 1.2.0, < 2.0.0両方を満たすもの
~> 1.0.41.0.5・1.0.10 ○　1.1.0 ×
~> 1.11.2・1.10 ○　2.0 ×
~> は『いちばん右の部分だけ』上がってよい。
再利用するモジュール>= で下限だけ（使う側が上げられる）
ルートモジュール~> で上限と下限（思わぬ大きな更新を防ぐ）
version を省くと『any version』。プレリリース版は = で正確に書いたときだけ。
出典：Version constraints（Operators／Best practices）／Provider Requirements

依存関係ロックファイル（.terraform.lock.hcl）

provider "registry.terraform.io/hashicorp/aws" { version = "5.10.0" constraints = "~> 5.0" hashes = [ "h1:...", "zh:...", ] }
init が作る・更新する。手で書かない。VCS にコミットしてレビュー。
問い答え
何を記録？プロバイダーのバージョンとチェックサムだけ（モジュールは記録しない）
新しい版が出たら？記録があれば同じ版を選び続ける
上げたいときは？terraform init -upgrade（制約に合う最新を選び直す）
なぜ .hcl？.tf の設定ファイルではないから
出典：Dependency Lock File／Command: init（-upgrade・-lockfile=readonly）

provider ブロックと terraform providers

provider "aws" { region = var.region # ○ 前もって分かる値 # region = aws_vpc.main.id ← × 適用で決まる値 } # 認証情報は環境変数などで渡す $ export AWS_ACCESS_KEY_ID=...
provider ブロックの version は非推奨。alias と同じブロックには書けない。
書かないと『an empty default configuration』（必須の引数があればエラー）。
$ terraform providers Providers required by configuration: . ├── provider[registry.terraform.io/hashicorp/aws] ~> 5.0 └── module.vpc └── provider[registry.terraform.io/hashicorp/aws]
要求がどのモジュールから来たかが分かる。
出典：provider block reference／Command: providers
第3章

複数のプロバイダーと alias

2 つのリージョン、2 つのクラウド。

Terraform #02 プロバイダー目標 2a・2b・2c

alias で同じプロバイダーを 2 つ

provider "aws" { # 既定 region = "us-east-1" } provider "aws" { # 別の設定 alias = "west" region = "us-west-2" } resource "aws_instance" "foo" { provider = aws.west # 引用符なしの参照 }
provider を書かない型名の先頭（aws）の既定の設定
provider = aws.west<PROVIDER_NAME>.<ALIAS> で選ぶ
全部に alias がある空の既定の設定がつくられる
AWS と Azure のように、ちがう種類のプロバイダーは required_providers に並べて書くだけ。
出典：provider block reference（alias／Select an alternate provider configuration）／Provider Requirements

子モジュールへの受け渡し

# ルート module "vpc_west" { source = "./modules/vpc" providers = { aws = aws.west } } # 子（alias を受け取るとき） terraform { required_providers { aws = { source = "hashicorp/aws" configuration_aliases = [ aws.west ] } } }
受け継ぐものどうなるか
既定の provider 設定自動で子に渡る
alias の設定子で configuration_aliases、親で providers
source・version の要求受け継がない（子の required_providers に書く）
子モジュールに provider ブロックを書くのは『strongly recommend against』。
出典：provider block reference（Pass provider configurations to a child module）
