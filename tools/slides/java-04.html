回しながら消すと ConcurrentModificationException

NG：拡張 for の中でリストの remove
List<String> list = new ArrayList<>(List.of("a", "b", "c"));
for (String s : list) {
  if (s.equals("a")) list.remove(s);
}
Exception in thread "main" java.util.ConcurrentModificationException
OK：removeIf か Iterator の remove
list.removeIf(s -> s.equals("a"));       // [b, c]

Iterator<String> it = list.iterator();
while (it.hasNext()) {
  if (it.next().equals("a")) it.remove(); // OK
}
用語中身
イテレータ要素を 1 つずつ取り出す係。拡張 for は中でこれを使う
構造の変更add・remove・clear など要素数が変わる操作。set は含まない
fail-fastイテレータ自身以外による構造の変更に気づいたら、すぐ例外で止まる
best-effort必ず止まる保証はない。例外を当てにしたコードは書かない
本番での判断：拡張 for の中で list.add・list.remove を呼ぶコード → ConcurrentModificationException を選ぶ。安全な書き方は removeIf・Iterator.remove。
出典：Java SE 17 API ArrayList（The iterators returned by this class's iterator and listIterator methods are fail-fast: if the list is structurally modified at any time after the iterator is created, in any way except through the iterator's own remove or add methods, the iterator will throw a ConcurrentModificationException／Fail-fast iterators throw ConcurrentModificationException on a best-effort basis）／結果は JDK 17 で確かめたもの

問われ方とまちがえやすい点

こう聞かれたら答えの考え方
配列の宣言がコンパイルできるか長さと {…} の同時はダメ。{…} だけは宣言と同時のみ。多次元は左の [] から長さを書く
何も入れていない要素の表示既定値：0・0.0・false・null
要素数の書き方配列 length、String length()、ArrayList size()
範囲外・負の長さコンパイルは通る。実行時に ArrayIndexOutOfBounds・NegativeArraySize
コピーしたあとの表示代入は共有。clone は別の配列だが、多次元の内側は共有（浅いコピー）
配列の比較・表示equals は ==。中身は Arrays.equals・Arrays.toString
ArrayList の操作の結果add(i, e) は挿入。set は前の値を返す。remove(int) と remove(Object) を見分ける
リストを変更できるかList.of は全部ダメ。asList は set だけ OK。どれも実行時の例外
