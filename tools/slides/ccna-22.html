第1章

ACL の基本

上から順に比べて、最初に合った行で決める。

CCNA #22 ACL5.6

上から順の照合と暗黙の deny

順番をまちがえた例（1台だけ止めたい）
access-list 1 permit any               ! 全部に合う
access-list 1 deny host 192.168.10.1   ! ここまで来ない
正しい順番
access-list 1 deny host 192.168.10.1
access-list 1 permit any               ! 書かないと全部止まる
2つの落とし穴：広い条件を上に書くと、下の細かい行に届かない。permit を1行も書かない ACL は全部を止める（暗黙の deny）。
Cisco の勧めよく合う行は上に置く（比べる回数が減る）
出典：Security CG IOS XE 17.9（Catalyst 9300）「IPv4 ACLs」（The first match determines whether the device accepts or rejects the packet … the order of the conditions is critical. If no conditions match, the device denies the packet）／Cisco Doc 26448「Configure Commonly Used IP ACLs」（If the order of the entries is reversed …, the first line matches every packet source address）／Cisco Doc 23602（you must have the frequently hit entries at the top of the list）

ワイルドカードマスク0 は「同じでなければならない」、1 は「何でもよい」

10.1.1.0 0.0.0.255 を2進数で見る
第1第2第3第4
アドレス00001010000000010000000100000000
ワイルドカード00000000000000000000000011111111
意味一致一致一致何でもよい
→ 10.1.1.0〜10.1.1.255 のどれにも合う。サブネットマスク（255.255.255.0）と 0 と 1 の意味が逆なので、逆マスク（inverse mask）とも呼ぶ。
ワイルドカード ＝ 255.255.255.255 − サブネットマスク
キーワードで書ける2つ
キーワード正式な書き方合うもの
any0.0.0.0 255.255.255.255全部（全ビット無視）
host 10.1.1.210.1.1.2 0.0.0.0その1台（全ビット一致）
求め方の例
プレフィックスサブネットマスクワイルドカード
/24255.255.255.00.0.0.255
/26255.255.255.1920.0.0.63
/27255.255.255.2240.0.0.31
/30255.255.255.2520.0.0.3
標準 ACL でマスクを省くと 0.0.0.0（host と同じ）とみなされる。
出典：Cisco Doc 23602「Configure IP Access Lists」（ACLs use a wildcard mask (also called an inverse mask) … each 0 … must match exactly, and each 1 … can be ignored／0.0.0.0/255.255.255.255 means any）／Security CG 17.9（9300）「IPv4 ACLs」（The keyword host … source 0.0.0.0／if you omit the mask …, 0.0.0.0 is assumed）。/26・/30 の行はClaudeが同じ式で計算した例

ワイルドカードの範囲を読む

192.168.148.0 0.0.1.255（Cisco の例）
第3オクテット第4オクテット
アドレス10010100（148）00000000
ワイルドカード00000001（1）11111111（255）
取りうる値148 と 1490〜255
→ 192.168.148.0〜192.168.149.255（/23 と同じ範囲）。ワイルドカードが 1 のビットの数だけ範囲が広がる。
172.20.128.64 0.0.0.31（Cisco の例）
範囲64 から 32 個 → 172.20.128.64〜172.20.128.95
読み方の手順
  1. ワイルドカードが 0 のオクテットはそのまま（一致が必要）
  2. 0 でも 255 でもないオクテットを探す（例：1、31、63）
  3. その値＋1 がそのオクテットの幅（1→2、31→32、63→64）
  4. アドレスのその値から、幅のぶんだけが範囲
  5. 右側の 255 のオクテットは 0〜255 全部
ひっかけ：/27 のワイルドカードを 0.0.0.32（ブロックの大きさそのもの）と答えない。1 を引いて 0.0.0.31。
出典：Cisco Doc 23602（access-list 10 permit 192.168.148.0 0.0.1.255）／Security CG 17.9（9300）「IPv4 ACLs」（access-list 6 permit 172.20.128.64 0.0.0.31 … source addresses 172.20.128.64 to 172.20.128.95）。読み方の手順はClaudeがまとめた

標準と拡張

送信元だけを見るか、宛先やポートまで見るか。

CCNA #22 ACL5.6

標準 ACL と拡張 ACL

標準 ACL拡張 ACL
番号1〜99、1300〜1999100〜199、2000〜2699
比べるもの送信元アドレスだけプロトコル・送信元・宛先・ポート・TCP のフラグなど
書き方access-list 6 permit 172.20.128.64 0.0.0.31access-list 106 permit ip any 172.20.128.64 0.0.0.31
名前付きで作るip access-list standard 名前ip access-list extended 名前
置き場所の目安宛先の近く送信元の近く
拡張 ACL の決まり：送信元と宛先の前にプロトコル（ip・tcp・udp・icmp など）を必ず書く。ip は TCP・UDP・ICMP も含む全部。
標準 ACL の限界：宛先を見られないので「この送信元から、このサーバーへの通信だけ止める」は書けない。それには拡張 ACL。
出典：Security CG 17.9（9300）「IPv4 ACLs」（Access List Numbers の表／standard ACLs use only source addresses …／with extended ACLs, you must enter the protocol (IP) before the source and destination information／例 access-list 6・access-list 106）／Cisco Doc 23602（IP includes TCP, UDP, ICMP）

拡張 ACL の1行を分解する

ポートの比べ方
書き方意味例
eq等しいeq 23（Telnet）
gt／ltより大きい／より小さいgt 1023
neq等しくないneq 80
range範囲（両端を含む）range 20 21
established
意味TCP の ACK か RST が立ったパケットに合う＝すでに始まった通信
access-list 102 permit tcp any 172.16.0.0 0.0.255.255 established
中から始めた TCP の戻りは通り、外から始める SYN だけのパケットは合わない。UDP には使えない。
出典：Security CG 17.9（9300）「IPv4 ACLs」（operator and port … source (if positioned after source …) or destination (if positioned after destination …)／eq, gt, lt, neq, range (inclusive range)／established … same function as matching on the ack or rst flag／the flag and established keywords are not valid for UDP）。上の1行の例はClaudeが書いた

名前付き ACL と IPv6 ACL

番号付きと名前付き
番号付き（access-list で作る）名前付き
作り方access-list 101 …ip access-list extended WEB
行を足すいつも最後に付く番号を付けて間に入れられる
1行だけ消すできない（no access-list で全部消える）できる（no 20 など）

名前の代わりに番号（ip access-list extended 101）で入ると、番号付き ACL も行ごとに直せる（第4章）。
IPv6 ACL
IPv4IPv6
作り方番号付き・名前付き名前付きだけ（ipv6 access-list）
付け方ip access-groupipv6 traffic-filter
最後暗黙の deny暗黙の deny

第3章

適用と置き場所

どのインタフェースに、どの向きで付けるか。

CCNA #22 ACL5.6

in と outip access-group 番号か名前 in｜out

interface g0/1
 ip access-group 106 in     ! 入ってくるパケット
interface g0/2
 ip access-group 6 out      ! 出ていくパケット
向きはルーターから見る：in＝そのインタフェースに入ってくる、out＝そのインタフェースから出ていく。in で捨てればルーティングの手間もかからない。
出典：Security CG 17.9（9300）「IPv4 ACLs」（For inbound ACLs, after receiving a packet, the device checks the packet against the ACL／For outbound ACLs, after receiving and routing a packet to a controlled interface, the device checks the packet／ip access-group 106 in・ip access-group 6 out）

どこに置くか拡張は送信元の近く、標準は宛先の近く

置き場所理由
拡張送信元のできるだけ近く宛先・ポートで絞れるので、早く捨てても止めすぎない
標準宛先のできるだけ近く宛先を見られないので、送信元の近くでは止めすぎる
Cisco の教材は、ほかに管理の範囲（自分が設定できる機器か）、帯域、設定のしやすさも置き場所を決める理由に挙げている。
出典：Cisco Networking Academy「Routing and Switching Essentials」Chapter 9（Extended ACLs - Locate extended ACLs as close as possible to the source … Standard ACLs - … place them as close to the destination as possible）／Cisco Doc 23602（It is a good practice to apply the ACL on the interface closest to the source of the traffic）。図の構成はClaudeが書いた例

3つの P・access-class・中身のない ACL

3つの P（1つのインタフェースに付けられる数）
ごとに1つ意味
ProtocolIPv4 と IPv6 は別の ACL
Directionin と out は別の ACL
Interfaceインタフェースごとに付ける
IPv4＋IPv6 で in と out → 1つのインタフェースに最大4つ。同じ向きに別の ACL を付けると入れ替わる。
中身のない ACL を付けたら
ip access-group 150 in と書いて ACL 150 を作っていないと、ACL がないのと同じで全部通る（暗黙の deny で止まるのではない）。
機器へのログインをしぼる：access-class
access-list 10 permit host 10.10.10.5
line vty 0 4
 access-class 10 in
ip access-groupaccess-class
付け先インタフェースVTY 回線
しぼるもの通り抜ける通信Telnet・SSH のログイン
ACL標準・拡張送信元だけで決めるので標準で足りる
出典：Netacad「Routing and Switching Essentials」Chapter 9（The Three Ps … One ACL per protocol … per direction … per interface／because the access-class command is used to filter … Telnet/SSH sessions by source address, a standard ACL can be used）／Security CG 17.9（9300）「IPv4 ACLs」（the new ACL replaces the previously configured one／When you apply an undefined ACL …, the device acts as if the ACL has not been applied … and permits all packets／access-class 10 in）
第4章

編集と確認

シーケンス番号で直し、一致数と付け先を確かめる。

CCNA #22 ACL5.6

シーケンス番号で直す

先頭に1行入れる（Cisco の例）
Router# show access-list
Extended IP access list 101
    10 permit tcp any any
    20 permit udp any any
    30 permit icmp any any
Router(config)# ip access-list extended 101
Router(config-ext-nacl)# 5 deny tcp any any eq telnet
Router# show access-list
Extended IP access list 101
    5 deny tcp any any eq telnet
    10 permit tcp any any
    20 permit udp any any
    30 permit icmp any any
番号を書かずに足した行は 10 ずつ増え、最後に付く。番号は 1〜32767（9300）。
直し方の早見表
やりたいことコマンド
間に入れるACL のモードで 15 permit …
1行消すACL のモードで no 20
番号を付け直すip access-list resequence 名前 100 15
ACL を全部消すno access-list 101
ひっかけ：グローバル設定で no access-list 101 deny icmp any any と1行を書いても、ACL 101 が丸ごと消える。
resequence kmd1 100 15 → 100、115、130 … と付け直す（順番は変わらない）。
出典：Cisco Doc 23602（The sequence numbers such as 10, 20, and 30／5 deny tcp any any eq telnet … added as the first entry／if you intend to delete a specific line from a numbered ACL …, the entire ACL is deleted）／Security CG: ACLs（IOS XE）「IP Access List Entry Sequence Numbering」（Use the no sequence-number command to delete an entry／ip access-list resequence kmd1 100 15）／Security CG 17.9（9300）「IPv4 ACLs」（sequence number (1 to 32767)）

確かめる：一致数と付け先

show ip access-lists（中身と一致数）
Router# show ip access-lists interface FastEthernet0/0 in
Extended IP access list 150 in
    10 permit ip host 10.1.1.1 any
    30 permit ip host 10.2.2.2 any (15 matches)
行の後ろの (15 matches) がその行に合ったパケットの数。合っていない行には出ない。show access-lists は IP 以外（MAC）の ACL も含めて出す。
remark と log
access-list 1 remark Permit only user1 workstation through
access-list 101 deny ip any any log
remark は説明（1行 100 文字まで、照合に使わない）。log は合ったパケットを informational のログに出す。
何で何が分かるか
コマンド分かること
show access-lists全部の ACL の中身と一致数
show ip access-listsIPv4 の ACL だけ
show ip interface g0/1そのインタフェースにどの ACL がどの向きで付いているか
show running-configACL の設定と付け先の両方
log の注意：ログはソフトウェアで作るので、たくさん合うと全部は記録されない。数を正確に数えるのは一致数（matches）で。
出典：Cisco IOS Security Command Reference: Commands S to Z「show ip access-lists」（出力例 30 permit ip host 10.2.2.2 any (15 matches)／identical to the show access-lists command, except that it is IP-specific）／Security CG 17.9（9300）「IPv4 ACLs」（show ip interface … the access groups are included in the display／Each remark line is limited to 100 characters／informational logging message … not all packets will be logged）

よくあるひっかけ

よくある思い込み正しくは
合った行が複数あれば、いちばん細かい行で決まる上から最初に合った行で決まる。下は見ない
どの行にも合わなければ通る最後の暗黙の deny で捨てる
/27 のワイルドカードは 0.0.0.320.0.0.31（255.255.255.255 − 255.255.255.224）
標準 ACL は 100〜199標準は 1〜99・1300〜1999、拡張が 100〜199・2000〜2699

同じ向きに ACL を2つ付けられる1つの向きに1つ。新しい方と入れ替わる

まとめ

ACL の基本上から順に比べ、最初に合った行で決定。最後は暗黙の deny。ワイルドカードは 0＝一致・1＝無視、any と host
標準と拡張標準 1〜99（送信元だけ）、拡張 100〜199（プロトコル・宛先・ポート・established）。名前付きは1行ずつ直せる。IPv6 は名前付きだけ
適用と置き場所ip access-group in／out。1つの向きに1つ。拡張は送信元、標準は宛先の近く。VTY は access-class
