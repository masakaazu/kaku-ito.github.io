アクセス制御のモデルと仕組み

だれが決めるのか、何をもとに判断するのか。

支援士 #10 アクセス制御と利用者認証25-4

アクセス制御の4つのモデル

モデルだれが決める判断のもと特徴
DAC 任意資源の所有者所有者が付けた ACL・パーミッション柔軟／誤って公開しやすい
MAC 強制システムの方針主体と資源のラベル（機密区分）所有者も変えられない
RBAC ロール管理者利用者に割り当てた役割異動はロールの付け替え
ABAC 属性管理者のポリシー主体・資源・環境（時刻・場所・端末）の属性細かい・状況に応じる
Bell-LaPadula（MAC の代表的なモデル）
極秘「秘」の人は読めない（no read up）
秘自分の区分
公開「秘」の人は書けない（no write down）＝下へ漏らさない
略語の MAC は3つある：強制アクセス制御（Mandatory Access Control）、メッセージ認証符号（Message Authentication Code、#15）、MAC アドレス（Media Access Control）。文脈で見分ける。
出典：IPA「支援士試験 シラバス（案）」用語例「MAC，DAC，RBAC，ABAC」／NIST SP 800-162

特権を絞る：最小特権・PAM・セキュア OS

特権アクセス管理（PAM）の流れ
申請・承認
→
一時的に貸出しパスワードは見せない
→
操作を記録・録画
→
返却・パスワード自動変更
必要なときだけ権限を上げる Just-In-Time。常に管理者権限で動かさない。
セキュア OS（SELinux・AppArmor・TOMOYO）
強制アクセス制御＋最小特権。root でも方針の外は操作できない。
# Web サーバのプロセスに許すのは httpd_t → /var/www/html 読み取り 許可 httpd_t → /etc/shadow 読み取り 拒否
乗っ取られても、被害を方針の範囲に閉じ込める。脆弱性そのものはなくならない。
出典：IPA「支援士試験 シラバス（案）」用語例「最小特権，特権アクセス管理（PAM），セキュア OS」。SELinux の例は Claude が単純化

保存データの暗号化：何から守れるか

方式単位守れる守れない
ストレージ暗号化ディスク全体（BitLocker・FileVault・SED）紛失・盗難・廃棄起動中の端末の乗っ取り
ファイル暗号化ファイルごと（IRM・DRM も）持ち出し・誤送信鍵を持つ人の漏えい
DB 暗号化（TDE）データファイル全体を DBMS が自動でデータファイル・バックアップの盗難SQL インジェクション・権限のある内部者
DB 暗号化（列）特定の列だけ（アプリで復号）DB 管理者からも隠せるアプリの脆弱性
TDE はアプリを変えずに入れられるが、正規の SQL で読めば復号された値が返る。「暗号化したから SQL インジェクションでも安全」は誤り。
出典：IPA「支援士試験 シラバス（案）」用語例「ストレージ暗号化，ファイル暗号化，データベース暗号化」。表は Claude がまとめた

生体認証とパスワードレス認証

生体情報は端末から出さない。

支援士 #10 アクセス制御と利用者認証25-4

生体認証の精度：FRR・FAR・EER

指標意味
FRR本人を拒否する割合（使いにくさ）
FAR他人を受け入れる割合（危なさ）
EERFRR＝FAR の点。小さいほど高精度
しきい値を厳しく → FAR↓ FRR↑。緩く → FAR↑ FRR↓。
R7秋 問10：成人の虹彩は変わらない → 更新ほぼ不要（正解）。静電容量方式の指紋は照明の影響なし。コイルの誘導起電力は非接触型 IC カード。
出典：JIS X 8101（ISO/IEC 19795-1）／IPA 午前Ⅱ 令和7年度秋期 問10。グラフは Claude が模式的に描いた

ライブネス検知と、生体認証の弱点

種類しくみ例
アクティブ利用者に動作を求めるまばたき、首振り、数字を読む
パッシブ動作を求めず画像などから判断質感・奥行き・血流・反射
写真・動画・マスク・偽の指、ディープフェイク（#05）への対策。
特徴の種類
身体的特徴指紋・静脈・顔・虹彩・声
行動的特徴署名の筆跡・筆圧、キーストローク、歩き方
生体情報は変更できない。だからサーバに送らず、端末の中で照合する方式（FIDO）が望ましい。
出典：IPA「支援士試験 シラバス（案）」用語例「身体的特徴，行動的特徴，ライブネス検知（アクティブ検知，パッシブ検知）」

Web サーバ Bしない

R1秋 問1 UAF：「スマホで顔認証 → スマホ内の秘密鍵で署名 → 署名を送る」が正解。「指紋情報を認証サーバに送信」は誤り。
サーバには公開鍵だけ。サーバから漏れても悪用しにくい。鍵はドメインごとなので偽サイトでは使えない。

まとめ：本番での問われ方

モデルを当てる：所有者が決める＝DAC、ラベルで強制＝MAC、役割＝RBAC、属性と状況＝ABAC。
要素を数える：知識・所持・生体の種類が違えば多要素。同じ種類を重ねても多段階。
暗号化の限界：TDE は媒体の盗難に効くが、SQL インジェクションや内部者には効かない。
FIDO の核心：生体情報と秘密鍵は端末から出ない。送るのは署名。サーバは公開鍵で検証。
言葉の区別：Identity Proofing（登録時の身元確認）と Authentication（ログイン時の当人認証）。FRR（本人拒否）と FAR（他人受入）。
SSO・SAML・OIDC・OAuth・Kerberos は #11 で。
