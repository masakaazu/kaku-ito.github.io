第1章

reduce と collect

単位元・アキュムレータ・コンバイナ。

Java Gold #07 リダクションとCollectors試験内容 3

reduce の 3 つの形

Stream.of(1,2,3).reduce(10, (x, y) -> x + y) // 16（10 も足す） Stream.of(1,2,3).reduce((x, y) -> x + y) // Optional[6] Stream.<Integer>empty().reduce((x, y) -> x + y) // Optional.empty Stream.<Integer>empty().reduce(0, Integer::sum) // 0 Integer o = Stream.of(1,2,3).reduce((x, y) -> x + y); // × Optional<Integer> cannot be converted to Integer
3 引数：要素と結果の型が違う
Stream.of("a","bb","ccc") .reduce(0, (n, s) -> n + s.length(), Integer::sum) // 6
単位元 identity足し算 0・掛け算 1・連結 ""
↓ accumulator：途中の結果 ＋ 要素
途中の結果逐次ならこれが答え
↓ combiner：途中の結果どうし（並列のときだけ）
最終の結果
単位元でない値（10）を渡すと、並列では何回も足されて結果が変わる（#09）。
出典：API Stream.reduce（3 つの版）／JDK 17 でのコンパイルと実行の結果

collect の 3 引数版

StringBuilder sb = Stream.of("a","b","c") .collect(StringBuilder::new, // supplier：入れ物を作る StringBuilder::append, // accumulator：要素を入れる StringBuilder::append); // combiner：入れ物どうし // abc List<Integer> r = Stream.of(1,2,3) .collect(ArrayList::new, ArrayList::add, ArrayList::addAll); // [1, 2, 3]
引数型
supplierSupplier<R>
accumulatorBiConsumer<R, ? super T>
combinerBiConsumer<R, R>
accumulator と combiner は値を返さない（BiConsumer）。ArrayList::add は boolean を返すが、戻り値を捨てて使える。
reduce で List を作ると毎回新しい List が要る。入れ物にためるなら collect。
出典：API Stream.collect(Supplier, BiConsumer, BiConsumer)、java.util.stream パッケージの説明「Mutable reduction」／JDK 17 での実行結果

toMap の 4 つの形

Stream.of("a","bb","cc").collect(toMap(String::length, s -> s)); // IllegalStateException: // Duplicate key 2 (attempted merging values bb and cc) Stream.of("a","bb","cc") .collect(toMap(String::length, s -> s, (x, y) -> x + "+" + y)); // {1=a, 2=bb+cc}（x が先の値） Stream.of("b","a","b") .collect(toMap(s -> s, s -> 1, Integer::sum, TreeMap::new)); // {a=1, b=2} Stream.of("a","b").collect(toMap(s -> s, s -> null)); // NullPointerException
引数役割
1 つ目キーを作る関数
2 つ目値を作る関数
3 つ目キーが重複したときのマージ（BinaryOperator）
4 つ目Map の Supplier（TreeMap::new）
重複で例外になるのはキー。値が同じなのは問題ない。

groupingBy と partitioningBy

Stream.of("a","bb","cc","d").collect(groupingBy(String::length)) // {1=[a, d], 2=[bb, cc]} Stream.of("a","bb","cc","d","eee") .collect(groupingBy(String::length, TreeMap::new, counting())) // {1=2, 2=2, 3=1}（TreeMap） Stream.of(2,4,6).collect(partitioningBy(n -> n > 10)) // {false=[2, 4, 6], true=[]} Stream.of(1,2,3,4,5).collect(partitioningBy(n -> n % 2 == 0, counting())) // {false=3, true=2}
groupingBypartitioningBy
キー分類関数の結果Boolean
要素がないキー入らない必ずある（空の List）
Map の Supplier3 引数版で指定指定できない
下流なしの値List<T>
Map<Integer, Integer> m = …groupingBy(n -> n % 2) はコンパイルエラー（値は List）。

下流例結果
mappinggroupingBy(String::length, TreeMap::new, mapping(s -> s.charAt(0), toCollection(TreeSet::new)))
