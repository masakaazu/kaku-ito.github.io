CCNA #24 自動化と SDN6.1

手作業の管理と自動化した管理

手作業自動化
設定1台ずつ CLIテンプレート・ポリシーからまとめて
間違い打ち間違い・ばらつき一貫性がある
規模人手と時間が足りない台数が増えても回る
新しい機器1台ずつ初期設定ゼロタッチ（PnP）
自動化の効果（Cisco）：効率が上がる・人のミスが減る・運用の費用（opex）が下がる。設定・管理・テスト・導入・運用をソフトウェアで行う。
落とし穴：自動化しても、機器がパケットを転送することや、ルーティングプロトコルが要ることは変わらない。変わるのは管理のしかた。
出典：Cisco「What Is Network Automation?」（Network automation is the process of automating the configuring, managing, testing, deploying, and operating of physical and virtual devices／improve efficiency, reduce human error, and lower operating expenses／Up to 95 percent of network changes today are done manually … operational costs 2 to 3 times higher／Manual changes lead to configuration errors and inconsistencies）

インテントベース・ゼロタッチ・テンプレート

インテントベースネットワーキング（IBN）の流れ
しくみ何をするか
ゼロタッチ（PnP）箱から出した機器をつなぐだけで、コントローラーから設定とソフトウェアを受け取る。現地に技術者がいなくてよい
テンプレート変わる部分を変数にしたひな形。機器ごとの値を入れて設定を作る
ポリシー業務の意図を、有線・無線で同じように当てはめる
hostname {{ name }}
ntp server {{ ntp_server }}
snmp-server location {{ site }}
ひな形の例（Claude が作成）。{{ }} の中に機器ごとの値が入る。
ポイント：同じひな形・同じポリシーから作るので、機器どうしの設定がそろう（一貫性）。
出典：Cisco「Catalyst Center 3.3.1 Data Sheet」（Defines policies based on business intent … Polices are translated into network-specific and device-specific configurations／push configuration using CLI templates）／Cisco「What Is Network Automation?」（Plug-and-play provisioning … Zero-touch provisioning of off-the-shelf devices／Easy control of device configurations for consistency and accuracy）
第2章

従来型とコントローラー型

機器の働きを3つのプレーンに分けて、どこが集中するのかを見る。

CCNA #24 自動化と SDN6.2・6.3.a

3つのプレーン

プレーンRFC 7426 の定義（要約）
コントロール機器に、パケットの処理と転送のしかたを指示する働き
データ（転送）全機器の中でトラフィックを転送する資源
マネジメント機器を見張り・設定し・保守する働き
見分け方：「表を作る」→コントロール、「表を使って送る」→データ、「人やツールが機器を管理する」→マネジメント。
落とし穴：SNMP や SSH はルーティングの話ではないので、コントロールではなくマネジメントプレーン。
出典：RFC 7426 2. Terminology（Forwarding Plane (FP) - The collection of resources across all network devices responsible for forwarding traffic／Control Plane (CP) - … CP instructs network devices with respect to how to process and forward packets／Management Plane (MP) - The collection of functions responsible for monitoring, configuring, and maintaining one or more network devices）。プレーンの例は Claude が書いた

従来型とコントローラー型を比べる

従来型コントローラー型
設定1台ずつ（box-by-box）コントローラーからまとめて
制御各機器が自分で（分散）コントローラーで集中
転送各機器各機器（変わらない）
全体の見え方機器ごと1か所で全体
外とのつなぎCLI・SNMPノースバウンド API・サウスバウンド
ポリシー機器ごとに入れる有線・無線で一貫
Cisco の製品：企業のキャンパスのコントローラーは Catalyst Center（旧 DNA Center）。SD-Access ではマネジメントプレーンを受け持つ。
出典：RFC 7426（Forwarding Plane … across all network devices）／Cisco「Software-Defined Access Solution Design Guide」（Consistent, centrally defined policy for both wired and wireless users and devices／In Cisco SD-Access the management plane is enabled and powered by Cisco Catalyst Center／LAN Automation … IS-IS）

SDN の考え方Software-Defined Networking

RFC 7426 の層（簡略化）
SDN の鍵（RFC 7426）：転送とコントロールの間に抽象化を入れて切り離し、アプリがプログラムでネットワークを制御できるようにする。
言葉意味
SDNソフトウェアでネットワークを定義・制御する考え方
SDN コントローラーアプリと機器の間に立つソフトウェア。上にノースバウンド、下にサウスバウンド
抽象化機器ごとの細かい違いを隠し、アプリから同じように扱えるようにすること
落とし穴：SDN でも転送は機器が行う。「コントローラーが全パケットを転送する」は誤り。
出典：RFC 7426（A key element in SDN is the introduction of an abstraction between the (traditional) forwarding and control planes in order to separate them and provide applications with the means necessary to programmatically control the network／SDN controllers … implement a CPSI … and provide a northbound interface for applications／the SDN southbound interface should encompass both CPSI and MPSI／OpenFlow and NETCONF … refer to control and management）。図は RFC 7426 の Figure 1 を Claude が簡略化した

ノースバウンド API とサウスバウンド API

ノースバウンドサウスバウンド
どこの間アプリ ⇔ コントローラーコントローラー ⇔ 機器
例Intent API（REST）NETCONF・SNMP・CLI・OpenFlow
使う人開発者・運用ツールコントローラー自身
Intent API：Catalyst Center のノースバウンドの REST API。HTTPS で GET・POST・PUT・DELETE を使い、JSON でやり取り。使う前に認証が要り、RBAC に従う。

アンダーレイ・オーバーレイ・ファブリック

アンダーレイオーバーレイ
何か物理のスイッチ・ルーターと IP の経路その上にカプセル化で作る仮想の網
数1つ上にいくつも作れる（VN）
中身機器どうしの IP利用者の端末・サブネット
SD-Accessレイヤ3のルーテッドアクセス。LAN Automation なら IS-ISVN ごとに VRF で分ける
ファブリック：Cisco は「ファブリックとは、要するにオーバーレイ」と説明する。全機器を論理的にフルメッシュでつなぐトンネルの網で、有線と無線に同じポリシーを当てられる。
落とし穴：「物理の配線＝ファブリック」ではない。物理の網はアンダーレイ。
出典：Cisco「Software-Defined Access Solution Design Guide」（A fabric is simply an overlay network. Overlays are created through encapsulation／The underlay network is defined by the physical switches and routers … All network elements of the underlay must establish IP connectivity via the use of a routing protocol … End-user subnets and endpoints are not part of the underlay network／permitting a physical network to host one or more logical networks）

SD-Access のプレーンと VXLAN・LISP

SD-Access のプレーン技術
マネジメントCatalyst Center
コントロール（オーバーレイ）LISP
データVXLAN
ポリシーCisco TrustSec（SGT）
VXLAN で包んだパケット（RFC 7348）
LISP：端末の「誰か」（EID）と「どこにいるか」（RLOC＝つながっているエッジノード）を分ける。エッジノードは宛先の RLOC をコントロールプレーンノードに問い合わせてから VXLAN で送る。
ファブリックの役割何をするか
エッジノード従来のアクセススイッチにあたる。端末を見つけて map-register で登録
コントロールプレーンノードLISP の map-server／map-resolver。端末とエッジの対応表を持つ
ボーダーノードファブリックと外のネットワークをつなぐ出入口
50 バイトぶん大きくなるので、SD-Access では MTU を 9100 にそろえることがすすめられている。SGT は ISE が割り当てる 16 ビットの値。
出典：Cisco「SD-Access Solution Design Guide」（the control plane is based on LISP … the data plane is based on VXLAN … the policy plane is based on Cisco TrustSec／VXLAN adds 50 bytes to the original packet／recommended MTU value … is 9100／fabric edge nodes are the equivalent of an access layer switch … issues a LISP map-register message／control plane node … combining both the map-server and map-resolver roles／border nodes serve as the gateway between the SD-Access fabric site and the networks external to the fabric）／RFC 7348（24-bit … VNI … up to 16 M VXLAN segments／Destination Port: IANA has assigned the value 4789）

AI と機械学習

ネットワーク運用で、予測する AI と、作る AI をどう使うか。

CCNA #24 自動化と SDN6.4

予測 AI と生成 AI

予測 AI（predictive AI）生成 AI（generative AI）
することデータのパターン認識で推論し、異常やこれから起きることを予測する頼まれた内容に合わせて、文章・画像・コードなどの新しい中身を作る
ネットワークでの例ベースラインから外れた異常の検知、Wi-Fi の干渉や接続の遅れの増加を前もって予測Catalyst Center の AI Assistant：「今日再起動したスイッチを見せて」と自然な文で聞ける。手順の説明・文書づくり
中身機械学習（教師なし学習など）深層学習のモデル（大規模言語モデル＝LLM など）
気をつけること学習データが足りないと誤った判断もっともらしい誤り（ハルシネーション）。答えは確かめて使う
Cisco の説明：予測 AI は「パターン認識で推論を引き出すもの」、生成 AI は「データを使って文章・画像・動画などの新しい中身を作るもの」。
落とし穴：「異常を見つける」「将来を予測する」は予測 AI。「質問に文で答える」「文書を書く」は生成 AI。逆にしない。
出典：Cisco Blogs「Why 2024 is the Year of AI for Networking」（predictive and generative AI – the former is about drawing inferences through pattern recognition, while the latter is about using data to create original content in the form of text, images, and videos）／Catalyst Center 3.3.1 Data Sheet（Use AI Assistant to interact with your network using natural language／AI-driven predictive analytics … predicting increases in Wi-Fi interference, onboarding delays）／Cisco「What is Generative AI?」（generate original content in response to a user request）

機械学習の学び方と、学習・推論

学び方学ぶもの向いている仕事
教師あり学習正解（ラベル）付きのデータ分類・予測
教師なし学習ラベルなしのデータの隠れたパターングループ分け・異常検知
強化学習試してみて、報酬と罰から資源の割り当て・ロボット
機械学習と機械推論：機械学習はデータからパターンを学ぶ。機械推論は知識から筋道を立てて結論（原因など）を出す。Catalyst Center は両方を使って原因を分析する。
学習と推論
学習は計算力とデータが多く要る。推論はできたモデルを使うだけ。
出典：Cisco「What Is AI Computing?」（Supervised learning: The most common form of AI, where models are trained on labeled datasets／Unsupervised learning … finds hidden patterns … clustering … anomaly detection／Reinforcement learning … rewards and penalties／Inference is the stage where the trained model is put into production to analyze new, "unseen" data）／Catalyst Center 3.3.1 Data Sheet（machine-reasoning engine）

ベースラインと異常検知・AIOps

AI によるベースライン（考え方の図・Claude が作成）
ベースラインはネットワークや場所ごとに作られ、環境が変わると学び直す。
ベースライン：ネットワークの動きを分析して取り出したふだん（正常）の振る舞い。Cisco AI Network Analytics は機械学習でこれを作り、実際の値と比べる。
異常検知：ベースラインから大きく外れたものだけを知らせる。害のない異常は無視して通知の雑音を減らす。
言葉意味
AIOpsIT 運用に AI・機械学習を使う。Gartner：イベントの関連づけ・異常検知・原因の特定を自動化
ハルシネーション生成 AI のもっともらしい誤り。RAG（答える前に最新の社内データを取り込む）で減らす
出典：Catalyst Assurance UG 2.3.7「Cisco AI Network Analytics Overview」（Baselining is a method used to analyze network dynamics to extract behavioral patterns that help define what is the normal (baseline) behavior／These baselines learn and adapt as the network environments change）／Catalyst Center 3.3.1 Data Sheet（ignore harmless network anomalies to reduce noise）／Cisco「What Is AIOps?」（event correlation, anomaly detection, and causality determination）／Cisco「What Is AI Computing?」（reduces the likelihood of "hallucinations"）

よくあるひっかけ

よくある思い込み正しくは
SDN ではコントローラーがパケットを転送する転送（データプレーン）は各機器に残る
SNMP・SSH はコントロールプレーン機器を管理する通信はマネジメントプレーン
REST の Intent API はサウスバウンドアプリ ⇔ コントローラーなのでノースバウンド
NETCONF はノースバウンドコントローラー ⇔ 機器なのでサウスバウンド
ファブリック＝物理の網物理はアンダーレイ。ファブリックはオーバーレイ
SD-Access のコントロールは VXLAN、データは LISP逆。コントロール＝LISP、データ＝VXLAN、ポリシー＝TrustSec
VXLAN の VNI は 12 ビット24 ビット（約 1600 万）。12 ビットは VLAN ID
異常検知・予測は生成 AI予測 AI。生成 AI は文章などを作る
ラベル付きのデータで学ぶのは教師なし学習教師あり学習。教師なしはラベルなしでパターンを探す
