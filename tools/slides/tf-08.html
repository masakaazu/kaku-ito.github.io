条件式と for 式

var.a != "" ? var.a : "default-a" # 2 つの値は同じ型にそろえる var.example ? 12 : "hello" # いつも文字列 var.example ? tostring(12) : "hello"
condition ? 真のとき : 偽のとき。型があいまいなら tostring などで明示する。
[for s in var.list : upper(s)] # タプル {for s in var.list : s => upper(s)} # オブジェクト [for s in var.list : s if s != ""] # 絞りこみ [for i, v in var.list : "${i} is ${v}"] # 番号と値 {for s in var.users : s.role => s.name...} # ... でグループ化（キーごとのリスト）
かこみ結果
[ ]タプル（値の式 1 つ）
{ }オブジェクト（キー => 値）。キーが重なるとエラー
{ … ... }グループ化モード：同じキーの値をリストに
マップ・オブジェクトの入力では、2 つの一時変数はキーと値。リスト・タプルでは番号と値。
マップ・オブジェクトはキーの辞書順、文字列のセットは値の辞書順でまわる（ほかの型のセットは順番の保証なし）。
出典：Conditional Expressions／for Expressions（Element Ordering）

スプラット式と文字列テンプレート

var.list[*].id # = [for o in var.list : o.id] aws_instance.web[*].public_ip # count で作ったリソース全部の IP
[*] はリスト・セット・タプルに使える。マップ・オブジェクトには使えないので for 式で書く。
リストでない 1 つの値に [*] を付けると要素 1 つのタプル、null なら空のタプル。
"Hello, ${var.name}!" # 埋めこみ "Hello, %{ if var.name != "" }${var.name}%{ else }unnamed%{ endif }!" <<EOT %{ for ip in aws_instance.example[*].private_ip ~} server ${ip} %{ endfor ~} EOT
書き方意味
$${ ・ %%{文字どおりの ${ ・ %{
~そちら側の空白・改行を取りのぞく
<<-EOTインデントを取りのぞくヒアドキュメント
出典：Splat Expressions／Strings and Templates

dynamic ブロック

resource "aws_security_group" "web" { name = "web" dynamic "ingress" { # 作るブロックの種類 for_each = var.ingress_rules # くり返す値 content { # ブロックの中身 from_port = ingress.value.port to_port = ingress.value.port protocol = "tcp" cidr_blocks = ingress.value.cidrs } } }
ラベル作る入れ子のブロックの名前（ingress など）
for_eachコレクション。要素ごとに 1 ブロック
iterator（省略可）一時変数の名前。既定はラベルと同じ。.key・.value
作れるのは resource・data・provider・provisioner に属する引数のブロックだけ。lifecycle・provisioner などメタ引数のブロックは作れない。
『Overuse of dynamic blocks can make configuration hard to read and maintain』。隠したい細部があるときだけ使う。
出典：dynamic Blocks

関数のしくみ

決まり内容
呼び方関数名(引数1, 引数2)。max(5, 12, 9) → 12
自作の関数『You cannot define your own functions in the Terraform configuration language』。プロバイダーの関数は provider::<ローカル名>::<関数名>(…)
引数の展開min([55, 2453, 2]...) → 2。... はピリオド 3 つ（三点リーダ … ではない）
sensitivesensitive な引数を使うと結果も sensitive
file・templatefile設定の最初の検証で読む。plan・apply の途中で作られるファイルは読めない
timestamp・uuid計画では unknown。apply のときに決まる
試す場所terraform console（関数のページの例は console の出力）
$ terraform console > cidrsubnet("10.1.2.0/24", 4, 15) "10.1.2.240/28"
