第1章

DHCP のしくみ

アドレスを知らないクライアントが、4つのメッセージでアドレスと設定を借りる。

CCNA #17 DHCP と DNS4.3

DORA：4つのメッセージでアドレスを借りる

メッセージ送り方と理由
DISCOVERブロードキャスト。サーバーの場所もアドレスも知らない
OFFERCisco の説明ではユニキャスト。まだ確定ではない
REQUESTブロードキャスト。選ばなかったサーバーも、申し出たアドレスを取り戻せる
ACKCisco の説明ではユニキャスト。ここで確定
数UDP。クライアント → サーバーは 67 番、サーバー → クライアントは 68 番
補足：RFC 2131 では、クライアントが求めたときは OFFER・ACK もブロードキャストで返す。割り当てられないときは DHCPNAK。
出典：DHCP Configuration Guide 15M&T「DHCP Overview」（DHCPDISCOVER broadcast … DHCPOFFER unicast … DHCPREQUEST broadcast … DHCPACK unicast … DHCPNAK）／RFC 2131（4.1：'DHCP server' port (67)・'DHCP client' port (68)・broadcast bit）。図はClaudeが作った例

リースと衝突チェック：アドレスは「借りる」もの

ip dhcp pool V10
 lease 7          ! 7日
 lease 0 8        ! 0日8時間
 lease infinite   ! 無期限
配る前の衝突チェック
  1. プールから空いているアドレスを選ぶ
  2. ping と gratuitous ARP で、だれも使っていないか確かめる
  3. 返事があれば衝突：そのアドレスはプールから外し、管理者が直すまで配らない
  4. 衝突の一覧は show ip dhcp conflict
なぜリースか：持ち主がいなくなったアドレスは、期限が来れば自動でプールに戻る。期限の前に更新すれば同じアドレスを使い続けられる。
出典：DHCP Configuration Guide 15M&T「Configuring the Cisco IOS DHCP Server」（lease … The default is a one-day lease／DHCP checks for conflicts by using ping and gratuitous ARP … the address is removed from the pool）／RFC 2131（T1 defaults to (0.5 * duration_of_lease)）
第2章

DHCP の設定

サーバーはプールを作る。リレーは ip helper-address。クライアントは ip address dhcp。

CCNA #17 DHCP と DNS4.6

サーバーの設定：除外 → プール → 中身

R1(config)#ip dhcp excluded-address 10.1.10.1 10.1.10.20
R1(config)#ip dhcp pool V10
R1(dhcp-config)#network 10.1.10.0 255.255.255.0
R1(dhcp-config)#default-router 10.1.10.1
R1(dhcp-config)#dns-server 10.1.99.53
R1(dhcp-config)#domain-name example.com
R1(dhcp-config)#lease 7
excluded-addressグローバルで入れる。手で設定するアドレスを外す（最初 最後）
network配るサブネット。ネットワークアドレス＋マスク（または /長さ）
default-routerPC のゲートウェイ。同じサブネットのアドレス（FHRP なら仮想 IP）
dns-serverPC に配る DNS サーバー（最大8個、優先順）
  • R1 自身のインタフェースのアドレスは自動で除外される。サーバー・プリンターなどほかに手で設定したアドレスは excluded-address が要る
  • VLAN ごとにプールを1つずつ作る（どのプールを使うかは、届いた VLAN か giaddr で決まる）
  • default-router を忘れると、PC は同じサブネットの中だけ通信できる
  • dns-server を忘れると、IP アドレスなら届くが名前で届かない
名前の似たコマンド：ip default-gateway・ip name-server はルーター自身の設定。PC に配るのはプールの default-router・dns-server。
出典：「Configuring the Cisco IOS DHCP Server」（ip dhcp excluded-address low-address [high-address]／The IP address configured on a device interface is automatically excluded／network … domain-name … dns-server … up to eight … default-router … should be on the same subnet as the client）。設定はClaudeが作った例

リレー：ブロードキャストを、サーバーへのユニキャストに変えて届ける

R1(config)#interface GigabitEthernet0/0   ! PC 側
R1(config-if)#ip helper-address 10.1.99.10
入れる場所：ブロードキャストを受け取る側＝クライアントのいる側（L3 スイッチなら VLAN の SVI）。サーバー側に入れても働かない。
  • ルーターはブロードキャストを転送しないので、別のサブネットのサーバーにはそのままでは届かない
  • giaddr＝helper-address を入れたインタフェースのアドレス。サーバーはこれでどのサブネットのプールかを決める
  • サーバーが何台かあれば、helper-address を1台ずつ書ける
出典：IP Addressing Services Configuration Guide 12.4T「Configuring the Cisco IOS DHCP Relay Agent」（the relay agent inserts the IP address of the interface containing the ip helper-address command into the gateway IP address (giaddr) field … sends the local broadcast, via IP unicast, to the DHCP server／you can configure one helper address for each server）。図はClaudeが作った例

L3 スイッチで VLAN ごとにリレーする

SW1(config)#interface vlan 10
SW1(config-if)# ip address 10.1.10.1 255.255.255.0
SW1(config-if)# ip helper-address 10.1.99.10
SW1(config)#interface vlan 20
SW1(config-if)# ip address 10.1.20.1 255.255.255.0
SW1(config-if)# ip helper-address 10.1.99.10

! サーバー側（R9）：VLAN ごとにプール
R9(config)#ip dhcp pool V10
R9(dhcp-config)# network 10.1.10.0 255.255.255.0
R9(dhcp-config)# default-router 10.1.10.1
R9(config)#ip dhcp pool V20
R9(dhcp-config)# network 10.1.20.0 255.255.255.0
R9(dhcp-config)# default-router 10.1.20.1
VLAN 20 の PC からgiaddr選ばれるプール
SVI vlan 20 で受ける10.1.20.1V20（10.1.20.0/24）
よくある失敗
SVI に helper-address がないDISCOVER がサーバーに届かない
サーバーに V20 のプールがないgiaddr に合うプールがなく、配れない
サーバーから 10.1.20.1 への経路がない返事がリレーに戻れない
default-router が別 VLAN のアドレスPC がほかのサブネットへ出られない
出典：「Configuring the Cisco IOS DHCP Relay Agent」（This IP address enables the DHCP server to determine which subnet should receive the offer）／RFC 2131（the server sends any return messages to the 'DHCP server' port on the BOOTP relay agent whose address appears in 'giaddr'）。設定と失敗の例はClaudeがまとめた

クライアントの設定と、確かめるコマンド

ルーターのインタフェースを DHCP クライアントにする
R1(config)#interface GigabitEthernet0/1   ! ISP 側
R1(config-if)#ip address dhcp
R1(config-if)#no shutdown

R1#show ip interface brief
Interface   IP-Address    OK? Method Status Protocol
Gi0/1       198.51.100.23 YES DHCP   up     up
  • ip address アドレス マスク の代わりに入れる
  • Method 列が DHCP なら DHCP でもらったアドレス（手で書いたものは manual）
  • Cisco のルーターは、同時に DHCP サーバーにもクライアントにもなれる
サーバー側で確かめる
R1#show ip dhcp binding
IP address    Client-ID/            Lease expiration      Type
              Hardware address
10.1.10.21    0100.5079.6668.00     Nov 08 2026 10:15 AM  Automatic
show ip dhcp binding貸したアドレス・相手・リースの期限
show ip dhcp poolプールの範囲と使っている数（足りているか）
show ip dhcp conflict衝突してプールから外したアドレス
PC 側：Windows なら ipconfig /all で、もらったアドレス・ゲートウェイ・DNS サーバー・リースを見る。
出典：DHCP Configuration Guide 15M&T「DHCP Client」（Your device can act as both the DHCP client and the DHCP server. Use the ip address dhcp command）／「Configuring the Cisco IOS DHCP Server」（show ip dhcp pool／show ip dhcp binding … lease expiration／show ip dhcp conflict）。出力はその形式にそろえてClaudeが作った例
第3章

DNS

名前で指定された相手の IP アドレスを、世界に分かれたデータベースから調べる。

CCNA #17 DHCP と DNS4.3

DNS の役割：名前から相手のアドレスを調べる

項目内容
役割ホスト名と IP アドレスなどの対応を持つ、分散・階層型のデータベース
ポートふつうの問い合わせは UDP 53。ゾーン転送などは TCP 53
権威サーバーそのゾーンの情報を元から持つサーバー
キャッシュ前の答えを覚えておき、同じ問い合わせを減らす
DHCP との違い：DHCP は自分のアドレス（と DNS サーバーのアドレス）をもらう。DNS はそれを使って相手のアドレスを調べる。
出典：DNS Configuration Guide 15SY「Configuring DNS」（distributed database … map hostnames to IP addresses／Name Servers・Cache・Name Resolvers・Authoritative Name Servers）／RFC 1035（4.2：TCP … port 53 … UDP port 53／UDP is not acceptable for zone transfers）。図はClaudeが作った例

レコードの種類：何を引くかで使い分ける

レコード中身例（Claudeが作った例）見分けの鍵
A名前 → IPv4www.example.com → 192.0.2.10正引き（IPv4）
AAAA名前 → IPv6www.example.com → 2001:db8::10128 ビット＝A の4倍
CNAME別名 → 正規名web.example.com → www.example.comアドレスは書かない
MXドメイン → メールサーバーexample.com → 10 mail.example.com数が小さいほど優先
PTRIP アドレス → 名前10.2.0.192.in-addr.arpa → www.example.com逆引き。アドレスを逆順に
NSゾーン → 権威ネームサーバーexample.com → ns1.example.comだれが答える責任者か
よく問われる組：「IPv6 を引く」＝AAAA、「逆引き」＝PTR、「メール」＝MX、「別名」＝CNAME。
ひっかけ：MX や CNAME はアドレスを直接持たない。最後は A・AAAA を引いてアドレスを得る。
出典：RFC 1035（3.2.2 TYPE values：A 1・NS 2・CNAME 5・PTR 12・MX 15／3.5 IN-ADDR.ARPA domain）／RFC 3596（2.1 AAAA record type … stores a single IPv6 address）

ルーター自身の名前解決の設定

R1(config)#ip domain name example.com
R1(config)#ip name-server 10.1.99.53
R1(config)#ip domain lookup          ! 初期値で有効
R1(config)#ip host R2 10.1.12.2

R1#ping server1
! → server1.example.com を 10.1.99.53 に問い合わせる
R1#ping R2
! → ip host の 10.1.12.2 を使う（DNS に聞かない）
ip name-serverルーターが問い合わせる DNS サーバー（最大6台）
ip domain nameドメインなしの名前の後ろに付けるドメイン
ip domain lookupDNS での名前解決を有効にする（初期値で有効）
ip host名前とアドレスをルーターの中に固定で登録
打ち間違いで待たされる：知らない単語（例 shwo）を打つと、ルーターはホスト名だと思って DNS で引こうとする。検証環境では no ip domain lookup を入れることが多い。
似た名前のコマンドを分ける
コマンドだれのための設定か
ip name-serverルーター自身が名前を引く
dns-server（DHCP プール）DHCP で PC に配る
ip helper-addressPC の DHCP をリレーする
関連SSH の鍵を作るには hostname と ip domain name が要る（#11）
出典：DNS Configuration Guide 15SY「Configuring DNS」（ip host … static hostname-to-address mapping／ip domain name … complete unqualified hostnames／ip name-server … up to six／ip domain lookup … DNS is enabled by default）。設定と ping の例はClaudeが作った例

よくあるひっかけ

よくある思い込み正しくは
DHCP の4つは全部ブロードキャストDISCOVER と REQUEST はブロードキャスト。OFFER・ACK は Cisco の説明ではユニキャスト
DHCP は TCP、DNS は UDP だけDHCP は UDP 67／68。DNS は UDP と TCP の 53
ip helper-address はサーバー側のインタフェースに入れるクライアント側（ブロードキャストを受ける側）に入れる
helper-address には DHCP サーバーの MAC を書くサーバーの IP アドレス
excluded-address はプールの中で入れるグローバル設定で入れる
ルーターに DNS サーバーを教えるのは dns-serverルーター自身は ip name-server。dns-server は PC に配る設定
リースの初期値は 8 日Cisco の DHCP サーバーは 1日
逆引きは A レコード、IPv6 は A6逆引きは PTR、IPv6 は AAAA
