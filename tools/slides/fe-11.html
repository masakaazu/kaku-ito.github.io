11-1 情報セキュリティ基本の考え方・攻撃の手口

情報セキュリティの3要素CIA
機密性・完全性・可用性の3つ
ポイントJIS Q 27000では、これに真正性・責任追跡性・否認防止・信頼性を加えることもある
Confidentiality＝機密性／Integrity＝完全性／Availability＝可用性
脅威きょうい / Threat
情報資産に損害を与えるおそれのあるもの
ポイント物理的脅威・技術的脅威・人的脅威に分かれる
脆弱性ぜいじゃくせい / Vulnerability
脅威に付け込まれる弱点
ポイントソフトウェアの不具合（セキュリティホール）や管理の甘さ
マルウェアMalware
悪意のあるソフトウェアの総称
ポイントウイルス・ワーム・トロイの木馬・スパイウェア・ランサムウェアなど
ワームWorm
自分を複製し、ネットワークを通じて広がるマルウェア
ポイントウイルスと違い、宿主のファイルを必要としない
トロイの木馬Trojan Horse
役に立つソフトを装って入り込み、裏で悪い動きをするマルウェア

11-1 情報セキュリティ攻撃の手口

ランサムウェアRansomware
データを暗号化するなどして使えなくし、元に戻すための身代金を要求するマルウェア
ポイントオフラインのバックアップが有効な対策
ボットBot
外部のC&Cサーバからの指令で遠隔操作されるマルウェア
ポイント感染した端末の集まりをボットネットという
ソーシャルエンジニアリングSocial Engineering
人の心理的な隙や油断を突いて、パスワードなどの情報を盗む手口
例電話でなりすまして聞き出す、肩越しに盗み見る
フィッシングPhishing
本物そっくりの偽サイトに誘導し、IDやパスワードを入力させて盗む手口
標的型攻撃ひょうてきがたこうげき / Targeted Attack
特定の組織を狙い、業務を装ったメールなどでマルウェアに感染させる攻撃
水飲み場型攻撃Watering Hole Attack
標的がよく見るWebサイトを改ざんし、訪れた人を感染させる攻撃

11-1 情報セキュリティ攻撃の手口

ゼロデイ攻撃Zero-day Attack
脆弱性が見つかってから修正プログラムが出るまでの間に、その脆弱性を突く攻撃
ブルートフォース攻撃総当たり攻撃 / Brute Force Attack
パスワードとして考えられるすべての組合せを試す攻撃
ポイント辞書攻撃はよく使われる単語を順に試す
パスワードリスト攻撃Password List Attack
ほかのサービスから漏れたIDとパスワードの組を使ってログインを試す攻撃
ポイントパスワードの使い回しが原因になる
リバースブルートフォース攻撃Reverse Brute Force Attack
パスワードを1つに固定し、IDを次々に変えて試す攻撃
ポイント一定回数の失敗でロックする対策が効きにくい
SQLインジェクションSQL Injection
入力欄に不正なSQLの一部を入れて、データベースを不正に操作する攻撃
ポイント対策はプレースホルダ（バインド機構）でSQL文と値を分けること
クロスサイトスクリプティングXSS / Cross Site Scripting
Webページに悪意のあるスクリプトを埋め込み、閲覧者のブラウザで実行させる攻撃
ポイント対策は出力時のエスケープ処理

11-1 情報セキュリティ攻撃の手口

CSRFしーさーふ / Cross Site Request Forgery
ログイン中の利用者に、意図しない操作の要求を送らせる攻撃
ポイント対策は正規の画面から送られたか確かめるトークン
Cross Site＝サイトをまたいだ／Request＝要求／Forgery＝偽造
DoS攻撃・DDoS攻撃ドスこうげき / Denial of Service
大量の通信を送りつけて、サービスを使えなくする攻撃。多数の端末から行うのがDDoS
Denial of Service＝サービスの妨害／Distributed＝分散した（DDoS）
DNSキャッシュポイズニングDNS Cache Poisoning
DNSサーバに偽の情報を覚えさせ、正しいドメイン名でも偽サイトへ誘導する攻撃
中間者攻撃MITM / Man-in-the-Middle Attack
通信の間に入り込んで、盗聴や改ざんをする攻撃
敵対的サンプルAdversarial Example
画像などに人には分からない小さな変化を加え、AIに誤認識させる攻撃
モデル反転攻撃Model Inversion Attack
AIの出力をもとに、学習に使ったデータ（個人情報など）を推測する攻撃

11-2 情報セキュリティ管理組織での管理

ISMSあいえすえむえす / Information Security Management System
情報セキュリティを組織として管理し、PDCAで継続的に改善する仕組み
ポイント規格は JIS Q 27001（ISO/IEC 27001）
Information Security＝情報セキュリティ／Management System＝管理の仕組み
情報セキュリティポリシーInformation Security Policy
組織の情報セキュリティの方針や決まりをまとめたもの
ポイント基本方針・対策基準・実施手順の3階層
リスクアセスメントRisk Assessment
リスクを特定し、分析し、評価すること
リスク対応Risk Treatment
評価したリスクにどう対処するかを決めること
ポイント回避（やめる）・低減（対策で小さくする）・移転（保険などで他者へ）・保有（受け入れる）
リスク移転Risk Transfer
保険に入るなどして、損失の負担を第三者に移すこと
リスク保有Risk Retention
リスクを受け入れ、損失が出たら自分で負担すること
ポイント小さなリスクに選ぶ

11-3 セキュリティ技術評価評価と検査

ペネトレーションテストPenetration Test
実際の攻撃と同じ手順でシステムに侵入を試み、弱点を確かめる検査
ファジングFuzzing

脆弱性の深刻さを、0〜10の点数で表す共通の評価方法
Common＝共通の／Vulnerability＝脆弱性／Scoring System＝点数の付け方

11-4 情報セキュリティ対策人と物の対策

多要素認証たようそにんしょう / Multi-factor Authentication
知識（パスワード）・所持（スマートフォン）・生体（指紋）のうち、2種類以上を組み合わせる認証
ポイント同じ種類を2回使うのは二段階認証であっても多要素ではない
ワンタイムパスワードOne-time Password
1回使うと無効になるパスワード
ポイント盗まれても再利用されにくい
生体認証せいたいにんしょう / Biometrics
指紋・顔・静脈など、体の特徴で本人を確認する方法
ポイント本人を拒否する率と、他人を受け入れる率のバランスが大切
シングルサインオンSSO / Single Sign-On
一度の認証で、複数のシステムを使えるようにする仕組み
セキュアブートSecure Boot
起動時に電子署名を確かめ、信頼できるOSだけを起動させる仕組み
BIOSパスワード・HDDパスワードBIOS / HDD Password
BIOSパスワードはPCの起動や設定の変更を制限し、HDDパスワードは記憶装置そのものの読み出しを制限する
基本情報 セキュリティ12

11-4 情報セキュリティ対策技術的な対策

ファイアウォールFirewall
決めたルールに従って、通信を通すか止めるかを判断する仕組み
ポイントパケットフィルタリングはIPアドレスやポート番号で判断する
DMZでぃーえむぜっと / DeMilitarized Zone
社内ネットワークとインターネットの間に置く、外部に公開するサーバ用の区域
ポイントWebサーバやメールサーバを置く
DeMilitarized＝非武装の／Zone＝地帯
WAFわふ / Web Application Firewall
Webアプリケーションへの攻撃（SQLインジェクションやXSSなど）を見つけて防ぐ仕組み
Web Application＝Webアプリ／Firewall＝防火壁
IDSあいでぃーえす / Intrusion Detection System
不正な侵入を見つけて知らせる仕組み
ポイント止めるところまで行うのがIPS（Intrusion Prevention System）
Intrusion＝侵入／Detection＝検知／System＝仕組み
マルウェア対策ソフトAnti-malware Software
マルウェアを見つけて取り除くソフト
ポイントパターンマッチング法は定義ファイルと照合、ヒューリスティック法は怪しい振る舞いから検出、コンペア法は正常な状態と比べる
基本情報 セキュリティ13

サンドボックスSandbox
隔離した環境で怪しいプログラムを動かし、振る舞いを観察する仕組み
WORMわーむ / Write Once Read Many
一度だけ書き込め、何度でも読める記録媒体や機能
ポイントログなどの改ざん防止に使う
Write Once＝一度だけ書く／Read Many＝何度も読む

11-5 セキュリティ実装技術暗号と認証の技術

共通鍵暗号方式きょうつうかぎあんごうほうしき / Symmetric-key Cryptography
暗号化と復号に同じ鍵を使う方式
ポイント速いが、鍵を安全に渡す方法が課題。代表はAES
公開鍵暗号方式こうかいかぎあんごうほうしき / Public-key Cryptography
公開鍵と秘密鍵のペアを使う方式
ポイント受信者の公開鍵で暗号化し、受信者の秘密鍵で復号する。代表はRSA
AESえーいーえす / Advanced Encryption Standard
米国の標準になっている共通鍵暗号
Advanced＝高度な／Encryption＝暗号化／Standard＝標準
RSAあーるえすえー / Rivest-Shamir-Adleman
大きな数の素因数分解が難しいことを安全性の根拠にする公開鍵暗号
考案した3人（Rivest・Shamir・Adleman）の頭文字
楕円曲線暗号だえんきょくせんあんごう / Elliptic Curve Cryptography
楕円曲線の性質を使う公開鍵暗号
ポイントRSAより短い鍵で同じくらいの強さを出せる
ハッシュ関数Hash Function
データから決まった長さの値（ハッシュ値）を作る関数
ポイント元に戻せず、少しでも違うと値が変わるので改ざんの検出に使う。例: SHA-256

11-5 セキュリティ実装技術暗号と認証の技術

ディジタル署名Digital Signature
送信者が自分の秘密鍵で署名し、受信者が送信者の公開鍵で検証する仕組み
ポイント本人であることと、改ざんされていないことを確かめられる
PKIぴーけーあい / Public Key Infrastructure
認証局（CA）が発行するディジタル証明書で、公開鍵が本人のものだと保証する仕組み
Public Key＝公開鍵／Infrastructure＝基盤
TLSてぃーえるえす / Transport Layer Security
Webなどの通信を暗号化し、相手を認証するプロトコル
ポイント前身はSSL。HTTPSで使う
Transport Layer＝トランスポート層の／Security＝安全
IPsecあいぴーせっく / IP Security
ネットワーク層でIP通信を暗号化・認証するプロトコル群
ポイントVPNで使われる
VPNぶいぴーえぬ / Virtual Private Network
共用の回線の上に、暗号化で仮想的な専用線を作る技術
Virtual＝仮想の／Private＝専用の／Network＝網

11-5 セキュリティ実装技術暗号と認証の技術

WPAだぶりゅーぴーえー / Wi-Fi Protected Access
無線LANの暗号化と認証の規格
ポイント今はWPA3が新しい
Wi-Fi＝無線LAN／Protected＝守られた／Access＝接続
DMARCでぃーまーく / Domain-based Message Authentication, Reporting and Conformance
SPFやDKIMの送信元認証の結果をもとに、なりすましメールをどう扱うかを送信側が示す仕組み
Domain-based＝ドメインに基づく／Message Authentication＝メールの認証／Reporting＝報告／Conformance＝適合
SPF・DKIMえすぴーえふ・でぃーきむ
送信元のメールサーバが正しいかを確かめる仕組み。SPFは送信元IPアドレス、DKIMは電子署名で確かめる
プロキシサーバProxy Server
社内の端末に代わって外部のサーバに接続する中継サーバ
ポイントアクセスの記録や制限に使う
