static メソッド

今のオブジェクトがない場所。this もインスタンス変数も、そのままでは使えない。

Java Silver #09 static とアクセス修飾子試験内容 4

static コンテキストで使えるもの

どこから何をJDK 17
static メソッドstatic のメンバーOK
インスタンス変数 nnon-static variable n cannot be referenced from a static context
this.nnon-static variable this …
new A().kOK（オブジェクトを通す）

理由：static メソッドは特定のオブジェクトなしで呼ばれるので、「どのオブジェクトの n か」が決まらない。
main からインスタンスメソッドを呼ぶ（Claude が作成）
public class Main {
  void hi() { System.out.println("hi"); }
  public static void main(String[] args) {
    hi();              // コンパイルエラー
    new Main().hi();    // OK → hi
  }
}
error: non-static method hi() cannot be referenced from a static context
static コンテキスト：static メソッド・static 初期化子・static フィールドの初期化式の中。this と super は使えない。
出典：JLS 8.4.3.2 static Methods（Notably, the keywords this and super are prohibited in a static context, as are unqualified references to instance variables, instance methods …）／Java Tutorials（Class methods cannot access instance variables or instance methods directly—they must use an object reference）／結果は JDK 17 で確かめたもの

null の変数でも static は使える

class C {
  static int s = 7;
  static String hello() { return "hello"; }
  int n = 1;
}
C c = null;
System.out.println(c.s + " " + c.hello());   // 7 hello
System.out.println(c.n);                        // NullPointerException
static は宣言された型で決まる。c.s は C.s と同じ意味で、c の中身（オブジェクト）は使わない。だから null でも例外にならない。
コード（c は null の C 型変数）結果（JDK 17）
c.s（static フィールド）7
c.hello()（static メソッド）hello
c.n（インスタンス変数）NullPointerException
変数を通して static を使う書き方は、読む人に誤解を与えるのですすめられない。試験では「例外になる」をえらばせるひっかけに使われる。
count の動き（Claude が作成）count

static 初期化子

クラスがはじめて使われる直前に 1 回だけ。

Java Silver #09 static とアクセス修飾子試験内容 4

初期化のタイミングと順番

class A {
  static { System.out.print("s1 "); }
  { System.out.print("i "); }
  A() { System.out.print("c "); }
  static { System.out.print("s2 "); }
}
// main：print("m "); new A(); new A();
m s1 s2 i c i c
こんなときクラスは初期化される？
main のあるクラスmain の前に（static 初期化子が先）
A a = null;（宣言だけ）されない
はじめての new A()される
はじめての A.f()される
2 回目の A.f()もう済んでいる
A a = null;  print("1 ");  A.f();  A.f();
// 1 A-init f f
出典：JLS 8.7 Static Initializers（A static initializer declared in a class is executed when the class is initialized）／JLS 12.4.1 When Initialization Occurs（T is a class and an instance of T is created. A static method declared by T is invoked …）／結果は JDK 17 で確かめたもの

上から順 ― 前方参照に注意

class A {
  static int x;            // 0
  static { x = 5; }          // 5
  static int y = x * 2;    // 10
}
System.out.println(A.x + " " + A.y);   // 5 10
static フィールドの初期化式と static 初期化子は、ひとまとめのブロックのように上から順に実行される。static 初期化子が全部のあとにまとめて動くわけではない。
コード結果（JDK 17）
static int a = b + 1;
static int b = 2;		illegal forward reference
static int a = A.b + 1;
static int b = 2;		a は 1、b は 2
static final int X;
static { X = 3; }		OK（3）
A.b と書くと前方参照のチェックを通るが、その時点の b はまだ既定値 0。だから a は 1 になる（試験ではまれ。しくみの理解用）。
出典：JLS 12.4.2（execute either the class variable initializers and static initializers of the class … in textual order, as though they were a single block）／JLS 8.3.3（For a reference by simple name to a class variable f … at a point to the left of f's declarator）／Java Tutorials「Initializing Fields」／結果は JDK 17 で確かめたもの
第4章

アクセス修飾子

同じクラス・同じパッケージ・サブクラス・どこからでも。

Java Silver #09 static とアクセス修飾子試験内容 4

4 つのアクセスレベル

修飾子同じクラス同じパッケージ別パッケージのサブクラスどこでも
public○○○○
protected○○○×
なし○○××
private○×××
広い順：public → protected → なし（パッケージアクセス）→ private。protected は「なし」の範囲に、別パッケージのサブクラスを足したもの。
「なし」を default と呼ぶこともあるが、default という修飾子を書くわけではない。
エラーの表示（JDK 17）
使ったものメッセージ
private（別クラスから）n has private access in A
なし（別パッケージから）def is not public in A; cannot be accessed from outside package
protected（別パッケージの非サブクラスから）pro has protected access in A
private はクラス単位。同じクラスの中なら、別のインスタンスの private フィールド（o.n）も使える。同じファイルの別クラスからは使えない。
出典：Java Tutorials「Controlling Access to Members of a Class」（Access Levels の表／The protected modifier specifies that the member can only be accessed within its own package … and, in addition, by a subclass of its class in another package）／JLS 6.6.1／結果は JDK 17 で確かめたもの（パッケージは p1・p2 にファイルを分けた）

protected のくわしいルール

p1 の A と、p2 の B（A のサブクラス）（Claude が作成）
package p1;
public class A {
  protected int pro = 2;
  protected static int ps = 5;
}
// ---- 別ファイル ----
package p2;
public class B extends p1.A {
  void t(p1.A a, B b) {
    int v1 = pro;        // OK
    int v2 = this.pro;   // OK
    int v3 = b.pro;      // OK（B 型）
    int v4 = a.pro;      // エラー（A 型）
    int v5 = ps;         // OK
  }
}
別パッケージのサブクラスでの条件：インスタンスのフィールド・メソッドは、自分（B）か B のサブクラスの型を通したときだけ。親の型 A の変数を通すとエラー。
サブクラスでない p2 のクラスからは、protected は static（A.ps）でも使えない。使えるのは public だけ。
出典：JLS 6.6.2.1 Access to a protected Member（Access is permitted only within the body of a subclass S of C … access to the instance field Id is permitted if and only if the qualifying type is S or a subclass of S）／結果は JDK 17 で確かめたもの

カプセル化と不変オブジェクト

隠して、決めた入口からだけ触らせる。

Java Silver #09 static とアクセス修飾子試験内容 4

カプセル化と private コンストラクタ

class Account {
  private int balance;              // 隠す
  void deposit(int x) {
    if (x > 0) balance += x;          // 入口で確かめる
  }
  int getBalance() { return balance; }
}
a.deposit(100);  a.deposit(-50);
System.out.println(a.getBalance());   // 100
カプセル化：フィールドを private にし、メソッドを通してだけ読み書きさせる。おかしな値をメソッドではじける。
Java Tutorials：「意味のある範囲でいちばん制限の強いアクセスレベルを使う。理由がなければ private」。
class S {
  private S() { }
  static S create() { return new S(); }   // 中からは OK
}
S s1 = new S();      // エラー
S s2 = S.create();    // OK
error: S() has private access in S
private コンストラクタ：外から new させず、作り方を static メソッド（ファクトリメソッド）に限る。
出典：Java Tutorials「Controlling Access to Members of a Class」（Use the most restrictive access level that makes sense for a particular member. Use private unless you have a good reason not to）／JLS 6.6.1／結果は JDK 17 で確かめたもの

不変オブジェクトの作り方

1 setter を作らない
2 フィールドはすべて private final
3 クラスを final にする（またはコンストラクタを private にしてファクトリメソッド）
4 配列などはコピーを保存し、コピーを返す
Java Tutorials「A Strategy for Defining Immutable Objects」の手順を Claude がまとめた。
final の参照フィールド list結果（JDK 17）
list.add("x")OK（中身は変えられる）
list = new ArrayList<>()cannot assign a value to final variable list
コピーしないと外から変えられる（Claude が作成）
final class P {
  private final int[] data;
  P(int[] d) { data = d; }          // ×そのまま
  int[] get() { return data; }     // ×そのまま
}
int[] src = {1, 2};
P p = new P(src);
src[0] = 9;  p.get()[1] = 9;
P の書き方p.get() の中身
そのまま保存・そのまま返す9 9（変えられた）
data = d.clone();・return data.clone();1 2（守られた）
出典：Java Tutorials「A Strategy for Defining Immutable Objects」（Don't provide "setter" methods／Make all fields final and private／Never store references to external, mutable objects passed to the constructor; if necessary, create copies）／JLS 4.12.4（the state of the object may be changed … but the variable will always refer to the same object）／結果は JDK 17 で確かめたもの

問われ方とまちがえやすい点

こう聞かれたら答えの考え方
static フィールドの表示1 つしかない。どの変数を通して変えても同じもの。new で 0 に戻らない
