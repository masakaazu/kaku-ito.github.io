9-1 データベース方式データベースの基本

データベースDatabase
多くのデータを整理して、共有・検索しやすくまとめたもの
DBMSでぃーびーえむえす / Database Management System
データベースを管理するソフトウェア。同時実行の制御や障害回復を行う
Database＝データベース／Management＝管理／System＝仕組み
関係データベースかんけいでーたべーす / Relational Database
データを行と列の表（関係）で表すデータベース
ポイント行をタプル（レコード）、列を属性（フィールド）と呼ぶ
3層スキーマさんそうすきーま / Three-schema Architecture
データベースを外部スキーマ・概念スキーマ・内部スキーマの3つに分けて定義する考え方
ポイント1つを変えても他への影響を小さくできる（データの独立性）
外部スキーマExternal Schema
利用者やアプリケーションから見たデータベースの見え方を定義したもの
ポイントビューにあたる
概念スキーマConceptual Schema
データベース全体の論理的な構造を定義したもの
ポイント表の定義にあたる

内部スキーマInternal Schema

NoSQLのーえすきゅーえる / Not only SQL

グラフ型Graph Database

9-2 データベース設計データの設計

E-R図いーあーるず / Entity Relationship Diagram
実体（エンティティ）と、実体どうしの関連（リレーションシップ）を表した図
ポイント1対多などの関係（カーディナリティ）も表す
Entity＝実体／Relationship＝関連／Diagram＝図
主キーしゅきー / Primary Key
表の中の行を1つに決められる列。重複やNULLは許されない
ポイント複数の列を組み合わせたものを複合主キーという
外部キーがいぶきー / Foreign Key
ほかの表の主キーを参照する列
ポイント参照先にない値は入れられない（参照制約）
正規化せいきか / Normalization
データの重複をなくすように表を分けること
ポイント更新したときの矛盾（更新時異状）を防ぐ
関数従属かんすうじゅうぞく / Functional Dependency
ある項目の値が決まると、別の項目の値が1つに決まる関係
部分関数従属ぶぶんかんすうじゅうぞく / Partial Functional Dependency
複合主キーの一部だけで、ほかの項目が決まってしまう関係
ポイント取り除くと第2正規形になる
基本情報 データベース7

9-2 データベース設計データの設計

推移的関数従属すいいてきかんすうじゅうぞく / Transitive Functional Dependency
主キー以外の項目を通して、さらに別の項目が決まる関係
ポイント取り除くと第3正規形になる
インデックスIndex
検索を速くするための索引
ポイント更新のたびにインデックスも直すので、更新は少し遅くなる

9-3 データ操作関係演算・SQL

選択せんたく / Selection
表から、条件に合う行を取り出す関係演算
射影しゃえい / Projection
表から、指定した列だけを取り出す関係演算
結合けつごう / Join
共通の列をもとに、2つの表をつなぎ合わせる関係演算
SQLえすきゅーえる / Structured Query Language
関係データベースを操作するための言語
ポイント定義するDDLと、操作するDMLがある
Structured＝構造化された／Query＝問合せ／Language＝言語
DDLでぃーでぃーえる / Data Definition Language
表などを定義するSQL。CREATE・ALTER・DROP
Data＝データ／Definition＝定義／Language＝言語
DMLでぃーえむえる / Data Manipulation Language
データを操作するSQL。SELECT・INSERT・UPDATE・DELETE
Data＝データ／Manipulation＝操作／Language＝言語

9-4 トランザクション処理トランザクション

トランザクションTransaction
データベースへの、ひとまとまりの処理
ポイント全部成功（コミット）か、全部取り消し（ロールバック）のどちらか
ACID特性あしっどとくせい / ACID Properties
トランザクションが満たすべき4つの性質
Atomicity＝原子性（全部か無か）／Consistency＝一貫性／Isolation＝独立性／Durability＝耐久性
排他制御はいたせいぎょ / Exclusive Control
複数の処理が同じデータを同時に更新して矛盾しないよう、ロックをかけて順番に処理させる仕組み
ポイント共有ロック（読むだけ）と専有ロック（書き換える）がある
コミットCommit
トランザクションの処理を確定させること
ロールバックRollback
更新前のログを使って、トランザクションの途中の更新を取り消すこと
ロールフォワードRollforward
障害のあと、バックアップを戻してから、ログ（ジャーナル）の更新後の記録を使って処理をやり直すこと
基本情報 データベース13

9-4 トランザクション処理トランザクション

ジャーナルファイルログファイル / Journal File
データベースへの更新の前後の内容を記録したファイル
ポイント障害回復に使う
チェックポイントCheckpoint
主記憶にある更新内容を、一定の時点でディスクに書き出すこと
ポイント回復はチェックポイントから行えばよい

9-5 データベース応用データの活用

データウェアハウスData Warehouse
いろいろなシステムのデータを、分析しやすい形で時系列に集めたデータベース
データマイニングData Mining
大量のデータから、隠れた規則や関係を見つけ出すこと
例一緒に買われやすい商品の発見
ビッグデータBig Data
量が多く、種類がさまざまで、速く発生する大量のデータ
構造化データ・非構造化データStructured / Unstructured Data
構造化データは表の形に整理されたデータ、非構造化データは画像・音声・自由記述文など決まった形のないデータ
データレイクData Lake
構造化・非構造化を問わず、データを元の形のままためておく場所
外部データベースExternal Database
外部の事業者が提供していて、利用料を払って使うデータベース
