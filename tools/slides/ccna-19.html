第1章

QoS の考え方

混むのは出口。待ち行列で起きる遅れ・ばらつき・捨てられを、通信の種類ごとに配り分ける。

CCNA #19 QoS4.7

どこで混むか：速い所から遅い所への出口

QoS が扱う4つの品質
要素意味
帯域一定時間に運べる量（bps）。QoS は配り分けるだけ
遅延届くまでの時間。伝搬（距離）＋キューで待つ時間
ジッター遅延のばらつき
損失届かないこと。主にキューがあふれて捨てられる
QoS で減らせるのはキューで待つ時間とそこで捨てられること。光の速さで決まる伝搬遅延は変えられない。
出典：RFC 3246 1.（The dominant causes of delay … are fixed propagation delays … and queuing delays in switches and routers）／QoS CG IOS XE 17.9（Catalyst 9300）「Configuring QoS」（Queuing is used to prevent traffic congestion）。図はClaudeが作った例

通信の種類で、守りたいものが違う

種類弱いものふつうの扱い
音声遅延・ジッター・損失すべて。UDP なので送り直さない優先キュー（EF）
映像会議遅延・損失。量が多い帯域を保証（AF4x）
業務データ損失（TCP は送り直すが遅くなる）帯域を保証（AF）
その他あまり気にしない残りを分け合う（Default）
注意右の列の対応は RFC 4594 の推奨の例。DSCP の決め方はネットワークごとに決めてよい
音声の目安（Cisco の VoIP の QoS の資料）
遅延片道 150 ms 未満（ITU G.114 の勧め）
損失G.729 の音声で 1% よりずっと小さく
ジッター受け手のジッターバッファーで吸収するが、そのぶん遅延が増えるので小さく
PHB：DiffServ では経路全体の予約はせず、各機器が印（DSCP）を見て1台ずつ同じ方針で扱う。この「1ホップごとの扱い」が PHB。
出典：Cisco「Quality of Service for Voice over IP」（Loss should be far less than 1 percent／ITU G.114 … less than 150 ms one-way／Jitter must therefore be minimized）／RFC 4594（Telephony → EF、Multimedia Conferencing → AF4x）／RFC 2475 1.4.2（PHB ＝ externally observable forwarding behavior of a DS node）

1台の中の流れ：見分ける → 印 → 制限 → 並べる → 送る

どの部品がどちら向きかが問われる。キューは送り出すための待ち行列なので出口のしくみ。だからキューを使うシェーピングも出口だけ。ポリシングはためないので入りにも使える。
出典：QoS CG IOS XE 17.9「Configuring QoS」QoS Components（Classification … Marking … Shaping and policing … Queuing）／Cisco「Compare Traffic Policing and Traffic Shaping」（Doc 19645）（Queues are an outbound concept … Only policing can be applied to inbound traffic）。図はClaudeが作った例
第2章

分類とマーキング

L2 の CoS、L3 の IP Precedence と DSCP。どこに何ビットあるかと、代表の値。

CCNA #19 QoS4.7

印はどこにあるか：CoS と DSCP

ひっかけ：ルーターを通るとフレームは作り直されるので、CoS（L2）は次の区間に残らない。ルーターを越えて印を伝えるなら DSCP。
出典：RFC 2474（2. DS field ＝ IPv4 TOS octet／IPv6 Traffic Class octet、3. Six bits of the DS field are used as a codepoint）／RFC 3168（残り2ビットは ECN）／QoS CG 17.9「Configuring QoS」（802.1Q … class of service (CoS) 3-bit field）／Cisco VoIP QoS（Precedence 5 — the three most significant bits of the IP ToS byte are set to 101）

DSCP の代表の値

PHBDSCP使い道の例
Default0（000000）ふつう（best effort）
EF46（101110）音声。低遅延・低損失・低ジッター
CSx8x（xxx000）IP Precedence と互換。CS3＝24、CS5＝40、CS6＝48
AFxy の DSCP ＝ 8 × x ＋ 2 × y
計算AF41 ＝ 32 ＋ 2 ＝ 34　／　AF31 ＝ 24 ＋ 2 ＝ 26　／　AF23 ＝ 16 ＋ 6 ＝ 22
式は RFC 2597 の表の値から Claude が書いたもの（ビットで見ると xxx yy0）
AF の表（x＝クラス、y＝落としやすさ）
y＝1 低y＝2 中y＝3 高
クラス1AF11＝10AF12＝12AF13＝14
クラス2AF21＝18AF22＝20AF23＝22
クラス3AF31＝26AF32＝28AF33＝30
クラス4AF41＝34AF42＝36AF43＝38
落としやすさ：混んだら、同じクラスの中では y が大きい方から捨てる（AF23 は AF21 より先に捨てられる）。x の大小は「どちらが偉いか」を決めない（各クラスにどれだけ配るかは設定しだい）。
出典：RFC 3246 5.（Codepoint 101110 is RECOMMENDED for the EF PHB）／RFC 2597 2.（discarding packets with a higher drop precedence value）・6.（AF の表）／RFC 2474 4.1（Default PHB 000000）・4.2.2.1（Class Selector xxx000）

決まり内容

どこに置くかできるだけ端末に近い所（アクセススイッチ）

第3章

キューイングと輻輳回避

どのキューから先に送るか。キューがいっぱいになりそうなとき、どう捨てるか。

CCNA #19 QoS4.7

LLQ：優先キュー＋クラスごとの最低保証

policy-map WAN-OUT
 class VOICE
  priority 512        ! いつも先に。混んだら 512 kbps まで
 class WEB
  bandwidth 2000      ! 混んでも最低 2000 kbps
 class class-default
  fair-queue
interface g0/1
 service-policy output WAN-OUT
priority厳密な優先（LLQ）。混んだときは決めた速さでポリシングされ、ほかを飢えさせない
bandwidth最低保証（CBWFQ）。空いていればそれ以上も送れる
Cisco は音声に LLQ を勧めている。音声は優先、データは帯域保証、という分担。
出典：Cisco「Quality of Service for Voice over IP」Low Latency Queueing（priority to certain classes and guaranteed minimum bandwidth for other classes／During periods of congestion, the priority queue is policed at the configured rate／None of the reserved queues are restricted to the configured bandwidth if bandwidth is available／we recommend LLQ）。設定はCiscoの例の書式でClaudeが作った例

テールドロップと WRED

キューの長さと、捨てる確率
形は RFC 2309 の RED の説明から Claude が描いた。WRED は印ごとに minth・maxth を変え、印の低いものほど早く捨てる
テールドロップWRED
いつ捨てるキューが満杯になってから満杯になる前から少しずつ
何を捨てる種類に関係なく全部DSCP・CoS などで差をつける
起きること多くの TCP が一斉に減速 → TCP グローバル同期一部の TCP だけ減速 → 同期を防ぐ
音声には効かない：WRED は「捨てられた TCP が速度を落とす」ことを利用する。UDP の音声は速度を落とさず音が欠けるだけなので、優先キューで守る。
出典：QoS CG IOS XE 17.9「Configuring Weighted Random Early Detection」（Tail drop treats all traffic equally／takes advantage of the congestion control mechanism of TCP／drops some packets early … minimizes the chances of TCP global synchronization）／RFC 2309 2.（global synchronization）・3.（minth・maxth）
第4章

ポリシングとシェーピング

決めた速さを超えた分を、すぐ捨てるか（ポリシング）、ためて後で送るか（シェーピング）。

CCNA #19 QoS4.7

捨てるか、ためるか

点線＝来た量、太線＝出ていく量。Cisco の資料の「ポリシングはのこぎり形、シェーピングはなめらか」を Claude が描いた
ポリシングシェーピング
超えた分捨てる（または印を下げる）キューにためる
遅延増えない増える（待つ）
向き入りでも出でも出口だけ
TCP への影響捨てられて送り直し捨てにくい
よくある場所ISP がお客さんの入りを制限お客さんが契約の速さに合わせて出す
例口は 1 Gbps、契約は 100 Mbps → 自分の出口で shape average 100000000。ISP 側で何が捨てられるかを選べない状態を避ける
出典：Cisco Doc 19645（policing … output rate that appears as a saw-tooth／shaping … a smoothed packet output rate／Buffer and queue excess packets・Drops (or remarks) excess packets／Only policing can be applied to inbound traffic）／QoS CG 17.9「Configuring QoS」（Shaping … downstream devices are not subjected to congestion）。例はClaudeが作った

トークンバケツと Tc ＝ Bc ÷ CIR

CIR守る平均の速さ（bps）
Bc1つの区切りの時間に送ってよい量（ビット）
Tc区切りの時間（秒）
Be使わずに残した分を後でまとめて使える上乗せ
Tc ＝ Bc ÷ CIR
例　CIR 8 Mbps、Bc 80,000 ビット
  1. Tc ＝ 80,000 ÷ 8,000,000 ＝ 0.01 秒 ＝ 10 ms
  2. 10 ms ごとに 80,000 ビットずつ送ると、1秒で 100 回 × 80,000 ＝ 8,000,000 ビット（平均 8 Mbps）
  3. 同じ CIR で Bc を 2 倍にすると、Tc も 2 倍の 20 ms（式から）
出典：Cisco Doc 19645 Token Bucket（the packet either waits until the bucket has enough tokens (in the case of a shaper), or the packet is discarded or marked down (in the case of a policer)／the largest burst … is roughly proportional to the size of the bucket／Tc = Bc/CIR (in seconds)／Be）。計算の例はClaudeが作った

MQC で組み立てる：class-map → policy-map → service-policy

! 1 何を（分類）
class-map match-any VOICE
 match dscp ef
class-map match-any GUEST
 match access-group name GUEST-NET
! 2 どうする（扱い）
policy-map EDGE-IN
 class GUEST
  police cir 10000000
   conform-action transmit
   exceed-action drop
 class class-default
  set dscp default
! 3 どこに・どちら向きに
interface g1/0/10
 service-policy input EDGE-IN
部品役目
class-mapmatch で何を見分けるか（DSCP・ACL など）
policy-mapクラスごとにどうするか（set・priority・bandwidth・police・shape）
service-policyインタフェースにinput／output を付けて当てる
class-defaultどのクラスにも当たらなかったもの。どの policy-map にもある
読み方：左は「入ってくるゲストの通信を 10 Mbps で制限し、超えたら捨てる。それ以外は印を 0 に書き直す（信頼しない）」。入りなので police は使えるが shape は使えない。
出典：QoS CG IOS XE 17.9「Configuring QoS」（Modular QoS CLI／class-map・policy-map・service-policy／Every policy map has a default class／police … conform-action・exceed-action）／Cisco Doc 19645（Only policing can be applied to inbound traffic）。設定はClaudeが作った例

よくあるひっかけ

よくある思い込み正しくは
QoS で回線が速くなる帯域は増えない。混んだときの配り分け
CoS はルーターを越えても残るCoS は 802.1Q タグ（L2）。越えて残るのは DSCP
EF の DSCP は 5EF は 46。5 は IP Precedence（または CoS）の音声の値
AF41 の DSCP は 418×4＋2×1＝34
AF13 は AF11 より守られるy が大きいほど先に捨てられる
bandwidth は上限最低保証。上限で抑えるのは police・shape、優先キューの上限は priority
WRED で音声を守るWRED は TCP 向け。音声は優先キュー
シェーピングは入りにも使えるシェーピングは出口だけ。入りで使えるのはポリシング
ポリシングは遅延を増やすためないので増えない。遅延が増えるのはシェーピング

まとめ

考え方帯域・遅延・ジッター・損失。音声は片道 150 ms 未満。混むのは出口。各機器が印を見て扱う＝PHB
印CoS 3ビット（L2）・IP Precedence 3ビット・DSCP 6ビット。EF 46・AFxy＝8x＋2y・CSx＝8x・Default 0。信頼境界はアクセスに
キューLLQ＝priority（音声）、CBWFQ＝bandwidth（最低保証）。テールドロップ→TCP グローバル同期、WRED で防ぐ
速さの制限ポリシング＝捨てる・入出どちらも／シェーピング＝ためる・出口だけ。Tc＝Bc÷CIR
