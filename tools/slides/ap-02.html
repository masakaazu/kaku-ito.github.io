データ構造

配列とリスト ／ スタックとキュー ／ 木（2分探索木・AVL木・ヒープ）／ ハッシュ表

スタックは「後から入れたものが先」、キューは「先に入れたものが先」

使い道：スタック＝関数の戻り先・逆ポーランド記法・深さ優先探索。キュー＝待ち行列・幅優先探索。優先度の高いものから出すのは優先度付きキュー（ヒープで作る）。
R3春 問5＝R7春 問5：A, B, C の順に入れ、出し入れ1回ずつ
出力順できるか操作（入＝プッシュ、出＝ポップ）
A B C○A入出 → B入出 → C入出
A C B○A入出 → B入 → C入出 → B出
B A C○A入 → B入出 → A出 → C入出
B C A○A入 → B入出 → C入出 → A出
C B A○A入 → B入 → C入出 → B出 → A出
C A B×C を先に出すと、一番上は B。A を B より先に出せない
並べ方6通りのうち、作れないのは CAB だけ → 5通り（ウ）。

配列は「参照が速い」、連結リストは「挿入・削除が速い」

双方向リストは前へのポインタももつ。挿入では、新しい要素の次・前と、前後の要素の計4か所を書き換える。
操作配列で作るポインタで作る
i番目を見るすぐ（添字）先頭からたどる（要素数に比例）
途中に挿入・削除後ろをずらす（要素数に比例）付け替えだけ（一定時間）
領域最大個数分を先に確保。使わない領域が出る要素の分だけ。ポインタの領域が余計に要る
R4春 問5：配列で作ったリストの特徴は「最大個数分の領域を確保し、使われない領域が出る（ア）」。イ・ウ・エはどれもポインタの方の特徴。

2分探索木は「左＜節＜右」。消したら左の最大か右の最小で埋める

R6秋 問5：12 を削除して、別の要素を移すだけで直す
2分探索木の決まり
どの節でも、左の部分木は全部小さく、右の部分木は全部大きい。中間順になぞると小さい順に並ぶ
削除のしかた
葉なら消すだけ。子が1つならその子を上げる。子が2つなら左の部分木の最大値か右の部分木の最小値を移す
12 の左の部分木の最大は 11、右の部分木の最小は 13。選択肢にあるのは 13（ウ）。9・10・14 を置くと、残った節で大小の決まりが崩れる。
偏った形（片側に一直線）になると探索が O(n) に落ちる。これを防ぐのが次の AVL木。

AVL木は「左右の高さの差が2になった一番下の節」で回転する

右回転（左に偏ったとき）
偏った節の左の子を上に上げ、偏った節はその右の子になる。3より上と右側（7・6）は動かさない

配列：9, 7, 8, 3, 5, 6

配列：10, 7, 9, 3, 5, 6, 8
10 を末尾（8 の右の子）に置き、親より大きければ交換：8 と交換 → 9 と交換 → 根へ。高さの分だけなので O(log n)。

アルゴリズム

流れ図 ／ 整列 ／ 探索 ／ 再帰と設計方法 ／ グラフ・文字列 ／ 記憶域の管理

流れ図は記号の形で役割が決まる。ループは「いつ抜けるか」を数で確かめる

ループ端には「変数名：初期値，増分，終値」を書く。定義済み処理は両端に縦線（中身は別の流れ図）。
R6春 問5：x←1, n←1 から「x←x×n, n←n＋1」を a まで繰り返す
回x←x×nn←n＋1a＝「n＞M」（M＝3）
11×1＝12No
21×2＝23No
32×3＝64Yes → 終了
左の流れ図は M から1まで掛けて M!＝6。右も 6 で止めるには、M まで掛けた直後（n＝M＋1）で抜ける n＞M（ウ）。n＞M−1 だと1回足りず、n＞M＋1 だと1回多い。
コツ：M＝3 のような小さい数を入れて、表で1行ずつ追う。

バブルソートは「1回なぞるごとに、端に最大が1つ決まる」

誤りの選択肢この状態にならない理由
クイックソート基準値（例えば3）で分けるので、状態1で 1, 2 が前へ移るはず
挿入ソート先頭から整列済みの部分が伸びる。末尾から決まらない
ヒープソート最初にヒープを作るので、全体の並びが大きく入れ替わる
バブルソートは10回で4回出た：説明文（R3秋 問5・R6春 問7）、流れ図（R4秋 問6）、途中経過（R5秋 問6）。比べる向きが「末尾から先頭へ」でも、隣どうしの交換ならバブルソート。

再帰は「止まる条件」と「小さくして自分を呼ぶ」の2つでできている

R7春 問7：fact(n) の再帰的な定義
if n＝0 then return 1
else return n × fact(n−1)
選択肢どうなるか
0 を返す, n−1最後に0が掛かり、いつも0
0 を返す, n＋1n が増え続けて止まらない
1 を返す, n−1正しい（ウ）
1 を返す, n＋1n＝0 にたどり着かず止まらない
呼ぶたびに引数と戻り先がスタックに積まれる。止まる条件がないと積み続けてあふれる（スタックオーバーフロー）。だから再帰には、呼出しごとに別のデータ領域が必要（→第3章「再帰的」）。

ダイクストラ法は「一番近い未確定の点を確定」を繰り返す

手順確定する点S からの距離（未確定は暫定）
1S＝0A＝2, B＝5
2A＝2B＝min(5, 2＋1)＝3, C＝2＋6＝8
3B＝3D＝3＋2＝5
4D＝5G＝5＋4＝9
5C＝8G＝min(9, 8＋1)＝9
6G＝9S→A→B→D→G（または S→A→C→G）
重みが負の辺があると使えない（確定した距離があとで縮むため）。負の辺があるときはベルマンフォード法（全部の辺で更新を繰り返す）。辺の重みがなければ幅優先探索で辺の本数が最少の道が求まる。

文字列照合は「どこから比べ、どれだけずらすか」の違い

本文「ABCABDABCABC」からパターン「ABCABC」を探す
方法比べ方
本文ABCABDABCABC
位置0ABCABC
力まかせA…
KMPABC…
BMABCABC
位置0は6文字目（本文の D）で不一致。力まかせは1つずらして先頭から。KMPは一致した ABCAB の末尾 AB がパターンの先頭と同じことを使い、3つずらして D の所から比べ直す。BMは末尾から比べるので最初に D を見る。D はパターンにない文字なので6つ一気にずらせる。
方法比べる向き不一致のとき
力まかせ法先頭から1文字ずらして先頭から比べ直す
KMP法先頭から一致していた部分のパターン自身の情報で、比べ直す位置を決める。本文の中で後戻りしない
BM法末尾から不一致の文字に応じてパターンを大きくずらす。実際の文章では速い
見分ける一言：「末尾から」ならBM法、「パターン自身の情報（一致した部分）」ならKMP法。名前はどちらも考案者の頭文字。

空き領域の割当て：ベストフィットは「入る中で一番小さい」

空き領域 30・12・20（アドレス順）に、10 を割り当てる
ベストフィットは 12 を使い、2 という使いにくい小さな空きが残る。これが積み重なるのが弱点（R7秋 問5 イ）。
方式選ぶ領域傾向
ファーストフィット先頭から見て最初に入る下位アドレスが細かくなる（R7秋 問5 ア）
ベストフィット入る中で最小小さな空きが多数残る
ワーストフィット最大大きな空きが減る
R5春 問5：ベストフィットを速くするには、空き領域を大きさをキーにした2分探索木（ウ）で持つ。大きさ順のリストでは先頭からたどるので O(n)。
細切れ（フラグメンテーション）は、使用中の領域を詰めるコンパクションで解消する。

言葉・圧縮・3次元図形のアルゴリズムは「何を順に決めるか」で覚える

形態素解析単語に区切り品詞を決める
→
構文解析係り受け（どこにかかるか）
→
意味解析単語・文の意味を決める
→
文脈解析指示語・省略を文をまたいで補う
圧縮やり方
ランレングス法AAAABBB → A4B3。同じ値が続くデータ（白黒画像・FAX）向き
ハフマン法よく出る記号ほど短い符号。区切りなしで元に戻せる
n-gram：「東京都」→「東京」「京都」と n 文字ずつ区切って索引を作る。文章間類似度は文章をベクトルにして近さを測る。
3次元図形やり方
Zバッファ法画素ごとに奥行き（Z値）を記録し、手前の物だけ描く
スキャンライン法横1行（走査線）ごとに、手前に見える面を決める
レイトレーシング法視点から光線を逆にたどり、反射・屈折・影を計算
Zバッファ法とスキャンライン法は隠面消去（隠れた面を消す）の方法。レイトレーシング法は写実的だが計算が重い。
第3章

プログラミング

プログラムの4つの性質 ／ プログラムの構造 ／ データ型 ／ Webプログラミング ／ BNF

プログラムの性質は4つ。「再入可能＝同時に呼ばれても正しい」

性質意味そのための条件
再入可能
リエントラント		複数のタスクから同時に呼ばれても、それぞれ正しい結果手続は共有、データはタスクごと
再使用可能
リユーザブル		読み込み直さずに、もう一度実行できる始めに初期化する（終わりに初期状態へ）
再帰的
リカーシブ		自分自身を呼び出せる呼出しごとに別のデータ領域
再配置可能
リロケータブル		主記憶のどこに置いても動くアドレスを相対で表す
R4春 問6：再入可能の特徴は「並行して実行されても、それぞれのタスクに正しい結果を返す（エ）」。ア＝再配置可能、イ＝再帰的、ウ＝オーバーレイ。
R3秋 問6：正しいのは再使用可能の説明（イ）。「再入可能はデータとコードの両方を共用」「再帰的は全てがデータを共用」「再配置可能は定まった領域で実行」がそれぞれ誤り。

オーバーロードは「同じ名前・違う引数」、オーバーライドは「親を書き直す」

用語意味
オーバーロード同じクラスに、名前が同じで引数の型や数が違うメソッドを複数定義（多重定義）
オーバーライド親クラスのメソッドを、名前も引数も同じまま子クラスで書き直す
多重継承複数の親クラスから引き継ぐ。C++はできる、Java・Scalaはクラスではできない
DLL実行時に結び付ける部品の集まり。部品だけ差し替えられる
静的リンク作るときに部品を実行ファイルに全部取り込む
class 図形 { 面積() }
class 円 extends 図形 { 面積() ← オーバーライド }

印刷(int x)　印刷(String s)　印刷(int x, int y)
↑ 同じ名前で引数が違う ＝ オーバーロード
モジュール分割：機能ごとに分け、モジュールの中のまとまりは強く、モジュールどうしのつながりは弱くするほど独立性が高い。コーディング標準では命名規則・字下げ・ネストの深さ・使用禁止命令（goto など）を決める。

Web技術は「ブラウザで動くか、サーバで動くか」で分ける

技術見分ける一言
Ajax画面を切り替えず、裏で非同期に通信して一部だけ書き換える
SPA1ページだけ読み込み、中身を入れ替えて画面を変える
WebAssemblyC言語などから作ったバイナリをブラウザで高速に実行
JSPHTMLにJavaを埋め込み、サーバでページを作る
リッチクライアントWebで配布しつつ、デスクトップアプリ並みの操作性

BNFは「::＝」と「|」だけ。繰返しは自分自身を使って書く

〈識別子〉::＝〈英字〉|〈識別子〉〈英字〉|〈識別子〉〈数字〉
〈英字〉::＝A|B|C
〈数字〉::＝0|1|2
文字列〈識別子〉か理由
A1B○A → A1（＋数字）→ A1B（＋英字）
1AB×必ず〈英字〉から始まる
AB3×3 は〈数字〉に入っていない
記法特徴
BNF「::＝」（定義）と「|」（または）。繰返しは再帰で表す
EBNFBNFに { }（繰返し）や [ ]（省略可）を足して短く書ける
構文図同じ決まりを、矢印でつないだ箱の図で表す
BNFで書けるのは文脈自由文法。多くのプログラム言語の構文規則（書き方の決まり）はこれで定める。何を意味するかの決まりは意味規則。
基礎理論の「形式言語とオートマトン」とつながる：文脈自由文法を受理するのはプッシュダウンオートマトン。

プログラム言語

言語の分類 ／ 過去問に出た言語 ／ 型付け ／ 引数の渡し方 ／ 記憶域

言語は「水準」と「書き方（パラダイム）」の2軸で分ける

高水準言語人の考え方に近い。C・Java・Python など
↓ コンパイラ・インタプリタ
中間言語CPUに依存しない形（Javaのバイトコード、CLIの共通中間言語）
↓ 仮想マシン・JITコンパイラ
アセンブラ言語機械語と1対1の記号（ADD・MOV）
機械語CPUが直接実行する0と1
分類考え方例
手続型手順を順に書き、変数を書き換えて進めるC、Fortran、COBOL
関数型関数の定義と適用を組み合わせる。値を書き換えないHaskell、Lisp
論理型事実と規則を書き、推論で答えを出すProlog
オブジェクト指向データと手続をまとめたオブジェクトが単位Java、C++
スクリプト手軽に書いてすぐ実行。動的型付けが多いPython、PHP、Ruby、Perl
共通言語基盤（CLI）：違う言語で書いた部品を共通の中間言語にして同じ環境で動かす仕様（JIS X 3016）。.NET がこれに沿う。

言語特徴型付け過去問

Python字下げでブロックを表す。AI・分析で人気動的R4春 問7

静的型付け：実行前（コンパイル時）に型を決めて誤りを見つける。動的型付け：代入された値で実行時に型が決まる。型推論：型を書かなくても処理系が決める（Scala・Kotlin・Go・TypeScript）。

ブロックの表し方：C・Java・PHP は { }、Pascal は begin〜end、Python は字下げ。

値呼出しはコピーを渡す、参照呼出しは場所を渡す

a←1, b←1
sub(a, b)　← a, b は実引数
sub(x, y) { x←x＋10; y←y＋10 }　← x, y は仮引数
渡し方渡すものsub のあと
値呼出し（x）a の値のコピーa＝1（変わらない）
参照呼出し（y）b の場所（アドレス）b＝11（変わる）
再帰で呼出しごとに別になるのは自動変数（スタック領域）。ヒープ領域の使われなくなったデータを自動で回収するのがガベージコレクション。解放し忘れて減っていくのはメモリリーク。

その他の言語

HTML・XML ／ DTDとXML Schema ／ DOM・SAX ／ JSON ／ スタイルシート ／ UML

XMLは「タグを自分で決められる」。UTF-8とUTF-16なら符号化宣言を省略できる

SGMLマークアップ言語を定義するための元の規格
HTML決まったタグだけ
XMLタグを自分で定義
XHTMLHTMLをXMLの規則で定義し直した。終了タグを省略できない
<?xml version="1.0" encoding="Shift_JIS"?>
<本><題名>応用情報</題名></本>
R4秋 問7：符号化宣言（encoding）を省略できるのは UTF-16（エ）（と UTF-8）。XMLの処理系はこの2つを必ず読めることになっていて、先頭のバイトから見分けられる。EUC-JP・ISO-2022-JP・Shift_JIS は宣言が必要。
決まりの書き方特徴
DTD使える要素・属性を定義。SGMLからの独自の書き方。データ型は細かく決められない
XML Schema同じ役割をXMLの書き方で。整数・範囲などデータ型まで決められる

JSONは「名前と値の組」と「値の並び」の2つの形だけ

{
　"試験": "応用情報",　← 名前と値の組
　"分野": ["基礎理論", "アルゴリズム"]　← 値の順序付きリスト
}
R5秋 問7：JavaScriptのオブジェクトの表記法が元で、この2つの構造でデータを表すのは JSON（イ）。Web API のデータ交換で一番使われる。字下げで書く YAML は設定ファイル向き。
名前役割
DOM文書を木の形で全部読み込み、自由に読み書きする
SAX先頭から読み、タグが現れるたびに処理を呼ぶ。メモリが少なくて済む
SOAPXMLのメッセージでほかのシステムの機能を呼ぶ通信の決まり
XSLXMLを別の形式に変換したり見た目を決めたりする
CSS構造は変えず見た目だけを指定する
SVG図形を線や形の情報としてXMLで書く画像形式
R5秋 問7 の誤りは DOM・SOAP・XML。どれもXMLに関係するが、「データ記述の仕様」で「JavaScriptが元」なのはJSONだけ。

UMLは「構造（形）」と「振る舞い（動き）」の図に分かれる

構造の図表すもの
クラス図クラスの属性・操作と関係（上の図）
オブジェクト図ある時点の具体的なオブジェクトのつながり
コンポーネント図ソフトウェアの部品とインタフェース
配置図どのハードウェアに何を置くか
振る舞いの図表すもの
ユースケース図利用者（アクター）から見た機能
アクティビティ図処理の流れ（分岐・並行）。流れ図に近い
ステートマシン図1つのオブジェクトの状態の移り変わり
シーケンス図メッセージのやり取りを時間の順に上から下へ
コミュニケーション図オブジェクトのつながりを中心に、順番は番号で
タイミング図横軸に時間をとり、状態が変わる時刻を正確に
シーケンス図とコミュニケーション図は同じ内容を別の見せ方で表す。「時間の順」ならシーケンス図、「つながり」ならコミュニケーション図。
