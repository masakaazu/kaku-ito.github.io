resource ブロックの中身

resource "aws_db_instance" "example" { # ↑型（何を・どの引数） ↑ローカル名 → アドレス aws_db_instance.example count = 2 # メタ引数（Terraform の管理のしかた） provider = aws.west engine = "postgres" # 引数（プロバイダーが決める） instance_class = "db.t3.micro" timeouts { # 対応する型だけの子ブロック create = "60m" delete = "2h" } lifecycle { prevent_destroy = true } }
型名の先頭 → プロバイダーaws_instance の aws。別の設定は provider = aws.west
メタ引数count・for_each・provider・depends_on・lifecycle
apply がすることないものを作る・消えたものを消す・その場で更新・できなければ作り直し・ステート更新
ローカルだけのリソース：random_id・tls_private_key（ステートにだけ値がある）
出典：Configure a resource／Create and manage resources overview

データソースはいつ読む？

引数がすべて計画で分かるplan の前の refresh で読む → 計画で値が使える
引数が、この計画で変わるリソース・適用で決まる値に依存apply まで延ばす → 計画では computed（known after apply）
延ばすと、その値を使うリソースも apply まで決まらない。
データソース何をするか
aws_ami・aws_vpc など外で作られたものを条件で探す
aws_iam_policy_documentIAM ポリシーの JSON を作る（手元で計算）
local_file手元のファイルを読む
terraform_remote_stateほかの設定のステートの出力値を読む
data にも count・for_each・provider・depends_on・precondition/postcondition が使える。
出典：Query infrastructure data（Data source behavior／Specialized data sources）／Remote State

参照とアドレス

名前で読む。参照が順番を決める。

Terraform #06 resourceとdata・参照目標 4a・4b

名前つきの値

種類書き方メモ
管理するリソースaws_instance.web.idほかの形に合わない名前はリソースとみなす
データソースdata.aws_ami.web.iddata. を付ける
入力変数var.region型の制約に変換された値
ローカル値local.name定義は locals ブロック
子モジュールの出力module.network.subnet_idscount ならリスト、for_each ならマップ
ファイル・ワークスペースpath.module・path.root・path.cwd・terraform.workspacepath.module 以外はルートだけで
ブロックの中だけcount.index・each.key・each.value・self入力変数とは別のもの
本物のオブジェクトではない：『you cannot use aws_instance in a for expression to iterate over every AWS instance resource』
出典：References to Named Values

属性の参照とスプラット

リソース値の形読み方
count・for_each なしオブジェクトaws_instance.web.id
countリスト[0].id・[*].id
for_eachマップ["a"].id・for 式・values(…)[*].id
引数（ami）も属性（id）も同じ書き方で読める。
var.list[*].id # ＝ [for o in var.list : o.id] aws_instance.example.ebs_block_device[*].device_name [for v in aws_instance.example : v.id] # for_each values(aws_instance.example)[*].id # for_each
スプラットはリスト・セット・タプルだけ。マップには for 式。
出典：References to Named Values（References to Resource Attributes）／Splat Expressions

暗黙の依存関係

resource "aws_vpc" "main" { cidr_block = "10.0.0.0/16" } resource "aws_subnet" "a" { vpc_id = aws_vpc.main.id # ← 参照 cidr_block = "10.0.1.0/24" }
↓ Terraform が式を読んで
aws_vpc.main → aws_subnet.aVPC が先。依存しないものは並列
『an expression in a resource argument that refers to another managed resource creates an implicit dependency』
local 値を通した間接の参照でも見つける。
参照では分からない依存（IAM ポリシーの付与を待つなど）は depends_on で明示（#09）。
出典：References to Named Values（Named Values and Dependencies）／Configure a resource（Specify resource dependencies）

リソースアドレス

[module path][resource spec] module.foo[0].module.bar["a"].aws_instance.web[2] └ foo の 1 つ目 ┘└ bar のキー a ┘└ web の 3 つ目 ┘
アドレス指すもの
aws_instance.web[3]count の 4 つ目（0 から数える）
aws_instance.web["example"]for_each のキー example
aws_instance.web全インスタンス
module.fooモジュールの中の全部
モジュールのパスを省くとルートモジュールだけ（0.12 以降）。
使う場所：state list・state show・-target・-replace・import・moved など。
sensitive な属性を output に使うなら、output にも sensitive = true。ステートには平文で残る。
出典：Resource Address Reference／References to Named Values（Sensitive Resource Attributes）
