第1章

String のしくみ

変わらない。だから同じリテラルは 1 つを使い回せる。

Java Silver #03 文字列試験内容 2

String は不変 ― 戻り値を受け取らないと変わらない

s.toUpperCase(); のとき（Claude が作成）
String s = "java";
s.toUpperCase();          // 戻り値を捨てている
s.concat("!");             // これも
System.out.println(s);    // java

s = s.toUpperCase();      // 受け取れば変わる
System.out.println(s);    // JAVA
String の「変えるように見える」メソッド（toUpperCase・concat・replace・trim・substring など）は、どれも新しい String を返すだけ。
変わるのは変数の中身（参照）だけ：s = s.toUpperCase(); は、s が新しいオブジェクトを指すようになる。"java" のオブジェクト自体は変わらない。
出典：Java SE 17 API String（Strings are constant; their values cannot be changed after they are created／Because String objects are immutable they can be shared）／結果は JDK 17 で確かめたもの

== と equals、リテラルのプール

オブジェクトの数（Claude が作成）

式結果

テキストブロック

""" と改行で始めて、見たままの複数行を書く。Java 15 から。

テキストブロックの形と、最後の改行

終了の """ を最後の行の末尾に置く
String s1 = """
    abc""";           // "abc"（長さ 3）
終了の """ を次の行に置く
String s2 = """
    abc
    """;              // "abc\n"（長さ 4）
NG の例（JDK 17 の表示）
String t = """abc""";
// illegal text block open delimiter sequence,
// missing line terminator
String u = "abc
    ";       // unclosed string literal
決まり中身
開始の """そのあとは空白（任意）と改行。同じ行に中身は書けない
中身開始の改行の次の行から、終了の """ の直前まで
最後の改行""" が単独の行 → 付く。中身の行末 → 付かない
型String。リテラルと同じくインターンされる（"hi\n" と == で true）
" の扱いそのまま書ける。""" が 3 つ続くときだけエスケープ
メソッドそのまま呼べる：""".formatted("Java")
出典：JLS 3.10.6 Text Blocks（The opening delimiter … concludes with a line terminator／A text block is always of type String／a text block always refers to the same instance of class String）／Programmer's Guide to Text Blocks（placing the closing delimiter on the last visible line effectively drops the last \n）／結果は JDK 17 で確かめたもの

左の空白はどこまで消えるか

空白を「・」で見えるようにした（Claude が作成）
String s = """
・・・・・・・・・・a
・・・・・・・・・・・・b
・・・・・・・・""";
灰色の 8 字が消える空白（付随的な空白）。残るのは a の前の 2 字と b の前の 4 字。
s.replace(' ', '.') を表示
..a
....b
終了の """ の位置結果（a 10 字・b 12 字下げ）
8 字下げ（中身より左）..a / ....b
10 字下げ（a と同じ）a / ..b
14 字下げ（中身より右）a / ..b（中身の最小に合わせる）
行末に置く（b"""）中身の行だけで決まる。最後の改行なし
決まり：中身の行と「""" だけの最後の行」のうち、いちばん左の行に合わせて全体を左に寄せる。行どうしの相対的な字下げは残る。
行末の空白も消える。残したいときは \s を使う（次のページ）。
出典：JLS 3.10.6（Incidental white space is removed, as if by execution of String.stripIndent）／Programmer's Guide to Text Blocks Incidental White Space（The entire contents of the text block is shifted to the left until the line with the least leading white space has no leading white space）・Trailing White Space／表の結果は JDK 17 で確かめたもの

テキストブロックのエスケープ

String s = """
    one \
    two\s
    """;
System.out.println("[" + s.replace("\n", "/") + "]" + s.length());
[one two /]9
行末の \：改行を取り消して次の行につなぐ。\ の前の空白は行末ではないので残る。
\s：空白 1 つ。エスケープは空白を消したあとに変換されるので、行末でも残る。
エスケープ意味
\n・\t改行・タブ（普通の文字列と同じ）
\""。テキストブロックではふつう不要
\\\ そのもの
\s空白 1 つ（Java 15〜）
\＋改行改行しない（テキストブロックの中だけ）
3 つの処理の順番：① 改行を LF にそろえる → ② 左と行末の空白を消す → ③ エスケープを変換する。だから \s や \040 は ② で消されない。
出典：JLS 3.10.6（Line terminators are normalized … Incidental white space is removed … Escape sequences are interpreted）／3.10.7 Escape Sequences（\s (space SP, Unicode \u0020)／\ LineTerminator (line continuation)）／Programmer's Guide to Text Blocks（\s can act as fence to prevent the stripping of trailing white space）／結果は JDK 17 で確かめたもの
