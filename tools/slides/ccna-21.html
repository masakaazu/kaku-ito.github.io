IPsec の4つの働きと部品

4つの働き
働き意味
機密性送る前に暗号化する
完全性途中で書き換えられていないか確かめる
送信元の認証本当にその相手から来たか確かめる
リプレイ防止記録して送り直されたパケットを捨てる
IPsec は1つのプロトコルではなく、開かれた標準の集まり。IP の層で守るので、アプリは変えなくてよい。
部品
部品役目
IKE相手を認証し、アルゴリズムを話し合い、鍵を作って SA を作る（UDP 500）
ESPデータを暗号化＋完全性・認証・リプレイ防止（プロトコル 50）
AH完全性・認証・リプレイ防止。暗号化しない（プロトコル 51）
SAどのプロトコル・アルゴリズム・鍵で守るかの取り決め。片方向
トランスフォームセットESP＋AES＋SHA などの組み合わせ。両側で同じものを選ぶ
Cisco の勧めDES・3DES・MD5・DH グループ 1／2／5 はやめ、AES・SHA・DH グループ 14 以上
出典：Security for VPNs with IPsec CG（IOS XE）「Configuring Security for VPNs with IPsec」（IPsec is a framework of open standards／Data confidentiality・Data integrity・Data origin authentication・Anti-replay／IKE provides authentication of IPsec peers, negotiates IPsec security associations, and establishes IPsec keys／SAs are unidirectional／A transform set represents a certain combination of security protocols and algorithms／Cisco no longer recommends using DES, 3DES, MD5 … and DH groups 1, 2 and 5）

ESP と AH・トンネルモードとトランスポートモード

ESPAH
プロトコル番号5051
暗号化するしない
NATNAT-T（UDP 4500）で通る通らない
AH と NAT：AH は送信元・宛先の IP アドレスも検査に入れる。NAT がアドレスを書き換えると検査が合わない。ESP はアドレスを入れないのでこの問題はない。RFC 4301 も「たいていは ESP だけで足りる」。
出典：RFC 4301 3.2・4.1（most security requirements can be met through the use of ESP by itself／transport mode … between a pair of hosts／whenever either end … is a security gateway, the SA MUST be tunnel mode）／RFC 4303 2.（50）／RFC 4302 2.（51）／RFC 3715 2.1（AH and NAT）／RFC 3948。図はClaudeが作った（ESP の後ろの部分は簡単にした）

CCNA #21 VPN5.5

クリプトマップと VTI

クリプトマップ（ACL で選んだ通信を守る）
crypto isakmp policy 10
 encryption aes 256
 authentication pre-share
 group 14
crypto isakmp key MyKey123 address 203.0.113.2
crypto ipsec transform-set TS esp-aes 256 esp-sha-hmac
access-list 120 permit ip 10.1.0.0 0.0.255.255 10.2.0.0 0.0.255.255
crypto map VPN 10 ipsec-isakmp
 set peer 203.0.113.2
 set transform-set TS
 match address 120       ! 守る通信
interface g0/0
 crypto map VPN          ! 物理 IF に付ける
相手側は送信元と宛先を入れかえた鏡写しの ACL にする
VTI（トンネルがインタフェースになる）
crypto ipsec profile P1
 set transform-set TS
interface Tunnel1
 ip address 172.16.0.1 255.255.255.252
 tunnel source g0/0
 tunnel destination 203.0.113.2
 tunnel mode ipsec ipv4
 tunnel protection ipsec profile P1
ip route 10.2.0.0 255.255.0.0 Tunnel1
クリプトマップVTI
何を守るACL に合う通信トンネルへルーティングした通信
マルチキャスト通らない通る（OSPF など）
出典：Cisco「Configuring Security for VPNs with IPsec」（Creating Crypto Access Lists：Specifies conditions to determine which IP packets are protected … "mirror image" crypto access lists／Example: Configuring AES-Based Static Crypto Map）／「IPsec Virtual Tunnel Interfaces」（routable interface type … support multicast … managed by the IP routing table／tunnel mode ipsec ipv4・tunnel protection）。設定はCiscoの例の書式でClaudeが作った例

GRE over IPsec：包むのは GRE、守るのは IPsec

GREIPsec
包めるものユニキャスト・マルチキャスト・ブロードキャストIP パケットだけ
暗号化・認証なしあり
interface Tunnel100
 ip address 128.1.1.1 255.255.255.0
 tunnel source 120.1.1.1

組み合わせると「ルーティングプロトコルも動く、暗号化されたトンネル」になる。
出典：GRE Configuration Guide IOS XE 17「GRE over IPsec」（encapsulates … unicast, multicast, broadcast … GRE does not itself provide data confidentiality or authentication … IPsec … can only secure IP packets／設定例 Tunnel100）／RFC 2784 4.（IPv4 protocol 47）

DMVPN：多くの拠点を少ない設定で

部品役目
mGRE1つのトンネルインタフェースで多くの相手。設定が増えない

SSL/TLS VPN と IPsec のリモートアクセス

方式端末に要るもの特徴
SSL/TLS VPN（クライアント）VPN クライアント（AnyConnect など）ネットワーク全体へ
クライアントレス SSL VPNブラウザーだけ「web VPN」。Web 画面から届くものだけ

よくあるひっかけ

よくある思い込み正しくは
サイト間 VPN では PC ごとにクライアントが要る要らない。拠点の機器がトンネルを作る
AH で暗号化するAH は暗号化しない。暗号化は ESP
ESP は 51、AH は 50ESP 50・AH 51。GRE は 47
IKE がデータを暗号化して運ぶIKE は鍵と SA を決める（UDP 500）。データは ESP
SA は両方向で1つ片方向。行きと帰りで別
GRE で暗号化できるGRE は包むだけ。守るなら IPsec と組み合わせる
クリプトマップで OSPF もそのまま通るマルチキャストは通らない。GRE over IPsec か VTI
AH は NAT を通れるアドレスを検査に入れるので通れない。ESP は NAT-T（UDP 4500）
クライアントレス VPN は専用ソフトが要るブラウザーだけでよい

まとめ

VPN の基本サイト間＝網と網（機器がトンネル）、リモートアクセス＝端末と網（クライアント）。スプリットトンネル・トポロジー
IPsec機密性・完全性・送信元の認証・リプレイ防止。IKE（UDP 500／4500）が鍵と SA、ESP（50）が暗号化、AH（51）は暗号化なし。SA は片方向
ルーターでの組み方クリプトマップ（ACL）・VTI（ルーティング）・GRE over IPsec（マルチキャスト）・DMVPN（mGRE＋NHRP＋IPsec）
リモートアクセスSSL/TLS（クライアント・クライアントレス）と IPsec IKEv2。二要素認証・ポスチャ

show crypto ipsec sa      ! IPsec の SA と数
