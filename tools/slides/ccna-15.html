第1章

FHRP の目的

何台かのルーターが1台の「仮想ルーター」を演じ、落ちたら別の1台が同じアドレスを引き継ぐ。

CCNA #15 FHRP3.5

困りごと：ゲートウェイのルーターが1台落ちると、PC は外へ出られない

  1. PC に書けるデフォルトゲートウェイは 1つのアドレス
  2. PC は、ゲートウェイが落ちても自分で別のルーターに切り替えない
  3. ルーターを2台置いても、PC が R1 のアドレスを書いていれば R1 と一緒に止まる
FHRP の答え：R1 と R2 で仮想 IP（例 10.1.10.1）と仮想 MACを共有し、PC のゲートウェイは仮想 IP にする。転送役が落ちたら、もう1台が同じ仮想 IP・仮想 MAC を引き継ぐ。
語FHRP＝First Hop Redundancy Protocol（最初のホップ＝ゲートウェイの冗長のプロトコル）
出典：IP Addressing Services Configuration Guide IOS XE 17.9（Catalyst 9300）「Configuring HSRP」（HSRP is useful for hosts that do not support a router discovery protocol and cannot switch to a new router when their selected router reloads or loses power）。図はClaudeが作った例

仮想ルーター：実アドレス n 組 ＋ 仮想 1 組

アドレスだれのもの使い道
10.1.10.2R1 の実アドレスR1 の管理・HSRP の Hello
10.1.10.3R2 の実アドレスR2 の管理・HSRP の Hello
10.1.10.1仮想（グループ）PC のゲートウェイ
  1. PC が 10.1.10.1 の ARP を出す → アクティブが仮想 MACで答える
  2. PC は仮想 MAC 宛てに送る → アクティブが転送
  3. アクティブが落ちる → スタンバイが同じ仮想 IP・仮想 MAC を引き継ぐ。PC は何も変えない
数n 台で組むと IP と MAC は n＋1 組（2台なら3組）
出典：IOS XE 17.9「HSRP Overview」（provides a virtual MAC address and an IP address that is shared among a group・For n routers running HSRP, there are n +1 IP and MAC addresses assigned）。アドレスはClaudeが作った例
第2章

HSRP

Cisco の FHRP。転送するアクティブ1台と、待つスタンバイ1台。優先度とプリエンプトで、どちらが転送するかを決める。

CCNA #15 FHRP3.5

HSRP の基本の値

項目値
役割アクティブ1台・スタンバイ1台・残りは Listen
優先度1〜255、初期値 100、大きいほうが勝ち
同点のときインタフェースの IP アドレスが大きいほう
プリエンプト初期値は無効
Hello／Hold3 秒／10 秒
バージョン初期値 v1（v2 と混ぜられない）
v1 の宛先224.0.0.2・UDP 1985
v2 の宛先224.0.0.102（IPv6 は v2 が必要）
v1 の仮想 MAC0000.0c07.acXX（XX＝グループ番号の16進数）
v1 のグループ番号0〜255（初期値 0）
設定の例（スイッチの SVI）
SW1(config)#interface vlan 10
SW1(config-if)#ip address 10.1.10.2 255.255.255.0
SW1(config-if)#standby 1 ip 10.1.10.1
SW1(config-if)#standby 1 priority 110
SW1(config-if)#standby 1 preempt
  • standby グループ ip 仮想IP で HSRP が動き出す
  • 設定できるのはレイヤ3 のインタフェース（SVI・ルーテッドポート・L3 の port-channel）
  • 仮想 MAC の計算：グループ 10 → 10 は16進数で 0a → 0000.0c07.ac0a
タイマーの取り違え：HSRP は 3／10、OSPF は 10／40、STP の Hello は 2。
出典：IOS XE 17.9「Configuring HSRP」（Default HSRP Configuration・HSRP Versions・HSRP Configuration Guidelines・Enabling HSRP）／ Network Services Configuration Guide IOS XE 17.x「HSRP Addressing」（224.0.0.2 … UDP port 1985・0000.0C07.ACxy … in hexadecimal）

計算手順：どちらがアクティブになるか

  1. 今アクティブがいるかを見る。いなければ（同時に起動）③へ
  2. いるなら、優先度が今のアクティブより大きく、かつ preempt が有効なルーターだけが交代させられる。それ以外は今のまま
  3. 選出：優先度が大きいほう → 同じならIP アドレスが大きいほう
  4. 2番目がスタンバイ。残りは Listen
同点・IP 大でも交代しない：優先度が同じで IP アドレスが大きいだけでは、preempt があってもアクティブを奪わない。
場面R1R2アクティブ
同時に起動100／.2100／.3R2（IP が大）
同時に起動110／.2100／.3R1（優先度）
R2 が先、R1 があとから110・preempt なし100R2 のまま
R2 が先、R1 があとから110・preempt あり100R1 に交代
R1 が先、R2 があとから100／.2100／.3・preemptR1 のまま
表「100／.2」＝優先度 100、アドレス 10.1.10.2
出典：IOS XE 17.x「HSRP Priority and Preemption」（Priority is determined first by the configured priority value, and then by the IP address … If you do not use the standby preempt … will not become the active router … A standby router with equal priority but a higher IP address will not preempt）。表はClaudeが作った練習

プリエンプトと track：WAN が切れたら交代させる

R1(config-if)#standby 1 priority 110
R1(config-if)#standby 1 track GigabitEthernet0/0 10
R2(config-if)#standby 1 priority 105
R2(config-if)#standby 1 preempt
  1. R1 の WAN 側 Gi0/0 が切れる。LAN 側は生きているので、HSRP だけなら R1 がアクティブのまま
  2. track が働き、R1 の優先度が 10 下がる（110→100）
  3. R2（105）のほうが大きくなり、R2 の preempt でアクティブを奪う
  4. Gi0/0 が戻ると R1 は 110 に戻る。R1 にも preempt があれば R1 に戻る
preempt を入れるのは「奪う側」：交代させたいルーター（ここでは R2）に入れる。track の初期の下げ幅は 10。
出典：IOS XE 17.9「Configuring HSRP Priority」（When a tracked interface fails, the hot standby priority … decreases by 10・If preemption is enabled, the router with the highest priority becomes the active router）。構成と値はClaudeが作った例

HSRP で両方のルーターを使う：グループを VLAN ごとに分ける

  • HSRP は1グループで1台しか転送しない。スタンバイの帯域は使われない
  • VLAN 10 はグループ 10、VLAN 20 はグループ 20 にし、アクティブを別のスイッチにする
  • PC のゲートウェイは VLAN ごとに違う仮想 IP
  • 両方に preempt を入れる。落ちて戻ったとき、元の分担に戻すため
STP と合わせる：VLAN 10 のルートブリッジも SW1 にそろえると、PC からの通り道がまっすぐになる（#09 のスパニングツリーと同じ考え方）。
出典：IOS XE 17.9「Multiple HSRP」（allows load sharing between two or more HSRP groups・you need to enter the standby preempt … so that … preemption restores load sharing）。STP と合わせる point はClaudeの補足
第3章

VRRP と GLBP

VRRP は HSRP とほぼ同じ考え方の標準。GLBP は1つのゲートウェイのアドレスのまま何台にも転送を分ける。

CCNA #15 FHRP3.5

VRRP：標準の FHRP。呼び名とプリエンプトの初期値が違う

項目HSRPVRRP
決めたところCisco 独自IETF 標準（RFC 5798）
転送する役アクティブマスター
待つ役スタンバイバックアップ
優先度の初期値100100
プリエンプト初期値 無効初期値 有効
宛先224.0.0.2（v1）224.0.0.18（IP プロトコル 112）
仮想 MAC0000.0c07.acXX0000.5e00.01XX（XX＝VRID）
仮想 IP実アドレスと別実アドレスと同じにもできる
アドレスの持ち主（優先度 255）
VRRP では、仮想 IP を自分の実アドレスとして持つルーターは優先度 255 で、必ずマスターになる
優先度 0
マスターが VRRP をやめるときに知らせる特別な値。バックアップはすぐ引き継げる

出典：RFC 5798 VRRP Version 3（Master・Backup／5.1.1.2 224.0.0.18／5.1.1.4 protocol number 112／5.2.4 Priority：255 for the owner・0 special meaning・default 100／6.1 Preempt_Mode Default is True／7.3 00-00-5E-00-01-{VRID}）

GLBP：1つのゲートウェイのまま、何台にも転送を分ける

AVG（Active Virtual Gateway）
グループに1台のまとめ役。メンバーに仮想 MAC を割り当て、仮想 IP の ARP に答える。PC ごとに違う仮想 MAC を返して負荷を分ける
AVF（Active Virtual Forwarder）
割り当てられた仮想 MAC 宛てのパケットを転送する役。1グループに最大4台。AVG も AVF を兼ねる
1台落ちたら
残りの AVF が落ちた AVF の仮想 MAC も引き受ける。AVG が落ちたら別のメンバーが AVG になる
値Hello 3 秒・224.0.0.102・UDP 3222／仮想 MAC 0007.b400.XXYY
出典：Network Services Configuration Guide IOS XE 17.x「Configuring GLBP」（GLBP Overview：single virtual IP address and multiple virtual MAC addresses・224.0.0.102, UDP port 3222／GLBP Active Virtual Gateway：Router A … 0007.b400.0101、Router B … 0007.b400.0102／up to four virtual MAC addresses per group）

よくあるひっかけ

よくある思い込み正しくは
PC のゲートウェイはアクティブの実アドレス仮想 IPを書く
優先度を上げれば HSRP はすぐ交代するHSRP は preempt が初期値で無効。入れないと交代しない
優先度が同じで IP が大きければ preempt で奪える奪えない。preempt は優先度が大きいときだけ
HSRP の Hello は 10 秒3 秒（Hold 10 秒）。10／40 は OSPF
グループ 10 の MAC は 0000.0c07.ac1016進数にする：0000.0c07.ac0a
HSRP は1グループで2台とも転送するアクティブ1台だけ。両方使うならグループを分ける
VRRP の役はアクティブとスタンバイマスターとバックアップ
FHRP は3つとも Cisco 独自VRRP は標準
GLBP の AVG が全部を転送するAVG は ARP に答えて MAC を割り振る。転送は AVF（最大4台）

まとめ

目的PC のゲートウェイ（1つ・自分で切り替えない）を、仮想 IP と仮想 MAC の共有で冗長にする
HSRP（Cisco）アクティブ／スタンバイ・優先度 100・preempt 無効・Hello 3／Hold 10・0000.0c07.acXX
VRRP（標準）マスター／バックアップ・preempt 有効・224.0.0.18・0000.5e00.01XX
GLBP（Cisco）AVG が ARP で MAC を割り振り、AVF 最大4台で負荷分散
