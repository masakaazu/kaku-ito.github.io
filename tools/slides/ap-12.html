12-1 システム要件定義・ソフトウェア要件定義要件

機能要件・非機能要件Functional / Non-functional Requirements
機能要件は何ができるか、非機能要件は性能・信頼性・セキュリティなどどれだけうまくできるか
非機能要求グレードNon-functional Requirements Grade
非機能要件を、可用性・性能・運用・移行・セキュリティなどの項目で段階的に決めるための表（IPA）
ユースケースUse Case
利用者（アクタ）とシステムのやり取りを、目的ごとに書いたもの
CRUD分析CRUD Analysis
処理ごとにデータを Create・Read・Update・Delete のどれで使うかを表にして整理する方法

12-2 設計設計の手法

DFDでぃーえふでぃー / Data Flow Diagram
データの流れを、プロセス・データストア・外部実体・データフローで表す図
ポイント処理の順番や条件は表さない
Data＝データ／Flow＝流れ／Diagram＝図
UMLの主な図UML Diagrams
クラス図（構造）、シーケンス図（時間順のやり取り）、コミュニケーション図（オブジェクトのつながり）、アクティビティ図（処理の流れ）、状態マシン図（状態の変化）
汎化・集約Generalization / Aggregation
汎化は「is-a」の関係（上位クラスと下位クラス）、集約は「part-of」の関係（全体と部分）
多態性ポリモーフィズム / Polymorphism
同じメッセージでも、受け取るオブジェクトによって違う動きをすること
デザインパターンDesign Pattern
オブジェクト指向設計でよく使う設計の型
例Singleton、Observer、Factory Method
モジュール強度Module Strength
モジュールの中の機能のまとまりの強さ
ポイント機能的強度が最も強くよい

12-2 設計設計の手法

モジュール結合度Module Coupling
モジュールどうしのつながりの強さ
ポイントデータ結合が最も弱くよい
決定表デシジョンテーブル / Decision Table
条件の組合せと、それに対する動作を表で表したもの
レビュー手法Review
ウォークスルー（作成者が説明）、インスペクション（モデレータが進行し役割を決める）、ラウンドロビン（参加者が順に進行）

12-4 統合・テストまとめ表

網羅の基準
基準満たす条件
命令網羅すべての命令を1回は実行する
判定条件網羅（分岐網羅）すべての分岐で真と偽を通る
条件網羅判定の中の各条件が真と偽をとる
複数条件網羅条件の組合せをすべて試す（最も強い）

12-4 統合・テストテスト

ブラックボックステストBlack Box Test
内部を見ず、仕様どおりに入出力が合うかを調べる
ポイント同値分割・限界値分析・原因結果グラフ
ホワイトボックステストWhite Box Test
内部の構造を見て、命令や分岐を通るか調べる
ポイント命令網羅・判定条件網羅・条件網羅・複数条件網羅
限界値分析Boundary Value Analysis
有効な範囲の境目と、そのすぐ外の値をテストする方法
スタブ・ドライバStub / Driver
スタブは下位モジュールの代わり（トップダウンテスト）、ドライバは上位モジュールの代わり（ボトムアップテスト）
回帰テストRegression Test
修正によってほかの部分に不具合が出ていないかを確かめるテスト
信頼度成長曲線ゴンペルツ曲線 / Reliability Growth Curve
テストの時間と発見したバグの累計の関係を表すS字の曲線
ポイント増え方が止まれば品質が安定してきたとみなす
応用情報 システム開発技術9

エラー埋込み法Error Seeding
わざと既知のエラーを埋め込み、その見つかった割合から残っているバグの数を推定する方法

12-5 導入・受入れ支援導入

受入れテストAcceptance Test
発注者が、要件を満たしているかを確かめて受け入れるテスト
移行方式Migration
一斉移行（一度に切り替え）、段階移行（少しずつ）、並行運用（新旧を同時に動かす）、パイロット移行（一部の部門で先に試す）
利用者マニュアル・教育User Manual / Training

12-6 保守・廃棄保守

保守の種類Types of Maintenance
是正保守（不具合を直す）、予防保守（問題が起きる前に直す）、適応保守（環境の変化に合わせる）、完全化保守（性能や保守性を上げる）
リバースエンジニアリングReverse Engineering
既存のプログラムから仕様や設計を明らかにすること
リファクタリングRefactoring
外から見た動作は変えずに、中の構造を整理すること
システムの廃棄Disposal
使わなくなったシステムを止め、データを確実に消去して処分すること
