キャストからパターンへ

前の書き方（Claude が作成）
if (o instanceof String) {
  String s = (String) o;      // 自分でキャスト
  System.out.println(s.length());
}
パターン・マッチング
if (o instanceof String s) {   // 型パターン
  System.out.println(s.length());
}
コード（o は Object 型）結果（JDK 17）
o が "hello"：o instanceof String strue、s は "hello"
o が 42：o instanceof Integer n && n > 40true
o が 42：o instanceof Number ntrue（Integer は Number の一種）
o が null：o instanceof String sfalse（例外なし）
o が null：o instanceof Objectfalse
パターン変数はふつうのローカル変数。Java 17 では final ではないので代入できる（s = s + "!"）。final を付けると代入できない。
出典：JLS 15.20.2 The instanceof Operator（If the value of the RelationalExpression is the null reference, then the result is false／A side effect of a true result is that pattern variables declared in Pattern will be initialized）／JLS 14.30.1／結果は JDK 17 で確かめたもの

書けるパターン・書けないパターン

式結果（JDK 17）
o instanceof Integer i（o は Object）OK
o instanceof final String tOK（t は代入不可）
o instanceof int iunexpected type
o instanceof var v'var' is not allowed here
str instanceof String s（str は String）expression type String is a subtype of pattern type String
str instanceof String（パターンなし）OK（true）
i instanceof String s（i は Integer）incompatible types: Integer cannot be converted to String
いつも true はエラー：左の型がパターンの型と同じか、その部分型なら、調べる意味がないのでコンパイルエラー。パターンのない型の比較ならエラーにならない。
ありえない組み合わせもエラー：キャストできない型どうし（Integer と String）は、型の比較でもパターンでもコンパイルエラー。
パターンの型は参照型だけ。var・基本型・初期化子（= 値）は書けない。
出典：JLS 15.20.2（If the type of the RelationalExpression is a subtype of the type of the Pattern, then a compile-time error occurs／The RelationalExpression must be compatible with the Pattern）／JLS 14.30.1（The LocalVariableType denotes a reference type (and furthermore is not var)／The VariableDeclarator has no initializer）／結果は JDK 17 で確かめたもの

3 種類のコンストラクタ

① 正規コンストラクタ（ふつうの形）
record P(int x, int y) {
  P(int x, int y) { this.x = x; this.y = y * 2; }
}   // new P(1, 2) → P[x=1, y=4]
② コンパクト・コンストラクタ（かっこなし）
record Name(String s) {
  Name { s = s.trim(); }       // s は引数
}   // new Name("  ann ").s() → "ann"
③ 正規でないコンストラクタ（this(…) が必須）
record P(int x, int y) {
  P(int x) { this(x, 0); }
}   // new P(7) → P[x=7, y=0]
書き方結果（JDK 17）
コンパクトで this.s = s.trim();cannot assign a value to final variable s
コンパクトで return;invalid compact constructor
コンパクトと P(int x) を両方constructor P(int) is already defined
P(int x) { }（this(…) なし）constructor is not canonical, so its first statement must invoke another constructor
コンパクトで x = x + 1;（new P(1)）x() は 2
コンパクトで v < 0 なら thrownew Age(-1) で例外
コンパクト・コンストラクタの中の名前は引数。本体が終わると、引数の値でフィールドが自動で初期化される。
出典：JLS 8.10.4（The body of every non-canonical constructor in a record declaration must start with an alternate constructor invocation）・8.10.4.2（The body must not contain a return statement／must not contain an assignment to a component field／the simple name c … denotes the implicit formal parameter）／結果は JDK 17 で確かめたもの

問われ方とまちがえやすい点

こう聞かれたら答えの考え方
instanceof の結果null は false。部分型なら true。パターンが付くと、いつも true の組み合わせはコンパイルエラー
パターン変数を使えるか確実にマッチした場所だけ。else・|| の右・if のあと（return なし）は NG
