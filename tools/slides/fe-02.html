2-1 データ構造基本のデータ構造

配列はいれつ / Array
同じ型のデータを連続した領域に並べ、番号（添字）で取り出す構造
ポイント添字で直接読めるが、途中への挿入・削除は後ろをずらす必要がある
リスト連結リスト / Linked List
各データが次のデータの場所（ポインタ）を持ち、数珠つなぎにした構造
ポイント挿入・削除はポインタの付け替えだけで済む。双方向リストは前後両方のポインタを持つ
スタックStack
後に入れたデータを先に取り出す（LIFO）構造。入れるのがpush、出すのがpop
ポイント関数呼出しの戻り先の管理やUndoに使う
LIFO＝Last In First Out（後入れ先出し）
キュー待ち行列 / Queue
先に入れたデータを先に取り出す（FIFO）構造
ポイント入れるのがエンキュー、出すのがデキュー
FIFO＝First In First Out（先入れ先出し）
木構造きこうぞう / Tree
根から枝分かれして節（ノード）をつなぐ階層構造
ポイント一番上が根、子を持たない節が葉

2-1 データ構造基本のデータ構造

二分木にぶんぎ / Binary Tree
各節の子が2つ以下の木
ポイント完全二分木は、根から葉までの深さがそろった（最下段以外がすべて埋まった）二分木
二分探索木にぶんたんさくぎ / Binary Search Tree
「左の子 ＜ 親 ＜ 右の子」が常に成り立つ二分木
ポイント中間順になぞると小さい順に並ぶ
ヒープHeap
親が子より常に大きい（または小さい）完全二分木
ポイント最大値（最小値）がいつも根にある。ヒープソートで使う
ハッシュ表はっしゅひょう / Hash Table
ハッシュ関数でキーから格納場所を計算して置く表
ポイント違うキーが同じ場所になることを衝突（シノニム）という
例17 mod 5 ＝ 2 の位置に格納

2-2 アルゴリズム探索・整列（ソート）

線形探索法せんけいたんさくほう / Linear Search
先頭から1つずつ順に比べて探す方法
ポイントデータが整列していなくても使える。番兵を置くと終了判定を減らせる
二分探索法にぶんたんさくほう / Binary Search
整列済みのデータで、中央の値と比べて探す範囲を半分ずつに絞る方法
ポイントn個なら最大で約 log₂n 回の比較で済む
ハッシュ探索法はっしゅたんさくほう / Hash Search
ハッシュ関数で格納場所を計算して、一度で取り出す方法
ポイント衝突がなければ探索回数はデータ量に関係なく一定
バブルソート交換法 / Bubble Sort
隣り合う要素を比べて、順序が逆なら交換することを繰り返す整列法
ポイント計算量は O(n²)
選択ソート基本選択法 / Selection Sort
未整列の部分から最小値を選び、未整列部分の先頭と交換する整列法
ポイント計算量は O(n²)
挿入ソート基本挿入法 / Insertion Sort
整列済みの部分の正しい位置に、次の要素を差し込んでいく整列法
ポイントほぼ整列済みのデータには速い
基本情報 アルゴリズムとプログラミング7

2-2 アルゴリズム整列（ソート）・アルゴリズムの評価

クイックソートQuick Sort
基準値（ピボット）より小さいグループと大きいグループに分けることを繰り返す整列法
ポイント平均の計算量は O(n log n)。最悪は O(n²)
ヒープソートHeap Sort
ヒープを作って最大値（最小値）を取り出すことを繰り返す整列法
ポイント計算量は O(n log n)
マージソートMerge Sort
データを半分ずつに分けて、整列しながら併合（マージ）していく整列法
ポイント計算量は O(n log n)
シェルソートShell Sort
一定の間隔ごとの要素で挿入ソートをし、間隔を狭めていく整列法
ポイント挿入ソートの改良版
オーダ記法おーだきほう / Big O Notation
データ量 n が増えたとき、処理量がどのくらい増えるかを表す書き方
ポイント増え方は O(1) ＜ O(log n) ＜ O(n) ＜ O(n log n) ＜ O(n²) の順に大きい
ダイクストラ法Dijkstra's Algorithm
グラフの最短経路を求める代表的なアルゴリズム
ポイント出発点から近い点を順に確定していく
基本情報 アルゴリズムとプログラミング8

2-3 プログラミングプログラムの性質

再帰リカーシブ / Recursive
プログラムが自分自身を呼び出して処理を進める性質
例階乗 n! ＝ n × (n−1)! 。呼び出しのたびにスタックを使う
再入可能リエントラント / Reentrant
実行中に別のタスクから呼び出されても、正しく動く性質
ポイント共有する変数を書き換えず、データをタスクごとに分ける
再使用可能リユーザブル / Reusable
一度実行した後、読み込み直さずにもう一度使える性質
ポイント実行のたびに初期化される
再配置可能リロケータブル / Relocatable
主記憶のどこに置いても実行できる性質
構造化プログラミングStructured Programming
順次・選択・繰返しの3つの基本構造だけで処理を組み立てる考え方
ポイントgoto文をなるべく使わず、読みやすくする
変数のスコープScope
変数を使える範囲
ポイント関数の中だけで使えるのがローカル変数、どこからでも使えるのがグローバル変数

2-5 その他の言語マークアップ言語とデータ形式

HTMLえいちてぃーえむえる / HyperText Markup Language
Webページの構造をタグで書くマークアップ言語
ポイント決められたタグを使う。見た目はCSSで指定する
HyperText＝リンクでつながる文書／Markup＝目印（タグ）を付ける／Language＝言語
XMLえっくすえむえる / Extensible Markup Language
用途に合わせて独自のタグを定義できるマークアップ言語
ポイントデータの記述や交換に向く
Extensible＝拡張できる／Markup Language＝タグを付ける言語
CSSしーえすえす / Cascading Style Sheets
Webページの色・大きさ・配置などの見た目を指定する言語
ポイントHTMLは構造、CSSは見た目
Cascading＝段階的に引き継がれる／Style Sheets＝見た目の指定書
JSONじぇいそん / JavaScript Object Notation
名前と値の組を { } で書く、軽いデータの書式
ポイントWeb APIのデータ交換でよく使う
JavaScript＝言語の名前／Object＝まとまり／Notation＝書き方
