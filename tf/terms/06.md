## 06-1 resource ブロック

### まとめ表

| | resource（管理するリソース） | data（データソース） |
| :-: | :-: | :-: |
| すること | 作る・変える・消す | 読むだけ（作らない・変えない） |
| 書き方 | resource "aws_instance" "web" { } | data "aws_ami" "web" { } |
| 参照 | aws_instance.web.id | data.aws_ami.web.id |
| ステート | 実物との対応づけを記録 | 読んだ結果を記録（読みなおす） |
| destroy で | 実物が消える | 何も消えない |

### resource

#### resource ブロック（りそーすぶろっく / resource block）

- 意味：Terraform で作って管理したいインフラのオブジェクト（仮想ネットワーク・インスタンス・DNS レコードなど）を宣言するブロック
- ポイント：ラベルは 2 つ。リソースの型（aws_instance）とローカル名（web）。型と名前の組がステートのアドレス（aws_instance.web）になり、モジュールの中で一意。作れるリソースの種類は、入れたプロバイダーで決まる
- 例：`resource "aws_instance" "web" { ami = "ami-a1b2c3d4"  instance_type = "t2.micro" }`

#### リソースの型（りそーすのかた / resource type）

- 意味：resource ブロックの 1 つ目のラベル。何の種類のオブジェクトを管理するか、どの引数が使えるかを決める
- ポイント：ほとんどはプロバイダーが実装する。型名はふつうプロバイダーの好ましいローカル名で始まり（aws_instance の aws）、それでプロバイダーが選ばれる。引数の説明はプロバイダーのドキュメント（Registry）にある

#### 引数と属性（ひきすうとぞくせい / arguments and attributes）

- 意味：引数は設定で値を入れるもの（ami など）。属性は参照で読める値で、設定した引数と、プロバイダーが作ったあとに返す値（exported attributes：id・arn など）の両方
- ポイント：引数も aws_instance.example.ami のように参照できる。id のように作ってはじめて決まる属性は、計画では (known after apply)

#### メタ引数（めたひきすう / meta-arguments）

- 意味：どのリソースの型にも使える、Terraform に組みこまれた引数。リソースのふるまいではなく、Terraform がどう作って管理するかを決める
- ポイント：count・for_each・provider・depends_on・lifecycle（create_before_destroy・prevent_destroy・ignore_changes・replace_triggered_by・precondition・postcondition）など。timeouts はメタ引数ではなく、対応するリソースの型だけにある子ブロック

#### apply でのリソースの扱い（あぷらいでのあつかい / what apply does to resources）

- 意味：apply は、ないものを作り、設定から消えたものを消し、変わった引数をその場で更新し、その場で更新できないものは消して作り直し、ステートを更新する
- ポイント：その場で更新できない（API の制限で作り直しが必要な）引数の変更は -/+ になる

#### ローカルだけのリソース（ろーかるだけのりそーす / local-only resources）

- 意味：Terraform の中で値を計算してステートに保存するだけで、クラウドに実物がないリソース
- ポイント：random_id・tls_private_key・tls_self_signed_cert など。消すとステートから値が消えるだけ。terraform_data は、ふつうのリソースのライフサイクルだけを持つ組みこみの型

## 06-2 data ブロック

### まとめ表

| 場面 | いつ読むか |
| :-: | :-: |
| 引数が計画の時点で分かる値だけ | plan の前の refresh のときに読む |
| 引数が、この計画で変わるリソースや適用で決まる値を参照 | apply まで読むのを延ばす（計画に表示） |
| count・for_each 付き | インスタンスごとに読み、data.x.y[0]・data.x.y["key"] で参照 |

### data

#### データソース（でーたそーす / data source）

- 意味：プロバイダーなどから情報を取ってきて、設定の中で使えるようにするもの。リソースを作ったり変えたりはしない
- ポイント：『Data sources fetch data from the provider, but do not create or modify resources.』。ほかの設定で作ったもの・Terraform の外で作ったもの・関数の結果などを読む。Terraform はデータソースに対して読む操作しかできない

#### data ブロック（でーたぶろっく / data block）

- 意味：データソースを宣言するブロック。データソースの型とラベル（名前）を書き、本体に絞りこみの条件（引数）を書く
- ポイント：結果は data.<TYPE>.<NAME>.<ATTRIBUTE> で参照する（data. を付ける）。型と名前の組は一意。式やメタ引数（count・for_each・provider・depends_on・lifecycle の precondition/postcondition）も使える
- 例：`data "aws_ami" "web" { most_recent = true  owners = ["self"] }` → `ami = data.aws_ami.web.id`

#### データソースを読むタイミング（よむたいみんぐ / data source read timing）

- 意味：Terraform はふつう plan のときにデータソースを読むが、引数が計画で分からない値に依存すると、apply まで読むのを延ばす
- ポイント：延ばすのは、この計画で変わるリソースに直接依存するとき・そうしたリソースに依存するカスタム条件があるとき・適用で決まる値を参照するとき。そのとき、データソースの属性は計画で computed（known after apply）になり、それを使うリソースも apply まで決まらない

#### 特別なデータソース（とくべつなでーたそーす / specialized data sources）

- 意味：Terraform の操作のあいだだけ存在するデータを作る、手元で動くデータソース。plan のたびに計算しなおす
- ポイント：local_file（手元のファイルを読む）・aws_iam_policy_document（IAM ポリシーの JSON を作る）・template_file など

#### terraform_remote_state（てらふぉーむりもーとすてーと / terraform_remote_state data source）

- 意味：ほかの設定のステートから、ルートモジュールの出力値を読み取り専用で取ってくる組みこみのデータソース
- ポイント：ネットワークのチームが VPC ID を出力し、アプリのチームが読む、のように設定を分けるときに使う。出力値しか読めない

## 06-3 参照とアドレス

### まとめ表

| 参照 | 値 |
| :-: | :-: |
| aws_instance.web.id | count・for_each なし：1 つのオブジェクトの属性 |
| aws_instance.web[0].id | count：リストの 1 つ目のインスタンス |
| aws_instance.web[*].id | count：全インスタンスの id のリスト（スプラット） |
| aws_instance.web["a"].id | for_each：キー "a" のインスタンス |
| [for v in aws_instance.web : v.id] | for_each：全インスタンスの id のリスト |
| data.aws_ami.web.id | データソースの属性 |
| var.x・local.x・module.m.out | 変数・ローカル値・子モジュールの出力 |
| path.module・path.root・terraform.workspace | ファイルシステムとワークスペースの情報 |

### 参照

#### 名前つきの値（なまえつきのあたい / named values）

- 意味：式の中で参照できる名前。リソース・入力変数（var.）・ローカル値（local.）・子モジュールの出力（module.）・データソース（data.）・ファイルシステムとワークスペースの情報・ブロックの中だけの値（count.index・each.key・self など）
- ポイント：どの決まった形にも合わない名前は、管理するリソースへの参照とみなされる。本物のオブジェクトではないので、aws_instance だけを for でくり返すことはできない

#### リソースの属性の参照（ぞくせいのさんしょう / references to resource attributes）

- 意味：<RESOURCE TYPE>.<NAME>.<ATTRIBUTE> の形で、ほかのリソースの引数や属性を読むこと
- ポイント：count があるとリソースはオブジェクトのリスト、for_each があるとマップになる。count なら [0] やスプラット [*]、for_each ならキー ["a"] や for 式で読む

#### 暗黙の依存関係（あんもくのいぞんかんけい / implicit dependency）

- 意味：resource の引数がほかのリソースを参照していると、Terraform がそれを見て自動で決める依存関係
- ポイント：参照される側を先に作る。ローカル値を通した間接の参照でも検出される。参照だけでは分からない依存は depends_on で明示する（#09）

#### スプラット式（すぷらっとしき / splat expression）

- 意味：[*] で、リストの全要素から同じ属性を取りだして、リストにする短い書き方
- ポイント：var.list[*].id は [for o in var.list : o.id] と同じ。リスト・セット・タプルにだけ使える。for_each のリソース（マップ）には直接使えないので、for 式か values(aws_instance.example)[*].id

#### リソースアドレス（りそーすあどれす / resource address）

- 意味：設定の中のリソースインスタンスを指す文字列。[モジュールのパス][リソースの指定] の形
- ポイント：module.foo[0].module.bar["a"].aws_instance.web[3] のように書く。モジュールのパスを省くとルートモジュール。count は 0 から数える番号 [N]、for_each は文字列のキー ["KEY"]。番号を省くと全インスタンス。state list・-target・import などで使う

#### path.module と terraform.workspace（ぱすもじゅーる / filesystem and workspace info）

- 意味：path.module は式があるモジュールのパス、path.root はルートモジュールのパス、path.cwd は元の作業ディレクトリ、terraform.workspace は今のワークスペースの名前
- ポイント：path.module 以外は、ルートモジュールだけで使うのがすすめられる。共有するモジュールで名前の前置きが要るなら、入力変数にして呼ぶ側が決める

#### sensitive な属性（せんしてぃぶなぞくせい / sensitive resource attributes）

- 意味：プロバイダーが機密として印を付けた属性。計画では (sensitive value) と表示され、そこから作った値も sensitive になる
- ポイント：出力値に使うと、出力にも sensitive = true を付けるよう求められる。ステートには平文で残る

### 06-2 data ブロック

#### 問 tf-06-o10

- 問：`data "aws_ami" "ubuntu" { ... }` の id を、aws_instance の ami に使う書き方として正しいものはどれか。
- ア：ami = aws_ami.ubuntu.id
- イ：ami = data.ubuntu.id
- ウ：ami = "data.aws_ami.ubuntu.id"
