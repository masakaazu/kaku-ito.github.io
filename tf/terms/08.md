## 08-1 式

### まとめ表

| 式 | 書き方 | 結果 |
| :-: | :-: | :-: |
| 条件式 | cond ? a : b | a か b（同じ型にそろえる） |
| for 式（リスト） | [for s in var.list : upper(s)] | タプル |
| for 式（マップ） | {for s in var.list : s => upper(s)} | オブジェクト |
| for 式の絞りこみ | [for s in var.list : s if s != ""] | 条件に合う要素だけ |
| スプラット式 | var.list[*].id | 全要素の id のリスト |
| 文字列の埋めこみ | "Hello, ${var.name}!" | 値を文字列にして埋めこむ |
| ディレクティブ | %{ if … }…%{ endif }・%{ for … }…%{ endfor } | 条件・くり返しの文字列 |
| dynamic ブロック | dynamic "setting" { for_each = …  content { … } } | 入れ子のブロックをくり返し作る |

### 式

#### 条件式（じょうけんしき / conditional expression）

- 意味：真偽値の式で、2 つの値のどちらかを選ぶ式。condition ? true_val : false_val
- ポイント：2 つの値は同じ型でなければならず、ちがえば共通に変換できる型にそろえる（var.example ? 12 : "hello" はいつも文字列）。あいまいなときは tostring などで明示する。よくある使い方は、不正な値を既定値に置きかえること
- 例：`var.a == "" ? "default-a" : var.a`

#### for 式（ふぉーしき / for expression）

- 意味：あるコレクションの各要素を変換して、新しい複合型の値を作る式
- ポイント：入力はリスト・セット・タプル・マップ・オブジェクト。[ ] でかこむとタプル、{ } でかこむとオブジェクト（キー => 値の 2 つの式が必要）。2 つの一時変数を書くと、マップならキーと値、リストなら 0 からの番号と値。if で要素を絞りこめる。マップやセットから作ると、キーや値の辞書順に並ぶ

#### グループ化モード（ぐるーぷかもーど / grouping mode）

- 意味：{ } の for 式で、値の式の後ろに ... を付けると、同じキーの値をリストにまとめるモード
- ポイント：ふつう { } の for 式ではキーが重ならなければならず、重なるとエラー。... を付けるとキーごとに値のリストになる
- 例：`{for name, user in var.users : user.role => name...}` → `{ admin = ["ps"], viewer = ["st", "zq"] }`

#### 文字列テンプレート（もじれつてんぷれーと / string templates）

- 意味：引用符の文字列やヒアドキュメントの中で、${ … } で値を埋めこみ（interpolation）、%{ … } で条件やくり返しを書く（directive）しくみ
- ポイント：${ を文字どおり書くには $${、%{ は %%{。~ を付けると前後の空白や改行を取りのぞく。ヒアドキュメントは <<EOT … EOT、<<-EOT ならインデントを取りのぞく。JSON や YAML はヒアドキュメントで作らず jsonencode・yamlencode を使う

#### dynamic ブロック（だいなみっくぶろっく / dynamic block）

- 意味：resource・data・provider・provisioner の中で、くり返す入れ子のブロック（setting・ingress など）を、コレクションから作るためのブロック
- ポイント：ラベルが作るブロックの種類、for_each がくり返す値、content がブロックの中身。一時変数の名前は既定でラベルと同じ（iterator で変えられる）で、.key と .value を持つ。lifecycle や provisioner などのメタ引数のブロックは作れない。使いすぎると読みにくいので、書けるところはそのまま書く

## 08-2 関数のしくみ

### まとめ表

| 決まり | 内容 |
| :-: | :-: |
| 呼び方 | 関数名(引数1, 引数2) |
| 自作の関数 | 設定の言語では作れない（プロバイダーで定義した関数は provider::<ローカル名>::<関数名> で呼ぶ） |
| リストの展開 | min([55, 2453, 2]...) |
| sensitive な引数 | 結果も sensitive になる |
| 外の状態を使う関数 | file・templatefile（最初の検証で読む）、timestamp・uuid（計画では unknown、apply で決まる） |
| 試す場所 | terraform console |

### しくみ

#### 組みこみ関数（くみこみかんすう / built-in functions）

- 意味：式の中で呼んで、値を変換したり組み合わせたりできる、Terraform に組みこまれた関数
- ポイント：『You cannot define your own functions in the Terraform configuration language』。自分の関数がほしければ、関数を提供するプロバイダーを作り、provider::<local-name>::<関数名>(…) で呼ぶ。ほとんどは結果が引数だけで決まる純粋な関数

#### 引数の展開（ひきすうのてんかい / expanding function arguments）

- 意味：リストやタプルの値の後ろに ...（ピリオド 3 つ）を付けて、別々の引数として関数に渡すこと
- ポイント：関数呼び出しの中でだけ使える。Unicode の三点リーダ（…）ではない
- 例：`min([55, 2453, 2]...)` → 2

#### terraform console（てらふぉーむこんそーる / terraform console）

- 意味：式を対話的に評価して、関数や式の動きを試せるコマンド
- ポイント：ドキュメントの関数の例は console の出力で書かれている。今のステートの値も参照できる

#### 外の状態を使う関数（そとのじょうたいをつかうかんすう / impure functions）

- 意味：file・templatefile・timestamp・uuid のように、引数以外のもの（ファイル・時刻・乱数）で結果が変わる関数
- ポイント：file と templatefile は、設定の最初の検証のときにファイルを読むので、plan・apply の途中で作られるファイルは読めない。timestamp と uuid は計画では値が分からず（unknown）、apply のときに決まる（timestamp は適用を始めた時刻）

## 08-3 よく使う関数

### まとめ表

| 関数 | 例 | 結果 |
| :-: | :-: | :-: |
| lookup | lookup({a="ay", b="bee"}, "c", "what?") | "what?" |
| merge | merge({a="b", c="d"}, {e="f", c="z"}) | {a="b", c="z", e="f"} |
| join | join("-", ["foo", "bar", "baz"]) | "foo-bar-baz" |
| split | split(",", "foo,bar,baz") | ["foo", "bar", "baz"] |
| element | element(["a", "b", "c"], 3) | "a"（くり返して数える） |
| length | length("hello") | 5 |
| contains | contains(["a", "b", "c"], "d") | false |
| coalesce | coalesce("", "b") | "b" |
| flatten | flatten([["a", "b"], [], ["c"]]) | ["a", "b", "c"] |
| zipmap | zipmap(["a", "b"], [1, 2]) | {a = 1, b = 2} |
| cidrsubnet | cidrsubnet("10.1.2.0/24", 4, 15) | "10.1.2.240/28" |
| format | format("There are %d lights", 4) | "There are 4 lights" |

### 関数

#### lookup（るっくあっぷ / lookup）

- 意味：マップからキーで 1 つの値を取りだす関数。キーがなければ、渡した既定値を返す
- ポイント：lookup(map, key, default)。var.m["key"] はキーがないとエラーになるが、lookup なら既定値にできる

#### merge（まーじ / merge）

- 意味：いくつかのマップやオブジェクトを 1 つにまとめる関数
- ポイント：同じキーがあると、後ろの引数の値が勝つ。共通のタグと個別のタグをまとめるときによく使う

#### join と split（じょいんとすぷりっと / join and split）

- 意味：join は文字列のリストを区切り文字でつないで 1 つの文字列に、split は文字列を区切り文字で分けてリストにする
- ポイント：引数の順番はどちらも（区切り文字, 対象）。join(separator, list)・split(separator, string)

#### element（えれめんと / element）

- 意味：リストから番号で 1 つの要素を取りだす関数
- ポイント：番号がリストの長さ以上だと、最初にもどって数える（element(["a","b","c"], 3) は "a"）。-1 は最後の要素。ふつうの list[3] は範囲外でエラー

#### length と contains（れんぐすとこんていんず / length and contains）

- 意味：length はリスト・マップの要素の数や文字列の長さ、contains はリスト・セットにその値があるかを返す
- ポイント：空でないことの確認は length(var.items) != 0。値の一覧に入っているかは contains(["dev","prod"], var.env)（validation でよく使う）

#### coalesce（こあれっす / coalesce）

- 意味：引数のうち、null でも空文字列でもない最初の値を返す関数
- ポイント：既定値を決めるのに使う。リストなら ... で展開して渡す（coalesce(["", "b"]...) → "b"）

#### try と can（とらいとかん / try and can）

- 意味：try は引数の式を順に評価して、エラーにならない最初の結果を返す。can は式がエラーなく評価できれば true、エラーなら false を返す
- ポイント：try はあるかどうか分からない属性を読むとき（try(local.raw.groups, [])）、can は validation の条件に使う（can(regex("^[a-z]+$", var.name))）

#### flatten（ふらってん / flatten）

- 意味：リストの中のリストを、平らな 1 つのリストにする関数
- ポイント：入れ子のデータ（ネットワークごとのサブネットなど）を、for_each に渡す 1 つのリストにするときに使う

#### zipmap（じっぷまっぷ / zipmap）

- 意味：キーのリストと値のリストから、マップを作る関数
- 例：`zipmap(["a", "b"], [1, 2])` → `{ a = 1, b = 2 }`

#### toset（とぅせっと / toset）

- 意味：値をセットに変換する関数
- ポイント：重複が消え、順番がなくなる。for_each にリストを渡すときに toset(var.names) とするのが定番。ふつう型は自動で変換されるので、明示の変換が必要な場面は多くない

#### file と templatefile（ふぁいるとてんぷれーとふぁいる / file and templatefile）

- 意味：file はファイルの中身を文字列として読む。templatefile はファイルを読み、渡した変数でテンプレートとして描画する
- ポイント：パスはふつう "${path.module}/…"。テンプレートファイルの拡張子は .tftpl がすすめられる。templatefile(path, vars) の vars はマップ

#### cidrsubnet（しーあいでぃーあーるさぶねっと / cidrsubnet）

- 意味：ネットワークのアドレス範囲の中から、サブネットのアドレスを計算する関数。cidrsubnet(prefix, newbits, netnum)
- ポイント：newbits はプレフィックス長に足すビット数、netnum は何番目のサブネットか
- 例：`cidrsubnet("172.16.0.0/12", 4, 2)` → "172.18.0.0/16"
- 語の意味：CIDR＝Classless Inter-Domain Routing

#### format（ふぉーまっと / format）

- 意味：C の printf のような書式の文字列で、値を整えて文字列を作る関数
- ポイント：%s は文字列、%d は整数。単純な埋めこみなら "Hello, ${var.name}!" のほうが読みやすいことが多い

- 書式：「#### 問 問題ID」の下に、問・ア〜エ・正解・解説・選択肢ごとの意味・出典を書く。「###」は小分類（クイズの範囲に使う）

### 08-1 式

#### 問 tf-08-o01

- 問：var.instance_type が空文字列なら "t3.micro"、そうでなければ var.instance_type を使いたい。正しい式はどれか。
- ア：var.instance_type == "" ? "t3.micro" : var.instance_type
- イ：var.instance_type ? "t3.micro" : var.instance_type
- ウ：if var.instance_type == "" then "t3.micro" else var.instance_type
- エ：var.instance_type == "" : "t3.micro" ? var.instance_type
- 正解：ア
- 解説：条件式は condition ? true_val : false_val。不正な値を既定値に置きかえるのはよくある使い方。
- アの意味：正しい。
- イの意味：条件は真偽値でなければならない（文字列は条件にならない）。
- ウの意味：Terraform に if 文はない。
- エの意味：? と : の順番が逆。
- 出典：オリジナル問題（根拠：HashiCorp「Conditional Expressions」（『condition ? true_val : false_val』『var.a == "" ? "default-a" : var.a』））

#### 問 tf-08-o02

- 問：条件式 var.example ? 12 : "hello" の結果の型として正しいものはどれか。
- ア：var.example によって number か string に変わる
- イ：いつも string（12 は "12" に変換される）
- ウ：エラーになる
- エ：いつも number
- 正解：イ
- 解説：2 つの値は同じ型でなければならない。ちがうときは両方が変換できる型に自動でそろえる。数は文字列に変換できるので、いつも string。あいまいなときは tostring で明示するのがすすめられる。
- アの意味：型は条件に関係なく決まる。
- イの意味：正しい。
- ウの意味：変換できるのでエラーにならない。
- エの意味："hello" は数に変換できない。
- 出典：オリジナル問題（根拠：HashiCorp「Conditional Expressions」Result Types（『the following expression is valid and will always return a string, because in Terraform all numbers can convert automatically to a string』））

#### 問 tf-08-o03

- 問：var.list = ["a", "b"] のとき、{for s in var.list : s => upper(s)} の結果はどれか。
- ア：["A", "B"]
- イ：["a", "b"]
- ウ：{ a = "A", b = "B" }
- エ：{ A = "a", B = "b" }
- 正解：ウ
- 解説：{ } でかこむとオブジェクトになり、=> の左がキー、右が値。[ ] でかこむとタプルになる。
- アの意味：[for s in var.list : upper(s)] の結果。
- イの意味：元のまま。
- ウの意味：正しい。
- エの意味：キーと値が逆。
- 出典：オリジナル問題（根拠：HashiCorp「for Expressions」Result Types（『If you use { and } instead, the result is an object and you must provide two result expressions that are separated by the => symbol』））

#### 問 tf-08-o04

- 問：var.list から空文字列をのぞいて、大文字にしたリストを作る式はどれか。
- ア：[for s in var.list : upper(s) where s != ""]
- イ：[for s in var.list if s != "" : upper(s)]
- ウ：filter(var.list, upper)
- エ：[for s in var.list : upper(s) if s != ""]
- 正解：エ
- 解説：for 式の最後に if を付けると、条件に合う要素だけが残る。
- アの意味：where はない。
- イの意味：if は最後に書く。
- ウの意味：filter という関数はない。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：HashiCorp「for Expressions」Filtering Elements（『[for s in var.list : upper(s) if s != ""]』））

#### 問 tf-08-o05

- 問：リスト var.list に対して `[for i, v in var.list : "${i} is ${v}"]` と書いた。i に入るものはどれか。
- ア：0 から始まる要素の番号
- イ：1 から始まる要素の番号
- ウ：要素の値
- エ：要素の値の長さ
- 正解：ア
- 解説：一時変数を 2 つ書くと、リストやタプルでは 1 つ目が 0 からの番号、2 つ目が値になる。マップならキーと値。
- アの意味：正しい。
- イの意味：0 から。
- ウの意味：値は v。
- エの意味：長さではない。
- 出典：オリジナル問題（根拠：HashiCorp「for Expressions」Input Types（『the additional symbol is the index of each element starting from zero』））

#### 問 tf-08-o06

- 問：ユーザー名をキー、役割を値にもつマップから、役割ごとにユーザー名のリストを作りたい（同じ役割の人が何人もいる）。正しい式はどれか。
- ア：{for name, user in var.users : user.role => name}
- イ：{for name, user in var.users : user.role => name...}
- ウ：[for name, user in var.users : user.role => name]
- エ：{for name, user in var.users : name => user.role}
- 正解：イ
- 解説：{ } の for 式ではキーが重なるとエラー。値の後ろに ... を付けるとグループ化モードになり、同じキーの値がリストにまとまる。
- アの意味：役割が重なるとエラーになる。
- イの意味：正しい。
- ウの意味：[ ] では => は使えない。
- エの意味：元のマップとほぼ同じで、まとまらない。
- 出典：オリジナル問題（根拠：HashiCorp「for Expressions」Grouping Results（『To activate grouping mode, add the symbol ... after the value expression.』『user.role => name...』））

#### 問 tf-08-o07

- 問：マップ { b = 2, a = 1, c = 3 } から for 式でリストを作った。要素の順番はどうなるか。
- ア：書いた順（b, a, c）
- イ：毎回ばらばら
- ウ：値の大きい順
- エ：キーの辞書順（a, b, c）
- 正解：エ
- 解説：順番のないマップ・オブジェクトから順番のあるリストを作るとき、キーの辞書順に並べる。文字列のセットは値の辞書順。
- アの意味：書いた順ではない。
- イの意味：マップは辞書順に決まる（文字列以外のセットは順番が決まっていない）。
- ウの意味：値では並べない。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：HashiCorp「for Expressions」Element Ordering（『For maps and objects, Terraform sorts the elements by key or attribute name, using lexical sorting.』））

#### 問 tf-08-o08

- 問：var.name を使って "Hello, Juan!" のような文字列を作る書き方として正しいものはどれか。
- ア："Hello, ${var.name}!"
- イ："Hello, $var.name!"
- ウ："Hello, {{var.name}}!"
- エ："Hello, " + var.name + "!"
- 正解：ア
- 解説：${ … } は埋めこみ（interpolation）で、式を評価し、必要なら文字列に変換して埋めこむ。
- アの意味：正しい。
- イの意味：${ } が必要。
- ウの意味：Terraform の書き方ではない。
- エの意味：+ は数の足し算で、文字列はつなげない。
- 出典：オリジナル問題（根拠：HashiCorp「Strings and Templates」Interpolation（『A ${ ... } sequence is an interpolation, which evaluates the expression given between the markers, converts the result to a string if necessary, and then inserts it into the final string』））

#### 問 tf-08-o09

- 問：文字列の中に「${foo}」という文字そのものを書きたい（埋めこみにしたくない）。正しい書き方はどれか。
- ア："\${foo}"
- イ："$${foo}"
- ウ："%{foo}"
- エ："${{foo}}"
- 正解：イ
- 解説：$${ と書くと、埋めこみを始めずに文字どおりの ${ になる。%{ は %%{。
- アの意味：バックスラッシュではエスケープできない。
- イの意味：正しい。
- ウの意味：%{ はディレクティブの始まり。
- エの意味：埋めこみとして読まれる。
- 出典：オリジナル問題（根拠：HashiCorp「Strings and Templates」Escape Sequences（『$${ Literal ${, without beginning an interpolation sequence.』））

#### 問 tf-08-o10

- 問：IAM ポリシーなどの JSON の文字列を作りたい。ドキュメントがすすめる方法はどれか。
- ア：ヒアドキュメント <<EOT で JSON を手で書く
