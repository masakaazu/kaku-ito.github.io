## 02-1 プロバイダーのしくみ

### まとめ表

| 部分 | 役割 |
| :-: | :-: |
| Terraform Core（terraform コマンド） | 設定とモジュールを読む・ステートの管理・リソースグラフ・計画の実行・プラグインと RPC で話す |
| プロバイダー（プラグイン） | API を呼ぶライブラリの準備・認証・リソースとデータソースの定義・関数の定義 |
| プロビジョナー（プラグイン） | 作ったリソースの上でコマンドやスクリプトを動かす |

### しくみ

#### プロバイダー（ぷろばいだー / provider）

- 意味：Terraform がクラウド・SaaS・ほかの API とやりとりするためのプラグイン
- ポイント：『Each provider adds a set of resource types and/or data sources that Terraform can manage.』『without providers, Terraform can't manage any kind of infrastructure.』。クラウドのほかに、乱数を作る random のような手元で動くものもある

#### Terraform Core（てらふぉーむこあ / Terraform Core）

- 意味：Go で書かれた terraform コマンドそのもの。設定の読み込み・ステートの管理・リソースグラフ・計画の実行を受け持つ
- ポイント：Core とプラグインは別のプロセスで、RPC（remote procedure call）でやりとりする。AWS などのサービスごとの処理はプラグイン側にある
- 語の意味：RPC＝Remote Procedure Call（別のプロセスの手続きを呼ぶこと）

#### プロバイダーの配布（ぷろばいだーのはいふ / provider distribution）

- 意味：プロバイダーは Terraform 本体とは別に配られ、それぞれが自分のリリースの周期とバージョン番号を持つ
- ポイント：『Providers are distributed separately from Terraform itself, and each provider has its own release cadence and version numbers.』。主な置き場所は Terraform Registry。プロバイダーは Go で書かれ、だれでも作って公開できる

#### プロバイダーのインストール（いんすとーる / provider installation）

- 意味：terraform init が、設定を読んで必要なプロバイダーを探し、Registry からダウンロードしてインストールすること
- ポイント：設定のプロバイダーを変えたら、init をやり直す。HCP Terraform と Terraform Enterprise は、実行（run）のたびにプロバイダーをインストールする。ダウンロードしたものは作業ディレクトリの .terraform サブディレクトリに置かれる

#### プラグインキャッシュ（ぷらぐいんきゃっしゅ / plugin cache）

- 意味：ダウンロードしたプロバイダーを 1 か所にためて、作業ディレクトリごとに何度も落とさないようにするしくみ
- ポイント：CLI 設定ファイルの plugin_cache_dir で有効にする。時間と通信量を節約できる

## 02-2 プロバイダーの宣言とバージョン

### まとめ表

| 書き方 | 意味 |
| :-: | :-: |
| = 1.2.0（演算子なしも同じ） | そのバージョンだけ |
| != 1.2.0 | そのバージョンを除く |
| >= 1.2.0, < 2.0.0 | 1.2.0 以上 2.0.0 未満（すべての条件を満たすもの） |
| ~> 1.0.4 | 1.0.5・1.0.10 は可、1.1.0 は不可（いちばん右だけ上がってよい） |
| ~> 1.1 | 1.2・1.10 は可、2.0 は不可 |

### 宣言

#### required_providers（りくわいあーどぷろばいだーず / required_providers）

- 意味：モジュールが必要とするプロバイダーを宣言するブロック。最上位の terraform ブロックの中に書く
- ポイント：キーがローカル名、値が source（ソースアドレス）と version（バージョン制約）のオブジェクト。各モジュールが自分で宣言する（子モジュールは親の source や version を受け継がない）
- 例：`terraform { required_providers { aws = { source = "hashicorp/aws", version = "~> 5.0" } } }`

#### ソースアドレス（そーすあどれす / source address）

- 意味：プロバイダーの世界で 1 つの名前で、ダウンロード元も表す。`[<HOSTNAME>/]<NAMESPACE>/<TYPE>` の形
- ポイント：ホスト名を省くと registry.terraform.io（公開の Registry）。hashicorp/aws は registry.terraform.io/hashicorp/aws と同じ。3 つ全部を書いた形を fully-qualified address という。source を省くと registry.terraform.io/hashicorp/<ローカル名> とみなされる（古い版との互換のため。明示がすすめられる）

#### ローカル名（ろーかるめい / local name）

- 意味：モジュールの中でプロバイダーを呼ぶ名前。required_providers のキー
- ポイント：required_providers の外では、いつもローカル名で呼ぶ（provider "aws" など）。ふつうは、リソースの型名の先頭（aws_instance の aws）と同じ「好ましいローカル名」を使う。リソースに provider を書かなければ、型名の最初の単語がローカル名とみなされる

#### provider ブロック（ぷろばいだーぶろっく / provider block）

- 意味：プロバイダーの設定（リージョン・認証・エンドポイントなど）を書くブロック。ルートモジュールに書く
- ポイント：provider ブロックを書かないと、空の既定の設定が使われる（必須の引数があるプロバイダーならエラー）。値には、適用の前に分かるもの（変数など）だけが使え、適用してはじめて決まるリソースの属性は使えない。認証情報は、設定ファイルではなく環境変数などで渡すのがよい。子モジュールに provider ブロックを書くのはすすめられない

#### バージョン制約（ばーじょんせいやく / version constraint）

- 意味：使ってよいバージョンの範囲を表す文字列。プロバイダー・モジュール・Terraform 本体（required_version）に書ける
- ポイント：条件は , でつなぎ、すべてを満たすものが選ばれる。version を省くとどのバージョンでもよいとみなされるが、書くことが強くすすめられる。プレリリース版（1.2.0-beta）は = で正確に書いたときだけ選ばれる

#### ~> 演算子（ちるだやじるし / pessimistic constraint operator）

- 意味：いちばん右のバージョンの部分だけが上がることを許す演算子
- ポイント：~> 1.0.4 は 1.0.x（1.0.4 以上）、~> 1.1 は 1.x（1.1 以上）。ルートモジュールでは ~> で上限と下限の両方を決め、再利用するモジュールでは >= で下限だけを決めるのがすすめられる

#### 依存関係ロックファイル（いぞんかんけいろっくふぁいる / dependency lock file）

- 意味：terraform init が選んだプロバイダーのバージョンとチェックサムを記録するファイル。名前は必ず .terraform.lock.hcl
- ポイント：ルートモジュールのディレクトリ（作業ディレクトリ）に置かれる。VCS にコミットする。ロックファイルに記録があると、新しいバージョンが出ても同じものを選ぶ。今のところ記録するのはプロバイダーだけで、モジュールのバージョンは記録しない。拡張子が .hcl なのは、Terraform の設定ファイル（.tf）ではないから

#### terraform init -upgrade（いにっとあっぷぐれーど / terraform init -upgrade）

- 意味：ロックファイルの記録を無視して、バージョン制約に合う最新のプロバイダーを選び直す init のオプション
- ポイント：プロバイダーを上げたいときは、required_providers の version を変えて init（必要なら -upgrade）。ロックファイルが更新されるので、変更をレビューしてコミットする

#### terraform providers（てらふぉーむぷろばいだーず / terraform providers）

- 意味：今のディレクトリの設定が必要とするプロバイダーと、その要求がどこ（どのモジュール）から来たかを表示するコマンド
- ポイント：サブコマンドに lock（ロックファイルに複数のプラットフォームのチェックサムを入れる）・mirror・schema がある

## 02-3 複数のプロバイダーと alias

### まとめ表

| 書き方 | 意味 |
| :-: | :-: |
| provider "aws" { region = "us-east-1" } | aws の既定（デフォルト）の設定 |
| provider "aws" { alias = "west"  region = "us-west-2" } | aws の別の設定（aws.west） |
| resource "aws_instance" "foo" { provider = aws.west } | このリソースは aws.west を使う |
| module "m" { providers = { aws = aws.west } } | 子モジュールに aws.west を渡す |

### 複数の設定

#### 複数のプロバイダー（ふくすうのぷろばいだー / multiple providers）

- 意味：1 つの設定の中で、AWS と Azure、AWS と Cloudflare のように、ちがう種類のプロバイダーをいっしょに使うこと
- ポイント：required_providers にそれぞれを書き、それぞれの provider ブロックで設定する。リソースは型名の先頭で、どのプロバイダーのものかが決まる

#### alias（えいりあす / alias）

- 意味：同じプロバイダーに、2 つ以上の設定（リージョンちがいなど）を作るための引数
- ポイント：alias のない provider ブロックが既定の設定。別の設定は `<PROVIDER_NAME>.<ALIAS>`（aws.west）で、resource・data・module の provider 引数（module では providers）に書いて選ぶ。全部の provider ブロックに alias があると、空の既定の設定がつくられる

#### provider メタ引数（ぷろばいだーめたひきすう / provider meta-argument）

- 意味：resource・data ブロックで、どのプロバイダーの設定を使うかを選ぶ引数
- ポイント：値は文字列ではなく aws.west のような参照（引用符を付けない）。書かなければ、型名に合う既定の設定が使われる

#### configuration_aliases（こんふぃぎゅれーしょんえいりあす / configuration_aliases）

- 意味：子モジュールが、親から別名の設定（aws.west など）を受け取ることを宣言する、required_providers の中の引数
- ポイント：子モジュールは、ルートモジュールの既定のプロバイダー設定を自動で受け継ぐ。alias の設定を使わせるには、子で configuration_aliases を宣言し、親の module ブロックの providers で渡す

#### provider ブロックの version（非推奨）（ぷろばいだーぶろっくのばーじょん / version argument (deprecated)）

- 意味：古い書き方で、provider ブロックの中に書くバージョン制約
- ポイント：非推奨（deprecated）で、将来なくなる。バージョン制約は terraform ブロックの required_providers に書く。alias と version は同じブロックに書けない

### 02-2 プロバイダーの宣言とバージョン
