## 14-1 コンソール

### まとめ表

| 方法 | 型 | 特徴 |
| :-: | :-: | :-: |
| System.in | InputStream | 標準入力（バイト） |
| System.out・System.err | PrintStream | 標準出力・標準エラー出力 |
| System.console() | Console | 端末がなければ null |
| new BufferedReader(new InputStreamReader(System.in)) | BufferedReader | 1 行ずつ readLine |

### コンソール

#### System.in・System.out・System.err（しすてむいん・あうと・えらー / standard streams）

- 意味：標準入力・標準出力・標準エラー出力を表す System クラスの static フィールド
- ポイント：System.in の型は InputStream（バイトで読む）、System.out と System.err の型は PrintStream。文字で 1 行ずつ読むには InputStreamReader で文字に変えて BufferedReader で包む

#### Console（こんそーる / Console）

- 意味：JVM につながった文字ベースの端末を表すクラス。System.console() で取得する（new はできない）
- ポイント：端末がない（IDE の中、入出力をリダイレクトした、など）と System.console() は null を返す。readLine(書式, 引数) は String、readPassword は入力を表示せず char[] を返す。format・printf は Console を返す。writer() は PrintWriter、reader() は Reader を返す
- 例：`Console c = System.console(); if (c != null) { String n = c.readLine("%s: ", "name"); char[] p = c.readPassword("pw: "); }`

#### readPassword（りーどぱすわーど / readPassword）

- 意味：入力した文字を画面に出さずに読む Console のメソッド
- ポイント：戻り値は String でなく char[]。使い終わったら配列を上書きして消せるので、パスワードが文字列として残らない

## 14-2 I/O ストリーム

### まとめ表

| 種類 | 読む | 書く |
| :-: | :-: | :-: |
| バイト | InputStream（FileInputStream・BufferedInputStream・DataInputStream・ObjectInputStream） | OutputStream（FileOutputStream・BufferedOutputStream・DataOutputStream・ObjectOutputStream・PrintStream） |
| 文字 | Reader（FileReader・BufferedReader・InputStreamReader・StringReader） | Writer（FileWriter・BufferedWriter・OutputStreamWriter・PrintWriter・StringWriter） |

### 基本のクラス

#### バイトストリーム（ばいとすとりーむ / byte stream）

- 意味：データを 1 バイト（8 ビット）ずつ読み書きするストリーム。抽象クラス InputStream・OutputStream が元になる
- ポイント：read() は 0〜255 の int を返し、終わりなら -1。画像などのバイナリや、シリアライズに使う

#### 文字ストリーム（もじすとりーむ / character stream）

- 意味：データを文字（char）単位で読み書きするストリーム。抽象クラス Reader・Writer が元になる
- ポイント：read() は文字の int、終わりなら -1。read(char[]) は読んだ文字数を返し、終わりなら -1。名前の終わりが Stream ならバイト、Reader・Writer なら文字

#### FileReader・FileWriter（ふぁいるりーだー・ふぁいるらいたー / FileReader, FileWriter）

- 意味：ファイルを文字で読み書きするクラス。バイト版は FileInputStream・FileOutputStream
- ポイント：FileWriter(ファイル) は上書き、FileWriter(ファイル, true) は追記。ないファイルを FileReader で開くと FileNotFoundException（IOException のサブクラス、チェック例外）

#### InputStreamReader・OutputStreamWriter（いんぷっとすとりーむりーだー / InputStreamReader, OutputStreamWriter）

- 意味：バイトストリームを文字ストリームに変える橋渡しのクラス。文字コード（Charset）を指定できる
- ポイント：System.in（バイト）を BufferedReader（文字）で読むときに間に入れる

### 包むクラス

#### BufferedReader・BufferedWriter（ばっふぁーどりーだー・らいたー / BufferedReader, BufferedWriter）

- 意味：ほかの Reader・Writer を包み、まとめて読み書きして速くするクラス
- ポイント：readLine は 1 行を改行なしで返し、終わりなら null（-1 ではない）。newLine で改行を書く。BufferedWriter は flush か close するまで、包んだ先に書かれない

#### PrintWriter・PrintStream（ぷりんとらいたー・ぷりんとすとりーむ / PrintWriter, PrintStream）

- 意味：print・println・printf・format で、いろいろな型を文字にして書くクラス。PrintStream はバイト側（System.out の型）、PrintWriter は文字側
- ポイント：print 系のメソッドは IOException を投げない。エラーは checkError() で調べる（閉じたあとに書くと true）

#### DataInputStream・DataOutputStream（でーたいんぷっとすとりーむ / DataInputStream, DataOutputStream）

- 意味：int・boolean・String（writeUTF）などの基本の値を、バイナリで書き、同じ順で読み戻すクラス
- ポイント：書いた順と同じ順で読む。終わりを過ぎて readInt すると EOFException（-1 ではない）。writeInt は 4 バイト

#### mark・reset・skip（まーく・りせっと・すきっぷ / mark, reset, skip）

- 意味：mark で今の位置に印を付け、reset でそこに戻る。skip(n) は n 文字（バイト）読み飛ばし、飛ばした数を返す
- ポイント：mark を使えるかは markSupported() で調べる（StringReader・BufferedReader は true）

### 後片付け

#### try-with-resources（とらいうぃずりそーしず / try-with-resources）

- 意味：try の () の中で開いたリソース（AutoCloseable）を、ブロックを出るときに自動で close する構文
- ポイント：close は開いたのと逆の順で、catch・finally より前に行われる。close の例外は、本体の例外の getSuppressed() に「抑制された例外」として入る。Java 9 からは、final か実質的に final の変数を `try (r)` と書ける（再代入した変数はコンパイルエラー）。close が IOException を投げる型（Writer など）は、その例外の処理も必要

#### AutoCloseable と Closeable（おーときろーざぶる / AutoCloseable, Closeable）

- 意味：AutoCloseable は close() throws Exception を持つインタフェース。Closeable は java.io の子インタフェースで、close() throws IOException
- ポイント：java.io のストリームはすべて Closeable。自作クラスも AutoCloseable を実装すれば try-with-resources で使える

## 14-3 シリアライズ

### まとめ表

| 項目 | シリアライズされるか |
| :-: | :-: |
| ふつうのインスタンス変数 | される |
| transient の変数 | されない（戻すと既定値） |
| static 変数 | されない（クラスの値のまま） |
| Serializable でない親クラスの変数 | されない（親の引数なしコンストラクタが動いて初期化） |

### シリアライズ

#### シリアライズ（しりあらいず / serialization）

- 意味：オブジェクトの状態をバイトの並びに変えて、ファイルやネットワークに書き出すこと。元に戻すことをデシリアライズという
- ポイント：ObjectOutputStream の writeObject で書き、ObjectInputStream の readObject で読む。readObject の戻り値は Object なのでキャストが要る（しないとコンパイルエラー）。終わりを過ぎて読むと EOFException

#### Serializable（しりあらいざぶる / Serializable）

- 意味：シリアライズしてよいクラスであることを示す、メソッドのないインタフェース（マーカー・インタフェース）
- ポイント：実装していないクラスを writeObject すると NotSerializableException（実行時）。フィールドの型が Serializable でない場合も同じ。親クラスが実装していれば、子クラスも Serializable

#### transient（とらんじぇんと / transient）

- 意味：シリアライズの対象から外すフィールドに付ける修飾子
- ポイント：デシリアライズすると既定値（0・false・null）になる。初期化子やコンストラクタの値には戻らない。Serializable でない型のフィールドも transient にすれば書ける
- 語の意味：transient＝一時的な

#### serialVersionUID（しりあるばーじょんゆーあいでぃー / serialVersionUID）

- 意味：シリアライズしたときと読むときのクラスが同じ版かを確かめる番号。`private static final long serialVersionUID = 1L;` のように書く
- ポイント：書いたときと読むときで番号がちがうと InvalidClassException。書かないとクラスの中身から自動で計算され、少し変えただけでも変わる

#### デシリアライズとコンストラクタ（でしりあらいずとこんすとらくた / deserialization and constructors）

- 意味：デシリアライズでは、Serializable なクラスのコンストラクタは呼ばれない。いちばん近い Serializable でない親クラスの、引数なしコンストラクタだけが呼ばれる
- ポイント：Serializable でない親クラスのフィールドは、そのコンストラクタと初期化子の値になる（書いたときの値ではない）。親に引数なしコンストラクタがないと InvalidClassException。レコードは例外で、標準コンストラクタ（canonical constructor）が呼ばれる

#### writeObject・readObject メソッド（らいとおぶじぇくと・りーどおぶじぇくと / writeObject, readObject）

- 意味：Serializable なクラスに private void writeObject(ObjectOutputStream)・private void readObject(ObjectInputStream) を書くと、シリアライズの方法を変えられる
- ポイント：中で defaultWriteObject・defaultReadObject を呼ぶと、ふつうのフィールドの書き込み・読み込みをする。同じオブジェクトを 2 回 writeObject すると 2 回目は参照だけ書かれ、読み戻すと同じオブジェクト（==）になる

#### Externalizable（えくすたーならいざぶる / Externalizable）

- 意味：writeExternal・readExternal を実装して、シリアライズの中身を全部自分で決める、Serializable の子インタフェース
- ポイント：読み戻すとき public の引数なしコンストラクタが呼ばれるので、それが必要

- 問：IDE の中や、入出力をリダイレクトして java を起動したとき、`System.out.println(System.console());` が表示するものはどれか。

### 14-2 I/O ストリーム

#### 問 jgold-14-o05

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  StringWriter sw = new StringWriter();
  try (BufferedWriter w = new BufferedWriter(sw)) { w.write("a"); w.newLine(); w.write("b"); }
  BufferedReader r = new BufferedReader(new StringReader(sw.toString()));
  ```

- アの意味：readLine は終わりで null を返す。-1 を返すのは read。
- イの意味：readLine の戻り値に改行は入らない。
- ウの意味：正しい。
- エの意味：newLine で改行しているので 2 行になる。
- 出典：オリジナル問題（根拠：API BufferedReader.readLine・BufferedWriter.newLine／JDK 17 での実行結果）
