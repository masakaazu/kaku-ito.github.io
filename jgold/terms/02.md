## 02-1 ジェネリッククラスとジェネリックメソッド

### まとめ表

| 書き方 | 意味 |
| :-: | :-: |
| `class Box<T> { ... }` | 型パラメータ T を持つジェネリッククラス |
| `new Box<>("hi")` | ダイヤモンド。型引数を推論する |
| `static <T> List<T> twice(T t)` | ジェネリックメソッド。<T> は戻り値の型の前 |
| `Main.<String>twice("x")` | 型引数を明示して呼ぶ（クラス名やthisの後に書く） |
| `var list = new ArrayList<>();` | ArrayList<Object> になる |

### 型パラメータ

#### ジェネリクス（じぇねりくす / generics）

- 意味：クラスやメソッドを、扱う型をパラメータにして定義するしくみ。総称型ともいう
- ポイント：コンパイル時に型を確かめられ、取り出すときのキャストがいらなくなる。型が合わない代入はコンパイルエラーで見つかる
- 例：`List<String> list = new ArrayList<>(); String s = list.get(0);`

#### 型パラメータ（かたぱらめーた / type parameter）

- 意味：`class Box<T>` の T のように、クラスやメソッドの宣言で、あとから決める型につけた名前
- ポイント：慣習で 1 文字の大文字を使う。T（Type）・E（Element）・K（Key）・V（Value）・R（Result）など。複数なら `<K, V>`

#### 型引数（かたひきすう / type argument）

- 意味：`Box<String>` の String のように、使うときに型パラメータに当てはめる具体的な型
- ポイント：参照型だけを書ける。`Box<int>` はコンパイルエラー（unexpected type）。ワイルドカード `?` も型引数の一種

#### ダイヤモンド演算子（だいやもんどえんざんし / diamond）

- 意味：`new ArrayList<>()` のように、new のあとの型引数を省いて `<>` だけ書くこと。左辺などから推論される
- ポイント：`var list = new ArrayList<>();` は手がかりがないので ArrayList<Object> になり、何でも入る。`new ArrayList<?>()` のように new でワイルドカードを使うのはコンパイルエラー

#### ジェネリックメソッド（じぇねりっくめそっど / generic method）

- 意味：メソッドごとに型パラメータを宣言したメソッド。`<T>` を修飾子と戻り値の型の間に書く
- ポイント：型引数は引数から推論される。明示するときは `Main.<String>twice("x")` のように、ドットのあとメソッド名の前に書く。static メソッドでも使える（クラスの T は static で使えないが、メソッドの <T> は使える）
- 例：`static <T> List<T> twice(T t) { return List.of(t, t); }`

#### ジェネリック型の継承（じぇねりっくがたのけいしょう / generic supertype）

- 意味：`class Dog implements Animal<String>` のように、型引数を決めてジェネリック型を継承・実装すること
- ポイント：オーバーライドするメソッドは、型引数を当てはめた形（speak(String)）で書く。speak(Object) と書くと、同じイレイジャで上書きにならず name clash のコンパイルエラー

## 02-2 境界とワイルドカード

### まとめ表

| 書き方 | 入れる（add） | 取り出す（get） | 代入できる例 |
| :-: | :-: | :-: | :-: |
| `List<Number>` | Number とその子 | Number | List<Number> だけ |
| `List<? extends Number>` | null だけ | Number | List<Integer>・List<Double> |
| `List<? super Integer>` | Integer とその子 | Object | List<Integer>・List<Number>・List<Object> |
| `List<?>` | null だけ | Object | どの List でも |

### 境界

#### 境界のある型パラメータ（きょうかいのあるかたぱらめーた / bounded type parameter）

- 意味：`<T extends Number>` のように、型パラメータに当てはめられる型を、ある型とその子に限ったもの
- ポイント：インタフェースでも extends と書く（implements ではない）。境界の型のメソッド（doubleValue など）を T に対して呼べる。範囲外の型引数（Shelf<String>）は「type argument String is not within bounds」のコンパイルエラー

#### 複数の境界（ふくすうのきょうかい / multiple bounds）

- 意味：`<T extends Number & Comparable<T>>` のように & でつないで、複数の型を同時に満たすよう求めること
- ポイント：クラスは 1 つだけで、必ず最初に書く。インタフェースを先に書いて後ろにクラスを書くと「interface expected here」のコンパイルエラー

#### 再帰的な境界（さいきてきなきょうかい / recursive bound）

- 意味：`<T extends Comparable<T>>` のように、型パラメータ自身を使って境界を書くこと
- ポイント：「自分と同じ型と比べられる T」という意味。max や sort のようなメソッドで使う

### ワイルドカード

#### 非境界ワイルドカード（ひきょうかいわいるどかーど / unbounded wildcard）

- 意味：`List<?>` のように、何の型かを問わない型引数
- ポイント：どんな List でも受け取れるが、何の型か分からないので null 以外は add できない。取り出すと Object。size や clear のような型に関係ない操作に使う。`List<Object>` とは違う（List<String> は List<Object> に代入できないが、List<?> にはできる）

#### 上限境界ワイルドカード（じょうげんきょうかいわいるどかーど / upper bounded wildcard）

- 意味：`List<? extends Number>` のように、Number またはその子の何かの型、を表す型引数
- ポイント：取り出すと Number として使えるが、実体が List<Integer> か List<Double> か分からないので、null 以外は add できない（no suitable method found for add）。値を読むだけの引数（生産者）に使う

#### 下限境界ワイルドカード（かげんきょうかいわいるどかーど / lower bounded wildcard）

- 意味：`List<? super Integer>` のように、Integer またはその親の何かの型、を表す型引数
- ポイント：Integer（とその子）は add できる。取り出すと何の型か分からないので Object になり、Integer の変数には代入できない。値を書き込む引数（消費者）に使う

#### PECS（ぺっくす / Producer Extends, Consumer Super）

- 意味：ワイルドカードの選び方の目安。値を取り出す（生産する）側は extends、値を入れる（消費する）側は super
- ポイント：`Collections.copy(List<? super T> dest, List<? extends T> src)` がこの形
- 語の意味：Producer＝生産者／Extends＝上限境界／Consumer＝消費者／Super＝下限境界

#### 不変性（ふへんせい / invariance）

- 意味：Integer が Number の子でも、List<Integer> は List<Number> の子ではない、というジェネリクスの性質
- ポイント：`List<Number> ln = new ArrayList<Integer>();` はコンパイルエラー。もし許すと、List<Integer> に Double を入れられてしまうため。広く受け取りたいときはワイルドカードを使う

#### 配列の共変性（はいれつのきょうへんせい / array covariance）

- 意味：String が Object の子なら、String[] は Object[] の子として扱える、という配列の性質
- ポイント：`Object[] arr = new String[1]; arr[0] = 1;` はコンパイルが通り、実行時に ArrayStoreException（JLS 10.5）。ジェネリクスは不変なので、この種のまちがいをコンパイル時に止められる

## 02-3 イレイジャと制限

### まとめ表

| ジェネリクスでできないこと | 理由・エラー |
| :-: | :-: |
| `new T()` | 実行時に T が分からない（unexpected type） |
| `static T field;` | static はインスタンスごとの T を使えない |
| `o instanceof T`・`o instanceof List<String>`（o が Object） | 実行時に確かめられない（cannot be safely cast） |
| `new List<String>[3]` | generic array creation |
| `m(List<String>)` と `m(List<Integer>)` のオーバーロード | name clash: ... have the same erasure |

### イレイジャ

#### 型消去（かたしょうきょ / type erasure）

- 意味：コンパイラがジェネリクスの型の情報を確かめたあと、型引数を消して境界の型（なければ Object）に置き換え、必要なキャストを足すこと
- ポイント：実行時には List<String> も List<Integer> も同じ ArrayList クラス（getClass() が等しい）。そのため、実行時に型引数を使う操作（new T()・instanceof T）はできない

#### 同じイレイジャ（おなじいれいじゃ / same erasure）

- 意味：型引数を消すと同じシグネチャになる、という関係
- ポイント：`print(List<String>)` と `print(List<Integer>)` は消すとどちらも `print(List)` なので、オーバーロードできない（name clash ... have the same erasure）

#### 原型（げんけい / raw type）

- 意味：`List` のように、ジェネリック型を型引数なしで使ったもの。古いコードとの互換のために残っている
- ポイント：何でも入れられ、コンパイラは警告（unchecked）を出すだけ。List<String> に代入すると、取り出すときのキャストで ClassCastException になることがある。新しいコードでは使わない

#### ヒープ汚染（ひーぷおせん / heap pollution）

- 意味：パラメータ化された型の変数が、その型ではないオブジェクトを指してしまう状態
- ポイント：原型や unchecked キャストで起きる。エラーはその場でなく、あとで取り出すときの ClassCastException として出る

### できないこと

#### ジェネリック配列の生成（じぇねりっくはいれつのせいせい / generic array creation）

- 意味：`new List<String>[3]` や `new T[3]` のように、型引数を持つ型の配列を作ること。コンパイルエラーになる
- ポイント：配列は実行時に要素の型を確かめる（ArrayStoreException）が、型引数は消えているので確かめられないため。`new List<?>[3]` は作れる。`(T[]) new Object[3]` は unchecked の警告つきでコンパイルできるが、外から T[] として受け取ると ClassCastException になりうる

#### static と型パラメータ（すたてぃっくとかたぱらめーた / type variable in static context）

- 意味：クラスの型パラメータ T を、static フィールドや static メソッドで使うこと。コンパイルエラーになる
- ポイント：T はインスタンスごとに違いうるが、static はクラスに 1 つだけなので。エラーは「non-static type variable T cannot be referenced from a static context」。static メソッドで型を使いたいなら、メソッド自身に <T> を宣言する

#### instanceof とジェネリクス（いんすたんすおぶとじぇねりくす / instanceof with generics）

- 意味：instanceof の右に型引数つきの型を書くこと
- ポイント：`o instanceof List<?>` はいつでも書ける。Java 16 から、安全に確かめられる場合（`List<String> l` に `l instanceof ArrayList<String>`）は書けるが、Object の変数に `instanceof List<String>` は「Object cannot be safely cast to List<String>」のコンパイルエラー

### 02-1 ジェネリッククラスとジェネリックメソッド

#### 問 jgold-02-o01

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  class Box<T> {
    private T value;
    Box(T value) { this.value = value; }
    T get() { return value; }
  }
  // main メソッドの中
  Box<String> b = new Box<>("hi");
  String s = b.get();
  Box<Integer> n = new Box<>(10);
  System.out.println(s.length() + n.get());
  ```

- ア：2 10
- イ：210
- ウ：12
- エ：コンパイルエラーになる（get の戻り値をキャストしていない）
- 正解：ウ
- 解説：Box<String> の get は String を、Box<Integer> の get は Integer を返すので、キャストはいらない。s.length() は int の 2、n.get() は Integer の 10 がアンボクシングされ、int どうしの足し算で 12。
- アの意味：空白が入ることはない。式は 1 つの足し算。
- イの意味：文字列の連結になると考えたまちがい。どちらも数なので足し算になる。
- ウの意味：正しい。
- エの意味：ジェネリクスでは取り出すときのキャストを書かなくてよい（コンパイラが入れる）。
- 出典：オリジナル問題（根拠：JLS 8.1.2 Generic Classes and Type Parameters／JDK 17 での実行結果）

#### 問 jgold-02-o02

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  static <T> List<T> twice(T t) { return List.of(t, t); }  // クラス Main の static メソッド
  // main メソッドの中
  List<String> a = Main.<String>twice("x");
  var b = twice(5);
  System.out.println(a + " " + b + " " + b.get(0).getClass().getSimpleName());
  ```

- ア：[x, x] [5, 5] Integer
- イ：[x, x] [5, 5] int
- ウ：[x, x] [5, 5] Object
- エ：コンパイルエラーになる（`Main.<String>twice` の書き方が誤り）
- 正解：ア
- 解説：ジェネリックメソッドの型引数は、明示するなら `Main.<String>twice("x")` のようにメソッド名の前に書く。twice(5) は 5 が Integer にボクシングされ、T は Integer と推論される。要素の実体は Integer。
- アの意味：正しい。
- イの意味：型引数は参照型なので、要素は Integer。getClass() は基本データ型を返さない。
- ウの意味：T は Object でなく、引数から Integer と推論される。どちらにしても getClass() は実体のクラスを返す。
- エの意味：型引数の明示は「型名.<型>メソッド名(...)」で正しい。
- 出典：オリジナル問題（根拠：JLS 8.4.4 Generic Methods・15.12 Method Invocation Expressions（TypeArguments）／JDK 17 での実行結果）

#### 問 jgold-02-o03

- 問：次のコードを実行した。結果として正しいものはどれか。

  ```
  var list = new ArrayList<>();
  list.add("a"); list.add(1);
  System.out.println(list);
  ```

- ア：コンパイルエラーになる（var とダイヤモンドは同時に使えない）
- イ：実行時に ClassCastException が投げられる
- ウ：コンパイルエラーになる（"a" と 1 の型が違う）
- エ：[a, 1] と表示される
- 正解：エ
- 解説：推論の手がかりがないので、`new ArrayList<>()` は ArrayList<Object> になり、list の型もそれになる。Object なので "a" も 1 も入る。
- アの意味：var とダイヤモンドを一緒に書くことはできる。手がかりがないと Object になるだけ。
- イの意味：取り出してキャストしていないので、例外は起きない。
- ウの意味：要素の型が Object なので、どちらも入る。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：JLS 14.4.1 Local Variable Declarators and Types、15.9.1（ダイヤモンドの推論）／JDK 17 での実行結果）

#### 問 jgold-02-o04

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  record Pair<K, V>(K first, V second) {
    Pair<V, K> swap() { return new Pair<>(second, first); }
  }
  // main メソッドの中
  Pair<String, Integer> p = new Pair<>("a", 1);
  Pair<Integer, String> q = p.swap();
  System.out.println(q.first() + q.first() + q.second());
  ```

- ア：11a
- イ：2a
- ウ：a11
- エ：コンパイルエラーになる（レコードはジェネリックにできない）
- 正解：イ
- 解説：swap で first が Integer の 1、second が String の "a" になる。式は左から計算され、Integer の 1 + 1 で 2（足し算）、次に 2 + "a" で連結されて "2a"。
- アの意味：最初から文字列の連結になると考えたまちがい。左の 2 つは数どうしなので足し算。
- イの意味：正しい。
- ウの意味：swap の前の順番で考えたまちがい。
- エの意味：レコードも型パラメータを持てる。
- 出典：オリジナル問題（根拠：JLS 8.10 Record Classes（TypeParameters を持てる）・15.18 Additive Operators／JDK 17 での実行結果）

#### 問 jgold-02-o05

- 問：次のコードについて正しいものはどれか。

  ```
  interface Animal<T> { T speak(T t); }
  class Dog implements Animal<String> {
    public Object speak(Object s) { return s; }
  }
  ```

- ア：コンパイルでき、Dog の speak は Animal の speak をオーバーライドする
- イ：コンパイルでき、Dog の speak は Animal の speak をオーバーロードする
- ウ：コンパイルエラーになる。speak(String) を実装しておらず、speak(Object) とは同じイレイジャで衝突する
- エ：実行時に ClassCastException が投げられる
- 正解：ウ
- 解説：Animal<String> を実装したので、実装すべきメソッドは speak(String)。speak(Object) はそれをオーバーライドしないうえ、イレイジャが同じなのでオーバーロードとしても並べられない。JDK 17 は「Dog is not abstract and does not override abstract method speak(String) in Animal」と「name clash: speak(Object) in Dog and speak(String) in Animal have the same erasure, yet neither overrides the other」の 2 つを表示する。`public String speak(String s)` と書けば正しくオーバーライドできる。
- アの意味：オーバーライドするには、型引数を当てはめた speak(String) と同じシグネチャにする。
- イの意味：イレイジャが同じ 2 つのメソッドは、オーバーロードとして共存できない。
- ウの意味：正しい。
- エの意味：コンパイルの段階でエラーになる。
- 出典：オリジナル問題（根拠：JLS 8.4.2 Method Signature・8.4.8.3（name clash）／JDK 17 でのコンパイル結果）

#### 問 jgold-02-o06

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  static <T> void show(T... items) {   // クラス Main の static メソッド
    System.out.println(items.length + " " + items.getClass().getSimpleName());
  }
  // main メソッドの中
  show("a", "b"); show(1, 2, 3); show();
  ```

- ア：2 String[]（改行）3 int[]（改行）0 Object[]
- イ：2 Object[]（改行）3 Object[]（改行）0 Object[]
- ウ：2 String[]（改行）3 Integer[]（改行）コンパイルエラー（show() の T が決まらない）
- エ：2 String[]（改行）3 Integer[]（改行）0 Object[]
- 正解：エ
- 解説：可変長引数は呼び出し側で配列にまとめられ、その配列の型は推論した T で決まる。"a","b" は String[]、1,2,3 は Integer[]（ボクシング）。引数がないと手がかりがなく T は Object になり、長さ 0 の Object[]。
- アの意味：T は参照型なので、1, 2, 3 はボクシングされて Integer[] になる。
- イの意味：配列は呼び出し側で推論した型で作られるので、いつも Object[] になるわけではない。
- ウの意味：引数がないときは Object と推論され、コンパイルできる。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：JLS 15.12.4.2 Evaluate Arguments（可変長引数の配列の生成）・18 型推論／JDK 17 での実行結果）

### 02-2 境界とワイルドカード

#### 問 jgold-02-o07

- 問：main メソッドの中に書いたとき、コンパイルエラーになるものはどれか。
- ア：`List<Object> list = new ArrayList<String>();`
- イ：`List<? extends Object> list = new ArrayList<String>();`
- ウ：`Object[] arr = new String[1];`
- エ：`Collection<String> c = new ArrayList<String>();`
- 正解：ア
- 解説：ジェネリクスは不変で、String が Object の子でも ArrayList<String> は List<Object> の子ではない。JDK 17 は「incompatible types: ArrayList<String> cannot be converted to List<Object>」と表示する。
- アの意味：正しい。コンパイルエラーになる。
- イの意味：上限境界ワイルドカードなら、Object の子の何かの型の List として受け取れる。
- ウの意味：配列は共変なので代入できる（あとで別の型を入れると実行時に ArrayStoreException）。
- エの意味：型引数が同じで、ArrayList は Collection を実装するので代入できる。
- 出典：オリジナル問題（根拠：JLS 4.10.2 Subtyping among Class and Interface Types、4.5.1／JDK 17 でのコンパイル結果）

#### 問 jgold-02-o30

- 問：ワイルドカードの使い分け（PECS）について、正しいものはどれか。
- ア：要素を読むだけの引数は `List<? super T>`、要素を書き込むだけの引数は `List<? extends T>` にする
- イ：要素を読むだけの引数は `List<? extends T>`、要素を書き込むだけの引数は `List<? super T>` にする
- ウ：読むときも書くときも `List<?>` にすれば、どんな List でも受け取れて要素も追加できる

- イの意味：正しい。
- ウの意味：`List<?>` には null 以外を add できない。
- エの意味：ジェネリクスは不変なので、List<String> などは List<Object> の引数に渡せない。
- 出典：オリジナル問題（根拠：The Java Tutorials「Guidelines for Wildcard Use」、API Collections.copy(List<? super T>, List<? extends T>)）
