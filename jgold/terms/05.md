## 05-1 関数型インタフェース

### まとめ表

| インタフェースの中身 | 抽象メソッドの数に入るか |
| :-: | :-: |
| ふつうの抽象メソッド | 入る |
| default メソッド・static メソッド・private メソッド | 入らない |
| Object の public メソッドと同じもの（equals・toString・hashCode） | 入らない |
| 親インタフェースから受け継いだ抽象メソッド | 入る（同じシグネチャなら 1 つと数える） |

### 関数型インタフェース

#### 関数型インタフェース（かんすうがたいんたふぇーす / functional interface）

- 意味：抽象メソッドをちょうど 1 つだけ持つインタフェース。ラムダ式やメソッド参照の代入先（ターゲット型）になれる（JLS 9.8）
- ポイント：default・static・private メソッドはいくつあってもよい。Comparator の equals のように、Object の public メソッドと同じシグネチャの抽象メソッドは数えない。親から同じシグネチャの抽象メソッドを 2 つ受け継いでも 1 つと数える

#### @FunctionalInterface（ふぁんくしょなるいんたふぇーすあのてーしょん / @FunctionalInterface）

- 意味：インタフェースが関数型インタフェースであることを示すアノテーション。条件を満たさないとコンパイラがエラーにする
- ポイント：付けなくても条件を満たせば関数型インタフェースとして使える。付けたのに抽象メソッドが 2 つ以上あると「Unexpected @FunctionalInterface annotation（multiple non-overriding abstract methods found）」。Runnable を継承して抽象メソッドを 1 つ足すと、run と合わせて 2 つになる

#### 関数記述子（かんすうきじゅつし / function descriptor）

- 意味：関数型インタフェースの抽象メソッドの「引数の型と戻り値の型」の組。ラムダ式はこの形に合わせて書く
- ポイント：Predicate<T> は T → boolean、Function<T, R> は T → R、Supplier<T> は () → T、Consumer<T> は T → void。メソッド名はインタフェースごとに違う（test・apply・get・accept）

#### ターゲット型（たーげっとがた / target type）

- 意味：ラムダ式やメソッド参照が、どの関数型インタフェースとして扱われるかを決める、代入先や引数の型
- ポイント：ラムダ式だけでは型が決まらない。`Object o = () -> ...;` は「Object is not a functional interface」、`var r = () -> ...;` は「lambda expression needs an explicit target-type」。`(Runnable) () -> ...` のようにキャストで型を与えればよい

## 05-2 ラムダ式の書き方

### まとめ表

| 書き方 | 可否 |
| :-: | :-: |
| `x -> x + 1` | ○ 引数 1 つで型なしなら丸かっこ省略可 |
| `(x, y) -> x + y` | ○ |
| `(Integer x, Integer y) -> x + y` | ○ 全部に型を書く |
| `(var x, var y) -> x + y` | ○ Java 11〜 |
| `(Integer x, y) -> x + y` | × 型ありと型なしは混ぜられない |
| `Integer x -> x + 1` | × 型を書いたら丸かっこが必要 |
| `() -> { return "hi"; }` | ○ ブロックなら return と ; |
| `() -> { "hi"; }` | × not a statement |

### 書き方

#### ラムダ式（らむだしき / lambda expression）

- 意味：関数型インタフェースの抽象メソッドの実装を、「引数 -> 本体」の形で短く書いた式
- ポイント：本体が式 1 つなら {} も return も書かない。{} を書いたら文の並び（ブロック）になり、値を返すなら return が必要。戻り値が void の型（Runnable など）に値を return すると「bad return type in lambda expression」
- 例：`Function<String, Integer> f = s -> s.length();`

#### ラムダ式の引数（らむだしきのひきすう / lambda parameters）

- 意味：ラムダ式の -> の左に書く引数。型は省略でき、ターゲット型から推論される
- ポイント：型を書くなら全部の引数に書き、型ありと型なしは混ぜられない（cannot mix implicitly-typed and explicitly-typed parameters）。var も全部にそろえる。Function<Integer, Integer> に `(int x) -> ...` と基本データ型を書くと「incompatible parameter types」

#### ラムダ式のスコープ（らむだしきのすこーぷ / scope of a lambda body）

- 意味：ラムダ式の本体は新しいスコープを作らず、外側のメソッドと同じスコープとして扱われる
- ポイント：外側のローカル変数と同じ名前の引数や変数は宣言できない（variable s is already defined）。this は外側のインスタンス。外側のローカル変数は effectively final のものだけ読める（#04）

#### 高階関数（こうかいかんすう / higher-order function）

- 意味：関数を引数に取ったり、関数を返したりする関数
- ポイント：`Function<Integer, Function<Integer, Integer>> adder = a -> b -> a + b;` は、a を受けて「b を受けて a + b を返す関数」を返す。adder.apply(3).apply(4) は 7

## 05-3 メソッド参照

### まとめ表

| 種類 | 書き方 | 同じ意味のラムダ式 |
| :-: | :-: | :-: |
| static メソッド | `Integer::parseInt` | `s -> Integer.parseInt(s)` |
| 特定のオブジェクトのメソッド | `prefix::concat`・`System.out::println` | `s -> prefix.concat(s)` |
| 任意のオブジェクトのメソッド | `String::length` | `s -> s.length()` |
| コンストラクタ | `ArrayList::new`・`int[]::new` | `() -> new ArrayList<>()`・`n -> new int[n]` |

### メソッド参照

#### メソッド参照（めそっどさんしょう / method reference）

- 意味：既存のメソッドを `::` で指して、ラムダ式の代わりに使う書き方
- ポイント：どのメソッドが選ばれるかはターゲット型の関数記述子で決まる。同じ `System.out::println` でも、Consumer<String> なら println(String)、Runnable なら引数なしの println()（改行だけ）

#### static メソッドの参照（すたてぃっくめそっどのさんしょう / reference to a static method）

- 意味：`クラス名::static メソッド名` の形のメソッド参照。引数がそのままメソッドの引数になる
- ポイント：`Math::max` は BiFunction<Integer, Integer, Integer> にも BinaryOperator<Integer> にもなる。`Integer::compare` は Comparator<Integer> にもなる

#### 束縛されたインスタンスメソッドの参照（そくばくされたいんすたんすめそっどのさんしょう / bound instance method reference）

- 意味：`式::メソッド名` の形で、特定のオブジェクトのインスタンスメソッドを指すメソッド参照
- ポイント：`prefix::concat` は、作った時点の prefix の文字列について concat を呼ぶ。引数は全部メソッドの引数になる。`w::length` は Supplier<Integer> になる

#### 束縛されていないインスタンスメソッドの参照（そくばくされていないいんすたんすめそっどのさんしょう / unbound instance method reference）

- 意味：`クラス名::インスタンスメソッド名` の形のメソッド参照。最初の引数がメソッドを呼ぶオブジェクトになり、残りの引数がメソッドの引数になる
- ポイント：`String::length` は Function<String, Integer>（s -> s.length()）。`String::startsWith` は BiFunction<String, String, Boolean>（(a, b) -> a.startsWith(b)）。呼ぶオブジェクトがないので Supplier<Integer> には使えず「invalid method reference（unexpected instance method length() found in unbound lookup）」

#### コンストラクタ参照（こんすとらくたさんしょう / constructor reference）

- 意味：`クラス名::new` の形で、コンストラクタを指すメソッド参照。配列なら `型[]::new`
- ポイント：どのコンストラクタかはターゲット型で決まる。Supplier なら引数なし、Function<String, StringBuilder> なら StringBuilder(String)。get や apply を呼ぶたびに新しいオブジェクトができる

## 05-4 java.util.function

### まとめ表

| インタフェース | メソッド | 形 | 主な default・static |
| :-: | :-: | :-: | :-: |
| Supplier<T> | get() | () → T | ― |
| Consumer<T> | accept(T) | T → void | andThen |
| Predicate<T> | test(T) | T → boolean | and・or・negate、isEqual・not |
| Function<T, R> | apply(T) | T → R | andThen・compose、identity |
| UnaryOperator<T> | apply(T) | T → T | identity |
| BinaryOperator<T> | apply(T, T) | (T, T) → T | minBy・maxBy |
| BiFunction<T, U, R> | apply(T, U) | (T, U) → R | andThen |
| BiConsumer<T, U> | accept(T, U) | (T, U) → void | andThen |
| BiPredicate<T, U> | test(T, U) | (T, U) → boolean | and・or・negate |

### 4 つの基本

#### Supplier（さぷらいやー / Supplier）

- 意味：引数を取らず、値を 1 つ返す関数型インタフェース。メソッドは get()
- ポイント：apply ではなく get。`ArrayList::new` を入れると、get するたびに新しい List ができる
- 語の意味：Supplier＝供給するもの

#### Consumer（こんしゅーまー / Consumer）

- 意味：値を 1 つ受け取り、何も返さない（副作用だけの）関数型インタフェース。メソッドは accept(T)
- ポイント：a.andThen(b) は、同じ引数で a を実行してから b を実行する。List.forEach や Map.forEach（BiConsumer）の引数
- 語の意味：Consumer＝消費するもの

#### Predicate（ぷれでぃけーと / Predicate）

- 意味：値を 1 つ受け取り、boolean を返す関数型インタフェース。メソッドは test(T)
- ポイント：and・or・negate でつなげる。static の `Predicate.not(p)` は否定、`Predicate.isEqual(x)` は Objects.equals(x, 引数) の判定（null も扱える）。removeIf の引数
- 語の意味：Predicate＝述語、判定するもの

#### Function（ふぁんくしょん / Function）

- 意味：値を 1 つ受け取り、別の値を返す関数型インタフェース。メソッドは apply(T)
- ポイント：f.andThen(g) は「f のあと g」（g(f(x))）、f.compose(g) は「g のあと f」（f(g(x))）。Function.identity() は受け取った値をそのまま返す

### 派生したもの

#### UnaryOperator（ゆなりーおぺれーた / UnaryOperator）

- 意味：引数と戻り値が同じ型の Function。UnaryOperator<T> は Function<T, T> を継承する
- ポイント：List.replaceAll の引数。`UnaryOperator<String> up = String::toUpperCase;`
- 語の意味：Unary＝単項の（1 つの）／Operator＝演算子

#### BinaryOperator（ばいなりーおぺれーた / BinaryOperator）

- 意味：同じ型の引数を 2 つ受け取り、同じ型を返す BiFunction。BinaryOperator<T> は BiFunction<T, T, T> を継承する
- ポイント：static の minBy・maxBy は、Comparator を受けて小さい（大きい）ほうを返す BinaryOperator を作る。reduce の引数によく使う
- 語の意味：Binary＝二項の（2 つの）

#### Bi〜（ばい / BiFunction, BiConsumer, BiPredicate）

- 意味：引数を 2 つ取る版。BiFunction<T, U, R> の apply(T, U)、BiConsumer<T, U> の accept(T, U)、BiPredicate<T, U> の test(T, U)
- ポイント：Bi の Supplier はない（引数がないので）。Map.forEach は BiConsumer、Map.replaceAll は BiFunction を取る

#### 基本データ型用の関数型インタフェース（きほんでーたがたようのかんすうがたいんたふぇーす / primitive specializations）

- 意味：int・long・double・boolean を、ボクシングせずに扱う版。IntPredicate・IntFunction<R>・ToIntFunction<T>・IntUnaryOperator・IntBinaryOperator・IntSupplier・BooleanSupplier など
- ポイント：メソッド名が変わるものに注意。IntSupplier は getAsInt、BooleanSupplier は getAsBoolean、ToIntFunction は applyAsInt、IntUnaryOperator は applyAsInt、IntPredicate は test、IntFunction は apply

#### 関数の合成（かんすうのごうせい / function composition）

- 意味：andThen・compose・and・or などの default メソッドで、小さな関数をつないで新しい関数を作ること
- ポイント：引数に null を渡すと、合成した時点で NullPointerException（Objects.requireNonNull で確かめている）。andThen の順は「左から右へ」実行される

### 05-1 関数型インタフェース

#### 問 jgold-05-o01

- 問：次のコードを実行した。結果として正しいものはどれか。

  ```
  @FunctionalInterface
  interface Calc {
    int apply(int a, int b);
    default int twice(int x) { return apply(x, 2); }
    static Calc plus() { return (a, b) -> a + b; }
    boolean equals(Object o);
    String toString();
  }
  // main メソッドの中
  Calc c = (a, b) -> a * b;
  System.out.println(c.apply(3, 4) + " " + c.twice(5));
  ```

- ア：コンパイルエラーになる（抽象メソッドが 3 つある）
- イ：コンパイルエラーになる（関数型インタフェースに default メソッドは書けない）
- ウ：12 10 と表示される
- エ：12 7 と表示される
- 正解：ウ
- 解説：equals と toString は Object の public メソッドと同じなので、抽象メソッドとして数えない。default と static も数えないので、抽象メソッドは apply だけで関数型インタフェースになる。c.apply(3, 4) は 12、twice(5) は apply(5, 2) で 10。
- アの意味：Object の public メソッドと同じシグネチャのものは数えない（JLS 9.8）。
- イの意味：default・static・private メソッドはいくつあってもよい。
- ウの意味：正しい。
- エの意味：twice は c の apply（掛け算）を使う。plus（足し算）は呼んでいない。
- 出典：オリジナル問題（根拠：JLS 9.8 Functional Interfaces、API java.lang.FunctionalInterface／JDK 17 での実行結果）

#### 問 jgold-05-o02

- 問：次のうち、@FunctionalInterface を付けてもコンパイルエラーにならないものはどれか。A と B は `String go(String s);` だけを持つインタフェースとする。
- ア：`interface Bad { void a(); void b(); }`
- イ：`interface D extends Runnable { void stop(); }`
- ウ：`interface E { }`
- エ：`interface C extends A, B { default String twice(String s) { return go(go(s)); } }`
- 正解：エ
- 解説：C は A と B から同じシグネチャの go を受け継ぐが、1 つと数えるので抽象メソッドは 1 つ。default メソッドは数えない。
- アの意味：抽象メソッドが 2 つ。「Unexpected @FunctionalInterface annotation（multiple non-overriding abstract methods found in interface Bad）」になる。
- イの意味：Runnable の run と stop で抽象メソッドが 2 つになり、同じエラー。
- ウの意味：抽象メソッドが 0 個のインタフェースは関数型インタフェースではない（no abstract method found）。
- エの意味：正しい。`C c = x -> x + "!";` で c.go("a") は a!、c.twice("b") は b!! になる。
- 出典：オリジナル問題（根拠：JLS 9.8（override-equivalent なメソッドは 1 つ）・9.6.4.9 @FunctionalInterface／JDK 17 でのコンパイルと実行の結果）

#### 問 jgold-05-o03

- 問：main メソッドの中に書いたとき、コンパイルできるものはどれか。
- ア：`Object o = () -> System.out.println("x");`
- イ：`var r = () -> System.out.println("x");`
- ウ：`Object o = (Runnable) () -> System.out.println("x");`
- エ：`Runnable r = () -> { return 1; };`
- 正解：ウ
- 解説：ラムダ式は、ターゲット型（関数型インタフェース）がないと型が決まらない。キャストで Runnable を与えれば、Runnable のインスタンスとして Object に代入できる。
- アの意味：Object は関数型インタフェースでないので「Object is not a functional interface」。
- イの意味：var では型を決められず「cannot infer type for local variable r（lambda expression needs an explicit target-type）」。
- ウの意味：正しい。
- エの意味：Runnable の run は void なので値を返せない（bad return type in lambda expression、unexpected return value）。
- 出典：オリジナル問題（根拠：JLS 15.27.3 Type of a Lambda Expression・14.4.1（var にラムダ式は使えない）／JDK 17 でのコンパイル結果）

### 05-2 ラムダ式の書き方

#### 問 jgold-05-o04

- 問：main メソッドの中に書いたとき、コンパイルできるものはどれか。
- ア：`Function<Integer, Integer> f = (int x) -> x + 1;`
- イ：`BiFunction<Integer, Integer, Integer> f = (var x, var y) -> x + y;`
- ウ：`BiFunction<Integer, Integer, Integer> f = (Integer x, y) -> x + y;`
- エ：`Supplier<String> s = () -> { "hi"; };`
- 正解：イ
- 解説：Java 11 から、ラムダ式の引数に var を書ける。全部の引数にそろえれば問題ない。
- アの意味：ターゲット型の引数は Integer なので、int と書くと「incompatible parameter types in lambda expression」。
- イの意味：正しい。f.apply(1, 2) は 3。
- ウの意味：型ありと型なしを混ぜると「invalid lambda parameter declaration（cannot mix implicitly-typed and explicitly-typed parameters）」。
- エの意味：ブロックの中は文でなければならず、"hi"; は「not a statement」。`() -> { return "hi"; }` か `() -> "hi"` と書く。
- 出典：オリジナル問題（根拠：JLS 15.27.1 Lambda Parameters・15.27.2 Lambda Body／JDK 17 でのコンパイル結果）

#### 問 jgold-05-o05

- 問：次のコードについて正しいものはどれか。

  ```
  String s = "outer";
  Function<String, String> f = s -> s.toUpperCase();
  ```

- ア：コンパイルでき、f.apply("a") は "A" を返す
- イ：コンパイルでき、f.apply("a") は "OUTER" を返す
- ウ：コンパイルエラーになる（ラムダ式の引数 s が、外側のローカル変数 s と重なる）
- エ：コンパイルエラーになる（s が effectively final でない）
- 正解：ウ
- 解説：ラムダ式の本体は外側と同じスコープとして扱われるので、外側にあるローカル変数と同じ名前の引数を宣言できない。「variable s is already defined in method main(String[])」になる。
- アの意味：無名クラスなら別のスコープなので同じ名前の引数を使えるが、ラムダ式は使えない。
- イの意味：同じく、コンパイルの段階でエラーになる。
- ウの意味：正しい。
- エの意味：外側の s は代入し直していないので effectively final。問題は名前の重なり。
- 出典：オリジナル問題（根拠：JLS 15.27.2（ラムダ式の本体は外側と同じスコープ）・6.4 Shadowing and Obscuring／JDK 17 でのコンパイル結果）

#### 問 jgold-05-o06

- 問：次のコードについて正しいものはどれか。

  ```
  int x = 5;
  Runnable r = () -> { int x = 10; System.out.println(x); };
  ```
