## 03-1 Comparable と自然順序

### まとめ表

| | Comparable<T> | Comparator<T> |
| :-: | :-: | :-: |
| パッケージ | java.lang | java.util |
| メソッド | int compareTo(T o) | int compare(T a, T b) |
| 実装する場所 | 並べたいクラス自身 | 別のクラスやラムダ式 |
| 順序の数 | 1 つ（自然順序） | いくつでも作れる |
| 使う例 | Collections.sort(list)・new TreeSet<>() | list.sort(c)・new TreeSet<>(c) |

### 自然順序

#### Comparable インタフェース（こんぱらぶるいんたふぇーす / Comparable）

- 意味：クラス自身に「自然順序」を持たせるためのインタフェース（java.lang）。compareTo(T o) の 1 つだけを持つ
- ポイント：自分が小さければ負、等しければ 0、大きければ正を返す。String・Integer・LocalDate などは実装済み。実装していないクラスの List を Collections.sort(list) に渡すとコンパイルエラー、TreeSet に add すると実行時に ClassCastException

#### 自然順序（しぜんじゅんじょ / natural ordering）

- 意味：Comparable の compareTo で決まる、そのクラスの標準の並び順
- ポイント：String は文字コードの辞書順（大文字が小文字より前）、数は小さい順、日付は古い順。Comparator.naturalOrder() はこの順、Comparator.reverseOrder()・Collections.reverseOrder() はその逆

#### compareTo の戻り値（こんぺあとぅーのもどりち / result of compareTo）

- 意味：比べた結果を符号で返す int。値の大きさには意味がない
- ポイント：String の compareTo は、最初に違う文字のコードの差（"apple" と "apricot" は 'p' − 'r' で −2）。片方が前の部分なら長さの差。"A".compareTo("a") は −32。判定は「負・0・正」だけを見る
- 例：`Integer.valueOf(3).compareTo(7)` → −1

#### equals との一貫性（いこーるずとのいっかんせい / consistent with equals）

- 意味：compareTo（compare）が 0 になるのは equals が true のときだけ、という性質
- ポイント：一貫していなくてもエラーにはならないが、TreeSet・TreeMap は compareTo が 0 なら同じ要素とみなすので、equals では違う要素が捨てられる。値段だけで比べると、値段が同じ別の商品が TreeSet に 1 つしか入らない

## 03-2 Comparator の作り方とつなぎ方

### まとめ表

| メソッド | 種類 | 意味 |
| :-: | :-: | :-: |
| comparing(キーの関数) | static | キーの自然順序で比べる |
| comparing(キーの関数, 比較器) | static | キーを渡した比較器で比べる |
| comparingInt・Long・Double | static | 基本データ型のキーで比べる |
| thenComparing(…) | default | 前の比較が 0 のときだけ次で比べる |
| reversed() | default | それまでにつないだ全体を逆にする |
| naturalOrder()・reverseOrder() | static | 自然順序・その逆 |
| nullsFirst(c)・nullsLast(c) | static | null を先頭・末尾に置き、残りは c で比べる |

### 比較器を作る

#### Comparator インタフェース（こんぱれーたいんたふぇーす / Comparator）

- 意味：2 つのオブジェクトの順序を決める関数型インタフェース（java.util）。抽象メソッドは compare(T a, T b)
- ポイント：equals も宣言されているが、Object のメソッドなので抽象メソッドとして数えない。ラムダ式・メソッド参照・クラスで作れる。`(a, b) -> b.length() - a.length()` は長い順

#### Comparator.comparing（こんぱれーたーどっとこんぺありんぐ / comparing）

- 意味：要素からキーを取り出す関数を受け取り、そのキーで比べる Comparator を作る static メソッド
- ポイント：`Comparator.comparing(String::length)` は長さの短い順。第 2 引数に比較器を渡すと、キーをその順で比べる（`comparing(P::name, Comparator.reverseOrder())`）
- 例：`list.sort(Comparator.comparing(P::age));`

#### comparingInt（こんぺありんぐいんと / comparingInt）

- 意味：int のキーを取り出す関数（ToIntFunction）で比べる Comparator を作る static メソッド。comparingLong・comparingDouble もある
- ポイント：ボクシングせずに比べられる。`Comparator.comparingInt(String::length)`

#### thenComparing（でんこんぺありんぐ / thenComparing）

- 意味：最初の比較で同じ（0）だったときに使う、2 番目の比較を足す default メソッド
- ポイント：引数はキーの関数でも Comparator でもよい。thenComparingInt などもある。並びの優先順位は、左に書いたものが先

#### reversed（りばーすど / reversed）

- 意味：Comparator の順を逆にした Comparator を返す default メソッド
- ポイント：それまでにつないだ全体が逆になる。`comparing(a).thenComparing(b).reversed()` は a も b も逆。a だけを逆にしたいなら `comparing(a).reversed().thenComparing(b)`

#### ラムダ式の型推論と reversed（らむだしきのかたすいろんとりばーすど / target typing in method chains）

- 意味：`Comparator.comparing(s -> s.length()).reversed()` のように、メソッドをつなぐと、ラムダ式の引数の型が推論されず Object になる問題
- ポイント：comparing の結果に reversed() を呼ぶ時点では、代入先（List<String> の sort）から型を伝えられない。s は Object になり「cannot find symbol: method length()」。`(String s) -> s.length()` と型を書くか、`String::length` を使うと通る

#### naturalOrder と reverseOrder（なちゅらるおーだーとりばーすおーだー / naturalOrder, reverseOrder）

- 意味：Comparator.naturalOrder() は自然順序の、Comparator.reverseOrder() はその逆の Comparator を返す static メソッド。Collections.reverseOrder() も逆順を返す
- ポイント：static なインタフェースメソッドは、インタフェース名で呼ぶ。`c.reverseOrder()` のようにインスタンスから呼ぶと「illegal static interface method call」のコンパイルエラー

#### nullsFirst と nullsLast（なるずふぁーすととなるずらすと / nullsFirst, nullsLast）

- 意味：null を最初（最後）に並べ、null 以外は渡した Comparator で比べる Comparator を作る static メソッド
- ポイント：自然順序の sort では null の compareTo を呼べず NullPointerException になる。null を含むときに使う
- 例：`list.sort(Comparator.nullsFirst(Comparator.naturalOrder()));` → [null, a, b]

#### String.CASE_INSENSITIVE_ORDER（すとりんぐどっとけーすいんせんしてぃぶおーだー / CASE_INSENSITIVE_ORDER）

- 意味：大文字と小文字を区別せずに比べる、String クラスの Comparator 定数
- ポイント：自然順序では "B" が "a" より前だが、これを使うと a・B・b・C の順。区別しないので "B" と "b" は 0（同じ）になる

### ソートのしかた

#### List.sort（りすとどっとそーと / List.sort）

- 意味：List の default メソッドで、渡した Comparator の順に並べ替える。null を渡すと自然順序
- ポイント：並べ替えは安定（stable）。同じ順位の要素は元の順番を保つ。変更できない List（List.of）では UnsupportedOperationException。Arrays.asList の List は set できるので並べ替えられる

#### Collections.sort（これくしょんずどっとそーと / Collections.sort）

- 意味：List を並べ替える static メソッド。sort(list) は自然順序、sort(list, c) は Comparator の順
- ポイント：sort(list) の要素は Comparable でなければならず、そうでないとコンパイルエラー（no suitable method found for sort(List<Item>)）。中では list.sort を呼ぶ

#### 安定なソート（あんていなそーと / stable sort）

- 意味：比べて同じ順位になった要素どうしが、並べ替える前の順番のまま残るソート
- ポイント：List.sort・Collections.sort・オブジェクトの Arrays.sort は安定（API ドキュメントが保証）。名前で並べたあと年齢で並べると、同じ年齢の中では名前順が残る

#### Arrays.sort（あれいずどっとそーと / Arrays.sort）

- 意味：配列を並べ替える static メソッド。sort(a)、範囲を指定する sort(a, from, to)、Comparator を渡す sort(a, c) がある
- ポイント：範囲は from を含み to を含まない。Comparator を渡せるのはオブジェクトの配列だけで、int[] に Comparator.reverseOrder() を渡すとコンパイルエラー。int[] を逆順にしたいなら Integer[] にする

## 03-3 Collections と Arrays の便利なメソッド

### まとめ表

| メソッド | 動き |
| :-: | :-: |
| reverse(list) | 順番を逆にする（並べ替えではない） |
| max・min(coll[, c]) | 最大・最小。c を渡すとその順で |
| binarySearch(list, key) | 昇順に並んだ list から探す。ないと −(挿入位置)−1 |
| frequency(c, o) | o の出てくる回数 |
| disjoint(c1, c2) | 共通の要素がなければ true |
| nCopies(n, o) | o を n 個並べた変更できない List |
| swap・fill・addAll | 入れ替え・全部を同じ値に・まとめて追加 |
| emptyList・unmodifiableList・synchronizedList | 空の List・読み取り専用のビュー・同期化したビュー |

### 探す・数える

#### Collections.binarySearch（ばいなりさーち / binarySearch）

- 意味：昇順に並んだ List から、二分探索で要素を探す static メソッド。見つかればその添字を返す
- ポイント：見つからないと「−(挿入位置) − 1」を返す。[1, 3, 5, 7] で 4 は挿入位置 2 なので −3、9 は挿入位置 4 なので −5。並んでいない List で使うと結果は保証されない。Comparator で並べた List には、同じ Comparator を渡す

#### Collections.max と min（まっくすとみん / max, min）

- 意味：コレクションの最大・最小の要素を返す static メソッド。Comparator を渡すとその順で決める
- ポイント：min(list, Comparator.reverseOrder()) は、逆順で最小、つまり自然順序の最大。空のコレクションでは NoSuchElementException

#### Collections.frequency（ふりーくえんしー / frequency）

- 意味：コレクションの中で、指定した要素（equals で等しいもの）が何個あるかを返す static メソッド
- ポイント：null も数えられる

#### Collections.disjoint（でぃすじょいんと / disjoint）

- 意味：2 つのコレクションに共通の要素が 1 つもなければ true を返す static メソッド
- ポイント：1 つでも共通があれば false。名前に反して「重なっている」とき false
- 語の意味：disjoint＝ばらばらの、交わらない

### 並べる・作る

#### Collections.reverse（りばーす / reverse）

- 意味：List の要素の順番をそのまま逆にする static メソッド
- ポイント：大きい順に並べ替えるのではない。[3, 1, 2] は [2, 1, 3] になる。大きい順にしたいなら sort(list, Collections.reverseOrder())

#### Collections.swap・fill・addAll（すわっぷ・ふぃる・あどおーる / swap, fill, addAll）

- 意味：swap(list, i, j) は 2 つの要素を入れ替え、fill(list, o) は全部を o にし、addAll(c, e...) は要素をまとめて足す static メソッド
- ポイント：fill に subList を渡すと、その範囲だけを書き換えられる（subList は元の List のビュー）

#### Collections.nCopies（えぬこぴーず / nCopies）

- 意味：同じオブジェクトを n 個並べた、変更できない List を返す static メソッド
- ポイント：`new ArrayList<>(Collections.nCopies(3, 0))` で、0 が 3 つの変更できる List を作れる

#### Collections.emptyList（えんぷてぃりすと / emptyList）

- 意味：要素のない、変更できない List を返す static メソッド。emptySet・emptyMap もある
- ポイント：add すると UnsupportedOperationException。「結果がないとき null の代わりに返す」のに使う

#### 同期化したビュー（どうきかしたびゅー / synchronized view）

- 意味：Collections.synchronizedList(list) などが返す、メソッドの呼び出しを同期化した元のコレクションのビュー
- ポイント：ビューなので、元とつながっている。回すときは、ビュー自身で synchronized して回す必要がある（API ドキュメント）。並行処理用のコレクション（#13）とは別物

### 03-1 Comparable と自然順序

#### 問 jgold-03-o01

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  record Item(String name, int price) implements Comparable<Item> {
    public int compareTo(Item o) { return Integer.compare(price, o.price); }
    public String toString() { return name; }
  }
  // main メソッドの中
  List<Item> list = new ArrayList<>(List.of(new Item("b", 2), new Item("a", 3), new Item("c", 1)));
  Collections.sort(list);
  System.out.println(list);
  ```

- ア：[a, b, c]
- イ：[c, b, a]
- ウ：[a, c, b]
- エ：[b, a, c]
- 正解：イ
- 解説：Collections.sort(list) は自然順序（compareTo）で並べる。compareTo は price を比べるので、price の小さい順に c(1)・b(2)・a(3)。
- アの意味：name の順で並べたまちがい。compareTo は price を比べている。
- イの意味：正しい。
- ウの意味：price の大きい順でも name の順でもない。
- エの意味：並べ替える前の順番のまま。sort は並べ替える。
- 出典：オリジナル問題（根拠：API Comparable・Collections.sort(List)／JDK 17 での実行結果）

#### 問 jgold-03-o02

- 問：次のコードについて正しいものはどれか。

  ```
  record Item(String name, int price) {}
  // main メソッドの中
  List<Item> list = new ArrayList<>(List.of(new Item("b", 2), new Item("a", 3)));
  Collections.sort(list);
  ```

- ア：name の順に並べ替えられる
- イ：実行時に ClassCastException が投げられる
- ウ：レコードの最初のコンポーネント（name）の順に並べ替えられる
- エ：コンパイルエラーになる
- 正解：エ
- 解説：Collections.sort(List<T>) は `T extends Comparable<? super T>` を求める。Item は Comparable を実装していないので、コンパイルエラー（no suitable method found for sort(List<Item>)）。
- アの意味：レコードは自動では Comparable にならない。
- イの意味：TreeSet の add なら実行時の ClassCastException だが、Collections.sort は型の境界でコンパイル時に止まる。
- ウの意味：レコードに自動で作られるのは equals・hashCode・toString とアクセサだけ。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：API Collections.sort（<T extends Comparable<? super T>>）、JLS 8.10.3／JDK 17 でのコンパイル結果）

#### 問 jgold-03-o03

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  System.out.println("apple".compareTo("apricot") + " " + "b".compareTo("a") + " " + "A".compareTo("a") + " " + Integer.valueOf(3).compareTo(7));
  ```

- ア：-2 1 -32 -1
- イ：-1 1 -1 -1
- ウ：-2 1 32 -4
- エ：2 -1 -32 1
- 正解：ア
- 解説：String の compareTo は最初に違う文字のコードの差を返す。"apple" と "apricot" は 3 文字目の 'p'(112) と 'r'(114) で −2。'b' − 'a' は 1。'A'(65) − 'a'(97) は −32。Integer の compareTo は −1・0・1 を返し、3 は 7 より小さいので −1。
- アの意味：正しい。
- イの意味：String の compareTo が −1・0・1 だけを返すと考えたまちがい。差をそのまま返す。
- ウの意味：大文字のほうが文字コードが小さいので、"A".compareTo("a") は負。Integer の compareTo は差ではなく −1。
- エの意味：符号をすべて逆に考えたまちがい。呼び出した側が小さいと負。
- 出典：オリジナル問題（根拠：API String.compareTo（the difference of the two character values）・Integer.compareTo／JDK 17 での実行結果）

#### 問 jgold-03-o04

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  record Item(String name, int price) implements Comparable<Item> {
    public int compareTo(Item o) { return Integer.compare(price, o.price); }
  }
  // main メソッドの中
  Set<Item> set = new TreeSet<>(List.of(new Item("pen", 100), new Item("cup", 100), new Item("box", 50)));
  Set<Item> hs = new HashSet<>(List.of(new Item("pen", 100), new Item("cup", 100), new Item("box", 50)));
  System.out.println(set.size() + " " + hs.size());
  ```

- ア：3 3
- イ：2 2
- ウ：2 3
- エ：3 2
- 正解：ウ
- 解説：TreeSet は compareTo が 0 なら同じ要素とみなすので、price が同じ pen と cup は 1 つしか入らず 2。HashSet はレコードの equals（name と price の両方）で判断するので 3 つとも入る。compareTo が equals と一貫していない例。
- アの意味：TreeSet も equals で重複を判断すると考えたまちがい。
- イの意味：HashSet も compareTo で判断すると考えたまちがい。
- ウの意味：正しい。
- エの意味：TreeSet と HashSet の結果を逆にしたまちがい。
- 出典：オリジナル問題（根拠：API Comparable（consistent with equals）・TreeSet（uses compareTo）／JDK 17 での実行結果）

#### 問 jgold-03-o05

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  List<String> list = new ArrayList<>(List.of("b", "C", "a", "B"));
  list.sort(null);
  System.out.print(list + " ");
  list.sort(String.CASE_INSENSITIVE_ORDER);
  System.out.println(list);
  ```

- ア：[a, b, B, C] [a, B, b, C]
- イ：[B, C, a, b] [a, b, B, C]
- ウ：コンパイルエラーになる（sort に null は渡せない）
- エ：[B, C, a, b] [a, B, b, C]
- 正解：エ
- 解説：List.sort(null) は自然順序で並べ、大文字が小文字より前なので [B, C, a, b]。CASE_INSENSITIVE_ORDER は大文字小文字を区別しないので a・b・c の順になり、"B" と "b" は同じ順位で、安定なソートなので元の順（B が先）のまま。
- アの意味：自然順序で大文字と小文字を区別しないと考えたまちがい。
- イの意味：CASE_INSENSITIVE_ORDER で、"b" が "B" より前に移ると考えたまちがい。同じ順位なら元の順番を保つ。
- ウの意味：List.sort は null を受け付け、自然順序で並べる（API ドキュメント）。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：API List.sort（If the specified comparator is null then all elements in this list must implement the Comparable interface）・String.CASE_INSENSITIVE_ORDER／JDK 17 での実行結果）

#### 問 jgold-03-o06
