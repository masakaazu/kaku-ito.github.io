## 13-1 ExecutorService と Future

### まとめ表

| メソッド | 引数 | 戻り値 |
| :-: | :-: | :-: |
| execute | Runnable | void |
| submit | Runnable | Future<?>（get は null） |
| submit | Runnable, 結果 | Future<T>（get は結果） |
| submit | Callable<T> | Future<T> |
| invokeAll | Collection<Callable<T>> | List<Future<T>>（全部終わるまで待つ） |
| invokeAny | Collection<Callable<T>> | T（どれか 1 つの結果） |

### スレッドプール

#### ExecutorService（えぐぜきゅーたーさーびす / ExecutorService）

- 意味：タスク（Runnable・Callable）を受け取り、スレッドプールのスレッドで実行するしくみのインタフェース。Executor を継承する
- ポイント：使い終わったら shutdown する（しないと、デーモンでないスレッドが残って JVM が終わらない）。Executors の static メソッドで作る

#### Executors（えぐぜきゅーたーず / Executors）

- 意味：ExecutorService を作る static メソッドを集めたクラス
- ポイント：newSingleThreadExecutor（1 スレッド、出した順に実行）、newFixedThreadPool(n)（n スレッド）、newCachedThreadPool（必要なだけ作って再利用）、newScheduledThreadPool(n)（時間を決めて実行）。スレッド名は「pool-番号-thread-番号」

#### execute と submit（えぐぜきゅーととさぶみっと / execute, submit）

- 意味：execute は Executor のメソッドで Runnable を実行し、何も返さない。submit は Runnable・Callable を実行して Future を返す
- ポイント：execute に Callable は渡せない（Callable<Integer> cannot be converted to Runnable）。submit(Runnable) の Future の get は null。タスクの中の例外は、execute ではそのスレッドで表示され、submit では Future.get で ExecutionException として受け取る

#### Callable（こーらぶる / Callable）

- 意味：値を返し、チェック例外を投げられるタスクを表す関数型インタフェース。メソッドは `V call() throws Exception`
- ポイント：Runnable の run は void で throws なし。ラムダ式 `() -> 42` は submit では Callable<Integer> として扱われる。Thread には直接渡せない

#### Future（ふゅーちゃー / Future）

- 意味：非同期のタスクの結果を、あとで受け取るためのインタフェース
- ポイント：get は終わるまで待つ。get(時間, 単位) は時間切れで TimeoutException。タスクの中の例外は ExecutionException に包まれ、getCause() で元の例外が取れる。cancel(true) で中止（実行中なら割り込み）、そのあと get は CancellationException。isDone は、正常・例外・中止のどれで終わっても true

#### shutdown と shutdownNow（しゃっとだうんとしゃっとだうんなう / shutdown, shutdownNow）

- 意味：shutdown は新しいタスクを受け付けなくし、受け付け済みのタスクは最後まで実行する。shutdownNow は実行中のタスクに割り込み、まだ始まっていないタスクの List<Runnable> を返す
- ポイント：shutdown のあとに execute・submit すると RejectedExecutionException。shutdown は待たないので、終わるのを待つなら awaitTermination(時間, 単位)。isShutdown は shutdown を呼んだら true、isTerminated はすべてのタスクが終わったら true

#### ScheduledExecutorService（すけじゅーるどえぐぜきゅーたーさーびす / ScheduledExecutorService）

- 意味：時間を決めて、または一定の間隔でタスクを実行する ExecutorService
- ポイント：schedule(タスク, 遅れ, 単位) は 1 回だけ（Callable も可、ScheduledFuture を返す）。scheduleAtFixedRate(Runnable, 最初の遅れ, 周期, 単位) は開始の間隔を一定に、scheduleWithFixedDelay は前の終わりから次の開始までを一定にする。くり返しのほうは Runnable だけ

## 13-2 並行コレクション

### まとめ表

| クラス | 特徴 |
| :-: | :-: |
| CopyOnWriteArrayList・CopyOnWriteArraySet | 書き込みのたびに配列をコピー。イテレータは作った時点のスナップショット |
| ConcurrentHashMap | 部分的なロックで高速。null のキー・値は不可 |
| ConcurrentSkipListMap・ConcurrentSkipListSet | 並行の TreeMap・TreeSet（並ぶ） |
| ArrayBlockingQueue・LinkedBlockingQueue | 空なら取り出しを、満杯なら追加を待つ |
| Collections.synchronizedList など | メソッドごとに同期（拡張 for は外で同期が必要） |

### コレクション

#### 並行コレクション（へいこうこれくしょん / concurrent collections）

- 意味：複数のスレッドから同時に使っても壊れないように作られた、java.util.concurrent のコレクション
- ポイント：ふつうの ArrayList を拡張 for の途中で add すると ConcurrentModificationException。並行コレクションは、走査中に変更しても ConcurrentModificationException を投げない

#### CopyOnWriteArrayList（こぴーおんらいとあれいりすと / CopyOnWriteArrayList）

- 意味：add・set・remove のたびに中の配列をコピーして作り直す List
- ポイント：イテレータは作った時点の配列を見る（スナップショット）ので、途中で add した要素は走査に出てこない。イテレータの remove は UnsupportedOperationException。読み込みが多く、書き込みが少ないときに向く

#### ConcurrentHashMap（こんかれんとはっしゅまっぷ / ConcurrentHashMap）

- 意味：複数のスレッドから安全に、速く使える Map。ConcurrentMap の実装
- ポイント：null のキーも値も入れられない（NullPointerException）。HashMap は null を入れられる。merge・compute・computeIfAbsent・putIfAbsent は原子的に動くので、4 スレッドで 1 万回ずつ merge しても 40000 になる

#### ConcurrentMap（こんかれんとまっぷ / ConcurrentMap）

- 意味：putIfAbsent・replace・remove(キー, 値) などを原子的に行う Map のインタフェース
- ポイント：putIfAbsent はキーがなければ入れて null を返し、あればそのままで今の値を返す

#### ConcurrentSkipListMap・ConcurrentSkipListSet（こんかれんとすきっぷりすと / ConcurrentSkipListMap, ConcurrentSkipListSet）

- 意味：キーの自然順序（または Comparator）で並ぶ、並行の Map と Set。TreeMap・TreeSet の並行版
- ポイント：firstKey・headMap など、NavigableMap・NavigableSet のメソッドが使える

#### BlockingQueue（ぶろっきんぐきゅー / BlockingQueue）

- 意味：空のときの取り出しや、満杯のときの追加を待つことができるキュー。生産者・消費者の受け渡しに使う
- ポイント：put・take は待つ。offer・poll は待たずに false・null を返す（時間を決めて待つ版もある）。add は満杯だと IllegalStateException。ArrayBlockingQueue は大きさ固定、LinkedBlockingQueue は指定しなければほぼ無制限

#### Collections.synchronizedList（これくしょんずしんくろないずどりすと / Collections.synchronizedList）

- 意味：ふつうの List の各メソッドを synchronized で包んだ List を返すメソッド。synchronizedMap・synchronizedSet もある
- ポイント：1 回ずつのメソッドは安全だが、拡張 for の途中で add すると ConcurrentModificationException になる。走査するときは、自分でその List を synchronized する必要がある

## 13-3 同期の道具と Flow

### まとめ表

| Flow のインタフェース | 役割 | 主なメソッド |
| :-: | :-: | :-: |
| Publisher<T> | データを出す | subscribe(Subscriber) |
| Subscriber<T> | データを受ける | onSubscribe・onNext・onError・onComplete |
| Subscription | 2 つをつなぐ | request(n)・cancel() |
| Processor<T, R> | 受けて変換して出す | Subscriber と Publisher の両方 |

### 同期の道具

#### CountDownLatch（かうんとだうんらっち / CountDownLatch）

- 意味：数を決めて作り、countDown で 1 ずつ減らし、0 になるまで await で待つ同期の道具
- ポイント：0 になったらもう使い回せない（数を戻せない）。await(時間, 単位) は 0 になれば true、時間切れなら false
- 語の意味：latch＝かけがね

#### CyclicBarrier（さいくりっくばりあ / CyclicBarrier）

- 意味：決めた数のスレッドが await でそろうまで待ち、そろったら全員を進ませる同期の道具。そろったときに 1 回動く処理（バリア・アクション）も渡せる
- ポイント：そろうたびに使い回せる（cyclic）。CountDownLatch は「0 になるのを待つ」、CyclicBarrier は「お互いがそろうのを待つ」
- 語の意味：cyclic＝くり返しの／barrier＝障壁

### Flow

#### Flow（ふろー / java.util.concurrent.Flow）

- 意味：データを出す側（Publisher）と受ける側（Subscriber）を、受ける側の処理できる量に合わせてつなぐための、4 つのインタフェースをまとめたクラス（Java 9〜、リアクティブ・ストリーム）
- ポイント：受ける側が request(n) で「n 個までなら受けられる」と伝える（背圧 back pressure）。要求した数より多くは onNext が呼ばれない

#### Publisher・Subscriber・Subscription（ぱぶりっしゃー・さぶすくらいばー・さぶすくりぷしょん / Publisher, Subscriber, Subscription）

- 意味：Publisher はデータを出す側、Subscriber は受ける側、Subscription は両者の約束（request・cancel）
- ポイント：呼ばれる順は onSubscribe（1 回）→ onNext（0 回以上）→ onComplete か onError（どちらか 1 回）。onSubscribe の中で request を呼ばないと onNext は来ない

#### SubmissionPublisher（さぶみっしょんぱぶりっしゃー / SubmissionPublisher）

- 意味：JDK にある Publisher の実装。submit でデータを出し、close で終わりを伝える
- ポイント：Subscriber への配信は別のスレッド（既定は ForkJoinPool の共通プール）で行う。AutoCloseable なので try-with-resources で close できる。close のあと、残りのデータが届いてから onComplete が呼ばれる

#### 背圧（はいあつ / back pressure）

- 意味：受ける側が、処理できる量を出す側に伝えて、データの流れの速さを調整すること
- ポイント：Subscriber が request(2) だけなら、5 個 submit しても onNext は 2 回だけ呼ばれる。残りは request されるまで待つ

#### 問 jgold-13-o01

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  ExecutorService es = Executors.newSingleThreadExecutor();
  es.execute(() -> System.out.print("A"));
  Future<?> f = es.submit(() -> System.out.print("B"));
  Future<Integer> g = es.submit(() -> 42);
  System.out.println(" " + f.get() + " " + g.get());
  es.shutdown();
  ```

- ア：AB null 42
- イ：AB B 42
- ウ：コンパイルエラーになる（execute に戻り値はない）
- エ：AB 0 42
- 正解：ア
- 解説：1 スレッドのプールなので、出した順に A、B が表示される。submit(Runnable) の Future の get は null、submit(Callable) の get は 42。
- アの意味：正しい。
- イの意味：Runnable は値を返さないので、get は null。
- ウの意味：execute の戻り値は使っていないので、問題ない。
- エの意味：結果がないときは 0 ではなく null。
- 出典：オリジナル問題（根拠：API Executor.execute・ExecutorService.submit・Future.get、Executors.newSingleThreadExecutor／JDK 17 での実行結果）

#### 問 jgold-13-o29

- 問：SubmissionPublisher の説明として正しいものはどれか。
- ア：Subscriber への配信は、submit を呼んだスレッドの中で同期的に行われる
- イ：AutoCloseable ではないので、try-with-resources では使えない

#### 問 jgold-13-o30

- 問：次のうち、ExecutorService のメソッドとして存在しないものはどれか。
- ア：invokeAll
- イ：awaitTermination
- ウ：shutdownNow
- エ：start
- 正解：エ
- 解説：ExecutorService にタスクを動かすための start メソッドはない。タスクは execute・submit・invokeAll・invokeAny で渡す。start は Thread のメソッド。
- アの意味：すべてのタスクを実行して、Future のリストを返す。
- イの意味：shutdown のあと、終わるのを時間を決めて待つ。
- ウの意味：実行中に割り込み、待っているタスクのリストを返す。
- エの意味：正しい（存在しない）。
- 出典：オリジナル問題（根拠：API ExecutorService）
