## 06-1 ストリームのしくみ

### まとめ表

| 段階 | 例 | 戻り値 | いつ動くか |
| :-: | :-: | :-: | :-: |
| 生成（ソース） | list.stream()・Stream.of | Stream | ― |
| 中間操作 | filter・map・sorted・peek | Stream | 終端操作が呼ばれたとき |
| 終端操作 | forEach・collect・count・findFirst | Stream 以外（void・値・Optional） | すぐ |

### パイプライン

#### ストリーム（すとりーむ / stream）

- 意味：要素の並びに対して、filter や map などの処理をつなげて一度に行うためのしくみ。java.util.stream.Stream など
- ポイント：コレクションと違って要素を保存しない。元のコレクションは変わらない。一度しか使えない（2 回目の操作で IllegalStateException「stream has already been operated upon or closed」）
- 例：`list.stream().filter(s -> s.length() > 1).map(String::toUpperCase).forEach(System.out::println);`

#### ストリーム・パイプライン（すとりーむぱいぷらいん / stream pipeline）

- 意味：ソース、0 個以上の中間操作、1 つの終端操作をつないだもの
- ポイント：中間操作は新しい Stream を返すだけで、処理はまだしない。終端操作を呼んだときに初めて全体が動く

#### 中間操作（ちゅうかんそうさ / intermediate operation）

- 意味：Stream を受けて新しい Stream を返す操作。filter・map・flatMap・distinct・sorted・peek・limit・skip・takeWhile・dropWhile など
- ポイント：遅延評価される。終端操作がなければ、filter や map のラムダ式は 1 回も呼ばれない

#### 終端操作（しゅうたんそうさ / terminal operation）

- 意味：パイプラインを実行して、結果（値・コレクション・Optional）や副作用を出す操作。forEach・collect・reduce・count・findFirst・anyMatch など
- ポイント：終端操作のあと、その Stream は使えない。中間操作で作った別の Stream を使った場合も、元の Stream は「使用済み」になる

#### 遅延評価（ちえんひょうか / laziness）

- 意味：中間操作は、終端操作が要素を求めたときに初めて実行されるというしくみ
- ポイント：要素は 1 つずつ、パイプライン全体を通って流れる（「全部 filter してから全部 map」ではない）。peek を入れると、要素ごとに filter → map の順に交互に出力される

#### 短絡操作（たんらくそうさ / short-circuiting operation）

- 意味：全部の要素を処理しなくても結果が出せる操作。中間操作の limit・takeWhile、終端操作の findFirst・anyMatch など
- ポイント：無限ストリームでも、短絡操作があれば終わる。findFirst なら、最初に条件を満たした要素のところで止まり、残りの要素は filter も呼ばれない

#### 状態を持つ中間操作（じょうたいをもつちゅうかんそうさ / stateful intermediate operation）

- 意味：前に見た要素を覚えておく必要がある中間操作。sorted・distinct・limit・skip など
- ポイント：sorted は全部の要素を見ないと最初の要素を決められないので、無限ストリームで sorted を使うと終わらない（終端操作を呼ぶまでは何も起きない）。filter・map は状態を持たない（stateless）

## 06-2 ストリームの生成

### まとめ表

| 書き方 | 中身 |
| :-: | :-: |
| list.stream() | コレクションの要素 |
| Stream.of(1, 2, 3) | 引数の要素 |
| Arrays.stream(arr, 1, 3) | 配列の添字 1〜2（3 は含まない） |
| IntStream.range(1, 5)・rangeClosed(1, 5) | 1〜4・1〜5 |
| Stream.iterate(1, n -> n * 2) | 1, 2, 4, 8…（無限） |
| Stream.iterate(1, n -> n < 20, n -> n * 3) | 1, 3, 9（条件付き） |
| Stream.generate(() -> "x") | x, x, x…（無限） |
| Stream.empty()・Stream.ofNullable(null) | 要素 0 個 |
| Stream.concat(a, b) | a のあとに b |
| "abc".chars() | IntStream（文字コード） |

### 生成の方法

#### Collection.stream（これくしょんすとりーむ / Collection.stream）

- 意味：コレクションの要素を順に流す Stream を返すメソッド。parallelStream なら並列ストリーム（#09）
- ポイント：ArrayList などは、終端操作が始まった時点の中身を流す（遅延バインディング）。stream() のあと、終端操作の前に add した要素も数えられる

#### Stream.of（すとりーむおぶ / Stream.of）

- 意味：引数に並べた値から Stream を作る static メソッド
- ポイント：int[] を渡すと、配列 1 つを要素とする Stream<int[]> になる（要素数 1）。int の要素を流したいなら Arrays.stream(int[]) か IntStream.of

#### Arrays.stream（あれいずすとりーむ / Arrays.stream）

- 意味：配列から Stream を作るメソッド。int[] なら IntStream、double[] なら DoubleStream、参照型の配列なら Stream<T>
- ポイント：`Arrays.stream(arr, 開始, 終了)` は終了の添字を含まない。Arrays.asList(int[]) は要素 1 つの List<int[]> になる点と並べて問われる

#### Stream.iterate（すとりーむいてれーと / Stream.iterate）

- 意味：最初の値と「次の値を作る関数」から、無限の Stream を作る static メソッド。Java 9 からは「続ける条件」を入れた 3 引数版もある
- ポイント：2 引数版は無限なので limit などで止める。3 引数版 `iterate(seed, hasNext, next)` は for 文と同じで、条件が false になったら終わる

#### Stream.generate（すとりーむじぇねれーと / Stream.generate）

- 意味：Supplier を呼び続けて、無限の Stream を作る static メソッド
- ポイント：要素どうしに関係がない（前の値を使わない）。limit で止める

#### IntStream.range（いんとすとりーむれんじ / IntStream.range, rangeClosed）

- 意味：連続した int の IntStream を作る static メソッド。range は終わりを含まず、rangeClosed は含む
- ポイント：range(1, 5) は 1〜4、rangeClosed(1, 5) は 1〜5。range(5, 1) のように始まりが大きいと要素 0 個（例外にならない）

#### Stream.ofNullable（すとりーむおぶなられぶる / Stream.ofNullable）

- 意味：値が null なら空の Stream、null でなければ要素 1 つの Stream を返す（Java 9〜）
- ポイント：Stream.of((String) null) は null を 1 つ持つ Stream になり、count は 1。ofNullable(null) は 0

#### Stream.concat（すとりーむこんかっと / Stream.concat）

- 意味：2 つの Stream をつなげて 1 つの Stream にする static メソッド
- ポイント：引数は 2 つだけ。つなげた元の Stream は使用済みになる。Stream.builder() の add で 1 つずつ足して build する方法もある

## 06-3 中間操作

### まとめ表

| 中間操作 | 引数 | すること |
| :-: | :-: | :-: |
| filter | Predicate | 条件に合う要素だけ残す |
| map | Function | 要素を変換（1 対 1） |
| flatMap | Function（Stream を返す） | 要素を Stream に展開して平らにつなぐ（1 対多） |
| mapMulti | BiConsumer（要素, 送り先） | 送り先に 0 個以上の要素を渡す（Java 16〜） |
| distinct | ― | 重複を取り除く（equals で判定） |
| sorted | なし・Comparator | 並べ替える |
| peek | Consumer | 要素をそのまま流し、途中で処理（デバッグ用） |
| limit・skip | long | 先頭 n 個だけ・先頭 n 個を飛ばす |
| takeWhile・dropWhile | Predicate | 条件を満たす間だけ取る・飛ばす |

### 変換

#### filter（ふぃるた / filter）

- 意味：Predicate が true を返した要素だけを残す中間操作
- ポイント：false の要素は後ろの操作（map など）に流れない

#### map（まっぷ / map）

- 意味：Function で要素を 1 対 1 に変換する中間操作
- ポイント：IntStream の map は IntUnaryOperator（int → int）なので、String を返すラムダ式は「bad return type in lambda expression（String cannot be converted to int）」。別の型にするなら mapToObj

#### flatMap（ふらっとまっぷ / flatMap）

- 意味：各要素を Stream に変換し、それらを 1 本の Stream に平らにつなぐ中間操作
- ポイント：`Stream<List<Integer>>` を `flatMap(List::stream)` で `Stream<Integer>` にする。空の List からは要素が出ない。map(List::stream) だと `Stream<Stream<Integer>>` になる。flatMapToInt なら IntStream になる
- 語の意味：flat＝平らな

#### mapMulti（まっぷまるち / mapMulti）

- 意味：各要素について、送り先（Consumer）に 0 個以上の要素を渡す中間操作（Java 16〜）
- ポイント：flatMap と同じく 1 対多の変換だが、Stream を作らずに済む。型引数を `<String>mapMulti(...)` と明示することが多い

#### プリミティブ型ストリームへの変換（ぷりみてぃぶがたすとりーむへのへんかん / mapToInt, mapToObj, boxed）

- 意味：Stream<T> と IntStream などを行き来する中間操作。mapToInt・mapToLong・mapToDouble は Stream → 基本データ型のストリーム、mapToObj と boxed は基本データ型のストリーム → Stream
- ポイント：Stream に mapToObj はない（cannot find symbol）。IntStream の boxed は Stream<Integer> を返す。IntStream には sum・average など数のメソッドがある

### 選別と並べ替え

#### distinct（でぃすてぃんくと / distinct）

- 意味：重複した要素を取り除く中間操作。equals で同じかどうかを判定する
- ポイント：順序のある Stream なら、最初に出てきたものが残る。状態を持つ操作

#### sorted（そーてっど / sorted）

- 意味：要素を並べ替える中間操作。引数なしなら自然順序（Comparable）、Comparator を渡せばその順
- ポイント：Comparable でない要素を引数なしの sorted にかけると、実行時に ClassCastException。全部の要素を集めてから流すので、そのあとに limit(1) があっても、並べ替えたあとの先頭だけが後ろに流れる

#### peek（ぴーく / peek）

- 意味：要素を変えずに流しながら、Consumer で何かをする中間操作。主にデバッグ用
- ポイント：中間操作なので、終端操作がなければ動かない。filter の前に置けば全要素、後ろに置けば残った要素だけが出る
- 語の意味：peek＝のぞき見る

#### limit・skip（りみっと・すきっぷ / limit, skip）

- 意味：limit(n) は先頭から n 個だけ残し、skip(n) は先頭から n 個を飛ばす中間操作
- ポイント：skip(1).limit(3) は 2〜4 番目。limit は短絡操作なので、無限ストリームを有限にできる

#### takeWhile・dropWhile（ていくほわいる・どろっぷほわいる / takeWhile, dropWhile）

- 意味：takeWhile は先頭から条件を満たす間だけ取り、dropWhile は先頭から条件を満たす間だけ飛ばす中間操作（Java 9〜）
- ポイント：filter と違い、条件を満たさない要素が 1 つ出た時点で切り替わる。[1, 2, 3, 10, 1, 2] に n < 5 なら takeWhile は [1, 2, 3]、dropWhile は [10, 1, 2]（後ろの 1, 2 も残る）

### 06-1 ストリームのしくみ

#### 問 jgold-06-o01

- 問：次のコードを実行した。結果として正しいものはどれか。

  ```
  Stream<String> s = Stream.of("a", "b");
  s.forEach(System.out::print);
  s.forEach(System.out::print);
  ```

- ア：abab と表示される
- イ：ab と表示され、2 回目の forEach では何も表示されない
- ウ：コンパイルエラーになる
- エ：ab と表示されたあと、IllegalStateException が投げられる
- 正解：エ
- 解説：ストリームは一度しか使えない。2 回目の forEach で「stream has already been operated upon or closed」の IllegalStateException になる。
- アの意味：コレクションなら何度でも forEach できるが、ストリームはできない。
- イの意味：黙って何もしないのではなく、例外になる。
- ウの意味：使用済みかどうかは実行時にしか分からないので、コンパイルは通る。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：API java.util.stream パッケージの説明「A stream should be operated on (invoking an intermediate or terminal stream operation) only once」、Stream／JDK 17 での実行結果）

#### 問 jgold-06-o02

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  Stream.of("a", "bb", "ccc")
      .filter(x -> { System.out.print("f" + x + " "); return x.length() > 1; })
      .map(x -> { System.out.print("m" + x + " "); return x.toUpperCase(); });
  System.out.println("end");
  ```

- ア：end
- イ：fa fbb fccc mbb mccc end
- ウ：fa fbb mbb fccc mccc end
- エ：コンパイルエラーになる（終端操作がない）
- 正解：ア
- 解説：中間操作は終端操作が呼ばれるまで実行されない（遅延評価）。このコードには終端操作がないので、filter と map のラムダ式は 1 回も呼ばれず、end だけが出る。
- アの意味：正しい。
- イの意味：終端操作があっても、この順（全部 filter してから map）にはならない。
- ウの意味：終端操作があればこの順で出るが、このコードにはない。
- エの意味：終端操作がなくても文法上は正しく、コンパイルは通る。
- 出典：オリジナル問題（根拠：API java.util.stream パッケージの説明「Laziness」／JDK 17 での実行結果）

#### 問 jgold-06-o03

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  Stream.of("a", "bb", "ccc")
      .peek(x -> System.out.print("p" + x + " "))
      .filter(x -> x.length() > 1)
      .forEach(x -> System.out.print("F" + x + " "));
  ```

- ア：pa pbb pccc Fbb Fccc
- イ：pa pbb Fbb pccc Fccc
- ウ：pbb Fbb pccc Fccc
- エ：Fbb Fccc
- 正解：イ
- 解説：要素は 1 つずつパイプライン全体を流れる。"a" は peek のあと filter で落ち、"bb" は peek → forEach、"ccc" も peek → forEach の順。
- アの意味：全部を peek してから forEach する、という順にはならない。
- イの意味：正しい。
- ウの意味：peek は filter より前にあるので、"a" も表示される。
- エの意味：終端操作があるので peek も動く。
- 出典：オリジナル問題（根拠：API java.util.stream パッケージの説明「Laziness」、Stream.peek／JDK 17 での実行結果）

#### 問 jgold-06-o04

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  Stream.of(1, 2, 3, 4)
      .filter(n -> { System.out.print("f" + n); return n % 2 == 0; })
      .map(n -> { System.out.print("m" + n); return n; })
      .findFirst()
      .ifPresent(n -> System.out.print(" ->" + n));
  ```

- ア：f1f2f3f4m2m4 ->2
- イ：f1f2m2f3f4m4 ->2
- ウ：f1f2m2 ->2
- エ：f2m2 ->2
- 正解：ウ
- 解説：findFirst は短絡操作で、最初の要素が見つかった時点で止まる。1 は filter で落ち、2 は filter・map を通って結果になるので、3 と 4 は filter も呼ばれない。
- アの意味：全部を filter してから map する、という順にはならない。
- イの意味：2 が見つかった時点で終わるので、3 と 4 は処理されない。
- ウの意味：正しい。
- エの意味：1 も filter にかけられるので f1 が出る。
- 出典：オリジナル問題（根拠：API java.util.stream パッケージの説明「Short-circuiting」、Stream.findFirst／JDK 17 での実行結果）

#### 問 jgold-06-o05

- 問：次のコードを実行した。表示されるものはどれか。

- ウの意味：s と t は別の Stream で、s を使い回すことはできない。
- エの意味：コンパイルは通り、実行時に例外になる。
- 出典：オリジナル問題（根拠：API java.util.stream パッケージの説明、Stream／JDK 17 での実行結果）

#### 問 jgold-06-o07

- 問：次のコードについて正しいものはどれか。

  ```
  var s = Stream.iterate(1, n -> n + 1).sorted().limit(3);
  System.out.println("built");
  ```

- ア：コンパイルエラーになる

- アの意味：var で Stream<Integer> を受けられ、文法上の問題はない。
- イの意味：正しい。
- ウの意味：終端操作がないので sorted はまだ動いていない。
- エの意味：終端操作がないので要素は表示されない。
- 出典：オリジナル問題（根拠：API java.util.stream パッケージの説明「Laziness」「Stateless behaviors」、Stream.sorted／JDK 17 での実行結果）

#### 問 jgold-06-o08
