## 16-1 接続

### まとめ表

| 部品 | 種類 | 役割 |
| :-: | :-: | :-: |
| DriverManager | クラス | URL から Connection を取る |
| DataSource | インタフェース（javax.sql） | 設定済みの接続元から Connection を取る |
| Connection | インタフェース | データベースとの接続。Statement を作る・トランザクション |
| Statement・PreparedStatement・CallableStatement | インタフェース | SQL を送る |
| ResultSet | インタフェース | SELECT の結果の表 |

### 接続

#### JDBC（じぇーでぃーびーしー / Java Database Connectivity）

- 意味：Java からデータベースを使うための標準の API（java.sql・javax.sql）。データベースごとの JDBC ドライバが、インタフェースの実装を用意する
- ポイント：Connection・Statement・ResultSet などはインタフェースなので new できない（Statement is abstract; cannot be instantiated）。メソッドの多くは SQLException（チェック例外）を投げる
- 語の意味：Java＝言語名／Database＝データベース／Connectivity＝接続性

#### JDBC URL（じぇーでぃーびーしーゆーあーるえる / JDBC URL）

- 意味：接続先のデータベースを表す文字列。「jdbc:サブプロトコル:サブネーム」の形
- ポイント：例 `jdbc:mysql://localhost:3306/shop`、`jdbc:postgresql://host/db`、`jdbc:h2:mem:test`。どのドライバも受け付けない URL だと SQLException（No suitable driver found for …）

#### DriverManager（どらいばーまねーじゃー / DriverManager）

- 意味：JDBC ドライバを管理し、getConnection(URL[, ユーザー, パスワード]) で Connection を返すクラス
- ポイント：JDBC 4.0 からは、クラスパス（モジュールパス）にあるドライバが自動で登録されるので Class.forName は不要。getConnection は SQLException を投げるので、処理しないとコンパイルエラー

#### DataSource（でーたそーす / DataSource）

- 意味：接続先の情報をあらかじめ設定しておき、getConnection() で Connection を取るインタフェース（javax.sql）。DriverManager の代わりに勧められる方法
- ポイント：アプリケーション・サーバーの設定（JNDI で取得）や、接続プール（コネクション・プール）と組み合わせて使う。コードに URL を書かなくてよい

#### Connection（こねくしょん / Connection）

- 意味：データベースとの 1 本の接続を表すインタフェース
- ポイント：createStatement・prepareStatement・prepareCall で Statement 類を作る。setAutoCommit・commit・rollback でトランザクションを扱う。close すると、その接続で作った Statement・ResultSet も使えなくなる。AutoCloseable なので try-with-resources で閉じる

## 16-2 Statement と ResultSet

### まとめ表

| メソッド | 戻り値 | 使う SQL |
| :-: | :-: | :-: |
| executeQuery | ResultSet | SELECT（ResultSet 以外を返す SQL なら SQLException） |
| executeUpdate | int（変わった行数、DDL は 0） | INSERT・UPDATE・DELETE・CREATE など（ResultSet を返す SQL なら SQLException） |
| execute | boolean（ResultSet なら true） | なんでも。結果は getResultSet・getUpdateCount で取る |

### SQL を送る

#### Statement（すてーとめんと / Statement）

- 意味：SQL の文字列をそのまま送って実行するインタフェース。Connection.createStatement() で作る
- ポイント：executeQuery・executeUpdate・execute の 3 つを使い分ける。同じ Statement で次の SQL を実行すると、前の ResultSet は自動で閉じられる

#### executeQuery・executeUpdate・execute（えぐぜきゅーとくえり / executeQuery, executeUpdate, execute）

- 意味：executeQuery は SELECT を実行して ResultSet を返す。executeUpdate は更新系の SQL を実行して、変わった行数を返す。execute はどの SQL でも実行でき、ResultSet が返るなら true
- ポイント：executeQuery に DELETE を、executeUpdate に SELECT を渡すと SQLException（コンパイルは通る）。executeUpdate の戻り値を ResultSet に代入するとコンパイルエラー。execute のあと、更新系なら getUpdateCount で行数、SELECT なら getUpdateCount は -1

### 結果を読む

#### ResultSet（りざるとせっと / ResultSet）

- 意味：SELECT の結果の表と、今いる行を指すカーソルを表すインタフェース
- ポイント：カーソルは最初、1 行目の「前」にある。next() で次の行に進み、行があれば true。next() を呼ぶ前に getInt などを呼ぶと SQLException。結果が 0 行でも ResultSet は null にならず、next() が false を返す

#### 列の指定（れつのしてい / column index, column label）

- 意味：getInt(1) のように列の番号で、または getInt("price") のように列の名前（ラベル）で値を取る
- ポイント：番号は 1 から（getInt(0) は SQLException）。名前は大文字・小文字を区別しない。AS で別名を付けたら、その別名で取る。ない列名は SQLException

#### wasNull（わずぬる / wasNull）

- 意味：最後に get した列の値が SQL の NULL だったかを返すメソッド
- ポイント：getInt は NULL のとき 0 を返すので、0 と NULL を区別するには get のすぐあとで wasNull を呼ぶ。別の列を get すると、その列の結果に変わる。getObject・getString は NULL なら null を返す

#### スクロール可能な ResultSet（すくろーるかのう / scrollable ResultSet）

- 意味：createStatement(ResultSet.TYPE_SCROLL_INSENSITIVE, ResultSet.CONCUR_READ_ONLY) などで作る、前後に自由に動ける ResultSet
- ポイント：既定の TYPE_FORWARD_ONLY では next しか使えず、previous などは SQLException。スクロール可能なら absolute(n)（n 行目、-1 は最後）・relative(n)（今から n 行）・first・last・beforeFirst・afterLast・previous が使え、行がなければ false。getRow は今の行番号

#### ResultSetMetaData（りざるとせっとめたでーた / ResultSetMetaData）

- 意味：ResultSet の列の数・名前・型などの情報。rs.getMetaData() で取る
- ポイント：getColumnCount は列の数。getColumnLabel は AS の別名、getColumnName は元の列名。列の番号は 1 から

## 16-3 PreparedStatement と CallableStatement

### まとめ表

| インタフェース | 作り方 | 特徴 |
| :-: | :-: | :-: |
| Statement | createStatement() | SQL を毎回文字列で送る |
| PreparedStatement | prepareStatement("… ? …") | ? に値を入れる。前もって準備され、SQL インジェクションを防ぐ |
| CallableStatement | prepareCall("{call 名前(?)}") | ストアド・プロシージャを呼ぶ |

### パラメータ付き

#### PreparedStatement（ぷりぺあーどすてーとめんと / PreparedStatement）

- 意味：? の場所（パラメータ）を持つ SQL を前もって準備しておき、setInt・setString などで値を入れて実行する。Statement の子インタフェース
- ポイント：パラメータの番号は 1 から（範囲外や 0 は SQLException）。値を入れていない ? があると、実行時に SQLException。入れた値は clearParameters するか入れ直すまで残るので、一部だけ変えて何度も実行できる。executeQuery・executeUpdate には引数を渡さない

#### SQL インジェクション（えすきゅーえるいんじぇくしょん / SQL injection）

- 意味：入力した文字列が SQL の一部として解釈され、意図しない SQL が実行される攻撃
- ポイント：Statement で `"… WHERE name = '" + 入力 + "'"` のように文字列をつなぐと起きる。PreparedStatement の ? に setString で入れると、値として扱われるので防げる

#### CallableStatement（こーらぶるすてーとめんと / CallableStatement）

- 意味：データベースのストアド・プロシージャ（関数）を呼ぶためのインタフェース。PreparedStatement の子インタフェース。Connection.prepareCall で作る
- ポイント：書き方は `{call 名前(?, ?)}`、戻り値のある関数は `{? = call 名前(?)}`。IN パラメータは setXxx、OUT パラメータは実行の前に registerOutParameter(番号, Types.INTEGER など) で型を登録し、実行のあとに getXxx で取る。INOUT は両方を行う

## 16-4 トランザクションとバッチ

### まとめ表

| メソッド | 中身 |
| :-: | :-: |
| setAutoCommit(false) | 自動コミットをやめる（既定は true） |
| commit() | ここまでの変更を確定 |
| rollback() | 最後の commit 以降の変更を取り消す |
| setSavepoint()・rollback(sp) | 途中の印まで戻す |
| setAutoCommit(true) | 途中のトランザクションがあれば commit される |

### トランザクション

#### 自動コミット（じどうこみっと / auto-commit）

- 意味：SQL を 1 つ実行するたびに、自動で commit するモード。Connection を取ったときは有効（getAutoCommit は true）
- ポイント：自動コミットのままでは rollback しても戻せない。複数の SQL をまとめて確定・取り消しするには setAutoCommit(false)。トランザクションの途中で setAutoCommit(true) に戻すと、その時点で commit される

#### commit と rollback（こみっと・ろーるばっく / commit, rollback）

- 意味：commit はトランザクションの変更を確定する。rollback は最後の commit 以降の変更を取り消す
- ポイント：commit したあとの rollback では、commit 前の変更は戻らない

#### Savepoint（せーぶぽいんと / Savepoint）

- 意味：トランザクションの途中に付ける印。rollback(sp) で、その印のあとの変更だけを取り消す
- ポイント：Connection.setSavepoint() か setSavepoint("名前") で作る。rollback(sp) のあともトランザクションは続き、commit で確定する

#### バッチ更新（ばっちこうしん / batch update）

- 意味：複数の更新の SQL をためておき、まとめて 1 回で送るしくみ
- ポイント：addBatch でためて、executeBatch で実行する。戻り値は int[] で、各 SQL で変わった行数が入る

#### 問 jgold-16-o07

- 問：次のコードを実行した。表示されるものはどれか。

- 出典：オリジナル問題（根拠：API Statement.executeUpdate（either the row count … or 0 for SQL statements that return nothing）／JDK 17 と H2 での実行結果）
