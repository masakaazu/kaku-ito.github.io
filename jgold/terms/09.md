## 09-1 並列ストリームの作り方

### まとめ表

| 書き方 | 結果 |
| :-: | :-: |
| list.parallelStream() | 並列ストリーム |
| stream.parallel() | 並列ストリーム |
| stream.sequential() | 逐次ストリーム |
| stream.isParallel() | 並列なら true |
| s.parallel().sequential() | 逐次（最後の指定が全体に効く） |

### 並列にする

#### 並列ストリーム（へいれつすとりーむ / parallel stream）

- 意味：要素をいくつかのまとまりに分け、複数のスレッドで同時に処理するストリーム
- ポイント：結果は逐次と同じになるように作られているが、順序・副作用・結合則に頼る処理では結果が変わる。要素が少なかったり処理が軽かったりすると、かえって遅くなることもある

#### parallelStream（ぱられるすとりーむ / Collection.parallelStream）

- 意味：コレクションから並列ストリームを作る Collection のメソッド
- ポイント：Collection のメソッドなので、Stream にはない（Stream.of(...).parallelStream() は cannot find symbol）。Stream を並列にするのは parallel()

#### parallel・sequential（ぱられる・しーけんしゃる / parallel, sequential）

- 意味：ストリームを並列・逐次に切り替える中間操作（BaseStream のメソッド）
- ポイント：途中で切り替えても、パイプライン全体が「最後に指定したほう」で動く。parallel().sequential() は逐次、sequential().parallel() は並列。一部だけ並列にはできない

#### isParallel（いずぱられる / isParallel）

- 意味：ストリームが並列かどうかを返すメソッド
- ポイント：Stream.of(...) や list.stream() は逐次なので false。unordered() は順序をなくすだけで、並列にはしない

#### 共通プール（きょうつうぷーる / common pool）

- 意味：並列ストリームの処理に使われる、ForkJoinPool の共有のスレッドプール
- ポイント：処理するスレッドは、呼び出したスレッド（main）と「ForkJoinPool.commonPool-worker-N」。スレッド数はふつう CPU のコア数 − 1
- 語の意味：fork＝分ける／join＝合わせる

#### 分割統治（ぶんかつとうち / divide and conquer）

- 意味：問題を小さく分けてそれぞれ解き、結果をまとめる方法。並列ストリームは Spliterator で要素を分け、途中の結果をまとめて最終の結果を出す
- ポイント：まとめる処理（reduce のコンバイナなど）が正しくないと、並列のときだけ結果がおかしくなる

## 09-2 順序

### まとめ表

| 操作 | 並列のときの順序 |
| :-: | :-: |
| forEach | 決まらない |
| forEachOrdered | 元の順（encounter order） |
| collect(toList())・toList()・joining | 元の順 |
| findFirst | 必ず最初の要素 |
| findAny | 決まらない |
| sorted のあとの forEach | 決まらない（forEachOrdered なら並んだ順） |

### 順序を守る・捨てる

#### 出現順序（しゅつげんじゅんじょ / encounter order）

- 意味：ストリームのソースが持つ要素の順序。List・配列・Stream.of・range などは順序を持ち、HashSet は持たない
- ポイント：並列でも、collect(toList())・toList()・joining・findFirst・forEachOrdered は出現順序を守る。並列にしても「順序がなくなる」わけではない

#### forEach と forEachOrdered（ふぉーいーちとふぉーいーちおーだーど / forEach, forEachOrdered）

- 意味：forEach は要素ごとに処理を行う終端操作で、並列では順序を守らない。forEachOrdered は出現順序どおりに処理する
- ポイント：並列で `forEach(System.out::print)` の出力順は実行ごとに変わる。順に出したいなら forEachOrdered（ただし並列の利点は減る）

#### unordered（あんおーだーど / unordered）

- 意味：「順序を気にしない」というしるしを付けたストリームを返す中間操作
- ポイント：並列の distinct・limit などが速くなることがある。並列にはしない（isParallel は変わらない）

#### findAny（ふぁいんどえにー / findAny）

- 意味：どれか 1 つの要素を返す終端操作
- ポイント：並列では実行ごとに違う要素が返りうる。findFirst は並列でも最初の要素

## 09-3 並列で正しく動かす条件

### まとめ表

| 条件 | 守らないと |
| :-: | :-: |
| 結合則を満たす（足し算・掛け算・max・連結） | 引き算などは並列で結果が変わる |
| 単位元が本当の単位元（足し算なら 0） | reduce(10, sum) が逐次 16・並列 36 などになる |
| 干渉しない（ソースを途中で変えない） | 例外や誤った結果 |
| 状態を持たない・副作用のない関数 | ArrayList への add で要素が欠ける・例外 |

### 条件

#### 結合則（けつごうそく / associativity）

- 意味：(a op b) op c ＝ a op (b op c) が成り立つこと。並列のリダクションでは、どこで区切ってまとめても同じ結果になるために必要
- ポイント：足し算・掛け算・max・min・文字列の連結は満たす。引き算・割り算は満たさないので、並列 reduce の結果が逐次と変わる（1〜8 を 0 から引くと、逐次は −36、並列では別の値になりうる）

#### 単位元の条件（たんいげんのじょうけん / identity constraint）

- 意味：reduce の単位元 identity は、どの値 x についても op(identity, x) ＝ x を満たさなければならない
- ポイント：並列では、分けたまとまりごとに単位元から計算を始めるので、単位元が何回も使われる。Stream.of(1, 2, 3).parallel().reduce(10, Integer::sum) は逐次の 16 にならない（JDK 17 では 36）

#### コンバイナの条件（こんばいなのじょうけん / combiner compatibility）

- 意味：3 引数の reduce・collect のコンバイナは、アキュムレータと矛盾しないように途中の結果をまとめなければならない
- ポイント：逐次ではコンバイナは呼ばれないので、まちがったコンバイナでも逐次では正しく見える。並列にしたときだけ結果がおかしくなる

#### 副作用（ふくさよう / side-effects）

- 意味：ラムダ式が、外の変数やコレクションを書きかえること
- ポイント：並列の forEach で ArrayList に add すると、要素が欠けたり ArrayIndexOutOfBoundsException になったりする。collect(toList()) を使うか、どうしても必要なら Collections.synchronizedList などのスレッドセーフなコレクションを使う

#### 干渉しない（かんしょうしない / non-interference）

- 意味：パイプラインの実行中に、ソースのコレクションを変更しないこと
- ポイント：逐次でも並列でも守る必要がある。ConcurrentModificationException や誤った結果になる

#### 状態を持たないラムダ式（じょうたいをもたないらむだしき / stateless behavioral parameters）

- 意味：結果が、その要素だけで決まり、処理中に変わる外の状態に頼らないラムダ式
- ポイント：外の Set に「すでに見たか」を記録するような map は、並列では結果が変わりうる

#### 並行コレクタ（へいこうこれくた / concurrent collector）

- 意味：複数のスレッドが 1 つの ConcurrentMap に同時に要素を入れる Collector。Collectors.groupingByConcurrent・toConcurrentMap
- ポイント：結果は ConcurrentMap（ConcurrentHashMap）。順序は守らないが、並列で途中の Map をまとめる手間がなく速い

#### 問 jgold-09-o01

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  Stream<Integer> s = List.of(1, 2, 3).parallelStream();
  System.out.println(s.isParallel() + " " + Stream.of(1).parallel().sequential().isParallel() + " "
      + Stream.of(1).sequential().parallel().isParallel() + " " + Stream.of(1).isParallel());
  ```

- ア：true true true false
- イ：true false false false
- ウ：true false true false
- エ：true false true true
- 正解：ウ
- 解説：parallelStream は並列。parallel・sequential は最後に呼んだほうがパイプライン全体に効くので、parallel().sequential() は逐次（false）、sequential().parallel() は並列（true）。Stream.of は逐次。
- アの意味：一度 parallel にしても、あとで sequential にすれば逐次になる。
- イの意味：sequential().parallel() は最後が parallel なので並列。
- ウの意味：正しい。
- エの意味：Stream.of で作ったストリームは逐次。
- 出典：オリジナル問題（根拠：API BaseStream.parallel・sequential・isParallel、java.util.stream パッケージの説明「Parallelism」／JDK 17 での実行結果）

### 09-2 順序
