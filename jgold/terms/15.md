## 15-1 Path の操作

### まとめ表

| メソッド | Path.of("/home/user/docs/a.txt") の結果 |
| :-: | :-: |
| getFileName() | a.txt |
| getParent() | /home/user/docs |
| getRoot() | /（相対パスなら null） |
| getNameCount() | 4（ルートは数えない） |
| getName(0) | home（0 から数える） |
| subpath(1, 3) | user/docs（3 は含まない） |

### パスを作る・調べる

#### Path（ぱす / Path）

- 意味：ファイルやディレクトリの場所を表すインタフェース（java.nio.file）。Path.of(…) か Paths.get(…) で作る
- ポイント：Path を作っただけでは、ファイルがあるかは調べない。Path は不変（immutable）で、resolve などは新しい Path を返し、元は変わらない。File との行き来は file.toPath()・path.toFile()

#### Path.of と Paths.get（ぱすおぶ・ぱすずげっと / Path.of, Paths.get）

- 意味：文字列（いくつでも）から Path を作る static メソッド。Path.of は Java 11 で追加、Paths.get は前からあり同じ結果
- ポイント：Path.of("a", "b") と Path.of("a/b") は equals で true。Path.of("a/./b") と Path.of("a/b") は equals で false（normalize しないと別もの）

#### 名前の要素（なまえのようそ / name elements）

- 意味：パスを区切り文字で分けた 1 つずつの部分。getNameCount・getName(i)・subpath(始め, 終わり) で扱う
- ポイント：ルート（/）は要素に数えない。番号は 0 から。subpath の終わりは含まない。範囲外や subpath(1, 1) は IllegalArgumentException。Path.of("/") は getFileName も getParent も null、getNameCount は 0

#### 絶対パスと相対パス（ぜったいぱすとそうたいぱす / absolute path, relative path）

- 意味：ルートから書いたパスが絶対パス、今のディレクトリなどからの位置で書いたパスが相対パス
- ポイント：isAbsolute で調べる。相対パスの getRoot は null。toAbsolutePath は今の作業ディレクトリを前に付ける（ファイルがなくても例外にならない）

### パスを組み合わせる

#### resolve（りぞるぶ / resolve）

- 意味：このパスの後ろに、引数のパスをつなげる
- ポイント：引数が絶対パスなら、引数をそのまま返す（/a/b に /x/y を resolve すると /x/y）。resolveSibling は親に対して resolve する（/a/b → /a/z）

#### relativize（れらてぃぶあいず / relativize）

- 意味：このパスから引数のパスへ行くための相対パスを作る
- ポイント：/a/b から /a/c/d へは ../c/d。片方だけが絶対パスだと IllegalArgumentException（'other' is different type of Path）。p.resolve(p.relativize(q)) は q になる

#### normalize（のーまらいず / normalize）

- 意味：パスの中の . と、「名前/..」の組を取り除いて、すっきりさせる
- ポイント：/a/./b/../c → /a/c。先頭の .. は消えない（../x/./y/.. → ../x）。ファイルがあるかは調べない

#### startsWith・endsWith（すたーつうぃず・えんずうぃず / startsWith, endsWith）

- 意味：パスが、指定したパスで始まるか・終わるかを、名前の要素の単位で調べる
- ポイント：文字列の比較ではない。/a/b/c.txt は "/a" で始まる（true）が "/a/b/c" では始まらない（false）。"c.txt" で終わる（true）が "txt" では終わらない（false）

## 15-2 Files でファイルを作る・写す・消す

### まとめ表

| メソッド | 失敗するとき | 例外 |
| :-: | :-: | :-: |
| createDirectory | 親がない／もうある | NoSuchFileException／FileAlreadyExistsException |
| createDirectories | （親もまとめて作る、あっても OK） | ― |
| copy・move | 写し先がもうある | FileAlreadyExistsException（REPLACE_EXISTING で上書き） |
| delete | ない／中身のあるディレクトリ | NoSuchFileException／DirectoryNotEmptyException |
| deleteIfExists | （なければ false） | DirectoryNotEmptyException |

### 作る・消す

#### Files（ふぁいるず / Files）

- 意味：ファイルやディレクトリを操作する static メソッドを集めたクラス（java.nio.file）。引数に Path を取る
- ポイント：多くのメソッドが IOException（チェック例外）を投げる。失敗の理由ごとにサブクラスの例外（NoSuchFileException など）を投げる

#### createDirectory と createDirectories（くりえいとでぃれくとり / createDirectory, createDirectories）

- 意味：createDirectory はディレクトリを 1 つ作る。createDirectories は、なければ親のディレクトリもまとめて作る
- ポイント：createDirectory は親がないと NoSuchFileException、もうあると FileAlreadyExistsException。createDirectories は、もうあっても例外にならない

#### delete と deleteIfExists（でりーと / delete, deleteIfExists）

- 意味：ファイルか空のディレクトリを消す
- ポイント：delete はないと NoSuchFileException、deleteIfExists はないと false を返す。中身のあるディレクトリはどちらも DirectoryNotEmptyException

#### copy と move（こぴー・むーぶ / copy, move）

- 意味：copy はファイルを写し、move は移す（名前を変える）
- ポイント：写し先がもうあると FileAlreadyExistsException。StandardCopyOption.REPLACE_EXISTING で上書き。ディレクトリを copy すると、中身は写されない空のディレクトリができる。move は ATOMIC_MOVE も指定できる

### オプションと比べる

#### StandardOpenOption（すたんだーどおーぷんおぷしょん / StandardOpenOption）

- 意味：ファイルを開くときの指定。CREATE・CREATE_NEW・APPEND・TRUNCATE_EXISTING・WRITE・READ など
- ポイント：何も指定しない write・writeString は「なければ作り、あれば中身を消して書く」（CREATE・TRUNCATE_EXISTING・WRITE）。CREATE_NEW はもうあると FileAlreadyExistsException。APPEND は後ろに足す

#### isSameFile と mismatch（いずせいむふぁいる・みすまっち / isSameFile, mismatch）

- 意味：isSameFile は 2 つのパスが同じファイルを指すか調べる。mismatch（Java 12〜）は 2 つのファイルの中身を比べ、最初にちがう位置を返す（同じなら -1）
- ポイント：isSameFile は . などを解決して比べる（f と ./f は true）。片方が短く、前が同じなら、短いほうの大きさを返す

#### exists と notExists（いぐじすつ・のっといぐじすつ / exists, notExists）

- 意味：ファイルがあるか・ないかを調べる。isDirectory・isRegularFile・isReadable なども同じなかま
- ポイント：調べられないとき（権限がないなど）は、exists も notExists も false になりうる。そのため !exists と notExists は同じではない

## 15-3 読み書きと走査・属性

### まとめ表

| メソッド | 戻り値 | 注意 |
| :-: | :-: | :-: |
| readAllLines(p) | List<String> | 全部をメモリに読む |
| lines(p) | Stream<String> | 少しずつ読む。try-with-resources で閉じる |
| readString(p)・writeString(p, s) | String・Path | Java 11〜 |
| list(dir) | Stream<Path> | すぐ下だけ |
| walk(dir[, 深さ]) | Stream<Path> | 下まで全部（自分も含む） |
| find(dir, 深さ, (path, attr) -> 条件) | Stream<Path> | 属性で絞る |

### 読む・書く

#### readAllLines と lines（りーどおーるらいんず・らいんず / readAllLines, lines）

- 意味：readAllLines はファイルの全部の行を List<String> で返す。lines は行の Stream<String> を返し、必要な分だけ読む
- ポイント：lines の戻り値を List に代入するとコンパイルエラー。lines・list・walk・find の Stream はファイルを開いているので、try-with-resources で閉じる。ないファイルは NoSuchFileException

#### readString と writeString（りーどすとりんぐ・らいとすとりんぐ / readString, writeString）

- 意味：ファイルの中身をまとめて String で読む・書く（Java 11〜）。文字コードの既定は UTF-8
- ポイント：Files.write(p, 行のリスト, オプション) は各行の後ろに改行を付ける。最後に改行のないファイルに APPEND で足すと、最後の行の続きに書かれる

#### newBufferedReader と newBufferedWriter（にゅーばっふぁーどりーだー / newBufferedReader, newBufferedWriter）

- 意味：Path から BufferedReader・BufferedWriter を作るメソッド。文字コードの既定は UTF-8
- ポイント：java.io の BufferedReader と同じように readLine・write が使える

### 走査と属性

#### walk・list・find（うぉーく・りすと・ふぁいんど / walk, list, find）

- 意味：ディレクトリの中のパスを Stream<Path> で返すメソッド
- ポイント：list はすぐ下だけ（自分は含まない）。walk は深さ優先で下まで全部、最初に自分自身を含む。walk(dir, 1) は自分とすぐ下。find は深さと BiPredicate<Path, BasicFileAttributes> で絞る。シンボリックリンクは、FileVisitOption.FOLLOW_LINKS を付けなければたどらない

#### BasicFileAttributes（べーしっくふぁいるあとりびゅーつ / BasicFileAttributes）

- 意味：大きさ・作った時刻・最後に変えた時刻・ディレクトリかどうか、などの基本の属性を、まとめて読むインタフェース
- ポイント：Files.readAttributes(p, BasicFileAttributes.class) で 1 回で読める（size・isDirectory・isRegularFile・lastModifiedTime・creationTime）。1 つだけなら Files.size・Files.getLastModifiedTime

### 15-1 Path の操作

#### 問 jgold-15-o01

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  Path p = Path.of("/home/user/docs/a.txt");
  System.out.println(p.getFileName() + " " + p.getParent() + " " + p.getRoot() + " " + p.getNameCount() + " " + p.getName(0) + " " + p.subpath(1, 3));
  ```

- ア：a.txt /home/user/docs / 5 / user/docs/a.txt
- イ：a.txt /home/user/docs / 4 home user/docs
- ウ：a.txt docs / 4 home user/docs
- エ：a.txt /home/user/docs / 4 user docs/a.txt
- 正解：イ
- 解説：ルートは名前の要素に数えないので 4。getName(0) は最初の要素 home。subpath(1, 3) は 1 番目と 2 番目（3 は含まない）で user/docs。getParent は最後の要素を除いたパス。
- アの意味：ルートは数えず、getName(0) は home。
- イの意味：正しい。
- ウの意味：getParent は親のフルパス（/home/user/docs）。
- エの意味：番号は 0 から、subpath の終わりは含まない。
- 出典：オリジナル問題（根拠：API Path.getFileName・getParent・getRoot・getNameCount・getName・subpath／JDK 17 での実行結果）
