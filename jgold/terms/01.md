## 01-1 オートボクシング

### まとめ表

| コード | 結果 | 理由 |
| :-: | :-: | :-: |
| `Integer a = 127, b = 127; a == b` | true | -128〜127 は同じオブジェクトを使い回す（JLS 5.1.7） |
| `Integer c = 128, d = 128; c == d` | false（既定の設定） | 別のオブジェクト。値の比較は equals |
| `Long l = 5;` | コンパイルエラー | int を Long にはボクシングできない（5L と書く） |
| `int n = map.get("x");`（値なし） | NullPointerException | null をアンボクシングした |
| `list.remove(1)`（List<Integer>） | 添字 1 の要素を消す | remove(int) が選ばれる。値で消すなら Integer.valueOf(1) |

### ボクシングとアンボクシング

#### オートボクシング（おーとぼくしんぐ / autoboxing）

- 意味：基本データ型の値を、対応するラッパークラスのオブジェクトにコンパイラが自動で変えること。int → Integer、double → Double など
- ポイント：コレクションには基本データ型を入れられないので、`list.add(1)` では 1 が Integer に変わる。変換できるのは対応する型どうしだけで、`Long l = 5;` は int → Long になるのでコンパイルエラー（incompatible types: int cannot be converted to Long）
- 例：`List<Integer> list = new ArrayList<>(); list.add(10);`

#### アンボクシング（あんぼくしんぐ / unboxing）

- 意味：ラッパークラスのオブジェクトから、基本データ型の値を自動で取り出すこと。Integer → int など
- ポイント：参照が null のときにアンボクシングすると NullPointerException（JLS 5.1.8）。`Map.get` は値がないと null を返すので、`int n = map.get(key);` は危ない。算術演算や `i == 10` の比較でもアンボクシングが起きる
- 例：`Integer x = null; int y = x;` → NullPointerException

#### ラッパークラス（らっぱーくらす / wrapper class）

- 意味：基本データ型の値を包むクラス。Byte・Short・Integer・Long・Float・Double・Character・Boolean の 8 つ
- ポイント：どれも不変（immutable）で final クラス。`equals` は型も比べるので、`Integer.valueOf(10).equals(10L)` は false（Long だから）

#### ボクシングのキャッシュ（ぼくしんぐのきゃっしゅ / boxing cache）

- 意味：-128〜127 の int、true と false、'\u0000'〜'\u007f' の char などをボクシングすると、いつも同じオブジェクトが返るしくみ（JLS 5.1.7）
- ポイント：`Integer a = 127, b = 127;` の `a == b` は true。128 は既定の設定では別のオブジェクトになり false。ラッパーどうしの値は == でなく equals で比べる
- 例：`Integer.valueOf(100) == Integer.valueOf(100)` → true

### オーバーロードとボクシング

#### remove(int) と remove(Object)（りむーぶ / remove）

- 意味：List には、添字を受け取る `remove(int index)` と、要素を受け取る `remove(Object o)` の 2 つがある
- ポイント：`List<Integer>` で `list.remove(1)` と書くと、ボクシングしなくてよい remove(int) が先に選ばれ、添字 1 の要素が消える。値の 1 を消したいときは `list.remove(Integer.valueOf(1))`
- 例：`[10, 20, 30, 1]` に `remove(1)` → `[10, 30, 1]`

#### オーバーロードの解決の順（おーばーろーどのかいけつのじゅん / overload resolution phases）

- 意味：呼び出せるメソッドが複数あるとき、まずボクシングも可変長引数も使わずに合うもの、次にボクシングを使って合うもの、最後に可変長引数を使って合うもの、の順に探す（JLS 15.12.2）
- ポイント：remove(1) で remove(int) が選ばれるのはこの順のため。前の段階で見つかれば、後の段階は見ない

## 01-2 コレクションの全体像と List

### まとめ表

| インタフェース | 特徴 | 主な実装 |
| :-: | :-: | :-: |
| List | 順序あり・重複あり・添字で取り出す | ArrayList・LinkedList |
| Set | 重複なし | HashSet・LinkedHashSet・TreeSet |
| Queue／Deque | 先頭・末尾から出し入れする | ArrayDeque・LinkedList |
| Map | キーと値の組。Collection を継承しない | HashMap・LinkedHashMap・TreeMap |

### 全体像

#### コレクション・フレームワーク（これくしょんふれーむわーく / Collections Framework）

- 意味：複数のオブジェクトをまとめて扱うためのインタフェースと実装クラスと便利なメソッドの集まり。java.util パッケージにある
- ポイント：変数の型はインタフェース（List・Set・Map など）にして、実装クラスは new のところだけに書くのが基本。`List<String> list = new ArrayList<>();`

#### Collection インタフェース（これくしょんいんたふぇーす / Collection）

- 意味：List・Set・Queue の親になるインタフェース。add・remove・contains・size・isEmpty・iterator などを決める。Iterable を継承するので拡張 for で回せる
- ポイント：Map は Collection を継承しない。`Collection<String> c = new HashMap<String, String>();` はコンパイルエラー。Map の中身は keySet()・values()・entrySet() で Collection として取り出す

#### List インタフェース（りすといんたふぇーす / List）

- 意味：要素を順番どおりに持ち、重複を許し、添字（0 から）で取り出せるコレクション
- ポイント：`equals` は、同じ要素が同じ順に並んでいれば実装クラスが違っても true（ArrayList と LinkedList でも true）。List と Set を equals で比べると false

#### ArrayList（あれいりすと / ArrayList）

- 意味：内部に配列を持ち、大きさを自動で広げる List の実装。添字での取り出しが速い
- ポイント：途中への挿入や削除は後ろの要素をずらすので遅い。null も入る。スレッドセーフではない

#### LinkedList（りんくどりすと / LinkedList）

- 意味：要素どうしを前後の参照でつないだ List の実装。Deque も実装しているので、キューやスタックとしても使える
- ポイント：先頭と末尾の出し入れは速いが、添字での取り出しは先頭から順にたどるので遅い。null も入る

## 01-3 Set

### まとめ表

| 実装 | 並び順 | null |
| :-: | :-: | :-: |
| HashSet | 決まらない | 1 つ入る |
| LinkedHashSet | 入れた順 | 1 つ入る |
| TreeSet | 自然順序（Comparable）か Comparator の順 | 自然順序では入らない（NullPointerException） |

### Set の実装

#### Set インタフェース（せっといんたふぇーす / Set）

- 意味：同じ要素を 2 つ持たないコレクション。同じかどうかは equals で判断する
- ポイント：add はすでにある要素なら何もせず false を返す。自作のクラスを HashSet に入れるときは equals と hashCode の両方をオーバーライドする（レコードは自動で作られる）

#### HashSet（はっしゅせっと / HashSet）

- 意味：要素のハッシュ値で置き場所を決める Set の実装。内部は HashMap
- ポイント：equals と hashCode をオーバーライドしていないクラスは、中身が同じでも別の要素として 2 つ入る。並び順は保証されない

#### LinkedHashSet（りんくどはっしゅせっと / LinkedHashSet）

- 意味：入れた順を覚えている HashSet
- ポイント：すでにある要素を入れ直しても順番は変わらない。重複を取り除きつつ順番を残したいときに使う

#### TreeSet（つりーせっと / TreeSet）

- 意味：要素を並べ替えた順で持つ Set の実装（NavigableSet）。内部は TreeMap
- ポイント：要素は Comparable を実装しているか、コンストラクタに Comparator を渡す。どちらもないクラスを add すると ClassCastException（コンパイルは通る）。同じかどうかは equals でなく compareTo（compare）が 0 かで決まる。文字列は文字コード順で、数字 → 大文字 → 小文字、"10" は "9" より前

#### ハッシュコード（はっしゅこーど / hash code）

- 意味：オブジェクトから計算する int の値。HashSet や HashMap が置き場所を決めるのに使う
- ポイント：equals で等しい 2 つのオブジェクトは、同じ hashCode を返さなければならない（Object.hashCode の決まり）。逆は成り立たなくてよい（ハッシュ値が同じでも等しくないことはある）

### 並んだ Set を探す

#### NavigableSet の探索メソッド（なびげーぶるせっとのたんさくめそっど / lower・floor・ceiling・higher）

- 意味：TreeSet で、指定した値に近い要素を探すメソッド。lower は未満の最大、floor は以下の最大、ceiling は以上の最小、higher はより大きい最小
- ポイント：該当がなければ null。TreeMap にも lowerKey・floorKey・ceilingKey・higherKey がある
- 例：{10, 20, 30, 40} で floor(25) → 20、ceiling(25) → 30、higher(30) → 40、lower(10) → null

#### 部分集合のビュー（ぶぶんしゅうごうのびゅー / headSet・tailSet・subSet）

- 意味：TreeSet の一部を取り出すメソッド。headSet(x) は x 未満、tailSet(x) は x 以上、subSet(a, b) は a 以上 b 未満
- ポイント：引数 1 つ（2 つ）の形は「始まりを含み、終わりを含まない」。boolean の引数を付けると含むかを選べる（headSet(5, true) は 5 以下）。返るのはビューなので、元の Set の変更が見える。TreeMap の headMap・tailMap・subMap も同じ決まり

## 01-4 Map

### まとめ表

| メソッド | 戻り値・動き |
| :-: | :-: |
| put(k, v) | 前の値（なければ null）。値を上書きする |
| putIfAbsent(k, v) | 前の値。キーがない（値が null）ときだけ入れる |
| getOrDefault(k, d) | 値。キーがなければ d |
| merge(k, v, f) | キーがなければ v を入れる。あれば f(前の値, v) で置き換え、結果が null なら削除 |
| computeIfAbsent(k, f) | キーがなければ f(k) の結果を入れて返す。あればその値を返す |

### Map の実装

#### Map インタフェース（まっぷいんたふぇーす / Map）

- 意味：キーと値の組（エントリ）を持つコレクション。キーは重複せず、1 つのキーに 1 つの値が対応する
- ポイント：Collection を継承しない。keySet()（Set）・values()（Collection）・entrySet()（Set<Map.Entry>）はビューで、keySet() から remove するとエントリも消える

#### HashMap（はっしゅまっぷ / HashMap）

- 意味：キーのハッシュ値で置き場所を決める Map の実装
- ポイント：null のキーを 1 つ、null の値をいくつでも入れられる。並び順は保証されない。get が null を返したとき、「キーがない」のか「値が null」なのかは containsKey で区別する

#### LinkedHashMap（りんくどはっしゅまっぷ / LinkedHashMap）

- 意味：入れた順を覚えている HashMap
- ポイント：すでにあるキーに put し直しても順番は変わらない（値だけ変わる）

#### TreeMap（つりーまっぷ / TreeMap）

- 意味：キーを並べ替えた順で持つ Map の実装（NavigableMap）
- ポイント：自然順序では null のキーを入れると NullPointerException。値は null でもよい。floorKey・ceilingKey・headMap・tailMap などで範囲を扱える

#### Map.Entry（まっぷえんとり / Map.Entry）

- 意味：Map の 1 組のキーと値を表すインタフェース。getKey・getValue・setValue を持つ
- ポイント：entrySet() で回して setValue すると、元の Map の値が変わる。`Map.entry(k, v)` で作ったエントリは変更できない

### 便利なメソッド

#### merge メソッド（まーじめそっど / merge）

- 意味：キーがなければ値を入れ、あれば前の値と新しい値を関数でまとめた結果に置き換えるメソッド
- ポイント：関数の結果が null ならエントリを削除する。数え上げは `map.merge(word, 1, Integer::sum)` が定番
- 例：`count.merge("a", 1, Integer::sum);` を 2 回 → a=2

#### computeIfAbsent メソッド（こんぴゅーといふあぶせんと / computeIfAbsent）

- 意味：キーがなければ関数で値を作って入れ、その値を返す。あれば今の値を返す
- ポイント：グループ分けで「なければ空のリストを作って add」を 1 行で書ける。`map.computeIfAbsent(k, x -> new ArrayList<>()).add(v);`

#### putIfAbsent メソッド（ぷっといふあぶせんと / putIfAbsent）

- 意味：キーがない（または値が null の）ときだけ値を入れるメソッド。戻り値は前の値
- ポイント：put は前の値を返して上書きする。putIfAbsent は上書きしない。どちらも、前にキーがなければ null を返す

#### getOrDefault メソッド（げっとおあでふぉると / getOrDefault）

- 意味：キーがあれば値を、なければ引数の既定値を返すメソッド。Map は変わらない
- ポイント：`int n = map.get(k);` の NullPointerException を避けるのに使える

## 01-5 Queue と Deque

### まとめ表

| 操作 | 失敗すると例外 | 失敗すると特別な値 |
| :-: | :-: | :-: |
| 入れる | add（addFirst・addLast） | offer（offerFirst・offerLast）→ false |
| 取り出して消す | remove（removeFirst・removeLast） | poll（pollFirst・pollLast）→ null |
| 見るだけ | element（getFirst・getLast） | peek（peekFirst・peekLast）→ null |
| スタック | push＝addFirst、pop＝removeFirst | peek＝peekFirst |

### キューとスタック

#### Queue インタフェース（きゅーいんたふぇーす / Queue）

- 意味：要素を順番に待たせるコレクション。ふつうは先に入れたものから出す（FIFO）
- ポイント：同じ操作に「例外を投げる版」と「null や false を返す版」がある。空のときに remove・element は NoSuchElementException、poll・peek は null

#### Deque インタフェース（でっくいんたふぇーす / Deque）

- 意味：先頭と末尾の両方から出し入れできるキュー。キュー（FIFO）にもスタック（LIFO）にも使える
- ポイント：push・pop・peek はどれも先頭（First）を使う。push 1・2・3 のあとの中身は [3, 2, 1]。Stack クラスより Deque を使うよう API ドキュメントがすすめている
- 語の意味：Deque＝Double Ended Queue（両端キュー）。「デック」と読む

#### ArrayDeque（あれいでっく / ArrayDeque）

- 意味：配列を使った Deque の実装。大きさは自動で広がる
- ポイント：null を入れられない（add・offer・push のどれでも NullPointerException）。スタックとしては Stack より、キューとしては LinkedList より速いことが多い（API ドキュメント）

#### FIFO と LIFO（ふぁいふぉとらいふぉ / First In First Out, Last In First Out）

- 意味：FIFO は先に入れたものから出す（キュー）、LIFO は後に入れたものから出す（スタック）
- ポイント：Deque では、offer（末尾）と poll（先頭）で FIFO、push（先頭）と pop（先頭）で LIFO
- 語の意味：First＝最初／In＝入る／Out＝出る／Last＝最後

## 01-6 イテレータと変更できないコレクション

### まとめ表

| 作り方 | set | add・remove | null | 元の変更 |
| :-: | :-: | :-: | :-: | :-: |
| List.of(...) | × | × | 入れると NPE | ― |
| Arrays.asList(...) | ○ | × | ○ | 配列と共有 |
| List.copyOf(c) | × | × | NPE | 見えない（コピー） |
| Collections.unmodifiableList(c) | × | × | ○ | 見える（ビュー） |

### 回しながら変える

#### イテレータ（いてれーた / Iterator）

- 意味：コレクションの要素を 1 つずつ取り出すためのオブジェクト。hasNext・next・remove を持つ
- ポイント：回している途中で要素を消すなら、イテレータの remove を使う。拡張 for は内部でイテレータを使う

#### ConcurrentModificationException（こんかれんともでぃふぃけーしょんえくせぷしょん / ConcurrentModificationException）

- 意味：イテレータで回している途中で、イテレータ以外の方法でコレクションの構造が変わったことを、次の next で見つけたときに投げられる例外
- ポイント：拡張 for の中で `list.remove(s)` すると起きる。ただし、最後から 2 番目の要素を消すと、hasNext が false になってループが終わるので例外は起きない（ArrayList の場合）。フェイルファストは「できるだけ」の動きで、保証ではない（API ドキュメント）

#### removeIf メソッド（りむーぶいふ / removeIf）

- 意味：条件（Predicate）に合う要素をまとめて消す Collection のメソッド
- ポイント：回しながら消すより安全で短い。`list.removeIf(n -> n % 2 == 0);`

### 変更できないコレクション

#### List.of・Set.of・Map.of（りすとおぶ / List.of, Set.of, Map.of）

- 意味：変更できない（unmodifiable）コレクションを作る static メソッド
- ポイント：add・set・remove などは UnsupportedOperationException。null を入れると NullPointerException。Set.of と Map.of は重複する要素・キーがあると IllegalArgumentException（duplicate element／duplicate key）

#### Arrays.asList（あれいずあずりすと / Arrays.asList）

- 意味：配列を元にした、大きさの決まった List を返すメソッド
- ポイント：set はできる（元の配列も変わる）。add・remove は大きさが変わるので UnsupportedOperationException。null も入る

#### List.copyOf（りすとこぴーおぶ / List.copyOf）

- 意味：渡したコレクションの中身をコピーした、変更できない List を作るメソッド
- ポイント：コピーなので、元のコレクションをあとで変えても影響しない。`Collections.unmodifiableList` は元のビューなので、元の変更が見える

#### 変更できないビュー（へんこうできないびゅー / unmodifiable view）

- 意味：`Collections.unmodifiableList(list)` などが返す、元のコレクションを読み取り専用で見せるもの
- ポイント：ビューを通しての変更は UnsupportedOperationException だが、元のコレクションを変えればビューからも見える。「不変（immutable）」とは違う

### 01-1 オートボクシング

#### 問 jgold-01-o01

- 問：次のコードを実行した。表示されるものはどれか（JVM の起動オプションは既定のまま）。

  ```
  Integer a = 127, b = 127;
  Integer c = 128, d = 128;
  System.out.println((a == b) + " " + (c == d) + " " + c.equals(d));
  ```

- ア：true true true
- イ：true false true
- ウ：false false true
