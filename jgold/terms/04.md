## 04-1 ネストしたクラスの種類

### まとめ表

| 種類 | 書く場所 | 外側のインスタンス | 作り方の例 |
| :-: | :-: | :-: | :-: |
| static なネストしたクラス | クラスのメンバー（static 付き） | いらない | `new Outer.Nested()` |
| 内部クラス（メンバー） | クラスのメンバー（static なし） | 必要 | `outer.new Inner()` |
| ローカルクラス | メソッドなどのブロックの中 | インスタンスメソッドの中なら持つ | `new Local()`（そのブロックの中だけ） |
| 無名クラス | new の式の中 | インスタンスメソッドの中なら持つ | `new Runnable() { ... }` |

### 種類

#### ネストしたクラス（ねすとしたくらす / nested class）

- 意味：ほかのクラスやインタフェースの中に宣言したクラス。外側にないクラスはトップレベルクラスという
- ポイント：static なネストしたクラスと、内部クラス（static でないもの全部：メンバーの内部クラス・ローカルクラス・無名クラス）に分かれる。外側のクラスの private なメンバーにもアクセスでき、外側からも内側の private に届く

#### 内部クラス（ないぶくらす / inner class）

- 意味：static でないネストしたクラス。JLS では、メンバーの内部クラス・ローカルクラス・無名クラスをまとめてこう呼ぶ
- ポイント：試験内容の「内部クラス」は、多くの場合メンバーの内部クラス（クラスのメンバーとして static なしで宣言したもの）を指す。外側のクラスのインスタンス（外側のインスタンス）に結び付いて作られる

#### static なネストしたクラス（すたてぃっくなねすとしたくらす / static nested class）

- 意味：static を付けてメンバーとして宣言したネストしたクラス。試験内容では「static な内部クラス」と書かれている
- ポイント：外側のインスタンスを持たないので、外側の static なメンバーだけを直接使える。外側のインスタンスフィールドを使うと「non-static variable … cannot be referenced from a static context」

#### バイナリ名（ばいなりめい / binary name）

- 意味：コンパイルしてできるクラスの名前。ネストしたクラスは「外側$内側」、無名クラスは「外側$1」のように番号になる
- ポイント：getClass().getName() で見える。Outer.Nested のバイナリ名は Outer$Nested、Outer の中の最初の無名クラスは Outer$1

## 04-2 内部クラスと static なネストしたクラス

### まとめ表

| 書き方 | 意味 |
| :-: | :-: |
| `Outer.Inner in = outer.new Inner();` | 外側のインスタンス outer に結び付けて作る |
| `new Inner()`（static メソッドの中） | コンパイルエラー（外側のインスタンスがない） |
| `Outer.this.x` | 外側のインスタンスの x |
| `this.x` | 内部クラス自身の x |
| `new Outer.Nested()` | static なネストしたクラスは外側なしで作れる |

### 内部クラス

#### 外側のインスタンス（そとがわのいんすたんす / enclosing instance）

- 意味：内部クラスのインスタンスが結び付いている、外側のクラスのインスタンス
- ポイント：内部クラスのメソッドから外側のフィールドを読むと、その外側のインスタンスの「今の値」を読む。作ったあとに外側のフィールドを変えれば、変えたあとの値が見える

#### 内部クラスの生成（ないぶくらすのせいせい / qualified class instance creation）

- 意味：`外側のインスタンス.new 内部クラス()` の形で内部クラスのインスタンスを作ること
- ポイント：外側のクラスのインスタンスメソッドの中なら `new Inner()` だけで書ける（this が外側のインスタンスになる）。main のような static メソッドの中で `new Inner()` と書くと「non-static variable this cannot be referenced from a static context」
- 例：`Outer.Inner in = new Outer().new Inner();`

#### Outer.this（あうたーどっとでぃす / qualified this）

- 意味：内部クラスの中で、外側のインスタンスを指す書き方。`外側のクラス名.this`
- ポイント：名前が重なったとき、x は一番内側（引数やローカル変数）、this.x は内部クラスのフィールド、Outer.this.x は外側のフィールド

#### 内部クラスの static メンバー（ないぶくらすのすたてぃっくめんばー / static members of inner classes）

- 意味：内部クラスの中に宣言した static なフィールドやメソッド
- ポイント：Java 16（JEP 395）から、内部クラスにも static なメンバーを宣言できるようになった。Java 17 では `class Inner { static int count = 5; }` はコンパイルできる。以前の版（Java 15 まで）では定数以外はエラーだったので、古い教材とちがう点に注意

#### メンバーのクラスのアクセス修飾子（めんばーのくらすのあくせすしゅうしょくし / access modifiers for member classes）

- 意味：メンバーとして宣言したネストしたクラスには、public・protected・private・なし（パッケージ）を付けられる
- ポイント：トップレベルクラスは public かなしだけで、private を付けると「modifier private not allowed here」。private なネストしたクラスも、外側のクラスの中からは自由に使える

### static なネストしたクラス

#### static なネストしたクラスの生成（すたてぃっくなねすとしたくらすのせいせい / creating a static nested class）

- 意味：`new Outer.Nested()` のように、外側のインスタンスなしで作ること。外側のクラスの中なら `new Nested()` でよい
- ポイント：static なネストしたクラスの static メソッドは `Outer.Nested.twice()` で呼べる

#### インタフェースの中のクラス（いんたふぇーすのなかのくらす / member class of an interface）

- 意味：インタフェースの中に宣言したクラス。暗黙に public で static になる（JLS 9.5）
- ポイント：外側のインスタンスを持たないので、`new Shape.Util()` のように作れる

## 04-3 ローカルクラス

### まとめ表

| ローカルクラスでできること | できないこと |
| :-: | :-: |
| final・abstract を付ける | public・private・protected・static を付ける |
| 外側のメンバーを使う | 宣言したブロックの外から使う |
| effectively final なローカル変数を読む | 代入し直したローカル変数を読む |
| ローカルのレコード・インタフェース・列挙を宣言する（Java 16〜） | ― |

### ローカルクラス

#### ローカルクラス（ろーかるくらす / local class）

- 意味：メソッドやブロックの中で宣言した、名前のあるクラス
- ポイント：使えるのは、宣言したところからブロックの終わりまで。アクセス修飾子も static も付けられない（付けると「illegal start of expression」など）。final や abstract は付けられる

#### effectively final（えふぇくてぃぶりーふぁいなる / effectively final）

- 意味：final を付けていないが、初期化のあと一度も代入し直していないローカル変数や引数。final と同じ扱いになる（JLS 4.12.4）
- ポイント：ローカルクラス・無名クラス・ラムダ式から読めるのは、final か effectively final のローカル変数だけ。クラスの宣言のあとでも、どこかで代入し直すと「local variables referenced from an inner class must be final or effectively final」（ラムダ式では「from a lambda expression」）

#### 変数の捕捉（へんすうのほそく / variable capture）

- 意味：ローカルクラス・無名クラス・ラムダ式が、外側のローカル変数の値を取り込んで使うこと
- ポイント：取り込むのは値のコピーなので、元の変数は変えられない決まりになっている。フィールドは捕捉ではなく外側のインスタンスを通して読むので、変えてもよい。配列の要素の変更もできる（配列の参照は変わらないから）

#### ローカルのレコード・インタフェース・列挙（ろーかるのれこーど / local records, interfaces, enums）

- 意味：メソッドの中で宣言したレコード・インタフェース・列挙型。Java 16 から書ける（JEP 395）
- ポイント：暗黙に static で、外側のインスタンスやローカル変数は使えない。メソッドの中だけで使うデータの組をまとめるのに便利

## 04-4 無名クラス

### まとめ表

| 無名クラスの決まり | 内容 |
| :-: | :-: |
| 作り方 | `new 親クラス(引数) { ... }` か `new インタフェース() { ... }` |
| 親 | クラスを 1 つ継承するか、インタフェースを 1 つ実装するか、どちらか一方 |
| コンストラクタ | 宣言できない。初期化はインスタンス初期化子 `{ ... }` で |
| 新しいメソッド | 宣言できるが、親の型の変数からは呼べない（var なら呼べる） |
| this | 無名クラス自身のインスタンス（ラムダ式では外側） |

### 無名クラス

#### 無名クラス（むめいくらす / anonymous class）

- 意味：名前を付けずに、宣言とインスタンスの生成を 1 つの式で行うクラス。`new Runnable() { public void run() { ... } }`
- ポイント：クラスを 1 つ継承するか、インタフェースを 1 つ実装するかのどちらかだけ。両方や、インタフェースを 2 つは書けない。フィールドやメソッドを追加でき、状態を持てる

#### 無名クラスのコンストラクタ（むめいくらすのこんすとらくた / constructor of an anonymous class）

- 意味：無名クラスには名前がないので、コンストラクタを宣言できない
- ポイント：コンストラクタのつもりで `Greeter() { }` と書くと、戻り値の型のないメソッドとみなされ「invalid method declaration; return type required」。親クラスのコンストラクタへの引数は `new Animal("cat") { ... }` の丸かっこに書く。初期化の処理は `{ add("a"); }` のようなインスタンス初期化子に書く

#### 無名クラスと this（むめいくらすとでぃす / this in an anonymous class）

- 意味：無名クラスの中の this は、無名クラス自身のインスタンスを指す
- ポイント：ラムダ式の中の this は、ラムダ式を書いたクラスのインスタンス。名前が同じフィールドがあると結果が変わる。外側を指すなら `Main.this.name`

#### 追加したメソッドの呼び出し（ついかしためそっどのよびだし / calling a member added by an anonymous class）

- 意味：無名クラスで追加したメソッドを、外から呼ぶこと
- ポイント：`Object obj = new Object() { int hello() {...} };` では、変数の型が Object なので obj.hello() は「cannot find symbol」。`var obj = new Object() { ... };` なら変数の型が無名クラスになり、呼べる

#### 二重かっこ初期化（にじゅうかっこしょきか / double brace initialization）

- 意味：`new ArrayList<>() {{ add("a"); }}` のように、無名クラスのインスタンス初期化子で要素を入れる書き方
- ポイント：ArrayList そのものでなく、ArrayList を継承した無名クラスのインスタンスができる（getClass() は ArrayList.class と等しくない）。外側のインスタンスを持つことがあり、ふつうは List.of などを使う

### 04-1 ネストしたクラスの種類

#### 問 jgold-04-o01

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  class Outer {
    static class Nested { }
    class Inner { }
    public static void main(String[] args) {
      System.out.println(new Nested().getClass().getName() + " " + new Outer().new Inner().getClass().getName());
      Runnable r = new Runnable() { public void run() {} };
      System.out.println(r.getClass().getName());
    }
  }
  ```

- ア：Nested Inner（改行）Runnable
- イ：Outer.Nested Outer.Inner（改行）Outer.Runnable
- ウ：Outer$Nested Outer$Inner（改行）Outer$1
- エ：Outer$Nested Outer$Inner（改行）Outer$Runnable
- 正解：ウ
- 解説：getName() はバイナリ名を返す。ネストしたクラスは「外側$内側」、無名クラスは名前がないので「外側$番号」（最初の無名クラスは $1）。
- アの意味：getSimpleName() に近いが、無名クラスの getSimpleName() は空文字列になる。getName() はバイナリ名。
- イの意味：ソースコードで使う正規名（Outer.Nested）は getCanonicalName() の形。getName() は $ で区切る。
- ウの意味：正しい。
- エの意味：無名クラスの名前は、実装したインタフェースの名前ではなく番号。
- 出典：オリジナル問題（根拠：JLS 13.1 The Form of a Binary（binary name）、API Class.getName／JDK 17 での実行結果）

#### 問 jgold-04-o02

- 問：次のうち、トップレベルクラス（ファイルの一番外側のクラス）の宣言としてコンパイルエラーになるものはどれか。
- ア：`public class Top {}`（ファイル名 Top.java）
- イ：`class Top {}`
- ウ：`final class Top {}`
- エ：`private class Top {}`
- 正解：エ
- 解説：トップレベルクラスに付けられるアクセス修飾子は public かなし（パッケージアクセス）だけ。private を付けると「modifier private not allowed here」。private や protected は、ネストしたクラス（メンバー）なら付けられる。
- アの意味：public なトップレベルクラスは、同じ名前のファイルに書けばよい。
- イの意味：修飾子なし（パッケージアクセス）は正しい。
- ウの意味：final は継承を禁止する修飾子で、トップレベルクラスにも付けられる。
- エの意味：正しい。コンパイルエラーになる。
- 出典：オリジナル問題（根拠：JLS 8.1.1 Class Modifiers（private・protected・static はメンバーのクラスだけ）／JDK 17 でのコンパイル結果）

#### 問 jgold-04-o03

- 問：Java のネストしたクラスについて、正しいものはどれか。
- ア：static なネストしたクラスは、外側のクラスのインスタンスフィールドを直接使える
- イ：内部クラスのインスタンスは、外側のクラスのインスタンスに結び付いて作られる
- ウ：ネストしたクラスからは、外側のクラスの private なメンバーを使えない
- エ：無名クラスは、クラスを 1 つ継承し、さらにインタフェースを 1 つ実装できる
- 正解：イ
- 解説：内部クラス（static でないネストしたクラス）は、外側のインスタンスを持ち、そのフィールドを使える。そのため作るときにも外側のインスタンスが必要。
- アの意味：static なネストしたクラスは外側のインスタンスを持たないので、使えるのは外側の static なメンバーだけ。
- イの意味：正しい。
- ウの意味：ネストしたクラスは外側のクラスの一部なので、private なメンバーも使える。
- エの意味：無名クラスは、クラスを 1 つ継承するか、インタフェースを 1 つ実装するかのどちらかだけ。
- 出典：オリジナル問題（根拠：JLS 8.1.3 Inner Classes and Enclosing Instances・6.6.1（private はトップレベルクラスの本体の中で使える）・15.9.5）

### 04-2 内部クラスと static なネストしたクラス

#### 問 jgold-04-o04

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  class Outer {
    private int x = 10;
    class Inner {
      int get() { return x * 2; }
    }
    public static void main(String[] args) {
      Outer o = new Outer();
      Outer.Inner in = o.new Inner();
      o.x = 7;
      System.out.println(in.get());
    }
  }
  ```

- ア：20
- イ：14
- ウ：コンパイルエラーになる（Inner から private な x を使えない）
- エ：コンパイルエラーになる（o.new Inner() の書き方が誤り）
- 正解：イ
- 解説：内部クラスは外側のインスタンス o に結び付いており、get は呼ばれたときの o.x を読む。o.x は 7 に変わっているので 14。
- アの意味：内部クラスが作られたときの x の値を覚えていると考えたまちがい。毎回外側のインスタンスのフィールドを読む。
- イの意味：正しい。
- ウの意味：ネストしたクラスは外側の private なメンバーを使える。
- エの意味：`外側のインスタンス.new 内部クラス()` は正しい書き方。
- 出典：オリジナル問題（根拠：JLS 8.1.3・15.9.2 Determining Enclosing Instances／JDK 17 での実行結果）

#### 問 jgold-04-o05

- 問：次のコードについて正しいものはどれか。

  ```
  class Outer {
    class Inner {}
    public static void main(String[] args) {
      Inner in = new Inner();
    }
  }
  ```

- ア：コンパイルでき、Inner のインスタンスが作られる
- イ：コンパイルでき、実行時に NullPointerException が投げられる
- ウ：コンパイルエラーになる（Inner の型名は Outer.Inner と書かなければならない）
- エ：コンパイルエラーになる（外側のインスタンスがない）
- 正解：エ
- 解説：main は static メソッドなので this（外側のインスタンス）がない。内部クラスは外側のインスタンスなしでは作れず、「non-static variable this cannot be referenced from a static context」になる。`new Outer().new Inner()` と書けば作れる。
- アの意味：インスタンスメソッドの中なら `new Inner()` で作れるが、static メソッドの中では作れない。
- イの意味：コンパイルの段階でエラーになる。
- ウの意味：外側のクラスの中では、型名を Inner とだけ書いてよい。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：JLS 15.9.2（static な文脈では外側のインスタンスがない）／JDK 17 でのコンパイル結果）

#### 問 jgold-04-o06

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  class Outer {
    int x = 1;
    class Inner {
      int x = 2;
      void show(int x) {
        System.out.println(x + " " + this.x + " " + Outer.this.x);
      }
    }
    public static void main(String[] args) {
      new Outer().new Inner().show(3);
    }
  }
  ```

- ア：3 2 1
- イ：3 3 3
- ウ：1 2 3
- エ：コンパイルエラーになる（Outer.this は static でない文脈では使えない）
- 正解：ア
- 解説：x は一番内側の引数（3）。this.x は Inner のフィールド（2）。Outer.this.x は外側のインスタンスのフィールド（1）。
- アの意味：正しい。
- イの意味：this.x と Outer.this.x も引数を指すと考えたまちがい。this はフィールドを指す。
