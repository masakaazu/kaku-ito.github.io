## 12-1 スレッドの作成と状態

### まとめ表

| 状態（Thread.State） | いつ |
| :-: | :-: |
| NEW | new Thread したが、start していない |
| RUNNABLE | 実行中、または実行できる |
| BLOCKED | synchronized のロックを待っている |
| WAITING | wait()・join()・LockSupport.park() で、時間の指定なしに待っている |
| TIMED_WAITING | sleep(ms)・wait(ms)・join(ms) で、時間を決めて待っている |
| TERMINATED | run が終わった |

### 作る

#### スレッド（すれっど / thread）

- 意味：プログラムの中で、ほかの処理と同時に進められる処理の流れ。java.lang.Thread で表す
- ポイント：main メソッドは「main」という名前のスレッドで動く。名前を付けないと「Thread-0」「Thread-1」…になる。優先度の初期値は 5（NORM_PRIORITY、範囲は 1〜10）
- 語の意味：thread＝糸

#### Thread クラスの継承（すれっどくらすのけいしょう / extending Thread）

- 意味：Thread を継承して run メソッドをオーバーライドし、start で新しいスレッドとして動かす作り方
- ポイント：ほかのクラスを継承できなくなる。run を直接呼ぶと、新しいスレッドではなく呼んだスレッド（main）でふつうのメソッドとして動く

#### Runnable（らなぶる / Runnable）

- 意味：引数なし・戻り値 void の run メソッドだけを持つ関数型インタフェース。new Thread(runnable) に渡して使う
- ポイント：ラムダ式で書ける（new Thread(() -> …)）。run は throws を宣言していないので、ラムダ式の中で Thread.sleep を呼ぶなら try-catch が必要（unreported exception InterruptedException; must be caught or declared to be thrown）。値を返したいなら Callable（#13）

#### start と run（すたーととらん / start, run）

- 意味：start は新しいスレッドを作って、その中で run を呼ぶメソッド。run は処理の中身
- ポイント：同じ Thread に start を 2 回呼ぶと IllegalThreadStateException（終わったあとでも）。start してからの実行の順は決まらない

#### join（じょいん / join）

- 意味：ほかのスレッドが終わるまで、呼んだスレッドを待たせるメソッド
- ポイント：InterruptedException を投げる（チェック例外）。join(ms) は時間を決めて待つ（TIMED_WAITING）

#### sleep（すりーぷ / Thread.sleep）

- 意味：今のスレッドを、指定した時間だけ止める static メソッド
- ポイント：InterruptedException を投げる。ロックを持ったまま止まる（wait とちがい、ロックを手放さない）

#### 割り込み（わりこみ / interrupt）

- 意味：スレッドに「止まってほしい」と知らせるしくみ。interrupt() で割り込みの状態にする
- ポイント：sleep・wait・join の途中で割り込まれると InterruptedException が投げられ、割り込みの状態はクリアされる（isInterrupted() は false）。割り込み状態のまま sleep を呼んでもすぐ InterruptedException。static の Thread.interrupted() は状態を返して、クリアする（2 回呼ぶと true、false）

#### デーモンスレッド（でーもんすれっど / daemon thread）

- 意味：ほかの（デーモンでない）スレッドがすべて終わると、途中でも JVM が終わるスレッド。裏方の処理に使う
- ポイント：setDaemon(true) は start の前に呼ぶ（start したあと、動いている間に呼ぶと IllegalThreadStateException）。デーモンスレッドから作ったスレッドは、初期値がデーモン

#### スレッドの状態（すれっどのじょうたい / Thread.State）

- 意味：getState() が返す、スレッドの今の状態。NEW・RUNNABLE・BLOCKED・WAITING・TIMED_WAITING・TERMINATED の 6 つ
- ポイント：synchronized のロック待ちは BLOCKED、wait()（時間なし）は WAITING、sleep は TIMED_WAITING。「RUNNING」という状態はない

## 12-2 synchronized と排他制御

### まとめ表

| 書き方 | 使うロック |
| :-: | :-: |
| synchronized void m() | this（そのインスタンス） |
| static synchronized void m() | クラスの Class オブジェクト（Main.class） |
| synchronized (obj) { … } | obj |
| synchronized (Main.class) { … } | Main.class |

### 排他

#### 競合状態（きょうごうじょうたい / race condition）

- 意味：複数のスレッドが同じデータを同時に読み書きして、実行のタイミングによって結果が変わってしまうこと
- ポイント：count++ は「読む → 1 足す → 書く」の 3 つの操作なので、同時に行うと更新が失われる。4 スレッドで 10 万回ずつ足しても 40 万にならないことがある

#### synchronized（しんくろないずど / synchronized）

- 意味：ロック（モニター）を取ってから処理し、同じロックを取ろうとするほかのスレッドを待たせる（排他制御）キーワード
- ポイント：インスタンスメソッドは this、static メソッドはクラスのロックを使う。この 2 つは別のロックなので、互いに待たせない。同じスレッドは同じロックを何度でも取れる（再入可能）。コンストラクタには付けられない

#### モニター（もにたー / monitor, intrinsic lock）

- 意味：すべてのオブジェクトが 1 つずつ持っているロック。synchronized で取り、wait・notify もこのロックを使う
- ポイント：ロックを待っているスレッドは BLOCKED。ブロックやメソッドを抜けると、例外で抜けたときもロックは自動で外れる

#### volatile（ぼらたいる / volatile）

- 意味：フィールドの読み書きを、ほかのスレッドからすぐ見えるようにする修飾子
- ポイント：見えること（可視性）は保証するが、count++ のような複数の操作をまとめる（原子性）ことは保証しない。止めるためのフラグ（volatile boolean running）に向く

### うまく進まない状態

#### デッドロック（でっどろっく / deadlock）

- 意味：2 つ以上のスレッドが、互いに相手の持つロックを待って、永久に進めなくなること
- ポイント：スレッド A がロック 1→2、スレッド B がロック 2→1 の順で取ると起きうる。ロックを取る順をそろえると防げる。状態は BLOCKED のまま

#### ライブロック（らいぶろっく / livelock）

- 意味：スレッドは動いている（ブロックされていない）が、互いに譲り合い続けて処理が先に進まないこと
- ポイント：デッドロックとちがい、スレッドは RUNNABLE のまま動き続ける

#### スタベーション（すたべーしょん / starvation）

- 意味：ほかのスレッドがロックなどの資源を長く使い続けるため、あるスレッドがいつまでも資源を得られないこと
- ポイント：ReentrantLock(true)（公平なロック）で、待った順に取れるようにして防ぐことができる
- 語の意味：starvation＝飢餓

## 12-3 待機・通知とロック・アトミック変数

### まとめ表

| 方法 | 特徴 |
| :-: | :-: |
| wait・notify・notifyAll | synchronized の中で呼ぶ。外で呼ぶと IllegalMonitorStateException |
| ReentrantLock | lock・unlock を自分で呼ぶ。tryLock で待たずに試せる |
| ReentrantReadWriteLock | 読み込みロックは複数で共有、書き込みロックは 1 つだけ |
| AtomicInteger など | incrementAndGet などを、ロックなしで原子的に行う |

### 待機と通知

#### wait・notify・notifyAll（うぇいと・のてぃふぁい・のてぃふぁいおーる / wait, notify, notifyAll）

- 意味：wait はロックを手放して通知を待ち、notify は待っているスレッドを 1 つ、notifyAll は全部を起こす Object のメソッド
- ポイント：そのオブジェクトのロックを持っていない（synchronized の外）と IllegalMonitorStateException。wait は while ループで条件を確かめながら呼ぶ（にせの目覚め spurious wakeup に備える）。wait() 中は WAITING

### ロック

#### ReentrantLock（りえんとらんとろっく / ReentrantLock）

- 意味：lock()・unlock() を明示的に呼ぶ、再入可能なロック（java.util.concurrent.locks）
- ポイント：unlock は finally で必ず呼ぶ。持っていないのに unlock すると IllegalMonitorStateException。lock した回数だけ unlock が必要（getHoldCount）。tryLock() はすぐ true/false を返し、tryLock(時間, 単位) は時間まで待つ
- 語の意味：reentrant＝再入可能な

#### ReentrantReadWriteLock（りえんとらんとりーどらいとろっく / ReentrantReadWriteLock）

- 意味：読み込み用と書き込み用の 2 つのロックを持つ ReadWriteLock の実装
- ポイント：読み込みロックは複数のスレッドが同時に持てる。読み込みロックを誰かが持っている間、書き込みロックは取れない

### アトミック変数

#### AtomicInteger（あとみっくいんてじゃー / AtomicInteger）

- 意味：int の値を、ロックを使わずに原子的（途中で割り込まれない一続きの操作として）に更新できるクラス。AtomicLong・AtomicBoolean・AtomicReference もある
- ポイント：incrementAndGet は足してから返す、getAndIncrement は返してから足す。compareAndSet(期待値, 新しい値) は今の値が期待値なら更新して true
- 語の意味：atomic＝それ以上分けられない

### 12-1 スレッドの作成と状態

#### 問 jgold-12-o01

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  static class T extends Thread {
    public void run() { System.out.print("run:" + Thread.currentThread().getName() + " "); }
  }
  // main メソッドの中
  T t = new T();
  t.setName("w");
  t.run();
  t.start();
  t.join();
  ```

- ア：run:w run:w
- イ：run:main run:w
- ウ：run:w だけ
- エ：run:main run:main
- 正解：イ
- 解説：t.run() は新しいスレッドを作らず、main スレッドでふつうのメソッドとして動くので「main」。t.start() は新しいスレッド（名前 w）で run を動かす。
- アの意味：run を直接呼ぶと、今のスレッド（main）で動く。
- イの意味：正しい。
- ウの意味：run を直接呼んだ分も表示される。
- エの意味：start で動く run は、新しいスレッド w で動く。
- 出典：オリジナル問題（根拠：API Thread.start・run・currentThread／JDK 17 での実行結果）

#### 問 jgold-12-o02

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  Thread t = new Thread(() -> System.out.print("x"));
  ```

  ```
  Thread t = new Thread(() -> { try { Thread.sleep(200); } catch (InterruptedException e) {} });
  ```

#### 問 jgold-12-o05

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  Thread t = new Thread(() -> {
  ```

#### 問 jgold-12-o10

- 問：デーモンスレッドの説明として正しいものはどれか。
- ア：デーモンスレッドが終わるまで、JVM は終わらない

- 解説：Runnable の run は void なので、値を返すラムダ式は渡せない（no suitable constructor found for Thread(()->"a")、lambda body is not compatible with a void functional interface）。値を返したいなら Callable を ExecutorService に渡す（#13）。
- アの意味：void の式なので Runnable として渡せる。
- イの意味：無名クラスで Runnable を実装している。
- ウの意味：正しい。コンパイルエラーになる。
- エの意味：Thread を継承した無名クラス。
- 出典：オリジナル問題（根拠：API Thread(Runnable)・Runnable、JLS 15.27.3）
