## 07-1 reduce と collect

### まとめ表

| 書き方 | 戻り値 | 要素 0 個のとき |
| :-: | :-: | :-: |
| reduce(accumulator) | Optional<T> | Optional.empty |
| reduce(identity, accumulator) | T | identity |
| reduce(identity, accumulator, combiner) | U | identity |
| collect(Collector) | Collector で決まる | 空のコレクションなど |
| collect(supplier, accumulator, combiner) | R | supplier が作ったもの |

### リダクション

#### リダクション（りだくしょん / reduction）

- 意味：ストリームの要素を、合計・最大値・連結した文字列・コレクションなど、1 つの結果にまとめる終端操作
- ポイント：reduce は値どうしを組み合わせて新しい値を作る「不変のリダクション」、collect は StringBuilder や List などの入れ物に足していく「可変リダクション」
- 語の意味：reduce＝減らす、まとめる

#### reduce（りでゅーす / reduce）

- 意味：BinaryOperator で要素を 2 つずつ組み合わせ、1 つの値にする終端操作
- ポイント：単位元（identity）を渡す版は T を返し、要素 0 個なら単位元。渡さない版は Optional<T> を返す。Optional を Integer に代入すると「incompatible types: Optional<Integer> cannot be converted to Integer」。単位元は計算に入るので、reduce(10, Integer::sum) は合計 + 10

#### 単位元（たんいげん / identity）

- 意味：reduce の最初の値。どの値 x と組み合わせても x のままになる値（足し算なら 0、掛け算なら 1、文字列の連結なら ""）
- ポイント：並列ストリームでは単位元が何回も使われることがあるので、単位元でない値（10 など）を渡すと逐次と並列で結果が変わる（#09）

#### アキュムレータとコンバイナ（あきゅむれーたとこんばいな / accumulator, combiner）

- 意味：アキュムレータは「途中の結果」に要素を 1 つ取り込む関数。コンバイナは、並列処理で別々に作った途中の結果どうしをまとめる関数
- ポイント：reduce の 3 引数版 `reduce(0, (n, s) -> n + s.length(), Integer::sum)` は、要素の型（String）と結果の型（Integer）が違うときに使う。逐次ストリームではコンバイナは呼ばれない
- 語の意味：accumulate＝ためる／combine＝結合する

#### collect（これくと / collect）

- 意味：要素を可変の入れ物にためていく終端操作。Collector を 1 つ渡す版と、supplier・accumulator・combiner の 3 つを渡す版がある
- ポイント：`collect(StringBuilder::new, StringBuilder::append, StringBuilder::append)` や `collect(ArrayList::new, ArrayList::add, ArrayList::addAll)` のように書ける。3 引数版の accumulator は BiConsumer（値を返さない）

#### Collector（これくた / Collector）

- 意味：collect に渡す「集め方」をまとめたインタフェース。supplier・accumulator・combiner・finisher の組。ふつうは Collectors の static メソッドで作る
- ポイント：Collector と Collectors（s 付きはユーティリティクラス）を区別する

## 07-2 集める Collectors

### まとめ表

| Collectors のメソッド | 結果 | 注意 |
| :-: | :-: | :-: |
| toList()・toSet() | List・Set | 実装の種類は保証なし |
| toUnmodifiableList() | 変更できない List | null があると NPE |
| toCollection(TreeSet::new) | 指定したコレクション | ― |
| toMap(キー, 値) | Map | キーの重複で IllegalStateException、値が null で NPE |
| toMap(キー, 値, マージ) | Map | 重複したら値をマージ |
| toMap(キー, 値, マージ, TreeMap::new) | 指定した Map | ― |
| joining(区切り, 前, 後) | String | 要素 0 個でも前後は付く |
| counting() | Long | int ではない |
| summingInt | Integer | ― |
| averagingInt | Double | 割り算は小数 |
| summarizingInt | IntSummaryStatistics | 件数・合計・最小・平均・最大 |
| minBy・maxBy | Optional<T> | ― |

### コレクションに集める

#### Collectors.toList・toSet（とぅりすと・とぅせっと / toList, toSet）

- 意味：要素を List・Set に集める Collector
- ポイント：どの実装（ArrayList・HashSet など）かや、変更できるかは保証されない。変更できないことを保証したいなら toUnmodifiableList。Stream.toList()（Java 16〜）とは別物

#### Collectors.toUnmodifiableList（とぅあんもでぃふぁいあぶるりすと / toUnmodifiableList）

- 意味：変更できない List に集める Collector（Java 10〜）。toUnmodifiableSet・toUnmodifiableMap もある
- ポイント：add で UnsupportedOperationException。要素に null があると NullPointerException（toList なら null も入る）

#### Collectors.toCollection（とぅこれくしょん / toCollection）

- 意味：Supplier で作ったコレクションに集める Collector
- ポイント：`toCollection(TreeSet::new)` なら重複がなく並んだ Set、`toCollection(ArrayDeque::new)` なら Deque になる

#### Collectors.toMap（とぅまっぷ / toMap）

- 意味：キーを作る関数と値を作る関数で、要素を Map に集める Collector
- ポイント：キーが重複すると IllegalStateException「Duplicate key 2 (attempted merging values bb and cc)」。3 つ目の引数（マージ関数）で重複時の値を決められる。4 つ目で Map の種類（TreeMap::new など）を指定。値が null だと NullPointerException

#### Collectors.joining（じょいにんぐ / joining）

- 意味：CharSequence の要素を 1 つの String に連結する Collector。区切り文字・前・後を指定できる
- ポイント：joining(",", "[", "]") は要素 0 個でも "[]" になる。要素が String でない Stream には使えない（map(String::valueOf) してから）

### 数を求める

#### Collectors.counting（かうんてぃんぐ / counting）

- 意味：要素の数を数える Collector。結果は Long
- ポイント：groupingBy(…, counting()) の値は Map<K, Long>。Map<K, Integer> に代入するとコンパイルエラー

#### Collectors.summingInt・averagingInt（さみんぐいんと・あべれーじんぐいんと / summingInt, averagingInt）

- 意味：ToIntFunction で取り出した int の合計（Integer）・平均（Double）を求める Collector。Long・Double 版もある
- ポイント：averagingInt は割り切れなくても小数になる（1, 2, 4 なら 2.3333333333333335）。要素 0 個なら 0 と 0.0

#### Collectors.summarizingInt（さまらいじんぐいんと / summarizingInt）

- 意味：件数・合計・最小・最大・平均をまとめて求め、IntSummaryStatistics を返す Collector
- ポイント：getCount は long、getSum は long、getAverage は double、getMin・getMax は int。要素 0 個なら getMin は Integer.MAX_VALUE

#### Collectors.minBy・maxBy（みんばい・まっくすばい / minBy, maxBy）

- 意味：Comparator で最小・最大の要素を選ぶ Collector。結果は Optional<T>
- ポイント：終端操作の Stream.max(Comparator) と同じ結果。groupingBy の下流に使うと値が Optional になる

## 07-3 グループ化と下流の Collectors

### まとめ表

| 書き方 | 結果の型 |
| :-: | :-: |
| groupingBy(f) | Map<K, List<T>> |
| groupingBy(f, counting()) | Map<K, Long> |
| groupingBy(f, TreeMap::new, toSet()) | TreeMap<K, Set<T>> |
| partitioningBy(p) | Map<Boolean, List<T>>（true と false の両方が必ずある） |
| partitioningBy(p, counting()) | Map<Boolean, Long> |
| groupingBy(f, mapping(g, toList())) | Map<K, List<U>> |

### 分ける

#### Collectors.groupingBy（ぐるーぴんぐばい / groupingBy）

- 意味：分類関数の結果をキーにして、要素をグループに分ける Collector
- ポイント：引数 1 つなら Map<K, List<T>>（実装は HashMap だが保証はない）。2 つ目に下流 Collector、真ん中に Map の Supplier（TreeMap::new）を渡せる。分類関数が null を返すと NullPointerException

#### Collectors.partitioningBy（ぱーてぃしょにんぐばい / partitioningBy）

- 意味：Predicate の true と false の 2 つに、要素を分ける Collector。キーは Boolean
- ポイント：該当する要素がなくても true と false の両方のキーがある（値は空の List）。groupingBy(p) だと、要素がないキーは入らない。Map の Supplier は渡せない

#### 下流コレクタ（かりゅうこれくた / downstream collector）

- 意味：groupingBy・partitioningBy などで、グループごとの要素をどうまとめるかを決める Collector
- ポイント：counting・summingInt・mapping・filtering・toSet・joining・maxBy・reducing など。groupingBy の下流にさらに groupingBy を入れて、入れ子の Map にもできる

### 下流で変換する

#### Collectors.mapping（まっぴんぐ / mapping）

- 意味：要素を Function で変換してから、下流 Collector に渡す Collector
- ポイント：groupingBy(String::length, mapping(s -> s.charAt(0), toSet())) で、長さごとに先頭の文字の Set

#### Collectors.filtering（ふぃるたりんぐ / filtering）

- 意味：Predicate を満たす要素だけを下流 Collector に渡す Collector（Java 9〜）
- ポイント：先に filter したときと違い、すべての要素が外れたグループもキーとして残る（値は空の List）

#### Collectors.flatMapping（ふらっとまっぴんぐ / flatMapping）

- 意味：要素を Stream に展開してから下流 Collector に渡す Collector（Java 9〜）
- ポイント：groupingBy(List::size, flatMapping(List::stream, toList())) で、リストの中身を平らに集める

#### Collectors.reducing（りでゅーしんぐ / reducing）

- 意味：下流で reduce を行う Collector
- ポイント：単位元なしの reducing(op) は Optional を返すので、groupingBy の値が Optional<T> になる

#### Collectors.collectingAndThen（これくてぃんぐあんどぜん / collectingAndThen）

- 意味：Collector で集めたあと、結果に Function（finisher）をかける Collector
- ポイント：`collectingAndThen(toList(), Collections::unmodifiableList)` で変更できない List にする

#### Collectors.teeing（てぃーいんぐ / teeing）

- 意味：要素を 2 つの Collector に同時に渡し、2 つの結果を BiFunction でまとめる Collector（Java 12〜）
- ポイント：teeing(summingInt(...), counting(), (s, c) -> (double) s / c) で平均を求められる
- 語の意味：tee＝T 字の分岐管

### 07-1 reduce と collect

#### 問 jgold-07-o01

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  System.out.println(Stream.of(1, 2, 3).reduce(10, (x, y) -> x + y) + " "
      + Stream.of(1, 2, 3).reduce((x, y) -> x + y) + " "
      + Stream.<Integer>empty().reduce((x, y) -> x + y) + " "
      + Stream.<Integer>empty().reduce(0, Integer::sum));
  ```

- ア：6 6 null 0
- イ：16 Optional[6] Optional.empty 0
- ウ：16 6 0 0
- エ：6 Optional[6] Optional.empty 10
- 正解：イ
- 解説：単位元を渡した reduce は単位元も計算に入るので 10 + 1 + 2 + 3 ＝ 16。単位元なしの reduce は Optional を返し、要素 0 個なら Optional.empty。単位元ありで要素 0 個なら単位元の 0。
- アの意味：単位元の 10 も足される。また、単位元なしの reduce は Optional を返す（null ではない）。
- イの意味：正しい。
- ウの意味：単位元なしの版は Optional なので Optional[6] と表示される。
- エの意味：単位元は計算に入る。4 つ目は単位元が 0。
- 出典：オリジナル問題（根拠：API Stream.reduce(T, BinaryOperator)・reduce(BinaryOperator)／JDK 17 での実行結果）

### 07-2 集めるCollectors

#### 問 jgold-07-o07

- 問：次のコードを実行した。結果として正しいものはどれか。

  ```
  Map<Integer, String> m = Stream.of("a", "bb", "cc").collect(toMap(String::length, s -> s));
  System.out.println(m);
  ```

- ア：{1=a, 2=cc} と表示される
- イ：{1=a, 2=bb} と表示される
- ウ：IllegalStateException が投げられる
- エ：コンパイルエラーになる
- 正解：ウ
- 解説：toMap は、キーが重複すると「Duplicate key 2 (attempted merging values bb and cc)」の IllegalStateException を投げる。重複がありうるなら 3 つ目の引数でマージ関数を渡す。
- アの意味：Map.put のように後勝ちで上書きはしない。
- イの意味：先勝ちで無視もしない。
- ウの意味：正しい。
- エの意味：型は合っており、コンパイルは通る。
- 出典：オリジナル問題（根拠：API Collectors.toMap(Function, Function)（If the mapped keys contain duplicates, an IllegalStateException is thrown）／JDK 17 での実行結果）

#### 問 jgold-07-o08

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  Map<Integer, String> m1 = Stream.of("a", "bb", "cc").collect(toMap(String::length, s -> s, (x, y) -> x + "+" + y));
  TreeMap<String, Integer> m2 = Stream.of("b", "a", "b").collect(toMap(s -> s, s -> 1, Integer::sum, TreeMap::new));
  System.out.println(m1 + " " + m2);
  ```

- ア：{1=a, 2=cc} {b=2, a=1}
- イ：{1=a, 2=bb+cc} {b=2, a=1}
- ウ：{1=a, 2=cc+bb} {a=1, b=2}
- エ：{1=a, 2=bb+cc} {a=1, b=2}
- 正解：エ
- 解説：マージ関数は (先の値, 後の値) で呼ばれ、"bb+cc"。m2 は同じキーの 1 を Integer::sum で足し、TreeMap なのでキーの順に a=1, b=2。

#### 問 jgold-07-o30

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  System.out.println(Stream.of("b", "a", "b").collect(toSet()).size() + " "
      + Stream.of("x", "y").collect(toMap(Function.identity(), String::length)));
  ```

- ア：3 {x=1, y=1}
- イ：2 {1=x, 1=y}
- ウ：2 と表示されたあと、IllegalStateException が投げられる
- エ：2 {x=1, y=1}
- 正解：エ
- 解説：toSet は重複をなくすので 2。toMap のキーは identity で要素そのもの、値は長さ。キーは x と y で重複しない（値が同じ 1 でも問題ない）。
- アの意味：Set なので重複した "b" は 1 つになる。
- イの意味：1 つ目の関数がキー、2 つ目が値。
- ウの意味：重複で例外になるのはキーだけで、値が同じでもよい。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：API Collectors.toSet・toMap、Function.identity／JDK 17 での実行結果）
