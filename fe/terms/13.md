## 13-1 開発プロセス・手法

### まとめ表

**開発モデルの比べ方**

| モデル | 進め方 | 向くもの |
| :-: | :-: | :-: |
| ウォーターフォール | 工程を順番に進め、原則として後戻りしない | 要件がはっきりした大規模開発 |
| プロトタイピング | 試作品を見せて要件を固める | 要件があいまいなとき |
| スパイラル | 設計・開発・評価を繰り返して大きくする | リスクの大きい開発 |
| アジャイル | 短い期間で動くものを作り、変化に合わせる | 変化が多い開発 |


### 開発モデル

#### ウォーターフォールモデル（Waterfall Model）

- 意味：要件定義から設計・プログラミング・テストまで、工程を順に進める開発モデル
- ポイント：計画や管理はしやすいが、後から変えにくい

#### プロトタイピングモデル（Prototyping Model）

- 意味：早い段階で試作品（プロトタイプ）を作り、利用者に見せて要件を固める開発モデル

#### スパイラルモデル（Spiral Model）

- 意味：設計・開発・評価を何回も繰り返し、少しずつ大きくしていく開発モデル

#### アジャイル開発（Agile Development）

- 意味：短い期間（イテレーション）ごとに動くソフトウェアを作り、変化に柔軟に対応する開発
- ポイント：スクラムやXPが代表

#### スクラム（Scrum）

- 意味：スプリントという短い期間を繰り返して開発を進めるアジャイルの手法
- ポイント：プロダクトオーナー・スクラムマスター・開発者の役割がある

#### XP（えっくすぴー / Extreme Programming）

- 意味：プログラムを書くことを重視したアジャイル開発の手法
- ポイント：ペアプログラミング、テスト駆動開発、リファクタリングなど
- 語の意味：Extreme＝極端な（良い習慣を徹底する）／Programming＝プログラミング

#### ペアプログラミング（Pair Programming）

- 意味：2人1組で、1人が書き、もう1人が確かめながらプログラムを作ること

#### テスト駆動開発（TDD / Test-Driven Development）

- 意味：先にテストを書き、そのテストに通るようにプログラムを作る開発の進め方

#### リファクタリング（Refactoring）

- 意味：外から見た動きは変えずに、プログラムの中の作りを整理して読みやすくすること

#### DevOps（でぶおぷす / Development and Operations）

- 意味：開発チームと運用チームが協力して、速く確実にソフトウェアを届ける考え方
- 語の意味：Development＝開発／Operations＝運用

#### CI/CD（しーあいしーでぃー / Continuous Integration / Continuous Delivery）

- 意味：変更を頻繁に統合して自動でテストし（CI）、いつでもリリースできる状態にする（CD）仕組み
- 語の意味：Continuous＝継続的な／Integration＝統合／Delivery＝提供

#### 共通フレーム（Common Frame）

- 意味：ソフトウェアの開発や取引で使う作業や用語の意味をそろえるための枠組み
- ポイント：発注者と受注者の誤解を防ぐ

#### CMMI（しーえむえむあい / Capability Maturity Model Integration）

- 意味：開発プロセスの成熟度を5段階で評価するモデル
- 語の意味：Capability＝能力／Maturity＝成熟度／Model＝モデル／Integration＝統合

#### リバースエンジニアリング（Reverse Engineering）

- 意味：既にあるソフトウェアを解析して、仕様や設計を明らかにすること
- ポイント：逆に、そこから新しく作り直すのがフォワードエンジニアリング


## 13-2 知的財産適用管理


### ソフトウェアの権利

#### ソフトウェアの著作権（Copyright of Software）

- 意味：プログラムは著作物として著作権で守られる
- ポイント：アルゴリズムやプログラム言語そのものは保護されない

#### ソフトウェアライセンス（Software License）

- 意味：ソフトウェアを使ってよい条件を定めた契約
- ポイント：使う前にライセンスの範囲を確かめる


## 13-3 開発環境管理


### 開発の道具

#### 開発環境（Development Environment）

- 意味：開発に使うコンピュータ・ツール・ライブラリなど
- ポイント：本番環境と分けて用意する

#### テスト環境（Test Environment）

- 意味：本番に近い形でテストをするための環境


## 13-4 構成管理・変更管理


### 管理の仕組み

#### 構成管理（こうせいかんり / Configuration Management）

- 意味：プログラムや文書などの成果物の版（バージョン）と、その組合せを管理すること

#### バージョン管理（Version Control）

- 意味：ファイルの変更の履歴を記録し、前の状態に戻したり複数人の変更をまとめたりすること
- 例：Git

#### 変更管理（へんこうかんり / Change Management）

- 意味：成果物を変えるときの依頼・審査・承認・実施の手順を管理すること
