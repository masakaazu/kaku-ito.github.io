## 9-1 データベース方式

### まとめ表

**3層スキーマ**

| スキーマ | 何を定義するか |
| :-: | :-: |
| 外部スキーマ | 利用者やアプリから見たデータ（ビュー） |
| 概念スキーマ | データベース全体の論理的な構造（表の定義） |
| 内部スキーマ | ディスク上にどう格納するか |

**NoSQLの種類**

| 種類 | データの持ち方 |
| :-: | :-: |
| キーバリュー型 | キーと値の組 |
| ドキュメント型 | JSONなどの文書 |
| カラム指向型 | 列ごとにまとめる |
| グラフ型 | ノードとエッジ（つながり） |


### データベースの基本

#### データベース（Database）

- 意味：多くのデータを整理して、共有・検索しやすくまとめたもの

#### DBMS（でぃーびーえむえす / Database Management System）

- 意味：データベースを管理するソフトウェア。同時実行の制御や障害回復を行う
- 語の意味：Database＝データベース／Management＝管理／System＝仕組み

#### 関係データベース（かんけいでーたべーす / Relational Database）

- 意味：データを行と列の表（関係）で表すデータベース
- ポイント：行をタプル（レコード）、列を属性（フィールド）と呼ぶ

#### 3層スキーマ（さんそうすきーま / Three-schema Architecture）

- 意味：データベースを外部スキーマ・概念スキーマ・内部スキーマの3つに分けて定義する考え方
- ポイント：1つを変えても他への影響を小さくできる（データの独立性）

#### 外部スキーマ（External Schema）

- 意味：利用者やアプリケーションから見たデータベースの見え方を定義したもの
- ポイント：ビューにあたる

#### 概念スキーマ（Conceptual Schema）

- 意味：データベース全体の論理的な構造を定義したもの
- ポイント：表の定義にあたる

#### 内部スキーマ（Internal Schema）

- 意味：データを記憶装置にどう格納するかを定義したもの

#### NoSQL（のーえすきゅーえる / Not only SQL）

- 意味：表の形にとらわれず、大量のデータを柔軟に扱うデータベースの総称
- ポイント：キーバリュー型・ドキュメント型・カラム指向型・グラフ型がある
- 語の意味：Not only＝〜だけではない／SQL＝関係データベースの言語

#### キーバリュー型（Key-Value Store）

- 意味：キーと値の組だけでデータを持つNoSQL
- ポイント：単純で速い

#### ドキュメント型（Document Store）

- 意味：JSONなどの文書の形でデータを持つNoSQL

#### グラフ型（Graph Database）

- 意味：ノード（点）とエッジ（線）で、データどうしのつながりを表すNoSQL
- 例：SNSの友達関係


## 9-2 データベース設計

### まとめ表

**正規化の段階**

| 段階 | やること |
| :-: | :-: |
| 第1正規形 | 繰返し項目をなくす |
| 第2正規形 | 主キーの一部だけに従属する項目（部分関数従属）を別の表に分ける |
| 第3正規形 | 主キー以外の項目に従属する項目（推移的関数従属）を別の表に分ける |


### データの設計

#### E-R図（いーあーるず / Entity Relationship Diagram）

- 意味：実体（エンティティ）と、実体どうしの関連（リレーションシップ）を表した図
- ポイント：1対多などの関係（カーディナリティ）も表す
- 語の意味：Entity＝実体／Relationship＝関連／Diagram＝図

#### 主キー（しゅきー / Primary Key）

- 意味：表の中の行を1つに決められる列。重複やNULLは許されない
- ポイント：複数の列を組み合わせたものを複合主キーという

#### 外部キー（がいぶきー / Foreign Key）

- 意味：ほかの表の主キーを参照する列
- ポイント：参照先にない値は入れられない（参照制約）

#### 正規化（せいきか / Normalization）

- 意味：データの重複をなくすように表を分けること
- ポイント：更新したときの矛盾（更新時異状）を防ぐ

#### 関数従属（かんすうじゅうぞく / Functional Dependency）

- 意味：ある項目の値が決まると、別の項目の値が1つに決まる関係

#### 部分関数従属（ぶぶんかんすうじゅうぞく / Partial Functional Dependency）

- 意味：複合主キーの一部だけで、ほかの項目が決まってしまう関係
- ポイント：取り除くと第2正規形になる

#### 推移的関数従属（すいいてきかんすうじゅうぞく / Transitive Functional Dependency）

- 意味：主キー以外の項目を通して、さらに別の項目が決まる関係
- ポイント：取り除くと第3正規形になる

#### インデックス（Index）

- 意味：検索を速くするための索引
- ポイント：更新のたびにインデックスも直すので、更新は少し遅くなる


## 9-3 データ操作

### まとめ表

**SQLの実行順序**

| 順番 | 句 | 役割 |
| :-: | :-: | :-: |
| 1 | FROM | 表を決める |
| 2 | WHERE | 行を絞る |
| 3 | GROUP BY | グループにまとめる |
| 4 | HAVING | グループを絞る |
| 5 | SELECT | 表示する列を決める |
| 6 | ORDER BY | 並べ替える |


### 関係演算

#### 選択（せんたく / Selection）

- 意味：表から、条件に合う行を取り出す関係演算

#### 射影（しゃえい / Projection）

- 意味：表から、指定した列だけを取り出す関係演算

#### 結合（けつごう / Join）

- 意味：共通の列をもとに、2つの表をつなぎ合わせる関係演算


### SQL

#### SQL（えすきゅーえる / Structured Query Language）

- 意味：関係データベースを操作するための言語
- ポイント：定義するDDLと、操作するDMLがある
- 語の意味：Structured＝構造化された／Query＝問合せ／Language＝言語

#### DDL（でぃーでぃーえる / Data Definition Language）

- 意味：表などを定義するSQL。CREATE・ALTER・DROP
- 語の意味：Data＝データ／Definition＝定義／Language＝言語

#### DML（でぃーえむえる / Data Manipulation Language）

- 意味：データを操作するSQL。SELECT・INSERT・UPDATE・DELETE
- 語の意味：Data＝データ／Manipulation＝操作／Language＝言語

#### WHERE句・HAVING句（WHERE, HAVING）

- 意味：WHEREは行を、HAVINGはGROUP BYでまとめたグループを条件で絞る

#### 集合関数（しゅうごうかんすう / Aggregate Function）

- 意味：複数の行をまとめて1つの値にする関数。SUM・AVG・COUNT・MAX・MIN

#### ビュー（View）

- 意味：表から必要な部分を取り出して、仮想的な表として見せるもの
- ポイント：外部スキーマにあたる

#### ストアドプロシージャ（Stored Procedure）

- 意味：よく使うSQLの処理をDBMSに保存しておき、呼び出して実行する仕組み
- ポイント：通信の回数を減らせる


## 9-4 トランザクション処理

### まとめ表

**障害からの回復**

| 処理 | 使うもの | どうするか |
| :-: | :-: | :-: |
| ロールバック | 更新前ログ | トランザクションの途中の更新を取り消す |
| ロールフォワード | バックアップ＋更新後ログ | バックアップを戻し、記録した更新をやり直す |


### トランザクション

#### トランザクション（Transaction）

- 意味：データベースへの、ひとまとまりの処理
- ポイント：全部成功（コミット）か、全部取り消し（ロールバック）のどちらか

#### ACID特性（あしっどとくせい / ACID Properties）

- 意味：トランザクションが満たすべき4つの性質
- 語の意味：Atomicity＝原子性（全部か無か）／Consistency＝一貫性／Isolation＝独立性／Durability＝耐久性

#### 排他制御（はいたせいぎょ / Exclusive Control）

- 意味：複数の処理が同じデータを同時に更新して矛盾しないよう、ロックをかけて順番に処理させる仕組み
- ポイント：共有ロック（読むだけ）と専有ロック（書き換える）がある

#### コミット（Commit）

- 意味：トランザクションの処理を確定させること

#### ロールバック（Rollback）

- 意味：更新前のログを使って、トランザクションの途中の更新を取り消すこと

#### ロールフォワード（Rollforward）

- 意味：障害のあと、バックアップを戻してから、ログ（ジャーナル）の更新後の記録を使って処理をやり直すこと

#### ジャーナルファイル（ログファイル / Journal File）

- 意味：データベースへの更新の前後の内容を記録したファイル
- ポイント：障害回復に使う

#### チェックポイント（Checkpoint）

- 意味：主記憶にある更新内容を、一定の時点でディスクに書き出すこと
- ポイント：回復はチェックポイントから行えばよい


## 9-5 データベース応用


### データの活用

#### データウェアハウス（Data Warehouse）

- 意味：いろいろなシステムのデータを、分析しやすい形で時系列に集めたデータベース

#### データマイニング（Data Mining）

- 意味：大量のデータから、隠れた規則や関係を見つけ出すこと
- 例：一緒に買われやすい商品の発見

#### ビッグデータ（Big Data）

- 意味：量が多く、種類がさまざまで、速く発生する大量のデータ

#### 構造化データ・非構造化データ（Structured / Unstructured Data）

- 意味：構造化データは表の形に整理されたデータ、非構造化データは画像・音声・自由記述文など決まった形のないデータ

#### データレイク（Data Lake）

- 意味：構造化・非構造化を問わず、データを元の形のままためておく場所

#### 外部データベース（External Database）

- 意味：外部の事業者が提供していて、利用料を払って使うデータベース

### 9-3 データ操作

#### 問 927no8-q1

- 問：関係演算で、条件に合う「行」を取り出す操作はどれか。
- ア：選択
- イ：射影
- ウ：結合
- エ：除算
- 正解：ア
- 解説：選択は条件に合う行を取り出す操作です。射影は列を取り出します。

#### 問 927no8-q2

- 問：表から社員番号と氏名だけを取り出す操作に最も対応するものはどれか。
- ア：選択
- イ：射影
- ウ：結合
- エ：直積
- 正解：イ
- 解説：必要な列を取り出すので射影です。SQLではSELECTで列を指定します。

#### 問 927no8-q3

- 問：表の定義を削除するSQL文として適切なものはどれか。
- ア：DELETE
- イ：DROP
- ウ：UPDATE
- エ：INSERT
- 正解：イ
- 解説：DROPは表などの定義を削除するDDLです。DELETEは表内の行を削除するDMLです。

#### 問 927no8-q4

- 問：SQLの内部的な実行順序として正しいものはどれか。
- ア：SELECT → FROM → WHERE → ORDER BY
- イ：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
- ウ：FROM → SELECT → WHERE → HAVING → GROUP BY → ORDER BY
- エ：WHERE → FROM → SELECT → GROUP BY → HAVING → ORDER BY
- 正解：イ
- 解説：FROMで対象表を決めてから、WHERE、GROUP BY、HAVING、SELECT、ORDER BYの順です。

#### 問 927no8-q5

- 問：GROUP BYで作られたグループを条件で絞り込む句はどれか。
- ア：WHERE
- イ：HAVING
- ウ：ORDER BY
- エ：FROM
- 正解：イ
- 解説：WHEREはグループ化前の行、HAVINGはグループ化後のグループを絞ります。

#### 問 927no9-db-4

- 問：DBMS側に保存したSQL命令群を実行し、通信回数を減らす仕組みはどれか。
- ア：ビュー
- イ：トリガ
- ウ：ストアドプロシージャ
- エ：外部スキーマ
- 正解：ウ
- 解説：ストアドプロシージャはDBMS上に保存・実行され、ネットワーク負荷の軽減などが期待できる。

#### 問 fe-9-q03

- 問：2つの表を、共通する列の値をもとにつなぎ合わせる関係演算はどれか。
- ア：選択
- イ：射影
- ウ：結合
- エ：和
- 正解：ウ
- 解説：結合（ジョイン）は共通列で表をつなぐ。行を取り出すのが選択、列を取り出すのが射影。

- ウ：コミット
- エ：チェックポイント
- 正解：ア
- 解説：途中までの更新は更新前ログで取り消す（ロールバック）。
