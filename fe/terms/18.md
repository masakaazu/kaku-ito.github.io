## 18-1 システム化計画


### 計画を立てる

#### システム化構想（System Concept）

- 意味：経営の課題をもとに、どの業務をどうシステム化するかの全体像を描くこと

#### システム化計画（System Planning）

- 意味：システム化の範囲・スケジュール・費用・体制などを決めること

#### 投資対効果（ROI / Return On Investment）

- 意味：投資した金額に対して、どれだけの利益が得られたかを表す指標
- ポイント：利益 ÷ 投資額 × 100（％）

#### 費用対効果分析（Cost-Effectiveness Analysis）

- 意味：かかる費用と得られる効果を比べて、投資するかを判断すること


## 18-2 要件定義


### 要件を決める

#### 業務要件（Business Requirements）

- 意味：システム化する業務の内容や手順など、業務の面から求められること

#### 要件定義（Requirements Definition）

- 意味：利用者の要望を整理し、システムが満たすべき機能や性能を決めること
- ポイント：発注者と開発者が合意する

#### 機能要件（Functional Requirements）

- 意味：システムが「何をするか」についての要件
- 例：注文を登録できる

#### 非機能要件（Non-functional Requirements）

- 意味：性能・信頼性・セキュリティなど、機能以外の要件
- 例：応答時間、稼働率

#### 利害関係者要件（Stakeholder Requirements）

- 意味：利用者や発注者など、関係する人たちが求めること


## 18-3 調達計画・実施

### まとめ表

**調達の流れ**

| 順番 | 文書・作業 | 誰から誰へ |
| :-: | :-: | :-: |
| 1 | RFI（情報提供依頼書） | 発注者 → ベンダ |
| 2 | RFP（提案依頼書） | 発注者 → ベンダ |
| 3 | 提案書・見積書 | ベンダ → 発注者 |
| 4 | ベンダの選定・契約 | 発注者とベンダ |


### 調達

#### ベンダ（Vendor）

- 意味：システムやサービスを開発・提供する側の企業
- ポイント：発注する側はユーザ企業という

#### RFI（あーるえふあい / Request For Information）

- 意味：ベンダに、製品や技術、実績などの情報の提供を頼む文書。情報提供依頼書
- 語の意味：Request＝依頼／For＝〜のための／Information＝情報

#### RFP（あーるえふぴー / Request For Proposal）

- 意味：ベンダに、システムの要件を示して具体的な提案を頼む文書。提案依頼書
- 語の意味：Request＝依頼／For＝〜のための／Proposal＝提案

#### RFQ（あーるえふきゅー / Request For Quotation）

- 意味：ベンダに見積りを頼む文書。見積依頼書
- 語の意味：Request＝依頼／Quotation＝見積り

#### 提案書（Proposal）

- 意味：RFPを受けたベンダが作る、システムの具体案をまとめた文書

#### 評価基準（Evaluation Criteria）

- 意味：提案を公平に比べるための基準
- ポイント：RFPを出す前に決めておく

#### グリーン調達（Green Procurement）

- 意味：環境への負担が少ない製品やサービスを選んで買うこと

### 18-1 システム化計画

#### 問 fe-18-q01

- 問：投資額200万円で、利益が50万円得られたときのROIはどれか。
- ア：4％
- イ：25％
- ウ：40％
- エ：250％
- 正解：イ
- 解説：ROI＝50÷200×100＝25％。

### 18-2 要件定義

#### 問 fe-18-q02

- 問：非機能要件の例として適切なものはどれか。
- ア：受注を登録する
- イ：在庫を照会する
- ウ：24時間365日稼働する
- エ：請求書を発行する
- 正解：ウ
- 解説：稼働率や性能は非機能要件。ほかは機能要件。

### 18-3 調達計画・実施

#### 問 916no1-strategy-0

- 問：システムの利用・発注側の企業に対し、開発・提供側の企業を何という？
- ア：ベンダ
- イ：ユーザ企業
- ウ：利用者
- エ：監査人
- 正解：ア
- 解説：ベンダはIT製品やシステムを提供・開発・導入する売り手側。

#### 問 916no1-strategy-1

- 問：製品・技術・実績について情報を集めるための依頼書は？
- ア：RFI
- イ：RFP
- ウ：RFQ
- エ：WORM
- 正解：ア
- 解説：RFIは情報提供依頼書。

#### 問 916no1-strategy-2

- 問：要件を示して具体的なシステム提案を依頼する文書は？
- ア：RFI
- イ：RFP
- ウ：RFQ
- エ：IDS
- 正解：イ
- 解説：RFPは提案依頼書。見積価格中心ならRFQ。

#### 問 927no2-development-0

- 問：RFPの説明として最も適切なものは？
- ア：情報を収集するための依頼書
- イ：提案を求めるための依頼書
- ウ：障害報告書
- エ：テスト結果報告書
- 正解：イ
- 解説：RFPはRequest For Proposal（提案依頼書）です。

#### 問 fe-18-q03

- 問：調達の手順として適切な順番はどれか。
- ア：RFP → RFI → 契約
- イ：RFI → RFP → 提案書の評価 → 契約
- ウ：提案書 → RFI → RFP
- エ：契約 → RFP → RFI
- 正解：イ
- 解説：まず情報を集め（RFI）、次に提案を依頼し（RFP）、提案を評価して契約する。
