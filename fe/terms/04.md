## 4-1 システムの構成

### まとめ表

**冗長構成の比べ方**

| 方式 | 普段の動き | 障害のとき |
| :-: | :-: | :-: |
| デュアルシステム | 2組で同じ処理をして結果を照合 | 片方を切り離して続ける |
| デュプレックスシステム | 1組が本番、もう1組は待機 | 待機系に切り替える |
| ホットスタンバイ | 待機系も起動済み | すぐ切り替わる |
| コールドスタンバイ | 待機系は止めている | 起動してから切り替える |


### 処理形態

#### 集中処理（しゅうちゅうしょり / Centralized Processing）

- 意味：1台の大きなコンピュータですべて処理する形態
- ポイント：管理しやすいが、止まると全体が止まる

#### 分散処理（ぶんさんしょり / Distributed Processing）

- 意味：複数のコンピュータで処理を分け合う形態
- ポイント：一部が止まっても続けやすいが、管理が複雑

#### バッチ処理（一括処理 / Batch Processing）

- 意味：データを一定期間ためて、まとめて処理する方式
- 例：月末の給与計算

#### リアルタイム処理（Real-time Processing）

- 意味：データが発生したらすぐに処理する方式
- 例：座席予約、銀行ATM

#### クライアントサーバシステム（Client Server System）

- 意味：サービスを頼む側（クライアント）と提供する側（サーバ）に役割を分けたシステム
- ポイント：2層はクライアントがアプリの処理も持つ。3層はプレゼンテーション層・アプリケーション層・データ層に分ける

#### 3層クライアントサーバシステム（3-tier Client Server）

- 意味：画面（プレゼンテーション層）、業務処理（アプリケーション層）、データ管理（データ層）の3つに分けた構成
- ポイント：業務処理はアプリケーションサーバが担当する。修正の影響を小さくできる

#### シンクライアント（Thin Client）

- 意味：端末には画面表示と入力だけをさせ、処理やデータはサーバに置く方式
- ポイント：端末にデータが残らないので情報漏えいを防ぎやすい

#### VDI（ぶいでぃーあい / Virtual Desktop Infrastructure）

- 意味：サーバ上の仮想マシンでデスクトップ環境を動かし、端末に画面だけ送る仕組み
- ポイント：クラウド事業者が提供する形態はDaaS
- 語の意味：Virtual＝仮想の／Desktop＝デスクトップ環境／Infrastructure＝基盤

#### ピアツーピア（Peer to Peer）

- 意味：対等な関係のコンピュータどうしが直接データをやり取りする形態
- ポイント：サーバを置かない

#### プル型・プッシュ型（Pull, Push）

- 意味：プル型は受け手が自分から情報を取りに行く方式、プッシュ型は送り手が受け手に届ける方式
- 例：Webページの閲覧はプル型、通知はプッシュ型


### システムの構成方式

#### デュアルシステム（Dual System）

- 意味：2組のシステムで同じ処理を同時に行い、結果を照合する方式
- ポイント：信頼性は高いが費用もかかる

#### デュプレックスシステム（Duplex System）

- 意味：1組を本番で動かし、もう1組を障害に備えた予備にする方式
- ポイント：予備の待ち方でホットスタンバイ・コールドスタンバイに分かれる

#### クラスタ（Cluster）

- 意味：複数のコンピュータをつないで、1台のシステムのように動かす構成
- ポイント：負荷分散や、障害時の切替え（フェールオーバ）に使う

#### スケールアウト（Scale Out）

- 意味：サーバの台数を増やして処理能力を上げる方法
- ポイント：負荷分散しやすい処理に向く

#### スケールアップ（Scale Up）

- 意味：1台のサーバのCPUやメモリを強くして処理能力を上げる方法

#### 仮想化（かそうか / Virtualization）

- 意味：1台の物理的なコンピュータの上で、複数の仮想的なコンピュータを動かす技術
- ポイント：ライブマイグレーションは、動いたまま別の物理サーバへ移すこと

#### コンテナ型仮想化（Container）

- 意味：OSを共有して、アプリごとに分けた実行環境（コンテナ）を動かす方式
- ポイント：仮想マシンより軽く、すぐ起動する

#### マイクロサービス（Microservices）

- 意味：システムの機能を、小さく独立したサービスに分けて組み合わせる構成
- ポイント：1つにまとめた構成はモノリシック。マイクロサービスは部分ごとに変更しやすい

#### RAID（れいど / Redundant Arrays of Inexpensive Disks）

- 意味：複数のディスクを組み合わせて、速さや信頼性を高める技術
- ポイント：RAID 0＝ストライピング（分散して速く、冗長なし）、RAID 1＝ミラーリング（同じデータを複数に）、RAID 5＝データとパリティを分散
- 語の意味：Redundant＝冗長な／Arrays＝並べたもの／Inexpensive Disks＝安価なディスク

#### NAS（なす / Network Attached Storage）

- 意味：ネットワークに直接つなぐファイルサーバ専用の記憶装置
- 語の意味：Network＝ネットワーク／Attached＝接続された／Storage＝記憶装置


### クラウドサービス

#### クラウドコンピューティング（Cloud Computing）

- 意味：サーバやソフトウェアを、インターネット経由で必要な分だけ使う形態
- ポイント：自社で持つのはオンプレミス

#### SaaS（さーす / Software as a Service）

- 意味：アプリケーションまでを事業者が用意し、利用者はそのまま使うサービス
- 例：Webメール、オンライン表計算
- 語の意味：Software＝ソフトウェア／as a Service＝サービスとして

#### PaaS（ぱーす / Platform as a Service）

- 意味：OSやミドルウェアなど、アプリを動かす基盤を提供するサービス
- ポイント：利用者はアプリを作って載せる
- 語の意味：Platform＝実行基盤／as a Service＝サービスとして

#### IaaS（いあーす / Infrastructure as a Service）

- 意味：サーバ・ストレージ・ネットワークなどの設備を提供するサービス
- ポイント：OSから上は利用者が管理する
- 語の意味：Infrastructure＝基盤設備／as a Service＝サービスとして

#### DaaS（だーす / Desktop as a Service）

- 意味：仮想デスクトップ環境をクラウドで提供するサービス
- 語の意味：Desktop＝デスクトップ環境／as a Service＝サービスとして

#### エッジコンピューティング（Edge Computing）

- 意味：利用者や機器の近くにサーバを置いて処理する方式
- ポイント：遅延を減らし、通信量を抑えられる


## 4-2 システムの評価指標

### まとめ表

**稼働率の計算**

| 構成 | 稼働率 |
| :-: | :-: |
| 単体 | MTBF ÷ (MTBF ＋ MTTR) |
| 直列（両方動く必要） | A × B |
| 並列（どちらかが動けばよい） | 1 − (1−A) × (1−B) |


### 性能

#### スループット（Throughput）

- 意味：単位時間あたりに処理できる仕事の量
- 例：1秒あたりの処理件数

#### レスポンスタイム（応答時間 / Response Time）

- 意味：要求を出し終えてから、最初の応答が返ってくるまでの時間
- ポイント：主にオンライン処理で使う

#### ターンアラウンドタイム（Turnaround Time）

- 意味：処理を依頼してから、すべての結果を受け取るまでの時間
- ポイント：主にバッチ処理で使う

#### ベンチマーク（Benchmark）

- 意味：標準的なプログラムを実行して、性能を比べる方法
- 例：SPEC、TPC

#### キャパシティプランニング（Capacity Planning）

- 意味：将来の利用量を見込んで、必要な処理能力や設備を計画すること


### 信頼性

#### RASIS（らしす）

- 意味：システムを評価する5つの観点。信頼性・可用性・保守性・保全性（完全性）・安全性
- 語の意味：Reliability＝信頼性／Availability＝可用性／Serviceability＝保守性／Integrity＝保全性／Security＝安全性

#### MTBF（えむてぃーびーえふ / Mean Time Between Failures）

- 意味：故障してから次に故障するまでの平均時間。平均故障間隔
- ポイント：長いほど信頼性が高い。稼働時間の合計 ÷ 故障回数
- 語の意味：Mean Time＝平均時間／Between Failures＝故障と故障の間の

#### MTTR（えむてぃーてぃーあーる / Mean Time To Repair）

- 意味：故障してから修理が終わるまでの平均時間。平均修復時間
- ポイント：短いほど保守性が高い
- 語の意味：Mean Time＝平均時間／To Repair＝修理までの

#### 稼働率（かどうりつ / Availability）

- 意味：システムが使える状態にある時間の割合
- 例：MTBF 3,600時間・MTTR 900時間なら 3,600÷4,500＝0.8

#### 故障率（こしょうりつ / Failure Rate）

- 意味：単位時間あたりに故障する割合。1 ÷ MTBF

#### バスタブ曲線（Bathtub Curve）

- 意味：時間と故障率の関係を表す、浴槽の形の曲線
- ポイント：初期故障期（だんだん減る）→ 偶発故障期（一定）→ 摩耗故障期（増える）


### 信頼性設計

#### フォールトアボイダンス（Fault Avoidance）

- 意味：品質の高い部品を使うなどして、故障そのものが起きないようにする考え方

#### フォールトトレランス（Fault Tolerance）

- 意味：故障が起きても、システム全体としては動き続けるようにする考え方
- ポイント：冗長化が代表的な方法

#### フェールセーフ（Fail Safe）

- 意味：故障したときに、安全な側に止まるようにする設計
- 例：信号機の故障時はすべて赤にする

#### フェールソフト（Fail Soft）

- 意味：故障した部分を切り離し、機能を落としてでも動き続ける設計

#### フールプルーフ（Fool Proof）

- 意味：人が誤った操作をしても、危険が起きないようにする設計
- 例：ドアが閉まらないと動かない電子レンジ

#### フォールトマスキング（Fault Masking）

- 意味：故障の影響を、冗長な部分で打ち消して外に見せない仕組み

#### バックアップ（Backup）

- 意味：障害に備えてデータを複製しておくこと
- ポイント：フル＝全部、差分＝最後のフルバックアップ以降の変更、増分＝直前のバックアップ以降の変更
