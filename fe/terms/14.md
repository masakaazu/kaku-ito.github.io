## 14-1 プロジェクトマネジメント

### まとめ表

**PMBOKの主な知識エリア**

| 知識エリア | 管理すること |
| :-: | :-: |
| 統合 | 全体の調整（計画・変更の管理） |
| スコープ | 作業範囲と成果物 |
| スケジュール | 日程・期限 |
| コスト | 予算・費用 |
| 品質 | 成果物の品質 |
| 資源 | 人や設備 |
| コミュニケーション | 関係者との情報のやり取り |
| リスク | 起こるかもしれない不確かなこと |
| 調達 | 外部からの購入・契約 |
| ステークホルダ | 利害関係者の関与 |


### 基本

#### プロジェクト（Project）

- 意味：決まった期間で、独自の成果物を作るための一時的な活動
- ポイント：始まりと終わりがある点が日常業務と違う

#### PMBOK（ぴんぼっく / Project Management Body of Knowledge）

- 意味：プロジェクトマネジメントの知識を体系的にまとめた手引書
- ポイント：10の知識エリアで整理する
- 語の意味：Project＝計画事業／Management＝管理／Body of Knowledge＝知識の体系

#### ステークホルダ（Stakeholder）

- 意味：プロジェクトに利害関係をもつ人や組織
- ポイント：発注者・利用者・開発メンバ・経営者など

#### プロジェクト憲章（Project Charter）

- 意味：プロジェクトを正式に認め、目的や責任者を示した文書

#### フィージビリティスタディ（Feasibility Study）

- 意味：計画が実現できるかどうかを、技術・費用・期間などの面から事前に調べること
- ポイント：実行可能性調査


## 14-2 統合・スコープ


### 範囲の管理

#### スコープ管理（Scope Management）

- 意味：プロジェクトの作業範囲と成果物を決めて管理すること

#### WBS（だぶりゅーびーえす / Work Breakdown Structure）

- 意味：プロジェクトの作業を、成果物を基準に細かく分けて階層で表したもの
- ポイント：いちばん下の単位をワークパッケージという
- 語の意味：Work＝作業／Breakdown＝分解／Structure＝構造

#### 変更管理（Change Control）

- 意味：計画や成果物を変更するとき、影響を調べて承認してから行う手順


## 14-3 資源・時間・コスト

### まとめ表

**EVMの式**

| 指標 | 式 | 読み方 |
| :-: | :-: | :-: |
| SV（スケジュール差異） | EV − PV | マイナスなら遅れ |
| CV（コスト差異） | EV − AC | マイナスなら予算オーバー |
| SPI（スケジュール効率） | EV ÷ PV | 1より小さいと遅れ |
| CPI（コスト効率） | EV ÷ AC | 1より小さいと予算オーバー |


### 日程

#### アローダイアグラム（PERT図 / Arrow Diagram）

- 意味：作業の順序と所要日数を矢印で表した図
- ポイント：最早結合点時刻は「先行作業の終了の最大値」、最遅結合点時刻は「後ろから求めた候補の最小値」

#### クリティカルパス（Critical Path）

- 意味：開始から終了までで、所要日数の合計が最も長い経路
- ポイント：この経路の作業が遅れると全体が遅れる（余裕日数0）

#### ガントチャート（Gantt Chart）

- 意味：作業を縦に、時間を横にとり、作業の予定と実績を横棒で表した図

#### クラッシング（Crashing）

- 意味：人や費用を追加して、クリティカルパス上の作業の期間を縮めること

#### ファストトラッキング（Fast Tracking）

- 意味：本来は順番に行う作業を並行して進め、期間を縮めること


### 見積りとコスト

#### ファンクションポイント法（Function Point Method）

- 意味：画面や帳票、ファイルなどの機能の数と複雑さから、開発の規模を見積もる方法

#### 類推見積法（Analogous Estimating）

- 意味：過去の似たプロジェクトの実績をもとに見積もる方法

#### EVM（いーぶいえむ / Earned Value Management）

- 意味：計画（PV）・出来高（EV）・実コスト（AC）を比べて、進み具合とコストを管理する方法
- 語の意味：Earned＝得られた／Value＝価値／Management＝管理

#### PV・EV・AC（Planned Value / Earned Value / Actual Cost）

- 意味：PVは計画した作業の予算、EVは終わった作業の予算での価値（出来高）、ACは実際にかかった費用
- 例：PV100万・EV80万・AC90万なら SV＝−20万（遅れ）、CV＝−10万（予算オーバー）
- 語の意味：Planned＝計画された／Earned＝得られた／Actual＝実際の／Cost＝費用

#### 人月（にんげつ / Man-month）

- 意味：1人が1か月で行う作業の量
- 例：6人月の作業を3人で行うと2か月


## 14-4 リスク・品質・調達・コミュニケーション


### その他の管理

#### リスク管理（Risk Management）

- 意味：起こるかもしれない不確かな出来事を見つけ、分析して対策をとること
- ポイント：対応は回避・転嫁・軽減・受容の4つ

#### リスクの転嫁（Risk Transfer）

- 意味：保険や外部委託で、リスクの影響を第三者に移すこと

#### 品質管理（Quality Management）

- 意味：成果物が求められる品質を満たすように計画し、確かめること

#### 調達管理（Procurement Management）

- 意味：外部から製品やサービスを買う計画・契約・管理を行うこと

#### コミュニケーション管理（Communications Management）

- 意味：関係者の間で、必要な情報を適切に伝え合えるようにすること

#### 責任分担表（RAM / Responsibility Assignment Matrix）

- 意味：作業ごとに、誰がどんな役割をもつかを表にしたもの
- 例：RACIチャート

### 14-3 資源・時間・コスト

#### 問 927no12-e1

- 問：画面数などの機能量を基準に、ソフトウェア開発規模を見積もる手法はどれか。
- ア：ファンクションポイント法
- イ：PERT図
- ウ：散布図
- エ：デシジョンテーブル
- 正解：ア
- 解説：ファンクションポイント法は、入出力・照会・ファイル・インタフェースなどの機能量から規模を見積もる。

#### 問 927no12-e2

- 問：アローダイアグラムで、最早結合点時刻を求めるときの考え方として適切なものはどれか。
- ア：先行作業の終了時刻の最小値を取る
- イ：先行作業の終了時刻の最大値を取る
- ウ：後続作業の開始時刻の最大値を取る
- エ：全作業時間を平均する
- 正解：イ
- 解説：結合点から後続作業を開始するには、すべての先行作業が終わる必要があるため最大値を取る。

#### 問 927no12-e3

- 問：アローダイアグラムで、最遅結合点時刻を逆方向に求めるときの考え方として適切なものはどれか。
- ア：後続から得られる候補時刻の最小値を取る
- イ：後続から得られる候補時刻の最大値を取る
- ウ：先行作業時間を加算する
- エ：最早時刻と常に同じにする
- 正解：ア
- 解説：工期を遅らせないためには、複数の後続作業の条件をすべて満たす必要がある。そのため最小値を取る。

#### 問 927no12-e4

- 問：クリティカルパスの説明として適切なものはどれか。
- ア：費用が最も高い作業の経路
- イ：作業数が最も多い経路
- ウ：作業日数の合計が最も長く、余裕がない経路
- エ：最初に開始する作業だけの経路
- 正解：ウ
- 解説：クリティカルパスは全体工期を決める最長経路であり、余裕時間が0である。

#### 問 927no12-e5

- 問：次の作業ネットワークを考える。開始→A(2日)→終了、開始→B(1日)→C(3日)→終了。クリティカルパスはどれか。
- ア：A
- イ：B→C
- ウ：AとB→Cの両方
- エ：判定できない
- 正解：イ
- 解説：A経路は2日、B→C経路は1+3=4日。最も長いB→Cがクリティカルパスで、全体工期は4日となる。

#### 問 fe-14-q02

- 問：EVMで、PV＝100万円、EV＝80万円、AC＝90万円のとき、正しい記述はどれか。
- ア：予定より進んでいて予算内
- イ：予定より進んでいて予算超過
- ウ：予定より遅れていて予算内
- エ：予定より遅れていて予算超過
- 正解：エ
- 解説：SV＝80−100＝−20で遅れ、CV＝80−90＝−10で予算超過。

#### 問 fe-14-q03

- 問：作業量6人月の作業を、3人で行うと何か月かかるか。
- ア：1か月
- イ：2か月
- ウ：3か月
- エ：18か月
- 正解：イ
- 解説：6人月÷3人＝2か月。

#### 問 fe-14-q04

- 問：クリティカルパス上の作業に要員を追加して期間を短縮する手法はどれか。
- ア：クラッシング
- イ：ファストトラッキング
- ウ：WBS
- エ：ベンチマーキング
- 正解：ア
- 解説：人や費用を追加して短縮するのがクラッシング。作業を並行させるのがファストトラッキング。

### 14-4 リスク・品質・調達・コミュニケーション

#### 問 927no12-p3

- 問：プロジェクトに必要なサービスや製品の調達、契約を管理するのはどれか。
- ア：品質管理
- イ：資源管理
- ウ：調達管理
- エ：コミュニケーション管理
- 正解：ウ
- 解説：調達管理は外部から必要な製品・サービスを入手するための調達・契約を扱う。

#### 問 927no12-p4

- 問：チームメンバやステークホルダー間の情報交換を管理するのはどれか。
- ア：コミュニケーション管理
- イ：スケジュール管理
- ウ：統合管理
- エ：リスク管理
- 正解：ア
- 解説：コミュニケーション管理は、必要な情報を適切な相手に適切な時点・方法で伝えることを扱う。

#### 問 927no12-p5

- 問：発生する可能性があり、プロジェクトへ影響を与える不確実な事象を管理するのはどれか。
- ア：品質管理
- イ：リスク管理
- ウ：資源管理
- エ：スコープ管理
- 正解：イ
- 解説：リスク管理は、発生し得るリスクを特定・分析し、対応策を計画・実施する。

#### 問 fe-14-q05

- 問：リスクへの対応のうち、保険をかけるなどして影響を第三者に移すものはどれか。
- ア：回避
- イ：転嫁
- ウ：軽減
- エ：受容
- 正解：イ
- 解説：転嫁はリスクの影響を他者に移す。
