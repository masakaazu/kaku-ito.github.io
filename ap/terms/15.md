## 15-1 サービスマネジメント

### まとめ表

**SLA・SLO・SLI と、ほかの合意**

| 名前 | 誰と誰の間か | 中身 |
| :-: | :-: | :-: |
| SLA（サービスレベル合意書） | サービス提供者 と 顧客 | サービスと、合意したパフォーマンス（目標値）を書いた合意文書 |
| SLO（サービスレベル目標） | SLAの中の項目 | 稼働率99.9％以上・応答3秒以内 のような目標値 |
| SLI（サービスレベル指標） | 実際に測るもの | 稼働率・応答時間の実測値。SLOと比べて達成を判断する |
| OLA（運用レベル合意書） | 提供者 と 社内の部門（内部供給者） | SLAを守るための、組織内の取決め |
| UC（裏付け契約） | 提供者 と 外部供給者 | SLAを支える外部との契約 |

**サービス可用性の計算（R5秋 問56・R7春 問55）**

| 手順 | 式 |
| :-: | :-: |
| ① 合意したサービス時間を出す | 提供時間帯 × 日数 −（計画停止がある場合はその時間） |
| ② 可用性を求める | （サービス時間 − 停止時間）÷ サービス時間 |
| ③ 許される停止時間 | サービス時間 ×（1 − 目標の可用性） |

- 計画停止は、合意したサービス時間に初めから入れないのが普通。R5秋 問56：30日×24時間＝720時間から月曜4回×6時間＝24時間を引いた696時間の1％、6.96時間 → 小数点以下を切り捨てて6時間
- 稼働率99.9％は、30日（720時間）なら約43分まで止まってよい。99.99％なら約4.3分

**サービスライフサイクルの段階（JIS Q 20000-1:2020）**

| 段階 | すること |
| :-: | :-: |
| 計画立案 | どのサービスを提供するか、要求事項と優先順位を決める |
| 設計 | 要求事項を満たすように設計し、SLA・サービスカタログなどを作る |
| 移行 | 構築・試験して、稼働環境に展開する |
| 提供 | 日々サービスを提供し、運用する |
| 改善 | パフォーマンスを評価し、継続的に改善する |

### サービスとサービスマネジメント

#### サービス（Service）

- 意味：顧客が達成したい成果を促進することによって、顧客に価値を提供する手段（JIS Q 20000-1:2020 の考え方）
- ポイント：形のある製品ではなく「成果を得やすくする手段」。サービスを作る部品はサービスコンポーネント、サービスを指揮し管理する能力とプロセスはサービスマネジメント
- 語の意味：Service＝仕えること・奉仕

#### サービスコンポーネント（Service Component）

- 意味：ほかの要素と組み合わせたときに、完全なサービスを提供するサービスの一部。インフラストラクチャ・アプリケーション・文書・ライセンス・情報・支援サービスなど
- ポイント：サービスそのものではなく、その部品。管理の単位として識別し記録したものは構成品目（CI）。サービス全体の質の度合いはサービス品質
- 語の意味：Service＝奉仕・役務／Component＝構成部品

#### サービス品質（Service Quality）

- 意味：サービスに固有の特性が、顧客や利用者の要求事項を満たす程度
- ポイント：可用性・応答時間・サポートの対応などで測る。品質の目標値を合意文書にしたものが SLA、その中の個々の目標がサービスレベル目標（SLO）
- 語の意味：Service＝奉仕／Quality＝質

#### サービスマネジメント（Service Management）

- 意味：価値を提供するため、サービスの計画立案・設計・移行・提供及び改善のための組織の活動及び資源を、指揮し、管理する、一連の能力及びプロセス（JIS Q 20000-1:2020）
- ポイント：R5春 問55 では、この定義が「継続的改善」の誤りの選択肢になった。サービスマネジメントを指揮・管理する仕組み全体はサービスマネジメントシステム（SMS）
- 例：R5春 問55 イ（誤り。これはサービスマネジメントの説明）
- 語の意味：Service＝奉仕・役務／Management＝管理

#### サービスマネジメントシステム（SMS / Service Management System）

- 意味：組織がサービスマネジメントを指揮し、管理するためのマネジメントシステム。方針・目的・計画・プロセス・文書化した情報・資源を含む
- ポイント：JIS Q 20000-1 は SMS を確立・実施・維持・継続的に改善するための要求事項を定めた規格。サービスを部品に分けたものはサービスコンポーネント
- 語の意味：Service＝役務／Management＝管理／System＝体系・仕組み

#### サービスの要求事項（Service Requirements）

- 意味：顧客・利用者・組織がサービスに求める条件。機能・サービスレベル・セキュリティ・法令などを含む
- ポイント：サービスの計画立案で決め、設計の基になる。要求事項と照らしてサービスの有効性を評価する（パフォーマンス評価）
- 語の意味：Requirement＝必要とされるもの・要件

#### プロセス（Process）

- 意味：意図した結果を得るためにインプットを使用する、相互に関連する又は相互に作用する一連の活動（JIS Q 20000-1:2020）
- ポイント：R5春 問55 で継続的改善の誤りの選択肢になった定義。サービスマネジメントは「能力及びプロセス」、継続的改善は「パフォーマンスを向上するために繰り返し行われる活動」
- 例：R5春 問55 ア（誤り。これはプロセスの説明）
- 語の意味：Process＝前に（pro）進む（cess）→過程・手順

### サービスにかかわる人と組織

#### 顧客（Customer）

- 意味：サービスを受け取る組織又は組織の一部。サービスの要求事項を決め、SLAを合意する側
- ポイント：お金を払って契約する側。実際にサービスを使う個人は利用者で、同じとは限らない（会社が顧客、社員が利用者）
- 語の意味：Customer＝いつも（custom＝習慣）来る人→得意先

#### 利用者（User）

- 意味：サービスを実際に利用する個人又は集団
- ポイント：サービスデスクに問い合わせたり、サービス要求を出したりするのは主に利用者。SLAを合意するのは顧客
- 語の意味：User＝使う人

#### サービス提供者（Service Provider）

- 意味：顧客にサービスを提供する組織。JIS Q 20000-1 では SMS を運営する「組織」がこれに当たる
- ポイント：サービスの一部を外部の会社に任せるときは、その会社が外部供給者。提供者は供給者を管理する責任を持ち続ける
- 語の意味：Service＝役務／Provider＝供給する人

#### 利害関係者（Interested Party）

- 意味：ある決定や活動に影響を与え、影響を受け、又は影響を受けると認識している個人又は組織。顧客・利用者・供給者・従業員・規制当局など
- ポイント：顧客や利用者より広い言葉。サービスカタログは、顧客・利用者・その他の利害関係者に、それぞれ適切な部分を見せる
- 語の意味：Interested＝関心を持った／Party＝当事者

### サービスライフサイクル

#### サービスライフサイクル（Service Lifecycle）

- 意味：サービスが計画立案・設計・移行・提供・改善の段階を経て、やがて廃止されるまでの一生
- ポイント：JIS Q 20000-1:2020 の段階は「計画立案・設計・移行・提供・改善」。ITIL 2011 の段階は「ストラテジ・デザイン・トランジション・オペレーション・継続的サービス改善」
- 語の意味：Life＝生涯／Cycle＝周期

#### サービスの計画立案（Service Planning）

- 意味：サービスライフサイクルの最初の段階。どのサービスを提供するかを決め、サービスの要求事項を決定し、変更要求や新しいサービスの提案に優先順位を付ける
- ポイント：作るものを決める段階。要求を満たすように形にするのは設計、稼働環境に展開するのは移行
- 語の意味：Planning＝計画を立てること

#### サービスの設計（Service Design）

- 意味：サービスライフサイクルの段階の一つ。サービスの要求事項を満たすように、新しいサービスや変更するサービスを設計し、文書化する段階。SLA・サービスカタログ・契約書も新設・更新する
- ポイント：サービス受入れ基準もここで決める。設計に合わせて作って試験し展開するのは移行
- 語の意味：Design＝設計

#### サービスの移行（Service Transition）

- 意味：サービスライフサイクルの段階の一つ。設計に合わせて構築・試験し、リリース及び展開管理を使って新しいサービスや変更を稼働環境に展開する段階
- ポイント：移行計画・移行リハーサル・移行判断・運用引継ぎなどが含まれる。展開した後に日々サービスを届けるのは提供
- 語の意味：Transition＝移り変わり

#### サービスの提供（Service Delivery）

- 意味：サービスライフサイクルの段階の一つ。稼働しているサービスを、合意したサービスレベルで日々顧客と利用者に届ける段階。インシデント管理やサービス要求管理などで支える
- ポイント：サービスを運用している段階。パフォーマンスを測って良くしていくのは改善
- 語の意味：Delivery＝届けること

#### サービスの改善（Service Improvement）

- 意味：サービスライフサイクルの段階の一つ。サービスと SMS のパフォーマンスを評価し、適切性・妥当性・有効性を継続的に高める段階
- ポイント：改善の機会を見つけ、評価基準で選び、承認した改善活動を管理する。是正処置は不適合が起きたときの原因除去
- 語の意味：Improvement＝改良・向上

### 規格とフレームワーク

#### JIS Q 20000-1（ISO/IEC 20000-1）

- 意味：サービスマネジメントシステムの要求事項を定めた日本産業規格（国際規格 ISO/IEC 20000-1 が基）。最新は JIS Q 20000-1:2020
- ポイント：認証の基準になる「要求事項」の規格。「〜しなければならない」と書かれている。使い方の手引は JIS Q 20000-2。品質マネジメントシステムの要求事項は JIS Q 9001、情報セキュリティは JIS Q 27001
- 例：R5春 問55・問56、R6秋 問56（JIS Q 20000-1:2020 によれば…）
- 語の意味：JIS＝Japanese Industrial Standards（日本産業規格）／Q＝管理システムの部門記号

#### JIS Q 20000-2（ISO/IEC 20000-2）

- 意味：JIS Q 20000-1 の要求事項を、どう適用するかの手引（ガイダンス）を示した規格
- ポイント：要求事項そのものは 20000-1。20000-2 は「こうするとよい」という解説の位置付け
- 語の意味：JIS＝日本産業規格／Guidance＝手引

#### ITIL（Information Technology Infrastructure Library）

- 意味：英国政府が作った、ITサービスマネジメントのベストプラクティス（成功事例）を集めたフレームワーク。デファクトスタンダードとして世界で使われている。版に ITIL 2011 edition と ITIL 4 がある
- ポイント：規格（守らなければならない要求事項）ではなく、手本の集まり。認証の基準になる規格は JIS Q 20000-1。版は ITIL 2011 edition（ライフサイクルの5段階）と ITIL 4
- 例：R3春 問56（ITIL 2011 のサービス・ポートフォリオ）、R4春 問56（ITIL 2011 の可用性管理のKPI）
- 語の意味：Information Technology＝情報技術／Infrastructure＝基盤／Library＝書籍の集まり

#### ITIL 4

- 意味：2019年に公開された ITIL の版。サービスを通じて顧客と一緒に価値を作る（価値の共創）と考え、サービスバリューシステムと34のプラクティスで整理する
- ポイント：ITIL 2011 は5段階のライフサイクルで整理していた。ITIL 4 ではアジャイルや DevOps との組合せも重視する
- 語の意味：ITIL＝IT Infrastructure Library／4＝第4版

#### サービスバリューシステム（SVS / Service Value System）

- 意味：ITIL 4 で、組織のさまざまな要素と活動が一緒に働いて、価値を作り出す仕組みの全体。従うべき原則・ガバナンス・サービスバリューチェーン・プラクティス・継続的改善からなる
- ポイント：ITIL 4 の中心になる考え方。ITIL 2011 の中心はサービスライフサイクルだった
- 語の意味：Service＝役務／Value＝価値／System＝仕組み

#### プラクティス（Practice）

- 意味：ITIL 4 で、作業を行ったり目的を達成したりするための、組織の資源の集まり。インシデント管理・問題管理・変更実現（チェンジイネーブルメント）など34ある
- ポイント：ITIL 2011 の「プロセス」に当たるものを、人・道具・情報まで含めて広くとらえ直した言葉
- 語の意味：Practice＝実践・慣行

### サービスレベルの合意

#### SLA（えすえるえー / Service Level Agreement）

- 意味：サービス及びその合意されたパフォーマンスを特定した、組織と顧客との間の合意文書（サービスレベル合意書）
- ポイント：顧客との合意。組織内の部門との取決めは OLA、外部供給者との契約は UC。SLAに書く個々の目標値は SLO、実際に測る値は SLI
- 例：R6春 問56（サービスレベル目標を決め、顧客と合意文書を交わす）、R7春 問55（可用性のSLA）
- 語の意味：Service＝役務／Level＝水準／Agreement＝合意

#### SLO（えすえるおー / Service Level Objective）

- 意味：サービスレベルの具体的な目標値（サービスレベル目標）。稼働率99.9％以上・応答時間3秒以内など
- ポイント：SLAの中の個々の約束。測った実績の値は SLI で、SLI が SLO を満たしているかを監視する
- 語の意味：Service＝役務／Level＝水準／Objective＝目標

#### SLI（えすえるあい / Service Level Indicator）

- 意味：サービスレベルを測るための指標と、その実測値（サービスレベル指標）。可用性・応答時間・エラー率など
- ポイント：「何を測るか」と「測った結果」。目標値は SLO、顧客との合意文書は SLA
- 語の意味：Service＝役務／Level＝水準／Indicator＝指し示すもの・指標

#### OLA（おーえるえー / Operational Level Agreement）

- 意味：サービス提供者と、同じ組織の中の部門（内部供給者）との間で、SLAを守るために結ぶ取決め（運用レベル合意書）
- ポイント：組織の中どうしの合意。顧客との合意は SLA、外部の会社との契約は UC（裏付け契約）
- 語の意味：Operational＝運用の／Level＝水準／Agreement＝合意

#### UC（ゆーしー / Underpinning Contract）

- 意味：サービス提供者と外部供給者との間で、SLAを支えるために結ぶ契約（裏付け契約）
- ポイント：外部の会社との契約。組織内の部門との取決めは OLA。外部供給者のパフォーマンスは供給者管理で監視する
- 語の意味：Underpinning＝下から支える／Contract＝契約

#### SLM（えすえるえむ / Service Level Management）

- 意味：サービスとサービスレベル目標を顧客と合意して SLA にし、パフォーマンスを監視・レビュー・報告するプロセス（サービスレベル管理）
- ポイント：SLA を作って守る活動。15-2 の「サービスレベル管理」と同じもの
- 語の意味：Service＝役務／Level＝水準／Management＝管理

### サービスレベルの指標

#### サービス可用性（Service Availability）

- 意味：合意した時点又は期間にわたって、要求された機能を実行するサービス又はサービスコンポーネントの能力。普通は「（合意したサービス時間 − 停止時間）÷ 合意したサービス時間」の割合で表す
- ポイント：計画停止の時間は、合意したサービス時間に初めから含めないことが多い（R5秋 問56）。故障しにくさは信頼性、直しやすさは保守性
- 例：R5秋 問56（許容される停止時間）、R7春 問55（目標達成に足りなかった停止時間）
- 語の意味：Service＝役務／Availability＝利用できること

#### 信頼性（Reliability）

- 意味：サービスやコンポーネントが、中断せずに、合意した機能を決められた期間実行し続けられる能力。MTBF や MTBSI で表す
- ポイント：「故障しにくさ」。故障から直す速さは保守性（MTTR・MTRS）。止まっても使い続けられる力は回復力（レジリエンス）
- 語の意味：Reliability＝頼りにできること

#### サービス時間（Service Hours）

- 意味：サービスを提供すると合意した時間帯（例：平日7時〜22時、24時間365日）
- ポイント：可用性は、このサービス時間を分母にして計算する。サービス時間外に止まっても、可用性は下がらない
- 例：R7春 問55（7時〜22時×20日＝300時間）
- 語の意味：Service＝役務／Hours＝時間

#### 応答時間（Response Time）

- 意味：利用者が要求を出してから、システムが応答を返し始めるまでの時間。SLA のサービスレベル目標によく使う
- ポイント：一件の処理にかかる時間の目標。決められた時間に処理できる件数はスループット。インシデントを解決するまでの時間の目標は解決目標時間
- 語の意味：Response＝応答／Time＝時間

#### 計画停止（Planned Downtime）

- 意味：保守作業などのために、前もって決めて利用者に知らせた上でサービスを止めること
- ポイント：計画外の中断はインシデント。可用性の計算では、計画停止を合意したサービス時間から除くのが普通（R5秋 問56 は「計画停止時間を除いて、毎日0時から24時まで提供」）
- 例：R5秋 問56（毎週月曜0時〜6時の計画停止）
- 語の意味：Planned＝計画された／Downtime＝止まっている時間

#### サービスのパフォーマンス（Service Performance）

- 意味：サービスが合意した目標に対して、どれだけの結果を出しているか。可用性・応答時間・インシデントの解決時間・顧客満足度などで測る
- ポイント：サービスレベル管理では、SLO に照らしたパフォーマンスを「あらかじめ定めた間隔で」監視・レビューし、顧客に報告する（R5春 問56）
- 語の意味：Performance＝遂行・成果

**インシデント・サービス要求・問題 の違い（R3秋 問54・R4秋 問55・R7秋 問56）**

| 名前 | 何か | 目的 | 例 |
| :-: | :-: | :-: | :-: |
| インシデント | 計画外の中断・品質の低下・まだ影響していない事象 | できるだけ早くサービスを元に戻す（回避策でもよい） | 画面が開かない |
| サービス要求 | 合意済みのサービスの一部として決まっている依頼 | 手順どおりに実現する | パスワードの再設定、ソフトの導入 |
| 問題 | 一つ以上のインシデントの根本原因 | 根本原因を特定し、発生と再発を防ぐ | 同じ障害を何度も起こすプログラムの誤り |
| 既知の誤り | 根本原因が分かった、又は回避策がある問題 | 記録して、インシデント対応で使う | 「再起動で直る」と分かっている不具合 |

**優先度は 影響 × 緊急度 で決める**

| 影響＼緊急度 | 高 | 中 | 低 |
| :-: | :-: | :-: | :-: |
| 大（多くの利用者・重要業務） | 1 | 2 | 3 |
| 中 | 2 | 3 | 4 |
| 小（一人・代わりがある） | 3 | 4 | 5 |

| :-: | :-: | :-: |

| MTBSI | 平均サービスインシデント間隔（サービス） | 信頼性 |
| MTTR | 平均修復時間（コンポーネント） | 保守性 |

**RTO・RPO・RLO（R4春 問55・R6秋 問55）**

| 指標 | 決めること | 例 |
| :-: | :-: | :-: |
| RTO（目標復旧時間） | 中断から何時間以内に戻すか | 中断から1日以内に |
| RPO（目標復旧時点） | どの時点のデータまで戻すか | 中断の12時間前の状態に |
| RLO（目標復旧レベル） | どの水準まで戻すか | 重要なサービスに限定して／利用者の50％以上に |

- RPO が12時間前なら、失ってよいデータは12時間分まで。だからバックアップは最長でも12時間ごとに取る（R4春 問55）。RTO の3時間は復旧作業にかけてよい時間で、バックアップの間隔とは関係しない

### 計画と支援

#### PDCA（ぴーでぃーしーえー / Plan-Do-Check-Act）

- 意味：計画（Plan）→実行（Do）→評価（Check）→処置・改善（Act）を繰り返して、仕組みを継続的に良くしていくサイクル
- ポイント：JIS Q 20000-1 や JIS Q 9001・JIS Q 27001 など、マネジメントシステムの規格の土台の考え方。Check で測った結果を Act で次の計画に生かす
- 語の意味：Plan＝計画／Do＝実行／Check＝評価／Act＝処置

#### マネジメントシステム（Management System）

- 意味：方針と目的を決め、それを達成するためのプロセスを確立するための、組織の相互に関連する又は相互に作用する要素の集まり
- ポイント：品質は JIS Q 9001、情報セキュリティは JIS Q 27001、サービスは JIS Q 20000-1 と、共通の構造で作られている。サービスのためのマネジメントシステムが SMS
- 語の意味：Management＝管理／System＝仕組み

#### JIS Q 9001（ISO 9001）

- 意味：品質マネジメントシステムの要求事項を定めた日本産業規格。顧客の要求を満たす製品・サービスを一貫して提供し、顧客満足を高めることがねらい
- ポイント：品質の規格。サービスマネジメントは JIS Q 20000-1、情報セキュリティは JIS Q 27001。どれも PDCA で継続的に改善する
- 語の意味：JIS＝日本産業規格／9001＝品質マネジメントシステムの番号

#### 力量（Competence）

- 意味：意図した結果を達成するために、知識及び技能を適用する能力
- ポイント：組織は、SMS にかかわる人に必要な力量を決め、教育・訓練などで身に付けさせ、その証拠を残す。自分の仕事が SMS にどう役立つかを分かっていることは認識
- 語の意味：Competence＝能力・適格性

#### 認識（Awareness）

- 意味：SMS にかかわる人が、サービスマネジメントの方針、自分の貢献、要求事項を満たさないときの影響などを理解していること
- ポイント：「知っていて分かっている」状態。知識と技能を使える能力は力量
- 語の意味：Awareness＝気付いていること・意識

#### 文書化した情報（Documented Information）

- 意味：組織が管理し維持するよう要求されている情報と、それが含まれている媒体。方針・計画・手順・記録など
- ポイント：作成・更新するときは識別・形式・レビューと承認が要り、変更や保管も管理する。サービスについての文書化した情報がサービスカタログ、構成についての文書化した情報の例が CMDB
- 語の意味：Documented＝文書にされた／Information＝情報

#### 知識（Knowledge）

- 意味：SMS とサービスの運用に必要な情報や経験。組織はこれを決定し、維持し、必要な人が使えるようにする
- ポイント：JIS Q 20000-1:2020 で追加された要求。サービスデスクの知識ベースや既知の誤りの記録も、知識を共有する仕組み
- 語の意味：Knowledge＝知っていること

### サービスポートフォリオ

#### サービスポートフォリオ（Service Portfolio）

- 意味：サービス提供者の約束事項と投資を表すもので、提供者が管理する「検討中か開発中」「稼働中か展開可能」「廃止済み」の全てのサービスを含む（ITIL 2011）
- ポイント：全部入り。開発中のものだけがサービス・パイプライン、稼働中のものだけで顧客に公開するのがサービス・カタログ
- 例：R3春 問56（正解はア）
- 語の意味：Service＝役務／Portfolio＝紙ばさみ→手持ちのものの一覧

#### サービス・パイプライン（Service Pipeline）

- 意味：サービスポートフォリオのうち、「検討中か開発中」でまだ顧客に提供していないサービスの部分
- ポイント：これから出てくるサービス。今提供しているものはサービス・カタログ、やめたものは廃止済みサービス
- 語の意味：Pipeline＝配管→準備中で流れてくるもの

#### サービスカタログ（Service Catalogue）

- 意味：顧客に提供しているサービスについての文書化した情報。サービスの意図した成果やサービス間の依存関係も含み、顧客・利用者・利害関係者が適切な部分を見られるようにする
- ポイント：ITIL 2011 では「稼働中か展開可能」のサービスだけを含み、顧客に公開してサービスの販売と提供の支援に使う（R3春 問56 イ）。開発中や廃止済みまで全部含むのはサービスポートフォリオ
- 例：R3春 問56 イ（誤り。これはサービス・カタログの説明）
- 語の意味：Service＝役務／Catalogue＝目録

#### 廃止済みサービス（Retired Services）

- 意味：サービスポートフォリオのうち、提供をやめたサービスの部分
- ポイント：やめたサービスも、記録や再利用のためにポートフォリオに残す。顧客に見せるサービス・カタログには含まない
- 語の意味：Retired＝引退した／Service＝役務

#### サービスの状態（Service Status）

- 意味：サービスがライフサイクルのどこにあるかの区分。計画中・開発中・稼働中・廃止など
- ポイント：サービスポートフォリオでは、この状態でサービス・パイプライン・サービス・カタログ・廃止済みサービスに分ける
- 語の意味：Status＝状態

#### 変更要求（RFC / Request for Change）

- 意味：サービスやサービスコンポーネント、SMS への変更を求める正式な依頼。追加・変更・廃止を含む
- ポイント：変更管理で記録・分類し、優先度を決めて承認するかを判断する。利用者からの、すでに合意済みの決まった依頼（パスワードの再設定など）はサービス要求
- 語の意味：Request＝依頼／Change＝変更

### 資産管理

#### 資産管理（ITAM / IT Asset Management）

- 意味：サービスを提供するために使っている資産（ハードウェア・ソフトウェア・ライセンスなど）を、要求事項と義務を満たすように管理すること（ITアセットマネジメント）。ソフトウェアの部分はソフトウェアアセットマネジメント
- ポイント：お金や契約の面から資産を管理する。サービスを構成する要素の関係や版を管理するのは構成管理
- 語の意味：IT＝情報技術／Asset＝資産／Management＝管理

#### ソフトウェアアセットマネジメント（SAM / Software Asset Management）

- 意味：資産管理のうちソフトウェアの部分。ソフトウェアとそのライセンスを、導入から廃棄まで管理し、違法コピーや過剰購入を防ぐ活動。規格は JIS X 0164 シリーズ（ISO/IEC 19770）
- ポイント：資産管理の中のソフトウェアの部分。保有ライセンス数と導入数を突き合わせるのがライセンスマネジメント
- 語の意味：Software＝ソフトウェア／Asset＝資産／Management＝管理

#### ライセンスマネジメント（License Management）

- 意味：ソフトウェアアセットマネジメントの中心の活動。ソフトウェアの使用許諾（ライセンス）の数・種類・条件を管理し、実際に導入・使用している数と照合して、契約違反や無駄を防ぐこと
- ポイント：SAM の中心の活動。ライセンスより多く導入すると契約違反、少なく使っていると費用の無駄
- 語の意味：License＝許可・使用許諾／Management＝管理

#### JIS X 0164（ISO/IEC 19770）

- 意味：ソフトウェア資産管理（ITアセットマネジメント）のプロセスや、ソフトウェアの識別タグなどを定めた日本産業規格のシリーズ
- ポイント：SAM の規格。サービスマネジメントの規格は JIS Q 20000、情報セキュリティは JIS Q 27001
- 語の意味：JIS＝日本産業規格／X＝情報処理の部門記号

### 構成管理

#### 構成管理（Configuration Management）

- 意味：構成品目（CI）を識別・記録・制御・追跡・検証し、サービスに関連する構成情報を管理する活動。定めた間隔で構成情報の正確さを確かめる
- ポイント：「何がどの版で、どうつながっているか」を管理する。資産の価値やライセンスを管理するのは資産管理。変更してよいかを判断するのは変更管理
- 語の意味：Configuration＝構成・配置／Management＝管理

#### 構成品目（CI / Configuration Item）

- 意味：サービスを提供するために管理する必要がある要素。ハードウェア・ソフトウェア・ネットワーク・文書・ライセンスなど
- ポイント：構成管理の管理の単位。CI の属性と関係を記録したものが構成情報で、その入れ物の例が CMDB
- 語の意味：Configuration＝構成／Item＝項目・品目

#### 構成情報（Configuration Information）

- 意味：CI の種類・名前・版・状態・場所・担当・ほかの CI との関係など、CI について記録した情報
- ポイント：インシデント管理や変更管理など、ほかの活動からも使えるようにする。変更が展開されたら更新する
- 語の意味：Configuration＝構成／Information＝情報

#### CMDB（しーえむでぃーびー / Configuration Management Database）

- 意味：構成情報を記録し管理するデータベース（構成管理データベース）。文書化された構成情報の例
- ポイント：CI どうしの関係が分かるので、変更の影響分析やインシデントの原因調査に使える。ソフトウェアのライセンスの台帳は資産管理の道具
- 語の意味：Configuration＝構成／Management＝管理／Database＝データベース

#### 版（バージョン / Version）

- 意味：同じ CI の、変更ごとに区別した状態。番号を付けて、どの版が使われているかを管理する
- ポイント：ある時点で合意した版の組合せは構成ベースライン。リリースは展開する版の集まり
- 語の意味：Version＝版・変形

#### 構成ベースライン（Configuration Baseline）

- 意味：ある時点で正式に合意した、CI とその版の組合せの記録。後の変更や復元の基準になる
- ポイント：「この状態に戻せば確実に動く」という基準点。版は一つの CI の状態、ベースラインは複数の CI の組
- 語の意味：Configuration＝構成／Baseline＝基準線

#### 構成識別（Configuration Identification）

- 意味：どの要素を CI として管理するかを決め、名前・番号・種類などで一意に識別する活動
- ポイント：構成管理の最初の活動。記録が実物と合っているかを確かめるのは構成監査
- 語の意味：Configuration＝構成／Identification＝識別

#### 構成監査（Configuration Audit）

- 意味：記録された構成情報が、実際の CI の状態と一致しているか、決められた手順で管理されているかを確かめる活動
- ポイント：JIS Q 20000-1 では「定められた間隔で構成情報の正確性を検証する」。CI を決めて番号を付けるのは構成識別
- 語の意味：Configuration＝構成／Audit＝監査

### 事業関係と供給者

#### 事業関係管理（Business Relationship Management）

- 意味：顧客との関係を管理し、顧客満足を維持する活動。顧客や利害関係者とのコミュニケーションの取決め、サービスの成果のレビュー、満足度の測定、苦情の管理を行う
- ポイント：顧客との「関係」全体を見る。個々の目標値を SLA で合意するのはサービスレベル管理。外部の会社を管理するのは供給者管理
- 語の意味：Business＝事業／Relationship＝関係／Management＝管理

#### 顧客満足（Customer Satisfaction）

- 意味：顧客の期待が満たされている程度についての、顧客の受け止め方。満足度調査などで測る
- ポイント：事業関係管理で、あらかじめ定めた間隔で測定する。SLA を全部守っていても、顧客満足が低いことはある
- 語の意味：Customer＝顧客／Satisfaction＝満足

#### 苦情（Complaint）

- 意味：サービスやその対応について、顧客や利用者が表した不満
- ポイント：事業関係管理で記録・調査・対応し、終了まで管理する。サービスの中断や品質の低下そのものはインシデント
- 語の意味：Complaint＝不平・不満

#### 供給者管理（Supplier Management）

- 意味：サービスの一部を担う供給者との関係・契約・パフォーマンスを管理する活動。外部供給者とは契約を結び、内部供給者や供給者として行動する顧客とは合意文書を作る
- ポイント：提供者はサービスの一部を任せても、サービス全体への責任を持ち続ける。顧客との関係を管理するのは事業関係管理
- 語の意味：Supplier＝供給する者／Management＝管理

#### 外部供給者（External Supplier）

- 意味：サービス提供者の組織の外にあって、契約に基づいてサービスやサービスコンポーネントを供給する組織
- ポイント：契約（UC）で管理する。同じ組織の中の別部門が供給する場合は内部供給者
- 語の意味：External＝外部の／Supplier＝供給者

#### 内部供給者（Internal Supplier）

- 意味：サービス提供者と同じ組織の中にあって、サービスやサービスコンポーネントを供給する部門（例：同じ会社のネットワーク部門）
- ポイント：契約ではなく合意文書（OLA）でサービスレベル目標とインタフェースを決める。組織の外の会社は外部供給者
- 語の意味：Internal＝内部の／Supplier＝供給者

#### 供給者として行動する顧客（Customer Acting as a Supplier）

- 意味：サービスを受ける顧客自身が、サービスの一部（例：顧客側のネットワークや機器の保守）を受け持つ場合の、その顧客
- ポイント：内部供給者と同じように、合意文書で目標とインタフェースを決め、パフォーマンスを監視する
- 語の意味：Customer＝顧客／Acting as＝〜として振る舞う／Supplier＝供給者

#### アウトソーシング（Outsourcing）

- 意味：業務やシステムの運用の一部又は全部を、外部の専門の会社に任せること
- ポイント：任せた先は外部供給者で、供給者管理の対象になる。業務プロセスごと任せるのは BPO（ビジネスプロセスアウトソーシング）
- 語の意味：Out＝外へ／Sourcing＝調達

### クラウドサービスの利用

#### IaaS（いあーす / Infrastructure as a Service）

- 意味：サーバ・ストレージ・ネットワークなどの基盤（インフラ）を、インターネット経由で使えるようにするクラウドサービス
- ポイント：物理サーバの起動・停止や保守ランプの目視監視は事業者の仕事になり、利用者からはなくなる。OS とミドルウェア、業務システムは利用者が管理する（R5春 問57）
- 例：R5春 問57・R7春 問56（IaaS への移行で不要になるのは②物理サーバの起動停止と③保守ランプの目視監視）
- 語の意味：Infrastructure＝基盤／as a Service＝サービスとして

#### PaaS（ぱーす / Platform as a Service）

- 意味：OS・ミドルウェア・データベースなど、アプリケーションを動かす土台（プラットフォーム）までを提供するクラウドサービス
- ポイント：ミドルウェアへのパッチ適用も事業者の仕事になる。その上で動く業務システムのバッチのジョブ監視は利用者に残る（R5春 問57）
- 例：R5春 問57・R7春 問56（PaaS への移行で不要になるのは④ミドルウェアへのパッチ適用）
- 語の意味：Platform＝土台／as a Service＝サービスとして

#### SaaS（さーす / Software as a Service）

- 意味：アプリケーションソフトウェアの機能を、インターネット経由で提供するクラウドサービス。利用者はアプリの設定と利用だけを行う
- ポイント：IaaS→PaaS→SaaS の順に、利用者の運用の範囲が小さくなる。課金は利用時間・トランザクション件数・ID 数などによる従量課金が多い（R6春 問55）
- 例：R6春 問55（SaaS の課金方式と年間利益）
- 語の意味：Software＝ソフトウェア／as a Service＝サービスとして

#### オンプレミス（On-premises）

- 意味：サーバや機器を自社の施設に置き、自社で運用すること
- ポイント：全部の層を自社で管理する。クラウドに移すほど、物理的な作業は事業者に移る
- 語の意味：On＝〜の上に／Premises＝構内・敷地

#### 責任共有モデル（Shared Responsibility Model）

- 意味：クラウドサービスで、どこまでを事業者が、どこからを利用者が管理し責任を持つかを分けた考え方
- ポイント：IaaS では OS から上が利用者、SaaS ではデータと利用者の管理だけが利用者、というように境目がサービスの種類で変わる
- 語の意味：Shared＝分け合った／Responsibility＝責任／Model＝型

### 予算と会計

#### サービスの予算業務及び会計業務（Budgeting and Accounting for Services）

- 意味：財務管理の方針に従い、サービスの費用を予算化し、あらかじめ定めた間隔で予算と実際の費用を比べて監視・報告し、財務予測をレビューして費用を管理する活動
- ポイント：「お金」の管理。R6春 問56 の「サービスの提供に必要な予算に応じて適切な資金を確保する」はこの活動で、サービスレベル管理ではない
- 例：R6春 問56 イ（誤り。予算業務の説明）
- 語の意味：Budgeting＝予算を立てること／Accounting＝会計

#### 財務管理（Financial Management）

- 意味：組織のお金の流れを計画し、予算・会計・課金を通じてサービスの費用と価値を管理すること
- ポイント：予算業務（前もって見積もる）・会計業務（実際にいくらかかったかを記録・配分する）・課金（顧客に請求する）からなる
- 語の意味：Financial＝財務の／Management＝管理

#### 課金（Charging）

- 意味：サービスの利用に対して、顧客に料金を請求すること。従量課金・定額課金などの方式がある
- ポイント：かかった費用を部門などに割り振るだけで、実際に請求しないのは配賦。R6春 問55 は、課金方式ごとの収入から運用費を引いて年間利益を比べる
- 例：R6春 問55
- 語の意味：Charging＝料金を課すこと

#### 従量課金（Usage-based Charging）

- 意味：利用した量（時間・件数・データ量・ID数など）に応じて料金が変わる課金方式
- ポイント：使った分だけ払う。使う量にかかわらず毎月同じ額を払うのは定額課金。R6春 問55 は①利用時間・②トランザクション件数・③ディスク割当て量・④ID 数の四つの従量課金を比べる
- 語の意味：Usage＝使用量／Charging＝課金

#### 定額課金（Flat-rate Charging）

- 意味：利用量にかかわらず、決まった期間ごとに同じ料金を払う課金方式
- ポイント：利用者は費用を予測しやすい。使った量に比例するのは従量課金
- 語の意味：Flat＝平らな・一律の／Rate＝料金

#### 配賦（はいふ / Allocation）

- 意味：複数の部門やサービスで共通にかかった費用を、使った量などの基準で各部門・各サービスに割り振ること
- ポイント：社内の会計上の割振りで、お金の請求ではない。顧客に料金を請求するのは課金
- 語の意味：配＝配る／賦＝割り当てる／Allocation＝割当て

#### 直接費（Direct Cost）

- 意味：特定のサービスのためだけにかかり、そのサービスにそのまま結び付けられる費用（専用サーバの費用など）
- ポイント：複数のサービスで共通にかかり、配賦しないと割り振れない費用は間接費
- 語の意味：Direct＝直接の／Cost＝費用

#### 間接費（Indirect Cost）

- 意味：複数のサービスや部門に共通してかかり、特定のサービスに直接結び付けられない費用（建物・電気代・管理部門の人件費など）
- ポイント：配賦の基準を決めて各サービスに割り振る。特定のサービスだけにかかるのは直接費
- 語の意味：Indirect＝間接の／Cost＝費用

#### 減価償却（Depreciation）

- 意味：長く使う設備の購入費用を、使う年数（耐用年数）にわたって少しずつ費用として配分する会計の手続
- ポイント：買った年に全額を費用にしない。サーバなどの費用をサービスの費用に含めるときに使う
- 語の意味：減価＝価値が減る／償却＝費用として配分する

#### TCO（てぃーしーおー / Total Cost of Ownership）

- 意味：システムの導入から運用・保守・廃棄までにかかる費用の総額（総所有費用）
- ポイント：導入費（初期費用）だけでなく、運用費・教育費・保守費なども含めて比べる。導入費が安くても運用費が高ければ TCO は大きい
- 語の意味：Total＝総計／Cost＝費用／Ownership＝所有

### 需要と容量・能力

#### 需要管理（Demand Management）

- 意味：あらかじめ定めた間隔で、サービスに対する今の需要を決め、将来の需要を予測し、需要と消費を監視・報告する活動
- ポイント：「どれだけ使われるか」を見る。需要に合わせて必要な資源（CPU・ディスクなど）を計画するのは容量・能力管理
- 語の意味：Demand＝需要／Management＝管理

#### 需要予測（Demand Forecast）

- 意味：過去の利用実績や事業計画を基に、将来のサービスの利用量を見積もること
- ポイント：需要管理の中心。予測した需要を基に容量・能力計画を立てる
- 語の意味：Demand＝需要／Forecast＝予測

#### 容量・能力管理（Capacity Management）

- 意味：需要に基づいて、今と将来に必要な資源の容量・能力を決め、計画し、提供する活動。利用状況を監視し、データを分析してパフォーマンスを改善する機会を見つける
- ポイント：R6春 問56 ア「現在の資源の調整と最適化を行い、将来の資源要件の予測を記載した計画を作成する」はこの活動。需要そのものを予測するのは需要管理
- 例：R6春 問56 ア（誤り。容量・能力管理の説明）
- 語の意味：Capacity＝収容力・能力／Management＝管理

#### 容量・能力計画（Capacity Plan）

- 意味：将来の需要の予測に基づいて、いつ、どの資源（CPU・メモリ・ディスク・回線）をどれだけ増やすかを書いた計画
- ポイント：容量・能力管理のアウトプット。しきい値を超えそうになる前に増設できるようにする
- 語の意味：Capacity＝能力／Plan＝計画

#### しきい値（閾値 / Threshold）

- 意味：監視している値がそれを超えたら警告や対応を始める、と決めておく境目の値（例：CPU 使用率80％）
- ポイント：容量・能力管理やシステムの監視で使う。しきい値を超えたことを知らせるのがアラート
- 語の意味：閾＝門の下の横木→境目／Threshold＝敷居

#### 管理指標（Capacity Metrics）

- 意味：容量・能力を監視するために測る値。CPU 使用率・メモリ使用率・ディスク使用率・ネットワーク使用率など
- ポイント：傾向を見ると、いつ容量が足りなくなるかが予測できる。サービスの目標値（SLO）と混同しない
- 語の意味：Metrics＝測定の尺度

### 変更管理

#### 変更管理（Change Management）

- 意味：変更管理方針に従って、変更要求を記録・分類し、優先度を決め、リスク・事業利益・実現可能性・財務影響を考えて承認し、計画・構築・試験した上でリリース及び展開管理に渡す活動
- ポイント：変更を「安全に」行うための活動。稼働環境に実際に展開するのはリリース及び展開管理。R4秋 問55 エ「変更の影響を評価し、リスクを最小とするようにして実施し、レビューする」は変更管理の目的
- 例：R4秋 問55 エ（誤り。変更管理の説明）
- 語の意味：Change＝変更／Management＝管理

#### 変更管理方針（Change Management Policy）

- 意味：変更管理の対象になるサービスコンポーネント、変更のカテゴリと管理の方法、顧客やサービスに重大な影響を及ぼす変更を判断する基準などを定めた方針
- ポイント：重大な影響がある変更は「サービスの設計及び移行」で、それ以外は変更管理の活動で扱う、という振り分けもこの方針で決める
- 語の意味：Policy＝方針

#### 標準変更（Standard Change）

- 意味：リスクが低く、手順が決まっていて、あらかじめ承認されている変更（例：決まった手順でのメモリ増設）
- ポイント：一件ずつ CAB の審議を通さずに実施できる。一件ずつ評価して承認するのは通常の変更、すぐに行わなければならないのは緊急変更
- 語の意味：Standard＝標準の／Change＝変更

#### 通常の変更（Normal Change）

- 意味：標準変更でも緊急変更でもない変更。一件ずつ影響とリスクを評価し、承認してから実施する
- ポイント：規模が大きい場合は CAB で審議する。事前承認済みは標準変更
- 語の意味：Normal＝通常の／Change＝変更

#### 緊急変更（Emergency Change）

- 意味：重大なインシデントの解決やセキュリティの修正など、できるだけ早く実施しなければならない変更
- ポイント：承認の手続を早めるが、なくすわけではない（緊急用の小さな委員会などで承認する）。実施後のレビューも行う
- 語の意味：Emergency＝緊急事態／Change＝変更

#### CAB（きゃぶ / Change Advisory Board）

- 意味：変更の評価・優先度付け・承認について、変更管理の責任者に助言する人の集まり（変更諮問委員会）
- ポイント：技術・業務・顧客の立場の人で構成する。「諮問」＝意見を出す会議。プロジェクトの CCB（変更管理委員会）と似ているが、CAB はサービスマネジメントの言葉
- 語の意味：Change＝変更／Advisory＝助言の／Board＝委員会

#### ロールバック（切り戻し / Rollback）

- 意味：変更がうまくいかなかったときに、変更前の状態に戻すこと
- ポイント：変更管理では、成功しなかった変更を戻す又は修正する活動を前もって計画し、できれば試験しておく
- 語の意味：Roll＝転がす／Back＝後ろへ→元に戻す

#### PIR（ぴーあいあーる / Post Implementation Review）

- 意味：変更を実施した後に、目的を達成したか、予想しなかった影響がなかったかをレビューすること（変更実施後のレビュー）
- ポイント：結果を次の変更の改善に生かす。実施前の影響評価とは別
- 語の意味：Post＝後の／Implementation＝実施／Review＝見直し

### サービスの設計及び移行

#### サービスの設計及び移行（Service Design and Transition）

- 意味：新規サービスや、顧客・サービスに重大な影響を及ぼすサービス変更について、計画・設計・構築・試験を行い、稼働環境に移す活動
- ポイント：大きな変更はここで、小さな変更は変更管理の活動で扱う。実際の展開はリリース及び展開管理を使う
- 語の意味：Design＝設計／Transition＝移行

#### サービス受入れ基準（Service Acceptance Criteria）

- 意味：新しいサービスや変更したサービスを稼働させてよいと判断するために、満たさなければならない条件
- ポイント：設計の段階で決め、構築後の試験で満たしていることを確かめる。リリースごとの条件はリリースの受入れ基準
- 語の意味：Acceptance＝受け入れること／Criteria＝基準

#### 移行計画（Transition Plan）

- 意味：業務とシステムを新しい環境に移すための作業・日程・体制・切り戻しの手順・判断の基準などをまとめた計画
- ポイント：計画に沿って本番と同じ手順を試すのが移行リハーサル、本番の移行をしてよいかを決めるのが移行判断
- 語の意味：Transition＝移行／Plan＝計画

#### 移行リハーサル（Transition Rehearsal）

- 意味：本番の移行の前に、移行の手順を本番に近い環境で実際にやってみて、手順・時間・問題点を確かめること
- ポイント：かかる時間を測って、決められた時間内に移行できるかも確かめる。結果を基に移行判断をする
- 語の意味：Transition＝移行／Rehearsal＝下げいこ

#### 移行判断（Go/No-go Decision）

- 意味：移行リハーサルや試験の結果を基に、本番の移行を実施してよいかを決めること
- ポイント：前もって決めた判断の基準と照らして決める。移行後に結果を評価するのは移行評価
- 語の意味：Go＝進む／No-go＝進まない

#### 運用テスト（Operational Test）

- 意味：運用を担当する人が、本番に近い環境で、運用の手順やマニュアルどおりに運用できるかを確かめるテスト
- ポイント：運用の側から見たテスト。利用者が業務の要件を満たしているかを確かめるのは受入れテスト
- 語の意味：Operational＝運用の／Test＝試験

#### 受入れテスト（Acceptance Test）

- 意味：システムやサービスを受け取る側（利用者・発注者）が、要求どおりに作られているかを確かめて受け入れるテスト
- ポイント：利用者の立場で業務要件を確かめる。運用の手順を確かめるのは運用テスト
- 語の意味：Acceptance＝受け入れること／Test＝試験

#### 運用引継ぎ（Handover to Operations）

- 意味：開発を担当したチームから、運用を担当するチームへ、システム・文書・知識・課題を渡すこと
- ポイント：運用サービス基準（運用でどこまで対応するかの基準）や手順書をそろえて渡す。引き継がないと、障害時に誰も対応できない
- 語の意味：Handover＝引き渡し／Operations＝運用

### リリース及び展開管理

#### リリース及び展開管理（Release and Deployment Management）

- 意味：新規サービスやサービス変更、サービスコンポーネントを稼働環境に展開することを計画し、実施する活動。リリースの成功・失敗を監視し、分析した結果をレビューする
- ポイント：変更管理で承認され試験された変更を、実際に本番に出す。R7秋 問56 エ「リリースの検証」はこの活動で、問題管理ではない
- 例：R7秋 問56 エ（誤り）
- 語の意味：Release＝解き放つ→公開／Deployment＝配置・展開

#### リリース（Release）

- 意味：稼働環境に展開される、一つ以上の新規又は変更したサービス又はサービスコンポーネントの集まり
- ポイント：まとめて出す単位。リリースを実際の環境に配置して動かすことが展開。急いで出すものは緊急リリース
- 語の意味：Release＝解き放つ・公開

#### 展開（Deployment）

- 意味：リリースを稼働環境などに配置して、使える状態にすること
- ポイント：リリースは「出すものの束」、展開は「出す行為」。リリースの配付を含む
- 語の意味：Deployment＝配置・配備

#### 緊急リリース（Emergency Release）

- 意味：緊急変更に伴って、通常の日程を待たずに行うリリース
- ポイント：リリースの種類には、決まった日程で出すものと緊急のものがある。緊急でも試験と記録は省かない
- 語の意味：Emergency＝緊急事態／Release＝公開

#### 受入れ試験環境（Acceptance Test Environment）

- 意味：リリースが受入れ基準を満たしているかを確かめるための、稼働環境に近い試験用の環境
- ポイント：本番の稼働環境とは分けておき、本番に影響を出さずに試験する
- 語の意味：Acceptance＝受入れ／Test＝試験／Environment＝環境

#### 稼働環境（Live Environment）

- 意味：顧客や利用者が実際にサービスを使っている本番の環境
- ポイント：ここへの展開は、承認と試験を終えたリリースだけにする。試験は受入れ試験環境で行う
- 語の意味：Live＝生きている・本番の／Environment＝環境

#### 継続的インテグレーション（CI / Continuous Integration）

- 意味：開発者が書いたプログラムを頻繁に共有のリポジトリに統合し、そのたびに自動でビルドとテストを行う手法
- ポイント：統合の不具合を早く見つける。テストを通ったものをいつでもリリースできる状態にするのは継続的デリバリー、本番まで自動で展開するのは継続的デプロイ。構成品目の CI とは別
- 語の意味：Continuous＝連続した／Integration＝統合

#### 継続的デリバリー（Continuous Delivery）

- 意味：ビルドとテストを自動化し、ソフトウェアをいつでも本番にリリースできる状態に保つ手法
- ポイント：本番への展開は人が判断して行う。本番への展開まで自動にするのは継続的デプロイ
- 語の意味：Continuous＝連続した／Delivery＝引渡し

#### 継続的デプロイ（Continuous Deployment）

- 意味：テストに合格した変更を、人の判断を挟まずに自動で本番環境へ展開する手法
- ポイント：継続的デリバリーの一歩先。いつでも出せる状態にとどめるのは継続的デリバリー
- 語の意味：Continuous＝連続した／Deployment＝展開

### インシデント管理

#### インシデント管理（Incident Management）

- 意味：インシデントを記録・分類し、影響と緊急度から優先順位を付け、必要ならエスカレーションして、できるだけ早く解決し、終了する活動
- ポイント：目的は「サービスを早く元に戻す」こと。R4秋 問55 ア「インシデントの解決を、合意したサービスレベル目標の時間枠内に達成する」はインシデント管理の目的で、根本原因を探すのは問題管理
- 例：R4秋 問55 ア（誤り。インシデント管理の目的）
- 語の意味：Incident＝出来事・事件／Management＝管理

#### インシデント（Incident）

- 意味：サービスに対する計画外の中断、サービスの品質の低下、又は顧客若しくは利用者へのサービスにまだ影響していない事象（JIS Q 20000-1:2020）
- ポイント：「まだ影響していない事象」（例：二重化した片方のディスクの故障）も含む。一つ以上のインシデントの根本原因は問題。決まった依頼はサービス要求
- 語の意味：Incident＝出来事・事件

#### 影響度（Impact）

- 意味：インシデントが業務に与える影響の大きさ。影響を受ける利用者の数や業務の重要さで決める
- ポイント：優先度は影響度と緊急度の組合せで決める。どれだけ急いで直す必要があるかは緊急度
- 語の意味：Impact＝衝撃・影響

#### 緊急度（Urgency）

- 意味：インシデントやサービス要求を、どれだけ早く解決する必要があるか（業務が待てる時間）
- ポイント：影響度と組み合わせて優先度を決める。影響が小さくても締切が迫っていれば緊急度は高い
- 語の意味：Urgency＝切迫・急ぎ

#### 優先度（Priority）

- 意味：インシデントなどに対応する順番。影響度と緊急度から決める
- ポイント：先着順ではなく優先度順に対応する。優先度ごとに解決目標時間を決めておく
- 語の意味：Priority＝優先されること

#### 解決目標時間（Target Resolution Time）

- 意味：インシデントを解決するまでにかけてよい時間の目標。優先度ごとに SLA などで決める
- ポイント：これを超えそうなときは階層的エスカレーションの合図になる。システムの一回の応答の速さ（応答時間）とは別
- 語の意味：Target＝目標／Resolution＝解決／Time＝時間

#### 機能的エスカレーション（Functional Escalation）

- 意味：インシデントの対応を、より専門的な知識や技術を持つ担当（二次・三次サポートなど）に引き継ぐこと
- ポイント：「横・専門へ」。管理者など上の権限を持つ人に知らせて判断を求めるのは階層的エスカレーション
- 語の意味：Functional＝機能の／Escalation＝段階的に上げること

#### 階層的エスカレーション（Hierarchical Escalation）

- 意味：解決目標時間を超えそうなときや重大な影響があるときに、管理者など組織の上位の階層に報告し、判断や資源の追加を求めること
- ポイント：「縦・上へ」。専門の担当に引き継ぐのは機能的エスカレーション
- 語の意味：Hierarchical＝階層の／Escalation＝段階的に上げること

#### 回避策（Workaround）

- 意味：根本原因はまだ取り除けていないが、インシデントや問題の影響を減らしたり、サービスを一時的に元に戻したりする方法（例：再起動・別の手順を使う）
- ポイント：インシデント管理では、回避策で早く戻すことも解決に含む。根本原因を取り除いて問題をなくすのは恒久的な解決策
- 語の意味：Work＝作業／Around＝回り込んで→迂回する方法

#### インシデントモデル（Incident Model）

- 意味：よく起きる種類のインシデントについて、対応の手順・担当・時間・エスカレーションの条件を前もって決めたもの
- ポイント：同じ種類のインシデントを、毎回同じ品質で早く処理できる
- 語の意味：Incident＝出来事／Model＝型

#### 重大なインシデント（Major Incident）

- 意味：事業に大きな影響を与えるインシデント。前もって決めた基準で特定し、文書化した手順で管理し、トップマネジメントに通知する
- ポイント：普通のインシデントより上の体制で対応する。解決した後は、根本原因を調べるために問題管理につなげる
- 語の意味：Major＝重大な／Incident＝出来事

### サービス要求管理

#### サービス要求管理（Service Request Management）

- 意味：サービス要求を記録・分類し、優先順位を付け、実現し、終了する活動
- ポイント：故障ではなく「決まった依頼」を処理する。R7秋 問56 イ「サービス要求の優先度付け」はこの活動で、問題管理ではない
- 例：R7秋 問56 イ（誤り）
- 語の意味：Service＝役務／Request＝依頼／Management＝管理

#### サービス要求（Service Request）

- 意味：利用者又はその代理人からの、合意したサービス提供の一部として既に組み込まれた行為に対する要求（パスワードの再設定・ソフトウェアの導入・情報の問合せなど）
- ポイント：計画外の中断ではないので、インシデントではない。サービスそのものの変更を求めるのは変更要求
- 語の意味：Service＝役務／Request＝依頼

#### サービス要求の実現（Fulfilment）

- 意味：サービス要求に応えて、決められた手順どおりに依頼された作業を行い、利用者に提供すること
- ポイント：手順が決まっているので、セルフサービスのポータルなどで自動化しやすい
- 語の意味：Fulfilment＝実現・履行

#### サービス要求の実現に関する指示書（Fulfilment Instructions）

- 意味：サービス要求ごとに、どう実現するかの手順を書いた指示書。実現にかかわる要員が使えるようにしておく
- ポイント：インシデントの対応手順を決めたものはインシデントモデル。どちらも決まった作業を同じ品質で行うための道具
- 語の意味：Instructions＝指示・手順書

### 問題管理

#### 問題管理（Problem Management）

- 意味：インシデントのデータと傾向を分析して問題を特定し、根本原因を分析して、インシデントの発生や再発を防ぐ処置を決める活動。記録・分類・優先順位付け・エスカレーション・可能なら解決・終了を行う
- ポイント：R4秋 問55 の目的は「インシデントの未知の根本原因を特定し、インシデントの発生又は再発を防ぐ」。R3秋 問54 では「問題を特定するために、インシデントのデータ及び傾向を分析する」が正解。根本原因が分かっても必ず恒久的に解決できるとは限らず、そのときは既知の誤りとして記録する
- 例：R3秋 問54・R4秋 問55・R7秋 問56（問題管理の活動は「根本原因の特定」）
- 語の意味：Problem＝問題／Management＝管理

#### 問題（Problem）

- 意味：一つ以上の現存する又は潜在的なインシデントの根本原因（JIS Q 20000-1:2020）
- ポイント：インシデント（起きた事象）の「原因」の側。原因が分かった、又は回避策がある問題は既知の誤り
- 語の意味：Problem＝問題・課題

#### 根本原因（Root Cause）

- 意味：インシデントや問題を引き起こしている、いちばん元にある原因。それを取り除けば再発しない
- ポイント：目に見える症状（画面が開かない）ではなく、その奥の原因（設定の誤り）。根本原因分析（RCA）で、なぜを繰り返して突き止める
- 語の意味：Root＝根／Cause＝原因

#### 既知の誤り（Known Error）

- 意味：根本原因が特定されているか、又はサービスへの影響を低減若しくは除去する方法（回避策）がある問題
- ポイント：恒久的に解決できていなくても記録し、インシデントの対応に使う（R3秋 問54 イ「既知の誤りは記録しない」は誤り）。記録を集めたデータベースが既知の誤りデータベース（KEDB）
- 例：R3秋 問54 イ（誤り）
- 語の意味：Known＝知られた／Error＝誤り

#### 傾向分析（Trend Analysis）

- 意味：インシデントなどの記録を時間の流れに沿って調べ、増えている・繰り返している・特定の CI に集中しているなどの傾向をつかむ分析
- ポイント：問題管理では、まだ起きていない問題を見つけて予防する（プロアクティブな問題管理）ためにも使う
- 例：R3秋 問54 エ（正解：インシデントのデータ及び傾向を分析する）
- 語の意味：Trend＝傾向／Analysis＝分析

#### 恒久的な解決策（Permanent Solution）

- 意味：問題の根本原因を取り除いて、同じインシデントが二度と起きないようにする対策。多くは変更管理を通して実施する
- ポイント：一時的に影響を減らすだけの回避策とは違う。問題管理に必要な変更は、変更管理の方針に従って管理する
- 語の意味：Permanent＝恒久の／Solution＝解決策

### サービス可用性管理

#### サービス可用性管理（Service Availability Management）

- 意味：サービス可用性のリスクを評価し、可用性の要求事項と目標を決め、可用性を監視・記録して目標と比べ、計画外の可用性の喪失を調査して処置をとる活動
- ポイント：「止まらない・すぐ直る」を管理する。災害のような大きな中断に備えるのはサービス継続管理
- 語の意味：Availability＝利用できること／Management＝管理

#### 保守性（Maintainability）

- 意味：故障したサービスやコンポーネントを、どれだけ早く・容易に元の状態に戻せるか。MTTR や MTRS で表す
- ポイント：R4春 問56：ITIL 2011 の可用性管理の KPI「保守性を表す指標値の短縮」に当たるのは平均サービス回復時間（MTRS）。故障しにくさ（MTBF・MTBSI）は信頼性
- 例：R4春 問56
- 語の意味：Maintainability＝保守できること

#### 回復力（レジリエンス / Resilience）

- 意味：一部が故障しても、サービスを提供し続けたり、早く元に戻ったりできる力
- ポイント：冗長化（二重化）などで高める。故障しにくさは信頼性、直しやすさは保守性
- 語の意味：Resilience＝跳ね返る力・しなやかさ

#### MTBF（えむてぃーびーえふ / Mean Time Between Failures）

- 意味：コンポーネントが故障してから次に故障するまでの平均時間（平均故障間隔）。信頼性を表す
- ポイント：大きいほど故障しにくい。サービスについての同じ考え方は MTBSI。直す時間の平均は MTTR
- 例：R4春 問56 イ（誤り。信頼性の指標）
- 語の意味：Mean＝平均の／Time＝時間／Between＝間の／Failures＝故障

#### MTTR（えむてぃーてぃーあーる / Mean Time To Repair）

- 意味：コンポーネントが故障してから修理が終わるまでの平均時間（平均修復時間）。保守性を表す
- ポイント：小さいほど直しやすい。サービスとして使えるようになるまでの平均は MTRS
- 語の意味：Mean＝平均の／Time＝時間／To Repair＝修理するまで

#### MTBSI（えむてぃーびーえすあい / Mean Time Between Service Incidents）

- 意味：サービスのインシデント（中断）が起きてから、次のインシデントが起きるまでの平均時間（平均サービスインシデント間隔）。信頼性を表す
- ポイント：コンポーネント単位の MTBF をサービス単位にしたもの。R4春 問56 ウ（誤り）
- 例：R4春 問56 ウ（誤り。信頼性の指標）
- 語の意味：Mean＝平均の／Between＝間の／Service Incidents＝サービスのインシデント

#### MTRS（えむてぃーあーるえす / Mean Time to Restore Service）

- 意味：サービスが中断してから、サービスが回復するまでの平均時間（平均サービス回復時間）。保守性を表す
- ポイント：R4春 問56 の正解。部品の修理だけでなく、サービスとして使えるようになるまでの時間
- 例：R4春 問56 エ（正解）
- 語の意味：Mean＝平均の／Restore＝回復させる／Service＝サービス

#### FTA（えふてぃーえー / Fault Tree Analysis）

- 意味：望ましくない事象（トップ事象）を頂点に置き、それを起こす原因を AND・OR の記号で木の形に分解して、発生経路と原因を分析し、発生確率も計算できる技法（故障の木解析）
- ポイント：上（結果）から下（原因）へ分析する。R7秋 問55 の正解。部品の故障モードから下から上へ影響を調べるのは FMEA
- 例：R7秋 問55 ア（正解）
- 語の意味：Fault＝故障・欠陥／Tree＝木／Analysis＝分析

#### FMEA（えふえむいーえー / Failure Mode and Effects Analysis）

- 意味：部品やプロセスの故障の起き方（故障モード）を一つずつ挙げ、それがシステム全体にどんな影響を与えるかを調べる技法（故障モード・影響解析）
- ポイント：下（部品）から上（全体）へ調べる。結果の事象から原因へ木の形で分解して確率を出すのは FTA
- 例：R7秋 問55 イ（誤り）
- 語の意味：Failure Mode＝故障の仕方／Effects＝影響／Analysis＝分析

#### CFIA（しーえふあいえー / Component Failure Impact Analysis）

- 意味：サービスを構成するコンポーネント（CI）ごとに、それが故障したときにどのサービスが影響を受けるかを表にして調べる技法（コンポーネント障害インパクト分析）
- ポイント：表（CI × サービス）で影響を見る。単一障害点も見つけられる。発生経路と確率を木で分析するのは FTA
- 例：R7秋 問55 ウ（誤り）
- 語の意味：Component＝構成要素／Failure＝故障／Impact＝影響／Analysis＝分析

#### SPOF（すぽふ / Single Point of Failure）

- 意味：そこが一か所故障しただけで、システムやサービス全体が止まってしまう部分（単一障害点）。それを探すのが単一障害点分析
- ポイント：冗長化して SPOF をなくす。R7秋 問55 エ（誤り）。故障の影響を表で調べるのは CFIA
- 例：R7秋 問55 エ（誤り）
- 語の意味：Single＝一つの／Point＝点／of Failure＝故障の

### サービス継続管理

#### サービス継続管理（Service Continuity Management）

- 意味：災害や大きな障害でサービスが中断するリスクを評価し、継続の要求事項を決め、サービス継続計画を作って実施・維持し、定めた間隔や大きな変更があったときに試験する活動
- ポイント：R6春 問56 ウ「災害や障害などで事業が中断しても、合意された期間内に確実に復旧できるように、事業影響度の評価や復旧優先順位を明確にする」はこの活動。日々の止まりにくさを管理するのはサービス可用性管理
- 例：R6春 問56 ウ（誤り。サービス継続管理の説明）
- 語の意味：Continuity＝継続／Management＝管理

#### サービス継続（Service Continuity）

- 意味：サービスを中断なしに、又は合意した可用性を一貫して提供する能力（JIS Q 20000-1:2020）
- ポイント：R5春 問55 ウはこの定義で、継続的改善の説明ではない
- 例：R5春 問55 ウ（誤り）
- 語の意味：Service＝役務／Continuity＝継続

#### BCP（びーしーぴー / Business Continuity Plan）

- 意味：災害や事故で被害を受けても、重要な事業を中断させない、又はできるだけ早く再開するための計画（事業継続計画）
- ポイント：事業全体の計画。その中の IT サービスの部分を具体化したのがサービス継続計画。どの業務から戻すかは事業影響度分析（BIA）で決める
- 語の意味：Business＝事業／Continuity＝継続／Plan＝計画

#### サービス継続計画（Service Continuity Plan）

- 意味：サービスが中断したときに、どの順で、どの水準まで、どれだけの時間で戻すか、その手順と体制を書いた計画
- ポイント：RTO・RPO・RLO を決めて書く。計画どおりに戻せるかを試験することも求められる
- 語の意味：Service＝役務／Continuity＝継続／Plan＝計画

#### BIA（びーあいえー / Business Impact Analysis）

- 意味：業務が止まったときの影響（損失・顧客・法令など）を業務ごとに分析し、復旧の優先順位や目標復旧時間を決める分析（事業影響度分析）
- ポイント：BCP やサービス継続計画を作る前に行う。結果から RTO や RLO を決める
- 語の意味：Business＝事業／Impact＝影響／Analysis＝分析

#### RTO（あーるてぃーおー / Recovery Time Objective）

- 意味：サービスが中断してから、どれだけの時間で復旧させるかの目標（目標復旧時間）
- ポイント：「いつまでに戻すか」。R6秋 問55 エ「中断から1日以内に」が RTO。どの時点のデータまで戻すかは RPO、どの水準まで戻すかは RLO
- 例：R4春 問55、R6秋 問55
- 語の意味：Recovery＝復旧／Time＝時間／Objective＝目標

#### RPO（あーるぴーおー / Recovery Point Objective）

- 意味：中断が起きたとき、どの時点の状態のデータまで戻すかの目標（目標復旧時点）
- ポイント：「何時間前のデータまで戻すか」＝失ってよいデータの量。RPO が12時間前なら、バックアップは最長12時間ごと（R4春 問55）。いつまでに戻すかは RTO
- 例：R4春 問55（正解ウ 12時間）
- 語の意味：Recovery＝復旧／Point＝時点／Objective＝目標

#### RLO（あーるえるおー / Recovery Level Objective）

- 意味：中断したサービスを、どの水準（機能・利用者・処理量）まで復旧させるかの目標（目標復旧レベル）
- ポイント：「全部ではなくここまで」。R6秋 問55 エ「重要なサービスに限定して」、ア「利用者の50％以上に」が RLO
- 例：R6秋 問55
- 語の意味：Recovery＝復旧／Level＝水準／Objective＝目標

#### コールドスタンバイ（Cold Standby）

- 意味：予備の機器を用意しておくが、ふだんは電源を入れず（又はソフトウェアを入れず）、障害が起きてから起動・設定して切り替える方式
- ポイント：費用は安いが、切替えに時間がかかる。予備機を起動して待機させておくのはホットスタンバイ、その中間がウォームスタンバイ。システムの起動方法のコールドスタートとは別
- 語の意味：Cold＝冷たい（動いていない）／Standby＝待機

#### ウォームスタンバイ（Warm Standby）

- 意味：予備の機器を起動しておくが、業務のアプリケーションやデータの同期は完全ではなく、切替えの時に準備を仕上げる方式
- ポイント：コールドとホットの中間。切替えの速さと費用も中間
- 語の意味：Warm＝暖かい（半分動いている）／Standby＝待機

#### ホットスタンバイ（Hot Standby）

- 意味：予備の機器を本番と同じ状態で起動し、データも同期させて待機させておき、障害が起きたらすぐに切り替える方式
- ポイント：切替えはいちばん速いが、費用は高い。電源も入れずに置いておくのはコールドスタンバイ
- 語の意味：Hot＝熱い（動いている）／Standby＝待機

### 情報セキュリティ管理

#### 情報セキュリティ管理（Information Security Management）

- 意味：情報セキュリティ方針を決め、情報セキュリティ管理策を実施し、情報セキュリティインシデントに対応するなど、サービスの情報の機密性・完全性・可用性を守る活動
- ポイント：サービスマネジメントの中の一つの活動。詳しいマネジメントシステムの要求事項は JIS Q 27001（ISMS）にある
- 語の意味：Information＝情報／Security＝安全／Management＝管理

#### 情報セキュリティ方針（Information Security Policy）

- 意味：トップマネジメントが示した、組織の情報セキュリティについての基本的な意図と方向付け
- ポイント：これに従って具体的な管理策を決める。方針の承認と周知はトップマネジメントの役目
- 語の意味：Information＝情報／Security＝安全／Policy＝方針

#### 情報セキュリティ管理策（Information Security Controls）

- 意味：情報セキュリティのリスクを下げるための具体的な対策（アクセス制御・暗号化・ログの監視・教育など）
- ポイント：リスクアセスメントの結果に基づいて選ぶ。JIS Q 27001 の附属書Aに一覧がある
- 語の意味：Controls＝管理策・統制

#### 情報セキュリティインシデント（Information Security Incident）

- 意味：情報セキュリティを脅かす、望まない又は予期しない事象（不正アクセス・情報漏えい・マルウェア感染など）
- ポイント：サービスに影響すれば、インシデント管理の手順とも連携して対応する。一般のインシデントの一種
- 語の意味：Information＝情報／Security＝安全／Incident＝出来事

#### JIS Q 27001（ISO/IEC 27001）

- 意味：情報セキュリティマネジメントシステム（ISMS）の要求事項を定めた日本産業規格
- ポイント：情報セキュリティの規格。サービスマネジメントは JIS Q 20000-1、品質は JIS Q 9001
- 語の意味：JIS＝日本産業規格／27001＝ISMS の要求事項の番号

## 15-3 パフォーマンス評価及び改善

### まとめ表

**JIS Q 20000-1:2020 の言葉の定義（R5春 問55 の選択肢）**

| 言葉 | 定義 |
| :-: | :-: |
| プロセス | 意図した結果を得るためにインプットを使用する、相互に関連する又は相互に作用する一連の活動 |
| サービスマネジメント | 価値を提供するため、サービスの計画立案・設計・移行・提供及び改善のための組織の活動及び資源を、指揮し、管理する、一連の能力及びプロセス |
| サービス継続 | サービスを中断なしに、又は合意した可用性を一貫して提供する能力 |
| 継続的改善 | パフォーマンスを向上するために繰り返し行われる活動 |
| 是正処置 | 不適合の原因を除去し、再発を防止するための処置（R5秋 問55） |

**CSF・KGI・KPI（R7春 問57）**

| 指標 | 何を表すか | 例 |
| :-: | :-: | :-: |
| KGI（重要目標達成指標） | 最終的に達成したいゴールの値 | 顧客満足度を90％に |
| CSF（重要成功要因） | ゴールの達成に重要な要因 | 問合せへの一次解決を増やすこと |
| KPI（重要業績評価指標） | CSF がどれだけ進んでいるかを測る値 | 一次解決率80％ |

- 順番は KGI（ゴール）→ CSF（何が効くか）→ KPI（途中の進み具合の物差し）

### 評価と報告

#### パフォーマンス評価（Performance Evaluation）

- 意味：サービスマネジメントの目的に照らして SMS のパフォーマンスと有効性を評価し、サービスの要求事項に照らしてサービスの有効性を評価すること。監視・測定・分析・評価からなる
- ポイント：何を・いつ・どの方法で測るかを決めておく。評価結果を報告するのがサービスの報告、結果を基に良くするのが改善
- 語の意味：Performance＝成果／Evaluation＝評価

#### サービスの報告（Service Reporting）

- 意味：報告の要求事項と目的を決め、SMS とサービスのパフォーマンスと有効性について報告を作ること。傾向情報も含める
- ポイント：SLO の達成状況・インシデントの件数・顧客満足などを、決めた間隔で顧客や経営者に報告する
- 語の意味：Service＝役務／Reporting＝報告すること

#### 有効性（Effectiveness）

- 意味：計画した活動を実行し、計画した結果を達成した程度
- ポイント：「ねらった結果が出たか」。少ない資源で出せたかは効率（効率性）
- 語の意味：Effectiveness＝効果があること

#### 傾向情報（Trend Information）

- 意味：パフォーマンスの値が時間とともにどう変わってきたかを示す情報。よくなっているか、悪くなっているかが分かる
- ポイント：一回の値だけでなく推移を見ると、問題の兆しや改善の効果が分かる。問題管理の傾向分析も同じ考え方
- 語の意味：Trend＝傾向／Information＝情報

#### 内部監査（Internal Audit）

- 意味：組織が、自分の SMS が規格の要求事項と自分の決めたルールに合っているか、有効に運用されているかを、あらかじめ定めた間隔で確かめる監査
- ポイント：監査する人は、自分の仕事を監査しない（客観性）。結果はマネジメントレビューのインプットになる
- 語の意味：Internal＝内部の／Audit＝監査

#### マネジメントレビュー（Management Review）

- 意味：トップマネジメントが、あらかじめ定めた間隔で SMS とサービスをレビューし、適切性・妥当性・有効性を確かめ、改善や変更を決めること
- ポイント：内部監査の結果、顧客満足、パフォーマンスなどをインプットにする。決めるのはトップマネジメント
- 語の意味：Management＝経営陣・管理／Review＝見直し

### 不適合と改善

#### 不適合（Nonconformity）

- 意味：要求事項を満たしていないこと
- ポイント：見つかったら、修正（すぐに直す）と是正処置（原因を取り除いて再発を防ぐ）を行う
- 語の意味：Non＝〜でない／Conformity＝適合

#### 修正（Correction）

- 意味：見つかった不適合を取り除くための処置（その場で直すこと）
- ポイント：結果を直すだけで、原因はそのまま。原因を取り除くのは是正処置
- 語の意味：Correction＝訂正・直すこと

#### 是正処置（Corrective Action）

- 意味：検出された不適合又はほかの望ましくない状況の原因を除去する、又は再発の起こりやすさを低減するための処置
- ポイント：R5秋 問55 の正解。「起きた」不適合の原因への処置。まだ起きていない問題を防ぐのは予防処置。問題を記録・分類・優先度付け…するのは問題管理
- 例：R5秋 問55 ア（正解）
- 語の意味：Corrective＝正す／Action＝処置

#### 予防処置（Preventive Action）

- 意味：まだ起きていない不適合や問題の原因を取り除き、起きないようにする処置
- ポイント：起きた不適合への処置は是正処置。問題管理での「インシデントの発生を防ぐ」処置もこの考え方
- 語の意味：Preventive＝予防の／Action＝処置

#### 継続的改善（Continual Improvement）

- 意味：パフォーマンスを向上するために繰り返し行われる活動。SMS とサービスの適切性・妥当性・有効性を継続的に改善する
- ポイント：R5春 問55 の正解。改善の機会に適用する評価基準には、改善とサービスマネジメントの目的との整合性を含める（R6秋 問56）。サービスだけでなく SMS も改善の対象で、改善の結果は設定した目標に照らして測定する
- 例：R5春 問55 エ（正解）、R6秋 問56 ウ（正解）
- 語の意味：Continual＝繰り返し続く／Improvement＝改善

#### 改善の評価基準（Evaluation Criteria for Improvement）

- 意味：見つかった改善の機会のうち、どれを実施するかを決めるための基準。サービスマネジメントの目的との整合性を含めなければならない（JIS Q 20000-1:2020）
- ポイント：R6秋 問56 の正解の内容。品質と費用の両方の目標が必須（ア）、SMS は対象外（イ）、目標に照らして測定しない（エ）は、どれも規格と違う
- 例：R6秋 問56
- 語の意味：Evaluation＝評価／Criteria＝基準

### 評価の指標と手法

#### CSF（しーえすえふ / Critical Success Factor）

- 意味：目標を達成するために、決定的に重要な要因（重要成功要因）
- ポイント：R7春 問57 の正解。「サービスの提供やマネジメントの成功に重要な要因」。ゴールの値は KGI、CSF の進み具合を測る値は KPI
- 例：R7春 問57 ア（正解）
- 語の意味：Critical＝決定的な／Success＝成功／Factor＝要因

#### KGI（けーじーあい / Key Goal Indicator）

- 意味：最終的に達成したい目標を、数値で表した指標（重要目標達成指標）。売上高・顧客満足度など
- ポイント：ゴールそのもの。ゴールに向かう途中の進み具合を測るのは KPI、成功に重要な要因は CSF
- 例：R7春 問57 イ（誤り）
- 語の意味：Key＝重要な／Goal＝目標／Indicator＝指標

#### KPI（けーぴーあい / Key Performance Indicator）

- 意味：目標の達成に向けて、活動がどれだけ進んでいるかを測る指標（重要業績評価指標）
- ポイント：CSF ごとに設定して途中経過を測る。R4春 問56 の「保守性を表す指標値（MTRS）の短縮」は可用性管理の KPI の例。最終目標の値は KGI
- 例：R7春 問57 ウ（誤り）、R4春 問56
- 語の意味：Key＝重要な／Performance＝業績／Indicator＝指標

#### OKR（おーけーあーる / Objectives and Key Results）

- 意味：挑戦的な目標（Objective）と、その達成を測る数個の主要な成果（Key Results）を組で決め、短い期間で見直す目標管理の手法
- ポイント：組織全体で目標をそろえるのに使う。成功に重要な要因を特定したものは CSF
- 例：R7春 問57 エ（誤り）
- 語の意味：Objectives＝目標／Key Results＝主要な成果

#### プロセス能力水準（Process Capability Level）

- 意味：プロセスがどれだけしっかり実施され、管理され、改善されているかを、成熟度モデルなどの段階で表したもの（プロセス成熟度水準）
- ポイント：プロセスアセスメントで判定する。今の水準と目標の水準の差を見るのがギャップ分析
- 語の意味：Process＝工程／Capability＝能力／Level＝水準

#### プロセスアセスメント（Process Assessment）

- 意味：決められたモデルを基準にして、組織のプロセスを調べ、プロセス能力水準を判定すること
- ポイント：改善の出発点として今の実力を測る。結果を目標と比べて、差を埋める計画を作る
- 語の意味：Process＝工程／Assessment＝評価・査定

#### ギャップ分析（Gap Analysis）

- 意味：あるべき姿（目標）と現在の姿を比べて、その差（ギャップ）と原因を明らかにし、埋めるための施策を考える分析
- ポイント：改善の対象と優先順位を決めるのに使う。プロセスアセスメントの結果を目標と比べるときにも使う
- 語の意味：Gap＝すき間・差／Analysis＝分析

#### 成熟度モデル（Maturity Model）

- 意味：組織やプロセスの成熟の度合いを、初期・管理された・定義された…のような段階で示したモデル（CMMI など）。プロセス能力水準の判定の基準になる
- ポイント：どの段階にいるかが分かると、次に何をすればよいかが分かる。段階の判定に使うのがプロセスアセスメント
- 語の意味：Maturity＝成熟／Model＝型

## 15-4 サービスの運用

### まとめ表

**バックアップの方式（R3春 問57＝R5秋 問57）**

| 方式 | 取るもの | バックアップの時間 | 復旧の手順 |
| :-: | :-: | :-: | :-: |
| フルバックアップ | 全部 | 長い | フルを戻すだけ |
| 差分バックアップ | 前回のフルから変わった分（毎回たまっていく） | 短い（日がたつと伸びる） | フル ＋ 最新の差分 |
| 増分バックアップ | 前回のバックアップ（フルでも増分でも）から変わった分 | いちばん短い | フル ＋ その後の増分を全部、順番に |

- 差分方式は、フルで戻した後に差分を反映して復旧する（R3春 問57 イ）。フルと併用して使うもので、差分だけでは戻せない

**シフト勤務の人数の求め方（R3秋 問56・R4秋 問56）**

| 手順 | R3秋 問56 | R4秋 問56 |
| :-: | :-: | :-: |
| ① 1週間に必要な延べの勤務 | 3シフト×2人×7日＝42回 | （2＋4＋2）人×7日＝56回 |
| ② 1人が1週間にできる勤務 | 5回（7日で5回以内） | 40時間÷7.5時間＝5.33 → 5回 |
| ③ 必要な人数 | 42÷5＝8.4 → 9人 | 56÷5＝11.2 → 12人 |

- 割り切れないときは切り上げる。1人ができる回数は切り捨てる（5.33回は5回）

**サービスデスクの組織（ITIL）**

| 形 | 中身 |
| :-: | :-: |
| ローカルサービスデスク | 利用者のいる拠点ごとに置く |
| 中央サービスデスク | 一か所にまとめて全拠点を受け持つ |
| バーチャルサービスデスク | 離れた場所の要員を、通信でつないで一つのデスクに見せる |
| フォロー・ザ・サン | 時差のある複数の拠点で、昼間の拠点が順番に受け持ち、24時間対応する |

### システム運用管理

#### システム運用管理（System Operations Management）

- 意味：日常の運用計画・障害発生時の運用の計画・運用の負荷を減らす改善計画を立て、容量・能力管理や情報セキュリティ管理などの方針を受けて、システムを安定して動かす管理
- ポイント：運用の「計画と管理」。手順に沿って実際に監視・操作するのは運用オペレーション
- 語の意味：System＝システム／Operations＝運用／Management＝管理

#### 運用の資源管理（Operational Resource Management）

- 意味：サービスを構成する設備・コンピュータ・データ・マニュアル・成果物、そして運用する要員を、組織の目標に合うように維持・運用する活動
- ポイント：資源には人的資源（要員）と技術的資源（ハードウェア・ソフトウェア・データ・ネットワーク）がある
- 語の意味：Operational＝運用の／Resource＝資源／Management＝管理

#### 仮想環境の運用管理（Virtual Environment Management）

- 意味：仮想サーバや仮想ネットワークについて、物理資源の割当て・仮想マシンの作成と削除・移動・性能の監視などを管理すること
- ポイント：仮想マシンは簡単に増やせるので、使われていない仮想マシンやライセンスの管理も必要になる
- 語の意味：Virtual＝仮想の／Environment＝環境

#### 利用者の管理（User Management）

- 意味：システムの利用者 ID の登録・変更・削除、権限の付与と見直しを管理すること
- ポイント：異動や退職の後に ID や権限が残らないよう、定期的に棚卸しする
- 語の意味：User＝利用者／Management＝管理

#### AIOps（えーあいおぷす / Artificial Intelligence for IT Operations）

- 意味：AI や機械学習を使って、ログや監視データを分析し、障害の予兆の検知・原因の推定・対応の自動化などを行う運用の考え方
- ポイント：人では見きれない大量の監視データを扱える。サービスデスクでの AI の活用（チャットボットなど）とは対象が違う
- 語の意味：AI＝人工知能／Ops＝Operations（運用）

### データの管理

#### データ管理（Data Management）

- 意味：業務で使うデータの定義・品質・保管・保護・廃棄などを、組織として管理すること
- ポイント：データの意味や項目の標準化を受け持つのはデータ管理者（DA）、データベースそのものの運用を受け持つのはデータベース管理者（DBA）
- 語の意味：Data＝データ／Management＝管理

#### データ管理者（DA / Data Administrator）

- 意味：組織全体のデータを管理する役割。業務の立場からデータの意味を決め、設計工程では主に論理データベース設計を行い、データ項目を管理して標準化する
- ポイント：R4春 問57 の正解。「論理設計・データ項目の標準化」が DA。ディスクの増設・パフォーマンスチューニング・障害時の復旧は DBA の仕事
- 例：R4春 問57 イ（正解）
- 語の意味：Data＝データ／Administrator＝管理者

#### データベース管理者（DBA / Database Administrator）

- 意味：データベース管理システムを技術面から管理する役割。物理設計・性能の調整（パフォーマンスチューニング）・容量の計画・バックアップと復旧・整合性のチェックを行う
- ポイント：R4春 問57 のア（ディスク増設の計画）・ウ（チューニング）・エ（障害時の復旧と整合性チェック）は DBA の役割。データの意味と標準化は DA
- 例：R4春 問57 ア・ウ・エ（誤り。DBA の役割）
- 語の意味：Database＝データベース／Administrator＝管理者

#### 入出力データの管理（Input/Output Data Management）

- 意味：システムに入れるデータ（入力原票・EDI 受信ファイルなど）と出すデータ（出力帳票など）を、正しく・漏れなく・安全に受け渡し、保管・廃棄する管理
- ポイント：R4秋 問57：出力帳票は授受管理表などで確実に受け渡し、重要なものは業務部門の管理者に手渡しする（正解）。帳票の停止や入力データの修正は業務部門の了解なしにしない。入力原票は後で確かめるために決めた期間保管する
- 例：R4秋 問57＝R6秋 問57（正解イ）
- 語の意味：Input＝入力／Output＝出力

#### 授受管理表（Handover Log）

- 意味：帳票や媒体を受け渡すときに、何を・いつ・誰から誰へ渡したかを記録し、受け取った人が確認印などを残す表
- ポイント：渡し漏れや紛失を防ぎ、後から追跡できるようにする。R4秋 問57 の正解の手段
- 例：R4秋 問57 イ
- 語の意味：授＝さずける／受＝うける／Handover＝引渡し

### 運用オペレーション

#### 運用オペレーション（Operations）

- 意味：システムを安定して動かすために、定められた手順に沿って監視・操作・状況の連絡を行うこと。操作は作業指示書に従って行う
- ポイント：ジョブスケジューリング・アウトプットの管理・バックアップなどを含む。運用の計画を立てるのはシステム運用管理
- 語の意味：Operations＝操作・運用

#### ジョブスケジューリング（Job Scheduling）

- 意味：バッチ処理などのジョブを、いつ・どの順番で・どの条件で実行するかを決め、自動で起動・監視すること
- ポイント：ジョブの前後関係や実行日（月末だけ等）を設計するのがスケジュール設計。異常終了したら、ジョブの復旧と再実行を行う
- 語の意味：Job＝仕事・処理の単位／Scheduling＝予定を立てること

#### スケジュール設計（Schedule Design）

- 意味：業務の締め時刻や処理の前後関係を基に、ジョブの実行の順番・時刻・条件・所要時間を設計すること
- ポイント：設計した内容をジョブ管理ツールに登録して、ジョブスケジューリングで自動実行する
- 語の意味：Schedule＝予定／Design＝設計

#### ジョブの復旧と再実行（Job Recovery and Rerun）

- 意味：ジョブが異常終了したときに、原因を取り除き、データを処理前の状態に戻すなどしてから、ジョブをもう一度実行すること
- ポイント：途中から再開するか最初からやり直すかを、前もって手順として決めておく
- 語の意味：Recovery＝回復／Rerun＝再実行

#### アウトプットの管理（Output Management）

- 意味：入出力データの管理のうち出力の部分。帳票や出力ファイルなどの処理結果を、正しい相手に、正しい時に、安全に届け、保管や廃棄まで管理すること
- ポイント：入出力データの管理の出力の部分。授受管理表で受渡しを記録する
- 語の意味：Output＝出力／Management＝管理

#### 運用支援ツール（Operations Support Tools）

- 意味：システムの運用を助けるソフトウェア。稼働状況を見張る監視ツールや、障害の原因を調べる診断ツールなど
- ポイント：監視ツールはしきい値を超えたら知らせる。診断ツールはログやダンプを解析する
- 語の意味：Operations＝運用／Support＝支援／Tools＝道具

#### 業務運用マニュアル（Operations Manual）

- 意味：システムを使う業務の手順や、運用担当者が行う操作・確認・異常時の対応を書いたマニュアル
- ポイント：運用引継ぎでそろえて渡す。具体的な一回の作業の指示は作業指示書
- 語の意味：Operations＝運用／Manual＝手引書

#### コールドスタート（Cold Start）

- 意味：システムを、主記憶などの内容を引き継がずに、初めから起動し直すこと。障害の後は、ログを使ってデータを復元してから再開する
- ポイント：何も引き継がない「冷えた」状態からの起動。前の状態を引き継いで途中から再開するのはウォームスタート。予備機を用意する方式のコールドスタンバイとは別の言葉
- 語の意味：Cold＝冷たい／Start＝開始

#### ウォームスタート（Warm Start）

- 意味：障害の直前の処理状態（主記憶やチェックポイントの情報）を引き継いで、システムを途中から再開すること
- ポイント：再開が速い。全部初めから起動し直すのはコールドスタート
- 語の意味：Warm＝暖かい／Start＝開始

### バックアップ

#### フルバックアップ（Full Backup）

- 意味：対象のデータを全部複製して取るバックアップ
- ポイント：取るのに時間がかかるが、復旧はこれ一つを戻すだけでよい。差分や増分の方式は、フルバックアップと組み合わせて使う
- 例：R3春 問57、R3秋 問55（毎月1日にフル）
- 語の意味：Full＝全部の／Backup＝予備

#### 差分バックアップ（Differential Backup）

- 意味：前回のフルバックアップから変わった部分を全部取るバックアップ。フルからの変更が毎回たまっていく
- ポイント：復旧はフル＋最新の差分の二つ。フルより取る時間は短いが、復旧はフルだけより時間がかかる（R3春 問57 のアとエは逆）
- 例：R3春 問57＝R5秋 問57（正解イ：フルで復元した後に差分を反映する）
- 語の意味：Differential＝差の／Backup＝予備

#### 増分バックアップ（Incremental Backup）

- 意味：前回のバックアップ（フルでも増分でも）から変わった部分だけを取るバックアップ
- ポイント：取る量はいちばん少ないが、復旧はフル＋その後の増分を全部、順番に反映する。前回のフルからの変わった分を毎回取るのは差分バックアップ
- 語の意味：Incremental＝増加の／Backup＝予備

#### 世代管理（Generation Management）

- 意味：バックアップを何回分（何世代）残すかを決めて、古いものから順に上書きや廃棄をする管理
- ポイント：R3秋 問55 は「6か月前の同一日まで戻せる」ように、フル7回分と差分7本分の世代を残すので14本
- 例：R3秋 問55（正解ウ 14本）
- 語の意味：Generation＝世代／Management＝管理

#### バックアップの保管（Offsite Backup）

- 意味：災害で本番のデータと一緒に失わないように、バックアップの媒体やデータを、離れた場所（遠隔地）に保管すること
- ポイント：同じ部屋に置いたバックアップは、火災や地震で一緒に失われる。RPO を満たす間隔で取ることと、離れた場所に置くことの両方が要る
- 語の意味：Offsite＝敷地の外／Backup＝予備

### サービスデスクの機能

#### サービスデスク（Service Desk）

- 意味：サービスの利用者からの問合せに対して単一の窓口（SPOC）を提供し、適切な部署への引継ぎ、対応結果の記録、記録の管理などを行う機能。組織の形にローカルサービスデスク・中央サービスデスク・バーチャルサービスデスクなどがある
- ポイント：利用者から見た窓口は一つ（SPOC）。インシデントとサービス要求の受付と一次対応をする。根本原因の分析は問題管理の担当
- 語の意味：Service＝役務／Desk＝窓口

#### SPOC（えすぴーおーしー / Single Point of Contact）

- 意味：利用者からの問合せを一か所で受け付ける、単一の窓口。サービスデスクの基本の考え方
- ポイント：利用者はどこに聞けばよいか迷わない。サービスデスクの基本の考え方。単一障害点の SPOF とは別
- 語の意味：Single＝一つの／Point＝点／of Contact＝連絡の

#### コールセンター（Call Center）

- 意味：電話による大量の問合せや受注を、専門の要員と設備で集中して受け付ける部門
- ポイント：電話の受付が中心。IT の問合せに一つの窓口で対応し、記録・引継ぎまで行うのがサービスデスク
- 語の意味：Call＝電話をかける／Center＝中心・施設

#### CTI（しーてぃーあい / Computer Telephony Integration）

- 意味：電話とコンピュータを連携させる技術。着信と同時に、かけてきた人の情報や過去の対応履歴を画面に表示するなど
- ポイント：コールセンターやサービスデスクで、応対を速く正確にする。チャットで自動応答するのはチャットボット
- 語の意味：Computer＝コンピュータ／Telephony＝電話／Integration＝統合

#### FAQ（えふえーきゅー / Frequently Asked Questions）

- 意味：よくある質問とその答えをまとめたもの
- ポイント：利用者が自分で解決できるので、問合せの件数を減らせる。対応のための知識を蓄えたものは知識ベース
- 語の意味：Frequently＝しばしば／Asked＝尋ねられる／Questions＝質問

#### 応対マニュアル（Response Manual）

- 意味：サービスデスクの要員が、問合せを受けたときの受け答えの手順・言葉づかい・確認事項・引継ぎの基準をまとめたマニュアル
- ポイント：誰が対応しても同じ品質になるようにする。技術的な解決方法を蓄えたものは知識ベース
- 語の意味：Response＝応答／Manual＝手引書

#### 知識ベース（Knowledge Base）

- 意味：過去の問合せと解決方法、既知の誤りと回避策などを蓄積し、検索できるようにしたもの
- ポイント：一次サポートで解決できる件数（一次解決率）を増やせる。利用者向けにまとめたものは FAQ
- 語の意味：Knowledge＝知識／Base＝基地・土台

#### チャットボット（Chatbot）

- 意味：文字の会話（チャット）で、利用者の質問に AI などが自動で答えるプログラム
- ポイント：サービスデスクでの AI の活用の例。24時間対応でき、簡単な問合せを人に回さずに済む。運用データを分析する AIOps とは違う
- 語の意味：Chat＝おしゃべり／Bot＝ロボット

### サポートの段階と組織

#### 一次サポート（First-line Support）

- 意味：問合せを最初に受け付け、記録し、知識ベースなどで解決できるものはその場で解決する段階。主にサービスデスクが受け持つ
- ポイント：解決できないものは、専門の二次サポートに引き継ぐ（機能的エスカレーション）
- 語の意味：First＝最初の／Line＝列・段階／Support＝支援

#### 二次サポート（Second-line Support）

- 意味：一次サポートで解決できなかった問合せを受け、より専門的な知識で調査・解決する段階（システムの運用担当・アプリケーションの担当など）
- ポイント：それでも解決できなければ、開発者やメーカーなどの三次サポートに引き継ぐ
- 語の意味：Second＝二番目の／Line＝段階／Support＝支援

#### 三次サポート（Third-line Support）

- 意味：二次サポートでも解決できない問題を受け持つ、最も専門的な段階（開発者・製品のメーカー・外部の専門家など）
- ポイント：一次→二次→三次と専門性が上がっていく。上司に報告して判断を求めるのは階層的エスカレーションで、段階の移動とは別
- 語の意味：Third＝三番目の／Line＝段階／Support＝支援

#### ローカルサービスデスク（Local Service Desk）

- 意味：利用者がいる拠点ごとに、その近くに置くサービスデスク
- ポイント：言葉や事情に合わせた対応ができるが、拠点が多いと費用がかかり、品質がばらつく。一か所にまとめるのは中央サービスデスク
- 語の意味：Local＝地元の

#### 中央サービスデスク（Centralized Service Desk）

- 意味：一か所に集めたサービスデスクで、全ての拠点の利用者からの問合せを受け持つ形
- ポイント：費用を抑え、品質をそろえやすい。拠点の近くに置くのはローカル、離れた要員をつないで一つに見せるのはバーチャル
- 語の意味：Centralized＝一か所に集められた

#### バーチャルサービスデスク（Virtual Service Desk）

- 意味：要員は複数の場所にいるが、通信と共通のシステムでつないで、利用者からは一つのサービスデスクに見えるようにする形
- ポイント：在宅勤務の要員も使える。時差を使って24時間対応するのはフォロー・ザ・サン
- 語の意味：Virtual＝仮想の

#### フォロー・ザ・サン（Follow the Sun）

- 意味：時差のある複数の国や地域にサービスデスクを置き、それぞれの昼間の時間に順番に受け持つことで、24時間対応する形
- ポイント：夜勤なしで24時間対応できる。「太陽を追いかける」ように担当が移る
- 語の意味：Follow＝追う／Sun＝太陽

### まとめ表

**消火設備の向き不向き**

| 設備 | 消し方 | サーバ室では |
| :-: | :-: | :-: |
| スプリンクラー | 水をまく | 機器が水で壊れるので、ふつうは使わない |
| 泡消火設備 | 泡で覆って空気を断つ | 油の火災向け。機器を汚すので向かない |
| ハロゲン化物消火設備 | 燃える反応を止める | 機器を傷めにくい。オゾン層への影響から新設は制限 |
| 不活性ガス消火設備 | 窒素・アルゴンなどで酸素の濃度を下げる | 機器を汚さないのでよく使う。放出時は人の退避が必要 |

**データセンターのエネルギーの指標**

| 指標 | 式・中身 | よい値 |
| :-: | :-: | :-: |
| PUE | データセンター全体の消費電力 ÷ IT機器の消費電力 | 1に近いほどよい |
| GEC | 使ったエネルギーのうち、再生可能エネルギーの割合 | 大きいほどよい |
| ITEE | IT機器の処理能力 ÷ IT機器の定格消費電力 | 大きいほどよい |
| ITEU | IT機器の実際の消費電力 ÷ 定格消費電力（使われ方） | 大きいほどよい |

**GHGプロトコルのスコープ（R6春 問57）**

| スコープ | 中身 | データセンター事業者の例 |
| :-: | :-: | :-: |
| 1 | 自社が所有・管理する排出源からの直接排出 | 自社の発電装置（非常用発電機など）を動かして出る分 |
| 2 | 購入した電気・熱の使用に伴う間接排出 | 自社のIT機器のために買った電力の発電で出る分 |
| 3 | それ以外の間接排出（取引先や顧客など） | 機器の廃棄を任せた業者の排出、ハウジング利用企業が買った電力 |

**液体冷却の方法（R7秋 問57）**

| 方法 | 中身 |
| :-: | :-: |
| 液浸冷却 | サーバを筐体ごと絶縁性の液体に漬けて冷やす。単相冷却（液体を循環させて熱交換器で冷やす）と二相冷却（気化熱を使う）がある |

### ファシリティマネジメントの考え方

#### ファシリティマネジメント（FM / Facility Management）

- 意味：建物・設備・環境などの施設（ファシリティ）を、経営の視点から計画・管理・活用し、費用の削減・快適性・安全性を確保する活動。施設管理・設備管理・施設・設備の維持保全を含む
- ポイント：コンピュータやネットワークを支える施設の基盤も対象。建物の維持だけでなく、費用と使いやすさのバランスを考える
- 語の意味：Facility＝施設・設備／Management＝管理

#### 施設管理（Facility Administration）

- 意味：データセンターなどの建物とその付帯設備（防災・防犯・入退室の管理など）を、安全に使えるように管理すること
- ポイント：建物そのもの。中にある電源・空調・通信などの設備を管理するのは設備管理
- 語の意味：施設＝建物とその付属物

#### 設備管理（Equipment Management）

- 意味：電気設備・空調設備・通信設備などを、必要な能力で動くように点検・保守・更新すること
- ポイント：電源や回線の冗長化、予備の設備の整備も含む
- 語の意味：設備＝備え付けの機械や装置

#### 施設・設備の維持保全（Maintenance）

- 意味：施設と設備を適正な状態に保つため、点検・保守・修繕を計画的に行い、長く使えるようにすること
- ポイント：水道光熱費・保守費・修繕費などを含むライフサイクル費用を減らすことを目指して、修繕計画を立てる
- 語の意味：維持＝保つ／保全＝安全に守る

#### ライフサイクル費用（LCC / Life Cycle Cost）

- 意味：施設や設備の企画・建設から、運用・保守・修繕・廃棄までにかかる費用の総額
- ポイント：建てる費用より、使っている間の光熱費や修繕費の方が大きいことが多い。IT システムでの同じ考え方が TCO
- 語の意味：Life Cycle＝一生／Cost＝費用

### 建物の防災と安全

#### 免震装置（Seismic Isolation）

- 意味：建物と地面の間に積層ゴムなどを入れて、地震の揺れが建物に伝わりにくくする装置
- ポイント：揺れそのものを建物に伝えない。建物を強くして揺れに耐えるのは耐震、ダンパーで揺れを吸収するのは制震
- 語の意味：免＝まぬがれる／震＝揺れ

#### 耐震（Earthquake Resistance）

- 意味：柱や壁を強くして、地震の揺れに建物が耐えられるようにする構造
- ポイント：建物は揺れるので、中の機器が倒れないよう固定も必要。揺れを伝えにくくするのは免震
- 語の意味：耐＝たえる／震＝揺れ

#### 制震（Vibration Control）

- 意味：建物の中にダンパーなどの装置を入れて、揺れのエネルギーを吸収し、揺れを小さくする構造
- ポイント：耐震（耐える）と免震（伝えない）の中間の考え方
- 語の意味：制＝おさえる／震＝揺れ

#### SPD（えすぴーでぃー / Surge Protective Device）

- 意味：落雷などで電源線や通信線に入る異常に高い電圧（サージ）を逃がして、機器を守る装置（サージ防護デバイス）。アレスタ（避雷器）もその一つ
- ポイント：雷の電流を地面に流す避雷針とは別に、線から入ってくるサージを防ぐ。停電に備えるのは UPS
- 語の意味：Surge＝急な高まり／Protective＝保護する／Device＝装置

#### 防災防犯設備（Disaster and Crime Prevention Equipment）

- 意味：火災報知器・消火設備・漏水検知・監視カメラ・入退室管理装置など、災害と侵入を防ぎ、早く見つけるための設備
- ポイント：データセンターでは、共連れを防ぐ入退室管理や、サーバ室に合った消火設備を選ぶことが大事
- 語の意味：防災＝災害を防ぐ／防犯＝犯罪を防ぐ

### 消火設備

#### スプリンクラー設備（Sprinkler）

- 意味：天井に付けたヘッドから水をまいて火を消す設備
- ポイント：一般の建物ではふつうだが、サーバ室では水で機器が壊れるので、ガスの消火設備を使うことが多い
- 語の意味：Sprinkle＝まき散らす

#### 泡消火設備（Foam Fire Extinguishing System）

- 意味：泡で燃えている物を覆い、空気（酸素）を断って消す設備
- ポイント：油の火災（駐車場など）に向く。電子機器を汚して傷めるので、サーバ室には向かない
- 語の意味：泡＝あわ／Foam＝泡

#### ハロゲン化物消火設備（Halogenated Agent System）

- 意味：ハロンなどのハロゲン化物のガスを放出し、燃える化学反応を止めて消す設備
- ポイント：機器を汚さず消火の力も強いが、オゾン層を壊すため、ハロンの新しい生産は禁止され、使い方が制限されている
- 語の意味：Halogen＝ハロゲン（フッ素・塩素などの元素の仲間）

#### 不活性ガス消火設備（Inert Gas System）

- 意味：窒素・アルゴン・二酸化炭素などの燃えないガスを放出し、酸素の濃度を下げて消す設備
- ポイント：水も泡も使わないので機器を汚さず、サーバ室でよく使われる。放出すると人が酸欠になるので、放出前に退避させる
- 語の意味：Inert＝反応しない・不活性の／Gas＝気体

### 電気設備

#### UPS（ゆーぴーえす / Uninterruptible Power Supply）

- 意味：停電や瞬間的な電圧の低下が起きたとき、内蔵の蓄電池から電気を送り、機器を止めずに動かし続ける装置（無停電電源装置）
- ポイント：動かせるのは数分〜数十分。その間に自家発電設備に切り替えるか、安全にシャットダウンする。長時間の停電に備えるのは自家発電設備
- 語の意味：Uninterruptible＝途切れない／Power＝電力／Supply＝供給

#### 自家発電設備（Private Power Generator）

- 意味：停電のときに、燃料でエンジンを回して電気を作る設備（非常用発電機）
- ポイント：起動に少し時間がかかるので、その間は UPS でつなぐ。長時間動かすには燃料の備蓄と補給の契約が要る
- 語の意味：自家＝自分のところで／発電＝電気を作る

#### CVCF（しーぶいしーえふ / Constant Voltage Constant Frequency）

- 意味：電圧と周波数を一定に保った電気を供給する装置（定電圧定周波数装置）
- ポイント：電気の質をそろえる。UPS の多くは CVCF の働きも持つ
- 語の意味：Constant＝一定の／Voltage＝電圧／Frequency＝周波数

#### 2回線受電（Dual Power Feed）

- 意味：電力会社の別々の変電所などから二つの系統で電気を受けて、片方が止まっても受電を続けられるようにすること
- ポイント：電源の冗長化の一つ。建物の中では、サーバの電源を二系統の配電につなぐ
- 語の意味：受電＝電気を受け取る

### 空調と冷却

#### コールドアイル（Cold Aisle）

- 意味：サーバラックの前面どうしを向かい合わせて、その間の通路に冷たい空気を送る通路
- ポイント：サーバは前から冷気を吸い、後ろから熱い空気を出す。背面どうしの通路はホットアイル。冷気と暖気を混ぜないことで冷却の効率が上がる
- 語の意味：Cold＝冷たい／Aisle＝通路

#### ホットアイル（Hot Aisle）

- 意味：サーバラックの背面どうしを向かい合わせて、サーバから出た熱い空気を集める通路
- ポイント：熱い空気をそのまま空調機に戻す。コールドアイルと交互に並べる。通路を壁や扉で囲うのがアイルキャッピング
- 語の意味：Hot＝熱い／Aisle＝通路

#### エアフロー（Airflow）

- 意味：サーバ室の中の空気の流れ。冷気がどこから入り、暖気がどこへ抜けるかの設計
- ポイント：冷気と暖気が混ざると冷却の効率が落ちる。コールドアイルとホットアイルの配置や、床下からの給気で整える
- 語の意味：Air＝空気／Flow＝流れ

#### 液浸冷却（Immersion Cooling）

- 意味：サーバを筐体ごと、電気を通さない液体に漬けて冷やす方式。液体を循環させて熱交換器で冷やす単相冷却と、液体の気化熱を使う二相冷却がある
- ポイント：R7秋 問57 の正解は a（単相と二相）と c（筐体ごと漬ける）。金属板と熱交換するのはコールドプレートの直接液冷。冷媒には絶縁性の液体を使い、水は使わない
- 例：R7秋 問57（正解イ a,c）
- 語の意味：Immersion＝浸すこと／Cooling＝冷却

#### 直接液冷（Direct Liquid Cooling）

- 意味：CPU・GPU に取り付けた金属板（コールドプレート）の中に冷却液を流し、熱を直接運び出す方式
- ポイント：冷却液には水がよく使われる。サーバ全体を液体に漬けるのは液浸冷却
- 例：R7秋 問57 b（誤り。液浸冷却ではない）
- 語の意味：Direct＝直接の／Liquid＝液体／Cooling＝冷却

#### フリークーリング（Free Cooling）

- 意味：冬や夜の外気の冷たさを使って、冷凍機をあまり動かさずにサーバ室を冷やす方式
- ポイント：空調の電力を減らし、PUE を 1 に近づける。寒い地域にデータセンターを作る理由の一つ
- 語の意味：Free＝ただの／Cooling＝冷却

### 通信設備と床

#### MDF（えむでぃーえふ / Main Distribution Frame）

- 意味：建物の外から引き込んだ通信回線を受けて、建物の中の配線につなぐ主配線盤
- ポイント：建物の入口に一つ。各フロアに置いて、MDF からの配線を各部屋に分けるのが IDF
- 語の意味：Main＝主な／Distribution＝分配／Frame＝枠・盤

#### IDF（あいでぃーえふ / Intermediate Distribution Frame）

- 意味：MDF から来た配線を、各フロアや各区画に分けるための中間配線盤
- ポイント：MDF → IDF → 各部屋の機器の順につながる
- 語の意味：Intermediate＝中間の／Distribution＝分配／Frame＝盤

#### フリーアクセスフロア（Raised Floor）

- 意味：床を二重にして、その間に電源ケーブルや通信ケーブルを通したり、空調の冷気を流したりできるようにした床
- ポイント：配線の変更がしやすい。床下から冷気を出してコールドアイルに送るのにも使う
- 語の意味：Free Access＝自由に出入りできる／Floor＝床

#### 回線の冗長化（Line Redundancy）

- 意味：通信回線を複数の通信事業者や別々の経路で用意し、一つが切れても通信を続けられるようにすること
- ポイント：同じ経路を通る2本では、工事の事故などで同時に切れる。経路も分けるのが大事
- 語の意味：冗長＝余分に持つこと／Redundancy＝余分

### データセンター

#### データセンター（Data Center）

- 意味：サーバや通信機器を安全に動かすための専用の建物や施設。電源・空調・防災・防犯・回線を備える
- ポイント：顧客の機器を預かるのがハウジング、事業者の機器を貸すのがホスティング
- 語の意味：Data＝データ／Center＝施設

#### ティア基準（Tier）

- 意味：データセンターの信頼性（電源・空調の冗長性、止まりにくさ）を、Tier 1〜Tier 4 の段階で表した基準。日本ではデータセンター ファシリティ スタンダード（JDCC）が定めている
- ポイント：数字が大きいほど冗長性が高く、止まりにくい。設備を止めずに保守できるか、一か所の故障に耐えられるかで分ける
- 語の意味：Tier＝段・階層

#### ハウジングサービス（Housing Service）

- 意味：データセンターの場所・電源・回線を貸し、顧客が自分の機器を持ち込んで置くサービス
- ポイント：機器は顧客のもの。機器も事業者が用意して貸すのはホスティング。R6春 問57 で、ハウジング利用企業が買った電力の排出は、事業者 X 社から見るとスコープ 3
- 例：R6春 問57 エ（誤り）
- 語の意味：Housing＝住まい・収容

#### ホスティングサービス（Hosting Service）

- 意味：事業者が用意したサーバを、その設備ごと顧客に貸すサービス
- ポイント：顧客は機器を持たない。顧客が機器を持ち込むのはハウジング
- 語の意味：Hosting＝主人役となってもてなす

### 環境への配慮

#### グリーンIT（Green IT）

- 意味：IT 機器やデータセンターの消費電力を減らすこと（IT の省エネ）と、IT を使って社会全体の環境負荷を減らすこと（IT による省エネ）の両方を進める考え方
- ポイント：テレワークやペーパーレスは「IT による」省エネ、PUE の改善は「IT の」省エネ
- 語の意味：Green＝緑→環境に優しい

#### PUE（ぴーゆーいー / Power Usage Effectiveness）

- 意味：データセンター全体の消費電力を、IT 機器の消費電力で割った指標
- ポイント：1.0 が理想（空調や照明に電力を使っていない）。値が小さいほど効率がよい。IT 機器の処理能力の効率は ITEE
- 語の意味：Power＝電力／Usage＝使用／Effectiveness＝有効性

#### GEC（じーいーしー / Green Energy Coefficient）

- 意味：データセンターで使うエネルギーのうち、再生可能エネルギー（太陽光など）でまかなっている割合
- ポイント：大きいほど環境によい。電力の使い方の効率を見るのは PUE
- 語の意味：Green Energy＝環境に優しいエネルギー／Coefficient＝係数

#### ITEE（あいてぃーいーいー / IT Equipment Energy Efficiency）

- 意味：IT 機器の処理能力を、その定格消費電力で割った指標。省エネ性能の高い機器を使っているかを表す
- ポイント：機器の「性能あたりの電力」。機器が実際にどれだけ使われているかは ITEU
- 語の意味：IT Equipment＝IT機器／Energy＝エネルギー／Efficiency＝効率

#### ITEU（あいてぃーいーゆー / IT Equipment Utilization）

- 意味：IT 機器の実際の消費電力を、定格消費電力で割った指標。機器がどれだけ有効に使われているか（遊んでいないか）を表す
- ポイント：仮想化などで機器を集約すると上がる。性能あたりの電力は ITEE
- 語の意味：IT Equipment＝IT機器／Utilization＝利用

#### ZEB（ぜぶ / net Zero Energy Building）

- 意味：省エネと再生可能エネルギーの利用によって、建物で使う一次エネルギーの収支を実質ゼロにすることを目指した建物
- ポイント：建物のエネルギーの「収支」の考え方。環境に配慮した建物の認証制度は LEED
- 語の意味：Net＝正味の／Zero＝ゼロ／Energy＝エネルギー／Building＝建物

#### LEED（りーど / Leadership in Energy and Environmental Design）

- 意味：米国の団体が運営する、環境に配慮した建物を評価して認証する制度
- ポイント：省エネ・水の利用・材料などを点数で評価し、等級を与える。エネルギー収支ゼロを目指す建物の考え方は ZEB
- 語の意味：Leadership＝先導／Energy＝エネルギー／Environmental＝環境の／Design＝設計

#### GHGプロトコル（GHG Protocol）

- 意味：事業者が出す温室効果ガス（GHG）の排出量を算定し報告するための国際的な基準。排出をスコープ1・スコープ2・スコープ3に分ける
- ポイント：R6春 問57：スコープ1 は自社が所有・管理する排出源からの直接排出（自社の発電装置）、スコープ2 は購入した電力の発電に伴う排出、スコープ3 はそれ以外の他社の排出
- 例：R6春 問57（正解ウ）
- 語の意味：GHG＝Greenhouse Gas（温室効果ガス）／Protocol＝取決め・手順

#### スコープ1（Scope 1）

- 意味：事業者が自分で所有又は管理している排出源から、直接出す温室効果ガス（燃料を燃やす発電機・ボイラー・社用車など）
- ポイント：R6春 問57 の正解「自社で管理する発電装置を稼働させて発生する温室効果ガス」。買った電力の分はスコープ2
- 例：R6春 問57 ウ（正解）
- 語の意味：Scope＝範囲

#### スコープ2（Scope 2）

- 意味：事業者が購入して使った電気・熱・蒸気の、作るときに出た温室効果ガス（間接排出）
- ポイント：R6春 問57 ア「自社の IT 機器のために購入した電力の発電に伴う排出」がスコープ2。自分で燃料を燃やす分はスコープ1
- 例：R6春 問57 ア（誤り）
- 語の意味：Scope＝範囲

#### スコープ3（Scope 3）

- 意味：スコープ1・2以外の間接排出。原材料の調達・輸送・製品の使用・廃棄・出張など、事業者の活動に関係するが他社が出す温室効果ガス
- ポイント：R6春 問57 イ（廃棄を任せた業者の排出）とエ（ハウジング利用企業が買った電力）がスコープ3
- 例：R6春 問57 イ・エ（誤り）
- 語の意味：Scope＝範囲

### 15-1 サービスマネジメント

#### 問 ap-15-r05a-q56

- 問：Y社は，受注管理システムを運用し，顧客に受注管理サービスを提供している。日数が30日，月曜日の回数が4回である月において，サービス提供条件を達成するために許容されるサービスの停止時間は最大何時間か。ここで，サービスの停止時間は，小数第1位を切り捨てるものとする。〔サービス提供条件〕・サービスは，計画停止時間を除いて，毎日0時から24時まで提供する。・計画停止は，毎週月曜日の0時から6時まで実施する。・サービスの可用性は99%以上とする。
- ア：0
- イ：6
- ウ：7
- エ：13
- 正解：イ
- 解説：まず合意したサービス時間を出す。30日×24時間＝720時間から、計画停止の月曜4回×6時間＝24時間を除いて696時間。可用性99%以上なので、止まってよいのは696×0.01＝6.96時間。小数第1位を切り捨てて6時間。計画停止はサービス時間に入れないので、停止時間には数えない。
- アの意味：0時間は、計画停止の24時間で可用性の余裕を使い切ったと考えた値。計画停止はサービス時間の外なので、可用性の計算には入らない。
- イの意味：正しい。696時間の1%は6.96時間で、切り捨てて6時間。
- ウの意味：7時間は、720時間（計画停止を除かない）の1%の7.2時間を切り捨てた値。計画停止の時間はサービス時間から除く。
- エの意味：13時間は、6.96時間を切り捨てずに計画停止の6時間を足すなど、計画停止を停止時間の枠に混ぜた値。計画停止と計画外の停止は別に扱う。
- 出典：IPA 令和5年度秋期 応用情報技術者試験 午前 問56

#### 問 ap-15-r07h-q55

- 問：あるサービスでは〔サービス可用性のSLA〕に基づき，サービス可用性の目標値の遵守状況を月ごとに測定して評価している。ある月の実績値は99.3%だった。この月にサービス可用性の目標値を達成するためには，サービス停止時間は，最低，何時間少なければよかったか。〔サービス可用性のSLA〕・サービス可用性の目標値：99.5%以上 ・サービス提供時間帯：7時〜22時 ・サービス提供日数：20日／月
- ア：0.4
- イ：0.6
- ウ：1.3
- エ：1.95
- 正解：イ
- 解説：サービス時間は（22−7）＝15時間×20日＝300時間。実績99.3%なので停止時間は300×0.007＝2.1時間。目標99.5%なら停止は300×0.005＝1.5時間まで。差は2.1−1.5＝0.6時間。
- アの意味：0.4時間は、可用性の差0.2%をそのまま時間に換算しようとして、サービス時間ではなく別の値（200時間など）を掛けた値。分母はサービス提供時間帯の合計300時間。

- ア：X社が自社で管理するIT機器を使用するために購入した電力の，発電に伴う温室効果ガス
- イ：X社が自社で管理するIT機器を廃棄処分するときに，産業廃棄物処理事業者が排出する温室効果ガス
- ウ：X社が自社で管理する発電装置を稼働させることによって発生する温室効果ガス
- エ：X社が提供するハウジングサービスを利用する企業が自社で管理するIT機器を使用するために購入した電力の，発電に伴う温室効果ガス

- 解説：スコープ1は、自社が所有・管理する排出源から自社が直接出すもの。自社の発電装置を動かして出るガスがこれに当たる。買った電力の分はスコープ2、他社が出す分はスコープ3。
- アの意味：X社が購入した電力の発電に伴う排出は、スコープ2。
- イの意味：廃棄を任せた産業廃棄物処理事業者の排出は、X社が管理していない排出源なのでスコープ3。
- ウの意味：正しい。自社で管理する発電装置からの直接排出はスコープ1。
- エの意味：ハウジングを利用する企業が自分で買った電力の排出は、X社から見るとスコープ3（その企業にとってはスコープ2）。

#### 問 ap-15-r07a-q57

- 問：生成AIの処理などで用いられる，大量に発熱するGPUを搭載したサーバを，空気冷却よりも少ない消費電力で効率良く冷却できる液体冷却の一つに液浸冷却がある。液体冷却の方法の説明のうちで，液浸冷却の方法の説明に該当するものの組みはどれか。〔液体冷却の方法の説明〕a：液体を循環させて熱交換器で冷やす単相冷却と，気化熱を利用する二相冷却とがある。b：サーバに取り付けた金属板と熱交換してサーバを冷却する。c：サーバを筐体ごと液体に漬けて冷却する。d：冷媒となる液体として通常は水を使用する。
- ア：a，b
- イ：a，c
- ウ：b，d
- エ：c，d
- 正解：イ
- 解説：液浸冷却は、サーバを筐体ごと電気を通さない液体に漬ける方式（c）。液体を循環させて熱交換器で冷やす単相冷却と、液体が沸騰するときの気化熱を使う二相冷却がある（a）。金属板（コールドプレート）と熱交換するのは直接液冷の方式で、その冷却液に多いのが水。
- アの意味：b の金属板と熱交換する方式は、コールドプレートによる直接液冷。液浸ではない。
- イの意味：正しい。a と c が液浸冷却の説明。
- ウの意味：b はコールドプレート方式、d の水は電気を通すので、サーバを漬ける液浸冷却には使わない。
- エの意味：c は正しいが、d は誤り。液浸冷却には絶縁性の液体（フッ素系の液体や油など）を使う。
- 出典：IPA 令和7年度秋期 応用情報技術者試験 午前 問57

#### 問 ap-15-o17

- 問：あるデータセンターの施設全体の消費電力が1,500kW，そのうち IT 機器の消費電力が1,000kWであるとき，PUE は幾らか。
- ア：1.5
- イ：0.67
- ウ：0.5
- エ：2.5
- 正解：ア
- 解説：PUE＝施設全体の消費電力 ÷ IT 機器の消費電力＝1,500 ÷ 1,000＝1.5。空調や照明などに使う電力が少ないほど1に近づき、効率がよいといえる。1より小さくなることはない。
- アの意味：正しい。1,500 ÷ 1,000＝1.5。
- イの意味：0.67 は、分母と分子を逆にした値（1,000 ÷ 1,500）。PUE は1以上になる。
- ウの意味：0.5 は、IT 機器以外の電力（500kW）を IT 機器の電力で割った値。PUE は施設全体の電力で計算する。
- エの意味：2.5 は、施設全体の電力と IT 機器の電力を足してから1,000で割るなど、施設全体の電力を二重に数えた値。
- 出典：オリジナル問題（シラバス Ver.7.2 中分類15「ファシリティマネジメント」の用語例（グリーンIT）と PUE の定義をもとに作成）

#### 問 ap-15-o18

- 問：サーバ室で，水を使わずに，ガスを放出して室内の酸素の濃度を下げることで火を消す設備はどれか。
- ア：スプリンクラー設備
- イ：泡消火設備
- ウ：ハロゲン化物消火設備
- エ：不活性ガス消火設備
- 正解：エ
- 解説：不活性ガス消火設備は、窒素や二酸化炭素などのガスで酸素の濃度を下げて消す（窒息の効果）。ハロゲン化物消火設備も水を使わないが、主に燃える反応を化学的に止める（抑制の効果）。水や泡は電子機器を傷めるので、サーバ室ではガス系を使うことが多い。
- アの意味：スプリンクラー設備は、水をまいて冷やして消す。電子機器を水で傷めるおそれがある。
- イの意味：泡消火設備は、泡で燃えている物を覆って消す。駐車場など、油の火災に向く。
- ウの意味：ハロゲン化物消火設備は、ガスで燃える反応を化学的に止めて消す。酸素の濃度を下げるのが主な働きではない。
- エの意味：正しい。不活性ガスで酸素の濃度を下げて消す。
- 出典：オリジナル問題（シラバス Ver.7.2 中分類15「ファシリティマネジメント」の用語例（防災防犯設備）と消防法の消火設備の区分をもとに作成）

#### 問 ap-15-o19

- 問：停電が起きた直後から，内蔵する蓄電池で短い時間だけ電力を供給し，自家発電設備が動き出すまでのつなぎや，システムの安全な停止のための時間を確保する装置はどれか。
- ア：自家発電設備
- イ：UPS
- ウ：CVCF
- エ：SPD
- 正解：イ
- 解説：UPS（無停電電源装置）は、停電の瞬間から蓄電池で電力を送る。供給できるのは数分から数十分なので、長い停電は自家発電設備に引き継ぐ。UPS で時間をかせぎ、その間に発電機を起動するか、システムを安全に止める。
- アの意味：自家発電設備は、燃料で発電して長い時間電力を送る。ただし起動に時間がかかるので、停電の直後からは送れない。
- イの意味：正しい。蓄電池で停電直後から短い時間電力を送るのは UPS。
- ウの意味：CVCF（定電圧定周波数装置）は、電圧と周波数を一定に保って電力を送る装置。UPS の中に組み込まれることがあるが、蓄電池で停電に備えるのは UPS の働き。
- エの意味：SPD（サージ防護デバイス）は、雷などで一瞬だけ高い電圧が入るのを防ぐ装置。停電に備えるものではない。
- 出典：オリジナル問題（シラバス Ver.7.2 中分類15「ファシリティマネジメント」の用語例（UPS・自家発電装置）をもとに作成）
