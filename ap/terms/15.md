## 15-1 サービスマネジメント

### まとめ表

**SLA・SLO・SLI**

| 用語 | 意味 | 例 |
| :-: | :-: | :-: |
| SLI | 実際に測る指標 | 月の稼働率の実測値 |
| SLO | 内部で決めた目標値 | 稼働率99.95％ |
| SLA | 利用者と結ぶ合意 | 稼働率99.9％、下回れば返金 |

**稼働率と停止時間（30日の場合）**

| 稼働率 | 停止してよい時間 |
| :-: | :-: |
| 99％ | 約7.2時間 |
| 99.9％ | 約43分 |
| 99.99％ | 約4.3分 |


### 基本

#### ITサービスマネジメント（ITSM / IT Service Management）

- 意味：ITサービスを利用者の要求に合わせて計画・提供・改善する管理

#### ITIL（あいてぃる / Information Technology Infrastructure Library）

- 意味：ITサービスマネジメントのベストプラクティス集
- ポイント：ITIL 4はサービスバリューシステムで価値を共創すると考える
- 語の意味：Information Technology＝情報技術／Infrastructure＝基盤／Library＝書籍集

#### JIS Q 20000（ISO/IEC 20000）

- 意味：サービスマネジメントシステム（SMS）の要求事項を定めた規格

#### SLA（えすえるえー / Service Level Agreement）

- 意味：提供者と利用者がサービスの水準について結ぶ合意
- 語の意味：Service＝サービス／Level＝水準／Agreement＝合意

#### SLO・SLI（Service Level Objective / Indicator）

- 意味：SLOは目標とする水準、SLIは実際に測る指標
- 語の意味：Objective＝目標／Indicator＝指標

#### OLA（おーえるえー / Operational Level Agreement）

- 意味：サービス提供者の社内の部門どうしで結ぶ合意
- 語の意味：Operational＝運用の／Level＝水準／Agreement＝合意

#### UC（Underpinning Contract）

- 意味：外部の供給者と結ぶ、サービスを支える契約


## 15-2 サービスマネジメントシステムの計画及び運用

### まとめ表

**インシデントと問題**

| プロセス | 目的 |
| :-: | :-: |
| インシデント管理 | サービスをできるだけ早く回復する |
| 問題管理 | 根本原因を見つけて再発を防ぐ |
| 変更管理 | 変更を評価・承認して安全に行う |
| リリース及び展開管理 | 承認された変更を本番に展開する |


### 主なプロセス

#### インシデント管理（Incident Management）

- 意味：サービスの中断や品質の低下から、できるだけ早く回復すること
- ポイント：回避策（ワークアラウンド）で一時的に戻すこともある

#### 問題管理（Problem Management）

- 意味：インシデントの根本原因を調べて取り除くこと
- ポイント：原因がわかり回避策がある問題を既知の誤り（ノウンエラー）という

#### 変更管理（Change Management）

- 意味：サービスの変更を記録・評価・承認・計画すること

#### リリース及び展開管理（Release and Deployment Management）

- 意味：承認された変更を、本番環境に計画どおり展開すること

#### 構成管理（Configuration Management）

- 意味：構成品目（CI）の情報をCMDBで正確に管理すること

#### サービスレベル管理（Service Level Management）

- 意味：SLAを合意し、達成状況を監視・報告・改善すること

#### 容量・能力管理（Capacity Management）

- 意味：現在と将来の需要に合うよう、資源の能力を計画すること

#### 可用性管理（Availability Management）

- 意味：合意した可用性を満たすよう、計画・監視すること

#### サービス継続管理（Service Continuity Management）

- 意味：災害などのときにも合意した水準でサービスを続けられるようにすること

#### サービス要求管理（Service Request Management）

- 意味：パスワードの再設定など、決まった要求に対応すること


## 15-3 パフォーマンス評価及び改善


### 評価

#### 継続的改善（Continual Improvement）

- 意味：評価の結果をもとに、サービスと管理のしくみを改善し続けること

#### 顧客満足度調査（Customer Satisfaction Survey）

- 意味：利用者がサービスに満足しているかを調べること


## 15-4 サービスの運用


### 運用

#### サービスデスク（Service Desk）

- 意味：利用者からの問合せの窓口（SPOC）
- ポイント：解決できないものは専門部署にエスカレーションする

#### エスカレーション（Escalation）

- 意味：機能的エスカレーション（専門の担当へ）と階層的エスカレーション（上位の管理者へ）がある

#### ジョブスケジューリング（Job Scheduling）

- 意味：決まった処理を、決めた時刻や順番で自動で実行すること

#### バックアップ方式（Backup）

- 意味：フル・差分（前回のフルから）・増分（前回のバックアップから）

#### SRE（えすあーるいー / Site Reliability Engineering）

- 意味：ソフトウェアの技術で運用の信頼性を高める考え方
- ポイント：エラーバジェット（SLOから許される失敗の量）で開発と運用のバランスをとる
- 語の意味：Site＝サイト／Reliability＝信頼性／Engineering＝工学


## 15-5 ファシリティマネジメント


### 設備

#### ファシリティマネジメント（Facility Management）

- 意味：建物・電源・空調などの設備を最適な状態に保つこと

#### UPS（Uninterruptible Power Supply）

- 意味：停電時に一時的に電力を送る装置
- ポイント：長時間の停電は自家発電装置で補う
- 語の意味：Uninterruptible＝途切れない／Power Supply＝電源供給

#### 免震・耐震（Seismic Isolation / Earthquake Resistance）

- 意味：免震は揺れを建物に伝えにくくする、耐震は揺れに耐える構造

#### グリーンIT（Green IT）

- 意味：IT機器の省エネや、ITを使った社会の省エネを進める考え方
- ポイント：データセンタの指標PUE（全体の電力÷IT機器の電力、1に近いほど効率がよい）


## 問題演習

- 書式：「#### 問 問題ID」の下に、問・ア〜エ・正解・解説を書く。「###」は小分類（クイズの範囲に使う）

### 15-1 サービスマネジメント

#### 問 ap-15-q01

- 問：30日間の稼働率をSLAで99.9％と定めたとき、許される停止時間に最も近いものはどれか。
- ア：約4分
- イ：約43分
- ウ：約7時間
- エ：約1日
- 正解：イ
- 解説：30日×24時間×60分×0.001≒43分。

#### 問 ap-15-q02

- 問：サービス提供者の社内の部門間で、サービスを支えるために結ぶ合意はどれか。
- ア：SLA
- イ：OLA
- ウ：UC
- エ：SLO
- 正解：イ
- 解説：社内はOLA、外部の供給者とはUC。

### 15-2 サービスマネジメントシステムの計画及び運用

#### 問 ap-15-q03

- 問：インシデント管理の目的として最も適切なものはどれか。
- ア：根本原因の除去
- イ：サービスの迅速な回復
- ウ：変更の承認
- エ：構成情報の更新
- 正解：イ
- 解説：まず回復を優先する。根本原因は問題管理。

#### 問 ap-15-q04

- 問：根本原因が特定され、回避策もわかっている問題を何というか。
- ア：インシデント
- イ：既知の誤り
- ウ：サービス要求
- エ：変更要求
- 正解：イ
- 解説：既知の誤り（ノウンエラー）。

#### 問 ap-15-q05

- 問：構成品目の情報を記録したデータベースはどれか。
- ア：CMDB
- イ：CRL
- ウ：DWH
- エ：WBS
- 正解：ア
- 解説：CMDB（構成管理データベース）。

### 15-4 サービスの運用

#### 問 ap-15-q06

- 問：サービスデスクで解決できない問合せを、より専門知識をもつ担当者に引き継ぐことを何というか。
- ア：機能的エスカレーション
- イ：階層的エスカレーション
- ウ：ワークアラウンド
- エ：フェールオーバ
- 正解：ア
- 解説：専門の担当へは機能的、上位の管理者へは階層的エスカレーション。

#### 問 ap-15-q07

- 問：SLOをもとに許容される失敗の量を決め、開発の速さと信頼性のバランスをとる考え方はどれか。
- ア：エラーバジェット
- イ：バックログ
- ウ：ベロシティ
- エ：MTBF
- 正解：ア
- 解説：SREのエラーバジェット。

### 15-5 ファシリティマネジメント

#### 問 ap-15-q08

- 問：データセンタの電力効率を表すPUEの説明として正しいものはどれか。
- ア：IT機器の電力÷全体の電力で、大きいほどよい
- イ：全体の電力÷IT機器の電力で、1に近いほどよい
- ウ：IT機器の台数÷床面積
- エ：冷却装置の電力÷全体の電力で、大きいほどよい
- 正解：イ
- 解説：PUE＝データセンタ全体の電力÷IT機器の電力。
