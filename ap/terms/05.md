## 5-1 OSの種類と構成

### まとめ表

**基本ソフトウェアの伝統的な分け方**

| 分類 | 役割 | 例 |
| :-: | :-: | :-: |
| 制御プログラム | ハードウェアと資源を管理し、プログラムを動かす土台になる | ジョブ管理・タスク管理・記憶管理・データ管理・入出力管理 |
| 言語プロセッサ | 人が書いたプログラムを、コンピュータが実行できる形にする | アセンブラ・コンパイラ・インタプリタ |
| サービスプログラム | よく使う定番の処理を、部品として用意しておく | 整列・併合・コピー・バックアップ・アーカイバ |

**カーネルの作り方**

| 方式 | カーネルモードで動かすもの | よいところ | 弱いところ |
| :-: | :-: | :-: | :-: |
| モノリシックカーネル | OSの機能のほとんど全部（記憶管理・ファイル管理・デバイスドライバなど） | 機能どうしの呼出しが直接で速い | 一部の不具合がOS全体を止めやすい |
| マイクロカーネル | 最小限の機能だけ（タスク切替え・記憶管理・プロセス間通信など） | 機能を差し替えやすく、障害が広がりにくい | 機能どうしのやり取りが増えて遅くなりやすい |

**CPUの動作モード**

| モード | 動くもの | 実行できる命令 |
| :-: | :-: | :-: |
| カーネルモード（スーパーバイザーモード・特権モード） | OSのカーネル | 特権命令を含む全ての命令（入出力・割込みの設定など） |
| ユーザーモード（非特権モード） | アプリケーションプログラム | 特権命令以外。OSの機能はシステムコールで頼む |

- 割込みの種類（SVC割込み・入出力割込み・タイマ割込みなど）と、DMA・チャネルなどの入出力制御の方式は #3 コンピュータ構成要素にまとめた
- 再入可能（リエントラント）・再使用可能・再帰的・再配置可能などのプログラムの性質は #2 アルゴリズムとプログラミングにまとめた

### OSの種類

#### リアルタイムOS（りあるたいむおーえす / Real-Time Operating System）

- 意味：決められた時間（デッドライン）までに処理を終えて応答することを最も重視したOS。RTOSとも呼ぶ
- ポイント：優先度に基づくプリエンプティブなスケジューリングで、急ぎのタスクをすぐに動かす。機器の制御などの組込みシステムでよく使う。速さの平均より「最悪でも何秒以内」を守ることが大事
- 例：R3春 問17・R7春 問14（プリエンプションで実行可能状態へ）、R4秋 問18（割込み処理）、R4春 問17・R7秋 問16（セマフォで排他制御）

#### 組込みOS（くみこみおーえす / Embedded Operating System）

- 意味：家電・自動車・産業機器などの機器の中に組み込まれて、その機器専用の制御を行うOS
- ポイント：メモリやCPUの資源が少ない環境で動くよう、小さく作られる。リアルタイムOSであることが多いが、「組込み＝リアルタイム」とは限らない（組込みLinuxなど）

#### モバイル端末用OS（もばいるたんまつようおーえす / Mobile Operating System）

- 意味：スマートフォンやタブレット向けのOS。AndroidやiOSが代表
- ポイント：タッチ操作、電池を長持ちさせる電力管理、アプリケーションごとの権限管理（サンドボックス）に力を入れている

#### PC用OS（ぴーしーようおーえす / Personal Computer Operating System）

- 意味：パソコンで使う汎用のOS。Windows、macOS、Linuxなど
- ポイント：一人の利用者が、多くの種類のアプリケーションを対話的に使うことを前提に作られている

#### セキュアOS（せきゅあおーえす / Secure Operating System）

- 意味：強制アクセス制御（MAC）や最小特権の考え方で、管理者（root）であっても決められた範囲しか操作できないようにしたOS。SELinuxが代表
- ポイント：ふつうのOSは root が何でもできるので、root を乗っ取られると全部やられる。セキュアOSは権限を細かく分けて被害を限定する

#### ネットワークOS（ねっとわーくおーえす / Network Operating System）

- 意味：ネットワークでつながった複数のコンピュータどうしで、ファイルやプリンタなどの資源を共有する機能を備えたOS
- ポイント：今のOSは標準でネットワーク機能を持つので、ほとんどのOSがこれにあたる。通信の制御はOSのネットワーク制御の機能（TCP/IPのプロトコル処理など）が受け持つ

### OSの標準と互換性

#### UNIX（ゆにっくす / UNIX）

- 意味：1960年代末にAT&Tのベル研究所で生まれた、マルチユーザー・マルチタスクのOS。Linux や BSD 系のOSのお手本になった
- ポイント：「小さな道具（コマンド）を組み合わせて使う」設計と、階層型のファイルシステムが特徴。UNIX の商標と仕様は The Open Group が管理している

#### POSIX（ぽじっくす / Portable Operating System Interface）

- 意味：UNIX 系のOSが、アプリケーションに提供するインタフェース（システムコールやコマンドなど）を統一したIEEEの規格
- ポイント：POSIX に従って書いたプログラムは、ソースコードのまま別の POSIX 準拠OSへ移しやすい（ソースレベルの移植性）。バイナリの互換性を決める ABI とは別もの
- 語の意味：Portable＝持ち運べる／Operating System＝OS／Interface＝接点

#### OSE（おーえすいー / Open Systems Environment）

- 意味：標準化されたインタフェースや規格に従って作ることで、メーカーや機種が違っても組み合わせて使えるようにしたシステム環境（オープンシステム環境）
- ポイント：特定メーカーに縛られない（ベンダーロックインを避ける）ことが目的。POSIX などの標準がその土台になる
- 語の意味：Open＝開かれた（標準に基づく）／Systems＝システム／Environment＝環境

#### 互換性（ごかんせい / Compatibility）

- 意味：あるシステムで動いていたプログラムやデータが、別のシステムや新しい版でもそのまま使えること
- ポイント：新しい版で古いものが使える「上位互換（後方互換）」、ソースのまま移せる「ソースレベルの互換性」、作った実行ファイルがそのまま動く「バイナリ互換性」を区別する

### ソフトウェアの体系

#### システムソフトウェア（しすてむそふとうぇあ / System Software）

- 意味：コンピュータそのものを動かし、管理するためのソフトウェアの総称。OS（基本ソフトウェア）とミドルウェアからなる
- ポイント：特定の業務をこなすための応用ソフトウェアと対になる言葉

#### 基本ソフトウェア（きほんそふとうぇあ / Basic Software）

- 意味：コンピュータを動かすのに欠かせない、いちばん土台のソフトウェア。広い意味のOS。制御プログラム・言語プロセッサ・サービスプログラムからなる
- ポイント：狭い意味でOSというと、制御プログラム（その中心がカーネル）を指す

#### 制御プログラム（せいぎょぷろぐらむ / Control Program）

- 意味：ジョブ管理・タスク管理・記憶管理・データ管理・入出力管理などを受け持ち、ハードウェアと資源を管理するプログラム群。狭い意味のOS
- ポイント：アプリケーションは、制御プログラムが用意した機能を呼び出して資源を使う

#### 言語プロセッサ（げんごぷろせっさ / Language Processor）

- 意味：プログラム言語で書かれたプログラムを、コンピュータが実行できる形に変換したり、そのまま解釈して実行したりするプログラム
- ポイント：アセンブラ・コンパイラ・インタプリタなど。各ツールの違いは 5-6 開発ツールにまとめた

#### サービスプログラム（さーびすぷろぐらむ / Service Program）

- 意味：ファイルの整列・併合・コピー・バックアップなど、多くの利用者が使う定番の処理を、すぐ使える形で用意したプログラム。ユーティリティプログラムとも呼ぶ
- ポイント：OSの機能そのものではないが、OSと一緒に提供されることが多い

#### 応用ソフトウェア（おうようそふとうぇあ / Application Software）

- 意味：給与計算・表計算・Webブラウザなど、利用者の具体的な目的のために作られたソフトウェア。アプリケーションソフトウェアとも呼ぶ
- ポイント：業務ごとに作る「個別アプリケーション」と、どの業種でも使える「共通アプリケーション」に分けることがある

### カーネルの構成

#### カーネル（かーねる / Kernel）

- 意味：OSの中核で、プロセス管理・記憶管理・入出力の制御など、アプリケーションが動くための基本機能を提供する部分
- ポイント：利用者が文字で命令を打ち込む「シェル」や、マウスで操作するデスクトップ環境（GUI）は、カーネルの外にある別のソフトウェア
- 例：R5秋 問19（Linuxカーネルはプロセス管理やメモリ管理などの基本機能を提供する）

#### モノリシックカーネル（ものりしっくかーねる / Monolithic Kernel）

- 意味：記憶管理・ファイル管理・デバイスドライバなど、OSの機能のほとんどを一つのかたまりとしてカーネルモードで動かす構成
- ポイント：機能どうしを直接呼び出せるので速い。そのかわり、一つの機能の不具合がOS全体を止めることがある。Linux はこの方式（モジュールを後から足すことはできる）
- 語の意味：Monolithic＝一枚岩の

#### マイクロカーネル（まいくろかーねる / Microkernel）

- 意味：タスク切替え・最低限の記憶管理・プロセス間通信など、最小限の機能だけをカーネルに残し、ファイル管理やデバイスドライバなどはユーザーモードのサーバプロセスとして動かす構成
- ポイント：機能を交換しやすく、一部が落ちても全体が止まりにくい。機能どうしのやり取りがメッセージ通信になるので、モノリシックカーネルより遅くなりやすい
- 語の意味：Micro＝ごく小さい

#### デバイスドライバ（でばいすどらいば / Device Driver）

- 意味：プリンタやディスクなどの個々の装置の違いを吸収し、OSから同じやり方で装置を操作できるようにするソフトウェア
- ポイント：装置ごとに用意する。OSに組み込んで使う（ふつうはカーネルモードで動く）。新しい装置をつなぐときは、その装置のドライバを入れる

### CPUの動作モード

#### カーネルモード（かーねるもーど / Kernel Mode）

- 意味：OSのカーネルが動くときのCPUの動作モード。全ての命令とメモリ領域を使える。スーパーバイザーモード・特権モードとも呼ぶ
- ポイント：入出力装置の操作や割込みの設定のような「特権命令」は、このモードでしか実行できない
- 語の意味：Supervisor＝監督する者

#### ユーザーモード（ゆーざーもーど / User Mode）

- 意味：アプリケーションプログラムが動くときのCPUの動作モード。特権命令を実行できず、使えるメモリも制限される。非特権モードとも呼ぶ
- ポイント：アプリケーションの誤りが、OSや他のプログラムを壊さないようにするための仕組み。特権が要る処理はシステムコールでOSに頼む

#### 特権命令（とっけんめいれい / Privileged Instruction）

- 意味：カーネルモードでだけ実行できる命令。入出力の操作、割込みの禁止・許可、記憶保護の設定などがある
- ポイント：ユーザーモードで特権命令を実行しようとすると、例外（プログラム割込み）が起きてOSに制御が移る

#### システムコール（しすてむこーる / System Call）

- 意味：アプリケーションが、ファイルの読み書きやメモリの確保などOSの機能を使うために、OSを呼び出す仕組み
- ポイント：呼び出すとSVC割込み（スーパーバイザーコール）が起き、CPUがカーネルモードに切り替わってOSの処理が動く。終わるとユーザーモードに戻る
- 語の意味：SVC＝SuperVisor Call（監督者の呼出し）

### OSの管理機能

#### ジョブ管理（じょぶかんり / Job Management）

- 意味：利用者から見た仕事の単位（ジョブ）を受け付け、実行の順番を決めて、ジョブステップごとに実行させるOSの機能。中心になるプログラムはジョブスケジューラー
- ポイント：ジョブを細かく分けた実行単位が「タスク」。ジョブ管理がタスクを作り、タスク管理がCPUを割り当てる

#### タスク管理（たすくかんり / Task Management）

- 意味：プログラムの実行単位（タスク、プロセス）を生成し、状態を管理して、どのタスクにCPUを割り当てるかを決めるOSの機能。プロセス管理とも呼ぶ
- ポイント：スケジューリング・ディスパッチ・排他制御・同期などはこの機能の仕事。詳しくは 5-2 タスク管理

#### 記憶管理（きおくかんり / Memory Management）

- 意味：主記憶の領域をプログラムに割り当てたり、返してもらったりして、限られた主記憶を効率よく使うOSの機能
- ポイント：実記憶の管理（区画方式・スワッピングなど）と仮想記憶の管理（ページングなど）がある。詳しくは 5-3 記憶管理

#### データ管理（でーたかんり / Data Management）

- 意味：補助記憶装置上のデータをファイルとして扱い、装置の違いを意識せずに読み書きできるインタフェースをアプリケーションに提供するOSの機能
- ポイント：レコード・スペース管理（空き領域の管理）・カタログ管理（ファイルの所在の管理）・ファイル保護などを受け持つ。今はファイルシステムがこの役割を担う

#### 入出力管理（にゅうしゅつりょくかんり / Input/Output Management）

- 意味：入出力装置の割当てと入出力の実行を制御し、装置を効率よく動かすOSの機能。装置ごとの細かい制御は IOCS などのプログラムが受け持つ
- ポイント：スプーリングやバッファリングで、遅い入出力装置を待つあいだのCPUのむだを減らす。入出力の制御方式（DMA・チャネルなど）は #3 を参照

#### 運用管理（うんようかんり / Operation Management）

- 意味：システムの起動・終了、オペレーターとのやり取り、利用者の管理、稼働状況の監視（システムモニタリング）など、システムを運用しやすくするOSの機能
- ポイント：ユーザーアカウント・ファイルアクセス権・ディスククオータなどの設定もここに入る

#### 障害管理（しょうがいかんり / Fault Management）

- 意味：障害の検出・記録・診断・回復（再構成やリスタート）など、障害が起きてから対策が終わるまでの一連の処理を受け持つOSの機能
- ポイント：ハードウェアの障害とソフトウェアの障害の両方が対象。障害の記録（ログ）を残すことが、原因の究明に欠かせない

### OSの起動

#### ブートストラップ（ぶーとすとらっぷ / Bootstrap）

- 意味：電源を入れたあと、ROMなどにある小さなプログラムが、より大きなプログラムを順に読み込んで、最後にOSを起動する一連の手順
- ポイント：「靴ひもを引っぱって自分を持ち上げる」という例えから来た言葉。IPL（Initial Program Load）とも呼ぶ。ファームウェア（BIOS・UEFI）→ブートローダ→OSカーネル、の順に進む
- 語の意味：Bootstrap＝ブーツのつまみ（自力で何とかすること）

#### ブートローダ（ぶーとろーだ / Boot Loader）

- 意味：補助記憶装置などからOSのカーネルを読み込んで主記憶に置き、実行を始めさせるプログラム
- ポイント：ファームウェアから呼ばれ、OSにバトンを渡す役目。GRUB などが代表

#### フラッシュブートローダ（ふらっしゅぶーとろーだ / Flash Boot Loader）

- 意味：組込み機器などで、フラッシュメモリに置かれたプログラムの起動と、そのプログラムの書換え（更新）を受け持つブートローダ
- ポイント：機器を工場に戻さなくても、通信などでファームウェアを更新できるようにするための仕組み

#### ネットワークブート（ねっとわーくぶーと / Network Boot）

- 意味：自分のディスクからではなく、ネットワーク上のサーバからOSのイメージを受け取って起動する方式。PXE ブートが代表
- ポイント：ディスクを持たない端末（シンクライアントなど）や、多くのPCを同じ状態で一斉に起動したいときに使う

#### マルチブート（まるちぶーと / Multi-boot）

- 意味：1台のコンピュータに複数のOSを入れておき、起動するときにどのOSで動かすかを選べるようにすること
- ポイント：同時に動くのは1つのOSだけ。複数のOSを同時に動かしたいなら仮想化（仮想マシン）を使う

### ジョブ管理のしくみ

#### ジョブ（じょぶ / Job）

- 意味：利用者がコンピュータに頼む、ひとまとまりの仕事の単位
- ポイント：ジョブは一つ以上のジョブステップからなる。「ジョブ→ジョブステップ→タスク」の順に細かくなる

#### ジョブステップ（じょぶすてっぷ / Job Step）

- 意味：ジョブを構成する、一つ一つのプログラムの実行の単位
- ポイント：例えば「データの整列→集計→印刷」というジョブなら、それぞれがジョブステップ。各ジョブステップを実行するときにタスクが作られる

#### ジョブスケジューラー（じょぶすけじゅーらー / Job Scheduler）

- 意味：投入されたジョブを読み込み、実行の順番を決めて開始させ、終わったら後始末をするジョブ管理のプログラム
- ポイント：リーダ（ジョブを読み込む）・イニシエータ（ジョブステップを開始させる）・ターミネータ（終了処理）・ライタ（結果を出力する）からなる

#### マスタスケジューラー（ますたすけじゅーらー / Master Scheduler）

- 意味：オペレーターとOSとのやり取りを受け持ち、システム全体の動きを監視して、ジョブスケジューラーなどに指示を出すジョブ管理のプログラム
- ポイント：ジョブスケジューラーが「個々のジョブ」を扱うのに対し、マスタスケジューラーは「システム全体」を見る

#### JCL（じぇいしーえる / Job Control Language）

- 意味：ジョブの名前、実行するプログラム、使うファイルなどを、OSに指示するための言語（ジョブ制御言語）
- ポイント：汎用機のバッチ処理で使う。今のPCやUNIXのシェルスクリプトが、近い役割を果たしている
- 語の意味：Job＝仕事／Control＝制御／Language＝言語

### 処理の進め方

#### バッチ処理（ばっちしょり / Batch Processing）

- 意味：データを一定の期間や量だけためておき、まとめて一括で処理する方式
- ポイント：給与計算や月末の集計のように、すぐに結果が要らない大量の処理に向く。夜間に自動で動かすことが多い
- 語の意味：Batch＝ひとまとめ

#### 対話型処理（たいわがたしょり / Interactive Processing）

- 意味：利用者が端末から命令や入力を与えるたびに、コンピュータがすぐ処理して応答を返す方式
- ポイント：応答時間の短さが重要。バッチ処理と対になる

#### バックグラウンドジョブ（ばっくぐらうんどじょぶ / Background Job）

- 意味：利用者が端末で対話的に操作している（フォアグラウンドの）処理の裏で、並行して動かしておくジョブ
- ポイント：UNIX系では、コマンドの最後に「&」をつけるとバックグラウンドで実行される

#### cron（くろん / cron）

- 意味：UNIX系OSで、決めた日時や間隔でコマンドを自動的に実行させる仕組み（常駐プログラム）
- ポイント：「毎日2時にバックアップ」のような定期処理の自動運転に使う。実行の予定は crontab というファイルに書く

### 入出力を効率よくする仕組み

#### スプーリング（すぷーりんぐ / Spooling）

- 意味：プリンタなど遅い装置への出力を、いったん高速な磁気ディスクにためておき、装置の空き具合に合わせて少しずつ出力する仕組み
- ポイント：プログラムは装置の終わりを待たずに次へ進めるので、CPUの待ち時間が減り、全体の処理効率（スループット）が上がる。印刷の待ち行列が代表
- 例：R4秋 問19（複数のプリンタに印刷データを空いた順に割り当てる）
- 語の意味：SPOOL＝Simultaneous Peripheral Operation On-Line（周辺装置の同時オンライン操作）

#### バッファリング（ばっふぁりんぐ / Buffering）

- 意味：速さの違う装置どうしのデータのやり取りで、主記憶上の一時的な置き場（バッファ）にデータをためて、速度の差を吸収すること
- ポイント：スプーリングがディスクを使って「ジョブの単位」でためるのに対し、バッファリングは主記憶を使って「入出力の単位」でためる

#### バッファプール（ばっふぁぷーる / Buffer Pool）

- 意味：入出力に使うバッファをまとめて確保しておき、必要なときに貸し出し、使い終わったら返してもらって使い回す仕組み
- ポイント：入出力のたびにバッファを作り直す手間が減る。DBMSでも、ページをためておく領域をこう呼ぶ

#### IOCS（あいおーしーえす / Input/Output Control System）

- 意味：入出力装置ごとの細かい制御を受け持ち、アプリケーションが装置を意識せずに読み書きできるようにするOSのプログラム（入出力制御システム）
- ポイント：アプリケーションは「レコードを読む」と頼むだけでよい。ブロッキング・デブロッキングもIOCSが行う
- 語の意味：Input/Output＝入出力／Control System＝制御システム

### 利用者の種類

#### スーパーユーザー（すーぱーゆーざー / Superuser）

- 意味：システムのあらゆる操作が許された、管理者のための特別な利用者。UNIX系では root、Windowsでは Administrator がこれにあたる
- ポイント：権限が強すぎるので、ふだんは一般ユーザーで作業し、必要なときだけ管理者の権限を使う（最小特権）。パスワードが漏れると被害が大きい

#### 一般ユーザー（いっぱんゆーざー / Standard User）

- 意味：自分のファイルの操作など、決められた範囲の操作だけが許された利用者
- ポイント：システムの設定変更やソフトウェアのインストールには、管理者の権限が要る

#### ゲストアカウント（げすとあかうんと / Guest Account）

- 意味：一時的な訪問者などが、個人のアカウントを持たずに使うための、権限をとても小さくした共用アカウント
- ポイント：誰が使ったか区別できず、不正に使われやすいので、ふつうは無効にしておく

#### UAC（ゆーえーしー / User Account Control）

- 意味：Windowsで、管理者の権限が要る操作をしようとしたときに確認の画面を出し、利用者の許可や管理者のパスワードを求める仕組み（ユーザーアカウント制御）
- ポイント：管理者でログインしていても、ふだんは一般の権限で動かし、必要な瞬間だけ権限を上げる。マルウェアが勝手に設定を変えるのを防ぐ
- 語の意味：User Account＝利用者のアカウント／Control＝制御

### 資源の使い方の制限

#### ユーザーアカウント（ゆーざーあかうんと / User Account）

- 意味：システムを使う権利を、利用者ごとに識別するための登録情報。利用者IDとパスワードなどの組
- ポイント：アカウントごとに、使えるファイルや操作（権限）を決める。退職者のアカウントはすぐに削除する

#### ファイルアクセス権（ふぁいるあくせすけん / File Access Permission）

- 意味：ファイルやディレクトリに対して、誰が「読む・書く・実行する」ことができるかを決めた権利
- ポイント：UNIX系では、所有者・グループ・その他の3者ごとに r（読み）w（書き）x（実行）を設定する

#### ディスククオータ（でぃすくくおーた / Disk Quota）

- 意味：利用者ごと（またはグループごと）に、使ってよい磁気ディスクの容量の上限を決める仕組み
- ポイント：一人が容量を使い切って、他の利用者が書き込めなくなるのを防ぐ
- 語の意味：Quota＝割当て量

#### プロファイル（ぷろふぁいる / Profile）

- 意味：利用者ごとの作業環境の設定（デスクトップの状態・環境変数・使うプログラムなど）をまとめた情報
- ポイント：ログインしたときに読み込まれ、その人用の環境ができる。どの端末からでも同じ環境を使えるようにしたものを「移動プロファイル」と呼ぶ

### アカウントの一元管理

#### ディレクトリサービス（でぃれくとりさーびす / Directory Service）

- 意味：ネットワーク上の利用者・コンピュータ・プリンタなどの情報を一か所にまとめて登録し、検索や認証に使えるようにするサービス
- ポイント：システムごとにアカウントを作らなくても、一か所の登録で多くのシステムを使えるようになる。ファイルの「ディレクトリ」とは別の意味

#### LDAP（えるだっぷ / Lightweight Directory Access Protocol）

- 意味：ディレクトリサービスに登録された情報を、検索したり更新したりするためのプロトコル
- ポイント：ディレクトリサービスそのものではなく、そこへ問い合わせるための「通信の約束ごと」。Active Directory も LDAP で問い合わせることができる
- 語の意味：Lightweight＝軽量の／Directory＝名簿／Access＝接続／Protocol＝通信規約

#### Active Directory（あくてぃぶでぃれくとり / Active Directory）

- 意味：マイクロソフトが提供する、Windowsネットワーク向けのディレクトリサービス
- ポイント：利用者やコンピュータを「ドメイン」という単位でまとめて管理し、一度のログインでドメイン内の資源を使えるようにする。認証には Kerberos を使う

#### ドメインコントローラ（どめいんこんとろーら / Domain Controller）

- 意味：Active Directory のドメインで、利用者の情報を持ち、ログインの認証を受け持つサーバ
- ポイント：止まるとドメイン全体でログインできなくなるので、ふつうは複数台を置いて情報を複製しておく

### OSのセキュリティ制御

#### 強制アクセス制御（きょうせいあくせすせいぎょ / Mandatory Access Control）

- 意味：システムの管理方針（セキュリティポリシー）に基づいてアクセスの可否が決められ、ファイルの所有者であっても変えられないアクセス制御。MACとも呼ぶ
- ポイント：セキュアOSの中心となる仕組み。情報の機密度（ラベル）と利用者の資格を比べて判断することが多い
- 語の意味：Mandatory＝強制の

#### 任意アクセス制御（にんいあくせすせいぎょ / Discretionary Access Control）

- 意味：ファイルの所有者が、自分の判断で、誰にどんなアクセスを許すかを決められるアクセス制御。DACとも呼ぶ
- ポイント：ふつうのOSのファイルアクセス権はこれ。所有者が誤って広く許すと、情報が漏れる
- 語の意味：Discretionary＝自由裁量の

#### 多重レベルセキュリティ（たじゅうれべるせきゅりてぃ / Multi-Level Security）

- 意味：情報に「極秘・秘・一般」のような機密度の段階をつけ、利用者の資格の段階と比べてアクセスを制御する方式
- ポイント：強制アクセス制御の代表的な使い方。軍や政府の情報管理から生まれた

#### BLPモデル（びーえるぴーもでる / Bell-LaPadula Model）

- 意味：多重レベルセキュリティで、情報の機密性を守るための規則を定めたモデル。「自分より上の機密度の情報は読めない（No Read Up）」「自分より下の機密度へは書けない（No Write Down）」
- ポイント：下へ書けないことで、秘密の情報を低いレベルに書き写して漏らすことを防ぐ。守るのは機密性で、完全性を守るのは Biba モデル
- 語の意味：Bell と LaPadula は考えた人の名前

#### セキュリティカーネル（せきゅりてぃかーねる / Security Kernel）

- 意味：アクセス制御など、セキュリティを守るための機能を集めて、OSの中核に組み込んだ部分
- ポイント：全てのアクセスはここを通って検査される（参照モニタの考え方）。小さく作って、正しさを検証できるようにする

### 障害への備え

#### タイマー監視（たいまーかんし / Timer Monitoring）

- 意味：決めた時間内に処理が終わらない、または応答が返らないことをタイマーで検出し、障害とみなす仕組み
- ポイント：組込み機器のウォッチドッグタイマーはその代表。プログラムが定期的にタイマーをクリアし、クリアされないまま時間が来たら、異常として機器をリセットする

#### 動的再構成（どうてきさいこうせい / Dynamic Reconfiguration）

- 意味：システムを止めずに、故障した装置を切り離したり、予備の装置を組み込んだりして、構成を組み替えること
- ポイント：CPUが故障したときに残りのCPUで運転を続ける「自動CPU再構成」などがある

#### チェックポイントリスタート（ちぇっくぽいんとりすたーと / Checkpoint Restart）

- 意味：処理の途中の状態を定期的に記録しておき（チェックポイント）、障害が起きたら、最後に記録した時点から処理をやり直す方法
- ポイント：最初からやり直さずに済むので、長い処理の回復時間が短くなる。データベースの障害回復でも同じ考え方を使う

#### ロギング（ろぎんぐ / Logging）

- 意味：システムで起きたこと（操作・アクセス・エラーなど）を、時刻とともに記録として残すこと
- ポイント：障害の原因の調査や、不正アクセスの追跡（監査）に使う。ログそのものが改ざんされないよう守ることも大事

### サービスプログラム

#### 整列プログラム（せいれつぷろぐらむ / Sort Program）

- 意味：ファイルのレコードを、指定した項目（キー）の順に並べ替えるサービスプログラム。ソートプログラムとも呼ぶ
- ポイント：昇順・降順や、複数のキーを指定できる。並べ替えのアルゴリズムそのものは #2 を参照

#### 併合プログラム（へいごうぷろぐらむ / Merge Program）

- 意味：同じキーの順に整列済みの複数のファイルを、順序を保ったまま一つのファイルにまとめるサービスプログラム。マージプログラムとも呼ぶ
- ポイント：入力するファイルは、あらかじめ同じキーで整列しておく必要がある

#### アーカイバ（あーかいば / Archiver）

- 意味：複数のファイルを一つのファイルにまとめたり（多くは圧縮も行う）、まとめたファイルを元に戻したりするプログラム
- ポイント：ZIP や tar が代表。配布や保管のときに、ファイルをまとめて扱いやすくする

#### フォーマッタ（ふぉーまった / Formatter）

- 意味：磁気ディスクなどの記憶媒体を、OSがデータを書き込める状態に初期化する（フォーマットする）プログラム
- ポイント：フォーマットすると、媒体の中のデータは原則として消える。ファイルシステムの種類（FAT・NTFSなど）もこのとき決める

## 5-2 タスク管理

### まとめ表

**タスクの3つの状態と移り変わり（R3春 問17・R6春 問16 の論点）**

| 移り変わり | きっかけ |
| :-: | :-: |
| 実行可能状態 → 実行状態 | ディスパッチ（CPUが割り当てられた） |
| 実行状態 → 実行可能状態 | プリエンプション（優先度の高いタスクが来た・タイムクウォンタムを使い切った） |
| 実行状態 → 待ち状態 | 入出力の開始・資源やイベントを待つ |
| 待ち状態 → 実行可能状態 | 入出力の終了・待っていたイベントが起きた |

- 待ち状態から直接、実行状態へは移らない（いったん実行可能状態に並ぶ）
- 実行可能状態から待ち状態へも移らない（動いていないタスクは入出力を始められない）

**スケジューリングの方式（R3春 問16・R6秋 問16・R7秋 問15 の論点）**

| 方式 | 次に動かすタスク | 途中で取り上げるか | 押さえどころ |
| :-: | :-: | :-: | :-: |
| 到着順（FCFS） | 先に来たもの | しない | 長い処理の後ろの短い処理が待たされる |
| 処理時間順（SJF） | 処理時間が最も短いもの | しない（取り上げる型もある） | 平均の待ち時間は最も短いが、長い処理がいつまでも待たされることがある |
| 優先度順 | 優先度が最も高いもの | することが多い | 低い優先度のタスクが待たされ続けることがある（エージングで防ぐ） |
| ラウンドロビン | 待ち行列の先頭 | する（タイムクウォンタムを使い切ったら最後尾へ） | 全てのタスクに公平に少しずつCPUを回す |
| 多段フィードバック待ち行列 | 優先度の高い待ち行列の先頭 | する（使い切ったら一段低い待ち行列へ） | 短い処理ほど早く終わる。長い処理は少しずつ後回しになる |

**ターンアラウンドタイムの計算の手順**

1. 到着時刻と処理時間を表にする
2. 方式のルールに従って、時刻0から順に「いつ・どのジョブが動くか」を時間の線（ガントチャート）に書く
3. ターンアラウンドタイム＝終了時刻－到着時刻（待っている時間も含む）

**デッドロックを防ぐ考え方（R4秋 問16・R6春 問17 の論点）**

| やり方 | 中身 |
| :-: | :-: |
| 資源を取る順番をそろえる | 全てのタスクが「X→Y」のように同じ順番で資源を取れば、互いに待つ輪ができない |
| 必要な資源をまとめて取る | 全部そろわなければ一つも取らない |
| 取れなかったら手放す | 待つ前に、持っている資源を返す |

### 実行の単位

#### プロセス（ぷろせす / Process）

- 意味：実行中のプログラムのこと。OSから見た、主記憶の領域やファイルなどの資源を割り当てる単位
- ポイント：プロセスどうしは、主記憶の空間が別々なので互いに干渉しない。その分、作るのも切り替えるのも手間がかかる。OSによってはタスクと同じ意味で使う

#### スレッド（すれっど / Thread）

- 意味：プロセスの中で、CPUを割り当てる処理の流れの単位。一つのプロセスの中に複数のスレッドを作れる
- ポイント：同じプロセスのスレッドどうしは、主記憶の空間やファイルを共有する。だからプロセスより軽く作れて速く切り替えられるが、共有データの取り合い（競合）に気をつける必要がある。軽量プロセスとも呼ぶ
- 語の意味：Thread＝糸（処理の筋道）

#### タスク（たすく / Task）

- 意味：OSから見た、CPUを割り当てて実行する仕事の単位。ジョブステップを実行するときに作られる
- ポイント：OSや文脈によって、プロセスと同じ意味にもスレッドと同じ意味にもなる。試験では「実行の単位」として読めばよい

#### マルチスレッド（まるちすれっど / Multi-thread）

- 意味：一つのプロセスの中で複数のスレッドを並行して動かすこと
- ポイント：一つのスレッドが入出力を待っていても、別のスレッドが処理を進められるので、応答が良くなる。共有データの扱いを誤ると、結果がおかしくなる
- 例：R4春 問17・R7秋 問16 ウ（排他制御の機能ではない）

### タスクの状態

#### 実行状態（じっこうじょうたい / Running State）

- 意味：タスクにCPUが割り当てられて、実際に命令を実行している状態
- ポイント：CPUが1個なら、実行状態のタスクは同時に1つだけ

#### 実行可能状態（じっこうかのうじょうたい / Ready State）

- 意味：CPUさえ割り当てられればすぐ実行できる状態で、CPUの空きを待っている状態。レディ状態とも呼ぶ
- ポイント：実行中のタスクがプリエンプション（横取り）されると、この状態に戻る。待ち状態ではない
- 例：R3春 問17・R7春 問14（プリエンプションで移る状態）

#### 待ち状態（まちじょうたい / Waiting State）

- 意味：入出力の終了や、資源の解放、イベントの発生などを待っていて、CPUが空いても実行できない状態。ブロック状態とも呼ぶ
- ポイント：待っていたことが起きると、まず実行可能状態に移る。待ち状態から直接、実行状態にはならない

#### 休止状態（きゅうしじょうたい / Dormant State）

- 意味：リアルタイムOSで、タスクが登録されているが、まだ起動されていない（または実行を終えた）状態
- ポイント：起動されると実行可能状態に移る。プリエンプションで移る先ではない

### 状態を切り替える動き

#### ディスパッチ（でぃすぱっち / Dispatch）

- 意味：実行可能状態のタスクの中から一つを選んで、CPUを割り当て、実行状態にすること
- ポイント：ディスパッチを行うOSのプログラムをディスパッチャと呼ぶ
- 語の意味：Dispatch＝送り出す

#### ディスパッチャ（でぃすぱっちゃ / Dispatcher）

- 意味：スケジューリングの規則に従って、次に実行するタスクを選び、CPUを割り当てるOSのプログラム
- ポイント：タスクを切り替えるときには、それまでのタスクのレジスタの内容などを保存し、次のタスクの内容を戻す（コンテキスト切替え）

#### プリエンプション（ぷりえんぷしょん / Preemption）

- 意味：実行中のタスクからOSがCPUを取り上げて、実行可能状態に戻すこと
- ポイント：優先度の高いタスクが実行可能になったときや、タイムクウォンタムを使い切ったときに起きる。取り上げられたタスクは待ち状態ではなく実行可能状態になる
- 語の意味：Preemption＝先取り・横取り

#### コンテキスト切替え（こんてきすときりかえ / Context Switch）

- 意味：CPUで実行するタスクを替えるときに、今のタスクのレジスタやプログラムカウンタの値を保存し、次のタスクの値を読み込むこと
- ポイント：切り替えのたびに時間がかかる（オーバーヘッド）。タスクを細かく切り替えすぎると、この時間が増えて効率が落ちる

### 切替えのきっかけ

#### プリエンプティブ方式（ぷりえんぷてぃぶほうしき / Preemptive Scheduling）

- 意味：実行中のタスクがあっても、OSが判断してCPUを取り上げ、別のタスクに切り替えられるスケジューリングの方式
- ポイント：優先度の高いタスクが実行可能になると、すぐに切り替わる。リアルタイムOSや今のPC用OSはこの方式
- 例：R6春 問16 エ（これはプリエンプティブ方式の動き）、R5秋 問17（優先度の高い周期タスクが割り込んで実行される）

#### ノンプリエンプティブ方式（のんぷりえんぷてぃぶほうしき / Non-preemptive Scheduling）

- 意味：実行中のタスクが自分からCPUを手放す（終了する・待ちに入る・中断をOSに頼む）までは、OSが切り替えない方式
- ポイント：一つのタスクが無限ループに入ると、他のタスクが動けなくなる。OSが優先度を上げて切替えを防ぐ、という仕組みではない
- 例：R6春 問16（自らの中断をOSに要求したときだけ切り替えられる）

#### タイムスライス方式（たいむすらいすほうしき / Time Slicing）

- 意味：CPUを使える時間を一定の長さ（タイムクウォンタム）に区切り、その時間が来たら次のタスクに切り替える方式
- ポイント：ラウンドロビン方式は、タイムスライスで切り替えた先を「待ち行列の順」にしたもの

#### イベントドリブン方式（いべんとどりぶんほうしき / Event-driven Scheduling）

- 意味：入出力の終了や割込みなどの出来事（イベント）が起きたときに、スケジューリングをやり直してタスクを切り替える方式
- ポイント：時間で区切るタイムスライス方式と対になる。リアルタイムOSでは、イベントと優先度の組合せで切り替えることが多い

### スケジューリングの方式

#### 到着順方式（とうちゃくじゅんほうしき / First Come First Served）

- 意味：実行可能状態になった順（待ち行列に並んだ順）にCPUを割り当てる方式。FCFS、先着順とも呼ぶ
- ポイント：公平で簡単だが、処理時間の長いタスクの後ろに並んだ短いタスクが長く待たされる
- 例：R3春 問16（到着順でジョブCのターンアラウンドタイムを求める）、R6秋 問16 エ
- 語の意味：First Come First Served＝先に来た人から先に

#### 処理時間順方式（しょりじかんじゅんほうしき / Shortest Job First）

- 意味：処理時間の短いタスクから順にCPUを割り当てる方式。SJF、最短時間順とも呼ぶ
- ポイント：平均の待ち時間は最も短くなる。そのかわり、短いタスクが次々に来ると、長いタスクがいつまでも実行されないことがある（スタベーション）
- 例：R6秋 問16（CPUの割当てを待ち続ける可能性が最も高い）、R7秋 問15（処理時間順でジョブBのターンアラウンドタイムを求める）
- 語の意味：Shortest＝最も短い／Job＝仕事／First＝先に

#### 優先度順方式（ゆうせんどじゅんほうしき / Priority Scheduling）

- 意味：タスクごとに優先度を決め、優先度の最も高いタスクにCPUを割り当てる方式。優先順方式とも呼ぶ
- ポイント：プリエンプティブにすると、優先度の高いタスクが来たときに、実行中の低いタスクが中断される。低いタスクが待たされ続けないように、エージングを組み合わせる

#### ラウンドロビン方式（らうんどろびんほうしき / Round Robin）

- 意味：待ち行列の順にCPUを割り当て、決められた時間（タイムクウォンタム）を使い切ったタスクは、中断して待ち行列の最後尾に回す方式
- ポイント：どのタスクにも順番が回ってくるので、待たされ続けるタスクは出ない。排他制御の機能ではない
- 例：R6秋 問16 イ、R4春 問17 エ（排他制御には使えない）
- 語の意味：Round Robin＝順番に回すこと（もとは署名の順番がわからないよう円形に書いた嘆願書）

#### 多段フィードバック待ち行列方式（ただんふぃーどばっくまちぎょうれつほうしき / Multilevel Feedback Queue）

- 意味：優先度ごとに複数の待ち行列を用意し、タイムクウォンタムを使い切ったタスクを一段低い待ち行列へ移していく方式
- ポイント：短いタスクは高い優先度のうちに終わり、長いタスクはだんだん後回しになる。処理時間を前もって知らなくても、処理時間順に近い効果が出る

### 優先度のつけ方

#### 静的優先順位方式（せいてきゆうせんじゅんいほうしき / Static Priority）

- 意味：タスクを作るときに決めた優先度を、実行が終わるまで変えない方式
- ポイント：仕組みが簡単で、動きを予測しやすい。リアルタイムOSでよく使う。低い優先度のタスクは待たされ続けるおそれがある

#### 動的優先順位方式（どうてきゆうせんじゅんいほうしき / Dynamic Priority）

- 意味：待ち時間の長さやCPUの使い方などに応じて、実行中に優先度を変えていく方式
- ポイント：エージングや、入出力の多いタスクの優先度を上げるやり方などがある

#### エージング（えーじんぐ / Aging）

- 意味：CPUの割当てを待っている時間が長くなるにつれて、そのタスクの優先度を少しずつ上げていく仕組み
- ポイント：優先度の低いタスクがいつまでも実行されない（スタベーション）のを防ぐ
- 例：R6秋 問16 ア（待ち時間に応じて優先度を上げるので、待ち続けにくい）
- 語の意味：Aging＝年をとること

#### スタベーション（すたべーしょん / Starvation）

- 意味：優先度が低い、または処理時間が長いなどの理由で、あるタスクにCPUなどの資源がいつまでも割り当てられない状態。リソーススタベーション、飢餓状態とも呼ぶ
- ポイント：デッドロックは「互いに待って全員が止まる」、スタベーションは「他は動いているのに、特定のタスクだけが待たされ続ける」
- 語の意味：Starvation＝飢え

### 多重プログラミング

#### 多重プログラミング（たじゅうぷろぐらみんぐ / Multiprogramming）

- 意味：主記憶に複数のプログラムを置いておき、あるプログラムが入出力を待つあいだに別のプログラムにCPUを使わせて、CPUの空き時間を減らす方式。マルチタスクとも呼ぶ
- ポイント：一つ一つのプログラムが速くなるのではなく、全体の処理量（スループット）が上がる

#### 多重度（たじゅうど / Degree of Multiprogramming）

- 意味：同時に並行して実行できるタスクやジョブの数
- ポイント：多重度を上げると処理が重なって全体は早く終わるが、上げすぎると主記憶が足りなくなり、かえって遅くなる（スラッシングなど）
- 例：R4春 問19・R6春 問18（多重度1と2で終わるまでの時間の差）、R4春 問16（多重度2でジョブの一時ファイルの容量を求める）

#### タイムクウォンタム（たいむくうぉんたむ / Time Quantum）

- 意味：時間で区切ってタスクを切り替える方式で、一つのタスクが一度に続けてCPUを使える時間の長さ
- ポイント：タイムスライスとも呼ぶ。短すぎると切替えのオーバーヘッドが増え、長すぎると到着順方式に近づいて応答が悪くなる
- 語の意味：Quantum＝ある決まった量

#### ターンアラウンドタイム（たーんあらうんどたいむ / Turnaround Time）

- 意味：ジョブを投入してから、その処理結果を全て受け取るまでの時間
- ポイント：実行している時間だけでなく、待ち行列で待っている時間も含む。「終了時刻－到着時刻」で求める
- 例：R3春 問16（到着順）、R7秋 問15（処理時間順）

### 排他制御の仕組み

#### 排他制御（はいたせいぎょ / Mutual Exclusion）

- 意味：複数のタスクが同じ資源（共有データ・装置）を同時に使って内容が壊れないように、ある時点で使えるタスクを一つに限ること。セマフォやミューテックスなどの仕組みで実現する
- ポイント：実現にはセマフォやミューテックスを使う。資源の取り方を誤ると、デッドロックが起きる
- 例：R4春 問17・R7秋 問16（一つのI2Cバスにつながる2つのセンサーを読む2つのタスクの排他制御）

#### クリティカルセクション（くりてぃかるせくしょん / Critical Section）

- 意味：プログラムの中で、共有資源を読み書きしているために、同時に一つのタスクしか実行してはいけない部分。危険区間とも呼ぶ
- ポイント：入る前に資源を確保（ロック）し、出たら解放する。この部分はできるだけ短く書く

#### セマフォ（せまふぉ / Semaphore）

- 意味：資源の空き数を表す変数（カウンタ）と、それを操作するP操作・V操作を使って、排他制御や同期を行う仕組み
- ポイント：P操作で「カウンタが1以上なら1減らして進む、0なら待つ」、V操作で「カウンタを1増やし、待っているタスクがあれば起こす」。カウンタが0と1だけのものをバイナリセマフォと呼ぶ
- 例：R4春 問17・R7秋 問16（2つのタスクの排他制御に使うリアルタイムOSの機能）
- 語の意味：Semaphore＝手旗信号・腕木式の信号機

#### ミューテックス（みゅーてっくす / Mutex）

- 意味：排他制御のためのロックの仕組みで、資源をロックした（所有した）タスクだけが、そのロックを解放できるもの
- ポイント：バイナリセマフォに似ているが、セマフォは別のタスクからV操作で解放できる点が違う。優先度逆転を防ぐ仕組み（優先度継承）をつけたものもある
- 語の意味：Mutual Exclusion（相互排除）の略

#### スピンロック（すぴんろっく / Spinlock）

- 意味：ロックが取れるまで、待ち状態にならずにループで繰り返し確認しながら待つ（ビジーウェイト）排他制御の方法
- ポイント：待つあいだもCPUを使い続ける。ロックがすぐ外れるとわかっているマルチプロセッサの環境では、待ち状態への切替えより速い
- 語の意味：Spin＝くるくる回る

### タスク間の同期と通信

#### イベントフラグ（いべんとふらぐ / Event Flag）

- 意味：タスクどうしで「ある出来事が起きた」ことを、ビットの立った・立たないで知らせ合う同期の仕組み
- ポイント：複数のビットを組み合わせて、「AとBの両方が起きたら」のような待ち方ができる。データそのものは渡さない

#### メッセージキュー（めっせーじきゅー / Message Queue）

- 意味：タスクどうしでデータ（メッセージ）を受け渡すための待ち行列。送った順に取り出される
- ポイント：送る側と受け取る側が、同じ時に動いていなくてもよい（非同期）。排他制御そのものの仕組みではない
- 例：R4春 問17・R7秋 問16 ア（キューは排他制御の機能ではない）

#### メールボックス（めーるぼっくす / Mailbox）

- 意味：リアルタイムOSで、タスクどうしがメッセージを置いたり取り出したりするための受け渡し場所
- ポイント：メッセージキューと同じく、データの受け渡しに使う。受け取る側は、メッセージが届くまで待ち状態になれる

#### 共有メモリ（きょうゆうめもり / Shared Memory）

- 意味：複数のタスクやプロセスから同じ主記憶の領域を読み書きできるようにして、データをやり取りする方法
- ポイント：コピーが要らないので速いが、同時に書き換えると壊れるので、セマフォなどの排他制御と組み合わせて使う

#### パイプ（ぱいぷ / Pipe）

- 意味：あるプロセスの出力を、別のプロセスの入力に直接つなぐ、プロセス間通信の仕組み
- ポイント：UNIX系のシェルでは「|」で書く（例：ls | sort）。データは一方向に、書いた順に流れる

### 並行処理で起きる問題

#### デッドロック（でっどろっく / Deadlock）

- 意味：複数のタスクが、互いに相手の持っている資源の解放を待ち合って、どれも先へ進めなくなった状態
- ポイント：全てのタスクが資源を同じ順番で取るようにすれば、待ちの輪ができず防げる。優先度を変えても防げない
- 例：R4秋 問16・R7秋 問18（資源獲得の順序を両方のタスクで同じにする）、R6春 問17（資源の取る順番が逆のプロセスと同時に動かすと起こる）
- 語の意味：Dead＝動かない／Lock＝錠

#### 競合状態（きょうごうじょうたい / Race Condition）

- 意味：複数のタスクが同じデータを同時に読み書きしたとき、実行のタイミングによって結果が変わってしまう状態。レースコンディションとも呼ぶ
- ポイント：「読む→計算→書く」の途中で別のタスクが割り込むと、更新が消えることがある。排他制御で防ぐ
- 語の意味：Race＝競争

#### スレッドセーフ（すれっどせーふ / Thread-safe）

- 意味：プログラムや関数を、複数のスレッドから同時に並行して呼び出しても、問題が起きない（正しく動く）性質
- ポイント：共有データを排他制御で守る、共有データを持たない、などで実現する。「複数スレッドから呼び出せないようにする」ことではない
- 例：R7秋 問17（複数のスレッドで並列に実行しても問題が生じない）

#### 優先度逆転（ゆうせんどぎゃくてん / Priority Inversion）

- 意味：優先度の低いタスクが資源をロックしているあいだに、中くらいの優先度のタスクが動き続け、その資源を待つ優先度の高いタスクが実行されなくなる現象
- ポイント：リアルタイムOSで問題になる。ロックを持つタスクの優先度を一時的に上げる「優先度継承」で防ぐ

#### ライブロック（らいぶろっく / Livelock）

- 意味：複数のタスクが互いに相手に譲り合う動きを繰り返して、動いてはいるのに、どれも処理が先へ進まない状態
- ポイント：デッドロックは止まったまま、ライブロックは動き続けているのに進まない。狭い廊下で互いによけ合う人に例えられる

### 割込みとリアルタイム処理

#### 割込みハンドラ（わりこみはんどら / Interrupt Handler）

- 意味：割込みが起きたときに呼び出されて、その割込みの処理を行うプログラム。割込み処理ルーチンとも呼ぶ
- ポイント：割込み処理は、どのタスクよりも優先して実行される（割込み禁止中を除く）。処理が長いと、その間タスクが動けず応答が悪くなるので、短く作る
- 例：R4秋 問18（割込み処理ルーチンは最も優先度の高いタスクよりも優先して実行される）

#### 割込み禁止（わりこみきんし / Interrupt Disable）

- 意味：決められた区間だけ、割込みを受け付けないようにすること
- ポイント：割込みハンドラとタスクが共有するデータを守るために使う。禁止の時間が長いと、急ぎの割込みに応えられなくなる。「タスクの切替えの禁止」とは別のもの

#### 周期タスク（しゅうきたすく / Periodic Task）

- 意味：一定の時間間隔（周期）ごとに起動される、リアルタイムシステムのタスク
- ポイント：周期内に、自分より優先度の高いタスクが使う時間を除いた残りで処理を終えられるかを確かめる必要がある
- 例：R5秋 問17（優先度の低いタスクBが周期内に処理を終えられる組合せ）

#### ティック（てぃっく / Tick）

- 意味：OSが時間を管理するために、一定の間隔で起こすタイマ割込みの1回分（システムクロックの刻み）
- ポイント：タイムスライスの切替えや、時間待ちのタスクを起こすタイミングは、ティックを単位に決まる

## 5-3 記憶管理

### まとめ表

**実記憶の割当て方式**

| 方式 | 主記憶の分け方 | 押さえどころ |
| :-: | :-: | :-: |
| 単一連続割当て方式 | OSの残りを1つのプログラムが全部使う | 同時に1つしか動かせない |
| 固定区画方式 | 前もって決めた大きさの区画に分ける | 区画の中に使われない余り（内部断片化）が出る |
| 可変区画方式 | プログラムの大きさに合わせて、その都度切り出す | 返された領域が細切れになる（外部断片化）。コンパクションで寄せ集める |

**ページングとセグメントの違い（R6秋 問18 の論点）**

| 方式 | 分ける単位 | よいところ | 弱いところ |
| :-: | :-: | :-: | :-: |
| ページング方式 | 決まった大きさのページ | 主記憶の外部断片化が起きない | ページの中の余り（内部断片化）が出る。論理的なまとまりで保護・共有しにくい |
| セグメント方式 | プログラムやデータなどの論理的なまとまり（大きさは色々） | まとまりごとに保護・共有でき、大きさも変えられる | 大きさがばらばらなので、外部断片化が起きる |

**ページ置換えのアルゴリズム（R5春 問17・R7春 問15・R7秋 問19 の論点）**

| 方式 | 追い出すページ | 表のどこを見るか |
| :-: | :-: | :-: |
| FIFO | いちばん先に読み込んだページ | 読み込んだ（ロードした）時刻が最も古い |
| LIFO | いちばん後に読み込んだページ | 読み込んだ時刻が最も新しい |
| LRU | 最後に参照されてから最も長い時間がたったページ | 最終参照時刻が最も古い |
| LFU | 参照された回数が最も少ないページ | 参照回数が最も少ない |
| OPT（最適） | これから最も長いあいだ参照されないページ | 先の参照順（実際には知ることができないので、比べる基準として使う） |

- 置換えの手順の問題は、ページ枠を横に並べた表を書き、参照のたびに「ヒット（そのまま）」か「フォールト（追い出して入れる）」かを1行ずつ記入すると間違えにくい
- ページフォールトが起きると必ずページインが起きる。空きのページ枠があればページアウトは起きない。だから「ページフォールト＝ページイン ≧ ページアウト」（R3春 問19）

**ページフォールトが入った時間の計算（R3秋 問17・R5秋 問16 の論点）**

- 1命令あたりの遅れ＝1命令あたりのアクセス回数 × ページフォールトの発生率 × 1回のページフォールトの処理時間
- 平均の処理時間＝（ページアウトなしの割合）×（ページインだけの時間）＋（ページアウトありの割合）×（置換え全体の時間）
- 単位をそろえる（ミリ秒＝10⁻³秒、マイクロ秒＝10⁻⁶秒）

### 実記憶の割当て方式

#### 単一連続割当て方式（たんいつれんぞくわりあてほうしき / Single Contiguous Allocation）

- 意味：主記憶のうち、OSが使う部分の残りを、ひとつのプログラムがまとめて全部使う方式
- ポイント：仕組みは最も簡単だが、同時に一つのプログラムしか主記憶に置けず、多重プログラミングができない

#### 固定区画方式（こていくかくほうしき / Fixed Partition）

- 意味：主記憶を、前もって決めた大きさのいくつかの区画に分けておき、一つの区画に一つのプログラムを置く方式
- ポイント：管理は簡単だが、プログラムが区画より小さいと余りが無駄になる（内部断片化）。区画より大きいプログラムは置けない

#### 可変区画方式（かへんくかくほうしき / Variable Partition）

- 意味：プログラムを置くたびに、その大きさに合わせた区画を主記憶から切り出して割り当てる方式
- ポイント：区画の中の余りは出ないが、プログラムが終わって返された領域があちこちに散らばり、細切れの空き（外部断片化）が出る。「空き領域を結合して連続した領域にすること」はコンパクションであり、可変区画方式とは呼ばない
- 例：R3春 問18 ア（空き領域を結合することを可変区画方式と呼ぶ、は誤り）

#### 実アドレス方式（じつあどれすほうしき / Real Addressing）

- 意味：仮想記憶を使わず、プログラムが主記憶の実際の番地（実アドレス）をそのまま使って動く方式
- ポイント：主記憶の大きさを超えるプログラムは、そのままでは動かせない。オーバーレイやスワッピングで工夫する

### 空き領域の選び方

#### ファーストフィット（ふぁーすとふぃっと / First Fit）

- 意味：空き領域を先頭から調べて、要求された大きさを満たす最初の空き領域を割り当てる方式
- ポイント：探す時間が短い。先頭のほうに細かい空きがたまりやすい

#### ベストフィット（べすとふぃっと / Best Fit）

- 意味：要求された大きさを満たす空き領域のうち、最も小さい（ぴったりに近い）空き領域を割り当てる方式
- ポイント：大きな空き領域が残りやすいが、使えないほど小さな余りがたくさんできる。全部の空きを調べるので探す時間がかかる

#### ワーストフィット（わーすとふぃっと / Worst Fit）

- 意味：要求された大きさを満たす空き領域のうち、最も大きい空き領域を割り当てる方式
- ポイント：残る余りが大きいので、次の要求にも使いやすい。そのかわり大きな空き領域がなくなりやすい

#### ネクストフィット（ねくすとふぃっと / Next Fit）

- 意味：前回割り当てた場所の続きから空き領域を調べ、要求を満たす最初の空き領域を割り当てる方式
- ポイント：ファーストフィットの改良版で、先頭に細かい空きが集まるのを避ける

### 断片化と対策

#### フラグメンテーション（ふらぐめんてーしょん / Fragmentation）

- 意味：領域の割当てと返却を繰り返すうちに、空き領域が小さく細切れになり、合計では十分な空きがあるのに、まとまった領域を確保できなくなる現象。断片化とも呼ぶ
- ポイント：区画やページの中の使われない余りを「内部断片化」、区画どうしの間にできる細切れの空きを「外部断片化」と呼ぶ。固定長の領域だけを使えば外部断片化は起きない
- 例：R4春 問18（合計では十分な空きがあっても、必要な領域を獲得できなくなることがある）、R6秋 問18（ページングは外部断片化が発生しない）

#### メモリコンパクション（めもりこんぱくしょん / Memory Compaction）

- 意味：使用中の領域を主記憶の片側に移動して寄せ集め、細切れになった空き領域を一つの連続した大きな領域にまとめること
- ポイント：外部断片化への対策。移動するプログラムは、どこに置いても動けるもの（再配置可能）である必要がある。移動のあいだ処理が止まる
- 例：R3春 問18 ア（空き領域を結合して連続領域にすること）
- 語の意味：Compaction＝詰め込むこと

#### ガーベジコレクション（がーべじこれくしょん / Garbage Collection）

- 意味：プログラムが確保したまま使わなくなったヒープ領域を、システムが自動的に見つけて回収し、再び使えるようにすること
- ポイント：Java などの言語の実行環境が行う。回収のあいだ、プログラムの実行が一時的に止まることがある。メモリリークを減らせる。ページフォールトの処理とは関係ない
- 例：R3春 問18（使わなくなったヒープ領域を回収して再度使用可能にする）、R4春 問18 エ（返却のたびにGCする必要はない）
- 語の意味：Garbage＝ごみ／Collection＝集めること

#### メモリリーク（めもりりーく / Memory Leak）

- 意味：プログラムが確保した領域を、使い終わっても返さないために、使える主記憶が少しずつ減っていく現象
- ポイント：長く動き続けるサーバなどで、だんだん遅くなったり止まったりする原因になる。ガーベジコレクションがない言語（C言語など）で起きやすい
- 語の意味：Leak＝漏れること

### 動的な領域の確保

#### 固定長メモリプール（こていちょうめもりぷーる / Fixed-size Memory Pool）

- 意味：同じ大きさのメモリブロックをあらかじめ用意しておき、要求があったら一つ貸し出して、使い終わったら返してもらう管理方式
- ポイント：大きさが決まっているので、獲得と返却が速く、外部断片化も起きない。要求より大きなブロックを渡すと余りがむだになる。リアルタイムOSでよく使う
- 例：R4春 問18 イ（固定長のほうがフラグメンテーションが発生しやすい、は誤り）、R7秋 問16 エ（メモリプールは排他制御の機能ではない）

#### 可変長メモリプール（かへんちょうめもりぷーる / Variable-size Memory Pool）

- 意味：要求された大きさのメモリブロックを、その都度プールから切り出して貸し出す管理方式
- ポイント：むだな余りは出ないが、獲得と返却を繰り返すとフラグメンテーションが起きる。探す時間もかかる
- 例：R4春 問18 ア（可変長ならフラグメンテーションが発生しない、は誤り）

#### ヒープ領域（ひーぷりょういき / Heap Area）

- 意味：プログラムの実行中に、必要になったときに確保し、要らなくなったら返す領域（動的に確保する領域）
- ポイント：確保と返却の順番が自由なので、断片化しやすい。返し忘れるとメモリリークになる。データ構造の「ヒープ」（#2）とは別の意味

#### スタック領域（すたっくりょういき / Stack Area）

- 意味：関数（手続）を呼び出すたびに、戻り先や局所変数を積み上げ、戻るときに取り除く領域
- ポイント：最後に積んだものから取り除く（後入れ先出し）ので、断片化しない。呼出しが深すぎるとあふれる（スタックオーバーフロー）

### 主記憶との出し入れ

#### スワップアウト（すわっぷあうと / Swap Out）

- 意味：主記憶が足りないときに、実行中でないプログラム（プロセス）を丸ごと補助記憶装置に書き出して、主記憶を空けること
- ポイント：ページ単位で書き出すページアウトと違い、プログラム全体が単位。書き出したものを主記憶へ戻すのがスワップイン
- 例：R3秋 問16 イ・R6秋 問17 イ（ページ置換えの多発で性能が落ちる現象の名前ではない）

#### スワップイン（すわっぷいん / Swap In）

- 意味：スワップアウトで補助記憶装置に書き出しておいたプログラムを、主記憶へ読み戻すこと
- ポイント：スワップアウトとスワップインを合わせてスワッピングと呼ぶ

#### ロールアウト・ロールイン（ろーるあうと・ろーるいん / Roll Out / Roll In）

- 意味：優先度の高いプログラムを動かすために、優先度の低いプログラムを補助記憶装置に退避し（ロールアウト）、終わったら戻す（ロールイン）こと
- ポイント：スワッピングとほぼ同じ意味だが、優先度を理由に入れ替える場面で使う言葉

#### オーバーレイ（おーばーれい / Overlay）

- 意味：プログラムを、同時に必要にならない部分（セグメント）に分けておき、必要な部分だけを順に同じ主記憶の領域へ読み込んで実行する方式
- ポイント：主記憶より大きなプログラムを、仮想記憶なしで動かす昔の工夫。どこで分けるかをプログラマが自分で決める

#### 動的再配置（どうてきさいはいち / Dynamic Relocation）

- 意味：プログラムの実行中に、主記憶上のプログラムの格納位置を移動させること
- ポイント：ベースレジスタなどで番地を相対的に扱えば、移動してもそのまま動ける。「必要になった時点でモジュールをロードすること」は動的リンキング（動的ローディング）の説明
- 例：R3春 問18 ウ・エ（実行中に格納位置を移動させるのが動的再配置。用語の入れ替えに注意）

### 仮想記憶の方式

#### 仮想記憶（かそうきおく / Virtual Memory）

- 意味：補助記憶装置の一部を主記憶の延長のように使い、実際の主記憶より大きなアドレス空間をプログラムに見せる仕組み。ページング方式やセグメント方式で実現する
- ポイント：プログラムのうち、今使う部分だけを主記憶に置き、残りは補助記憶装置に置いておく。補助記憶装置は、主記憶から追い出された（ページアウトされた）ページを格納する
- 例：R3秋 問19（補助記憶はページアウトされたページを格納する）

#### ページング方式（ぺーじんぐほうしき / Paging）

- 意味：仮想アドレス空間と主記憶を、同じ決まった大きさの「ページ」に区切り、ページ単位で主記憶と補助記憶の間を出し入れする仮想記憶の方式
- ポイント：大きさが全部同じなので、主記憶のどの空きページ枠にも置けて、外部断片化が起きない。ページの中の余りは出る
- 例：R6秋 問18（セグメンテーション方式と比べた長所は、外部断片化が発生しないこと）

#### セグメント方式（せぐめんとほうしき / Segmentation）

- 意味：プログラムやデータなどの論理的なまとまり（セグメント）を単位に、大きさの違う領域として管理する仮想記憶の方式。セグメンテーション方式とも呼ぶ
- ポイント：まとまりごとに保護したり、プログラム間で共有したりしやすい。大きさがばらばらなので、外部断片化が起きる
- 例：R6秋 問18 ア・イ・ウ（論理単位の保護・共有・大きさの変更はセグメント方式の長所）

#### セグメントページング方式（せぐめんとぺーじんぐほうしき / Segmented Paging）

- 意味：論理的なまとまりをセグメントに分け、さらに各セグメントをページに区切って管理する方式
- ポイント：セグメントの「保護や共有のしやすさ」と、ページングの「断片化が起きにくい」を両立させる。アドレス変換は2段階になる

### アドレスと空間

#### 仮想アドレス（かそうあどれす / Virtual Address）

- 意味：プログラムが使う、仮想記憶上の番地。論理アドレスとも呼ぶ
- ポイント：実行のたびに、動的アドレス変換で実アドレスに変換されてから主記憶にアクセスする

#### 実アドレス（じつあどれす / Real Address）

- 意味：主記憶の実際の番地。物理アドレスとも呼ぶ
- ポイント：仮想アドレスが同じでも、ページがどのページ枠に置かれたかで実アドレスは変わる

#### 単一仮想空間方式（たんいつかそうくうかんほうしき / Single Virtual Address Space）

- 意味：全てのプログラムが、一つの仮想アドレス空間を分け合って使う方式
- ポイント：プログラムどうしの共有はしやすいが、全体の大きさが一つの空間に限られ、互いの領域を守る仕組みが要る

#### 多重仮想空間方式（たじゅうかそうくうかんほうしき / Multiple Virtual Address Spaces）

- 意味：プログラム（プロセス）ごとに、別々の仮想アドレス空間を与える方式
- ポイント：それぞれが空間全体を使えて、互いに干渉しない。今のOSはこの方式。そのかわりページテーブルもプロセスごとに要る

### アドレス変換の仕組み

#### DAT（だっと / Dynamic Address Translator）

- 意味：プログラムの実行中に、仮想アドレスを実アドレスに変換する仕組み（動的アドレス変換機構）
- ポイント：ページテーブルを引いて変換する。CPUの中のMMU（メモリ管理ユニット）がこの役割を受け持つ
- 語の意味：Dynamic＝動的な／Address＝番地／Translator＝変換するもの

#### ページテーブル（ぺーじてーぶる / Page Table）

- 意味：仮想ページの番号と、そのページが置かれている主記憶のページ枠の番号との対応を記録した表
- ポイント：ページが主記憶にあるかどうかを示すビット（存在ビット）も持つ。インデックス方式なら、主記憶にあるページだけでなく、仮想アドレス空間の全ページ分の項目が要る
- 例：R5春 問18 イ（主記憶に存在する全ページ分のページテーブルが必要、は誤り）

#### TLB（てぃーえるびー / Translation Lookaside Buffer）

- 意味：最近使ったページテーブルの項目（仮想ページと実ページの対応）を一時的に覚えておく、アドレス変換専用の高速なバッファ
- ポイント：TLBにあれば、主記憶上のページテーブルを引かずに変換でき、速くなる。キャッシュメモリのアドレス変換版
- 語の意味：Translation＝変換／Lookaside＝脇に置いて参照する／Buffer＝一時的な置き場

#### ベースアドレス方式（べーすあどれすほうしき / Base Address Method）

- 意味：プログラムの先頭の実アドレスをベースレジスタに入れておき、プログラム中の相対的なアドレスに足して実アドレスを求める方式
- ポイント：ベースレジスタの値を書き換えるだけで、プログラムを主記憶の別の場所へ移せる（再配置）

### ページの出し入れ

#### ページフォールト（ぺーじふぉーると / Page Fault）

- 意味：参照しようとしたページが主記憶になかったときに起きる割込み
- ポイント：起きると、OSがそのページを補助記憶から読み込む（ページイン）。主記憶に空きがなければ、先にどれかのページを追い出す（ページアウト）。だから「ページフォールトの回数＝ページインの回数」
- 例：R3春 問19（ページフォールト＝ページイン≧ページアウト）、R3秋 問17・R5秋 問16（ページフォールトの処理時間の計算）

#### ページイン（ぺーじいん / Page In）

- 意味：必要になったページを、補助記憶装置から主記憶のページ枠に読み込むこと
- ポイント：ページフォールトのたびに必ず1回起きる

#### ページアウト（ぺーじあうと / Page Out）

- 意味：主記憶に空きのページ枠がないときに、どれかのページを選んで補助記憶装置に書き出し、ページ枠を空けること
- ポイント：空きのページ枠があればページアウトは起きないので、回数はページインより多くならない。読み込んでから書き換えていないページは、書き出さずに捨てるだけで済む

#### デマンドページング（でまんどぺーじんぐ / Demand Paging）

- 意味：ページが実際に参照されて、ページフォールトが起きたときに初めて、そのページを読み込む方式
- ポイント：使わないページは読み込まないので主記憶を節約できる。今の仮想記憶の基本の方式
- 語の意味：Demand＝要求

#### プリページング（ぷりぺーじんぐ / Prepaging）

- 意味：これから参照されそうなページを予測して、参照される前にまとめて読み込んでおく方式
- ポイント：予測が当たればページフォールトが減るが、外れると使わないページで主記憶を無駄にする

### ページ置換えのアルゴリズム

#### FIFO（ふぁいふぉ / First In First Out）

- 意味：主記憶にあるページのうち、いちばん先に読み込んだページを追い出す置換え方式
- ポイント：参照されたかどうかは見ない。ページ枠を増やしたのにページフォールトが増えることがある（Belady の異常）
- 例：R5春 問17（FIFOで、参照列 1,4,2,4,1,3 の後のページ枠の状態）、R7秋 問19 ア（ロード時刻が最も古いC0が対象になる）
- 語の意味：First In First Out＝最初に入れたものを最初に出す

#### LIFO（らいふぉ / Last In First Out）

- 意味：主記憶にあるページのうち、いちばん後に読み込んだページを追い出す置換え方式
- ポイント：ページ置換えにはあまり使われないが、試験では「最後に読み込んだもの」を選ぶ誤りの選択肢として出る
- 例：R7秋 問19 ウ（ロード時刻が最も新しいC3が対象になる）
- 語の意味：Last In First Out＝最後に入れたものを最初に出す

#### LRU（えるあーるゆー / Least Recently Used）

- 意味：最後に参照されてから、最も長い時間がたっている（最近いちばん使われていない）ページを追い出す置換え方式
- ポイント：「最近使われていないものは、これからも使われにくい」という考え方。読み込んだ時刻ではなく、最後に使った時刻で選ぶ点がFIFOとの違い
- 例：R5春 問18 ア（使用後の経過時間が最長のページを置換対象とする）、R7春 問15（LRUで最後のページ4が入る番地）、R7秋 問19（最終参照時刻が最も古いC2を置換対象にする）
- 語の意味：Least＝最も少なく／Recently＝最近／Used＝使われた

#### LFU（えるえふゆー / Least Frequently Used）

- 意味：参照された回数が最も少ないページを追い出す置換え方式
- ポイント：回数を数えるので、昔たくさん使われたページがいつまでも残りやすい
- 例：R7秋 問19 イ（参照回数が最も少ないC1が対象になる）
- 語の意味：Least＝最も少なく／Frequently＝頻繁に／Used＝使われた

#### OPT（おぷと / Optimal Page Replacement）

- 意味：これから先、最も長いあいだ参照されないページを追い出す置換え方式（最適置換え）
- ポイント：ページフォールトの回数が理論上最も少なくなるが、未来の参照順は知りようがないので、実際には使えない。ほかの方式の良し悪しを比べる基準に使う
- 語の意味：Optimal＝最適な

### 仮想記憶の性能

#### スラッシング（すらっしんぐ / Thrashing）

- 意味：ページ置換えが頻繁に起こり、ページの出し入ればかりに時間を取られて、システムの処理能力が急激に落ちる現象
- ポイント：多重度を上げすぎたり、主記憶が足りなかったりすると起きる。多重度を下げる、主記憶を増やすなどで防ぐ
- 例：R3秋 問16・R6秋 問17（ページ置換えの発生頻度が高くなり処理能力が急激に低下する現象）
- 語の意味：Thrash＝のたうち回る・激しく打つ

#### ワーキングセット（わーきんぐせっと / Working Set）

- 意味：あるプログラムが、ある期間に参照するページの集まり
- ポイント：ワーキングセットのページが全部主記憶に入っていれば、ページフォールトは少ない。入りきらないとスラッシングが起きやすい。主記憶の割当て量を決める目安になる

#### 参照の局所性（さんしょうのきょくしょせい / Locality of Reference）

- 意味：プログラムは、ある期間には特定の狭い範囲のアドレスを集中して参照する、という性質
- ポイント：一度使った場所はまたすぐ使われやすい（時間的局所性）、近くの場所も使われやすい（空間的局所性）。仮想記憶やキャッシュメモリがうまく働くのは、この性質があるから

#### ページサイズ（ぺーじさいず / Page Size）

- 意味：ページング方式で、1ページの大きさ
- ポイント：小さくすると、ページの中の余り（内部断片化）が減って主記憶を無駄なく使えるが、ページテーブルが大きくなり、ページフォールトの回数は増えやすい。大きくするとその逆
- 例：R4秋 問17（プログラムの大半がページサイズの半分以下なら、ページサイズを半分にするとページ内の無駄な空きが減って主記憶不足が緩和される）

## 5-4 ミドルウェア

### まとめ表

**ソフトウェアの重なり方**

| 層 | 例 | 役割 |
| :-: | :-: | :-: |
| 応用ソフトウェア | 販売管理・会計・Webアプリケーション | 利用者の目的の処理をする |
| ミドルウェア | DBMS・TPモニター・Webサーバ・運用管理ツール | 多くのアプリケーションが共通に使う機能を、OSより使いやすい形で提供する |
| OS | カーネル・デバイスドライバ | ハードウェアと資源を管理する |
| ハードウェア | CPU・主記憶・ディスク | 実際に計算・記憶をする |

**ライブラリのつなぎ方**

| つなぎ方 | いつつなぐか | よいところ | 弱いところ |
| :-: | :-: | :-: | :-: |
| 静的リンク | 実行ファイルを作るとき（リンク時） | 実行ファイルだけで動く | 実行ファイルが大きくなる。ライブラリを直したら作り直しが要る |
| 動的リンク（DLLなど） | 実行するとき | 複数のプログラムで共有でき、ライブラリだけ入れ替えられる | 必要なライブラリがないと動かない。版の違いで動かなくなることがある |

**代表的な開発フレームワーク**

| フレームワーク | 言語 | 押さえどころ |
| :-: | :-: | :-: |
| Apache Struts | Java | MVCモデルの、昔からあるWebアプリケーションの枠組み |
| Spring Framework | Java | DI（依存性の注入）を中心にした、Javaの総合的な枠組み |
| Ruby on Rails | Ruby | 「設定より規約」。決まりごとに従えば少ないコードで作れる |
| CakePHP | PHP | Ruby on Rails の考え方をPHPに取り入れた枠組み |

### ミドルウェアの種類

#### TPモニター（てぃーぴーもにたー / Transaction Processing Monitor）

- 意味：大量のトランザクション（オンラインの取引などの処理の単位）を、効率よく、確実に処理するように制御するミドルウェア
- ポイント：トランザクションの受付・振り分け・同時に動かす数の制御・障害時の回復などを受け持つ。銀行や座席予約などの基幹系システムで使う
- 語の意味：Transaction Processing＝トランザクション処理／Monitor＝監視・制御するもの

#### DBMS（でぃーびーえむえす / Database Management System）

- 意味：データベースを定義・操作・管理し、複数の利用者が同時に正しくデータを使えるようにするミドルウェア（データベース管理システム）
- ポイント：同時実行の制御（排他制御）・障害回復・機密保護などを受け持つ。詳しくは #9 データベース
- 語の意味：Database＝データベース／Management System＝管理システム

#### 運用管理ツール（うんようかんりつーる / Operations Management Tool）

- 意味：サーバやネットワークの稼働状況の監視、ジョブの自動実行、ログの収集などを行い、システムの運用を助けるミドルウェア
- ポイント：多くの機器をまとめて監視し、異常があれば知らせる。OSSでは Zabbix などがある

#### メッセージ指向ミドルウェア（めっせーじしこうみどるうぇあ / Message-Oriented Middleware）

- 意味：アプリケーションどうしが、メッセージを待ち行列（キュー）経由で受け渡して連携できるようにするミドルウェア。MOMとも呼ぶ
- ポイント：送る側と受け取る側が同時に動いていなくてもよい（非同期）。異なるシステムをつなぐアプリケーション連携に使う

### シェル

#### シェル（しぇる / Shell）

- 意味：利用者が入力したコマンドを解釈して、プログラムを起動したり、カーネルの機能を呼び出したりするプログラム。コマンドインタプリタとも呼ぶ（Bシェル・Cシェル・cmd.exe などがある）
- ポイント：カーネルを貝殻（シェル）のように包み、利用者との間を取り持つ。カーネルの一部ではない
- 例：R5秋 問19 ア（シェルはLinuxカーネルに組み込まれているわけではない）
- 語の意味：Shell＝貝殻

#### Bシェル（びーしぇる / Bourne Shell）

- 意味：UNIXの初期から使われてきた標準的なシェル。開発者の名前（Stephen Bourne）から名付けられた。sh とも書く
- ポイント：シェルスクリプトを書くための基本になった。広く使われる bash（Bourne Again Shell）は、Bシェルを拡張したもの

#### Cシェル（しーしぇる / C Shell）

- 意味：C言語に似た書き方ができるシェル。csh とも書く
- ポイント：コマンドの履歴（ヒストリ）や別名（エイリアス）など、対話的に使いやすい機能を早くから取り入れた

#### cmd.exe（こまんどぷろんぷと / Command Prompt）

- 意味：Windowsに標準で入っているシェル（コマンドプロンプト）
- ポイント：MS-DOSのコマンドを受け継いでいる。より高機能な PowerShell も用意されている

#### シェルスクリプト（しぇるすくりぷと / Shell Script）

- 意味：シェルに実行させるコマンドの並びを、ファイルに書いておいたもの
- ポイント：決まった手順の作業を自動化できる。cron と組み合わせて定期的に動かすことが多い

### API

#### API（えーぴーあい / Application Programming Interface）

- 意味：あるソフトウェアの機能を、別のプログラムから呼び出して使うための約束ごと（関数の名前・引数・戻り値など）。ネットワーク越しに呼ぶものは特に Web API と呼ぶ
- ポイント：中の作りを知らなくても、決められた呼び方をすれば機能を使える。OSのAPIはシステムコールを包んだ関数として提供されることが多い
- 語の意味：Application＝アプリケーション／Programming＝プログラミング／Interface＝接点

#### Web API（うぇぶえーぴーあい / Web API）

- 意味：HTTPなどのWebの仕組みを使って、ネットワーク越しに機能を呼び出せるようにしたAPI
- ポイント：結果は JSON や XML で返すことが多い。地図や決済などの外部サービスを、自分のシステムに組み込むときに使う

#### REST（れすと / Representational State Transfer）

- 意味：Web API の設計の考え方の一つ。データを URL で表される「リソース」とみなし、HTTPのメソッド（GET・POST・PUT・DELETE）で操作する
- ポイント：サーバは状態（セッション）を持たない（ステートレス）のが原則。この考え方に沿ったAPIを RESTful API と呼ぶ
- 語の意味：Representational＝表現の／State＝状態／Transfer＝転送

#### OpenAPI Specification（おーぷんえーぴーあいすぺしふぃけーしょん / OpenAPI Specification）

- 意味：REST の Web API の仕様（どのURLに、どんな入力を送ると、何が返るか）を、YAML や JSON で書くための標準の書式
- ポイント：仕様を機械が読める形で書いておくと、文書やプログラムの雛形を自動で作れる。もとは Swagger という名前の仕様だった
- 例：R7春 問17（OpenAPI Specificationに従ったAPIの定義・開発を支援するOSS）
- 語の意味：Specification＝仕様

#### ABI（えーびーあい / Application Binary Interface）

- 意味：コンパイル済みのプログラム（機械語）と、OSやライブラリとの間の約束ごと。関数の呼び出し方、データの並べ方、システムコールの番号などを決める
- ポイント：APIは「ソースコードの書き方」の約束、ABIは「できあがった実行ファイル」の約束。ABIが同じなら、作り直さずにそのまま動く（バイナリ互換）
- 語の意味：Application＝アプリケーション／Binary＝2進の（機械語の）／Interface＝接点

### ライブラリ

#### ソースライブラリ（そーすらいぶらり / Source Library）

- 意味：ソースプログラム（原始プログラム）や、共通に使うデータ構造の定義などを、ソースのまま集めて格納したライブラリ
- ポイント：コンパイルの前に取り込んで使う（C言語のヘッダファイルなど）

#### オブジェクトライブラリ（おぶじぇくとらいぶらり / Object Library）

- 意味：コンパイル済みの目的プログラム（オブジェクトモジュール）を集めて格納したライブラリ
- ポイント：リンカがここから必要なモジュールを取り出して、ロードモジュールを作る

#### ロードライブラリ（ろーどらいぶらり / Load Library）

- 意味：リンクが済んで、すぐに主記憶に読み込んで実行できるロードモジュールを格納したライブラリ
- ポイント：ローダは、ここからプログラムを読み込んで実行させる

#### DLL（でぃーえるえる / Dynamic Link Library）

- 意味：プログラムの実行時に読み込まれて結び付けられる（動的リンクされる）ライブラリ。Windowsでの呼び名で、UNIX系では共有ライブラリと呼ぶ
- ポイント：複数のプログラムで共有できて主記憶の節約になり、DLLだけ入れ替えて直せる。DLLの版が合わないと、プログラムが動かなくなることがある
- 語の意味：Dynamic＝動的な／Link＝結び付け／Library＝ライブラリ

#### クラスライブラリ（くらすらいぶらり / Class Library）

- 意味：オブジェクト指向のプログラムで、再利用できるクラスを集めたライブラリ
- ポイント：継承して自分用に作り替えたり、そのまま部品として使ったりできる。呼び出す順番まで決めているのが開発フレームワーク

#### 開発フレームワーク（かいはつふれーむわーく / Development Framework）

- 意味：アプリケーションの標準的な構造（骨組み）と、よく使う機能を、クラスやライブラリの集まりとして提供するもの
- ポイント：ライブラリは「自分のプログラムが呼び出すもの」、フレームワークは「フレームワークが自分のプログラムを呼び出す」（制御の反転）。Webアプリケーションの多くは MVC の考え方で作られている

### コンポーネントウェア

#### コンポーネント（こんぽーねんと / Component）

- 意味：決められたインタフェースを通じて使う、独立して入れ替えられるソフトウェアの部品
- ポイント：部品を組み合わせてソフトウェアを作る開発手法を、コンポーネントウェアと呼ぶ。中の作りを知らずに、インタフェースだけで組み合わせられる

#### JavaBeans（じゃゔぁびーんず / JavaBeans）

- 意味：Java で、再利用できる部品（コンポーネント）を作るための決まりごと
- ポイント：プロパティを get・set で始まるメソッドで読み書きできるようにするなど、作り方の約束が決められている

#### CORBA（こーば / Common Object Request Broker Architecture）

- 意味：ネットワーク上のさまざまな言語や機種で作られたオブジェクトどうしが、互いにメソッドを呼び出せるようにするための標準の仕様。OMG が定めた
- ポイント：仲立ちをするORB（Object Request Broker）が、呼出しを相手に届ける。言語やOSの違いを越えた分散オブジェクトの仕組み
- 語の意味：Common＝共通の／Object Request Broker＝オブジェクトへの要求の仲介者／Architecture＝構成

#### OSGi（おーえすじーあい / OSGi）

- 意味：Java で、ソフトウェアを「バンドル」という部品に分け、動かしたまま部品の追加・更新・削除ができるようにする仕様
- ポイント：システムを止めずに機能を入れ替えられる。統合開発環境の Eclipse もこの仕組みで作られている

### 開発フレームワーク

#### Apache Struts（あぱっちすとらっつ / Apache Struts）

- 意味：Java で Web アプリケーションを作るための、MVCモデルに基づく開発フレームワーク
- ポイント：古くから広く使われてきたが、重大な脆弱性が見つかったことがある。開発は終わりに向かっている

#### Spring Framework（すぷりんぐふれーむわーく / Spring Framework）

- 意味：Java でアプリケーションを作るための総合的な開発フレームワーク
- ポイント：DI（依存性の注入）で部品どうしのつながりを緩くし、テストしやすくするのが特徴。Webアプリケーション向けの Spring MVC などを含む

#### Ruby on Rails（るびーおんれいるず / Ruby on Rails）

- 意味：プログラム言語 Ruby で Web アプリケーションを作るための開発フレームワーク
- ポイント：「設定より規約（決まりに従えば設定を書かなくてよい）」と「同じことを繰り返さない（DRY）」を大事にし、少ないコードで素早く作れる

#### CakePHP（けーくぴーえいちぴー / CakePHP）

- 意味：プログラム言語 PHP で Web アプリケーションを作るための開発フレームワーク
- ポイント：Ruby on Rails の考え方（MVC・設定より規約）を PHP に取り入れたもの

## 5-5 ファイルシステム

### まとめ表

**バックアップの方式と復元のしかた**

| 方式 | 毎回取るもの | バックアップの時間 | 復元に使うもの |
| :-: | :-: | :-: | :-: |
| フルバックアップ | 全部のデータ | 長い | 最新のフルバックアップだけ |
| 差分バックアップ | 前回の「フル」から変わった全部 | 日がたつほど長くなる | 最新のフル＋最新の差分1つ |
| 増分バックアップ | 前回の「バックアップ（フルでも増分でも）」から変わった分 | 短い | 最新のフル＋その後の増分を全部、古い順に |

**パスの書き方（ルートの下に /home/sato/doc/a.txt があり、今いるのが /home/sato のとき）**

| 書き方 | 例 | 起点 |
| :-: | :-: | :-: |
| 絶対パス | /home/sato/doc/a.txt | ルートディレクトリ |
| 相対パス | doc/a.txt または ./doc/a.txt | カレントディレクトリ |
| 一つ上をたどる相対パス | ../tanaka/b.txt（/home/tanaka/b.txt） | 「..」は親ディレクトリ、「.」は今のディレクトリ |

**ファイル編成**

| 編成 | レコードの並べ方 | 得意なアクセス |
| :-: | :-: | :-: |
| 順編成 | 書いた順に並べる | 先頭から順に読む（順次アクセス） |
| 直接編成 | キーから計算した場所（ハッシュ）に置く | キーで1件を直接読む |
| 索引順編成 | キーの順に並べ、索引をつける | 順次でも、索引を使った直接でも読める |
| 区分編成 | ファイルをメンバーに分け、メンバーの一覧（登録簿）をつける | プログラムのライブラリの格納 |

### 基準になるディレクトリ

#### ルートディレクトリ（るーとでぃれくとり / Root Directory）

- 意味：階層型のディレクトリ構造で、いちばん上にあるディレクトリ。UNIX系では「/」で表す
- ポイント：絶対パスは、ここを起点に書く

#### カレントディレクトリ（かれんとでぃれくとり / Current Directory）

- 意味：利用者やプログラムが、今作業の対象にしているディレクトリ。作業ディレクトリとも呼ぶ
- ポイント：相対パスは、ここを起点に書く。cd コマンドで移動すると変わる

#### ホームディレクトリ（ほーむでぃれくとり / Home Directory）

- 意味：利用者ごとに用意された、その人専用のディレクトリ。ログインした直後のカレントディレクトリになる
- ポイント：UNIX系では「~」で表せる。自分の設定ファイルや作業ファイルを置く

#### 親ディレクトリ（おやでぃれくとり / Parent Directory）

- 意味：あるディレクトリの、一つ上の階層にあるディレクトリ
- ポイント：相対パスでは「..」で表す（今のディレクトリは「.」）

### パスの書き方

#### パス名（ぱすめい / Path Name）

- 意味：階層型のディレクトリの中で、目的のファイルまでの道筋を、ディレクトリ名を区切り文字でつないで表したもの
- ポイント：区切り文字は UNIX系では「/」、Windowsでは「\」。絶対パスと相対パスの2通りの書き方がある

#### 絶対パス（ぜったいぱす / Absolute Path）

- 意味：ルートディレクトリを起点にして、目的のファイルまでの道筋を全部書いたパス
- ポイント：今どのディレクトリにいても、同じファイルを指す。UNIX系では「/」で始まる

#### 相対パス（そうたいぱす / Relative Path）

- 意味：カレントディレクトリを起点にして、目的のファイルまでの道筋を書いたパス
- ポイント：カレントディレクトリが変わると、同じ書き方でも指すファイルが変わる。「..」で一つ上に上がれる

#### ワイルドカード（わいるどかーど / Wildcard）

- 意味：ファイル名を指定するときに、任意の文字の代わりに使える記号。「*」は0文字以上の任意の文字列、「?」は任意の1文字
- ポイント：「*.txt」で、拡張子が txt のファイルを全部まとめて指定できる

### ディレクトリの形

#### 単一ディレクトリ（たんいつでぃれくとり / Single-level Directory）

- 意味：全てのファイルを、一つのディレクトリにまとめて置く構造
- ポイント：簡単だが、ファイル名が全部の中で重ならないようにする必要がある。利用者が増えると管理しきれない

#### 2階層ディレクトリ（にかいそうでぃれくとり / Two-level Directory）

- 意味：最上位の下に、利用者ごとのディレクトリを一段だけ作る構造
- ポイント：利用者が違えば同じファイル名を使えるが、自分のファイルをさらに分類することはできない

#### 階層型ディレクトリ（かいそうがたでぃれくとり / Hierarchical Directory）

- 意味：ディレクトリの中に、さらにディレクトリを何段でも作れる構造。木構造ディレクトリとも呼ぶ
- ポイント：今のOSのほとんどがこの形。ファイルはパス名で特定する

#### 共有ファイル（きょうゆうふぁいる / Shared File）

- 意味：複数の利用者やプログラムから、同時に、または交互に使えるようにしたファイル
- ポイント：同時に書き込むと内容が壊れるので、ファイルや範囲をロックして排他制御する。アクセス権で使える人を限る

### 別名で指す仕組み

#### シンボリックリンク（しんぼりっくりんく / Symbolic Link）

- 意味：別のファイルやディレクトリのパス名を中身として持ち、そこへの案内役になる特別なファイル
- ポイント：元のファイルを消したり移したりすると、たどれなくなる（リンク切れ）。別のファイルシステム上のファイルやディレクトリも指せる

#### ハードリンク（はーどりんく / Hard Link）

- 意味：ファイルの実体（UNIX系では i ノード）に、もう一つ別の名前をつけること
- ポイント：どちらの名前も対等で、片方を消しても、もう片方からは使える（全部の名前が消えたときに実体が消える）。同じファイルシステムの中のファイルにしか作れない

#### ショートカット（しょーとかっと / Shortcut）

- 意味：Windowsで、別の場所にあるファイルやフォルダ、プログラムを開くための案内役のファイル
- ポイント：ショートカットを消しても元のファイルは消えない。シンボリックリンクに似ているが、Windowsの画面（エクスプローラー）の機能として扱われる

#### エイリアス（えいりあす / Alias）

- 意味：macOSで、ほかのファイルやフォルダを指す案内役のファイル。一般には「別名」の意味
- ポイント：元のファイルを同じディスクの中で移動しても、たどることができる

### ファイルを扱う手がかり

#### ファイル記述子（ふぁいるきじゅつし / File Descriptor）

- 意味：UNIX系で、プログラムが開いたファイルを識別するためにOSが渡す小さな整数
- ポイント：標準入力は0、標準出力は1、標準エラー出力は2。以後の読み書きは、ファイル名ではなくこの番号で行う

#### ファイルハンドル（ふぁいるはんどる / File Handle）

- 意味：プログラムが開いたファイルを、以後の操作で指定するためにOSから受け取る識別子。Windowsなどでの呼び名
- ポイント：ファイル記述子と同じ役割。中身はOSが管理していて、プログラムは「取っ手（ハンドル）」として持つだけ

#### ファイルポインタ（ふぁいるぽいんた / File Pointer）

- 意味：開いたファイルの中で、次に読み書きする位置を示すもの
- ポイント：読み書きするたびに後ろへ進む。位置を動かせば、ファイルの途中から読み書きできる

#### ファイル制御ブロック（ふぁいるせいぎょぶろっく / File Control Block）

- 意味：開いているファイルについて、OSが管理する情報（ファイルの場所・大きさ・アクセス権・今の位置など）をまとめた領域。FCBとも呼ぶ
- ポイント：ファイルを開くとOSが作り、閉じると消す。プログラムは記述子やハンドルを通して間接的に使う

### デバイスとファイル

#### キャラクターデバイス（きゃらくたーでばいす / Character Device）

- 意味：データを1文字（1バイト）ずつ、順に読み書きする装置。キーボードや端末、シリアルポートなど
- ポイント：好きな位置へ飛んで読むことはできない。UNIX系では、装置もファイルとして扱う

#### ブロックデバイス（ぶろっくでばいす / Block Device）

- 意味：決まった大きさのブロック単位でデータを読み書きし、どの位置のブロックにも直接アクセスできる装置。磁気ディスクやSSDなど
- ポイント：ファイルシステムを作れるのはこちらの装置

#### デバイスファイル（でばいすふぁいる / Device File）

- 意味：UNIX系で、入出力装置をファイルとして扱うための特別なファイル。/dev の下に置かれる。スペシャルファイルとも呼ぶ
- ポイント：ふつうのファイルと同じ読み書きの命令で、装置を操作できる

#### マウント（まうんと / Mount）

- 意味：ディスクやUSBメモリなどにあるファイルシステムを、今のディレクトリの木構造の一部（マウントポイント）につないで、使えるようにすること
- ポイント：外すことをアンマウントと呼ぶ。書込み中に抜くとデータが壊れることがある

### ディスクの使い方

#### ボリューム（ぼりゅーむ / Volume）

- 意味：OSが一つのまとまりとして扱う記憶領域。ファイルシステムを作る単位
- ポイント：1台のディスクを複数のボリュームに分けることも、複数のディスクを一つのボリュームにまとめることもできる

#### パーティション（ぱーてぃしょん / Partition）

- 意味：1台の物理的なディスクを、論理的にいくつかに区切った領域
- ポイント：区切った領域ごとに、別のファイルシステムや別のOSを入れられる（マルチブートに使う）

#### クラスタ（くらすた / Cluster）

- 意味：ファイルシステムが、ファイルに領域を割り当てるときの最小の単位（複数のセクタをまとめたもの）
- ポイント：1バイトのファイルでも1クラスタを使う。クラスタを大きくすると、小さなファイルが多いときに無駄が増える

#### ジャーナリング（じゃーなりんぐ / Journaling）

- 意味：ファイルシステムの更新内容を、実際に書き込む前に記録（ジャーナル）しておき、途中で電源が切れても、記録を使ってすぐに整合性を取り戻せるようにする仕組み
- ポイント：起動時に全部を検査し直さなくて済む。NTFS・ext4 などが備えている。データを守る仕組みであって、書込みの場所をならすウェアレベリングとは別
- 語の意味：Journal＝日誌

### ファイルシステムの種類

#### FAT（ふぁっと / File Allocation Table）

- 意味：ファイルがディスクのどのクラスタに入っているかを、表（FAT）で管理するファイルシステム
- ポイント：仕組みが簡単で、多くのOSや機器で読み書きできるので、USBメモリやSDカードでよく使う。アクセス権の管理やジャーナリングはない。FAT32 では1ファイル4Gバイト未満の制限がある
- 語の意味：File＝ファイル／Allocation＝割当て／Table＝表

#### NTFS（えぬてぃーえふえす / NT File System）

- 意味：Windowsの標準のファイルシステム
- ポイント：ファイルごとのアクセス権の設定、ジャーナリング、暗号化、圧縮などの機能を持つ。FATより大きなファイルやボリュームを扱える

#### ReFS（れふす / Resilient File System）

- 意味：Windows Server 向けに作られた、データの壊れにくさ（回復力）を重視したファイルシステム
- ポイント：データの誤りを自動で検出・修復する機能を持ち、大容量のストレージに向く。NTFSの後継の位置づけだが、全ての機能を置き換えてはいない
- 語の意味：Resilient＝回復力のある

#### ext4（いーえっくすてぃーふぉー / Fourth Extended File System）

- 意味：Linuxで広く使われる標準のファイルシステム
- ポイント：ext3 の後継で、ジャーナリングを持ち、大きなファイルやボリュームを扱える

### ネットワークでのファイル共有

#### NFS（えぬえふえす / Network File System）

- 意味：ネットワーク上の別のコンピュータにあるファイルを、自分のコンピュータのファイルと同じように使えるようにする仕組み。主に UNIX系で使う
- ポイント：サーバのディレクトリを、クライアントのディレクトリにマウントして使う。NASが提供するプロトコルの一つ
- 語の意味：Network＝ネットワーク／File System＝ファイルシステム

#### SMB（えすえむびー / Server Message Block）

- 意味：Windowsで、ネットワーク上のファイルやプリンタを共有するためのプロトコル。古い版の仕様は CIFS とも呼ばれた
- ポイント：Windowsの「共有フォルダ」はこれで動いている。UNIX系でも Samba を使えば SMB で共有できる。古い版（SMBv1）には脆弱性があり、使わないようにする
- 語の意味：Server＝サーバ／Message＝メッセージ／Block＝かたまり

#### CIFS（しふす / Common Internet File System）

- 意味：SMB の古い版を、インターネットでも使えるよう公開した仕様の名前
- ポイント：今は SMB と同じ意味で使われることが多い。NFS と並んで NAS のプロトコルとして出てくる
- 語の意味：Common＝共通の／Internet＝インターネット／File System＝ファイルシステム

#### WebDAV（うぇぶだぶ / Web-based Distributed Authoring and Versioning）

- 意味：HTTPを拡張して、Webサーバ上のファイルを、ネットワーク越しに作成・更新・削除できるようにしたプロトコル
- ポイント：HTTP（HTTPS）を使うので、ファイアウォールを通りやすい
- 語の意味：Web-based＝Webを使った／Distributed＝分散した／Authoring＝作成／Versioning＝版の管理

### レコードとブロック

#### 論理レコード（ろんりれこーど / Logical Record）

- 意味：プログラムから見た、データの読み書きの単位（社員1人分のデータなど）
- ポイント：装置に実際に読み書きする単位は物理レコード（ブロック）。論理レコードを何件かまとめて1ブロックにする

#### 物理レコード（ぶつりれこーど / Physical Record）

- 意味：補助記憶装置に、実際に1回で読み書きするデータの単位。ブロックとも呼ぶ
- ポイント：ブロックの間には、データのないすき間（ブロック間ギャップ）ができる

#### ブロッキング（ぶろっきんぐ / Blocking）

- 意味：複数の論理レコードを、一つのブロック（物理レコード）にまとめること。まとめた件数をブロッキング因数と呼ぶ
- ポイント：入出力の回数とすき間が減るので、速く、記憶容量も無駄なく使える。そのかわりバッファが大きくなる

#### デブロッキング（でぶろっきんぐ / Deblocking）

- 意味：読み込んだブロックから、論理レコードを1件ずつ取り出すこと
- ポイント：ブロッキングの逆の操作。IOCSなどOSが行うので、プログラムは論理レコードの単位で読める

### ファイル編成

#### 順編成（じゅんへんせい / Sequential Organization）

- 意味：レコードを書き込んだ順に、先頭から並べて格納するファイル編成
- ポイント：先頭から順に読む処理（順次アクセス）は速いが、途中の1件だけを読むのは遅い。磁気テープでも使える

#### 直接編成（ちょくせつへんせい / Direct Organization）

- 意味：レコードのキーから計算（ハッシュ関数など）で格納場所を決めて、そこに格納するファイル編成
- ポイント：キーから場所を直接求めるので、1件を読むのが速い。別のキーが同じ場所になる（シノニム）と、あふれた分を別の場所に置く

#### 索引順編成（さくいんじゅんへんせい / Indexed Sequential Organization）

- 意味：レコードをキーの順に並べて格納し、さらにキーと格納場所の対応を示す索引（インデックス）をつけたファイル編成
- ポイント：順次にも、索引を使って直接にも読める。追加したレコードは「あふれ域」に置かれ、増えると遅くなるので、ときどき整理し直す

#### 区分編成（くぶんへんせい / Partitioned Organization）

- 意味：ファイルを「メンバー」という順編成の区分に分け、メンバー名と格納場所の一覧（登録簿）をつけたファイル編成
- ポイント：プログラムのライブラリの格納によく使う。メンバー名で目的のメンバーを探して読む

### アクセスと検索

#### 順次アクセス（じゅんじあくせす / Sequential Access）

- 意味：ファイルのレコードを、先頭から順番に読み書きするアクセス方法
- ポイント：全件を処理するバッチ処理に向く

#### 直接アクセス（ちょくせつあくせす / Direct Access）

- 意味：目的のレコードの場所を指定して、そのレコードだけを読み書きするアクセス方法。ランダムアクセスとも呼ぶ
- ポイント：1件ずつ問い合わせるオンライン処理に向く

#### 動的アクセス（どうてきあくせす / Dynamic Access）

- 意味：一つのプログラムの中で、順次アクセスと直接アクセスを切り替えながら使うアクセス方法
- ポイント：索引順編成のように、両方に対応したファイル編成で使える

#### ハッシング（はっしんぐ / Hashing）

- 意味：キーをハッシュ関数で計算して、データの格納場所（アドレス）を直接求める検索の方法
- ポイント：データの件数が増えても、1件を探す時間がほぼ変わらない。違うキーが同じ場所になる衝突（シノニム）への対策が要る

#### インデックス（いんでっくす / Index）

- 意味：キーと、そのデータの格納場所との対応をまとめた表（索引）
- ポイント：本の索引と同じ考え方。全部を順に調べなくても、索引から場所がわかる。データを更新すると索引も直す必要がある

### バックアップの方式

#### フルバックアップ（ふるばっくあっぷ / Full Backup）

- 意味：対象のデータを、毎回全部バックアップする方式
- ポイント：取るのに時間がかかるが、復元は最新のフルバックアップ1つだけで済む

#### 差分バックアップ（さぶんばっくあっぷ / Differential Backup）

- 意味：最後のフルバックアップから後に変わったデータを、全部バックアップする方式
- ポイント：日がたつほど取る量が増える。復元は「最新のフル＋最新の差分」の2つで済む

#### 増分バックアップ（ぞうぶんばっくあっぷ / Incremental Backup）

- 意味：前回のバックアップ（フルでも増分でも）から後に変わったデータだけを、バックアップする方式
- ポイント：毎回の量が最も少なく速い。復元は「最新のフル＋その後の増分全部」を古い順に当てるので、手間と時間がかかる

#### 世代管理（せだいかんり / Generation Management）

- 意味：バックアップを、取った日ごとに複数世代残しておき、決めた数を超えたら古いものから消していく管理のしかた
- ポイント：最新のバックアップが壊れていても、一つ前の世代から戻せる。マルウェアに気づくのが遅れたときにも役立つ

#### 多重バックアップ（たじゅうばっくあっぷ / Multiple Backup）

- 意味：同じデータのバックアップを、複数の媒体や場所に重ねて保管しておくこと
- ポイント：一つの媒体が壊れたり、災害で一か所が失われたりしても戻せる。例えば「3つのコピー・2種類の媒体・1つは別の場所」（3-2-1ルール）

## 5-6 開発ツール

### まとめ表

**ソースから実行までの流れ**

| 段階 | 道具 | できあがるもの |
| :-: | :-: | :-: |
| 1. 書く | エディタ・IDE | 原始プログラム（ソースプログラム） |
| 2. 下ごしらえ | プリプロセッサ | マクロや取り込みを展開したソース |
| 3. 翻訳 | コンパイラ・アセンブラ | 目的プログラム（オブジェクトモジュール） |
| 4. 結合 | リンカ（リンケージエディタ） | ロードモジュール（実行形式） |
| 5. 読み込み | ローダ | 主記憶上で実行できる状態 |

**コンパイラの処理の順番（R6秋 問20 の論点）**

| 順 | 処理 | すること |
| :-: | :-: | :-: |
| 1 | 字句解析 | 文字の並びを、名前・数値・記号などの字句（トークン）に切り分ける |
| 2 | 構文解析 | 字句の並びが文法に合っているかを調べ、構文木を作る |
| 3 | 意味解析 | 型が合っているか、宣言されているかなど、意味の正しさを調べる |
| 4 | 最適化 | 結果を変えずに、速く・小さく動くようにプログラムを作り替える |
| 5 | コード生成 | 目的のコンピュータの機械語（目的プログラム）を作る |

**プログラムの実行のしかた**

| 道具 | 翻訳する時期 | 押さえどころ |
| :-: | :-: | :-: |
| コンパイラ | 実行の前に全部 | 実行が速い |
| インタプリタ | 実行しながら1文ずつ | すぐ試せるが、実行は遅い |
| 実行時コンパイラ（JIT） | 実行中に、よく使う部分をまとめて | 中間コードを、実行中に機械語に直して速くする |
| クロスコンパイラ | 実行の前に全部 | 開発に使うコンピュータとは別の種類のコンピュータ用の機械語を作る |

**テストとデバッグのツール**

| 分け方 | ツール |
| :-: | :-: |
| 動かさずに調べる（静的） | 静的解析ツール・プリティプリンタ・クロスリファレンス |
| 動かして調べる（動的） | デバッガ・トレーサ・インスペクタ・スナップショット・プロファイラ・アサーションチェッカ |
| テストを助ける | テストデータ生成ツール・テストカバレージツール・テストベッドツール |
| 別の環境をまねる | エミュレーター・シミュレーター・ICE |

### 言語プロセッサの種類

#### アセンブラ（あせんぶら / Assembler）

- 意味：機械語の命令と1対1に対応する記号（ニーモニック）で書いたアセンブリ言語のプログラムを、機械語に翻訳するプログラム
- ポイント：ハードウェアを細かく制御できるが、CPUの種類ごとに書き方が違う

#### コンパイラ（こんぱいら / Compiler）

- 意味：高水準言語で書かれた原始プログラムを、実行の前にまとめて目的プログラム（機械語など）に翻訳するプログラム。クロスコンパイラ・最適化コンパイラ・実行時コンパイラは、その特別な形
- ポイント：翻訳を先に済ませるので、実行は速い。字句解析→構文解析→意味解析→最適化→コード生成の順に処理する
- 例：R6秋 問20（コード生成までに行う処理のうち、最後に行うのは最適化）

#### インタプリタ（いんたぷりた / Interpreter）

- 意味：原始プログラムを1文ずつ解釈しながら、そのつど実行するプログラム
- ポイント：目的プログラムを作らない。書いてすぐ試せるが、繰り返しのたびに解釈し直すので実行は遅い
- 語の意味：Interpreter＝通訳者

#### 実行時コンパイラ（じっこうじこんぱいら / Just-In-Time Compiler）

- 意味：プログラムの実行中に、中間コード（バイトコード）のよく使われる部分を、その場で機械語に翻訳して実行を速くするコンパイラ。JITコンパイラとも呼ぶ
- ポイント：Java の実行環境（JVM）や JavaScript のエンジンが使う。インタプリタの手軽さとコンパイラの速さを両立させる
- 語の意味：Just In Time＝ちょうどよいときに

#### クロスコンパイラ（くろすこんぱいら / Cross Compiler）

- 意味：あるコンピュータの上で、それとは命令形式が異なる別のコンピュータで実行できる目的プログラムを作るコンパイラ
- ポイント：資源の少ない組込み機器のプログラムを、パソコンで作るときに使う。作るのは「目的プログラム」で、動きをまねるエミュレーターとは違う
- 例：R5秋 問18（異なる命令形式のコンピュータで実行できる目的プログラムを生成する）
- 語の意味：Cross＝またがる

### コードを生成・変換するツール

#### プリプロセッサ（ぷりぷろせっさ / Preprocessor）

- 意味：コンパイルの前に、原始プログラムの中のマクロの展開や、別ファイルの取り込みなどの下ごしらえをするプログラム
- ポイント：C言語の #include や #define を処理するのがこれ。プリ（前の）＋プロセッサ（処理するもの）

#### プログラムジェネレーター（ぷろぐらむじぇねれーたー / Program Generator）

- 意味：入力・処理・出力の条件などを指定すると、それに合ったプログラムを自動的に作り出すツール
- ポイント：決まった形のプログラム（帳票の出力など）を、手で書かずに素早く作れる。別の機種用に翻訳するものではない
- 例：R5秋 問18 エ（異なる命令形式のコンピュータ用の目的プログラムを作るものではない）

#### 最適化コンパイラ（さいてきかこんぱいら / Optimizing Compiler）

- 意味：結果を変えずに、実行が速く、または目的プログラムが小さくなるようにプログラムを作り替えて翻訳するコンパイラ
- ポイント：ループの外へ計算を出す、使われない計算を省く、などを行う。最適化を強くすると、ソースと機械語の対応がわかりにくくなり、デバッグしにくくなる
- 例：R5秋 問18 ウ（別の命令形式のコンピュータ用に作るのはクロスコンパイラ）

#### トランスパイラ（とらんすぱいら / Transpiler）

- 意味：ある高水準言語で書いたソースプログラムを、別の高水準言語のソースプログラムに変換するツール
- ポイント：TypeScript を JavaScript に変換するのが代表。機械語ではなく、別の言語のソースを作る点がコンパイラとの違い

### コンパイラの処理段階

#### 字句解析（じくかいせき / Lexical Analysis）

- 意味：原始プログラムの文字の並びを、名前・予約語・数値・演算子などの字句（トークン）に切り分ける処理
- ポイント：コンパイラが最初に行う処理。空白やコメントもここで取り除く
- 例：R6秋 問20 エ（最初の処理であり、最後ではない）

#### 構文解析（こうぶんかいせき / Syntax Analysis）

- 意味：字句の並びが、プログラム言語の文法に合っているかを調べ、文の構造を表す構文木（解析木）を作る処理
- ポイント：かっこの対応の誤りや、文の形の誤りは、ここで見つかる
- 例：R6秋 問20 イ

#### 意味解析（いみかいせき / Semantic Analysis）

- 意味：構文木をもとに、変数が宣言されているか、型が合っているかなど、意味の上での正しさを調べる処理
- ポイント：文法としては正しいが「数値と文字列を足している」ような誤りは、ここで見つかる
- 例：R6秋 問20 ア

#### 最適化（さいてきか / Optimization）

- 意味：実行結果を変えずに、実行時間や記憶容量が少なくなるように、プログラムを作り替える処理
- ポイント：コード生成の直前（またはコード生成と組み合わせて）に行う。同じ計算をまとめる、使われない処理を消す、などがある
- 例：R6秋 問20（コード生成までに行う処理のうち、最後に行うもの）

#### コード生成（こーどせいせい / Code Generation）

- 意味：解析と最適化が済んだプログラムをもとに、目的のコンピュータの機械語（目的プログラム）を作り出す処理
- ポイント：コンパイラの処理の最後の段階。レジスタの割当てなど、CPUごとの違いはここで扱う

### プログラムの形

#### 原始プログラム（げんしぷろぐらむ / Source Program）

- 意味：人がプログラム言語で書いた、翻訳する前のプログラム。ソースプログラム、ソースコードとも呼ぶ
- ポイント：人が読んで直すためのもの。そのままではCPUは実行できない

#### 目的プログラム（もくてきぷろぐらむ / Object Program）

- 意味：コンパイラやアセンブラが原始プログラムを翻訳して作った、機械語などのプログラム。オブジェクトモジュールとも呼ぶ
- ポイント：ほかのモジュールやライブラリとリンクする前なので、まだそのままでは実行できないことが多い

#### ロードモジュール（ろーどもじゅーる / Load Module）

- 意味：目的プログラムとライブラリなどをリンカで結合して作った、主記憶に読み込めばすぐ実行できる形のプログラム。実行形式とも呼ぶ
- ポイント：Windowsの .exe ファイルなどがこれ。ローダが主記憶に読み込んで実行させる

#### 中間コード（ちゅうかんこーど / Intermediate Code）

- 意味：原始プログラムと機械語の中間の形で、特定のCPUに依存しないように作ったコード。Java のバイトコードなど
- ポイント：仮想マシン（JVMなど）があれば、CPUやOSが違っても同じ中間コードを実行できる。インタプリタや実行時コンパイラで実行する

### リンクとロード

#### リンカ（りんか / Linker）

- 意味：複数の目的プログラムやライブラリを結合し、互いの呼出しの番地を決めて、一つのロードモジュールを作るプログラム。リンケージエディタ、連係編集プログラムとも呼ぶ
- ポイント：別々にコンパイルしたモジュールの間の参照（外部参照）を解決する

#### ローダ（ろーだ / Loader）

- 意味：ロードモジュールを補助記憶装置から主記憶に読み込み、実行できる状態にするプログラム
- ポイント：読み込む場所に合わせて番地を直す（再配置する）こともある。リンカは「結合して作る」、ローダは「読み込む」

#### 静的リンキング（せいてきりんきんぐ / Static Linking）

- 意味：実行ファイルを作るときに、必要なライブラリのモジュールを全部組み込んで結合しておく方法
- ポイント：実行ファイルだけで動くが、ファイルが大きくなる。ライブラリを直したら、作り直しが要る

#### 動的リンキング（どうてきりんきんぐ / Dynamic Linking）

- 意味：プログラムの実行時（または必要になった時点）に、ライブラリのモジュールを読み込んで結び付ける方法
- ポイント：複数のプログラムでライブラリを共有でき、主記憶を節約できる。WindowsのDLLが代表。実行中に格納位置を動かす「動的再配置」とは別もの
- 例：R3春 問18 ウ・エ（必要になった時点でモジュールをロードするのは動的リンキングの考え方）

### 動かして調べるツール

#### デバッガ（でばっが / Debugger）

- 意味：プログラムを一行ずつ実行したり、決めた場所（ブレークポイント）で止めたりして、変数の値を確かめながら誤り（バグ）を探すツール
- ポイント：誤りの場所を突き止めるための道具。どの関数に何秒かかったかを集めるのはプロファイラ
- 例：R6春 問19 ウ
- 語の意味：Debug＝虫（バグ）を取る

#### プロファイラ（ぷろふぁいら / Profiler）

- 意味：プログラムを実行して、モジュールや関数ごとの実行回数・実行時間などを集め、性能の改善に役立つ情報を出すツール
- ポイント：「どこに時間がかかっているか（ボトルネック）」を見つけるための道具
- 例：R6春 問19（モジュールや関数の実行回数・実行時間など、性能改善のための情報を収集する）
- 語の意味：Profile＝人物像・特徴をまとめたもの

#### トレーサ（とれーさ / Tracer）

- 意味：プログラムが実行した命令の順番や、そのときのレジスタ・変数の値を、時間を追って記録するツール
- ポイント：どの順に処理が進んだか（実行の道筋）を後から調べられる
- 語の意味：Trace＝跡をたどる

#### インスペクタ（いんすぺくた / Inspector）

- 意味：プログラムの実行を止めたときに、変数やデータ構造の中身を表示して調べるツール
- ポイント：デバッガの機能の一部として備わっていることが多い
- 語の意味：Inspect＝詳しく調べる

#### スナップショット（すなっぷしょっと / Snapshot）

- 意味：プログラムの実行中に、指定した時点の主記憶やレジスタの内容を出力（ダンプ）するツール。スナップショットダンプとも呼ぶ
- ポイント：プログラムを止めずに、その瞬間の状態を写真のように残す

#### アサーションチェッカ（あさーしょんちぇっか / Assertion Checker）

- 意味：プログラムの中の決めた場所で「この時点では、この条件が成り立っているはず」という表明（アサーション）を書き、実行中に成り立たなかったら知らせるツール
- ポイント：前提が崩れた場所で、すぐに誤りに気づける
- 語の意味：Assertion＝断言・表明

### 動かさずに調べる・テストを助けるツール

#### 静的解析ツール（せいてきかいせきつーる / Static Analysis Tool）

- 意味：プログラムを実行せずに、ソースコードを読んで、誤りの疑いやコーディング規約の違反、構造の複雑さなどを調べるツール
- ポイント：実行しなくても、初期化していない変数や、通らない処理などを見つけられる。OSSでは SonarQube などがある

#### プリティプリンタ（ぷりてぃぷりんた / Pretty Printer）

- 意味：ソースプログラムの字下げや改行を整えて、構造を読みやすい形で出力するツール
- ポイント：プログラムの動きは変えない。見た目を整えて、誤りに気づきやすくする

#### クロスリファレンス（くろすりふぁれんす / Cross Reference）

- 意味：プログラムの中の変数名や関数名が、どこで定義され、どこで使われているかを一覧にした表を作るツール
- ポイント：変数を直すときに、影響する場所をもれなく探せる

#### テストカバレージツール（てすとかばれーじつーる / Test Coverage Tool）

- 意味：テストを実行したときに、プログラムの命令や分岐のうち、どれだけを通ったか（網羅率）を測るツール
- ポイント：テストしていない部分を見つけられる。100％通っても、誤りが全くないとは限らない

#### テストデータ生成ツール（てすとでーたせいせいつーる / Test Data Generator）

- 意味：仕様やプログラムの構造をもとに、テストに使う入力データを自動的に作り出すツール
- ポイント：境界値や同値クラスなどの考え方でデータを作るものがある

#### テストベッドツール（てすとべっどつーる / Test Bed Tool）

- 意味：テストの対象を動かすための環境（呼び出す側のドライバや、呼ばれる側のスタブなど）を用意し、テストの実行を助けるツール
- ポイント：まだできていない部分の代わりを用意して、一部だけを先にテストできる

### 別の環境をまねる

#### エミュレーター（えみゅれーたー / Emulator）

- 意味：あるコンピュータの上で、別のコンピュータ（命令形式などが違うもの）の動きをまねて、そのコンピュータ用のプログラムをそのまま実行できるようにする装置やソフトウェア
- ポイント：目的プログラムを作り出すのではなく、できたプログラムを「まねて動かす」。性能情報を集める道具でもない
- 例：R5秋 問18 ア・R6春 問19 ア
- 語の意味：Emulate＝まねる・張り合う

#### シミュレーター（しみゅれーたー / Simulator）

- 意味：実際の装置や環境、現象を、コンピュータ上の模型（モデル）で再現して、動きを確かめるツール
- ポイント：本物がまだない、または本物で試すと危ない・高いときに使う。プログラムの実行回数や時間を集める道具ではない
- 例：R6春 問19 イ
- 語の意味：Simulate＝模擬する

#### ICE（あいす / In-Circuit Emulator）

- 意味：組込み機器のCPUの代わりに回路につないで、CPUの動きをまねながら、実機の上でプログラムの実行を止めたり中身を調べたりできるデバッグ用の装置
- ポイント：実際のハードウェアにつないだまま、ソフトウェアの誤りを探せる
- 語の意味：In-Circuit＝回路の中で／Emulator＝まねるもの

#### クロス開発（くろすかいはつ / Cross Development）

- 意味：プログラムを作るコンピュータ（ホスト）と、プログラムを動かすコンピュータ（ターゲット）が別の種類である開発のしかた
- ポイント：組込み機器の開発でふつうに行う。ホストでクロスコンパイラを使って作り、ターゲットに書き込んで、ICEなどで確かめる

### 開発環境

#### IDE（あいでぃーいー / Integrated Development Environment）

- 意味：エディタ・コンパイラ・デバッガ・バージョン管理などの開発ツールを、一つの画面から使えるようにまとめた環境（統合開発環境）
- ポイント：Eclipse や Visual Studio が代表。道具を行き来する手間が減る
- 語の意味：Integrated＝統合された／Development＝開発／Environment＝環境

#### ツールチェーン（つーるちぇーん / Toolchain）

- 意味：プリプロセッサ・コンパイラ・アセンブラ・リンカのように、前の道具の出力を次の道具の入力にして、つなげて使う開発ツールのひと組
- ポイント：組込み機器向けに、ターゲットのCPU用のツールチェーンをそろえて使う

#### ローコードツール（ろーこーどつーる / Low-code Tool）

- 意味：画面の部品の配置などをマウス操作で行い、足りない部分だけを少しのプログラムで補って、アプリケーションを作るツール
- ポイント：プログラムをたくさん書かずに、早く作れる。複雑な処理は、プログラムを書いて補う

#### ノーコードツール（のーこーどつーる / No-code Tool）

- 意味：プログラムを全く書かずに、画面の操作だけでアプリケーションを作れるツール
- ポイント：業務の担当者が自分で作れるが、ツールが用意した範囲のことしかできない

### 設計を助けるツール

#### SADT（えすえーでぃーてぃー / Structured Analysis and Design Technique）

- 意味：システムの機能を、入力・出力・制御・仕組みの矢印がついた箱の図で表し、上から順に細かく分解していく分析・設計の技法
- ポイント：この考え方を図の規格にしたのが IDEF0。構造化分析の流れをくむ
- 語の意味：Structured＝構造化された／Analysis＝分析／Design＝設計／Technique＝技法

#### SREM（えすあーるいーえむ / Software Requirements Engineering Methodology）

- 意味：要求仕様を、決められた言語（RSL）で書いて、矛盾やもれをツールで自動的に調べる要求分析の方法
- ポイント：リアルタイムシステムの要求の分析のために作られた
- 語の意味：Software Requirements＝ソフトウェアの要求／Engineering＝工学／Methodology＝方法論

#### PSL/PSA（ぴーえすえる・ぴーえすえー / Problem Statement Language / Problem Statement Analyzer）

- 意味：要求を専用の言語（PSL）で書き、それを解析するツール（PSA）で、矛盾やもれを調べたり、文書を作ったりする仕組み
- ポイント：書く言語と、調べる道具がセットになっている
- 語の意味：Problem Statement＝問題の記述／Language＝言語／Analyzer＝解析するもの

#### ドキュメント生成ツール（どきゅめんとせいせいつーる / Documentation Generator）

- 意味：ソースコードの中のコメントや構造から、仕様書や説明書を自動的に作り出すツール
- ポイント：Javadoc や Doxygen が代表。コードと文書の中身を食い違いにくくする

### バージョン管理ツール

#### Git（ぎっと / Git）

- 意味：各開発者の手元に、全ての変更履歴を含む中央リポジトリの完全な複製（ローカルリポジトリ）を持つ、分散型のバージョン管理ツール
- ポイント：中央のサーバにつながらなくても、手元で履歴を調べたり、変更を記録（コミット）したりできる。GitHub などのサービスの土台
- 例：R3秋 問18・R6秋 問19（全履歴を含む中央リポジトリの完全な複製を持つバージョン管理ツール）

#### Subversion（さぶばーじょん / Apache Subversion）

- 意味：一つの中央リポジトリで履歴をまとめて管理する、集中型のバージョン管理ツール。SVNとも呼ぶ
- ポイント：CVSの後継として作られた。履歴は中央のサーバにあるので、つながらないと履歴の調査やコミットができない
- 例：R3秋 問18 ア・R6秋 問19 ア

#### CVS（しーぶいえす / Concurrent Versions System）

- 意味：一つの中央リポジトリで、複数の人の変更を管理する集中型のバージョン管理ツール
- ポイント：Subversion より前に広く使われた。ファイルごとに版を管理する
- 例：R3秋 問18 イ・R6秋 問19 イ
- 語の意味：Concurrent＝同時に起こる／Versions＝版／System＝仕組み

#### RCS（あーるしーえす / Revision Control System）

- 意味：一つ一つのファイルの変更履歴を、手元で管理する初期のバージョン管理ツール
- ポイント：ネットワーク越しの共同作業には向かない。CVS は RCS をもとに作られた
- 例：R3秋 問18 エ・R6秋 問19 エ
- 語の意味：Revision＝改訂／Control＝管理／System＝仕組み

## 5-7 オープンソースソフトウェア

### まとめ表

**OSSのライセンスと、ソースコードを公開しなければならない場面（R7春 問16 の論点）**

| ライセンス | OSSを直したもの | OSSと静的にリンク | OSSと動的にリンク | 種類 |
| :-: | :-: | :-: | :-: | :-: |
| GPL | 公開する | 公開する | 公開する | コピーレフト（強い） |
| LGPL | 公開する | 公開する | 公開しなくてよい | コピーレフト（弱い） |
| MPL | 公開する（直したファイル） | 公開しなくてよい | 公開しなくてよい | ファイル単位のコピーレフト |
| BSDL・MIT・Apache | 公開しなくてよい | 公開しなくてよい | 公開しなくてよい | 非コピーレフト（著作権表示などは残す） |

- 静的リンクについては、LGPLの条件（利用者が作り直せるよう目的プログラムを渡すなど）を満たせば公開しなくてもよい、という説明もある。試験では上の表のとおりに覚える

**用途ごとの代表的なOSS**

| 用途 | OSS |
| :-: | :-: |
| 仮想化 | Xen・KVM・QEMU |
| コンテナとクラウドの基盤 | Docker・Kubernetes・Istio・OpenStack |
| 構成管理の自動化 | Ansible・Chef・Puppet・Terraform |
| 機械学習 | TensorFlow・PyTorch・Keras・Chainer・OpenCV |
| 開発の支援 | Eclipse・Jenkins・SonarQube・Selenium・Redmine |
| 監視 | Zabbix・Prometheus・Grafana |

**OSSを使うときに考えること**

- ライセンスの条件（ソースの公開・著作権表示など）を守る。組み合わせたOSSどうしのライセンスが両立するかも確かめる
- 原則として無保証。不具合や脆弱性への対応は自分たちで行うか、有償のサポートを買う
- 脆弱性の情報を集め、更新を続ける体制を用意する

### OSSの考え方

#### OSS（おーえすえす / Open Source Software）

- 意味：ソースコードが公開されていて、誰でも自由に使用・改変・再配布ができるソフトウェア。FSFのフリーソフトウェアと考え方は近いが、OSIの定義（オープンソースの定義）に基づく
- ポイント：OSI が定めた「オープンソースの定義（OSD）」を満たすものを指す。無料とは限らないし、著作権を放棄しているわけでもない。使い方の条件はライセンスで決まる
- 語の意味：Open Source＝ソースが公開された／Software＝ソフトウェア

#### オープンソースの定義（おーぷんそーすのていぎ / Open Source Definition）

- 意味：OSI が定めた、オープンソースと呼べるライセンスの条件。OSDとも呼ぶ
- ポイント：再配布の自由、ソースコードの公開、派生物（改変したもの）の許可、個人やグループ・利用分野による差別の禁止など、10項目からなる。「商用利用の禁止」はオープンソースの条件に合わない

#### コピーレフト（こぴーれふと / Copyleft）

- 意味：ソフトウェアを改変・再配布するときにも、元と同じ自由（ソースの公開・改変・再配布の自由）を引き継がなければならない、という考え方
- ポイント：GPL が代表。作ったものを他人が囲い込んで、自由を奪うことを防ぐ。著作権（コピーライト）をもじった言葉
- 語の意味：Copyright（著作権）の right（右）を left（左）に替えたしゃれ

#### デュアルライセンス（でゅあるらいせんす / Dual License）

- 意味：同じソフトウェアを、二つのライセンス（例えばGPLと商用ライセンス）で提供し、利用者がどちらかを選べるようにすること
- ポイント：ソースを公開したくない企業は商用ライセンスを買う、という形で、開発元がOSSを続けながら収入を得られる。MySQL がこの方式

#### フリーソフトウェア（ふりーそふとうぇあ / Free Software）

- 意味：FSF が唱えた、利用者が「実行・研究・改変・再配布」の4つの自由を持つソフトウェア
- ポイント：free は「無料」ではなく「自由」の意味。無料で配られるだけで改変できない「フリーウェア」とは別もの

### ライセンスの種類

#### GPL（じーぴーえる / GNU General Public License）

- 意味：FSF が作った、代表的なコピーレフトのライセンス
- ポイント：GPLのソフトウェアを改変したり、組み込んだり（静的リンク・動的リンクとも）して配布するときは、全体のソースコードをGPLで公開しなければならない。社内で使うだけで配布しないなら、公開の義務はない
- 例：R7春 問16（a：改変・静的リンク・動的リンクのどれでも公開が必要）
- 語の意味：GNU＝FSFのOS開発の計画の名前／General Public＝一般公衆向けの／License＝利用許諾

#### LGPL（えるじーぴーえる / GNU Lesser General Public License）

- 意味：主にライブラリ向けに、GPLの条件を弱めたコピーレフトのライセンス
- ポイント：LGPLのライブラリを動的にリンクして使うだけなら、自分のプログラムのソースは公開しなくてよい。ライブラリそのものを改変したら、その部分は公開する
- 例：R7春 問16（b：動的リンクなら公開は不要）
- 語の意味：Lesser＝より弱い

#### MPL（えむぴーえる / Mozilla Public License）

- 意味：Mozilla が作った、ファイル単位でコピーレフトを求めるライセンス
- ポイント：MPLのファイルを改変したら、そのファイルのソースは公開する。自分で書いた別のファイルと組み合わせるだけなら、そちらは公開しなくてよい
- 例：R7春 問16（c：OSSのソースを修正したときだけ公開が必要）
- 語の意味：Mozilla＝Firefox などを作る団体の名前

#### BSDL（びーえすでぃーえる / BSD License）

- 意味：カリフォルニア大学バークレー校のBSD（UNIX系OS）から生まれた、条件のゆるいライセンス
- ポイント：著作権表示と免責の文を残せば、改変したものを公開しなくてよく、自分の製品に組み込んで売ってもよい（非コピーレフト）
- 例：R7春 問16（d：どの場合も公開は不要）
- 語の意味：BSD＝Berkeley Software Distribution（バークレーのソフトウェア配布物）

#### Apacheライセンス（あぱっちらいせんす / Apache License）

- 意味：Apache Software Foundation が作った、条件のゆるい（非コピーレフトの）ライセンス
- ポイント：改変したものを公開しなくてよい。BSDLとの違いは、特許の利用許諾を明記している点と、改変したことの表示を求める点

#### MITライセンス（えむあいてぃーらいせんす / MIT License）

- 意味：マサチューセッツ工科大学（MIT）で生まれた、最も条件のゆるいライセンスの一つ
- ポイント：著作権表示とライセンスの文を残せば、何に使ってもよい（非コピーレフト）。jQuery などが使っている

### OSSを支える団体

#### OSI（おーえすあい / Open Source Initiative）

- 意味：オープンソースの普及を目的とする団体。「オープンソースの定義（OSD）」を管理し、その条件を満たすライセンスを認定している
- ポイント：OSIが認定したライセンスを使っていれば、OSSと名乗れる。ネットワークの「OSI基本参照モデル」とは別もの
- 語の意味：Open Source＝オープンソース／Initiative＝取組み

#### FSF（えふえすえふ / Free Software Foundation）

- 意味：リチャード・ストールマンが作った、フリーソフトウェアの普及を目的とする団体
- ポイント：GPLを作り、GNUプロジェクト（自由なUNIX互換のOSを作る計画）を進めている
- 語の意味：Free Software＝自由なソフトウェア／Foundation＝財団

#### Linux Foundation（りなっくすふぁうんでーしょん / Linux Foundation）

- 意味：Linuxの開発を支え、普及を進めるための非営利の団体
- ポイント：Linuxの開発者の活動を支えるほか、Kubernetes を育てる CNCF なども傘下に置く

#### Apache Software Foundation（あぱっちそふとうぇあふぁうんでーしょん / Apache Software Foundation）

- 意味：Apache HTTP Server や Hadoop などの多くのOSSの開発を支える非営利の団体。ASFとも呼ぶ
- ポイント：Apacheライセンスを定めた。プロジェクトは、まず育成の段階を経てから正式なプロジェクトになる

#### OpenSSF（おーぷんえすえすえふ / Open Source Security Foundation）

- 意味：OSSのセキュリティを高めるための取組みを進める団体。Linux Foundation の傘下にある
- ポイント：多くのシステムがOSSに頼っているので、OSSの脆弱性はサプライチェーン全体の問題になる。その対策（安全な開発の指針や評価など）を進めている

### UNIX系のOSS

#### Linux（りなっくす / Linux）

- 意味：リーナス・トーバルズが開発を始めた、UNIX互換のOSのカーネル。GPLで公開されている
- ポイント：厳密には「Linux」はカーネルだけを指す。サーバ・組込み機器・スマートフォン（Android）まで広く使われている

#### Linuxディストリビューション（りなっくすでぃすとりびゅーしょん / Linux Distribution）

- 意味：Linuxカーネルに、シェル・ライブラリ・アプリケーション・インストーラなどを組み合わせて、すぐ使える形にまとめて配布するもの
- ポイント：Red Hat Enterprise Linux・Ubuntu・Debian などがある。カーネルは同じでも、使えるパッケージや管理のしかたが違う

#### FreeBSD（ふりーびーえすでぃー / FreeBSD）

- 意味：BSD系のUNIX互換OSのうち、PCやサーバ向けの性能と使いやすさを重視したもの
- ポイント：BSDLで公開されている。ネットワーク機器などの製品の土台にも使われる

#### NetBSD（ねっとびーえすでぃー / NetBSD）

- 意味：BSD系のUNIX互換OSのうち、さまざまなハードウェアで動くこと（移植性）を重視したもの
- ポイント：非常に多くの種類のCPUや機器に移植されている

#### OpenBSD（おーぷんびーえすでぃー / OpenBSD）

- 意味：BSD系のUNIX互換OSのうち、セキュリティを最も重視したもの
- ポイント：ソースコードの監査を重ねている。暗号通信のOSSである OpenSSH は、ここから生まれた

### Webシステムの定番の組合せ

#### LAMP（らんぷ / LAMP）

- 意味：Linux・Apache HTTP Server・MySQL・PHP（または Perl・Python）を組み合わせた、Webシステムを作るための定番のOSSの組合せ
- ポイント：OS・Webサーバ・データベース・言語の4層を、全部OSSでそろえられる
- 語の意味：4つのOSSの頭文字

#### LAPP（らっぷ / LAPP）

- 意味：LAMPのデータベースを、MySQL から PostgreSQL に替えた組合せ
- ポイント：Linux・Apache・PostgreSQL・PHP の頭文字

#### Apache HTTP Server（あぱっちえいちてぃーてぃーぴーさーば / Apache HTTP Server）

- 意味：Apache Software Foundation が開発する、代表的なOSSのWebサーバ
- ポイント：機能をモジュールで足していける。Webサーバのソフトであって、Java EE のアプリケーションサーバではない
- 例：R3春 問20 イ（様々なプラットフォームで動作するWebサーバは Hadoop の説明ではない）

#### MySQL（まいえすきゅーえる / MySQL）

- 意味：広く使われているOSSの関係データベース管理システム（RDBMS）
- ポイント：GPLと商用ライセンスのデュアルライセンスで提供されている。Webシステムでよく使われる

#### PostgreSQL（ぽすとぐれすきゅーえる / PostgreSQL）

- 意味：機能の豊富さと標準SQLへの準拠を重視した、OSSの関係データベース管理システム（RDBMS）
- ポイント：BSDLに近い条件のゆるいライセンスで提供されている
- 例：R3春 問20 ウ（機能の豊富さが特徴のRDBMSは Hadoop の説明ではない）

### ライブラリを配る仕組み

#### CPAN（しーぱん / Comprehensive Perl Archive Network）

- 意味：プログラム言語 Perl のモジュール（ライブラリ）を集めて配布しているネットワーク上の保管庫
- ポイント：必要なモジュールを探して、取り込んで使える
- 語の意味：Comprehensive＝包括的な／Perl＝言語の名前／Archive＝保管庫／Network＝ネットワーク

#### PEAR（ぺあ / PHP Extension and Application Repository）

- 意味：プログラム言語 PHP の部品（ライブラリ）を集めて配布している保管庫
- ポイント：今は Composer という仕組みで部品を管理することが多い
- 語の意味：PHP＝言語の名前／Extension＝拡張／Application＝アプリケーション／Repository＝保管庫

#### PyPI（ぱいぴーあい / Python Package Index）

- 意味：プログラム言語 Python のパッケージ（ライブラリ）を集めて配布している保管庫
- ポイント：pip というコマンドで、ここからパッケージを取り込む。悪意のあるパッケージが紛れ込む事件も起きている
- 語の意味：Python＝言語の名前／Package Index＝パッケージの目録

#### npm（えぬぴーえむ / npm）

- 意味：JavaScript（Node.js）のパッケージを集めた保管庫と、それを取り込むための管理ツール
- ポイント：一つのパッケージが多くの別のパッケージに頼っているので、どれか一つの不具合や乗っ取りが広く影響する（ソフトウェアサプライチェーンの問題）

### WebとAPI・データ処理のOSS

#### jQuery（じぇいくえり / jQuery）

- 意味：Webページの要素の操作や、非同期通信（Ajax）などを、短く書けるようにする JavaScript のライブラリ
- ポイント：ブラウザごとの違いを吸収してくれるので広く使われた。MITライセンス

#### Swagger（すわがー / Swagger）

- 意味：OpenAPI Specification に従って Web API を定義・設計・文書化・テストするのを支援するツール群
- ポイント：API の仕様から、説明の文書や、プログラムの雛形を自動で作れる。もとは仕様そのものの名前だった
- 例：R7春 問17（OpenAPI Specificationに従ったAPIの定義・開発を支援する機能を提供するOSS）

#### curl（かーる / curl）

- 意味：URLを指定して、HTTPなどのプロトコルでデータを送ったり受け取ったりするコマンドラインツールとライブラリ
- ポイント：Web API を手で試しに呼んでみるときによく使う。APIの定義を作る機能はない
- 例：R7春 問17 ア

#### OpenAM（おーぷんえーえむ / OpenAM）

- 意味：シングルサインオンやアクセス管理（認証・認可）を実現するOSS
- ポイント：一度のログインで複数のWebシステムを使えるようにする。APIの開発を支援するものではない
- 例：R7春 問17 イ
- 語の意味：AM＝Access Management（アクセス管理）

#### Hadoop（はどぅーぷ / Apache Hadoop）

- 意味：大規模なデータセットを、多数のコンピュータに分散させて保存・処理するためのソフトウェアライブラリ（フレームワーク）
- ポイント：分散ファイルシステム（HDFS）と、処理を分けて集める MapReduce が中心。ビッグデータの処理の土台になった
- 例：R3春 問20（大規模なデータセットを分散処理するためのソフトウェアライブラリ）

### 仮想化のOSS

#### Xen（ぜん / Xen）

- 意味：物理サーバの上で直接動く、ハイパーバイザー型（ホストOSを使わない型）の仮想化ソフトウェア。管理用のOS（Dom0）も、特別な仮想マシンとして動かす
- ポイント：その上で複数のゲストOSを動かす。ケンブリッジ大学で生まれた。コンテナ型の仮想化ではない
- 例：R5春 問20 エ

#### KVM（けーぶいえむ / Kernel-based Virtual Machine）

- 意味：Linuxカーネルに組み込まれて、Linux自体をハイパーバイザーとして働かせる仮想化の仕組み
- ポイント：ゲストOSを動かすので、コンテナ型の仮想化ではない。装置のまねは QEMU と組み合わせて行う
- 例：R5春 問20 イ
- 語の意味：Kernel-based＝カーネルを使った／Virtual Machine＝仮想マシン

#### QEMU（きゅーえむ / QEMU）

- 意味：CPUや周辺装置をソフトウェアでまねて（エミュレートして）、仮想マシンを動かすソフトウェア
- ポイント：命令形式の違うCPU用のプログラムも動かせる。KVM と組み合わせると速く動く。コンテナ型の仮想化ではない
- 例：R5春 問20 ウ
- 語の意味：Quick EMUlator（速いエミュレーター）から

#### Docker（どっかー / Docker）

- 意味：コンテナ型仮想化の環境を作り、アプリケーションの構築・実行・管理を行うためのプラットフォームを提供するOSS
- ポイント：アプリケーションと必要なライブラリを「コンテナイメージ」にまとめ、どこでも同じように動かせる。ゲストOSを持たず、ホストOSのカーネルを共有する
- 例：R5春 問20（コンテナ型仮想化の環境で、アプリケーションの構築・実行・管理を行うプラットフォーム）

### クラウド基盤とインフラの自動化

#### Kubernetes（くーばねてぃす / Kubernetes）

- 意味：多数のコンテナを、複数のサーバにまたがって配置・起動・増減・回復させる管理（オーケストレーション）のOSS。K8sとも書く
- ポイント：Docker が「コンテナを作って動かす」のに対し、Kubernetes は「たくさんのコンテナをまとめて運用する」
- 語の意味：ギリシャ語で「船の舵取り」

#### Istio（いすてぃお / Istio）

- 意味：コンテナで作った多数のサービス（マイクロサービス）どうしの通信を、まとめて制御・監視・暗号化する仕組み（サービスメッシュ）を提供するOSS
- ポイント：アプリケーションを書き換えずに、通信の制御や認証を後から加えられる。Kubernetes と組み合わせて使う

#### OpenStack（おーぷんすたっく / OpenStack）

- 意味：自社などでIaaS型のクラウド環境（仮想マシン・ストレージ・ネットワーク）を作るためのOSS
- ポイント：多くの部品（計算・ストレージ・ネットワークなど）からなる。プライベートクラウドを作るときに使う

#### Terraform（てらふぉーむ / Terraform）

- 意味：サーバやネットワークなどのクラウドの構成をコードで書き、そのとおりに環境を自動で作ったり変えたりするIaCのツール
- ポイント：多くのクラウド事業者に対応している。「あるべき状態」をコードに書き、今の状態との差を埋めるように動く

### 構成管理の自動化

#### Ansible（あんしぶる / Ansible）

- 意味：サーバの設定やソフトウェアのインストールなどの構成管理を、YAMLで書いた手順（プレイブック）に従って自動で行うツール
- ポイント：管理される側のサーバに専用のソフト（エージェント）を入れなくてよく、SSHで操作する

#### Chef（しぇふ / Chef）

- 意味：サーバの構成をRubyで書いた「レシピ」に従って自動で整える、構成管理の自動化ツール
- ポイント：管理される側にエージェントを入れて使う。料理の言葉（レシピ・クックブック）で部品を表す

#### Puppet（ぱぺっと / Puppet）

- 意味：サーバのあるべき構成を専用の言語（マニフェスト）で書いておき、そのとおりの状態に自動で保つ、構成管理の自動化ツール
- ポイント：管理される側にエージェントを入れて使う。Chef と並ぶ古くからのツール

#### Serverspec（さーばすぺっく / Serverspec）

- 意味：サーバの設定が、期待どおりの状態になっているか（パッケージが入っているか、ポートが開いているかなど）を自動でテストするツール
- ポイント：構成を「作る」のではなく「確かめる」ための道具。API の定義とも関係ない
- 例：R7春 問17 ウ

### 機械学習のOSS

#### TensorFlow（てんそるふろー / TensorFlow）

- 意味：Googleが開発した、機械学習・ディープラーニングのためのフレームワーク
- ポイント：大規模な学習から、スマートフォンなどでの推論まで幅広く使える

#### PyTorch（ぱいとーち / PyTorch）

- 意味：Meta（旧Facebook）が開発した、Python で使うディープラーニングのフレームワーク

#### Keras（けらす / Keras）

- 意味：ディープラーニングのモデルを、短く簡単に書けるようにした Python のライブラリ
- ポイント：TensorFlow などの上で動く、使いやすさを重視した「高水準のAPI」

#### Chainer（ちぇいなー / Chainer）

- 意味：日本のPreferred Networks社が開発した、Python で使うディープラーニングのフレームワーク

#### OpenCV（おーぷんしーぶい / Open Source Computer Vision Library）

- 意味：画像処理やコンピュータビジョン（画像からの物体の検出など）のためのライブラリ
- ポイント：ディープラーニングのフレームワークではなく、画像を扱う関数を数多くそろえたライブラリ
- 語の意味：Computer Vision＝コンピュータによる視覚

#### Deeplearning4j（でぃーぷらーにんぐふぉーじぇい / Deeplearning4j）

- 意味：Java などのJVMの上で動く、ディープラーニングのフレームワーク
- ポイント：Java で作られた業務システムに、ディープラーニングを組み込みやすい
- 語の意味：4j＝for Java（Java向け）

### 開発を助けるOSS

#### Eclipse（えくりぷす / Eclipse）

- 意味：Java をはじめ多くの言語に対応した、OSSの統合開発環境（IDE）
- ポイント：プラグインで機能を足していける（OSGi の仕組みを使っている）

#### Jenkins（じぇんきんす / Jenkins）

- 意味：ソースコードの変更をきっかけに、ビルドやテストを自動で実行する、継続的インテグレーション（CI）のためのツール
- ポイント：誤りを早く見つけられる。プラグインで多くのツールと連携できる

#### SonarQube（そなーきゅーぶ / SonarQube）

#### 問 ap-5-r07h-q16

- 問：表は，OSSのライセンスごとに，そのライセンスのOSSを利用したプログラムを配布するとき，ソースコードを公開しなければならないかどうかを示す。a〜dに入れるライセンスの適切な組合せはどれか。ここで，表中の“○”は公開しなければならないことを表し，“×”は公開しなくてもよいことを表す。〔表〕（a，b，c，dの順）OSSのソースコードを修正して作ったプログラム：○，○，○，×／OSSに静的にリンクしたプログラム：○，○，×，×／OSSに動的にリンクしたプログラム：○，×，×，×（表は文字で書き直した）
- ア：a GPL，b LGPL，c MPL，d BSD
- イ：a GPL，b MPL，c BSD，d LGPL
- ウ：a LGPL，b GPL，c MPL，d BSD
- エ：a LGPL，b MPL，c BSD，d GPL
- 正解：ア
- 解説：コピーレフトの強さの順に並べると読める。どの使い方でも公開が要るaが最も強いGPL。動的リンクなら公開しなくてよいbがLGPL。ソースを直したときだけ公開が要るcが、ファイル単位のMPL。どれも公開が要らないdがBSD。
- アの意味：正しい。GPL→LGPL→MPL→BSDの順に、公開が要る場面が減っていく。
- イの意味：bとcとdがずれている。BSDは直したものも公開不要なので、cの「修正したら公開」に合わない。LGPLは修正したら公開が要るので、dの全部×に合わない。
- ウの意味：aとbが逆。動的リンクでも公開が要るのはGPLで、LGPLは動的リンクなら公開不要。
- エの意味：全体が逆向き。dのGPLは全ての場面で公開が要るので、全部×に合わない。
- 出典：IPA 令和7年度春期 応用情報技術者試験 午前 問16

#### 問 ap-5-o15

- 問：GPL（GNU General Public License）のOSSを改変したプログラムに関する記述として，適切なものはどれか。
- ア：改変したプログラムを第三者に配布する場合は，そのソースコードもGPLの条件で入手できるようにしなければならない。
- イ：改変したプログラムを社内だけで使用する場合でも，ソースコードを一般に公開しなければならない。
- ウ：改変したプログラムを配布する場合は，ソースコードを公開しない代わりに，ライセンス料を開発者に支払えばよい。
- エ：改変したプログラムは，元の著作権表示を残せば，ソースコードを公開せずに自社製品として配布してよい。
- 正解：ア
- 解説：GPLはコピーレフトのライセンスで、改変したものを配布するときは、受け取った人にも同じ自由（ソースコードの入手・改変・再配布）を与えなければならない。義務が生じるのは「配布するとき」で、社内で使うだけなら公開の義務はない。
- アの意味：正しい。配布するなら、ソースコードもGPLで提供する。
- イの意味：社内で使うだけで外に配布しないなら、ソースコードを公開する義務はない。
- ウの意味：GPLに、お金を払えばソースを公開しなくてよい、という定めはない。開発元が別に商用ライセンスを用意している（デュアルライセンス）場合は、そちらで契約することになる。
- エの意味：BSDLやMITライセンスなど、非コピーレフトのライセンスの条件。GPLでは認められない。
