## 9-1 データベース方式

### まとめ表

**3層スキーマ（ANSI/SPARC）**

| スキーマ | 別名 | 定義するもの | 例 |
| :-: | :-: | :-: | :-: |

| 概念スキーマ | ― | データ全体の論理的な構造 | 表・列・制約（E-R図や正規化の結果） |

| 型 | データの持ち方 | 製品の例 |

### データベースの種類

#### 関係データベース（かんけいでーたべーす / Relational Database）

- 意味：データを行と列からなる2次元の表で表し、表どうしを共通の列の値で関連付けるデータベース。略してRDB
- ポイント：SQLで操作する。正規化で重複をなくし、主キー・外部キーで表どうしをつなぐ。レコード間をポインタでつなぐ階層型・網型とは違い、値でつなぐ
- 例：R5春 問26（項目名を個別の列名にした表を定義する選択肢が関係データベース）
- 語の意味：Relational＝関係の／Database＝データの基地

#### 階層型データベース（かいそうがたでーたべーす / Hierarchical Database）

- 意味：データを親1つに子が複数ある木構造（親子関係）で表すデータベース。略してHDB。網型とともに構造型データベースの一つ
- ポイント：子から見た親は1つだけ。親が複数ある関係（多対多）は直接表せない。網型データベースとまとめて構造型データベースと呼ぶ
- 語の意味：Hierarchical＝階層の

#### 網型データベース（もうがたでーたべーす / Network Database）

- 意味：レコードどうしを網の目のようにつなぎ、子が複数の親をもてるデータベース。略してNDB（ネットワーク型データベース）。階層型とともに構造型データベースの一つ
- ポイント：階層型データベースと違い多対多も表せる。CODASYL型とも呼ぶ。レコードの関係をバックマン線図で表す
- 語の意味：Network＝網

#### 構造型データベース（こうぞうがたでーたべーす / Structured Database）

- 意味：レコードどうしの関係をポインタなどの物理的なつながりで表すデータベースの総称。階層型データベースと網型データベースのこと
- ポイント：関係データベースのように値で表をつなぐのではなく、たどる道筋があらかじめ決まっている

#### オブジェクト指向データベース（おぶじぇくとしこうでーたべーす / Object Oriented Database）

- 意味：データとそれを操作する手続（メソッド）をまとめたオブジェクトの形で記録するデータベース。略してOODB
- ポイント：クラスの継承や、複雑な構造のデータをそのまま扱える。関係データベースを拡張して型の継承や操作の定義をできるようにしたものはオブジェクト関係データベース（R6春 問29のア）
- 語の意味：Object＝もの／Oriented＝向いた

#### XMLデータベース（えっくすえむえるでーたべーす / XML Database）

- 意味：XML形式の文書を、タグの階層構造を保ったまま記録・検索するデータベース
- ポイント：XPathやXQueryで検索する。項目の構成が文書ごとに違ってもよい

### NoSQLデータベース

#### NoSQL（のーえすきゅーえる / Not only SQL）

- 意味：関係データベース以外のデータベースの総称。表の形にとらわれず、大量のデータを多数のサーバに分散して扱うことを重視する
- ポイント：キーバリュー型・ドキュメント指向・列指向・グラフ型が代表。ACID特性より、BASE特性（結果整合性）を選ぶものが多い。ビッグデータの基盤（R6春 問29）
- 語の意味：Not only SQL＝SQLだけではない

#### キーバリュー型データベース（きーばりゅーがたでーたべーす / Key-Value Store）

- 意味：1つのキーに1つの値を対応付けて記録する、最も単純な形のNoSQLデータベース
- ポイント：値の型は決まっていないので、様々な形式のデータを入れられる。キーを指定した読み書きが速い。Redisが代表（R3春 問28のウ、R6春 問29のウ）
- 語の意味：Key＝鍵／Value＝値

#### ドキュメント指向データベース（どきゅめんとしこうでーたべーす / Document-Oriented Database）

- 意味：JSONやXMLのような階層構造をもつデータを、1件ずつドキュメントとして記録するNoSQLデータベース
- ポイント：ドキュメントごとに項目の構成が違ってもよい。ドキュメント内の項目にインデックスも作れる。MongoDB・CouchDBが代表（R5春 問26の正解、R3春 問28のア）
- 語の意味：Document＝文書／Oriented＝向いた

#### 列指向データベース（れつしこうでーたべーす / Wide-Column Store）

- 意味：1つのキー（行）に任意の数の列をもたせ、列ごとに値を記録するNoSQLデータベース。ワイドカラム型ともいう
- ポイント：関係データベースと違い、行ごとに列の数や型が違ってもよい。Apache Cassandraが代表（R7春 問24の正解、R3春 問28のエ）
- 語の意味：Wide＝幅の広い／Column＝列

#### グラフデータベース（ぐらふでーたべーす / Graph Database）

- 意味：データをノード（点）とリレーション（辺）で表し、ノードやリレーションに属性（プロパティ）をもたせるNoSQLデータベース
- ポイント：人と人のつながり（SNS）や経路のように、関係をたどる検索が得意。Neo4jが代表（R3春 問28の正解）
- 語の意味：Graph＝点と線のつながりの図

#### プロパティグラフ（Property Graph）

- 意味：グラフデータベースで使うデータモデルの一つで、ノードとリレーションのそれぞれに、名前と値の組（プロパティ）をもたせて表すもの
- ポイント：グラフデータベースの多くが採用する。もう1つのグラフ型のデータモデルがトリプルストア
- 語の意味：Property＝属性／Graph＝つながりの図

#### トリプルストア（Triple Store）

- 意味：グラフデータベースで使うデータモデルの一つで、「主語・述語・目的語」の3つ組（トリプル）を単位としてデータを記録するもの
- ポイント：RDFという形式で表すことが多い。プロパティグラフと違い、属性もすべて3つ組で表す
- 語の意味：Triple＝3つ組／Store＝ためる所

#### インメモリデータベース（いんめもりでーたべーす / In-Memory Database）

- 意味：データを磁気ディスクやSSDではなく、主記憶（メモリ）上に置いて処理するデータベース
- ポイント：ディスクの入出力がないので高速。電源が切れると消えるので、ログやスナップショットを不揮発の装置に書いて守る

### 3層スキーマ

#### 外部スキーマ（がいぶすきーま / External Schema）

- 意味：利用者やプログラムから見たデータの定義。必要な部分だけを、使いやすい形で見せる。副スキーマともいう
- ポイント：関係データベースではビューが外部スキーマに当たる
- 語の意味：External＝外側の／Schema＝構造の定義

#### 概念スキーマ（がいねんすきーま / Conceptual Schema）

- 意味：データベース全体の論理的なデータ構造の定義。どんな表・列・関連・制約があるか
- ポイント：関係データベースでは表（実表）の定義。E-Rモデルの作成、一意性制約・参照制約の設定、正規化は概念スキーマの設計（R4春 問27のイ〜エ）
- 語の意味：Conceptual＝概念の／Schema＝構造の定義

#### 内部スキーマ（ないぶすきーま / Internal Schema）

- 意味：データを記憶装置にどう格納するかの物理的な定義。記憶スキーマともいう
- ポイント：インデックスの定義、ファイル編成、ブロックの大きさなど。SQLの応答時間を良くするためのインデックスの定義は内部スキーマの設計（R4春 問27の正解）
- 例：R4春 問27
- 語の意味：Internal＝内側の／Schema＝構造の定義

#### データ独立性（でーたどくりつせい / Data Independence）

- 意味：あるスキーマを変えても、別のスキーマやプログラムに影響が及ばない性質
- ポイント：格納方法（内部スキーマ）を変えても概念スキーマに影響しないのが物理的データ独立性、概念スキーマを変えても外部スキーマ（プログラム）に影響しないのが論理的データ独立性。3層に分ける目的

### データモデルの段階

#### 概念データモデル（がいねんでーたもでる / Conceptual Data Model）

- 意味：対象業務にどんなデータがあり、どう関連しているかを、DBMSの種類に関係なく表したモデル
- ポイント：E-R図やUMLのクラス図で表す。次に論理データモデル、物理データモデルへと具体化する
- 例：R3春 問29・R5春 問29（UMLで表した概念データモデル）
- 語の意味：Conceptual＝概念の／Data Model＝データの模型

#### 論理データモデル（ろんりでーたもでる / Logical Data Model）

- 意味：概念データモデルを、使うDBMSの方式（関係モデル・階層モデル・網モデル）に合わせて表したモデル
- ポイント：関係モデルなら表・列・主キー・外部キーの形にする。どの製品を使うか、どう格納するかはまだ決めない
- 語の意味：Logical＝論理の

#### 物理データモデル（ぶつりでーたもでる / Physical Data Model）

- 意味：論理データモデルを、使うDBMS製品の上で記憶装置にどう格納するかまで決めたモデル
- ポイント：データ型・インデックス・表の分割・ファイル編成など。性能に直結する
- 語の意味：Physical＝物理的な

#### 企業データモデル（きぎょうでーたもでる / Enterprise Data Model）

- 意味：個別のシステムではなく、企業全体のデータを1つにまとめて表したデータモデル
- ポイント：システムごとに同じデータがばらばらに定義されるのを防ぐ。データ中心アプローチ（DOA）の土台になる
- 語の意味：Enterprise＝企業

### 関係モデルの用語

#### 関係（かんけい / Relation）

- 意味：関係モデルで、データを表す2次元の表のこと。リレーションともいう
- ポイント：同じタプル（行）が2つあってはならず、行の順番・列の順番には意味がない。この点が表計算の表とは違う
- 語の意味：Relation＝関係

#### タプル（Tuple）

- 意味：関係（表）の1行のこと。組ともいう。1件のデータに当たる
- ポイント：関係の中で同じタプルは重複しない。タプルを一意に識別する属性の組が候補キー
- 語の意味：Tuple＝組（n個の値の組）

#### 属性（ぞくせい / Attribute）

- 意味：関係（表）の1列のこと。列やフィールドともいい、データの項目に当たる
- ポイント：属性ごとに、とりうる値の集合（定義域）が決まっている。属性の名前を並べたものが関係スキーマ
- 語の意味：Attribute＝属性・特性

#### 定義域（ていぎいき / Domain）

- 意味：ある属性がとりうる値の集合。ドメインともいう
- ポイント：例えば「月」の定義域は1〜12。SQLの検査制約（CHECK）やデータ型で表す
- 語の意味：Domain＝領域

#### 実現値（じつげんち / Instance）

- 意味：関係スキーマ（表の形）に対して、ある時点で実際に入っているタプルの集まり。関係の中身
- ポイント：関係スキーマはあまり変わらないが、実現値は追加・更新・削除のたびに変わる

#### 関係スキーマ（かんけいすきーま / Relation Schema）

- 意味：関係の名前と、それがもつ属性の名前の並び。例：社員（社員番号，氏名，部門コード）
- ポイント：表の「形」の定義。中身（実現値）とは区別する。主キーに下線、外部キーに破線の下線を付けて書くことが多い

### DBMSの機能

#### データベース管理システム（でーたべーすかんりしすてむ / Database Management System）

- 意味：データベースを定義・操作・制御し、多数の利用者が安全に共有できるようにするソフトウェア。略してDBMS
- ポイント：データベース定義機能・データベース操作機能・データベース制御機能（同時実行制御・障害回復・機密保護）をもつ
- 語の意味：Management＝管理／System＝仕組み

#### データベース定義機能（でーたべーすていぎきのう / Data Definition Function）

- 意味：スキーマ・表・ビュー・インデックスなどの構造を定義するDBMSの機能
- ポイント：SQLではDDL（CREATE文・DROP文など）で使う

#### データベース操作機能（でーたべーすそうさきのう / Data Manipulation Function）

- 意味：データの検索・追加・更新・削除を行うDBMSの機能
- ポイント：SQLではDML（SELECT・INSERT・UPDATE・DELETE）で使う

#### データベース制御機能（でーたべーすせいぎょきのう / Data Control Function）

- 意味：同時実行制御（排他制御）・障害回復・アクセス権の管理などで、データの正しさと安全を守るDBMSの機能。保全機能とデータ機密保護機能を含む
- ポイント：SQLではDCL（GRANT・REVOKE・COMMIT・ROLLBACK）で使う。保全機能・データ機密保護機能もここに入る

#### 保全機能（ほぜんきのう / Integrity Function）

- 意味：データベース制御機能のうち、一意性制約・参照制約などの制約を守らせて、誤ったデータや矛盾したデータが入らないようにする機能。完全性を保つ機能
- ポイント：一意性制約・参照制約・検査制約で誤ったデータを入れさせない

#### データ機密保護機能（でーたきみつほごきのう / Data Security Function）

- 意味：データベース制御機能のうち、利用者ごとにアクセス権を与え、許された人だけがデータを読み書きできるようにする機能
- ポイント：GRANT文で権限を与え、REVOKE文で取り消す。ビューで見せる列や行を絞る方法もある

### DBMSの製品

#### MySQL（まいえすきゅーえる）

- 意味：LAMP構成（Linux・Apache・MySQL・PHP）の「M」として、Webサービスの裏側で最も広く使われてきたオープンソースの関係データベース管理システム
- ポイント：Webサービスの裏側でよく使われる。関係データベースの代表例として、PostgreSQL・SQLiteと並べて覚える

#### PostgreSQL（ぽすとぐれすきゅーえる）

- 意味：大学の研究用DBMS（Ingres）の後継として生まれ、標準SQLへの対応が広く、MVCCで読み取りと更新を待ち合わせないオープンソースの関係データベース管理システム
- ポイント：標準SQLへの対応が広く、MVCC（多版同時実行制御）で読み取りと書き込みが待ち合わせない

#### SQLite（えすきゅーらいと）

- 意味：サーバを置かず、1つのファイルにデータベースを入れて、アプリケーションに組み込んで使う関係データベース管理システム
- ポイント：スマートフォンのアプリやWebブラウザの内部で使われる。設定がいらず軽い

#### MongoDB（もんごでぃーびー）

- 意味：JSONを2進にしたBSON形式でドキュメントを記録し、シャーディングで多数のサーバに分散できる、最も代表的なドキュメント指向のNoSQLデータベース（Apache CouchDBと同じ型）
- ポイント：ドキュメントごとに項目が違ってもよい。CouchDBも同じドキュメント指向

#### Redis（れでぃす）

- 意味：データを主記憶上に置いて高速に処理する、代表的なキーバリュー型のNoSQLデータベース
- ポイント：キャッシュやセッション情報の保存によく使われる。インメモリデータベースの例でもある

#### Neo4j（ねおふぉーじぇい）

- 意味：ノードとリレーションでデータを表す、代表的なグラフデータベース
- ポイント：プロパティグラフのデータモデルを使い、つながりをたどる検索が得意

#### Apache Cassandra（あぱっちかさんどら）

- 意味：多数のサーバに分散してデータを記録する、代表的な列指向（ワイドカラム型）のNoSQLデータベース
- ポイント：どのサーバが止まっても動き続けることを重視する（CAP定理のAとP）

#### Apache CouchDB（あぱっちかうちでぃーびー）

- 意味：HTTPで操作でき、複数のサーバ間でデータを複製（レプリケーション）し合う機能を特長とする、MongoDBと同じドキュメント指向のNoSQLデータベース
- ポイント：HTTPで操作でき、複数のサーバ間でデータを複製（レプリケーション）する機能が強い。MongoDBと同じ型

## 9-2 データベース設計

### まとめ表

**正規化の手順**

| 正規形 | 満たす条件 | 前の段階から分解するもの |
| :-: | :-: | :-: |
| 非正規形 | ― | 繰返し項目がある |
| 第1正規形 | 繰返し項目がない（全部の値が単一） | 繰返しを別の行・表へ |
| 第2正規形 | 主キーの一部への関数従属（部分関数従属）がない | 主キーの一部で決まる項目を別の表へ |
| 第3正規形 | 主キー以外の項目どうしの関数従属（推移関数従属）がない | 主キー以外の項目で決まる項目を別の表へ（R7春 問26） |

**キーの種類**

| キー | 中身 |
| :-: | :-: |
| スーパーキー | タプルを一意に識別できる属性の組（余計な属性を含んでもよい） |
| 候補キー | スーパーキーのうち、それ以上減らせない極小のもの |
| 主キー | 候補キーから1つ選んだもの。NULL不可・重複不可 |
| 代替キー | 主キーに選ばれなかった候補キー |
| 外部キー | 他の関係の候補キー（主キー）を参照する属性（R5秋 問27） |

**参照制約の削除規則（ON DELETE）**

| 指定 | 参照される行を削除したとき |
| :-: | :-: |
| CASCADE | 参照している行も一緒に削除（R5春 問30・R7春 問27） |
| SET NULL | 参照している列をNULLにする |
| SET DEFAULT | 参照している列を既定値にする |
| RESTRICT ／ NO ACTION | 参照している行があれば削除させない |

### データ分析

#### データ項目の標準化（でーたこうもくのひょうじゅんか / Data Standardization）

- 意味：データ項目の名前・意味・データ型・桁数などを全社で統一して決め、同じものを同じ名前で扱えるようにすること
- ポイント：命名規約と、項目名と意味を登録した辞書（データディクショナリ）で、異音同義語・同音異義語の発生を防ぐ
- 例：R4秋 問26（命名規約だけでは値の範囲の違いは防げない）

#### 異音同義語（いおんどうぎご / Synonym）

- 意味：名前が違うのに同じ意味のデータ項目。シノニム
- ポイント：例：「賞与金額」と「ボーナス金額」。項目名と意味を辞書に登録すれば防げる（R4秋 問26のウ）
- 語の意味：Synonym＝同義語

#### 同音異義語（どうおんいぎご / Homonym）

- 意味：名前が同じなのに意味が違うデータ項目。ホモニム
- ポイント：例：ある表では「取引先」がコード、別の表では名前。末尾に区分語（コード・名）を付ける規約で防げる（R4秋 問26のエ）
- 語の意味：Homonym＝同音異義語

#### メタデータ（Metadata）

- 意味：データについてのデータ。データ項目の名前・意味・型・桁数・格納場所・作成者などの情報
- ポイント：メタデータを集めて管理する仕組みがデータディクショナリやリポジトリ。データそのものではない
- 語の意味：Meta＝一段上の

#### データディクショナリ（Data Dictionary）

- 意味：データ項目の名前・意味・形式・格納場所などのメタデータを集めて管理する辞書。データ辞書
- ポイント：データの標準化に使う。DBMSが内部で表や列の定義を記録する部分（システムカタログ）を指すこともある（R6春 問29のエ）
- 語の意味：Dictionary＝辞書

#### トップダウンアプローチ（Top-down Approach）

- 意味：業務全体から必要なデータを洗い出し、全体像から細部へとデータモデルを作る方法
- ポイント：全社で一貫したモデルになるが、時間がかかる。反対は今ある帳票や画面から積み上げるボトムアップアプローチ
- 語の意味：Top-down＝上から下へ

#### ボトムアップアプローチ（Bottom-up Approach）

- 意味：今ある帳票・画面・ファイルのデータ項目を集め、正規化しながら積み上げてデータモデルを作る方法
- ポイント：具体的で早く作れるが、全体の一貫性が欠けやすい。トップダウンアプローチと組み合わせることが多い
- 語の意味：Bottom-up＝下から上へ

#### データ中心アプローチ（でーたちゅうしんあぷろーち / Data Oriented Approach）

- 意味：業務の処理手順より先に、業務で使うデータの構造を分析・設計し、それを中心にシステムを作る考え方。略してDOA
- ポイント：処理は変わってもデータの構造は変わりにくい、という考えに基づく。処理を中心に作るのはプロセス中心アプローチ（POA）
- 語の意味：Data＝データ／Oriented＝中心の／Approach＝取り組み方

### E-R図とUML

#### E-R図（いーあーるず / Entity-Relationship Diagram）

- 意味：実体（エンティティ）と、実体どうしの関連（リレーションシップ）でデータの構造を表す図
- ポイント：概念データモデルを表すのに使う。DBMSの種類に関係なく書ける。関連の多重度（1対1・1対多・多対多）を線の端に書く
- 語の意味：Entity＝実体／Relationship＝関連／Diagram＝図

#### エンティティ（Entity）

- 意味：データとして管理する対象になる、業務上の「もの」や「こと」。実体ともいう。例：顧客・商品・注文
- ポイント：E-R図では箱で書き、属性をもつ。関係データベースではふつう1つの表になる
- 語の意味：Entity＝実体

#### リレーションシップ（Relationship）

- 意味：エンティティどうしの関連。例：「顧客」が「注文」を行う
- ポイント：多重度（カーディナリティ）で、相手側にいくつ対応するかを表す。多対多の関連は、間に連関エンティティ（例：注文明細）を置いて1対多に分ける
- 語の意味：Relationship＝関係

#### カーディナリティ（Cardinality）

- 意味：1つのエンティティに、相手のエンティティがいくつ対応するか。1対1・1対多・多対多などの多重度
- ポイント：UMLでは「1」「0..1」「1..*」「*（0..*）」で書く。「1人以上が所属」なら1..*、「0個以上」なら*。条件の言葉から多重度を読む問題が出る（R5春 問29）
- 例：R5春 問29
- 語の意味：Cardinality＝要素の数

#### バックマン線図（ばっくまんせんず / Bachman Diagram）

- 意味：レコード型を箱で、親子関係（1対多）を矢印で表す図。網型データベースの構造を表すのに使った
- ポイント：矢印は「1」の側から「多」の側へ向ける。考えた人の名前（C.W.Bachman）から

#### クラス図（くらすず / Class Diagram）

- 意味：UMLの図の1つで、クラス（箱）とクラスどうしの関連（線）、多重度を表す図
- ポイント：データベース設計では概念データモデルを表すのに使う。線の両端に多重度を書く。「顧客1―*注文1―*注文明細*―1商品」の形がよく出る（R3春 問29）
- 例：R3春 問29・R5春 問29・R7春 問25
- 語の意味：Class＝種類・分類／Diagram＝図

#### オブジェクト図（おぶじぇくとず / Object Diagram）

- 意味：UMLの図の1つで、クラスの代わりに、ある時点の具体的なインスタンス（例：「東京：地域」）とそのつながりを表す図
- ポイント：インスタンスどうしの線の数から、クラス図の多重度を読み取れる（R6秋 問29）
- 例：R6秋 問29
- 語の意味：Object＝もの・実例

### キー

#### 主キー（しゅきー / Primary Key）

- 意味：表の行（タプル）を一意に識別するために、候補キーの中から1つ選んだキー
- ポイント：値の重複も、NULLも許されない（主キー制約）。表記では実線の下線で示す
- 語の意味：Primary＝第一の／Key＝鍵

#### 候補キー（こうほきー / Candidate Key）

- 意味：タプルを一意に識別できる属性の組のうち、どの属性を取り除いても一意に識別できなくなる、極小のもの
- ポイント：候補キーが複数あるとき、1つを主キーに選ぶ。残りは代替キー（R5秋 問27のウ）
- 語の意味：Candidate＝候補

#### スーパーキー（Super Key）

- 意味：タプルを一意に識別できる属性の組。余計な属性を含んでいてもよい
- ポイント：スーパーキーから余計な属性を除いて極小にしたものが候補キー（R5秋 問27のエ）
- 語の意味：Super＝上位の・より大きい

#### 代替キー（だいたいきー / Alternate Key）

- 意味：候補キーのうち、主キーに選ばれなかったもの
- ポイント：主キーではないが、タプルを一意に識別できる。一意性制約（UNIQUE）を付けて重複を防ぐ（R5秋 問27のイ）
- 語の意味：Alternate＝代わりの

#### 外部キー（がいぶきー / Foreign Key）

- 意味：他の関係（表）の候補キー（ふつうは主キー）を参照する属性、または属性の組
- ポイント：表どうしを関連付ける。参照先にない値を入れられない（参照制約）。表記では破線の下線で示す
- 例：R5秋 問27
- 語の意味：Foreign＝外の

#### 複合キー（ふくごうきー / Composite Key）

- 意味：複数の属性を組み合わせて1つのキーにしたもの。連結キーともいう
- ポイント：例：注文明細の（注文番号，明細番号）。複合キーの一部だけで決まる項目があると第2正規形でない（部分関数従属）
- 語の意味：Composite＝組み合わせた

#### サロゲートキー（Surrogate Key）

- 意味：業務上の意味をもたない連番などを、主キーとして人工的に付け加えたもの。代理キー
- ポイント：自然な候補キーが長い・変わる・複合キーになるときに使う。業務の値が変わっても主キーを変えずに済む
- 語の意味：Surrogate＝代理の

### 制約

#### 一意性制約（いちいせいせいやく / Unique Constraint）

- 意味：列の値が表の中で重複しないようにする制約。SQLではUNIQUE
- ポイント：主キー制約は一意性制約に「NULL不可」を加えたもの。UNIQUEの列はNULLを許すことがある

#### 主キー制約（しゅきーせいやく / Primary Key Constraint）

- 意味：主キーの列について、値の重複とNULLを許さない制約。SQLではPRIMARY KEY
- ポイント：一意性制約と非NULL制約を合わせたもの。1つの表に1つだけ

#### 参照制約（さんしょうせいやく / Referential Constraint）

- 意味：外部キーの値が、参照先の表の主キー（候補キー）に必ず存在するようにする制約。参照整合性制約
- ポイント：SQLではFOREIGN KEY … REFERENCES。参照される行を削除・更新したときの動き（CASCADEなど）も決められる
- 例：R5春 問30・R7春 問27

#### 検査制約（けんさせいやく / Check Constraint）

- 意味：列の値が決められた条件を満たすようにする制約。SQLではCHECK
- ポイント：例：CHECK（数量 > 0）。定義域（ドメイン）を表すのに使う

#### 非NULL制約（ひなるせいやく / NOT NULL Constraint）

- 意味：列にNULL（値なし）を入れさせない制約。SQLではNOT NULL
- ポイント：必ず値が要る列に付ける。主キーには自動で付く

#### NULL（なる）

- 意味：値が存在しない、または不明であることを表す特別な印。0や空の文字列とは違う
- ポイント：NULLとの比較（= NULL）は真にならないので、IS NULLで調べる。集約関数（SUM・AVGなど）はNULLを無視する

### 参照動作

#### CASCADE（かすけーど）

- 意味：参照制約で、参照される行を削除（更新）したとき、それを参照している行も一緒に削除（更新）する指定
- ポイント：「注文を削除したら注文明細も自動で削除」なら ON DELETE CASCADE（R5春 問30・R7春 問27の正解）
- 例：R5春 問30・R7春 問27
- 語の意味：Cascade＝滝のように連なって落ちる

#### RESTRICT（りすとりくと）

- 意味：参照制約で、参照している行があるときは、参照される行の削除（更新）をその場でエラーにしてさせない指定。NO ACTIONとほぼ同じ
- ポイント：NO ACTIONもほぼ同じで、どちらも削除をエラーにする。自動で削除するCASCADEとは逆
- 語の意味：Restrict＝制限する

#### SET NULL（せっとなる）

- 意味：参照制約で、参照される行を削除したとき、参照している行の外部キーをNULLにする指定
- ポイント：参照している行は残る。外部キーの列にNOT NULLが付いていると使えない

#### SET DEFAULT（せっとでふぉると）

- 意味：参照制約で、参照される行を削除したとき、参照している行の外部キーを既定値（DEFAULTの値）にする指定
- ポイント：SET NULLと同じく、参照している行は残す

#### NO ACTION（のーあくしょん）

- 意味：参照制約で、何も指定しないときの動き。文の実行の最後に調べ、参照している行が残っていれば削除（更新）の文をエラーにする。RESTRICTとほぼ同じ
- ポイント：RESTRICTとほぼ同じ。違いは制約を調べる時点（文の最後に調べる）

### 正規形

#### 非正規形（ひせいきけい / Unnormalized Form）

- 意味：1つの項目に複数の値が入っている（繰返し項目がある）表
- ポイント：繰返しを別の行や表に分けて、全部の値を単一にすると第1正規形になる（R7春 問26のエ）

#### 第1正規形（だいいちせいきけい / First Normal Form）

- 意味：すべての属性の値が単一で、繰返し項目がない関係
- ポイント：主キーの一部だけで決まる属性（部分関数従属）が残っていれば、まだ第2正規形ではない（R3秋 問28の正解）
- 例：R3秋 問28・R4春 問28

#### 第2正規形（だいにせいきけい / Second Normal Form）

- 意味：第1正規形で、主キー（候補キー）以外のすべての属性が、主キーに完全関数従属している関係。部分関数従属がない
- ポイント：主キーが1つの属性だけなら、第1正規形は自動的に第2正規形。主キー以外の属性どうしの従属（推移関数従属）はまだ残ってよい
- 例：R4春 問28

#### 第3正規形（だいさんせいきけい / Third Normal Form）

- 意味：第2正規形で、主キー以外の属性が主キーに推移的に関数従属していない関係
- ポイント：第2正規形から、候補キー以外の属性どうしの関数従属を別の表に分けると第3正規形（R7春 問26の正解）
- 例：R4春 問28・R7春 問26

#### ボイス・コッド正規形（ぼいすこっどせいきけい / Boyce-Codd Normal Form）

- 意味：すべての関数従属で、決める側（左辺）が必ずスーパーキーである関係。略してBCNF
- ポイント：第3正規形でも、候補キー以外の属性から候補キーの一部が決まるとBCNFではない（R7春 問26のア）
- 語の意味：Boyce・Codd＝考えた人の名前

#### 非正規化（ひせいきか / Denormalization）

- 意味：処理を速くするため、あえて正規化を崩し、表を結合した形やデータを重複させた形にしておくこと
- ポイント：結合の時間は減るが、更新時に矛盾が起きやすくなる。分析用のデータウェアハウスでよく使う

### 関数従属

#### 関数従属（かんすうじゅうぞく / Functional Dependency）

- 意味：属性Xの値が決まると、属性Yの値がただ1つに決まる関係。X→Yと書く。完全関数従属・部分関数従属・推移関数従属はこの関係の種類
- ポイント：例：商品コード→単価。正規化は関数従属をもとに表を分ける作業

#### 完全関数従属（かんぜんかんすうじゅうぞく / Full Functional Dependency）

- 意味：属性Yが主キー全体に関数従属していて、主キーのどの一部にも関数従属していないこと
- ポイント：主キー以外の全部の属性が主キーに完全関数従属していれば第2正規形

#### 部分関数従属（ぶぶんかんすうじゅうぞく / Partial Functional Dependency）

- 意味：属性Yが、複合した主キーの一部だけに関数従属していること
- ポイント：例：主キーが（受注番号，項番）のとき、受注日は受注番号だけで決まる。これがあると第2正規形でない（R3秋 問28・R4春 問28のa）
- 例：R3秋 問28

#### 推移関数従属（すいいかんすうじゅうぞく / Transitive Functional Dependency）

- 意味：主キー→X、X→Yのように、主キー以外の属性Xを通して、間接的にYが主キーに関数従属していること
- ポイント：例：社員番号→部門コード→部門名。これがあると第3正規形でない。Xを主キーとする別の表に分ける（R4春 問28のb）

#### 決定項（けっていこう / Determinant）

- 意味：関数従属 X→Y で、値を決める側（左側）の属性X
- ポイント：例：商品コード→単価 の決定項は商品コード。決定項が主キーの一部なら部分関数従属、主キー以外の属性なら推移関数従属になる。すべての決定項がスーパーキーならボイス・コッド正規形

#### 多値従属（たちじゅうぞく / Multivalued Dependency）

- 意味：属性Xの値が決まると、属性Yの値の「集合」が、他の属性に関係なく決まる関係
- ポイント：独立した多値従属を別の表に分けると第4正規形。応用情報では第3正規形までが中心

### 物理設計と運用

#### 副次索引（ふくじさくいん / Secondary Index）

- 意味：主キー以外の列に作る索引（インデックス）
- ポイント：よく検索条件に使う列に作ると速くなる。ただし作りすぎると、更新のたびに索引の更新も要るので遅くなる

#### 表の分割（ひょうのぶんかつ / Partitioning）

- 意味：大きな表を、行の範囲（水平分割）や列のまとまり（垂直分割）で複数に分けて格納すること。分割法
- ポイント：検索する範囲が狭くなり速くなる。日付の範囲で分けるのが代表。分散データベースで別のサーバに置くこともある

#### ディスク容量見積り（でぃすくようりょうみつもり / Disk Capacity Estimation）

- 意味：レコード長・件数・ブロックの大きさ・増え方から、データベースに必要な記憶装置の容量を見積もること
- ポイント：1ブロックに入るレコード数（端数は切り捨て）、必要なブロック数（端数は切り上げ）の順に計算する

#### 再編成（さいへんせい / Reorganization）

- 意味：追加・削除を繰り返して物理的な格納が散らばったデータベースを、整理し直して格納し直すこと
- ポイント：空き領域の回収・あふれ領域の解消でアクセス効率が戻る。データベースの性能が落ちたときの運用作業

#### チューニング（Tuning）

- 意味：性能を評価した結果から、索引の追加・SQLの書き換え・パラメータの調整などで処理を速くすること
- ポイント：オプティマイザが選んだ実行計画を確かめて、遅い原因を探す
- 語の意味：Tuning＝調整

#### インバーテッドファイル（Inverted File）

- 意味：データの値（語）から、その値をもつレコードの位置を引けるようにした索引のファイル。転置ファイル。転置インデックスと同じ考え方
- ポイント：全文検索で、単語から文書を探すのに使う。転置インデックスと同じ考え方
- 語の意味：Inverted＝逆にした
## 9-3 データ操作

### まとめ表

**集合演算と関係演算**

| 演算 | 結果 | SQL |
| :-: | :-: | :-: |
| 和 R∪S | RかSの少なくとも一方にある行（重複は1つ） | UNION（R3秋 問26・R3秋 問29） |
| 差 R−S | Rにあって、Sにない行 | EXCEPT（R4秋 問27） |
| 積 R∩S | RとSの両方にある行。R−(R−S)と同じ（R7春 問28） | INTERSECT |
| 直積 R×S | Rの各行とSの各行の全部の組合せ | CROSS JOIN |
| 選択 | 条件に合う行を取り出す | WHERE |
| 射影 | 指定した列を取り出す | SELECT 列名 |
| 結合 | 共通の列の値が等しい行どうしをつなぐ | JOIN … ON |

**SELECT文の書く順と実行される順**

| 書く順 | 句 | 実行される順 |
| :-: | :-: | :-: |
| 1 | SELECT 列・集約関数 | 5 |
| 2 | FROM 表（JOIN） | 1 |
| 3 | WHERE 行の条件 | 2 |
| 4 | GROUP BY グループ化 | 3 |
| 5 | HAVING グループの条件 | 4 |
| 6 | ORDER BY 並べ替え | 6 |

### 集合演算

#### 和（わ / Union）

- 意味：2つの関係のどちらか一方、または両方にあるタプルを全部集めた関係。R∪S
- ポイント：重複するタプルは1つにする。SQLではUNION（重複を残すならUNION ALL）。縦に並んだ2つの結果を1つにまとめるのに使う（R3秋 問26・問29の正解）
- 例：R3秋 問26・R3秋 問29
- 語の意味：Union＝結合・合併

#### 差（さ / Difference）

- 意味：一方の関係にあって、もう一方の関係にないタプルの集まり。R−S
- ポイント：R−SとS−Rは違う結果になる。SQLではEXCEPT（製品によってはMINUS）（R4秋 問27の正解）
- 例：R4秋 問27
- 語の意味：Difference＝違い

#### 積（せき / Intersection）

- 意味：2つの関係の両方にあるタプルの集まり。共通集合。R∩S
- ポイント：差を2回使って R−(R−S) としても求められる（R7春 問28）。SQLではINTERSECT
- 例：R7春 問28
- 語の意味：Intersection＝交わり

#### 直積（ちょくせき / Cartesian Product）

- 意味：一方の関係の各タプルと、もう一方の関係の各タプルを、全部の組合せでつないだ関係。R×S
- ポイント：行数は「Rの行数×Sの行数」になる。SQLではCROSS JOIN、またはFROMに表を並べて結合条件を書かない形
- 語の意味：Cartesian＝デカルトの／Product＝積

#### 和両立（わりょうりつ / Union-Compatible）

- 意味：2つの関係の属性の数が同じで、対応する属性の定義域も同じであること
- ポイント：和・差・積の集合演算は、和両立な関係どうしでないとできない

### 関係演算

#### 選択（せんたく / Selection）

- 意味：関係から、条件に合うタプル（行）だけを取り出す演算
- ポイント：SQLのWHERE句に当たる。行を減らす演算。列を減らすのは射影
- 語の意味：Selection＝選ぶこと

#### 射影（しゃえい / Projection）

- 意味：関係から、指定した属性（列）だけを取り出す演算
- ポイント：SQLのSELECTの直後に書く列名に当たる。取り出した結果に同じ行ができたら1つにまとめる（DISTINCT）
- 語の意味：Projection＝投影

#### 結合（けつごう / Join）

- 意味：2つの関係を、共通する属性の値が条件を満たすタプルどうしでつないで、1つの関係にする演算
- ポイント：直積をとってから選択したものと同じ。共通の列を1つにまとめた等結合を自然結合という
- 語の意味：Join＝つなぐ

#### 商（しょう / Division）

- 意味：関係Rの中で、関係Sのすべてのタプルと組になっている値だけを取り出す演算。R÷S
- ポイント：「全部の科目を履修した学生」のように「すべての〜」を求めるときに使う
- 語の意味：Division＝割り算

### データベース言語の種類

#### DDL（でぃーでぃーえる / Data Definition Language）

- 意味：表・ビュー・インデックスなどの構造を定義するSQLの文。データ定義言語
- ポイント：CREATE（作る）・ALTER（変える）・DROP（消す）
- 語の意味：Data＝データ／Definition＝定義／Language＝言語

#### DML（でぃーえむえる / Data Manipulation Language）

- 意味：データの検索・追加・更新・削除を行うSQLの文。データ操作言語
- ポイント：SELECT・INSERT・UPDATE・DELETE
- 語の意味：Manipulation＝操作

#### DCL（でぃーしーえる / Data Control Language）

- 意味：アクセス権の付与・取消しやトランザクションの確定などを行うSQLの文。データ制御言語
- ポイント：GRANT・REVOKE。COMMIT・ROLLBACKを含めることもある
- 語の意味：Control＝制御

#### 埋込みSQL（うめこみえすきゅーえる / Embedded SQL）

- 意味：C言語やCOBOLなどのプログラムの中にSQL文を書き込んで使う方式。親言語方式
- ポイント：SQLは結果を表（複数行）で返すが、プログラムは1行ずつしか扱えないので、カーソルで1行ずつ取り出す
- 語の意味：Embedded＝埋め込まれた

#### 会話型SQL（かいわがたえすきゅーえる / Interactive SQL）

- 意味：利用者が端末からSQL文を直接入力し、その場で結果を受け取る使い方。独立言語方式
- ポイント：プログラムの中に書く埋込みSQLとの違いを押さえる

#### モジュール言語（もじゅーるげんご / Module Language）

- 意味：SQL文を手続（モジュール）としてプログラムとは別にまとめておき、プログラムからそれを呼び出す方式
- ポイント：SQLをプログラムの中に直接書く埋込みSQLとは違い、SQLの部分を切り離して管理できる

### 表とビュー

#### 実表（じつひょう / Base Table）

- 意味：CREATE TABLEで定義し、実際にデータが記録されている表。基底表
- ポイント：ビュー（仮想の表）のもとになる表。概念スキーマに当たる

#### ビュー（View）

- 意味：実表から必要な行や列を取り出したり結合したりして作る、仮想の表。CREATE VIEWで定義する。条件を満たせば更新可能なビューにもなる
- ポイント：データそのものはもたず、使うたびに定義のSELECT文が実行される。列名は基の表と違う名前にできる（R7秋 問28の正解）。行の絞込み（WHERE）や和集合（UNION）でも定義できる
- 例：R7秋 問28
- 語の意味：View＝見え方

#### 更新可能なビュー（こうしんかのうなびゅー / Updatable View）

- 意味：ビューに対してINSERT・UPDATE・DELETEをすると、その変更を基の実表に反映できるビュー
- ポイント：ビューの1行が実表の1行に対応している必要がある。DISTINCT・GROUP BY・集約関数（SUM・AVG）を使ったビューは、元の行が特定できないので更新できない（R5秋 問28）
- 例：R5秋 問28

#### マテリアライズドビュー（Materialized View）

- 意味：ビューの検索結果を、実際のデータとして記録しておくビュー。実体化ビュー
- ポイント：毎回SELECTを実行しないので検索が速いが、基の表が変わったら更新（リフレッシュ）が要る
- 語の意味：Materialized＝実体化された

#### トリガー（Trigger）

- 意味：表のデータの追加・更新・削除をきっかけに、あらかじめDBMSに定義しておいた処理を自動で起動・実行する仕組み
- ポイント：クライアントのCALL文で呼び出すストアドプロシージャとの違いを押さえる（R5春 問27のエ）
- 語の意味：Trigger＝引き金

#### ストアドプロシージャ（Stored Procedure）

- 意味：よく使う一連のSQL文を手続としてまとめてDBMSに登録しておき、クライアントからCALL文で呼び出して実行する仕組み
- ポイント：SQL文を1つずつネットワークで送らずに済むので、通信量が減る（R6春 問25の正解）。データの変更をきっかけに自動で起動するのはトリガー
- 例：R5春 問27・R6春 問25
- 語の意味：Stored＝しまっておいた／Procedure＝手続

### SELECT文の句

#### WHERE句（うぇあく）

- 意味：SELECT文で、取り出す行の条件を指定する句
- ポイント：グループ化（GROUP BY）より前に働く。集約関数（SUMなど）の条件はWHEREには書けず、HAVINGに書く

#### GROUP BY句（ぐるーぷばいく）

- 意味：指定した列の値が同じ行をまとめてグループにする句
- ポイント：グループごとにSUM・AVG・COUNTなどの集約関数で集計する。SELECTに書ける列は、GROUP BYの列と集約関数だけ（R6春 問26）

#### HAVING句（はびんぐく）

- 意味：GROUP BYでまとめたグループのうち、条件に合うグループだけを残す句
- ポイント：例：HAVING COUNT(*) >= 3。行の条件はWHERE、グループの条件はHAVING

#### ORDER BY句（おーだーばいく）

- 意味：結果の行を、指定した列の値で並べ替える句
- ポイント：ASCが昇順（省略時）、DESCが降順。複数の列を書くと、最初の列が同じときに次の列で並べる

#### DISTINCT（でぃすてぃんくと）

- 意味：SELECTの結果から、同じ行の重複を取り除く指定
- ポイント：SELECT DISTINCT 列名 の形で使う。DISTINCTを使ったビューは更新できない（R5秋 問28のイ）

### 述語

#### BETWEEN（びとうぃーん）

- 意味：値が指定した範囲に入っているかを調べる述語。A BETWEEN x AND y
- ポイント：両端の値（xとy）も含む。x ≦ A AND A ≦ y と同じ

#### IN（いん）

- 意味：値が、並べた値の一覧（または副問合せの結果）のどれかと一致するかを調べる述語
- ポイント：A IN（1，3，5）は A=1 OR A=3 OR A=5 と同じ。NOT INで「どれとも一致しない」

#### LIKE（らいく）

- 意味：文字列が、パターンに合うかを調べる述語
- ポイント：%は0文字以上の任意の文字列、_は任意の1文字。例：商品名 LIKE 'DB%'（DBで始まる）。前方一致の検索にはハッシュインデックスは使えない（R5秋 問26のウ）

#### IS NULL（いずなる）

- 意味：値がNULLかどうかを調べる述語
- ポイント：「= NULL」では調べられない（NULLとの比較は真にも偽にもならない）。NULLでないものはIS NOT NULL

#### EXISTS（いぐじすつ）

- 意味：副問合せの結果に1行でも行があれば真になる述語
- ポイント：NOT EXISTSは、副問合せの結果が1行もないとき真。相関副問合せと組み合わせて「条件に合う在庫が1つもない製品」などを求める（R5秋 問29）
- 例：R5秋 問29
- 語の意味：Exists＝存在する

### 集約関数

#### COUNT（かうんと）

- 意味：行の数を数える集約関数
- ポイント：COUNT(*)は全部の行を数え、COUNT(列名)はその列がNULLでない行だけを数える

#### SUM（さむ）

- 意味：列の値の合計を求める集約関数
- ポイント：NULLは無視する。対象の行が1行もないと結果はNULLになるので、0にしたいときはCOALESCEを使う（R6春 問26）

#### AVG（あぶぇれーじ）

- 意味：列の値の平均を求める集約関数
- ポイント：NULLの行は数に入れずに平均する。副問合せでAVGを求め、平均より大きい行を取り出す問題が出る（R4秋 問28）
- 例：R4秋 問28
- 語の意味：Average＝平均

#### MAXとMIN（まっくすとみん）

- 意味：列の値の最大値・最小値を求める集約関数
- ポイント：学生ごとの初回の実施回を求めるのにMIN（実施回）を使う（R6秋 問30）

#### COALESCE（こあれす）

- 意味：引数を左から順に調べ、最初のNULLでない値を返す関数
- ポイント：COALESCE（SUM（在庫数），0）で、在庫の行がなくSUMがNULLになる部品を0として扱える（R6春 問26の正解）
- 例：R6春 問26
- 語の意味：Coalesce＝合体する

### 結合の種類

#### 内部結合（ないぶけつごう / Inner Join）

- 意味：2つの表で、結合の条件に合う行どうしだけをつなぐ結合。INNER JOIN
- ポイント：相手の表に対応する行がない行は、結果から消える
- 語の意味：Inner＝内側の

#### 左外部結合（ひだりがいぶけつごう / Left Outer Join）

- 意味：左の表の行を全部残し、右の表に対応する行がなければ右の列をNULLにしてつなぐ結合。LEFT OUTER JOIN
- ポイント：在庫が1件もない部品も結果に残せる（R6春 問26）。右の表を全部残すのは右外部結合、両方を全部残すのは完全外部結合
- 例：R6春 問26
- 語の意味：Outer＝外側の

#### 完全外部結合（かんぜんがいぶけつごう / Full Outer Join）

- 意味：左右どちらの表の行も全部残し、対応する行がない側の列をNULLにしてつなぐ結合。FULL OUTER JOIN
- ポイント：左外部結合と右外部結合を合わせた結果になる

#### 自己結合（じこけつごう / Self Join）

- 意味：同じ表に別々の相関名を付けて、表を自分自身と結合すること
- ポイント：例：社員表で「社員」と「上司」を同じ表から取り出す。相関名で2つを区別する

#### UNIONとINTERSECTとEXCEPT（ゆにおんといんたーせくととえくせぷと）

- 意味：2つのSELECTの結果を、和（UNION）・積（INTERSECT）・差（EXCEPT）でまとめるSQLの集合演算子
- ポイント：横持ちの「第1期売上・第2期売上」を縦に並べるには、それぞれをSELECTしてUNIONでまとめる（R3秋 問29の正解）

### 副問合せとウィンドウ関数

#### 副問合せ（ふくといあわせ / Subquery）

- 意味：SELECT文の中に、括弧で囲んで入れた別のSELECT文。外側の行ごとに実行される相関副問合せと違い、ふつうは先に1回だけ実行される
- ポイント：外側の問合せより先に1回だけ実行され、その結果を条件などに使う。例：平均より売上が大きい商品（R4秋 問28）

#### 相関副問合せ（そうかんふくといあわせ / Correlated Subquery）

- 意味：外側の問合せの行の値を使って実行される副問合せ。外側の1行ごとに副問合せが実行される
- ポイント：EXISTSと組み合わせることが多い。例：WHERE 製品.製品番号 = 在庫.製品番号 のように外側の表を参照する（R5秋 問29）

#### 相関名（そうかんめい / Correlation Name）

- 意味：FROM句で表に付ける別名。例：FROM 成績 R1
- ポイント：同じ表を2回使う（自己結合）ときや、副問合せから外側の表を参照するときに使う

#### ウィンドウ関数（うぃんどうかんすう / Window Function）

- 意味：行をグループにまとめずに、指定した範囲（ウィンドウ）の中で順位や累計などを計算し、各行に付ける関数の総称。ROW_NUMBER・RANKなど
- ポイント：OVER（PARTITION BY 区切る列 ORDER BY 並べる列）の形で書く。GROUP BYと違い、行の数は減らない
- 例：R6秋 問30

#### ROW_NUMBER（ろうなんばー）

- 意味：ウィンドウの中で、並べた順に1，2，3…と連番を付けるウィンドウ関数
- ポイント：PARTITION BY 学生番号 ORDER BY 実施回 とすると、学生ごとに実施回の小さい順に番号が付くので、番号＝1で各学生の初回が取り出せる（R6秋 問30の正解）
- 例：R6秋 問30
- 語の意味：Row Number＝行の番号

#### CASE式（けーすしき）

- 意味：条件によって返す値を変える式。CASE WHEN 条件 THEN 値 ELSE 値 END
- ポイント：発注点と在庫数を比べて「必要」「不要」を出すような問題で使う（R6春 問26）

### 更新とカーソル

#### INSERT文（いんさーとぶん）

- 意味：表に新しい行を追加するSQL文
- ポイント：INSERT INTO 表（列，…）VALUES（値，…）。SELECTの結果をまとめて追加する書き方もある

#### UPDATE文（あっぷでーとぶん）

- 意味：表の行の値を変更するSQL文
- ポイント：UPDATE 表 SET 列＝値 WHERE 条件。WHEREを書き忘れると全部の行が変わる

#### DELETE文（でりーとぶん）

- 意味：表から行を削除するSQL文
- ポイント：DELETE FROM 表 WHERE 条件。表そのものを消すのはDDLのDROP TABLE

#### カーソル（Cursor）

- 意味：埋込みSQLで、SELECTの結果（複数行）を1行ずつ取り出すための仕組み
- ポイント：DECLARE（宣言）→ OPEN（開く）→ FETCH（1行取り出す）を繰り返す → CLOSE（閉じる）の順で使う
- 語の意味：Cursor＝位置を示す印
## 9-4 トランザクション処理

### まとめ表

**障害と回復の方法**

| 障害 | 回復の方法 | 使うもの |
| :-: | :-: | :-: |
| トランザクション障害（プログラムの異常終了） | ロールバック | ログの更新前情報 |
| システム障害（OSやDBMSの停止） | コミット済み→ロールフォワード、未コミット→ロールバック | チェックポイント＋ログの更新前・更新後情報（R4春 問29） |
| 媒体障害（ディスクの故障） | バックアップをリストアしてからロールフォワード | バックアップ＋ログの更新後情報 |

**システム障害のときの扱い（チェックポイントが基準）**

| トランザクション | 扱い |
| :-: | :-: |
| チェックポイントより前にコミット | 何もしない（データベースに書き出し済み） |
| チェックポイントの後にコミット | ロールフォワード（R4秋 問29・R5秋 問30・R6春 問27） |
| 障害の時点でコミットしていない | ロールバック（更新がなければ不要） |

**隔離性水準と起きる現象（○＝起きうる）**

| 隔離性水準 | ダーティリード | ノンリピータブルリード | ファントムリード |
| :-: | :-: | :-: | :-: |
| READ UNCOMMITTED | ○ | ○ | ○ |
| READ COMMITTED | ― | ○ | ○ |
| REPEATABLE READ | ― | ― | ○ |
| SERIALIZABLE | ― | ― | ― |

### トランザクションとACID特性

#### トランザクション（Transaction）

- 意味：データベースに対する、分けてはいけない一連の処理のまとまり。例：口座Aから引いて口座Bに足す
- ポイント：全部成功してコミットするか、全部取り消してロールバックするかのどちらか。ACID特性を満たす必要がある
- 語の意味：Transaction＝取引・処理

#### 原子性（げんしせい / Atomicity）

- 意味：トランザクションの処理が、全部実行されるか、全く実行されないかのどちらかになる性質
- ポイント：途中まで実行された状態を残さない。ACIDのA（R4秋 問30）。「全部成功か何もしないか」はべき等とは別の考え（R5春 問28のイ）
- 例：R4秋 問30
- 語の意味：Atomic＝それ以上分けられない

#### 一貫性（いっかんせい / Consistency）

- 意味：トランザクションの前後で、データベースが矛盾のない状態（制約を満たす状態）に保たれる性質
- ポイント：ACIDのC。例：振込の前後で口座の合計額が変わらない（R4秋 問30）
- 語の意味：Consistency＝首尾一貫していること

#### 独立性（どくりつせい / Isolation）

- 意味：複数のトランザクションを同時に実行しても、1つずつ順番に実行した場合と同じ結果になる性質。隔離性
- ポイント：ACIDのI。排他制御（ロック）で実現する。どこまで厳しく守るかを隔離性水準で選べる
- 語の意味：Isolation＝隔離

#### 耐久性（たいきゅうせい / Durability）

- 意味：コミットしたトランザクションの結果は、その後に障害が起きても失われない性質
- ポイント：ACIDのD。ログをディスクに書いてからコミットする（WAL）ことで実現する（R4秋 問30）
- 語の意味：Durability＝長持ちすること

#### コミット（Commit）

- 意味：トランザクションの処理結果を確定させ、データベースに反映させること
- ポイント：コミットした後は取り消せない（耐久性）。取り消すのはロールバック
- 語の意味：Commit＝確約する

### 排他制御

#### 専有ロック（せんゆうろっく / Exclusive Lock）

- 意味：データを更新するときにかけるロック。かけている間、他のトランザクションは読むことも書くこともできない。排他ロック
- ポイント：専有ロックどうし、専有ロックと共有ロックは同時にかけられない
- 語の意味：Exclusive＝独占的な

#### 共有ロック（きょうゆうろっく / Shared Lock）

- 意味：データを読むときにかけるロック。他のトランザクションも共有ロックをかけて読めるが、専有ロック（更新）はかけられない
- ポイント：読み取りどうしは同時にできる。データの異なる版を用意して読み書きを待たせない仕組みはMVCC（R7秋 問29のエ）
- 語の意味：Shared＝共有された

#### ロック粒度（ろっくりゅうど / Lock Granularity）

- 意味：1回のロックでまとめて押さえるデータの大きさ。表・ページ・行など
- ポイント：粒度が大きいと管理は楽だが待ちが増えて同時実行性が下がる。粒度が小さいと同時実行性は上がるがロックの数が増えて管理の負荷が大きい

#### 2相ロッキングプロトコル（にそうろっきんぐぷろとこる / Two-Phase Locking Protocol）

- 意味：トランザクションの中で、ロックをかける段階を全部終えてから、ロックを外す段階に入るという規則
- ポイント：一度でもロックを外したら、新しいロックはかけない。これを守ると、同時に実行しても直列に実行した結果と同じになる（直列化可能性）。2相コミットメントとは別のもの（R7秋 問29のア）
- 語の意味：Two-Phase＝2つの段階

#### デッドロック（Deadlock）

- 意味：2つ以上のトランザクションが、互いに相手のロックしているデータの解放を待ち合い、どれも先に進めなくなる状態
- ポイント：ロックをかける順番を全部のトランザクションでそろえると起きにくい。起きたら、どれか1つをロールバックさせて解消する
- 語の意味：Dead＝止まった／Lock＝錠

#### 待ちグラフ（まちぐらふ / Wait-for Graph）

- 意味：どのトランザクションがどのトランザクションのロック解放を待っているかを矢印で表した図
- ポイント：矢印が輪（閉路）になっていればデッドロック。DBMSはこれでデッドロックを見つける（R3春 問30のウ）

#### セマフォ（Semaphore）

- 意味：共有する資源を使える数を表す変数を、P操作（使う・1減らす）とV操作（返す・1増やす）で増減させて排他制御する仕組み
- ポイント：OSのプロセス間の排他制御でも使う。データベースではロックと並ぶ同時実行制御の方式
- 語の意味：Semaphore＝腕木式の信号機

### 同時実行の方式

#### 多版同時実行制御（たはんどうじじっこうせいぎょ / Multi-Version Concurrency Control）

- 意味：同じデータ項目について更新前と更新後など複数の版を用意し、読むトランザクションには確定した版を見せることで、読み取りと更新を待ち合わせずに同時に実行できるようにする仕組み。略してMVCC
- ポイント：読み取りが更新のロックを待たないので、同時実行性が高い（R7秋 問29の正解）。PostgreSQLなど多くのDBMSが使う
- 例：R7秋 問29
- 語の意味：Multi-Version＝複数の版／Concurrency＝同時実行／Control＝制御

#### 楽観的排他制御（らっかんてきはいたせいぎょ / Optimistic Concurrency Control）

- 意味：ロックをかけずに処理を進め、更新して確定するときに、他のトランザクションが同じデータを変えていないかを調べる方式
- ポイント：変えられていたら処理をやり直す。競合が少ないときに効率が良い。最初からロックをかけるのが悲観的排他制御
- 語の意味：Optimistic＝楽観的な

#### Wait-Die方式（うぇいとだいほうしき / Wait-Die Scheme）

- 意味：ロック待ちになったとき、古い（先に始まった）トランザクションは待ち、新しいトランザクションは自分がロールバックしてやり直す方式
- ポイント：トランザクションの開始時刻（タイムスタンプ）で優先順位を決め、デッドロックを起こさない。新しいほうが「死ぬ（Die）」
- 語の意味：Wait＝待つ／Die＝死ぬ

#### Wound-Wait方式（うーんどうぇいとほうしき / Wound-Wait Scheme）

- 意味：ロック待ちになったとき、古いトランザクションは相手の新しいトランザクションをロールバックさせてロックを奪い、新しいトランザクションは待つ方式
- ポイント：Wait-Die方式と逆で、古いほうが相手を「傷つける（Wound）」。どちらも古いトランザクションを優先する
- 語の意味：Wound＝傷つける／Wait＝待つ

### 同時実行で起きる現象

#### ダーティリード（Dirty Read）

- 意味：他のトランザクションがまだコミットしていない更新途中のデータを読んでしまうこと
- ポイント：相手がロールバックすると、存在しなかった値を読んだことになる。READ COMMITTED以上の隔離性水準で防げる
- 語の意味：Dirty＝汚れた／Read＝読み取り

#### ノンリピータブルリード（Non-Repeatable Read）

- 意味：同じトランザクションの中で同じ行を2回読んだとき、間に他のトランザクションが更新・コミットしたために、値が変わってしまうこと
- ポイント：REPEATABLE READ以上で防げる。行の「値」が変わる現象
- 語の意味：Non-Repeatable＝繰り返せない

#### ファントムリード（Phantom Read）

- 意味：同じ条件で2回検索したとき、間に他のトランザクションが行を追加・削除したために、結果の行の数が変わってしまうこと
- ポイント：前になかった行が「幽霊（ファントム）」のように現れる。SERIALIZABLEで防げる。行の「数」が変わる現象
- 語の意味：Phantom＝幽霊

#### ロストアップデート（Lost Update）

- 意味：2つのトランザクションが同じデータを読んで、それぞれ更新したため、先にした更新が後の更新で上書きされて消えること
- ポイント：排他制御（専有ロック）をしないと起きる。最も基本的な同時実行の問題
- 語の意味：Lost＝失われた／Update＝更新

#### 隔離性水準（かくりせいすいじゅん / Isolation Level）

- 意味：同時に実行するトランザクションどうしを、どれだけ厳しく切り離すかの段階。READ UNCOMMITTED・READ COMMITTED・REPEATABLE READ・SERIALIZABLEの4つ
- ポイント：厳しくするほど起きる現象は減るが、待ちが増えて性能が下がる。SQLのSET TRANSACTIONで指定する

#### 直列化可能性（ちょくれつかかのうせい / Serializability）

- 意味：複数のトランザクションを同時に実行した結果が、どれかの順番で1つずつ実行した結果と同じになること
- ポイント：独立性を最も厳しく満たした状態。2相ロッキングプロトコルで実現できる。べき等とは別の考え（R5春 問28のエ）

### 分散トランザクション

#### 2相コミットメント（にそうこみっとめんと / Two-Phase Commit）

- 意味：分散データベースで、調停者（コーディネーター）が全部の参加者に「コミットできるか」を問い合わせ（第1相）、全員が可と答えたらコミットの決定を、1つでも否ならロールバックの決定を送る（第2相）方式
- ポイント：全部のサイトで原子性を保つ。調停者が決定を送る直前に障害が起きると、可と答えた参加者はコミットすべきかロールバックすべきか判断できない状態になる（R6秋 問27）
- 例：R6秋 問27
- 語の意味：Two-Phase＝2つの段階／Commit＝確定

#### 補償トランザクション（ほしょうとらんざくしょん / Compensating Transaction）

- 意味：すでにコミットした処理の効果を、逆の処理をするトランザクションを実行して打ち消すこと
- ポイント：例：注文の登録を、注文の取消しで打ち消す。ロールバックできない（コミット済みの）処理を元に戻すのに使う。Sagaパターンの部品
- 語の意味：Compensating＝埋め合わせる

#### Sagaパターン（さーがぱたーん / Saga Pattern）

- 意味：複数のサービスにまたがる処理を、サービスごとの小さなトランザクションの列にして順に実行し、途中で失敗したら、それまでの処理を補償トランザクションで打ち消すパターン
- ポイント：マイクロサービスで、2相コミットメントのように全部をロックせずに整合性を保つ。結果整合性になる
- 語の意味：Saga＝長い物語

#### TCCパターン（てぃーしーしーぱたーん / Try-Confirm/Cancel Pattern）

- 意味：分散した処理を、仮押さえ（Try）→確定（Confirm）または取消し（Cancel）の3段階で行うパターン
- ポイント：例：座席を仮押さえして、全部そろったら確定、だめなら取り消す。2相コミットメントを業務の処理で行う考え方
- 語の意味：Try＝試す／Confirm＝確定する／Cancel＝取り消す

#### べき等（べきとう / Idempotent）

- 意味：同じ操作を何回実行しても、1回だけ実行した結果と同じになる性質
- ポイント：通信の失敗で同じ要求を再送しても結果が変わらないので、分散システムで再試行を安全にできる（R5春 問28の正解）
- 例：R5春 問28
- 語の意味：Idem＝同じ／Potent＝力がある

### 障害回復の手法

#### ロールバック（Rollback）

- 意味：ログの更新前情報（更新前ログ）を使って、トランザクションの更新を取り消し、開始前の状態に戻すこと。後退復帰、バックワードリカバリ
- ポイント：プログラムの異常終了や、システム障害のときにコミットしていなかったトランザクションに使う（R3秋 問27のエ）
- 語の意味：Roll back＝巻き戻す

#### ロールフォワード（Roll Forward）

- 意味：ログの更新後情報（更新後ログ）を使って、コミットしたトランザクションの更新をやり直し、障害の直前の状態にすること。前進復帰、フォワードリカバリ
- ポイント：システム障害ではチェックポイントの後にコミットしたもの、媒体障害ではバックアップの後にコミットしたものに使う（R4秋 問29・R6春 問27の正解）
- 例：R4秋 問29・R5秋 問30・R6春 問27
- 語の意味：Roll forward＝先へ進める

#### シャドウページ法（しゃどうぺーじほう / Shadow Paging）

- 意味：更新するページを別の場所に書き、コミットのときにページの対応表を新しいほうへ切り替える回復の方法
- ポイント：元のページ（シャドウページ）が残っているので、障害時は対応表を戻すだけで更新前に戻せる。ログを使わない（R6春 問27のイ）

#### ウォームスタート（Warm Start）

- 意味：システム障害の後、ログとチェックポイントを使って、障害の直前の状態まで回復させてから再開すること
- ポイント：コミット済みはロールフォワード、未コミットはロールバックして再開する。主記憶の内容だけを失った場合に使う
- 語の意味：Warm＝温かい（途中から）

#### コールドスタート（Cold Start）

- 意味：障害の後、データベースを初期の状態やバックアップから立ち上げ直して再開すること
- ポイント：媒体障害でデータが壊れたときなど、ウォームスタートができない場合に使う
- 語の意味：Cold＝冷たい（最初から）

### ログとチェックポイント

#### ジャーナルファイル（Journal File）

- 意味：データベースへの更新の内容（更新前情報・更新後情報）を、時刻の順に記録したファイル。ログファイル
- ポイント：障害回復に使う。undo/redo方式では更新前情報も更新後情報も両方必要（R4春 問29）
- 例：R4春 問29
- 語の意味：Journal＝日誌

#### 更新前情報（こうしんまえじょうほう / Before Image）

- 意味：ログに記録する、更新する前のデータの値。更新前ログ、ビフォーイメージ
- ポイント：ロールバック（undo）に使う。媒体障害でロールフォワードするときに使うのは更新前情報ではなく更新後情報（R3秋 問27のウ）

#### 更新後情報（こうしんごじょうほう / After Image）

- 意味：ログに記録する、更新した後のデータの値。更新後ログ、アフターイメージ
- ポイント：ロールフォワード（redo）に使う。異常終了したトランザクションを戻すのに使うのは更新後情報ではなく更新前情報（R3秋 問27のエ）

#### チェックポイント（Checkpoint）

- 意味：主記憶のデータベースバッファの内容を、ディスク（二次記憶）に書き出す時点。その時点の情報をログに記録する
- ポイント：チェックポイントより前にコミットしたトランザクションは、障害回復のときに何もしなくてよい。回復の時間を短くする仕組み（R3秋 問27・R6秋 問31の正解）
- 例：R3秋 問27・R6秋 問31
- 語の意味：Checkpoint＝点検の地点

#### WALプロトコル（わるぷろとこる / Write-Ahead Logging）

- 意味：データベースの更新をディスクに書き出す前に、必ずログを先にディスクへ書くという規則
- ポイント：コミットの時点ではログさえ書かれていれば、データ本体はまだ書かれていなくても障害から回復できる。耐久性を保つ
- 語の意味：Write＝書く／Ahead＝先に／Logging＝記録

#### セーブポイント（Savepoint）

- 意味：トランザクションの途中に任意に設定できる時点。プログラムでその時点まで部分的にロールバックできる
- ポイント：チェックポイント（DBMSがバッファを書き出す時点）とは別のもの（R6秋 問31のウ）
- 語の意味：Save＝保存する／Point＝地点

### バックアップ

#### フルバックアップ（Full Backup）

- 意味：対象のデータを全部コピーして保存するバックアップ
- ポイント：復元はこれ1つで済むが、取るのに時間と容量がかかる。差分バックアップ・増分バックアップの起点になる
- 語の意味：Full＝全部の

#### 差分バックアップ（さぶんばっくあっぷ / Differential Backup）

- 意味：最後のフルバックアップから後に変わったデータを、全部まとめて保存するバックアップ
- ポイント：復元は「フル＋最後の差分」の2つで済む。日がたつほど1回の差分が大きくなる
- 語の意味：Differential＝差の

#### 増分バックアップ（ぞうぶんばっくあっぷ / Incremental Backup）

- 意味：前回のバックアップ（フルでも増分でも）から後に変わったデータだけを保存するバックアップ
- ポイント：1回の量は少なく速いが、復元には「フル＋その後の全部の増分」を順に戻す必要がある
- 語の意味：Incremental＝増えた分の

#### ダンプファイル（Dump File）

- 意味：ある時点のデータベースの内容を、そのまま丸ごと書き出したファイル
- ポイント：バックアップとして保存し、媒体障害のときにリストアする
- 語の意味：Dump＝どさっと出す

#### リストア（Restore）

- 意味：バックアップしておいたデータを、記憶装置に書き戻すこと
- ポイント：媒体障害では、リストアしただけではバックアップ時点の状態なので、その後ログの更新後情報でロールフォワードして最新にする（R3秋 問27のウ）
- 語の意味：Restore＝元に戻す

#### 世代管理（せだいかんり / Generation Management）

- 意味：バックアップを1つだけでなく、何回分か前のもの（世代）まで残して管理すること
- ポイント：最新のバックアップ自体が壊れていたり、誤ったデータごと保存されていたりしても、古い世代から戻せる

### インデックス

#### B+木インデックス（びーぷらすぎいんでっくす / B+ Tree Index）

- 意味：キーの値を並べた木構造で、葉のノードどうしもつながっている索引
- ポイント：値の順に並んでいるので、範囲の検索（1万円以上、今月など）や前方一致・並べ替えに強い。等しい値の検索だけならハッシュインデックスのほうが速い
- 語の意味：B＝Balanced（釣り合った）／Tree＝木

#### ハッシュインデックス（Hash Index）

- 意味：キーの値をハッシュ関数で計算して、格納場所を直接求める索引
- ポイント：「利用者IDが'1001'」のような一致検索（等価検索）がとても速い。値の順に並んでいないので、範囲の検索や前方一致には使えない（R5秋 問26・R7秋 問27の正解）
- 例：R5秋 問26・R7秋 問27
- 語の意味：Hash＝細かく刻む

#### ビットマップインデックス（Bitmap Index）

- 意味：列の値ごとに、各行がその値をもつかどうかを1と0のビットの並びで表した索引
- ポイント：性別のように値の種類が少ない列に向く。複数の条件のAND・ORをビット演算で速く求められる。更新が多い表には向かない
- 語の意味：Bitmap＝ビットの地図

#### クラスタ化インデックス（Clustered Index）

- 意味：表の行そのものを、索引のキーの順に物理的に並べて格納する索引
- ポイント：キーの範囲の検索で、続けて読めるので速い。並べ方は1通りしかないので、1つの表に1つだけ作れる
- 語の意味：Clustered＝まとめて集めた

#### ユニークインデックス（Unique Index）

- 意味：キーの値の重複を許さない索引
- ポイント：一意性制約や主キー制約を実現するのに使われる

#### カバリングインデックス（Covering Index）

- 意味：問合せに必要な列がすべて索引に含まれていて、表本体を読まずに索引だけで結果を返せる索引
- ポイント：表を読みに行かないので速い。索引に入れる列が増えるぶん容量と更新の負荷は増える
- 語の意味：Covering＝覆う

#### 転置インデックス（てんちいんでっくす / Inverted Index）

- 意味：文書の中の単語ごとに、その単語を含む文書の一覧を記録した索引
- ポイント：全文検索エンジンで使う。単語から文書を引くので、文書から単語を引く普通の向きと逆（転置）になっている
- 語の意味：Inverted＝逆にした

### 実行計画

#### 実行計画（じっこうけいかく / Execution Plan）

- 意味：SQL文を実行するときに、どの索引を使うか、どの順で表を結合するかなどの、具体的な処理の手順
- ポイント：DBMSのオプティマイザが作る。EXPLAIN文で見て、遅いSQLのチューニングに使う

#### コストベースオプティマイザ（Cost-Based Optimizer）

- 意味：表の行数や値の分布などの統計情報から、各手順の処理コストを見積もり、最もコストの小さい実行計画を選ぶ仕組み
- ポイント：統計情報が必要。統計情報が古いと誤った計画を選ぶ（R3春 問30）
- 例：R3春 問30
- 語の意味：Cost＝費用／Based＝もとにした／Optimizer＝最適化するもの

#### ルールベースオプティマイザ（Rule-Based Optimizer）

- 意味：「索引があれば使う」のように、あらかじめ決めた規則の優先順位で実行計画を選ぶ仕組み
- ポイント：統計情報を使わない。データの量や分布が変わっても計画が変わらない

#### 統計情報（とうけいじょうほう / Statistics）

- 意味：表の行数、列の値の種類の数や分布、索引の状態など、データベースの中身についての情報
- ポイント：コストベースオプティマイザが実行計画を作るのに使う（R3春 問30の正解）。データが大きく変わったら取り直す

### アクセス制御

#### GRANT文（ぐらんとぶん）

- 意味：利用者（またはロール）に、表やビューに対する権限を与えるSQL文
- ポイント：例：GRANT SELECT, INSERT ON 受注 TO 担当者A。WITH GRANT OPTIONを付けると、受け取った人が他の人に権限を与えられる
- 語の意味：Grant＝与える

#### REVOKE文（りぼーくぶん）

- 意味：GRANT文で与えた権限を取り消すSQL文
- ポイント：例：REVOKE INSERT ON 受注 FROM 担当者A
- 語の意味：Revoke＝取り消す

#### 参照権限（さんしょうけんげん / SELECT Privilege）

- 意味：表やビューのデータを検索（SELECT）できる権限
- ポイント：一部の列や行だけ見せたいときは、ビューを作ってビューに参照権限を与える

#### 挿入権限（そうにゅうけんげん / INSERT Privilege）

- 意味：表に新しい行を追加（INSERT）できる権限
- ポイント：更新（UPDATE）・削除（DELETE）の権限とは別々に与える

#### 更新権限（こうしんけんげん / UPDATE Privilege）

- 意味：表の行の値を変更（UPDATE）できる権限
- ポイント：列を指定して、特定の列だけ更新できるように与えることもできる

#### 削除権限（さくじょけんげん / DELETE Privilege）

- 意味：表から行を削除（DELETE）できる権限
- ポイント：表そのものを消す（DROP TABLE）権限とは別

#### ロール（Role）

- 意味：複数の権限をまとめて名前を付けたもの。利用者にロールを与えると、まとめて権限が付く
- ポイント：人の異動のたびに権限を1つずつ付け替えずに済む
- 語の意味：Role＝役割
## 9-5 データベース応用

### まとめ表

| A＋P | 整合性（結果整合性で妥協） | 多くのNoSQL（R4春 問26） |

### データをためる場所

#### データウェアハウス（Data Warehouse）

- 意味：複数の業務システムからデータを集め、形式をそろえて時系列に蓄積した、分析のためのデータベース
- ポイント：意思決定を支援するため、ある主題に基づくデータを、現在の情報だけでなく過去の情報も含めて蓄積する（R6春 問29のイ）。更新より検索・集計が中心
- 語の意味：Data＝データ／Warehouse＝倉庫

#### データマート（Data Mart）

- 意味：データウェアハウスのデータの一部を、特定の部門や用途のために切り出して格納したデータベース
- ポイント：営業部門用・経理部門用のように、使う人に合わせて小さくまとめる（R3春 問31のイ・R4春 問30のイ）
- 語の意味：Mart＝市場・店

#### データレイク（Data Lake）

- 意味：後で必要に応じて加工するために、様々なデータを発生したままの形で格納しておく場所
- ポイント：構造化データも、画像・ログ・センサーのデータのような非構造化データも、形を整えずにそのままためる（R3春 問31の正解）。整えてからためるデータウェアハウスとの違いが出る
- 例：R3春 問31
- 語の意味：Lake＝湖

#### オペレーショナルデータストア（Operational Data Store）

- 意味：複数の業務システムのデータを集めて統合した、現在の業務のためのデータベース。略してODS
- ポイント：データウェアハウスと違い、過去の履歴より最新の状態を保つ。データウェアハウスへ送る前の中継に使うこともある
- 語の意味：Operational＝業務の／Store＝ためる所

### データを集める処理

#### ETL（いーてぃーえる / Extract/Transform/Load）

- 意味：業務システムからデータを取り出し（Extract）、形式や値をそろえて変換し（Transform）、データウェアハウスに書き込む（Load）一連の処理
- ポイント：変換してから書き込む。書き込んでから変換するのがELT
- 語の意味：Extract＝取り出す／Transform＝変換する／Load＝書き込む

#### ELT（いーえるてぃー / Extract/Load/Transform）

- 意味：データを取り出したら、先にそのまま書き込み（Load）、後から書き込み先の中で変換（Transform）する処理
- ポイント：大量のデータを速く取り込める。処理能力の高いクラウドのデータウェアハウスやデータレイクで使う。ETLとは変換と書込みの順番が逆
- 語の意味：Extract＝取り出す／Load＝書き込む／Transform＝変換する

#### データクレンジング（Data Cleansing）

- 意味：集めたデータの誤り・表記の揺れ・重複・欠けている値などを見つけて、直したり取り除いたりすること
- ポイント：例：「（株）」と「株式会社」をそろえる。ETLの変換（Transform）の段階で行う。分析の結果の質を左右する
- 語の意味：Cleansing＝洗浄

#### 名寄せ（なよせ / Name Identification）

- 意味：別々のシステムに登録された同じ顧客などのデータを見つけて、1つにまとめること
- ポイント：氏名・住所・電話番号の表記の揺れをそろえてから照らし合わせる。データクレンジングの一部として行う

### 分析の処理

#### OLAP（おーらっぷ / Online Analytical Processing）

- 意味：データウェアハウスやデータマートのデータを、商品・地域・期間などの多くの切り口（次元）から対話的に集計・分析すること。多次元分析
- ポイント：ドリルダウン・スライシング・ダイシングなどの操作をする（R3春 問31のウ）。日々の取引を処理するOLTPとの違いが出る
- 語の意味：Online＝その場で／Analytical＝分析の／Processing＝処理

#### OLTP（おーえるてぃーぴー / Online Transaction Processing）

- 意味：受注・入金・予約のような日々の取引（トランザクション）を、端末からの要求に応じてその場で処理すること
- ポイント：短い更新処理を大量に速くこなし、ACID特性を守る。分析のためのOLAPとの違いを押さえる
- 語の意味：Transaction＝取引／Processing＝処理

#### データマイニング（Data Mining）

- 意味：大量に蓄積されたデータを統計や機械学習で分析し、単なる検索では分からない隠れた規則や相関関係を見つけ出すこと
- ポイント：例：「おむつとビールが一緒に買われる」のような関係。仮説を立てずに知識を掘り出す（R4春 問30の正解、R3春 問31のア）
- 例：R4春 問30
- 語の意味：Mining＝採掘

#### ドリルダウン（Drill Down）

- 意味：OLAPで、集計の単位を細かくしていき、より詳しいデータを見る操作。例：年→月→日
- ポイント：反対に、まとめて粗くする操作はドリルアップ（ロールアップ）
- 語の意味：Drill down＝掘り下げる

#### スライシング（Slicing）

- 意味：OLAPで、多次元のデータの、ある次元の値を1つに固定して、残りの次元で切り出して見る操作
- ポイント：例：「2026年10月」に固定して、商品×地域の表を見る。立方体を薄く切るイメージ
- 語の意味：Slice＝薄く切る

#### ダイシング（Dicing）

- 意味：OLAPで、集計の軸にする次元を入れ替えて、別の切り口からデータを見る操作
- ポイント：例：商品×地域の表を、地域×期間の表に切り替える。サイコロを転がすイメージ
- 語の意味：Dice＝サイコロ

### スタースキーマ

#### スタースキーマ（Star Schema）

- 意味：分析の対象になる数値をもつファクトテーブルを中心に置き、その周りに分析の切り口のディメンジョンテーブルを星形に配置したデータウェアハウスの表の構成
- ポイント：分析しやすいよう、ディメンジョンテーブルはあえて正規化しない（非正規化）
- 例：R6春 問28
- 語の意味：Star＝星／Schema＝構造

#### ファクトテーブル（Fact Table）

- 意味：スタースキーマの中心に置く、売上金額・数量などの分析の対象になるトランザクションデータ（事実）を記録した表
- ポイント：各ディメンジョンテーブルへの外部キーと、数値（メジャー）をもつ。行数が最も多い（R6春 問28の正解）
- 例：R6春 問28
- 語の意味：Fact＝事実

#### ディメンジョンテーブル（Dimension Table）

- 意味：スタースキーマで、商品・顧客・店舗・日付など、分析の切り口（次元）の情報を記録した表
- ポイント：ファクトテーブルの周りに置く。コストベースオプティマイザが使う統計情報とは別のもの（R3春 問30のア）
- 語の意味：Dimension＝次元

#### スノーフレークスキーマ（Snowflake Schema）

- 意味：スタースキーマのディメンジョンテーブルを、さらに正規化して枝分かれさせた表の構成
- ポイント：例：商品→商品分類→大分類。重複は減るが、結合が増えて検索は遅くなりやすい
- 語の意味：Snowflake＝雪の結晶

#### サマリテーブル（Summary Table）

- 意味：よく使う集計の結果を、あらかじめ計算して記録しておく表
- ポイント：毎回ファクトテーブル全体を集計せずに済むので速い。元のトランザクションデータを格納するのはファクトテーブル（R6春 問28のア）
- 語の意味：Summary＝要約

### 分散データベースの透過性

#### 位置に対する透過性（いちにたいするとうかせい / Location Transparency）

- 意味：利用者やプログラムが、表がどのサーバにあるかを意識せずに使えること
- ポイント：分散データベースの最も基本の透過性。どこにあっても1つのデータベースのように見える

#### 移動に対する透過性（いどうにたいするとうかせい / Migration Transparency）

- 意味：表が別のサーバに移動されても、利用者やプログラムがそれを意識する必要がないこと
- ポイント：プログラムを書き換えずにデータの置き場所を変えられる（R3秋 問30のウ）

#### 分割に対する透過性（ぶんかつにたいするとうかせい / Fragmentation Transparency）

- 意味：1つの表が複数のサーバに分割して配置されていても、利用者やプログラムがそれを意識する必要がないこと
- ポイント：行で分ける水平分割・列で分ける垂直分割のどちらでも、1つの表として扱える（R3秋 問30のイ）

#### 複製に対する透過性（ふくせいにたいするとうかせい / Replication Transparency）

- 意味：同じ表が複数のサーバに重複して存在していても、利用者やプログラムがそれを意識する必要がないこと
- ポイント：どの複製を読むか、更新をどう全部の複製に反映するかはDBMSが受け持つ（R3秋 問30の正解）
- 例：R3秋 問30

#### 異種性に対する透過性（いしゅせいにたいするとうかせい / Heterogeneity Transparency）

- 意味：サーバごとにDBMSの種類が違っていても、利用者やプログラムがその違いを意識する必要がないこと
- ポイント：違う製品のDBMSを1つのデータベースのように扱える（R3秋 問30のア）

### 分散の方式

#### レプリケーション（Replication）

- 意味：あるデータベースのデータの複製を別のサーバに作り、更新を複製先にも反映させて同じ内容に保つこと
- ポイント：負荷分散（読み取りを複製先で処理）や、障害時の切替えに使う。データを複数のサーバに複製して性能と可用性を上げる（R4春 問30のエ、R5春 問28のウ）
- 語の意味：Replication＝複製

#### 水平分散（すいへいぶんさん / Horizontal Distribution）

- 意味：役割が同じ複数のサーバに処理やデータを分けて受け持たせる分散の方式
- ポイント：サーバを足して処理能力を上げやすい（スケールアウト）。役割ごとに分けるのは垂直分散

#### 垂直分散（すいちょくぶんさん / Vertical Distribution）

- 意味：画面の処理・業務の処理・データ管理のように、役割の違う複数のサーバに処理を分けて受け持たせる分散の方式
- ポイント：クライアントサーバシステムや3層アーキテクチャが代表

#### 水平分割（すいへいぶんかつ / Horizontal Partitioning）

- 意味：1つの表を、行の単位で分けて（例：東日本の顧客と西日本の顧客）別々に格納すること。分けたものを別々のサーバに置くとシャーディング
- ポイント：分けたそれぞれは同じ列をもつ。全部を和（UNION）でまとめると元の表に戻る

#### 垂直分割（すいちょくぶんかつ / Vertical Partitioning）

- 意味：1つの表を、列の単位で分けて別々に格納すること
- ポイント：分けたそれぞれに主キーを残しておき、主キーで結合すると元の表に戻る。よく使う列とあまり使わない列を分ける

#### シャーディング（Sharding）

- 意味：表を水平分割した一つ一つ（シャード）を、それぞれ別のサーバに置いて負荷を分散させる方法
- ポイント：水平分割を複数のサーバで行うもの。どの行をどのサーバに置くかはキーの値（範囲やハッシュ）で決める
- 語の意味：Shard＝かけら

### CAP定理とBASE特性

#### CAP定理（きゃっぷていり / CAP Theorem）

- 意味：分散システムは、整合性（Consistency）・可用性（Availability）・分断耐性（Partition tolerance）の3つを同時には満たせず、満たせるのは2つまでという定理
- ポイント：AとPを満たすシステムは、ネットワークが分断されても応答を返し続けるが、ノードによって古いデータを返すことがある（整合性を満たさない）（R4春 問26）
- 例：R4春 問26
- 語の意味：Consistency＝整合性／Availability＝可用性／Partition＝分断

#### BASE特性（べーすとくせい / BASE Properties）

- 意味：基本的にいつでも使え（Basically Available）、状態は厳密でなくてよく（Soft state）、最終的には整合する（Eventually consistent）という、NoSQLの多くが選ぶ性質
- ポイント：ACID特性の厳しい整合性をゆるめ、可用性と性能を優先する。ACIDと対になるように名前が付けられている（酸と塩基）
- 例：R7秋 問26
- 語の意味：Basically＝基本的に／Soft＝やわらかい／Eventually＝最終的に

#### 結果整合性（けっかせいごうせい / Eventual Consistency）

- 意味：更新した直後はノードによって値が違うことがあるが、障害がなければ、いつかは全部のノードに更新が反映されて同じ値になるという考え方。BASE特性のE
- ポイント：BASE特性のE。同時に参照したら全部のノードが必ず同じ結果を返すのは強い整合性（R7秋 問26の正解）
- 例：R7秋 問26
- 語の意味：Eventual＝最終的な

#### 分断耐性（ぶんだんたいせい / Partition Tolerance）

- 意味：ノード間のネットワークが分断されて通信できなくなっても、システム全体としては動き続けられる性質
- ポイント：CAP定理のP。分散システムでは分断は避けられないので、実際にはCとAのどちらを優先するかを選ぶことになる

#### スプリットブレイン（Split Brain）

- 意味：クラスタのノード間の通信が切れたとき、それぞれが「相手が止まった」と判断して両方が主系として動き出してしまう状態
- ポイント：両方で別々にデータが更新され、矛盾が起きる。過半数のノードと通信できる側だけを動かす（クォーラム）などで防ぐ
- 語の意味：Split＝割れた／Brain＝脳

### ビッグデータの基盤

#### ビッグデータ（Big Data）

- 意味：量（Volume）が多く、種類（Variety）が多様で、発生する速さ（Velocity）が速いため、従来のデータベースでは扱いにくいデータ
- ポイント：SNSの投稿・センサーのデータ・ログなど。NoSQL・Hadoop・Sparkなどの分散処理の技術で扱う
- 語の意味：Big＝大きい／Data＝データ

#### Apache Hadoop（あぱっちはどぅーぷ）

- 意味：大量のデータを多数のサーバに分散して格納し、並列に処理するためのオープンソースのフレームワーク
- ポイント：分散ファイルシステムのHDFSと、処理を分けて集めるMapReduceが中心。ディスクに書きながら処理する
- 語の意味：Hadoop＝作者の子どものぬいぐるみの名前

#### Apache Spark（あぱっちすぱーく）

- 意味：大量のデータを、主記憶（メモリ）上で分散して高速に処理するオープンソースのフレームワーク
- ポイント：途中の結果をメモリに置くので、ディスクに書くHadoopのMapReduceより繰り返しの処理（機械学習など）が速い
- 語の意味：Spark＝火花

#### HDFS（えいちでぃーえふえす / Hadoop Distributed File System）

- 意味：Hadoopで使う分散ファイルシステム。大きなファイルをブロックに分け、複数のサーバに複製して置く
- ポイント：どれかのサーバが壊れても、別のサーバの複製から読める。CephやGlusterFSも分散ファイルシステム
- 語の意味：Distributed＝分散した／File System＝ファイルの管理の仕組み

#### Apache Hive（あぱっちはいぶ）

- 意味：Hadoopに格納された大量のデータを、SQLに似た言語で問い合わせられるようにする仕組み
- ポイント：大規模なデータセットのクエリエンジンの1つ。Prestoも同じ仲間で、複数のデータの置き場所をまたいで速く問い合わせられる
- 語の意味：Hive＝蜂の巣

#### MapReduce（まっぷりでゅーす）

- 意味：大量のデータの処理を、多数のサーバで分けて行う段階（Map）と、その結果を集めてまとめる段階（Reduce）に分けて並列に処理する方式
- ポイント：例：単語の出現回数を、文書ごとに数えて（Map）から合計する（Reduce）。Hadoopの処理の仕組み
- 語の意味：Map＝対応付ける／Reduce＝まとめる

### データの形

#### 構造化データ（こうぞうかでーた / Structured Data）

- 意味：関係データベースの表のように、項目と型があらかじめ決まった形で整理されたデータ
- ポイント：SQLで検索・集計しやすい。企業のデータのうち、実は一部にすぎない

#### 半構造化データ（はんこうぞうかでーた / Semi-structured Data）

- 意味：決まった表の形ではないが、タグや項目名で構造が示されているデータ。JSON・XML・CSVなど
- ポイント：データごとに項目が違ってもよい。ドキュメント指向データベースで扱いやすい

#### 非構造化データ（ひこうぞうかでーた / Unstructured Data）

- 意味：決まった構造をもたないデータ。文書・画像・音声・動画・メールの本文など
- ポイント：そのままでは検索・集計しにくい。データレイクにそのままためて、必要に応じて加工する

#### ストリーミングデータ（Streaming Data）

- 意味：センサーやログなどから、途切れなく次々と発生し続けるデータ
- ポイント：ためてからまとめて処理（バッチ処理）するのではなく、届いた順にその場で処理する（ストリーム処理）
- 語の意味：Stream＝流れ

### データ資源管理

#### リポジトリ（Repository）

- 意味：ソフトウェアの開発や保守で使う、設計書・プログラム・データの定義などの様々な情報を一元的に管理する場所
- ポイント：データの定義だけを集めたデータディクショナリより範囲が広い
- 語の意味：Repository＝貯蔵庫

#### IRDS（あいあーるでぃーえす / Information Resource Dictionary System）

- 意味：組織の情報資源（データ・プログラム・システムなど）の定義を管理するための、データディクショナリの国際規格。情報資源辞書システム
- ポイント：データディクショナリを標準化したもの
- 語の意味：Information Resource＝情報資源／Dictionary＝辞書／System＝仕組み

#### ファクトデータベース（Fact Database）

- 意味：統計の数値・物質の性質・株価など、事実のデータそのものを収めたデータベース
- ポイント：文献の書誌情報や所在を収めて、元の資料へ案内するリファレンスデータベースとの違いを押さえる
- 語の意味：Fact＝事実

#### リファレンスデータベース（Reference Database）

- 意味：文献の題名・著者・掲載誌などの書誌情報や、情報の所在を収めたデータベース。参照型データベース
- ポイント：データそのものではなく、元の資料を探す手がかりを提供する
- 語の意味：Reference＝参照

#### データベースサービス（Database Service）

- 意味：クラウド事業者が、データベースの構築・運用・バックアップなどをまとめて提供するサービス。DBaaS
- ポイント：利用者はサーバやDBMSの管理をせずにデータベースを使える。PaaSの一種
- 語の意味：DBaaS＝Database as a Service（サービスとしてのデータベース）

### ブロックチェーンとデータベース

#### ブロックチェーン（Blockchain）

- 意味：取引の記録をまとめたブロックを、前のブロックのハッシュ値を含めて鎖のようにつなぎ、多数の参加者で同じ記録を共有する仕組み
- ポイント：1つのブロックを改ざんすると、後ろのブロックのハッシュ値が全部合わなくなるので、改ざんが分かる。中央の管理者のいない分散型の台帳
- 語の意味：Block＝かたまり／Chain＝鎖

#### コンセンサスアルゴリズム（Consensus Algorithm）

- 意味：ブロックチェーンなどの分散システムで、参加者のあいだでどの記録を正しいとするかを合意する手順の総称。PoW・PoSなど
- ポイント：計算量で決めるPoW（Proof of Work）、保有量で決めるPoS（Proof of Stake）などがある
- 語の意味：Consensus＝合意／Algorithm＝手順

#### ファイナリティ（Finality）

- 意味：取引の記録が確定し、後から取り消されたり覆されたりしない状態になること
- ポイント：PoWでは、後に続くブロックが増えるほど覆る確率が下がるだけで、確率的なファイナリティになる
- 語の意味：Finality＝最終的であること

#### PoW（ぴーおーだぶりゅー / Proof of Work）

- 意味：ブロックを追加する権利を、膨大なハッシュ計算を最初に解いた参加者に与えるコンセンサスアルゴリズム
- ポイント：ビットコインが使う。改ざんには全体の過半の計算能力が必要なので安全だが、電力を大量に使う。PoSは保有量で決める
- 語の意味：Proof＝証明／Work＝仕事

#### PoS（ぴーおーえす / Proof of Stake）

- 意味：ブロックを追加する権利を、通貨を多く・長く保有している参加者ほど得やすくするコンセンサスアルゴリズム
- ポイント：PoWのような膨大な計算をしないので、電力の消費が少ない。イーサリアムが移行した
- 語の意味：Proof＝証明／Stake＝賭け金・持ち分

#### スマートコントラクト（Smart Contract）

- 意味：あらかじめ決めた条件が満たされたときに、契約の処理をブロックチェーン上で自動的に実行するプログラム
- ポイント：仲介者なしで取引を実行でき、実行の記録も改ざんしにくい。プログラムに誤りがあると、そのまま実行されてしまう
- 語の意味：Smart＝賢い／Contract＝契約

#### 51%攻撃（ごじゅういちぱーせんとこうげき / 51% Attack）

- 意味：PoWのブロックチェーンで、全体の計算能力の過半数を握った者が、取引の記録を書き換えたり二重に支払ったりする攻撃
- ポイント：過半数の計算能力があれば、正しい鎖より長い鎖を作れてしまうため。参加者が少ない小さなブロックチェーンほど狙われやすい
