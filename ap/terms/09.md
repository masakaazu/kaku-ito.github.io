## 9-1 データベース方式

### まとめ表

**3層スキーマ**

| スキーマ | 定義するもの |
| :-: | :-: |
| 外部スキーマ | 利用者から見たデータ（ビュー） |
| 概念スキーマ | 全体の論理構造（表） |
| 内部スキーマ | 記憶装置への格納方法 |


### 方式

#### 関係データベース（Relational Database）

- 意味：データを表（関係）で表すデータベース
- ポイント：行をタプル、列を属性、属性がとりうる値の集合をドメインという

#### 3層スキーマ（Three-schema Architecture）

- 意味：外部・概念・内部の3つに分けて定義する構造
- ポイント：データの独立性を高める

#### NoSQL（のーえすきゅーえる / Not only SQL）

- 意味：表の形にとらわれないデータベース
- ポイント：キーバリュー・ドキュメント・列指向・グラフ型。整合性より拡張性を優先するBASE特性
- 語の意味：Not only＝〜だけではない／SQL＝関係DBの言語

#### CAP定理（CAP Theorem）

- 意味：分散データベースでは、一貫性・可用性・分断耐性の3つを同時にすべて満たすことはできないという定理
- 語の意味：Consistency＝一貫性／Availability＝可用性／Partition tolerance＝分断耐性


### 方式の種類（発展）

#### 階層型データベース（Hierarchical Database）

- 意味：データを親子の木構造で表すデータベース
- ポイント：1つの子は1つの親だけを持つ

#### ネットワーク型データベース（Network Database）

- 意味：データを網の目のようにつなぐデータベース
- ポイント：1つの子が複数の親を持てる

#### 外部スキーマ・概念スキーマ・内部スキーマ（External / Conceptual / Internal Schema）

- 意味：利用者から見た形、データ全体の論理的な形、記憶装置での物理的な形
- ポイント：外部スキーマはビューに当たる

#### データ独立性（Data Independence）

- 意味：物理的な格納方法を変えても、プログラムに影響が出ないこと
- ポイント：3層スキーマで実現する

#### DBMS（でぃーびーえむえす / Database Management System）

- 意味：データベースを管理するソフトウェア
- ポイント：同時実行の制御、障害からの回復、権限の管理などを行う
- 語の意味：Database＝データベース／Management＝管理／System＝システム

#### キーバリューストア（KVS / Key-Value Store）

- 意味：キーと値の組だけでデータを持つNoSQL
- ポイント：高速で、横に広げやすい

#### ドキュメント指向データベース（Document-oriented Database）

- 意味：JSONのような文書の形でデータを持つNoSQL
- 例：MongoDB

#### グラフ指向データベース（Graph Database）

- 意味：ノードと辺でデータのつながりを表すNoSQL
- ポイント：SNSの友達関係などに向く

#### 列指向データベース（Column-oriented Database）

- 意味：データを列ごとにまとめて記録するデータベース
- ポイント：集計や分析に強い

#### BASE特性（BASE Properties）

- 意味：NoSQLで重視される、可用性を優先し最終的に一貫すればよいとする考え方
- ポイント：Basically Available, Soft state, Eventually consistent

#### 結果整合性（Eventual Consistency）

- 意味：一時的にデータが食い違っても、時間がたてば一致すること

#### インメモリデータベース（In-memory Database）

- 意味：データを主記憶に置いて処理するデータベース
- ポイント：非常に速い


## 9-2 データベース設計

### まとめ表

**正規化**

| 正規形 | 条件 |
| :-: | :-: |
| 第1正規形 | 繰返し項目がない |
| 第2正規形 | 部分関数従属がない |
| 第3正規形 | 推移的関数従属がない |


### 設計

#### E-R図（Entity Relationship Diagram）

- 意味：実体と実体どうしの関連を表した図
- ポイント：1対多・多対多などのカーディナリティを表す。多対多は連関エンティティで分解する

#### 主キー・外部キー（Primary / Foreign Key）

- 意味：主キーは行を1つに決める列、外部キーはほかの表の主キーを参照する列
- ポイント：外部キーで参照制約を守る

#### 候補キー（Candidate Key）

- 意味：行を1つに決められる最小の列の組合せ
- ポイント：主キーは候補キーから1つ選ぶ

#### 正規化（Normalization）

- 意味：重複をなくすように表を分けること
- ポイント：更新時の矛盾（更新時異状）を防ぐ

#### 部分関数従属（Partial Functional Dependency）

- 意味：複合主キーの一部の列だけで、ほかの列が決まる関係
- ポイント：なくすと第2正規形

#### 推移的関数従属（Transitive Functional Dependency）

- 意味：主キー → 非キー列 → 別の非キー列 と、間接的に決まる関係
- ポイント：なくすと第3正規形

#### 非正規化（Denormalization）

- 意味：性能を上げるため、あえて表をまとめて重複を許すこと

#### インデックス（Index）

- 意味：検索を速くするための索引
- ポイント：B+木やハッシュで作る。更新は遅くなる


### 正規化の段階（発展）

#### 第1正規形（First Normal Form）

- 意味：繰り返しの項目をなくし、1つのセルに1つの値だけが入るようにした形

#### 第2正規形（Second Normal Form）

- 意味：第1正規形で、主キーの一部だけに従属する項目（部分関数従属）をなくした形

#### 第3正規形（Third Normal Form）

- 意味：第2正規形で、主キー以外の項目に従属する項目（推移的関数従属）をなくした形

#### ボイス・コッド正規形（BCNF / Boyce-Codd Normal Form）

- 意味：すべての関数従属で、決める側が候補キーになっている形
- ポイント：第3正規形をさらに厳しくしたもの

#### 関数従属（Functional Dependency）

- 意味：ある項目の値が決まると、別の項目の値がただ1つに決まる関係
- 例：社員番号 → 氏名

#### 更新時異常（Update Anomaly）

- 意味：正規化されていない表で、追加・更新・削除のときに起きる不都合
- 例：同じ情報を何か所も直す必要がある

#### 複合キー（Composite Key）

- 意味：複数の列を組み合わせた主キー

#### スーパーキー（Super Key）

- 意味：行を一意に決められる列の集まり
- ポイント：候補キーはその中で最小のもの

#### 代替キー（Alternate Key）

- 意味：候補キーのうち、主キーに選ばれなかったもの

#### 参照制約（Referential Integrity Constraint）

- 意味：外部キーの値が、参照先の表に必ずあるようにする制約
- 例：存在しない部署コードの社員は登録できない

#### 一意性制約（UNIQUE Constraint）

- 意味：列の値が重ならないようにする制約

#### 非NULL制約（NOT NULL Constraint）

- 意味：列に空の値（NULL）を入れられないようにする制約

#### 検査制約（CHECK Constraint）

- 意味：列に入る値の条件を決める制約
- 例：年齢は0以上

#### カーディナリティ（多重度 / Cardinality）

- 意味：実体どうしが「1対1」「1対多」「多対多」のどの関係かを表すもの
- ポイント：多対多は連関エンティティで1対多に分ける

#### 連関エンティティ（Associative Entity）

- 意味：多対多の関係を2つの1対多に分けるために作る実体
- 例：学生と科目の間の「履修」

#### データディクショナリ（Data Dictionary）

- 意味：データの名前・型・意味などをまとめた辞書


## 9-3 データ操作

### まとめ表

**結合の種類**

| 結合 | 結果 |
| :-: | :-: |
| 内部結合（INNER JOIN） | 両方の表に一致する行だけ |
| 左外部結合（LEFT OUTER JOIN） | 左の表の行はすべて残し、一致しない所はNULL |
| 完全外部結合（FULL OUTER JOIN） | 両方の表の行をすべて残す |


### 関係演算とSQL

#### 選択・射影・結合（Selection / Projection / Join）

- 意味：選択は行を取り出す、射影は列を取り出す、結合は共通の列で表をつなぐ

#### 和・差・積（Union / Difference / Intersection）

- 意味：和は両方の行を合わせる、差は片方にだけある行、積は両方にある行

#### 直積（Cartesian Product）

- 意味：2つの表のすべての行の組合せ
- ポイント：行数は両方の行数の積

#### SELECT文（SELECT Statement）

- 意味：表からデータを取り出すSQL
- ポイント：実行の順は FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY

#### 内部結合・外部結合（Inner / Outer Join）

- 意味：内部結合は両方に一致する行だけ、外部結合は一致しない行もNULLで補って残す

#### 副問合せ（Subquery）

- 意味：SQLの中に入れた別のSELECT文
- ポイント：IN・EXISTSと組み合わせる。外側の値を使うのが相関副問合せ

#### GROUP BY・HAVING

- 意味：GROUP BYで行をまとめ、HAVINGでまとめたグループを条件で絞る
- ポイント：WHEREはまとめる前の行を絞る

#### ビュー（View）

- 意味：SELECT文の結果を仮想的な表として見せるもの
- ポイント：見せる範囲を絞ってセキュリティにも使う

#### GRANT・REVOKE

- 意味：利用者に権限を与える（GRANT）、取り上げる（REVOKE）SQL
- ポイント：DCL（データ制御言語）


### SQLの書き方（発展）

#### WHERE句（WHERE Clause）

- 意味：取り出す行の条件を指定する部分

#### ORDER BY句（ORDER BY Clause）

- 意味：結果を並べ替える部分
- ポイント：ASCは昇順、DESCは降順

#### DISTINCT（でぃすてぃんくと）

- 意味：結果から重複した行を取り除く指定

#### 集合関数（Aggregate Function）

- 意味：複数の行をまとめて1つの値を求める関数
- ポイント：COUNT・SUM・AVG・MAX・MIN

#### LIKE述語（LIKE Predicate）

- 意味：文字の一部が一致するかで探す条件
- ポイント：%は任意の文字列、_は任意の1文字

#### IN述語・BETWEEN述語（IN / BETWEEN Predicate）

- 意味：値が一覧の中にあるか、範囲の中にあるかを調べる条件

#### EXISTS述語（EXISTS Predicate）

- 意味：副問合せの結果が1行以上あるかを調べる条件
- ポイント：相関副問合せでよく使う

#### 相関副問合せ（Correlated Subquery）

- 意味：外側の問合せの行ごとに、内側の副問合せを実行する書き方

#### INSERT・UPDATE・DELETE文（Data Manipulation）

- 意味：行を追加する、値を変える、行を消すSQL

#### CREATE TABLE文（CREATE TABLE Statement）

- 意味：表を作るSQL
- ポイント：DDL（データ定義言語）の1つ

#### DDL・DML・DCL（Data Definition / Manipulation / Control Language）

- 意味：表などを定義する命令、データを操作する命令、権限などを制御する命令
- 語の意味：Definition＝定義／Manipulation＝操作／Control＝制御

#### UNION（ゆにおん）

- 意味：2つのSELECTの結果を合わせる
- ポイント：重複は取り除かれる。残すときはUNION ALL

#### カーソル（Cursor）

- 意味：SQLの結果を1行ずつ取り出して処理するための仕組み
- ポイント：埋込みSQLで使う

#### ストアドプロシージャ（Stored Procedure）

- 意味：よく使う処理をデータベースの中に保存しておき、呼び出して使う仕組み
- ポイント：通信の回数が減る

#### トリガ（Trigger）

- 意味：表に追加や更新があったとき、自動で決まった処理を動かす仕組み

#### NULL（ぬる）

- 意味：値がない、または不明であることを表す特別な値
- ポイント：比較はIS NULLで行う


## 9-4 トランザクション処理

### まとめ表

**障害回復**

| 障害 | 回復の方法 |
| :-: | :-: |
| トランザクション障害 | 更新前ログでロールバック |
| システム障害 | チェックポイント以降をロールフォワード／ロールバック |
| 媒体障害 | バックアップを戻して更新後ログでロールフォワード |


### 同時実行と回復

#### ACID特性（ACID Properties）

- 意味：トランザクションが守るべき4つの性質
- 語の意味：Atomicity＝原子性／Consistency＝一貫性／Isolation＝独立性／Durability＝耐久性

#### 排他制御（Exclusive Control）

- 意味：同時の更新で矛盾が起きないよう、ロックをかける制御
- ポイント：共有ロックどうしは同時にかけられるが、専有ロックはほかと同時にかけられない

#### 2相ロック（Two-phase Locking）

- 意味：ロックをかけていく段階と外していく段階に分け、外し始めたら新しくかけない方式
- ポイント：直列化可能性を保証する

#### 隔離性水準（Isolation Level）

- 意味：トランザクションをどれだけ独立させるかの段階
- ポイント：ダーティリード・反復不能読取り・ファントムを防ぐ程度が違う

#### デッドロック（Deadlock）

- 意味：トランザクションがお互いのロックの解除を待ち合う状態
- ポイント：待ちグラフで検出し、どちらかをロールバックする

#### ロールバック・ロールフォワード（Rollback / Rollforward）

- 意味：ロールバックは更新前ログで取り消すこと、ロールフォワードはバックアップに更新後ログを当て直すこと

#### チェックポイント（Checkpoint）

- 意味：バッファの内容をディスクに書き出す時点
- ポイント：回復はここから始めればよい

#### 2相コミット（Two-phase Commit）

- 意味：分散データベースで、全員に準備ができたか確かめてから一斉に確定する方式
- ポイント：調停者からの指示を待つ間は動けなくなることがある


### 障害と回復（発展）

#### トランザクション（Transaction）

- 意味：分けられないひとまとまりの処理
- ポイント：全部成功するか、全部なかったことにする

#### コミット（Commit）

- 意味：トランザクションの処理を確定させること

#### 共有ロック・専有ロック（Shared / Exclusive Lock）

- 意味：読む人どうしは一緒に使える鍵と、1人しか使えない鍵
- ポイント：更新のときは専有ロック

#### ロックの粒度（Lock Granularity）

- 意味：ロックをかける範囲の大きさ（表・ページ・行）
- ポイント：細かいほど同時に動ける処理が増えるが、管理の負担は増える

#### 楽観的ロック（Optimistic Locking）

- 意味：競合はまれと考えてロックをかけず、更新するときに他の人が変えていないかを確かめる方法

#### ダーティリード（Dirty Read）

- 意味：他のトランザクションがまだ確定していないデータを読んでしまうこと

#### ノンリピータブルリード（Non-repeatable Read）

- 意味：同じデータを2回読むと、間で他の人が更新して値が違うこと

#### ファントムリード（Phantom Read）

- 意味：同じ条件で2回検索すると、間で他の人が追加して行が増えること

#### ログファイル（ジャーナル / Log File）

- 意味：データベースの更新前と更新後の内容を記録したファイル
- ポイント：回復に使う

#### 更新前ログ・更新後ログ（Before / After Image）

- 意味：変える前の内容と変えた後の内容の記録
- ポイント：ロールバックは更新前、ロールフォワードは更新後を使う

#### バックアップ（Backup）

- 意味：障害に備えてデータの写しを取っておくこと
- ポイント：フル・差分・増分の方式がある

#### 差分バックアップ・増分バックアップ（Differential / Incremental Backup）

- 意味：前回のフルバックアップからの変更分と、前回のバックアップからの変更分
- ポイント：回復は差分の方が簡単、取る時間は増分の方が短い

#### WAL（Write Ahead Log）

- 意味：データを書き換える前に、必ずログを先に書く決まり
- 語の意味：Write＝書く／Ahead＝先に／Log＝記録

#### レプリケーション（Replication）

- 意味：データベースの写しをほかのサーバに作り、同じ内容に保つこと
- ポイント：負荷を分けたり、障害に備えたりする

#### シャーディング（Sharding）

- 意味：データを複数のサーバに分けて持つこと
- ポイント：大量のデータを扱える


## 9-5 データベース応用


### 活用

#### データウェアハウス（Data Warehouse）

- 意味：分析のために、いろいろなシステムのデータを時系列にためたもの

#### OLAP（おーらっぷ / Online Analytical Processing）

- 意味：データを多次元で分析する処理
- ポイント：ドリルダウン・スライシング・ダイシング
- 語の意味：Online＝オンライン／Analytical＝分析の／Processing＝処理

#### データマイニング（Data Mining）

- 意味：大量のデータから規則や関係を見つけること

#### データレイク（Data Lake）

- 意味：構造化・非構造化を問わず、元の形のままためておく場所

#### ETL（いーてぃーえる / Extract, Transform, Load）

- 意味：データを取り出し、形を変え、データウェアハウスに読み込む処理
- 語の意味：Extract＝取り出す／Transform＝変換する／Load＝読み込む

#### ブロックチェーン（Blockchain）

- 意味：取引の記録をハッシュ値でつないで、改ざんを難しくした分散型の台帳


### データの活用（発展）

#### データマート（Data Mart）

- 意味：データウェアハウスから、部門や目的ごとに必要なデータを取り出したもの

#### ダイシング・スライシング・ドリルダウン（Dicing / Slicing / Drill-down）

- 意味：OLAPで、分析の切り口を変える、ある値で切り出す、細かい階層へ下りていく操作

#### BIツール（Business Intelligence Tool）

- 意味：社内のデータを集めて分析し、グラフなどで見せるツール

#### メタデータ管理（Metadata Management）

- 意味：データの意味や出どころなどの情報を管理すること

#### データクレンジング（Data Cleansing）

- 意味：データの誤りや重複、表記ゆれを直してきれいにすること

#### ビッグデータ（Big Data）

- 意味：量が多く、種類も多く、発生が速いデータ
- ポイント：Volume・Variety・Velocityの3つのV

#### 分散データベース（Distributed Database）

- 意味：複数の場所にあるデータベースを、1つのデータベースのように使える仕組み
- ポイント：利用者が場所を意識しない（透過性）


## 問題演習

### 9-1 データベース方式

#### 問 ap-9-q01

- 問：分散システムで、一貫性・可用性・分断耐性の3つを同時にすべて満たせないことを示すものはどれか。

- イ：CAP定理
- ウ：BASE特性
- エ：2相コミット
- 正解：イ
- 解説：CAP定理。NoSQLは一貫性より可用性を優先することが多い。

#### 問 ap-9-q20

- 問：NoSQLのうち、キーと値の組でデータを保持するものはどれか。
- ア：グラフ指向
- イ：ドキュメント指向
- ウ：キーバリューストア
- エ：列指向
- 正解：ウ
- 解説：KVSはキーと値だけを持つ。

### 9-2 データベース設計

#### 問 ap-9-q02

- 問：複合主キーの一部の属性だけで、ほかの属性が決まる関係を取り除いた正規形はどれか。
- ア：第1正規形
- イ：第2正規形
- ウ：第3正規形
- エ：ボイス・コッド正規形
- 正解：イ
- 解説：部分関数従属をなくすと第2正規形。

#### 問 ap-9-q03

- 問：主キー以外の属性を通じて、別の属性が間接的に決まる関係を何というか。
- ア：部分関数従属
- イ：推移的関数従属
- ウ：多値従属
- エ：完全関数従属
- 正解：イ
- 解説：主キー→A→B のように決まるのが推移的関数従属。

#### 問 ap-9-q12

- 問：第2正規形の表を第3正規形にするために取り除くものはどれか。
- ア：繰返し項目
- イ：部分関数従属
- ウ：推移的関数従属
- エ：主キー
- 正解：ウ
- 解説：主キー以外の項目に従属する推移的関数従属を取り除く。

#### 問 ap-9-q13

- 問：外部キーの値が参照先の表に必ず存在するように保証する制約はどれか。
- ア：一意性制約
- イ：参照制約
- ウ：検査制約
- エ：非NULL制約
- 正解：イ
- 解説：参照制約（参照整合性）。

#### 問 ap-9-q14

- 問：多対多の関係を1対多の関係に分けるために設ける実体を何というか。
- ア：弱実体
- イ：連関エンティティ
- ウ：スーパータイプ
- エ：サブタイプ
- 正解：イ
- 解説：連関エンティティ（関連実体）を間に置く。

### 9-3 データ操作

#### 問 ap-9-q04

- 問：2つの表を結合し、左側の表の行は一致する行がなくてもすべて残す結合はどれか。
- ア：内部結合
- イ：左外部結合
- ウ：直積
- エ：自然結合
- 正解：イ
- 解説：左外部結合は一致しない所をNULLで補う。

#### 問 ap-9-q05

- 問：SQLで、GROUP BYでまとめたグループに条件を付ける句はどれか。
- ア：WHERE
- イ：HAVING
- ウ：ORDER BY
- エ：DISTINCT
- 正解：イ
- 解説：グループの条件はHAVING、行の条件はWHERE。

#### 問 ap-9-q06

- 問：表Aが3行、表Bが4行のとき、AとBの直積の行数はどれか。
- ア：3
- イ：4
- ウ：7
- エ：12
- 正解：エ
- 解説：直積はすべての組合せなので 3×4＝12。

#### 問 ap-9-q15

- 問：SQLで、検索結果から重複した行を取り除く指定はどれか。
- ア：DISTINCT
- イ：GROUP BY
- ウ：ORDER BY
- エ：HAVING
- 正解：ア
- 解説：DISTINCTで重複を除く。

#### 問 ap-9-q16

- 問：表の定義を行うCREATE文が属するSQLの区分はどれか。
- ア：DCL
- イ：DDL
- ウ：DML
- エ：TCL
- 正解：イ
- 解説：表などの定義はDDL。

### 9-4 トランザクション処理

#### 問 ap-9-q07

- 問：トランザクションのACID特性のうち、コミット後の結果が障害が起きても失われない性質はどれか。
- ア：原子性
- イ：一貫性
- ウ：独立性
- エ：耐久性
- 正解：エ
- 解説：Durability（耐久性）。

#### 問 ap-9-q08

- 問：媒体障害が起きたときの回復手順として適切なものはどれか。
- ア：更新前ログでロールバックする
- イ：バックアップを戻し、更新後ログでロールフォワードする
- ウ：チェックポイントまでロールバックする
- エ：何もしない
- 正解：イ
- 解説：ディスクが壊れたら、バックアップに更新後ログを当て直す。

#### 問 ap-9-q09

- 問：共有ロックと専有ロックについて正しいものはどれか。
- ア：共有ロックどうしは同時にかけられる
- イ：専有ロックどうしは同時にかけられる
- ウ：共有ロックと専有ロックは同時にかけられる
- エ：どのロックも同時にかけられない
- 正解：ア
- 解説：読むだけの共有ロックは同時にかけられる。

#### 問 ap-9-q10

- 問：分散データベースで、全サイトの準備完了を確かめてから一斉にコミットする方式はどれか。
- ア：2相ロック
- イ：2相コミット
- ウ：チェックポイント
- エ：ロールフォワード
- 正解：イ
- 解説：2相コミット。

#### 問 ap-9-q17

- 問：他のトランザクションが更新中で、まだコミットしていないデータを読んでしまう現象はどれか。
- ア：ダーティリード
- イ：ファントムリード
- ウ：ノンリピータブルリード
- エ：デッドロック
- 正解：ア
- 解説：未確定のデータを読むのがダーティリード。

#### 問 ap-9-q18

- 問：障害の回復で、増分バックアップに比べた差分バックアップの特徴はどれか。
- ア：取得時間が短い
- イ：復旧に必要なファイルが少ない
- ウ：容量が小さい
- エ：フルバックアップが要らない
- 正解：イ
- 解説：差分はフル＋最新の差分だけで戻せる。

#### 問 ap-9-q19

- 問：更新の競合はまれと考え、更新時に他者が変更していないかを確かめる方式はどれか。
- ア：2相ロック
- イ：楽観的ロック
- ウ：専有ロック
- エ：デッドロック検出
- 正解：イ
- 解説：楽観的ロック（楽観的排他制御）。
