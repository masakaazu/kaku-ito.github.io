## 11-1 情報セキュリティ

### まとめ表

**情報セキュリティの3要素（CIA）**

| 要素 | 意味 |
| :-: | :-: |
| 機密性（Confidentiality） | 許された人だけが使える |
| 完全性（Integrity） | 正しく、改ざんされていない |
| 可用性（Availability） | 必要なときに使える |

**暗号方式の比較**

| 方式 | 鍵 | 特徴 |
| :-: | :-: | :-: |
| 共通鍵暗号（AES） | 送る側と受ける側で同じ鍵 | 速い。鍵の受け渡しが課題 |
| 公開鍵暗号（RSA・楕円曲線） | 公開鍵で暗号化、秘密鍵で復号 | 遅いが鍵の配送が楽 |


### 基本と暗号

#### 共通鍵暗号方式（Symmetric Key Cryptography）

- 意味：暗号化と復号に同じ鍵を使う方式
- ポイント：n人がお互いに通信するには n(n−1)/2 個の鍵が要る。代表はAES

#### 公開鍵暗号方式（Public Key Cryptography）

- 意味：公開鍵と秘密鍵の組を使う方式
- ポイント：受信者の公開鍵で暗号化し、受信者の秘密鍵で復号する。n人なら2n個

#### ハイブリッド暗号（Hybrid Encryption）

- 意味：共通鍵を公開鍵暗号で送り、データ本体は共通鍵で暗号化する方式
- ポイント：TLSで使う

#### ハッシュ関数（Hash Function）

- 意味：データから決まった長さの値を作る関数
- ポイント：元に戻せない、同じ値になる別のデータを見つけにくい。改ざんの検出に使う。例: SHA-256

#### ディジタル署名（Digital Signature）

- 意味：送信者が自分の秘密鍵で署名し、受信者が送信者の公開鍵で確かめるしくみ
- ポイント：送信者の本人確認と改ざんの検出ができる

#### PKI（ぴーけーあい / Public Key Infrastructure）

- 意味：認証局（CA）が公開鍵の持ち主を証明するしくみ
- ポイント：ディジタル証明書は認証局の秘密鍵で署名される。失効した証明書はCRLやOCSPで確かめる
- 語の意味：Public Key＝公開鍵／Infrastructure＝基盤

#### MAC（めっく / Message Authentication Code）

- 意味：共通鍵とデータから作る値で、改ざんを検出する符号
- 語の意味：Message＝メッセージ／Authentication＝認証／Code＝符号


### 攻撃の手口

#### 標的型攻撃（Targeted Attack）

- 意味：特定の組織をねらい、本物らしいメールでマルウェアを送り込む攻撃
- ポイント：APT（長い期間にわたる攻撃）もある

#### ランサムウェア（Ransomware）

- 意味：データを暗号化して使えなくし、元に戻す代わりに金銭を要求するマルウェア
- ポイント：対策はオフラインのバックアップ

#### SQLインジェクション（SQL Injection）

- 意味：入力にSQL文の一部を入れて、データベースを不正に操作する攻撃
- ポイント：対策はプレースホルダ（バインド機構）

#### クロスサイトスクリプティング（XSS / Cross-Site Scripting）

- 意味：Webページに不正なスクリプトを埋め込み、閲覧者のブラウザで実行させる攻撃
- ポイント：対策は出力時のエスケープ処理

#### CSRF（しーさーふ / Cross-Site Request Forgery）

- 意味：ログイン中の利用者に、意図しない処理の要求を送らせる攻撃
- ポイント：対策はトークンの確認
- 語の意味：Cross-Site＝サイトをまたいだ／Request＝要求／Forgery＝偽造

#### DDoS攻撃（Distributed Denial of Service Attack）

- 意味：多くの機器から大量の通信を送り、サービスを止める攻撃
- 語の意味：Distributed＝分散した／Denial of Service＝サービス妨害

#### DNSキャッシュポイズニング（DNS Cache Poisoning）

- 意味：DNSサーバに偽の情報を覚えさせ、偽のサイトに誘導する攻撃

#### 中間者攻撃（MITM / Man-in-the-Middle Attack）

- 意味：通信の間に割り込んで、盗み見や改ざんをする攻撃

#### ゼロデイ攻撃（Zero-day Attack）

- 意味：修正プログラムが出る前に、その弱点（脆弱性）をねらう攻撃

#### パスワードリスト攻撃（Password List Attack）

- 意味：ほかのサイトから漏れたIDとパスワードの組で、ログインを試す攻撃
- ポイント：パスワードの使い回しが原因

#### ソーシャルエンジニアリング（Social Engineering）

- 意味：人の心のすきをついて、パスワードなどを聞き出す手口
- 例：電話でなりすます、肩越しにのぞく

#### サイドチャネル攻撃（Side-channel Attack）

- 意味：処理の時間や消費電力などを測って、暗号の鍵を推測する攻撃


### 基本と暗号（発展）

#### 機密性・完全性・可用性（CIA / Confidentiality, Integrity, Availability）

- 意味：許された人だけが見られること、正しく改ざんされていないこと、使いたいときに使えること
- ポイント：情報セキュリティの3要素

#### 真正性・責任追跡性・否認防止・信頼性（Authenticity / Accountability / Non-repudiation / Reliability）

- 意味：本物であること、誰がしたかをたどれること、後から否定できないこと、意図どおり動くこと
- ポイント：3要素に加えて求められる性質

#### AES（えーいーえす / Advanced Encryption Standard）

- 意味：現在よく使われる共通鍵暗号
- ポイント：鍵の長さは128・192・256ビット

#### RSA（あーるえすえー）

- 意味：大きな数の素因数分解が難しいことを利用した公開鍵暗号
- ポイント：考えた3人の名前の頭文字

#### 楕円曲線暗号（ECC / Elliptic Curve Cryptography）

- 意味：楕円曲線の計算の難しさを使う公開鍵暗号
- ポイント：RSAより短い鍵で同じ強さ

#### SHA-256（しゃー256）

- 意味：256ビットのハッシュ値を作るハッシュ関数
- ポイント：改ざんの検出に使う

#### 認証局（CA / Certification Authority）

- 意味：公開鍵が本人のものであることを証明する電子証明書を発行する機関

#### 電子証明書（Digital Certificate）

- 意味：公開鍵とその持ち主を結び付け、認証局が署名したデータ
- ポイント：X.509という形式

#### CRL（しーあーるえる / Certificate Revocation List）

- 意味：期限前に無効になった証明書の一覧
- ポイント：今はOCSPでその場で確かめる方法もある

#### タイムスタンプ（Time Stamp）

- 意味：ある時刻に電子データが存在し、その後変わっていないことを証明する仕組み

#### 鍵管理（Key Management）

- 意味：暗号の鍵を作る・配る・保管する・捨てるまでを安全に管理すること

#### 危殆化（きたいか / Compromise）

- 意味：暗号の鍵が漏れたり、暗号が破られたりして安全でなくなること

#### 耐量子計算機暗号（PQC / Post-Quantum Cryptography）

- 意味：量子コンピュータでも破られにくい暗号


### 攻撃の手口（発展）

#### フィッシング（Phishing）

- 意味：本物そっくりの偽のメールやサイトで、IDやパスワードをだまし取る攻撃

#### ビジネスメール詐欺（BEC / Business Email Compromise）

- 意味：取引先や上司になりすましたメールで、お金を振り込ませる詐欺

#### 水飲み場型攻撃（Watering Hole Attack）

- 意味：狙う相手がよく見るWebサイトを改ざんし、ウイルスに感染させる攻撃

#### ドライブバイダウンロード（Drive-by Download）

- 意味：Webサイトを見ただけで、知らないうちにウイルスを入れられる攻撃

#### ブルートフォース攻撃（総当たり攻撃 / Brute Force Attack）

- 意味：パスワードを、すべての組合せで試す攻撃

#### 辞書攻撃（Dictionary Attack）

- 意味：よく使われる言葉をパスワードとして順に試す攻撃

#### リバースブルートフォース攻撃（Reverse Brute Force Attack）

- 意味：パスワードを1つに決めて、IDを次々に変えて試す攻撃
- ポイント：アカウントのロックをすり抜けやすい

#### レインボーテーブル攻撃（Rainbow Table Attack）

- 意味：ハッシュ値と元の文字列の対応表を使って、パスワードを割り出す攻撃
- ポイント：ソルトを加えると防ぎやすい

#### バッファオーバフロー攻撃（Buffer Overflow Attack）

- 意味：用意された領域より大きなデータを送り込み、不正な命令を動かす攻撃

#### ディレクトリトラバーサル（Directory Traversal）

- 意味：「../」などを使って、公開していないファイルを読み出す攻撃

#### OSコマンドインジェクション（OS Command Injection）

- 意味：入力欄にOSの命令を混ぜて、サーバで勝手に実行させる攻撃

#### セッションハイジャック（Session Hijacking）

- 意味：ログイン中の利用者のセッションIDを盗み、なりすます攻撃

#### クリックジャッキング（Clickjacking）

- 意味：透明なページを重ね、利用者に意図しない所をクリックさせる攻撃

#### ボット・C&Cサーバ（Bot / Command and Control Server）

- 意味：乗っ取られて攻撃者の命令で動くコンピュータと、命令を出すサーバ

#### サプライチェーン攻撃（Supply Chain Attack）

- 意味：守りの弱い取引先やソフトウェアの部品を足がかりにして、狙う組織を攻める攻撃

#### APT（えーぴーてぃー / Advanced Persistent Threat）

- 意味：特定の組織を長い期間ねばり強く狙い続ける攻撃
- 語の意味：Advanced＝高度な／Persistent＝しつこい／Threat＝脅威

#### ポートスキャン（Port Scan）

- 意味：どのポートが開いているかを調べること
- ポイント：攻撃の下調べに使われる

#### SYNフラッド攻撃（SYN Flood Attack）

- 意味：接続の要求（SYN）を大量に送り、サーバの資源を使い切らせる攻撃

#### 踏み台攻撃（Stepping Stone Attack）

- 意味：他人のコンピュータを乗っ取り、そこから別の相手を攻撃すること

#### シャドーIT（Shadow IT）

- 意味：会社が認めていない機器やクラウドを、社員が勝手に仕事に使うこと

#### 内部不正（Insider Threat）

- 意味：社員や関係者が、情報を持ち出したり壊したりすること
- ポイント：不正のトライアングル（動機・機会・正当化）


## 11-2 情報セキュリティ管理

### まとめ表

**リスク対応の4つ**

| 対応 | 意味 |
| :-: | :-: |
| リスク回避 | 原因となる活動をやめる |
| リスク低減 | 対策をして起こる確率や影響を小さくする |
| リスク移転（共有） | 保険や外部委託で他者と分け合う |
| リスク保有（受容） | 影響が小さいので受け入れる |


### 管理のしくみ

#### ISMS（あいえすえむえす / Information Security Management System）

- 意味：組織で情報セキュリティを管理するしくみ
- ポイント：JIS Q 27001。PDCAで改善する
- 語の意味：Information Security＝情報セキュリティ／Management System＝管理の仕組み

#### リスクアセスメント（Risk Assessment）

- 意味：リスクを特定・分析・評価すること

#### リスク対応（Risk Treatment）

- 意味：評価したリスクに、回避・低減・移転・保有のどれで対応するかを決めること

#### 情報セキュリティポリシ（Information Security Policy）

- 意味：組織の情報セキュリティの方針と規則
- ポイント：基本方針・対策基準・実施手順の3階層

#### CSIRT（しーさーと / Computer Security Incident Response Team）

- 意味：セキュリティ事故（インシデント）に対応する組織
- 語の意味：Computer Security＝コンピュータの安全／Incident＝事故／Response＝対応／Team＝チーム

#### SOC（そっく / Security Operation Center）

- 意味：ネットワークを24時間監視して、攻撃を見つける組織
- 語の意味：Security＝安全／Operation＝運用／Center＝拠点

#### サイバーセキュリティ経営ガイドライン（Cyber Security Management Guidelines）

- 意味：経営者がセキュリティ対策を進めるために経済産業省とIPAが示した指針


### 管理のしくみ（発展）

#### 情報資産（Information Asset）

- 意味：守るべき価値のある情報や、それを扱う機器・ソフトウェアなど

#### 脅威・脆弱性（Threat / Vulnerability）

- 意味：損害を与えるきっかけと、そのつけ込まれる弱点

#### リスク回避・低減・移転・保有（Risk Avoidance / Reduction / Transfer / Acceptance）

- 意味：やめる、対策で小さくする、保険などでほかに移す、受け入れる
- ポイント：リスク対応の4つの方法

#### 残留リスク（Residual Risk）

- 意味：対策をした後にも残るリスク

#### 個人情報保護（Personal Information Protection）

- 意味：個人を特定できる情報を、決めた目的の範囲で安全に扱うこと
- ポイント：プライバシーマークの制度がある

#### インシデント（Incident）

- 意味：情報セキュリティを損なうおそれのある出来事

#### BCP（びーしーぴー / Business Continuity Plan）

- 意味：災害や事故のときにも、大事な業務を続けたり早く戻したりするための計画
- 語の意味：Business＝事業／Continuity＝継続／Plan＝計画

#### JPCERT/CC（JPCERTコーディネーションセンター）

- 意味：日本のインシデントの情報を集めて調整する組織

#### J-CRAT・J-CSIP（Cyber Rescue and Advice Team / Initiative for Cyber Security Information sharing Partnership）

- 意味：IPAの、標的型攻撃の被害を相談できる窓口と、企業どうしで攻撃の情報を共有する取組み


## 11-3 セキュリティ技術評価


### 評価の基準

#### CVSS（しーぶいえすえす / Common Vulnerability Scoring System）

- 意味：脆弱性の深刻さを0〜10の点数で表す共通の基準
- 語の意味：Common＝共通の／Vulnerability＝脆弱性／Scoring＝点数付け／System＝方式

#### ISO/IEC 15408（コモンクライテリア / Common Criteria）

- 意味：IT製品のセキュリティ機能を評価する国際規格

#### ペネトレーションテスト（Penetration Test）

- 意味：実際に攻撃してみて、侵入できるかを確かめるテスト

#### ファジング（Fuzzing）

- 意味：予想外のデータを大量に与えて、ソフトウェアの脆弱性を見つける方法


## 11-4 情報セキュリティ対策


### 技術的な対策

#### 多要素認証（Multi-factor Authentication）

- 意味：知識（パスワード）・所持（スマホ）・生体（指紋）のうち、2種類以上を組み合わせる認証

#### ファイアウォール（Firewall）

- 意味：通信を、決めたルールで通したり止めたりする装置

#### DMZ（でぃーえむぜっと / DeMilitarized Zone）

- 意味：外部と内部のネットワークの間に置く、公開サーバ用の区域
- 語の意味：DeMilitarized＝非武装の／Zone＝地帯

#### WAF（わふ / Web Application Firewall）

- 意味：Webアプリへの攻撃（SQLインジェクションやXSS）を、通信の中身を見て防ぐ装置
- 語の意味：Web Application＝Webアプリ／Firewall＝防火壁

#### IDS・IPS（Intrusion Detection / Prevention System）

- 意味：IDSは不正な侵入を見つけて知らせる、IPSは見つけて止める
- 語の意味：Intrusion＝侵入／Detection＝検知／Prevention＝防止

#### EDR（いーでぃーあーる / Endpoint Detection and Response）

- 意味：パソコンなどの端末で不審な動きを見つけ、すぐに対応するしくみ
- 語の意味：Endpoint＝端末／Detection＝検知／Response＝対応

#### SIEM（しーむ / Security Information and Event Management）

- 意味：いろいろな機器のログをまとめて分析し、攻撃を見つけるしくみ
- 語の意味：Security＝安全／Information＝情報／Event＝出来事／Management＝管理

#### ゼロトラスト（Zero Trust）

- 意味：社内のネットワークでも信用せず、すべてのアクセスを毎回確かめる考え方

#### デジタルフォレンジックス（Digital Forensics）

- 意味：事故の後、法的な証拠になるようにログやデータを集めて分析すること


### 管理的・物理的な対策

#### 最小権限の原則（Principle of Least Privilege）

- 意味：仕事に必要な最小限の権限だけを与えること

#### セキュアブート（Secure Boot）

- 意味：起動するとき、署名を確かめて正しいソフトウェアだけを動かすしくみ

#### TPM（てぃーぴーえむ / Trusted Platform Module）

- 意味：鍵の生成や保管を安全に行う、耐タンパ性のあるチップ
- 語の意味：Trusted＝信頼された／Platform＝基盤／Module＝部品


### 技術的な対策（発展）

#### ソルト（Salt）

- 意味：パスワードをハッシュにする前に加える、ランダムな文字列
- ポイント：同じパスワードでも違うハッシュ値になる

#### ストレッチング（Stretching）

- 意味：ハッシュの計算を何回も繰り返し、総当たりにかかる時間を増やすこと

#### ワンタイムパスワード（One-time Password）

- 意味：1回しか使えないパスワード
- ポイント：盗まれても次には使えない

#### 生体認証（Biometric Authentication）

- 意味：指紋・顔・静脈など体の特徴で本人を確かめる方法
- ポイント：本人を拒否する率と他人を受け入れる率の釣り合いが大事

#### シングルサインオン（SSO / Single Sign-On）

- 意味：1回のログインで、複数のシステムを使えるようにする仕組み
- ポイント：SAMLやOpenID Connectを使う

#### リスクベース認証（Risk-based Authentication）

- 意味：いつもと違う場所や端末からのログインのときだけ、追加の確認をする認証

#### CAPTCHA（きゃぷちゃ）

- 意味：ゆがんだ文字を読ませるなどして、人間かプログラムかを見分ける仕組み

#### サンドボックス（Sandbox）

- 意味：怪しいプログラムを、外に影響しない隔離した環境で動かして調べる仕組み

#### パターンマッチング方式（Pattern Matching）

- 意味：既知のウイルスの特徴（シグネチャ）と比べて見つける方式
- ポイント：新しいウイルスには弱い

#### ビヘイビア法（Behavior Method）

- 意味：プログラムの動きを見て、怪しい振る舞いからウイルスを見つける方式

#### 検疫ネットワーク（Quarantine Network）

- 意味：社内につなぐ前に、パソコンが安全かを隔離した場所で確かめる仕組み

#### UTM（ゆーてぃーえむ / Unified Threat Management）

- 意味：ファイアウォール・IPS・ウイルス対策などを1台にまとめた機器

#### MDM（えむでぃーえむ / Mobile Device Management）

- 意味：会社のスマートフォンなどをまとめて管理する仕組み
- ポイント：なくしたときに遠隔でデータを消せる

#### DLP（でぃーえるぴー / Data Loss Prevention）

- 意味：大事な情報が外に出ていかないように見張り、止める仕組み

#### DNSSEC（でぃーえぬえすせっく）

- 意味：DNSの応答に電子署名を付けて、偽の応答を見分ける仕組み

#### OP25B（おーぴーにじゅうごびー / Outbound Port 25 Blocking）

- 意味：迷惑メールを防ぐため、家庭などから外への25番ポートの通信を止める仕組み


### 管理的・物理的な対策（発展）

#### 入退室管理（Physical Access Control）

- 意味：ICカードなどで、建物や部屋に入る人を管理すること
- ポイント：前の人について入る共連れを防ぐ

#### クリアデスク・クリアスクリーン（Clear Desk / Clear Screen）

- 意味：机の上に書類を置いたままにせず、離席するときは画面をロックすること

#### セキュリティ教育（Security Awareness Training）

- 意味：社員に攻撃の手口や守り方を教えること
- ポイント：標的型メールの訓練など


## 11-5 セキュリティ実装技術


### 安全な通信と開発

#### TLS（てぃーえるえす / Transport Layer Security）

- 意味：通信を暗号化し、サーバの正しさを証明書で確かめるプロトコル
- ポイント：HTTPSで使う。ハンドシェイクで暗号方式と鍵を決める
- 語の意味：Transport Layer＝トランスポート層／Security＝安全

#### IPsec（あいぴーせっく / IP Security）

- 意味：IPの層で暗号化と認証を行うプロトコル
- ポイント：VPNに使う。トンネルモードとトランスポートモード

#### SPF・DKIM・DMARC

- 意味：送信元のなりすましを防ぐメールの認証技術
- ポイント：SPFは送信元のIPアドレス、DKIMは電子署名で確かめる。DMARCは結果に応じた扱いを決める

#### S/MIME（えすまいむ / Secure MIME）

- 意味：公開鍵を使って、メールを暗号化・署名する方式
- 語の意味：Secure＝安全な／MIME＝メールの形式の規格

#### セキュアプログラミング（Secure Programming）

- 意味：脆弱性を作らないようにプログラムを書くこと
- ポイント：入力のチェック、エスケープ、プレースホルダなど

#### 無線LANのセキュリティ（WPA3）

- 意味：無線LANの暗号化の規格
- ポイント：WEPは弱く使ってはいけない
