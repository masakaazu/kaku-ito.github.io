## 11-1 情報セキュリティ

### まとめ表

**JIS Q 27000 の情報セキュリティの特性（過去問の定義文で覚える）**

| 特性 | 定義の決まり文句 | 迷いやすい相手 |
| :-: | :-: | :-: |
| 機密性 | 認可されていない者に、情報を使用させず、開示しない | 可用性（逆に「認可された者が使える」） |
| 完全性 | 正確さ及び完全さ | 信頼性 |
| 可用性 | 認可されたエンティティが要求したときに、アクセス及び使用が可能 | 機密性 |
| 真正性 | エンティティは、それが主張するとおりのものである | 否認防止 |
| 信頼性 | 意図する行動と結果とが一貫している | 完全性 |
| 否認防止 | 主張された事象・処置の発生と、それを引き起こしたエンティティを証明できる | 責任追跡性 |
| 責任追跡性 | 誰が何をしたかを後から一意にたどれる（JIS Q 27000の定義語ではない） | 否認防止 |

**パスワードへの攻撃（何を固定して、何を変えるか）**

| 攻撃 | 固定するもの | 試すもの | 主な対策 |
| :-: | :-: | :-: | :-: |
| ブルートフォース | 利用者ID | あらゆる文字の組合せ | アカウントロック・長いパスワード |
| 辞書攻撃 | 利用者ID | 辞書の単語・よくある文字列 | 推測されにくいパスワード |
| リバースブルートフォース | パスワード（よくあるもの） | 利用者IDを次々に | ロックが効かないので多要素認証・監視 |
| パスワードリスト攻撃 | 他サイトから漏れたIDとパスワードの組 | 別のサイトで同じ組 | 使い回し禁止・多要素認証 |
| レインボーテーブル攻撃 | 盗んだハッシュ値 | 事前に作った「平文とハッシュの連鎖表」で逆引き | ソルト・ストレッチング |

**ハッシュ関数の3つの性質**

| 性質 | 何が難しいか |
| :-: | :-: |
| 原像計算困難性（一方向性） | ハッシュ値から元のメッセージを見つける |
| 第二原像計算困難性 | あるメッセージと同じハッシュ値になる別のメッセージを見つける |
| 衝突発見困難性 | 同じハッシュ値になる2つのメッセージの組を自由に見つける |

**デジタル署名と暗号化で使う鍵**

| 目的 | 送信者が使う鍵 | 受信者が使う鍵 |
| :-: | :-: | :-: |
| 暗号化（盗み見を防ぐ） | 受信者の公開鍵で暗号化 | 受信者の秘密鍵で復号 |
| デジタル署名（なりすまし・改ざんを見抜く） | 送信者の秘密鍵（署名鍵）で署名 | 送信者の公開鍵（検証鍵）で検証 |

### 情報セキュリティの特性

#### 機密性（きみつせい / Confidentiality）

- 意味：認可されていない個人、エンティティ又はプロセスに対して、情報を使用させず、また、開示しない特性
- ポイント：可用性の定義（認可された者が要求したときに使える）と対になる。「認可されていない者に〜しない」と否定形なら機密性
- 例：R5秋 問40で定義文から特性名を選ぶ問題。R7秋 問41では定義dとして誤りの選択肢に出た

#### 完全性（かんぜんせい / Integrity）

- 意味：情報が正確で、欠けたり改ざんされたりしていない特性
- ポイント：ハッシュ値やデジタル署名で改ざんを検出するのは完全性を守る対策。信頼性（行動と結果の一貫性）と混同しない

#### 可用性（かようせい / Availability）

- 意味：認可されたエンティティが要求したときに、アクセス及び使用が可能である特性
- ポイント：DoS攻撃・故障・災害は可用性を損なう。冗長化・バックアップ・UPSは可用性を高める対策
- 例：R3秋 問39、R7秋 問41で、否認防止・真正性を問う問題の誤りの選択肢として出た

#### 真正性（しんせいせい / Authenticity）

- 意味：エンティティ（人・機器・情報）が、それが主張するとおりのものであるという特性
- ポイント：「なりすましでない」こと。利用者認証やデジタル証明書が真正性を確かめる手段
- 例：R7秋 問41で、定義a〜dから真正性と信頼性の組合せを選ぶ問題

#### 信頼性（しんらいせい / Reliability）

- 意味：意図する行動と結果とが一貫しているという特性
- ポイント：システムがバグなく期待どおり動くこと。完全性（データが正しい）や可用性（使える）とは別
- 例：R7秋 問41（信頼性＝定義a）、R3秋 問39の誤りの選択肢エ

#### 否認防止（ひにんぼうし / Non-repudiation）

- 意味：ある事象や行為が起きたこと、それを誰が行ったかを後から証明でき、本人が「やっていない」と否定できない特性
- ポイント：デジタル署名やタイムスタンプ、操作ログで実現する。真正性は「今その人か」、否認防止は「後から否定させない」
- 例：R3秋 問39「ある利用者があるシステムを利用したという事実が証明可能である」が正解

#### 責任追跡性（せきにんついせきせい / Accountability）

- 意味：ある操作を誰が行ったかを一意にたどれるようにしておく特性
- ポイント：利用者IDの共用禁止とアクセスログの記録で実現する。否認防止は「証明して否定させない」、責任追跡性は「たどれる」

#### 多層防御（たそうぼうぎょ / Defense in Depth）

- 意味：入口・内部・出口などに複数の対策を重ね、一つが破られても次で止める考え方
- ポイント：入口対策（ファイアウォール・メールフィルタ）、内部対策（EDR・ログ監視）、出口対策（通信の監視・DLP）を組み合わせる。ゼロトラストは「内側も信用しない」考え方で、別物

#### セキュリティバイデザイン（Security by Design）

- 意味：システムの企画・設計の段階からセキュリティを組み込んでおく考え方
- ポイント：後から対策を足すより手戻りとコストが小さい。プライバシーバイデザインは個人情報の保護を最初から組み込む考え方で、対象が違う

#### プライバシーバイデザイン（Privacy by Design）

- 意味：個人情報を扱うシステムで、企画・設計の段階からプライバシー保護を組み込んでおく考え方
- ポイント：初期設定で保護が最大になる（プライバシーバイデフォルト）ことも含む。セキュリティバイデザインと対で覚える

### マルウェア

#### ワーム（Worm）

- 意味：ほかのプログラムに寄生せず、自分自身を複製してネットワーク経由で次々に感染を広げる不正プログラム
- ポイント：コンピュータウイルスは他のファイルに寄生する。ワームは単独で動き、自分で広がる

#### コンピュータウイルス（Computer Virus）

- 意味：他のプログラムやファイルに寄生し、それが実行されたときに感染・発病する不正プログラム
- ポイント：経済産業省の「コンピュータウイルス対策基準」では、自己伝染・潜伏・発病のいずれか一つ以上の機能をもつものと定義する

#### マクロウイルス（Macro Virus）

- 意味：表計算ソフトや文書作成ソフトのマクロ機能を悪用し、文書ファイルを開くと動くウイルス
- ポイント：添付された文書ファイルを開くだけで感染する。マクロの自動実行を無効にするのが対策

#### トロイの木馬（Trojan Horse）

- 意味：役に立つソフトウェアに見せかけて利用者に実行させ、裏で不正な処理をする不正プログラム
- ポイント：自己増殖しない点がワーム・ウイルスと違う

#### ボット（Bot）

- 意味：感染したコンピュータを、外部の攻撃者が遠隔操作できる状態にする不正プログラム
- ポイント：大量のボットが組織されたものがボットネットで、DDoS攻撃やスパム送信に使われる。指令を出すのがC&Cサーバ

#### C&Cサーバ（しーあんどしーさーば / Command and Control Server）

- 意味：ボットやRATに感染したコンピュータへ指令を送り、盗んだ情報を受け取る攻撃者側のサーバ
- ポイント：出口対策として、社内からC&Cサーバへの通信を検知・遮断する
- 例：R5春 問36「遠隔操作が可能なマルウェアに、情報収集及び攻撃活動を指示する」が正解
- 語の意味：Command＝命令／Control＝制御

#### RAT（らっと / Remote Access Trojan）

- 意味：感染したPCを攻撃者が遠隔から自由に操作できるようにするトロイの木馬
- ポイント：遠隔操作型ウイルスとも呼ぶ。標的型攻撃で侵入後の足場として使われる
- 語の意味：Remote＝遠隔の／Access＝接続して操作すること／Trojan＝トロイの木馬

#### スパイウェア（Spyware）

- 意味：利用者が気付かないうちに個人情報や操作の履歴などを収集し、外部に送る不正プログラム
- ポイント：キーロガーはスパイウェアの一種で、キー入力の記録に特化している

#### キーロガー（Keylogger）

- 意味：キーボードの入力内容を記録して、パスワードなどを盗む不正プログラムや装置
- ポイント：ソフトウェアキーボードやワンタイムパスワードが対策になる

#### ランサムウェア（Ransomware）

- 意味：PCやサーバのデータを暗号化して使えなくし、元に戻すことと引換えに金銭（身代金）を要求するマルウェア
- ポイント：最近はデータを盗んでから暗号化し「公開されたくなければ払え」と二重に脅す（二重脅迫）。対策は書換えできないバックアップ（WORM・イミュータブル）と3-2-1ルール
- 例：R5秋 問43でWORM機能のストレージにバックアップするのが正解。RAID5・レプリケーション・ネットワークドライブは暗号化が及ぶので不正解

#### ルートキット（Rootkit）

- 意味：攻撃者が侵入後に使う道具一式で、侵入の痕跡やマルウェアの存在をOSから隠す機能をもつもの
- ポイント：ログの改ざんやプロセスの隠蔽をする。バックドアは「再び入るための裏口」で、目的が違う

#### バックドア（Backdoor）

- 意味：一度侵入した攻撃者が、正規の認証を通らずに再び侵入できるようにしておく裏口
- ポイント：ルートキットは隠す道具、バックドアは入口

#### ポリモーフィック型マルウェア（Polymorphic Malware）

- 意味：感染するたびに自身のコードを暗号化し直すなどして見た目を変え、パターンマッチングによる検知を逃れるマルウェア
- ポイント：メタモーフィック型はコードそのものを書き換える。どちらもステルス技術で、対策はビヘイビア法など振る舞いで見る検知

#### ファイルレスマルウェア（Fileless Malware）

- 意味：実行ファイルをディスクに保存せず、PowerShellなど正規のツールやメモリ上だけで動くマルウェア
- ポイント：ファイルを調べるパターンマッチングでは見つけにくい。EDRで振る舞いを監視する

#### エクスプロイトコード（Exploit Code）

- 意味：ソフトウェアの脆弱性を悪用するために作られたプログラムで、攻撃コードとも呼ぶ
- ポイント：使い方によっては脆弱性が実在するかの検証にも使える。エクスプロイトキットは複数のエクスプロイトコードをまとめた攻撃用ツール集
- 例：R6秋 問46が正解ア。誤りの選択肢はマルウェア定義ファイル（イ）、HMAC（ウ）、ワンタイムパスワード（エ）の説明

#### マルウェア定義ファイル（Malware Definition File）

- 意味：既知のマルウェアを見分けるための特徴的なコード（シグネチャ）を集めたファイル
- ポイント：パターンファイルとも呼ぶ。パターンマッチング法で使い、未知のマルウェアは見つけられない
- 例：R6秋 問46でエクスプロイトコードの誤りの選択肢イとして出た

### 不正のしくみと攻撃者

#### 不正のトライアングル（Fraud Triangle）

- 意味：「機会」「動機」「正当化」の3つがそろうと内部不正が起きやすくなるという理論
- ポイント：アクセス権を絞る・監視するは「機会」を減らす対策。米国の犯罪学者クレッシーが提唱

#### 状況的犯罪予防（じょうきょうてきはんざいよぼう / Situational Crime Prevention）

- 意味：犯罪が起きにくい状況を作って予防する考え方で、「やりにくくする」「見つかりやすくする」など5つの観点がある
- ポイント：IPA「組織における内部不正防止ガイドライン」の基本原則のもとになっている（犯行を難しくする・捕まるリスクを高める・犯行の見返りを減らす・犯行の誘因を減らす・犯罪の弁明をさせない）

#### 割れ窓理論（われまどりろん / Broken Windows Theory）

- 意味：小さな乱れを放置すると、より大きな犯罪や規律違反を招くという考え方
- ポイント：クリアデスクや小さなルール違反の是正が、内部不正を防ぐ環境づくりにつながる

#### シャドーIT（Shadow IT）

- 意味：従業員が会社の許可を得ずに業務で使う私物端末やクラウドサービス
- ポイント：情報漏えいの原因になる。CASBで利用状況を見える化して制御する

#### ハクティビズム（Hacktivism）

- 意味：政治的・社会的な主張を目的としたサイバー攻撃
- ポイント：Webサイトの改ざんやDDoS攻撃で主張を発信する。R3春 問38ではフットプリンティングの誤りの選択肢アとして出た

#### 二重脅迫（にじゅうきょうはく / Double Extortion）

- 意味：ランサムウェアでデータを暗号化するだけでなく、事前に盗んだデータを公開すると脅して二重に身代金を要求する手口
- ポイント：盗んだデータを晒す場所がリークサイト。バックアップがあっても情報漏えいの被害は防げない

#### サイバーキルチェーン（Cyber Kill Chain）

- 意味：標的型攻撃の流れを「偵察→武器化→配送→エクスプロイト→インストール→C&C→目的の実行」の7段階に分けたモデル
- ポイント：各段階でどの対策が攻撃を断ち切れるかを考えるのに使う。偵察＝公開情報で調べる、配送＝メールを送る、エクスプロイト＝脆弱性を突いて実行させる
- 例：R4春 問37で「偵察」（SNSの経歴から関係者を洗い出す）、R7秋 問36で「エクスプロイト」（OSの脆弱性を悪用して攻撃ツールを実行させる）が出た

#### 脅威モデリング（Threat Modeling）

- 意味：設計段階でシステムに対する脅威を洗い出し、どこにどんな対策が要るかを分析する手法
- ポイント：STRIDE（なりすまし・改ざん・否認・情報漏えい・サービス拒否・権限昇格）の分類がよく使われる

### パスワードへの攻撃

#### ブルートフォース攻撃（総当たり攻撃 / Brute Force Attack）

- 意味：利用者IDを固定し、パスワードになり得る文字の組合せを全部試してログインを試みる攻撃
- ポイント：一定回数失敗したらロックするアカウントロックが有効
- 例：R4春 問42でレインボー攻撃の誤りの選択肢イとして出た

#### 辞書攻撃（じしょこうげき / Dictionary Attack）

- 意味：辞書の単語や人名など、パスワードによく使われる文字列のリストを順に試す攻撃
- ポイント：R6秋 問40ではパスワードリスト攻撃の誤りの選択肢ア（一般的な単語や人名からリストを作成）として出た

#### リバースブルートフォース攻撃（Reverse Brute Force Attack）

- 意味：よく使われるパスワードを一つ固定し、利用者IDのほうを次々に変えてログインを試みる攻撃
- ポイント：IDごとの失敗回数は1回なので、アカウントロックが効かない

#### パスワードリスト攻撃（Password List Attack）

- 意味：あるサイトから漏れた利用者IDとパスワードの組のリストを使い、別のサイトにログインを試みる攻撃
- ポイント：クレデンシャルスタッフィングとも呼ぶ。パスワードの使い回しを狙う。対策は使い回さないことと多要素認証
- 例：R6秋 問40が正解ウ。R4春 問42では誤りの選択肢アとして出た

#### レインボーテーブル攻撃（Rainbow Table Attack）

- 意味：平文のパスワードとハッシュ値の対応を「チェーン」でまとめた表を事前に作っておき、盗んだハッシュ値から元のパスワードを効率よく割り出す攻撃
- ポイント：対策はソルト（利用者ごとに違う文字列を足してからハッシュ化）。ソルトがあると事前に作った表が使えない
- 例：R4春 問42・R5秋 問36（同じ問題）で正解ウ「平文のパスワードとハッシュ値をチェーンによって管理するテーブル」

### Webアプリケーションへの攻撃

#### クロスサイトスクリプティング（XSS / Cross-Site Scripting）

- 意味：Webページに悪意のあるスクリプトを埋め込み、そのページを見た利用者のブラウザ上で実行させる攻撃
- ポイント：cookieの盗み出しなどに使われる。対策は出力時のエスケープ処理（＜を&amp;lt;に置き換えるなど）と、cookieのHttpOnly属性
- 例：R3春 問37でクリックジャッキング対策の誤りの選択肢ウ（HTMLタグを置き換える）として出た

#### CSRF（しーさーふ / Cross-Site Request Forgery）

- 意味：ログイン中の利用者に罠のリンクを踏ませ、本人が意図しない処理（投稿・送金・設定変更など）を正規サイトに送らせる攻撃
- ポイント：XSSは「利用者のブラウザでスクリプトを動かす」、CSRFは「利用者になりすましてリクエストを送らせる」。対策はページごとの秘密のトークンとSameSite属性
- 語の意味：Cross-Site＝別のサイトをまたぐ／Request＝要求／Forgery＝偽造

#### クリックジャッキング（Clickjacking）

- 意味：透明にした正規サイトのページを罠ページの上に重ね、利用者に気付かせずにボタンをクリックさせる攻撃
- ポイント：対策はHTTPレスポンスヘッダのX-Frame-Options（またはCSPのframe-ancestors）で、自分のページを他サイトのフレームに表示させないこと
- 例：R3春 問37が正解イ「X-Frame-Optionsを設定する」。アのX-Content-Type-Optionsは内容の種類の誤認を防ぐヘッダで別物

#### SQLインジェクション（SQL Injection）

- 意味：入力欄にSQL文の断片を入れて、Webアプリケーションが組み立てるSQL文を書き換え、データベースを不正に操作する攻撃
- ポイント：対策はプレースホルダ（バインド機構）でSQL文を組み立てること
- 例：R4秋 問37でサイドチャネル攻撃の誤りの選択肢エ、R7春 問42でOSコマンドインジェクション対策の誤りの選択肢ア（プレースホルダ）として出た

#### OSコマンドインジェクション（OS Command Injection）

- 意味：入力値にOSのコマンドを紛れ込ませ、Webサーバ上でシェル経由で実行させる攻撃
- ポイント：「;cat /etc/passwd」のように区切り文字の後にコマンドを続ける。対策はシェルを起動できる言語機能を使わないこと
- 例：R7春 問36（ログから脆弱性を推測）と問42（対策はシェルを起動する機能を避ける）

#### ディレクトリトラバーサル（Directory Traversal）

- 意味：ファイル名の入力に「../」を入れて上位のディレクトリをたどり、公開していないファイルを読み出す攻撃
- ポイント：対策はファイル名にディレクトリ名が含まれないかを確認すること。R7春 問42では誤りの選択肢エとして出た

#### バッファオーバーフロー（Buffer Overflow）

- 意味：確保した領域より長いデータを送り込んであふれさせ、プログラムを異常終了させたり、不正なコードを実行させたりする攻撃
- ポイント：C言語のようにメモリを直接扱う言語で起きやすい。対策は入力長の確認と、境界をチェックする関数を使うこと

#### HTTPヘッダインジェクション（HTTP Header Injection）

- 意味：入力値に改行コードを紛れ込ませ、Webアプリケーションが返すHTTPレスポンスヘッダに任意のヘッダや本文を追加させる攻撃
- ポイント：偽のcookieを設定させたりする。R7春 問36では誤りの選択肢アとして出た

#### オープンリダイレクトの悪用（Open Redirect）

- 意味：アクセスすると指定のURLへ自動で移動させる機能を悪用し、正規サイトのURLから攻撃者の偽サイトへ誘導する手口
- ポイント：リンクのドメインは正規サイトなので利用者が信用してしまう。普通のフィッシングとの違いは「正規サイトの転送機能を踏み台にする」こと
- 例：R3秋 問44が正解イ。誤りの選択肢はHTMLメールの偽リンク（ア）、オープンリゾルバ（ウ）、オープンプロキシ（エ）

#### ドライブバイダウンロード（Drive-by Download）

- 意味：Webサイトを閲覧しただけで、利用者が気付かないうちにマルウェアをダウンロード・実行させる攻撃
- ポイント：ブラウザやプラグインの脆弱性を突く。水飲み場型攻撃で使われることが多い

#### セッションハイジャック（Session Hijacking）

- 意味：ログイン後の利用者を見分けるセッションIDを盗んだり推測したりして、その利用者になりすます攻撃
- ポイント：対策はセッションIDを推測できない乱数にする、ログイン時に再発行する、ログアウト時にサーバ側で無効にする、cookieにSecure属性を付ける
- 例：R3春 問44で「WebサーバにおいてセッションIDを無効にする」が正解

### 通信・DNSへの攻撃

#### 中間者攻撃（MITM / Man-in-the-Middle Attack）

- 意味：通信する2者の間に割り込み、両者になりすまして通信内容を盗聴・改ざんする攻撃
- ポイント：相手の証明書を確認するTLSで防ぐ。R4秋 問37でサイドチャネル攻撃の誤りの選択肢ウとして出た

#### MITB攻撃（えむあいてぃーびー / Man-in-the-Browser Attack）

- 意味：利用者のPCのブラウザに入り込んだマルウェアが、通信内容を書き換える攻撃
- ポイント：ネットバンキングで振込先を書き換える。画面も正規サイトも本物でTLSも正しいため、TLSでは防げない。取引内容を別経路で確認する「トランザクション認証」が対策
- 語の意味：Man＝人／in-the-Browser＝ブラウザの中にいる

#### リプレイ攻撃（Replay Attack）

- 意味：盗聴した認証情報などを、そのまま後で再送してなりすます攻撃
- ポイント：毎回値が変わるチャレンジレスポンス認証やワンタイムパスワードで防げる

#### IPスプーフィング（IP Spoofing）

- 意味：送信元IPアドレスを偽ったパケットを送る手口
- ポイント：リフレクション攻撃は送信元を攻撃対象のアドレスに偽って、応答を対象に集中させる

#### DNSキャッシュポイズニング（DNS Cache Poisoning）

- 意味：DNSキャッシュサーバに偽の応答を覚え込ませ、利用者を偽のWebサイトなどへ誘導する攻撃
- ポイント：対策は問合せの送信元ポート番号とDNSヘッダのIDをランダムにすること、DNSSECで応答の正しさを検証すること
- 例：R6春 問36（社内利用者が本来と違うWebサーバに誘導される）、R6秋 問42（IDをランダムに変える）

#### オープンリゾルバ（Open Resolver）

- 意味：インターネット上の誰からの再帰的な問合せにも答えてしまうDNSキャッシュサーバ
- ポイント：DNSリフレクション（DNSアンプ）攻撃の踏み台になる。対策は問合せを受け付けるクライアントを社内に限ること
- 例：R4秋 問36で「送信元IPアドレスを偽装したDNS問合せを多数のDNSサーバに送る」が正解

#### DNSリフレクション攻撃（DNS Reflection Attack）

- 意味：送信元を攻撃対象に偽ったDNS問合せをオープンリゾルバへ大量に送り、増幅された大きな応答を攻撃対象に集中させるDDoS攻撃
- ポイント：小さな問合せが大きな応答になる「増幅」がポイントで、DNSアンプ攻撃とも呼ぶ。R3秋 問44の誤りの選択肢ウの説明

#### 第三者中継（だいさんしゃちゅうけい / Open Relay）

- 意味：外部から来た、外部宛ての電子メールを中継してしまうメールサーバの状態で、スパムの踏み台にされる
- ポイント：送信者も受信者も自社のドメインでなく、接続元も社外なら第三者中継
- 例：R5秋 問38でログから判定（接続元が社外、送信者・受信者とも他社ドメイン＝ウ）

#### DDoS攻撃（でぃーどす / Distributed Denial of Service Attack）

- 意味：多数のコンピュータ（ボットネットなど）から一斉に大量の通信を送り、サービスを停止させる攻撃
- ポイント：DoSは1台から、DDoSは多数から。SYNフラッドはTCPの接続要求だけを大量に送る手口
- 語の意味：Distributed＝分散した／Denial of Service＝サービスの妨害

#### フィッシング（Phishing）

- 意味：実在の企業などを装ったメールやSMSで偽サイトへ誘導し、IDやカード番号を入力させて盗む詐欺
- ポイント：SMSを使うものをスミッシングと呼ぶ。対策は送信ドメイン認証（SPF・DKIM・DMARC）やリンクを直接開かないこと

#### クリプトジャッキング（Cryptojacking）

- 意味：他人のコンピュータの計算資源を無断で使い、暗号資産のマイニング（採掘）をさせる攻撃
- ポイント：情報を盗むのではなく、CPUを盗む。PCが急に重くなるのが兆候

### 標的型攻撃と人をだます手口

#### 標的型攻撃（Targeted Attack / APT）

- 意味：特定の組織を狙い、業務に見せかけたメールなどで侵入し、長期間潜伏して情報を盗む攻撃
- ポイント：APT（Advanced Persistent Threat）は高度で執拗な標的型攻撃を指す。侵入後はラテラルムーブメントで社内に広がる
- 語の意味：Advanced＝高度な／Persistent＝執拗な・持続的な／Threat＝脅威

#### 水飲み場型攻撃（Watering Hole Attack）

- 意味：標的の組織の人がよく見るWebサイトを改ざんし、そこを訪れた標的だけにマルウェアを感染させる攻撃
- ポイント：メールを使わず「待ち伏せ」する。標的のIPアドレスのときだけ感染させることもある

#### やり取り型攻撃（Interaction-based Attack）

- 意味：問合せなどを装って普通のメールを何度かやり取りし、相手が信用したところでマルウェア付きのメールを送る標的型攻撃
- ポイント：最初のメールには何も仕込まないので、怪しまれにくい

#### ビジネスメール詐欺（BEC / Business Email Compromise）

- 意味：取引先や経営者になりすましたメールで、偽の口座に送金させる詐欺
- ポイント：マルウェアを使わないことが多い。対策は送金先の変更を電話など別の手段で確認すること
- 語の意味：Business＝業務の／Email＝電子メール／Compromise＝乗っ取り・侵害

#### ソーシャルエンジニアリング（Social Engineering）

- 意味：技術を使わず、人の心理的なすきや不注意につけ込んでパスワードなどの秘密情報を手に入れる手口
- ポイント：電話でのなりすまし、のぞき見（ショルダーハッキング）、ごみ箱をあさるトラッシングなど

#### トラッシング（Trashing）

- 意味：ごみ箱やごみ置き場から、捨てられた書類や記憶媒体をあさって秘密情報を探す手口
- ポイント：スキャビンジングとも呼ぶ。対策はシュレッダー・溶解処理。R4秋 問37の誤りの選択肢イの説明

#### ショルダーハッキング（Shoulder Hacking）

- 意味：パスワードなどを入力している人の肩越しに画面やキー操作をのぞき見る手口
- ポイント：のぞき見防止フィルタが対策。R7秋 問38の誤りの選択肢ウの説明

#### SEOポイズニング（SEO Poisoning）

- 意味：検索エンジンの検索結果の上位に悪意のあるサイトが表示されるよう細工して、利用者を誘導する手口
- ポイント：話題のキーワードを狙う。SEOは検索エンジン最適化

#### ディープフェイク（Deepfake）

- 意味：AIで人物の顔や声を本物そっくりに合成した偽の動画や音声
- ポイント：経営者の声を偽って送金を指示させるなどの詐欺に使われる
- 例：R6秋 問39で「AI技術によって加工したCEOの音声で送金を指示」が正解。エ（盗んだ認証情報で本物のアカウントから偽メール）はBECでディープフェイクではない

#### プロンプトインジェクション（Prompt Injection）

- 意味：生成AIへの入力に細工した指示を紛れ込ませ、開発者が意図しない回答や動作をさせる攻撃
- ポイント：AIを狙う攻撃。敵対的サンプルは画像などに人には分からない小さなノイズを加えてAIの判定を誤らせる攻撃で、別物

#### 敵対的サンプル（Adversarial Examples）

- 意味：人には気付けないわずかなノイズを加えて、機械学習モデルに誤った判定をさせるように作った入力データ
- ポイント：道路標識の誤認識などが例。プロンプトインジェクションは「指示文で操る」、敵対的サンプルは「入力データの微小な変化でだます」

### 物理・実装への攻撃と攻撃の準備

#### サイドチャネル攻撃（Side-channel Attack）

- 意味：暗号装置が処理中に出す消費電力・処理時間・電磁波などを測定し、その物理的な情報から内部の秘密鍵を推定する攻撃
- ポイント：暗号の計算式そのものを解く攻撃（線形解読法・差分解読法・選択平文攻撃・総当たり）と区別する。消費電力なら電力解析攻撃、時間ならタイミング攻撃、電磁波ならテンペスト攻撃
- 例：ほぼ毎回出る。R4秋 問37、R5秋 問41＝R7春 問37、R7秋 問38

#### テンペスト攻撃（TEMPEST Attack）

- 意味：ディスプレイやケーブルから漏れる微弱な電磁波を受信して、表示内容などを盗み見る攻撃
- ポイント：サイドチャネル攻撃の一種。電磁波を遮るシールドが対策

#### タイミング攻撃（Timing Attack）

- 意味：暗号処理にかかる時間の差を測って、秘密鍵などを推定する攻撃
- ポイント：サイドチャネル攻撃の一種。入力によらず処理時間を一定にするのが対策

#### 電力解析攻撃（Power Analysis Attack）

- 意味：暗号処理中の消費電力の変化を測定・統計処理して、秘密鍵を推定する攻撃
- ポイント：サイドチャネル攻撃の一種。R7秋 問38の正解アの説明

#### プローブ攻撃（Probing Attack）

- 意味：ICチップの配線に探針（プローブ）を当てて信号を直接読み出し、内部の秘密情報を得る攻撃
- ポイント：対策はプローブの取付けを検知したら情報を消去する回路（耐タンパ性）

#### 線形解読法・差分解読法（Linear / Differential Cryptanalysis）

- 意味：暗号アルゴリズムを数学的に分析して鍵を求める解読法。前者は暗号化関数を一次式で近似し、後者は2つの平文の差と暗号文の差の関係を使う
- ポイント：物理量を使わないので、サイドチャネル攻撃ではない
- 例：R5秋 問41・R7春 問37でサイドチャネル攻撃の誤りの選択肢ア（線形近似）・ウ（差分）として出た

#### ゼロデイ攻撃（Zero-day Attack）

- 意味：脆弱性が見つかってから修正プログラムが公開されるまでの間に、その脆弱性を突く攻撃
- ポイント：パッチがまだないので、振る舞い検知やWAF・IPSでの緩和策で守る

#### バージョンロールバック攻撃（Version Rollback Attack）

- 意味：通信の暗号化方式を決める交渉に介入し、脆弱な古いバージョンの方式を使わせる攻撃
- ポイント：ダウングレード攻撃とも呼ぶ。古いSSL/TLSを無効にするのが対策

#### フットプリンティング（Footprinting）

- 意味：攻撃の前に、攻撃対象のPC・サーバ・ネットワークの情報を調べておくこと
- ポイント：公開情報の調査、ポートスキャン、DNSの調査など。サイバーキルチェーンの「偵察」に当たる
- 例：R3春 問38で正解イ。誤りの選択肢はハクティビズム（ア）、ログに偽の痕跡を残す（エ）

#### ポートスキャン（Port Scan）

- 意味：サーバのポートに順に接続を試み、どのポートが開いていて、どんなサービスが動いているかを調べること
- ポイント：TCPでSYNを送りSYN/ACKが返れば開いている、RST/ACKなら閉じている。UDPでICMP port unreachableが返れば閉じている
- 例：R7秋 問43（UDPでICMP port unreachableを受信＝閉じている）

#### ラテラルムーブメント（Lateral Movement）

- 意味：社内の1台に侵入した攻撃者が、そこを足場に認証情報を盗むなどして、ほかのPCやサーバへ横に広がっていくこと
- ポイント：横展開とも呼ぶ。侵入後の内部対策（ログ監視・権限の最小化）が必要

#### RaaS（らーす / Ransomware as a Service）

- 意味：ランサムウェアの開発者が攻撃ツールや基盤を提供し、実行役の攻撃者から身代金の分け前を受け取るビジネスの形
- ポイント：専門知識がなくても攻撃できるようになり、被害が増えた
- 語の意味：Ransomware＝身代金要求型マルウェア／as a Service＝サービスとして提供する

#### ダークネット（Darknet）

- 意味：インターネット上で到達可能だが、どの機器にも割り当てられていない未使用のIPアドレス空間
- ポイント：正規の通信は届かないので、届くパケットは攻撃対象を探すスキャンやマルウェアの通信。観測して攻撃の傾向をつかむ（NICTERなど）。ダークウェブ（特殊なソフトでしか入れない匿名サイト群）とは別
- 例：R6秋 問38で「攻撃者やマルウェアが攻撃対象を探すために送信するパケット」が正解

### 暗号

#### 共通鍵暗号方式（Symmetric Key Cryptography）

- 意味：暗号化と復号に同じ鍵を使う暗号方式
- ポイント：処理が速いが、鍵を安全に渡す方法が課題。n人が互いに通信するには n(n−1)/2 個の鍵が要る。代表はAES

#### 公開鍵暗号方式（Public Key Cryptography）

- 意味：暗号化と復号に、公開鍵と秘密鍵という異なる一組の鍵を使う暗号方式
- ポイント：受信者の公開鍵で暗号化し、受信者の秘密鍵で復号する。n人なら一人一組で2n個
- 例：R6春 問38で鍵の数（2n）を問う問題

#### RSA暗号（あーるえすえー / RSA）

- 意味：大きな数の素因数分解が難しいことを安全性の根拠にした公開鍵暗号
- ポイント：開発者3人（Rivest・Shamir・Adleman）の頭文字。楕円曲線暗号より長い鍵が要る

#### 楕円曲線暗号（だえんきょくせんあんごう / ECC / Elliptic Curve Cryptography）

- 意味：楕円曲線上の離散対数問題の難しさを安全性の根拠にした公開鍵暗号
- ポイント：RSAより短い鍵長で同じレベルの安全性がある
- 例：R5秋 問37で正解ア。誤りの選択肢は「共通鍵暗号方式」「解読不可能が証明されている」「復号鍵を秘密にしなくてよい」

#### Diffie-Hellman鍵共有（でぃふぃーへるまん / DH Key Exchange）

- 意味：盗聴されている通信路でも、お互いが公開する値から同じ共通鍵を作り出せる鍵共有の方式
- ポイント：鍵そのものは送らない。TLSで共通鍵を決めるのに使う。認証機能はないので中間者攻撃には別の対策が要る

#### ハイブリッド暗号（Hybrid Encryption）

- 意味：データ本体は速い共通鍵暗号で暗号化し、その共通鍵を公開鍵暗号で暗号化して渡す方式
- ポイント：両方の長所を組み合わせる。S/MIMEやTLSで使われる

#### AES（えーいーえす / Advanced Encryption Standard）

- 意味：米国の標準として選ばれた共通鍵のブロック暗号で、128ビット単位で暗号化し、鍵長は128・192・256ビット
- ポイント：現在の共通鍵暗号の代表。CRYPTRECの電子政府推奨暗号リストにも入っている
- 語の意味：Advanced＝高度な／Encryption＝暗号化／Standard＝標準

#### ブロック暗号とストリーム暗号（Block Cipher / Stream Cipher）

- 意味：ブロック暗号はデータを決まった長さの塊ごとに暗号化し、ストリーム暗号は1ビットや1バイトずつ順に暗号化する
- ポイント：ブロック暗号を連続したデータに使う方法が暗号利用モード（CBC・CTRなど）。CBCは前のブロックの暗号文を次の暗号化に混ぜ、CTRはカウンタ値を暗号化した結果とXORする

#### CRYPTREC暗号リスト（くりぷとれっく）

- 意味：デジタル庁・総務省・経済産業省が定めた、電子政府で使うべき暗号のリスト。電子政府推奨暗号リスト・推奨候補暗号リスト・運用監視暗号リストの3つからなる
- ポイント：電子政府推奨暗号リスト＝安全性と実装性能が確認され、利用実績が十分か普及が見込まれるもの。推奨候補暗号リスト＝安全性と実装性能は確認済みだが実績がまだ。運用監視暗号リスト＝推奨されなくなったが互換性のために使うもの
- 例：R7春 問35で各リストの説明を選ぶ問題（正解ウ＝電子政府推奨暗号リスト）

#### 危殆化（きたいか / Compromise）

- 意味：暗号アルゴリズムや鍵が、解読や漏えいによって安全でなくなること
- ポイント：秘密鍵が漏れたら証明書を失効させ、CRLやOCSPで知らせる

#### ゼロ知識証明（Zero-knowledge Proof）

- 意味：ある秘密を知っていることを、その秘密自体は一切相手に教えずに証明する方法
- ポイント：秘密計算はデータを暗号化したまま計算する技術で、別物

#### 秘密計算（Secure Computation）

- 意味：データを暗号化などで秘匿したまま計算し、元のデータを見せずに結果だけを得る技術
- ポイント：複数の組織がデータを持ち寄って分析するときに使う

### ハッシュとメッセージ認証

#### ハッシュ関数（Hash Function）

- 意味：任意の長さのデータから、決まった長さの値（ハッシュ値・メッセージダイジェスト）を計算する関数
- ポイント：入力が少しでも違えばハッシュ値は大きく変わる。改ざん検知・デジタル署名・パスワードの保存に使う。SHA-256はSHA-2の一つ

#### 原像計算困難性（一方向性 / Preimage Resistance）

- 意味：あるハッシュ値が与えられたとき、そのハッシュ値になるメッセージを見つけることが計算量的に難しいという性質
- ポイント：ハッシュ値から元に戻せないこと
- 例：R3春 問40で正解ア。ウ（ハッシュ値が一致する2つのメッセージを見つけるのが難しい）は衝突発見困難性

#### 第二原像計算困難性（Second Preimage Resistance）

- 意味：あるメッセージが与えられたとき、それと同じハッシュ値になる別のメッセージを見つけることが難しいという性質
- ポイント：元のメッセージが決まっている点が衝突発見困難性との違い

#### 衝突発見困難性（Collision Resistance）

- 意味：同じハッシュ値になる、異なる2つのメッセージの組を見つけることが難しいという性質
- ポイント：2つとも自由に選んでよい点が第二原像計算困難性との違い

#### MAC（めっく / Message Authentication Code）

- 意味：メッセージと共通鍵から計算する短い値で、受信者が同じ鍵で計算し直して一致すれば、改ざんされておらず鍵を知る相手から来たと確かめられる
- ポイント：共通鍵を使うので、送信者を第三者に証明する否認防止はできない。ハッシュ関数を使うものがHMAC
- 例：R6秋 問46の誤りの選択肢ウ「メッセージとシークレットデータから計算されるハッシュコード」はHMACの説明
- 語の意味：Message＝通信文／Authentication＝認証／Code＝符号

#### HMAC（えっちまっく / Hash-based MAC）

- 意味：ハッシュ関数と共通の秘密鍵を組み合わせて計算するメッセージ認証符号
- ポイント：改ざん検知と、鍵を知っている相手からのメッセージであることを確認できる
- 語の意味：Hash-based＝ハッシュ関数を使った／MAC＝メッセージ認証符号

#### デジタル署名（Digital Signature）

- 意味：送信者が自分の秘密鍵（署名鍵）でメッセージのハッシュ値から署名を作り、受信者が送信者の公開鍵（検証鍵）で検証して、送信者の確認と改ざんの検出を行うしくみ
- ポイント：署名に使うのは送信者の秘密鍵、検証は送信者の公開鍵。暗号化（受信者の公開鍵で暗号化）と逆になる。内容は秘匿しない
- 例：R4春 問39（署名鍵で署名を作成し付加する）、R5春 問38（検証鍵＝送信者の公開鍵で、受信者がメッセージダイジェストを取り出す）

#### タイムスタンプ（時刻認証 / Time Stamp）

- 意味：ある時刻にその電子データが存在し、その後改ざんされていないことを第三者（時刻認証局）が証明するしくみ
- ポイント：デジタル署名は「誰が」、タイムスタンプは「いつ」を証明する

#### コードサイニング（Code Signing）

- 意味：ソフトウェアの配布元がプログラムにデジタル署名を付け、発行元と改ざんされていないことを利用者が確認できるようにすること
- ポイント：署名に使う証明書がコードサイニング証明書

### 利用者認証

#### チャレンジレスポンス認証（Challenge-Response Authentication）

- 意味：サーバが毎回違う乱数（チャレンジ）を送り、クライアントがパスワードと組み合わせて計算した値（レスポンス）を返して、サーバが検証する認証方式
- ポイント：パスワードそのものは通信路に流れず、毎回値が違うのでリプレイ攻撃に強い
- 例：R4春 問38で正解エ。ウ（トークンが表示する毎回違う数字）はワンタイムパスワード。R6秋 問37ではSAMLの誤りの選択肢エとして出た

#### リスクベース認証（Risk-based Authentication）

- 意味：普段と違う端末・場所・時間からのアクセスなど、リスクが高いと判断したときだけ追加の本人確認をする認証方式
- ポイント：いつも2つの方式を使うのは多要素認証。リスクが高いときだけ追加するのがリスクベース認証
- 例：R3春 問39で正解ウ。R7春 問44でもストレッチングの誤りの選択肢ア（普段と異なるログインのときに追加で質問）として出た

#### 多要素認証（Multi-factor Authentication）

- 意味：知識（パスワード）・所有（スマートフォン・ICカード）・生体（指紋・顔）のうち、異なる2種類以上の要素を組み合わせる認証
- ポイント：パスワードと秘密の質問は同じ「知識」なので多要素ではなく多段階認証。多段階認証は認証を何回かに分けて行うこと

#### ワンタイムパスワード（One-time Password）

- 意味：1回しか使えない、使うたびに変わるパスワード
- ポイント：トークンやスマートフォンのアプリが時刻などから生成する。盗まれても再利用できない
- 例：R4春 問38でチャレンジレスポンス認証の誤りの選択肢ウとして出た

#### FIDO2（ふぁいどつー / パスワードレス認証）

- 意味：端末側で生体認証などを行い、その結果を公開鍵暗号を使ってサーバに証明する、パスワードを使わない認証の規格。ブラウザ側の仕様がWebAuthn
- ポイント：サーバには公開鍵しか置かないので、サーバから漏れても悪用されにくい。FIDO UAFはスマートフォン向け、FIDO U2Fはパスワードに追加する2要素目
- 語の意味：FIDO＝Fast IDentity Online（速いオンラインの本人確認）

#### Kerberos認証（けるべろす / Kerberos）

- 意味：認証サーバが発行するチケットを使って、一度の認証でネットワーク上の複数のサーバを利用できるようにする認証方式
- ポイント：Windowsのドメイン認証で使われる。時刻がずれるとチケットが使えない

#### シングルサインオン（SSO / Single Sign-On）

- 意味：一度の認証で、複数のシステムやサービスを利用できるようにするしくみ
- ポイント：実現方式に、cookie型・リバースプロキシ型・SAMLなどのフェデレーション型がある
- 例：R4春 問41（リバースプロキシ型で、利用者IDなどをWebサーバに送るのはリバースプロキシ）

#### SAML（さむる / Security Assertion Markup Language）

- 意味：異なるドメインのシステムやサービスの間で、認証や認可の情報（アサーション）をXML形式で交換するための仕様
- ポイント：IdP（認証する側）が認証結果をブラウザ経由でSP（クラウドサービス側）に渡す。パスワードはクラウド側に渡さない
- 例：R4春 問36（認証や認可に関する情報を交換するための仕様）、R6秋 問37（認証サーバから認証結果をクライアント経由でクラウドサービスに送信）
- 語の意味：Security＝安全／Assertion＝表明・主張／Markup Language＝マークアップ言語

#### OpenID Connect（おーぷんあいでぃーこねくと）

- 意味：OAuth 2.0を土台にして、利用者が誰かという認証の結果（IDトークン）を受け渡す仕様
- ポイント：OAuthは「認可」（何をしてよいか）、OpenID Connectは「認証」（誰か）を足したもの。SAMLはXML、OpenID ConnectはJSON

#### OAuth（おーおーす）

- 意味：利用者のパスワードを渡さずに、あるサービスが別のサービスのデータに限定的にアクセスすることを許可（認可）するしくみ
- ポイント：アクセストークンを発行する。認証ではなく認可のための仕組み

#### IdP（あいでぃーぴー / Identity Provider）

- 意味：利用者を認証し、その結果をほかのサービスに提供する側のシステム
- ポイント：認証結果を受け取って使う側をSP（Service Provider）と呼ぶ。IDaaSはIdPの機能をクラウドで提供するサービス
- 語の意味：Identity＝利用者の身元／Provider＝提供者

#### EMV 3-Dセキュア（3Dセキュア2.0）

- 意味：ネットショッピングでのクレジットカード決済時に、カード会社が本人確認をするサービスで、2.0では取引履歴や端末情報からリスクが高いと判断したときだけ追加認証をする
- ポイント：リスクベース認証の一種。カード券面のセキュリティコードは盗まれたカード番号と一緒に漏れると防げない
- 例：R3秋 問42（盗まれたカードのネットでの不正利用には3Dセキュア）、R6春 問35（高リスクと判断したときに追加の本人認証）

#### CAPTCHA（きゃぷちゃ）

- 意味：ゆがんだ文字の読み取りや画像の選択をさせ、操作しているのが人間かプログラムかを見分ける仕組み
- ポイント：ボットによる自動登録や不正ログインの試行を防ぐ。R6春 問35の誤りの選択肢エ「操作しているのが人間であることを確認」はCAPTCHAの考え方

#### 本人拒否率と他人受入率（FRR / FAR）

- 意味：生体認証で、本人なのに拒否してしまう割合がFRR（本人拒否率）、他人なのに受け入れてしまう割合がFAR（他人受入率）
- ポイント：判定を厳しくするとFARは下がりFRRは上がる。両方は同時に下げられない
- 語の意味：False Rejection Rate＝誤って拒否する率／False Acceptance Rate＝誤って受け入れる率

#### 生体認証（Biometric Authentication）

- 意味：指紋・静脈・虹彩・顔などの身体的特徴や、声紋・署名の書き方などの行動的特徴で本人を確認する認証
- ポイント：忘れたり盗まれたりしにくいが、漏れても変更できない。静脈・虹彩は身体的特徴、声紋・署名は行動的特徴

### 公開鍵基盤（PKI）

#### PKI（ぴーけーあい / Public Key Infrastructure）

- 意味：認証局がデジタル証明書を発行して公開鍵の持ち主を保証し、公開鍵暗号やデジタル署名を安全に使えるようにする基盤
- ポイント：証明書の発行・失効（CRL・OCSP）までを含む
- 語の意味：Public Key＝公開鍵／Infrastructure＝基盤

#### 認証局（CA / Certification Authority）

- 意味：公開鍵とその持ち主の対応を確認し、自らの秘密鍵で署名したデジタル証明書を発行する機関
- ポイント：最上位の認証局がルートCA、その下で実際に発行するのが中間CA。利用者は認証局の公開鍵で証明書の署名を検証する

#### デジタル証明書（公開鍵証明書 / Digital Certificate）

- 意味：公開鍵とその持ち主の情報に、認証局がデジタル署名を付けたデータ
- ポイント：形式はX.509。有効期限内でも、秘密鍵の漏えいなどで失効することがある

#### ルート証明書（Root Certificate）

- 意味：最上位の認証局（ルートCA）が自分自身に発行した証明書で、信頼の起点（トラストアンカー）になるもの
- ポイント：OSやブラウザにあらかじめ組み込まれている。中間CA証明書はルートCAが中間CAに発行したもので、サーバ証明書とルート証明書をつなぐ

#### サーバ証明書（Server Certificate）

- 意味：Webサーバなどの正当性を利用者に示すための証明書で、TLS通信で使う
- ポイント：EV SSL証明書は組織の実在を厳格に審査して発行するサーバ証明書
- 例：R7秋 問37でコードサイニング証明書の誤りの選択肢として出た

#### クライアント証明書（Client Certificate）

- 意味：サーバに接続する利用者や端末の正当性を証明するための証明書
- ポイント：TLSのクライアント認証では、サーバ証明書の送付→クライアント証明書の送付→サーバがクライアントを認証、の順になる
- 例：R3春 問45（順序 b→a→c）、R4春 問41（リバースプロキシで利用者を認証）

#### コードサイニング証明書（Code Signing Certificate）

- 意味：ソフトウェアに付けたデジタル署名を検証して、発行元と改ざんされていないことを確認するための証明書
- ポイント：インストール時に「発行元」を確かめるのに使う
- 例：R7秋 問37で正解ウ。誤りの選択肢はEV SSL証明書・クライアント証明書・サーバ証明書

#### CRL（しーあーるえる / Certificate Revocation List）

- 意味：認証局が、有効期限内だが失効させたデジタル証明書のシリアル番号を載せて公開するリスト
- ポイント：有効期限切れの証明書は載せない。リスト全体をダウンロードして確認する
- 例：R7秋 問39（有効期限内の証明書が失効されたとき、そのシリアル番号をCRLに記載）
- 語の意味：Certificate＝証明書／Revocation＝失効・取消し／List＝一覧

#### OCSP（おーしーえすぴー / Online Certificate Status Protocol）

- 意味：デジタル証明書が失効しているかどうかを、オンラインで問い合わせて確認するプロトコル
- ポイント：CRLは一覧を取り寄せる、OCSPは1枚ずつ問い合わせる。応答するサーバをOCSPレスポンダという
- 例：R4秋 問38（誤りの選択肢はCHAP・LDAP・SNMP）、R7春 問38（失効しているかどうかの状態を問い合わせる）
- 語の意味：Online＝オンラインの／Certificate Status＝証明書の状態／Protocol＝通信の約束事

#### GPKI・BCA（政府認証基盤 / ブリッジ認証局）

- 意味：前者は行政機関の手続をオンラインで安全に行うための政府の公開鍵基盤で、後者は異なる認証局どうしを相互に信頼させるための橋渡しをする認証局
- ポイント：BCAがあると、地方公共団体の認証局や民間の認証局が発行した証明書も政府側で検証できる
- 語の意味：Government＝政府／Bridge＝橋渡し／Certification Authority＝認証局

## 11-2 情報セキュリティ管理

### まとめ表

**リスクアセスメントの3つのプロセス（JIS Q 31000）**

| プロセス | すること | 迷いやすい点 |
| :-: | :-: | :-: |
| リスク特定 | リスクを発見し、認識し、記述する | 資産や組織の資源の性質・価値などを考慮する |
| リスク分析 | 起こりやすさと結果から、リスクレベルを決める | 「結果の性質及び大きさ」「起こりやすさ」はここ |
| リスク評価 | リスク基準と比べて、対応が必要か・優先順位を決める | 「残留リスクが許容可能か」の判断は対応側 |

リスクアセスメント＝特定＋分析＋評価。リスク対応はアセスメントの外（R4秋 問41）。

**リスク対応の選択肢**

| 対応 | すること | 例 |
| :-: | :-: | :-: |
| リスク回避 | リスクの原因となる活動そのものをやめる | 個人情報を持たない業務に変える |
| リスク低減 | 対策で起こりやすさや影響を小さくする | 暗号化・バックアップ・教育 |
| リスク共有（移転） | 他者と分け合う | サイバー保険・外部委託 |
| リスク保有（受容） | 対策せずに受け入れる | 影響が小さく、対策費のほうが高い |

**セキュリティの組織（CSIRT・PSIRT・SOC）**

| 組織 | 守る対象 | すること |
| :-: | :-: | :-: |
| CSIRT | 自組織の情報システム | インシデントの受付・対応・社外との窓口 |
| PSIRT | 自社が販売した製品・サービス | 自社製品の脆弱性への対応、修正、利用者への通知 |
| SOC | 自組織のネットワーク・機器 | ログやアラートを24時間監視して攻撃を検知・分析 |

**脆弱性情報の流れ（情報セキュリティ早期警戒パートナーシップ）**

| 役割 | 担当 |
| :-: | :-: |
| 届出の受付 | IPA |
| 製品開発者との調整（公表日の調整など） | JPCERT/CC |
| 対策情報の公表 | JVN（IPAとJPCERT/CCが共同運営） |

### ISMSの規格と管理策

#### ISMS（あいえすえむえす / Information Security Management System）

- 意味：組織が情報セキュリティのリスクを管理し、方針・目的を決めてPDCAで継続的に改善していく仕組み
- ポイント：要求事項はJIS Q 27001、管理策の手引きはJIS Q 27002。第三者機関の審査を受けるとISMS認証を取得できる
- 語の意味：Information Security＝情報セキュリティ／Management System＝管理の仕組み

#### JIS Q 27001（ISO/IEC 27001）

- 意味：ISMSを確立・実施・維持・改善するための要求事項を定めた規格で、ISMS認証の審査基準になる
- ポイント：27001は「要求事項（〜しなければならない）」、27002は「管理策の実践の手引き」
- 例：R3春 問41で、サイバーセキュリティ経営ガイドラインの誤りの選択肢イ（方針、マネジメントシステムの要求事項、CIAの観点）として出た

#### JIS Q 27002（ISO/IEC 27002）

- 意味：ISMSで使う情報セキュリティ管理策を、組織的・人的・物理的・技術的の4つに分けて具体的に示した手引き
- ポイント：管理策を選ぶときの参考にする。認証の審査基準そのものは27001

#### JIS Q 27017（ISO/IEC 27017）

- 意味：クラウドサービスに特化した情報セキュリティ管理策の指針で、クラウドを提供する側と利用する側の両方の管理策を示した規格
- ポイント：R5春 問39でISMAPの誤りの選択肢エ（パブリッククラウドに特化した管理策を追加した国際規格）として出た

#### JIS Q 27014（ISO/IEC 27014）

- 意味：情報セキュリティガバナンス、つまり経営陣が情報セキュリティを方向付け、監視・評価するための原則と活動を示した規格
- ポイント：ISMSは管理の仕組み、ガバナンスは経営陣による統制

#### 情報セキュリティ方針（Information Security Policy）

- 意味：経営陣が示す、組織の情報セキュリティに対する考え方と取り組む姿勢
- ポイント：情報セキュリティポリシーは「基本方針→対策基準→実施手順」の3層で作ることが多い。基本方針と対策基準をポリシーと呼ぶのが一般的

#### 管理策の4分類（Organizational / People / Physical / Technological Controls）

- 意味：JIS Q 27002:2024で管理策を、組織的管理策・人的管理策・物理的管理策・技術的管理策の4つに分けたもの
- ポイント：管理策のタイプは予防・検知・是正の3つ。サイバーセキュリティ概念は識別・防御・検知・対応・復旧の5つ

#### サイバーハイジーン（Cyber Hygiene）

- 意味：OSの更新、パスワード管理、不要なアカウントの削除など、日頃から基本的な対策を続けて組織を清潔な状態に保つこと
- ポイント：hygiene＝衛生。手洗いのように基本を習慣にする考え方

#### クラウドサービスの責任共有モデル（Shared Responsibility Model）

- 意味：クラウドの利用で、セキュリティの責任をクラウド事業者と利用者がどう分担するかを示した考え方
- ポイント：IaaSでは利用者の責任範囲が広く（OSから上）、SaaSでは狭い。データとアカウントの管理は、どの形態でも利用者の責任

### リスクマネジメント

#### リスクアセスメント（Risk Assessment）

- 意味：リスク特定・リスク分析・リスク評価の3つからなるプロセス全体
- ポイント：リスク対応はアセスメントに含まれない。リスク受容もアセスメントのプロセスではない
- 例：R4秋 問41（リスク特定、リスク分析、リスク評価）

#### リスク特定（Risk Identification）

- 意味：組織の目的の達成を助けたり妨げたりするリスクを発見し、認識し、記述するプロセス
- ポイント：JIS Q 31000では、有形・無形のリスク源、脅威と機会、脆弱性と能力、資産及び組織の資源の性質及び価値などを考慮するとしている
- 例：R6春 問40で正解ウ「資産及び組織の資源の性質及び価値」。ア（結果の性質及び大きさ）・エ（起こりやすさ及び結果）はリスク分析、イ（残留リスクが許容可能か）はリスク対応の考慮事項

#### リスク分析（Risk Analysis）

- 意味：リスクの性質と特徴を理解し、起こりやすさと結果（影響）からリスクレベルを決めるプロセス
- ポイント：数値で表す定量的分析（年間予想損失額など）と、高・中・低などで表す定性的分析がある

#### リスク評価（Risk Evaluation）

- 意味：リスク分析の結果をリスク基準と比べ、どのリスクに対応が必要か、その優先順位を決めるプロセス
- ポイント：「評価」は分析した後の判断。分析と評価の順番を入れ替えた選択肢に注意

#### リスクレベル（Level of Risk）

- 意味：結果とその起こりやすさの組合せとして表現される、リスクの大きさ
- ポイント：起こりやすさを縦軸、影響を横軸にした表がリスクマトリックス
- 例：R4春 問43で正解イ。ア（弱点）は脆弱性、エ（重大性を評価する目安とする条件）はリスク基準

#### リスク基準（Risk Criteria）

- 意味：リスクの重大性を評価するための目安とする条件
- ポイント：どこまでのリスクなら受け入れるかを決めたリスク受容基準を含む。R4春 問43の誤りの選択肢エ

#### 脆弱性（ぜいじゃくせい / Vulnerability）

- 意味：一つ以上の脅威によって付け込まれる可能性のある、資産又は管理策の弱点
- ポイント：脅威は「害を与えるもの（攻撃者・災害など）」、脆弱性は「付け込まれる弱点」。R4春 問43の誤りの選択肢アはこの定義

#### 残留リスク（Residual Risk）

- 意味：リスク対応をした後にも残るリスク
- ポイント：リスクはゼロにできない。残留リスクを受け入れるかどうかはリスク所有者が判断する

#### リスク所有者（Risk Owner）

- 意味：リスクを運用管理することについて、説明責任及び権限をもつ人又は組織
- ポイント：残留リスクの受容やリスク対応計画の承認をする

#### リスク回避（Risk Avoidance）

- 意味：リスクの原因となる活動そのものをやめたり、始めなかったりすることで、リスクをなくす対応
- ポイント：リスク低減は「対策して小さくする」、回避は「やめる」

#### リスク低減（Risk Reduction）

- 意味：対策を講じて、リスクの起こりやすさや起きたときの影響を小さくする対応
- ポイント：暗号化・アクセス制御・教育・バックアップなど、多くの技術的対策はこれに当たる

#### リスク共有（リスク移転 / Risk Sharing）

- 意味：保険や契約によって、リスクの影響を他者と分け合う対応
- ポイント：サイバー保険への加入や業務の外部委託が例。責任そのものまで移せるわけではない

#### リスク保有（リスク受容 / Risk Retention）

- 意味：特に対策をせず、リスクをそのまま受け入れる対応
- ポイント：影響が小さい、または対策費が損失より大きい場合に選ぶ。根拠を残して意思決定する

#### リスクファイナンシング（Risk Financing）

- 意味：損失が起きたときの資金をあらかじめ手当てしておくこと
- ポイント：保険への加入（移転）や引当金の積立て（保有）がある。対策で損失自体を減らすのはリスクコントロール

### インシデント対応と事業継続

#### 情報セキュリティインシデント（Information Security Incident）

- 意味：事業運営を危うくする確率や情報セキュリティを脅かす確率が高い、望まない又は予期しない情報セキュリティ事象
- ポイント：情報セキュリティ事象（セキュリティ上の問題の可能性がある出来事）のうち、実際に脅威となるものがインシデント

#### インシデントハンドリング（Incident Handling）

- 意味：インシデントの検知・連絡受付→トリアージ→インシデントレスポンス（対応）→報告・情報公開、という一連の対応
- ポイント：最初に被害の拡大を防ぐ（封じ込め）ことが大事

#### トリアージ（Triage）

- 意味：受け付けたインシデントの重要度や緊急度を判断し、対応の優先順位を決めること
- ポイント：もとは医療で患者の治療の優先順位を決めること

#### テイクダウン（Takedown）

- 意味：フィッシングサイトや不正なサイトを、管理者やプロバイダに依頼して閉鎖させること
- ポイント：JPCERT/CCなどが依頼を代行することがある

#### デジタルフォレンジックス（Digital Forensics）

- 意味：インシデントが起きたときに、コンピュータやネットワークの記録を法的な証拠として使えるように保全・調査・分析すること
- ポイント：手順は収集→検査→分析→報告。証拠を書き換えないように、ディスクを複製して複製のほうを調べる
- 例：R5春 問42＝R7秋 問44で「ハードディスクを解析し、削除されたログファイルを復元して不正アクセスの痕跡を発見する」が正解。ア（リアルタイム相関分析）はSIEM、エ（ハッシュ値と脅威情報の突合せ）はマルウェア検査

#### コンティンジェンシー計画（緊急時対応計画 / Contingency Plan）

- 意味：災害や重大な障害などの緊急事態が起きたときに、何をどの順で行うかをあらかじめ決めておく計画
- ポイント：BCP（事業継続計画）は事業を止めない・早く戻すための計画全体。コンティンジェンシー計画は緊急時の初動に重点がある

### セキュリティの組織と制度

#### CSIRT（しーさーと / Computer Security Incident Response Team）

- 意味：組織内でセキュリティインシデントの報告を受け付け、対応し、社内外の窓口となるチーム
- ポイント：JPCERT/CCの「CSIRTガイド」は機能とサービス対象で6つに分類（組織内CSIRT・国際連携CSIRT・コーディネーションセンター・分析センター・ベンダーチーム・インシデントレスポンスプロバイダー）
- 例：R4秋 問39（CSIRTマテリアル）、R5秋 問39（コーディネーションセンター＝他のCSIRTとの情報連携・調整）
- 語の意味：Computer Security＝コンピュータの安全／Incident Response＝インシデントへの対応／Team＝チーム

#### PSIRT（ぴーさーと / Product Security Incident Response Team）

- 意味：自社が開発・販売した製品やサービスの脆弱性やインシデントに対応するチーム
- ポイント：CSIRTは自社の情報システム、PSIRTは自社の製品。在庫管理システムや従業員の個人情報のシステムで起きたものはCSIRTの担当
- 例：R6春 問39（自社製品の脆弱性に起因するリスク）、R7秋 問40（顧客に販売した製品とその利用で発生したインシデント）
- 語の意味：Product＝製品／Security Incident＝セキュリティの事故／Response Team＝対応チーム

#### SOC（そっく / Security Operation Center）

- 意味：組織のネットワークや機器のログを24時間体制で監視し、攻撃を検知・分析して対応を助ける組織
- ポイント：SOCは監視と検知、CSIRTはインシデントへの対応と調整。外部の専門業者に委託することも多い
- 語の意味：Security＝安全／Operation＝運用／Center＝拠点

#### JPCERT/CC（JPCERTコーディネーションセンター）

- 意味：特定の政府機関や企業から独立した組織で、国内のインシデントの報告受付、対応支援、発生状況の把握、手口の分析、再発防止策の検討・助言を行う
- ポイント：脆弱性情報では製品開発者との調整役。海外のCSIRTとの窓口でもある
- 例：R3春 問42で正解ウ。ア＝日本産業標準調査会、イ＝CRYPTREC、エ＝NISC。R3秋 問38では製品開発者が公表スケジュールをJPCERT/CCと調整する

#### JVN（じぇいぶいえぬ / Japan Vulnerability Notes）

- 意味：JPCERT/CCとIPAが共同で運営する、日本で使われているソフトウェアなどの脆弱性関連情報と対策情報を提供するポータルサイト
- ポイント：脆弱性を検出するツール（ア）や評価手法（CVSS）、タイプの識別基準（CWE）ではない
- 例：R4秋 問40で正解イ

#### 情報セキュリティ早期警戒パートナーシップ

- 意味：ソフトウェア製品やWebサイトの脆弱性情報を、IPAが届出を受け付け、JPCERT/CCが開発者と調整し、対策と一緒に公表する仕組み
- ポイント：製品開発者は、脆弱性の公表スケジュールをJPCERT/CCと調整して決める。統計情報の公表（イ）やJVNへの書込み（エ）は開発者の役割ではない
- 例：R3秋 問38で正解ウ

#### NISC（にすく / 内閣サイバーセキュリティセンター）

- 意味：内閣官房に置かれた、国のサイバーセキュリティ政策の司令塔となる組織
- ポイント：2025年7月に国家サイバー統括室へ改組された。R3春 問42でJPCERT/CCの誤りの選択肢エ（内閣官房に設置された司令塔）として出た
- 語の意味：National center of Incident readiness and Strategy for Cybersecurity＝インシデントへの備えとサイバーセキュリティ戦略のための国の機関

#### CRYPTREC（くりぷとれっく）

- 意味：電子政府で使う暗号の安全性を評価・監視し、暗号技術の適切な実装法・運用法を調査・検討するプロジェクト
- ポイント：総務省と経済産業省が共同で運営する暗号技術検討会などからなる。CRYPTREC暗号リストを作る
- 語の意味：CRYPTography Research and Evaluation Committees＝暗号技術の調査・評価の委員会

#### J-CSIP・J-CRAT（サイバー情報共有イニシアティブ / サイバーレスキュー隊）

- 意味：前者はIPAを中心に重要インフラなどの企業が標的型攻撃の情報を共有する取組みで、後者はIPAが標的型攻撃を受けた組織の被害の拡大を防ぐために支援するチーム
- ポイント：J-CSIPは「共有」、J-CRATは「救助（レスキュー）」

#### ISMAP（いすまっぷ / 政府情報システムのためのセキュリティ評価制度）

- 意味：政府が求めるセキュリティ要求を満たしているクラウドサービスをあらかじめ評価・登録し、政府のクラウドサービス調達のセキュリティ水準を確保する制度
- ポイント：対象はクラウドサービス。個人情報の保護体制（プライバシーマーク）とは別
- 例：R5春 問39で正解ウ
- 語の意味：Information system Security Management and Assessment Program＝情報システムのセキュリティ管理と評価の制度

#### ISAC（あいざっく / Information Sharing and Analysis Center）

- 意味：同じ業界の企業などが集まって、サイバー攻撃などの情報を共有・分析する組織
- ポイント：金融ISAC・ICT-ISACなど業界ごとにある
- 語の意味：Information Sharing＝情報の共有／Analysis＝分析／Center＝拠点

#### SECURITY ACTION（せきゅりてぃあくしょん）

- 意味：中小企業が情報セキュリティ対策に取り組むことを自ら宣言する、IPAの制度
- ポイント：一つ星・二つ星の2段階がある。第三者の認証ではなく自己宣言

#### NOTICE（のーてぃす）

- 意味：総務省・NICTなどが行う、パスワード設定に不備のあるIoT機器を調査して利用者に注意を呼びかける取組み
- ポイント：IoT機器がボットに乗っ取られるのを防ぐのが目的
- 語の意味：National Operation Towards IoT Clean Environment＝IoTを清潔な環境にするための国の取組み

### 基準とガイドライン

#### サイバーセキュリティ経営ガイドライン

- 意味：経済産業省とIPAが策定した、サイバー攻撃から企業を守るために、経営者が認識すべき3原則と、経営者がセキュリティ担当幹部に指示すべき重要10項目をまとめたもの
- ポイント：経営者向け。対象は経営者のリーダーシップ。ISMS（27001）やCOBITとは別物
- 例：R3春 問41で正解ア。イ＝JIS Q 27001、ウ＝COBIT（ITガバナンスとITマネジメントの40プロセス）、エ＝サイバーセキュリティ基本法

#### サイバーセキュリティ基本法

- 意味：サイバーセキュリティに関する施策の基本理念と、国・地方公共団体・事業者などの責務を定めた法律
- ポイント：NISCやサイバーセキュリティ戦略本部の根拠になる。R3春 問41の誤りの選択肢エ

#### IoTセキュリティガイドライン

- 意味：IoT推進コンソーシアム・総務省・経済産業省が策定した、IoT機器やシステムの方針・分析・設計・構築・運用保守の各段階での要点をまとめた指針
- ポイント：要点17「出荷・リリース後も安全安心な状態を維持する」の対策例は、アップデート方法の検討、アップデート機能の搭載、アップデートの実施
- 例：R3秋 問37で正解イ

#### PCI DSS（ぴーしーあいでぃーえすえす）

- 意味：クレジットカード会員のデータを安全に扱うために、カード会社のブランドが共同で定めたセキュリティ基準
- ポイント：カード情報を扱う加盟店やサービス事業者が対象。R3秋 問41ではCVSSの誤りの選択肢ウとして出た
- 語の意味：Payment Card Industry＝クレジットカード業界／Data Security Standard＝データ保護の基準

#### サイバーセキュリティフレームワーク（NIST CSF）

- 意味：米国のNISTが作った、組織のサイバーセキュリティ対策を「統治・識別・防御・検知・対応・復旧」の機能で整理した枠組み
- ポイント：2.0で「統治（Govern）」が加わり6つになった
- 語の意味：NIST＝米国国立標準技術研究所／Cybersecurity Framework＝サイバーセキュリティの枠組み

#### サイバー・フィジカル・セキュリティ対策フレームワーク（CPSF）

- 意味：経済産業省が作った、仮想空間と現実空間がつながる社会でのサプライチェーン全体のセキュリティ対策の枠組み
- ポイント：企業間のつながり・現実とサイバーの境界・サイバー空間の3つの層で考える

#### 中小企業の情報セキュリティ対策ガイドライン

- 意味：IPAが作った、中小企業が情報セキュリティ対策に取り組むための手順や考え方をまとめた指針
- ポイント：SECURITY ACTIONの宣言とセットで使われる

#### 組織における内部不正防止ガイドライン

- 意味：IPAが作った、組織の内部不正を防ぐための対策を、状況的犯罪予防の考え方をもとにまとめた指針
- ポイント：R4秋 問39でCSIRTマテリアルの誤りの選択肢として出た

#### CSIRTマテリアル

- 意味：JPCERT/CCが作った、組織内CSIRTの構築・運用を支援するための資料
- ポイント：作成したのはJPCERT/CC。ISMSユーザーズガイドはJIPDEC、証拠保全ガイドラインはデジタル・フォレンジック研究会、内部不正防止ガイドラインはIPA
- 例：R4秋 問39で正解ア

### まとめ表

**脆弱性を表すしくみ（Cで始まる4つ）**

| 名前 | 何を表すか | 例 |
| :-: | :-: | :-: |
| CVE | 個々の脆弱性に付ける識別番号 | CVE-2024-12345 |
| CWE | 脆弱性の種類（タイプ） | CWE-79（XSS） |
| CVSS | 脆弱性の深刻度（0.0〜10.0） | 基本評価基準・現状評価基準・環境評価基準 |
| CCE | セキュリティ設定項目の識別子 | パスワードの最小長の設定など |

### 脆弱性の識別と評価

#### CVE（しーぶいいー / Common Vulnerabilities and Exposures）

- 意味：個々の製品に含まれる既知の脆弱性を、一意に識別するために付ける識別子
- ポイント：米国のMITREが採番する。JVNなどの脆弱性情報サイトでも使われる
- 例：R5春 問40（既知の脆弱性を一意に識別）、R6秋 問41（製品に含まれる脆弱性を識別するための識別子）
- 語の意味：Common＝共通の／Vulnerabilities＝脆弱性／Exposures＝露出・さらされた状態

#### CWE（しーだぶりゅーいー / Common Weakness Enumeration）

- 意味：SQLインジェクションやXSSなど、ソフトウェアの脆弱性の種類（タイプ）を体系的に分類した一覧
- ポイント：CVEは「個々の脆弱性」、CWEは「脆弱性のタイプ」。R4秋 問40の誤りの選択肢エ（タイプを識別するための基準）はCWE
- 語の意味：Common＝共通の／Weakness＝弱点／Enumeration＝一覧・列挙

#### CVSS（しーぶいえすえす / Common Vulnerability Scoring System）

- 意味：脆弱性の深刻度を、ベンダーに依存しない共通の基準で0.0〜10.0の点数に評価する仕組み
- ポイント：CVSS v3は基本評価基準（脆弱性そのものの特性）・現状評価基準（攻撃コードの有無など今の状況）・環境評価基準（利用者の環境）の3つ。v4は名前が変わっている
- 例：R3秋 問41で正解ア（基本・現状・環境の3つの基準）
- 語の意味：Common＝共通の／Vulnerability＝脆弱性／Scoring System＝点数を付ける仕組み

#### CCE（しーしーいー / Common Configuration Enumeration）

- 意味：OSやアプリケーションのセキュリティに関する設定項目に付けた識別子
- ポイント：R5春 問40・R6秋 問41の誤りの選択肢（設定項目を識別するための識別子）
- 語の意味：Common＝共通の／Configuration＝設定／Enumeration＝一覧

#### 脆弱性診断（Vulnerability Assessment）

- 意味：システムやWebアプリケーションに既知の脆弱性や設定の不備がないかを、ツールや手作業で網羅的に調べること
- ポイント：ペネトレーションテストは「実際に侵入できるか」を攻撃者の視点で試す。脆弱性診断は「弱点を一覧にする」

#### ペネトレーションテスト（Penetration Test）

- 意味：攻撃者と同じ手法で実際にシステムへの侵入を試み、侵入できるか、どこまで被害が及ぶかを確かめる検査
- ポイント：侵入テストとも呼ぶ。レッドチーム演習は組織の検知・対応力まで含めて試す

#### ファジング（Fuzzing）

- 意味：問題を引き起こしそうな多様なデータ（ファズ）を大量に入力し、ソフトウェアの挙動を監視して脆弱性を見つける検査手法
- ポイント：ポートスキャン（稼働サービスを探す）、IDS（攻撃パターンと照合）、負荷テスト（処理量を測る）、エスケープ処理（無害化）と区別する
- 例：R4春 問45、R4秋 問45、R5秋 問46とよく出る

#### 脆弱性報奨金制度（バグバウンティ / Bug Bounty Program）

- 意味：企業が自社製品やサービスの脆弱性を見つけて報告した人に、報奨金を支払う制度
- ポイント：外部のエシカルハッカー（善意のハッカー）の力を借りて脆弱性を見つける

#### 耐タンパ性（たいたんぱせい / Tamper Resistance）

- 意味：機器やICチップの内部の秘密情報を、外部から不正に読み出したり改変したりすることが難しい性質
- ポイント：分解やプローブの取付けを検知したら情報を消す回路、チップの配線を読み取りにくくする工夫など。予備機・暗号化通信・位置検知は耐タンパ性ではない
- 例：R3秋 問40（ケースが開けられたら内蔵メモリの秘密情報を消去）、R3春 問46＝R6春 問44（プローブの取付けを検出すると保存情報を消去）

### 製品の評価制度

#### ISO/IEC 15408（コモンクライテリア / CC / Common Criteria）

- 意味：IT製品やシステムが、セキュリティの観点から適切に設計・実装されているかを評価するための国際規格
- ポイント：評価方法を定めたのがISO/IEC 18045（CEM）。日本での評価・認証制度がJISEC
- 語の意味：Common＝共通の／Criteria＝評価基準

#### PP（ぴーぴー / Protection Profile）

- 意味：ある種類の製品（ファイアウォール、複合機など）に必要なセキュリティ要件を、ISO/IEC 15408の形式でまとめた文書
- ポイント：調達者が「この製品にはこの要件が要る」と示すのに使う。個々の製品の要件を書いたものはST（セキュリティターゲット）
- 語の意味：Protection＝保護／Profile＝要件をまとめたもの

#### EAL（いーえーえる / Evaluation Assurance Level）

- 意味：ISO/IEC 15408で、評価がどれだけ厳密に行われたかを示す7段階の評価保証レベル
- ポイント：EAL1が最も低く、EAL7が最も厳密。製品の強さではなく「評価の厳密さ」の段階
- 語の意味：Evaluation＝評価／Assurance＝保証／Level＝段階

#### JISEC（じぇいせっく / ITセキュリティ評価及び認証制度）

- 意味：IT製品のセキュリティ機能をISO/IEC 15408に基づいて第三者が評価し、IPAが認証する日本の制度
- ポイント：JCMVPは暗号モジュール（暗号の処理をする部品）を試験・認証する制度で、対象が違う
- 語の意味：Japan Information Technology Security Evaluation and Certification Scheme＝日本のITセキュリティ評価・認証の制度

#### JCMVP（じぇいしーえむぶいぴー / 暗号モジュール試験及び認証制度）

- 意味：暗号機能を実装したハードウェアやソフトウェア（暗号モジュール）が、暗号を正しく安全に実装しているかを試験・認証する制度
- ポイント：IPAが運営する。製品全体のセキュリティ機能を評価するJISECと区別する
- 語の意味：Japan Cryptographic Module Validation Program＝日本の暗号モジュール検証の制度

### 人的セキュリティ対策

#### セキュリティクリアランス（Security Clearance）

- 意味：重要な秘密情報を扱う業務に就く予定の人について、信頼性や適性をあらかじめ評価し、資格を与える制度
- ポイント：日本でも2025年に重要経済安保情報保護活用法が施行された。アクセス権の棚卸し（イ）やクリアデスク（エ）とは別
- 例：R7春 問39で正解ウ「配属される予定の個人の適性を評価する」

#### UEBA（ゆーいーびーえー / User and Entity Behavior Analytics）

- 意味：利用者や機器のふだんの行動を機械学習などで学習し、そこから外れた不審な行動を検知する技術
- ポイント：UBAは利用者の行動だけ、UEBAは機器やアプリ（エンティティ）の行動も対象。内部不正やアカウントの乗っ取りの発見に使う
- 語の意味：User＝利用者／Entity＝機器などの実体／Behavior Analytics＝行動の分析

#### レッドチーム演習（Red Team Exercise）

- 意味：攻撃者役のチームが実際の攻撃と同じように組織を攻め、組織の検知・対応力を試す演習
- ポイント：守る側をブルーチームと呼ぶ。ペネトレーションテストより範囲が広く、人や手順も試す

#### 標的型メール訓練（Targeted Email Training）

- 意味：本物に似せた訓練用の攻撃メールを従業員に送り、開かずに報告できるかを試す訓練
- ポイント：開封率だけでなく、報告までの速さを見るのが大事

### マルウェア対策とバックアップ

#### パターンマッチング法（Pattern Matching）

- 意味：既知のマルウェアの特徴的なコードを集めた定義ファイルとファイルを照合して、マルウェアを検出する方法
- ポイント：誤検知は少ないが、未知のマルウェアや形を変えるポリモーフィック型は見つけられない

#### ビヘイビア法（振る舞い検知 / Behavior Method）

- 意味：プログラムを実際に動かし、ファイルの大量書換えなどの不審な振る舞いを監視してマルウェアを検出する方法
- ポイント：未知のマルウェアも見つけられるが、正常なプログラムを誤検知することがある

#### ヒューリスティック法（Heuristic Method）

- 意味：プログラムの命令の並びなどを調べ、マルウェアに特有の動作をしそうかどうかを推測して検出する方法
- ポイント：静的ヒューリスティック（実行しないで調べる）と動的ヒューリスティック（仮想環境で動かす）がある

#### サンドボックス（Sandbox）

- 意味：外部と隔離した仮想環境でプログラムを実際に動かし、振る舞いを観察してマルウェアかどうかを判定する仕組み
- ポイント：本番の環境に影響を与えずに未知のマルウェアを調べられる。サンドボックスを検知して動きを止めるマルウェアもある

#### EDR（いーでぃーあーる / Endpoint Detection and Response）

- 意味：PCやサーバなどの端末の動作を常に記録・監視し、侵入後の不審な動きを検知して、隔離などの対応を支援する製品
- ポイント：従来のマルウェア対策ソフトは侵入前に止める、EDRは侵入された後に早く見つけて対処する
- 語の意味：Endpoint＝端末／Detection＝検知／Response＝対応

#### 3-2-1ルール（3-2-1 Backup Rule）

- 意味：データのコピーを3つ持ち、2種類の媒体に保存し、そのうち1つは別の場所（オフラインやオフサイト）に置くというバックアップの原則
- ポイント：ランサムウェアにバックアップまで暗号化されないよう、ネットワークから切り離したコピーを持つ

#### WORM（わーむ / Write Once Read Many）

- 意味：一度書き込んだデータは、決められた期間は変更も削除もできず、読み出しだけができる記憶の方式
- ポイント：ランサムウェアにバックアップを書き換えられない。イミュータブルバックアップ（変更できないバックアップ）も同じ考え方
- 例：R5秋 問43で正解ア
- 語の意味：Write Once＝一度だけ書ける／Read Many＝何度でも読める

#### RAID5とレプリケーション（ランサムウェアには効かない冗長化）

- 意味：RAID5はパリティを分散して書き、ディスク1台の故障に耐える構成。レプリケーションはデータを常に別の場所へ複製すること
- ポイント：どちらも故障には強いが、暗号化された内容もそのまま反映されるのでランサムウェア対策にならない
- 例：R5秋 問43の誤りの選択肢イ・ウ

### ネットワーク・クラウドの防御製品

#### ファイアウォール（Firewall）

- 意味：ネットワークの境界で、IPアドレスやポート番号などをもとに、通信を通すか遮断するかを決める仕組み
- ポイント：パケットフィルタリング型とアプリケーションゲートウェイ型がある。Webアプリケーションへの攻撃の中身までは見ない

#### WAF（わふ / Web Application Firewall）

- 意味：Webアプリケーションへの通信（HTTPのやり取り）の中身を検査し、SQLインジェクションやXSSなどの攻撃を遮断する仕組み
- ポイント：DNSキャッシュポイズニング、メールの第三者中継、メール爆弾はHTTPの攻撃ではないので防げない
- 例：R4秋 問42・R6春 問41で正解イ（REST APIサービスに対するAPIの脆弱性を狙った攻撃）
- 語の意味：Web Application＝Webアプリケーション／Firewall＝防火壁

#### IDS（あいでぃーえす / Intrusion Detection System）

- 意味：ネットワークやサーバを監視し、不正な通信や攻撃を検知して管理者に知らせる仕組み
- ポイント：ネットワーク型（NIDS）とホスト型（HIDS）がある。IDSは知らせるだけ、IPSは遮断まで
- 語の意味：Intrusion＝侵入／Detection＝検知／System＝仕組み

#### IPS（あいぴーえす / Intrusion Prevention System）

- 意味：不正な通信を検知したら、その通信を自動的に遮断する仕組み
- ポイント：通信の経路上に置く必要がある。誤検知（フォールスポジティブ）で正常な通信が止まる危険がある
- 語の意味：Intrusion＝侵入／Prevention＝防止／System＝仕組み

#### フォールスポジティブとフォールスネガティブ（False Positive / False Negative）

- 意味：フォールスポジティブは正常なものを誤って攻撃と判定すること（誤検知）、フォールスネガティブは攻撃を見逃して正常と判定すること（見逃し）
- ポイント：検知を厳しくするとフォールスポジティブが増え、緩くするとフォールスネガティブが増える

#### UTM（ゆーてぃーえむ / Unified Threat Management）

- 意味：ファイアウォール・IPS・マルウェア対策・URLフィルタリングなど、複数のセキュリティ機能を1台に統合した装置
- ポイント：中小企業でまとめて導入しやすい。R5春 問41・R7秋 問42で誤りの選択肢として出た
- 語の意味：Unified＝統合された／Threat＝脅威／Management＝管理

#### SIEM（しーむ / Security Information and Event Management）

- 意味：ファイアウォールやサーバなどのログを一元的に集め、相関分析して、セキュリティ上の異常を検知・通知する仕組み
- ポイント：R5春 問41の誤りの選択肢エ（ログを一元管理し、監視者への通知及び相関分析）、R6秋 問43の誤りの選択肢アはSIEMの説明
- 語の意味：Security Information＝セキュリティ情報／Event Management＝出来事の管理

#### DLP（でぃーえるぴー / Data Loss Prevention）

- 意味：機密情報を含むデータを識別し、メールやUSBメモリなどで外部に持ち出されるのを検知・防止する仕組み
- ポイント：守るのは「データ」。どの情報が機密かをあらかじめ登録しておく
- 語の意味：Data＝データ／Loss＝失うこと（漏えい）／Prevention＝防止

#### CASB（きゃすびー / Cloud Access Security Broker）

- 意味：従業員とクラウドサービスの間に入り、クラウドの利用状況を見える化して、許可していない利用（シャドーIT）を検出・制限する仕組み
- ポイント：R7秋 問42の誤りの選択肢ウ（SaaSの利用状況を可視化し、ポリシー違反を検出して接続制限）はCASB
- 語の意味：Cloud Access＝クラウドの利用／Security Broker＝セキュリティの仲介役

#### CSPM（しーえすぴーえむ / Cloud Security Posture Management）

- 意味：クラウドサービスの設定を継続的に監視し、情報漏えいにつながる設定の不備を見つけたり自動で直したりするサービス
- ポイント：CASBは「使い方（利用者側）」、CSPMは「設定（クラウドの構成）」を見る
- 例：R7秋 問42で正解ア
- 語の意味：Cloud Security＝クラウドの安全／Posture＝状態・態勢／Management＝管理

#### MDM（えむでぃーえむ / Mobile Device Management）

- 意味：会社が配ったスマートフォンやタブレットを一元管理し、設定の配布、アプリの制限、紛失時の遠隔ロック・データ消去などを行う仕組み
- 語の意味：Mobile Device＝携帯端末／Management＝管理

#### 検疫ネットワーク（Quarantine Network）

- 意味：社内ネットワークに接続しようとするPCを、まず隔離したネットワークにつなぎ、パッチやマルウェア定義ファイルが最新かを確認してから本来のネットワークへの接続を許す仕組み
- ポイント：持ち込んだPCや長期間使っていないPCからの感染を防ぐ

#### DMZ（でぃーえむぜっと / DeMilitarized Zone）

- 意味：インターネットと社内ネットワークの間に設ける、ファイアウォールで区切られた中間の区域
- ポイント：外部に公開するWebサーバ・メールサーバ・DNSサーバや、両方のネットワークと通信する機器を置く
- 例：R3秋 問45（制御ネットワークとの境界のDMZには、情報ネットワークからアップデートを入手して配るパッチ管理サーバを置く）
- 語の意味：DeMilitarized＝非武装の／Zone＝地帯

#### Webアイソレーション（VDIによる分離 / Web Isolation）

- 意味：Webの閲覧を社内のPCではなく、隔離したサーバ上のブラウザで行い、PCには画面の画像だけを送ることで、マルウェアがPCに届かないようにする仕組み
- ポイント：VDI（仮想デスクトップ）をDMZに置いて使う。画面の画像しか送らないのが効果の理由
- 例：R4春 問44で正解ウ（デスクトップ画面の画像データだけをPCに送信）

### ハードウェア・データ・ソフトウェアの保護

#### TPM（てぃーぴーえむ / Trusted Platform Module）

- 意味：PCなどに搭載され、鍵の生成・保管、ハッシュ演算、暗号処理を行うセキュリティチップ
- ポイント：耐タンパ性があり、中の鍵を外から取り出しにくい。セキュアブートやストレージ暗号化（BitLocker）で使う
- 例：R5春 問41で正解ア。イ＝DKIMなど送信ドメイン認証、ウ＝UTM、エ＝SIEM
- 語の意味：Trusted＝信頼できる／Platform＝基盤／Module＝部品

#### セキュアブート（Secure Boot）

- 意味：PCの起動時に、OSのブートローダやドライバのデジタル署名を検証し、署名が正しいものだけを実行することで、OSが起動する前に動くマルウェアを防ぐ技術
- ポイント：UEFIの機能。BIOSパスワードやHDDパスワードは「誰が起動するか」を制限するだけで、起動するプログラムが正しいかは確かめない
- 例：R5秋 問42で正解ウ

#### セキュアエレメント（Secure Element）

- 意味：スマートフォンやICカードに組み込まれた、耐タンパ性をもつ安全な領域で、鍵や決済情報を保管して処理するチップ
- ポイント：TPMはPC向け、セキュアエレメントはスマートフォンやICカード向けと覚える

#### 暗号化消去（CE / Cryptographic Erase）

- 意味：記憶媒体のデータを暗号化して保存しておき、廃棄するときはその暗号鍵を消すことで、データを読めなくする消去方法
- ポイント：上書きより短時間で済む。SSDなど上書き消去が確実にできない媒体で使う

#### データマスキング（Data Masking）

- 意味：個人情報などの一部を別の文字に置き換えたり隠したりして、元のデータが分からないようにすること
- ポイント：テスト用に本番データを使うときなどに使う

#### k-匿名化（けーとくめいか / k-anonymization）

- 意味：どの組合せで調べても、同じ属性をもつ人が必ずk人以上いるようにデータを加工し、個人を特定しにくくする手法
- ポイント：年齢を「30代」にまとめる一般化などで実現する。上限以上をまとめるのがトップコーディング

#### 電子透かし（Digital Watermark）

- 意味：画像・音声・動画などに、人には分からない形で著作者などの情報を埋め込む技術
- ポイント：不正コピーの追跡や著作権の主張に使う

#### SBOM（えすぼむ / Software Bill of Materials）

- 意味：ソフトウェアを構成するコンポーネント（ライブラリなど）、そのバージョンや相互の依存関係などを一覧にしたもの
- ポイント：使っているライブラリに脆弱性が見つかったとき、影響を受けるかどうかをすぐ調べられる。SBOM管理ツールは脆弱性管理に使う
- 例：R6秋 問43（コンポーネント、相互の依存関係などをリスト化した一覧）、R7春 問40（脆弱性管理に用いる）
- 語の意味：Software＝ソフトウェア／Bill of Materials＝部品表

#### OSINT（おしんと / Open Source Intelligence）

- 意味：インターネット上の公開情報（Webサイト・SNS・報道など）を集めて分析し、役立つ情報を得ること
- ポイント：攻撃者が偵察に使うこともあれば、守る側が脅威インテリジェンスに使うこともある
- 語の意味：Open Source＝公開されている情報源／Intelligence＝情報・諜報

#### 脅威インテリジェンス（Threat Intelligence）

- 意味：攻撃者の手口や使われるIPアドレス・マルウェアの特徴などを集めて分析し、防御に役立てる情報
- ポイント：STIXは脅威情報を記述する形式、TAXIIはそれを交換する仕組み。R4春 問36の誤りの選択肢イ（脅威情報を交換する仕様）はSTIX・TAXIIの説明

### 物理的セキュリティ対策

#### 入退室管理（Physical Access Control）

- 意味：ICカードや生体認証などで、誰がいつどの部屋に入退室したかを管理・記録すること
- ポイント：共連れ（認証した人の後に続いて入る）を防ぐのがアンチパスバックとインターロック

#### アンチパスバック（Anti-passback）

- 意味：入室の記録がない人は退室できない、退室の記録がない人は再び入室できないようにして、共連れを防ぐ仕組み
- ポイント：インターロックは「一方の扉が閉まらないと、もう一方の扉が開かない」二重扉の仕組みで、別物

#### インターロック（Interlock）

- 意味：二つの扉のうち一方が閉まっていないと他方が開かない仕組みで、一度に一人ずつしか通れないようにするもの
- ポイント：共連れの防止に使う。アンチパスバックは記録の矛盾で防ぐ

#### クリアデスク・クリアスクリーン（Clear Desk / Clear Screen）

- 意味：離席するときに机の上に書類や記憶媒体を出したままにせず、PCの画面もロックしておくこと
- ポイント：R7春 問39でセキュリティクリアランスの誤りの選択肢エとして出た

### 安全な通信プロトコル

#### IPsec（あいぴーせっく / IP Security）

- 意味：ネットワーク層（IP）で通信を暗号化・認証するプロトコルの集まりで、認証ヘッダ（AH）と暗号ペイロード（ESP）、鍵交換のIKEからなる
- ポイント：IPv6では拡張ヘッダを使って実現する。AHは認証と改ざん検知だけで暗号化しない、ESPは暗号化もする
- 例：R3秋 問36（IPv6の拡張ヘッダで実現できるのは暗号化通信機能）、R3秋 問43（AHとESPを含む）、R6春 問42（IPv6でネットワーク層の暗号化）
- 語の意味：IP＝インターネットプロトコル／Security＝安全

#### TLS（てぃーえるえす / Transport Layer Security）

- 意味：TCPの上で、サーバ証明書による相手の認証と、通信の暗号化・改ざん検知を行うプロトコル
- ポイント：SSLの後継。HTTPS・メールの暗号化・SSL-VPNで使う。クライアント証明書で利用者を認証することもできる
- 語の意味：Transport Layer＝トランスポート層／Security＝安全

#### SSH（えすえすえいち / Secure Shell）

- 意味：ネットワーク越しにほかのコンピュータへ安全にログインし、操作やファイル転送をするための暗号化プロトコル
- ポイント：アプリケーション層のプロトコル。公開鍵による利用者認証ができる。R3秋 問43・R6春 問42で誤りの選択肢として出た
- 語の意味：Secure＝安全な／Shell＝コマンドを受け付けるプログラム

#### L2TP（えるつーてぃーぴー / Layer 2 Tunneling Protocol）

- 意味：データリンク層（レイヤ2）のフレームをIPネットワーク上でトンネルのように運ぶプロトコル
- ポイント：暗号化機能はないので、IPsecと組み合わせて使う（L2TP/IPsec）
- 例：R7春 問43（上から TLS／IPsec／L2TP の順）
- 語の意味：Layer 2＝第2層（データリンク層）／Tunneling＝トンネルを作る／Protocol＝通信の約束事

#### QUIC（くいっく）

- 意味：UDPの上で、TLS1.3による暗号化を組み込んで高速に接続を確立する通信プロトコルで、HTTP/3で使われる
- ポイント：TCPとTLSのやり取りを一つにまとめて、接続までの往復を減らす

#### WPA3（だぶりゅーぴーえーすりー / Wi-Fi Protected Access 3）

- 意味：無線LANの暗号化と認証の規格で、WPA2の後継
- ポイント：パスワードを総当たりで試されにくいSAEという鍵交換を使う。Enhanced Open（OWE）は、パスワードなしの公衆無線LANでも通信を暗号化する方式
- 語の意味：Wi-Fi＝無線LAN／Protected Access＝保護された接続

#### HSTS（えっちえすてぃーえす / HTTP Strict Transport Security）

- 意味：Webサーバがブラウザに「このサイトには今後HTTPSだけで接続せよ」と指示し、HTTPでの接続をさせない仕組み
- ポイント：最初にHTTPで接続した瞬間を狙う中間者攻撃を防ぐ
- 語の意味：HTTP＝Web通信のプロトコル／Strict＝厳格な／Transport Security＝通信の安全

### メールのなりすまし対策

#### SPF（えすぴーえふ / Sender Policy Framework）

- 意味：受信側のメールサーバが、送信元ドメインのDNSに登録された送信サーバのIPアドレスと、実際にメールを送ってきたサーバのIPアドレスを照合し、送信元ドメインの詐称を見抜く仕組み
- ポイント：IPアドレスで確かめるのがSPF、デジタル署名で確かめるのがDKIM
- 例：R4秋 問44＝R6春 問43で正解イ。アはDKIM
- 語の意味：Sender＝送信者／Policy＝方針／Framework＝枠組み

#### DKIM（でぃーきむ / DomainKeys Identified Mail）

- 意味：送信側のメールサーバが電子メールのヘッダにデジタル署名を付け、受信側がDNSで公開された公開鍵で検証して、送信元ドメインの認証と改ざんの検知を行う仕組み
- ポイント：署名するのはメールサーバ（ドメイン単位）。利用者が自分で署名・暗号化するのはS/MIME
- 例：R5秋 問44（イ＝SMTP-AUTH、ウ＝DMARC、エ＝SPF）、R7秋 問45（誤りの選択肢はOP25B・S/MIME・SPF）
- 語の意味：DomainKeys＝ドメインの鍵／Identified＝識別された／Mail＝電子メール

#### DMARC（でぃーまーく / Domain-based Message Authentication, Reporting and Conformance）

- 意味：SPFやDKIMの認証に失敗したメールをどう扱うか（何もしない・隔離・拒否）のポリシーを送信側がDNSに登録し、受信側からの認証結果の報告を受け取る仕組み
- ポイント：SPF・DKIMの結果を使う「上乗せ」の仕組み。R5秋 問44の誤りの選択肢ウ
- 語の意味：Domain-based＝ドメインに基づく／Message Authentication＝メッセージ認証／Reporting＝報告／Conformance＝適合

#### SMTP-AUTH（えすえむてぃーぴーおーす）

- 意味：メールを送信するときに、送信側のメールサーバが利用者IDとパスワードで送信者を認証する仕組み
- ポイント：サブミッションポート（587番）と組み合わせて使う
- 例：R5春 問44で正解エ（サブミッションポートの目的）。R5秋 問44の誤りの選択肢イ
- 語の意味：SMTP＝メール送信のプロトコル／AUTH＝Authentication（認証）

#### サブミッションポート（Submission Port）

- 意味：利用者のメールソフトがメールサーバへメールを送るときに使う587番ポートで、SMTP-AUTHによる送信者の認証と組み合わせる
- ポイント：OP25Bで25番が使えなくても、587番で認証してから送れる
- 例：R5春 問44（目的はSMTP-AUTHで送信者を認証すること）

#### OP25B（おーぴーにじゅうごびー / Outbound Port 25 Blocking）

- 意味：ISPが、自社の接続サービスの利用者のPCなどから外部のメールサーバへの25番ポートの通信を遮断し、スパムの直接送信を防ぐ仕組み
- ポイント：外へ出ていく（outbound）25番を止める。正規のメールはISPのメールサーバかサブミッションポートを使う
- 語の意味：Outbound＝外向きの／Port 25＝25番ポート（SMTP）／Blocking＝遮断

#### POP before SMTP（ぽっぷびふぉあえすえむてぃーぴー）

- 意味：メールを送る前にPOPで受信の認証をさせ、認証に成功したIPアドレスから一定時間だけメールの送信を許す仕組み
- ポイント：SMTP-AUTHが普及する前の方法。R5春 問44の誤りの選択肢ウ

#### S/MIME（えすまいむ / Secure MIME）

- 意味：利用者が公開鍵の証明書を使って、電子メールの本文の暗号化とデジタル署名を行う規格
- ポイント：利用者の端末で行う。DKIMはメールサーバがドメイン単位で署名する
- 語の意味：Secure＝安全な／MIME＝Multipurpose Internet Mail Extensions（いろいろな形式のデータをメールで送る規格）

### ネットワークの認証とDNSの保護

#### DNSSEC（でぃーえぬえすせっく / DNS Security Extensions）

- 意味：権威DNSサーバがリソースレコードに秘密鍵でデジタル署名を付け、DNSキャッシュサーバが公開鍵で検証することで、DNSの応答が正しく改ざんされていないことを確かめる仕組み
- ポイント：使うのは公開鍵暗号によるデジタル署名。通信の暗号化はしない（情報漏えいは防げない）。ポート番号のランダム化やオープンリゾルバ対策とは別
- 例：R5秋 問45、R6春 問37、R6秋 問44とほぼ毎年出る
- 語の意味：DNS＝ドメイン名の仕組み／Security Extensions＝安全のための拡張

#### IEEE 802.1X（あいとりぷるいーはちまるにーてんいちえっくす）

- 意味：LANや無線LANに機器を接続するときに、認証サーバ（RADIUS）で利用者や端末を認証し、認証に成功した場合だけ通信を許す規格
- ポイント：認証方式にEAP-TLS（クライアント証明書で認証）やPEAP（サーバ証明書＋ID・パスワード）を使う

#### RADIUS（らでぃうす / Remote Authentication Dial In User Service）

- 意味：ネットワークに接続しようとする利用者の認証や、利用記録の管理を、一つのサーバでまとめて行うためのプロトコル
- ポイント：IEEE 802.1Xの認証サーバとして使う。後継がDiameter
- 語の意味：Remote Authentication＝遠隔からの認証／Dial In User Service＝電話回線で接続する利用者向けのサービス

#### 認証VLAN（にんしょうぶいらん / Authentication VLAN）

- 意味：PCをネットワークにつないだときに利用者を認証し、その利用者に応じたVLAN（セグメント）に動的に割り当てる仕組み
- ポイント：スタティックVLANはポートごとに固定でVLANを決める。フリーアドレスで席が変わっても、幹部だけ特定のセグメントに入れるには認証VLAN
- 例：R5春 問45で正解エ

#### VLANによるセグメントの分割（Virtual LAN）

- 意味：1台のスイッチのポートをグループに分け、論理的に別々のネットワーク（セグメント）として扱うこと
- ポイント：ブロードキャストが届く範囲を限るので、アドレス情報が不要に広がるのを防げる。MACアドレスでの接続可否の判断はMACアドレスフィルタリング
- 例：R6秋 問45で正解イ

#### MACアドレスフィルタリング（MAC Address Filtering）

- 意味：登録したMACアドレスをもつ機器だけを、スイッチや無線LANのアクセスポイントに接続させる仕組み
- ポイント：MACアドレスは偽装できるので、なりすましは完全には防げない
- 例：R5春 問43の誤りの選択肢ア（偽装した端末からの接続を遮断できる、が誤り）

#### プライバシーセパレータ（Privacy Separator）

- 意味：同じ無線LANのアクセスポイントに接続している端末どうしが、アクセスポイントを経由して通信することを遮断する機能
- ポイント：公衆無線LANで、同じアクセスポイントにつないだ他人の端末から攻撃されるのを防ぐ。SSIDの暗号化はできない
- 例：R5春 問43で正解エ

#### IPマスカレード（NAPT / Network Address Port Translation）

- 意味：ルータが、プライベートIPアドレスとポート番号の組を、グローバルIPアドレスと別のポート番号の組に変換し、1つのグローバルアドレスを複数の端末で共有する仕組み
- ポイント：外へ出るパケットは送信元のIPアドレスとポート番号が書き換わる。インターネット側から内部の端末に直接接続を始められないので、侵入を防ぐ効果もある
- 例：R4秋 問43（家庭の無線LANルータで期待できる効果）、R5春 問45では誤りの選択肢
- 語の意味：Network Address＝ネットワークのアドレス／Port＝ポート番号／Translation＝変換

#### リバースプロキシ（Reverse Proxy）

- 意味：Webサーバの手前に置き、利用者からのリクエストを代わりに受けてWebサーバに中継するサーバ
- ポイント：シングルサインオンでは、リバースプロキシが利用者を認証し、利用者IDなどの情報をWebサーバに送る
- 例：R4春 問41で正解エ

#### ハニーポット（Honeypot）

- 意味：わざと攻撃されやすく見せかけたおとりのシステムを置き、攻撃の手口を観察・記録する仕組み
- ポイント：本物の資産は置かない。ダークネットの観測とあわせて攻撃の傾向をつかむ

### OSとWebアプリケーションの防御

#### セキュアOS（Secure OS）

- 意味：強制アクセス制御や最小特権の機能を備え、管理者権限を奪われても被害を限定できるようにしたOS
- ポイント：SELinuxが代表例。シングルサインオン（ア）・WAF（イ）・ワンタイムパスワード（エ）とは別
- 例：R5春 問37で正解ウ（強制アクセス制御で、侵入されてもファイルの改ざんを防止）

#### 強制アクセス制御（MAC / Mandatory Access Control）

- 意味：システムの管理者が決めたセキュリティポリシーに従ってアクセス権を強制し、ファイルの所有者でも自由に変更できないようにするアクセス制御
- ポイント：任意アクセス制御（DAC）は所有者が自分でアクセス権を決める。ここでのMACはメッセージ認証符号やMACアドレスとは別
- 語の意味：Mandatory＝強制の／Access Control＝アクセス制御

#### プレースホルダ（Placeholder）

- 意味：SQL文の中で値を入れる場所を記号（?など）で確保しておき、値を後から機械的に当てはめる仕組み
- ポイント：入力値がSQL文の一部として解釈されないので、SQLインジェクションを防げる。バインド機構とも呼ぶ

#### エスケープ処理（Escaping）

- 意味：特別な意味をもつ文字（＜、＞、"、'など）を、意味をもたない別の文字列に置き換えて無害にする処理
- ポイント：HTMLへの出力時に行えばXSS対策。R4秋 問45ではファジングの誤りの選択肢エとして出た

#### cookieのSecure属性（Secure Attribute）

- 意味：cookieに付けると、HTTPSで通信するときだけブラウザがそのcookieを送るようにする属性
- ポイント：HttpOnly属性はJavaScriptからcookieを読めなくする（XSS対策）。SameSite属性は他サイトからのリクエストにcookieを付けない（CSRF対策）。有効期限はExpires、送る範囲はPath
- 例：R7春 問41で正解イ。ア＝Expires、ウ＝Path、エ＝HttpOnly

#### サードパーティcookie（Third-party Cookie）

- 意味：閲覧しているWebサイトとは別のドメイン（広告配信事業者など）が発行するcookie
- ポイント：複数のサイトをまたいで閲覧の履歴を追跡（トラッキング）するのに使われる。ブロックするとトラッキングされにくくなる
- 例：R4春 問40で正解イ

#### Same Origin Policy（同一オリジンポリシー）

- 意味：あるオリジン（スキーム・ホスト・ポート番号の組）から読み込んだスクリプトは、別のオリジンのデータにアクセスできないというブラウザの制限
- ポイント：CORSはこの制限を、サーバ側の許可によって安全に緩める仕組み

#### CORS（こーず / Cross-Origin Resource Sharing）

- 意味：Webサーバがレスポンスヘッダで許可を示すことで、別のオリジンのWebページからのアクセスをブラウザに許可させる仕組み
- ポイント：許可するオリジンを「*（すべて）」にすると危険
- 語の意味：Cross-Origin＝オリジンをまたぐ／Resource Sharing＝資源の共有

#### X-Frame-Options（えっくすふれーむおぷしょんず）

- 意味：自分のWebページを、他のサイトのフレーム（iframe）の中に表示してよいかをブラウザに指示するHTTPレスポンスヘッダ
- ポイント：クリックジャッキング対策。X-Content-Type-Optionsはファイルの種類の推測をさせないためのヘッダで別物
- 例：R3春 問37で正解イ

#### セッションIDの管理（Session Management）

- 意味：ログイン中の利用者を識別するセッションIDを、推測できない乱数にし、ログイン時に新しく発行し直し、ログアウト時にサーバ側で無効にすること
- ポイント：ブラウザのキャッシュを消してもサーバ側でセッションIDが有効なら乗っ取られる
- 例：R3春 問44で正解イ

#### ソルト（Salt）

- 意味：パスワードをハッシュ化する前に、利用者ごとに異なるランダムな文字列を付け加えること
- ポイント：同じパスワードでもハッシュ値が利用者ごとに違うので、レインボーテーブルが使えなくなる
- 例：R7春 問44でストレッチングの誤りの選択肢エ（利用者IDごとに異なる文字列を付加してからハッシュ化）

#### ストレッチング（Stretching）

- 意味：パスワードのハッシュ化を何千回、何万回と繰り返し、1回の照合にかかる時間を長くすること
- ポイント：総当たりで試す攻撃者の手間を大きく増やす。ソルトは「付け足す」、ストレッチングは「繰り返す」
- 例：R7春 問44で正解ウ

#### アカウントロック（Account Lockout）

- 意味：一定時間内にパスワードを一定回数間違えたら、そのアカウントへのログインをしばらくできなくする仕組み
- ポイント：ブルートフォース攻撃に有効。リバースブルートフォース攻撃やパスワードリスト攻撃には効きにくい。R7春 問44の誤りの選択肢イ

#### ソースコード静的検査（Static Code Analysis）

- 意味：プログラムを実行せずに、ソースコードを読んで脆弱性や規約違反を見つける検査
- ポイント：動的検査（ファジングなど）はプログラムを動かして調べる。SASTとも呼ぶ

#### コンテナセキュリティ（Container Security）

- 意味：Dockerなどのコンテナで動くアプリケーションを守るための対策で、イメージの脆弱性検査、権限の最小化、実行時の監視などを行う
- ポイント：コンテナはホストのOSを共有するので、一つが乗っ取られると他に広がるおそれがある
