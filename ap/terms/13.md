## 13-1 開発プロセス・手法

### まとめ表

**アジャイルの主な手法**

| 手法 | 特徴 |
| :-: | :-: |
| スクラム | スプリントを繰り返す。役割はプロダクトオーナー・スクラムマスター・開発者 |
| XP | ペアプログラミング・テスト駆動開発・リファクタリング・継続的インテグレーション |
| かんばん | 作業を見える化し、同時に進める作業の量を制限する |


### 開発モデルと手法

#### ウォーターフォールモデル（Waterfall Model）

- 意味：工程を順番に進め、原則として後戻りしないモデル

#### プロトタイピングモデル（Prototyping Model）

- 意味：試作品を作って利用者に確かめ、要件を固めるモデル

#### スパイラルモデル（Spiral Model）

- 意味：設計・開発・評価を繰り返して、少しずつ大きくするモデル
- ポイント：リスク分析を各周回で行う

#### アジャイル開発（Agile Development）

- 意味：短い期間で動くものを作り、変化に合わせて進める開発
- ポイント：アジャイルソフトウェア開発宣言の4つの価値

#### スクラム（Scrum）

- 意味：スプリント（1〜4週間）を繰り返して進めるアジャイルの枠組み
- ポイント：プロダクトバックログ・スプリントレビュー・レトロスペクティブ

#### ユーザーストーリー（User Story）

- 意味：利用者から見た要求を「〜として、〜したい、なぜなら〜」の形で短く書いたもの

#### ベロシティ（Velocity）

- 意味：1回のスプリントで終えた作業の量
- ポイント：次の計画に使う

#### DevOps（でぶおぷす / Development and Operations）

- 意味：開発と運用が協力し、速く確実にリリースする考え方
- 語の意味：Development＝開発／Operations＝運用

#### CI/CD（Continuous Integration / Continuous Delivery）

- 意味：変更を頻繁に統合して自動でテストし、いつでもリリースできる状態に保つこと
- 語の意味：Continuous＝継続的な／Integration＝統合／Delivery＝提供

#### 共通フレーム（SLCP-JCF）

- 意味：ソフトウェアの開発から廃棄までの作業と用語の意味をそろえた枠組み

#### CMMI（しーえむえむあい / Capability Maturity Model Integration）

- 意味：組織の開発プロセスの成熟度を5段階で評価するモデル
- 語の意味：Capability＝能力／Maturity＝成熟度／Model＝模型／Integration＝統合

#### マッシュアップ（Mashup）

- 意味：公開されている複数のWeb APIを組み合わせて、新しいサービスを作ること


### 開発モデルと手法（発展）

#### V字モデル（V-Model）

- 意味：設計の各工程と、それを確かめるテストの工程を、V字の形で対応させた開発モデル
- ポイント：要件定義と受入れテスト、詳細設計と単体テストが対応する

#### W字モデル（W-Model）

- 意味：V字モデルに、設計の段階からテストの準備を並行して進める考えを加えたもの

#### インクリメンタルモデル（Incremental Model）

- 意味：システムを機能ごとに分け、少しずつ作って追加していく開発モデル

#### 反復型開発（Iterative Development）

- 意味：計画・設計・作成・評価を何度も繰り返して、完成度を上げていく開発

#### RAD（らど / Rapid Application Development）

- 意味：少人数で、開発ツールや試作を使って短い期間で作る開発の方法
- 語の意味：Rapid＝速い／Application＝アプリケーション／Development＝開発

#### タイムボックス（Timebox）

- 意味：作業に使う期間を先に決めて、その中でできることをする考え方

#### アジャイルソフトウェア開発宣言（Agile Manifesto）

- 意味：個人と対話、動くソフトウェア、顧客との協調、変化への対応を大事にするという宣言

#### イテレーション（Iteration）

- 意味：アジャイル開発で、計画から評価までを行う短い期間
- ポイント：1〜4週間くらい

#### スプリント（Sprint）

- 意味：スクラムでのイテレーションの呼び方

#### プロダクトバックログ（Product Backlog）

- 意味：プロダクトに必要な機能や改善を、優先順に並べた一覧
- ポイント：プロダクトオーナーが管理する

#### スプリントバックログ（Sprint Backlog）

- 意味：今回のスプリントでやる作業の一覧

#### プロダクトオーナー（Product Owner）

- 意味：何を作るかと優先順位を決める責任者

#### スクラムマスター（Scrum Master）

- 意味：スクラムがうまく進むように、チームを支える役割

#### デイリースクラム（Daily Scrum）

- 意味：毎日短い時間で、進み具合と困りごとを共有する会

#### スプリントレビュー・レトロスペクティブ（Sprint Review / Retrospective）

- 意味：作ったものを関係者に見せる会と、チームの進め方をふり返る会

#### バーンダウンチャート（Burndown Chart）

- 意味：残りの作業量が日ごとにどう減っているかを表したグラフ

#### インセプションデッキ（Inception Deck）

- 意味：プロジェクトの目的や範囲を、始める前にチームで確かめるための質問の集まり

#### ストーリーポイント（Story Point）

- 意味：ユーザーストーリーの大きさを、ほかと比べた相対的な数で表したもの

#### 計画ポーカー（Planning Poker）

- 意味：数字の書かれたカードを同時に出して、作業の大きさを見積もる方法

#### カンバン（Kanban）

- 意味：作業をカードにして「やる・やっている・終わった」の列に並べ、流れを見えるようにする方法
- ポイント：同時に進める作業の数を制限する

#### 継続的インテグレーション（Continuous Integration）

- 意味：変更を頻繁にまとめ、自動でビルドとテストを行うこと

#### 継続的デリバリ・継続的デプロイ（Continuous Delivery / Deployment）

- 意味：いつでも本番に出せる状態を保つことと、テストに通ったら自動で本番に出すこと

#### 自動テスト（Automated Testing）

- 意味：テストをプログラムで自動に行うこと
- ポイント：CI/CDには欠かせない

#### ペアプログラミング（Pair Programming）

- 意味：2人1組で、1人が書き、もう1人が確かめながらプログラムを作ること

#### モブプログラミング（Mob Programming）

- 意味：チーム全員が1つの画面を見ながら、一緒にプログラムを作ること

#### テスト駆動開発（TDD / Test-Driven Development）

- 意味：先にテストを書き、そのテストに通るようにプログラムを作る開発の進め方

#### リファクタリング（Refactoring）

- 意味：外から見た動きは変えずに、プログラムの中の作りを整理すること

#### 振る舞い駆動開発（BDD / Behavior-Driven Development）

- 意味：利用者から見た振る舞いを、決まった書き方で例として書き、それをテストにする開発
- ポイント：Given-When-Thenの形

#### XP（えっくすぴー / Extreme Programming）

- 意味：ペアプログラミングやテスト駆動開発などの習慣を徹底するアジャイルの手法
- 語の意味：Extreme＝極端な／Programming＝プログラミング

#### FDD（えふでぃーでぃー / Feature-Driven Development）

- 意味：利用者に価値のある機能（フィーチャ）ごとに計画して作るアジャイルの手法

#### リーンソフトウェア開発（Lean Software Development）

- 意味：トヨタの生産方式の考え方を取り入れ、むだをなくすことを大事にする開発

#### SAFe（せいふ / Scaled Agile Framework）

- 意味：大きな組織で、たくさんのチームがアジャイルで協力するための枠組み

#### MVP（えむぶいぴー / Minimum Viable Product）

- 意味：利用者の反応を確かめるための、必要最小限の機能を持った製品
- 語の意味：Minimum＝最小の／Viable＝成り立つ／Product＝製品

#### SPI（えすぴーあい / Software Process Improvement）

- 意味：ソフトウェアを作る進め方を、ふり返りながら良くしていく活動

#### 成熟度レベル（Maturity Level）

- 意味：CMMIで、プロセスの成熟の度合いを表す5段階
- ポイント：初期・管理された・定義された・定量的に管理された・最適化している

#### 共通フレームのプロセス（SLCP-JCF Processes）

- 意味：企画・要件定義・開発・運用・保守などの工程と作業を、決めた言葉で表したもの

#### ISO/IEC 12207（ソフトウェアライフサイクルプロセス）

- 意味：ソフトウェアの企画から廃棄までの工程を定めた国際規格
- ポイント：共通フレームのもとになっている

#### フォワードエンジニアリング（Forward Engineering）

- 意味：仕様や設計から、新しくシステムを作ること
- ポイント：リバースエンジニアリングで得た情報を使うことも多い

#### リエンジニアリング（Reengineering）

- 意味：既にあるソフトウェアを解析し、作り直して改善すること

#### ソフトウェア再利用（Software Reuse）

- 意味：作ったことのある部品や設計を、別の開発で使い回すこと
- ポイント：開発の速さと品質が上がる

#### コンポーネント指向（Component-based Development）

- 意味：独立した部品（コンポーネント）を組み合わせてシステムを作る考え方

#### ローコード開発・ノーコード開発（Low-code / No-code Development）

- 意味：プログラムをほとんど書かずに、画面の操作でアプリケーションを作る開発

#### オープンソースソフトウェア（OSS / Open Source Software）

- 意味：プログラムの中身（ソースコード）が公開され、決まった条件で自由に使えるソフトウェア


## 13-2 知的財産適用管理


### 権利の管理

#### ソフトウェアの著作権（Copyright of Software）

- 意味：プログラムは著作物として守られる
- ポイント：アルゴリズムやプログラム言語、規約は守られない

#### 特許とソフトウェア（Software Patent）

- 意味：ソフトウェアのアイデアも、条件を満たせば特許になる

#### ライセンス管理（License Management）

- 意味：使っているソフトウェアのライセンスの数や条件を管理すること
- ポイント：OSSのライセンス条件も確かめる


### 権利の管理（発展）

#### 著作権の帰属（Copyright Ownership）

- 意味：請負で作ったプログラムの著作権は、特に契約がなければ作った側（受注者）にある
- ポイント：発注者に移すなら契約で決める

#### 職務著作（Work for Hire）

- 意味：会社の仕事として社員が作ったプログラムで、会社の名前で公表するもの
- ポイント：著作者は会社になる

#### 使用許諾契約（License Agreement）

- 意味：ソフトウェアを使ってよい範囲や条件を決めた契約

#### ボリュームライセンス（Volume License）

- 意味：1つの契約で、たくさんの台数分の使用を認めるライセンス

#### サブスクリプション（Subscription）

- 意味：期間ごとに料金を払って、ソフトウェアやサービスを使う形

#### GPL（じーぴーえる / GNU General Public License）

- 意味：改変したプログラムを配るときは、その中身も同じ条件で公開することを求めるOSSのライセンス
- ポイント：コピーレフトの代表

#### コピーレフト（Copyleft）

- 意味：改変したものにも、同じ自由な利用の条件を受け継がせる考え方

#### MITライセンス・BSDライセンス（MIT / BSD License）

- 意味：著作権の表示を残せば、改変したものを公開しなくてもよい、ゆるいOSSのライセンス

#### SBOM（えすぼむ / Software Bill of Materials）

- 意味：ソフトウェアに使われている部品（ライブラリ）とそのライセンスや版をまとめた一覧
- ポイント：脆弱性やライセンスの管理に使う
- 語の意味：Software＝ソフトウェア／Bill of Materials＝部品表

#### 技術ライセンス（Technology Licensing）

- 意味：特許などの技術を、ほかの会社に使わせて対価をもらうこと

#### クロスライセンス（Cross License）

- 意味：会社どうしで、お互いの特許を使えるようにする契約

#### エスクロー（Software Escrow）

- 意味：ソフトウェアの中身を第三者に預け、開発会社が倒産したときなどに利用者が受け取れるようにする仕組み

#### 営業秘密（Trade Secret）

- 意味：秘密として管理され、事業に役立ち、世に知られていない情報
- ポイント：不正競争防止法で守られる


## 13-3 開発環境管理


### 環境

#### 開発環境・ステージング環境・本番環境（Development / Staging / Production）

- 意味：開発するための環境、本番とほぼ同じ形で最後に確かめる環境、実際に使う環境

#### IaC（あいえーしー / Infrastructure as Code）

- 意味：サーバなどの設定をコードで書き、自動で同じ環境を作れるようにすること
- 語の意味：Infrastructure＝基盤／as Code＝コードとして


### 環境と道具（発展）

#### IDE（あいでぃーいー / Integrated Development Environment）

- 意味：エディタ・コンパイラ・デバッガなどを1つにまとめた開発用のソフトウェア
- 語の意味：Integrated＝統合された／Development＝開発／Environment＝環境

#### CASEツール（Computer Aided Software Engineering）

- 意味：設計図を書いたり、コードを作ったりして、開発を助けるツール

#### ビルドツール（Build Tool）

- 意味：ソースコードのコンパイルやまとめを自動で行うツール

#### パッケージ管理（Package Management）

- 意味：使うライブラリとその版を管理し、まとめて入れたり更新したりする仕組み

#### コンテナ（Container）

- 意味：アプリケーションと動くのに必要なものをまとめて、どこでも同じように動かせる仕組み
- 例：Docker

#### 仮想環境（Virtual Environment）

- 意味：1台のコンピュータの中に、別の環境を作って開発やテストに使うこと

#### テストデータ管理（Test Data Management）

- 意味：テストに使うデータを用意して管理すること
- ポイント：本番の個人情報はそのまま使わず、匿名化する

#### 開発標準（Development Standards）

- 意味：開発の進め方や書き方を、組織でそろえるための決まり

#### 開発ツールのライセンス管理（Tool License Management）

- 意味：開発で使うツールの数や期限を管理し、違反がないようにすること

#### エミュレータ・シミュレータ（Emulator / Simulator）

- 意味：ほかの機器の動きをまねて、本物がなくても開発やテストができるようにするソフトウェア

#### クロス開発（Cross Development）

- 意味：動かす機器とは別のコンピュータでプログラムを作ること
- ポイント：組込みシステムで多い

#### コード生成ツール（Code Generator）

- 意味：設計図や定義から、プログラムを自動で作るツール

#### 静的コード解析ツール（Static Code Analyzer）

- 意味：プログラムを動かさずに、書き方の誤りや危ない所を見つけるツール

#### AIコーディング支援（AI Coding Assistant）

- 意味：AIがプログラムの候補を出したり、説明したりして開発を助ける道具
- ポイント：出てきたコードは人が確かめる


## 13-4 構成管理・変更管理


### 管理

#### 構成管理（Configuration Management）

- 意味：成果物のバージョンと、その組合せ（ベースライン）を管理すること

#### バージョン管理システム（Version Control System）

- 意味：ファイルの変更の履歴を記録するしくみ
- 例：Git。ブランチで並行して開発し、マージで統合する

#### 変更管理（Change Management）

- 意味：変更の依頼・影響の評価・承認・実施を管理する手順


### 管理の仕組み（発展）

#### ベースライン（Baseline）

- 意味：承認されて、変更するときは手続きが必要になった成果物の版

#### 構成品目（CI / Configuration Item）

- 意味：構成管理の対象にする、1つ1つの成果物や部品

#### リポジトリ（Repository）

- 意味：ファイルとその変更の履歴を保存する場所

#### コミット・ブランチ・マージ（Commit / Branch / Merge）

- 意味：変更を記録すること、別の流れに分けること、分けた流れを合わせること

#### プルリクエスト（Pull Request）

- 意味：自分の変更を取り込んでもらうよう依頼し、レビューを受ける仕組み

#### 集中型・分散型バージョン管理（Centralized / Distributed Version Control）

- 意味：1か所のサーバで履歴を持つ方式と、各自が履歴の全部を持つ方式
- ポイント：Gitは分散型

#### チェックイン・チェックアウト（Check-in / Check-out）

- 意味：変更したファイルを戻して登録することと、取り出して作業を始めること

#### リリース管理（Release Management）

- 意味：新しい版を、計画・テストして本番に出すまでを管理すること

#### 変更要求（RFC / Request for Change）

- 意味：成果物を変えたいときに出す正式な依頼

#### 変更管理委員会（CCB / Change Control Board）

- 意味：変更要求を審査して、認めるかを決める会

#### 影響分析（Impact Analysis）

- 意味：変更がほかのどこに影響するかを調べること

#### 版数管理（Version Numbering）

- 意味：版に番号を付けて区別すること
- 例：1.2.3（大きな変更.機能追加.修正）


## 問題演習

- 書式：「#### 問 問題ID」の下に、問・ア〜エ・正解・解説を書く。「###」は小分類（クイズの範囲に使う）

### 13-1 開発プロセス・手法

#### 問 ap-13-q01

- 問：スクラムで、スプリントの終わりに作業の進め方を振り返る会議はどれか。
- ア：スプリントプランニング
- イ：デイリースクラム
- ウ：スプリントレビュー
- エ：スプリントレトロスペクティブ
- 正解：エ
- 解説：進め方の振り返りはレトロスペクティブ。成果物の確認はスプリントレビュー。

#### 問 ap-13-q02

- 問：1回のスプリントで完了した作業量を表し、次の計画に使う指標はどれか。
- ア：ベロシティ
- イ：バーンダウンチャート
- ウ：ストーリーポイント
- エ：バックログ
- 正解：ア
- 解説：ベロシティは1スプリントで終えた量。

#### 問 ap-13-q03

- 問：XPのプラクティスとして適切なものはどれか。
- ア：ウォーターフォール型の工程管理
- イ：ペアプログラミング
- ウ：一括での要件定義
- エ：大規模な設計書の作成
- 正解：イ
- 解説：XPはペアプログラミングやテスト駆動開発を重視する。

#### 問 ap-13-q04

- 問：組織の開発プロセスの成熟度を5段階で評価するモデルはどれか。
- ア：CMMI
- イ：ITIL
- ウ：PMBOK
- エ：COBIT
- 正解：ア
