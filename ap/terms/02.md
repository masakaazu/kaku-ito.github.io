## 2-1 データ構造

### まとめ表

**データの出し入れの順番**

| 構造 | 取り出す順 | 主な操作 | 使い道 |
| :-: | :-: | :-: | :-: |
| スタック | 最後に入れたものから（LIFO） | プッシュ・ポップ | 関数呼出しの戻り先、逆ポーランド記法の計算、深さ優先探索 |
| キュー | 最初に入れたものから（FIFO） | エンキュー・デキュー | 待ち行列、プリンタの印刷待ち、幅優先探索 |
| 優先度付きキュー | 優先度の高いものから | 挿入・最大（最小）の取出し | OSのスケジューリング。ヒープで作る |

**リストの作り方による違い（R4春 問5の論点）**

| 項目 | 配列で作るリスト | ポインタで作るリスト（連結リスト） |
| :-: | :-: | :-: |
| 領域 | 最大個数分を先に確保する。使わない領域が出る | 要素の分だけ確保する。ポインタの領域が別に要る |
| i番目の参照 | 添字で一度に参照できる | 先頭から順にたどる（要素数に比例） |
| 途中への挿入・削除 | 後ろの要素をずらす（要素数に比例） | ポインタの付け替えだけ（一定時間） |

**木の種類**

| 木 | 決まり | 試験での見分け方 |
| :-: | :-: | :-: |
| 2分探索木 | 左の子孫＜節＜右の子孫 | 中間順になぞると小さい順に並ぶ |
| AVL木 | どの節でも左右の高さの差が1以下 | 崩れたら回転で直す |
| B木 | 1つの節に複数のキー。全部の葉が同じ深さ | ディスク上の索引に使う |
| ヒープ | 親が子以上（または以下）の完全2分木 | 根が最大（最小）。配列で表せる |

**木のなぞり方（＋の下に A と ×、× の下に B と C がある木）**

| なぞり方 | 節を出力するタイミング | 出力 |
| :-: | :-: | :-: |
| 先行順（行きがけ順） | 子より先 | ＋A×BC（前置記法） |
| 中間順（通りがけ順） | 左の子と右の子の間 | A＋B×C（中置記法） |
| 後行順（帰りがけ順） | 子より後 | ABC×＋（逆ポーランド記法） |
| 幅優先 | 根に近い段から順に | ＋A×BC（この木では先行順と同じ。一般には違う） |

### 配列とリスト

#### 配列（はいれつ / Array）

- 意味：同じ型のデータを連続した領域に並べ、添字（番号）で位置を指定して読み書きするデータ構造
- ポイント：何番目でもすぐ参照できるが、途中に挿入・削除すると後ろの要素をずらす必要がある
- 例：R3春 問6（配列で2分木を表すと、先頭から調べることは幅優先探索に当たる）

#### 線形リスト（せんけいりすと / Linear List）

- 意味：データを1列に並べ、前後の順番に意味をもたせたデータ構造。配列でも、ポインタでつなぐ連結リストでも作れる
- ポイント：作り方で性質が変わる。配列で作ると参照が速く、ポインタで作ると挿入・削除が速い
- 例：R4春 問5（配列で作ったリストの特徴→最大個数分の領域を確保し、使わない領域が出る）

#### 連結リスト（れんけつりすと / Linked List）

- 意味：各要素が「次の要素の場所（ポインタ）」をもち、ポインタをたどってつながるリスト。リンク付リストとも呼ぶ（単方向リスト・双方向リスト・環状リストはその種類）
- ポイント：挿入・削除はポインタの付け替えだけで済むが、i番目を参照するには先頭からたどる。ポインタの分だけ領域が余計に要る

#### 単方向リスト（たんほうこうりすと / Singly Linked List）

- 意味：各要素が次の要素へのポインタだけをもち、先頭から末尾へ一方向にしかたどれないリスト
- ポイント：ある要素を消すには「1つ前の要素」のポインタを変える必要があり、それを探すのに先頭からたどる

#### 双方向リスト（そうほうこうりすと / Doubly Linked List）

- 意味：各要素が次の要素へのポインタと前の要素へのポインタの両方をもつリスト
- ポイント：前にも後ろにもたどれる。挿入では新しい要素の next・prev と、前後の要素のポインタの合計4か所を書き換える
- 例：R5秋 問5（Dの次にCを挿入したあとの next[6]・prev[6] を答える）

#### 環状リスト（かんじょうりすと / Circular List）

- 意味：末尾の要素のポインタが先頭の要素を指し、輪のようにつながったリスト
- ポイント：どの要素からでも全部をたどれる。終わりの判定は「最初の要素に戻ったか」で行う

#### ポインタ（ぽいんた / Pointer）

- 意味：データそのものではなく、データが置かれている場所（アドレス）を値としてもつもの
- ポイント：リストや木をつなぐのに使う。指す先のないことを表す値をNULL（ヌル）と呼ぶ

### 配列の種類とレコード

#### 多次元配列（たじげんはいれつ / Multidimensional Array）

- 意味：添字を2つ以上使って、表や立体のようにデータを並べたもの
- ポイント：メモリには1列に並ぶので、行ごとに並べる（行優先）か列ごとに並べる（列優先）かでアドレスの計算が変わる

#### 静的配列（せいてきはいれつ / Static Array）

- 意味：プログラムを作る段階で要素数を決め、実行中は大きさを変えられない配列
- ポイント：最大個数分の領域を先に確保するので、使わない領域が出ることがある

#### 動的配列（どうてきはいれつ / Dynamic Array）

- 意味：実行中に必要に応じて要素数を増やしたり減らしたりできる配列
- ポイント：足りなくなると大きな領域を取り直して中身を写す。JavaのArrayListやPythonのlistがこの形

#### レコード（れこーど / Record）

- 意味：型の違う複数の項目（氏名・年齢など）を1つにまとめたデータのかたまり
- ポイント：C言語の構造体に当たる。同じ型を並べる配列との違いが問われる

### 出し入れの順番が決まったデータ構造

#### スタック（すたっく / Stack）

- 意味：最後に入れたデータを最初に取り出すデータ構造（後入れ先出し）
- ポイント：出入口が1つの箱のイメージ。関数呼出しの戻り先の保存、逆ポーランド記法の計算、深さ優先探索に使う
- 例：R3春 問5＝R7春 問5（A, B, C の順に入れて、各データを1回ずつ出し入れするときの出力順は5通り）

#### キュー（きゅー / Queue）

- 意味：最初に入れたデータを最初に取り出すデータ構造（先入れ先出し）
- ポイント：入口と出口が別の筒のイメージ。待ち行列やバッファ、幅優先探索に使う

#### 優先度付きキュー（ゆうせんどつききゅー / Priority Queue）

- 意味：入れた順番ではなく、優先度の高い（または低い）データから取り出すデータ構造
- ポイント：ヒープを使うと、挿入も取出しも O(log n) で行える

#### 両端キュー（りょうたんきゅー / Double-ended Queue）

- 意味：列の先頭と末尾のどちらからでも、データを入れたり取り出したりできるデータ構造。デックとも呼ぶ
- ポイント：片方の端だけ使えばスタック、入れる端と出す端を分ければキューとして使える

### 出し入れの操作と順序

#### LIFO（らいふぉ / Last In First Out）

- 意味：最後に入れたものを最初に取り出す順序のこと（後入れ先出し）
- ポイント：スタックの取り出し方。在庫の評価方法の「後入先出法」とは文脈が違う
- 語の意味：Last＝最後の／In＝入る／First＝最初に／Out＝出る

#### FIFO（ふぁいふぉ / First In First Out）

- 意味：最初に入れたものを最初に取り出す順序のこと（先入れ先出し）
- ポイント：キューの取り出し方。ページ置換アルゴリズムのFIFOも「一番古いものから追い出す」の意味
- 語の意味：First＝最初に／In＝入る／First＝最初に／Out＝出る

#### プッシュ（ぷっしゅ / Push）

- 意味：スタックの一番上にデータを積む操作
- ポイント：取り出す操作（ポップ）と対で出る。キューに入れる操作はエンキューと呼ぶ

#### ポップ（ぽっぷ / Pop）

- 意味：スタックの一番上のデータを取り出す操作
- ポイント：取り出したデータはスタックから消える。逆ポーランド記法では演算子が来たら2つポップして計算し、結果をプッシュする

#### エンキュー（えんきゅー / Enqueue）

- 意味：キューの末尾にデータを入れる操作
- ポイント：取り出す操作はデキュー（Dequeue）。「両端キュー」の略称のデック（Deque）とつづりが似ている

### 木の部品

#### 根（ね / Root）

- 意味：木構造の一番上にあり、親をもたない節
- ポイント：1つの木に根は1つだけ。根から各節までの枝の数を、その節の深さと呼ぶ

#### 葉（は / Leaf）

- 意味：木構造で、子をもたない節
- ポイント：末端の節のこと。B木ではすべての葉が同じ深さにそろう

#### 節（せつ / Node）

- 意味：木構造で、データを入れる1つ1つの点。ノードとも呼ぶ（根や葉もその一種）
- ポイント：子をもつ節を内部節と呼ぶ

#### 枝（えだ / Edge）

- 意味：木構造で、親の節と子の節を結ぶ線
- ポイント：節が n 個の木には、枝がちょうど n−1 本ある

#### 部分木（ぶぶんぎ / Subtree）

- 意味：ある節と、その子孫すべてを取り出してできる小さな木
- ポイント：木は「根と、いくつかの部分木」でできていると考えられるので、再帰的な処理と相性がよい

### 木の種類

#### 2分木（にぶんぎ / Binary Tree）

- 意味：どの節も、子を2つ以下（左の子・右の子）しかもたない木
- ポイント：左右の区別がある。数式を表す木（演算子を節、数を葉に置く）も2分木

#### 完全2分木（かんぜんにぶんぎ / Complete Binary Tree）

- 意味：一番下の段以外はすべての節が埋まり、一番下の段は左から順に埋まっている2分木（ヒープはこの形を使う）
- ポイント：配列で表せる。A[i] の左の子を A[2i]、右の子を A[2i+1] とすると、親は A[i÷2]（切捨て）
- 例：R3春 問6（配列を先頭から順に調べることは、2分木の幅優先探索に当たる）

#### 多分木（たぶんぎ / Multiway Tree）

- 意味：1つの節が3つ以上の子をもてる木
- ポイント：B木は多分木の一種。1つの節に多くのキーを入れて、木の高さを低く抑える

#### 2分探索木（にぶんたんさくぎ / Binary Search Tree）

- 意味：どの節でも「左の部分木の値＜節の値＜右の部分木の値」となるように並べた2分木（AVL木はこれに高さの条件を加えたもの）
- ポイント：中間順になぞると小さい順に並ぶ。偏ると線形リストと同じになり、探索が O(n) に落ちる。節を消したら、左の部分木の最大値か右の部分木の最小値をその位置に移す
- 例：R6秋 問5（12を消したら右の部分木の最小値13を移す）

#### AVL木（えーぶいえるぎ / AVL Tree）

- 意味：どの節でも、左の部分木と右の部分木の高さの差が1以下になるように保つ2分探索木
- ポイント：差が2になったら「回転」で形を直す。B木のように偏らない形を保つ木をまとめてバランス木と呼ぶ。考えた2人（Adelson-Velsky と Landis）の頭文字
- 例：R7春 問6（1と0を順に足すと節2で偏るので、1を上げて 0・2 を子にする）
- 語の意味：A＝Adelson／V＝Velsky／L＝Landis（考案者の名前）

#### B木（びーぎ / B-tree）

- 意味：1つの節に複数のキーと子を入れ、すべての葉が同じ深さにそろうように保つ多分木
- ポイント：1回のディスク読込みで多くのキーを調べられるので、データベースの索引に使う。葉だけにデータを置き、葉どうしをつないだものがB+木

#### ヒープ（ひーぷ / Heap）

- 意味：どの節でも「親の値≧子の値」（または≦）となる完全2分木
- ポイント：根が最大（または最小）。IPAの問題文では「順序木」と呼ぶこともある（R3秋 問5 エ）。値を足したら葉に置いて親と比べながら上へ、根を取り出したら最後の葉を根に移して下へ入れ替える（ヒープの再構成）。プログラムの「ヒープ領域」とは別物

### 木のなぞり方

#### 先行順（せんこうじゅん / Preorder）

- 意味：節を先に出力し、そのあと左の部分木、右の部分木の順になぞる方法。行きがけ順とも呼ぶ
- ポイント：数式の木を先行順になぞると前置記法（ポーランド記法）になる

#### 中間順（ちゅうかんじゅん / Inorder）

- 意味：左の部分木をなぞってから節を出力し、そのあと右の部分木をなぞる方法。通りがけ順とも呼ぶ
- ポイント：2分探索木を中間順になぞると小さい順に並ぶ。数式の木では中置記法になる

#### 後行順（こうこうじゅん / Postorder）

- 意味：左の部分木、右の部分木をなぞったあとで、最後に節を出力する方法。帰りがけ順とも呼ぶ
- ポイント：数式の木を後行順になぞると逆ポーランド記法になる。右と左の順番を変えた問題も出る
- 例：R6春 問6（右の子→左の子→自分の順に出力すると ED−CB×÷A＋）

#### レベル順（れべるじゅん / Level Order）

- 意味：根に近い段から順に、同じ段の中は左から右へなぞる方法
- ポイント：幅優先探索で木をなぞったときの順番。キューを使って実現する

### ハッシュ表

#### ハッシュ表（はっしゅひょう / Hash Table）

- 意味：キーから計算した値（ハッシュ値）を格納位置にしてデータを置く表
- ポイント：衝突が少なければ、探索・追加・削除が平均 O(1) で済む。範囲検索や順番どおりの取出しは苦手

#### ハッシュ関数（はっしゅかんすう / Hash Function）

- 意味：キーを入力して、表の中の格納位置（ハッシュ値）を計算する関数
- ポイント：代表は除算法 h(x)＝x mod n。値がばらけるように、n には素数を選ぶことが多い
- 例：R4秋 問5＝R6秋 問6（x mod n で a と b が衝突する条件は「a−b が n の倍数」）

#### シノニム（しのにむ / Synonym）

- 意味：異なるキーから同じハッシュ値が計算され、格納位置がぶつかること。また、ぶつかったキーどうしのこと。衝突（コリジョン）とも呼ぶ
- ポイント：ゼロにはできないので対策を用意する。対策にはチェイン法とオープンアドレス法がある

#### チェイン法（ちぇいんほう / Chaining）

- 意味：同じ格納位置に来たデータを、その位置から伸ばした連結リストにつないでおくシノニム対策
- ポイント：表があふれない。リストが長くなると、その分だけ探索が遅くなる

#### オープンアドレス法（おーぷんあどれすほう / Open Addressing）

- 意味：格納位置がふさがっていたら、決まった規則で表の中の別の空き位置を探して入れるシノニム対策
- ポイント：隣を順に探す方法（線形走査法）が代表。削除するときは「消した印」を残さないと、後ろの探索が途切れる

## 2-2 アルゴリズム

### まとめ表

**整列（ソート）アルゴリズム（n個を並べる）**

| 方法 | やり方 | 平均の計算量 | 最悪 | 安定 |
| :-: | :-: | :-: | :-: | :-: |
| バブルソート | 隣どうしを比べて逆なら交換。1回なぞると端に最大（最小）が決まる | O(n²) | O(n²) | 安定 |
| 選択ソート | 残りから最小を探して、残りの先頭と交換 | O(n²) | O(n²) | 不安定 |
| 挿入ソート | 整列済みの部分の正しい位置に1つずつ差し込む | O(n²) | O(n²) | 安定 |
| シェルソート | 間隔をあけた要素どうしで挿入ソートし、間隔を詰めていく | O(n^1.25)〜O(n^1.5) 程度（間隔の決め方による） | O(n²) | 不安定 |
| クイックソート | 基準値より小さいグループと大きいグループに分け、それぞれで繰り返す | O(n log n) | O(n²) | 不安定 |
| マージソート | 半分ずつに分け、分けられなくなったら整列済みどうしを併合していく | O(n log n) | O(n log n) | 安定 |
| ヒープソート | ヒープを作り、根（最大）を取り出して末尾へ置くことを繰り返す | O(n log n) | O(n log n) | 不安定 |

**探索アルゴリズム（n個から1つ探す）**

| 方法 | 前提 | 平均の比較回数 | 最大の比較回数 |
| :-: | :-: | :-: | :-: |
| 線形探索法 | なし | (n＋1)/2（見つかる場合） | n |
| 2分探索法 | 整列済み | 約 log₂n | ⌊log₂n⌋＋1 |
| ハッシュ表探索法 | ハッシュ表に格納済み | 衝突がなければ1回 | 衝突が多いと増える |

**アルゴリズムの設計方法（R3春 問7の選択肢に並んだもの）**

| 方法 | 考え方 |
| :-: | :-: |
| 分割統治法 | 小さな問題に分けて独立に解き、結果をつなぎ合わせる |
| 貪欲法 | その時点で一番よいものを選び続ける。全体の最適解になるとは限らない |
| 動的計画法 | 部分問題の答えを表に記録し、使い回して全体を解く |
| 分枝限定法 | 場合分けをしながら、見込みのない枝を途中で切り捨てる |

**空き領域の割当て方式**

| 方式 | 選ぶ空き領域 | 結果として残るもの |
| :-: | :-: | :-: |
| ファーストフィット | 先頭から見て最初に入る領域 | 前の方に小さな空きが集まる |
| ベストフィット | 入る中で一番小さい領域 | 使えない小さな空きが多数残る |
| ワーストフィット | 一番大きい領域 | 大きな空きが減っていく |

### 流れ図

#### 流れ図（ながれず / Flowchart）

- 意味：処理の手順を、決まった形の記号と線で図にしたもの。フローチャートとも呼ぶ
- ポイント：記号はJIS X 0121で決まっている。順次・選択・繰返しの3つの組合せで、どんな手順も表せる
- 例：R4秋 問6（流れ図の内側のループが末尾から隣どうしを比べて交換している→バブルソート）

#### 端子（たんし / Terminal）

- 意味：流れ図の始まりと終わりを表す、角の丸い長方形の記号
- ポイント：「開始」「終了」と書く。サブルーチンの入口・出口にも使う

#### 処理（しょり / Process）

- 意味：計算や代入など、ひとまとまりの操作を表す長方形の記号（左右に縦線を入れた記号とは別）
- ポイント：「x←x×n」のように中に操作を書く

#### 定義済み処理（ていぎずみしょり / Predefined Process）

- 意味：別の場所で定義した処理（サブルーチンなど）を呼び出すことを表す、左右に縦線を入れた長方形の記号
- ポイント：中身は別の流れ図に書いてあるという意味。普通の処理の記号とは縦線の有無で見分ける

#### 判断（はんだん / Decision）

- 意味：条件によって進む道を分けることを表す、ひし形の記号
- ポイント：出口に「Yes／No」や「＜／≧」などの条件を書く

#### ループ端（るーぷたん / Loop Limit）

- 意味：繰返しの始まりと終わりを表す、角を切り落とした長方形の記号。上下で対にして使う
- ポイント：始まりの記号に「変数名：初期値, 増分, 終値」を書く形が過去問でよく出る
- 例：R6春 問5（n を M から1まで1ずつ減らすループと同じ結果にするには、n を1から増やして n＞M で終わる）

### 整列のアルゴリズム

#### バブルソート（ばぶるそーと / Bubble Sort）

- 意味：隣り合う要素を比べて、大小が逆なら入れ替えることを繰り返して並べる方法
- ポイント：1回なぞるごとに、最大（または最小）の値が端に決まる。O(n²)。過去10回で4回出た
- 例：R3秋 問5、R4秋 問6、R5秋 問6（9が末尾へ→6が9の前へ、と大きい値から端に決まる）、R6春 問7

#### 選択ソート（せんたくそーと / Selection Sort）

- 意味：まだ並べていない部分から最小値を探し、その部分の先頭と入れ替えることを繰り返す方法
- ポイント：交換は1回のなぞりで1回だけ。O(n²)。「最小値を探して先頭と交換」が見分ける言葉
- 例：R6春 問7 エ（未処理の中から最小値を探索し、最初の数字と入れ替える）

#### 挿入ソート（そうにゅうそーと / Insertion Sort）

- 意味：整列済みの部分に、残りの要素を1つずつ正しい位置へ差し込んでいく方法
- ポイント：ほとんど並んでいるデータなら速い（最良 O(n)）。トランプの手札を並べる動きと同じ

#### シェルソート（しぇるそーと / Shell Sort）

- 意味：一定の間隔をあけて取り出した要素の列ごとに挿入ソートを行い、間隔を詰めながら最後は間隔1で仕上げる方法
- ポイント：挿入ソートの改良。遠く離れた要素を早めに動かせる
- 例：R3秋 問5 ア（ある間隔おきに取り出した部分列を整列し、間隔を詰める）

#### クイックソート（くいっくそーと / Quick Sort）

- 意味：基準値（ピボット）を決めて、それより小さいグループと大きいグループに分け、各グループで同じことを繰り返す方法
- ポイント：平均 O(n log n) で実用上は最も速い部類。基準値が毎回端の値だと O(n²) に落ちる
- 例：R5春 問7（2,3,5,4,1 を左端を基準に分けると、2回目の分割後は 1,2,3,5,4）

#### マージソート（まーじそーと / Merge Sort）

- 意味：データを半分ずつに分けていき、分けられなくなったら整列済みの列どうしを併合しながら大きくしていく方法
- ポイント：いつでも O(n log n) で安定。併合のための作業領域が要る
- 例：R6春 問7 ウ（ほぼ同じ長さの2つに分割していき、分割できなくなった時点から並べる）

#### ヒープソート（ひーぷそーと / Heap Sort）

- 意味：未整列の部分でヒープを作り、根にある最大値（最小値）を取り出して整列済みの部分へ移すことを繰り返す方法
- ポイント：いつでも O(n log n)。作業領域がほとんど要らない
- 例：R3秋 問5 エ（未整列の部分を順序木にし、最小値を取り出して整列済みの部分に移す）

### 整列と計算の性質

#### 安定ソート（あんていそーと / Stable Sort）

- 意味：同じキーの値をもつ要素どうしの並び順が、整列の前後で変わらない整列方法
- ポイント：バブル・挿入・マージは安定。選択・クイック・ヒープ・シェルは不安定。複数のキーで順に並べ直すときに大事になる

#### 内部ソート（ないぶそーと / Internal Sort）

- 意味：整列するデータを全部主記憶に載せて並べる方法
- ポイント：この分野で出る各ソートはこれ。データが多すぎて主記憶に載らないときは別の方法をとる

#### 外部ソート（がいぶそーと / External Sort）

- 意味：主記憶に載りきらない大量のデータを、補助記憶装置を使いながら並べる方法
- ポイント：主記憶に載る分ずつ並べて補助記憶に書き出し、それらを併合（マージ）していく。マージソートの考え方が土台

#### 近似アルゴリズム（きんじあるごりずむ / Approximation Algorithm）

- 意味：最適解を求めるのに時間がかかりすぎる問題で、最適に近い解を現実的な時間で求める方法
- ポイント：巡回セールスマン問題のようなNP困難な問題で使う。どれだけ最適解に近いかの保証つきのものもある

#### 計算量（けいさんりょう / Complexity）

- 意味：データの個数 n が増えたとき、処理の手間がどれだけ増えるかを表したもの。O記法で書く
- ポイント：O(n²) のソートは n が10倍で手間が約100倍、O(n log n) なら約13倍（n＝1,000→10,000 のとき）。基礎理論の「計算量」と同じ考え方

### 探索のアルゴリズム

#### 線形探索法（せんけいたんさくほう / Linear Search）

- 意味：先頭から1つずつ順に目的のデータと比べていく探索方法
- ポイント：並んでいなくても使える。見つかるときの平均比較回数は (n＋1)/2、ないときは n 回
- 例：R5春 問6（存在しない確率が a のとき、平均比較回数は (n＋1)(1−a)/2＋na）

#### 2分探索法（にぶんたんさくほう / Binary Search）

- 意味：整列済みのデータの真ん中と比べ、探す範囲を毎回半分に絞っていく探索方法
- ポイント：最大比較回数は ⌊log₂n⌋＋1。1,000個なら最大10回。前もって整列しておく必要がある

#### ハッシュ表探索法（はっしゅひょうたんさくほう / Hash Search）

- 意味：探すキーからハッシュ関数で格納位置を計算し、その位置を直接調べる探索方法
- ポイント：シノニムがなければ1回で見つかる。データ量が増えても比較回数がほとんど増えない

#### 番兵（ばんぺい / Sentinel）

- 意味：線形探索で、探すデータと同じ値を表の末尾に置いておき、「表の終わりか」の判定を省く工夫
- ポイント：必ず見つかるので、ループの中の判定が「一致したか」だけになり速くなる

#### ブロック探索（ぶろっくたんさく / Block Search）

- 意味：整列済みの表を m 個ずつのブロックに分け、各ブロックの最後のデータを見て目的のブロックを探し、その中を線形探索する方法
- ポイント：平均比較回数は (n/m)/2＋m/2。m＝√n のとき最も少なくなる
- 例：R7秋 問6（m/2＋n/(2m) を選ぶ）

### 再帰とアルゴリズムの設計方法

#### 再帰（さいき / Recursion）

- 意味：ある処理や定義の中で、それ自身をより小さな問題に対して使うこと
- ポイント：「止まる条件（基底）」と「自分を小さな問題で呼ぶ部分」の2つがそろって正しく動く。階乗は fact(0)＝1、fact(n)＝n×fact(n−1)
- 例：R7春 問7（n＝0 のとき 1 を返し、それ以外は n×fact(n−1) を返す）

#### 分割統治法（ぶんかつとうちほう / Divide and Conquer）

- 意味：問題を小さな問題に分け、それぞれを独立に解いた結果を組み合わせて元の問題を解く設計方法
- ポイント：マージソートやクイックソートがこの考え方。再帰で書くことが多い
- 例：R3春 問7（全体を小さな問題に分割し、独立に処理した結果をつなぎ合わせる）

#### 貪欲法（どんよくほう / Greedy Algorithm）

- 意味：その時点で最もよく見える選択を、先のことを考えずに繰り返して答えを作る設計方法
- ポイント：速いが、全体の最適解になるとは限らない。ダイクストラ法は貪欲法でも最適解が出る例
- 例：R3春 問7 エ（各時点で最良の解を選択し、これを繰り返す）

#### 動的計画法（どうてきけいかくほう / Dynamic Programming）

- 意味：問題を部分問題に分け、部分問題の答えを表に記録して使い回しながら全体を解く設計方法
- ポイント：同じ部分問題を何度も解かずに済む。分割統治法との違いは、部分問題どうしが重なっていて答えを使い回す点

#### 分枝限定法（ぶんしげんていほう / Branch and Bound）

- 意味：場合分けで解の候補を木のように広げながら、よい解になる見込みのない枝を途中で調べるのをやめる方法
- ポイント：全部を調べる総当たりより速い。似た方法に、行き詰まったら1つ前に戻るバックトラック法がある
- 例：R3春 問7 イ（無駄な組合せを除いて、実際に調べる組合せ数を減らす）はこの考え方に近い誤りの選択肢

#### バックトラック法（ばっくとらっくほう / Backtracking）

- 意味：場合分けを深さ優先で進め、条件に合わなくなったら1つ前の場合分けに戻って別の道を試す方法
- ポイント：迷路や8クイーン問題が典型。基礎理論のAIの選択肢にも「深さ優先で探索し、後戻りする」として出た

#### モンテカルロ法（もんてかるろほう / Monte Carlo Method）

- 意味：乱数を使って何度も試行し、その結果の割合から答えを近似的に求める方法
- ポイント：確率アルゴリズムの代表。正方形の中に点を打ち、円の中に入った割合から円周率を求める例が有名。試行を増やすほど精度が上がる

#### 遺伝的アルゴリズム（いでんてきあるごりずむ / Genetic Algorithm）

- 意味：解の候補を遺伝子に見立てて、選択（とう汰）・交叉・突然変異を繰り返し、よりよい解に近づける最適化の方法
- ポイント：生物の進化をまねた方法。基礎理論でも「生物の進化を模倣」としてディープラーニングの誤りの選択肢に出た

### グラフと文字列のアルゴリズム

#### 深さ優先探索（ふかさゆうせんたんさく / Depth-First Search）

- 意味：グラフや木で、行けるところまで奥へ進み、行き止まりになったら戻って別の道を進む探索方法
- ポイント：スタック（または再帰）で実現する。木の先行順・中間順・後行順はこの探索でのなぞり方

#### 幅優先探索（はばゆうせんたんさく / Breadth-First Search）

- 意味：出発点から近い順に、同じ距離の点をすべて調べてから次の距離へ進む探索方法
- ポイント：キューで実現する。辺の重みがないグラフなら、最短経路（通る辺の数が最少の道）が見つかる
- 例：R3春 問6（配列で表した2分木を先頭から順に調べる→幅優先探索）

#### ダイクストラ法（だいくすとらほう / Dijkstra's Algorithm）

- 意味：出発点から距離が確定した点を1つずつ増やしながら、各点への最短距離を求める方法
- ポイント：辺の重み（距離）が負だと使えない。カーナビの経路探索やOSPFで使われる

#### ベルマンフォード法（べるまんふぉーどほう / Bellman-Ford Algorithm）

- 意味：すべての辺について「この辺を通ると近くなるか」の確認を繰り返して、最短距離を求める方法
- ポイント：ダイクストラ法より遅いが、重みが負の辺があっても使える。負の閉路があれば検出できる

#### 力まかせ法（ちからまかせほう / Brute-force String Search）

- 意味：文字列照合で、パターンを1文字ずつずらしながら、毎回先頭から比べ直す方法。単純照合法とも呼ぶ
- ポイント：作り方は簡単だが、不一致のたびに1文字しか進まない

#### KMP法（けーえむぴーほう / Knuth-Morris-Pratt Algorithm）

- 意味：文字列照合で、パターンを先頭から比べ、不一致になったときはパターン自身の情報（どこまで一致していたか）を使って、比べ直す位置を決める方法
- ポイント：調べる文字列の中を後戻りしない。考えた3人の頭文字
- 語の意味：K＝Knuth／M＝Morris／P＝Pratt（考案者の名前）

#### BM法（びーえむほう / Boyer-Moore Algorithm）

- 意味：文字列照合で、パターンの末尾から先頭へ向かって比べ、不一致の文字に応じてパターンを大きくずらす方法
- ポイント：実際の文章では多くの場合 KMP法より速い。「末尾から比べる」が見分ける言葉
- 語の意味：B＝Boyer／M＝Moore（考案者の名前）

### ファイル処理

#### 併合処理（へいごうしょり / Merge Processing）

- 意味：同じキーで整列済みの複数のファイルを、キーの順番を保ったまま1つにまとめる処理
- ポイント：2つのファイルの先頭どうしを比べ、小さい方を出力して読み進めることを繰り返す。マージソートの土台

#### マッチング処理（まっちんぐしょり / Matching Processing）

- 意味：同じキーで整列済みの2つのファイル（例えばマスタファイルとトランザクションファイル）を先頭から読み比べ、キーが一致するレコードどうしを突き合わせて処理する方法
- ポイント：キーの大小を比べて、小さい方のファイルを読み進める。マスタの更新処理で使う

#### コントロールブレーク処理（こんとろーるぶれーくしょり / Control Break Processing）

- 意味：キーで整列済みのデータを順に読み、キーの値が変わった所で小計などのまとめ処理を行う方法
- ポイント：「部門が変わったら部門の合計を出す」ような集計に使う。前もってキーで整列しておく

#### 編集処理（へんしゅうしょり / Editing）

- 意味：データを、帳票や画面に出すための形（桁区切り・ゼロの抑制・日付の書式など）に整える処理
- ポイント：中身の計算ではなく見せ方を変える処理。バッチ処理の最後の段階で行うことが多い

### 自然言語処理

#### 形態素解析（けいたいそかいせき / Morphological Analysis）

- 意味：文を、意味をもつ最小の単位（形態素）に区切り、それぞれの品詞を決める処理
- ポイント：日本語は単語の間に空白がないので、最初にこれが要る。「すもも／も／もも／も」のように分ける

#### 係り受け解析（かかりうけかいせき / Dependency Parsing）

- 意味：文の中で、どの文節がどの文節にかかっているか（修飾しているか）を決める処理
- ポイント：日本語の構文解析でよく使う方法。「黒い猫の目」で「黒い」が「猫」と「目」のどちらにかかるかを決める

#### 意味解析（いみかいせき / Semantic Analysis）

- 意味：構文解析した結果をもとに、単語や文の意味を決め、意味の通らない解釈を除く処理
- ポイント：同じ単語の複数の意味（「はし」が橋か箸か）を文の内容から選ぶ

#### 文脈解析（ぶんみゃくかいせき / Context Analysis）

- 意味：複数の文にまたがって、指示語（それ・これ）が何を指すかや、省略された語を補う処理
- ポイント：1文の中で行う意味解析より広い範囲を見る。処理の順番は形態素解析→構文解析→意味解析→文脈解析

#### n-gram（えぬぐらむ / N-gram）

- 意味：文字列を、隣り合う n 個の文字（または単語）ずつ区切った断片の並びとして扱う方法
- ポイント：「東京都」を2文字ずつ区切ると「東京」「京都」。辞書がなくても全文検索の索引を作れる

#### 文章間類似度（ぶんしょうかんるいじど / Document Similarity）

- 意味：2つの文章が内容としてどれだけ似ているかを数値で表したもの
- ポイント：文章をベクトル（単語の出現回数など）にして、その向きの近さ（コサイン類似度）で測るのが代表。検索や重複記事の判定に使う

### データ圧縮と図形のアルゴリズム

#### ランレングス法（らんれんぐすほう / Run-Length Encoding）

- 意味：同じ値が続く部分を「値と、続く個数」の組に置き換えて圧縮する方法
- ポイント：AAAABBB→A4B3。同じ値が長く続く白黒画像やFAXに向く。値がばらばらだと逆に大きくなる

#### ハフマン法（はふまんほう / Huffman Coding）

- 意味：よく出る記号ほど短いビット列、まれな記号ほど長いビット列を割り当てて圧縮する方法
- ポイント：どの符号も他の符号の先頭部分にならないので、区切りなしで元に戻せる。作り方は基礎理論のハフマン木と同じ

#### Zバッファ法（ぜっとばっふぁほう / Z-buffer Algorithm）

- 意味：画面の画素ごとに一番手前の物体までの奥行き（Z値）を記録しておき、より手前の物体だけを描くことで、隠れた面を消す方法
- ポイント：隠面消去の代表。処理は単純だが、画素の数だけ奥行きを入れるメモリが要る

#### スキャンライン法（すきゃんらいんほう / Scanline Algorithm）

- 意味：画面を横1行（走査線）ずつ処理し、その行で一番手前に見える面を決めて描く隠面消去の方法
- ポイント：Zバッファ法が画素ごとなのに対し、行ごとにまとめて判定する

#### レイトレーシング法（れいとれーしんぐほう / Ray Tracing）

- 意味：視点から画素ごとに光線を逆向きに飛ばし、物体での反射・屈折・影を追いかけて色を決める描画方法
- ポイント：鏡のような反射や透明な物体をリアルに描けるが、計算量が多い

### 記憶域の管理

#### ファーストフィット（ふぁーすとふぃっと / First Fit）

- 意味：空き領域を先頭から調べ、要求した大きさ以上の領域が最初に見つかったところを割り当てる方式
- ポイント：探す手間が少なく速い。前の方に小さな空き領域がたまりやすい

#### ベストフィット（べすとふぃっと / Best Fit）

- 意味：要求した大きさ以上の空き領域のうち、一番小さいものを割り当てる方式
- ポイント：大きな空き領域を残せるが、使えないほど小さな空き領域が多数残る。空き領域を大きさをキーにした2分探索木で管理すると速い
- 例：R5春 問5（大きさをキーとする2分探索木）、R7秋 問5（小さな空きブロックが多数残る傾向）

#### ワーストフィット（わーすとふぃっと / Worst Fit）

- 意味：空き領域のうち、一番大きいものを割り当てる方式
- ポイント：残る空き領域が大きめになるので使い回しやすい反面、大きな要求に応えられなくなりやすい

#### フラグメンテーション（ふらぐめんてーしょん / Fragmentation）

- 意味：割当てと解放を繰り返すうちに、空き領域が小さく細切れになって散らばること。断片化とも呼ぶ
- ポイント：空きの合計は足りるのに、続いた大きな領域が取れなくなる。直すにはコンパクションを行う

#### コンパクション（こんぱくしょん / Compaction）

- 意味：使用中の領域を詰めて移動し、散らばった空き領域を1つの大きな続いた領域にまとめること
- ポイント：フラグメンテーションの解消方法。移動中は処理が止まり、移動したプログラムは再配置可能である必要がある

## 2-3 プログラミング

### まとめ表

**プログラムの性質（R3秋 問6・R4春 問6の選択肢に並んだ4つ）**

| 性質 | 一言で | 条件 |
| :-: | :-: | :-: |
| 再入可能（リエントラント） | 同時に何人が呼んでも正しく動く | 手続（命令）の部分と、呼出しごとのデータの部分を分ける |
| 再使用可能（リユーザブル） | 終わったら読み込み直さずにまた使える | 最初に変数を初期化する（終わるときに初期状態へ戻す） |
| 再帰的（リカーシブ） | 自分自身を呼び出せる | 呼出しごとに別のデータ領域を使う。再入可能でもある |
| 再配置可能（リロケータブル） | 主記憶のどこに置いても動く | アドレスを相対的に表す（ベースレジスタなどを使う） |

**オーバーロードとオーバーライド**

| 用語 | 何が同じで何が違うか | 場所 |
| :-: | :-: | :-: |
| オーバーロード | 名前が同じで、引数の型や数が違う | 同じクラスの中 |
| オーバーライド | 名前も引数も同じで、中身だけ違う | 親クラスのメソッドを子クラスで書き直す |

**Webプログラミングの技術**

| 技術 | 動く場所 | 何をするか |
| :-: | :-: | :-: |
| Ajax | ブラウザ | 画面を切り替えずに、裏でサーバと通信して一部だけ書き換える |
| SPA | ブラウザ | 最初に1ページだけ読み込み、あとは中身を入れ替えて画面を変える |
| WebAssembly | ブラウザ | C言語などから作ったバイナリを、ブラウザ上で高速に動かす |
| JSP | サーバ | HTMLの中にJavaのコードを埋め込み、サーバでページを作る |

### プログラミング作法

#### コーディング標準（こーでぃんぐひょうじゅん / Coding Standard）

- 意味：プログラムの書き方について、チームや組織で守ると決めた約束ごと。命名規則・字下げ・ネストの深さ・使用禁止命令などを決める
- ポイント：読みやすさと保守性を上げ、人によるばらつきや誤りを減らすのが目的

#### 字下げ（じさげ / Indentation）

- 意味：プログラムの行頭に空白を入れて、処理のまとまりや入れ子の深さを見た目でわかるようにすること。インデンテーションとも呼ぶ
- ポイント：多くの言語では見た目だけの意味だが、Pythonでは字下げそのものがブロックの範囲を決める
- 例：R4春 問7（記号や予約語を使わず、字下げでブロックを表す言語→Python）

#### ネストの深さ（ねすとのふかさ / Nesting Depth）

- 意味：if文や繰返しの中にさらに if文や繰返しを入れたときの、入れ子の段数
- ポイント：深すぎると読みにくく誤りが増えるので、コーディング標準で上限を決めることが多い

#### 命名規則（めいめいきそく / Naming Convention）

- 意味：変数・関数・クラスなどに名前を付けるときの決まり
- ポイント：「定数はすべて大文字」「関数名は動詞で始める」など。名前を見ただけで役割がわかるようにする

#### 使用禁止命令（しようきんしめいれい / Prohibited Statement）

- 意味：誤りや保守のしにくさの原因になるので、コーディング標準で使わないと決めた命令や書き方
- ポイント：goto文のように処理の流れを追いにくくするものや、安全でない関数が対象になる

### プログラムの構造

#### モジュール分割（もじゅーるぶんかつ / Modularization）

- 意味：大きなプログラムを、機能ごとのまとまり（モジュール）に分けて作ること
- ポイント：分けたモジュールどうしの独立性が高いほど、1か所の修正がほかに広がりにくい

#### モジュール独立性（もじゅーるどくりつせい / Module Independence）

- 意味：あるモジュールが、ほかのモジュールの影響をどれだけ受けずに済むかの度合い
- ポイント：モジュールの中のまとまり（強度・凝集度）は高く、モジュールどうしのつながり（結合度）は低いほど独立性が高い。詳しくはシステム開発技術の分野で出る

#### メインルーチン（めいんるーちん / Main Routine）

- 意味：プログラムの実行が始まる中心の部分で、サブルーチンを順に呼び出して全体の流れを組み立てるもの
- ポイント：C言語やJavaでは main という名前の関数（メソッド）がこれに当たる

#### サブルーチン（さぶるーちん / Subroutine）

- 意味：ひとまとまりの処理に名前を付けて切り出し、ほかの場所から呼び出して使えるようにしたもの
- ポイント：同じ処理を何度も書かずに済む。値を返すものを関数、返さないものを手続と呼び分ける言語もある

#### オーバーロード（おーばーろーど / Overloading）

- 意味：同じ名前で、引数の型や数が違うメソッド（関数）を複数定義すること。多重定義とも呼ぶ
- ポイント：呼び出したときの引数の形で、どれが実行されるかが決まる。名前も引数も同じで書き直すのは別の用語

#### オーバーライド（おーばーらいど / Overriding）

- 意味：親クラス（スーパークラス）のメソッドと名前も引数も同じメソッドを子クラス（サブクラス）で定義し、中身を書き直すこと
- ポイント：同じ呼び出し方でも、オブジェクトの種類によって違う動きになる（ポリモーフィズム）

#### DLL（でぃーえるえる / Dynamic Link Library）

- 意味：実行するときになってからプログラムに結び付けて使う、部品プログラムの集まり
- ポイント：複数のプログラムで共有でき、部品だけを差し替えて更新できる。作るときに全部を結び付けてしまう静的リンクと対になる
- 語の意味：Dynamic＝動的な／Link＝結び付ける／Library＝（部品の）図書館

#### 静的リンク（せいてきりんく / Static Linking）

- 意味：プログラムを作る（リンクする）段階で、使う部品プログラムを実行ファイルの中に全部取り込んでおく方法
- ポイント：実行時に部品がなくても動くが、実行ファイルが大きくなり、部品を直したら作り直しが要る

### プログラムの性質

#### 再入可能（さいにゅうかのう / Reentrant）

- 意味：複数のタスクから同時に呼び出されて並行して実行されても、それぞれに正しい結果を返せるプログラムの性質。リエントラントとも呼ぶ
- ポイント：手続の部分は共有し、データの部分は呼出しごとに別に用意する。「データとコードの両方を共用」は誤り
- 例：R4春 問6（並行して実行されても、それぞれのタスクに正しい結果を返す）、R3秋 問6 ウ（両方を共用は誤り）

#### 再使用可能（さいしようかのう / Reusable）

- 意味：一度実行して終わったあと、主記憶に読み込み直さなくても、もう一度正しく実行できるプログラムの性質。シリアリリユーザブルとも呼ぶ
- ポイント：実行の始めに変数を初期化するか、終わるときに初期状態に戻しておく。同時に複数から呼べるとは限らない
- 例：R3秋 問6（実行の始めに変数を初期化する、又は変数を初期状態に戻した後に終了する）

#### 再帰的（さいきてき / Recursive）

- 意味：自分自身を呼び出して使うことができるプログラムの性質。リカーシブとも呼ぶ
- ポイント：呼出しごとに別のデータ領域（スタック上の領域）を使うので、再入可能でもある。「全てがデータを共用する」は誤り
- 例：R3秋 問6 ア、R4春 問6 イ（手続の内部から自分自身を呼び出せる）

#### 再配置可能（さいはいちかのう / Relocatable）

- 意味：主記憶上のどのアドレスに置いても、正しく実行できるプログラムの性質。リロケータブルとも呼ぶ
- ポイント：アドレスを、プログラムの先頭からの相対的な位置で表しておく。「定まった領域で実行される」は誤り
- 例：R3秋 問6 エ、R4春 問6 ア（どのアドレスから配置しても実行できる）

### データ型

#### 整数型（せいすうがた / Integer Type）

- 意味：小数点以下をもたない整数を入れるデータ型
- ポイント：ビット数で表せる範囲が決まる。16ビットの符号付き整数なら −32,768〜32,767。範囲を超えるとあふれ（オーバーフロー）が起きる

#### 実数型（じっすうがた / Real Type）

- 意味：小数点以下をもつ数を、浮動小数点数などで近似して入れるデータ型
- ポイント：10進の0.1のように正確に表せない数があるので、金額の計算には注意が要る

#### 論理型（ろんりがた / Boolean Type）

- 意味：真（true）と偽（false）の2つの値だけを入れるデータ型。ブール型とも呼ぶ
- ポイント：条件式の結果を入れるのに使う

#### 文字型（もじがた / Character Type）

- 意味：1つの文字（を表す文字コード）を入れるデータ型
- ポイント：文字が並んだものは文字列型として別に扱う言語が多い

#### 構造型（こうぞうがた / Structured Type）

- 意味：配列やレコード（構造体）のように、複数の値を組み合わせて1つにしたデータ型
- ポイント：整数型・実数型のような1つの値だけの型（基本型）と対になる

#### 列挙型（れっきょがた / Enumerated Type）

- 意味：とりうる値を「赤・黄・青」のように名前で並べて決めたデータ型
- ポイント：決められた値以外を入れられないので、誤りを防げる

#### 抽象データ型（ちゅうしょうでーたがた / Abstract Data Type）

- 意味：データと、それに対してできる操作をひとまとめにし、中の作り方を外から見えなくした型
- ポイント：スタックなら「プッシュ・ポップができる」ことだけを決め、配列で作るかリストで作るかは隠す。オブジェクト指向のカプセル化のもとになる考え方

### Webプログラミング

#### サーバサイドプログラミング（さーばさいどぷろぐらみんぐ / Server-side Programming）

- 意味：Webサーバの側で動くプログラムを作り、ブラウザに返すページやデータをサーバで組み立てること（JSPやPHPなどを使う）
- ポイント：データベースの読み書きや認証はここで行う。ブラウザの側で動くものはクライアントサイド（フロントエンド）と呼ぶ

#### リッチクライアント（りっちくらいあんと / Rich Client）

- 意味：Webの仕組みで配布しながら、クライアントの側でデスクトップアプリのように操作性のよい画面を実現する方式
- ポイント：ブラウザで表示だけするシンクライアント的なWebアプリと、配布に手間がかかるデスクトップアプリの中間をねらったもの

#### Ajax（えいじゃっくす / Asynchronous JavaScript and XML）

- 意味：ブラウザ上のJavaScriptが、画面を切り替えずに裏でサーバと非同期に通信し、受け取ったデータでページの一部だけを書き換える技術
- ポイント：地図を動かすと続きの部分だけ読み込まれる、という動きがこれ。データはXMLに限らず、今はJSONが多い
- 語の意味：Asynchronous＝非同期の／JavaScript＝言語の名前／And＝と／XML＝データの形式

#### SPA（えすぴーえー / Single Page Application）

- 意味：最初に1つのページを読み込んだあとは、ページ全体を読み直さずにJavaScriptで中身を入れ替えて画面を変えるWebアプリ
- ポイント：アプリのように素早く画面が変わる。部品を作る仕組みとして、ReactやVue.jsなどのフロントエンドフレームワークを使うことが多い
- 語の意味：Single＝1つの／Page＝ページ／Application＝アプリケーション

#### フロントエンドフレームワーク（ふろんとえんどふれーむわーく / Front-end Framework）

- 意味：ブラウザで動く画面の部品や状態の管理を、決まった型に沿って作れるようにしたソフトウェアの枠組み
- ポイント：React・Vue.js・Angularが代表。SPAを作るときの土台になる

#### WebAssembly（うぇぶあせんぶり / WebAssembly）

- 意味：C言語やRustなどから変換して作る、ブラウザ上で高速に実行できるバイナリ形式のプログラム
- ポイント：JavaScriptより速く動くので、ゲームや画像処理などに使う。略してWasm

#### JSP（じぇいえすぴー / Jakarta Server Pages）

- 意味：HTMLの中にJavaのコードを埋め込んでおき、Webサーバで実行してページを作る技術
- ポイント：サーバの側で動く。もとは JavaServer Pages という名前だった
- 語の意味：Jakarta＝Java EEを引き継いだ技術群の名前／Server＝サーバ／Pages＝ページ

#### Apache（あぱっち / Apache HTTP Server）

- 意味：オープンソースで提供されている、代表的なWebサーバのソフトウェア
- ポイント：機能をモジュールとして追加できる。同じ役割のソフトウェアに nginx がある

### 文法の表記法と言語の規則

#### BNF（びーえぬえふ / Backus-Naur Form）

- 意味：プログラム言語の構文の決まりを、「::＝」（定義）と「|」（または）だけを使って書き表す記法。繰返しは自分自身を使って（再帰で）表す
- ポイント：〈数〉::＝〈数字〉|〈数〉〈数字〉のように書く。文脈自由文法を書くのに使う
- 語の意味：Backus＝バッカス（考案者）／Naur＝ナウア（考案者）／Form＝形式

#### EBNF（いーびーえぬえふ / Extended Backus-Naur Form）

- 意味：BNFに、繰返し（{ }）や省略できる部分（[ ]）などの記号を足して、短く書けるようにした記法。拡張バッカス記法とも呼ぶ
- ポイント：BNFでは再帰で書く繰返しを、{ } で直接書ける
- 語の意味：Extended＝拡張した／Backus＝バッカス（考案者）／Naur＝ナウア（考案者）／Form＝形式

#### 構文図（こうぶんず / Syntax Diagram）

- 意味：プログラム言語の構文の決まりを、矢印でつながった箱の図で表したもの
- ポイント：BNFと同じ内容を図で表したもの。線路をたどるように、通れる道が正しい書き方になる

#### 構文規則（こうぶんきそく / Syntax Rule）

- 意味：プログラム言語で、文字や記号をどう並べれば正しい文になるかという書き方の決まり
- ポイント：BNFや構文図で書く。コンパイラの構文解析で調べる

#### 意味規則（いみきそく / Semantic Rule）

- 意味：構文として正しく書かれたプログラムが、何を意味し、どう動くかを決める決まり
- ポイント：「型の違う値を代入できない」なども意味規則。数学的にきちんと定める方法を形式的意味論と呼ぶ

#### 文脈自由文法（ぶんみゃくじゆうぶんぽう / Context-free Grammar）

- 意味：左辺に1つの記号だけを置く書き換え規則で、言語の構文を定める文法
- ポイント：多くのプログラム言語の構文はこれで書ける。BNFはこの文法を書く記法。受理する機械はプッシュダウンオートマトン（基礎理論）

| :-: | :-: | :-: |
| 値呼出し | 実引数の値のコピー | 1（変わらない） |
| 参照呼出し | 実引数の場所（アドレス） | 2（変わる） |

### 言語の水準

#### 機械語（きかいご / Machine Language）

- 意味：CPUが直接読んで実行できる、0と1の並びで書かれた命令の言葉
- ポイント：CPUの種類ごとに違う。人が読み書きするのはとても難しい

#### アセンブラ言語（あせんぶらげんご / Assembly Language）

- 意味：機械語の命令の1つ1つを、ADD や MOV のような覚えやすい記号に置き換えて書く言語
- ポイント：機械語とほぼ1対1で対応する低水準言語。アセンブラで機械語に変換する

#### 高水準言語（こうすいじゅんげんご / High-level Language）

- 意味：CPUの命令を意識せず、人の考え方に近い書き方で処理を書ける言語
- ポイント：コンパイラやインタプリタで機械語に変換して実行する。CやJava、Pythonなど

#### 中間言語（ちゅうかんげんご / Intermediate Language）

- 意味：高水準言語をすぐ機械語にせず、特定のCPUに依存しない形にいったん変換したコード
- ポイント：Javaのバイトコードや、共通言語基盤（CLI）の共通中間言語がこれ。仮想マシンやJITコンパイラが実行時に機械語にする

### 言語の分類

#### 手続型言語（てつづきがたげんご / Procedural Language）

- 意味：処理の手順（命令）を順に並べ、変数の値を書き換えながら計算を進める言語
- ポイント：C、Fortran、COBOL、Pascal、BASICなど。命令型言語とも呼ぶ

#### 関数型言語（かんすうがたげんご / Functional Language）

- 意味：関数の定義と、関数を値に当てはめること（関数適用）を組み合わせて計算を書く言語
- ポイント：変数の値を書き換えず、同じ入力にはいつも同じ結果を返すように書く。Haskell、Lisp など

#### 論理型言語（ろんりがたげんご / Logic Programming Language）

- 意味：事実と規則を論理式で書いておき、問いに対して推論で答えを導く言語
- ポイント：Prolog が代表。手順は書かず「何が成り立つか」を書く

#### オブジェクト指向言語（おぶじぇくとしこうげんご / Object-oriented Language）

- 意味：データとそれを扱う手続をまとめた「オブジェクト」を単位にしてプログラムを組み立てる言語
- ポイント：カプセル化・継承・ポリモーフィズムが3つの特徴。Java、C++ など

#### スクリプト言語（すくりぷとげんご / Scripting Language）

- 意味：コンパイルの手間をかけずに、書いてすぐ実行できるようにした、手軽に使える言語の総称
- ポイント：インタプリタで動くものが多く、変数の型を宣言しない（動的型付け）ものが多い。Perl、PHP、Python、Ruby、JavaScript など

### 手続型の言語

#### Fortran（ふぉーとらん / FORmula TRANslation）

- 意味：数式の計算を書きやすくした、科学技術計算向けの古い手続型言語
- ポイント：1950年代にできた最初期の高水準言語。今もスーパーコンピュータの計算で使われる
- 語の意味：FORmula＝数式／TRANslation＝翻訳

#### COBOL（こぼる / COmmon Business Oriented Language）

- 意味：英語に近い書き方で、事務処理（帳票・会計）を書くために作られた手続型言語
- ポイント：10進の計算が正確なので、銀行や役所の基幹システムで今も使われている
- 語の意味：COmmon＝共通の／Business＝事務・ビジネス／Oriented＝向けの／Language＝言語

#### Pascal（ぱすかる / Pascal）

- 意味：プログラミング教育のために作られた、構造化プログラミングの考え方を取り入れた手続型言語
- ポイント：型の決まりが厳しく、きれいな書き方が身に付く。名前は数学者パスカルから

#### BASIC（べーしっく / Beginner's All-purpose Symbolic Instruction Code）

- 意味：初心者が学びやすいように作られた、簡単な書き方の手続型言語
- ポイント：昔のパソコンに標準で入っていた。Visual Basic や VBScript の元になった
- 語の意味：Beginner's＝初心者の／All-purpose＝汎用の／Symbolic＝記号の／Instruction＝命令／Code＝コード

#### C（しー / C Language）

- 意味：OS（UNIX）を書くために作られた、ハードウェアに近い操作もできる手続型言語
- ポイント：ポインタで主記憶を直接扱える。組込みシステムで広く使う。C++ や Java など多くの言語の元になった

#### R（あーる / R Language）

- 意味：統計解析やグラフ描画のために作られた、オープンソースの言語と実行環境
- ポイント：データ分析・機械学習のパッケージが多数ある。変数に型がなく、代入した値の型が実行時に決まる。シラバスでは手続型言語の例に入っている
- 例：R3春 問8＝R6秋 問7（統計解析や機械学習に適し、変数自体には型がない→R）

### オブジェクト指向の言語

#### Java（じゃば / Java）

- 意味：一度書けばどの環境でも動くことをめざした、オブジェクト指向言語
- ポイント：コンパイルしてバイトコード（中間コード）にし、JVM（Java仮想マシン）で実行する。クラスの多重継承はできない（インタフェースで代わりをする）

#### C++（しーぷらすぷらす / C++）

- 意味：C言語にクラスなどのオブジェクト指向の機能を足した言語
- ポイント：Cと同じく速く動き、ハードウェアに近い操作もできる。クラスの多重継承ができる

#### Go（ごー / Go）

- 意味：グーグル社が作った、簡潔な文法で並行処理を書きやすくした、コンパイルして実行する言語
- ポイント：ゴルーチンという軽い並行処理の仕組みをもつ。サーバやクラウドのツールで使う。シラバスではオブジェクト指向言語の例に入っている
- 例：R3春 問8 ア（誤りの選択肢）

#### Julia（じゅりあ / Julia）

- 意味：科学技術計算やデータ分析向けに、書きやすさと実行の速さを両立させた言語
- ポイント：Pythonのように書けてCに近い速さで動くことをめざした。実行時にその場で機械語に変換する（JITコンパイル）

#### Kotlin（ことりん / Kotlin）

- 意味：JVM上で動き、Javaのプログラムと一緒に使える、簡潔な書き方の言語
- ポイント：Androidアプリ開発の推奨言語。null による誤りを防ぐ仕組みをもつ
- 例：R3春 問8 イ（誤りの選択肢）

#### Scala（すから / Scala）

- 意味：オブジェクト指向プログラミングと関数型プログラミングの両方の書き方ができる、JVM上で動く言語
- ポイント：静的型付けで、型推論があるので型を書く量が少なくて済む。クラスの多重継承はできない（トレイトで代わりをする）
- 例：R7秋 問7（オブジェクト指向と関数型の両方が可能）

### スクリプト言語

#### ECMAScript（えくますくりぷと / ECMAScript）

- 意味：JavaScriptの文法や機能を、標準化団体のEcma Internationalが定めた標準仕様
- ポイント：JavaScriptはこの仕様に沿って作られた言語。ES2015（ES6）のように年で版を呼ぶ。変数に型を宣言しない（動的型付け）
- 例：R3秋 問7 ア（静的型付けはできない）

#### JavaScript（じゃばすくりぷと / JavaScript）

- 意味：Webブラウザの中で動き、ページに動きや操作を付けるためのスクリプト言語。ECMAScriptの仕様に沿って作られている
- ポイント：名前が似ているが Java とは別の言語。今はサーバ側（Node.js）でも動く。動的型付け

#### TypeScript（たいぷすくりぷと / TypeScript）

- 意味：JavaScriptに静的な型の仕組みを足した言語。JavaScriptに変換して実行する
- ポイント：コンパイル（変換）のときに型の誤りを見つけられる。大きなWebアプリの開発で使う
- 例：R3秋 問7（Webのスクリプト言語のうち、変数の静的型付けができるもの）

#### VBScript（ぶいびーすくりぷと / Visual Basic Scripting Edition）

- 意味：Microsoftが作った、Visual Basicを元にしたWindows向けのスクリプト言語
- ポイント：動的型付けで、すべての変数が1つの型（Variant）になる。今は使われなくなっている
- 例：R3秋 問7 エ（誤りの選択肢）

#### Perl（ぱーる / Perl）

- 意味：文字列の処理、特に正規表現を使ったテキストの加工が得意なスクリプト言語
- ポイント：昔のWebのCGIでよく使われた。動的型付け

#### PHP（ぴーえいちぴー / PHP: Hypertext Preprocessor）

- 意味：HTMLの中に埋め込んで書き、Webサーバの側で実行してページを作るスクリプト言語
- ポイント：WordPressなど多くのWebサービスで使われている。ブロックは { } で表す
- 語の意味：PHP＝（自分自身の略）／Hypertext＝ハイパーテキスト／Preprocessor＝前処理するもの

#### Python（ぱいそん / Python）

- 意味：読みやすさを重視し、字下げでブロックの範囲を表すスクリプト言語
- ポイント：機械学習・データ分析のライブラリが多い。動的型付け。{ } や begin/end を使わない
- 例：R4春 問7（記号や予約語を使わず、等しい文字数の字下げでブロックを表す）

#### Ruby（るびー / Ruby）

- 意味：日本人のまつもとゆきひろ氏が作った、すべての値をオブジェクトとして扱うスクリプト言語
- ポイント：Webアプリのフレームワーク Ruby on Rails で広まった。JIS規格・ISO規格にもなっている

### 型と実行の基盤

#### 静的型付け（せいてきかたづけ / Static Typing）

- 意味：変数の型をプログラムを実行する前（コンパイル時）に決め、そのときに型の誤りを調べる方式
- ポイント：変数名の誤りや、型の違う値の代入を実行前に見つけられる。Java、C、TypeScript、Scala など
- 例：R3秋 問7（コンパイル時に誤りを発見できる→TypeScript）

#### 動的型付け（どうてきかたづけ / Dynamic Typing）

- 意味：変数には型がなく、代入された値の型が実行するときに決まる方式
- ポイント：書くのは手軽だが、型の誤りは実行して初めてわかる。Python、R、JavaScript、Ruby など
- 例：R3春 問8（変数自体には型がない）、R7秋 問7 エ（Scalaは動的型付けではない）

#### 型推論（かたすいろん / Type Inference）

- 意味：変数の型を書かなくても、代入する値や式から処理系が型を自動で決める仕組み
- ポイント：静的型付けのまま、型を書く手間を減らせる。Scala、Kotlin、Go、TypeScript などがもつ

#### 共通言語基盤（きょうつうげんごきばん / Common Language Infrastructure）

- 意味：違う言語で書いたプログラムを、共通の中間言語に変換して同じ実行環境で動かせるようにする仕様。CLIと略す
- ポイント：JIS X 3016（ISO/IEC 23271）で標準化。Microsoftの .NET がこれに沿っている。C# と Visual Basic で作った部品を組み合わせられる
- 語の意味：Common＝共通の／Language＝言語／Infrastructure＝基盤

### 制御構造と並行処理

#### 連接（れんせつ / Sequence）

- 意味：処理を書いた順番どおりに1つずつ実行する制御構造。順次とも呼ぶ
- ポイント：選択・繰返しと合わせた3つで、どんな処理も書ける（構造化定理）

#### 選択（せんたく / Selection）

- 意味：条件によって、実行する処理を選び分ける制御構造
- ポイント：if文や switch文で書く。流れ図ではひし形（判断）で表す

#### 繰返し（くりかえし / Iteration）

- 意味：条件を満たす間（または満たすまで）、同じ処理を何度も実行する制御構造
- ポイント：前判定（先に条件を調べる while）と後判定（1回実行してから調べる do-while）がある。後判定は必ず1回は実行される

#### 手続呼出し（てつづきよびだし / Procedure Call）

- 意味：ほかの場所に書いた手続（サブルーチン）に制御を移して実行し、終わったら呼び出した所の次に戻ること
- ポイント：戻り先はスタックに積んでおく。だから自分自身を呼ぶ再帰呼出しもできる

#### 再帰呼出し（さいきよびだし / Recursive Call）

- 意味：ある手続や関数が、その中で自分自身を呼び出すこと
- ポイント：呼ぶたびに引数や局所変数の領域がスタックに積まれる。止まる条件がないと積み続けてあふれる（スタックオーバーフロー）

#### プロセス（ぷろせす / Process）

- 意味：実行中のプログラムのことで、OSが主記憶などの資源を割り当てる単位
- ポイント：プロセスごとに別々のメモリ空間をもつ。1つのプロセスの中で並行して動く単位がスレッドで、スレッドどうしはメモリを共有する

#### 擬似並列制御（ぎじへいれつせいぎょ / Pseudo-parallel Control）

- 意味：CPUが1つでも、複数の処理を短い時間ずつ切り替えて実行し、同時に動いているように見せる制御
- ポイント：本当に同時に動かす（複数のCPUで動かす）並列処理とは違う。コルーチンもこの考え方

### 引数の渡し方

#### 仮引数（かりひきすう / Formal Parameter）

- 意味：手続や関数を定義するときに、受け取る値を入れるために書いておく変数
- ポイント：sub(x) の x がこれ。呼び出すときに実際に渡す値の方は別の用語

#### 実引数（じつひきすう / Actual Parameter）

- 意味：手続や関数を呼び出すときに、実際に渡す値や変数
- ポイント：sub(a) の a がこれ。引数のことをパラメータとも呼ぶ

#### 値呼出し（あたいよびだし / Call by Value）

- 意味：実引数の値をコピーして渡す引数の渡し方
- ポイント：呼ばれた側で仮引数を書き換えても、呼んだ側の変数は変わらない

#### 参照呼出し（さんしょうよびだし / Call by Reference）

- 意味：実引数の格納場所（アドレス）を渡す引数の渡し方
- ポイント：呼ばれた側で仮引数を書き換えると、呼んだ側の変数も同じように変わる

### 記憶域

#### 目的プログラムテキスト（もくてきぷろぐらむてきすと / Object Program Text）

- 意味：コンパイルして作られた機械語の命令が入る記憶域
- ポイント：実行中に書き換えない部分なので、複数の実行で共有できる（再入可能プログラムの手続部分）

#### 静的変数（せいてきへんすう / Static Variable）

- 意味：プログラムの実行の始めから終わりまで、同じ記憶域にずっと置かれる変数
- ポイント：関数を抜けても値が残る。大域変数（グローバル変数）もここに置かれる

#### 自動変数（じどうへんすう / Automatic Variable）

- 意味：関数やブロックに入るたびに確保され、抜けると自動的に解放される変数
- ポイント：スタック領域に置かれる局所変数。呼出しごとに別の領域になるので、再帰呼出しができる

#### ヒープ領域（ひーぷりょういき / Heap Area）

- 意味：プログラムの実行中に、必要になった大きさの分だけ確保して使う記憶域
- ポイント：C言語の malloc や Java の new で確保する。使い終わっても解放しないと、使えない領域が増える（メモリリーク）。データ構造のヒープとは別物

#### ガベージコレクション（がべーじこれくしょん / Garbage Collection）

- 意味：プログラムからもう参照されなくなったヒープ領域のデータを探し、自動的に解放して再び使えるようにする仕組み
- ポイント：Java、Python、Go などがもつ。メモリリークを防げるが、実行中に一時的に処理が止まることがある

#### スコープ（すこーぷ / Scope）

- 意味：変数や関数の名前を、プログラムのどの範囲から使えるかという有効範囲
- ポイント：ブロックの中で宣言した変数は、そのブロックの中だけで使える。同じ名前でも範囲が違えば別の変数になる

#### ブロック（ぶろっく / Block）

- 意味：複数の文を1つにまとめた、プログラムの区切りの単位
- ポイント：C や Java は { }、Pascal は begin〜end、Python は字下げで表す。変数の有効範囲の単位にもなる

### マークアップ言語

#### SGML（えすじーえむえる / Standard Generalized Markup Language）

- 意味：文書の構造をタグで表すマークアップ言語を、自分で定義するための国際規格
- ポイント：HTMLはSGMLで定義された言語。SGMLを簡単にしてWebで使いやすくしたのがXML
- 語の意味：Standard＝標準の／Generalized＝汎用化した／Markup＝印付け／Language＝言語

#### HTML（えいちてぃーえむえる / HyperText Markup Language）

- 意味：Webページの見出し・段落・リンクなどの構造を、決められたタグで書くマークアップ言語
- ポイント：使えるタグは決まっていて、自分で新しく作れない。見た目はCSSで決める
- 語の意味：HyperText＝ほかの文書へのリンクをもつ文書／Markup＝印付け／Language＝言語

#### XML（えっくすえむえる / Extensible Markup Language）

- 意味：利用者が独自のタグを定義して、データの意味と構造を書けるマークアップ言語
- ポイント：インターネットでのデータ交換に使う。文書の始めのXML宣言で文字コードを示す（符号化宣言）が、UTF-8とUTF-16なら省略できる
- 例：R4秋 問7（符号化宣言を省略できる文字コード→UTF-16）
- 語の意味：Extensible＝拡張できる／Markup＝印付け／Language＝言語

#### XHTML（えっくすえいちてぃーえむえる / Extensible HyperText Markup Language）

- 意味：HTMLを、XMLの規則に沿って定義し直したマークアップ言語
- ポイント：XMLの規則に従うので、終了タグの省略や大文字・小文字の混在ができない。携帯端末向けに機能を絞った XHTML Basic、機能を部品に分けた XHTML Modularization がある
- 語の意味：Extensible＝拡張できる／HyperText＝リンクをもつ文書／Markup＝印付け／Language＝言語

### タグと文書型

#### 開始タグ（かいしたぐ / Start Tag）

- 意味：マークアップ言語で、要素の始まりを示す〈p〉のようなタグ
- ポイント：属性（〈a href="…"〉の href）は開始タグの中に書く

#### 終了タグ（しゅうりょうたぐ / End Tag）

- 意味：マークアップ言語で、要素の終わりを示す〈/p〉のような、名前の前に / を付けたタグ
- ポイント：HTMLでは省略できるものがあるが、XMLとXHTMLでは省略できない。中身のない要素は〈br /〉のように書く

#### DTD（でぃーてぃーでぃー / Document Type Definition）

- 意味：文書で使える要素・属性と、その並び方の決まりを、SGMLから続く独自の書き方で書いたもの。文書型定義とも呼ぶ
- ポイント：XMLの書き方ではない。データ型（数値・日付など）は細かく決められない
- 語の意味：Document＝文書／Type＝型／Definition＝定義

#### XML Schema（えっくすえむえるすきーま / XML Schema）

- 意味：XML文書の要素・属性の構造やデータ型の決まりを、XMLの書き方で定義する仕様
- ポイント：DTDより細かく、「この要素は整数」「0以上100以下」のような型や範囲まで決められる

### XMLを扱う仕組み

#### DOM（どむ / Document Object Model）

- 意味：HTMLやXMLの文書を木の形のオブジェクトとして表し、プログラムから要素を読んだり書き換えたりするための仕様
- ポイント：文書全体をメモリに読み込むので、前後に自由に動いて変更できるが、大きな文書ではメモリを多く使う。JavaScriptで画面を書き換えるときに使う
- 例：R5秋 問7 ア（誤りの選択肢）
- 語の意味：Document＝文書／Object＝オブジェクト／Model＝模型・型

#### SAX（さっくす / Simple API for XML）

- 意味：XML文書を先頭から順に読み、開始タグや終了タグが現れるたびにプログラムの処理を呼び出す仕組み
- ポイント：全体をメモリに載せないので、大きな文書でも少ないメモリで読める。その代わり、前に戻ったり書き換えたりは苦手
- 語の意味：Simple＝簡単な／API＝プログラムから呼び出す窓口／for＝のための／XML＝XML

#### SOAP（そーぷ / SOAP）

- 意味：XMLで書いたメッセージをHTTPなどで送り、ほかのシステムの機能を呼び出すための通信の決まり（プロトコル）
- ポイント：Webサービスで使う。今はもっと簡単な REST と JSON の組合せが多い
- 例：R5秋 問7 ウ（誤りの選択肢）

#### SVG（えすぶいじー / Scalable Vector Graphics）

- 意味：図形を点の集まりではなく、線や形の情報としてXMLで書く画像形式
- ポイント：拡大しても粗くならない。ブラウザで表示でき、HTMLの中に直接書ける
- 語の意味：Scalable＝大きさを変えられる／Vector＝方向と大きさをもつ線／Graphics＝図

#### XSL（えっくすえすえる / Extensible Stylesheet Language）

- 意味：XML文書の表示の仕方を決めたり、XML文書をHTMLなどの別の形式に変換したりするためのスタイルシートの言語
- ポイント：変換を受けもつ部分をXSLTと呼ぶ。見た目を決めるだけのCSSと違い、文書の構造そのものを組み替えられる
- 語の意味：Extensible＝拡張できる／Stylesheet＝見た目を決める指定／Language＝言語

#### CSS（しーえすえす / Cascading Style Sheets）

- 意味：HTMLやXMLの文書の構造は変えずに、文字の大きさ・色・配置などの見た目だけを指定するスタイルシートの言語
- ポイント：文書の構造（HTML）と見た目（CSS）を分けて書ける。複数の指定が重なったときに優先順位に従って決まることを「カスケード」と呼ぶ
- 語の意味：Cascading＝段々に流れる（重なりが順に適用される）／Style＝見た目／Sheets＝指定書

### データ記述の言語

#### JSON（じぇいそん / JavaScript Object Notation）

- 意味：JavaScriptのオブジェクトの書き方を元にした、「名前と値の組の集まり」と「値の順序付きリスト」の2つの形でデータを表すテキスト形式
- ポイント：{ "名前": 値 } と [ 値, 値 ] の組合せで書く。XMLより短く書けるので、Web APIのデータ交換で最もよく使われる
- 例：R5秋 問7（“名前と値との組みの集まり”と“値の順序付きリスト”）
- 語の意味：JavaScript＝言語の名前／Object＝オブジェクト／Notation＝表記法

#### YAML（やむる / YAML Ain't Markup Language）

- 意味：字下げと「名前: 値」の形で構造を表す、人が読み書きしやすいデータの書き方
- ポイント：設定ファイルによく使う。JSONで書けるデータはYAMLでも書ける
- 語の意味：YAML＝（自分自身の略）／Ain't＝ではない／Markup Language＝マークアップ言語

#### DDL（でぃーでぃーえる / Data Definition Language）

- 意味：データベースの表や索引などの構造を定義するための言語。SQLの CREATE・ALTER・DROP がこれ
- ポイント：データを操作する DML（SELECT・INSERT など）と対になる。詳しくはデータベースの分野で出る
- 語の意味：Data＝データ／Definition＝定義／Language＝言語

#### SDL（えすでぃーえる / Specification and Description Language）

- 意味：通信の仕組みのような、状態が変わりながら動くシステムの仕様を、図と文で書くための言語
- ポイント：ITU-T が標準化。通信プロトコルの仕様書で使われてきた
- 語の意味：Specification＝仕様／Description＝記述／Language＝言語

#### ADL（えーでぃーえる / Architecture Description Language）

- 意味：ソフトウェアやシステムの全体構成（アーキテクチャ）を、部品とそのつながりとして書き表すための言語の総称。アーキテクチャ記述言語とも呼ぶ
- ポイント：プログラムの中身ではなく、部品の組み合わせ方を書く
- 語の意味：Architecture＝構造・全体構成／Description＝記述／Language＝言語

### UMLの構造を表す図

#### クラス図（くらすず / Class Diagram）

- 意味：クラスの名前・属性・操作と、クラスどうしの関係（関連・汎化・集約など）を表すUMLの図
- ポイント：箱を3段に分け、上から名前・属性・操作を書く。設計で最もよく使う図

#### オブジェクト図（おぶじぇくとず / Object Diagram）

- 意味：ある時点での、具体的なオブジェクト（インスタンス）とそれらのつながりを表すUMLの図
- ポイント：クラス図の「型」に対して、こちらは実際の値の入った「例」を表す。名前に下線を引く

#### コンポーネント図（こんぽーねんとず / Component Diagram）

- 意味：ソフトウェアを構成する部品（コンポーネント）と、部品の間のインタフェースや依存関係を表すUMLの図
- ポイント：どの部品がどの部品の機能を使うかがわかる

#### パッケージ図（ぱっけーじず / Package Diagram）

- 意味：クラスなどの要素をまとめたグループ（パッケージ）と、グループどうしの依存関係を表すUMLの図
- ポイント：大きなシステムを整理して見せるのに使う。フォルダのような形の記号で書く

#### 配置図（はいちず / Deployment Diagram）

- 意味：ソフトウェアの部品を、どのハードウェア（ノード）に置いて動かすかを表すUMLの図
- ポイント：サーバや端末を立体の箱で表し、その中に動く部品を書く

#### コンポジット構造図（こんぽじっとこうぞうず / Composite Structure Diagram）

- 意味：1つのクラスの内部が、どんな部品（パート）とそのつながりでできているかを表すUMLの図
- ポイント：クラス図がクラスどうしの関係を表すのに対し、こちらはクラスの内側を表す

### UMLの振る舞いとやり取りを表す図

#### ユースケース図（ゆーすけーすず / Use Case Diagram）

- 意味：システムの外にいる利用者（アクター）と、利用者から見たシステムの機能（ユースケース）を表すUMLの図
- ポイント：人型の記号がアクター、楕円がユースケース。要件定義で使う

#### アクティビティ図（あくてぃびてぃず / Activity Diagram）

- 意味：処理の流れを、分岐や並行して進む部分も含めて表すUMLの図
- ポイント：流れ図に近い。担当者ごとに区切る（スイムレーン）と、業務の流れも表せる

#### ステートマシン図（すてーとましんず / State Machine Diagram）

- 意味：1つのオブジェクトがとる状態と、どんな出来事（イベント）で状態が移り変わるかを表すUMLの図
- ポイント：状態遷移図と同じ考え方。基礎理論のオートマトンを図にしたものに近い

#### シーケンス図（しーけんすず / Sequence Diagram）

- 意味：オブジェクトの間でやり取りされるメッセージを、時間の流れに沿って上から下へ並べて表すUMLの図
- ポイント：オブジェクトを横に並べ、縦の点線（ライフライン）の間を矢印でつなぐ。「時間の順序」が見分ける言葉

#### コミュニケーション図（こみゅにけーしょんず / Communication Diagram）

- 意味：オブジェクトどうしのつながりを線で表し、その上にメッセージを番号付きで書いて、やり取りを表すUMLの図
- ポイント：時間の順番は番号で表す。「どのオブジェクトがどれとつながっているか」が見やすい。UML 1.x ではコラボレーション図と呼んだ

#### 相互作用概要図（そうごさようがいようず / Interaction Overview Diagram）

- 意味：いくつものシーケンス図などを部品として、アクティビティ図の形でつないだUMLの図
- ポイント：やり取りの全体の流れを一枚で見渡すのに使う

#### タイミング図（たいみんぐず / Timing Diagram）

- 意味：横軸に時間をとり、オブジェクトの状態がいつ変わるかを正確な時刻で表すUMLの図
- ポイント：組込みシステムのように、時間の制約が大事な処理で使う

### UMLの要素

#### 属性（ぞくせい / Attribute）

- 意味：クラス図で、クラスがもつデータ（性質）を表す項目
- ポイント：クラスの箱の2段目に書く。「−名前: String」のように、公開範囲・名前・型を書く

#### 操作（そうさ / Operation）

- 意味：クラス図で、クラスがもつ処理（メソッド）を表す項目
- ポイント：クラスの箱の3段目に書く。「＋計算する(): int」のように書く

#### ロール名（ろーるめい / Role Name）

- 意味：クラス図の関連の線の端に書く、その関連の中で相手のクラスが果たす役割の名前
- ポイント：「社員」と「会社」の関連で、会社側に「雇用主」と書くようなもの

#### 多重度（たじゅうど / Multiplicity）

- 意味：クラス図の関連の線の端に書く、相手のオブジェクトがいくつつながるかを表す数
- ポイント：「1」「0..1」「1..*」「*」のように書く。データベースの設計でも同じ考え方を使う

### 2-1 データ構造

#### 問 ap-2-r03h-q5

- 問：A，B，Cの順序で入力されるデータがある。各データについてスタックへの挿入と取出しを1回ずつ行うことができる場合，データの出力順序は何通りあるか。（原文はA, B, Cがスタックに入る図付き）
- ア：3
- イ：4
- ウ：5
- エ：6
- 正解：ウ
- 解説：3つの並べ方は全部で6通り（3!）。そのうち「C, A, B」だけは作れない。Cを最初に出すには A, B を積んだあとで C を出すことになり、次に出せるのは一番上の B なので、A を B より先に出せない。残りの ABC・ACB・BAC・BCA・CBA の5通りは、入れるとすぐ出す・ためてから出すの組合せで作れる。
- アの意味：3通り。「全部すぐ出す（ABC）」「全部ためてから出す（CBA）」など、思いつきやすい形だけを数えた数。BAC・ACB・BCA も作れる。
- イの意味：4通り。作れる5通りのどれかを数え漏らした数。
- ウの意味：正しい。並べ方6通りから、作れない CAB の1通りを引いた数。
- エの意味：6通り。並べ方の全部（3!）。スタックでは CAB が作れないので、全部はそろわない。
- 出典：IPA 令和3年度春期 応用情報技術者試験 午前 問5（令和7年度春期 問5と同じ問題）

#### 問 ap-2-r03h-q6

- 問：配列A[1]，A[2]，…，A[n]で，A[1]を根とし，A[i]の左側の子をA[2i]，右側の子をA[2i+1]とみなすことによって，2分木を表現する。このとき，配列を先頭から順に調べていくことは，2分木の探索のどれに当たるか。
- ア：行きがけ順（先行順）深さ優先探索
- イ：帰りがけ順（後行順）深さ優先探索
- ウ：通りがけ順（中間順）深さ優先探索
- エ：幅優先探索
- 正解：エ
- 解説：A[1] が根、A[2]・A[3] が2段目、A[4]〜A[7] が3段目…と、配列には根に近い段から順に、同じ段は左から右へ並んでいる。先頭から順に調べるのは、段ごとに調べる幅優先探索と同じ。
- アの意味：行きがけ順なら、A[1] の次に左の子 A[2]、その次はさらに左の子 A[4] を調べる。A[3] より A[4] が先になるので、配列の順と合わない。
- イの意味：帰りがけ順は、子を全部調べてから親を調べる。最初に来るのは左下の葉で、根の A[1] は最後になる。
- ウの意味：通りがけ順は、左の部分木→親→右の部分木の順。最初に来るのは一番左下の節で、A[1] ではない。
- エの意味：正しい。段ごとに左から右へ調べる。
- 出典：IPA 令和3年度春期 応用情報技術者試験 午前 問6

#### 問 ap-2-r04h-q5

- 問：リストには，配列で実現する場合とポインタで実現する場合とがある。リストを配列で実現した場合の特徴として，適切なものはどれか。ここで，配列を用いたリストは配列に要素を連続して格納することによってリストを構成し，ポインタを用いたリストは要素と次の要素へのポインタを用いることによってリストを構成するものとする。
- ア：リストにある実際の要素数にかかわらず，リストに入れられる要素の最大個数に対応した領域を確保し，実際には使用されない領域が発生する可能性がある。
- イ：リストの中間要素を参照するには，リストの先頭から順番に要素をたどっていくことから，要素数に比例した時間が必要となる。
- ウ：リストの要素を格納する領域の他に，次の要素を指し示すための領域が別途必要となる。
- エ：リストへの挿入位置が分かる場合には，リストにある実際の要素数にかかわらず，要素の挿入を一定時間で行うことができる。
- 正解：ア
- 解説：配列は、先に決めた大きさの連続した領域を確保して使う。入れられる最大個数の分だけ確保するので、要素が少ないうちは使わない領域が出る。イ・ウ・エはどれもポインタで作ったリストの特徴。
- アの意味：正しい。配列で作るリストの短所。
- イの意味：ポインタで作ったリストの特徴。配列なら添字で、何番目でもすぐ参照できる。
- ウの意味：ポインタで作ったリストの特徴。配列は並び順そのものが次の要素を表すので、ポインタの領域は要らない。
- エの意味：ポインタで作ったリストの特徴（ポインタの付け替えだけで済む）。配列では、挿入位置より後ろの要素を全部1つずつずらすので、要素数に比例した時間がかかる。
- 出典：IPA 令和4年度春期 応用情報技術者試験 午前 問5

#### 問 ap-2-r04a-q5

- 問：自然数をキーとするデータを，ハッシュ表を用いて管理する。キーxのハッシュ関数h(x)を h(x)＝x mod n とすると，任意のキーaとbが衝突する条件はどれか。ここで，nはハッシュ表の大きさであり，x mod nはxをnで割った余りを表す。
- ア：a＋bがnの倍数
- イ：a−bがnの倍数
- ウ：nがa＋bの倍数
- エ：nがa−bの倍数
- 正解：イ
- 解説：衝突するのは a mod n ＝ b mod n のとき。a と b を n で割った余りが同じなら、差の a−b では余りが打ち消し合って n で割り切れる。例えば n＝5 で a＝12、b＝7 なら、余りはどちらも2で、差の5は5の倍数。
- アの意味：和が n の倍数になるのは、余りどうしを足すと n（または0）になるとき。n＝5、a＝1、b＝4 なら和は5だが、余りは1と4で衝突しない。
- イの意味：正しい。余りが等しい ⇔ 差が n の倍数。
- ウの意味：「n が a＋b の倍数」は a＋b が n の約数という意味で、向きが逆。余りが同じかどうかとは関係しない。
