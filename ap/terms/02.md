## 2-1 データ構造

### まとめ表

**主なデータ構造**

| 構造 | 特徴 |
| :-: | :-: |
| スタック | 後入れ先出し（LIFO）。push・pop |
| キュー | 先入れ先出し（FIFO）。enqueue・dequeue |
| リスト | ポインタで次の要素をつなぐ。挿入・削除が速い |
| 2分探索木 | 左の子＜親＜右の子。探索は平均 O(log n) |
| ヒープ | 親が子より常に大きい（小さい）完全2分木。優先度付きキューに使う |
| ハッシュ表 | キーから計算した位置に格納。探索は平均 O(1) |


### データ構造

#### 配列（Array）

- 意味：同じ型のデータを連続した場所に並べたもの
- ポイント：添字で直接アクセスできるが、途中への挿入は遅い

#### スタック（Stack）

- 意味：最後に入れたデータを最初に取り出す構造（LIFO）
- ポイント：関数呼出しの戻り先や、逆ポーランド記法の計算に使う

#### キュー（Queue）

- 意味：最初に入れたデータを最初に取り出す構造（FIFO）
- ポイント：待ち行列やバッファに使う

#### 連結リスト（Linked List）

- 意味：各要素が次の要素へのポインタを持つ構造
- ポイント：単方向・双方向・循環がある

#### 2分探索木（Binary Search Tree）

- 意味：左の部分木の値＜節の値＜右の部分木の値となる2分木
- ポイント：偏ると探索が遅くなるため、AVL木など平衡木を使う

#### 完全2分木（Complete Binary Tree）

- 意味：最下段以外がすべて埋まり、最下段は左から詰まっている2分木

#### ヒープ（Heap）

- 意味：親の値が子の値以上（または以下）になる完全2分木
- ポイント：最大値（最小値）がすぐ取り出せる

#### B木（B-tree）

- 意味：1つの節に多くのキーを持つ平衡多分木
- ポイント：ディスク上のデータベースの索引に使う

#### ハッシュ表（Hash Table）

- 意味：ハッシュ関数でキーから格納位置を決める表
- ポイント：位置がぶつかること（衝突・シノニム）への対策が必要

#### グラフ（Graph）

- 意味：頂点と辺で、ものどうしのつながりを表す構造
- ポイント：隣接行列や隣接リストで表す


### 木のなぞり方

#### 深さ優先探索（DFS / Depth-First Search）

- 意味：行けるところまで深く進み、行き止まりで戻る探索
- ポイント：前順・間順・後順のなぞり方がある

#### 幅優先探索（BFS / Breadth-First Search）

- 意味：出発点に近い頂点から順に調べる探索
- ポイント：最短の手数を求めるのに向く


### データ構造（発展）

#### レコード・構造体（Record / Structure）

- 意味：型の違うデータをひとまとめにしたもの

#### ポインタ（Pointer）

- 意味：データが置かれている場所（アドレス）を指す値

#### 双方向リスト（Doubly Linked List）

- 意味：前の要素と次の要素の両方へのポインタを持つリスト
- ポイント：前にも後ろにもたどれる

#### 循環リスト（Circular List）

- 意味：最後の要素が先頭を指し、輪になったリスト

#### 両端キュー（Deque）

- 意味：先頭と末尾の両方から出し入れできるキュー

#### 優先度付きキュー（Priority Queue）

- 意味：優先度の高いものから取り出すキュー
- ポイント：ヒープで実現する

#### 2分木（Binary Tree）

- 意味：各節が最大2つの子を持つ木

#### 根・葉・節（Root / Leaf / Node）

- 意味：木の一番上が根、子を持たないものが葉、各要素が節

#### 木の高さ（Height of Tree）

- 意味：根から最も遠い葉までの深さ
- ポイント：n個の節をもつ完全2分木の高さは約 log2 n

#### 平衡木・AVL木（Balanced Tree / AVL Tree）

- 意味：左右の高さの差が小さくなるように保つ2分探索木
- ポイント：探索は常に O(log n)

#### B+木（B+ tree）

- 意味：データを葉だけに置き、葉どうしをつないだB木
- ポイント：範囲の検索に強く、データベースの索引に使う

#### トライ木（Trie）

- 意味：文字列を1文字ずつたどる木
- ポイント：辞書の検索や入力補完に使う

#### 隣接行列・隣接リスト（Adjacency Matrix / List）

- 意味：グラフのつながりを、表で表す方法と、頂点ごとのリストで表す方法

#### 有向グラフ・無向グラフ（Directed / Undirected Graph）

- 意味：辺に向きがあるグラフとないグラフ

#### ハッシュ関数（Hash Function）

- 意味：キーから格納位置（ハッシュ値）を計算する関数
- ポイント：除算法など

#### オープンアドレス法・チェイン法（Open Addressing / Chaining）

- 意味：衝突したとき、空いた別の場所を探す方法と、同じ場所にリストでつなぐ方法

#### 静的・動的データ構造（Static / Dynamic Data Structure）

- 意味：大きさが決まっている構造（配列）と、実行中に大きさが変わる構造（リスト）


### 木のなぞり方（発展）

#### 前順・間順・後順（Preorder / Inorder / Postorder）

- 意味：前順は親→左→右、間順は左→親→右、後順は左→右→親の順になぞる


## 2-2 アルゴリズム

### まとめ表

**整列の計算量**

| 整列 | 平均 | 最悪 | 特徴 |
| :-: | :-: | :-: | :-: |
| バブルソート | O(n²) | O(n²) | 隣どうしを比べて交換 |
| 選択ソート | O(n²) | O(n²) | 最小値を選んで先頭へ |
| 挿入ソート | O(n²) | O(n²) | ほぼ整列済みなら速い |
| クイックソート | O(n log n) | O(n²) | 基準値で分けて再帰 |
| マージソート | O(n log n) | O(n log n) | 分けて併合。安定 |
| ヒープソート | O(n log n) | O(n log n) | ヒープを使う |


### 探索と整列

#### 線形探索（Linear Search）

- 意味：先頭から順に1つずつ調べる探索
- ポイント：計算量 O(n)。番兵を置くと終了判定が減る

#### 2分探索（Binary Search）

- 意味：整列済みのデータを半分に分けながら調べる探索
- ポイント：計算量 O(log n)。最大の比較回数は約 log2 n ＋1

#### クイックソート（Quick Sort）

- 意味：基準値（ピボット）より小さいグループと大きいグループに分け、再帰的に整列する
- ポイント：平均は速いが、最悪 O(n²)

#### マージソート（Merge Sort）

- 意味：データを半分ずつに分けて整列し、併合（マージ）する
- ポイント：常に O(n log n)。安定な整列

#### 安定な整列（Stable Sort）

- 意味：同じ値のデータの並び順が、整列の前後で変わらない整列

#### 計算量（Computational Complexity）

- 意味：アルゴリズムの処理の手間を、データ量nの関数で表したもの
- ポイント：O記法で表す


### いろいろなアルゴリズム

#### 再帰（Recursion）

- 意味：関数が自分自身を呼び出すこと
- ポイント：終了条件が必要。例: 階乗、ハノイの塔

#### 動的計画法（Dynamic Programming）

- 意味：小さな問題の答えを表に記録し、それを使って大きな問題を解く方法
- ポイント：同じ計算を繰り返さない

#### ダイクストラ法（Dijkstra's Algorithm）

- 意味：重みが0以上のグラフで、最短経路を求める方法
- ポイント：ネットワークの経路選択（OSPF）にも使う

#### ユークリッドの互除法（Euclidean Algorithm）

- 意味：2つの数の最大公約数を、割り算の余りを繰り返して求める方法

#### 逆ポーランド記法（後置記法 / Reverse Polish Notation）

- 意味：演算子を後ろに書く記法
- 例：(A＋B)×C は AB＋C×。スタックで計算できる


### 探索・整列（発展）

#### ハッシュ探索（Hash Search）

- 意味：ハッシュ関数で位置を計算して直接探す方法
- ポイント：衝突がなければ O(1)

#### 番兵法（Sentinel）

- 意味：探す値を配列の最後に置き、終了の判定を減らす工夫

#### バブルソート（Bubble Sort）

- 意味：隣り合う要素を比べて入れ替えることを繰り返す整列
- ポイント：O(n²)

#### 選択ソート（Selection Sort）

- 意味：残りの中から最小値を選んで、先頭と入れ替える整列
- ポイント：O(n²)

#### 挿入ソート（Insertion Sort）

- 意味：整列済みの部分の正しい位置に1つずつ挿入する整列
- ポイント：ほぼ整列済みなら速い

#### シェルソート（Shell Sort）

- 意味：一定の間隔で離れた要素どうしで挿入ソートを行い、間隔を狭めていく整列

#### ヒープソート（Heap Sort）

- 意味：ヒープを作り、最大値を取り出すことを繰り返す整列
- ポイント：O(n log n)。安定ではない

#### ビンソート・基数ソート（Bin Sort / Radix Sort）

- 意味：値ごとの箱に振り分ける整列。比較をしない

#### 分割統治法（Divide and Conquer）

- 意味：問題を小さく分けて解き、結果を合わせる方法
- ポイント：クイックソート・マージソート

#### 貪欲法（Greedy Algorithm）

- 意味：その時点で最もよいものを選び続ける方法
- ポイント：必ず最適になるとは限らない

#### バックトラック法（Backtracking）

- 意味：試して行き詰まったら1つ前に戻って別の道を試す方法
- 例：8クイーン問題

#### 文字列照合（String Matching）

- 意味：文の中から特定の文字列を探すこと
- ポイント：BM法・KMP法で効率よく探す

#### ハノイの塔（Tower of Hanoi）

- 意味：再帰で解く代表的な問題
- ポイント：n枚の円盤の移動回数は 2^n −1

#### 素数判定（Primality Test）

- 意味：ある数が素数かを調べること
- ポイント：√n まで割ってみればよい

#### 流れ図（Flowchart）

- 意味：処理の流れを記号で表した図
- ポイント：端子・処理・判断・ループ端など

#### 擬似言語（Pseudo Language）

- 意味：試験で使う、アルゴリズムを表すための言語
- ポイント：科目Bで出題される

#### 計算量の比較（Comparison of Complexity）

- 意味：線形探索 O(n)、2分探索 O(log n)、ハッシュ探索 O(1)

#### アルゴリズムの正当性（Correctness）

- 意味：正しい答えを出し、必ず終わること
- ポイント：ループ不変条件で確かめる


## 2-3 プログラミング


### プログラムの性質

#### 再入可能（リエントラント / Reentrant）

- 意味：複数のプロセスから同時に呼ばれても正しく動くプログラム
- ポイント：データをプロセスごとに分けて持つ

#### 再使用可能（Reusable）

- 意味：一度実行したあと、読み込み直さずに再び実行できるプログラム

#### 再帰的（Recursive）

- 意味：実行中に自分自身を呼び出せるプログラム

#### 再配置可能（Relocatable）

- 意味：主記憶のどこに置いても実行できるプログラム

#### コーディング規約（Coding Standards）

- 意味：プログラムの書き方をそろえるための決まり
- ポイント：読みやすさと保守のしやすさを上げる


### プログラムの作り方（発展）

#### 構造化プログラミング（Structured Programming）

- 意味：順次・選択・繰返しの3つの基本構造だけでプログラムを作る方法
- ポイント：GOTO文を使わない

#### 変数のスコープ（Scope）

- 意味：変数を使える範囲
- ポイント：大域変数（どこでも）と局所変数（関数の中だけ）

#### 値渡し・参照渡し（Call by Value / Call by Reference）

- 意味：値渡しは値のコピーを渡す、参照渡しは場所を渡すので呼ばれた側の変更が呼んだ側にも反映される

#### 例外処理（Exception Handling）

- 意味：実行中のエラーを捕まえて、決めた処理を行うこと
- ポイント：try〜catch

#### 再帰呼出し（Recursive Call）

- 意味：関数が自分自身を呼ぶこと
- ポイント：スタックで戻り先を管理する

#### コメント（Comment）

- 意味：プログラムの中に書く説明文
- ポイント：実行には影響しない

#### デバッグ（Debugging）

- 意味：プログラムの誤り（バグ）を見つけて直すこと

#### 単体テスト用のアサーション（Assertion）

- 意味：ある時点で成り立つべき条件をプログラムに書いて確かめるもの


## 2-4 プログラム言語


### 言語の種類

#### 手続型言語（Procedural Language）

- 意味：処理の手順を順に書いていく言語
- 例：C、COBOL

#### オブジェクト指向言語（Object-Oriented Language）

- 意味：データと処理をまとめたオブジェクトを組み合わせて作る言語
- 例：Java、C++、Python

#### 関数型言語（Functional Language）

- 意味：関数の組合せでプログラムを作る言語
- ポイント：副作用を避ける。例: Haskell

#### 論理型言語（Logic Programming Language）

- 意味：事実と規則を書き、問合せに答えを推論させる言語
- 例：Prolog

#### スクリプト言語（Script Language）

- 意味：コンパイルせずにインタプリタで手軽に実行できる言語
- 例：JavaScript、Python


### 言語（発展）

#### 機械語（Machine Language）

- 意味：CPUが直接実行できる0と1の命令

#### アセンブリ言語（Assembly Language）

- 意味：機械語の命令を記号で表した言語
- ポイント：アセンブラで機械語に変える

#### 高水準言語（High-level Language）

- 意味：人が読みやすい形で書ける言語

#### C言語（C Language）

- 意味：OSや組込みに使われる手続型言語
- ポイント：ポインタで直接メモリを扱える

#### Java（ジャバ）

- 意味：オブジェクト指向の言語
- ポイント：バイトコードを仮想マシン（JVM）で動かすので、OSに依存しにくい

#### Python（パイソン）

- 意味：読みやすい文法のスクリプト言語
- ポイント：AIやデータ分析で広く使う

#### JavaScript（ジャバスクリプト）

- 意味：Webブラウザで動くスクリプト言語
- ポイント：画面に動きを付ける。サーバ側でも使える

#### 静的型付け・動的型付け（Static / Dynamic Typing）

- 意味：変数の型を実行前に決める言語と、実行中に決まる言語

#### ガーベジコレクション（Garbage Collection）

- 意味：使われなくなったメモリを自動で解放するしくみ

#### コンパイル方式・インタプリタ方式（Compile / Interpret）

- 意味：まとめて機械語にしてから実行する方式と、1行ずつ解釈して実行する方式


## 2-5 その他の言語


### マークアップとデータ

#### HTML（えいちてぃーえむえる / HyperText Markup Language）

- 意味：Webページの構造をタグで書く言語
- 語の意味：HyperText＝リンクでつながる文書／Markup＝目印をつける／Language＝言語

#### XML（えっくすえむえる / Extensible Markup Language）

- 意味：利用者が自由にタグを決められるマークアップ言語
- ポイント：データ交換に使う。DTDやXML Schemaで構造を定める
- 語の意味：Extensible＝拡張できる／Markup＝目印付け／Language＝言語

#### JSON（じぇいそん / JavaScript Object Notation）

- 意味：「名前：値」の組でデータを表す軽い形式
- ポイント：Web APIのデータのやり取りで多く使う
- 語の意味：JavaScript＝言語名／Object＝もの／Notation＝表記法

#### CSS（しーえすえす / Cascading Style Sheets）

- 意味：Webページの見た目（色・配置など）を指定する言語
- 語の意味：Cascading＝段階的に重なる／Style Sheets＝書式の指定

#### UML（ゆーえむえる / Unified Modeling Language）

- 意味：オブジェクト指向の設計を図で表す標準の書き方
- 語の意味：Unified＝統一された／Modeling＝モデルを描く／Language＝言語


### データ・記述言語（発展）

#### DTD・XML Schema（Document Type Definition）

- 意味：XML文書の構造（使える要素や順番）を定義するもの

#### YAML（やむる）

- 意味：字下げで構造を表す、読みやすいデータの書き方
- ポイント：設定ファイルによく使う

#### CSV（しーえすぶい / Comma-Separated Values）

- 意味：値をカンマで区切った表の形式
- 語の意味：Comma＝カンマ／Separated＝区切られた／Values＝値

#### SQL（えすきゅーえる / Structured Query Language）

- 意味：関係データベースを操作する言語

#### Markdown（マークダウン）

- 意味：記号で見出しや箇条書きを書く、軽いマークアップの書き方

#### DOM（どむ / Document Object Model）

- 意味：HTMLやXMLの文書を木構造として扱い、プログラムから操作するしくみ
- 語の意味：Document＝文書／Object＝もの／Model＝模型

#### Ajax（えいじゃっくす）

- 意味：ページ全体を読み込み直さずに、裏でサーバとデータをやり取りする技術

#### SVG（えすぶいじー / Scalable Vector Graphics）

- 意味：XMLで図形を書くベクタ画像の形式
- 語の意味：Scalable＝拡大縮小できる／Vector＝ベクタ／Graphics＝画像


## 問題演習

- 書式：「#### 問 問題ID」の下に、問・ア〜エ・正解・解説を書く。「###」は小分類（クイズの範囲に使う）

### 2-1 データ構造

#### 問 ap-2-q01

- 問：後入れ先出し（LIFO）でデータを扱う構造はどれか。
- ア：キュー
- イ：スタック
- ウ：連結リスト
- エ：ハッシュ表
- 正解：イ
- 解説：最後に入れたものを最初に出すのはスタック。

#### 問 ap-2-q02

- 問：2分探索木を間順（中間順）でなぞったときの特徴として正しいものはどれか。
- ア：値が昇順に並ぶ
- イ：根が最初に出る
- ウ：葉だけが出る
- エ：深さの順に並ぶ
- 正解：ア

### 2-2 アルゴリズム

#### 問 ap-2-q04

- ア：10
- イ：100
- ウ：500
- エ：1,000
- 正解：ア
- 解説：log2 1000 ≒ 10。2分探索は O(log n)。

#### 問 ap-2-q05

- イ：ヒープソート
- ウ：マージソート
- エ：選択ソート
- 正解：ウ
- 解説：マージソートは常に O(n log n) で安定。ヒープソートは安定ではない。

#### 問 ap-2-q06

- イ：A＋B×C−D
- ウ：AB＋×CD−
- エ：＋AB×−CD
- 正解：ア
- 解説：演算子を後ろに書くと AB＋ と CD− を × でつなぐ。

#### 問 ap-2-q07

- ウ：2分探索
- エ：ハフマン法
- 正解：ア

#### 問 ap-2-q13

#### 問 ap-2-q14

#### 問 ap-2-q15

#### 問 ap-2-q20
