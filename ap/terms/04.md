## 4-1 システムの構成

### まとめ表

**クラウドのサービスの形**

| 形 | 事業者が用意する範囲 |
| :-: | :-: |
| IaaS | サーバ・ストレージ・ネットワーク |
| PaaS | ＋OS・ミドルウェア・実行環境 |
| SaaS | ＋アプリケーション |

**RAIDの種類**

| RAID | 方式 | 特徴 |
| :-: | :-: | :-: |
| RAID0 | ストライピング | 速いが冗長性なし |
| RAID1 | ミラーリング | 同じ内容を2台に書く |
| RAID5 | 分散パリティ | 1台壊れても復元できる |
| RAID6 | 二重パリティ | 2台壊れても復元できる |


### 処理の形と構成

#### クライアントサーバシステム（Client Server System）

- 意味：依頼する側（クライアント）と処理する側（サーバ）に役割を分けたシステム

#### 3層クライアントサーバ（3-tier Client Server）

- 意味：プレゼンテーション層・ファンクション層（アプリケーション）・データベース層の3つに分けた構成
- ポイント：層ごとに変更しやすい

#### デュプレックスシステム（Duplex System）

- 意味：主系と待機系の2つを用意し、主系が故障したら待機系に切り替える構成
- ポイント：ホットスタンバイ（待機系を動かしておく）とコールドスタンバイがある

#### デュアルシステム（Dual System）

- 意味：2つのシステムで同じ処理を同時に行い、結果を照合する構成
- ポイント：信頼性が高い

#### クラスタ構成（Cluster）

- 意味：複数のサーバをまとめて1つのシステムのように動かす構成
- ポイント：HAクラスタ（可用性）と負荷分散クラスタがある

#### ロードバランサ（Load Balancer）

- 意味：複数のサーバに処理を振り分ける装置

#### スケールアウト・スケールアップ（Scale-out / Scale-up）

- 意味：スケールアウトはサーバの台数を増やすこと、スケールアップはサーバ1台の性能を上げること

#### 仮想化（Virtualization）

- 意味：1台の物理サーバの上で、複数の仮想的なサーバを動かす技術
- ポイント：ハイパーバイザ型・ホスト型・コンテナ型がある

#### コンテナ型仮想化（Container）

- 意味：OSのカーネルを共有し、アプリの実行環境だけを分ける仮想化
- ポイント：軽くて起動が速い

#### ライブマイグレーション（Live Migration）

- 意味：動いている仮想マシンを、止めずに別の物理サーバに移すこと

#### RAID（れいど / Redundant Arrays of Independent Disks）

- 意味：複数のディスクを組み合わせ、速さや信頼性を高める技術
- 語の意味：Redundant＝冗長な／Arrays＝並び／Independent＝独立した／Disks＝ディスク

#### NAS・SAN（Network Attached Storage / Storage Area Network）

- 意味：NASはLANにつなぐファイルサーバ型の記憶装置、SANはサーバと記憶装置を専用のネットワークでつなぐ方式
- 語の意味：Attached＝接続された／Storage＝記憶装置／Area＝領域

#### IaaS・PaaS・SaaS（Infrastructure / Platform / Software as a Service）

- 意味：クラウドで提供される範囲の違い
- 語の意味：Infrastructure＝基盤／Platform＝土台／Software＝ソフトウェア／as a Service＝サービスとして

#### エッジコンピューティング（Edge Computing）

- 意味：端末の近くでデータを処理し、遅れや通信量を減らす考え方


### 処理形態（発展）

#### 集中処理・分散処理（Centralized / Distributed Processing）

- 意味：1台のコンピュータでまとめて処理する方式と、複数のコンピュータで分担する方式

#### 垂直分散・水平分散（Vertical / Horizontal Distribution）

- 意味：役割の違うコンピュータで階層的に分担するのが垂直分散、同じ役割のコンピュータを並べて分担するのが水平分散

#### バッチ処理（Batch Processing）

- 意味：データをためておき、まとめて一度に処理する方式
- 例：月末の給与計算

#### オンライントランザクション処理（OLTP）

- 意味：端末からの要求をその場で処理する方式

#### リアルタイム処理（Real-time Processing）

- 意味：決められた時間内に処理を終える方式

#### シンクライアント（Thin Client）

- 意味：端末には最小限の機能だけを持たせ、処理やデータをサーバに置く方式
- ポイント：情報漏えい対策になる

#### VDI（ぶいでぃーあい / Virtual Desktop Infrastructure）

- 意味：サーバ上の仮想マシンでデスクトップを動かし、端末には画面だけを送るしくみ
- 語の意味：Virtual＝仮想の／Desktop＝デスクトップ／Infrastructure＝基盤

#### P2P（ぴあつーぴあ / Peer to Peer）

- 意味：端末どうしが対等な立場で直接やり取りする方式
- 語の意味：Peer＝対等な相手

#### Webシステム（Web System）

- 意味：ブラウザを使ってサーバの機能を利用するシステム
- ポイント：Webサーバ・APサーバ・DBサーバの3層が多い

#### ストアドプロシージャの利用（Stored Procedure）

- 意味：DBサーバに処理を置き、通信の回数を減らすこと

#### グリッドコンピューティング（Grid Computing）

- 意味：ネットでつながった多くのコンピュータの力を合わせて、大きな計算を行うこと

#### HPC（えいちぴーしー / High Performance Computing）

- 意味：高速な計算を行うスーパーコンピュータなどの技術
- 語の意味：High Performance＝高性能な／Computing＝計算


### 高信頼化の構成（発展）

#### シンプレックスシステム（Simplex System）

- 意味：予備を持たない1系統だけのシステム

#### フェールオーバ（Failover）

- 意味：障害が起きたとき、自動で待機系に切り替わること
- ポイント：元に戻すのはフェールバック

#### ウォームスタンバイ（Warm Standby）

- 意味：待機系を起動はしているが、すぐには業務を引き継げない状態で待たせる方式

#### 負荷分散（Load Balancing）

- 意味：処理を複数のサーバに振り分けて、1台に集中しないようにすること

#### 単一障害点（SPOF / Single Point of Failure）

- 意味：そこが壊れるとシステム全体が止まってしまう部分
- ポイント：冗長化してなくす

#### ミラーリング（Mirroring）

- 意味：同じデータを2台以上のディスクに書くこと（RAID1）

#### ストライピング（Striping）

- 意味：データを複数のディスクに分けて書き、速くすること（RAID0）

#### RAID10（RAID 1+0）

- 意味：ミラーリングしたものをストライピングする構成
- ポイント：速くて信頼性も高いが、使える容量は半分

#### ホットスペア（Hot Spare）

- 意味：故障したディスクの代わりに、自動で組み込まれる予備のディスク


### 仮想化とクラウド（発展）

#### ハイパーバイザ型（Hypervisor）

- 意味：ハードウェアの上で直接ハイパーバイザが動き、その上で複数のゲストOSを動かす方式

#### ホスト型仮想化（Hosted Virtualization）

- 意味：ホストOSの上で仮想化ソフトを動かす方式
- ポイント：手軽だがオーバヘッドが大きい

#### オーケストレーション（Orchestration）

- 意味：多くのコンテナや仮想マシンの配置・起動・管理を自動で行うこと
- 例：Kubernetes

#### サーバレス（Serverless）

- 意味：サーバを意識せず、関数（コード）だけを置いて実行するクラウドのしくみ
- ポイント：使った分だけ料金がかかる

#### マイクロサービス（Microservices）

- 意味：システムを小さな独立したサービスに分け、APIでつなぐ構成
- ポイント：個別に変更・拡張しやすい

#### パブリッククラウド・プライベートクラウド（Public / Private Cloud）

- 意味：多くの利用者で共有するクラウドと、1つの組織専用のクラウド
- ポイント：組み合わせるとハイブリッドクラウド

#### マルチクラウド（Multi-cloud）

- 意味：複数のクラウド事業者のサービスを使い分けること

#### オートスケーリング（Auto Scaling）

- 意味：負荷に合わせてサーバの台数を自動で増減させること

#### ストレージ仮想化（Storage Virtualization）

- 意味：複数の記憶装置を1つにまとめて見せる技術
- ポイント：シンプロビジョニングで実際より大きな容量を割り当てられる

#### オブジェクトストレージ（Object Storage）

- 意味：データをIDとメタデータ付きのオブジェクトとして保存する記憶方式
- ポイント：大容量のデータに向く

#### iSCSI（あいすかじー / Internet SCSI）

- 意味：SCSIの命令をIPネットワークで送り、SANを作る方式

#### データセンタ（Data Center）

- 意味：サーバやネットワーク機器を集めて運用する専用の施設


### システムの形

#### メインフレーム（Mainframe）

- 意味：大企業や銀行の基幹業務に使う大型の汎用コンピュータ

#### 組込み型の構成（Embedded Configuration）

- 意味：機器の中にコンピュータを組み込み、特定の制御を行う構成

#### 3層アーキテクチャの各層（Three-tier Layers）

- 意味：プレゼンテーション層（画面）・ファンクション層（業務処理）・データ層（データベース）

#### Webサーバ・APサーバ・DBサーバ（Web / Application / Database Server）

- 意味：画面のやり取り、業務の処理、データの管理をそれぞれ受け持つサーバ

#### リバースプロキシ（Reverse Proxy）

- 意味：サーバの前に置き、外からの要求を受けて中のサーバに振り分けるサーバ

#### キャッシュサーバ（Cache Server）

- 意味：よく使うデータを手元に持ち、応答を速くするサーバ

#### ハイブリッドクラウド（Hybrid Cloud）

- 意味：オンプレミスやプライベートクラウドと、パブリッククラウドを組み合わせて使う形

#### IaC（Infrastructure as Code）

- 意味：サーバなどの構成をコードで書き、自動で構築できるようにすること

#### BCPのための構成（DR / Disaster Recovery）

- 意味：災害に備えて、離れた場所に予備のシステムやデータを置くこと
- ポイント：ホットサイト・ウォームサイト・コールドサイト

#### バックアップサイト（Backup Site）

- 意味：災害時に業務を引き継ぐための予備の拠点
- ポイント：すぐ切り替えられるホットサイトほど費用が高い

#### レプリケーション（Replication）

- 意味：データを別の場所に複製し続けること
- ポイント：同期型はデータが失われにくいが遅くなる

#### スナップショット（Snapshot）

- 意味：ある時点のデータの状態を、すばやく丸ごと記録すること

#### ストレージ階層化（Storage Tiering）

- 意味：よく使うデータは速い装置に、あまり使わないデータは安い装置に置くこと

#### 仮想マシンの集約（Server Consolidation）

- 意味：多くの物理サーバを、少ない台数の上の仮想マシンにまとめること
- ポイント：費用や電力を減らせる

#### コンテナイメージ（Container Image）

- 意味：アプリと必要なライブラリをまとめた、コンテナの元になるファイル

#### エッジサーバ（Edge Server）

- 意味：利用者や機器の近くに置いて処理を行うサーバ

#### 冗長電源（Redundant Power Supply）

- 意味：電源装置を2つ以上持たせ、1つが壊れても動き続けるようにしたもの

#### ネットワークの冗長化（Network Redundancy）

- 意味：回線や機器を二重にして、片方が止まっても通信できるようにすること


## 4-2 システムの評価指標

### まとめ表

**稼働率の計算**

| 構成 | 稼働率 |
| :-: | :-: |
| 1台 | MTBF ÷（MTBF ＋ MTTR） |
| 直列 | A × B |
| 並列 | 1 −（1 − A）×（1 − B） |


### 性能

#### スループット（Throughput）

- 意味：単位時間あたりに処理できる仕事の量

#### レスポンスタイム（Response Time）

- 意味：要求を出し終えてから、最初の応答が返ってくるまでの時間

#### ターンアラウンドタイム（Turnaround Time）

- 意味：仕事を出してから、結果をすべて受け取るまでの時間

#### ベンチマーク（Benchmark）

- 意味：決まったプログラムを動かして性能を比べる方法
- ポイント：SPECやTPCがある

#### キャパシティプランニング（Capacity Planning）

- 意味：将来の負荷を予測し、必要な性能や台数を計画すること


### 信頼性

#### RASIS（らしす）

- 意味：信頼性を評価する5つの観点
- 語の意味：Reliability＝信頼性／Availability＝可用性／Serviceability＝保守性／Integrity＝完全性／Security＝安全性

#### MTBF（えむてぃーびーえふ / Mean Time Between Failures）

- 意味：故障から次の故障までの平均の時間（平均故障間隔）。長いほど信頼性が高い
- 語の意味：Mean＝平均の／Time Between＝間の時間／Failures＝故障

#### MTTR（えむてぃーてぃーあーる / Mean Time To Repair）

- 意味：故障してから直るまでの平均の時間（平均修復時間）。短いほど保守性が高い
- 語の意味：Mean＝平均の／Time To＝〜までの時間／Repair＝修理

#### 稼働率（Availability）

- 意味：システムが使える状態にある時間の割合
- ポイント：MTBF÷(MTBF＋MTTR)

#### バスタブ曲線（Bathtub Curve）

- 意味：故障率が時間とともに「初期故障期→偶発故障期→摩耗故障期」と変わる様子を表した曲線

#### フォールトトレラント（Fault Tolerant）

- 意味：故障が起きても、システム全体としては機能を続ける考え方
- ポイント：フェールセーフ・フェールソフト・フールプルーフなどの設計がある

#### フェールセーフ（Fail Safe）

- 意味：故障したとき、安全な側に止まるようにする設計
- 例：故障したら信号を赤にする

#### フェールソフト（Fail Soft）

- 意味：故障した部分を切り離し、機能を落としてでも動き続ける設計

#### フールプルーフ（Fool Proof）

- 意味：人が誤った操作をしても、危険にならないようにする設計


### 性能（発展）

#### TPC（Transaction Processing Performance Council）

- 意味：トランザクション処理の性能を測るベンチマークを決める団体

#### SPEC（Standard Performance Evaluation Corporation）

- 意味：CPUなどの性能を測るベンチマークを決める団体

#### モニタリング（Monitoring）

- 意味：動いているシステムの資源の使い方や性能を、測り続けること

#### ボトルネック（Bottleneck）

- 意味：全体の性能を下げている、いちばん遅い部分

#### 性能評価のシミュレーション（Simulation）

- 意味：模型を使って、負荷がかかったときの性能を予測すること

#### 応答時間の計算（Response Time Calculation）

- 意味：待ち時間＋処理時間
- ポイント：待ち行列理論で求める


### 信頼性（発展）

#### 故障率（Failure Rate）

- 意味：単位時間あたりに故障する割合
- ポイント：1 ÷ MTBF

#### アベイラビリティの計算（Availability）

- 意味：2台のうちどちらか1台動けばよい並列は 1−(1−A)²、両方必要な直列は A²

#### 複合系の稼働率（Combined Systems）

- 意味：直列と並列を組み合わせた構成は、内側から順に計算する

#### フォールトアボイダンス（Fault Avoidance）

- 意味：品質の高い部品を使うなどして、故障そのものを起こさないようにする考え方

#### フォールトマスキング（Fault Masking）

- 意味：故障が起きても、多数決などで影響を外に見せないようにすること

#### 冗長化（Redundancy）

- 意味：予備を持たせて、一部が壊れても動き続けるようにすること

#### 保守性（Serviceability）

- 意味：故障したときに直しやすい性質
- ポイント：MTTRが短いほど保守性が高い

#### 予防保守（Preventive Maintenance）

- 意味：故障が起きる前に点検や部品の交換をすること
- ポイント：MTBFを延ばす

#### 遠隔保守（Remote Maintenance）

- 意味：ネットワークを通じて離れた場所から保守を行うこと
- ポイント：MTTRを短くする

#### 初期故障期・偶発故障期・摩耗故障期（Early / Random / Wear-out Failure）

- 意味：バスタブ曲線の3つの時期
- ポイント：初期は製造時の不良、偶発は故障率が一定、摩耗は劣化で増える

#### TCO（てぃーしーおー / Total Cost of Ownership）

- 意味：システムの導入から運用・廃棄までにかかる費用の合計
- ポイント：初期費用と運用費用の両方を考える
- 語の意味：Total＝合計の／Cost＝費用／Ownership＝所有

#### 初期コスト・ランニングコスト（Initial / Running Cost）

- 意味：導入するときにかかる費用と、運用し続けるのにかかる費用

#### 経済性の評価（Economic Evaluation）

- 意味：投資に見合う効果があるかを、TCOやROIで評価すること

#### 信頼性ブロック図（Reliability Block Diagram）

- 意味：装置の直列・並列のつながりを図で表し、稼働率を計算するための図

#### MTBSI・MTRS（Mean Time Between Service Incidents / Mean Time to Restore Service）

- 意味：サービスとして見た、障害の間隔の平均と、復旧までの時間の平均


## 問題演習

- 書式：「#### 問 問題ID」の下に、問・ア〜エ・正解・解説を書く。「###」は小分類（クイズの範囲に使う）

### 4-1 システムの構成

#### 問 ap-4-q01

- 問：4台のディスクでRAID5を構成したとき、1台500GBなら実際に使える容量はどれか。
- ア：500GB
- イ：1,000GB
- ウ：1,500GB
- エ：2,000GB
- 正解：ウ
- 解説：RAID5は1台分をパリティに使うので (4−1)×500＝1,500GB。

#### 問 ap-4-q02

- 問：待機系を起動した状態で待たせておき、障害時にすぐ切り替える方式はどれか。
- ア：コールドスタンバイ
- イ：ホットスタンバイ
- ウ：デュアルシステム
- エ：シンプレックス
- 正解：イ
- 解説：待機系を動かしておくのはホットスタンバイ。

#### 問 ap-4-q03

- 問：OSのカーネルを共有し、アプリケーションの実行環境を分離する仮想化はどれか。
- ア：ハイパーバイザ型

### 4-2 システムの評価指標

#### 問 ap-4-q05

- 問：MTBFが450時間、MTTRが50時間の装置の稼働率はどれか。
- ア：0.8
- イ：0.85
- ウ：0.9
- エ：0.95
- 正解：ウ
- 解説：450÷(450＋50)＝0.9。

#### 問 ap-4-q06

- 問：稼働率0.9の装置を2台並列につないだシステムの稼働率はどれか。
- ア：0.81
- イ：0.9
- ウ：0.95
- エ：0.99
- 正解：エ
- 解説：1−(1−0.9)×(1−0.9)＝0.99。

#### 問 ap-4-q07

- エ：0.99

- 解説：0.9×0.9＝0.81。直列は両方動く必要がある。
