## 4-1 システムの構成

### まとめ表

**冗長化の方式（R4春 問13・R5秋 問15 の論点）**

| 方式 | 系の数 | 動き方 | 押さえどころ |
| :-: | :-: | :-: | :-: |
| シンプレックス | 1 | 1系統だけで処理 | 安いが、壊れたら止まる |
| デュアル | 2 | 2系統が同じ処理をして結果を照合 | 信頼性は最も高いが、高価 |
| デュプレックス | 2 | 現用系が処理し、待機系は控える | 切替えの間だけ止まる |
| ロードシェアリング | 2以上 | 全部の系で処理を分け合う | 1台が止まっても残りで処理を続ける |

**待機系の待ち方とバックアップサイト（R4春 問13の論点）**

| 待機系・拠点 | 待っている状態 | 切替えにかかる時間 |
| :-: | :-: | :-: |
| ホットスタンバイ／ホットサイト | 電源が入り、同じ業務プログラムが動いて、データも同期している | 短い（数秒〜数分） |
| ウォームスタンバイ／ウォームサイト | 機器は動いているが、業務プログラムやデータを準備する必要がある | 中くらい |
| コールドスタンバイ／コールドサイト | 機器や場所だけ用意し、電源も入っていない | 長い（数時間〜数日） |

**仮想化の方式（R3秋 問14・R4秋 問12の論点）**

| 方式 | 仮想化ソフトの置き場所 | ゲストOS | 押さえどころ |
| :-: | :-: | :-: | :-: |
| ホスト型 | ホストOSの上 | ある | 手軽だが、ホストOSを経由するぶん遅い |
| ハイパーバイザー型 | 物理サーバの上に直接（ホストOSなし） | ある | ホストOSを経由しないので速い |
| コンテナ型 | ホストOSの上のコンテナエンジン | ない（ホストOSのカーネルを共有） | 軽く、すぐ起動する。別の種類のOSは動かせない |

**クラウドのサービスモデル（利用者が自分で用意・管理する範囲）**

| モデル | 事業者が提供するもの | 利用者が用意するもの |
| :-: | :-: | :-: |
| IaaS | サーバ・ストレージ・ネットワーク（仮想マシン） | OS・ミドルウェア・アプリケーション |
| PaaS | IaaSの範囲＋OS・ミドルウェア・実行環境 | アプリケーション |
| SaaS | アプリケーションまで全部 | データと設定だけ |
| FaaS | 関数を動かす実行環境（イベントが来たときだけ起動） | 関数（プログラムの断片） |

- 密結合・疎結合マルチプロセッサ、SMP、タンデム結合、アレイプロセッサ、超並列は #3 コンピュータ構成要素の「マルチプロセッサの構成」にまとめた（R3春 問15・R6春 問14 の問題は #4 の問題演習に入れた）

### 集中と分散

#### 集中処理システム（しゅうちゅうしょりしすてむ / Centralized Processing System）

- 意味：1台の大型コンピュータ（ホスト）に処理とデータをまとめ、端末はそこにつないで使う形態
- ポイント：管理や保守を1か所で行えて、データの一貫性も保ちやすい。ホストが止まると全部止まる
- 語の意味：Centralized＝1か所に集めた／Processing＝処理

#### 分散処理システム（ぶんさんしょりしすてむ / Distributed Processing System）

- 意味：ネットワークでつないだ複数のコンピュータに、処理やデータを分けて受け持たせる形態
- ポイント：1台が止まっても全体は止まりにくく、少しずつ増設できる。そのかわり管理する場所が増え、データの一貫性を保つのが難しい
- 語の意味：Distributed＝分散した

#### 垂直機能分散システム（すいちょくきのうぶんさんしすてむ / Vertical Function Distribution）

- 意味：ホスト・部門サーバ・端末のように上下の階層をつくり、階層ごとに違う機能を受け持たせる分散の形
- ポイント：上位ほど全体にかかわる処理、下位ほど身近な処理を受け持つ。クライアントサーバシステムもこの一種

#### 水平機能分散システム（すいへいきのうぶんさんしすてむ / Horizontal Function Distribution）

- 意味：対等な立場の複数のコンピュータが、それぞれ違う機能（受注・在庫・会計など）を受け持つ分散の形
- ポイント：上下関係はないが、機能ごとに担当が決まっている。担当の1台が止まると、その機能だけ使えなくなる

#### 水平負荷分散システム（すいへいふかぶんさんしすてむ / Horizontal Load Distribution）

- 意味：同じ機能をもつ対等な複数のコンピュータに、同じ種類の処理を振り分けて負荷を分け合う形
- ポイント：機能で分けるのではなく、量で分ける。台数を増やせば処理できる量が増える（スケールアウト）

### 分散のよしあしを見る観点

#### コスト性能比（こすとせいのうひ / Cost Performance Ratio）

- 意味：同じ費用でどれだけの性能を得られるか（性能÷費用）という比べ方
- ポイント：かつては大型機1台にまとめたほうが有利だったが、安い小型機を並べる分散処理のほうが有利になった。クライアントサーバシステムの長所としても挙がる

#### 保守要員の集中化（ほしゅよういんのしゅうちゅうか / Centralization of Maintenance Staff）

- 意味：機器が1か所にあるので、運用や保守をする人を1か所にまとめて置けること
- ポイント：集中処理の長所。分散処理では、拠点ごとに保守の人や手順が必要になる

#### 情報資源の組織への対応性（じょうほうしげんのそしきへのたいおうせい / Fitness to Organization）

- 意味：部門ごとに必要なデータや機器を部門の近くに置き、組織の形に合わせてシステムを組めること
- ポイント：分散処理の長所。組織が変わったときにも、その部門の部分だけ変えればよい

#### 管理責任（かんりせきにん / Management Responsibility）

- 意味：機器・データ・セキュリティを誰が管理し、障害のときに誰が対応するかという責任の所在
- ポイント：分散処理やクライアントサーバでは、管理する場所が部門に散らばるので、責任があいまいになりやすい

#### 分散アーキテクチャ（ぶんさんあーきてくちゃ / Distributed Architecture）

- 意味：処理・データ・機器を、ネットワーク上のどこに、どう分けて置くかというシステム全体の設計の考え方
- ポイント：集中か分散か、垂直か水平か、機能で分けるか負荷で分けるか、といった選び方の総称
- 語の意味：Architecture＝全体の構造・設計

#### 機能配分（きのうはいぶん / Function Allocation）

- 意味：システムを構成する各コンピュータ（ホスト・サーバ・クライアントなど）に、どの機能を受け持たせるか決めること
- ポイント：ネットワークを流れるデータ量や応答の速さ、保守のしやすさを考えて決める

### 利用形態

#### バッチ処理（ばっちしょり / Batch Processing）

- 意味：データを一定期間や一定量ためておき、まとめて一度に処理する形態
- ポイント：給与計算や月末の集計など、すぐに結果がいらない大量の処理に向く。夜間に行うことが多い
- 語の意味：Batch＝ひとまとまり

#### リアルタイム処理（りあるたいむしょり / Real-time Processing）

- 意味：データが発生したら、決められた時間内にすぐ処理して結果を返す形態
- ポイント：座席予約や銀行のATM、機械の制御など、待たせられない処理に向く

#### 対話型処理（たいわがたしょり / Interactive Processing）

- 意味：利用者が画面で入力し、コンピュータが応答を返す、というやり取りを繰り返しながら進める形態
- ポイント：会話型処理とも呼ぶ。応答の速さ（レスポンスタイム）が使い心地を決める

#### オンライントランザクション処理（おんらいんとらんざくしょんしょり / Online Transaction Processing）

- 意味：端末から送られた取引（トランザクション）を、通信回線を通じてその場で1件ずつ処理する形態
- ポイント：OLTPと略す。大量の短い取引を、データの一貫性を保ちながら素早く処理する
- 語の意味：Online＝回線でつながった／Transaction＝ひとまとまりの取引

### 冗長化の方式

#### シンプレックスシステム（しんぷれっくすしすてむ / Simplex System）

- 意味：予備をもたず、1系統の装置だけで処理を行うシステム構成
- ポイント：最も安いが、どこか1か所壊れるとシステム全体が止まる
- 語の意味：Simplex＝単一の

#### デュアルシステム（でゅあるしすてむ / Dual System）

- 意味：2系統の装置で同じ処理を同時に行い、結果を照合しながら動かすシステム構成
- ポイント：片方が壊れても、もう片方がそのまま処理を続けるので切替えの時間がない。信頼性は高いが費用も高い
- 語の意味：Dual＝二つの

#### デュプレックスシステム（でゅぷれっくすしすてむ / Duplex System）

- 意味：2系統の装置を用意し、ふだんは片方（現用系）で処理して、もう片方（待機系）は障害に備えて控えるシステム構成。アクティブ-スタンバイ構成とも呼ぶ
- ポイント：現用系が止まると待機系に切り替える。照合はしないので、切り替える間は処理が止まる
- 語の意味：Duplex＝二重の

#### ロードシェアリングシステム（ろーどしぇありんぐしすてむ / Load Sharing System）

- 意味：複数の装置に処理を分けて受け持たせ、全部の装置を同時に使うシステム構成。アクティブ-アクティブ構成とも呼ぶ
- ポイント：ふだんは負荷を分け合い、1台が止まったら残りの装置で処理を続ける。待機するだけの装置がない
- 語の意味：Load＝負荷／Sharing＝分け合うこと

#### アクティブ-スタンバイ構成（あくてぃぶすたんばいこうせい / Active-Standby Configuration）

- 意味：2台のうち1台（アクティブ）だけが処理を行い、もう1台（スタンバイ）は障害に備えて待つ構成。デュプレックスシステムと同じ考え方
- ポイント：サーバのクラスタでよく使う呼び方。切替え（フェールオーバ）の間はサービスが止まる
- 例：R5秋 問15（各サーバのMTBF 99時間、フェールオーバに2時間→システムの稼働率は約0.98）

#### アクティブ-アクティブ構成（あくてぃぶあくてぃぶこうせい / Active-Active Configuration）

- 意味：2台以上が全部同時に動いて処理を分け合い、1台が止まったら残りが処理を続ける構成。ロードシェアリングシステムと同じ考え方
- ポイント：ふだんから負荷を分け合うので、待機するだけの機械がない。1台が止まると残りの台の負荷が増える

### 現用系と待機系

#### 主系（しゅけい / Primary System）

- 意味：ふだん実際に業務の処理を行っている側の系統。現用系とも呼ぶ
- ポイント：障害が起きると、処理を待機系に引き継ぐ

#### 従系（じゅうけい / Secondary System）

- 意味：主系に障害が起きたときに処理を引き継ぐため、控えている側の系統。待機系とも呼ぶ
- ポイント：ふだんの使い方（電源を入れておくか、データを同期しておくか）で、切替えにかかる時間が変わる

#### フェールオーバ（ふぇーるおーば / Failover）

- 意味：現用系に障害が起きたとき、処理を自動的に待機系に引き継ぐこと
- ポイント：切替えの間はサービスが止まるので、その時間（フェールオーバ時間）が稼働率の計算に入ることがある
- 例：R5秋 問15（MTBF 99時間、フェールオーバに2時間かかるアクティブ-スタンバイ構成の稼働率→99÷101≒0.98）
- 語の意味：Fail＝故障する／Over＝引き渡して

#### フェールバック（ふぇーるばっく / Failback）

- 意味：障害を直した元の現用系に、待機系から処理を戻すこと
- ポイント：引き継ぐ方向がフェールオーバの逆

#### ハートビート（はーとびーと / Heartbeat）

- 意味：現用系が「動いている」ことを知らせるために、待機系へ一定の間隔で送り続ける信号
- ポイント：これが途切れたら、待機系は現用系に障害が起きたと判断して処理を引き継ぐ
- 例：R4春 問13（ホットスタンバイで切り替わる契機→現用系から定期的に送られるメッセージが途切れたとき）
- 語の意味：Heartbeat＝心臓の鼓動

### 待機系の待ち方

#### ホットスタンバイ（ほっとすたんばい / Hot Standby）

- 意味：待機系の電源を入れ、現用系と同じ業務プログラムを起動し、データも同期させたまま待たせる方式
- ポイント：切替えが最も速い。そのかわり待機系も動かし続けるので費用がかかる
- 例：R4春 問13（現用系から定期的に送られ、動作中であることを示すメッセージが途切れたときに切り替わる）

#### ウォームスタンバイ（うぉーむすたんばい / Warm Standby）

- 意味：待機系の機器は動いているが、業務プログラムの起動やデータの準備をしてから引き継ぐ方式
- ポイント：切替えの速さも費用も、ホットとコールドの間

#### コールドスタンバイ（こーるどすたんばい / Cold Standby）

- 意味：予備の機器を用意しておくだけで、障害が起きてから電源を入れ、準備を始めて引き継ぐ方式
- ポイント：最も安いが、切替えに時間がかかる。処理中だったトランザクションは引き継げない
- 例：R6秋 問12（コールドスタンバイ構成のサーバに障害が起きると、サービスは中断し、トランザクションも継続できない）

### 災害に備える拠点

#### ホットサイト（ほっとさいと / Hot Site）

- 意味：本番と同じ機器を常に動かし、データも同期させて待機している、災害対策用のバックアップサイト
- ポイント：本番の拠点が被災しても、すぐ業務を引き継げる。費用が最も高い

#### ウォームサイト（うぉーむさいと / Warm Site）

- 意味：機器は設置してあるが、最新のデータやプログラムを入れてから業務を引き継ぐ、災害対策用のバックアップサイト
- ポイント：再開までの時間も費用も、ホットサイトとコールドサイトの間

#### コールドサイト（こーるどさいと / Cold Site）

- 意味：建物・電源・回線などの場所だけを用意し、災害が起きてから機器を運び込んで立ち上げる、災害対策用のバックアップサイト
- ポイント：安いが、業務の再開に日単位の時間がかかる

#### ディザスタリカバリ（でぃざすたりかばり / Disaster Recovery）

- 意味：地震・火災などの災害でシステムが壊れたとき、別の場所で復旧して業務を再開させるための備えと手順
- ポイント：DRと略す。データの遠隔地への複製や、バックアップサイトの用意がその手段
- 語の意味：Disaster＝災害／Recovery＝回復

### 災害対策の計画

#### バックアップサイト（ばっくあっぷさいと / Backup Site）

- 意味：本番の拠点が使えなくなったときに業務を引き継ぐために、離れた場所に用意しておく拠点
- ポイント：準備の度合いによって、ホット・ウォーム・コールドの3種類に分ける

#### 事業継続計画（じぎょうけいぞくけいかく / Business Continuity Plan）

- 意味：災害や大きな障害が起きても、重要な業務を止めない、または早く再開するために前もって決めておく計画
- ポイント：BCPと略す。システムだけでなく、人・建物・取引先まで含めて考える
- 語の意味：Business＝事業／Continuity＝継続／Plan＝計画

#### RPO（あーるぴーおー / Recovery Point Objective）

- 意味：障害が起きたとき、どの時点までのデータを取り戻せればよいかという目標。目標復旧時点
- ポイント：「1時間前まで戻れればよい」ならRPOは1時間。バックアップや複製をとる間隔を決める
- 語の意味：Recovery＝復旧／Point＝時点／Objective＝目標

#### RTO（あーるてぃーおー / Recovery Time Objective）

- 意味：障害が起きてから、どれだけの時間で業務を再開させるかという目標。目標復旧時間
- ポイント：RPOは「どこまで戻すか（データ）」、RTOは「いつまでに直すか（時間）」
- 語の意味：Recovery＝復旧／Time＝時間／Objective＝目標

### データの共有のしかた

#### シェアードエブリシング（しぇあーどえぶりしんぐ / Shared Everything）

- 意味：複数のサーバが、同じディスク（データベース）を共有して処理する構成
- ポイント：どのサーバからでも全データにアクセスできる。サーバが増えると、共有部分での取り合い（排他制御）が増える
- 語の意味：Shared＝共有された／Everything＝全部

#### シェアードナッシング（しぇあーどなっしんぐ / Shared Nothing）

- 意味：サーバごとに専用のディスクとデータを持たせ、何も共有せずに処理する構成
- ポイント：取り合いがないので、サーバを増やすほど性能が伸びやすい。データの置き場所をうまく分ける必要がある
- 語の意味：Shared＝共有された／Nothing＝何もない

#### シャーディング（しゃーでぃんぐ / Sharding）

- 意味：大きなデータベースを、キーの値の範囲などで複数のサーバに分けて置くこと
- ポイント：シェアードナッシングを実現する方法の一つ。分けた一つ一つをシャードと呼ぶ
- 語の意味：Shard＝かけら

#### レプリケーション（れぷりけーしょん / Replication）

- 意味：データの複製を別のサーバや別の場所に作り、更新があるたびに同じ内容に保つこと
- ポイント：読み込みを複製に分散して速くしたり、障害や災害のときの予備にしたりする
- 語の意味：Replication＝複製すること

### 端末のつながり方

#### シンクライアント（しんくらいあんと / Thin Client）

- 意味：利用者の端末には最小限の機能だけをもたせ、アプリケーションやデータはサーバ側で処理・保存する方式。また、その端末。VDIなどで実現する
- ポイント：端末にデータが残らないので、紛失しても情報が漏れにくい。サーバから画面だけを送ってもらう
- 例：R3秋 問14（サーバで実行したアプリケーションの画面をクライアントに送り、操作をサーバへ送る→コンテナ型仮想化ではない誤りの選択肢）
- 語の意味：Thin＝薄い／Client＝サービスを受ける側

#### ファットクライアント（ふぁっとくらいあんと / Fat Client）

- 意味：アプリケーションを端末側に入れて、端末で処理を行う方式。また、その端末
- ポイント：通信が切れても動くが、端末ごとにソフトの導入や更新が必要になる。リッチクライアントとも呼ぶ
- 語の意味：Fat＝太った

#### ピアツーピア（ぴあつーぴあ / Peer to Peer）

- 意味：サーバを置かず、対等な立場のコンピュータどうしが直接データをやり取りする方式
- ポイント：P2Pと略す。一部が止まっても全体は動き続けるが、全体を管理する者がいない
- 語の意味：Peer＝対等な仲間

#### VDI（ぶいでぃーあい / Virtual Desktop Infrastructure）

- 意味：利用者ごとのデスクトップ環境（OSとアプリケーション）をサーバ上の仮想マシンで動かし、端末には画面だけを送るしくみ。デスクトップ仮想化と呼び、シンクライアントを実現する方式の一つ
- ポイント：端末は画面の表示と、キーボード・マウスの操作の送信だけを行う
- 語の意味：Virtual＝仮想の／Desktop＝机の上の作業環境／Infrastructure＝基盤

### 処理を分け合う方式

#### グリッドコンピューティング（ぐりっどこんぴゅーてぃんぐ / Grid Computing）

- 意味：ネットワーク上にある多数のコンピュータ（PCから大型機まで）に処理を分けて、1つの大規模な処理を行う方式
- ポイント：性能も種類もばらばらなコンピュータをつないで、仮想的に1台の大きなコンピュータとして使う
- 例：R3春 問11（PCから大型コンピュータまで、ネットワーク上にある複数のプロセッサに処理を分散して、大規模な一つの処理を行う方式）
- 語の意味：Grid＝電力網（電気のように計算能力を使えるようにする、という意味）

#### ハイパフォーマンスコンピューティング（はいぱふぉーまんすこんぴゅーてぃんぐ / High Performance Computing）

- 意味：気象予測やシミュレーションなど、精度の高い大量の計算を高速に行うための計算技術や環境
- ポイント：HPCと略す。スーパーコンピュータや、多数のコンピュータをつないだ大規模並列の構成で実現する
- 語の意味：High＝高い／Performance＝性能

#### PCクラスタ（ぴーしーくらすた / PC Cluster）

- 意味：多数の一般的なPC（サーバ）を高速なネットワークでつなぎ、全体で1台の高性能なコンピュータとして使う構成
- ポイント：安い機械を並べてHPCを実現する方法。同じ場所に、同じ種類の機械を並べる点がグリッドと違う

#### ボランティアコンピューティング（ぼらんてぃあこんぴゅーてぃんぐ / Volunteer Computing）

- 意味：グリッドコンピューティングの一種で、一般の人が自分のPCの使っていない時間の計算能力を提供し、インターネット越しに集めて大きな計算をする方式
- ポイント：科学研究の計算で使われてきた

### 仮想化の方式

#### ホスト型仮想化（ほすとがたかそうか / Host-based Virtualization）

- 意味：物理サーバで動くOS（ホストOS）の上に仮想化ソフトウェアを入れ、その上でゲストOSを動かす方式
- ポイント：ふだん使っているOSの上で手軽に使えるが、ハードウェアへのアクセスにホストOSを経由するので遅くなる
- 例：R3秋 問14（ホストOSで仮想化ソフトウェアを動かし、その上で複数のゲストOSを動かす→コンテナ型の説明ではない）

#### ハイパーバイザー型仮想化（はいぱーばいざーがたかそうか / Hypervisor-based Virtualization）

- 意味：物理サーバにホストOSを入れず、直接入れた仮想化ソフトウェア（ハイパーバイザー）の上で、ゲストOSを動かす方式
- ポイント：ホストOSを経由しないので速い。サーバの仮想化ではこれが主流
- 例：R4秋 問12（物理サーバにホストOSをもたず、インストールした仮想化ソフトウェアによって個別のゲストOSをもった仮想サーバを動かす）

#### コンテナ型仮想化（こんてながたかそうか / Container-based Virtualization）

- 意味：ホストOSの上で、アプリケーションと、その実行に必要なライブラリなどを1つにまとめた隔離された区画（コンテナ）を複数動かす方式
- ポイント：コンテナはゲストOSをもたず、ホストOSのカーネルを共有する。軽くてすぐ起動するが、ホストOSと違う種類のOSは動かせない
- 例：R3秋 問14（アプリケーションの起動に必要なプログラムやライブラリをまとめ、ホストOSで動かす）、R4秋 問12（ホストOSと仮想化ソフトウェアによってプログラムの実行環境を仮想化するので、仮想サーバに個別のゲストOSをもたない）

#### 準仮想化（じゅんかそうか / Paravirtualization）

- 意味：ゲストOSを仮想化環境向けに書き換え、ハイパーバイザーと直接やり取りさせることで、仮想化による性能の低下を小さくする方式
- ポイント：ゲストOSに手を加えずにそのまま動かす方式（完全仮想化）より速いが、書き換えたOSしか動かせない
- 語の意味：Para＝そばに・準じた／Virtualization＝仮想化

### 仮想化の部品

#### 仮想マシン（かそうましん / Virtual Machine）

- 意味：ソフトウェアで作り出した、1台の独立したコンピュータのように動く仮想の機械
- ポイント：VMと略す。1台の物理サーバで複数の仮想マシンを動かし、それぞれ別のOSを入れられる
- 語の意味：Virtual＝仮想の／Machine＝機械

#### ハイパーバイザー（はいぱーばいざー / Hypervisor）

- 意味：物理サーバのCPU・メモリ・ディスクを分けて、複数の仮想マシンに割り当てて動かす制御用のソフトウェア
- ポイント：仮想マシンモニタとも呼ぶ。ホストOSなしで物理サーバに直接入れるものと、ホストOSの上で動くものがある
- 語の意味：Hyper＝上位の／Visor＝監督するもの

#### ホストOS（ほすとおーえす / Host OS）

- 意味：物理サーバに直接入れて動かすOS。この上で仮想化ソフトウェアやコンテナが動く
- ポイント：コンテナ型では、全部のコンテナがホストOSのカーネルを共有する

#### ゲストOS（げすとおーえす / Guest OS）

- 意味：仮想マシンの中で動くOS
- ポイント：仮想マシンごとに違う種類のOSを動かせる。コンテナ型にはゲストOSがない

#### コンテナ（こんてな / Container）

- 意味：アプリケーションと、その実行に必要なライブラリや設定を1つにまとめ、ほかから隔離して動かす単位
- ポイント：ゲストOSを含まないので小さく、どの環境に持っていっても同じように動く
- 語の意味：Container＝入れ物

### 仮想化の運用

#### ライブマイグレーション（らいぶまいぐれーしょん / Live Migration）

- 意味：動いている仮想マシンを止めずに、別の物理サーバへ移すこと
- ポイント：物理サーバの保守や負荷の偏りを直すときに、サービスを止めずに済む
- 語の意味：Live＝動いたままの／Migration＝移動

#### コールドマイグレーション（こーるどまいぐれーしょん / Cold Migration）

- 意味：仮想マシンをいったん停止させてから、別の物理サーバへ移すこと
- ポイント：移している間はサービスが止まる。止めずに移すライブマイグレーションと対になる

#### サーバコンソリデーション（さーばこんそりでーしょん / Server Consolidation）

- 意味：何台もの物理サーバで動いていたシステムを、仮想化を使って少ない台数の物理サーバにまとめること
- ポイント：サーバ集約とも呼ぶ。台数・電力・設置場所・保守の費用を減らせる
- 語の意味：Consolidation＝統合

#### オーバーコミット（おーばーこみっと / Overcommit）

- 意味：物理サーバが実際にもっているCPUやメモリの量より多くの量を、仮想マシンに割り当てること
- ポイント：全部の仮想マシンが同時に使い切ることはない、という前提で資源を有効に使う。同時に使われると性能が落ちる
- 語の意味：Over＝超えて／Commit＝割り当てる

### クラウドのサービスモデル

#### SaaS（さーす / Software as a Service）

- 意味：アプリケーションの機能を、インターネット経由のサービスとして提供する形態
- ポイント：利用者はソフトを入れずに、ブラウザなどから使うだけ。電子メールや会計ソフトのクラウド版など
- 語の意味：Software＝ソフトウェア／as a Service＝サービスとして

#### PaaS（ぱーす / Platform as a Service）

- 意味：アプリケーションを動かすための土台（OS・ミドルウェア・実行環境）を、サービスとして提供する形態
- ポイント：利用者は自分で作ったアプリケーションを載せるだけで、OSなどの管理は事業者が行う
- 語の意味：Platform＝土台／as a Service＝サービスとして

#### IaaS（いあーす / Infrastructure as a Service）

- 意味：サーバ・ストレージ・ネットワークなどの基盤（仮想マシン）を、サービスとして提供する形態
- ポイント：OSから上は利用者が自分で入れて管理する。自由度が最も高い
- 例：R7秋 問12（利用者がOSやアプリケーションなどのソフトウェアを基盤に実装して操作できる→IaCではなくIaaSの説明）
- 語の意味：Infrastructure＝基盤／as a Service＝サービスとして

#### FaaS（ふぁーす / Function as a Service）

- 意味：プログラムの関数を登録しておき、イベントが起きたときだけ実行してくれるサービスの形態
- ポイント：サーバを常に動かしておく必要がなく、実行した分だけ料金がかかる。サーバレスの代表
- 語の意味：Function＝関数／as a Service＝サービスとして

#### DaaS（だーす / Desktop as a Service）

- 意味：利用者が使うPCのデスクトップ環境を、クラウドからサービスとして提供する形態
- ポイント：VDI（デスクトップ仮想化）を、自社のサーバではなくクラウド事業者のサービスで使うもの
- 語の意味：Desktop＝デスクトップ環境／as a Service＝サービスとして

### クラウドの置き場所

#### パブリッククラウド（ぱぶりっくくらうど / Public Cloud）

- 意味：クラウド事業者の設備を、不特定多数の利用者が共同で使う形態
- ポイント：すぐ使い始められ、使った分だけ払う。設備は他社と共有している

#### プライベートクラウド（ぷらいべーとくらうど / Private Cloud）

- 意味：特定の1つの企業だけが使うように作ったクラウドの環境
- ポイント：自社の設備に作るものと、事業者の設備を専用で借りるものがある。自由に設定でき、安全性を高めやすい

#### ハイブリッドクラウド（はいぶりっどくらうど / Hybrid Cloud）

- 意味：事業者の共用のクラウドと、自社専用のクラウドや自社の設備を組み合わせて使う形態
- ポイント：大事なデータは自社側、変動の大きい処理はパブリック側、のように使い分ける

#### オンプレミス（おんぷれみす / On-premises）

- 意味：サーバなどの機器を自社で買って、自社の建物の中に置いて運用する形態
- ポイント：クラウドと対比して使う言葉。自由に作れるが、初期費用も保守の手間も自社で負う
- 語の意味：On＝〜の上に／Premises＝敷地・構内

### 処理を置く場所

#### クラウドコンピューティング（くらうどこんぴゅーてぃんぐ / Cloud Computing）

- 意味：サーバ・ストレージ・アプリケーションなどの資源を、インターネット経由で必要なときに必要なだけ使う形態
- ポイント：自分で機器を持たずに、使った分だけ料金を払う。量を増やしたり減らしたりすることも簡単
- 語の意味：Cloud＝雲（ネットワークの向こう側を雲で描いたことから）

#### エッジコンピューティング（えっじこんぴゅーてぃんぐ / Edge Computing）

- 意味：データが発生する機器やその近く（ネットワークの端）で処理を行い、必要な結果だけをクラウドへ送る方式
- ポイント：遠くのクラウドまで往復しないので応答が速く、通信量も減らせる。IoTや自動運転で使われる
- 語の意味：Edge＝端

#### フォグコンピューティング（ふぉぐこんぴゅーてぃんぐ / Fog Computing）

- 意味：機器とクラウドの間に置いた中間のサーバ（ゲートウェイなど）で、データを処理する方式
- ポイント：雲（クラウド）より地上に近い霧（フォグ）という意味。エッジとクラウドの間を受け持つ
- 語の意味：Fog＝霧

#### サーバレスアーキテクチャ（さーばれすあーきてくちゃ / Serverless Architecture）

- 意味：利用者がサーバの用意や管理を意識せず、プログラムだけを用意して、クラウド事業者の環境で実行させるシステムの作り方
- ポイント：実際にはサーバがあるが、利用者からは見えない。FaaSなどを組み合わせて作る
- 語の意味：Serverless＝サーバのない

### インフラの作り方

#### IaC（あいえーしー / Infrastructure as Code）

- 意味：サーバやネットワークの構成・設定をプログラム（コード）として書き、ソフトウェアがその内容に従って自動的にシステムを作ったり設定したりする考え方
- ポイント：手作業の設定と違い、同じ環境を何度でも同じように作れる。コードなので変更の履歴も管理できる
- 例：R5秋 問14（ソフトウェアによる自動実行を可能にするために、システムの構成や状態をコードに定義すること）、R7秋 問12（システムの構成、設定などをプログラムとして記述し、専用のソフトウェアがその内容に従って自動的にシステムに適用する）
- 語の意味：Infrastructure＝基盤／as Code＝コードとして

#### ベアメタルサーバ（べあめたるさーば / Bare Metal Server）

- 意味：OSや仮想化ソフトなどが何も入っていない、まっさらな状態の物理サーバ。また、それを1社で専有して借りるサービス
- ポイント：ほかの利用者と共有しないので性能が安定する。利用者が自分でOSなどを入れる
- 例：R7秋 問12（OS、仮想化ソフトなどが何もインストールされていない、初期状態のサーバ→IaCではない誤りの選択肢）
- 語の意味：Bare＝むき出しの／Metal＝金属（機械そのもの）

#### オーケストレーション（おーけすとれーしょん / Orchestration）

- 意味：たくさんのサーバやコンテナの配置・起動・設定・台数の増減を、まとめて自動的に管理すること
- ポイント：コンテナを大量に動かすときに使う。何台をどこで動かすかを指揮者のように調整する
- 語の意味：Orchestration＝（オーケストラの）編成・指揮

#### イミュータブルインフラストラクチャ（いみゅーたぶるいんふらすとらくちゃ / Immutable Infrastructure）

- 意味：一度作ったサーバには変更を加えず、変更が必要なときは新しく作り直して入れ替える運用の考え方
- ポイント：手で直していくうちに環境ごとの違いが生まれる問題を防ぐ。IaCで作り直しを自動にして実現する
- 語の意味：Immutable＝変更できない／Infrastructure＝基盤

## 4-2 クライアントサーバとWebシステム

### まとめ表

**3層クライアントサーバシステム**

| 層 | 受け持つ処理 | 置く場所の例 |
| :-: | :-: | :-: |
| プレゼンテーション層 | 画面の表示と入力の受付け | クライアント（Webブラウザ） |
| ファンクション層 | 業務の処理（計算・判断） | アプリケーションサーバ |
| データベースアクセス層 | データの検索・更新 | データベースサーバ |

- 2層は「クライアント」と「データベースサーバ」の2つに分け、業務の処理をクライアント側に置く。3層では業務の処理を真ん中の層に分けるので、処理を変えてもクライアントを入れ替えずに済む

**クライアントサーバシステムのよしあし（シラバスの観点）**

| 観点 | 長所 | 短所 |
| :-: | :-: | :-: |
| ローカル処理の応答速度 | 手元で済む処理は速い | ― |
| コスト性能比・柔軟性 | 安い機械を組み合わせ、少しずつ増やせる | ― |
| 管理責任 | ― | 管理する場所が散らばり、責任があいまいになる |
| サーバへの利用集中 | ― | 利用者が増えるとサーバに処理が集中して遅くなる |

**Webシステムを止めない工夫（R6秋 問12の論点）**

| 構成 | 1台が止まったとき：サービス | 1台が止まったとき：処理中の取引 |
| :-: | :-: | :-: |
| コールドスタンバイ | 中断する | 継続できない |
| セッションを共有しないクラスタ | 継続できる | 継続できない（そのサーバにあった状態が消える） |
| セッションを共有するクラスタ | 継続できる | 継続できる |

### クライアントサーバの層

#### 2層クライアントサーバシステム（にそうくらいあんとさーばしすてむ / Two-tier Client Server System）

- 意味：クライアントサーバシステムのうち、システムをクライアントとデータベースサーバの2つに分け、画面と業務の処理はクライアント、データの管理はサーバが受け持つ構成
- ポイント：業務の処理を変えると、全部のクライアントのプログラムを入れ替える必要がある

#### 3層クライアントサーバシステム（さんそうくらいあんとさーばしすてむ / Three-tier Client Server System）

- 意味：クライアントサーバシステムのうち、システムを画面の表示・業務の処理・データの管理の3つの層に分けて作る構成
- ポイント：層ごとに独立して作り直せる。業務の処理を変えても、クライアントは入れ替えずに済む

#### プレゼンテーション層（ぷれぜんてーしょんそう / Presentation Layer）

- 意味：3層構成のうち、利用者に画面を表示し、入力を受け付ける部分
- ポイント：入力の形式のチェックまではここで行う。Webシステムではブラウザが受け持つ
- 語の意味：Presentation＝見せること

#### ファンクション層（ふぁんくしょんそう / Function Layer）

- 意味：3層構成のうち、受け取った入力をもとに、業務の計算や判断を行う部分
- ポイント：アプリケーション層とも呼ぶ。アプリケーションサーバが受け持つ
- 語の意味：Function＝機能

#### データベースアクセス層（でーたべーすあくせすそう / Database Access Layer）

- 意味：3層構成のうち、ファンクション層からの要求を受けて、データベースの検索や更新を行う部分
- ポイント：データ層とも呼ぶ。データベースサーバが受け持つ

### クライアントとサーバ

#### クライアント（くらいあんと / Client）

- 意味：サーバにサービスを要求し、その結果を受け取って使う側のコンピュータやプログラム
- ポイント：利用者が直接操作する側。サーバとの役割分担は構成によって変わる
- 語の意味：Client＝依頼人・顧客

#### サーバ（さーば / Server）

- 意味：クライアントからの要求を受けて、処理を行ったりデータを提供したりする側のコンピュータやプログラム
- ポイント：多くのクライアントの要求を受けるので、利用が集中すると遅くなりやすい
- 語の意味：Server＝仕える者・提供者

#### クライアントサーバシステム（くらいあんとさーばしすてむ / Client Server System）

- 意味：サービスを要求する側（クライアント）と提供する側（サーバ）に役割を分け、ネットワークでつないで処理する構成
- ポイント：垂直機能分散の一種。処理を分け合うので、1台の大型機より安く柔軟に作れる

#### ミドルウェア（みどるうぇあ / Middleware）

- 意味：OSとアプリケーションの間に入り、データベースへの接続や通信、トランザクションの管理など、多くのアプリケーションが共通に使う機能を提供するソフトウェア
- ポイント：クライアントサーバシステムやWebシステムでは、アプリケーションサーバやデータベース管理システムがその代表
- 語の意味：Middle＝中間の／ware＝製品（ソフトウェア）

### クライアントサーバのよしあし

#### ローカル処理の応答速度（ろーかるしょりのおうとうそくど / Local Response Speed）

- 意味：サーバに問い合わせず、クライアントの中だけで済む処理なら、すぐに結果が返ること
- ポイント：クライアントサーバシステムの長所。入力のチェックなどをクライアントで行えば、サーバまで往復しなくてよい

#### 柔軟性（じゅうなんせい / Flexibility）

- 意味：必要に応じてクライアントやサーバを少しずつ増やしたり、入れ替えたりしやすいこと
- ポイント：クライアントサーバシステムの長所。大型機をまるごと買い替えなくてよい

#### サーバへの利用集中（さーばへのりようしゅうちゅう / Server Load Concentration）

- 意味：多くのクライアントの要求が1台のサーバに集まり、処理が追いつかなくなって応答が遅くなること
- ポイント：クライアントサーバシステムの短所。サーバを増やして負荷を分散するなどの対策が必要

#### 運用管理の分散（うんようかんりのぶんさん / Distributed Operations Management）

- 意味：クライアントやサーバが部門ごとに散らばり、ソフトの更新やバックアップなどの管理を、あちこちで行う必要が出ること
- ポイント：クライアントサーバシステムの短所。管理の責任もあいまいになりやすい

### サーバに処理を頼む方法

#### RPC（あーるぴーしー / Remote Procedure Call）

- 意味：ネットワーク上の別のコンピュータにある手続き（関数）を、自分のプログラムの中の手続きと同じように呼び出すしくみ
- ポイント：通信の細かい手順を意識せずに、ほかのコンピュータに処理を頼める。遠隔手続き呼出し
- 語の意味：Remote＝遠くの／Procedure＝手続き／Call＝呼出し

#### ストアドプロシージャ（すとあどぷろしーじゃ / Stored Procedure）

- 意味：よく使う一連のSQLの処理をまとめて、データベースサーバに登録しておき、クライアントからは名前を指定して呼び出すしくみ
- ポイント：SQLを1文ずつ送らずに済むので、通信の回数が減り、処理が速くなる
- 語の意味：Stored＝保存された／Procedure＝手続き

#### Web API（うぇぶえーぴーあい / Web API）

- 意味：HTTPなどのWebの技術を使って、ほかのシステムの機能やデータを呼び出せるようにした窓口
- ポイント：結果はJSONやXMLで受け取ることが多い。RESTと呼ばれる作り方がよく使われる
- 語の意味：API＝Application Programming Interface（プログラムどうしの接点）

#### メッセージキューイング（めっせーじきゅーいんぐ / Message Queuing）

- 意味：システムどうしでやり取りするデータを、いったん待ち行列（キュー）にためて、受け取る側が自分の都合で取り出すしくみ
- ポイント：送る側と受け取る側が同時に動いていなくてよい（非同期）。受け取る側が混んでいても、送る側は待たずに済む
- 語の意味：Message＝伝言／Queue＝待ち行列

### Webシステムのサーバ

#### Webブラウザ（うぇぶぶらうざ / Web Browser）

- 意味：Webサーバから受け取ったHTMLなどを読み込んで画面に表示し、利用者の操作をサーバに送るソフトウェア
- ポイント：Webシステムのクライアントの役目をする。専用のソフトを入れなくても、ブラウザがあれば使える
- 語の意味：Browse＝拾い読みする

#### Webサーバ（うぇぶさーば / Web Server）

- 意味：ブラウザからのHTTPの要求を受けて、Webページや画像などを返すサーバ
- ポイント：決まった内容のページは自分で返し、業務の処理が必要な要求はアプリケーションサーバに渡す

#### アプリケーションサーバ（あぷりけーしょんさーば / Application Server）

- 意味：Webシステムで、業務の処理（計算・判断・データベースへの問合せ）を行うプログラムを動かすサーバ
- ポイント：APサーバと略す。3層構成のファンクション層にあたる
- 例：R6秋 問12（Webアプリケーションサーバの信頼性→セッションを共有するクラスタ構成なら、1台に障害が起きてもサービスとトランザクションを続けられる）

#### データベースサーバ（でーたべーすさーば / Database Server）

- 意味：データベース管理システムを動かし、データの検索や更新の要求に応えるサーバ
- ポイント：DBサーバと略す。3層構成のデータベースアクセス層にあたる

### 負荷分散とセッション

#### ロードバランサ（ろーどばらんさ / Load Balancer）

- 意味：利用者からの要求を受けて、複数のサーバに振り分け、負荷を平均化する装置やソフトウェア
- ポイント：負荷分散装置とも呼ぶ。止まったサーバには振り分けないので、可用性も上がる
- 語の意味：Load＝負荷／Balancer＝釣り合わせるもの

#### スティッキーセッション（すてぃっきーせっしょん / Sticky Session）

- 意味：同じ利用者からの一連の要求を、ロードバランサが毎回同じサーバに振り分けるしくみ
- ポイント：ログイン状態などをサーバごとにもっていても困らない。ただし、そのサーバが止まると状態は失われる
- 語の意味：Sticky＝くっつく／Session＝一連のやり取り

#### セッション共有（せっしょんきょうゆう / Session Sharing）

- 意味：利用者ごとのやり取りの状態（セッション）を、複数のサーバが共通に読み書きできる場所に置くこと
- ポイント：1台が止まっても、ほかのサーバがその利用者の状態を引き継いで処理を続けられる
- 例：R6秋 問12（セッションを共有するクラスタ構成で1台に障害が起きた場合、サービス及びトランザクションは継続できる）

#### リバースプロキシ（りばーすぷろきし / Reverse Proxy）

- 意味：Webサーバの手前に置き、利用者からの要求をいったん受けて、後ろのサーバへ中継するサーバ
- ポイント：負荷分散・暗号化の処理の肩代わり・内容のキャッシュなどを受け持つ。利用者からは後ろのサーバが見えない
- 語の意味：Reverse＝逆の／Proxy＝代理

## 4-3 ストレージ

### まとめ表

**RAIDの種類（ディスクn台、1台の容量をCとする）**

| 種類 | やり方 | 使える容量 | 何台まで壊れても大丈夫か |
| :-: | :-: | :-: | :-: |
| RAID0 | ストライピング（分散して書く） | n×C | 0台（1台でも壊れたら全部失う） |
| RAID1 | ミラーリング（同じものを2台に書く） | n×C÷2 | 片方のどちらか1台 |
| RAID10 | ミラーリングした組をストライピング | n×C÷2 | 各組の1台まで |
| RAID3 | ビット・バイト単位のストライピング＋パリティ専用ディスク | (n−1)×C | 1台 |
| RAID4 | ブロック単位のストライピング＋パリティ専用ディスク | (n−1)×C | 1台 |
| RAID5 | ブロック単位のストライピング＋パリティを全ディスクに分散 | (n−1)×C | 1台 |
| RAID6 | RAID5に、もう1つのパリティを加えて分散 | (n−2)×C | 2台 |

- RAID2 は誤りを直す符号（ハミング符号）を専用のディスクに書く方式で、実際にはほとんど使われない
- RAID4 はパリティ専用ディスクに書込みが集中するので、パリティを分散させた RAID5 が広く使われる

**ストレージのつなぎ方（R5秋 問12の論点）**

| 方式 | つなぎ方 | 読み書きの単位 | 例 |
| :-: | :-: | :-: | :-: |
| DAS | サーバに直接（1対1） | ブロック | 内蔵ディスク、SATA・SASでつないだ装置 |
| NAS | LANにつなぐファイルサーバ | ファイル | NFS・CIFS（SMB）で共有 |
| SAN | ストレージ専用のネットワーク | ブロック | FC-SAN（ファイバチャネル）、IP-SAN（iSCSI） |

**データの置き方（R6春 問13・R6秋 問13・R7春 問10の論点）**

| 方式 | データの単位 | 探し方 | 向いている用途 |
| :-: | :-: | :-: | :-: |
| ブロックストレージ | 決まった大きさのブロック | ブロックの番号（アドレス） | データベースなど、速さが必要なもの |
| ファイルストレージ | ファイル | フォルダの階層とファイル名 | 部門のファイル共有 |
| オブジェクトストレージ | データ＋メタデータ（オブジェクト） | 一意な識別子（ID） | 画像・動画・バックアップなど、大量で更新の少ないデータ |

### ディスクをまとめる技術

#### JBOD（じぇいぼっど / Just a Bunch Of Disks）

- 意味：複数のディスクを単純につなげて、容量の大きな1台のディスクに見せる構成。データを分けて書くことも、冗長にすることもしない
- ポイント：容量は全部使えるが、速くもならず、1台が壊れるとそのディスクのデータを失う。冗長性がない点はRAID0と同じだが、ストライピングもしない
- 語の意味：Just a Bunch Of Disks＝ただのディスクの束

#### ストライピング（すとらいぴんぐ / Striping）

- 意味：データを一定の大きさに区切り、複数のディスクに順番に分けて書き込むこと
- ポイント：複数のディスクを同時に読み書きできるので速くなる。これだけでは冗長性はない（RAID0）
- 語の意味：Stripe＝縞模様

#### ミラーリング（みらーりんぐ / Mirroring）

- 意味：同じデータを2台以上のディスクに同時に書き込むこと
- ポイント：1台が壊れても、もう1台にそのまま同じデータが残る（RAID1）。使える容量は半分になる
- 語の意味：Mirror＝鏡

#### パリティ（ぱりてぃ / Parity）

- 意味：複数のディスクのデータから計算して作る、誤りの訂正用のデータ。排他的論理和（XOR）で作る
- ポイント：1台が壊れても、残りのデータとパリティから、壊れたディスクのデータを計算で作り直せる
- 語の意味：Parity＝等しいこと（1の個数をそろえる、という意味）

#### チャンクサイズ（ちゃんくさいず / Chunk Size）

- 意味：ストライピングで、1台のディスクに続けて書き込むデータの大きさ（区切りの単位）
- ポイント：ストライプサイズとも呼ぶ。小さいと1つのデータを多くのディスクで並行して読めるが、管理の手間が増える
- 語の意味：Chunk＝かたまり／Size＝大きさ

#### ホットスペア（ほっとすぺあ / Hot Spare）

- 意味：RAIDの中に、ふだんは使わない予備のディスクを入れておき、どれかが壊れたら自動的に代わりに使い始めるしくみ
- ポイント：壊れたディスクの内容を、残りのディスクから予備のディスクに作り直す（リビルド）。予備の分は容量に数えない
- 語の意味：Hot＝電源が入ったままの／Spare＝予備

### ミラーリングとストライピング

#### RAID0（れいどぜろ / RAID 0）

- 意味：データを複数のディスクに分けて書き込む（ストライピング）だけの構成
- ポイント：最も速く、全部の容量を使えるが、冗長性はなく、1台でも壊れると全部のデータを失う

#### RAID1（れいどわん / RAID 1）

- 意味：同じデータを2台のディスクに書き込む（ミラーリング）構成
- ポイント：1台が壊れても続けて使える。使える容量は全体の半分

#### RAID10（れいどいちぜろ / RAID 1+0）

- 意味：2台ずつミラーリングした組を作り、その組どうしでストライピングする構成
- ポイント：RAID1の信頼性とRAID0の速さを合わせもつ。使える容量は半分。各組から1台ずつまでなら壊れても大丈夫

#### RAID01（れいどぜろいち / RAID 0+1）

- 意味：ストライピングした組を2つ作り、その組どうしをミラーリングする構成
- ポイント：容量はRAID10と同じだが、片方の組で1台壊れるとその組全体が使えなくなるので、RAID10より壊れたときに弱い

### パリティを使うRAID

#### RAID2（れいどつー / RAID 2）

- 意味：データをビット単位で分けて書き、誤り訂正の符号（ハミング符号）を専用のディスクに書く構成
- ポイント：符号用のディスクが多く必要で効率が悪く、実際にはほとんど使われない

#### RAID3（れいどすりー / RAID 3）

- 意味：データをビットやバイトの細かい単位で分けて書き、パリティを1台の専用ディスクに書く構成
- ポイント：大きなデータを続けて読み書きするのは速いが、小さなデータの読み書きが多いと遅い

#### RAID4（れいどふぉー / RAID 4）

- 意味：データをブロック単位で分けて書き、パリティを1台の専用ディスクに書く構成
- ポイント：書き込むたびにパリティ用のディスクも書き換えるので、そこに書込みが集中して遅くなる

#### RAID5（れいどふぁいぶ / RAID 5）

- 意味：データをブロック単位で分けて書き、パリティを専用のディスクに置かずに、全部のディスクに分散して書く構成
- ポイント：パリティの書込みが1台に集中しない。n台のうち1台分がパリティになり、1台まで壊れても復元できる

#### RAID6（れいどしっくす / RAID 6）

- 意味：データをブロック単位で分けて書き、計算方法の違う2種類のパリティを、全部のディスクに分散して書く構成
- ポイント：パリティが1つのRAID5より書込みは遅くなるが、2台同時に壊れても復元できる。n台のうち2台分がパリティになるので、使える容量は (n−2)台分

### ストレージのつなぎ方

#### DAS（だす / Direct Attached Storage）

- 意味：サーバに、内蔵したりケーブルで直接つないだりして、そのサーバ専用に使うストレージ
- ポイント：1台のサーバと1対1でつなぐ。ほかのサーバとは共有しにくい。容量が足りなくなれば、そのサーバに足す
- 例：R5秋 問12（シリアルATAなどの接続方式によって内蔵ストレージとして1対1に接続する→SANではない）
- 語の意味：Direct＝直接の／Attached＝取り付けた／Storage＝記憶装置

#### NAS（なす / Network Attached Storage）

- 意味：LANに直接つなぎ、複数のコンピュータからファイル単位で共有して使えるようにしたストレージ
- ポイント：中身はファイルサーバ。NFSやCIFS（SMB）などのファイル共有の手順でアクセスする
- 例：R5秋 問12（プロトコルはNFSやCIFSを使用し、LANで接続する→NASの説明で、SANではない）
- 語の意味：Network＝ネットワーク／Attached＝取り付けた／Storage＝記憶装置

#### SAN（さん / Storage Area Network）

- 意味：サーバとストレージをつなぐためだけに作った専用のネットワーク。複数のサーバが複数のストレージを共有する。ファイバチャネルでつなぐFC-SANと、IPでつなぐIP-SANがある
- ポイント：ブロック単位で読み書きするので、サーバからは自分のディスクのように見える。業務用のLANとは別に作る
- 例：R5秋 問12（ファイバチャネルなどによる専用ネットワークで接続する）
- 語の意味：Storage＝記憶装置／Area＝領域／Network＝ネットワーク

#### ストレージ仮想化（すとれーじかそうか / Storage Virtualization）

- 意味：複数のストレージ装置をまとめて、仮想的な1台の大きなストレージとして扱う技術
- ポイント：装置の違いを隠して、容量をまとめて割り当てたり、移したりできる
- 例：R6春 問13（複数のストレージを組み合わせることによって、仮想的な1台のストレージとして運用する→オブジェクトストレージではない誤りの選択肢）

### SANの種類

#### FC-SAN（えふしーさん / Fibre Channel SAN）

- 意味：ファイバチャネル（FC）という、ストレージ専用の高速な規格でつないだSAN
- ポイント：速くて安定しているが、専用のスイッチやケーブルが必要で費用が高い
- 語の意味：FC＝Fibre Channel（ストレージ接続用の規格）

#### IP-SAN（あいぴーさん / IP SAN）

- 意味：ふつうのLANと同じイーサネットやIPの技術でつないだSAN
- ポイント：iSCSIを使うのが代表。既存のネットワーク機器や知識を使えるので安い
- 語の意味：IP＝Internet Protocol（インターネットの通信手順）

#### iSCSI（あいすかじー / Internet Small Computer System Interface）

- 意味：ディスクを読み書きするSCSIの命令を、TCP/IPのパケットに入れて送る手順
- ポイント：IP-SANで使う。ネットワークの先のディスクを、手元のディスクのように扱える
- 語の意味：Internet＝インターネット／SCSI＝ディスクなどをつなぐ規格

#### FCoE（えふしーおーいー / Fibre Channel over Ethernet）

- 意味：ファイバチャネルのデータを、イーサネットの上で送る規格
- ポイント：ストレージ用のネットワークと業務用のLANを、1本のイーサネットにまとめられる
- 語の意味：over Ethernet＝イーサネットの上で

### データの置き方

#### ブロックストレージ（ぶろっくすとれーじ / Block Storage）

- 意味：ストレージの領域を決まった大きさのブロックに分け、ブロックの番号を指定してデータを読み書きする方式
- ポイント：OSからは自分のディスクに見える。速いので、データベースや仮想マシンのディスクに使う。SANやDASがこの方式
- 例：R6秋 問13（ストレージの論理ボリュームを決まったサイズに分割し、その単位でデータにアクセスする→オブジェクトストレージではない）

#### ファイルストレージ（ふぁいるすとれーじ / File Storage）

- 意味：フォルダ（ディレクトリ）の階層の中にファイルを置き、パスとファイル名を指定して読み書きする方式
- ポイント：人にとってわかりやすく、共有もしやすい。NASがこの方式。数が非常に多くなると管理が重くなる
- 例：R6秋 問13（ストレージにファイルシステムを構成し、ファイル単位でデータにアクセスする→オブジェクトストレージではない）、R7春 問10（ディレクトリの概念を使った階層構造→オブジェクトストレージではない）

#### オブジェクトストレージ（おぶじぇくとすとれーじ / Object Storage）

- 意味：データと、そのデータを説明する情報（メタデータ）をまとめた「オブジェクト」を単位として保存し、オブジェクトごとに付けた一意の識別子でアクセスする方式
- ポイント：階層をもたない平らな空間に置くので、量が増えてもいくらでも広げやすい。画像や動画、バックアップなど、更新の少ない大量のデータに向く
- 例：R6春 問13（更新頻度の少ない非構造型データの格納に適しており、大容量で拡張性のあるストレージ空間を仮想的に実現する）、R6秋 問13（データとメタデータをセットにして保存し、固有の識別子でデータにアクセスする）、R7春 問10（オブジェクトにはユニークな識別子が割り当てられ、識別子を使ってアクセスする）

#### メタデータ（めたでーた / Metadata）

- 意味：データそのものではなく、そのデータの作成日時・種類・作成者などを表す、データについてのデータ
- ポイント：オブジェクトストレージでは、利用者が好きなメタデータを付けて、検索や管理に使える
- 語の意味：Meta＝〜についての（一段上の）

### 容量を上手に使う技術

#### シンプロビジョニング（しんぷろびじょにんぐ / Thin Provisioning）

- 意味：利用者には大きな容量を見せておき、実際のディスクは書き込まれた分だけその都度割り当てる技術
- ポイント：最初から全部の容量を買わなくてよい。実際の使用量が増えたら、そのとき物理ディスクを足す
- 語の意味：Thin＝薄い／Provisioning＝割り当てて用意すること

#### 重複排除（ちょうふくはいじょ / Deduplication）

- 意味：同じ内容のデータが何度も保存されるとき、実体は1つだけにして、残りはそれを指す印だけにする技術
- ポイント：バックアップのように似たデータを何度も保存する用途で、容量を大きく減らせる

#### ストレージ階層化（すとれーじかいそうか / Storage Tiering）

- 意味：よく使うデータは速くて高い装置（SSD）に、あまり使わないデータは遅くて安い装置（HDDやテープ）に、自動的に置き分ける技術
- ポイント：ティアリングとも呼ぶ。速さと費用の釣り合いをとる
- 語の意味：Tier＝段・階層

#### スナップショット（すなっぷしょっと / Snapshot）

- 意味：ある瞬間のストレージ（や仮想マシン）の状態を、そのまま記録しておく機能
- ポイント：変更された部分だけを記録するので、短い時間で取れる。誤操作の前の状態に戻すときに使う
- 語の意味：Snapshot＝早撮りの写真

## 4-4 信頼性設計

### まとめ表

**信頼性設計の考え方（R3春 問13・R5春 問15・R3秋 問13の論点。毎年のように出る）**

| 考え方 | ひとことで | 例 |
| :-: | :-: | :-: |
| フォールトアボイダンス | そもそも故障しないようにする | 品質の高い部品を使う、予防保守をする |
| フォールトトレランス | 故障しても、全体として機能を続ける | 部品やシステムを多重化（冗長化）する |
| フェールセーフ | 故障したら、安全な側に止める | 故障した信号機を全部赤にする |
| フェールソフト | 故障したら、機能を落としてでも動き続ける | 故障した部分を切り離して縮退運転する |
| フールプルーフ | 人がまちがえても、困ったことにならないようにする | 扉を閉めないと動かない電子レンジ |

- 過去問のひっかけ：「フェールソフト＝機能を縮退させることなく稼働を継続」は誤り（縮退させて続けるのがフェールソフト）。「フェールセーフ＝利用者の誤操作でも異常終了しない」は誤り（それはフールプルーフ）。「フォールトアボイダンス＝故障が発生しても運用を継続」は誤り（それはフォールトトレランス）

**信頼性ブロック図と稼働率（R3春 問14・R5春 問16・R6秋 問14・R7春 問13の論点）**

| つなぎ方 | 稼働率 | 覚え方 |
| :-: | :-: | :-: |
| 直列（両方動いて初めて動く） | A × B | 掛けると小さくなる |
| 並列（どちらか動けば動く） | 1 − (1 − A)(1 − B) | 「両方止まる確率」を1から引く |
| 2台並列（同じ稼働率 x） | 1 − (1 − x)² ＝ 2x − x² | x＝0.9 なら 0.99 |
| 3台中2台以上（同じ稼働率 x） | 3x² − 2x³ | 2台動く場合と3台動く場合の合計 |

### 信頼性設計の考え方

#### フォールトトレランス（ふぉーるととれらんす / Fault Tolerance）

- 意味：部品やシステムを多重化（冗長化）しておき、一部が故障しても、システム全体としては必要な機能を続けられるようにする考え方
- ポイント：故障は起きる前提で備える。故障しても止まらないシステムをフォールトトレラントシステムと呼ぶ
- 例：R5春 問15（システムを構成する重要部品を多重化して、故障に備える技術）
- 語の意味：Fault＝故障・欠陥／Tolerance＝耐えること

#### フォールトアボイダンス（ふぉーるとあぼいだんす / Fault Avoidance）

- 意味：品質の高い部品を使ったり、点検や予防保守をしたりして、そもそも故障が起きないようにする考え方
- ポイント：故障を「避ける」。故障しても動き続けるための多重化は、フォールトトレランスの考え方
- 例：R3春 問13（システム構成要素の個々の品質を高めて故障が発生しないようにする概念）、R5春 問15（構成部品に故障が発生しても運用を継続できるようにする→フォールトアボイダンスではないので誤り）
- 語の意味：Fault＝故障・欠陥／Avoidance＝避けること

#### フェールセーフ（ふぇーるせーふ / Fail Safe）

- 意味：故障や異常が起きたとき、システムを安全な状態に固定して、被害が広がらないようにする考え方
- ポイント：止めたほうが安全なら止める。故障した信号機は全部赤にする、エレベータは止まる、など
- 例：R3春 問13（あらかじめ定められた安全状態にシステムを固定し、全体として安全が維持されるような設計方法→フォールトトレランスの説明として書かれているので誤り）
- 語の意味：Fail＝故障する／Safe＝安全な

#### フェールソフト（ふぇーるそふと / Fail Soft）

- 意味：故障が起きたとき、故障した部分を切り離して、機能や性能を落としてでもシステムを動かし続ける考え方
- ポイント：全部止めずに、使える部分だけで動き続ける（縮退運転）。「機能を縮退させることなく」と書かれていたら誤り
- 例：R3春 問13（故障が発生した場合でも機能を縮退させることなく稼働を継続する→誤り）、R3秋 問13（システムの一部に不具合が生じたとき、その部分を停止させて機能を縮小して稼働し続ける→インタロックではない）
- 語の意味：Fail＝故障する／Soft＝やわらかく（急に全部止まらずに）

#### フールプルーフ（ふーるぷるーふ / Fool Proof）

- 意味：利用者がまちがった操作をしても、危ないことや困ったことが起きないように、あらかじめ防いでおく考え方
- ポイント：人の誤りを前提にする。誤った入力を受け付けない、扉を閉めないと動かない、など
- 例：R3春 問13（利用者の誤操作によってシステムが異常終了しないように、単純なミスを発生させないようにする設計方法→フェールセーフの説明として書かれているので誤り）
- 語の意味：Fool＝愚かな人／Proof＝〜に耐える

### 人と機械を守る仕組み

#### インタロック（いんたろっく / Interlock）

- 意味：危険な状態のときは機械が動かないように、ある条件が満たされないと次の動作に進めなくする仕組み
- ポイント：フールプルーフを実現する仕組みの一つ。人が危ない範囲に入ったらセンサが感知して機械を止める、など
- 例：R3秋 問13（動作中の機械から一定の範囲内に人間が立ち入ったことをセンサが感知したとき、機械の動作を停止させる仕組み）
- 語の意味：Inter＝互いに／Lock＝錠をかける

#### フォールトマスキング（ふぉーるとますきんぐ / Fault Masking）

- 意味：フォールトトレランスを実現する仕組みの一つで、故障が起きても、冗長な部分がその影響を打ち消して、外からは故障が起きていないように見せる仕組み
- ポイント：3台で同じ計算をして多数決をとる、メモリの誤りを自動で訂正する（ECC）、など
- 例：R4春 問14（記憶装置のビット誤り訂正機能や命令再試行機能は、故障を隠してMTBFを長くする→MTTRを短くするものではない）
- 語の意味：Fault＝故障／Masking＝覆い隠すこと

#### 縮退運転（しゅくたいうんてん / Degraded Operation）

- 意味：システムの一部が故障したとき、その部分を切り離し、機能や性能を落とした状態で運転を続けること
- ポイント：フォールバックとも呼ぶ。フェールソフトを実現した状態
- 例：R3秋 問13（システムの一部に不具合が生じたとき、その部分を停止させて機能を縮小してシステムを稼働し続ける仕組み→インタロックではない）

#### アクセス制御（あくせすせいぎょ / Access Control）

- 意味：決められた条件のもとで、許された人だけがシステムや情報を使えるようにする仕組み
- ポイント：安全性（セキュリティ）を守る仕組みで、人の誤りを防ぐフールプルーフとは目的が違う
- 例：R3秋 問13（ある条件下では、特定の人間だけがシステムを利用することを可能にする仕組み→インタロックではない）

### 冗長な部分の動かし方

#### 予備切替（よびきりかえ / Standby Switching）

- 意味：ふだんは予備の装置を待機させておき、使っている装置が故障したら予備に切り替える方式
- ポイント：デュプレックスシステムやアクティブ-スタンバイ構成の考え方。切り替える間は止まる
- 例：R3秋 問13（ある機械が故障したとき、それを停止させて代替の機械に自動的に切り替える仕組み→インタロックではない）

#### 並列運転（へいれつうんてん / Parallel Operation）

- 意味：複数の装置を同時に動かして同じ処理（または分けた処理）を行わせ、1台が故障しても残りで処理を続ける方式
- ポイント：デュアルシステムやアクティブ-アクティブ構成の考え方。切替えの時間がない

#### 競合制御（きょうごうせいぎょ / Contention Control）

- 意味：複数の装置や処理が、同じ資源（データ・ディスクなど）を同時に使おうとしたとき、順番を決めて矛盾が起きないようにすること
- ポイント：冗長な装置を並列に動かすときや、共有のデータを複数のサーバで更新するときに必要になる。排他制御もその方法の一つ

#### 多数決冗長（たすうけつじょうちょう / Majority Voting Redundancy）

- 意味：3台以上の装置に同じ処理をさせ、出力の多数決で結果を決める方式
- ポイント：3台のうち1台が故障して誤った結果を出しても、残り2台の正しい結果が採用される（フォールトマスキング）

### 止めないための設備

#### 無停止コンピュータ（むていしこんぴゅーた / Non-stop Computer）

- 意味：CPU・メモリ・電源などの主要な部品を全部多重化し、どこかが故障しても止まらずに処理を続けるコンピュータ
- ポイント：フォールトトレラントコンピュータ（FTサーバ）とも呼ぶ。部品を動かしたまま交換できる

#### UPS（ゆーぴーえす / Uninterruptible Power Supply）

- 意味：停電や電圧の乱れが起きたとき、内蔵の電池から短い時間だけ電力を送り続ける装置。無停電電源装置
- ポイント：数分〜数十分しかもたないので、その間にシステムを安全に止めるか、自家発電に切り替える
- 語の意味：Uninterruptible＝途切れない／Power＝電力／Supply＝供給

#### 自家発電装置（じかはつでんそうち / Private Power Generator）

- 意味：エンジンなどで自分で発電し、停電が長く続いても電力を送り続ける設備
- ポイント：動き出すまでに少し時間がかかるので、その間をUPSでつなぐ

#### ホットスワップ（ほっとすわっぷ / Hot Swap）

- 意味：電源を入れたまま、システムを止めずに部品（ディスク・電源ユニットなど）を取り外したり交換したりできること
- ポイント：活線挿抜とも呼ぶ。故障した部品の交換でシステムを止めずに済むので、可用性が上がる
- 語の意味：Hot＝電源が入ったまま／Swap＝取り替える

### 故障をあらわす言葉

#### フォールト（ふぉーると / Fault）

- 意味：システムの中にある、故障やまちがいのもとになる欠陥。部品の故障やプログラムの誤りなど
- ポイント：フォールトがあっても、それが働かなければ問題は表に出ない
- 語の意味：Fault＝欠陥

#### エラー（えらー / Error）

- 意味：フォールトが原因で、システムの内部の状態が正しい状態からずれていること
- ポイント：まだ外から見える故障（障害）になっていない段階

#### 障害（しょうがい / Failure）

- 意味：システムが、決められた機能を果たせなくなり、利用者から見て使えない状態になること
- ポイント：フォールト（原因）→エラー（内部のずれ）→障害（外から見える停止や誤り）の順につながる

#### 単一障害点（たんいつしょうがいてん / Single Point of Failure）

- 意味：そこが1か所壊れるだけでシステム全体が止まってしまう、多重化されていない部分
- ポイント：SPOFと略す。信頼性設計では、まず単一障害点をなくすように冗長化する

### 信頼性ブロック図

#### 信頼性ブロック図（しんらいせいぶろっくず / Reliability Block Diagram）

- 意味：システムを作る装置を箱で表し、直列や並列のつなぎ方で、全体がどの装置に頼って動いているかを表した図
- ポイント：この図から、全体の稼働率を計算する。どれか1つでも止まると止まる部分は直列、どれか1つ動けばよい部分は並列に描く
- 例：R3春 問14（稼働率 x の装置を2台直列にした組を2組並列にした図）、R5春 問16（並列部分と直列部分をもつ2つの図の稼働率を比べる）

#### 直列システム（ちょくれつしすてむ / Series System）

- 意味：全部の装置が動いているときだけ、システム全体が動く構成
- ポイント：稼働率は各装置の稼働率の積。装置を増やすほど稼働率は下がる
- 例：R7春 問13（2台並列にした組に、もう1台を直列につないだ構成の稼働率のグラフ→常に装置単体の稼働率より低い）

#### 並列システム（へいれつしすてむ / Parallel System）

- 意味：どれか1台でも動いていれば、システム全体が動く構成
- ポイント：稼働率は「1 − 全部が止まっている確率」。装置を増やすほど稼働率は上がる
- 例：R6秋 問14（2台並列・1台＋並列の直列・2台直列を2組並列、の3つを稼働率の高い順に並べる→2台並列が最も高い）

#### k-out-of-n システム（けいあうとおぶえぬしすてむ / k-out-of-n System）

- 意味：n台の装置のうち、k台以上が動いていればシステム全体が動く構成
- ポイント：3台中2台以上（2-out-of-3）が代表。稼働率 x の装置なら 3x² − 2x³

## 4-5 システムの性能

### まとめ表

**性能の指標**

| 指標 | 何を測るか | 主に使う場面 |
| :-: | :-: | :-: |
| レスポンスタイム | 要求を出し終えてから、最初の応答が返り始めるまでの時間 | 対話型処理・オンライン処理 |
| ターンアラウンドタイム | 処理を頼んでから、結果を全部受け取るまでの時間 | バッチ処理 |
| スループット | 決まった時間に処理できる仕事の量 | システム全体の処理能力 |
| 使用率（利用率） | 装置が動いていた時間の割合 | CPUやディスクの混み具合 |

**処理件数の計算（R3秋 問15・R4秋 問15・R6秋 問15の論点）**

- 処理がいくつかの段階に分かれ、段階どうしを重ねて実行できるとき、1件あたりの時間は「一番遅い段階（ボトルネック）」で決まる
- 例：読取り40ms・CPU30ms・書込み50msを重ねる→50msごとに1件終わる→1分（60,000ms）で 60,000÷50＝1,200件
- サーバとネットワークの両方を通る処理は、遅い方で決まる：サーバ 100MIPS÷100万命令＝100件／秒、ネットワーク 8×10⁷ビット÷8÷(2×10⁵バイト)＝50件／秒 → 50件／秒

**スケールの4つの言葉（R3秋 問12・R5春 問13・R5秋 問13の論点）**

| | 増やす | 減らす |
| :-: | :-: | :-: |
| 台数を変える | スケールアウト | スケールイン |
| 1台の能力を変える | スケールアップ | スケールダウン |

### 性能の指標

#### レスポンスタイム（れすぽんすたいむ / Response Time）

- 意味：利用者が要求の入力を終えてから、システムが応答を返し始めるまでの時間。応答時間
- ポイント：対話型の処理の速さを表す。全部の結果を受け取るまでではなく、最初の応答までを測る
- 語の意味：Response＝応答／Time＝時間

#### ターンアラウンドタイム（たーんあらうんどたいむ / Turnaround Time）

- 意味：処理を依頼してから、その結果を全部受け取り終わるまでの時間
- ポイント：バッチ処理の速さを表す。待ち時間・処理時間・結果を出力する時間を全部含む
- 語の意味：Turnaround＝一回りして戻ってくること

#### スループット（するーぷっと / Throughput）

- 意味：単位時間（1秒・1分など）あたりに、システムが処理できる仕事の量
- ポイント：「1分あたり何件」「1秒あたり何トランザクション」のように表す。処理を重ねて並行させると上がる
- 例：R3秋 問15（読取り40ms・CPU処理30ms・書込み50msを重ねて実行→1分当たり最大1,200件）、R4秋 問15（サーバとネットワークのうち遅い方で決まる→1秒当たり50件）
- 語の意味：Through＝通り抜ける／Put＝出す

#### 使用率（しようりつ / Utilization）

- 意味：ある期間のうち、装置（CPUやディスク）が実際に処理をしていた時間の割合
- ポイント：利用率とも呼ぶ。1に近いほど混んでいて、待ち時間が急に長くなる
- 例：R5春 問14（ジョブA・Bを順に実行したときのCPUと磁気ディスク装置の使用率→全体25秒のうちCPUは15秒で0.60、ディスクは17秒で0.68）

### 性能評価のやり方

#### ベンチマーク（べんちまーく / Benchmark）

- 意味：決められた標準のプログラム（テスト用の処理）を実際に動かし、かかった時間や処理量を測って、性能を比べる方法
- ポイント：実機で測るので結果が具体的。どの処理を使うかで結果が変わるので、目的に合ったものを選ぶ
- 語の意味：Benchmark＝基準点・水準点

#### シミュレーション（しみゅれーしょん / Simulation）

- 意味：システムの動きを模したモデルを作り、乱数などで要求を発生させてコンピュータ上で動かし、性能を数値で求める方法
- ポイント：式で解けない複雑なモデルでも、数値的に答えを求められる。そのかわり計算量は多く、結果に誤差を含む
- 例：R6春 問15（シミュレーションを用いた方法の特徴→解析的に解が求められないモデルに対しても、数値的に解が求まる）
- 語の意味：Simulation＝模擬・まねること

#### 解析的手法（かいせきてきしゅほう / Analytical Method）

- 意味：待ち行列理論などの数式でシステムをモデル化し、計算によって性能を求める方法
- ポイント：計算量が少なく、正確な値がすぐ出る。そのかわり、式で表せる単純なモデルにしか使えない
- 例：R6春 問15（シミュレーションは解析的な方法より計算量が少ない→誤り。少ないのは解析的な方法のほう）

#### モニタリング（もにたりんぐ / Monitoring）

- 意味：稼働しているシステムのCPU使用率・応答時間・処理件数などを継続して測り、記録して、性能や異常の兆しをつかむこと
- ポイント：測るための道具（ソフトウェアやハードウェア）をシステムモニタと呼ぶ。キャパシティプランニングの材料になる
- 語の意味：Monitor＝見張る

### 標準のベンチマーク

#### TPC（てぃーぴーしー / Transaction Processing Performance Council）

- 意味：トランザクション処理やデータベースの性能を測るベンチマークを定めている団体。また、そのベンチマーク
- ポイント：TPC-C（受注処理のようなオンライントランザクション処理）が代表。1分あたりの処理件数（tpmC）などで表す
- 語の意味：Transaction＝取引／Processing＝処理／Performance＝性能／Council＝協議会

#### SPEC（すぺっく / Standard Performance Evaluation Corporation）

- 意味：CPUやサーバの性能を測る標準のベンチマークを定めている団体。また、そのベンチマーク
- ポイント：CPUの整数演算はSPECint、浮動小数点演算はSPECfpで測る
- 語の意味：Standard＝標準の／Performance＝性能／Evaluation＝評価／Corporation＝法人

#### SPECint（すぺっくいんと / SPECint）

- 意味：SPECが定めたベンチマークのうち、CPUの整数演算の性能を測るもの
- ポイント：コンパイラや圧縮など、整数の計算が中心の処理を動かして測る。事務処理向けの性能の目安
- 語の意味：int＝integer（整数）

#### SPECfp（すぺっくえふぴー / SPECfp）

- 意味：SPECが定めたベンチマークのうち、CPUの浮動小数点演算の性能を測るもの
- ポイント：流体の計算など、科学技術計算に近い処理を動かして測る
- 語の意味：fp＝floating point（浮動小数点）

#### ギブソンミックス（ぎぶそんみっくす / Gibson Mix）

- 意味：科学技術計算でよく使われる命令の種類と出現の割合を決めた、命令ミックスの一つ
- ポイント：命令ごとの実行時間に出現の割合を掛けて足し、1命令の平均実行時間を求める。事務計算向けのものはコマーシャルミックス

### キャパシティプランニング

#### キャパシティプランニング（きゃぱしてぃぷらんにんぐ / Capacity Planning）

- 意味：システムに求められる処理の量や応答時間の目標から、必要なサーバやストレージの能力を見積もり、将来も目標を守れるように計画すること
- ポイント：今の性能を測るだけでなく、利用の増え方を予測して、増強の時期や量まで決める
- 例：R7秋 問14（目的の一つ→システムの現在の応答時間を調査し、長期的に監視することによって、将来を含めて応答時間を維持すること）
- 語の意味：Capacity＝能力・容量／Planning＝計画

#### サイジング（さいじんぐ / Sizing）

- 意味：求められる性能や処理量を満たすように、サーバのCPU・メモリ・ディスクの大きさや台数を決めること
- ポイント：キャパシティプランニングの中の、具体的な機器の大きさを決める作業
- 語の意味：Size＝大きさ

#### 容量・能力管理（ようりょうのうりょくかんり / Capacity Management）

- 意味：システムの資源の使われ方を継続して監視し、今と将来の需要に見合う容量や能力を、費用に見合う形で確保し続ける管理の活動
- ポイント：一度の計画で終わらず、運用しながら見直し続ける。ITサービスマネジメントの活動の一つ

#### パフォーマンスチューニング（ぱふぉーまんすちゅーにんぐ / Performance Tuning）

- 意味：今あるソフトウェアやハードウェアの設定を調整して、処理能力を最大限に引き出すこと
- ポイント：機器を増やさずに、今の構成のまま速くする。ボトルネックを見つけてそこを直すのが基本
- 例：R7秋 問14（ソフトウェアとハードウェアをチューニングして、現状の処理能力を最大限に引き出し、スループットを向上させる→キャパシティプランニングの目的ではない）
- 語の意味：Performance＝性能／Tuning＝調整

#### ボトルネック（ぼとるねっく / Bottleneck）

- 意味：システムの中で最も処理の遅い部分。全体の性能はここで決まってしまう
- ポイント：ボトルネック以外を速くしても全体は速くならない。重ねて実行する処理は、最も遅い段階の時間で1件ずつ終わる
- 例：R3秋 問15（書込みの50msが最も遅いので、50msごとに1件→1分で1,200件）、R7秋 問14（応答時間に最も影響があるボトルネックだけに着目して変更を行う→キャパシティプランニングの目的ではない）
- 語の意味：Bottleneck＝瓶の首（細くなって流れが詰まるところ）

### 性能の見積りに使う言葉

#### 負荷（ふか / Workload）

- 意味：システムに求められる処理の量。利用者の数、1時間あたりのトランザクションの数、データの量など
- ポイント：ワークロードとも呼ぶ。ピーク時（最も混む時間）の負荷で見積もる

#### 性能要件（せいのうようけん / Performance Requirement）

- 意味：システムが満たすべき性能の条件。「応答時間は3秒以内」「1時間に1万件を処理」など
- ポイント：キャパシティプランニングやサイジングの出発点になる

#### システムパラメータ（しすてむぱらめーた / System Parameter）

- 意味：OSやミドルウェアの動き方を決める設定値。同時に動かせる処理の数、バッファの大きさなど
- ポイント：システムの性能に大きく影響するので、負荷に合わせて調整する
- 語の意味：Parameter＝設定値・変数

#### プロビジョニング（ぷろびじょにんぐ / Provisioning）

- 意味：利用者の求めに応じて、サーバ・ストレージ・ネットワークなどの資源を割り当て、すぐ使える状態に準備すること
- ポイント：クラウドでは、画面やプログラムからの要求で自動的に行う
- 例：R7秋 問12（サーバなどの新規利用申請があった場合に、資源の割当て、設定などを手動で行う→IaCではない誤りの選択肢）
- 語の意味：Provision＝用意・供給

### スケールの方法

#### スケールアウト（すけーるあうと / Scale Out）

- 意味：サーバの台数を増やして、システム全体の処理能力を上げること
- ポイント：処理を分けて並行できるもの（参照中心の処理など）に向く。更新が多くデータの整合性を取る手間が大きい処理には向かない
- 例：R3秋 問12（システムを構成する物理サーバの台数を増やすことによって、処理能力を向上する→スケールインではない）、R5秋 問13（参照系のトランザクションが多いので、複数のサーバで分散処理を行っているシステムに適している）
- 語の意味：Scale＝規模／Out＝外へ（横に広げる）

#### スケールイン（すけーるいん / Scale In）

- 意味：サーバの台数を減らして、余っている資源を減らし、費用を抑えること
- ポイント：処理量に対して台数が多すぎるときに行う。台数を増やすスケールアウトの逆
- 例：R3秋 問12（物理サーバの台数を減らすことによって、システムとしてのリソースを最適化し、無駄なコストを削減する）、R5春 問13（想定されるシステムの処理量に対して、サーバの台数が過剰なとき、サーバの台数を減らすこと）
- 語の意味：Scale＝規模／In＝内へ（縮める）

#### スケールアップ（すけーるあっぷ / Scale Up）

- 意味：CPUを性能の高いものに替えたりメモリを増やしたりして、1台のサーバの処理能力を上げること
- ポイント：台数は変えない。分けにくい処理も速くなるが、1台の能力には上限がある
- 例：R3秋 問12（高い処理能力のCPUへの交換やメモリの追加などによって処理能力を向上する→スケールインではない）
- 語の意味：Scale＝規模／Up＝上へ

#### スケールダウン（すけーるだうん / Scale Down）

- 意味：CPUを性能の低いものに替えたりメモリを減らしたりして、1台のサーバの能力を下げ、費用を抑えること
- ポイント：台数は変えずに、1台の能力を下げる。スケールアップの逆
- 例：R5春 問13（想定されるCPU使用率に対して、サーバの能力が過剰なとき、CPUの能力を減らすこと→スケールインではない）
- 語の意味：Scale＝規模／Down＝下へ

#### オートスケーリング（おーとすけーりんぐ / Auto Scaling）

- 意味：負荷の増減に合わせて、サーバの台数（や能力）を自動的に増やしたり減らしたりするしくみ
- ポイント：クラウドでよく使われる。混む時間だけ台数を増やし、空いたら減らして費用を抑える
- 語の意味：Auto＝自動の／Scaling＝規模を変えること

## 4-6 信頼性と経済性の評価

### まとめ表

**信頼性の数値**

| 指標 | 意味 | 式・ポイント |
| :-: | :-: | :-: |
| MTBF | 故障と故障の間の平均の動いている時間 | 長いほどよい（信頼性） |
| MTTR | 故障してから直るまでの平均の時間 | 短いほどよい（保守性） |
| 稼働率 | 全体の時間のうち、動いている時間の割合 | MTBF ÷ (MTBF ＋ MTTR) |
| 故障率 | 単位時間あたりに故障する割合 | 1 ÷ MTBF |

- R4秋 問14：MTBFとMTTRがともに1.5倍→ 1.5MTBF ÷ (1.5MTBF＋1.5MTTR) なので稼働率は変わらない
- R7春 問12：稼働率 ＝ 1 ÷ (1 ＋ MTTR／MTBF)。稼働率が等しいなら MTTR／MTBF も等しい（MTBFやMTTRそれぞれが等しいとは限らない）
- R4春 問14：MTTRを短くするのは「直す時間」を縮めるもの（エラーログ、遠隔保守）。MTBFを長くするのは「故障しにくくする・故障を隠す」もの（予防保守、ECC、命令再試行）

**RASIS（システムを評価する5つの観点）**

| 観点 | 意味 | 指標 |
| :-: | :-: | :-: |
| Reliability（信頼性） | 故障しにくい | MTBF |
| Availability（可用性） | 使いたいときに使える | 稼働率 |
| Serviceability（保守性） | 直しやすい | MTTR |
| Integrity（完全性） | データが壊れず矛盾しない | ― |
| Security（安全性） | 不正に使われない・漏れない | ― |

**経済性（TCO）**

| 分け方 | 中身 |
| :-: | :-: |
| 初期コスト（イニシャルコスト） | 機器・ソフトの購入、開発、導入の費用 |
| 運用コスト（ランニングコスト） | 保守料、電気代、回線料、運用する人の人件費 |
| 直接コスト | 機器や保守料など、費用として直接見えるもの |
| 間接コスト | 利用者が自分で直す時間や、止まっている間の損失など、見えにくいもの |

### RASIS

#### 信頼性（しんらいせい / Reliability）

- 意味：システムが故障せずに、決められた機能を果たし続けられる度合い
- ポイント：RASISのR。MTBF（故障と故障の間の平均の時間）で表す

#### 可用性（かようせい / Availability）

- 意味：使いたいときに、システムが使える状態にある度合い
- ポイント：RASISのA。稼働率で表す。故障しにくいことと、すぐ直ることの両方で上がる

#### 保守性（ほしゅせい / Serviceability）

- 意味：故障したときに、原因を見つけて直しやすい度合い
- ポイント：RASISの1つめのS。MTTR（直るまでの平均の時間）で表す

#### 完全性（かんぜんせい / Integrity）

- 意味：データが壊れたり、矛盾した状態になったりせず、正しく保たれている度合い
- ポイント：RASISのI。障害が起きても、データの一貫性が保たれることを指す

#### 安全性（あんぜんせい / Security）

- 意味：不正なアクセスや情報の漏えい・改ざんから、システムとデータが守られている度合い
- ポイント：RASISの2つめのS。機密性とも言い換えられる

### 信頼性の数値

#### RASIS（らしす / RASIS）

- 意味：信頼性・可用性・保守性・完全性・安全性の5つの頭文字を並べた、システムを評価する観点
- ポイント：前の3つ（RAS）はMTBF・稼働率・MTTRで数値にできる
- 語の意味：Reliability＝信頼性／Availability＝可用性／Serviceability＝保守性／Integrity＝完全性／Security＝安全性

#### MTBF（えむてぃーびーえふ / Mean Time Between Failures）

- 意味：故障が直ってから次に故障するまでの、動いている時間の平均。平均故障間動作時間
- ポイント：長いほど故障しにくい（信頼性が高い）。「運用を始めてから初めて故障するまでの時間」ではない
- 例：R7秋 問13（MTBFは正常なシステムが運用を開始してから初めて故障が起きるまでの時間→誤り）
- 語の意味：Mean＝平均の／Time＝時間／Between＝〜の間の／Failures＝故障

#### MTTR（えむてぃーてぃーあーる / Mean Time To Repair）

- 意味：故障が起きてから、直して再び動き出すまでの時間の平均。平均修復時間
- ポイント：短いほど直しやすい（保守性が高い）。エラーログを残す、遠隔保守をする、などで短くできる
- 例：R4春 問14（MTBFを長くするよりも、MTTRを短くするのに役立つもの→エラーログ取得機能）
- 語の意味：Mean＝平均の／Time＝時間／To Repair＝修理するまでの

#### 稼働率（かどうりつ / Availability Ratio）

- 意味：全体の時間のうち、システムが正常に動いている時間の割合。MTBF ÷ (MTBF ＋ MTTR) で求める
- ポイント：MTBFとMTTRを同じ倍率にしても変わらない。直列は掛け算、並列は「1 − 全部止まる確率」で計算する
- 例：R4秋 問14（MTBFとMTTRがともに1.5倍→変わらない）、R7秋 問13（MTBF÷(MTBF＋MTTR)はシステムが稼働している時間の割合を表す）、R4春 問15（稼働率0.7と0.6のプリンタで、いずれか一方だけが稼働している確率→0.7×0.4＋0.3×0.6＝0.46）

#### 故障率（こしょうりつ / Failure Rate）

- 意味：単位時間あたりに故障が起きる割合。MTBFの逆数（1 ÷ MTBF）
- ポイント：MTBFが100時間なら、故障率は1時間あたり0.01。直列につないだシステムの故障率は、各装置の故障率の和で近似できる

#### MTTF（えむてぃーてぃーえふ / Mean Time To Failure）

- 意味：使い始めてから故障するまでの時間の平均。直さずに使い捨てる部品の寿命の目安
- ポイント：修理して使い続けるものはMTBF、修理しないものはMTTFで表す
- 語の意味：Mean＝平均の／Time＝時間／To Failure＝故障するまでの

### 故障の時期

#### バスタブ曲線（ばすたぶきょくせん / Bathtub Curve）

- 意味：機器を使い始めてからの時間と故障率の関係を表したグラフ。はじめ高く、しばらく低く安定し、最後にまた高くなる
- ポイント：形が浴槽（バスタブ）の断面に似ている。初期故障期・偶発故障期・摩耗故障期の3つに分かれる
- 語の意味：Bathtub＝浴槽／Curve＝曲線

#### 初期故障期（しょきこしょうき / Early Failure Period）

- 意味：使い始めてすぐの、設計や製造の不良による故障が多く起きる時期
- ポイント：故障率は時間とともに下がっていく。出荷前の試運転（エージング）や検査で減らす

#### 偶発故障期（ぐうはつこしょうき / Random Failure Period）

- 意味：初期の不良が出尽くした後の、故障率が低く、ほぼ一定になる時期
- ポイント：故障はいつ起きるか予測できない偶然のもの。機器を使う期間の大半がこの時期

#### 摩耗故障期（まもうこしょうき / Wear-out Failure Period）

- 意味：長く使って部品がすり減ったり劣化したりして、故障率が再び上がっていく時期
- ポイント：寿命が近いので、予防保守で部品を交換したり、機器を更新したりする

### 保守のしかた

#### 予防保守（よぼうほしゅ / Preventive Maintenance）

- 意味：故障が起きる前に、点検や部品の交換を計画的に行って、故障を防ぐこと
- ポイント：予防保全とも呼ぶ。故障しにくくするので、MTTRではなくMTBFを長くする
- 例：R4春 問14（予防保全はMTBFを長くするもので、MTTRを短くするものではない）

#### 事後保守（じごほしゅ / Corrective Maintenance）

- 意味：故障が起きてから、原因を調べて修理すること
- ポイント：事後保全とも呼ぶ。止まっても困らない機器や、故障を予測しにくい機器に使う

#### 遠隔保守（えんかくほしゅ / Remote Maintenance）

- 意味：保守の担当者が現地に行かずに、通信回線を通じて離れた場所からシステムの状態を調べたり直したりすること
- ポイント：駆けつける時間がかからないので、MTTRが短くなる

#### エラーログ（えらーろぐ / Error Log）

- 意味：システムで起きた異常やエラーの内容・時刻などを、自動的に記録したもの
- ポイント：故障の原因を早く突き止められるので、MTTRを短くするのに役立つ
- 例：R4春 問14（MTBFを長くするよりも、MTTRを短くするのに役立つもの→エラーログ取得機能）
- 語の意味：Error＝誤り／Log＝記録

### コストの分け方

#### TCO（てぃーしーおー / Total Cost of Ownership）

- 意味：システムを導入してから使い終わるまでにかかる費用の総額。買うときの費用と、使い続ける間の費用を全部合わせたもの
- ポイント：初期コストと運用コストの合計。買うときの値段だけでなく、運用・保守・教育など目に見えにくい費用まで含めて比べる。総所有費用
- 語の意味：Total＝合計の／Cost＝費用／Ownership＝所有

#### 初期コスト（しょきこすと / Initial Cost）

- 意味：システムを使い始めるまでにかかる費用。機器やソフトの購入、開発、導入作業など
- ポイント：イニシャルコストとも呼ぶ。一度だけかかる費用

#### 運用コスト（うんようこすと / Running Cost）

- 意味：システムを使い続ける間、毎月・毎年かかる費用。保守料・電気代・回線料・運用する人の人件費など
- ポイント：ランニングコストとも呼ぶ。長く使うほど、初期コストより大きくなることが多い

#### 直接コスト（ちょくせつこすと / Direct Cost）

- 意味：機器の購入費や保守料のように、システムのために払ったことがはっきりわかる費用
- ポイント：見積りや請求書に出てくる費用

#### 間接コスト（かんせつこすと / Indirect Cost）

- 意味：利用者が自分で操作を調べたりトラブルに対応したりする時間や、システムが止まっている間の損失など、見えにくい費用
- ポイント：TCOではこれも含めて考える。見落とすと、安く見えた製品が結局高くつくことがある
