## 7-1 ユーザーインタフェース技術

### まとめ表

### 情報アーキテクチャ

#### 情報アーキテクチャ（じょうほうあーきてくちゃ / Information Architecture）

- 意味：利用者が必要な情報を見つけて理解できるように、情報を分類・構造化し、名前（ラベル）と案内（ナビゲーション）を決める考え方
- ポイント：情報の「組織化」（五十音・カテゴリ・時間などで分ける）と「構造化」（階層型・タグ付けなどで並べる）の2つが柱。見た目のデザインより前に決める骨組み
- 語の意味：Information＝情報／Architecture＝建築・構造

#### ラベル（Label）

- 意味：メニューやリンク、見出しに付ける名前。押した先に何があるかを短い言葉で伝える
- ポイント：作り手の社内用語ではなく、利用者が使う言葉で付ける。ラベルがあいまいだと、利用者は押してみるまで中身が分からない

#### チャンク（Chunk）

- 意味：人がひとまとまりとして覚えたり理解したりできる情報のかたまり
- ポイント：人が一度に覚えられるのは数個のチャンクまで。電話番号を3つに区切って書く、長い説明を見出しで区切るなど、情報を小さな単位に分けると理解しやすくなる

#### ナビゲーション（Navigation）

- 意味：利用者が今どこにいて、どこへ行けるかを示し、目的のページまで案内するしくみ。これを設計することをナビゲーションデザインと呼び、ナビゲーションバーやパンくずリストで作る
- ポイント：グローバルナビゲーション（全ページ共通のメニュー）・ローカルナビゲーション（その分類の中のメニュー）・パンくずリストなどの部品で作る
- 例：R3春 問26（今いるページまでの経路を示す部品）

#### メタデータ（Metadata）

- 意味：データについてのデータ。作成者・作成日・分類・キーワードなど、本体の中身を説明する情報
- ポイント：情報アーキテクチャでは、メタデータを付けておくと検索や並べ替え、関連ページの表示ができる。写真の撮影日時・場所（Exif）もメタデータ
- 語の意味：Meta＝一段上の・について／Data＝データ

### サイトの構造

#### 階層型（かいそうがた / Hierarchical Structure）

- 意味：トップから大分類・中分類・小分類へと、木の枝のように情報を分けていく構造
- ポイント：最もよく使われる構造。階層が深すぎると目的のページまで何度も押すことになるので、浅く広くするのが基本

#### 直線型（ちょくせんがた / Linear Structure）

- 意味：決まった順番に1ページずつ進む構造
- ポイント：申込みや購入の手続き、学習の教材のように、順番どおりに読ませたい内容に向く。途中のページに直接は行きにくい

#### Webリンク型（うぇぶりんくがた / Web Link Structure）

- 意味：ページどうしが上下関係なく、自由にリンクでつながる構造
- ポイント：関連する情報をたどりやすいが、今どこにいるか分からなくなりやすい。百科事典やWikiの形

#### フォークソノミー型（ふぉーくそのみーがた / Folksonomy）

- 意味：作り手が決めた分類ではなく、利用者が自由に付けたタグによって情報を分類する構造
- ポイント：folk（人々）とtaxonomy（分類法）を合わせた造語。同じタグの付いた情報を集めて見られる。言葉の揺れ（同じ意味の別のタグ）が起きやすい
- 語の意味：Folk＝人々／Taxonomy＝分類学

#### セマンティックWeb（せまんてぃっくうぇぶ / Semantic Web）

- 意味：Webページの情報に「意味」を表すメタデータを付け、コンピュータが内容を理解して処理できるようにする考え方
- ポイント：W3Cが提唱。RDFなどの形式で「この文字列は人名」「この数字は価格」といった意味を書く。人が読むための文章だけでなく、機械が読めるデータにする点が違い
- 語の意味：Semantic＝意味の／Web＝WWW

### 使いやすさの性質

#### ユーザビリティ（Usability）

- 意味：特定の利用者が、特定の利用状況で、特定の目標を達成するために使うときの、有効さ・効率・満足度の度合い（ISO 9241-11の定義）
- ポイント：「その人がその場面で使いやすいか」。アクセシビリティ（障害や年齢にかかわらず使えるか）と区別する
- 例：R4春 問24・R7春 問22（ユーザビリティの評価手法）
- 語の意味：Use＝使う／-ability＝できること

#### アクセシビリティ（Accessibility）

- 意味：高齢者や障害のある人を含め、できるだけ多くの人が情報や機能を利用できること
- ポイント：画像に代替テキストを付ける、色だけで情報を伝えない、キーボードだけで操作できるなど。規格はJIS X 8341、Webの指針はWCAG
- 語の意味：Access＝近づく・利用する／-ability＝できること

#### インタラクティブシステム（Interactive System）

- 意味：利用者の操作に応じて、システムがその場で反応を返し、やり取りしながら進むシステム
- ポイント：一度に全部を指示して結果だけを受け取るバッチ処理と反対の形。ISO 9241はインタラクティブシステムの人間工学の規格
- 語の意味：Interactive＝対話的な／System＝仕組み

#### インタラクションの原則（いんたらくしょんのげんそく / Interaction Principles）

- 意味：利用者とシステムのやり取りを設計するときの原則。ISO 9241-110（JIS Z 8520）で、仕事への適合性・自己記述性・期待への一致・エラーへの耐性などを定める
- ポイント：「今なにができるかが画面から分かる（自己記述性）」「利用者の予想どおりに動く（期待への一致）」「間違えても直せる（エラーへの耐性）」が試験の言い回しによく出る

#### ヒューマンインタフェース（Human Interface）

- 意味：人とコンピュータ（機械）が情報をやり取りする接点。画面・キーボード・音声などの全体
- ポイント：ユーザーインタフェースとほぼ同じ意味で使う。人の感覚・認知・身体の特性に合わせて設計する点を強調した言い方
- 語の意味：Human＝人間／Interface＝接点

#### 身体的適合性（しんたいてきてきごうせい / Physical Compatibility）

- 意味：機器の大きさ・形・操作に必要な力などが、利用者の体の特性に合っていること
- ポイント：ボタンが指で押せる大きさか、片手で持てるかなど。エルゴノミクス（人間工学）の考え方を使う

### 認識の技術と人の特性

#### 音声認識（おんせいにんしき / Speech Recognition）

- 意味：人の話した声をコンピュータが聞き取り、文字や命令に変換する技術
- ポイント：音声で操作するVUIやスマートスピーカーの土台。話した人が誰かを当てる「話者認識」とは別

#### 画像認識（がぞうにんしき / Image Recognition）

- 意味：画像に何が写っているかをコンピュータが判別する技術
- ポイント：顔認証・文字の読取り（OCR）・ジェスチャーの読取りに使う。ディープラーニングで精度が大きく上がった

#### 動画認識（どうがにんしき / Video Recognition）

- 意味：動画の連続した画像から、人や物の動き・行動を判別する技術
- ポイント：1枚の画像ではなく時間の変化を見る。ジェスチャー操作や防犯カメラの異常検知に使う

#### 特徴抽出（とくちょうちゅうしゅつ / Feature Extraction）

- 意味：音声や画像などのデータから、判別の手がかりになる特徴（輪郭・色・周波数など）を取り出す処理
- ポイント：認識の前段の処理。特徴を取り出してから、学習済みのパターンと照らし合わせて判別する

#### 学習機能（がくしゅうきのう / Learning Function）

- 意味：利用者の使い方や入力の結果から学び、認識の精度や提案を良くしていく機能
- ポイント：日本語入力の変換候補が、よく使う言葉から順に出るようになるのが身近な例

#### 選択的知覚（せんたくてきちかく / Selective Perception）

- 意味：人は周りの情報を全部受け取るのではなく、関心のあるものや目立つものだけを選んで知覚するという性質
- ポイント：騒がしい場所でも自分の名前は聞き取れる（カクテルパーティー効果）。大事な情報は色や位置で目立たせないと見落とされる、という画面設計の根拠になる

#### ユーザー操作の分析（ゆーざーそうさのぶんせき / User Operation Analysis）

- 意味：利用者が実際にどこを押し、どこで迷い、どれだけ時間がかかったかを記録して調べること
- ポイント：アクセスログ・操作ログ・アイトラッキングなどのデータを使う。設計の改善点を見つける

### 操作の手がかり

#### シグニファイア（Signifier）

- 意味：「ここを押せる」「ここを引ける」と、どう操作すればよいかを利用者に伝える手がかり（表示や形）
- ポイント：アフォーダンス（物と人の間にある、行為の可能性そのもの）と区別する。ボタンの影、リンクの下線、ドアの「押す」の表示などがシグニファイア。ノーマンが整理した
- 語の意味：Signify＝示す・意味する／-er＝もの

#### アフォーダンス（Affordance）

- 意味：物の形や性質が、人にとってどんな行為を可能にしているかという関係
- ポイント：取っ手の付いた扉は「引ける」ことをアフォードする。画面設計では、押せそうな見た目かどうかの意味で使われることが多いが、それを伝える表示を特にシグニファイアと呼ぶ
- 語の意味：Afford＝与える・できる

#### メンタルモデル（Mental Model）

- 意味：利用者が頭の中に持っている「これはこう動くはず」という思い込みのモデル
- ポイント：システムの動きがメンタルモデルと合っていれば迷わない。ごみ箱のアイコンに入れると消える、のように現実の物に似せるのはメンタルモデルに合わせる工夫

#### フィードバック（UI）（ふぃーどばっく / Feedback）

- 意味：利用者の操作に対して、システムが受け付けたことや結果を、表示・音・振動ですぐに返すこと
- ポイント：ボタンを押したら色が変わる、処理中は進み具合を表示する、など。返事がないと利用者は何度も押してしまう

### インタフェースの種類

#### CUI（しーゆーあい / Character User Interface）

- 意味：キーボードから文字で命令を入力して操作するインタフェース
- ポイント：コマンドを覚える必要があるが、決まった操作を速く、まとめて実行できる。CLI（Command Line Interface）とも呼ぶ
- 語の意味：Character＝文字／User＝利用者／Interface＝接点

#### GUI（じーゆーあい / Graphical User Interface）

- 意味：ウィンドウ・アイコン・ボタンなどの図を、マウスやタッチで操作するインタフェース
- ポイント：見て分かるので覚えることが少ない。WIMP（Window・Icon・Menu・Pointer）とも呼ばれる構成
- 語の意味：Graphical＝図による／User＝利用者／Interface＝接点

#### NUI（えぬゆーあい / Natural User Interface）

- 意味：触る・話す・身ぶりをするなど、人の自然な動作で直感的に操作するインタフェース
- ポイント：タッチ・音声・ジェスチャー・視線などをまとめた考え方。マウスやキーボードの使い方を覚えなくてよい
- 語の意味：Natural＝自然な／User＝利用者／Interface＝接点

#### VUI（ぶいゆーあい / Voice User Interface）

- 意味：声で話しかけて操作し、音声で答えが返ってくるインタフェース
- ポイント：スマートスピーカー・カーナビ。手や目がふさがっていても使えるが、画面がないので選択肢を多く並べるのは苦手
- 語の意味：Voice＝声／User＝利用者／Interface＝接点

#### ノンバーバルインタフェース（Nonverbal Interface）

- 意味：言葉を使わず、表情・視線・身ぶり・しぐさなどで情報をやり取りするインタフェース
- ポイント：自然言語インタフェース（言葉で操作）と反対。表情からの感情の推定などを含む
- 語の意味：Non＝ない／Verbal＝言葉の

#### マルチモーダルインタフェース（Multimodal Interface）

- 意味：音声・タッチ・ジェスチャー・視線など、複数の入出力の手段を組み合わせて使えるインタフェース
- ポイント：「この（指さし）を消して」と声と指を同時に使う、など。1つの手段が使えない人や場面でも、別の手段で操作できる
- 語の意味：Multi＝複数の／Modal＝様式の

#### 空間型インタフェース（くうかんがたいんたふぇーす / Spatial Interface）

- 意味：画面の中だけでなく、周りの3次元の空間に情報を置き、その中で手や体を動かして操作するインタフェース
- ポイント：VR・ARのゴーグルで、空中に浮かぶ画面を手でつかむ操作など

#### 自然言語インタフェース（しぜんげんごいんたふぇーす / Natural Language Interface）

- 意味：人がふだん使う言葉（日本語の文章など）で質問や命令をすると、システムが理解して応じるインタフェース
- ポイント：チャットボットや生成AIへの指示。決まったコマンドを覚えなくてよい

#### ジェスチャーインタフェース（Gesture Interface）

- 意味：手や体の動き（身ぶり）をカメラやセンサーで読み取って操作するインタフェース
- ポイント：画面に触れない操作も含む。手を振って次のページへ、など

#### マルチタッチインタフェース（Multi-touch Interface）

- 意味：画面の複数の点に同時に触れて操作できるインタフェース
- ポイント：2本の指でつまんで縮める・広げて拡大する（ピンチ）が代表。スマートフォンやタブレットの基本の操作
- 語の意味：Multi＝複数の／Touch＝触れる

### タッチの操作

#### タップ（Tap）

- 意味：画面を指で1回軽くたたく操作。マウスのクリックに当たる
- ポイント：2回続けてたたくのがダブルタップ（拡大などに使う）

#### スワイプ（Swipe）

- 意味：画面に触れたまま、指を一定の距離すべらせる操作
- ポイント：ページの切替え・ロックの解除。フリックより長く、ゆっくり動かす

#### フリック（Flick）

- 意味：画面に触れた指を、素早くはじくように払う操作
- ポイント：スクロールを勢いよく進める、文字入力で上下左右に払って文字を選ぶ（フリック入力）など。スワイプより短く速い

#### ピンチ（Pinch）

- 意味：2本の指で画面をつまむように狭める（ピンチイン）・広げる（ピンチアウト）操作
- ポイント：ピンチインで縮小、ピンチアウトで拡大。マルチタッチでないとできない

#### ロングプレス（Long Press）

- 意味：画面の同じ場所を長く押し続ける操作。長押し
- ポイント：補足のメニューを出す、アイコンを動かせる状態にするなど、マウスの右クリックに近い使い方をする

#### ドラッグ（Drag）

- 意味：物をつかんだまま動かす操作。タッチでは触れたまま指を動かし、マウスではボタンを押したまま動かす
- ポイント：アイコンの移動・範囲の選択。目的の場所で放す操作までをドラッグアンドドロップと呼ぶ

### UIの組み立て方

#### オブジェクト指向UI（おぶじぇくとしこうゆーあい / OOUI: Object-Oriented User Interface）

- 意味：先に操作の対象（もの）を選び、その後でそれに対する操作（こと）を選ぶ「名詞→動詞」の順のUI
- ポイント：メールの一覧からメールを選び、そこで「返信」「削除」を選ぶ形。利用者が自由な順番で作業できる。タスク指向UIと対で問われる
- 語の意味：Object＝もの・対象／Oriented＝向きの／User Interface＝利用者との接点

#### タスク指向UI（たすくしこうゆーあい / Task-Oriented User Interface）

- 意味：先にやりたいこと（操作）を選び、その手順に沿って対象を指定していく「動詞→名詞」の順のUI
- ポイント：「振込み」を選んでから口座・金額を入れるATMのような形。手順が決まった作業に向き、迷いにくいが、順番を変えにくい

#### モーダル（Modal）

- 意味：その画面（ウィンドウ）を閉じるか応答するまで、ほかの操作ができない状態。この状態で開く画面がモーダルウィンドウ
- ポイント：保存の確認ダイアログなど。大事な確認には向くが、多用すると作業が止まって煩わしい。モーダルウィンドウはR6秋 問25の誤答
- 語の意味：Mode＝様式・状態

#### モードレス（Modeless）

- 意味：画面を開いたままでも、ほかのウィンドウを並行して操作できる状態
- ポイント：検索と置換のウィンドウを開いたまま本文を編集できる、など。モーダルと反対
- 語の意味：Mode＝状態／-less＝ない

### 画面の基本の部品

#### ウィンドウ（Window）

- 意味：画面の中で、1つのアプリや文書を表示する四角い区画
- ポイント：複数を重ねて表示し、切り替えて作業できる。GUIの基本の部品

#### アイコン（Icon）

- 意味：ファイル・機能・アプリなどを、小さな絵で表したもの
- ポイント：JIS X 9303-1では、アイコンの性質として、意味が理解された後に容易に思い出せるかを示す「習得性」などを定めている
- 例：R5秋 問24（アイコンの習得性）

#### テキストボックス（Text Box）

- 意味：利用者が文字を自由に入力するための枠
- ポイント：入力される内容が決まっているなら、選ぶ部品（ラジオボタンなど）にしたほうが入力の間違いが減る。1行用と複数行用（テキストエリア）がある

#### ダイアログボックス（Dialog Box）

- 意味：確認やエラーの通知、設定の入力のために、一時的に表示される小さなウィンドウ
- ポイント：「保存しますか？ はい／いいえ」など、利用者との対話（ダイアログ）に使う。多くはモーダル

### 選ぶ部品

#### ラジオボタン（Radio Button）

- 意味：複数の選択肢の中から1つだけを選ばせる、丸い印の部品
- ポイント：1つを選ぶと、ほかの選択が外れる。昔のラジオの選局ボタンが名前の由来。選択肢を全部見せられる少ない数（2〜5個ほど）に向く。ラジオボックスとも呼ぶ

#### チェックボックス（Check Box）

- 意味：当てはまる選択肢をいくつでも選べる、四角い印の部品
- ポイント：0個でも全部でも選べる。「1つだけ」ならラジオボタン、「いくつでも」ならチェックボックス

#### トグルボタン（Toggle Button）

- 意味：押すたびにオンとオフが切り替わるボタン
- ポイント：スマートフォンの設定画面のスイッチ。押した瞬間に設定が反映されるのが一般的
- 語の意味：Toggle＝切り替える

#### リストボックス（List Box）

- 意味：選択肢を一覧の形で表示し、その中から選ばせる部品
- ポイント：いくつかの選択肢が常に見えている。数が多いとスクロールして選ぶ。複数を選べる設定もある

#### プルダウンメニュー（Pull-down Menu）

- 意味：押すと下に選択肢の一覧が開き、その中から1つを選ぶ部品。ドロップダウンリストとも呼ぶ
- ポイント：閉じているときは選んだ1つだけが表示されるので、画面を節約できる。都道府県のように選択肢が多いときに向く。ドロップダウンメニューはR7秋 問24の誤答
- 語の意味：Pull＝引く／Down＝下へ

#### コンボボックス（Combo Box）

- 意味：一覧から選ぶこともでき、直接文字を入力することもできる部品
- ポイント：テキストボックスとリスト（プルダウン）を組み合わせた（combination）もの。一覧にない値も入れられる

### 開いて出す部品

#### ポップアップメニュー（Pop-up Menu）

- 意味：画面上の操作した場所に、その場で浮き上がるように表示されるメニュー
- ポイント：右クリックやロングプレスで出るメニュー（コンテキストメニュー）。選んだ対象に合った項目だけが出る
- 語の意味：Pop up＝飛び出す

#### ハンバーガーメニュー（Hamburger Menu）

- 意味：三本線のアイコンを押すと、隠れていたメニューが表示されるしくみ
- ポイント：三本線がハンバーガーに見えるのが名前の由来。スマートフォンのように画面が狭く、常にメニューを表示しておくのが難しいときに使う
- 例：R7秋 問24

#### アコーディオン（Accordion）

- 意味：見出しを押すと、その下の詳しい内容が開き、もう一度押すと閉じる部品
- ポイント：楽器のアコーディオンが伸び縮みするように開閉する。よくある質問（FAQ）の一覧に多い。R6秋 問25・R7秋 問24の誤答

#### タブ（Tab）

- 意味：画面の上部などに並んだ見出しを選ぶと、表示する中身が切り替わる部品
- ポイント：同じ場所に複数の画面を重ねて、見出しで切り替える。ノートの見出しのインデックスが名前の由来。R6秋 問25の誤答

#### カルーセル（Carousel）

- 意味：決まった表示領域の中で、複数の画像などが横方向に順に入れ替わって表示される部品
- ポイント：回転木馬（カルーセル）が名前の由来。矢印やスワイプで送り、下の点で今何枚目かを示す。トップページのおすすめ商品などに使う
- 例：R6秋 問25

#### モーダルウィンドウ（Modal Window）

- 意味：開いている間、後ろの画面の操作ができなくなる（モーダルな）ウィンドウ
- ポイント：後ろの画面を暗くして手前に表示することが多い。閉じるまで先に進めないので、大事な確認や入力に使う
- 語の意味：Modal＝モード（状態）の／Window＝窓

### 案内の部品

#### パンくずリスト（ぱんくずりすと / Breadcrumb List）

- 意味：今見ているページが、トップページからどの経路でたどれるかを「トップ ＞ 分類 ＞ 今のページ」のように並べたもの
- ポイント：童話「ヘンゼルとグレーテル」で帰り道にパンくずを落とした話が由来。上の階層へ1回で戻れる
- 例：R3春 問26

#### サイトマップ（Site Map）

- 意味：Webサイトにあるページ全体を、構造が分かるように一覧にしたページ
- ポイント：サイト全体の地図。今いるページまでの経路を示すパンくずリストとは役目が違う

#### ナビゲーションバー（Navigation Bar）

- 意味：サイトのナビゲーションの部品の1つで、ページの上部などに、主な分類へのリンクを横一列に並べた帯
- ポイント：どのページにも同じ場所に表示して、サイトの主な入り口にする（グローバルナビゲーション）

#### スクロールバー（Scroll Bar）

- 意味：画面に入りきらない内容を上下・左右に動かして見るための棒
- ポイント：つまみの位置で全体のどこを見ているか、つまみの長さで全体に対する表示の割合が分かる

#### ツールチップ（Tooltip）

- 意味：ボタンやアイコンにマウスポインターを重ねると表示される、短い説明の吹き出し
- ポイント：アイコンだけでは意味が分かりにくいときの補足。ホバーしたときに出る。タッチ操作では出しにくい

#### ホバー（Hover）

- 意味：マウスポインターを、押さずに要素の上に重ねている状態。そのとき表示を変えることをロールオーバーとも呼ぶ
- ポイント：リンクの色が変わる、ツールチップが出るなど、押せることを伝えるのに使う。タッチ画面には「重ねるだけ」の状態がないので、大事な情報をホバーだけで出すのは避ける
- 語の意味：Hover＝空中に浮かぶ・とどまる

### 文字の表示

#### ビットマップフォント（Bitmap Font）

- 意味：文字の形を、点（ドット）の並びで表したフォント
- ポイント：決まった大きさでは表示が速く、くっきりしているが、拡大すると点が目立ってギザギザになる。大きさごとにデータが必要
- 例：R3秋 問24・R6春 問24（アウトラインフォントとの比較）
- 語の意味：Bit＝ビット／Map＝配置図

#### アウトラインフォント（Outline Font）

- 意味：文字の輪郭を、座標と線・曲線の式で表したフォント
- ポイント：計算して描くので、どんな倍率に拡大・縮小しても滑らかに表示できる。TrueType・OpenTypeが代表
- 例：R3秋 問24・R6春 問24（文字を任意の倍率に拡大して表示する場合）
- 語の意味：Outline＝輪郭

#### 等幅フォント（とうはばふぉんと / Monospaced Font）

- 意味：どの文字も同じ幅で表示されるフォント
- ポイント：桁がそろうので、プログラムのソースコードや表の数字に向く。「各文字の幅を一定にして表示する」のは、アウトラインかビットマップかとは関係ない

#### プロポーショナルフォント（Proportional Font）

- 意味：文字ごとに形に合わせた幅で表示されるフォント
- ポイント：「i」は狭く「m」は広い。文章が読みやすく、詰まって見える。等幅フォントと反対

## 7-2 UX/UIデザイン

### まとめ表

**UXデザインの五段階モデル（下から上へ、抽象から具体へ）**

| 段階 | 決めること | 作るもの |
| :-: | :-: | :-: |
| 表層 | 色・文字・画像などの見た目 | ビジュアルデザイン |
| 骨格 | 画面のどこに何を置くか | ワイヤーフレーム |
| 構造 | 画面や情報のつながり・流れ | サイトの構造図・画面遷移 |
| 要件 | どんな機能・内容を用意するか | 機能の一覧 |
| 戦略 | 誰のために何を目指すか | 利用者のニーズと事業の目的 |

**入力チェックの種類**

| チェック | 調べること | 例 |
| :-: | :-: | :-: |
| ニューメリックチェック | 数字であるべき項目が数字か | 数量に「１０個」と文字が入っていない |
| フォーマットチェック | 決まった形式・桁数か | 日付が YYYY-MM-DD の形 |
| リミットチェック | 値が決まった範囲の中か | 月が1〜12 |
| 組合せチェック | 複数の項目の組合せが正しいか | 2月30日は存在しない |
| 照合チェック | マスターに登録された値か | 入力した商品コードが商品表にある |
| バランスチェック | 合計など、別々に求めた値が一致するか | 借方の合計＝貸方の合計 |
| チェックキャラクター | 検査用の数字（文字）が計算と合うか | コードの最後の1桁で打ち間違いを検出 |

**ユーザビリティ評価の手法（誰が参加するか）**

| 手法 | 参加する人 | やり方 |
| :-: | :-: | :-: |
| ヒューリスティック評価 | 専門家だけ | 経験則（ガイドライン）に照らして問題点を探す |
| 認知的ウォークスルー | 専門家だけ | 利用者になったつもりで操作の手順を1つずつたどる |
| 思考発話法 | 利用者 | 考えていることを声に出しながら操作してもらう |
| 回顧法 | 利用者 | 操作が終わった後に、録画などを見ながら振り返ってもらう |
| アイトラッキング分析 | 利用者 | 視線の動きを機器で記録する |
| NEM | 利用者（初心者と熟練者） | 同じ操作の時間を比べ、差の大きい手順を問題とみる |
| A/Bテスト | 利用者（実際の訪問者） | 2つの案を振り分けて、成果の良いほうを選ぶ |

### UXデザイン

#### UX（ゆーえっくす / User Experience）

- 意味：製品やサービスを使う前・使っている間・使った後に、利用者が得る体験の全体（楽しさ・便利さ・安心感など）
- ポイント：UI（画面や操作の接点）は、UXをつくる手段の1つ。「使いやすい」（ユーザビリティ）だけでなく「使いたい」「また使いたい」まで含む
- 語の意味：User＝利用者／Experience＝体験

#### UXデザインの五段階モデル（ゆーえっくすでざいんのごだんかいもでる / The Elements of User Experience）

- 意味：UXの設計を、戦略・要件・構造・骨格・表層の5段階に分け、抽象的な段階から具体的な段階へ順に決めていくモデル
- ポイント：J.J.ギャレットが示した。下の段階の決定が上の段階の土台になるので、見た目（表層）から先に決めない

#### UXハニカム構造（ゆーえっくすはにかむこうぞう / UX Honeycomb）

- 意味：良いUXに必要な要素を、役に立つ・使いやすい・望ましい・見つけやすい・アクセスしやすい・信頼できる・価値がある、の7つの六角形（蜂の巣）で表したもの
- ポイント：P.モービルが示した。中心が「価値がある」。どの要素が足りないかを見つけるのに使う
- 語の意味：Honeycomb＝蜂の巣

#### エモーショナルデザイン（Emotional Design）

- 意味：使う人の感情（楽しい・うれしい・愛着）に働きかけるように設計すること
- ポイント：D.ノーマンは、見た目の印象（本能）・使いやすさ（行動）・意味や思い出（内省）の3つのレベルで説明した。見た目が魅力的だと使いやすく感じる
- 語の意味：Emotional＝感情の

#### インタラクションデザイン（Interaction Design）

- 意味：利用者の操作と、それに対するシステムの反応（動き・表示・音）を設計すること
- ポイント：押したら何がどう変わるか、待つ間に何を見せるかなど、やり取りの流れと手ごたえを決める
- 語の意味：Interaction＝相互作用・やり取り

#### ペルソナ（Persona）

- 意味：製品の典型的な利用者を、名前・年齢・生活・目的まで具体的に描いた架空の人物像
- ポイント：「みんな」ではなく1人の具体的な人を思い浮かべて設計の判断をそろえる。カスタマージャーニーマップの主人公にもなる

#### カスタマージャーニーマップ（Customer Journey Map）

- 意味：利用者が製品を知り、使い、使い終えるまでの行動・考え・感情の動きを、時間の順に図にしたもの
- ポイント：どの場面で不満や迷いが出るか（タッチポイントごとの課題）を見つける

### 五段階モデルの各段階

#### 戦略（UX）（せんりゃく / Strategy Plane）

- 意味：五段階モデルの一番下。利用者のニーズと事業の目的をはっきりさせる段階
- ポイント：「誰のために、何のために作るか」。ここがぶれると、上の段階を全部作り直すことになる

#### 要件（UX）（ようけん / Scope Plane）

- 意味：五段階モデルの下から2番目。戦略を実現するために、どんな機能や内容を用意するかを決める段階
- ポイント：作るものの範囲（スコープ）を決める。機能の一覧やコンテンツの要件を書く

#### 構造（UX）（こうぞう / Structure Plane）

- 意味：五段階モデルの真ん中。情報や画面がどうつながり、利用者がどう進むかを決める段階
- ポイント：情報アーキテクチャとインタラクションデザインを決める。画面遷移図やサイトの構造図を作る

#### 骨格（UX）（こっかく / Skeleton Plane）

- 意味：五段階モデルの下から4番目。1つの画面の中で、ボタンや情報をどこにどう配置するかを決める段階
- ポイント：線と箱だけで配置を描くワイヤーフレームを作るのがこの段階。色や画像はまだ入れない

#### 表層（UX）（ひょうそう / Surface Plane）

- 意味：五段階モデルの一番上。色・文字・画像など、利用者の目に直接見える仕上げを決める段階
- ポイント：ビジュアルデザイン。下の4段階で決めたことを見た目に表す

### 情報デザインの原則

#### 近接（デザイン）（きんせつ / Proximity）

- 意味：関係のある要素どうしを近くに、関係のない要素は離して置くというデザインの原則
- ポイント：近くにあるものは一つのまとまりに見える（空間近接原理）。見出しと本文、ラベルと入力欄を近づける

#### 整列（デザイン）（せいれつ / Alignment）

- 意味：要素の端や中心を、見えない線にそろえて配置するというデザインの原則
- ポイント：左端がそろっているだけで整理されて見え、読み進めやすくなる

#### 反復（デザイン）（はんぷく / Repetition）

- 意味：同じ種類の要素には、同じ色・形・書式を繰り返し使うというデザインの原則
- ポイント：見出しは全部同じ書式、リンクは全部同じ色にすると、利用者はルールを一度覚えれば済む。一貫性を生む

#### 対比（デザイン）（たいひ / Contrast）

- 意味：違うものは、大きさ・色・太さなどをはっきり変えて、違いを目立たせるというデザインの原則
- ポイント：大事なボタンだけ色を変える、見出しを大きくする、など。中途半端な違いはかえって分かりにくい

### 情報の見せ方

#### LATCH（らっち / LATCH）

- 意味：情報を整理する切り口は、場所（Location）・五十音やアルファベット（Alphabet）・時間（Time）・カテゴリ（Category）・階層や量（Hierarchy）の5つしかない、という考え方
- ポイント：R.S.ワーマンが示した。例えば店の一覧なら、地図（L）・名前順（A）・開店日（T）・ジャンル（C）・評価順（H）で並べられる
- 語の意味：Location＝場所／Alphabet＝文字の順／Time＝時間／Category＝分類／Hierarchy＝階層・順位

#### インフォグラフィック（Infographic）

- 意味：データや情報を、図・グラフ・イラストを使って、ひと目で分かるように視覚的に表現したもの
- ポイント：路線図・天気予報の地図・統計のイラストなど。文章や表だけより早く理解できる
- 語の意味：Information＝情報／Graphic＝図の

#### タイポグラフィ（Typography）

- 意味：文字の書体・大きさ・行間・字間などを工夫して、文字を読みやすく、美しく配置する技術
- ポイント：本文と見出しの書体の組合せ、1行の長さ、行間などで読みやすさが大きく変わる
- 語の意味：Typo＝活字／Graphy＝書くこと

#### ムードボード（Mood Board）

- 意味：作りたいデザインの雰囲気を伝えるために、写真・色・素材・文字の見本などを1枚に集めたもの
- ポイント：見た目の方向性を、関係者で言葉より先に共有するのに使う

### 画面設計の進め方

#### 画面設計（がめんせっけい / Screen Design）

- 意味：画面に表示する項目、配置、入力の方法、画面の移り変わりを決めること
- ポイント：入出力の項目とデータベースの項目、項目とその処理の対応も決める。利用者の用語を使い、よく使う項目を見やすい位置に置く

#### 情報提示ストーリー（じょうほうていじすとーりー / Information Presentation Story）

- 意味：利用者が情報を受け取って理解し、行動するまでの流れに沿って、どの順番で何を見せるかを組み立てたもの
- ポイント：一覧→詳細→申込み、のように利用者の考える順に情報を出す

#### ストーリーボード（Storyboard）

- 意味：利用者がシステムを使う場面と画面の流れを、絵コンテのように1コマずつ並べて描いたもの
- ポイント：映画やアニメの絵コンテが由来。どんな状況で、どの画面を見て、何をするかを関係者で共有する

#### ワイヤーフレーム（Wireframe）

- 意味：画面のどこに何を置くかを、線と箱だけで簡単に描いた設計図
- ポイント：色や画像を入れず配置だけを決める。UXの五段階モデルの骨格に当たる。実際に操作できるようにしたものはプロトタイプ
- 語の意味：Wire＝針金・線／Frame＝枠

#### 利用者の用語（りようしゃのようご / User's Terms）

- 意味：画面のラベルや説明に、作り手の専門用語ではなく、利用者がふだん使っている言葉を使うこと
- ポイント：社内の略語やシステムの項目名をそのまま表示すると、利用者には意味が分からない

### 入力の方式

#### 穴埋め方式（あなうめほうしき / Fill-in-the-blank Method）

- 意味：決まった書式の画面の空欄に、必要な値を埋めていく入力方式
- ポイント：申込書のように項目が並び、そこに入力する。項目が多いときに一覧で見渡せる

#### メニューインプット方式（めにゅーいんぷっとほうしき / Menu Input Method）

- 意味：表示された選択肢（メニュー）の中から選んで入力する方式
- ポイント：入力の手間と誤りが少なく、初心者に向く。選択肢が多すぎると探しにくい

#### 部分送信（ぶぶんそうしん / Partial Submission）

- 意味：画面全体を送り直さずに、入力された一部の項目だけをサーバーに送って処理すること
- ポイント：郵便番号を入れたら住所を自動で表示する、入力中にその項目だけチェックする、など。画面全体の再表示を待たなくてよい

#### オートコンプリート（Autocomplete）

- 意味：入力の途中で、続きの候補を予測して表示し、選ぶだけで入力を完成させる機能
- ポイント：検索窓の候補・住所の入力など。入力の手間と打ち間違いを減らす
- 語の意味：Auto＝自動／Complete＝完成させる

### 入力チェック

#### ニューメリックチェック（Numeric Check）

- 意味：数字であるべき項目に、数字以外の文字が入っていないかを調べるチェック
- ポイント：数値チェックとも呼ぶ。範囲までは調べない（範囲はリミットチェック）
- 語の意味：Numeric＝数の

#### フォーマットチェック（Format Check）

- 意味：入力された値が、決められた形式（桁数・文字の種類・区切り）になっているかを調べるチェック
- ポイント：郵便番号が「3桁-4桁」、メールアドレスに「@」がある、など。形式が違う誤りをフォーマットエラーと呼ぶ
- 語の意味：Format＝形式

#### リミットチェック（Limit Check）

- 意味：入力された値が、決められた上限と下限の範囲の中にあるかを調べるチェック
- ポイント：範囲チェックとも呼ぶ。年齢が0〜150、月が1〜12など
- 語の意味：Limit＝限度

#### 組合せチェック（くみあわせちぇっく / Combination Check）

- 意味：複数の項目の値の組合せが、あり得るものかどうかを調べるチェック
- ポイント：月が2なら日は29まで、性別と続柄の組合せ、など。項目ひとつずつは正しくても、組み合わせると矛盾するものを見つける。論理エラーの検出に使う

#### 照合チェック（しょうごうちぇっく / Matching Check）

- 意味：入力された値が、マスターファイルなどに登録されている値と一致するかを調べるチェック
- ポイント：入力した社員番号が社員マスターにあるか、など。存在しないコードの入力を防ぐ

#### バランスチェック（Balance Check）

- 意味：別々の方法で求めた値（合計など）が一致するかを調べるチェック
- ポイント：簿記の借方の合計と貸方の合計、明細を足した値と合計欄の値が一致するか、など
- 語の意味：Balance＝つり合い

#### チェックキャラクター（Check Character）

- 意味：コードの末尾などに付ける、元の数字から計算で求めた検査用の文字（数字）。チェックディジットとも呼ぶ
- ポイント：入力されたコードから同じ計算をして、検査用の文字と合わなければ入力の誤りと分かる。1桁の打ち間違いや、隣り合う2桁の入れ替えを見つけられる
- 語の意味：Check＝検査／Character＝文字

#### シーケンスチェック（Sequence Check）

- 意味：データが決められた順番（番号の昇順など）に並んでいるかを調べるチェック
- ポイント：順番が飛んだり逆になったりしている誤りをシーケンスエラーと呼ぶ。伝票番号の抜けを見つける
- 語の意味：Sequence＝順番

### 入力エラーの種類

#### フォーマットエラー（Format Error）

- 意味：入力された値の形式（桁数・文字の種類など）が決まりと違うという誤り
- ポイント：フォーマットチェックやニューメリックチェックで見つける

#### 論理エラー（ろんりえらー / Logical Error）

- 意味：1つ1つの値の形式は正しいが、内容として矛盾している、あり得ないという誤り
- ポイント：終了日が開始日より前、2月30日など。組合せチェックやリミットチェックで見つける

#### シーケンスエラー（Sequence Error）

- 意味：データの並び順や処理の順番が、決められた順と違うという誤り
- ポイント：シーケンスチェックで見つける。番号の抜け・重複・逆転

#### 重複エラー（ちょうふくえらー / Duplication Error）

- 意味：一つしかあってはならない値（番号など）が、すでに登録されているのにもう一度入力されたという誤り
- ポイント：同じ注文を二重に登録しない、同じ会員番号を二人に割り当てない、などを照合で防ぐ

### 帳票設計

#### 帳票設計（ちょうひょうせっけい / Form Design）

- 意味：請求書・納品書・一覧表など、紙や画面に出力する帳票の項目・配置・書式を決めること
- ポイント：使う人と目的に合わせて、必要な項目に絞り、見る順に並べる。プリンターの種類や用紙など、装置の制約も考える

#### 出力特性（しゅつりょくとくせい / Output Characteristics）

- 意味：帳票を出力するときの条件。出力の時期・頻度・枚数・部数・用紙・配布先など
- ポイント：毎日何百枚も出すのか、月に1枚か、複写が必要かなどで、プリンターや用紙の選び方が変わる

#### 入力特性（にゅうりょくとくせい / Input Characteristics）

- 意味：データを入力するときの条件。入力する人・場所・時期・量・元になる伝票の形など
- ポイント：伝票の項目の並びと入力画面の並びを合わせると、入力の誤りが減る

#### フォームオーバーレイ（Form Overlay）

- 意味：帳票の罫線や見出しなどの決まった書式（フォーム）を、データと重ねて同時に印刷する方法
- ポイント：あらかじめ印刷した用紙（プレプリント用紙）を用意しなくても、白い紙に帳票を印刷できる
- 語の意味：Form＝書式／Overlay＝上に重ねる

#### プレプリント用紙（ぷれぷりんとようし / Preprinted Form）

- 意味：罫線や見出し、会社名などをあらかじめ印刷しておいた専用の用紙。事前印刷用紙
- ポイント：データだけをその上に印字する。複写式の伝票などに使う。用紙の在庫と、印字位置のずれに注意がいる
- 語の意味：Pre＝前もって／Print＝印刷

### コード設計

#### コード設計（こーどせっけい / Code Design）

- 意味：商品・顧客などを識別するためのコードの体系と桁数を決めること
- ポイント：将来の件数の増加を見込んで桁数を決める。使える文字がn種類でk桁なら、表せるのは n の k 乗通り
- 例：R4秋 問24（英大文字26種類で、3年後の顧客数を表せる桁数）

#### 順番コード（じゅんばんこーど / Sequential Code）

- 意味：対象に、発生した順や五十音の順に、1から連続した番号を付けるコード
- ポイント：桁数が少なく作りやすいが、番号から分類は分からない。途中に追加するのが難しい。連番コードとも呼ぶ

#### 区分コード（くぶんこーど / Block Code）

- 意味：番号をいくつかのブロックに区切り、ブロックごとに分類を割り当てるコード。分類コードとも呼ぶ
- ポイント：1〜99は文房具、100〜199は家具、のように範囲で分類する。少ない桁で分類が表せるが、ブロックの空きがなくなると追加しにくい

#### 桁別コード（けたべつこーど / Group Classification Code）

- 意味：コードの各桁（又はいくつかの桁のまとまり）に、それぞれ分類の意味を持たせたコード
- ポイント：1桁目が大分類、2桁目が中分類、3〜4桁目が品番、のように作る。分類が分かりやすく集計しやすいが、桁数が増えやすい

#### 表意コード（ひょういこーど / Mnemonic Code）

- 意味：英字の略語や数字の値そのものなど、コードを見ただけで対象の意味が分かるようにしたコード
- ポイント：「TV-32」（32型テレビ）や「JPN」など。覚えやすいが、桁数がそろいにくい
- 語の意味：Mnemonic＝記憶を助ける

#### 合成コード（ごうせいこーど / Combined Code）

- 意味：複数のコードを組み合わせて、1つのコードとして使うもの
- ポイント：「店舗コード＋日付＋連番」で伝票番号を作る、など。それぞれのコードの意味を保ったまま一意にできる

### Webデザインの技術

#### スタイルシート（Style Sheet）

- 意味：Webページの見た目（文字の大きさ・色・配置など）を、文書の内容とは別に定義するしくみ。WebではCSSを使う
- ポイント：内容（HTML）と見た目（CSS）を分けるので、1つのスタイルシートを変えればサイト全体のデザインを統一して変えられる
- 語の意味：Style＝様式／Sheet＝紙

#### クロスブラウザ（Cross Browser）

- 意味：種類やバージョンの違うWebブラウザで、同じようにページが表示され、動作するようにすること
- ポイント：Chrome・Safari・Firefoxなどで表示を確かめる。ブラウザごとに独自の機能に頼りすぎない

#### プログレッシブエンハンスメント（Progressive Enhancement）

- 意味：まずどの環境でも使える基本の内容と機能を作り、そのうえで高機能なブラウザ向けに表現や機能を段階的に足していく考え方
- ポイント：古いブラウザでも最低限は使え、新しいブラウザではより便利になる。高機能版から作り、古い環境では機能を落とすのは反対の考え方（グレースフルデグラデーション）
- 語の意味：Progressive＝段階的な／Enhancement＝強化

#### モバイルファースト（Mobile First）

- 意味：画面が小さいスマートフォンでの利用を先に考えてWebサイトを設計し、その後でパソコン向けに広げていく考え方
- ポイント：狭い画面に必要なものだけを載せるので、本当に大事な内容が絞られる
- 語の意味：Mobile＝携帯端末／First＝最初に

#### レスポンシブWebデザイン（れすぽんしぶうぇぶでざいん / Responsive Web Design）

- 意味：1つのHTMLのページが、画面の幅に合わせてレイアウトを自動で変えて表示されるように作る手法
- ポイント：スマートフォン用とパソコン用のページを別々に作らない。画面の幅によるCSSの切替えにはメディアクエリを使う
- 語の意味：Responsive＝反応する・応じる

#### メディアクエリ（Media Query）

- 意味：CSSで、画面の幅や向き・解像度などの条件に応じて、適用するスタイルを切り替えるしくみ
- ポイント：「幅が600px以下ならメニューを縦に並べる」のように書く。レスポンシブWebデザインを実現する技術
- 語の意味：Media＝媒体／Query＝問合せ

### Webの設計と確認

#### フレーム（Webデザイン）（Frame）

- 意味：Webページの画面を複数の区画に分け、それぞれに別のページを表示するしくみ
- ポイント：メニューを左の区画に固定して、右の区画だけを切り替える、など。今はアクセシビリティや検索の面で問題があるとされ、使われなくなった

#### サイト内検索機能（さいとないけんさくきのう / Site Search）

- 意味：そのWebサイトの中のページだけを対象に、キーワードで探せるようにする機能
- ポイント：メニューをたどるより早く目的のページに着ける。ナビゲーションで見つけにくいときの補い

#### ナビゲーションデザイン（Navigation Design）

- 意味：利用者が迷わず目的のページにたどり着けるように、メニュー・リンク・パンくずリストなどの案内（ナビゲーション）を設計すること
- ポイント：今どこにいるか、どこへ行けるか、どう戻るかが常に分かるようにする

#### UXライティング（ゆーえっくすらいてぃんぐ / UX Writing）

- 意味：ボタンの文言・エラーメッセージ・説明文など、画面の中の短い言葉を、利用者が迷わず行動できるように書くこと
- ポイント：「エラー 0x1F」ではなく「カード番号の桁数が足りません」と、何が起きて、どうすればよいかを書く

#### スクローリーテリング（Scrollytelling）

- 意味：ページを下にスクロールするにつれて、図や写真・文章が動いたり切り替わったりしながら、物語のように情報を伝える表現手法
- ポイント：scroll（スクロール）とstorytelling（物語を語る）を合わせた造語。報道機関の特集ページなどで使う

#### ビジュアルリグレッションテスト（Visual Regression Test）

- 意味：プログラムやCSSを変更した前後の画面を画像として比べ、意図しない見た目の変化がないかを確かめるテスト
- ポイント：1か所のCSSの変更が別のページの崩れを起こしていないかを自動で見つける
- 語の意味：Visual＝見た目の／Regression＝後戻り・退行

### 人間中心設計

#### 人間中心設計（にんげんちゅうしんせっけい / HCD: Human-Centred Design）

- 意味：利用者の特性やニーズ、利用状況を理解し、利用者の評価を取り入れて、設計と評価を繰り返しながら使いやすいシステムを作る考え方
- ポイント：規格はJIS Z 8530（ISO 9241-210）。「利用状況の理解及び明示→ユーザ要求事項の明示→設計解の作成→設計の評価」を、要求を満たすまで繰り返す
- 語の意味：Human＝人間／Centred＝中心の／Design＝設計

#### 利用状況の理解及び明示（りようじょうきょうのりかいおよびめいじ / Understanding and Specifying the Context of Use）

- 意味：人間中心設計の最初の活動。誰が、どんな目的で、どんな環境（場所・機器・時間）で使うかを調べて明らかにすること
- ポイント：観察やインタビューで、実際の利用の場面を調べる

#### ユーザ要求事項の明示（ゆーざようきゅうじこうのめいじ / Specifying the User Requirements）

- 意味：人間中心設計の2番目の活動。利用状況をもとに、利用者が何を達成できなければならないかを、要求として書き出すこと
- ポイント：ユーザビリティの目標（何分以内に予約できる、など）も決める

#### 設計解の作成（せっけいかいのさくせい / Producing Design Solutions）

- 意味：人間中心設計の3番目の活動。ユーザ要求事項を満たす設計案を作ること
- ポイント：紙やワイヤーフレーム、プロトタイプなど、評価できる形にする

#### 設計の評価（せっけいのひょうか / Evaluating the Design）

- 意味：人間中心設計の4番目の活動。設計案をユーザ要求事項に照らして、利用者の視点で評価すること
- ポイント：ユーザビリティテストなどで評価し、要求を満たさなければ前の活動に戻って繰り返す

### 誰でも使える設計

#### ユニバーサルデザイン（Universal Design）

- 意味：年齢・能力・国籍などにかかわらず、最初からできるだけ多くの人が使えるように設計すること。考え方はユニバーサルデザインの7原則にまとめられている
- ポイント：R.メイスが提唱した7原則がある。障害を後から取り除くバリアフリーと違い、最初から全員を対象にする
- 語の意味：Universal＝すべての人の

#### ユニバーサルデザインの7原則（ゆにばーさるでざいんのななげんそく / Seven Principles of Universal Design）

- 意味：ユニバーサルデザインの考え方をまとめた、公平な利用・利用における柔軟性・単純で直感的な利用・認知できる情報・失敗に対する寛大さ・少ない身体的な努力・接近や利用のためのサイズと空間、の7つ
- ポイント：ITでは、音声読み上げ（認知できる情報）、Undo機能（失敗に対する寛大さ）、イラストによる説明（単純で直感的な利用）などに当たる

#### インクルーシブデザイン（Inclusive Design）

- 意味：高齢者・障害のある人など、これまで設計の対象から外されがちだった人を、設計の初めから一緒に参加させて作る手法
- ポイント：ユニバーサルデザインが「多くの人が使える結果」を目指すのに対し、インクルーシブデザインは「当事者が設計に加わる過程」を重視する
- 語の意味：Inclusive＝包み込む・含める

#### バリアフリー（Barrier Free）

- 意味：高齢者や障害のある人にとって妨げ（バリア）になっているものを、取り除くこと
- ポイント：段差にスロープを付ける、など。今あるバリアを後から取り除く考え方で、最初から全員を対象にするユニバーサルデザインと区別する
- 語の意味：Barrier＝障壁／Free＝ない

#### エルゴノミクス（Ergonomics）

- 意味：人の体や心の特性に合わせて、道具や作業の環境を設計するための学問。人間工学
- ポイント：疲れにくいキーボード、手の大きさに合ったマウス、画面と目の距離など。身体的適合性の土台
- 語の意味：Ergon＝仕事／Nomos＝法則

### 分かりやすく伝える工夫

#### ピクトグラム（Pictogram）

- 意味：言葉を使わずに、単純な絵で意味を伝える図記号
- ポイント：非常口・トイレの案内など。言語や年齢にかかわらず意味が伝わる。東京オリンピック（1964年）で広まった
- 語の意味：Picto＝絵／Gram＝書いたもの

#### UDフォント（ゆーでぃーふぉんと / Universal Design Font）

- 意味：文字の形を分かりやすくし、読み間違いが起きにくいように工夫された書体
- ポイント：「3」と「8」、濁点の「ば」と半濁点の「ぱ」を見分けやすくするなど。視力の弱い人や高齢者にも読みやすい
- 語の意味：UD＝ユニバーサルデザイン

#### 音声読み上げ（おんせいよみあげ / Screen Reader）

- 意味：画面に表示された文字を、合成音声で読み上げる機能やソフトウェア（スクリーンリーダー）
- ポイント：目の見えない人がWebページを使うための手段。画像には代替テキストを付けないと内容が伝わらない

#### Undo機能（あんどぅきのう / Undo）

- 意味：直前の操作を取り消して、元の状態に戻す機能
- ポイント：間違えてもやり直せるので、安心して操作できる（ユニバーサルデザインの「失敗に対する寛大さ」）。取り消したものをもう一度行うのはRedo
- 語の意味：Undo＝元に戻す

### 規格とガイドライン

#### ISO 9241（あいえすおーきゅうにーよんいち / ISO 9241）

- 意味：人とシステムのやり取り（インタラクティブシステム）の人間工学についての国際規格群
- ポイント：第11部でユーザビリティを「有効さ・効率・満足度」と定義し、第210部で人間中心設計のプロセスを定める（JIS Z 8530）
- 語の意味：ISO＝International Organization for Standardization（国際標準化機構）

#### JIS Z 8530（じすぜっとはちごーさんぜろ / JIS Z 8530）

- 意味：人間中心設計のプロセスを定めた日本産業規格。ISO 9241-210を日本語にしたもの
- ポイント：「利用状況の理解及び明示」から「設計の評価」までの活動と、その繰り返しを定める

#### JIS X 8341（じすえっくすはちさんよんいち / JIS X 8341）

- 意味：高齢者・障害者等に配慮した情報通信の機器・ソフトウェア・サービスのアクセシビリティについての日本産業規格
- ポイント：第3部（JIS X 8341-3）がWebコンテンツの規格で、内容はWCAG 2.0と同じ。適合レベルはA・AA・AAAの3つ。「やさしく（8）さしのべる（341）」の語呂

#### WCAG（だぶりゅーかぐ / Web Content Accessibility Guidelines）

- 意味：W3CのWAIが作った、Webコンテンツのアクセシビリティのガイドライン
- ポイント：知覚可能・操作可能・理解可能・堅牢（POUR）の4原則で、達成基準をA・AA・AAAの3段階で示す
- 語の意味：Web Content＝Webの内容／Accessibility＝利用のしやすさ／Guidelines＝指針

#### WAI（わい / Web Accessibility Initiative）

- 意味：Webのアクセシビリティを高めるために、W3Cが進めている活動（の組織）
- ポイント：WCAGなどのガイドラインを作っている。WAIは活動の名前、WCAGはそこで作ったガイドラインの名前
- 語の意味：Web＝WWW／Accessibility＝利用のしやすさ／Initiative＝取組み

#### JIS X 9303-1（じすえっくすきゅーさんぜろさん / JIS X 9303-1）

- 意味：ユーザシステムインタフェースで使うアイコンについての日本産業規格（ISO/IEC 11581-1に対応）
- ポイント：アイコンの一般的な要求事項と性質を定める。習得性＝アイコンの表す機能が、一度理解された後にどれだけ容易に思い出せるか
- 例：R5秋 問24

### ユーザビリティの中身

#### 有効さ（ゆうこうさ / Effectiveness）

- 意味：ユーザビリティの3要素の1つ。利用者が目標を、正確に、完全に達成できる度合い
- ポイント：「最後まで正しく申込めたか」。達成率や誤りの数で測る

#### 効率（ユーザビリティ）（こうりつ / Efficiency）

- 意味：ユーザビリティの3要素の1つ。目標を達成するまでに使った時間や手間などの資源の少なさ
- ポイント：「何分で、何回の操作で申込めたか」。作業時間や操作の回数で測る

#### 満足度（まんぞくど / Satisfaction）

- 意味：ユーザビリティの3要素の1つ。利用者が使っていて不快がなく、肯定的な気持ちを持てる度合い
- ポイント：アンケートやインタビューで測る。有効で効率的でも、不快なら満足度は低い

#### 利用状況（りようじょうきょう / Context of Use）

- 意味：ユーザビリティを考えるときの前提になる、利用者・目標・作業・機器・環境（物理的・社会的）の組合せ
- ポイント：同じ画面でも、事務所の大きな画面と、移動中のスマートフォンとでは使いやすさが違う。ユーザビリティは利用状況を決めて初めて測れる

### ユーザビリティ評価

#### ヒューリスティック評価（ひゅーりすてぃっくひょうか / Heuristic Evaluation）

- 意味：ユーザビリティの専門家が、経験則にもとづくガイドライン（ヒューリスティクス）に照らして、画面の問題点を見つける評価手法
- ポイント：利用者を集めずに専門家だけで行うので、早く安く実施できる。ニールセンの10原則が有名
- 例：R4春 問24・R7春 問22（専門家だけで実施する手法）
- 語の意味：Heuristic＝経験則による・発見的な

#### 認知的ウォークスルー（にんちてきうぉーくするー / Cognitive Walkthrough）

- 意味：専門家が利用者になったつもりで、作業の手順を1つずつたどり、各手順で利用者が迷わず正しい操作を選べるかを調べる評価手法
- ポイント：専門家だけで行う。特に初めて使う人にとっての分かりやすさを調べるのに向く
- 例：R4春 問24・R7春 問22の誤答（利用者が参加する手法の側に置かれている）
- 語の意味：Cognitive＝認知の／Walkthrough＝通しで歩く・たどる

#### 思考発話法（しこうはつわほう / Think Aloud Method）

- 意味：利用者に実際に操作してもらいながら、考えていることを声に出して話してもらい、それを記録する評価手法
- ポイント：利用者が参加する手法。どこで、なぜ迷ったのかが分かる
- 例：R4春 問24・R7春 問22（利用者が参加する手法）

#### 回顧法（かいこほう / Retrospective Method）

- 意味：利用者に操作してもらった後で、録画などを見ながら、そのとき何を考えていたかを振り返って話してもらう評価手法
- ポイント：利用者が参加する手法。操作中に話さないので自然な操作が見られるが、記憶があいまいになることがある。思考発話法と対で問われる

#### NEM（ねむ / Novice Expert ratio Method）

- 意味：同じ作業を初心者と熟練者（設計者など）に行ってもらい、手順ごとの操作時間の比（初心者÷熟練者）を求め、比が大きい手順を問題のある箇所とする評価手法
- ポイント：数値で問題の箇所を示せる。比が大きい＝熟練者は速いのに初心者はつまずく手順
- 語の意味：Novice＝初心者／Expert＝熟練者／Ratio＝比／Method＝方法

#### アイトラッキング分析（あいとらっきんぐぶんせき / Eye Tracking Analysis）

- 意味：専用の機器で利用者の視線の動きと止まった時間を記録し、画面のどこを見て、どこを見落としているかを分析する手法
- ポイント：見られた量を色で表したヒートマップで示すことが多い。本人も気づいていない見方が分かる

#### ユーザビリティテスト（Usability Test）

- 意味：実際の利用者（又はそれに近い人）に課題を与えて操作してもらい、その様子を観察して問題点を見つける評価手法
- ポイント：思考発話法・回顧法などと組み合わせて行う。5人ほどで主な問題の多くが見つかるとされる

#### A/Bテスト（えーびーてすと / A/B Test）

- 意味：画面のデザインなどを2つの案（AとB）用意し、利用者をランダムに振り分けて、成果（購入率など）の良いほうを選ぶ手法
- ポイント：公開中のWebサイトで実際のデータを使って比べる。一度に変える部分を1か所にすると、何が効いたかが分かる

#### アンケート（ユーザビリティ）（Questionnaire）

- 意味：利用者に質問紙に答えてもらい、使いやすさや満足度を調べる手法
- ポイント：利用者が参加する手法。満足度など主観的な評価を、多くの人から集めやすい。R4春 問24・R7春 問22の誤答に出る

- 問：ある操作を4つの手順に分けて，初心者と熟練者の操作時間（秒）を測ったところ，表のとおりであった。NEM（Novice Expert ratio Method）によって，最も問題があると判断される手順はどれか。（表は文字で書き直した。手順1：初心者50秒・熟練者15秒，手順2：初心者30秒・熟練者5秒，手順3：初心者64秒・熟練者40秒，手順4：初心者20秒・熟練者8秒）
- ア：手順1
- イ：手順2
- ウ：手順3
- エ：手順4
- 正解：イ
- 解説：NEMでは、手順ごとに「初心者の時間÷熟練者の時間」を求め、比が大きいほど初心者がつまずいている（設計者の意図が伝わっていない）と判断する。比は手順1が約3.3、手順2が6、手順3が1.6、手順4が2.5なので、手順2。
- アの意味：初心者と熟練者の時間の「差」（35秒）が最も大きい手順。NEMは差ではなく比で比べる。
- イの意味：正しい。比が6で最も大きい。
- ウの意味：初心者の時間が最も長い手順。熟練者も長くかかる手順なので、比は1.6と小さく、もともと時間のかかる作業と考えられる。
- エの意味：比は2.5で、手順1・2より小さい。

#### 問 ap-7-o20

- 問：公開中のWebサイトで，購入ボタンの色だけが異なる2つの画面を用意し，訪問者をランダムに振り分けて，購入率の高い方を採用する手法はどれか。
- ア：A/Bテスト
- イ：アイトラッキング分析
- ウ：認知的ウォークスルー
- エ：ビジュアルリグレッションテスト
- 正解：ア
- 解説：2つの案（AとB）を実際の利用者に見せ分けて、成果の良いほうを選ぶのがA/Bテスト。変える部分を1か所にすると、何が効いたかが分かる。
- アの意味：正しい。2案を振り分けて比べる。
- イの意味：視線の動きを機器で記録して、画面のどこを見ているかを分析する手法。購入率は比べない。
- ウの意味：専門家が利用者になったつもりで操作の手順をたどる評価手法。実際の訪問者は参加しない。
- エの意味：変更の前後の画面を画像で比べ、意図しない見た目の変化がないかを確かめるテスト。どちらの案が良いかを決めるものではない。
