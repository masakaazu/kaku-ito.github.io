## 19-1 デジタルフォレンジック

### まとめ表

| 揮発性 | 保全する順の例（RFC 3227 を基に） |
| :-: | :-: |
| 高い（先に） | レジスタ・キャッシュ |
| ↓ | ルーティングテーブル・ARP キャッシュ・プロセス表・メモリ |
| ↓ | 一時ファイル |
| ↓ | ディスク |
| ↓ | 遠隔のログ・監視データ |
| 低い（後で） | 物理的な構成・保管用の媒体（バックアップ・インストール用 CD） |

### 証拠の保全

#### デジタルフォレンジック（でじたるふぉれんじっく / Digital Forensics）

- 意味：犯罪や不正、インシデントの証拠となりうるデジタルデータを、改変しないように保全し、調査・分析して、訴訟などにも使える形で事実を明らかにすること
- ポイント：過去問の言い方は「犯罪に関する証拠となり得るデータを保全し，調査，分析，その後の訴訟などに備える」（R2 問13）。電子透かし・ペネトレーションテスト・ソーシャルエンジニアリングが誤りの選択肢に並ぶ

#### 揮発性データの収集順序（きはつせいでーたのしゅうしゅうじゅんじょ / Order of Volatility）

- 意味：電源を切ったり時間がたったりすると消える情報から先に保全するという、証拠の収集の順序の原則。RFC 3227 が順序の例を示す
- ポイント：メモリ・ルーティングテーブル・ARP キャッシュ → ディスク → 遠隔のログ → 保管用の媒体の順。遠隔のログサーバのログはすぐには消えないので後でよい（R3秋 問12、R5春・R7春 問13・15）

#### ディスクイメージの取得と書込み防止（でぃすくいめーじのしゅとくとかきこみぼうし / Disk Imaging and Write Blocking）

- 意味：調査対象のディスクを、書込み防止装置（ライトブロッカ）を介して、空き領域も含めて1ビットずつ複製（ビットストリームコピー、ディスクイメージ）し、調査は複製に対して行うこと
- ポイント：原本に直接触ると、アクセス日時の更新などで証拠が変わってしまう。ファイルのコピーでは、削除されたファイルの残りや空き領域が取れない

#### ハッシュ値による同一性の証明（はっしゅちによるどういつせいのしょうめい / Hash Verification）

- 意味：取得した証拠（ディスクイメージなど）のハッシュ値を取得直後に計算して記録し、後で再計算して一致することで、証拠が改変されていないことを示すこと
- ポイント：SHA-256 などを使う。原本と複製のハッシュ値が一致すれば、複製が原本と同じであることも示せる

#### Chain of Custody（ちぇーんおぶかすとでぃ / Chain of Custody）

- 意味：証拠を、いつ・誰が・どこで取得し、誰に渡し、どう保管・分析したかを途切れなく記録し、証拠が改ざんされていないことを説明できるようにすること（証拠保全の連鎖）
- ポイント：記録が途切れると、裁判などで証拠の信頼性を否定されうる。ハッシュ値は「中身が同じ」、Chain of Custody は「誰が扱ったか」を示す

### 解析の手法

#### タイムライン分析（たいむらいんぶんせき / Timeline Analysis）

- 意味：ファイルの作成・更新・アクセスの日時、ログ、レジストリなどの時刻の情報を時系列に並べ、侵入から被害までの攻撃者の行動を再構成すること
- ポイント：機器の時刻がずれていると並べられないので、NTP による時刻同期（#12）が前提。攻撃者が日時を書き換える（タイムスタンプの改ざん）ことにも注意する

#### メモリフォレンジック（めもりふぉれんじっく / Memory Forensics）

- 意味：稼働中の機器のメモリの内容を取得（メモリダンプ）し、動いていたプロセス、通信の状態、メモリ上だけにあるマルウェアや復号された鍵などを解析すること
- ポイント：ファイルを残さないファイルレスマルウェア（#05）は、ディスクを調べても見つからない。電源を切る前にメモリを取る

## 19-2 マルウェア解析

### まとめ表

| 仕組み | 目的 |
| :-: | :-: |
| サンドボックス | 隔離した環境で検体を動かし、振る舞いを観察する |
| ハニーポット | わざと攻撃させるおとりの機器で、攻撃の手口を集める |
| ハニーネット | ハニーポットを複数つないだおとりのネットワーク |
| パケットキャプチャ | 通信を記録し、C&C サーバとの通信などを分析する |
| 逆アセンブル | 機械語をアセンブリ言語に戻して処理を読む |
| アンパック | 圧縮・暗号化（パック）された検体を元のコードに戻す |

### 解析の環境と手法

#### サンドボックス（さんどぼっくす / Sandbox）

- 意味：外部や本番の環境から隔離した仮想環境などで、疑わしいファイルを実際に動かし、作成するファイル、レジストリの変更、通信先などの振る舞いを観察する仕組み
- ポイント：動かして見るので動的解析（#12）の一つ。マルウェアは仮想環境を検知すると動きを止めることがある（サンドボックス回避）

#### ハニーポット（はにーぽっと / Honeypot）

- 意味：攻撃者を誘い込むために、わざと脆弱に見せて公開するおとりのシステム。攻撃の手口や使われるマルウェアを集めて分析する
- ポイント：本物の資産は置かない。乗っ取られて踏み台にされないように、外への通信を制限する。複数をつないだものがハニーネット

#### バイナリ解析と逆アセンブル（ばいなりかいせきとぎゃくあせんぶる / Binary Analysis, Disassembly）

- 意味：ソースコードのない実行ファイル（バイナリ）を、逆アセンブラで機械語からアセンブリ言語に戻すなどして、動かさずに処理の内容を読み解くこと
- ポイント：動かさずに読むので静的解析。デバッガで1命令ずつ動かしながら見る方法も組み合わせる

### 解析を妨げる技術

#### パッカーとアンパック（ぱっかーとあんぱっく / Packer, Unpacking）

- 意味：実行ファイルを圧縮・暗号化し、実行時に自分で元に戻して動くようにするツールがパッカー。解析のためにパックされた検体を元のコードに戻すのがアンパック
- ポイント：パックするとファイルの中身が変わるので、パターンマッチング法（#12）で検知されにくく、逆アセンブルしても処理が読めない

#### 難読化（なんどくか / Obfuscation）

- 意味：プログラムの動作は変えずに、変数名を意味のない名前にする、処理を複雑に組み替える、文字列を暗号化するなどして、人や解析ツールが読みにくくすること
- ポイント：攻撃者は検知と解析の回避に、正規の開発者は知的財産の保護に使う。スクリプトのマルウェア（#05）で多い

#### アンチデバッグ（あんちでばっぐ / Anti-Debugging）

- 意味：マルウェアが、デバッガで解析されていることや、仮想環境・サンドボックスで動いていることを検知し、動作を止めたり違う動きをしたりする技術
- ポイント：解析を回避する技術には、ほかにマルウェア対策ソフトの停止、一定時間待ってから動く（スリープ）などがある

## 19-3 脆弱性の評価

### まとめ表

| 名前 | 何か | 管理 |
| :-: | :-: | :-: |
| CVE | 個々の脆弱性の識別子（CVE-2021-44228 など） | MITRE |
| CWE | 脆弱性の種類の一覧（CWE-79 XSS など） | MITRE |
| CVSS | 深刻度の評価方法（0.0〜10.0） | FIRST |
| EPSS | 今後30日に悪用される確率の予測 | FIRST |
| KEV | 悪用が確認された脆弱性の一覧 | 米国 CISA |
| SSVC | 対応の判断を決定木で決める方法 | 米国 CISA など |
| SCAP | 脆弱性管理を自動化する規格群 | NIST |
| JVN | 日本の脆弱性対策情報ポータルサイト | JPCERT/CC・IPA |

### 識別と評価の基準

#### CVE（しーぶいいー / Common Vulnerabilities and Exposures）

- 意味：個々の製品の脆弱性に付けられる、世界共通の識別子。「CVE-年-番号」の形で、MITRE が中心となって採番を管理する
- ポイント：同じ脆弱性を、ベンダ・JVN・セキュリティ製品が同じ番号で呼べる。過去問は「製品に含まれる脆弱性を識別するための識別子」（R3春 問8）
- 語の意味：Common＝共通の、Exposures＝露出（危険にさらされた状態）

#### CWE（しーだぶりゅいー / Common Weakness Enumeration）

- 意味：ソフトウェアとハードウェアの脆弱性の種類（弱点のタイプ）を分類した一覧。CWE-79（XSS）、CWE-89（SQL インジェクション）など
- ポイント：CVE は「個々の脆弱性」、CWE は「脆弱性の種類」。過去問は「ソフトウェア及びハードウェアの脆弱性の種類の一覧」（R6春 問9）
- 語の意味：Weakness＝弱点、Enumeration＝列挙

#### CVSS の評価基準（しーぶいえすえすのひょうかきじゅん / CVSS Metric Groups）

- 意味：CVSS で深刻度を計算するときの観点のまとまり。v3.1 は基本評価基準・現状評価基準・環境評価基準、v4.0 は基本・脅威・環境・補足
- ポイント：基本評価基準は脆弱性そのものの特性で変わらない。現状（v4.0 では脅威）は攻撃コードの有無などで時間とともに変わる。環境は利用者の環境に合わせて利用者が評価する。「三つの基準で深刻度を評価する」のは CVSS（R1秋 問9）

#### EPSS（いーぴーえすえす / Exploit Prediction Scoring System）

- 意味：脆弱性が今後30日以内に実際に悪用される確率を、過去のデータから機械学習で予測して 0〜1 の数値で示す仕組み。FIRST が公開する
- ポイント：CVSS は「深刻さ」、EPSS は「悪用されそうか」、KEV は「悪用が確認されたか」。組み合わせてパッチの優先順位を決める

#### SSVC（えすえすぶいしー / Stakeholder-Specific Vulnerability Categorization）

- 意味：悪用の状況、自動化できるか、影響の大きさなどの質問に答えていく決定木で、脆弱性への対応（すぐ対応・監視など）を決める方法。CISA などが使う
- ポイント：点数ではなく「どう行動するか」を直接決める。立場（ベンダか利用者か）によって決定木が違う

#### SCAP（えすきゃっぷ / Security Content Automation Protocol）

- 意味：脆弱性管理、設定の確認、評価を自動化するために、NIST が定めた規格群。CVE・CVSS・CPE（製品の識別）・CCE（設定項目の識別）・XCCDF・OVAL などからなる
- ポイント：過去問の正解（R5秋 問12）。CPE は「製品を識別するためのプラットフォーム名の一覧」、CCE は「セキュリティに関連する設定項目を識別するための識別子」で、CWE の問題の誤りの選択肢になる

### 管理と検査

#### SBOM（えすぼむ / Software Bill of Materials）

- 意味：ソフトウェアを構成するコンポーネント（ライブラリなど）とその版、互いの依存関係、ライセンスなどの一覧。形式に SPDX・CycloneDX がある
- ポイント：新しい脆弱性が公表されたとき、影響を受ける製品をすぐ特定できる。SBOM を作って管理する検査が SCA（ソフトウェア構成分析）。過去問は「ソフトウェアを構成するコンポーネント，互いの依存関係などのリスト」（R6春 問17）

#### JVN（じぇいぶいえぬ / Japan Vulnerability Notes）

- 意味：JPCERT/CC と IPA が共同で運営する、日本で使われる製品の脆弱性対策情報のポータルサイト。JVN iPedia は脆弱性対策情報のデータベース
- ポイント：脆弱性の届出（#07 の情報セキュリティ早期警戒パートナーシップ）で調整された情報が公表される。CVE・CVSS・CWE を採用している

#### ペネトレーションテスト（ぺねとれーしょんてすと / Penetration Test）

- 意味：攻撃者と同じ手法で実際にシステムへの攻撃と侵入を試み、目的（データの取得など）を達成できるかで、セキュリティの弱さを確かめる検査
- ポイント：脆弱性診断は「脆弱性を網羅的に洗い出す」、ペネトレーションテストは「侵入できるかを試す」。IoT 機器ではネットワーク・バス・デバッグインタフェースを使う（R5春 問22）

#### バグバウンティプログラム（ばぐばうんてぃぷろぐらむ / Bug Bounty Program）

- 意味：製品やサービスの脆弱性を見つけて報告した外部の研究者に、企業が報奨金を支払う制度（脆弱性報奨金制度）
- ポイント：対象の範囲、禁止する行為、報告の手順を事前に公開する。決めた範囲での調査を許すことで、研究者が安心して報告できる

## 19-4 製品と暗号の評価・認証

### まとめ表

| 名前 | 評価するもの |
| :-: | :-: |
| ISO/IEC 15408（コモンクライテリア） | IT 製品・システムのセキュリティ機能と保証 |
| ISO/IEC 18045（CEM） | 15408 に基づいて評価する方法 |
| JISEC | 日本で 15408 による評価・認証を行う制度（IPA） |
| FIPS 140-3 | 暗号モジュールのセキュリティ要求事項 |
| JCMVP | 日本で暗号モジュールを試験・認証する制度（IPA） |
| CRYPTREC 暗号リスト | 電子政府で使う暗号のアルゴリズム |

### コモンクライテリア

#### ISO/IEC 15408（あいえすおーあいいーしーいちごーよんぜろはち / Common Criteria）

- 意味：IT 製品やシステムのセキュリティ機能と、その作り込みの確かさ（保証）を評価するための国際規格。コモンクライテリア（CC）とも呼ばれ、JIS X 5070 として JIS 化されている
- ポイント：過去問の言い方は「調達者が判断する際に役立つ評価結果を提供し，独立したセキュリティ評価結果間の比較を可能にする」（R4秋 問9）。27002 は管理策、27017 はクラウドの管理策

#### プロテクションプロファイル（ぷろてくしょんぷろふぁいる / PP: Protection Profile）

- 意味：ファイアウォールや複合機などの製品の種類ごとに、満たすべきセキュリティ要件を、特定の製品によらずにまとめた文書
- ポイント：調達者側の要求をまとめたものが PP。個々の製品について、評価の対象と要件を開発者が書いたものがセキュリティターゲット（ST）

#### EAL（いーえーえる / Evaluation Assurance Level）

- 意味：ISO/IEC 15408 で、評価でどれだけ厳密に確かめたか（保証の深さ）を示す7段階の評価保証レベル。EAL1 から EAL7 まで
- ポイント：数字が大きいほど、設計の文書や検査を深く確かめている。機能が多い・強いという意味ではない
- 語の意味：Evaluation Assurance Level＝評価の保証のレベル

#### JISEC（じぇいせっく / Japan Information Technology Security Evaluation and Certification Scheme）

- 意味：IT 製品やシステムを ISO/IEC 15408 と ISO/IEC 18045（CEM）に基づいて評価機関が評価し、IPA が認証する日本の制度（IT セキュリティ評価及び認証制度）
- ポイント：国際的な相互承認（CCRA）に参加しているので、日本の認証が加盟国でも通用する

### 暗号の評価

#### JCMVP（じぇいしーえむぶいぴー / Japan Cryptographic Module Validation Program）

- 意味：暗号モジュール（暗号の機能を持つハードウェア・ソフトウェア）が、暗号アルゴリズムを正しく実装し、鍵などを適切に保護していることを試験・認証する日本の制度。IPA が運営する
- ポイント：要求事項は ISO/IEC 19790（米国の FIPS 140-3 と同じ内容）。米国とカナダの同様の制度が CMVP
- 語の意味：Cryptographic Module Validation＝暗号モジュールの妥当性確認

#### FIPS 140-3（ふぃっぷすいちよんまるのさん / FIPS PUB 140-3）

- 意味：米国 NIST が定めた、暗号モジュールのセキュリティ要求事項の規格。セキュリティレベル1〜4がある
- ポイント：過去問の正解（R6春 問10）。PKI の証明書の技術仕様は RFC 5280、ISMS の要求事項は ISO/IEC 27001、無線 LAN のセキュリティは IEEE 802.11i で、誤りの選択肢になる

#### CRYPTREC 暗号リスト（くりぷとれっくあんごうりすと / CRYPTREC Ciphers List）

- 意味：デジタル庁・総務省・経済産業省が定めた「電子政府における調達のために参照すべき暗号のリスト」。電子政府推奨暗号リスト、推奨候補暗号リスト、運用監視暗号リストの三つからなる
- ポイント：電子政府推奨暗号リスト＝安全性・実装性能が確認され、利用実績が十分か今後の普及が見込まれ、利用を推奨。推奨候補暗号リスト＝安全性・実装性能は確認され、今後推奨リストに載る可能性がある。運用監視暗号リスト＝解読のリスクが高まり、互換性維持のためだけに利用を認める

#### 問 sc-19-r07a-q1

- 問：デジタル庁，総務省及び経済産業省が策定した“電子政府における調達のために参照すべき暗号のリスト（CRYPTREC 暗号リスト）”に関する記述のうち，適切なものはどれか。
- ア：CRYPTREC 暗号リストには運用監視暗号リストがあり，それは運用監視システムにおける利用実績が十分であると判断され，電子政府において利用を推奨する暗号技術のリストである。
- イ：CRYPTREC 暗号リストには証明書失効リストがあり，それは政府共用認証局が公開している，危殆化した暗号技術のリストである。
- ウ：CRYPTREC 暗号リストには推奨候補暗号リストがあり，それは安全性及び実装性能が確認され，今後，電子政府推奨暗号リストに掲載される可能性がある暗号技術のリストである。
- エ：CRYPTREC 暗号リストには電子政府推奨暗号リストがあり，それは互換性維持目的に限った継続利用を推奨する暗号技術のリストである。

- イの意味：CRYPTREC 暗号リストに証明書失効リストはない。証明書失効リスト（CRL）は PKI の仕組み（#16）。

- エの意味：互換性維持の目的に限るのは運用監視暗号リスト。

#### 問 sc-19-o08

- 問：ISO/IEC 15408 の EAL（評価保証レベル）の説明として、適切なものはどれか。
- ア：製品が持つセキュリティ機能の数を7段階で示す。
- イ：評価でどれだけ厳密に確かめたか（保証の深さ）を、EAL1 から EAL7 の7段階で示す。
- ウ：脆弱性の深刻度を 0.0〜10.0 で示す。
- エ：暗号モジュールの物理的な耐タンパ性をレベル1〜4で示す。
- 正解：イ
- 解説：EAL は保証の深さで、数字が大きいほど深く確かめている。機能の多さではない。
- アの意味：EAL は機能の数や強さを示すものではない。
- イの意味：正しい。
- ウの意味：CVSS の説明。
- エの意味：FIPS 140-3 のセキュリティレベルの説明。
- 出典：オリジナル問題（根拠：JIS X 5070-3（ISO/IEC 15408-3）／IPA「IT セキュリティ評価及び認証制度（JISEC）」）

#### 問 sc-19-o09

- 問：ファイアウォールなどの製品の種類ごとに、特定の製品によらず、満たすべきセキュリティ要件をまとめた ISO/IEC 15408 の文書はどれか。

- イ：評価保証レベル（EAL）

- イの意味：保証の深さを示す段階。
- ウの意味：評価の方法を定めた ISO/IEC 18045。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：JIS X 5070-1（ISO/IEC 15408-1）／IPA「支援士試験 シラバス（案）」用語例「プロテクションプロファイル（PP）」）
