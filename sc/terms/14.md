## 14-1 無線 LAN と IEEE 802.1X

### まとめ表

| 802.1X の役割 | 実体の例 | RADIUS での役割 |
| :-: | :-: | :-: |
| サプリカント | PC・スマホ（の OS のソフト） | ー（RADIUS は話さない） |
| オーセンティケータ | 無線 LAN のアクセスポイント・L2 スイッチ | RADIUS クライアント |
| 認証サーバ | RADIUS サーバ | RADIUS サーバ |

| 無線 LAN の方式 | 認証 | 鍵 |
| :-: | :-: | :-: |
| WPA2/WPA3-Personal | 全員で同じパスフレーズ（PSK・SAE） | パスフレーズから作る |
| WPA2/WPA3-Enterprise | 802.1X で利用者ごと | 認証のあと動的に配布 |
| Enhanced Open | なし（パスワード入力なし） | 端末ごとに鍵交換して暗号化 |

### IEEE 802.1X と RADIUS

#### IEEE 802.1X（あいとりぷるいーはちまるにいちえっくす / IEEE 802.1X Port-Based Network Access Control）

- 意味：有線 LAN や無線 LAN に機器がつながるとき、アクセスポイントやスイッチが EAP を使ってクライアントを認証し、認証に成功するまでは通信を通さないようにする、ポート単位のアクセス制御の規格
- ポイント：R7秋 問17 の正解は「アクセスポイントが EAP を使用して、クライアントを認証する枠組み」。暗号の方式や電波の衝突検知の規格ではない
- 語の意味：Port-Based＝ポート単位の

#### サプリカント（さぷりかんと / Supplicant）

- 意味：802.1X で、認証を要求するクライアント側の装置やソフトウェア
- ポイント：R6春 問14 の正解。仲介するのはオーセンティケータ、認証するのは認証サーバ。「一度の認証で複数のサーバ」は SSO
- 語の意味：Supplicant＝嘆願者、申し出る人

#### オーセンティケータ（おーせんてぃけーた / Authenticator）

- 意味：802.1X で、サプリカントと認証サーバの仲介役となり、クライアントから受け取った認証情報を認証サーバに送り、結果に応じて通信を通すネットワーク機器（アクセスポイントやスイッチ）
- ポイント：オーセンティケータは RADIUS サーバに問い合わせる側なので「RADIUS クライアント」の機能をもつ（R4春・R6秋 問17 の正解）。PC が RADIUS クライアントになるのではない

#### EAP（いーぷ / Extensible Authentication Protocol）

- 意味：パスワード、証明書、トークンなど、いろいろな認証方式を同じ枠組みで運ぶための認証プロトコル（RFC 3748）。中に入れる方式を EAP-TLS、PEAP などと呼ぶ
- ポイント：EAP は認証の「枠組み」であり、暗号化の規格ではない。H31春・R3秋・R5春 の誤りの選択肢「EAP は共通鍵による暗号化通信の規格」に注意
- 語の意味：Extensible＝拡張できる

#### EAP-TLS（いーぷてぃーえるえす / EAP-Transport Layer Security）

- 意味：EAP の方式の一つで、デジタル証明書によって、認証サーバとクライアントの相互認証を行うもの（RFC 5216）
- ポイント：パスワードを使わず、クライアントにも証明書が要る。R1秋・R3秋 問16 の正解。サーバの証明書で TLS のトンネルを作り、その中でパスワードを使う PEAP・EAP-TTLS と区別する

#### RADIUS（らでぃうす / Remote Authentication Dial In User Service）

- 意味：リモートアクセスや無線 LAN で、認証・認可の情報やアカウンティング（利用の記録）の情報を、アクセスサーバと RADIUS サーバの間でやり取りするプロトコル（RFC 2865・2866、UDP 1812・1813）
- ポイント：R2 問19 の正解。CHAP・PAP は PPP の認証方式、PPTP は VPN のトンネルのプロトコル。RADIUS の後継として設計されたのが Diameter

#### AAA（とりぷるえー / Authentication, Authorization, Accounting）

- 意味：認証（Authentication）、認可（Authorization）、アカウンティング（Accounting：利用の記録・課金）の3つの機能の枠組み。RADIUS や Diameter、TACACS+ が提供する
- ポイント：R6秋 問1 の正解は Accounting。Audit（監査）と混同しない

### 無線 LAN のセキュリティ

#### WPA3（だぶりゅーぴーえーすりー / Wi-Fi Protected Access 3）

- 意味：Wi-Fi Alliance が 2018 年に定めた無線 LAN のセキュリティの認定規格。Personal、Enterprise、と別の認定の Enhanced Open がある
- ポイント：WPA3-Personal は、WPA2 の PSK の代わりに SAE（Simultaneous Authentication of Equals）で鍵を決めるので、通信を盗聴してもパスフレーズを手元で総当たりする攻撃（オフライン辞書攻撃）がしにくく、前方秘匿性もある

#### WPA3-Enterprise（だぶりゅーぴーえーすりーえんたーぷらいず / WPA3-Enterprise）

- 意味：IEEE 802.1X の規格に沿った利用者認証と、認証後に動的に配布される暗号化の鍵を用いて、暗号化通信を行う方式
- ポイント：R3秋・R5春 問14（H31春 問13 は WPA2-Enterprise）の正解。SSID は秘密鍵ではなくネットワークの識別名、RADIUS は認証のプロトコルで暗号化の規格ではない

#### PSK（ぴーえすけー / Pre-Shared Key）

- 意味：アクセスポイントと全ての端末が、あらかじめ同じパスフレーズ（事前共有鍵）を設定して接続する方式
- ポイント：家庭や小規模向け。パスフレーズを知る人は誰でも接続でき、退職者が出たら全員分を変える必要がある。利用者ごとの認証が要るなら Enterprise（802.1X）

#### Enhanced Open（えんはんすどおーぷん / Wi-Fi CERTIFIED Enhanced Open）

- 意味：パスワードの入力なしで接続する公衆無線 LAN などで、端末とアクセスポイントの間で鍵を交換し、通信を暗号化する Wi-Fi Alliance の仕様。基になる技術は RFC 8110 の OWE（Opportunistic Wireless Encryption）
- ポイント：R3春 問17・R6春 問12 の正解。「パスワードの入力なしに、暗号化が可能」。ただしアクセスポイントの認証はしないので、偽のアクセスポイントは防げない

#### プライバシーセパレータ（ぷらいばしーせぱれーた / Privacy Separator）

- 意味：同じアクセスポイントに無線で接続している機器同士の通信を禁止する機能。アクセスポイントアイソレーションとも呼ぶ
- ポイント：公衆無線 LAN で、隣の利用者の端末を攻撃されるのを防ぐ。R4秋 問17 の正解。MAC アドレスフィルタリングや SSID のステルスとは別

## 14-2 TLS・IPsec・SSH・DNS の保護

### まとめ表

| プロトコル | 層 | 守るもの | 補足 |
| :-: | :-: | :-: | :-: |
| IPsec | ネットワーク層 | IP パケット | ESP で暗号化、AH は認証だけ、IKE で鍵交換 |
| TLS | トランスポート層の上 | TCP の上の通信 | 1.3 が最新。SSL・1.0・1.1 は廃止 |
| DTLS | トランスポート層の上 | UDP のペイロード | TLS を UDP 向けにしたもの |
| QUIC | トランスポート層 | UDP の上で TLS 1.3 を内蔵 | HTTP/3 が使う |
| SSH | アプリケーション層 | 遠隔ログイン・ファイル転送 | 暗号化と認証、TCP 22 |
| DNSSEC | DNS | 応答の正当性と完全性 | 署名。暗号化はしない |
| DoT・DoH | DNS | 問合せの盗聴防止 | TLS（853）・HTTPS（443）で暗号化 |

### TLS

#### TLS 1.3（てぃーえるえすいってんさん / Transport Layer Security 1.3）

- 意味：2018 年に RFC 8446 で定められた TLS の最新の版。ハンドシェイクを 1 往復に短くし、安全でない古い方式を取り除いた
- ポイント：鍵交換は（EC）DHE だけになり、常に前方秘匿性がある。RSA による鍵交換、CBC モード、RC4、圧縮などは廃止。SSL 3.0、TLS 1.0、TLS 1.1 は使ってはならない（RFC 8996、2021年）

#### 暗号スイート（あんごうすいーと / Cipher Suite）

- 意味：TLS の通信で使う暗号アルゴリズムの組合せ。サーバとクライアントが対応するものの中から一つを選んで合意する
- ポイント：TLS 1.3 の暗号スイートは「AEAD（認証付き暗号）とハッシュアルゴリズムの組」（例：TLS_AES_128_GCM_SHA256）で、鍵交換と署名の方式は別に決める。R3秋 問17・R5秋 問2 の正解。サーバとクライアントは同じスイートを使う

#### AEAD（いーえーでぃー / Authenticated Encryption with Associated Data）

- 意味：暗号化と改ざんの検出（認証）を一度に行う暗号の方式。AES-GCM や ChaCha20-Poly1305 がある
- ポイント：TLS 1.3 では AEAD だけが使える。暗号化と MAC を別々に組み合わせた CBC モードの方式は、パディングオラクル攻撃などの弱点があったので外された

#### 常時 SSL/TLS（じょうじえすえすえるてぃーえるえす / Always On SSL/TLS）

- 意味：Web サイトのログイン画面だけでなく、全てのページを HTTPS で提供すること
- ポイント：効果は、中間者による通信の盗聴・改ざんの防止と、サーバ証明書による偽サイトの見分け（R1秋 問14 の正解）。SQL インジェクションやブルートフォース攻撃は防げない。HTTP で最初につながる隙をなくすには HSTS を使う

#### DTLS（でぃーてぃーえるえす / Datagram Transport Layer Security）

- 意味：TLS を、順番どおりに届かずに消えることもある UDP の通信でも使えるようにしたプロトコル。UDP のペイロードデータを暗号化できる
- ポイント：R6秋 問15 の正解。音声・映像の通話（WebRTC）や VPN などで使う。IP パケットの暗号化は IPsec

#### QUIC（くいっく / QUIC）

- 意味：UDP の上で動き、TLS 1.3 による暗号化を組み込んだトランスポート層のプロトコル（RFC 9000・9001）。HTTP/3 が使う
- ポイント：ヘッダの多くも暗号化されるので、途中の機器が中身を見にくい。UDP 443 を使うので、ファイアウォールやプロキシでの扱いに注意

### IPsec・SSH・DNS

#### IPsec（あいぴーせっく / IP Security）

- 意味：ネットワーク層で IP パケットを暗号化・認証するプロトコル群。ESP、AH、鍵交換の IKE からなる
- ポイント：IPv6 の通信をネットワーク層で暗号化するときに使う（R4秋 問13 の正解）。ESP は暗号化と認証、AH は認証（改ざん検出）だけで暗号化しない。拠点間 VPN はトンネルモード、端末同士はトランスポートモード

#### IKE（あいく / Internet Key Exchange）

- 意味：IPsec で使う鍵や暗号の方式を、通信する二者の間で安全に合意（SA を確立）するためのプロトコル（IKEv2 は RFC 7296、UDP 500）
- ポイント：事前共有鍵や証明書で相手を認証し、Diffie-Hellman で鍵を共有する

#### SSH（えすえすえいち / Secure Shell）

- 意味：通信の暗号化と利用者の認証の機能をもち、遠隔にあるコンピュータに安全にログインしてコマンドを操作するためのプロトコル（TCP 22）
- ポイント：R5秋 問15 の正解。パスワードより公開鍵認証が安全。初回の接続でサーバの鍵の指紋（フィンガープリント）を確かめないと中間者攻撃を受ける。L2TP はトンネル、LDAP はディレクトリ、RADIUS は認証のプロトコル

#### DNSSEC（でぃーえぬえすせっく / DNS Security Extensions）

- 意味：権威 DNS サーバのリソースレコードにデジタル署名を付け、リゾルバ（キャッシュサーバ）が受け取ったときに署名を検証して、データの作成元の正当性と完全性を確かめる仕組み
- ポイント：キャッシュポイズニングを防ぐ。暗号化はしないので盗聴は防げない。署名するのは権威サーバ、検証するのはリゾルバ（R5秋 問13 の正解）。DoS や、似た文字のドメイン名（ホモグラフ）、入力ミスのドメイン（タイポスクワッティング）も防げない

#### DoT と DoH（どっと・どー / DNS over TLS, DNS over HTTPS）

- 意味：DNS の問合せと応答を、TLS（DoT、TCP 853）や HTTPS（DoH、TCP 443）で暗号化して、盗聴や改ざんを防ぐ方式
- ポイント：DNSSEC は「正しさの証明（署名）」、DoT・DoH は「通信路の暗号化」で目的が違う。DoH は普通の Web 通信に紛れるので、組織の DNS のフィルタリングを迂回されることがある

## 14-3 電子メールのセキュリティ

### まとめ表

| 対策 | だれが設定 | しくみ |
| :-: | :-: | :-: |
| OP25B | ISP | 自社の動的 IP から外部のメールサーバへの 25 番の通信を止める |
| IP25B | ISP | 他社の動的 IP から自社のメールサーバへの 25 番の通信を止める |
| SMTP-AUTH | メールサーバ | 送信時に利用者 ID とパスワードで認証（587 番） |
| SPF | 送信ドメインの所有者 | DNS に送信してよいサーバの IP を登録 |
| DKIM | 送信ドメインの所有者 | 送信サーバが署名、DNS に公開鍵 |
| DMARC | 送信ドメインの所有者 | 認証に失敗したときの処理方針とレポート先を DNS に |

| 暗号化 | 公開鍵を用意する単位 | 守る範囲 |
| :-: | :-: | :-: |
| PGP | メールアドレス（利用者）ごと | メールの本文（端から端まで） |
| S/MIME | メールアドレスごと | メールの本文（端から端まで） |
| SMTP over TLS | メールサーバごと | サーバ間の通信路 |

### 送信の制限と送信ドメイン認証

#### OP25B（おーぴーにじゅうごびー / Outbound Port 25 Blocking）

- 意味：ISP が、自社の管理下のネットワーク（動的 IP アドレス）から、管理外のネットワークのメールサーバの TCP 25 番への通信を遮断すること
- ポイント：感染 PC が直接スパムメールを送るのを止める（R7春 問17 ほか多数）。正規の利用者は自社のメールサーバのサブミッションポート（587）に SMTP-AUTH で送る
- 語の意味：Outbound＝外向きの

#### IP25B（あいぴーにじゅうごびー / Inbound Port 25 Blocking）

- 意味：ISP が、他社の ISP の動的 IP アドレスから、自社のメールサーバの TCP 25 番への通信を制限すること
- ポイント：OP25B は「外向き」を自社の出口で止め、IP25B は「内向き」を自社のメールサーバの入口で止める（R2 問17）

#### SMTP-AUTH（えすえむてぃーぴーおーす / SMTP Service Extension for Authentication）

- 意味：メールクライアントからメールサーバへの送信時に、利用者 ID とパスワードなどで利用者を認証する SMTP の拡張（RFC 4954）
- ポイント：R2 問16・R4秋 問14 の正解。「POP で認証済みなら送信を許す」のは POP before SMTP という別の方式。認証情報を守るため、587 番の STARTTLS か 465 番の TLS で使う

#### SPF（えすぴーえふ / Sender Policy Framework）

- 意味：送信ドメインの所有者が、そのドメインのメールを送信してよいサーバの IP アドレスを DNS に SPF レコード（TXT）として登録し、受信側が送信元の IP アドレスと照合する送信ドメイン認証（RFC 7208）
- ポイント：送信側で行う設定は「DNS サーバに SPF レコードを登録する」（H31春・R4秋 問15 の正解）。転送されたメールは送信元の IP が変わるので失敗しやすい

#### DKIM（でぃーきむ / DomainKeys Identified Mail）

- 意味：送信側のメールサーバがメールのヘッダと本文からデジタル署名を作ってヘッダに付け、受信側がその署名を DNS に公開された公開鍵で検証する送信ドメイン認証（RFC 6376）
- ポイント：R1秋・R5春 問15 の正解。転送されても署名が残るので検証できる（本文を書き換えられると失敗）

#### DMARC（でぃーまーく / Domain-based Message Authentication, Reporting and Conformance）

- 意味：SPF や DKIM の認証の結果とヘッダの From のドメインが一致するか（アライメント）を確かめ、認証に失敗したときの処理方針を送信側のドメイン管理者が DNS で指定する仕組み（RFC 7489）
- ポイント：R6秋 問10 の正解。方針は none（何もしない・監視だけ）、quarantine（隔離）、reject（拒否）。rua で指定した宛先に集約レポートが届くので、まず none で自社のメールの送られ方を把握してから強める

### 通信と本文の暗号化

#### STARTTLS（すたーとてぃーえるえす / STARTTLS）

- 意味：SMTP・POP・IMAP で、平文で接続したあと STARTTLS のコマンドで同じポートのまま TLS に切り替える方式（SMTP は RFC 3207）
- ポイント：途中の攻撃者が STARTTLS の応答を消すと平文のまま送られてしまう（ダウングレード攻撃）。サーバ間では MTA-STS や DANE で TLS を強制する。最初から TLS でつなぐ方式（465・993・995 番）は暗黙の TLS と呼ぶ

#### SMTP over TLS（えすえむてぃーぴーおーばーてぃーえるえす / SMTP over TLS）

- 意味：メールサーバとメールサーバ（またはクライアント）の間の SMTP の通信を TLS で暗号化すること
- ポイント：公開鍵（証明書）は「メールサーバごと」。守るのは通信路だけで、サーバに届いたメールは平文で保存される。端から端まで守るなら S/MIME か PGP（R4秋・R6春 問16）

#### S/MIME（えすまいむ / Secure/Multipurpose Internet Mail Extensions）

- 意味：認証局が発行した利用者の証明書を使って、電子メールの本文の暗号化とデジタル署名を行う規格（S/MIME 4.0 は RFC 8551）
- ポイント：証明書（公開鍵）は「メールアドレスごと」。PGP は認証局でなく利用者同士の信頼の輪（web of trust）で鍵を信頼する点が違う

#### PGP（ぴーじーぴー / Pretty Good Privacy）

- 意味：利用者ごとの鍵の組で、電子メールやファイルの暗号化とデジタル署名を行う方式。標準化したものが OpenPGP
- ポイント：公開鍵は「メールアドレス（利用者）ごと」。認証局を使わず、利用者同士が互いの鍵に署名し合って信頼を広げる

#### IMAPS（あいまっぷえす / IMAP over TLS）

- 意味：メールを受信・管理する IMAP を TLS で暗号化したもの（TCP 993）。POP3 を TLS で暗号化したものは POP3S（TCP 995）
- ポイント：スマホとメールサーバの間で本文を含めて暗号化するのは IMAPS（R4春・R5秋 問16 の正解）。APOP はパスワードの送り方を変えるだけで本文は平文、SMTP Submission は送信の仕組み

#### APOP（えーぽっぷ / Authenticated Post Office Protocol）

- 意味：POP3 で、パスワードを平文で送る代わりに、サーバが送るチャレンジとパスワードから作った MD5 のハッシュ値を送って認証する方式
- ポイント：守るのはパスワードだけで、メール本文は暗号化しない。MD5 の弱点を使ってパスワードを推測する攻撃が知られており、今は POP3S や IMAPS を使う

#### 添付ファイルの無害化（てんぷふぁいるのむがいか / File Sanitization, CDR）

- 意味：受信したメールの添付ファイルから、マクロやスクリプト、埋め込みオブジェクトなど攻撃に使われうる部分を取り除いたり、画像や PDF に変換したりして、安全な形にしてから利用者に渡すこと。CDR（Content Disarm and Reconstruction）とも呼ぶ
- ポイント：未知のマルウェアでも、動く部分を取り除くので効く。マクロが必要な業務のファイルは使えなくなるので、元のファイルを取り出す手順を決めておく

- アの意味：クライアントの送信時の認証で、サーバ間の暗号化の強制ではない。
- イの意味：正しい。
- ウの意味：署名で改ざんは分かるが、本文の盗聴は防げない。
- エの意味：ISP の出口でのスパム対策で、関係がない。
- 出典：オリジナル問題（根拠：RFC 3207 SMTP Service Extension for Secure SMTP over TLS 6／RFC 8461 SMTP MTA Strict Transport Security）

#### 問 sc-14-o07

- 問：受信したメールの添付ファイルから、マクロやスクリプトなどの動く部分を取り除いたり、PDF や画像に変換したりしてから利用者に渡す対策の名称として、適切なものはどれか。
- ア：S/MIME
- イ：DMARC
- ウ：添付ファイルの無害化（サニタイズ）
- エ：OP25B
- 正解：ウ
- 解説：無害化（CDR）は、未知のマルウェアでも、動く部分を取り除くので効く。
- アの意味：本文の暗号化とデジタル署名の規格。
- イの意味：送信ドメイン認証に失敗したときの処理方針の仕組み。
- ウの意味：正しい。
- エの意味：ISP の出口で 25 番の通信を止める対策。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「添付ファイルの無害化（サニタイズ）」）
