### ISMS の骨組み

#### ISMS（あいえすえむえす / Information Security Management System）

- 意味：組織が情報セキュリティのリスクを管理し、機密性・完全性・可用性を保つための、方針・体制・手順・資源などの仕組み全体。情報セキュリティマネジメントシステム
- ポイント：要求事項は JIS Q 27001。計画（Plan）・実施（Do）・点検（Check）・改善（Act）を回して継続的に改善する。製品やシステムではなく、組織の管理の仕組みを対象にする
- 語の意味：Information Security＝情報セキュリティ／Management System＝管理の仕組み

#### JIS Q 27001（じすきゅー27001 / ISO/IEC 27001）

- 意味：ISMS を確立・実施・維持・継続的に改善するための要求事項を定めた規格。ISMS 認証の審査の基準になる
- ポイント：本文（箇条4〜10）は「しなければならない（shall）」の要求事項で、附属書 A に 93 の管理策の一覧がある（2022年版）。管理策の実施の手引は JIS Q 27002。2022年の改訂で、管理策が 114 から 93 に整理され、4つのテーマ（組織・人・物理・技術）にまとめられた。ほかのマネジメントシステム規格と同じ共通の構造（附属書 SL、調和構造）をもつ

#### ISMS適用範囲（あいえすえむえすてきようはんい / Scope of the ISMS）

- 意味：ISMS を適用する組織・事業・拠点・資産・技術の範囲。箇条 4.3 で、内外の課題、利害関係者の要求、他の組織とのインタフェースや依存関係を考慮して決め、文書化する
- ポイント：全社でなく、特定の部門や事業所に限って認証を受けることもできる。範囲の外とのつながり（委託先、クラウド）も考える

#### 情報セキュリティ目的（じょうほうせきゅりてぃもくてき / Information Security Objectives）

- 意味：情報セキュリティ方針と整合し、測定可能（実行可能な場合）で、監視・伝達・更新される、組織が達成をめざす目標。箇条 6.2
- ポイント：「何を、どの資源で、だれが、いつまでに、どう評価するか」を決める。方針（方向性）と目的（具体的な目標）を区別する

#### 適用宣言書（てきようせんげんしょ / SoA: Statement of Applicability）

- 意味：附属書 A の管理策と、組織が追加した管理策のそれぞれについて、採用するかしないか、その理由、実施しているかを記した文書。箇条 6.1.3 d) で作成を求める
- ポイント：リスク対応で決めた必要な管理策を附属書 A と比べ、見落としがないことを確かめる。附属書 A のすべてを採用する必要はないが、採用しない理由を書く
- 語の意味：Statement＝宣言／Applicability＝適用できるかどうか

#### 内部監査（ないぶかんさ / Internal Audit）

- 意味：ISMS が組織自身の要求事項と JIS Q 27001 の要求事項に適合しているか、有効に実施・維持されているかを、あらかじめ定めた間隔で組織自らが確かめる活動。箇条 9.2
- ポイント：監査員は、自分の仕事を監査しない（客観性と公平性）。結果は関連する管理層に報告する。外部の認証機関による審査とは別

#### マネジメントレビュー（まねじめんとれびゅー / Management Review）

- 意味：トップマネジメントが、あらかじめ定めた間隔で ISMS を見直し、引き続き適切・妥当・有効であることを確かめる活動。箇条 9.3
- ポイント：内部監査の結果、不適合と是正処置、監視・測定の結果、リスクアセスメントの結果、利害関係者の要望などを入力にして、改善の機会や ISMS の変更の必要性を決める。内部監査（監査員が確かめる）と取り違えさせる選択肢に注意

#### 不適合と是正処置（ふてきごうとぜせいしょち / Nonconformity and Corrective Action）

- 意味：不適合は要求事項を満たしていないこと。是正処置は、不適合の原因を取り除き、再発を防ぐための処置。箇条 10.2
- ポイント：まず不適合そのものを修正し（修正）、次に原因を調べて再発を防ぐ（是正処置）。「修正」と「是正処置」を区別する。2013年版にあった「予防処置」の箇条は、リスクと機会への取組（箇条6.1）に吸収されてなくなった

#### 継続的改善（けいぞくてきかいぜん / Continual Improvement）

- 意味：ISMS の適切性・妥当性・有効性を、くり返し高めていく活動。箇条 10.1
- ポイント：PDCA の Act にあたる。一度作って終わりではなく、内部監査やマネジメントレビューの結果をもとに改善を続ける

### 認証の制度

#### ISMS適合性評価制度（あいえすえむえすてきごうせいひょうかせいど / ISMS Conformity Assessment Scheme）

- 意味：組織の ISMS が JIS Q 27001 に適合しているかを、第三者の認証機関が審査して認証する制度。日本では ISMS-AC（情報マネジメントシステム認定センター）が認証機関を認定する
- ポイント：認定機関（ISMS-AC）→ 認証機関（審査して認証する）→ 組織、の関係。要員認証機関は審査員の資格を認める。認証の有効期間は通常3年で、毎年のサーベイランス審査と3年ごとの再認証審査がある

#### ISMS認証（あいえすえむえすにんしょう / ISMS Certification）

- 意味：認証機関の審査に合格し、組織の ISMS が JIS Q 27001 に適合していると認められること
- ポイント：取引先への信頼の証明や、入札の条件に使われる。認証は「仕組みが規格に合っている」ことを示すもので、事故が起きないことを保証するものではない。クラウドサービスについては、JIS Q 27017 の追加の管理策も審査する ISMS クラウドセキュリティ認証がある

### 関連する規格

#### 情報セキュリティガバナンス（じょうほうせきゅりてぃがばなんす / Information Security Governance）

- 意味：組織の情報セキュリティの活動を、経営陣が指示し、管理するための仕組み。JIS Q 27014 が考え方とプロセスを示す
- ポイント：JIS Q 27014:2015 は、経営陣が行うガバナンスプロセスとして、評価・指示・モニタ・コミュニケーション・保証の5つを示した。モニタは「戦略的目的の達成を評価することを可能にする」プロセス。2020年版（JIS Q 27014:2021）では、評価・指示・モニタ・コミュニケーションの4つに整理された

#### JIS Q 27002（じすきゅー27002 / ISO/IEC 27002）

- 意味：情報セキュリティ管理策の参照の一覧と、それぞれの目的・実施の手引を示した規格
- ポイント：JIS Q 27001 の附属書 A は、この規格の管理策の名前と内容の要約にあたる。27001 は要求事項（認証の基準）、27002 は手引（認証の基準ではない）

#### JIS Q 27017（じすきゅー27017 / ISO/IEC 27017）

- 意味：クラウドサービスに関する情報セキュリティ管理策の実施の手引。JIS Q 27002 の管理策にクラウド向けの手引を加え、さらにクラウドサービス固有の管理策を追加している
- ポイント：多くの管理策について、クラウドサービスの「利用者」向けと「提供者」向けの手引を対で示している。過去の午前Ⅱで「27002 にはないが 27017 にはある管理策」としてクラウドサービス固有の管理策が問われた

## 08-2 管理策のしくみ（JIS Q 27002）

### まとめ表

| テーマ（箇条） | 管理策の数 | 例 |
| :-: | :-: | :-: |
| 5 組織的管理策 | 37 | 方針群、職務の分離、脅威インテリジェンス、クラウドサービス |
| 6 人的管理策 | 8 | 選考、意識向上、懲戒、リモートワーク、事象の報告 |
| 7 物理的管理策 | 14 | セキュリティ境界、入退、クリアデスク、装置の処分 |
| 8 技術的管理策 | 34 | 特権的アクセス権、ログ取得、データマスキング、セキュアコーディング |

### 分類と属性

#### 情報セキュリティ管理策（じょうほうせきゅりてぃかんりさく / Information Security Control）

- 意味：情報セキュリティのリスクを修正（低減）するための手段。方針、手順、組織の体制、物理的な設備、技術的な仕組みなどを含む
- ポイント：JIS Q 27002:2022 は 93 の管理策を、組織的・人的・物理的・技術的の4つのテーマに分けた。各管理策には「属性」が付き、目的に応じて並べ替えて使える

#### 管理策タイプ（かんりさくたいぷ / Control Type）

- 意味：管理策が、インシデントの発生に対してどう働くかによる分類。予防（起きる前に防ぐ）、検知（起きたときに見つける）、是正（起きたあとに被害を抑え元に戻す）の3つ
- ポイント：JIS Q 27002:2022 の属性の1つ。1つの管理策が複数のタイプをもつこともある。ほかの属性は、情報セキュリティ特性（機密性・完全性・可用性）、サイバーセキュリティ概念（識別・防御・検知・対応・復旧）、運用能力、セキュリティドメイン
- 例：予防＝アクセス制御・教育、検知＝ログの監視・IDS、是正＝バックアップからの復旧・インシデント対応

#### 予防的管理策（よぼうてきかんりさく / Preventive Control）

- 意味：インシデントが起きることを防ぐ管理策
- 例：アクセス権の設定、暗号化、従業員の教育、入退室の制限、パッチの適用

#### 検知的管理策（けんちてきかんりさく / Detective Control）

- 意味：インシデントが起きたこと、または起きつつあることを見つける管理策
- 例：ログの監視、侵入検知、監視カメラ、ファイルの改ざん検知、内部監査

#### 是正的管理策（ぜせいてきかんりさく / Corrective Control）

- 意味：インシデントが起きたあとに、影響を抑え、元の状態に戻す管理策
- 例：バックアップからの復元、インシデント対応の手順、感染した端末の隔離、パッチによる修正

#### 2022年版で新しく加わった管理策（にせんにじゅうにねんばんであたらしくくわわったかんりさく / New Controls in ISO/IEC 27002:2022）

- 意味：JIS Q 27002:2022 で新設された11の管理策。脅威インテリジェンス、クラウドサービスの利用における情報セキュリティ、事業継続のための ICT の備え、物理的セキュリティの監視、構成管理、情報の削除、データマスキング、データ漏えい防止、監視活動、ウェブ・フィルタリング、セキュリティに配慮したコーディング
- ポイント：クラウド・テレワーク・データ保護など、2013年版以降の環境の変化に対応した。シラバス案の用語例にもすべて入っている

## 08-3 主な管理策

### まとめ表

| 管理策 | ねらい | 取り違えやすいもの |
| :-: | :-: | :-: |
| 職務の分離 | 1人に権限を集めず不正と誤りを防ぐ | 最小権限 |
| 関係当局との連絡 | 警察・規制当局との連絡体制 | 専門組織との連絡 |
| 情報の分類・ラベル付け | 重要度に応じた扱い | 資産の目録 |
| クリアデスク・クリアスクリーン | 離席時の盗み見・持ち去り防止 | 物理的入退 |
| データマスキング | 本番データの一部を隠す | 暗号化 |
| 環境の分離 | 開発・テスト・本番を分ける | ネットワークの分離 |

### 組織的管理策（箇条5）

#### 職務の分離（しょくむのぶんり / Segregation of Duties）

- 意味：相反する職務や責任の範囲を、別々の人に分担させること
- ポイント：1人で申請と承認、開発と本番への導入、発注と検収などができると、不正や誤りに気付けない。小さな組織で分けられないときは、ログの監視や上長のレビューで補う

#### 関係当局との連絡（かんけいとうきょくとのれんらく / Contact with Authorities）

- 意味：警察、監督官庁、個人情報保護委員会など、法令や規制に関わる当局との連絡の体制を、あらかじめ確立しておくこと
- ポイント：インシデントのときにだれがどこに報告するかを決めておく。業界団体や CSIRT の協議会などとの連絡は「専門組織との連絡」として別の管理策

#### 専門組織との連絡（せんもんそしきとのれんらく / Contact with Special Interest Groups）

- 意味：セキュリティの専門家の団体、業界のフォーラム（ISAC など）、CSIRT の協議会などとの連絡を確立・維持すること
- ポイント：最新の脅威や対策の情報を得るため。関係当局（法令・規制）との連絡と区別する

#### 脅威インテリジェンス（きょういいんてりじぇんす / Threat Intelligence）

- 意味：情報セキュリティの脅威に関する情報を集め、分析して、組織が使える知見（インテリジェンス）にすること。2022年版で新設
- ポイント：戦略的（経営向けの傾向）・戦術的（攻撃者の TTP）・運用的（攻撃の兆候、IoC）のレベルがある（#09）

#### 情報の分類とラベル付け（じょうほうのぶんるいとらべるづけ / Classification and Labelling of Information）

- 意味：情報を機密性・完全性・可用性と利害関係者の要求にもとづいて分類し（例：極秘・社外秘・公開）、分類が分かるように表示（ラベル付け）すること
- ポイント：分類ごとに、保管・転送・廃棄の扱いを決める。「情報及びその他の関連資産の目録」（何があるか）、「許容される利用」（どう使ってよいか）、「資産の返却」（退職時に返す）と並ぶ資産管理の管理策

#### 情報の転送（じょうほうのてんそう / Information Transfer）

- 意味：組織の内外への、あらゆる手段（メール、ファイル共有、媒体、口頭）での情報の転送について、規則・手順・合意を定めること
- ポイント：暗号化、宛先の確認、相手方との合意（取扱いの条件）など

#### クラウドサービスの利用における情報セキュリティ（くらうどさーびすのりようにおけるじょうほうせきゅりてぃ / Information Security for Use of Cloud Services）

- 意味：クラウドサービスの取得・利用・管理・利用の終了の手順を、組織の情報セキュリティの要求事項に従って確立すること。2022年版で新設
- ポイント：責任共有モデル（#06）を理解して利用者の責任を果たす。利用の終了時のデータの返却・削除まで決めておく

#### 事業継続のためのICTの備え（じぎょうけいぞくのためのあいしーてぃーのそなえ / ICT Readiness for Business Continuity）

- 意味：事業継続の目的と ICT の継続性の要求事項にもとづいて、ICT の備えを計画・実施・維持・試験すること。2022年版で新設
- ポイント：目標復旧時間（RTO）・目標復旧時点（RPO）を決め、バックアップや代替の拠点を用意して、実際に復旧できるか試験する（#22）

### 人的管理策（箇条6）

#### 人的管理策（じんてきかんりさく / People Controls）

- 意味：人に関わる8つの管理策。選考（経歴の確認）、雇用条件、意識向上・教育・訓練、懲戒手続、雇用の終了・変更後の責任、秘密保持契約（守秘義務契約）、リモートワーク、情報セキュリティ事象の報告
- ポイント：採用前・在職中・退職後の3つの段階で考える。「事象の報告」は、気付いた人だれもが速やかに報告できる仕組み（#06 の事象とインシデント）。リモートワークは2022年版で独立した管理策になった

### 物理的管理策（箇条7）

#### クリアデスク・クリアスクリーン（くりあですく・くりあすくりーん / Clear Desk and Clear Screen）

- 意味：机の上に書類や記憶媒体を放置しない（クリアデスク）、離席時に画面をロックし情報を表示したままにしない（クリアスクリーン）という規則
- ポイント：盗み見（ショルダーハッキング）や持ち去りを防ぐ。印刷物はすぐ取りに行く、施錠できる場所にしまう

#### サポートユーティリティ（さぽーとゆーてぃりてぃ / Supporting Utilities）

- 意味：電気・通信・水道・空調など、情報処理施設を支える設備。停電や故障から装置を守ること
- ポイント：無停電電源装置（UPS）、自家発電、空調の冗長化など。可用性を守る物理的管理策

#### 装置のセキュリティを保った処分又は再利用（そうちのせきゅりてぃをたもったしょぶんまたはさいりよう / Secure Disposal or Re-use of Equipment）

- 意味：記憶媒体を含む装置を処分・再利用する前に、機密情報やライセンスのあるソフトウェアが確実に消去・上書きされていることを確かめること
- ポイント：ファイルの削除や初期化だけでは復元できることがある。上書き消去、暗号化した鍵の消去（暗号消去）、物理的破壊などを、情報の重要度に応じて選ぶ

### 技術的管理策（箇条8）

#### 特権的アクセス権（とっけんてきあくせすけん / Privileged Access Rights）

- 意味：管理者権限など特権的なアクセス権の割当てと利用を、制限し管理すること
- ポイント：必要な人だけに、必要な間だけ与える、通常の作業用とは別のアカウントにする、利用を記録して見直す（#10 の特権 ID 管理）

#### データマスキング（でーたますきんぐ / Data Masking）

- 意味：個人情報などの機密データの一部を、隠したり別の値に置き換えたりして、見る人に必要な範囲だけを見せること。2022年版で新設
- ポイント：仮名化・匿名化・伏字（`****-****-****-1234`）など。テスト用のデータに本番の個人情報をそのまま使わない（テスト用情報の管理策とも関係）

#### データ漏えい防止（でーたろうえいぼうし / Data Leakage Prevention）

- 意味：機密情報を処理・保存・転送するシステム、ネットワーク、端末に、漏えいを防ぐ対策を適用すること。2022年版で新設
- ポイント：DLP 製品（機密情報を含むメールやアップロードを検知・遮断する、#13）、USB メモリの制限、外部への送信の監視など

#### 情報の削除（じょうほうのさくじょ / Information Deletion）

- 意味：情報システムや装置などに保存された情報を、必要がなくなったときに削除すること。2022年版で新設
- ポイント：保存期間の経過、契約の終了、本人からの削除の求めなど。クラウドの事業者に削除を依頼したときは、その証明を求める

#### クロックの同期（くろっくのどうき / Clock Synchronization）

- 意味：組織が使う情報処理システムの時刻を、承認された時刻源に合わせること
- ポイント：ログの時刻がずれていると、複数の機器のログを突き合わせて、攻撃の順番を追えない（#19 のフォレンジック）。NTP などで同期する

#### 開発環境・テスト環境・本番環境の分離（かいはつかんきょう・てすとかんきょう・ほんばんかんきょうのぶんり / Separation of Development, Test and Production Environments）

- 意味：開発・テストの作業が本番のシステムやデータに影響しないように、それぞれの環境を分け、セキュリティを保つこと
- ポイント：開発者が本番を直接変更できない、テストに本番の個人情報を使わない（テスト用情報）、本番への導入は変更管理の手続きで行う

#### 開発及び受入れにおけるセキュリティテスト（かいはつおよびうけいれにおけるせきゅりてぃてすと / Security Testing in Development and Acceptance）

- 意味：開発のライフサイクルの中で、セキュリティの試験の手順を定めて実施すること
- ポイント：セキュリティ機能の試験は、開発の途中で行う。開発の期間が終わってからまとめて行うのは不適切（過去の午前Ⅱで監査の指摘事項として出た）。受入れのときにも、要求を満たすか試験する
