## 13-1 境界での通信の制御

### まとめ表

| ファイアウォールの方式 | 見る層 | 判断のもと | 特徴 |
| :-: | :-: | :-: | :-: |
| パケットフィルタリング型 | ネットワーク層・トランスポート層 | 1個ずつのパケットのアドレス・ポート | 速い。戻りのパケット用に広く開ける必要 |
| ステートフルインスペクション型 | 同上＋セッションの状態 | 過去に通過したパケットから認識したセッション | 戻りのパケットだけを自動で通す |
| アプリケーションゲートウェイ型 | アプリケーション層 | プロトコルごとのプロキシが中身を検査 | 中身まで見られるが遅い。対応プロトコルが限られる |

### ファイアウォール

#### パケットフィルタリング型（ぱけっとふぃるたりんぐがた / Packet Filtering Firewall）

- 意味：パケットのヘッダにある送信元・宛先の IP アドレス、ポート番号、プロトコルを、決めたルールと照らして、通すか捨てるかを判断するファイアウォール
- ポイント：パケットを1個ずつ独立に見る（静的）。Web の戻りの通信を通すには「送信元ポート 443 からの全ての通信を許可」のように広く開けることになり、それを悪用される

#### ステートフルインスペクション型（すてーとふるいんすぺくしょんがた / Stateful Inspection Firewall）

- 意味：パケットフィルタリングを拡張し、過去に通過したパケットから通信のセッションを認識して状態表に記録し、受け付けたパケットがそのセッションの状態に合うかで、通すか遮断するかを判断するファイアウォール
- ポイント：内から外への要求を許可すれば、それに対応する「戻りのパケット」だけを自動で通す。ダイナミックパケットフィルタリングもほぼ同じ意味で出題される（R1秋 問5・R3秋 問6・H31春 問17・R3春 問6）
- 語の意味：Stateful＝状態をもつ、Inspection＝検査

#### アプリケーションゲートウェイ型（あぷりけーしょんげーとうぇいがた / Application Gateway Firewall）

- 意味：HTTP・SMTP など、アプリケーションのプロトコルごとのプロキシソフトウェアが、クライアントからの接続をいったん受け付け、中身を検査してから、目的のサーバに改めて接続して中継するファイアウォール
- ポイント：アプリケーション層のデータを検査でき、内部の端末の IP アドレスが外に見えない。ただし処理が重く、プロキシのないプロトコルは通せない。リバースプロキシ型の WAF とは置き場所と目的が違う

### 侵入の検知と防御

#### NIDS（えぬあいでぃーえす / Network-based Intrusion Detection System）

- 意味：ネットワークに置き、流れる通信を監視して侵入や攻撃を検知する IDS
- ポイント：一台でセグメント全体を見られるが、暗号化された通信の中身は見えない。通信を止められる置き方（インライン）にしたものが IPS（#12）

#### HIDS（えいちあいでぃーえす / Host-based Intrusion Detection System）

- 意味：サーバなどのホストに導入し、ログ、ファイルの改ざん、プロセスの動きなど、そのホストの中の事象を監視して侵入を検知する IDS
- ポイント：TLS で暗号化された通信でも、ホストの中で復号された後の動きやログを見られる。監視したいホストごとに入れる手間がある

### VPN

#### SSL-VPN のリバースプロキシ方式（りばーすぷろきしほうしき / SSL-VPN Reverse Proxy Mode）

- 意味：利用者は Web ブラウザで SSL-VPN 装置に HTTPS でつなぎ、装置がリバースプロキシとして社内の Web アプリケーションに中継する方式
- ポイント：端末に専用ソフトが要らないが、使えるのは Web（HTTP）のアプリケーションだけ。NIST SP 800-113 の「ポータル型」に当たる

#### SSL-VPN のポートフォワーディング方式（ぽーとふぉわーでぃんぐほうしき / SSL-VPN Port Forwarding Mode）

- 意味：端末に配布した小さなモジュールが、特定の TCP のポートへの通信を受け取り、SSL/TLS のトンネルで SSL-VPN 装置に転送する方式
- ポイント：Web 以外の TCP のアプリケーション（メールの受信など）も使えるが、ポート番号が決まったものに限られ、UDP や動的にポートが変わるものは難しい

#### SSL-VPN の L2 フォワーディング方式（えるつーふぉわーでぃんぐほうしき / SSL-VPN L2 Forwarding Mode）

- 意味：端末に仮想のネットワークインタフェースを作り、データリンク層のフレームを SSL/TLS のトンネルで運ぶ方式。端末は社内の LAN につながったのと同じように通信できる
- ポイント：UDP を含むほぼ全ての IP のアプリケーションが使える。その分、端末がマルウェアに感染していると社内全体に広がるので、接続時の端末の検査や通信先の制限が必要

## 13-2 内部への接続の制御と公開サービスの保護

### まとめ表

| 対策 | 防ぐもの | しくみ |
| :-: | :-: | :-: |
| 検疫ネットワーク | 対策の不十分な端末の接続 | 検査 → 隔離 → 治療 → 接続 |
| MAC アドレスフィルタリング | 未登録の機器の接続 | 登録した MAC アドレスだけ通す（偽装には弱い） |
| DHCP スヌーピング | 偽の DHCP サーバ | 信頼するポート以外からの DHCP の応答を捨てる |
| VLAN | ブロードキャストの到達・セグメント間の通信 | スイッチのポートを論理的に分ける |
| スクラビングセンター | 大規模な DDoS | 通信を引き込み、攻撃を取り除いて返す |
| Anycast・CDN | DDoS の集中 | 同じアドレスを多くの拠点で受けて分散 |

### 内部ネットワークへの接続の制御

#### 検疫ネットワーク（けんえきねっとわーく / Quarantine Network）

- 意味：社内ネットワークに接続しようとする端末を、いったん隔離したネットワークに入れて、パッチの適用やマルウェア対策ソフトの定義ファイルの状態を検査し、基準を満たさなければ治療（更新）させてから、社内への接続を許す仕組み
- ポイント：流れは「隔離 → 検査 → 治療 → 接続」。持ち出した PC を社内に戻すときの対策として出る

#### NAC（なっく / Network Access Control）

- 意味：ネットワークに接続する端末や利用者を認証し、端末の健全性（OS の更新、マルウェア対策の状態）も検証したうえで、接続の可否や接続先の VLAN を決める仕組み
- ポイント：その仕様の一つが Trusted Computing Group の TNC（Trusted Network Connect）。802.1X（#14）と組み合わせ、検証に通らない端末を検疫用の VLAN に入れることが多い
- 語の意味：Network Access＝ネットワークへの接続、Control＝制御

#### MAC アドレスフィルタリング（まっくあどれすふぃるたりんぐ / MAC Address Filtering）

- 意味：スイッチや無線 LAN のアクセスポイントで、登録した MAC アドレスの機器だけを接続させる仕組み
- ポイント：MAC アドレスは通信を盗み見れば分かり、簡単に偽装できるので、これだけでは不十分。802.1X などの認証と組み合わせる

#### DHCP スヌーピング（でぃーえいちしーぴーすぬーぴんぐ / DHCP Snooping）

- 意味：スイッチが DHCP のやり取りを監視し、正規の DHCP サーバをつないだ「信頼するポート」以外から来た DHCP の応答（OFFER・ACK）を捨てる機能。払い出した IP アドレスと MAC アドレスとポートの対応表も作る
- ポイント：偽の DHCP サーバが、自分をデフォルトゲートウェイや DNS サーバとして配り、通信を横取りする攻撃を防ぐ。作った対応表は、ARP スプーフィングを防ぐダイナミック ARP インスペクションにも使われる
- 語の意味：Snooping＝のぞき見

#### VLAN（ぶいらん / Virtual LAN）

- 意味：スイッチのポートなどを論理的なグループに分け、物理的な配線と関係なく、別々のネットワーク（ブロードキャストドメイン）として扱う技術
- ポイント：セキュリティ上の効果は、ブロードキャストの届く範囲を制限してアドレス情報などの不要な流出を減らすことと、セグメント間の通信をルータやファイアウォールのルールで制限できること（H31春 問12）

#### マイクロセグメンテーション（まいくろせぐめんてーしょん / Microsegmentation）

- 意味：ネットワークを、サーバや仮想マシン、ワークロードの単位まで細かく分け、それぞれの間の通信を必要なものだけに制限すること
- ポイント：侵入された1台から隣のサーバへ広がる「横移動（ラテラルムーブメント）」を防ぐ。境界の内側も信頼しない、ゼロトラスト（#18）の実装技術の一つ

### 公開サービスの保護

#### リバースプロキシ（りばーすぷろきし / Reverse Proxy）

- 意味：公開する Web サーバの手前に置き、インターネットからの要求を代わりに受け付けて、内部のサーバに中継するサーバ
- ポイント：内部のサーバを直接さらさずに済み、TLS の終端、負荷分散、キャッシュ、WAF の機能をまとめて置ける。利用者側に置いて外への通信を中継する（フォワード）プロキシと向きが逆

#### スクラビングセンター（すくらびんぐせんたー / Scrubbing Center）

- 意味：DDoS 攻撃を受けたとき、BGP や DNS の切替えで対象への通信をいったん大容量の専用設備に引き込み、攻撃の通信を取り除いて、正常な通信だけを元のサーバに戻すサービス
- ポイント：自社の回線の容量を超える量の攻撃は、自社の機器では防げない。回線の手前（上流）で取り除くのがスクラビング
- 語の意味：Scrubbing＝ごしごし洗うこと

#### Anycast（えにーきゃすと / Anycast）

- 意味：同じ IP アドレスを複数の拠点から経路広告し、利用者の通信をネットワーク的に最も近い拠点に届ける方式
- ポイント：DDoS の通信が多くの拠点に分散されるので、一か所に集中しない。DNS のルートサーバや CDN が使っている

#### レート制限（れーとせいげん / Rate Limiting）

- 意味：送信元の IP アドレスや利用者ごとに、一定時間に受け付ける要求の数に上限を設け、超えた分を拒否・遅延させること
- ポイント：アプリケーション層の DDoS、パスワードリスト攻撃、Bot による大量のアクセスの対策。CAPTCHA（人か機械かを判定する問題）と組み合わせて Bot を防ぐ

### 監視と検査

#### ポートスキャン（ぽーとすきゃん / Port Scan）

- 意味：対象のホストのポートに順に接続を試みて、どのポートが開いていて、どのサービスが動いているかを調べること
- ポイント：攻撃者の下調べに使われるが、自組織の検査では「不要なポートが開いていないか」を確かめるのに使う。TCP の SYN スキャンでは、SYN/ACK が返れば open、RST が返れば closed、応答がなければ filtered（ファイアウォールで捨てられている）と判断する

#### ネットワーク脆弱性検査（ねっとわーくぜいじゃくせいけんさ / Network Vulnerability Scanning）

- 意味：ネットワーク経由で対象の機器のサービスやソフトの版数を調べ、既知の脆弱性や設定の不備がないかを検査すること
- ポイント：本番の機器に負荷や停止を起こすことがあるので、許可と時間帯を決めて行う。自組織の外の資産を誤って検査しない

## 13-3 セキュリティ製品とクラウドのサービス

### まとめ表

| 製品・サービス | 主な利用者 | 何をするか |
| :-: | :-: | :-: |
| UTM | 中小の拠点 | FW・IPS・ウイルス対策・URL フィルタ・VPN を1台に |
| WAF | Web サイトの運営者 | Web アプリケーションへの攻撃を HTTP の中身で防ぐ |
| CASB | クラウドの利用組織 | 従業員のクラウドの利用を可視化・制御（シャドー IT） |
| CSPM | クラウドの利用組織 | クラウドの設定を継続的に監視し、不適切な設定を検知 |
| CWPP | クラウドの利用組織 | 仮想マシン・コンテナなどのワークロードを守る |
| SASE | 拠点・在宅の利用者 | ネットワークとセキュリティをクラウドからまとめて提供 |
| VDI | 利用者の端末 | デスクトップを仮想環境で動かし画面だけ転送 |

### 境界と Web の保護

#### UTM（ゆーてぃーえむ / Unified Threat Management）

- 意味：ファイアウォール、IDS/IPS、マルウェア対策、URL フィルタリング、迷惑メール対策、VPN など、複数のセキュリティ機能を1台の装置にまとめたもの
- ポイント：導入と管理が楽で、中小企業や拠点に向く。一方で、機能を全部有効にすると性能が落ち、故障するとすべての機能が止まる（単一障害点）
- 語の意味：Unified＝統合された、Threat＝脅威

#### WAF（わふ / Web Application Firewall）

- 意味：Web サーバの手前などに置き、HTTP の要求の中身を検査して、SQL インジェクションやクロスサイトスクリプティングなど Web アプリケーションへの攻撃を遮断するもの
- ポイント：ネットワークのファイアウォールはアドレスとポートで判断し、WAF は HTTP の中身で判断する。脆弱性を直すまでの間の「仮想パッチ」としても使う。誤検知（#12）に注意

#### VDI（ぶいでぃーあい / Virtual Desktop Infrastructure）

- 意味：デスクトップの環境をサーバ上の仮想マシンで動かし、利用者の端末には画面の情報だけを転送して操作させる仕組み
- ポイント：インターネットの閲覧を DMZ の VDI で行わせ、端末と VDI の間は「画面転送プロトコルだけ」にすると、Web からのマルウェアは端末に届かず、端末のファイルも Web に出せない（H31春・R3春 問16）。ファイル転送を許すとこの効果が崩れる
- 語の意味：Virtual Desktop＝仮想のデスクトップ、Infrastructure＝基盤

### クラウドのサービス

#### CASB（きゃすびー / Cloud Access Security Broker）

- 意味：従業員とクラウドサービスの間に入り、どのクラウドサービスがどう使われているかを可視化し、許可していないサービスの利用やデータの持ち出しを制御する仕組み
- ポイント：使うのはクラウドサービスを「利用する」組織の管理者。許可を得ずにクラウドを使う者（シャドー IT）の特定が定番の正解（R3春 問11・R4秋 問10・R6春 問11）。プロバイダ側の DDoS 対策や入退室管理ではない
- 語の意味：Broker＝仲介者

#### CSPM（しーえすぴーえむ / Cloud Security Posture Management）

- 意味：IaaS や PaaS の設定（ストレージの公開範囲、ログの有効化、権限の付け方など）を継続的に監視し、ベストプラクティスや基準に反する不適切な設定を検知する仕組み
- ポイント：クラウドの事故の多くは設定の誤りから起きる。「設定」を見るのが CSPM、「ワークロード（中身）」を守るのが CWPP、「利用状況」を見るのが CASB（R7秋 問15）
- 語の意味：Posture＝態勢、姿勢

#### CWPP（しーだぶりゅーぴーぴー / Cloud Workload Protection Platform）

- 意味：クラウドの仮想マシン、コンテナ、サーバレスの関数などのワークロードを対象に、脆弱性の管理、マルウェアの検知、実行時の不審な動作の検知などを行う仕組み
- ポイント：ワークロードは作っては消されるので、従来のサーバ用のウイルス対策では追いつかない。コンテナのイメージの検査なども含む
- 語の意味：Workload＝処理の単位、Protection Platform＝保護の基盤

#### SASE（さっしー / Secure Access Service Edge）

- 意味：SD-WAN などのネットワークの機能と、SWG（Web のゲートウェイ）、CASB、ZTNA、FWaaS などのセキュリティの機能を、クラウドのサービスとしてまとめて提供する考え方
- ポイント：拠点や在宅の利用者が、データセンターを経由せずに、近くのクラウドの拠点でセキュリティの検査を受けてから各サービスへつながる。ガートナーが 2019 年に提唱した
- 語の意味：Edge＝（利用者に近い）端

#### ZTNA（ぜっとてぃーえぬえー / Zero Trust Network Access）

- 意味：利用者と端末を毎回認証・検証し、許可した特定のアプリケーションにだけ接続させる方式。ネットワーク全体に入れる従来の VPN に代わるもの
- ポイント：VPN は一度つながると社内ネットワークの広い範囲に届くが、ZTNA はアプリケーション単位で許可するので、横移動されにくい

## 問題演習

- 書式：「#### 問 問題ID」の下に、問・ア〜エ・正解・解説・選択肢ごとの意味・出典を書く。「###」は小分類（クイズの範囲に使う）
- 過去問の問題IDは「sc-13-年度-q問番号」。オリジナル問題は「sc-13-o番号」

### 13-1 境界での通信の制御

#### 問 sc-13-r03h-q6

- 問：ステートフルパケットインスペクション方式のファイアウォールの特徴はどれか。

- 問：本社のデータセンターを経由せず、拠点や在宅の利用者が近くのクラウドの拠点で Web ゲートウェイ、CASB、ZTNA、ファイアウォールなどの検査を受けてから各サービスにつながるように、ネットワークとセキュリティの機能をクラウドからまとめて提供する考え方はどれか。
- ア：SASE
- イ：UTM
- ウ：VDI
- エ：DMZ
- 正解：ア
- 解説：SASE は、SD-WAN などのネットワーク機能とセキュリティ機能をクラウドのサービスとして統合して提供する。
- アの意味：正しい。
- イの意味：複数のセキュリティ機能を1台の装置にまとめたもの。社内に置く装置で、クラウドのサービスではない。
- ウの意味：デスクトップを仮想環境で動かし画面だけを転送する仕組み。
- エの意味：インターネットと内部ネットワークの間に置く緩衝のネットワーク。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「SASE（Secure Access Service Edge）」／Gartner「The Future of Network Security Is in the Cloud」2019年）

#### 問 sc-13-o11

- 問：UTM を導入するときに注意すべき点として、最も適切なものはどれか。
- ア：多くの機能を1台に集めるので、機能を有効にするほど性能が落ち、故障するとすべての機能が同時に止まる。
- イ：Web アプリケーションの脆弱性を自動で修正するので、アプリケーションの改修が不要になる。
- ウ：クラウドのサービスとして提供されるので、社内に機器を置けない。
- エ：ファイアウォールの機能がないので、別にファイアウォールを用意する必要がある。
- 正解：ア
- 解説：UTM は導入・管理が楽な一方、性能と単一障害点に注意が必要。冗長構成や機能の取捨選択を検討する。
- アの意味：正しい。
- イの意味：UTM も WAF も脆弱性そのものは直さない。
- ウの意味：UTM は主に拠点に置く装置。
- エの意味：ファイアウォールは UTM の中心の機能。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「統合脅威管理（UTM）」）
