## 18-1 ゼロトラストと AI のセキュリティ

### まとめ表

| 境界型防御 | ゼロトラスト |
| :-: | :-: |
| 社内ネットワークの中は信頼する | 場所に関係なく、何も信頼しない |
| 一度 VPN でつながれば広く届く | アクセスのたびに、リソースごとに検証 |
| 境界の FW・IDS で守る | 利用者・端末・状態を見て PDP が判断し、PEP が実施 |

| LLM のアプリの脅威 | 主な対策 |
| :-: | :-: |
| 直接のプロンプトインジェクション | 入力されたプロンプトの検証、システムプロンプトの強化 |
| 間接のプロンプトインジェクション | 外部参照データ（Web・文書）の検証と分離 |
| システムプロンプトの漏えい | 機密情報をシステムプロンプトに入れない |
| 過剰な権限（エージェント） | エージェントの権限分離、重要な操作は人が確認 |
| RAG 経由の情報漏えい | RAG のデータとデータストアへのアクセス制御 |

### ゼロトラストアーキテクチャ

#### ゼロトラストアーキテクチャ（ぜろとらすとあーきてくちゃ / ZTA: Zero Trust Architecture）

- 意味：社内か社外かというネットワークの場所では信頼を与えず、リソースへのアクセスのたびに、利用者・端末・状況を検証して、必要最小限のアクセスだけを許すという考え方に基づくシステムの設計（NIST SP 800-207）
- ポイント：SP 800-207 の基本の考え方に、全ての通信を場所に関係なく保護する、アクセスはセッションごとに許可する、利用者や端末の状態などの動的なポリシーで決める、全ての資産の状態を監視する、などがある。マイクロセグメンテーション・ZTNA（#13）・継続的な検証が実装技術

#### PDP（ぴーでぃーぴー / Policy Decision Point）

- 意味：ゼロトラストで、アクセスの要求を、ポリシーと、利用者・端末・脅威の情報に照らして、許可するか拒否するかを判断する部分。ポリシーエンジン（PE）とポリシーアドミニストレータ（PA）からなる
- ポイント：判断するのは PDP、実際に通信をつないだり切ったりするのは PEP。SP 800-207 では、この二つを分ける（制御プレーンとデータプレーン）
- 語の意味：Policy Decision＝ポリシーの判断

#### PEP（ぴーいーぴー / Policy Enforcement Point）

- 意味：ゼロトラストで、利用者とリソースの間に置かれ、PDP の判断に従って、接続を許可・監視・切断する部分
- ポイント：ゲートウェイやエージェントとして実装される。PEP を通らずにリソースに届く経路があると、ゼロトラストが成り立たない
- 語の意味：Policy Enforcement＝ポリシーの実施

### AI とセキュリティ

#### AI を使ったセキュリティ技術（えーあいをつかったせきゅりてぃぎじゅつ / AI for Security）

- 意味：機械学習や生成 AI を、セキュリティの業務に使う技術。異常な通信やログの検知、アラートの要約と優先順位付け、マルウェアの分類、脆弱性の発見など
- ポイント：大量のアラートの処理（#12 のトリアージ）を速くできる。AI の判断の誤りや、攻撃者による学習データの汚染もあるので、人の確認と組み合わせる

#### プロンプトインジェクション対策（ぷろんぷといんじぇくしょんたいさく / Prompt Injection Mitigation）

- 意味：LLM に、開発者の意図しない命令を入力や外部のデータに紛れ込ませ、指示を上書きさせる攻撃（#05）を防ぐ対策
- ポイント：開発者の指示（システムプロンプト）と、利用者の入力や外部のデータを明確に分けて扱う（プロンプト分離）。LLM は命令とデータを完全には区別できないので、出力を信用しきらず、LLM が実行できる操作の権限を絞ることが重要

#### 外部参照データの分離（がいぶさんしょうでーたのぶんり / Segregation of External Content）

- 意味：LLM が参照する Web ページ、メール、文書などの外部のデータを、命令ではなくデータとして扱われるように区切って渡し、内容も検証すること
- ポイント：外部のデータに隠された命令で LLM を操る「間接プロンプトインジェクション」への対策。RAG の検索結果やエージェントが読む Web ページが入口になる

#### エージェントの権限分離（えーじぇんとのけんげんぶんり / Agent Privilege Separation）

- 意味：LLM を使って自律的に操作する AI エージェントに、仕事に必要な最小限のツールと権限だけを与え、重要な操作（送金・削除・外部への送信）には人の承認を入れること
- ポイント：OWASP Top 10 for LLM の「過剰な権限（Excessive Agency）」への対策。プロンプトインジェクションが成功しても、できることが限られるので被害が小さくなる

#### システムプロンプトの保護（しすてむぷろんぷとのほご / System Prompt Protection）

- 意味：LLM のアプリケーションで、開発者が与える指示（システムプロンプト）を強化し、パスワードや API キーなどの機密情報をシステムプロンプトに入れないこと
- ポイント：システムプロンプトは聞き出されることがある（システムプロンプトの漏えい）ので、「秘密にして」と書くだけでは守れない。認可の判断も LLM に任せず、プログラムの側で行う

#### RAG のアクセス制御（らぐのあくせすせいぎょ / Access Control for RAG）

- 意味：検索拡張生成（RAG）で LLM に渡す文書やベクトルデータベースに対して、質問した利用者が本来見てよい文書だけを検索の対象にするアクセス制御
- ポイント：RAG のデータストアに全社の文書を権限なしで入れると、LLM を通して、見る権限のない人事や役員の文書の内容が答えに出てしまう
- 語の意味：RAG＝Retrieval-Augmented Generation（検索で補強した生成）

## 18-2 クラウドとコンテナのセキュリティ

### まとめ表

| 責務 | IaaS | PaaS | SaaS |
| :-: | :-: | :-: | :-: |
| データ・アクセス権の設定 | 利用者 | 利用者 | 利用者 |
| アプリケーション（開発・脆弱性診断） | 利用者 | 利用者 | 事業者 |
| ミドルウェア・DBMS | 利用者 | 事業者 | 事業者 |
| OS | 利用者 | 事業者 | 事業者 |
| ハードウェア・物理 | 事業者 | 事業者 | 事業者 |

### クラウドの責任と設定

#### 責任共有モデル（せきにんきょうゆうもでる / Shared Responsibility Model）

- 意味：クラウドのセキュリティの責任を、クラウドサービスプロバイダ（事業者）とクラウドサービスカスタマ（利用者）で分担する考え方。サービスの区分によって分担の境目が変わる
- ポイント：どの区分でも、データ、アカウントとアクセス権、設定は利用者の責任。JIS X 9401 の区分で、利用者がアプリケーションのアクセス制御とセキュアプログラミングを、事業者が DBMS・OS・ハードウェアを担うのは PaaS（R2・R4春 問11・12 の正解）

#### クラウドの設定不備（くらうどのせっていふび / Cloud Misconfiguration）

- 意味：ストレージを誰でも読める公開設定にする、必要以上に強い権限を付ける、ログを無効にするなど、クラウドの設定の誤りによってデータが漏れたり侵入されたりする状態
- ポイント：クラウドの事故の多くの原因。CSPM（#13）で継続的に見つけ、IaC のスキャンで作る前に防ぐ。最小権限の IAM ポリシーと、多要素認証のある管理者アカウントが基本

#### インスタンスメタデータサービスの保護（いんすたんすめただーたさーびすのほご / IMDS Protection）

- 意味：クラウドの仮想マシンが自分の設定や一時的な認証情報を取得するための内部のサービス（IMDS）を、SSRF などで外から悪用されないように守ること
- ポイント：Web アプリケーションの SSRF の脆弱性（#03）で IMDS にアクセスされ、一時的な認証情報を盗まれる事件が起きた。AWS の IMDSv2 は、先に PUT でセッショントークンを取得しないと応答しないので、単純な SSRF では情報を取られにくい

### コンテナと IaC

#### コンテナイメージの脆弱性管理（こんてなめーじのぜいじゃくせいかんり / Container Image Vulnerability Management）

- 意味：コンテナイメージに含まれる OS のパッケージやライブラリの既知の脆弱性を、ビルド時やレジストリで検査し、修正したイメージを作り直して入れ替えること
- ポイント：信頼できる最小のベースイメージを使う、イメージに秘密情報を入れない、署名したイメージだけを動かす。動いているコンテナに直接パッチを当てるのではなく、作り直して入れ替える

#### コンテナオーケストレーションのアクセス制御（こんてなおーけすとれーしょんのあくせすせいぎょ / Kubernetes RBAC and Network Policy）

- 意味：Kubernetes などで、利用者やサービスアカウントの操作を役割（Role）と割当て（RoleBinding）で制限する RBAC と、Pod の間の通信を許可したものだけに絞るネットワークポリシー
- ポイント：Kubernetes は初期状態では Pod 同士が全て通信できるので、ネットワークポリシーで必要な通信だけを許可する（マイクロセグメンテーション）。クラスタ全体の管理者権限（cluster-admin）を安易に付けない

#### IaC のセキュリティスキャン（あいえーしーのせきゅりてぃすきゃん / IaC Security Scanning）

- 意味：Terraform や CloudFormation などで書いたインフラの定義（Infrastructure as Code）を、適用する前に検査して、公開設定や過剰な権限、暗号化の無効などの設定不備を見つけること
- ポイント：作ってから CSPM で見つけるより前の段階で防げる（シフトレフト）。CI のパイプラインに組み込み、問題があれば適用を止める

## 18-3 ハードウェア・IoT・制御システムのセキュリティ

### まとめ表

| ハードウェアの仕組み | 何をするか |
| :-: | :-: |
| セキュアエレメント | 耐タンパ性のあるチップで鍵や決済の情報を保管・処理（IC カード・スマホ） |
| TPM | PC の鍵の保管、起動の計測（PCR）、状態の証明 |
| セキュアブート（UEFI） | 起動するブートローダや OS の署名を検証し、改ざんされたものを起動しない |
| SED 自己暗号化ドライブ | ドライブ自体が常に暗号化。鍵の消去で瞬時に消去 |
| 耐タンパ性 | こじ開け・解析されても内部の秘密を守る性質 |

| コンテンツ保護技術 | 使われる場所 |
| :-: | :-: |
| AACS | ブルーレイディスク |
| CSS | DVD-Video（市販の DVD） |
| CPRM | 記録用の媒体（SD メモリカード、DVD-R など） |
| CPPM | 記録済みの媒体（DVD-Audio） |
| DTCP | 機器の間のデジタル伝送（ネットワーク・IEEE 1394） |
| HDCP | 機器とディスプレイの間（HDMI・DisplayPort） |

### ハードウェアのセキュリティ

#### TPM（てぃーぴーえむ / Trusted Platform Module）

- 意味：PC などに搭載され、鍵の生成と保管、起動の過程のソフトウェアのハッシュ値の記録（PCR）、その状態の証明（アテステーション）を行う耐タンパ性のあるチップ。Trusted Computing Group が仕様を定める
- ポイント：BitLocker は、起動の過程が改ざんされていないことを TPM が確かめたときだけ鍵を出す。Windows 11 は TPM 2.0 を必須にした。TEE（#16）は CPU の中の実行領域で、TPM とは別

#### セキュアブート（せきゅあぶーと / UEFI Secure Boot）

- 意味：UEFI が、起動するブートローダや OS のローダのデジタル署名を、登録された鍵で検証し、署名が正しいものだけを起動する仕組み
- ポイント：OS より先に動いて隠れるマルウェア（ブートキット・ルートキット）を防ぐ。検証して止めるのがセキュアブート、TPM に記録して後で確かめるのが計測ブート（メジャードブート）

#### 自己暗号化ドライブ（じこあんごうかどらいぶ / SED: Self-Encrypting Drive）

- 意味：ドライブのコントローラが、書き込むデータを常にハードウェアで暗号化するドライブ。ドライブの中の鍵を消せば、データを瞬時に読めなくできる（暗号消去）
- ポイント：OS の負荷なく暗号化でき、廃棄の消去が速い。PC の起動中にロックが解除された状態では、盗まれても読まれうる

#### セキュアエレメント（せきゅあえれめんと / Secure Element）

- 意味：IC カードやスマホに搭載され、決済や認証の鍵などの秘密情報を、耐タンパ性のある環境で保管・処理するチップ
- ポイント：マイナンバーカードや決済用の IC、スマホの電子マネーなどに使われる。物理的な解析やサイドチャネル攻撃（#05）にも耐えるように作られる

#### 耐タンパ性（たいたんぱせい / Tamper Resistance）

- 意味：機器をこじ開けたり、電圧・電波・処理時間を観測したりして内部の秘密情報を取り出そうとする攻撃に対して、情報を守る性質
- ポイント：こじ開けを検知したら鍵を消す、配線を多層に埋め込む、処理時間や消費電力を一定にする、などで実現する。HSM（#15）・セキュアエレメント・TPM の前提

### IoT と制御システム

#### IEC 62443（あいいーしーろくにーよんよんさん / IEC 62443）

- 意味：産業用オートメーション及び制御システム（IACS）のセキュリティの国際規格群。組織の管理（2 シリーズ）、システム（3 シリーズ）、部品と開発（4 シリーズ）などに分かれる
- ポイント：制御システムの部品（コンポーネント）のセキュリティ要件は IEC 62443-4-2 で、これに基づく認証が ISASecure CSA。組織のマネジメントシステムを認証するのが CSMS 適合性評価制度

#### CSMS（しーえすえむえす / Cyber Security Management System）

- 意味：制御システムを運用する組織が、IEC 62443-2-1 などに基づいて、制御システムのセキュリティを継続的に管理する仕組み
- ポイント：情報システムの ISMS（#08）に当たる、制御システム版のマネジメントシステム。日本では JIPDEC が適合性評価を行っている

#### JC-STAR（じぇいしーすたー / Japan Cyber-Security Technical Assessment Requirements）

- 意味：IoT 製品のセキュリティの機能を、決められた基準で評価し、適合した製品にラベルを付けて示す日本の制度（セキュリティ要件適合評価及びラベリング制度）。IPA が運営し、2025 年 3 月から ★1 の受付が始まった
- ポイント：★1 は全ての IoT 製品が満たすべき最低限の基準で、★2 以上は用途に応じた上乗せ。調達する側がラベルで製品を選べる。政府機関の調達の要件にも使われる

#### Purdue モデル（ぱーでゅーもでる / Purdue Model）

- 意味：工場などの制御システムのネットワークを、現場の機器（レベル 0）から、制御装置、監視、生産管理、企業の情報システム（レベル 4・5）まで、階層に分けて整理するモデル
- ポイント：情報システム（IT）と制御システム（OT）の間に DMZ（レベル 3.5）を置き、直接つながないようにする。IT 側の感染が OT に広がるのを防ぐ

#### 一方向ゲートウェイ（いっぽうこうげーとうぇい / Unidirectional Gateway, Data Diode）

- 意味：物理的に一方向にしかデータを送れない構造（データダイオード）で、制御システムから情報システムへの送信だけを許し、逆方向の通信を不可能にする装置
- ポイント：ファイアウォールはソフトウェアの設定の誤りや脆弱性で逆方向の通信が通りうるが、一方向ゲートウェイは物理的に戻れない。監視データを外に出しつつ、外からの侵入を防ぐ

#### ファームウェアのセキュアアップデート（ふぁーむうぇあのせきゅああっぷでーと / Secure Firmware Update）

- 意味：IoT 機器などのファームウェアの更新で、更新データの署名を機器が検証し、正規のものだけを適用し、古い版に戻されないようにする仕組み
- ポイント：署名の検証がないと、偽のファームウェアを入れられて機器を乗っ取られる。脆弱性を直す手段がない機器は、JC-STAR などでも問題とされる

#### コンテンツ保護技術（こんてんつほごぎじゅつ / Content Protection）

- 意味：映像・音楽などのデジタルコンテンツを、暗号化と機器の認証によって、無断の複製や不正な機器への出力から守る技術
- ポイント：媒体や伝送路ごとに方式が違う。ブルーレイは AACS（R3秋 問23）、SD メモリカードは CPRM（R4秋 問23）、HDMI は HDCP

- 問：NIST SP 800-207 のゼロトラストアーキテクチャで、アクセスの要求をポリシーと利用者・端末の情報に照らして許可か拒否かを判断する構成要素はどれか。
- ア：PDP（Policy Decision Point）
- イ：PEP（Policy Enforcement Point）
- ウ：IdP（Identity Provider）
- エ：SIEM
- 正解：ア
- 解説：判断するのは PDP（ポリシーエンジンとポリシーアドミニストレータ）。PEP はその判断に従って接続を許可・切断する。
- アの意味：正しい。
- イの意味：判断に従って接続を実施する構成要素で、判断はしない。
- ウの意味：利用者を認証して情報を提供する側で、PDP の判断に使われる情報源の一つ。
- エの意味：ログを集めて分析する仕組みで、PDP の判断に使われる情報源の一つ。
- 出典：オリジナル問題（根拠：NIST SP 800-207 Zero Trust Architecture 3 Logical Components）

#### 問 sc-18-o02

- 正解：エ
- 解説：ゼロトラストでは場所で信頼を与えず、セッションごと・リソースごとに動的に判断する。

#### 問 sc-18-o03
