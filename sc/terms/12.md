## 12-1 マルウェアとランサムウェアへの対策

### まとめ表

| 検出の手法 | 何を見るか | 未知のマルウェア | 弱点 |
| :-: | :-: | :-: | :-: |
| パターンマッチング法 | 既知のマルウェアの特徴的なコード（定義ファイル） | 検出できない | 定義の更新が前提 |
| コンペア法 | 原本（安全な場所の保管物）との比較 | 改変は分かる | 原本が必要 |
| チェックサム法（インテグリティチェック法） | 事前に付けた検査用の情報との不整合 | 改変は分かる | 事前の付加が必要 |
| ヒューリスティック法（静的） | 実行せずにコードの怪しい命令や構造 | 検出できることがある | 誤検知 |
| ビヘイビア法（動的） | 実行中の動作（書込み・通信など） | 検出できる | 動いてからの検知 |

### 検出の手法

#### パターンマッチング法（ぱたーんまっちんぐほう / Pattern Matching）

- 意味：既知のマルウェアに特徴的なコードをパターン（シグネチャ）として登録した定義ファイルと、検査対象を比べ、同じパターンがあれば検出する方法
- ポイント：既知のものは確実で速いが、未知のものや、少し書き換えた亜種は検出できない。R3春 問13 の誤りの選択肢ア

#### ビヘイビア法（びへいびあほう / Behavior-based Detection）

- 意味：マルウェアが感染・発病したときに起こす、データの読込み・書込み、通信などの動作を監視して検出する方法。振る舞い検知ともいう
- ポイント：未知のマルウェアにも効く。実際の環境で動作を見る方法と、サンドボックス（仮想環境）で動かして見る方法がある。R3春 問13 の正解
- 語の意味：Behavior＝振る舞い

#### ヒューリスティック法（ひゅーりすてぃっくほう / Heuristic Detection）

- 意味：プログラムを実行せずに、コードの中のマルウェアらしい命令や構造（自己複製、暗号化された部分、怪しい API の呼出しなど）を経験則で調べて、未知のマルウェアを検出する方法
- ポイント：ビヘイビア法は「動かして」見る、ヒューリスティック法は「動かさずに」コードを見る（静的ヒューリスティック）。ただし製品によっては、エミュレータで少し動かす動的ヒューリスティックもある
- 語の意味：Heuristic＝経験則による

#### 静的解析（せいてきかいせき / Static Analysis）

- 意味：マルウェアを実行せずに、ファイルの表層情報（ハッシュ値、文字列、インポートする関数）や、逆アセンブルしたコードを読んで、機能を調べる解析
- ポイント：安全に調べられるが、暗号化や難読化（パッカー）されていると読めない

#### 動的解析（どうてきかいせき / Dynamic Analysis）

- 意味：マルウェアを、外部と切り離したサンドボックスなどで実際に動かし、作るファイル、レジストリの変更、通信先などを観察する解析
- ポイント：難読化されていても動作が分かる。ただし、仮想環境を検知すると動きを止める（サンドボックス回避）マルウェアもある

### ランサムウェアへの備え

#### 3-2-1 ルール（さんにいちるーる / 3-2-1 Backup Rule）

- 意味：バックアップを「3つ」のコピー（元データを含む）にし、「2種類」の媒体に保存し、そのうち「1つ」は離れた場所（オフサイト）に置く、という原則
- ポイント：ランサムウェアはネットワークでつながるバックアップも暗号化する。さらに1つをオフラインか変更できない形で持ち、復元のテストでエラー0を確かめる「3-2-1-1-0」という拡張もある

#### バックアップの分離（ばっくあっぷのぶんり / Backup Isolation）

- 意味：バックアップを、本番のネットワークやアカウントから切り離して保管すること（テープや外付けディスクを外す、別の認証で守る、エアギャップ）
- ポイント：ドメインの管理者権限を奪った攻撃者は、同じ権限で届くバックアップを先に消す。バックアップの管理用アカウントを本番と分けることも分離の一つ

#### WORM（わーむ / Write Once Read Many）

- 意味：一度書き込んだデータを、決めた期間は書き換えも削除もできず、読むことだけができるようにする記録の方式や機能
- ポイント：ワーム（Worm、自己増殖するマルウェア）とは別物。ログの改ざん防止やイミュータブルバックアップに使う。クラウドのオブジェクトロックもこの考え方
- 語の意味：Write Once＝一回だけ書く、Read Many＝何回も読む

#### イミュータブルバックアップ（いみゅーたぶるばっくあっぷ / Immutable Backup）

- 意味：保持期間中は、管理者の権限でも変更・削除できないように保存したバックアップ
- ポイント：ランサムウェアの攻撃者が管理者権限を奪っても消せないので、確実に戻せる。ただし保持期間の設定を誤ると、容量やコストが膨らむ
- 語の意味：Immutable＝変更できない

#### カナリアファイル（かなりあふぁいる / Canary File）

- 意味：業務では使わないおとりのファイルを置いておき、それが変更・暗号化・読み出しされたら、ランサムウェアや侵入の兆候として検知する仕組み
- ポイント：正規の利用者は触らないので、触られたら誤検知が少ない警報になる。炭鉱のカナリアが由来。ハニーポット（#13）のファイル版

#### 暗号化挙動検知（あんごうかきょどうけんち / Encryption Behavior Detection）

- 意味：短時間に大量のファイルを読み出して書き換える、ファイルのエントロピー（乱雑さ）が急に高くなる、拡張子が一斉に変わる、などのランサムウェアの暗号化の動きを検知して止める機能
- ポイント：ビヘイビア法の一種。EDR やストレージの機能として実装される。検知して止めたファイルを自動で戻す製品もある

## 12-2 脆弱性管理とデータ保護

### まとめ表

| 指標・情報源 | 作った組織 | 何が分かるか |
| :-: | :-: | :-: |
| CVE | MITRE（CVE Program） | 脆弱性の識別番号 |
| CVSS | FIRST | 脆弱性の深刻度（0.0〜10.0） |
| EPSS | FIRST | 今後30日に悪用される確率の予測 |
| KEV カタログ | CISA | 実際に悪用が確認された脆弱性の一覧 |
| JVN | JPCERT/CC・IPA | 日本の製品を含む脆弱性対策情報 |

### 脆弱性への対応

#### 脆弱性情報の収集と適用判断（ぜいじゃくせいじょうほうのしゅうしゅうとてきようはんだん / Vulnerability Triage）

- 意味：ベンダや JVN などから脆弱性情報を集め、自組織に影響がある資産を特定し、深刻度・悪用の状況・資産の重要度から、パッチを当てる順番と時期を決めること
- ポイント：CVSS の基本値は「深刻度」であって「自組織のリスク」ではない。悪用が確認されている（KEV に載った）か、インターネットに公開された資産か、を加えて優先順位を付ける

#### CVSS（しーぶいえすえす / Common Vulnerability Scoring System）

- 意味：脆弱性の深刻度を、ベンダに依存しない共通の基準で 0.0〜10.0 の数値に表す評価方法。FIRST が管理し、最新は v4.0（2023年）
- ポイント：v3.1 は基本・現状・環境の3つの評価基準。v4.0 は基本・脅威・環境・補足の4つ。基本評価基準は時間がたっても変わらない、脆弱性そのものの特性
- 語の意味：Common＝共通の、Scoring＝点数付け

#### KEV カタログ（けぶかたろぐ / Known Exploited Vulnerabilities Catalog）

- 意味：米国 CISA が公開する、実際に悪用が確認された脆弱性の一覧。米国の連邦機関には、載った脆弱性を期限内に直す義務がある
- ポイント：CVSS が高くても悪用されない脆弱性もあり、低めでも悪用中のものもある。KEV や EPSS は「悪用の可能性」で優先度を補う

#### パッチ管理（ぱっちかんり / Patch Management）

- 意味：ソフトウェアの修正プログラムを、情報収集、影響の評価、検証環境でのテスト、段階的な適用、適用状況の確認、という流れで計画的に当てること
- ポイント：当てられない機器（保守切れ、業務停止できない装置）は、通信の制限や WAF の仮想パッチなど別の対策で補い、記録しておく（NIST SP 800-40 Rev.4）

#### 資産インベントリ（しさんいんべんとり / Asset Inventory）

- 意味：組織のハードウェア・ソフトウェア・クラウドのアカウントなどの資産を、所有者・版数・設置場所とともに一覧にしたもの
- ポイント：知らない資産にはパッチを当てられない。クラウドや在宅勤務の端末で資産はすぐ変わるので「継続的に」把握することがシラバスで強調されている

#### ASM（えーえすえむ / Attack Surface Management）

- 意味：インターネットから攻撃の入口になり得る資産（公開サーバ、VPN 機器、ドメイン、クラウドのサービスなど）を、外から見て継続的に洗い出し、脆弱性やリスクを評価する取組み。外部に絞ったものを EASM（External ASM）という
- ポイント：攻撃者と同じ「外からの目」で、管理部門が把握していない資産（シャドー IT、廃止し忘れたサーバ）を見つけるのが目的。経済産業省が「ASM 導入ガイダンス」（2023年）を公表
- 語の意味：Attack Surface＝攻撃される面（攻撃対象領域）

### データを守る仕組み

#### DLP（でぃーえるぴー / Data Loss Prevention）

- 意味：個人情報や機密の文書など、守るべきデータの内容（キーワード、番号の形式、指紋）を識別して、メール・Web・USB メモリなどで外に出ようとするのを監視・遮断する仕組み
- ポイント：アクセス制御は「だれが読めるか」、DLP は「読めた人が外に出そうとしたら止める」。正規の権限をもつ内部者の持ち出しや誤送信の対策になる
- 語の意味：Data Loss＝データの喪失（漏えい）、Prevention＝防止

#### Web 分離（うぇぶぶんり / Web Isolation）

- 意味：Web の閲覧を、利用者の端末ではなく、隔離したサーバや仮想環境の中で行い、端末には画面の情報だけを送る方式。リモートブラウザ分離（RBI）とも呼ぶ
- ポイント：悪意のある Web ページのコードは隔離環境で動くので、端末や社内ネットワークに届かない。自治体のインターネット接続系の分離でも使われる

#### データマスキング（でーたますきんぐ / Data Masking）

- 意味：個人情報などの値を、一部を伏せ字にする、別の値に置き換える、などして、元の値が分からないようにすること
- ポイント：テスト環境に本番データを複製するときは、元に戻せない形で置き換える（静的マスキング）。閲覧する人の権限に応じて表示のときだけ伏せる方法（動的マスキング）もある

#### 情報の削除（じょうほうのさくじょ / Media Sanitization）

- 意味：媒体を廃棄・再利用するときに、データを復元できないようにすること。NIST SP 800-88 では、上書きなどの Clear、暗号消去や専用コマンドの Purge、物理的に壊す Destroy に分ける
- ポイント：ファイルの削除やフォーマットだけでは復元できる。SSD は上書きでは消しきれない領域があるので、暗号消去（暗号化の鍵を消す）や Purge のコマンドを使う

## 12-3 ログ管理と検知・監視

### まとめ表

| 製品 | 監視の対象 | 主な役割 |
| :-: | :-: | :-: |
| SIEM | 複数の機器のログ | 集約・相関分析・アラート |
| EDR | 端末（PC・サーバ） | 動作の記録・検知・隔離 |
| NDR | ネットワークの通信 | 通信の振る舞いの分析 |
| XDR | 端末・ネットワーク・メール・クラウドを横断 | まとめて検知・対応 |
| SOAR | 各製品のアラート | 対応手順の自動化 |

### ログの管理

#### ログ設計（ろぐせっけい / Log Design）

- 意味：どの機器から、どの事象を、どれだけの期間、どこに、どう守って保存するかを、インシデント調査と法令の要件から決めること
- ポイント：取得範囲（認証の成否、管理者の操作、通信の許可・拒否）、保存期間、改ざん防止（WORM・追記のみ・別サーバへの転送）、時刻同期を決める。攻撃者はまず手元のログを消すので、ほかの場所に送っておく

#### 時刻同期（じこくどうき / Time Synchronization）

- 意味：全ての機器の時計を NTP などで同じ時刻源に合わせ、ログのタイムスタンプを比べられるようにすること
- ポイント：時刻がずれていると、複数の機器のログをつないで攻撃の流れを追えない。タイムゾーンの表記もそろえる

#### ログの相関分析（ろぐのそうかんぶんせき / Log Correlation）

- 意味：ファイアウォール、プロキシ、認証サーバ、端末などの複数のログを、時刻・IP アドレス・利用者などで結び付けて、単独では分からない攻撃の流れを見つけること
- 例：「VPN に海外から失敗が100回」→「同じアカウントで成功」→「深夜にファイルサーバへ大量アクセス」をつなげて一つの事案と判断する

### 検知の方式と精度

#### シグネチャ型（しぐねちゃがた / Signature-based Detection）

- 意味：既知の攻撃の特徴（シグネチャ）をあらかじめ定義し、それに合致する通信や動作を不正と判断する検知の方式。不正検出（ミスユース検知）ともいう
- ポイント：「異常な通信を定義し、合致したら不正」。誤検知は少ないが、未知の攻撃は見逃す

#### アノマリ型（あのまりがた / Anomaly-based Detection）

- 意味：通常時の通信や動作を定義（学習）し、そこから外れたものを不正と判断する検知の方式。異常検出ともいう
- ポイント：「通常を定義し、外れたら不正」。未知の攻撃も見つけられるが、正常な変化（繁忙期など）を誤検知しやすい
- 語の意味：Anomaly＝異常、普通でないこと

#### インラインモードとミラーポート接続（いんらいんもーど / Inline Mode, Port Mirroring）

- 意味：インラインモードは、IPS を通信経路の上に置き、通信を通過させながら検査して、その場で遮断できる置き方。ミラーポート接続は、スイッチのミラーポートから通信の複製を受け取って経路の外で監視する置き方
- ポイント：経路の外（ミラー）からでは、その通信自体は止められない（IDS 的）。インラインは止められるが、IPS の故障や誤検知が業務の通信を止める。R5春 問12・R6秋 問13 は「置き方」×「シグネチャ／アノマリ」の4択

#### フォールスポジティブ（ふぉーるすぽじてぃぶ / False Positive）

- 意味：正常なものを、誤って攻撃や不正と判定すること（偽陽性、誤検知）
- ポイント：WAF で「<」を含む正当な数式の入力を攻撃として遮断するのが典型（R5春 問10・R6秋 問12）。多すぎると担当者が警報を見なくなる（アラート疲れ）

#### フォールスネガティブ（ふぉーるすねがてぃぶ / False Negative）

- 意味：攻撃や不正を、誤って正常と判定して見逃すこと（偽陰性）
- ポイント：WAF が検査しない独自のフィールドに攻撃を入れる、リクエストを分割して送る、などの回避で起きる。フォールスポジティブを減らそうと検知を緩めると増える

### 検知・対応の基盤

#### SIEM（しーむ / Security Information and Event Management）

- 意味：ファイアウォール、IDS、サーバ、端末など多くの機器のログを集めて保管し、相関分析して、不審な事象をアラートとして知らせる仕組み
- ポイント：SIEM は「集めて分析して知らせる」まで。対応の手順の自動化は SOAR。R6秋 問11 の誤りの選択肢エは SIEM の説明
- 語の意味：Information＝情報、Event＝事象、Management＝管理

#### EDR（いーでぃーあーる / Endpoint Detection and Response）

- 意味：PC やサーバ（エンドポイント）に入れたエージェントが、プロセスの起動、ファイルやレジストリの変更、通信などを記録・監視し、侵入後の不審な動作を検知して、端末の隔離などの対応を行う製品
- ポイント：従来のウイルス対策（EPP）は「入らせない」、EDR は「入られたあとに見つけて対応する」。記録が残るので調査にも使える
- 語の意味：Endpoint＝末端の機器、Detection＝検知、Response＝対応

#### NDR（えぬでぃーあーる / Network Detection and Response）

- 意味：ネットワークの通信を監視し、機械学習などで通常と違う振る舞い（横移動、C&C 通信、大量の持ち出し）を検知して対応する製品
- ポイント：エージェントを入れられない IoT 機器や、EDR を止められた端末の動きも、通信から見つけられる

#### XDR（えっくすでぃーあーる / Extended Detection and Response）

- 意味：端末（EDR）だけでなく、ネットワーク、メール、クラウド、ID などの複数の情報を一つの基盤で横断して分析し、検知と対応をまとめて行う製品
- ポイント：EDR を「拡張」したもの。SIEM が汎用のログ集約なのに対し、XDR は製品群の深いデータを最初から連携させて使う点が違う
- 語の意味：Extended＝拡張された

#### SOAR（そあー / Security Orchestration, Automation and Response）

- 意味：脅威インテリジェンスを活用し、複数のセキュリティ製品を連携（オーケストレーション）させ、プレイブックに沿って対応を自動化し、インシデント対応を効率化する技術
- ポイント：R6秋 問11 の正解。「全てを信頼しない」はゼロトラスト、「脅威情報構造化記述形式の交換の自動化」は TAXII、「ログの集約と相関分析」は SIEM
- 語の意味：Orchestration＝指揮して協調させること、Automation＝自動化

#### アラートトリアージ（あらーととりあーじ / Alert Triage）

- 意味：SOC で、大量のアラートを、本物の攻撃か誤検知か、どれだけ緊急か、で選別し、対応の優先順位を付けること
- ポイント：誤検知の多いルールは調整（チューニング）して減らし、本当に危ないアラートを見落とさないようにする。SOAR で情報の付加や一次判断を自動化することも多い
- 語の意味：Triage＝（救急医療の）選別

- 問：ファイアウォール、VPN 装置、認証サーバのログを突き合わせて攻撃の流れを調べようとしたが、同じ通信の記録の時刻が機器ごとに数分ずつ違っていて、つながりが分からなかった。事前にしておくべきだった対策として、最も適切なものはどれか。
- ア：ログの保存期間を延ばしておく。
- イ：全ての機器の時計を NTP で同じ時刻源に同期させておく。
- ウ：ログを WORM の媒体に保存しておく。
- エ：ログの出力を最小限にして容量を減らしておく。
- 正解：イ
- 解説：相関分析には、機器間で時刻がそろっていることが前提になる。NTP で同期させ、タイムゾーンの表記もそろえる。
- アの意味：古いログを調べるのには役立つが、時刻のずれは解決しない。
- イの意味：正しい。
- ウの意味：改ざん防止には役立つが、時刻のずれは解決しない。
- エの意味：必要な記録まで失い、調査がさらに難しくなる。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「時刻同期（NTP）とタイムスタンプ，ログの相関分析」／NIST SP 800-92）

#### 問 sc-12-o11

- 問：端末だけでなく、ネットワーク、メール、クラウド、ID の情報を一つの基盤で横断して分析し、検知と対応をまとめて行う製品の分類はどれか。
- ア：EDR
- イ：NDR
- ウ：XDR
- エ：EPP
- 正解：ウ
- 解説：XDR は EDR を拡張し、複数の領域のデータを連携させて検知・対応する。
- アの意味：端末に絞った検知と対応の製品。
- イの意味：ネットワークの通信に絞った検知と対応の製品。
- ウの意味：正しい。
- エの意味：端末にマルウェアを入らせないための、従来型の保護製品（ウイルス対策など）。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「EDR，NDR，XDR」）

#### 問 sc-12-o12

- 問：SOC で、1日に数千件のアラートが出て、担当者が重要なアラートを見落とすようになった。最初に取り組む対策として、最も適切なものはどれか。
- ア：アラートを緊急度と誤検知の可能性で選別（トリアージ）し、誤検知の多いルールを調整して減らす。
- イ：全てのアラートを止めて、月に1回ログをまとめて確認する。
- ウ：アノマリ型の検知を増やして、アラートの数をさらに増やす。
- エ：アラートの通知先を全社員に広げる。
- 正解：ア
- 解説：アラート疲れには、トリアージと検知ルールの調整（誤検知の低減）で、本当に危ないものに集中できるようにする。
- アの意味：正しい。
- イの意味：攻撃への気付きが遅れ、被害が広がる。
- ウの意味：アノマリ型は誤検知が多く、アラート疲れが悪化する。
- エの意味：判断できない人に送っても対応にならない。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「SOC の運用（アラートトリアージ，誤検知の低減）」）
