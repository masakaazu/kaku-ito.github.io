## 07-1 社内の規程と体制

### まとめ表

| 組織 | 主に対応するもの | 一言で |
| :-: | :-: | :-: |
| CSIRT | 自組織で起きたインシデント | 組織の消防署 |
| PSIRT | 自社が作った製品の脆弱性 | 製品の品質保証窓口 |
| SOC | ログ・通信の常時監視と検知 | 見張り台 |
| 情報セキュリティ委員会 | 方針の決定と全社の調整 | 経営の会議体 |

### 規程

#### 情報セキュリティ方針（じょうほうせきゅりてぃほうしん / Information Security Policy）

- 意味：組織が情報セキュリティに取り組む方向性を、トップマネジメントが正式に表明したもの。情報セキュリティポリシー
- ポイント：一般に、基本方針（なぜ・何を守るか）→ 対策基準（何をするか）→ 実施手順（どうやるか）の3階層で作る。基本方針と対策基準をあわせて「ポリシー」と呼ぶことが多い。JIS Q 27001 は、トップマネジメントが方針を確立し、文書化して組織内に伝達し、利害関係者が入手できるようにすることを求めている

#### 情報セキュリティインシデント対応規程（じょうほうせきゅりてぃいんしでんとたいおうきてい / Incident Response Policy）

- 意味：インシデントが起きたときの報告先・判断の基準・対応の手順・役割と権限・外部への連絡を定めた規程
- ポイント：「見つけたらだれに、どう報告するか」を全員が知っていることが大切。マルウェアに感染したときの対応（ネットワークから切り離す、電源は切らずに証拠を残す、報告する）も含める（#09・#19）

#### プライバシーポリシー（ぷらいばしーぽりしー / Privacy Policy）

- 意味：組織が個人情報をどのように取得・利用・提供・管理するかを、外部に向けて示した方針。個人情報保護方針
- ポイント：個人情報保護法の利用目的の公表などに対応する（#23）。社内向けの情報セキュリティ方針とは目的と読み手が違う

### 体制と窓口

#### 情報セキュリティ委員会（じょうほうせきゅりてぃいいんかい / Information Security Committee）

- 意味：経営層と各部門の責任者で構成し、情報セキュリティ方針の決定、リスク対応の承認、全社の対策の調整を行う会議体
- ポイント：CISO（最高情報セキュリティ責任者）が率いることが多い。現場でインシデントに対応する CSIRT と役割を分ける

#### CSIRT（しーさーと / Computer Security Incident Response Team）

- 意味：組織の中でインシデントの報告を受け、分析・対応・調整を行い、再発を防ぐ活動をするチーム
- ポイント：組織の内外の窓口（PoC）になり、JPCERT/CC や他組織の CSIRT と連携する。専任でなく兼任のメンバーで作る組織も多い。日本シーサート協議会（NCA）は国内の CSIRT の連携の場
- 語の意味：Computer Security＝コンピュータセキュリティ／Incident Response＝インシデント対応／Team＝チーム

#### PSIRT（ぴーさーと / Product Security Incident Response Team）

- 意味：自社が開発・販売する製品やサービスの脆弱性について、報告の受付、調査、修正版の提供、公表を行うチーム
- ポイント：CSIRT が「自組織で起きたインシデント」を扱うのに対し、PSIRT は「自社製品の脆弱性」を扱う。過去の午前Ⅱで、自社製品の脆弱性に起因するリスクに対応するのは PSIRT、と問われた。FIRST が PSIRT Services Framework を公開している
- 語の意味：Product＝製品

#### SOC（そっく / Security Operation Center）

- 意味：ファイアウォール・IDS・EDR などのログや通信を24時間体制で監視し、攻撃を検知・分析して、CSIRT などに通知する組織
- ポイント：SOC は「見張って見つける」、CSIRT は「対応して収める」の役割分担が典型。外部の事業者に委託する MSS（マネージドセキュリティサービス）も多い（#09）
- 語の意味：Security＝セキュリティ／Operation＝運用／Center＝拠点

#### 推奨される連絡窓口（すいしょうされるれんらくまどぐち / Role-based Mailbox）

- 意味：外部の人が組織にセキュリティの問題を知らせるために、決まった名前で用意しておくメールアドレス。abuse@ドメイン名（自組織からの迷惑メールや攻撃の苦情）、noc@ドメイン名（ネットワークの運用）、security@ドメイン名（セキュリティの問題・脆弱性の報告）など
- ポイント：RFC 2142 が役割ごとの名前を定めている。Web サイトでは、`/.well-known/security.txt` に連絡先や脆弱性の報告方針を書く方法もある（RFC 9116）

## 07-2 国内外の機関

### まとめ表

| 機関 | 何をする | 区別のポイント |
| :-: | :-: | :-: |
| サイバーセキュリティ戦略本部 | 国の戦略を決める | 内閣に置かれる本部 |
| 国家サイバー統括室（NCO） | 本部の事務、政府全体の司令塔 | 2025年に NISC から改組 |
| JPCERT/CC | インシデント対応の調整、脆弱性の調整 | 国内の CSIRT の調整役 |
| IPA | 届出の受付、ガイドライン、試験 | 経済産業省所管の独立行政法人 |
| NICT | 観測（NICTER）、NOTICE | 総務省所管の研究機関 |
| CRYPTREC | 暗号技術の評価・監視 | 暗号リストを作る |
| NIST | 米国の標準・ガイドライン | CSF、SP 800、FIPS |
| MITRE | CVE の運営、ATT&CK | 米国の非営利組織 |
| FIRST | CSIRT の国際フォーラム | CVSS を管理 |
| ISAC | 業界ごとの情報共有 | 金融 ISAC など |

### 国の体制

#### サイバーセキュリティ戦略本部（さいばーせきゅりてぃせんりゃくほんぶ / Cybersecurity Strategic Headquarters）

- 意味：サイバーセキュリティ基本法にもとづいて内閣に置かれ、国のサイバーセキュリティ戦略の案の作成や、政府機関の対策の基準の作成などを行う本部。本部長は内閣官房長官
- ポイント：政府機関等の統一基準群（07-4）を決定する。重要インフラの行動計画もここで決める

#### 国家サイバー統括室（こっかさいばーとうかつしつ / NCO: National Cybersecurity Office）

- 意味：内閣官房に置かれ、サイバーセキュリティ戦略本部の事務と、政府全体のサイバーセキュリティ施策の総合調整を行う組織
- ポイント：2025年に、内閣サイバーセキュリティセンター（NISC）を改組して発足した。能動的サイバー防御に関する法律の整備に合わせた体制の強化。古い問題では NISC の名前で出る
- 語の意味：National＝国家の／Cybersecurity＝サイバーセキュリティ／Office＝室

### 調整・情報共有の機関

#### JPCERTコーディネーションセンター（じぇいぴーさーとこーでぃねーしょんせんたー / JPCERT/CC）

- 意味：日本国内のインシデントの報告を受け付け、対応の支援や関係者との調整を技術的な立場から行う一般社団法人
- ポイント：特定の組織に属さない中立の調整機関。早期警戒パートナーシップでは、製品の脆弱性について開発者との調整を担う。海外の CSIRT との窓口（日本の代表的な PoC）でもある。過去の午前Ⅱの MITRE の問題で「国内のインシデントの受付・対応支援」は JPCERT/CC の役割として誤りの選択肢になった

#### FIRST（ふぁーすと / Forum of Incident Response and Security Teams）

- 意味：世界の CSIRT が加盟する国際的なフォーラム。加盟チームどうしの信頼関係の構築や情報交換を支える
- ポイント：脆弱性の深刻度の評価方法 CVSS（#12）や、PSIRT Services Framework、Traffic Light Protocol（TLP：情報の共有範囲を色で示す）を管理・公開している

#### ISAC（あいさっく / Information Sharing and Analysis Center）

- 意味：同じ業界の組織どうしで、サイバー攻撃の情報や対策を共有・分析する組織
- ポイント：金融 ISAC、ICT-ISAC、電力 ISAC など。同じ業界は同じ攻撃者にねらわれやすいので、共有の効果が大きい

#### J-CSIP（じぇいしっぷ / Initiative for Cyber Security Information sharing Partnership of Japan）

- 意味：IPA が事務局になり、重要インフラなどの業界の参加組織の間で、標的型サイバー攻撃などの情報を秘密保持契約のもとで共有する取組。サイバー情報共有イニシアティブ
- ポイント：2011年に発足。参加組織から提供された情報を IPA が分析し、匿名化して共有する。過去の午前Ⅱで「標的型サイバー攻撃などの情報を参加組織間で共有」が正解

#### NOTICE（のーてぃす / National Operation Towards IoT Clean Environment）

- 意味：総務省と NICT が2019年2月から行っている、サイバー攻撃に悪用されるおそれのある IoT 機器の調査と注意喚起の取組
- ポイント：国内のグローバル IP アドレスの IoT 機器に、推測されやすいパスワードでログインを試すなどして危険な機器を見つけ、ISP を通じて利用者に注意喚起する。ダークネット観測で感染済みの機器を見つける NICTER の取組と区別する。過去の午前Ⅱで3回出た

### 標準化・技術評価の機関

#### CRYPTREC（くりぷとれっく / Cryptography Research and Evaluation Committees）

- 意味：電子政府で使う暗号技術の安全性を評価・監視し、適切な実装法・運用法を検討する日本のプロジェクト
- ポイント：デジタル庁・総務省・経済産業省が「CRYPTREC 暗号リスト」（電子政府推奨暗号リスト・推奨候補暗号リスト・運用監視暗号リスト）を策定する（#15）。NISC（現 NCO）の基本戦略の立案、ISMS の認証、暗号モジュールの試験（JCMVP）は CRYPTREC の役割ではない

#### NIST（にすと / National Institute of Standards and Technology）

- 意味：米国国立標準技術研究所。米国商務省の機関で、暗号の標準（FIPS）、サイバーセキュリティフレームワーク（CSF）、SP 800 シリーズのガイドラインなどを発行する
- ポイント：AES・SHA-3・耐量子計算機暗号（ML-KEM など）の標準化も NIST。脆弱性データベース NVD も運営する。MITRE の役割と取り違えさせる選択肢に注意

#### MITRE（まいたー / MITRE Corporation）

- 意味：米国政府の研究開発を支援する非営利組織。CVE（共通脆弱性識別子）の運営と、攻撃の手口を体系化した MITRE ATT&CK（#02）、CWE（脆弱性の種類の一覧）の公開を行う
- ポイント：過去の午前Ⅱで「CVE の事務局であり、サイバー攻撃のプロセスを記述したナレッジベースの公開をする」が正解。フレームワークや SP の発行は NIST、EU の支援は ENISA、国内のインシデント対応は JPCERT/CC

## 07-3 届出・評価の制度

### まとめ表

| 制度 | 何をするか | 窓口・運営 |
| :-: | :-: | :-: |
| コンピュータウイルス届出制度 | ウイルスの発見・感染を届け出る | IPA |
| コンピュータ不正アクセス届出制度 | 不正アクセスの被害を届け出る | IPA |
| 早期警戒パートナーシップ | 脆弱性を届け出て、調整して公表 | IPA・JPCERT/CC（JVN で公表） |
| SECURITY ACTION | 中小企業の自己宣言 | IPA |
| 情報セキュリティサービス基準 | 監査・診断などのサービスの登録 | 経済産業省・IPA |
| ISMAP | 政府が使うクラウドの評価・登録 | ISMAP 運営委員会 |
| SCS 評価制度 | 取引先の対策の段階を評価 | 経済産業省 |

### 届出と公表

#### コンピュータウイルス届出制度（こんぴゅーたういるすとどけでせいど / Computer Virus Reporting System）

- 意味：経済産業省の告示「コンピュータウイルス対策基準」にもとづき、ウイルスを発見したり感染したりした人が IPA に届け出る制度
- ポイント：届出は義務ではなく、被害の拡大と再発の防止のための情報収集。不正アクセスの被害は「コンピュータ不正アクセス届出制度」で、同じく IPA に届け出る

#### コンピュータ不正アクセス届出制度（こんぴゅーたふせいあくせすとどけでせいど / Unauthorized Computer Access Reporting System）

- 意味：経済産業省の告示「コンピュータ不正アクセス対策基準」にもとづき、不正アクセスの被害を受けた人が IPA に届け出る制度
- ポイント：警察への被害の届出（犯罪の捜査）とは別。IPA は届出を集計・分析し、傾向と対策を公表する

#### 情報セキュリティ早期警戒パートナーシップ（じょうほうせきゅりてぃそうきけいかいぱーとなーしっぷ / Information Security Early Warning Partnership）

- 意味：ソフトウェア製品や Web サイトの脆弱性を発見した人が IPA に届け出て、JPCERT/CC が製品の開発者と調整し、修正の準備ができたら JVN で公表する、という官民の枠組み。経済産業省の告示「ソフトウェア製品等の脆弱性関連情報に関する取扱規程」にもとづく
- ポイント：Web サイトの脆弱性は、IPA がサイトの運営者に直接連絡する（JVN では公表しない）。修正前に公表して悪用されることを防ぐ「調整された開示」の考え方

#### ISO/IEC 29147（あいえすおー29147 / Vulnerability Disclosure）

- 意味：製品の開発者が、外部から脆弱性の報告を受け付け、利用者に開示（公表）するための方法を定めた国際規格
- ポイント：組織の「外」とのやりとり（受付・公表）を扱う。組織の「中」で報告を調べて修正する手順は ISO/IEC 30111。両方を合わせて PSIRT の活動の基準になる

#### ISO/IEC 30111（あいえすおー30111 / Vulnerability Handling Processes）

- 意味：製品の開発者が、報告を受けた脆弱性を組織の中で調査・検証し、修正する手順を定めた国際規格
- ポイント：29147 が開示、30111 が取扱い（処理）。セットで覚える

#### サイバー攻撃被害に係る情報の共有・公表ガイダンス（さいばーこうげきひがいにかかるじょうほうのきょうゆう・こうひょうがいだんす / Guidance on Sharing and Disclosure of Cyber Attack Damage Information）

- 意味：被害を受けた組織が、だれと、いつ、どの情報を共有し、どう公表するかの考え方と手順をまとめた指針。2023年3月に、内閣官房（当時の NISC）・警察庁・総務省・経済産業省の官民の検討会がまとめた
- ポイント：被害を受けた組織の名前を伏せた「攻撃の技術情報」は、早く共有するほど他の組織の被害を防げる、という考え方。被害の公表とは分けて考える

### 評価と登録

#### SECURITY ACTION（せきゅりてぃあくしょん / SECURITY ACTION）

- 意味：中小企業が、IPA「中小企業の情報セキュリティ対策ガイドライン」に沿った対策に取り組むことを自ら宣言する制度。一つ星（情報セキュリティ5か条に取り組む）と二つ星（自社診断と基本方針の策定・外部への公開）がある
- ポイント：第三者による認証ではなく自己宣言。ISMS 適合性評価制度（第三者の認証）、IT セキュリティ評価及び認証制度（JISEC、製品の評価）、MyJVN（脆弱性の確認ツール）と並べて出た

#### 情報セキュリティサービス基準（じょうほうせきゅりてぃさーびすきじゅん / Information Security Service Standards）

- 意味：情報セキュリティ監査、脆弱性診断、デジタルフォレンジック、セキュリティ監視・運用（SOC）などのサービスについて、一定の品質を満たすための基準。経済産業省が定め、基準に適合すると IPA が審査して「情報セキュリティサービス基準適合サービスリスト」に掲載する
- ポイント：利用者が品質の確かなサービス事業者を選びやすくするための制度。政府機関の調達でも参照される

#### サプライチェーン強化に向けたセキュリティ対策評価制度（さぷらいちぇーんきょうかにむけたせきゅりてぃたいさくひょうかせいど / SCS評価制度）

- 意味：取引先（サプライチェーン）の企業のセキュリティ対策の状況を、星の数の段階で評価・可視化する、経済産業省が整備を進める制度
- ポイント：2025年4月の中間取りまとめでは、★3（すべての企業が最低限実施すべき対策、専門家の確認を付けた自己評価）、★4（標準的に目指す対策、第三者評価）、★5（到達点、検討中）の段階を示した。発注側が取引先に求める水準をそろえるねらい
- 語の意味：SCS＝Supply Chain Security

#### ISMAP（いすまっぷ / Information system Security Management and Assessment Program）

- 意味：政府が求めるセキュリティ要求を満たすクラウドサービスを、あらかじめ評価・登録しておくことで、政府のクラウドサービスの調達のセキュリティ水準を確保する制度。政府情報システムのためのセキュリティ評価制度
- ポイント：登録は監査機関による評価にもとづく。評価の基準の「ISMAP 管理基準」は、日本セキュリティ監査協会の「クラウド情報セキュリティ管理基準（平成28年度版）」を基礎に、統一基準群などを加えて作られた。リスクの小さい業務・情報の処理に使う SaaS を対象にした、簡単な仕組みが ISMAP-LIU
- 語の意味：Management and Assessment Program＝管理と評価の制度

#### ISMAP-LIU（いすまっぷえるあいゆー / ISMAP for Low-Impact Use）

- 意味：リスクの小さな業務・情報の処理に用いる SaaS を対象として、ISMAP より少ない管理策で評価・登録する仕組み
- ポイント：過去の午前Ⅱで、「リスクの小さな業務・情報の処理に用いる SaaS サービスを対象とする」が正解。ISMS クラウドセキュリティ認証（JIS Q 27001＋27017）、SOC2 報告書（監査法人の意見）、統一基準群（政府機関のベースライン）を誤りの選択肢に並べた
- 語の意味：LIU＝Low-Impact Use（影響の小さい利用）

### 国内の指針

#### 政府機関等のサイバーセキュリティ対策のための統一基準群（せいふきかんとうのさいばーせきゅりてぃたいさくのためのとういつきじゅんぐん / Common Standards for Cybersecurity Measures for Government Agencies）

- 意味：政府機関と独立行政法人などが守るべき情報セキュリティ対策の基準をまとめたもの。統一規範・統一基準・対策基準策定ガイドラインなどで構成し、サイバーセキュリティ戦略本部が決定する
- ポイント：各機関は統一基準を最低限の水準（ベースライン）として、自らのポリシーを作る。ISMAP の要求事項の基礎にもなっている

#### サイバーセキュリティ経営ガイドライン（さいばーせきゅりてぃけいえいがいどらいん / Cyber Security Management Guidelines）

- 意味：経済産業省と IPA が策定した、経営者が認識すべきサイバーセキュリティの原則と、経営者が CISO などに指示すべき重要項目をまとめた指針
- ポイント：Ver 3.0（2023年）は「3原則」と「重要10項目」。サイバーセキュリティ対策を「コスト」ではなく将来の事業活動のための「投資」と位置付ける。過去の午前Ⅱで「投資ではなくコストとして捉える」が誤りの選択肢になった。すべての企業に一律の対策を定めたものではない

#### 中小企業の情報セキュリティ対策ガイドライン（ちゅうしょうきぎょうのじょうほうせきゅりてぃたいさくがいどらいん / Information Security Guidelines for SMEs）

- 意味：IPA が中小企業向けに、情報セキュリティ対策の考え方と進め方をまとめた指針。「情報セキュリティ5か条」、「5分でできる！情報セキュリティ自社診断」、基本方針やポリシーのひな形を含む
- ポイント：SECURITY ACTION の自己宣言の基準になる。できることから段階的に進める構成

#### サイバー・フィジカル・セキュリティ対策フレームワーク（さいばーふぃじかるせきゅりてぃたいさくふれーむわーく / CPSF: Cyber/Physical Security Framework）

- 意味：経済産業省が2019年に策定した、サイバー空間とフィジカル（現実）空間がつながる新たな産業社会（Society5.0）でのセキュリティ対策の全体像を示したフレームワーク
- ポイント：企業間のつながり（第1層）、フィジカルとサイバーの間の転写（第2層）、サイバー空間のつながり（第3層）の三層構造と、6つの構成要素（ソシキ・ヒト・モノ・データ・プロシージャ・システム）でリスクを捉える。過去の午前Ⅱで「リスクを適切に捉えるためのモデルを構築し、求められるセキュリティ対策の全体像を整理すること」が正解

### 米国 NIST のフレームワークとガイドライン

#### NISTサイバーセキュリティフレームワーク（にすとさいばーせきゅりてぃふれーむわーく / NIST CSF: Cybersecurity Framework）

- 意味：組織がサイバーセキュリティのリスクを管理するための枠組み。中心となる「コア」は機能・カテゴリ・サブカテゴリで構成する
- ポイント：1.1 版のコアの機能は、識別（IDENTIFY）・防御（PROTECT）・検知（DETECT）・対応（RESPOND）・復旧（RECOVER）の5つ。2024年2月の 2.0 版で、統治（GOVERN）が加わって6つになり、対象も重要インフラからあらゆる組織に広がった。現状と目標の姿を「プロファイル」で表し、取組の度合いを「ティア」（4段階）で表す。過去の午前Ⅱで 1.1 版の5つ、2.0 版の6つ目（GOVERN）が出た

#### NIST SP 800シリーズ（にすとえすぴー800しりーず / NIST Special Publication 800 Series）

- 意味：NIST が発行するコンピュータセキュリティのガイドライン群。シラバス案は SP 800-53（組織と情報システムのセキュリティとプライバシーの管理策の一覧）、SP 800-61（インシデント対応の手引き）、SP 800-171（政府以外の組織で管理される重要な非機密情報 CUI の保護）、SP 800-207（ゼロトラストアーキテクチャ）を挙げている
- ポイント：SP 800-61 の Rev.2 はインシデント対応を「準備／検知と分析／封じ込め・根絶・復旧／事件後の対応」の4段階で示した（#09）。2025年の Rev.3 は CSF 2.0 の6つの機能に合わせて組み直した。SP 800-171 は米国の防衛産業のサプライチェーンでの要求として知られる

### 分野別の規格と指針

#### JIS Q 27701（じすきゅー27701 / ISO/IEC 27701）

- 意味：ISMS（JIS Q 27001・27002）を拡張して、個人情報（PII）の保護を管理するプライバシー情報マネジメントシステム（PIMS）の要求事項と指針を定めた規格
- ポイント：PII 管理者（自ら個人情報を扱う組織）と PII 処理者（委託を受けて処理する組織）の両方の管理策がある。国内の個人情報保護の認証であるプライバシーマーク（JIS Q 15001）とは別のもの

#### ISO/IEC 42001（あいえすおー42001 / AI Management System）

- 意味：AI を開発・提供・利用する組織が、AI を責任をもって管理するためのマネジメントシステム（AIMS）の要求事項を定めた国際規格。2023年に発行された
- ポイント：ISMS（27001）と同じ構造（附属書 SL の共通構造）で、AI のリスクアセスメントや影響評価の要求を加えている

#### AI事業者ガイドライン（えーあいじぎょうしゃがいどらいん / AI Guidelines for Business）

- 意味：総務省と経済産業省が2024年4月に策定した、AI の開発者・提供者・利用者が取り組むべき事項をまとめた指針
- ポイント：法的な拘束力のない、自主的な取組を促すもの（ソフトロー）。共通の指針として、人間中心・安全性・公平性・プライバシー保護・セキュリティ確保・透明性・アカウンタビリティなどを挙げ、AI の主体ごとに重要事項を示す

#### つながる世界の開発指針（つながるせかいのかいはつししん / Development Principles for the Connected World）

- 意味：IPA が2016年に公表した、IoT 製品やシステムを安全・安心に開発するための17の指針
- ポイント：方針・分析・設計・保守・運用の段階ごとに、開発者が考えるべきことを示す。具体的な設計の方法は、IPA「IoT 開発におけるセキュリティ設計の手引き」が補う（脅威分析と対策の例を示す）

#### SIM3（しむきゅーぶ / Security Incident Management Maturity Model）

- 意味：CSIRT などのセキュリティインシデント管理の成熟度を評価するモデル。Open CSIRT Foundation が開発した
- ポイント：組織・人・ツール・プロセスの4つの分野で評価する。CMMC（米国防総省の取引先のサイバーセキュリティ成熟度の認証）、CMMI（開発プロセスの能力成熟度）、SAMM（OWASP のソフトウェアの保証の成熟度）と並べて出た
