## 01-1 脅威の種類と動向

### まとめ表

| 用語 | ひとことで | まぎらわしい相手 |
| :-: | :-: | :-: |
| 攻撃ベクトル | 攻撃が入ってくる「経路・手段」 | アタックサーフェス（入口の「総量」） |
| アタックサーフェス | 攻撃されうる入口の総和 | 攻撃ベクトル |
| 脅威モデリング | 設計段階で脅威を洗い出す作業 | リスクアセスメント（組織全体のリスク） |
| STRIDE | 脅威を6種類に分ける覚え方 | サイバーキルチェーン（攻撃の段階） |
| BEC | 取引先や役員になりすまして送金させる | フィッシング（偽サイトで認証情報を盗む） |
| 踏み台 | 乗っ取った機器を次の攻撃の中継に使う | 水飲み場型攻撃 |

### 脅威のとらえ方

#### 攻撃ベクトル（こうげきべくとる / Attack Vector）

- 意味：攻撃者が標的に到達し、侵入するために使う経路や手段。メール、Web サイト、VPN 機器、USB メモリ、委託先の接続など
- ポイント：「どこから・何を使って入るか」という1本1本の道筋。アタックサーフェスは、その道筋になりうる入口を全部合わせた「面積」のこと。CVSS の基本評価基準にも「攻撃元区分（Attack Vector）」として出てくる（ネットワーク・隣接・ローカル・物理）
- 例：ランサムウェア被害では、VPN 機器の脆弱性やリモートデスクトップの弱い認証が攻撃ベクトルになることが多い

#### 攻撃対象領域（こうげきたいしょうりょういき / Attack Surface）

- 意味：システムや組織が攻撃を受けうる入口（公開ポート、公開サーバ、API、アカウント、従業員、委託先など）の総和。アタックサーフェスとも呼ぶ
- ポイント：対策の基本は「攻撃対象領域の最小化」（使わないサービスを止める、公開範囲を絞る）。外部から見える資産を継続的に洗い出して管理するのが ASM／EASM（#12）
- 例：退職者のアカウント、検証用に立てたまま放置したクラウドのサーバ、使っていない公開ポートは、どれも攻撃対象領域を広げる

#### 脅威モデリング（きょういもでりんぐ / Threat Modeling）

- 意味：システムの設計段階で、データの流れや信頼の境界を図にし、どんな脅威がありうるかを体系的に洗い出して対策を決める作業
- ポイント：開発の早い段階（要件定義・設計）で行うのがセキュリティ・バイ・デザインの考え方。洗い出しの枠組みとして STRIDE がよく使われる。リスクアセスメント（#06）は組織の情報資産全体のリスクを評価する、もっと広い作業
- 例：データフロー図に「ブラウザ → Web サーバ → DB」と信頼境界を書き、境界をまたぐ流れごとに STRIDE の6つを当てはめる

#### STRIDE（すとらいど / STRIDE）

- 意味：Microsoft が提唱した、脅威を6種類に分類する頭文字。なりすまし（Spoofing）、改ざん（Tampering）、否認（Repudiation）、情報漏えい（Information disclosure）、サービス妨害（Denial of service）、権限昇格（Elevation of privilege）
- ポイント：それぞれ、守りたい性質の裏返しになっている。なりすまし↔認証（真正性）、改ざん↔完全性、否認↔否認防止、情報漏えい↔機密性、サービス妨害↔可用性、権限昇格↔認可。サイバーキルチェーン（#02）は攻撃の「段階」の分け方で、STRIDE は脅威の「種類」の分け方
- 語の意味：Spoofing＝なりすまし／Tampering＝改ざん／Repudiation＝否認／Information disclosure＝情報漏えい／Denial of service＝サービス妨害／Elevation of privilege＝権限昇格

#### 脅威シナリオ（きょういしなりお / Threat Scenario）

- 意味：「だれが・どの経路で・何を狙い・どんな被害になるか」を一続きの筋書きとして書いたもの
- ポイント：個々の脅威を並べるだけでなく、攻撃の流れとして書くことで、どこで止めるか（予防・検知・対応）を考えやすくなる。科目Bの事例問題も、多くはこの筋書きを読み解く形
- 例：「委託先の VPN アカウントが盗まれる → 社内の管理サーバに侵入 → 権限昇格 → 全サーバを暗号化し、データを持ち出して脅迫」

#### 情報セキュリティ10大脅威（じょうほうせきゅりてぃじゅうだいきょうい / 10 Major Security Threats）

- 意味：IPA が毎年公表する、前年に社会的影響が大きかった脅威のランキング。「組織」向けは順位付き、「個人」向けは五十音順
- ポイント：2026年版の組織向けは、1位 ランサム攻撃による被害、2位 サプライチェーンや委託先を狙った攻撃、3位 AIの利用をめぐるサイバーリスク（初選出）、4位 システムの脆弱性を悪用した攻撃、5位 機密情報を狙った標的型攻撃、6位 地政学的リスクに起因するサイバー攻撃（情報戦を含む）、7位 内部不正による情報漏えい等、8位 リモートワーク等の環境や仕組みを狙った攻撃、9位 DDoS攻撃、10位 ビジネスメール詐欺
- 例：シラバス案の用語例にも「情報セキュリティ 10 大脅威」が入っている。順位そのものより、各脅威の手口と対策が問われる

### 人と組織をねらう脅威

#### ビジネスメール詐欺（びじねすめーるさぎ / BEC: Business Email Compromise）

- 意味：取引先や自社の経営者になりすましたメールで、担当者をだまして攻撃者の口座に送金させる詐欺
- ポイント：マルウェアを使わないことも多く、メールのやり取りを盗み見たうえで「振込先が変わった」と自然な流れで送ってくる。対策は、メールだけで振込先の変更を受け付けず、電話など別の経路で確かめる手順を決めること。送信ドメイン認証（#14）も有効
- 語の意味：Business＝業務の／Email＝電子メール／Compromise＝侵害、危険にさらすこと

#### ソーシャルエンジニアリング（そーしゃるえんじにありんぐ / Social Engineering）

- 意味：技術ではなく、人の心理のすきや行動のミスにつけこんで、パスワードなどの秘密情報を聞き出したり、操作をさせたりする手口の総称
- ポイント：なりすまし電話、ショルダーハッキング（肩越しののぞき見）、トラッシング（ごみあさり）、権威や緊急性をよそおうメールなど。BEC やフィッシングもこれを使う。人的脆弱性をつく攻撃なので、技術的対策だけでは防げず、教育・訓練と手順で守る
- 例：「システム部です。至急確認したいのでパスワードを教えてください」という電話

#### 踏み台（ふみだい / Stepping Stone）

- 意味：攻撃者が乗っ取ったコンピュータを中継点にして、別の標的を攻撃すること。また、その中継に使われる機器
- ポイント：攻撃元を隠すため、または被害者のネットワークの内側から次の標的を狙うために使う。踏み台にされると、自社が加害者側に見えてしまう。オープンリゾルバやオープンリレー（#04）も「踏み台」の一種
- 例：セキュリティの弱い子会社のサーバを踏み台にして、親会社のネットワークに侵入する

#### アクセス権の誤設定（あくせすけんのごせってい / Access Misconfiguration）

- 意味：本来見せるべきでない人にまで閲覧や変更の権限を与えてしまう設定の誤り。クラウドストレージの公開設定ミスが典型
- ポイント：攻撃がなくても情報漏えいにつながる「脅威」として、シラバス案の脅威の種類に挙がっている。OWASP Top 10:2025 では「A01 アクセス制御の不備」「A02 セキュリティ設定のミス」が上位2つ
- 例：社外共有リンクを「リンクを知っている全員」にしたまま、顧客名簿を置いてしまう

## 01-2 マルウェア・不正プログラム

### まとめ表

| 用語 | 何をする | 見分けるキーワード |
| :-: | :-: | :-: |
| RAT | 感染した PC を遠隔操作する | 遠隔操作・C&C |
| リバースシェル | 内側から攻撃者へ接続してシェルを渡す | コネクトバック・外向き通信 |
| ランサムウェア | 暗号化して身代金を要求する | 暗号化・脅迫 |
| ポリモーフィック型 | 感染のたびに暗号化の鍵や復号部を変える | 中身の本体は同じ |
| メタモーフィック型 | 感染のたびにコード自体を書き換える | 本体も変わる |
| ファイルレスマルウェア | ディスクにファイルを残さずメモリ上で動く | PowerShell・メモリ |
| ルートキット | 侵入の痕跡やツールを隠す | 隠ぺい |
| エクスプロイトキット | 脆弱性攻撃のコードをまとめた道具箱 | 専門知識がなくても攻撃できる |

### 遠隔操作と潜伏

#### ボットとC&Cサーバ（ぼっととしーあんどしーさーば / Bot and C&C Server）

- 意味：ボットは、感染した機器を攻撃者が外部から指令して動かすためのマルウェア。指令を出すサーバを C&C サーバ（Command and Control サーバ）と呼び、多数のボットの集まりをボットネットと呼ぶ
- ポイント：ボットは C&C サーバに定期的に問い合わせて命令を受け取る（外向きの通信）。DDoS 攻撃、スパム送信、別の機器への感染拡大などに使われる。シラバス案では攻撃のライフサイクルの「C2（Command and Control）」の段階に当たる
- 例：Mirai に感染した大量の IoT 機器が、C&C サーバの指令で一斉に DDoS 攻撃を行った

#### RAT（らっと / Remote Access Trojan）

- 意味：感染したコンピュータを、攻撃者が遠隔から自由に操作できるようにするマルウェア。遠隔操作型ウイルスとも呼ぶ
- ポイント：ファイル操作、画面の取得、キー入力の記録、カメラの起動などができる。標的型攻撃で、侵入後の足場づくりに使われる。正規の遠隔操作ツール（Remote Access Tool）と同じ略語なので、文脈に注意
- 語の意味：Remote＝遠隔の／Access＝接続、利用／Trojan＝トロイの木馬

#### リバースシェル（りばーすしぇる / Reverse Shell）

- 意味：侵害したコンピュータの側から攻撃者のサーバへ接続を張り、その接続の上で攻撃者にコマンド実行の窓口（シェル）を渡すしくみ。侵害した側から通信を始めることをコネクトバックという
- ポイント：多くのファイアウォールは外から内への接続を止めるが、内から外への通信（Web 閲覧など）は通すため、それを逆手にとる。対策は外向き通信（出口）の制限と監視。過去の午前Ⅱで「コネクトバックの説明」が問われた（侵害したシステムから攻撃者のサーバに対して通信を開始する）
- 例：Web アプリの OS コマンドインジェクションで、サーバから攻撃者の 443 番ポートへ接続させる

#### ルートキット（るーときっと / Rootkit）

- 意味：攻撃者がシステムに侵入したあと、不正に組み込んだツールやプロセス、ファイル、ログの痕跡を隠すためのプログラムの集まり
- ポイント：「侵入する」道具ではなく「隠す」道具。OS のカーネルやコマンドを改変して、管理者が調べても見えないようにする。シラバス案の「ステルス技術」の一つ。見つかったら、OS の再インストールを考える
- 例：プロセス一覧を表示するコマンドを改ざんし、バックドアのプロセスだけを表示しないようにする

#### バックドア（ばっくどあ / Backdoor）

- 意味：正規の認証を通らずに、あとから再びシステムに入れるよう、攻撃者が仕込んでおく裏口
- ポイント：侵入した攻撃者が、パッチを当てられても戻ってこられるように残す（攻撃のライフサイクルでいう「永続化」）。開発者が保守用に残した隠しアカウントも、結果としてバックドアになる

### 身代金と資源の不正利用

#### ランサムウェア（らんさむうぇあ / Ransomware）

- 意味：コンピュータのファイルを暗号化したり画面をロックしたりして使えなくし、元に戻すことと引き換えに金銭（身代金）を要求するマルウェア
- ポイント：最近は、VPN 機器やリモートデスクトップから侵入し、組織のネットワーク全体を調べてから一斉に暗号化する「人手による攻撃」が中心。暗号化の前にデータを盗み、「払わなければ公開する」と脅す二重恐喝が一般的（01-4）。対策の中心は、ネットワークから切り離したバックアップ（#12）
- 語の意味：Ransom＝身代金／ware＝ソフトウェア

#### クリプトジャッキング（くりぷとじゃっきんぐ / Cryptojacking）

- 意味：他人の PC やサーバに不正に入り込み、その計算資源を勝手に使って暗号資産のマイニング（台帳への追記の計算）を行い、報酬を得る攻撃
- ポイント：データを盗んだり暗号化したりしない点が、ランサムウェアや情報窃取との違い。被害は、CPU 使用率の上昇、電気代やクラウド利用料の増加。Web ページにマイニング用スクリプトを埋め込み、閲覧者のブラウザで計算させる手口もある
- 語の意味：Crypto＝暗号（資産）／Hijacking＝乗っ取り

### 検知を逃れる工夫

#### ポリモーフィック型マルウェア（ぽりもーふぃっくがた / Polymorphic Malware）

- 意味：感染するたびに、本体を暗号化する鍵や復号用のコードを変えて、見た目（バイナリのパターン）を毎回変えるマルウェア
- ポイント：復号されたあとの本体の処理は同じ。パターンマッチング方式の検知を逃れるのがねらいで、振る舞いを見るビヘイビア法（#12）で対抗する。メタモーフィック型との違いは「本体のコードまで変えるかどうか」
- 語の意味：Poly＝多くの／morphic＝形をもつ

#### メタモーフィック型マルウェア（めたもーふぃっくがた / Metamorphic Malware）

- 意味：感染するたびに、命令の並べ替えや無意味な命令の挿入などで、本体のコードそのものを書き換えるマルウェア
- ポイント：暗号化に頼らず、コードが毎回まったく違って見えるので、ポリモーフィック型よりさらに検知しにくい。どちらもシラバス案の「ステルス技術」の例
- 語の意味：Meta＝変化して／morphic＝形をもつ

#### ファイルレスマルウェア（ふぁいるれすまるうぇあ / Fileless Malware）

- 意味：実行ファイルをディスクに保存せず、PowerShell や WMI など OS に元からある正規のツールを使って、メモリ上だけで悪意のある処理を行うマルウェア
- ポイント：ファイルが残らないので、ファイルを調べるタイプのマルウェア対策ソフトでは見つけにくく、再起動で痕跡が消えることもある。対策は、EDR による振る舞いの監視、PowerShell の実行ログの取得、メモリフォレンジック（#19）
- 例：メールの添付文書のマクロが PowerShell を起動し、攻撃コードをダウンロードしてメモリ上で実行する

### 脆弱性をつく道具

#### エクスプロイトコード（えくすぷろいとこーど / Exploit Code）

- 意味：ソフトウェアの脆弱性を悪用するためのコード。攻撃コードとも呼ぶ
- ポイント：攻撃に使われる一方、脆弱性が本当にあるかの検証にも使われる。公開されると攻撃が一気に増えるので、修正プログラムの適用を急ぐ判断材料になる（KEV、EPSS は #19）
- 例：脆弱性の情報が公表された数日後に、エクスプロイトコードがインターネット上に公開される

#### エクスプロイトキット（えくすぷろいときっと / Exploit Kit）

- 意味：OS やアプリケーションの複数の脆弱性を悪用する攻撃コードと、その管理機能をひとまとめにしたツール。脆弱性の専門知識がなくても攻撃ができる
- ポイント：改ざんした Web サイトなどに仕込み、閲覧者のブラウザやプラグインの種類を調べて、効く攻撃コードを自動で選んで送り込む（ドライブバイダウンロード、#03）
- 例：閲覧しただけで、古い版のブラウザプラグインの脆弱性をつかれてマルウェアに感染する

#### Mirai（みらい / Mirai）

- 意味：2016年に大規模な DDoS 攻撃を起こした、IoT 機器をねらうボットのマルウェア
- ポイント：ランダムな宛先 IP アドレスに Telnet（TCP 23番など）で接続し、初期設定のままの ID・パスワードでログインして感染を広げ、C&C サーバの指令で標的に DDoS 攻撃を行う。ソースコードが公開され、多くの亜種が生まれた。対策は初期パスワードの変更と不要なポートを閉じること
- 例：Web カメラや家庭用ルータが知らないうちにボットになっていた

## 01-3 脆弱性

### まとめ表

| 脆弱性 | どんな不備か | CWE の例 |
| :-: | :-: | :-: |
| 認可・アクセス制御の不備 | 他人のデータや機能に手が届く | CWE-862 認可の欠如 |
| 不適切な入力確認 | 想定外の入力をそのまま使う | CWE-20 |
| パスワードのハードコード | 認証情報をプログラムに書き込む | CWE-798 |
| 認証バイパス | 認証を経ずに機能に到達できる | CWE-306 重要な機能の認証の欠如 |
| 重要情報の平文での保存・送信 | 暗号化せずに保存・送信する | CWE-312・CWE-319 |
| レースコンディション | 処理の順序やタイミングのずれをつかれる | CWE-362・CWE-367 |

### 技術的な脆弱性

#### セキュリティホール（せきゅりてぃほーる / Security Hole）

- 意味：ソフトウェアの設計や実装の誤りによって生じた、セキュリティ上の弱点。技術的な脆弱性とほぼ同じ意味で使われる
- ポイント：修正プログラム（パッチ）が出る前に悪用されるのがゼロデイ攻撃。脆弱性には CVE の識別番号が振られ、CVSS で深刻度が評価される（#19）

#### 認可・アクセス制御の不備（にんか・あくせすせいぎょのふび / Broken Access Control）

- 意味：ログインした利用者が、本来は権限のない他人のデータや管理者用の機能にアクセスできてしまう不備
- ポイント：OWASP Top 10:2025 の1位（A01）。URL やパラメータの ID を書き換えるだけで他人の情報が見えるもの（IDOR）が典型。API でも「オブジェクトレベルの認可の不備（BOLA）」が API Security Top 10 2023 の1位。対策はサーバ側で、要求のたびに「この利用者がこのデータを扱ってよいか」を確かめること
- 例：`/orders?id=1001` を `id=1002` に変えると、他人の注文が表示される

#### 不適切な入力確認（ふてきせつなにゅうりょくかくにん / Improper Input Validation）

- 意味：外部から受け取った入力の形式・長さ・範囲を確かめずに処理に使ってしまう不備
- ポイント：SQL インジェクション、OS コマンドインジェクション、バッファオーバーフローなど多くの攻撃の入口になる（#03）。ただし入力確認だけでは足りず、出力先に合わせたエスケープやプレースホルダが根本的な対策（#17）

#### パスワードのハードコード（ぱすわーどのはーどこーど / Hard-coded Password）

- 意味：パスワードや API キーなどの認証情報を、プログラムのソースコードや設定ファイルに直接書き込んでしまうこと
- ポイント：ソースコードの公開や製品の解析で知られると、すべての利用者の機器で同じパスワードが使えてしまう。利用者が変更できないことも多い。対策はシークレットストアで管理し、コードから排除すること（#17）。CWE-798 に当たる
- 例：IoT 機器のファームウェアに保守用の固定パスワードが入っていた

#### 認証バイパス（にんしょうばいぱす / Authentication Bypass）

- 意味：本来は認証を経なければ使えない機能やデータに、認証を経ずに到達できてしまう脆弱性
- ポイント：ログイン画面は守っているが、管理画面の URL を直接指定すると開けてしまう、認証の判定をクライアント側だけで行っている、などが原因。認可の不備は「ログイン後に権限を超える」、認証バイパスは「ログインそのものを飛ばす」
- 例：`/admin/` には認証があるが `/admin/export.php` には認証の確認がない

#### 重要情報の平文での保存・送信（じゅうようじょうほうのへいぶんでのほぞん・そうしん / Cleartext Storage and Transmission）

- 意味：パスワード、個人情報、カード番号などの重要な情報を、暗号化せずに保存したり通信したりすること
- ポイント：保存は CWE-312、送信は CWE-319。パスワードは暗号化ではなく、ソルトとストレッチングを使ったハッシュで保存するのが原則（#17）。OWASP Top 10:2025 の A04「暗号化の失敗」に当たる

#### レースコンディション（れーすこんでぃしょん / Race Condition）

- 意味：複数の処理が同じ資源を同時に扱うとき、実行の順序やタイミングによって結果が変わってしまう不具合。これを悪用する攻撃もある
- ポイント：代表例が TOCTOU（Time of Check to Time of Use、確認した時点と使う時点のずれ）。権限を確認してからファイルを開くまでのすきに、ファイルをシンボリックリンクに差し替える、など。対策は確認と使用を不可分（アトミック）にすること
- 例：クーポンの使用済みチェックと使用済みフラグの更新の間に、同じ要求を同時に大量に送り、1枚のクーポンを何度も使う

### 人と組織の脆弱性

#### 人的脆弱性（じんてきぜいじゃくせい / Human Vulnerability）

- 意味：人の不注意、知識不足、心理的な弱さなど、人に起因する弱点
- ポイント：ソーシャルエンジニアリングが狙う弱点。対策は教育・訓練（標的型メール訓練など、#09）と、一人の判断だけに頼らない手順づくり（二重チェック、職務の分離）
- 例：添付ファイルを確認せずに開いてしまう、パスワードを付箋に書いて貼る

#### シャドーIT（しゃどーあいてぃー / Shadow IT）

- 意味：会社の情報システム部門の許可や管理を受けずに、従業員が業務に使っている IT 機器やクラウドサービス
- ポイント：管理の外にあるので、設定の不備や退職者のアカウントが放置されやすく、情報漏えいの原因になる。生成 AI サービスへの機密情報の入力も問題になっている。見つけて管理するには CASB（#13）が使われる
- 例：個人契約のファイル共有サービスに、顧客データを置いて取引先とやり取りする

#### 内部統制の不備（ないぶとうせいのふび / Internal Control Deficiency）

- 意味：職務の分離、承認、記録の確認などのしくみが不十分で、不正やミスを防いだり見つけたりできない状態
- ポイント：一人で申請も承認もできる、ログを誰も見ていない、などは内部不正の「機会」を生む（不正のトライアングル）。シラバス案では技術的な脆弱性と並んで「脆弱性」の例に挙がっている

### 脆弱性のリスト

#### OWASP Top 10（おわすぷとっぷてん / OWASP Top 10）

- 意味：Web アプリケーションのセキュリティ上の重大なリスクを、OWASP（Open Worldwide Application Security Project）が10項目にまとめた文書
- ポイント：2025年版は A01 アクセス制御の不備、A02 セキュリティ設定のミス、A03 ソフトウェアサプライチェーンの不備、A04 暗号化の失敗、A05 インジェクション、A06 安全でない設計、A07 認証の不備、A08 ソフトウェアやデータの完全性の不備、A09 セキュリティログとアラートの不備、A10 例外的な状況の不適切な処理。2021年版にあった SSRF は A01 に含められ、サプライチェーンが新しく入った
- 語の意味：Open＝開かれた／Worldwide＝世界規模の／Application＝アプリケーション／Security＝セキュリティ／Project＝プロジェクト

#### OWASP Top 10 for LLM Applications（おわすぷとっぷてんふぉーえるえるえむ / OWASP Top 10 for LLM Applications）

- 意味：大規模言語モデル（LLM）を使ったアプリケーションに特有のリスクを10項目にまとめた OWASP の文書
- ポイント：2025年版は LLM01 プロンプトインジェクション、LLM02 機密情報の漏えい、LLM03 サプライチェーン、LLM04 データとモデルのポイズニング、LLM05 不適切な出力の処理、LLM06 過剰な権限（エージェンシー）、LLM07 システムプロンプトの漏えい、LLM08 ベクトルと埋め込みの弱点、LLM09 誤情報、LLM10 際限のない資源の消費。攻撃の中身は #05、対策は #18
- 語の意味：LLM＝Large Language Model（大規模言語モデル）

#### OWASP API Security Top 10（おわすぷえーぴーあいせきゅりてぃとっぷてん / OWASP API Security Top 10）

- 意味：Web API に特有のリスクを10項目にまとめた OWASP の文書
- ポイント：2023年版の1位は API1 オブジェクトレベルの認可の不備（BOLA）。ほかに API2 認証の不備、API3 オブジェクトのプロパティレベルの認可の不備、API4 際限のない資源の消費、API5 機能レベルの認可の不備、API7 SSRF、API9 不適切なインベントリ管理（古い版の API が残っている）など。認可の不備が上位を占める
- 語の意味：API＝Application Programming Interface

## 01-4 不正の動機とメカニズム

### まとめ表

| 用語 | ひとことで |
| :-: | :-: |
| 不正のトライアングル | 動機・機会・正当化の3つがそろうと不正が起きる |
| ハクティビズム | 政治的・社会的な主張のためのハッキング |
| RaaS | ランサムウェアを「サービス」として貸し出す分業のしくみ |
| イニシャルアクセスブローカー | 侵入口（アクセス権）を売る業者 |
| 二重恐喝（多重恐喝） | 暗号化に加えて「公開するぞ」と脅す |
| ダークウェブ | 特別なソフトでしか接続できない匿名のネットワーク上のサイト |

### 内部不正の理論

#### 不正のトライアングル（ふせいのとらいあんぐる / Fraud Triangle）

- 意味：米国の犯罪学者クレッシーが唱えた理論で、「動機・プレッシャー」「機会」「正当化」の3つの要素がそろったときに不正が起きるとする考え方
- ポイント：組織が直接減らしやすいのは「機会」（アクセス権の最小化、職務の分離、ログの監視）。IPA の「組織における内部不正防止ガイドライン」は、状況的犯罪予防の考え方から「犯行を難しくする」「捕まるリスクを高める」「犯行の見返りを減らす」「犯行の誘因を減らす」「犯罪の弁明をさせない」の5つの基本原則を示している
- 例：動機＝借金の返済、機会＝一人で顧客データを持ち出せる権限、正当化＝「会社は自分を正当に評価していない」

### 攻撃者とその分業

#### ハクティビズム（はくてぃびずむ / Hacktivism）

- 意味：政治的・社会的な主張を広めるために行うハッキング活動。ハック（Hack）とアクティビズム（Activism、社会運動）を合わせた言葉
- ポイント：金銭目的ではなく、主張の対象となる政府機関や企業に DDoS 攻撃や Web ページの改ざんを行う。10大脅威 2026 の「地政学的リスクに起因するサイバー攻撃」とも関係が深い

#### RaaS（らーす / Ransomware as a Service）

- 意味：ランサムウェアの開発者が、攻撃を実行する者（アフィリエイト）にランサムウェアや交渉用の基盤を提供し、得た身代金を分け合う分業のしくみ
- ポイント：高い技術がなくても攻撃に参加できるため、攻撃が増える原因になった。侵入口はイニシャルアクセスブローカーから買うこともあり、「開発・侵入・実行」が別々の集団に分かれている
- 語の意味：Ransomware＝ランサムウェア／as a＝として／Service＝サービス

#### イニシャルアクセスブローカー（いにしゃるあくせすぶろーかー / IAB: Initial Access Broker）

- 意味：企業のネットワークに侵入するための足がかり（盗んだ VPN の認証情報、侵害したサーバへのアクセス権など）を手に入れて、ほかの攻撃者に売る者
- ポイント：RaaS のアフィリエイトがここから侵入口を買い、すぐに暗号化や情報窃取に移れる。売買はダークウェブのフォーラムなどで行われる
- 語の意味：Initial＝最初の／Access＝アクセス／Broker＝仲介業者

#### 二重恐喝（にじゅうきょうかつ / Double Extortion）

- 意味：ランサムウェア攻撃で、データを暗号化するだけでなく、事前に盗んだデータを「身代金を払わなければ公開する」と脅すこと。さらに DDoS 攻撃や取引先・顧客への連絡で圧力をかけるものを多重恐喝という
- ポイント：バックアップから復旧できても、情報漏えいの脅迫は残る。だから「バックアップがあれば大丈夫」とはいえず、持ち出しの検知（DLP、外向き通信の監視）も必要
- 語の意味：Double＝二重の／Extortion＝恐喝、ゆすり

#### ダークウェブ（だーくうぇぶ / Dark Web）

- 意味：Tor などの特別なソフトウェアを使わないと接続できない、匿名性の高いネットワーク上の Web サイト群
- ポイント：盗まれた個人情報や認証情報、攻撃ツール、侵入口の売買、ランサムウェア集団のリーク（暴露）サイトなどがある。脅威インテリジェンス（#09）では、自社の情報が出回っていないかを監視する対象になる

### 01-1 脅威の種類と動向

#### 問 sc-01-o01

- 問：STRIDE の分類と、その脅威によって主に損なわれる性質の組合せとして、適切なものはどれか。
- ア：Repudiation（否認）― 機密性
- イ：Elevation of privilege（権限昇格）― 否認防止
- ウ：Spoofing（なりすまし）― 可用性
- エ：Tampering（改ざん）― 完全性
- 正解：エ
- 解説：STRIDE の6つは、守りたい性質の裏返しになっている。改ざんは完全性、なりすましは真正性（認証）、否認は否認防止、情報漏えいは機密性、サービス妨害は可用性、権限昇格は認可を損なう。
- アの意味：否認が損なうのは否認防止。機密性を損なうのは Information disclosure（情報漏えい）。
- イの意味：権限昇格が損なうのは認可。否認防止を損なうのは Repudiation。
- ウの意味：なりすましが損なうのは真正性（認証）。可用性を損なうのは Denial of service。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：Microsoft「脅威モデリング」の STRIDE の説明）

#### 問 sc-01-o02

- 問：攻撃対象領域（アタックサーフェス）の説明として、最も適切なものはどれか。
- ア：攻撃者が標的に侵入するために実際に使った1本の経路
- イ：攻撃者が侵入後に権限を広げていくときに通る内部ネットワークの範囲
- ウ：攻撃を受けうる公開サービス、API、アカウント、委託先の接続などの入口の総和
- エ：脆弱性の深刻度を、攻撃元の位置によって4段階に分けた評価項目
- 正解：ウ
- 解説：攻撃対象領域は、攻撃されうる入口を全部合わせた「面積」。小さくするほど攻撃を受けにくくなるので、「攻撃対象領域の最小化」が設計の原則になる。
- アの意味：攻撃ベクトル（攻撃の経路・手段）の説明。
- イの意味：ラテラルムーブメント（横展開）の範囲の話で、攻撃対象領域ではない。
- ウの意味：正しい。
- エの意味：CVSS の基本評価基準の「攻撃元区分（Attack Vector）」の説明。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」中分類23 小分類1 の用語例「攻撃ベクトル，攻撃対象領域（アタックサーフェス）」、中分類24 小分類1「攻撃対象領域の最小化」）

#### 問 sc-01-o03

- 問：A社の経理担当者に、取引先の営業担当者を名乗るメールが届いた。これまでのやり取りの文面を引用したうえで「口座を変更したので、今月分から新しい口座に振り込んでほしい」と書かれていた。この攻撃に対する対策として、最も有効なものはどれか。
- ア：経理部の PC のマルウェア対策ソフトの定義ファイルを毎日更新する
- イ：社外からのメールを、すべて本文をテキスト形式に変換して受信する
- ウ：メールの添付ファイルを開く前に、拡張子を確認するよう教育する
- エ：振込先の変更依頼は、メールではなく、あらかじめ登録した電話番号に電話して取引先に確かめる手順にする
- 正解：エ
- 解説：ビジネスメール詐欺（BEC）は、マルウェアや添付ファイルを使わずに、だまして送金させる。メール以外の、あらかじめ確かめてある連絡先で本人に確認する手順が最も有効。
- アの意味：BEC はマルウェアを使わないことが多く、定義ファイルの更新では防げない。
- イの意味：HTML メールによる攻撃への対策で、文面でだます BEC は防げない。
- ウの意味：添付ファイルのない詐欺メールには効かない。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：IPA「情報セキュリティ10大脅威 2026」10位 ビジネスメール詐欺）

#### 問 sc-01-o04

- 問：脅威モデリングに関する記述として、適切なものはどれか。
- ア：運用中のシステムに疑似的な攻撃を行い、侵入できるかどうかを確かめる
- イ：組織が保有する情報資産を洗い出し、資産ごとに年間予想損失額を算出する
- ウ：設計段階でデータの流れと信頼境界を整理し、ありうる脅威を体系的に洗い出して対策を決める
- エ：攻撃者の行動を偵察から目的の実行までの段階に分け、どの段階で止めるかを決める
- 正解：ウ
- 解説：脅威モデリングは、作る前（設計段階）に脅威を洗い出す作業。データフロー図に信頼境界を書き、STRIDE などで脅威を当てはめる。
- アの意味：ペネトレーションテスト（#19）の説明。
- イの意味：定量的リスク分析（#06）の説明。
- ウの意味：正しい。
- エの意味：サイバーキルチェーン（#02）を使った防御の考え方。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」中分類23 小分類1 用語例「脅威モデリング（STRIDE など）」）

#### 問 sc-01-o05

- 問：IPA「情報セキュリティ10大脅威 2026」の組織向けで、初めて選ばれ3位になった脅威はどれか。
- ア：リモートワーク等の環境や仕組みを狙った攻撃
- イ：地政学的リスクに起因するサイバー攻撃（情報戦を含む）

- アの意味：2021年から選ばれていて、2026年は8位。
- イの意味：2025年に初めて選ばれ、2026年は6位。
- ウの意味：正しい。
- エの意味：2019年から選ばれていて、2026年は2位。

### 01-2 マルウェア・不正プログラム

- エ：LLM に、メールの送信やファイルの削除まで行える広い権限の外部ツールを使わせており、不正な指示で意図しない操作が実行される
- 正解：エ
- 解説：過剰な権限（LLM06）は、LLM に必要以上の機能・権限・自律性を与えたために、誤動作や攻撃で有害な操作が行われるリスク。対策は、ツールの権限を必要最小限にし、重要な操作には人の承認をはさむこと。
- アの意味：誤情報（LLM09）。
- イの意味：不適切な出力の処理（LLM05）。
- ウの意味：データとモデルのポイズニング（LLM04）。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：OWASP「OWASP Top 10 for LLM Applications 2025」）

#### 問 sc-01-o14

- 問：シャドーITに関する記述として、適切なものはどれか。
- ア：自社の Web サイトをまねて作られた、フィッシング用の偽サイト
- イ：攻撃者が正規のサービスに見せかけて、通信を外部に持ち出すしくみ

- イの意味：ドメインフロンティングなど、C2 通信の隠ぺいの説明に近い（#02）。

- エの意味：正しい。

### 01-4 不正の動機とメカニズム

#### 問 sc-01-o15

- 問：不正のトライアングルの3要素のうち、アクセス権の最小化や職務の分離によって、組織が直接減らすことをねらうものはどれか。
- ア：動機・プレッシャー
- イ：機会
- ウ：正当化
- エ：報酬
- 正解：イ
- 解説：不正のトライアングルは「動機・プレッシャー」「機会」「正当化」の3つ。権限を絞る、一人で完結させない、ログを監視する、といった対策は「機会」を減らす。
- アの意味：個人の事情（借金など）によるもので、組織が直接なくすのは難しい。
- イの意味：正しい。
- ウの意味：「自分は悪くない」という言い訳。ルールの周知や公平な評価で減らすが、権限の最小化が直接ねらうものではない。
- エの意味：不正のトライアングルの要素ではない。
- 出典：オリジナル問題（根拠：IPA「組織における内部不正防止ガイドライン」／IPA「支援士試験 シラバス（案）」用語例「不正のトライアングル」）

#### 問 sc-01-o16

- 問：RaaS（Ransomware as a Service）の説明として、適切なものはどれか。
- ア：ランサムウェアの被害を受けた企業に代わって、攻撃者と身代金の交渉を行うサービス
- イ：ランサムウェアで暗号化されたファイルを、身代金を払わずに復号するツールを提供するサービス
- ウ：ランサムウェアの開発者が攻撃の実行者にランサムウェアや基盤を提供し、得た身代金を分け合う分業のしくみ
- エ：クラウド上のバックアップを、ランサムウェアで書き換えられないように保護するサービス
- 正解：ウ
- 解説：RaaS は攻撃者側の分業モデル。開発者とアフィリエイト（実行者）が分かれ、侵入口はイニシャルアクセスブローカーから買うこともある。高い技術がなくても攻撃に加われるので、被害が広がった。
- アの意味：身代金交渉の代行で、攻撃者側のしくみではない。
- イの意味：防御側の復号ツールの提供（No More Ransom など）。
- ウの意味：正しい。
- エの意味：イミュータブルバックアップ（#12）の説明。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「RaaS（Ransomware as a Service），イニシャルアクセスブローカー」）

#### 問 sc-01-o17

- 問：ランサムウェア攻撃の「二重恐喝」の説明として、適切なものはどれか。
- ア：身代金の支払いを、暗号資産と現金の2つの方法で要求する
- イ：同じ企業を2回続けて攻撃し、2回分の身代金を要求する
- ウ：攻撃者が、被害企業と取引先の両方のネットワークを同時に暗号化する
- エ：暗号化したデータの復号と引き換えの要求に加えて、事前に盗んだデータを公開すると脅して支払いを迫る
- 正解：エ
- 解説：二重恐喝では、暗号化の前にデータを盗み出しておく。バックアップから復旧できても情報漏えいの脅迫が残るため、支払いの圧力が強くなる。DDoS 攻撃や顧客への連絡を加えるものは多重恐喝と呼ぶ。
- アの意味：支払い手段の話で、恐喝の手口とは関係ない。
- イの意味：再攻撃は起こりうるが、二重恐喝の意味ではない。
- ウの意味：サプライチェーンへの被害の広がりで、二重恐喝の意味ではない。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「二重恐喝（多重恐喝）」／IPA「情報セキュリティ10大脅威 2026」1位 ランサム攻撃による被害）

#### 問 sc-01-o18

- 問：イニシャルアクセスブローカーの説明として、適切なものはどれか。
- ア：企業のアクセス権の申請を受け付けて、承認した権限を各システムに設定する担当者
- イ：脆弱性を発見した研究者と製品開発者の間に入り、脆弱性情報の公表時期を調整する機関
- ウ：企業のネットワークに侵入するための認証情報やアクセス権を入手し、ほかの攻撃者に販売する者

- 正解：ウ

- アの意味：アクセス権管理の担当者の説明。
- イの意味：JPCERT/CC などの調整機関の役割（#07）。
- ウの意味：正しい。
- エの意味：CASB（#13）の説明。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「イニシャルアクセスブローカー」）
