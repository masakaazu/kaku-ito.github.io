## 10-1 アクセス制御のモデルと仕組み

### まとめ表

| モデル | だれが権限を決めるか | 判断のもと | 例 |
| :-: | :-: | :-: | :-: |
| DAC 任意アクセス制御 | 資源の所有者 | 所有者が付けた権限 | UNIX のパーミッション |
| MAC 強制アクセス制御 | システム（管理者の方針） | 主体と資源のラベル（機密区分） | SELinux、軍の機密区分 |
| RBAC ロールベース | 管理者 | 利用者に割り当てた役割 | 「経理担当」ロール |
| ABAC 属性ベース | 管理者（ポリシー） | 主体・資源・環境の属性 | 「営業部かつ勤務時間内かつ社内端末」 |

### 制御のモデル

#### 任意アクセス制御（にんいあくせすせいぎょ / DAC: Discretionary Access Control）

- 意味：ファイルなどの資源の所有者が、自分の判断で、だれにどのアクセスを許すかを決める方式
- ポイント：柔軟だが、所有者が誤って広く公開したり、マルウェアが所有者の権限で権限を変えたりできる。UNIX のパーミッションや Windows の ACL が代表
- 語の意味：Discretionary＝裁量による、任意の

#### 強制アクセス制御（きょうせいあくせすせいぎょ / MAC: Mandatory Access Control）

- 意味：システムが定めた方針（主体と資源に付けた機密区分などのラベル）にもとづいて、所有者の意思に関係なくアクセスを強制的に制御する方式
- ポイント：所有者でも方針に反する権限は付けられない。Bell-LaPadula モデルでは「自分より上の区分は読めない（no read up）」「自分より下の区分には書けない（no write down）」で情報の漏れを防ぐ。メッセージ認証符号の MAC と同じ略語なので注意
- 語の意味：Mandatory＝強制の

#### ロールベースアクセス制御（ろーるべーすあくせすせいぎょ / RBAC: Role-Based Access Control）

- 意味：「経理担当」「人事部長」などの役割（ロール）に権限を割り当て、利用者にはロールを割り当てることで、アクセスを制御する方式
- ポイント：人事異動のときはロールを付け替えるだけでよく、管理が楽になる。職務の分離（#08）も、相反するロールを同じ人に割り当てない制約で表せる

#### 属性ベースアクセス制御（ぞくせいべーすあくせすせいぎょ / ABAC: Attribute-Based Access Control）

- 意味：利用者（部署・役職）、資源（機密度・所有部署）、環境（時刻・場所・端末の状態）などの属性と、それを組み合わせたポリシーにもとづいて、アクセスのたびに許可を判断する方式
- ポイント：RBAC より細かく、状況に応じた判断ができる。ゼロトラスト（#18）の「アクセスのたびに判断する」考え方と相性がよい。ポリシーの記述言語に XACML がある

#### 最小特権（さいしょうとっけん / Least Privilege）

- 意味：利用者やプロセスに、仕事に必要な最小限の権限だけを与えること（#06 の最小権限の原則）
- ポイント：OS では、管理者権限で常に動かさない、サービスごとに専用の権限の低いアカウントで動かす。必要なときだけ一時的に権限を上げる（Just-In-Time）

### 特権とデータを守る仕組み

#### 特権アクセス管理（とっけんあくせすかんり / PAM: Privileged Access Management）

- 意味：管理者アカウントなどの特権 ID の利用を、申請・承認、一時的な貸出し、パスワードの自動変更、操作の記録と監視によって管理する仕組み
- ポイント：特権 ID のパスワードを金庫（ボールト）で管理して利用者に見せない、使うたびにパスワードを変える、操作を録画して後で確かめられるようにする。攻撃者は横展開で特権 ID をねらう（#02）
- 語の意味：Privileged＝特権のある／Access Management＝アクセスの管理

#### セキュアOS（せきゅあおーえす / Secure OS）

- 意味：強制アクセス制御と最小特権の仕組みを組み込み、管理者（root）であっても方針の外の操作をできないようにした OS、またはその機能
- ポイント：SELinux、AppArmor、TOMOYO Linux など。Web サーバのプロセスが乗っ取られても、方針で許されたファイル以外には触れられないので、被害を限定できる

#### ストレージ暗号化（すとれーじあんごうか / Storage Encryption）

- 意味：ディスク全体や、ボリューム単位でデータを暗号化すること。フルディスク暗号化（BitLocker・FileVault など）や、暗号化機能付きのディスク（SED）
- ポイント：PC やディスクの紛失・盗難、廃棄のときの漏えいを防ぐ。ログインして起動している間は自動で復号されるので、動いている端末を乗っ取られたときの漏えいは防げない

#### ファイル暗号化（ふぁいるあんごうか / File Encryption）

- 意味：ファイル単位で暗号化すること。ファイルを持ち出したり送ったりしても、鍵を持たない人は読めない
- ポイント：ストレージ暗号化と違い、ファイルがディスクの外に出ても暗号化されたまま。共有の範囲の管理には、鍵や権限を一元管理する IRM（DRM）も使われる

#### データベース暗号化（でーたべーすあんごうか / Database Encryption）

- 意味：データベースに格納するデータを暗号化すること。データファイル全体をデータベース管理システムが自動で暗号化・復号する透過的データ暗号化（TDE）や、特定の列だけを暗号化する列暗号化がある
- ポイント：TDE はアプリケーションを変えずに導入でき、ディスクやバックアップの盗難には効く。しかし、正規の SQL で取り出すと復号された状態で返るので、SQL インジェクションや権限のある内部者の持ち出しは防げない

## 10-2 利用者認証の方式

### まとめ表

| 認証の要素 | 意味 | 例 |
| :-: | :-: | :-: |
| 知識 | 本人だけが知っていること | パスワード、PIN、秘密の質問 |
| 所持 | 本人だけが持っているもの | IC カード、スマートフォン、セキュリティキー |
| 生体 | 本人の身体・行動の特徴 | 指紋、顔、静脈、虹彩、署名の筆圧 |

### 認証の組み立て

#### 多要素認証（たようそにんしょう / MFA: Multi-Factor Authentication）

- 意味：知識・所持・生体の3つの要素のうち、異なる2つ以上を組み合わせて本人を確かめる認証
- ポイント：パスワードと秘密の質問は、どちらも知識なので多要素ではない（多段階認証）。パスワードとスマートフォンのワンタイムコードは、知識と所持で多要素。ただし、フィッシングで中継されると突破されうる（AiTM、#02）

#### 多段階認証（ただんかいにんしょう / Multi-Step Authentication）

- 意味：認証を複数の段階に分けて行うこと。要素の種類が同じでもよい
- ポイント：「パスワードのあとに秘密の質問」は2段階だが1要素。多要素認証と取り違えさせる選択肢に注意

#### リスクベース認証（りすくべーすにんしょう / Risk-Based Authentication）

- 意味：ログインのときの端末、場所、時刻、IP アドレス、操作のくせなどからリスクを評価し、普段と違う（リスクが高い）ときだけ追加の認証を求める方式
- ポイント：利用者の手間を減らしつつ、不正ログインを防ぐ。クレジットカードの EMV 3-D セキュアも、リスクが低い取引は追加の入力なしで通す（フリクションレス）

#### フィッシング耐性のある認証（ふぃっしんぐたいせいのあるにんしょう / Phishing-Resistant Authentication）

- 意味：利用者が偽のサイトにだまされて操作しても、認証の情報が攻撃者に使われない認証の方式
- ポイント：FIDO2・パスキーは、認証の情報を正規のサイトのドメイン（オリジン）に結び付けるので、偽のサイトでは使えない。パスワードや SMS・アプリのワンタイムコードは、偽のサイトに入力させて中継できるので、フィッシング耐性がない。クライアント証明書を使う TLS の相互認証も耐性がある

#### ワンタイムパスワード（わんたいむぱすわーど / OTP: One-Time Password）

- 意味：1回だけ使える使い捨てのパスワード。時刻をもとに作る TOTP（RFC 6238、30秒ごとに変わる）、回数のカウンタをもとに作る HOTP（RFC 4226）、SMS やメールで送るワンタイムコードなどがある
- ポイント：盗まれても次は使えないので、パスワードの使い回しやリプレイ攻撃に強い。ただし、偽のサイトにその場で入力させて中継されると突破される。SMS は SIM の乗っ取り（SIM スワップ）でも奪われる
- 語の意味：One-Time＝1回限りの

#### チャレンジレスポンス認証（ちゃれんじれすぽんすにんしょう / Challenge-Response Authentication）

- 意味：サーバが毎回違う乱数（チャレンジ）を送り、利用者側がパスワードや秘密鍵を使ってその応答（レスポンス）を計算して返し、サーバが確かめる方式
- ポイント：パスワードそのものはネットワークに流れず、毎回の応答が違うので、盗聴とリプレイ攻撃に強い。FIDO の認証も、チャレンジに秘密鍵で署名して返すチャレンジレスポンスの一種

#### エンティティ認証（えんてぃてぃにんしょう / Entity Authentication）

- 意味：通信の相手（利用者、機器、サーバ）が、主張するとおりの本物であることを確かめること
- ポイント：メッセージ認証（内容が改ざんされていない、送信元が正しいことを確かめる）と区別する。TLS のサーバ証明書の検証は、サーバのエンティティ認証

#### 身元確認（みもとかくにん / Identity Proofing）

- 意味：利用者をシステムに登録するときに、その人が実在する本人であることを、身分証明書などで確かめること。NIST SP 800-63 では IAL（身元確認保証レベル）で強さを表す
- ポイント：ログインのたびに本人かを確かめる「当人認証（Authentication、AAL）」とは別。過去の午前Ⅱで、「利用者本人と写真付き身分証とを照合」が Identity Proofing として正解。SP 800-63 は IAL（身元確認）・AAL（当人認証）・FAL（フェデレーション）の3つの保証レベルを分けて定める。2025年に第4版（SP 800-63-4）が公表された
- 語の意味：Identity＝身元／Proofing＝証明すること

#### 3Dセキュア（すりーでぃーせきゅあ / 3-D Secure）

- 意味：ネットショッピングのクレジットカード決済で、カード会社が本人を確かめる認証の仕組み。カード会社に登録したパスワードやワンタイムパスワード、スマートフォンのアプリでの承認などで確かめる
- ポイント：カードの番号・有効期限・セキュリティコードは盗まれると第三者でも入力できるので、それだけでは本人の確認にならない。現在の EMV 3-D セキュア（2.0）はリスクベース認証を取り入れている。日本ではクレジットカード・セキュリティガイドラインにより、2025年3月末までにすべての EC 加盟店での導入が求められた
- 語の意味：3-D＝3つのドメイン（カード会社・加盟店・その間の基盤）

## 10-3 生体認証とパスワードレス認証

### まとめ表

| 指標 | 意味 | しきい値を厳しくすると |
| :-: | :-: | :-: |
| FRR 本人拒否率 | 本人なのに拒否される割合 | 上がる（使いにくい） |
| FAR 他人受入率 | 他人なのに受け入れる割合 | 下がる（安全） |
| EER 等価誤り率 | FRR と FAR が等しくなる点の値 | ― |

### 生体認証

#### 生体認証（せいたいにんしょう / Biometric Authentication）

- 意味：身体的特徴（指紋、静脈、顔、虹彩、声など）や行動的特徴（署名の筆跡や筆圧、キーストロークのくせ、歩き方）を使って本人を確かめる認証
- ポイント：忘れたり貸したりできないが、一度漏れた特徴は変更できない。だからサーバに生体情報を送らず、端末の中で照合する方式（FIDO）が望ましい。成人の虹彩のパターンはほとんど変わらないので、登録の更新がほぼ不要（過去の午前Ⅱの正解）

#### 本人拒否率（ほんにんきょひりつ / FRR: False Rejection Rate）

- 意味：生体認証で、本人なのに誤って拒否してしまう割合
- ポイント：照合のしきい値を厳しくすると上がる。高いと利用者が何度も認証をやり直すことになり、使いにくい
- 語の意味：False Rejection＝誤った拒否

#### 他人受入率（たにんうけいれりつ / FAR: False Acceptance Rate）

- 意味：生体認証で、他人を誤って本人として受け入れてしまう割合
- ポイント：しきい値を厳しくすると下がる。安全性に直結するので、重要なシステムでは FAR を低くする。FRR と FAR はトレードオフの関係
- 語の意味：False Acceptance＝誤った受入れ

#### 等価誤り率（とうかあやまりりつ / EER: Equal Error Rate）

- 意味：しきい値を変えていったときに、FRR と FAR が等しくなる点の誤りの割合
- ポイント：生体認証の方式の精度を1つの数で比べるときに使う。小さいほど精度が高い。実際の運用のしきい値は、用途に応じて EER の点からずらして決める
- 語の意味：Equal Error＝等しい誤り

#### ライブネス検知（らいぶねすけんち / Liveness Detection）

- 意味：生体認証で、写真・動画・マスク・シリコン製の偽の指などではなく、生きた本人がその場にいることを確かめる技術
- ポイント：アクティブ検知は、まばたきや首を動かすなどの動作を利用者に求めて確かめる。パッシブ検知は、利用者に動作を求めず、画像の質感や奥行き、血流などから判断する。ディープフェイク（#05）への対策としても重要

### パスワードレス認証

#### FIDO（ふぁいど / Fast IDentity Online）

- 意味：パスワードに頼らない認証の標準を作る業界団体 FIDO Alliance と、その仕様。利用者の端末（認証器）で生体認証や PIN による本人確認を行い、端末の秘密鍵でサーバからのチャレンジに署名して返す
- ポイント：生体情報も秘密鍵も端末から出ない。サーバには公開鍵しか登録されないので、サーバから漏れても悪用されにくい。古い仕様に UAF（パスワードレス）・U2F（2つ目の要素）がある。過去の午前Ⅱで「スマートフォンで顔認証を行った後、スマートフォン内の秘密鍵でデジタル署名を生成して認証サーバに送信」が UAF の正解
- 語の意味：Fast＝速い／IDentity＝身元／Online＝オンライン

#### FIDO2（ふぁいどつー / FIDO2）

- 意味：W3C の WebAuthn と、FIDO Alliance の CTAP を合わせた、Web でのパスワードレス認証の仕様
- ポイント：WebAuthn はブラウザと Web サイト（サーバ）の間の API、CTAP はブラウザ・OS と認証器（セキュリティキーやスマートフォン）の間のプロトコル。登録時にサイトごとに鍵ペアを作るので、サイト間で追跡されにくい

#### WebAuthn（うぇぶおーせん / Web Authentication）

- 意味：Web サイトが、ブラウザを通じて公開鍵暗号による認証を行うための W3C の標準 API
- ポイント：鍵は Web サイトのドメイン（RP ID）に結び付けて作られ、ブラウザが今開いているサイトのドメインを確かめるので、偽のサイトでは正規のサイトの鍵が使われない（フィッシング耐性）

#### CTAP（しーたっぷ / Client to Authenticator Protocol）

- 意味：パソコンやスマートフォン（クライアント）と、外部の認証器（USB・NFC・Bluetooth のセキュリティキーや、別のスマートフォン）の間の通信の手順
- ポイント：パソコンでのログインに、近くにある自分のスマートフォンを認証器として使う（QR コードと Bluetooth で近さを確かめる）ことも CTAP で行う

#### パスキー（ぱすきー / Passkey）

- 意味：FIDO の認証情報（サイトごとの鍵ペア）の呼び名。OS やパスワード管理ソフトのアカウントを通じて複数の端末で同期できるもの（同期パスキー）と、1台の端末やセキュリティキーから出ないもの（デバイス固定パスキー）がある
- ポイント：パスワードの代わりに、端末の生体認証や PIN でロックを解除して使う。IdP がパスキーに対応していれば、IdP を使ってログインする Web サーバも利用者の生体情報を受け取らない。生体情報は利用者の端末の中だけで使われ、ブラウザ・Web サーバ・IdP のどれにも送られない（過去の午前Ⅱの正解）

### 10-1 アクセス制御のモデルと仕組み

#### 問 sc-10-o01

- 問：アクセス制御の方式のうち、資源に付けた機密区分のラベルと利用者の許可のレベルにもとづいてシステムが制御し、資源の所有者であっても方針に反する権限を付けられないものはどれか。
- ア：任意アクセス制御（DAC）
- イ：ロールベースアクセス制御（RBAC）
- ウ：強制アクセス制御（MAC）
