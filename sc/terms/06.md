## 06-1 情報セキュリティの考え方

### まとめ表

| 特性 | 守るもの | 損なう例 | 主な対策 |
| :-: | :-: | :-: | :-: |
| 機密性 | 許された人だけが見られる | 情報漏えい、盗聴 | アクセス制御、暗号化 |
| 完全性 | 正確で完全なまま | 改ざん、誤った更新 | ハッシュ・署名、入力の確認 |
| 可用性 | 必要なときに使える | DoS、故障、ランサムウェア | 冗長化、バックアップ |
| 真正性 | 本物であると確かめられる | なりすまし | 認証、デジタル署名 |
| 責任追跡性 | だれがしたか追える | 共有 ID での操作 | 個人ごとの ID、ログ |
| 否認防止 | したことを後で否定させない | 「送っていない」と言い張る | デジタル署名、タイムスタンプ |
| 信頼性 | 意図どおりに一貫して動く | 誤動作、処理の欠陥 | テスト、品質管理 |

### 情報セキュリティの7つの特性

#### 機密性（きみつせい / Confidentiality）

- 意味：認可されていない個人・エンティティ（主体）・プロセスに対して、情報を使用させず、また、開示しない特性
- ポイント：完全性・可用性と合わせて情報セキュリティの3要素（CIA）。JIS Q 27000 は、ほかに真正性・責任追跡性・否認防止・信頼性を「含めることもある」としている。どの特性かを問う問題では、損なう事象（漏えい＝機密性、改ざん＝完全性、停止＝可用性）から考える

#### 完全性（かんぜんせい / Integrity）

- 意味：情報が正確で、完全である特性。許可なく変更・削除されていないこと
- ポイント：改ざんの検知にはハッシュ値やメッセージ認証符号（MAC）、デジタル署名を使う（#15・#16）。「誤ったデータが入力されない」ことも完全性の問題

#### 可用性（かようせい / Availability）

- 意味：認可されたエンティティが要求したときに、アクセスと使用が可能である特性
- ポイント：DoS 攻撃（#04）、ランサムウェア（#01）、機器の故障、災害で損なわれる。冗長化、バックアップ、事業継続計画（BCP）で守る

#### 真正性（しんせいせい / Authenticity）

- 意味：エンティティ（利用者・装置・情報など）が、それが主張するとおりのものであるという特性
- ポイント：なりすましや偽のデータの防止。利用者の認証、メッセージの送信元の確認、デジタル署名で確かめる

#### 責任追跡性（せきにんついせきせい / Accountability）

- 意味：あるエンティティの動作が、そのエンティティだけにさかのぼって一意に追跡できる特性
- ポイント：共有のアカウントを使うと、だれの操作か分からず責任追跡性が損なわれる。個人ごとの ID、改ざんされないログの記録と保管で確保する

#### 否認防止（ひにんぼうし / Non-repudiation）

- 意味：ある事象や行為が起きたこと、およびそれを起こしたエンティティを、後から否認できないように証明できる特性
- ポイント：送信者の秘密鍵によるデジタル署名とタイムスタンプで実現する。共通鍵を使う MAC は、受信者も同じ MAC を作れるので第三者に対する否認防止にならない（#15）

#### 信頼性（しんらいせい / Reliability）

- 意味：意図した動作と結果が、一貫して得られる特性
- ポイント：システムの品質の面。可用性（使えること）と混同しやすい。信頼性は「使ったとき正しく動くこと」

### 守り方の原則

#### 多層防御（たそうぼうぎょ / Defense in Depth）

- 意味：1つの対策が破られても被害を防げるように、入口・内部・出口、ネットワーク・端末・アプリケーション・データなど、複数の層に独立した対策を重ねる考え方
- ポイント：入口対策（メールの検査、ファイアウォール）だけでなく、内部対策（アクセス制御、横展開の検知）と出口対策（外向き通信の監視、C2 の遮断）を組み合わせる。同じ種類の対策を2つ重ねるだけでは、同じ方法で両方破られうる

#### セキュリティ・バイ・デザイン（せきゅりてぃ・ばい・でざいん / Security by Design）

- 意味：システムの企画・設計の段階からセキュリティを組み込んでおくこと
- ポイント：後から対策を足すより費用が少なく、効果が高い。開発工程の早い段階で安全を確かめることを「シフトレフト」ともいう（#17）。CISA などは、製品の提供者が利用者に対策を任せず、自ら安全に作る責任を負うことを求めている

#### セキュア・バイ・デフォルト（せきゅあ・ばい・でふぉると / Secure by Default）

- 意味：製品を初期設定のまま使っても安全であるようにしておくこと
- ポイント：初期パスワードの共通化、不要なサービスが最初から有効、などは反対の例。利用者が追加の設定をしなくても、MFA やログの記録が有効になっている状態をめざす

#### 最小権限の原則（さいしょうけんげんのげんそく / Principle of Least Privilege）

- 意味：利用者やプログラムには、業務や処理に必要な最小限の権限だけを与えるという原則
- ポイント：アカウントを乗っ取られたときの被害を小さくする。管理者権限の常用をやめる、DB のアカウントの権限を絞る（#03）、使わなくなった権限を外す

#### need-to-knowの原則（にーどとぅのうのげんそく / Need-to-know Principle）

- 意味：業務上その情報を知る必要がある人にだけ、情報へのアクセスを許すという原則
- ポイント：最小権限の原則が「操作の権限」の考え方なのに対し、need-to-know は「どの情報を知ってよいか」の考え方。役職が高くても、業務に必要なければ見せない

#### フェイルセーフ（ふぇいるせーふ / Fail-safe）

- 意味：故障や異常が起きたときに、システムを人命や設備にとって安全な状態に移す設計
- ポイント：停電のときに非常口の電気錠を開ける（逃げられるようにする）のはフェイルセーフ。故障しても機能を落として動き続けるのはフェールソフト、誤った操作をできないようにするのはフールプルーフ、故障しても全機能を続けるのはフォールトトレランス
- 語の意味：Fail＝故障する／Safe＝安全な

#### フェイルセキュア（ふぇいるせきゅあ / Fail-secure）

- 意味：故障や異常が起きたときに、情報や資産を守る側（閉じる・拒否する）の状態に移す設計
- ポイント：停電のときにサーバ室の電気錠を閉じたままにする、認証サーバにつながらないときはログインを拒否する、など。人命が関わる場所ではフェイルセーフを優先する

#### フールプルーフ（ふーるぷるーふ / Foolproof）

- 意味：利用者が誤った操作をしても、システムが危険な状態にならないように、誤りを防いだり知らせたりする設計
- ポイント：入力の誤りを知らせて正しい入力を促す、ふたを閉めないと動かない電子レンジ、など。過去の午前Ⅱで、フェールセーフ・フェールソフト・フォールトトレランスと並べて出た

#### 攻撃対象領域の最小化（こうげきたいしょうりょういきのさいしょうか / Attack Surface Reduction）

- 意味：攻撃者がねらえる入口（公開しているサービス、ポート、機能、アカウント）を、必要なものだけに減らすこと
- ポイント：不要なサービスの停止、使わない機能の削除、管理画面をインターネットに公開しない。攻撃対象領域そのものの意味は #01

### マネジメントの基本

#### リスクマネジメント（りすくまねじめんと / Risk Management）

- 意味：リスクについて、組織を指揮・管理するための調整された活動。JIS Q 31000 は、リスクを「目的に対する不確かさの影響」と定義している
- ポイント：JIS Q 31000 の流れは、適用範囲・状況・基準の確定 → リスクアセスメント（特定・分析・評価）→ リスク対応、これをコミュニケーション・協議と、モニタリング・レビューが取り囲む。影響には好ましいもの（機会）も含む

#### 情報セキュリティ事象（じょうほうせきゅりてぃじしょう / Information Security Event）

- 意味：情報セキュリティ方針への違反や管理策の不具合の可能性、またはセキュリティに関係するかもしれない未知の状況を示す、システム・サービス・ネットワークの状態の発生
- ポイント：「何か起きたかもしれない」段階。そのうち、事業運営を危うくし情報セキュリティを脅かす可能性が高いものが情報セキュリティインシデント。事象をすべてインシデントとして扱うわけではない

#### 情報セキュリティインシデント（じょうほうせきゅりてぃいんしでんと / Information Security Incident）

- 意味：望まない、または予期しない、単独または一連の情報セキュリティ事象であって、事業運営を危うくする可能性と、情報セキュリティを脅かす可能性が高いもの
- ポイント：インシデント対応（#09）の対象。事象を報告させ、インシデントかどうかを判断（トリアージ）する手順を決めておく

#### 責任共有モデル（せきにんきょうゆうもでる / Shared Responsibility Model）

- 意味：クラウドサービスで、セキュリティの責任をクラウド事業者と利用者がどう分担するかを示す考え方
- ポイント：IaaS は OS から上が利用者の責任、PaaS はアプリケーションとデータ、SaaS はデータとアカウントの管理と設定が利用者の責任。どの形態でも、データとアクセス権の管理は利用者に残る。クラウドの設定の誤りによる漏えいは、多くが利用者側の責任の範囲で起きる（#18）

#### 外部委託のセキュリティ（がいぶいたくのせきゅりてぃ / Supplier Security）

- 意味：業務やシステムの運用を外部に委託したり、クラウドサービスを使ったりするときに、委託先・提供者のセキュリティを確保するための管理
- ポイント：選ぶときの評価（認証の取得状況、ISMAP、#07）、契約でのセキュリティ要件・再委託の条件・監査の権利・事故の報告の定め、委託中の監視、終了時のデータの返却・消去。委託しても、委託元の責任はなくならない

## 06-2 リスクの見つけ方と測り方

### まとめ表

| 段階 | JIS Q 27000 でいう内容 | 成果 |
| :-: | :-: | :-: |
| リスク特定 | リスクを発見・認識・記述する（リスク源・事象・原因・結果） | リスクの一覧 |
| リスク分析 | リスクの特質を理解し、リスクレベルを決定する | リスクレベル |
| リスク評価 | 分析の結果をリスク基準と比べ、受容できるかを決める | 対応の優先順位 |
| リスク対応 | リスクを修正する（回避・低減・移転・保有） | リスク対応計画 |

### 資産とリスクの種類

#### 情報資産台帳（じょうほうしさんだいちょう / Information Asset Inventory）

- 意味：組織が持つ情報資産（データ、ソフトウェア、機器、サービス、人、施設など）を洗い出し、管理責任者、保管場所、重要度（機密性・完全性・可用性の評価）などを記録した一覧
- ポイント：リスクアセスメントの出発点。台帳にない資産は守れない。クラウドのデータや、私物の端末、シャドー IT（#01）の把握が漏れやすい

#### リスクの種類（りすくのしゅるい / Types of Risk）

- 意味：シラバス案は、オペレーショナルリスク（業務の誤り・システムの障害・不正など、日常の業務から起きるもの）、サプライチェーンリスク（取引先や委託先から起きるもの）、外部サービス利用のリスク、SNS による情報発信のリスク（炎上・誤投稿・なりすまし）、地政学的リスク（国家間の対立による攻撃や規制）を挙げている
- ポイント：情報セキュリティの脅威は技術的なものだけではない。地政学的リスクには、国家が背景にある攻撃（#01 の APT）や、特定の国の製品・サービスの利用の制限がある

#### ISO/IEC 27005（あいえすおー27005 / ISO/IEC 27005）

- 意味：情報セキュリティのリスクマネジメントの進め方を示した国際規格。JIS Q 27001 のリスクアセスメントとリスク対応の要求を、実際にどう行うかを説明する指針
- ポイント：2022年版では、資産から考える「資産ベース」に加えて、起こりうる出来事から考える「事象ベース」の特定の方法も示した。JIS Q 31000 の考え方に合わせてある

### リスクの測り方

#### 年間予想損失額（ねんかんよそうそんしつがく / ALE: Annualized Loss Expectancy）

- 意味：あるリスクによって、1年間に失うと予想される金額。ALE＝SLE（単一損失予想額）× ARO（年間発生率）
- ポイント：定量的リスク分析の代表的な指標。対策の費用と比べて、対策をする価値があるかを判断する。対策の年間の効果＝対策前の ALE − 対策後の ALE
- 例：SLE が 500 万円、ARO が 0.2（5年に1回）なら、ALE は 100 万円
- 語の意味：Annualized＝1年あたりにした／Loss＝損失／Expectancy＝予想

#### 単一損失予想額（たんいつそんしつよそうがく / SLE: Single Loss Expectancy）

- 意味：あるリスクが1回起きたときに失うと予想される金額。SLE＝資産の価値 × 暴露係数（EF：1回の事故で資産の価値の何割を失うか）
- 例：資産の価値が 2,000 万円、EF が 25% なら、SLE は 500 万円
- 語の意味：Single＝1回の

#### 年間発生率（ねんかんはっせいりつ / ARO: Annualized Rate of Occurrence）

- 意味：あるリスクが1年間に起きると予想される回数
- ポイント：10年に1回なら 0.1、1年に3回なら 3。過去の事故の記録や、業界の統計から見積もる
- 語の意味：Rate of Occurrence＝発生の割合

#### リスクの定量的分析（りすくのていりょうてきぶんせき / Quantitative Risk Analysis）

- 意味：リスクの大きさを、金額や確率などの数値で表す分析
- ポイント：対策の費用との比較がしやすい。一方、発生率や損失額の正確な見積もりが難しい。定性的分析は、大・中・小や 1〜5 のような段階でリスクを表す方法で、手軽だが評価する人によって差が出やすい

#### リスクの定性的分析（りすくのていせいてきぶんせき / Qualitative Risk Analysis）

- 意味：リスクの大きさを、「高・中・低」のような段階や言葉で表す分析
- ポイント：数値の根拠が乏しくても行える。リスクマトリックスで、起こりやすさと影響の段階を組み合わせてリスクレベルを決めることが多い

#### リスクマトリックス（りすくまとりっくす / Risk Matrix）

- 意味：縦軸に影響の大きさ、横軸に起こりやすさを取った表で、リスクレベルを決める道具
- ポイント：右上（起こりやすく影響が大きい）ほど優先して対応する。リスクレベルは、起こりやすさと結果の組合せで表したリスクの大きさ

#### リスクレベル（りすくれべる / Level of Risk）

- 意味：結果（影響）と、その起こりやすさの組合せで表される、リスクの大きさ
- ポイント：リスク分析の成果。リスク評価で、これをリスク基準と比べる

### 分析のアプローチ

#### ベースラインアプローチ（べーすらいんあぷろーち / Baseline Approach）

- 意味：既存の規格やガイドライン（管理策の一覧）を基準として、それと比べて足りない対策を洗い出すリスク分析の方法
- ポイント：手間が少なく速いが、組織に固有のリスクを見落としやすく、基準のレベルが組織に合わないことがある

#### 非形式的アプローチ（ひけいしきてきあぷろーち / Informal Approach）

- 意味：組織の内外の専門家や担当者の経験と判断にもとづいて、リスクを分析する方法
- ポイント：速く手軽だが、分析する人によって結果が偏り、根拠の説明が難しい

#### 詳細リスク分析（しょうさいりすくぶんせき / Detailed Risk Analysis）

- 意味：情報資産ごとに、資産の価値、脅威、脆弱性を詳しく評価して、リスクを分析する方法
- ポイント：精度が高いが、時間と費用が大きい

#### 組合せアプローチ（くみあわせあぷろーち / Combined Approach）

- 意味：重要な資産やリスクの高い部分には詳細リスク分析を、それ以外にはベースラインアプローチを使うなど、複数の方法を組み合わせる方法
- ポイント：手間と精度のバランスが取れる。多くの組織で採用されている

### アセスメントの言葉（JIS Q 27000）

#### 脅威（きょうい / Threat）

- 意味：システムや組織に損害を与える可能性がある、望ましくないインシデントの潜在的な原因
- ポイント：脆弱性（弱点）と取り違えさせる選択肢が過去の午前Ⅱで2回出た。脅威＝原因（攻撃者、災害、誤操作）、脆弱性＝付け込まれる弱点
- 例：マルウェア、不正アクセス、地震、従業員の誤操作

#### 脆弱性（ぜいじゃくせい / Vulnerability）

- 意味：1つ以上の脅威によって付け込まれる可能性のある、資産または管理策の弱点
- ポイント：脅威があっても脆弱性がなければ、リスクは小さい。ソフトウェアの欠陥だけでなく、手順の不備や人の知識不足も脆弱性（#01）

#### リスク基準（りすくきじゅん / Risk Criteria）

- 意味：リスクの重大性を評価するための目安とする条件。JIS Q 27001 は、リスク受容基準と、情報セキュリティリスクアセスメントを実施するための基準を確立・維持することを求めている
- ポイント：リスク評価のときに使う物差し。前もって決めておき、くり返しても一貫した、妥当で比較できる結果が出るようにする

#### リスク源（りすくげん / Risk Source）

- 意味：それ自体または他との組合せによって、リスクを生じさせる力を本来もっている要素
- ポイント：リスク特定で、リスク源・事象・その原因・起こりうる結果を特定する

#### リスク所有者（りすくしょゆうしゃ / Risk Owner）

- 意味：リスクを運用管理することについて、責任と権限をもつ人または主体
- ポイント：JIS Q 27001 は、リスク所有者を特定すること、リスク対応計画と残留リスクの受容についてリスク所有者の承認を得ることを求めている。情報システム部門が自動的にリスク所有者になるわけではなく、業務の責任者がなることが多い

#### リスク特定（りすくとくてい / Risk Identification）

- 意味：リスクを発見、認識、記述するプロセス。リスク源、事象、それらの原因と起こりうる結果の特定を含む
- ポイント：JIS Q 27000 の用語の問題（過去の午前Ⅱで2回）の正解の選択肢

#### リスク分析（りすくぶんせき / Risk Analysis）

- 意味：リスクの特質を理解し、リスクレベルを決定するプロセス
- ポイント：起こりうる結果と、起こりやすさを見積もる

#### リスク評価（りすくひょうか / Risk Evaluation）

- 意味：リスクとその大きさが、受容可能か許容可能かを決定するために、リスク分析の結果をリスク基準と比較するプロセス
- ポイント：過去の午前Ⅱでは、この定義を「リスク対応とは」と書き換えた誤りの選択肢が出た。リスク対応は「リスクを修正するプロセス」

#### リスク態度（りすくたいど / Risk Attitude）

- 意味：リスクを評価して、追求・保有・テイク（取る）・回避する組織の取り組み方
- ポイント：リスク選好（リスクアペタイト）は、組織が目的のために追求したり保有したりしてよいとするリスクの量と種類。リスク回避的な態度の組織は、小さなリスクでも避けようとする

## 06-3 リスク対応

### まとめ表

| 選択肢 | すること | 例 |
| :-: | :-: | :-: |
| リスク回避 | 原因となる活動をやめる | 個人情報を扱うサービスをやめる |
| リスク低減（軽減） | 起こりやすさや影響を小さくする | 暗号化、MFA、バックアップ |
| リスク移転（共有） | 他者と分け合う | サイバー保険、外部委託 |
| リスク保有（受容） | 何もせず受け入れる | 損失が小さいので対策しない |

### 対応の選択肢

#### リスク回避（りすくかいひ / Risk Avoidance）

- 意味：リスクを生じさせる活動を始めない、またはやめることで、リスクをなくす対応
- ポイント：事業の機会も失う。「Web でのクレジットカードの決済をやめ、決済代行に任せる」は、自社でカード情報を扱うことの回避（決済代行への移転とも見られる）

#### リスク低減（りすくていげん / Risk Modification / Reduction）

- 意味：リスクの起こりやすさや、起きたときの影響を小さくする対応。リスク軽減ともいう
- ポイント：管理策（対策）を導入するのはほとんどがこれ。起こりやすさを下げる（パッチ、MFA）ものと、影響を下げる（暗号化、バックアップ）ものがある

#### リスク移転（りすくいてん / Risk Transfer / Sharing）

- 意味：保険や契約によって、リスクの全部または一部を他者と分け合う対応。リスク共有ともいう
- ポイント：サイバー保険で損害の費用を移せるが、評判の低下や法的な責任は移せないことが多い。外部委託しても、委託元の管理の責任は残る

#### リスク保有（りすくほゆう / Risk Retention / Acceptance）

- 意味：特に対策をせず、リスクを受け入れる対応。リスク受容ともいう
- ポイント：リスクがリスク受容基準を下回る、または対策の費用が見合わないときに選ぶ。何もしないのではなく、受け入れることを判断し、承認し、監視する

### 対応の管理

#### リスク対応計画（りすくたいおうけいかく / Risk Treatment Plan）

- 意味：選んだリスク対応をどのように実施するか（だれが、いつまでに、どの管理策を、どれだけの資源で）を定めた計画
- ポイント：JIS Q 27001 は、リスク対応計画を作り、リスク所有者の承認を得ることを求めている。必要な管理策を附属書 A と比べて漏れがないか確かめ、適用宣言書（#08）にまとめる

#### リスク登録簿（りすくとうろくぼ / Risk Register）

- 意味：特定したリスクと、その分析・評価の結果、リスク所有者、対応の状況などを記録して管理する一覧
- ポイント：リスクの状況を継続的に見直すための台帳。情報資産台帳が「何を持っているか」なのに対し、リスク登録簿は「何が起こりうるか」の一覧

#### 残留リスク（ざんりゅうりすく / Residual Risk）

- 意味：リスク対応をしたあとに残っているリスク
- ポイント：リスクを完全になくすことはできないので、必ず残る。残留リスクがリスク受容基準以下であることを確かめ、リスク所有者が受容を承認する（リスク受容の承認）。気付いていないリスクも含まれうる

#### リスクコミュニケーション（りすくこみゅにけーしょん / Risk Communication）

- 意味：リスクについて、経営者、従業員、取引先、利用者などの利害関係者と、情報を提供・共有し、意見を交わすこと
- ポイント：JIS Q 31000 では「コミュニケーション及び協議」として、リスクマネジメントのすべての段階で行うものとされる

#### リスクコントロール（りすくこんとろーる / Risk Control）

- 意味：リスクの起こりやすさや影響を、管理策によって抑えること。損失が起きたときの資金の手当て（リスクファイナンス：保険など）と対になる考え方
- ポイント：リスク回避・低減はリスクコントロール、リスク移転（保険）・保有はリスクファイナンスに分類されることが多い

- ウの意味：資産の価値そのもの。

- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「年間予想損失額（ALE），単一損失予想額（SLE），年間発生率（ARO）」）

#### 問 sc-06-o07

- 問：SLE が 1,000 万円、ARO が 0.25（ALE は 250 万円）のリスクに対し、年間 80 万円の費用がかかる対策を入れると、ARO が 0.25 から 0.1 に下がると見積もった。この対策について、最も適切な判断はどれか。
- ア：ALE は対策の判断には使えない
- イ：対策後も損失がなくならないので、導入する価値はない
- ウ：対策後の ALE は 170 万円で、効果が費用を下回る
- エ：対策後の ALE は 100 万円で、年間 150 万円の損失が減り、費用 80 万円を上回るので、導入する価値がある
- 正解：エ
- 解説：対策後の ALE＝1,000 万円×0.1＝100 万円。減る損失＝250−100＝150 万円/年。費用 80 万円より大きいので、費用に見合う。
- アの意味：ALE はまさに対策の費用対効果の判断に使う。
- イの意味：残留リスクは必ず残る。費用対効果で判断する。
- ウの意味：計算を誤っている。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「年間予想損失額（ALE）」）

#### 問 sc-06-o08

- 問：リスク分析のアプローチのうち、既存の基準や管理策の一覧と比べて、足りない対策を洗い出す方法はどれか。
- ア：非形式的アプローチ
- イ：詳細リスク分析
- ウ：組合せアプローチ
- エ：ベースラインアプローチ
- 正解：エ
- 解説：既存の基準（ベースライン）と比べるのがベースラインアプローチ。手間は少ないが、組織に固有のリスクを見落としやすい。
- アの意味：専門家の経験と判断にもとづく方法。
- イの意味：資産ごとに価値・脅威・脆弱性を詳しく評価する方法。
- ウの意味：重要な部分は詳細リスク分析、それ以外はベースラインで、と組み合わせる方法。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「リスク分析のアプローチ」／ISO/IEC TR 13335-3）

#### 問 sc-06-o09

- 問：JIS Q 27001:2023 で、リスク対応計画と残留リスクの受容について承認を得る相手として定められているものはどれか。
- ア：内部監査員
- イ：認証機関の審査員
- ウ：リスク所有者
- エ：情報システム部門の担当者
- 正解：ウ
- 解説：リスクを運用管理する責任と権限をもつリスク所有者が、対応計画を承認し、残留リスクを受け入れる。
- アの意味：ISMS が規格や方針に合っているかを確かめる人で、リスクを受け入れる立場ではない。
- イの意味：外部から適合を審査する立場。
- ウの意味：正しい。
- エの意味：リスクの責任と権限をもつとは限らない。
- 出典：オリジナル問題（根拠：JIS Q 27001:2023 6.1.3 f)）

### 06-3 リスク対応

#### 問 sc-06-o10

- 問：EC サイトで、サイバー攻撃による損害の費用に備えてサイバー保険に加入した。このリスク対応はどれか。
- ア：リスク回避
- イ：リスク低減
- ウ：リスク移転
- エ：リスク保有
- 正解：ウ
- 解説：保険は、損害の費用を保険会社と分け合う（移す）リスク移転（共有）。攻撃の起こりやすさ自体は変わらない。
- アの意味：原因となる活動（EC サイトの運営）をやめること。
- イの意味：対策で起こりやすさや影響を小さくすること。
- ウの意味：正しい。
- エの意味：対策せず受け入れること。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「リスク対応の選択肢」）

#### 問 sc-06-o11

- 問：リスク保有（リスク受容）の説明として、最も適切なものはどれか。
- ア：リスクを把握しないまま、何も対策をしないこと
- イ：リスクがリスク受容基準を下回るなどの理由で対策をしないことを判断し、承認を得て、その後も監視すること
- ウ：保険でリスクを第三者に移すこと
- エ：リスクの原因となる業務をやめること
- 正解：イ
- 解説：リスク保有は、分析・評価をしたうえで「受け入れる」と判断する対応。承認と監視を伴う。
- アの意味：把握していないのは対応ではなく、管理の不備。
- イの意味：正しい。
- ウの意味：リスク移転。
- エの意味：リスク回避。
- 出典：オリジナル問題（根拠：JIS Q 31000:2019 6.5.2 リスク対応の選択肢）

#### 問 sc-06-o12

- 問：残留リスクの説明として、最も適切なものはどれか。
- ア：リスクアセスメントで見つからなかったリスクだけを指す
- イ：リスク対応をすれば、残留リスクは必ずゼロにできる
- ウ：リスク対応をしたあとに残るリスクで、リスク所有者が受容を承認する
- エ：リスク移転をしたリスクは、残留リスクに含まれない
- 正解：ウ
- 解説：どの対応をしてもリスクは残る。残留リスクがリスク受容基準以下かを確かめ、リスク所有者が受け入れる。
- アの意味：気付かないリスクも含みうるが、それだけではない。
- イの意味：リスクをゼロにはできない。
- ウの意味：正しい。
- エの意味：保険で移せない部分（評判など）は残る。
- 出典：オリジナル問題（根拠：JIS Q 27000:2019 残留リスク／JIS Q 27001:2023 6.1.3 f)）
