### 暗号方式の種類

#### 共通鍵暗号方式（きょうつうかぎあんごうほうしき / Symmetric-key Cryptography）

- 意味：暗号化と復号に同じ鍵を使う暗号方式。処理が速いので、データ本体の暗号化に使う
- ポイント：通信相手ごとに別の鍵が要るので、n 人が互いに通信するには n(n-1)/2 個の鍵が必要。鍵を相手に安全に渡す方法（鍵配送）が課題で、それを公開鍵暗号や鍵交換で解く

#### 公開鍵暗号方式（こうかいかぎあんごうほうしき / Public-key Cryptography）

- 意味：対になる公開鍵と秘密鍵を使い、公開鍵で暗号化したものは対の秘密鍵でだけ復号できる暗号方式。鍵の数は1人1組でよい
- ポイント：RSA は大きな数の素因数分解、楕円曲線暗号は楕円曲線上の離散対数問題の難しさに安全性を置く。処理が遅いので、データ本体ではなく共通鍵の暗号化や署名に使う

#### RSA 暗号（あーるえすえーあんごう / RSA）

- 意味：二つの大きな素数の積を公開鍵に使い、その素因数分解が難しいことに安全性を置く公開鍵暗号。暗号化とデジタル署名の両方に使える
- ポイント：今は 2048 ビット以上を使う。NIST の移行指針では、112 ビットセキュリティ（RSA 2048 ビット）は 2030 年まで、その後は 128 ビットセキュリティ以上が求められる。量子コンピュータの Shor のアルゴリズムで解読されうる

#### 楕円曲線暗号（だえんきょくせんあんごう / ECC: Elliptic Curve Cryptography）

- 意味：楕円曲線上の点の演算における離散対数問題の難しさに安全性を置く公開鍵暗号の総称
- ポイント：RSA より短い鍵で同じ強さになる（256 ビットで RSA 3072 ビットに相当）ので、スマホや IC カードに向く。署名の ECDSA、鍵交換の ECDH がある

#### ECDSA（いーしーでぃーえすえー / Elliptic Curve Digital Signature Algorithm）

- 意味：DSA（デジタル署名アルゴリズム）を楕円曲線の上で行うようにした署名方式
- ポイント：署名のたびに使う乱数（ノンス）が漏れたり、使い回されたりすると秘密鍵が計算されてしまう。ゲーム機の署名鍵がこれで漏れた事件が有名

#### ハイブリッド暗号（はいぶりっどあんごう / Hybrid Encryption）

- 意味：データ本体は速い共通鍵暗号で暗号化し、その共通鍵を受信者の公開鍵で暗号化して送る、という両方式を組み合わせた暗号
- ポイント：公開鍵暗号の「鍵配送が楽」と、共通鍵暗号の「速い」を両立する。S/MIME や PGP の暗号化がこの形

### 鍵交換

#### Diffie-Hellman 鍵交換（でぃふぃーへるまんかぎこうかん / DH Key Exchange）

- 意味：二者がそれぞれ秘密の値を選び、公開の値だけをやり取りして、第三者には計算できない共通の秘密（共通鍵の元）を作る方式。離散対数問題の難しさに安全性を置く
- ポイント：鍵交換そのものは相手を認証しないので、間に入った攻撃者がそれぞれと鍵交換する中間者攻撃を受ける。TLS では証明書と署名で相手を確かめる

#### ECDH（いーしーでぃーえいち / Elliptic Curve Diffie-Hellman）

- 意味：Diffie-Hellman 鍵交換を楕円曲線の上で行うもの。短い鍵で同じ強さになる
- ポイント：通信のたびに使い捨ての鍵で行うものを ECDHE（E は Ephemeral＝一時的）といい、TLS 1.3 の標準

#### 前方秘匿性（ぜんぽうひとくせい / PFS: Perfect Forward Secrecy）

- 意味：鍵交換に使った秘密鍵（サーバの長期の秘密鍵など）が後で漏えいしても、それより前に記録された暗号文は解読されない性質
- ポイント：通信ごとに使い捨ての DH・ECDH の鍵（DHE・ECDHE）で鍵を作り、すぐ捨てることで実現する。RSA で共通鍵を送る方式では、サーバの秘密鍵が漏れると過去の通信も全部解読される。R4秋 問8 の正解

## 15-2 ハッシュ関数と共通鍵暗号

### まとめ表

| ハッシュ関数の性質 | 意味 | n ビットのハッシュでの総当たりの目安 |
| :-: | :-: | :-: |
| 原像計算困難性（一方向性） | ハッシュ値から元のメッセージを求めにくい | 2 の n 乗 |
| 第二原像発見困難性 | あるメッセージと同じハッシュ値の別のメッセージを見つけにくい | 2 の n 乗 |
| 衝突発見困難性 | ハッシュ値が一致する二つのメッセージを見つけにくい | 2 の n/2 乗（誕生日攻撃） |

| 暗号利用モード | 暗号化の並列 | 復号の並列 | パディング | 1ビットの誤りの影響 |
| :-: | :-: | :-: | :-: | :-: |
| ECB | できる | できる | 要る | そのブロック全体（同じ平文は同じ暗号文になり危ない） |
| CBC | できない | できる | 要る | そのブロック全体＋次のブロックの同じ位置のビット |
| CTR | できる | できる | 要らない | 同じ位置の1ビットだけ |
| GCM | できる | できる | 要らない | 認証で改ざんとして検出 |

### ハッシュ関数

#### 原像計算困難性（げんぞうけいさんこんなんせい / Preimage Resistance）

- 意味：ハッシュ値が与えられたとき、そのハッシュ値になる元のメッセージを求めることが難しい性質。一方向性ともいう
- ポイント：パスワードをハッシュ値で保存できるのはこの性質による。H31春・R3春・R5春 問4 の誤りの選択肢ウはこの性質の説明

#### 第二原像発見困難性（だいにげんぞうはっけんこんなんせい / Second Preimage Resistance）

- 意味：あるメッセージが与えられたとき、それと同じハッシュ値になる「別の」メッセージを見つけることが難しい性質
- ポイント：衝突発見困難性は「二つとも自由に選んでよい」、第二原像は「一つは決まっている」。決まっている分、第二原像を見つけるほうが難しい

#### 衝突発見困難性（しょうとつはっけんこんなんせい / Collision Resistance）

- 意味：ハッシュ値が一致する二つの異なるメッセージを見つけることが難しい性質
- ポイント：誕生日のパラドックスにより、n ビットのハッシュでは約 2 の n/2 乗回の試行で衝突が見つかる（SHA-256 なら 2 の 128 乗）。H31春・R3春・R5春 問4 の正解はエ。「256 の 2 乗」「2 の 256 乗」はどちらも誤り

#### SHA-2（しゃーつー / Secure Hash Algorithm 2）

- 意味：NIST が定めたハッシュ関数の一群（FIPS 180-4）。SHA-224、SHA-256、SHA-384、SHA-512、SHA-512/224、SHA-512/256 がある
- ポイント：SHA-512/256 は、SHA-512 の計算（初期値は専用のもの）を1回行って得た 512 ビットの値を、256 ビットに切り詰めて出力する（R7春 問3 の正解）。64 ビットの CPU では SHA-256 より速いことがある

#### SHA-3（しゃーすりー / Secure Hash Algorithm 3）

- 意味：公募で選ばれた Keccak を基に、2015 年に FIPS 202 として定められたハッシュ関数。スポンジ構造という、SHA-2 とまったく違う作りをもつ
- ポイント：SHA-2 が破られたときの予備として作られた。SHA-2 の後継で「置き換え」ではなく、両方とも推奨されている

#### MD5・SHA-1 の危殆化（えむでぃーふぁいぶ・しゃーわんのきたいか / Compromise of MD5 and SHA-1）

- 意味：MD5（128 ビット）と SHA-1（160 ビット）は、現実的な計算量で衝突を作れることが示され、デジタル署名などには使えなくなったこと
- ポイント：MD5 は 2004 年に衝突が示され、SHA-1 は 2017 年に実際に衝突する二つの PDF が公開された（SHAttered）。CRYPTREC 暗号リストでも SHA-1 は運用監視暗号リスト（互換性維持のためだけに使う）に入っている

### 共通鍵暗号

#### AES（えーいーえす / Advanced Encryption Standard）

- 意味：NIST が公募で選び、2001 年に FIPS 197 として定めたブロック暗号。ブロック長は 128 ビット、鍵長は 128・192・256 ビットから選ぶ
- ポイント：R3春 問7 の正解は「128・192・256 ビットから選択」。DES（56 ビットの鍵）の後継。ブロック長と鍵長を混同しない

#### ブロック暗号とストリーム暗号（ぶろっくあんごう・すとりーむあんごう / Block Cipher, Stream Cipher）

- 意味：ブロック暗号は、平文を決まった長さ（AES は 128 ビット）のブロックに区切って暗号化する方式。ストリーム暗号は、鍵から作った鍵ストリームと平文を1ビットや1バイトごとに排他的論理和して暗号化する方式
- ポイント：ストリーム暗号の例に KCipher-2（KDDI などが開発、CRYPTREC 暗号リストの電子政府推奨暗号）や ChaCha20 がある。同じ鍵ストリームを2回使うと、二つの暗号文の排他的論理和から平文が漏れる

#### 暗号利用モード（あんごうりようもーど / Block Cipher Mode of Operation）

- 意味：ブロック長より長いデータをブロック暗号で暗号化するときの、ブロックのつなぎ方の方式。ECB、CBC、CFB、OFB、CTR、GCM などがある
- ポイント：ECB は同じ平文のブロックが同じ暗号文になり、模様が透けるので使わない。CBC は前の暗号文ブロックと排他的論理和してから暗号化するので、暗号化は並列にできないが復号はできる

#### CTR モード（かうんたもーど / Counter Mode）

- 意味：カウンタの値を暗号化して鍵ストリームを作り、それと平文のブロックの排他的論理和をとって暗号文にするモード。復号も同じ鍵ストリームとの排他的論理和
- ポイント：暗号化も復号も並列にでき、パディングは不要、ビット誤りはその1ビットにしか広がらない。R5春 問7 の正解ア。誤りの選択肢ウ（次のブロックにも影響）とエ（暗号化は並列にできない）は CBC の性質

#### 認証付き暗号（にんしょうつきあんごう / AEAD: Authenticated Encryption with Associated Data）

- 意味：暗号化（機密性）と、改ざんの検出（完全性・認証）を一度に行う暗号。暗号化しないヘッダなど（関連データ）も改ざん検出の対象にできる
- ポイント：AES-GCM、AES-CCM、ChaCha20-Poly1305 が代表。TLS 1.3 では AEAD だけが使える（#14）

#### 軽量暗号（けいりょうあんごう / Lightweight Cryptography）

- 意味：IoT 機器のセンサーなど、計算能力・メモリ・電力が限られた機器でも使えるように、回路の規模や消費電力を小さくした暗号
- ポイント：NIST は 2023 年に Ascon を軽量暗号として選び、標準化を進めた。「軽量」は安全性を下げてよいという意味ではない

## 15-3 鍵と乱数の管理、量子と耐量子計算機暗号

### まとめ表

| 言葉 | 何か | 仕組み |
| :-: | :-: | :-: |
| 量子暗号（量子鍵配送） | 鍵を配る方法 | 量子通信路で乱数を共有。盗聴すると状態が変わり気付ける |
| 耐量子計算機暗号（PQC） | 暗号アルゴリズム | 従来のコンピュータで動き、量子コンピュータでも解けない数学問題を使う |
| Shor のアルゴリズム | 解読の手法 | 量子コンピュータで素因数分解と離散対数を速く解く |
| ワンタイムパッド | 暗号方式 | 平文と同じ長さの使い捨ての乱数の鍵。情報理論的に安全 |

### 鍵と乱数の管理

#### 鍵のライフサイクル（かぎのらいふさいくる / Key Lifecycle）

- 意味：暗号鍵の、生成、配送、保管、利用、更新、廃棄（と、必要なら回収・失効）までの一連の段階
- ポイント：段階ごとに漏えいを防ぐ管理を決める。鍵の有効期間（暗号期間）を決めて定期的に更新し、廃棄では復元できないように消す。設計の指針に CRYPTREC「暗号鍵管理システム設計指針」、NIST SP 800-57 がある

#### HSM（えいちえすえむ / Hardware Security Module）

- 意味：暗号鍵を生成・保管し、鍵を外に出さずに内部で暗号化や署名の処理を行う、耐タンパ性をもつ専用の装置
- ポイント：こじ開けると鍵を消すなど物理的な攻撃にも強い。認証局の署名鍵や、決済の鍵を守るのに使う。安全性の評価に FIPS 140-3 がある

#### 鍵管理システム（かぎかんりしすてむ / KMS: Key Management System）

- 意味：暗号鍵の生成、保管、利用の権限、ローテーション、廃棄、利用の記録をまとめて管理するシステムやクラウドのサービス
- ポイント：クラウドでは、データを暗号化する鍵（データキー）を、KMS の中のマスターキーでさらに暗号化して保存する「エンベロープ暗号化」が使われる。マスターキーは KMS の外に出ない

#### 擬似乱数生成器（ぎじらんすうせいせいき / PRNG: Pseudo-Random Number Generator）

- 意味：決まった計算によって、乱数のように見える数列を作るもの。最初の値（シード）が同じなら同じ数列になる
- ポイント：暗号の鍵やセッション ID には、出力から次の値を予測できない「暗号論的に安全な擬似乱数生成器（CSPRNG）」を使い、シードは予測できないもの（エントロピー源）から取る。NIST SP 800-90A の DRBG が代表。普通の rand() は使わない

#### 量子乱数生成器（りょうしらんすうせいせいき / QRNG: Quantum Random Number Generator）

- 意味：光子の振る舞いなど、量子力学的な現象の本質的な予測できなさを使って、真の乱数を作る装置
- ポイント：計算で作る擬似乱数と違い、原理的に予測できない。量子コンピュータとは別物で、普通のコンピュータにつないで使う

#### 危殆化（きたいか / Compromise）

- 意味：暗号アルゴリズムの安全性が、計算機の性能向上や新しい解読法で低下すること。また、秘密鍵の漏えいなどで暗号の安全性が失われること
- ポイント：アルゴリズムの危殆化には、より安全な方式へ計画的に移行する（CRYPTREC 暗号リストを参照）。鍵の危殆化には、その鍵を失効させて作り直す（証明書なら失効、#16）

#### ビットセキュリティ（びっとせきゅりてぃ / Bits of Security）

- 意味：暗号を破るのに必要な計算量を 2 の何乗かで表した、暗号の強さの尺度。128 ビットセキュリティなら約 2 の 128 乗回の計算が必要
- ポイント：方式が違っても強さを比べられる。AES-128、RSA 3072 ビット、楕円曲線 256 ビットがほぼ同じ 128 ビットセキュリティ

### 量子と耐量子計算機暗号

#### 耐量子計算機暗号（たいりょうしけいさんきあんごう / PQC: Post-Quantum Cryptography）

- 意味：量子コンピュータを使った攻撃に対しても、従来のコンピュータを使って安全性を確保できる暗号技術。格子問題などの、量子コンピュータでも解きにくい数学問題に安全性を置く
- ポイント：PQC は「従来のコンピュータで動く暗号」で、量子コンピュータを使う暗号ではない（R3秋・R6秋・R7秋 問3・5 の正解）。NIST は 2024 年に FIPS 203（ML-KEM）、204（ML-DSA）、205（SLH-DSA）を定めた。今の通信を記録しておき将来解読する「Harvest Now, Decrypt Later」への対策で移行が急がれる

#### 量子暗号（りょうしあんごう / Quantum Cryptography, QKD）

- 意味：量子通信路を用いて安全に乱数列を共有し、それを使い捨ての暗号鍵として用いることで、原理的に第三者に解読されない秘匿通信を実現するもの。中心の技術は量子鍵配送（QKD）
- ポイント：盗聴すると量子の状態が変わるので、気付ける。R4春・R6秋 問6・9 の正解エ。量子コンピュータで暗号化を速くする技術ではない。PQC と名前が似ているので注意

#### ワンタイムパッド（わんたいむぱっど / One-time Pad）

- 意味：平文と同じ長さの、真の乱数による使い捨ての鍵と、平文の排他的論理和をとる暗号。鍵を二度と使わない
- ポイント：どんなに計算能力があっても解読できない「情報理論的安全性」をもつ（R7秋 問9 の正解）。RSA・DH・楕円曲線暗号は、計算が難しいことに頼る「計算量的安全性」

#### ブロックチェーン（ぶろっくちぇーん / Blockchain）

- 意味：取引などのデータをブロックにまとめ、各ブロックに前のブロックのハッシュ値を入れて鎖のようにつなぎ、P2P ネットワークの多くの参加者で共有する仕組み

- イの意味：SPF は電子メールの送信ドメイン認証で、関係がない。
- ウの意味：楕円曲線暗号は取引の署名に使われるが、P2P 通信の暗号化に必須ではない。
- エの意味：正しい。
- 出典：IPA 令和4年度秋期 情報処理安全確保支援士試験 午前Ⅱ 問12（令和2年度10月 問5 と同じ）

#### 問 sc-15-o07

- 問：暗号鍵を外部に取り出せない形で生成・保管し、署名や暗号化の処理を装置の中で行う、耐タンパ性をもつ専用の装置はどれか。
- ア：ソフトウェアで実装した暗号化ファイルシステム
- イ：鍵管理システムのエクスポート機能
- ウ：HSM
- エ：QRNG
- 正解：ウ
- 解説：HSM（Hardware Security Module）は、鍵を装置の外に出さずに処理し、物理的な攻撃にも耐える。認証局の署名鍵などを守る。
- アの意味：ソフトウェアによる暗号化で、鍵を守る専用の装置ではない。
- イの意味：鍵を外に取り出す機能で、問いの逆。
- ウの意味：正しい。
- エの意味：量子現象で乱数を作る装置で、鍵の保管や署名の処理はしない。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「HSM（Hardware Security Module）」／NIST FIPS 140-3）

#### 問 sc-15-o08

- 問：暗号の分野で「危殆化」の説明として、適切なものはどれか。
- ア：鍵を定期的に新しいものに取り替えること
- イ：計算機の性能向上や解読法の発見で暗号アルゴリズムの安全性が低下すること、また秘密鍵の漏えいなどで暗号の安全性が失われること
- ウ：暗号文を復号して元の平文に戻すこと
- エ：暗号化の処理に掛かる時間を一定にして、サイドチャネル攻撃を防ぐこと
- 正解：イ
- 解説：危殆化はアルゴリズムや鍵の安全性が失われること。MD5・SHA-1 の危殆化が代表例。
- アの意味：鍵の更新（ローテーション）の説明。
- イの意味：正しい。
- ウの意味：復号の説明。
- エの意味：定数時間実装の説明。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「危殆化，MD5 及び SHA-1 の危殆化」／CRYPTREC 暗号リスト）

#### 問 sc-15-o09

- 問：Web アプリケーションのセッション ID やパスワードリセット用のトークンを生成するときの乱数の使い方として、最も適切なものはどれか。
- ア：暗号論的に安全な擬似乱数生成器（CSPRNG）を使い、シードは予測できないエントロピー源から取る。
- イ：プログラミング言語の標準の rand() 関数を、現在時刻をシードにして使う。
- ウ：利用者 ID と日付をつなげた文字列を Base64 で符号化して使う。
- エ：連番に一定の数を足した値を使う。
- 正解：ア
- 解説：セッション ID などは推測されると乗っ取られるので、出力から次を予測できない CSPRNG を使う。
- アの意味：正しい。
- イの意味：普通の rand() は出力から内部状態を推測でき、時刻のシードは推測されやすい。
- ウの意味：Base64 は符号化で、元の値は誰でも分かる。
- エの意味：規則が分かれば次の値が推測される。
- 出典：オリジナル問題（根拠：NIST SP 800-90A Rev.1／IPA「安全なウェブサイトの作り方」1.4 セッション管理の不備）
