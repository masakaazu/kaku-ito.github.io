## 02-1 攻撃のライフサイクルとフレームワーク

### まとめ表

| 枠組み | 作ったところ | 何を分けたか | 使い方 |
| :-: | :-: | :-: | :-: |
| サイバーキルチェーン | Lockheed Martin | 攻撃を7つの段階に | どの段階で鎖を断つか考える |
| MITRE ATT&CK | MITRE | 実際の攻撃の戦術・技術・手順（TTP） | 検知ルールや演習の網羅性を確かめる |
| STRIDE（#01） | Microsoft | 脅威を6つの種類に | 設計時の脅威の洗い出し |

### 攻撃を段階で見る

#### サイバーキルチェーン（さいばーきるちぇーん / Cyber Kill Chain）

- 意味：標的型攻撃の攻撃者の行動を、攻撃者の視点で7つの段階に分けたモデル。偵察 → 武器化 → 配送 → 攻撃（エクスプロイト） → インストール → 遠隔操作（C&C） → 目的の実行
- ポイント：攻撃は鎖のようにつながっているので、どこか1つの段階で断ち切れば目的の実行を防げる、という防御の考え方につながる。過去の午前Ⅱで「偵察の段階に当たる行動はどれか」が問われた。偵察は標的の外から公開情報を集める段階で、社内に入り込んでからの情報収集は後の段階
- 例：偵察＝役員の SNS から人間関係を調べる、配送＝取引先を装ったメールにマルウェアを添付して送る

#### MITRE ATT&CK（まいたーあたっく / MITRE ATT&CK）

- 意味：実際に観測されたサイバー攻撃の手口を、攻撃者の目的（戦術）と、その実現方法（技術）、具体的なやり方（手順）に分類した、MITRE が公開しているナレッジベース
- ポイント：Enterprise 版の戦術は14個（偵察、リソース開発、初期アクセス、実行、永続化、権限昇格、防御回避、認証情報アクセス、探索、横展開、収集、C&C、持ち出し、影響）。キルチェーンより細かく、実際の攻撃グループごとの手口も載っている。CVSS（深刻度の評価）や STIX/TAXII（脅威情報の記述・交換形式）と取り違えさせる問題が出る
- 語の意味：ATT&CK＝Adversarial Tactics, Techniques, and Common Knowledge（敵対的な戦術・技術と共通知識）

#### TTP（てぃーてぃーぴー / Tactics, Techniques, and Procedures）

- 意味：攻撃者の行動を、戦術（なぜ・何のために）、技術（どうやって）、手順（具体的にどの道具で、どの順に）の3つの階層で表したもの
- ポイント：IP アドレスやハッシュ値のような IoC（#09）は攻撃者がすぐ変えられるが、TTP は変えにくい。だから TTP に基づく検知のほうが長く効く
- 語の意味：Tactics＝戦術／Techniques＝技術／Procedures＝手順

### 侵入までの準備

#### フットプリンティング（ふっとぷりんてぃんぐ / Footprinting）

- 意味：攻撃の準備として、標的の組織のドメイン名、IP アドレスの範囲、公開サーバ、従業員の情報などを調べ上げること。偵察の一部
- ポイント：Whois や DNS、Web サイト、SNS など公開情報（OSINT）から集める受動的なものと、ポートスキャンのように相手に直接働きかける能動的なものがある
- 例：求人情報の「使用技術」から、社内で使っている製品と版を推測する

#### ポートスキャン（ぽーとすきゃん / Port Scan）

- 意味：標的の機器のどのポートが開いていて、どんなサービスが動いているかを外部から調べる行為
- ポイント：攻撃者の偵察にも、自社のネットワークの検査（#13）にも使う。TCP の SYN だけを送って応答を見るものなど、方式がいくつかある
- 例：TCP 23番や 3389番（リモートデスクトップ）が開いている機器を探す

### 侵入してから目的を果たすまで

#### 初期侵入（しょきしんにゅう / Initial Access）

- 意味：攻撃者が標的のネットワークに最初の足がかりを得ること
- ポイント：典型は、標的型メールの添付・リンク、公開サーバや VPN 機器の脆弱性、盗んだ認証情報での正規のログイン、委託先経由。ATT&CK では「初期アクセス」の戦術

#### 権限昇格（けんげんしょうかく / Privilege Escalation）

- 意味：一般利用者などの低い権限から、管理者やシステムの権限を手に入れること
- ポイント：OS やソフトウェアの脆弱性、設定の不備、管理者の認証情報の窃取などで行う。STRIDE の E（Elevation of privilege）に当たる

#### 永続化（えいぞくか / Persistence）

- 意味：再起動やパスワードの変更があっても、攻撃者が侵入した状態を保ち続けられるようにすること
- ポイント：自動起動の登録、タスクの登録、バックドアや不正なアカウントの作成など。インシデント対応で「根絶」が難しいのはこのため

#### ラテラルムーブメント（らてらるむーぶめんと / Lateral Movement）

- 意味：最初に侵入した端末から、同じネットワーク内のほかの端末やサーバへ次々に侵入を広げること。横展開ともいう
- ポイント：盗んだ認証情報（Pass the Hash など）や管理用ツールを使い、最終的に AD のドメインコントローラなど重要なサーバをねらう。対策はネットワークの分離、特権アカウントの管理、内部の通信の監視
- 例：経理部の PC から、ファイルサーバ、ドメインコントローラへと広がる

#### C2（しーつー / Command and Control）

- 意味：侵入した攻撃者が、マルウェアに命令を送り、結果を受け取るための通信。C&C とも書く
- ポイント：内から外への HTTPS や DNS の通信にまぎれさせることが多い（コネクトバック、#01）。CDN を悪用して通信先を隠すドメインフロンティングもその一つ

#### 持ち出し（もちだし / Exfiltration）

- 意味：攻撃者が、標的のネットワークから機密情報を外部へ送り出すこと
- ポイント：ランサムウェアの二重恐喝ではこれが暗号化の前に行われる。圧縮・暗号化して、正規のクラウドストレージなどに送ることもある。対策は外向き通信の監視と DLP（#12）

#### ドメインフロンティング（どめいんふろんてぃんぐ / Domain Fronting）

- 意味：CDN の機能を悪用して、表向きは有名な正規のドメインと通信しているように見せかけ、実際の通信先（攻撃者のサーバ）を隠す手法
- ポイント：TLS の SNI（接続先として見えるドメイン名）と、暗号化された HTTP の Host ヘッダ（実際に届けてほしい先）に別のドメインを書く。外から見えるのは正規のドメインだけなので、URL フィルタで止めにくい。多くの CDN は対策として、この使い方を禁止している
- 語の意味：Domain＝ドメイン／Fronting＝表に立てる、隠れみのにする

## 02-2 パスワードと資格情報への攻撃

### まとめ表

| 攻撃 | 固定するもの | 変えて試すもの | 主な対策 |
| :-: | :-: | :-: | :-: |
| ブルートフォース | 利用者 ID | パスワード（総当たり） | アカウントロック・MFA |
| 辞書攻撃 | 利用者 ID | よく使われる単語のパスワード | 推測されにくいパスワード |
| リバースブルートフォース | パスワード | 利用者 ID | ロックが効かない → MFA・IP 単位の制限 |
| パスワードスプレー | よく使われるパスワード | 多数の ID に少しずつ・時刻と IP を変えて | ロックを避ける → MFA・異常検知 |
| クレデンシャルスタッフィング | 他サイトで漏れた ID とパスワードの組 | サイト | 使い回しの禁止・MFA |
| レインボーテーブル | 盗んだハッシュ値 | 事前計算した表で逆引き | ソルト |
| Pass the Hash | 盗んだハッシュ値 | （解読せずそのまま使う） | 特権の分離・認証方式の強化 |

### パスワードを当てる攻撃

#### ブルートフォース攻撃（ぶるーとふぉーすこうげき / Brute Force Attack）

- 意味：ある利用者 ID に対して、考えられるすべての文字の組合せをパスワードとして順に試す攻撃。総当たり攻撃
- ポイント：使える文字の種類が M、文字数が n のパスワードは M の n 乗通り（重複を許して並べる）。文字の種類や長さを増やすと試す数が指数的に増える。対策は、一定回数失敗したらロックする、MFA を使う
- 例：英小文字26種類で8文字なら 26⁸ ≒ 2,088億通り

#### 辞書攻撃（じしょこうげき / Dictionary Attack）

- 意味：辞書の単語、人名、よく使われるパスワードとその組合せを、パスワードとして順に試す攻撃
- ポイント：総当たりより試す数がずっと少なくてすむ。意味のある単語や、単語に数字を足しただけのパスワードは見つかりやすい

#### リバースブルートフォース攻撃（りばーすぶるーとふぉーすこうげき / Reverse Brute Force Attack）

- 意味：パスワードを1つに固定し、利用者 ID のほうを次々に変えてログインを試す攻撃
- ポイント：1つの ID に対しては1回しか失敗しないので、ID ごとのアカウントロックが効かない。対策は MFA、同じ接続元からの大量の試行の検知・制限

#### パスワードスプレー攻撃（ぱすわーどすぷれーこうげき / Password Spray Attack）

- 意味：よく使われるパスワードを、多数の利用者 ID に少しずつ試す攻撃。攻撃の時刻や接続元 IP アドレスを変え、アカウントロックにかからないように行う
- ポイント：リバースブルートフォースに似ているが、時間と接続元を散らして検知を逃れる点が特徴。過去の午前Ⅱで、辞書攻撃・総当たり・パスワードリスト攻撃と並べて問われた。対策は MFA と、組織全体のログイン失敗の傾向を見る監視
- 例：「Spring2026!」を全社員の ID に、1時間に1回ずつ、違う IP アドレスから試す

#### クレデンシャルスタッフィング（くれでんしゃるすたっふぃんぐ / Credential Stuffing）

- 意味：ほかのサイトから漏れた利用者 ID とパスワードの組の一覧を使って、別のサイトへのログインを試す攻撃。パスワードリスト攻撃ともいう
- ポイント：正しい組を使うので、失敗が少なく見つけにくい。パスワードの使い回しが原因。対策は使い回しをしないこと、MFA、漏えいしたパスワードの利用の拒否
- 語の意味：Credential＝資格情報（ID とパスワード）／Stuffing＝詰め込むこと

### ハッシュ値をねらう攻撃

#### レインボーテーブル攻撃（れいんぼーてーぶるこうげき / Rainbow Table Attack）

- 意味：パスワードとそのハッシュ値の対応を、効率よく圧縮した表（レインボーテーブル）として事前に作っておき、盗んだハッシュ値から元のパスワードを短時間で探す攻撃
- ポイント：対策はソルト（利用者ごとに異なる乱数をパスワードに付けてからハッシュ化する）。ソルトが違えば同じパスワードでもハッシュ値が変わり、事前に作った表が使えない。さらにストレッチング（ハッシュ化を何度も繰り返す）で1回あたりの計算を重くする（#17）

#### Pass the Hash（ぱすざはっしゅ / Pass the Hash）

- 意味：盗んだパスワードのハッシュ値を、元のパスワードに戻さずにそのまま使って認証を通る攻撃
- ポイント：Windows の NTLM 認証のように、ハッシュ値だけで認証できるしくみを悪用する。ハッシュ値を解読するわけではない点が、レインボーテーブル攻撃との違い。ラテラルムーブメントでよく使われる。過去の午前Ⅱで繰り返し出ている
- 例：ある PC のメモリから管理者のハッシュ値を盗み、それを使ってファイルサーバにログインする

#### Pass the Ticket（ぱすざちけっと / Pass the Ticket）

- 意味：Kerberos 認証のチケットを盗み、そのチケットを使って正規の利用者になりすます攻撃
- ポイント：Pass the Hash のチケット版。ドメインの重要な鍵まで盗まれると、任意のチケットを偽造されることもある（ゴールデンチケット）。Kerberos のしくみは #10

### 多要素認証をすり抜ける攻撃

#### MFA 疲労攻撃（えむえふえーひろうこうげき / MFA Fatigue Attack）

- 意味：盗んだ ID とパスワードでログインを何度も試み、利用者のスマートフォンに承認のプッシュ通知を大量に送りつけて、根負けや誤操作で「承認」させる攻撃。プッシュ通知爆撃（Push Bombing）ともいう
- ポイント：対策は、画面に表示された番号を入力させる番号照合（ナンバーマッチング）、通知に接続元の地域などを表示する、短時間に繰り返す要求を制限する、フィッシング耐性のある認証（パスキーなど、#10）に移ること
- 語の意味：MFA＝Multi-Factor Authentication（多要素認証）／Fatigue＝疲労

#### AiTM フィッシング（えーあいてぃーえむふぃっしんぐ / Adversary-in-the-Middle Phishing）

- 意味：本物のログインページとの間に攻撃者のプロキシをはさみ、利用者が入力した ID・パスワード・ワンタイムコードをそのまま本物に中継して、ログイン後のセッション cookie を盗むフィッシング
- ポイント：ワンタイムパスワードや SMS の認証コードは、その場で中継されると防げない。オリジン（接続先のドメイン）に結び付いた認証のパスキー・FIDO2 は、偽のドメインでは動かないのでフィッシング耐性がある（#10）
- 語の意味：Adversary＝敵対者／in the Middle＝中間に

## 02-3 セッションと通信への攻撃

### まとめ表

| 攻撃 | 何を奪う・使う | 主な対策 |
| :-: | :-: | :-: |
| セッションハイジャック | ログイン後のセッション ID | 推測できない ID、HTTPS と Secure 属性 |
| セッション固定化 | 攻撃者が先に用意したセッション ID | ログイン成功時に ID を新しくする |
| リプレイ攻撃 | 盗聴した認証データ | チャレンジレスポンス、時刻やナンス |
| 中間者攻撃 | 通信の途中に割り込む | TLS とサーバ証明書の検証 |
| MITB | ブラウザの中で取引内容を書き換える | トランザクション署名 |

### セッションを乗っ取る

#### セッションハイジャック（せっしょんはいじゃっく / Session Hijacking）

- 意味：ログイン後の利用者を識別しているセッション ID を、盗んだり推測したりして手に入れ、その利用者になりすます攻撃
- ポイント：セッション ID が盗まれる経路は、XSS による cookie の窃取、暗号化されていない通信の盗聴、推測しやすい ID など。対策は、推測できない乱数の ID、HTTPS と cookie の Secure・HttpOnly 属性（#17）
- 例：連番のセッション ID の数字を1つずらして、他人のセッションに入る

#### セッション固定化攻撃（せっしょんこていかこうげき / Session Fixation）

- 意味：攻撃者が自分で手に入れたセッション ID を、何らかの方法で利用者に使わせ、利用者がそのままログインしたあとで、同じ ID を使ってなりすます攻撃
- ポイント：ログインの前後でセッション ID が変わらないことが原因。対策は、ログインに成功したときに新しいセッション ID を発行し直すこと（IPA「安全なウェブサイトの作り方」）
- 例：URL のパラメータにセッション ID を埋め込んだリンクを送り、利用者にそこからログインさせる

#### リプレイ攻撃（りぷれいこうげき / Replay Attack）

- 意味：通信を盗聴して得た認証の情報やメッセージを、そのまま再送して、正規の利用者になりすましたり処理を繰り返させたりする攻撃
- ポイント：中身を解読しなくても成功する。対策は、毎回変わる値（チャレンジ、ナンス、タイムスタンプ、シーケンス番号）を認証やメッセージに含めること。ワンタイムパスワードもリプレイ攻撃への対策になる

### 通信の途中で割り込む

#### 中間者攻撃（ちゅうかんしゃこうげき / Man-in-the-Middle Attack）

- 意味：通信する二者の間に攻撃者が入り込み、双方に正規の相手であるかのように振る舞って、通信を盗聴したり改ざんしたりする攻撃
- ポイント：偽の Wi-Fi アクセスポイントや ARP スプーフィングなどで経路に入り込む。対策は TLS の利用と、サーバ証明書をきちんと検証すること（警告を無視しない）。AiTM ともいう
- 語の意味：Man＝人／in the Middle＝中間に

#### MITB 攻撃（えむあいてぃーびーこうげき / Man-in-the-Browser Attack）

- 意味：利用者の PC に感染したマルウェアがブラウザの中に入り込み、正規のサイトとの間でやり取りされる取引の内容を、利用者に気付かれないように書き換える攻撃
- ポイント：通信は正規のサイトと TLS で暗号化されていて、ログインも本人が行うので、サーバ証明書の確認やワンタイムパスワードでは防げない。インターネットバンキングの不正送金に使われた。有効な対策はトランザクション署名
- 例：利用者が入力した振込先を、画面上はそのまま見せたまま、送信時だけ攻撃者の口座に書き換える

#### トランザクション署名（とらんざくしょんしょめい / Transaction Signing）

- 意味：送金のときに、PC とは別の機器（ハードウェアトークンやスマートフォン）に振込先や金額を入力して、取引内容から計算した値（MAC など）を作り、それをサイトに送らせて、サイト側でも同じ計算をして照合するしくみ
- ポイント：PC のブラウザが乗っ取られていても、別の機器で計算した値は書き換えられないので、取引内容が改ざんされていないことを確かめられる。ログインのワンタイムパスワードは「だれか」を確かめるだけで、取引内容は守れない点との違いが問われる

- 解説：AiTM フィッシングでは、利用者が入力したものはすべて攻撃者に中継される。パスキーはブラウザが接続先のオリジンを確かめて署名するので、偽のドメインでは認証が成り立たず、フィッシング耐性がある。
- アの意味：認証アプリのコードも利用者が入力するので、中継されれば防げない。
- イの意味：その場で中継される攻撃には効かない。
- ウの意味：気付くきっかけにはなるが、防ぐことはできない。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」中分類25 用語例「フィッシング耐性のある認証」「FIDO（FIDO2，WebAuthn，CTAP，パスキー）」）

#### 問 sc-02-o09

- 問：Pass the Ticket 攻撃の説明として、適切なものはどれか。
- ア：Kerberos 認証のチケットを盗み、そのチケットを使って正規の利用者になりすます
- イ：電子チケットの販売サイトに大量のアクセスを行い、サービスを止める
- ウ：盗んだパスワードのハッシュ値を NTLM 認証にそのまま使う
- エ：利用者のブラウザに保存された cookie を盗み、Web サービスに入る
- 正解：ア
- 解説：Pass the Ticket は Kerberos のチケットを再利用する攻撃。Pass the Hash のチケット版で、Windows のドメイン内のラテラルムーブメントに使われる。
- アの意味：正しい。
- イの意味：DoS 攻撃の説明で、名前の「チケット」に引っかける選択肢。
- ウの意味：Pass the Hash。
- エの意味：セッションハイジャック（cookie の窃取）。
- 出典：オリジナル問題（根拠：MITRE「ATT&CK」Use Alternate Authentication Material: Pass the Ticket）

### 02-3 セッションと通信への攻撃

#### 問 sc-02-r04h-q11

- 問：インターネットバンキングの利用時に被害をもたらす MITB（Man-in-the-Browser）攻撃に有効なインターネットバンクでの対策はどれか。
- ア：インターネットバンキングでの送金時に接続する Web サイトの正当性を利用者が確認できるよう，EV SSL サーバ証明書を採用する。
- イ：インターネットバンキングでの送金時に利用者が入力した情報と，金融機関が受信した情報とに差異がないことを検証できるよう，トランザクション署名を利用する。
- ウ：インターネットバンキングでのログイン認証において，一定時間ごとに自動的に新しいパスワードに変更されるワンタイムパスワードを導入する。
- エ：インターネットバンキング利用時の通信を SSL ではなく TLS を利用して暗号化するように Web サイトを設定する。
- 正解：イ
- 解説：MITB は、ブラウザの中で取引内容を書き換える。接続先は本物で、通信も暗号化され、ログインも本人なので、取引内容そのものを別の機器で検証するトランザクション署名が有効。
- アの意味：接続先は本物のサイトなので、証明書の確認では見抜けない。
- イの意味：正しい。
- ウの意味：ログインは本人が行うので、ワンタイムパスワードでは防げない。
- エの意味：改ざんは暗号化される前のブラウザの中で起きるので、暗号方式を変えても防げない。
- 出典：IPA 令和4年度春期 情報処理安全確保支援士試験 午前Ⅱ 問11（令和2年度10月 問10 と同じ）

#### 問 sc-02-h31-q8

- 問：インターネットバンキングサービスを提供する Web サイトを利用する際に，トランザクション署名の機能をもつハードウェアトークンを利用する。次の処理を行うとき，(4)によってできることはどれか。ここで，ハードウェアトークンは利用者ごとに異なり，本人だけが利用する。〔処理〕(1) ハードウェアトークンに振込先口座番号と振込金額を入力し，メッセージ認証符号（MAC）を生成する。(2) Web サイトの振込処理画面に振込先口座番号，振込金額及び(1)で生成された MAC を入力し，Web サイトに送信する。(3) Web サイトでは，本人に発行したハードウェアトークンと同じ処理手順によって振込先口座番号と振込金額から MAC を生成する。(4) Web サイトでは，(2)で入力された MAC と，(3)で生成した MAC を比較する。
- ア：通信経路において盗聴されていないことを確認できる。
- イ：通信経路における盗聴者を特定できる。
- ウ：振込先口座番号と振込金額が改ざんされていないことを確認できる。
- エ：振込先口座番号と振込金額の改ざんされた箇所を訂正できる。
- 正解：ウ
- 解説：MAC は、同じ鍵と同じ手順で計算すれば同じ値になる。届いた振込先と金額から計算した MAC が、トークンで作った MAC と一致すれば、途中で書き換えられていないことが分かる。
- アの意味：MAC は改ざんを検知するもので、盗聴（のぞき見）されたかどうかは分からない。
- イの意味：だれが盗聴したかは分からない。
- ウの意味：正しい。
- エの意味：MAC で分かるのは「一致するかどうか」だけで、どこが違うかや正しい値は分からない。
- 出典：IPA 平成31年度春期 情報処理安全確保支援士試験 午前Ⅱ 問8

#### 問 sc-02-r05a-q7

- 問：インターネットバンキングでの MITB 攻撃による不正送金について，対策として用いられるトランザクション署名の説明はどれか。
- ア：携帯端末からの送金取引の場合，金融機関から利用者の登録メールアドレスに送金用のワンタイムパスワードを送信する。
- イ：特定認証業務の認定を受けた認証局が署名したデジタル証明書をインターネットバンキングでの利用者認証に用いることによって，ログインパスワードが漏えいした際の不正ログインを防止する。
- ウ：利用者が送金取引時に，“送金操作を行う PC とは別のデバイスに振込先口座番号などの取引情報を入力して表示された値”をインターネットバンキングに送信する。
- エ：ログイン時に，送金操作を行う PC とは別のデバイスによって，一定時間だけ有効なログイン用のワンタイムパスワードを算出し，インターネットバンキングに送信する。
- 正解：ウ
- 解説：トランザクション署名の要点は、「取引の内容」を「PC とは別の機器」に入力して値を作ること。取引内容に結び付いていない値は、MITB で書き換えられた取引にもそのまま使われてしまう。
- アの意味：取引内容に結び付いていないワンタイムパスワード。
- イの意味：ログインの強化で、ログイン後の取引の改ざんは防げない。
- ウの意味：正しい。
- エの意味：別の機器を使っているが、ログイン用で、取引内容に結び付いていない。
- 出典：IPA 令和5年度秋期 情報処理安全確保支援士試験 午前Ⅱ 問7

#### 問 sc-02-o10

- 問：セッション固定化攻撃への対策として、最も適切なものはどれか。
- ア：セッション ID を cookie ではなく URL のパラメータで受け渡す
- イ：ログイン画面の入力値をエスケープしてから表示する
- ウ：セッションの有効期限を長くして、ログインの回数を減らす
- エ：ログインに成功した時点で、新しいセッション ID を発行し、古い ID を無効にする
- 正解：エ
- 解説：セッション固定化攻撃は、攻撃者が用意したセッション ID のまま利用者にログインさせる。ログインの前後で ID を変えれば、攻撃者の知っている ID は使えなくなる。

- イの意味：XSS への対策で、セッション固定化には直接効かない。
- ウの意味：乗っ取られたときの被害の時間が延びる。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：IPA「安全なウェブサイトの作り方」セッション管理の不備／IPA「支援士試験 シラバス（案）」用語例「セッション固定化攻撃（Session Fixation）」）

#### 問 sc-02-o11

- 問：リプレイ攻撃への対策として、適切なものはどれか。
- ア：認証のたびにサーバが異なるチャレンジ（乱数）を送り、クライアントはその値を使って応答を計算する
- イ：パスワードを毎回同じハッシュ関数でハッシュ化してから送る

- エ：ログイン画面に CAPTCHA を表示する
- 正解：ア

- ウの意味：圧縮は暗号化ではなく、再送も防げない。
- エの意味：自動化されたログイン試行への対策で、盗聴した値の再送は防げない。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「リプレイ攻撃」）

#### 問 sc-02-o12

- 問：MITB 攻撃に対して、ログイン時のワンタイムパスワードが有効でない理由として、最も適切なものはどれか。
- ア：ワンタイムパスワードは盗聴されるとそのまま再利用できるから
- イ：ログインは利用者本人が正しく行い、その後の取引の内容がブラウザの中で書き換えられるから

- エの意味：MITB は利用者の PC（ブラウザ）に感染したマルウェアが行う。
- 出典：オリジナル問題（根拠：IPA「支援士試験 シラバス（案）」用語例「セッションハイジャック」ほか／IPA 午前Ⅱ 令和4年度春期 問11 の解説）
