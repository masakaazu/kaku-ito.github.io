## 09-1 脅威インテリジェンス

### まとめ表

| 言葉 | 何か | 例 |
| :-: | :-: | :-: |
| OSINT | 公開されている情報からの収集 | 報道、SNS、公開レポート、証明書の公開ログ |
| IoC | 侵害された痕跡を示す指標 | 悪性ファイルのハッシュ値、C2 の IP・ドメイン |
| STIX | 脅威情報を記述する形式 | JSON で攻撃者・手口・IoC を表す |
| TAXII | 脅威情報を交換する手順 | HTTPS で STIX を配る・受け取る |
| TLP | 共有してよい範囲の目印 | RED・AMBER・GREEN・CLEAR |

### 集める・表す・配る

#### OSINT（おしんと / Open Source Intelligence）

- 意味：報道、Web サイト、SNS、公開された報告書、ドメインや証明書の公開情報など、だれでも入手できる情報源から集めて分析するインテリジェンス
- ポイント：防御側は自組織に関する漏えいや攻撃の予告を探すのに使い、攻撃者は偵察（#02）に使う。証明書の透明性ログ（CT ログ）で、自組織の名前に似たドメインの証明書の発行に気付ける
- 語の意味：Open Source＝公開された情報源／Intelligence＝分析して使える情報

#### IoC（あいおーしー / Indicator of Compromise）

- 意味：システムが侵害されたことを示す痕跡や指標。マルウェアのファイルのハッシュ値、C2 サーバの IP アドレスやドメイン名、不審なレジストリの変更、特徴的な通信のパターンなど
- ポイント：過去の午前Ⅱで「ネットワーク機器のログに残された C&C サーバとの通信履歴」が正解。脆弱性情報や証明書の失効リスト、ファイアウォールのルールは IoC ではない。IoC は攻撃者が簡単に変えられる（ハッシュ値や IP アドレス）ので、手口（TTP）に注目する方が長く役立つ
- 語の意味：Indicator＝指標／Compromise＝侵害

#### 痛みのピラミッド（いたみのぴらみっど / Pyramid of Pain）

- 意味：防御側が検知に使う指標を、攻撃者にとって変えにくい順に並べたモデル。下からハッシュ値、IP アドレス、ドメイン名、ネットワーク・ホストの痕跡、ツール、TTP
- ポイント：下の指標（ハッシュ値）は攻撃者がすぐ変えられ、防御の効果が短い。上の TTP を検知できれば、攻撃者は手口ごと変える必要があり、大きな「痛み」を与えられる

#### STIX（すてぃっくす / Structured Threat Information eXpression）

- 意味：脅威情報を、機械が読める形で記述するための標準の形式。脅威情報構造化記述形式
- ポイント：攻撃者、攻撃キャンペーン、攻撃パターン、マルウェア、IoC（指標）、対策などを「オブジェクト」として表し、その関係も記述できる。2.x 版は JSON を使う。OASIS が標準化している
- 語の意味：Structured＝構造化された／Threat Information＝脅威情報／eXpression＝表現

#### TAXII（たくしー / Trusted Automated eXchange of Indicator Information）

- 意味：STIX などで記述した脅威情報を、組織の間で自動的に交換するための手順。検知指標情報自動交換手順
- ポイント：HTTPS の上で、情報の集まり（コレクション）を取得・登録する API を定めている。STIX が「何を書くか（形式）」、TAXII が「どう運ぶか（手順）」
- 語の意味：Trusted＝信頼できる／Automated＝自動の／eXchange＝交換／Indicator Information＝指標の情報

#### TLP（てぃーえるぴー / Traffic Light Protocol）

- 意味：共有する情報に付けて、受け取った人がその情報をどこまで広めてよいかを色で示す目印。FIRST が定めている
- ポイント：TLP 2.0 は、TLP:RED（その場の受け手だけ）、TLP:AMBER（受け手の組織と、必要な顧客まで）、TLP:AMBER+STRICT（受け手の組織の中だけ）、TLP:GREEN（コミュニティの中まで、公開はしない）、TLP:CLEAR（制限なし。旧 WHITE）。情報の重要度や危険度を示すものではない
- 語の意味：Traffic Light＝信号機

### 探す・止める

#### 脅威ハンティング（きょういはんてぃんぐ / Threat Hunting）

- 意味：既存の検知の仕組みでは見つかっていない攻撃者が、すでに内部に潜んでいると仮定して、仮説を立ててログや端末を能動的に調べ、痕跡を探す活動
- ポイント：アラートを待つ受け身の監視（SOC の通常業務）に対して、能動的に探すのが特徴。脅威インテリジェンスの TTP や IoC から仮説を作る。見つけた手口は検知のルールに加える

#### テイクダウン（ていくだうん / Takedown）

- 意味：フィッシングサイトやマルウェアの配布サイト、C2 サーバなどについて、ホスティング事業者やドメインの登録事業者に依頼して、停止・削除してもらうこと
- ポイント：自社をかたるフィッシングサイトを見つけたら、JPCERT/CC や専門の事業者を通じて依頼することが多い。証拠（URL、画面）を残してから依頼する

## 09-2 インシデント対応と事業継続

### まとめ表

| 段階（SP 800-61 Rev.2） | 主な作業 |
| :-: | :-: |
| 準備 | 体制・連絡先・手順（IRP）、ツール、訓練 |
| 検知・分析 | 兆候の発見、トリアージ、影響範囲の特定、記録 |
| 封じ込め・根絶・復旧 | 隔離、原因の除去、バックアップからの復旧、監視 |
| 事後対応 | 事後レビュー、再発防止、報告書 |

### 対応の流れ

#### インシデントハンドリング（いんしでんとはんどりんぐ / Incident Handling）

- 意味：インシデントの報告を受けてから、検知・分析・封じ込め・根絶・復旧・事後対応までを行う一連の活動
- ポイント：JPCERT/CC のマニュアルは、検知・連絡受付 → トリアージ → インシデントレスポンス（分析・対応）→ 報告・情報公開、の流れで示す。最初に記録を始め、時刻と行ったことを残す

#### インシデント対応プロセス（いんしでんとたいおうぷろせす / Incident Response Process）

- 意味：NIST SP 800-61 Rev.2 が示した、準備、検知と分析、封じ込め・根絶・復旧、事件後の対応（事後対応）の4つの段階のライフサイクル
- ポイント：封じ込め（被害の拡大を止める）→ 根絶（マルウェアや攻撃者のアカウントを取り除く）→ 復旧（正常な状態に戻し、監視を強める）の順。根絶する前に復旧すると、同じ攻撃者に再び入られる。2025年の Rev.3 は、これを CSF 2.0 の6つの機能（統治・識別・防御・検知・対応・復旧）に合わせて組み直した

#### トリアージ（とりあーじ / Triage）

- 意味：報告された事象について、本当にインシデントか、対応の範囲内か、影響の大きさと緊急度はどうかを判断し、対応の優先順位を決めること
- ポイント：医療の救急の現場の言葉から来ている。すべての報告に同じ力をかけず、重大なものから対応する。判断の基準は前もってインシデント対応計画に書いておく

#### インシデントレスポンス計画（いんしでんとれすぽんすけいかく / IRP: Incident Response Plan）

- 意味：インシデントへの対応の目的、体制、役割と権限、連絡先、判断の基準、手順、報告の方法などを、前もって定めた計画
- ポイント：準備の段階の中心。経営層の承認を得て、訓練（机上演習など）で実際に使えるか確かめ、見直す。インシデントの種類ごとの手順書（プレイブック）を付けることが多い

#### 封じ込め（ふうじこめ / Containment）

- 意味：インシデントの被害が広がらないように、影響を受けた端末やアカウント、ネットワークを隔離・停止すること
- ポイント：感染した端末はネットワークから切り離すが、電源は切らない（メモリ上の証拠が消えるため、#19）。短期的な封じ込めのあと、証拠を保全して長期的な封じ込めに移る

#### CSIRTマテリアル（しーさーとまてりある / CSIRT Material）

- 意味：JPCERT/CC が公開している、組織の中に CSIRT を作り、運用するための手引の資料群
- ポイント：構想フェーズ（目的と範囲を決める）、構築フェーズ（体制・規程・窓口を作る）、運用フェーズ（対応と改善）の3つで構成する。CSIRT の構築・運用の参考にする

### 報告・公表・事後

#### 法令に基づく報告と本人への通知（ほうれいにもとづくほうこくとほんにんへのつうち / Legally Required Reporting and Notification）

- 意味：個人データの漏えいなどが起きたときに、法令で定められた相手（個人情報保護委員会など）へ報告し、本人に通知すること
- ポイント：個人情報保護法では、要配慮個人情報の漏えい、財産的被害のおそれ、不正の目的によるおそれ（不正アクセスなど）、1,000人を超える漏えい（それぞれのおそれを含む）のときに、個人情報保護委員会への報告と本人への通知が義務。報告は、知ってから速やかに（おおむね3〜5日以内）の速報と、30日以内（不正の目的によるおそれがある場合は60日以内）の確報の2段階（#23）

#### 関係機関への届出（かんけいきかんへのとどけで / Reporting to Relevant Organizations）

- 意味：法令の義務とは別に、警察（被害の相談・届出）、IPA（ウイルス・不正アクセスの届出）、JPCERT/CC（インシデントの報告）、監督官庁、業界団体などに届け出ること
- ポイント：届け出ることで、捜査や他の組織の被害の防止、助言を受けることにつながる（#07 の届出制度、被害情報の共有・公表ガイダンス）

#### 公表の判断と広報対応（こうひょうのはんだんとこうほうたいおう / Disclosure Decision and Public Relations）

- 意味：インシデントを外部に公表するかどうか、いつ、何を、だれに伝えるかを判断し、報道や問い合わせに対応すること
- ポイント：被害の拡大や二次被害（偽のお詫びメールなど）の防止、利害関係者への説明責任を考えて判断する。攻撃者に調査の進み具合が伝わる情報は出し方に注意する。問い合わせ窓口の準備も必要

#### サイバー保険（さいばーほけん / Cyber Insurance）

- 意味：サイバー攻撃などによって生じた損害（他者への損害賠償、調査・復旧・お詫びなどの事故対応の費用、事業の中断による利益の損失など）を補償する保険
- ポイント：リスク移転の手段（#06）。保険会社が調査会社や弁護士を紹介するサービスが付くことも多い。身代金の支払いは補償の対象外とするものが多い

#### 事後レビュー（じごれびゅー / Post-incident Review / Lessons Learned）

- 意味：インシデントの対応が終わったあとに、何が起きたか、対応はうまくいったか、何を改善すべきかを関係者で振り返り、再発防止や手順の改善につなげること
- ポイント：個人の責任を追及するのではなく、仕組みの改善に目を向ける（ブレームレス）。結果はインシデント対応計画や管理策の見直しに反映する

### 事業継続とレジリエンス

#### 目標復旧時間（もくひょうふっきゅうじかん / RTO: Recovery Time Objective）

- 意味：障害や災害が起きてから、業務やシステムを再開するまでに許される目標の時間
- ポイント：RTO が短いほど、待機系やホットサイトなどの費用がかかる。業務の影響度分析（BIA）で、業務ごとに決める
- 語の意味：Recovery Time＝復旧までの時間／Objective＝目標

#### 目標復旧時点（もくひょうふっきゅうじてん / RPO: Recovery Point Objective）

- 意味：障害が起きたときに、どの時点までのデータを取り戻すかの目標。言い換えると、失ってよいデータの期間
- ポイント：RPO が24時間なら、1日1回のバックアップでよい。RPO を0に近づけるには、リアルタイムの複製（レプリケーション）が必要。RTO（時間）と RPO（データの時点）を取り違えさせる選択肢に注意
- 語の意味：Recovery Point＝復旧する時点

#### バックアップからの復旧手順の検証（ばっくあっぷからのふっきゅうてじゅんのけんしょう / Testing Restoration from Backup）

- 意味：バックアップを取るだけでなく、実際にそこからデータやシステムを復元できるか、RTO の時間内に終わるかを、定期的に試して確かめること
- ポイント：ランサムウェアはバックアップも暗号化・削除しようとするので、ネットワークから切り離したもの（オフライン）や書き換えられないもの（イミュータブル）を持つ。3-2-1 ルール（3つのコピーを、2種類の媒体に、1つは離れた場所に）も目安になる

#### ホットサイト（ほっとさいと / Hot Site）

- 意味：本番と同じ機器とデータを常に用意して稼働させておき、障害時にすぐ切り替えられる代替の拠点
- ポイント：RTO を最も短くできるが、費用が最も高い。機器はあるがデータの復元や設定に時間がかかるのがウォームサイト

#### コールドサイト（こーるどさいと / Cold Site）

- 意味：建物・電源・通信回線などの場所だけを用意し、障害が起きてから機器を運び込んで構築する代替の拠点
- ポイント：費用は安いが、再開まで時間（数日〜数週間）がかかる。RTO の長い業務に向く

## 09-3 人的・物理的な対策

### まとめ表

| 対策 | 何を防ぐ・見つける | 種類 |
| :-: | :-: | :-: |
| 内部不正防止ガイドライン | 従業員などによる不正 | 人的 |
| 標的型メール訓練 | 不審なメールの開封 | 人的 |
| UEBA | 利用者・機器の異常なふるまい | 技術（人の行動の分析） |
| アンチパスバック | 共連れ、カードの貸し借り | 物理的 |
| MDM | モバイル機器の紛失・設定の不備 | 装置の管理 |

### 人的な対策

#### 組織における内部不正防止ガイドライン（そしきにおけるないぶふせいぼうしがいどらいん / Guidelines for Prevention of Internal Fraud in Organizations）

- 意味：IPA が公表している、従業員などによる内部不正を防ぐための対策をまとめた指針。状況的犯罪予防の考え方をもとに、5つの基本原則を示す
- ポイント：5つの基本原則は、犯行を難しくする（やりにくく）、捕まるリスクを高める（やると見つかる）、犯行の見返りを減らす（割に合わない）、犯行の誘因を減らす（その気にさせない）、犯罪の弁明をさせない（言い訳させない）。不正のトライアングル（#01）の動機・機会・正当化と対応させて考える
- 例：アクセスログの監視を周知する（見つかる）、重要情報の暗号化（見返りを減らす）、公平な人事評価（その気にさせない）、ルールの周知と誓約書（言い訳させない）

#### 情報セキュリティ訓練（じょうほうせきゅりてぃくんれん / Security Exercises）

- 意味：インシデントへの備えを、実際の場面に近い形で試し、身に付けるための訓練。シラバス案は、標的型メールに関する訓練、レッドチーム演習、机上演習を挙げている
- ポイント：標的型メール訓練は、疑似の攻撃メールを送って開封率や報告率を測る。開封した人を責めるより、すぐ報告できたかを重視する

#### レッドチーム演習（れっどちーむえんしゅう / Red Team Exercise）

- 意味：攻撃者の役のチーム（レッドチーム）が、実在の攻撃者の手口で、決めた目標（重要情報の窃取など）の達成を試み、組織の検知・対応の力を総合的に評価する演習
- ポイント：脆弱性を網羅的に探すペネトレーションテスト（#19）に対し、目標の達成と、防御側（ブルーチーム）が気付けるかに重点がある。両チームが協力して改善するのがパープルチーム

#### 机上演習（きじょうえんしゅう / Tabletop Exercise）

- 意味：インシデントのシナリオをもとに、関係者が会議室で話し合いながら、だれが何をどう判断・行動するかを確かめる演習
- ポイント：実際のシステムは動かさないので、費用が少なく、経営層も参加しやすい。インシデント対応計画の抜け（連絡先、判断の基準、公表の手順）を見つけられる

#### UEBA（ゆーいーびーえー / User and Entity Behavior Analytics）

- 意味：利用者や機器（エンティティ）の通常のふるまいを学習し、そこから外れた異常なふるまいを検知する技術
- ポイント：深夜の大量ダウンロード、普段使わないサーバへのアクセス、ありえない場所からのログインなど。内部不正や、乗っ取られたアカウントの発見に役立つ。過去の午前Ⅱで「利用者や機器の異常な振る舞いを検知する」が正解
- 語の意味：User＝利用者／Entity＝機器などの主体／Behavior Analytics＝ふるまいの分析

#### セキュリティクリアランス（せきゅりてぃくりあらんす / Security Clearance）

- 意味：国が保護する重要な情報を扱う人について、信頼性を調べたうえで、その情報に触れることを認める制度
- ポイント：日本では、重要経済安保情報の保護及び活用に関する法律（2024年成立、2025年施行）で、政府が民間の人も含めて適性評価を行う仕組みができた。防衛などの特定秘密保護法の適性評価と合わせて運用される。組織の中の need-to-know の原則（#06）とも関係する

#### 秘密保持契約・誓約書（ひみつほじけいやく・せいやくしょ / NDA and Written Pledge）

- 意味：業務で知った秘密を漏らさないことを、契約や書面で約束させること。従業員の入社時・退職時、委託先との契約時などに交わす
- ポイント：退職後の守秘義務も定める。内部不正防止の「言い訳させない」の手段にもなる

### 物理的な対策と装置

#### セキュリティゾーニング（せきゅりてぃぞーにんぐ / Security Zoning）

- 意味：建物の中を、扱う情報の重要度に応じて区域（ゾーン）に分け、内側の区域ほど入れる人を絞り、入退の管理を厳しくすること
- ポイント：一般エリア（受付）→ 執務エリア → セキュリティエリア（サーバ室）のように、層を重ねる（多層防御、#06）。重要な区域を、外から直接入れない内側に置く

#### 入退管理システム（にゅうたいかんりしすてむ / Physical Access Control System）

- 意味：IC カード、生体認証、暗証番号などで、区域に入れる人を確かめ、入退の記録を残すシステム
- ポイント：1人の認証で複数人が入る「共連れ」を防ぐために、アンチパスバック、1人ずつしか通れないサークル型のゲート、2つの扉が同時に開かないインターロックを組み合わせる

#### アンチパスバック（あんちぱすばっく / Anti-passback）

- 意味：入室の記録がない IC カードでは退室できない、退室の記録がないカードでは再び入室できないようにする入退管理の機能
- ポイント：共連れで入った人は入室の記録がないので、出るときに止められる。1枚のカードを渡して別の人が入る「カードの貸し借り」も防げる

#### MDM（えむでぃーえむ / Mobile Device Management）

- 意味：組織が使うスマートフォンやタブレット、ノート PC などのモバイル機器を一元的に管理する仕組み
- ポイント：パスコードや暗号化の設定を強制する、入れてよいアプリを制限する、紛失したときに遠隔で画面をロックしたりデータを消去（リモートワイプ）したりする。業務アプリとデータだけを管理する MAM、私物の端末を業務に使う BYOD の管理にも使う
- 語の意味：Mobile Device＝モバイル機器／Management＝管理
