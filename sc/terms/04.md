## 04-1 なりすましと信頼の悪用

### まとめ表

| 攻撃 | 何を偽る・悪用するか | 主な目的 |
| :-: | :-: | :-: |
| IP スプーフィング | 送信元 IP アドレス | 追跡を逃れる、反射させる |
| ARP スプーフィング | IP と MAC の対応 | LAN 内の通信の盗聴・改ざん |
| 第三者中継 | 制限のないメールサーバ | 迷惑メールの踏み台 |
| フィッシング・スミッシング | 本物そっくりのサイトとメール・SMS | 資格情報・カード番号の窃取 |
| 水飲み場型攻撃 | 標的がよく見る正規のサイト | 特定の組織への感染 |
| SEO ポイズニング | 検索エンジンの順位 | 罠のサイトへの誘導 |

### 通信の送り主を偽る

#### IPスプーフィング（あいぴーすぷーふぃんぐ / IP Spoofing）

- 意味：IP パケットの送信元 IP アドレスを偽って送ること
- ポイント：UDP や ICMP は応答を待たないので偽装がそのまま通る。リフレクション攻撃や Smurf 攻撃の前提になる。対策は、ISP や組織の出入口で「自分のネットワークに属さない送信元」のパケットを捨てる送信元検証（イングレスフィルタリング、BCP 38 / RFC 2827）。外から来たのに内部の送信元アドレスをもつパケットも捨てる
- 語の意味：Spoofing＝なりすまし、だますこと

#### ARPスプーフィング（あーぷすぷーふぃんぐ / ARP Spoofing）

- 意味：LAN の中で偽の ARP 応答を送り、他の端末の「IP アドレスと MAC アドレスの対応表（ARP キャッシュ）」を書き換えて、通信を自分の端末に引き寄せる攻撃。ARP ポイズニングともいう
- ポイント：デフォルトゲートウェイになりすますと、LAN の外へ出る通信をすべて中継・盗聴できる（中間者攻撃、#02）。対策は、スイッチの DAI（ダイナミック ARP インスペクション）、DHCP スヌーピング（#13）、静的な ARP エントリ
- 語の意味：ARP＝Address Resolution Protocol（アドレス解決プロトコル）

#### 第三者中継（だいさんしゃちゅうけい / Open Relay）

- 意味：自分の組織と関係のない送信者から、自分の組織と関係のない宛先へのメールを、メールサーバが制限なく中継してしまう状態。オープンリレー
- ポイント：迷惑メールの送信の踏み台にされ、そのサーバの IP アドレスがブラックリストに載って、正規のメールまで届かなくなる。対策は、中継を許す送信元を自組織に限る、SMTP-AUTH で送信者を認証する、OP25B（#14）
- 例：社外の A さんから社外の B さんへのメールを、自社のメールサーバが受け取って配送してしまう

### 人と信頼をだます

#### フィッシング（ふぃっしんぐ / Phishing）

- 意味：実在の金融機関や EC サイトなどを装ったメールなどで、本物そっくりの偽サイトに誘導し、ID・パスワードやクレジットカード番号などを入力させて盗む攻撃
- ポイント：最近は AiTM フィッシング（#02）のように、多要素認証の結果まで中継して盗む手口もある。対策は、ブックマークや公式アプリから開く、送信ドメイン認証（DMARC、#14）、フィッシングに強い認証（FIDO2・パスキー、#10）
- 語の意味：Phishing＝fishing（釣り）の綴りを変えた造語。sophisticated（洗練された）の ph という説がある

#### スミッシング（すみっしんぐ / Smishing）

- 意味：SMS（ショートメッセージ）を使ったフィッシング。宅配便の不在通知や、携帯電話会社・銀行を装った SMS で偽サイトに誘導する
- ポイント：SMS は電話番号だけで届き、送信者の偽装もしやすい。偽サイトから不正なアプリ（Android の APK）を入れさせ、端末の SMS を盗んで認証コードを奪う手口もある
- 語の意味：SMS＋Phishing

#### 標的型攻撃（ひょうてきがたこうげき / Targeted Attack）

- 意味：特定の組織や個人をねらい、業務に関係のありそうな内容のメール（標的型攻撃メール）などで、マルウェアを実行させて侵入し、長い時間をかけて情報を盗む攻撃
- ポイント：ばらまき型と違い、事前に偵察（#02）して文面を作る。継続的なものを APT（Advanced Persistent Threat）ともいう。入口だけでなく、内部での横展開や外部への通信（C2）を見つける「出口対策」も重要

#### 水飲み場型攻撃（みずのみばがたこうげき / Watering Hole Attack）

- 意味：標的の組織の人がよく閲覧する Web サイトを改ざんし、そのサイトを見た標的だけにマルウェアを感染させる攻撃
- ポイント：特定の IP アドレス（標的の組織）からのアクセスのときだけ攻撃コードを返し、ほかの人には普通のページを見せて発見を遅らせる。ドライブバイダウンロード（#03）の手口を使う
- 語の意味：獲物が集まる水飲み場で待ち伏せる肉食動物にたとえた

#### SEOポイズニング（えすいーおーぽいずにんぐ / SEO Poisoning）

- 意味：検索エンジンの順位を上げる技術（SEO）を悪用し、話題の言葉や製品名で検索したときに、罠のサイトが上位に表示されるようにする攻撃
- ポイント：偽のダウンロードサイトからマルウェア入りのインストーラを入れさせたり、偽の警告ページ（サポート詐欺）を出したりする。検索の広告枠を悪用するものはマルバタイジング
- 語の意味：SEO＝Search Engine Optimization（検索エンジン最適化）／Poisoning＝毒を入れること

## 04-2 DNS への攻撃

### まとめ表

| 攻撃 | ねらう相手 | 何が起きるか | 対策 |
| :-: | :-: | :-: | :-: |
| DNS キャッシュポイズニング | キャッシュ DNS サーバ | 偽の IP アドレスを覚えさせる | ポートと ID のランダム化、DNSSEC |
| カミンスキー攻撃 | キャッシュ DNS サーバ | 存在しない名前を使い、何度でも試す | 送信元ポートのランダム化 |
| ドメイン名ハイジャック | 登録情報・権威 DNS | ドメインごと乗っ取る | レジストリロック、登録アカウントの MFA |
| DNS アンプ攻撃 | 第三者（踏み台はオープンリゾルバ） | 大きな応答で回線をあふれさせる | オープンリゾルバをなくす |

### DNS の応答を偽る

#### DNSキャッシュポイズニング（でぃーえぬえすきゃっしゅぽいずにんぐ / DNS Cache Poisoning）

- 意味：キャッシュ DNS サーバ（フルリゾルバ）が権威 DNS サーバに問い合わせている間に、攻撃者が偽の応答を先に届けて、偽の IP アドレスを覚え（キャッシュ）させる攻撃
- ポイント：キャッシュを使う利用者全員が、正しいドメイン名を入れても偽のサイトに誘導される。偽の応答が受け入れられる条件は、問い合わせの送信元ポート番号・DNS ヘッダの ID（16 ビット）・問い合わせ名が一致すること。だから対策は、ID と送信元ポート番号を固定せずランダムにすること（ポート番号を 53 に固定するのは逆効果）。根本的な対策は DNSSEC（#16）で応答に署名すること
- 語の意味：Cache＝一時的に覚えておく場所／Poisoning＝毒を入れること

#### カミンスキー攻撃（かみんすきーこうげき / Kaminsky Attack）

- 意味：2008年に Dan Kaminsky が公表した DNS キャッシュポイズニングの手法。存在しないサブドメイン（`a1.example.jp`、`a2.example.jp`…）を次々に問い合わせさせ、そのたびに偽の応答を送り込む。偽の応答には、ドメイン全体の権威サーバを偽サーバに差し替える情報を含める
- ポイント：従来の攻撃は、一度失敗すると正しい答えがキャッシュされて TTL の間は再挑戦できなかった。毎回新しい名前を使うことでこの制限を回避し、成功するまで何度でも試せる。対策は、送信元ポート番号のランダム化で偽の応答が当たる確率を大きく下げること（RFC 5452）。過去の午前Ⅱでは選択肢の並びを変えて2回出た
- 例：ID が 16 ビット（65,536 通り）だけなら当たりやすいが、ポート番号も約6万通りにランダム化すると、組合せは約40億通りになる

#### ドメイン名ハイジャック（どめいんめいはいじゃっく / Domain Name Hijacking）

- 意味：ドメイン名の登録情報（レジストラのアカウント）や権威 DNS サーバの設定を不正に書き換え、ドメイン名そのものを乗っ取って、偽のサーバへ誘導する攻撃
- ポイント：キャッシュポイズニングと違い、正しい問い合わせ先の情報そのものが書き換わる。対策は、レジストラのアカウントの MFA、レジストリロック、登録情報の監視。使われなくなったサブドメインの CNAME が残っていて乗っ取られるサブドメインテイクオーバーも似た被害になる

#### オープンリゾルバ（おーぷんりぞるば / Open Resolver）

- 意味：インターネット上のだれからの再帰問い合わせにも答えてしまうキャッシュ DNS サーバ
- ポイント：送信元を偽った問い合わせに答えてしまうので、DNS アンプ攻撃の踏み台になり、キャッシュポイズニングも受けやすい。対策は、再帰問い合わせを受け付ける範囲を自組織の利用者に限ること。権威 DNS サーバとキャッシュ DNS サーバを分けるのも基本

## 04-3 サービス妨害（DoS・DDoS）

### まとめ表

| 攻撃 | 何を使い切らせるか | 特徴 |
| :-: | :-: | :-: |
| SYN フラッド | サーバの接続待ちの領域 | SYN だけ送り、ACK を返さない |
| UDP フラッド | 回線・処理能力 | 大量の UDP パケット |
| HTTP フラッド | Web サーバ・アプリの処理 | 正規に見える HTTP 要求（L7） |
| Slow HTTP | Web サーバの同時接続数 | 少しずつ送り続けて接続を占有 |
| Smurf | 標的の回線 | ブロードキャスト宛の ICMP エコー要求 |
| リフレクション（DRDoS） | 標的の回線 | 送信元を標的に偽り、第三者のサーバの応答を浴びせる |

### 1台から・プロトコルの性質を使う

#### DoS攻撃（どすこうげき / Denial of Service Attack）

- 意味：サーバや回線に大量の処理やデータを送りつけたり、脆弱性をついて停止させたりして、正規の利用者がサービスを使えないようにする攻撃。サービス妨害攻撃
- ポイント：情報セキュリティの3要素のうち可用性を損なう。原因は「量で押す」ものと「欠陥をつく」もの（不正なパケットで停止させる、ReDoS など）に分けられる

#### SYNフラッド攻撃（しんふらっどこうげき / SYN Flood Attack）

- 意味：TCP の3ウェイハンドシェイクの最初の SYN パケットだけを大量に送り、サーバが SYN/ACK を返して ACK を待つ状態（ハーフオープン）を大量に作って、接続待ちの領域を使い切らせる攻撃
- ポイント：送信元 IP アドレスを偽ることが多い。対策は、SYN cookie（接続の情報を待ち行列に置かず、SYN/ACK のシーケンス番号に埋め込んでおく、RFC 4987）、待ち時間の短縮、上流での遮断
- 語の意味：SYN＝synchronize（同期）／Flood＝洪水

#### バックスキャッタ（ばっくすきゃった / Backscatter）

- 意味：送信元 IP アドレスを偽った攻撃を受けたサーバが、偽の送信元あてに返す応答パケット。とくに、SYN フラッドを受けたサーバが返す SYN/ACK
- ポイント：偽の送信元に「使われていない IP アドレス（ダークネット）」が選ばれると、そこに大量の SYN/ACK が届く。だから「送信元 A・送信元ポート 80/tcp の SYN/ACK を未使用アドレスで大量に観測」したら、A が SYN フラッドを受けている（A が攻撃先）と推定できる。過去の午前Ⅱで3回出た
- 語の意味：Back＝跳ね返った／Scatter＝飛び散ったもの

#### Smurf攻撃（すまーふこうげき / Smurf Attack）

- 意味：送信元 IP アドレスを標的のアドレスに偽り、宛先をネットワークのブロードキャストアドレスにした ICMP エコー要求を送ることで、そのネットワークの多数の機器から標的に ICMP エコー応答を集中させる攻撃
- ポイント：1つの要求が多数の応答になる「増幅」を使う。対策は、ルータで外部からのブロードキャスト宛のパケット（ダイレクテッドブロードキャスト）を転送しないこと。SYN フラッド（SYN を送る）、Ping of Death（大きすぎるパケット）、メール爆弾と並べて出る

#### UDPフラッド攻撃（ゆーでぃーぴーふらっどこうげき / UDP Flood Attack）

- 意味：大量の UDP パケットを標的に送り、回線の帯域や、受け取った機器の処理能力を使い切らせる攻撃
- ポイント：UDP には接続の手順がないので、偽った送信元からでも送れる。閉じたポートに届くと標的は ICMP の到達不能メッセージを返すため、その処理でも負荷がかかる

#### HTTPフラッド攻撃（えいちてぃーてぃーぴーふらっどこうげき / HTTP Flood Attack）

- 意味：Web サーバに大量の HTTP の GET や POST の要求を送り、Web サーバやアプリケーション、データベースの処理を使い切らせる攻撃。アプリケーション層（L7）の DDoS
- ポイント：1つ1つは正規の要求に見えるので、パケットの検査だけでは見分けにくい。検索や集計など重い処理をねらうと少ない量でも効く。対策は、レート制限、CAPTCHA や JavaScript による Bot の判定、WAF、CDN（#13）

#### Slow HTTP攻撃（すろーえいちてぃーてぃーぴーこうげき / Slow HTTP Attack）

- 意味：HTTP の要求のヘッダや本文を、わざとゆっくり少しずつ送り続けて接続を長時間保ち、Web サーバの同時接続数の上限を使い切らせる攻撃。ヘッダを送り続ける Slowloris、本文をゆっくり送る Slow HTTP POST がある
- ポイント：量は少ないので、帯域の監視では気付きにくい。対策は、ヘッダや本文の受信のタイムアウトを短くする、1つの IP アドレスからの同時接続数を制限する、イベント駆動型の Web サーバやリバースプロキシを前に置く。過去の午前Ⅱの DRDoS の問題で「多数の HTTP リクエストを長期間掛けて送信し続ける」がこの攻撃の誤りの選択肢として出た

### 多数から・第三者を使う

#### DDoS攻撃（でぃーどすこうげき / Distributed Denial of Service Attack）

- 意味：ボットネット（#01）など、多数の機器から一斉に DoS 攻撃を行うこと。分散型サービス妨害攻撃
- ポイント：送信元が多数で、それぞれは正規の利用者と見分けにくいので、1つの IP アドレスを遮断する対策が効かない。対策は、回線の容量の大きい CDN やスクラビングセンター（攻撃の通信を取り除く設備）、Anycast で負荷を分散すること（#13）。IoT 機器のボットネット Mirai（#01）は大規模な DDoS で知られる

#### マルチベクトル型DDoS攻撃（まるちべくとるがた / Multi-vector DDoS Attack）

- 意味：複数の種類の DDoS 攻撃（例：SYN フラッドと HTTP POST フラッド、UDP の反射とアプリケーション層の攻撃）を同時に、または切り替えながら組み合わせて行う攻撃
- ポイント：ネットワーク層とアプリケーション層の両方を同時にねらうので、1種類の対策では防ぎきれない。過去の午前Ⅱでは「Web サイトに対して SYN Flood 攻撃と HTTP POST Flood 攻撃を同時に行う」が正解。IoT 機器から UDP Flood だけ、DNS リフレクタだけ、は1種類なので当たらない
- 語の意味：Multi＝複数の／Vector＝攻撃の経路・手段

#### リフレクション攻撃（りふれくしょんこうげき / Reflection Attack）

- 意味：送信元 IP アドレスを標的のアドレスに偽った要求を、多数の第三者のサーバに送り、そのサーバの応答を標的に集中させる攻撃。反射型 DDoS（DRDoS：Distributed Reflection Denial of Service）ともいう
- ポイント：要求より応答が大きいプロトコルを使うと、攻撃者の送る量の何倍もの通信を標的に浴びせられる（増幅、アンプ攻撃）。悪用されやすいのは UDP の DNS・NTP・Memcached・SSDP・CLDAP・SNMP など。DKIM・SPF・DNSSEC（送信ドメイン認証・署名）、IPsec・TLS（暗号化）は悪用されるサービスの例ではない
- 語の意味：Reflection＝反射

#### DNSアンプ攻撃（でぃーえぬえすあんぷこうげき / DNS Amplification Attack）

- 意味：送信元を標的に偽って、オープンリゾルバなどに応答の大きい問い合わせ（ANY 型や、DNSSEC の署名付きの応答など）を送り、大きな応答を標的に集中させるリフレクション攻撃。DNS リフレクタ攻撃
- ポイント：CISA は DNS の増幅率を 28〜54 倍としている。対策は、オープンリゾルバをなくす、権威 DNS サーバで応答の量を制限する（RRL：Response Rate Limiting）、送信元検証
- 語の意味：Amplification＝増幅

#### NTPリフレクション攻撃（えぬてぃーぴーりふれくしょんこうげき / NTP Reflection Attack）

- 意味：送信元を標的に偽って、NTP サーバに応答が大きくなる要求（古い ntpd の monlist コマンドなど）を送り、大きな応答を標的に送らせるリフレクション攻撃
- ポイント：monlist は直近に通信した最大600件のアドレスの一覧を返すため、CISA は増幅率を約557倍としている。NTP サーバそのものを攻撃するのではなく、踏み台にして第三者を攻撃する。対策は、monlist を無効にする（ntpd 4.2.7 以降は既定で無効）、問い合わせの範囲を制限する
- 例：Memcached（UDP 11211番）は増幅率が数万倍になり、2018年に大規模な攻撃に悪用された

- 解説：SYN フラッドは「接続待ちの領域」を使い切らせる攻撃。SYN cookie は、ACK が返るまで領域を使わないので、領域が尽きない。
- アの意味：正しい。
- イの意味：名前は似ているが、HTTP の cookie とは関係ない。
- ウの意味：逆引きでは偽装を見抜けず、処理の負荷も増える。
- エの意味：TCP の SYN は暗号化されない。
- 出典：オリジナル問題（根拠：RFC 4987 3.6 SYN Cookies）

#### 問 sc-04-o08

- 問：Web サーバへのアクセス量は普段と変わらないのに、同時接続数が上限に達して新しい利用者が接続できなくなった。ログを見ると、少数の IP アドレスから、HTTP のヘッダを数秒おきに1行ずつ送り続ける接続が多数あった。この攻撃と対策の組合せとして、最も適切なものはどれか。
- ア：攻撃＝HTTP フラッド攻撃／対策＝CDN のキャッシュを有効にする
- イ：攻撃＝SYN フラッド攻撃／対策＝SYN cookie を有効にする
- ウ：攻撃＝DNS アンプ攻撃／対策＝オープンリゾルバをなくす
- エ：攻撃＝Slow HTTP 攻撃／対策＝ヘッダの受信のタイムアウトを短くし、1つの IP アドレスからの同時接続数を制限する
- 正解：エ
- 解説：少ない量で接続を長く占有するのが Slow HTTP 攻撃（Slowloris）。タイムアウトの短縮と同時接続数の制限で防ぐ。
- アの意味：HTTP フラッドは大量の要求を送るので、アクセス量が普段と変わらないことと合わない。
- イの意味：ヘッダを送っているので TCP の接続は確立している。ハーフオープンを作る SYN フラッドではない。
- ウの意味：DNS の応答を浴びせる攻撃で、Web サーバの接続は占有しない。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：Apache HTTP Server ドキュメント「Security Tips」Denial of Service (DoS) attacks・mod_reqtimeout）

#### 問 sc-04-o09

- 問：リフレクション攻撃で、攻撃者が送る通信の量に比べて、標的に届く通信の量が大きくなる理由として、最も適切なものはどれか。
- ア：踏み台のサーバが、攻撃者の要求を暗号化して送るから
- イ：要求に比べて応答のサイズが大きいサービスを選び、応答を標的に送らせるから
- ウ：TCP の再送のしくみで、同じパケットが何度も送られるから
- エ：標的のサーバが、届いたパケットをブロードキャストで転送するから
- 正解：イ
- 解説：DNS の ANY 型の問い合わせや NTP の monlist のように、小さな要求で大きな応答が返るサービスを使うと、応答の大きさの比（増幅率）の分だけ通信量が増える。CISA は NTP（monlist）で約557倍、DNS で28〜54倍としている。
- アの意味：暗号化では通信量はほとんど増えない。
- イの意味：正しい。
- ウの意味：リフレクションに使われるのは主に UDP で、再送は関係ない。
- エの意味：Smurf では踏み台のネットワークのブロードキャストを使うが、標的が転送するわけではない。
- 出典：オリジナル問題（根拠：CISA「Alert TA14-017A UDP-Based Amplification Attacks」）
