## 05-1 だれが何をしたか（CloudTrail）

### まとめ表

| 記録のしかた | 中身 | 期間・料金 |
| :-: | :-: | :-: |
| イベント履歴 | そのリージョンの管理イベント | 過去 90 日。料金なし。変更できない |
| 証跡 | 選んだイベントを S3 へ（CloudWatch Logs・EventBridge へも送れる） | S3 に置くかぎり。管理イベントの1コピーは無料（S3 の保存料はかかる） |
| CloudTrail Lake | イベントデータストアに集めて SQL で分析 | 料金オプションで最長約 10 年など。保存とクエリに料金 |

### CloudTrail の基本

#### AWS CloudTrail（えーだぶりゅーえすくらうどとれいる / AWS CloudTrail）

- 意味：ユーザー・ロール・AWS のサービスが行った操作（API の呼び出し）を、イベントとして記録するサービス
- ポイント：コンソール・CLI・SDK・API での操作が記録される。「だれが・いつ・どこから・何をしたか」を答えるもの。運用とリスクの監査、ガバナンス、コンプライアンスに使う
- 例：「セキュリティグループのルールを消したのはだれか」→ CloudTrail
- 語の意味：Cloud＝クラウド、Trail＝足跡

#### イベント履歴（いべんとりれき / Event history）

- 意味：リージョンの過去 90 日間の管理イベントを、コンソールで見たり検索したりダウンロードしたりできる機能
- ポイント：アカウントを作ると自動で使え、料金はかからない。記録は変更できない。90 日より長く残すなら証跡か CloudTrail Lake

#### 証跡（しょうせき / trail）

- 意味：CloudTrail のイベントを S3 バケットに配信して保存する設定。CloudWatch Logs や EventBridge にも送れる
- ポイント：長期保存・監査用。管理イベントの1コピーは CloudTrail の料金なしで S3 に送れる（S3 の保存料はかかる）。CloudWatch Logs に送れば、特定の操作でアラームを鳴らせる

#### 管理イベント（かんりいべんと / management events）

- 意味：AWS のリソースに対して行う管理の操作の記録。コントロールプレーンの操作とも呼ぶ
- ポイント：証跡とイベントデータストアは、デフォルトで管理イベントを記録する
- 例：IAM の `AttachRolePolicy`、EC2 の `CreateSubnet`、CloudTrail の `CreateTrail`

#### データイベント（でーたいべんと / data events）

- 意味：リソースの上や中で行われる操作の記録。S3 のオブジェクトの `GetObject`・`PutObject`・`DeleteObject` や、Lambda 関数の実行など
- ポイント：量が多いので、デフォルトでは記録されない。「S3 のどのオブジェクトをだれが読んだか」を残すなら、データイベントを有効にする（追加料金）

#### マルチリージョン証跡（まるちりーじょんしょうせき / multi-Region trail）

- 意味：アカウントで有効なすべてのリージョンのイベントを記録して、1つの S3 バケットに届ける証跡
- ポイント：使っていないリージョンでの不正な操作も見逃さない。リージョンごとに証跡を作るより漏れがない

#### 組織の証跡（そしきのしょうせき / organization trail）

- 意味：Organizations の管理アカウント（または委任された管理者）が作る、組織のすべてのアカウントのイベントを記録する証跡
- ポイント：メンバーアカウントのユーザーは、組織の証跡を消したり、記録を止めたり、変えたりできない。全社の操作の記録を1か所に集めるときの答え

#### ログファイルの整合性の検証（ろぐふぁいるのせいごうせいのけんしょう / log file integrity validation）

- 意味：CloudTrail が届けたあとで、ログファイルが変更・削除されていないかを確かめる機能
- ポイント：SHA-256 のハッシュと、RSA のデジタル署名を使う。気づかれずに改ざんすることが計算上できなくなる。「ログが改ざんされていないことを証明したい」→ これ（S3 のオブジェクトロックで消せなくするのとは別の話）

#### CloudTrail Lake（くらうどとれいるれいく / AWS CloudTrail Lake）

- 意味：ユーザーと API の操作を集めて保存し、SQL で分析できる、監査とセキュリティのためのマネージドなデータレイク
- ポイント：イベントはイベントデータストアに集まり、変更できない。料金オプションによって最長で約 10 年などの長い期間残せる。S3 にある既存の CloudTrail のログも取り込める

#### CloudTrail Insights（くらうどとれいるいんさいと / CloudTrail Insights）

- 意味：API の呼び出しの率やエラーの率をふだんと比べ、外れたときに Insights イベントを出す機能
- ポイント：「急に `RunInstances` が大量に呼ばれた」など、異常な操作の量に気づく。だれが何をしたかの記録そのものは通常の CloudTrail

## 05-2 設定とネットワークの記録

### まとめ表

| 問われていること | 答え |
| :-: | :-: |
| だれがその操作をしたか（API） | CloudTrail |
| リソースの設定が今どうなっていて、いつどう変わったか | AWS Config |
| ルールに合わない設定を見つけて直す | Config ルール＋修復 |
| VPC の中を流れた IP の通信 | VPC フローログ |
| アプリや OS のログを集めて検索・アラーム | CloudWatch Logs |

### AWS Config

#### AWS Config（えーだぶりゅーえすこんふぃぐ / AWS Config）

- 意味：アカウントの AWS リソースの設定の詳細を記録し、設定とリソースどうしの関係の履歴を残すサービス
- ポイント：リソースの作成・変更・削除を続けて記録し、設定がいつどう変わったかを見られる。設定のスナップショットと履歴は S3 に届ける。CloudTrail が「だれが何をした」なら、Config は「リソースがどういう状態か・どう変わったか」
- 例：「先月のある日の、このセキュリティグループのルールはどうだったか」→ Config

#### Config ルール（こんふぃぐるーる / AWS Config rules）

- 意味：リソースのあるべき設定を決め、記録した設定がそれに準拠しているかを評価するルール
- ポイント：AWS が用意したマネージドルール（変更してパラメータを決められる）と、自分で書くカスタムルールがある。設定が変わったときや、決めた頻度で評価する。評価するだけで、それ自体は設定を止めない（止めるのは SCP など）
- 例：「暗号化されていない EBS ボリュームを見つける」「S3 バケットがパブリックになっていないか」

#### 修復（しゅうふく / remediation）

- 意味：Config ルールで準拠していないと評価されたリソースを、Systems Manager の自動化ドキュメントで直すこと
- ポイント：手動の修復と自動の修復を設定できる。AWS が用意した修復アクションもある
- 例：パブリックになった S3 バケットを自動でブロックする

#### コンフォーマンスパック（こんふぉーまんすぱっく / conformance pack）

- 意味：Config ルールと修復アクションをまとめた集まり。アカウント・リージョン・組織全体に1つのまとまりとして配れる
- ポイント：YAML のテンプレートで作る。PCI DSS などの基準に合わせたルール一式をまとめて入れるときに使う

#### アグリゲータ（あぐりげーた / aggregator）

- 意味：複数のアカウントとリージョンから、Config の設定と準拠のデータを1か所に集める仕組み
- ポイント：組織全体の準拠状況を一覧で見たいときの答え。データを集めて見るためのもので、ルールを配るのはコンフォーマンスパックや組織ルール

### ネットワークとアプリのログ

#### VPC フローログ（ぶいぴーしーふろーろぐ / VPC Flow Logs）

- 意味：VPC のネットワークインターフェイスに出入りする IP の通信の情報を記録する機能
- ポイント：送信元・送信先・ポート・許可か拒否かなどの情報で、パケットの中身は記録しない。CloudWatch Logs・S3・Data Firehose に送れる。通信の経路の外で集めるので、速さに影響しない。厳しすぎるセキュリティグループのルールの診断などに使う
- 例：「EC2 に届かない通信が SG で拒否されているか調べる」→ フローログで REJECT を探す

#### CloudWatch Logs（くらうどうぉっちろぐず / Amazon CloudWatch Logs）

- 意味：EC2・CloudTrail・Route 53 などのログファイルを集めて、監視・保存・検索するサービス
- ポイント：すべてのシステム・アプリ・AWS のサービスのログを1か所に集められる。クエリで検索したり、フィルターでログからメトリクスを作ってアラームを鳴らしたりできる。標準と低頻度アクセスの2つのログクラスがある
- 例：アプリのログに「ERROR」が1分に10回出たら通知する

## 05-3 脅威の検出と調査

### まとめ表

| サービス | 一言で | 見るもの |
| :-: | :-: | :-: |
| GuardDuty | 怪しい動きを見つける | CloudTrail 管理イベント・VPC フローログ・DNS のログなど |
| Macie | S3 の機密データを見つける | S3 のオブジェクトとバケットの設定 |
| Inspector | 脆弱性を見つける | EC2・ECR のイメージ・Lambda |
| Security Hub CSPM | まとめて採点・一覧 | 基準に照らしたチェックとほかのサービスの検出結果 |
| Detective | 原因を調べる | ログを集めてグラフで可視化 |

### 検出のサービス

#### Amazon GuardDuty（あまぞんがーどでゅーてぃー / Amazon GuardDuty）

- 意味：AWS のデータソースとログを続けて監視・分析し、怪しい動きや悪意のある可能性がある動きを見つけて知らせる脅威検出サービス
- ポイント：悪い IP やドメインの一覧、機械学習などを使う。漏れた認証情報の悪用・暗号通貨のマイニング・マルウェアなどを見つけ、検出結果（finding）を出す。通信を止めたりリソースを隔離したりするのは別の仕組み（EventBridge と Lambda など）
- 語の意味：Guard＝守る、Duty＝任務

#### GuardDuty の基本データソース（がーどでゅーてぃーのきほんでーたそーす / GuardDuty foundational data sources）

- 意味：GuardDuty を有効にするとすぐ分析が始まるログ。CloudTrail の管理イベント・VPC フローログ・Route 53 Resolver の DNS クエリログ
- ポイント：GuardDuty は独立した複製のストリームでログを読むので、自分で証跡やフローログを有効にしなくてよく、既存の設定にも影響しない。リージョンで初めて有効にすると 30 日間の無料トライアルがある

#### 検出結果の自動対応（けんしゅつけっかのじどうたいおう / automated response with EventBridge）

- 意味：GuardDuty の検出結果が EventBridge にイベントとして自動で送られることを使い、SNS で通知したり Lambda で対処したりすること
- ポイント：GuardDuty はブロックしないので、止めたいなら EventBridge のルールで Lambda などを呼ぶ
- 例：怪しい EC2 の検出結果 → EventBridge → Lambda がそのインスタンスを隔離用のセキュリティグループに付け替える（構成は Claude が作った例）

#### Amazon Macie（あまぞんめいしー / Amazon Macie）

- 意味：機械学習とパターンマッチングで機密データを見つけ、データのセキュリティのリスクを見えるようにするサービス
- ポイント：対象は S3。オブジェクトの中の個人情報などを見つけると検出結果を出す。バケットがパブリックになっているなどの問題も知らせる
- 例：「S3 に置いたファイルにクレジットカード番号やマイナンバーがふくまれていないか調べたい」→ Macie

#### Amazon Inspector（あまぞんいんすぺくたー / Amazon Inspector）

- 意味：ソフトウェアの脆弱性や意図しないネットワークの露出を、自動で見つけて続けてスキャンする脆弱性管理サービス
- ポイント：対象は EC2 インスタンス・ECR のコンテナイメージ・Lambda 関数。「OS やライブラリに既知の脆弱性（CVE）がないか」→ Inspector。怪しい動き（GuardDuty）や機密データ（Macie）とは別

#### AWS Security Hub CSPM（えーだぶりゅーえすせきゅりてぃはぶしーえすぴーえむ / AWS Security Hub CSPM）

- 意味：AWS 環境をセキュリティの業界標準やベストプラクティスに照らして評価し、セキュリティの状態をまとめて見せるサービス
- ポイント：AWS の基礎的なセキュリティのベストプラクティス（FSBP）・CIS・PCI DSS・NIST などの基準でチェックする。GuardDuty・Inspector・Macie などの検出結果も受け取り、1か所で優先度を付けて見られる。多くのチェックは AWS Config を使うので、Config の有効化が要る
- 語の意味：CSPM＝Cloud Security Posture Management（クラウドのセキュリティの状態の管理）

#### Amazon Detective（あまぞんでぃてくてぃぶ / Amazon Detective）

- 意味：セキュリティの検出結果や怪しい動きの根本原因を、分析・調査するためのサービス
- ポイント：ログを自動で集め、機械学習・統計・グラフ理論で可視化する。「GuardDuty の検出結果について、何が起きたかをさかのぼって調べたい」→ Detective。見つけるのは GuardDuty、調べるのは Detective

#### AWS Artifact（えーだぶりゅーえすあーてぃふぁくと / AWS Artifact）

- 意味：AWS のセキュリティとコンプライアンスの文書（ISO・PCI・SOC のレポートなど）を、必要なときにダウンロードできるサービス
- ポイント：「監査人に AWS 側の SOC レポートを出したい」→ Artifact。自分の環境をチェックするもの（Config・Security Hub CSPM）ではない

### 05-1 だれが何をしたか（CloudTrail）

#### 問 aws-05-o01

- 問：本番のセキュリティグループのルールがいつの間にか消されていた。だれが、いつ、どの操作で消したかを調べたい。最も適したサービスはどれか。
- ア：AWS CloudTrail
- イ：AWS Config
- ウ：VPC フローログ
- エ：Amazon Inspector
- 正解：ア
- 解説：CloudTrail はユーザー・ロール・サービスが行った操作をイベントとして記録する。だれが何をしたかを調べるならこれ。
- アの意味：正しい。
- イの意味：リソースの設定がどう変わったかを記録するもので、「だれがどの操作をしたか」を記録するのは CloudTrail。
- ウの意味：IP の通信の記録で、API の操作は記録しない。
- エの意味：脆弱性のスキャン。
- 出典：オリジナル問題（根拠：AWS「とは AWS CloudTrail」（『ユーザー、ロール、または AWS のサービスによって実行されたアクションは、CloudTrail にイベントとして記録されます。』））

#### 問 aws-05-o02

- 問：CloudTrail の設定を何もしていないアカウントで、5 日前の IAM の操作を調べたい。正しいものはどれか。
- ア：証跡を作っていないので、何も記録されていない
- イ：イベント履歴で、過去 90 日間の管理イベントを料金なしで見られる
- ウ：CloudTrail Lake を有効にしないと見られない
- エ：過去 7 日間の分しか見られない
- 正解：イ
- 解説：イベント履歴は、アカウントを作ると自動で使え、リージョンの過去 90 日間の管理イベントを見られる。料金はかからない。
- アの意味：証跡がなくてもイベント履歴はある。
- イの意味：正しい。
- ウの意味：Lake は長期保存・分析用で、90 日以内ならイベント履歴で足りる。
- エの意味：90 日。
- 出典：オリジナル問題（根拠：AWS「とは AWS CloudTrail」（『イベント履歴 では、 AWS リージョン 内の過去 90 日間の管理イベントに関するレコードを表示、検索、ダウンロードできます。』／『イベント履歴 の閲覧には CloudTrail の料金はかかりません。』））

#### 問 aws-05-o03

- 問：S3 バケットの機密ファイルを、だれがいつダウンロードしたかを記録したい。CloudTrail の証跡で何をする必要があるか。
- ア：何もしなくてよい。証跡はデフォルトで GetObject を記録する
- イ：Insights イベントを有効にする
- ウ：ログファイルの整合性の検証を有効にする
- エ：データイベント（S3 のオブジェクトレベルの API）の記録を有効にする
- 正解：エ
- 解説：GetObject などの S3 のオブジェクトの操作はデータイベント。量が多いので、証跡のデフォルトでは記録されない。
- アの意味：デフォルトで記録されるのは管理イベントだけ。
- イの意味：API の呼び出しの率の異常を見つける機能で、個々のダウンロードの記録ではない。
- ウの意味：ログが改ざんされていないかを確かめる機能。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：AWS「CloudTrail のコンセプト」（『デフォルトでは、証跡とイベントデータストアは管理イベントをログ記録しますが、データイベントまたは Insights イベントは記録しません。』／『S3 バケット内のオブジェクトに対する Amazon S3 オブジェクトレベルの API アクティビティ (例: `GetObject`、`DeleteObject`、`PutObject` API オペレーション)。』））

#### 問 aws-05-o04
