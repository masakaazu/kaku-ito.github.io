## 03-1 サブネットとセキュリティグループ

### まとめ表

| 特性 | セキュリティグループ | ネットワーク ACL |
| :-: | :-: | :-: |
| 効く単位 | インスタンス（リソース） | サブネット |
| ルール | 許可だけ | 許可と拒否 |
| 評価 | すべてのルールを見てから決める | 番号の小さい順に見て、最初に一致したもので決める |
| 戻りの通信 | 自動で許可（ステートフル） | 明示的に許可が必要（ステートレス） |

### サブネットの分け方

#### パブリックサブネット（ぱぶりっくさぶねっと / public subnet）

- 意味：インターネットゲートウェイへの直接のルートがあるサブネット。中のリソースはインターネットにアクセスできる
- ポイント：ロードバランサーや NAT ゲートウェイなど、インターネットに面するものを置く。「パブリックかどうか」はサブネットの名前ではなく、ルートテーブルで決まる
- 例：ルートテーブルに `0.0.0.0/0 → igw-…` がある

#### プライベートサブネット（ぷらいべーとさぶねっと / private subnet）

- 意味：インターネットゲートウェイへの直接のルートがないサブネット。インターネットへ出るには NAT デバイスが要る
- ポイント：AWS は、リソースを守るためにプライベートサブネットを使うよう勧めている。アプリサーバーやデータベースはここに置く
- 例：ルートテーブルの `0.0.0.0/0` の行き先が NAT ゲートウェイ（#17）

#### 踏み台ホスト（ふみだいほすと / bastion host）

- 意味：プライベートサブネットのインスタンスに管理のために入るとき、まず経由するパブリックサブネットのサーバー
- ポイント：SSH のポートをインターネットに開く必要があり、鍵の管理も要る。今は Session Manager で置き換えられることが多い

#### Session Manager（せっしょんまねーじゃー / AWS Systems Manager Session Manager）

- 意味：EC2 インスタンスやオンプレミスのサーバーに、ブラウザや CLI からシェルで入れる Systems Manager の機能
- ポイント：インバウンドのポートを開かず、踏み台ホストや SSH キーも管理しなくてよい。アクセスは IAM ポリシーで一元管理し、セッションの記録も残せる
- 例：プライベートサブネットのインスタンスに、セキュリティグループのインバウンドを1つも開けずに入る

### セキュリティグループ

#### セキュリティグループ（せきゅりてぃぐるーぷ / security group）

- 意味：EC2 インスタンスなどのリソースに付け、そのリソースに届く通信と、そこから出ていく通信を制御する仮想のファイアウォール
- ポイント：AWS は VPC へのネットワークアクセスを制御する主な手段としている。1つのリソースに複数付けられ、そのときはルールが合わさって1つのルールの集まりになる。追加料金はない
- 例：Web サーバー用に「443 を 0.0.0.0/0 から許可」

#### インバウンドルールとアウトバウンドルール（いんばうんどるーるとあうとばうんどるーる / inbound and outbound rules）

- 意味：リソースに入ってくる通信（インバウンド）と出ていく通信（アウトバウンド）のそれぞれに書く許可のルール。プロトコル・ポート範囲・送信元（送信先）を指定する
- ポイント：セキュリティグループに書けるのは許可だけで、拒否は書けない。作ったばかりのセキュリティグループはインバウンドのルールがなく（何も入れない）、アウトバウンドはすべて許可されている
- 例：送信元に単一の IP を書くときは `/32`（`203.0.113.1/32`）

#### ステートフル（すてーとふる / stateful）

- 意味：通信の状態を覚えていて、許可した通信への応答（戻りの通信）を自動で通すこと
- ポイント：セキュリティグループはステートフル。インバウンドで 443 を許可すれば、その応答はアウトバウンドのルールに関係なく出られる。ネットワーク ACL はステートレス（03-2）

#### セキュリティグループの参照（せきゅりてぃぐるーぷのさんしょう / security group referencing）

- 意味：ルールの送信元や送信先に、IP アドレスの代わりに別のセキュリティグループを書くこと
- ポイント：そのセキュリティグループが付いたすべてのリソースからの通信が対象になる。台数が増減しても IP を書き直さなくてよいので、多層構成でよく使う
- 例：DB のセキュリティグループで「3306 をアプリ層のセキュリティグループ（sg-…）から許可」

#### デフォルトのセキュリティグループ（でふぉるとのせきゅりてぃぐるーぷ / default security group）

- 意味：VPC を作ると自動で付いてくる「default」という名前のセキュリティグループ
- ポイント：インバウンドは「同じセキュリティグループが付いたリソースから」すべて許可、アウトバウンドはすべて許可。ルールは変更できるが、削除はできない。AWS は用途ごとにセキュリティグループを作るよう勧めている

## 03-2 ネットワーク ACL

### まとめ表

| 項目 | デフォルトのネットワーク ACL | 新しく作ったカスタムネットワーク ACL |
| :-: | :-: | :-: |
| できるとき | VPC と一緒に自動で | 自分で作る |
| 最初の状態 | すべてのインバウンド・アウトバウンドを許可 | 番号付きのルールがなく、すべて拒否（`*` のルールだけ） |
| 関連付け | どの ACL にも関連付けていないサブネット | 関連付けたサブネット |

### NACL のしくみ

#### ネットワーク ACL（ねっとわーくえーしーえる / network access control list, NACL）

- 意味：サブネットの単位で、出入りする通信を許可または拒否するルールの一覧
- ポイント：ステートレスで、きめの粗い制御。セキュリティグループに加える「追加の防御の層」として使う。1つの NACL は複数のサブネットに付けられるが、1つのサブネットに付けられる NACL は一度に1つだけ。追加料金はない
- 例：特定の IP アドレスの範囲からの通信を、サブネット全体でまとめて拒否する
- 語の意味：Network＝ネットワーク、Access Control List＝アクセス制御の一覧

#### ステートレス（すてーとれす / stateless）

- 意味：通信の状態を覚えていないため、行きの通信と戻りの通信を別々に評価すること
- ポイント：ネットワーク ACL はステートレス。インバウンドで 443 を許可しても、その応答（一時ポートあて）をアウトバウンドで許可しないと戻れない

#### ルール番号（るーるばんごう / rule number）

- 意味：ネットワーク ACL の各ルールに付ける番号。小さい番号から順に評価する
- ポイント：一致するルールが見つかった時点で、それより大きな番号の反対のルールがあっても関係なく適用される。広いポートを許可しつつ一部を拒否したいときは、拒否のルールを小さい番号にする。最後に番号が `*` のルールがあり、どれにも一致しない通信を拒否する（このルールは消せない）
- 例：100 で 0.0.0.0/0 を許可、90 で 198.51.100.0/24 を拒否 → 198.51.100.0/24 は拒否される

#### デフォルトのネットワーク ACL（でふぉるとのねっとわーくえーしーえる / default network ACL）

- 意味：VPC に自動で付いてくるネットワーク ACL。すべての通信の出入りを許可するよう設定されている
- ポイント：サブネットを明示的にほかの NACL に関連付けないと、自動でデフォルトの NACL に関連付けられる。ルールは追加・削除できる

#### カスタムネットワーク ACL（かすたむねっとわーくえーしーえる / custom network ACL）

- 意味：自分で作ってサブネットに関連付けるネットワーク ACL
- ポイント：作った直後はアスタリスク（`*`）のルールしかなく、すべての通信が拒否される。ルールを足すたびに、応答の通信を通すための反対向きのルールも要る

#### 一時ポート（いちじぽーと / ephemeral ports）

- 意味：通信を始めるクライアント側が、その通信のために選ぶ送信元のポート番号。範囲は OS などで変わる
- ポイント：多くの Linux カーネルは 32768～61000、Windows Server 2008 以降は 49152～65535、ELB・NAT ゲートウェイ・Lambda は 1024～65535。いろいろなクライアントを受けるなら、NACL で 1024～65535 を開けることが多い
- 例：Web サーバーのあるサブネットの NACL で、アウトバウンドに「TCP 1024-65535 を 0.0.0.0/0 へ許可」（応答の通信）

## 03-3 外からの攻撃への守り

### まとめ表

| サービス | 守るもの | 層 |
| :-: | :-: | :-: |
| AWS Shield Standard | すべての AWS のお客様（自動・追加料金なし） | ネットワーク・トランスポート層の DDoS |
| AWS Shield Advanced | 指定したリソース（有料） | DDoS 全般。SRT・コスト保護つき |
| AWS WAF | CloudFront・ALB・API Gateway など | HTTP(S)（アプリケーション層） |
| AWS Network Firewall | VPC のサブネット | VPC の境界の通信（IPS・ドメインのフィルター） |
| AWS Firewall Manager | 組織の複数のアカウント | 上のルールを一元管理 |

### DDoS と Shield

#### DDoS 攻撃（でぃーどすこうげき / distributed denial of service attack）

- 意味：たくさんの送信元から大量の通信を送りつけ、サービスを使えなくする攻撃
- ポイント：UDP リフレクション攻撃や TCP SYN フラッドのような大量の通信の攻撃（ネットワーク・トランスポート層）と、HTTP のリクエストを大量に送る攻撃（アプリケーション層）がある
- 語の意味：Distributed＝分散した、Denial of Service＝サービスの妨害

#### AWS Shield Standard（えーだぶりゅーえすしーるどすたんだーど / AWS Shield Standard）

- 意味：すべての AWS のお客様に追加料金なしで自動で付く DDoS の保護
- ポイント：よくあるネットワーク層・トランスポート層の DDoS を防ぐ。特に Route 53 のホストゾーン・CloudFront・Global Accelerator の標準アクセラレーターで効果が大きい。申し込みや設定は要らない

#### AWS Shield Advanced（えーだぶりゅーえすしーるどあどばんすと / AWS Shield Advanced）

- 意味：申し込んで使う、より高いレベルの DDoS の保護サービス（有料）
- ポイント：保護するリソースを指定する（CloudFront・Route 53 のホストゾーン・Global Accelerator・Elastic IP・ALB など）。アプリケーション層の DDoS の自動緩和、SRT の支援、DDoS による請求の急増に対するコスト保護、保護するリソースの WAF の標準料金がふくまれる
- 例：「DDoS 攻撃で増えたデータ転送の料金も守りたい」「専門チームに対応を頼みたい」

#### SRT（えすあーるてぃー / Shield Response Team）

- 意味：DDoS への対応を専門とする AWS のセキュリティエンジニアのチーム。Shield Advanced のお客様を支援する
- ポイント：Shield Standard だけでは使えない
- 語の意味：Shield＝盾、Response＝対応、Team＝チーム

### WAF とファイアウォール

#### AWS WAF（えーだぶりゅーえすわふ / AWS WAF）

- 意味：守る Web アプリのリソースに届く HTTP(S) のリクエストを監視・制御する Web アプリケーションファイアウォール
- ポイント：付けられる先は CloudFront・API Gateway の REST API・ALB・AppSync・Cognito のユーザープールなど。NLB や EC2 そのものには付けない。条件に合うリクエストを許可・ブロック・カウント、または CAPTCHA やチャレンジで確かめる
- 例：ALB の前で SQL インジェクションのリクエストを止める
- 語の意味：Web Application Firewall＝Web アプリ用の防火壁

#### ウェブ ACL（うぇぶえーしーえる / web ACL）

- 意味：AWS WAF で、守るリソースに付けるルールの集まり（新しいコンソールでは「保護パック」）
- ポイント：ルールに一致しなかったリクエストをどうするかの「デフォルトアクション」（Allow か Block）を必ず決める。多くの人に見せるサイトなら Allow にして、悪いものだけをルールで止める

#### レートベースのルール（れーとべーすのるーる / rate-based rule）

- 意味：リクエストの数を数え、同じ IP アドレスなどからのリクエストが速すぎるときに制限する WAF のルール
- ポイント：HTTP のリクエストを大量に送る攻撃（アプリケーション層の DDoS）やブルートフォースの対策に使う
- 例：同じ IP から5分間に一定数を超えたらブロック

#### マネージドルールグループ（まねーじどるーるぐるーぷ / managed rule group）

- 意味：AWS や AWS Marketplace の販売者が作って保守する、WAF のルールの集まり
- ポイント：アプリの脆弱性（よくある攻撃のパターン）や不要な通信への保護を、自分でルールを書かずに使える。本番に入れる前にテストして誤検出を確かめる

#### 地理的一致（ちりてきいっち / geo match）

- 意味：リクエストの送信元の国や地域で、Web リクエストを扱い分ける WAF のルール
- 例：サービスを提供していない国からのアクセスをブロックする
- ポイント：国でブロックするだけなら CloudFront の地理的制限（#19）でもできる

#### SQL インジェクション・XSS の対策ルール（えすきゅーえるいんじぇくしょん / SQL injection, cross-site scripting）

- 意味：リクエストの中の悪意のある SQL コード（データベースを変えたり抜き出したりする）や、悪意のあるスクリプトを調べる WAF のルール
- ポイント：アプリケーション層の攻撃なので、セキュリティグループやネットワーク ACL（ポートと IP しか見ない）では防げない。WAF の出番

#### AWS Firewall Manager（えーだぶりゅーえすふぁいあうぉーるまねーじゃー / AWS Firewall Manager）

- 意味：WAF・Shield Advanced・セキュリティグループ・ネットワーク ACL・Network Firewall・DNS Firewall などのルールを、組織の複数のアカウントとリソースにまとめて適用・管理するサービス
- ポイント：新しく増えたアカウントやリソースにも自動で保護を付けられる。組織全体を守りたいとき、守るリソースがよく増えるときに向く
- 例：組織の全アカウントの ALB に、同じ WAF のルールを自動で付ける

#### AWS Network Firewall（えーだぶりゅーえすねっとわーくふぁいあうぉーる / AWS Network Firewall）

- 意味：VPC のための、ステートフルなマネージドのネットワークファイアウォール兼、侵入検知・防止（IDS/IPS）のサービス
- ポイント：VPC の境界で通信をフィルターする。Suricata 互換のルール、ドメイン名のリストでのフィルター、出入りする通信の詳しい中身の検査（ディープパケットインスペクション）ができる。HTTP 以外の通信も対象
- 例：VPC から外へは、許可したドメインにだけ通信させる

#### Route 53 Resolver DNS Firewall（るーとごじゅうさんりぞるばーでぃーえぬえすふぁいあうぉーる / Route 53 Resolver DNS Firewall）

- 意味：VPC の中から Route 53 Resolver に送られる DNS の問い合わせをフィルターする機能
- ポイント：セキュリティグループやネットワーク ACL では、Route 53 Resolver（VPC＋2 のアドレス）との DNS のやりとりは止められない。悪いドメインの名前解決を止めたいときはこれ

### 03-1 サブネットとセキュリティグループ

#### 問 aws-03-o01

- 問：Web サーバー（ALB の後ろの EC2）と RDS のデータベースからなるシステムで、データベースをインターネットから直接触れないようにしたい。配置として最も適切なものはどれか。
- ア：すべてをパブリックサブネットに置き、セキュリティグループで絞る
- イ：ALB はパブリックサブネット、EC2 と RDS はプライベートサブネットに置く
- ウ：RDS だけパブリックサブネットに置き、EC2 はプライベートサブネットに置く
- エ：すべてをプライベートサブネットに置き、ALB もインターネットゲートウェイを使わない
- 正解：イ
- 解説：インターネットからの入口（ALB）だけをパブリックサブネットに置き、アプリとデータベースはインターネットゲートウェイへのルートがないプライベートサブネットに置く。AWS はリソースを守るためにプライベートサブネットを勧めている。
- アの意味：動かせるが、データベースにインターネットへの直接のルートができ、設定を誤ると外から届いてしまう。
- イの意味：正しい。
- ウの意味：守りたいデータベースを外に面した側に置いていて逆。
- エの意味：インターネットに面した ALB はインターネットゲートウェイへのルートがあるパブリックサブネットに置く。これではユーザーが届かない。
- 出典：オリジナル問題（根拠：AWS「Amazon VPC ユーザーガイド」サブネット（『AWS リソースを保護するために、プライベートサブネットを使用することをお勧めします。』／『サブネットには、インターネットゲートウェイへの直接ルートがありません。』））

#### 問 aws-03-o02

- 問：あるサブネットが「パブリックサブネット」であるかどうかを決めるものはどれか。
- ア：サブネットの名前に public が入っているかどうか
- イ：サブネットのルートテーブルに、インターネットゲートウェイへの直接のルートがあるかどうか
- ウ：サブネットに付けたネットワーク ACL がすべてを許可しているかどうか
