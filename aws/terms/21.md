## 21-1 オンラインのファイル転送

### まとめ表

| サービス | 何をするか | 選ぶ決め手 |
| :-: | :-: | :-: |
| DataSync | ストレージどうしでファイル・オブジェクトを速く安全に移す | NFS・SMB・HDFS から S3・EFS・FSx へ。移行・定期的な転送 |
| Transfer Family | SFTP・FTPS・FTP・AS2 で S3・EFS にファイルを送る | 取引先のいまの SFTP のクライアントを変えない |
| S3 Transfer Acceleration | エッジロケーション経由で S3 へのアップロードを速くする | 世界中から 1 つのバケットへ・長距離 |

数字や条件は AWS「AWS DataSync とは」「AWS Transfer Family とは」による

### DataSync

#### AWS DataSync（でーたしんく / AWS DataSync）

- 意味：ストレージサービスとの間で、ファイルやオブジェクトのデータを速く簡単に転送する、安全で信頼性の高いファイル転送サービス
- ポイント：オンプレミスの NFS・SMB・HDFS・オブジェクトストレージ、S3・EFS・FSx の各種、ほかのクラウド（Google Cloud Storage・Azure など）の間で転送する。AWS が設計した転送プロトコルで、増分転送・インライン圧縮などの最適化をする。転送中のデータは TLS で暗号化される
- 例：オンプレミスの NAS にある 50 TB のファイルを、S3 に移行する

#### DataSync エージェント（えーじぇんと / DataSync agent）

- 意味：データ転送のために、自分のストレージの環境に置く仮想マシン（VM）のアプライアンス
- ポイント：オンプレミスのストレージと AWS の間の転送などで必要になる（自分やほかのクラウドが管理するストレージがあるとき）。同じアカウントの AWS のストレージサービスどうしの転送や、S3 とほかのクラウドのオブジェクトストレージの間の転送では要らない
- 例：データセンターの VMware にエージェントを置き、NFS の共有に接続する

#### 検証と増分転送（けんしょうとぞうぶんてんそう / Data verification, Transfer only changed data）

- 意味：DataSync が転送の中でデータの整合性を確かめることと、2 回目からは変わったデータだけを送ること
- ポイント：チェックサムとメタデータを計算して比べ、違いがあれば検証が失敗してエラーになる。変更されたデータだけを転送するので、繰り返しの転送が速い
- 例：移行の最後に、もう一度タスクを動かして、前回から変わったファイルだけを送る

#### 帯域幅制限とスケジュール（たいいきはばせいげん / Bandwidth limit, Task scheduling）

- 意味：DataSync のタスクが使うネットワークの最大帯域幅（MiB/秒）を決める設定と、タスクを決まった間隔で動かす設定
- ポイント：帯域幅制限は、作成・編集・開始のとき、実行中にも変えられる。スケジュールは最短 1 時間の間隔で、cron か rate の式で書く
- 例：業務時間中は社内回線を圧迫しないよう、帯域幅を 100 MiB/秒に制限する

### そのほかの転送

#### AWS Transfer Family（とらんすふぁーふぁみりー / AWS Transfer Family）

- 意味：SFTP・FTPS・FTP・AS2・ウェブブラウザでのファイル転送を、S3 や EFS と直接やり取りできるフルマネージドのサービス
- ポイント：認証・アクセス・ファイアウォールについて、利用者のクライアント側の設定をそのまま保ったまま、ファイル転送のワークフローを AWS に移せる。アップロードされたファイルの処理を自動化するワークフローもある
- 例：取引先が毎日 SFTP で送ってくる請求データを、S3 で直接受け取る
- 語の意味：SFTP＝SSH File Transfer Protocol、AS2＝Applicability Statement 2

#### S3 Transfer Acceleration（とらんすふぁーあくせられーしょん / Amazon S3 Transfer Acceleration）

- 意味：クライアントと S3 のバケットの間の長距離のファイル転送を速くする、バケット単位の機能
- ポイント：CloudFront のエッジロケーションを使い、エッジに着いたデータを最適化された経路で S3 へ送る。世界中から 1 つのバケットにアップロードするとき、大陸をまたいで GB〜TB を定期的に送るときに向く。追加の転送料金がかかることがある。仮想ホスト形式のリクエストだけで使える
- 例：世界中の支社が、東京のバケットに動画をアップロードする

## 21-2 ハイブリッドストレージと物理的な転送

### まとめ表

| ゲートウェイ | オンプレミスからの見え方 | データの置き場所 |
| :-: | :-: | :-: |
| S3 ファイルゲートウェイ | NFS・SMB のファイル共有 | S3 のオブジェクト（ローカルにキャッシュ） |
| FSx ファイルゲートウェイ | SMB のファイル共有 | FSx for Windows File Server（ローカルにキャッシュ） |
| ボリュームゲートウェイ（キャッシュ型） | iSCSI のディスク | S3（よく使う一部だけローカル） |
| ボリュームゲートウェイ（保管型） | iSCSI のディスク | すべてローカル、スナップショットを S3 へ |
| テープゲートウェイ | 仮想テープ | S3 Glacier Flexible Retrieval・Deep Archive |

数字や条件は AWS「ボリュームゲートウェイについて」「テープゲートウェイについて」による

### Storage Gateway

#### AWS Storage Gateway（すとれーじげーとうぇい / AWS Storage Gateway）

- 意味：オンプレミスのソフトウェアのアプライアンスをクラウドのストレージにつなぎ、オンプレミスと AWS のストレージを統合するサービス
- ポイント：ファイル（S3 ファイルゲートウェイ・FSx ファイルゲートウェイ）、ボリューム（ボリュームゲートウェイ）、テープ（テープゲートウェイ）の 3 種類がある。オンプレミスの VM（VMware ESXi・KVM・Hyper-V など）、ハードウェアアプライアンス、EC2 インスタンスとして置ける
- 例：オンプレミスのアプリは変えずに、保存先だけを AWS にする

#### S3 ファイルゲートウェイ（えすすりーふぁいるげーとうぇい / Amazon S3 File Gateway）

- 意味：S3 へのファイルのインターフェイスを用意し、NFS や SMB で S3 にファイルを保存・取得できるゲートウェイ
- ポイント：保存したファイルは S3 のオブジェクトになり、AWS のアプリやサービスから直接アクセスできる。ライフサイクル・クロスリージョンレプリケーション・バージョニングで管理できる。透過的なローカルキャッシュで、低いレイテンシーでアクセスできる
- 例：オンプレミスのアプリのログを NFS で書き、S3 で Athena の分析に使う

#### FSx ファイルゲートウェイ（えふえすえっくすふぁいるげーとうぇい / Amazon FSx File Gateway）

- 意味：オンプレミスから、クラウドの FSx for Windows File Server のファイル共有に、低いレイテンシーでアクセスできるゲートウェイ
- ポイント：オンプレミスのファイルサーバーをなくし、データを AWS に集められる。FSx for Windows File Server が 1 つ以上と、VPN か Direct Connect での接続が必要。Active Directory のドメインに参加させて使う
- 例：支社の Windows のファイルサーバーをやめ、FSx for Windows File Server にまとめる

#### キャッシュ型ボリューム（きゃっしゅがたぼりゅーむ / Cached volumes）

- 意味：データを S3 に保存し、よくアクセスする一部のデータのコピーだけをローカルに持つ、ボリュームゲートウェイの構成
- ポイント：オンプレミスのサーバーからは iSCSI のデバイスとしてマウントする。主なストレージのコストを大きく下げ、オンプレミスのストレージを増やす必要を減らす。よく使うデータへのアクセスは速いまま
- 例：容量が足りなくなったオンプレミスのディスクを、S3 で広げる
- 語の意味：iSCSI＝Internet Small Computer System Interface

#### 保管型ボリューム（ほかんがたぼりゅーむ / Stored volumes）

- 意味：すべてのデータをローカルに保存し、その時点のスナップショットを非同期で S3 にバックアップする、ボリュームゲートウェイの構成
- ポイント：データ全体に低いレイテンシーでアクセスしたいときに使う。スナップショットは増分で、EBS スナップショットとしても保存されるので、オンプレミスや EC2 に復元できる
- 例：データはすべて手元に置き、災害に備えて AWS にバックアップする

#### テープゲートウェイ（てーぷげーとうぇい / Tape Gateway）

- 意味：クラウドの仮想テープのストレージを用意するゲートウェイ
- ポイント：バックアップデータを、S3 Glacier Flexible Retrieval か S3 Glacier Deep Archive に安く長くアーカイブできる。物理テープの用意・増設・保守の手間がなくなる
- 例：テープライブラリを使うバックアップソフトはそのままで、保存先を AWS の仮想テープにする

### 物理的な転送

#### AWS Snowball Edge（すのーぼーるえっじ / AWS Snowball Edge）

- 意味：ストレージとコンピューティングの力を持つ頑丈なデバイスで、データを入れて配送することで、インターネットより速く AWS に転送できるもの
- ポイント：ストレージ最適化 210 TB と、コンピューティング最適化の 2 つの設定がある。データのローカル処理やエッジコンピューティングにも使える。ただし新しい顧客には提供されなくなった。代わりにオンラインは DataSync、安全な物理的な転送は AWS Data Transfer Terminal を使う
- 例：（以前のやり方）ネットワークで何か月もかかる大量のデータを、デバイスで送る

#### AWS Data Transfer Terminal（でーたとらんすふぁーたーみなる / AWS Data Transfer Terminal）

- 意味：自分のストレージデバイスを持ち込んで、クラウドへ高速にデータを転送するための、安全な物理的な場所
- ポイント：コンソールから最寄りのターミナルを予約して使う。Snowball Edge の代わりの、オフラインのデータ転送の手段
- 例：撮影した大量の映像データのディスクを持ち込み、まとめてアップロードする

## 21-3 データベースとサーバーの移行

### まとめ表

| 場面 | 使うもの |
| :-: | :-: |
| 同じエンジンどうし（Oracle → Oracle） | DMS（RDS に相当するものへは同種データ移行も） |
| 違うエンジンどうし（Oracle → PostgreSQL） | スキーマを DMS Schema Conversion か AWS SCT で変換 → DMS でデータ |
| 止める時間を短く | DMS の全ロード＋CDC |
| サーバーを丸ごと（リホスト） | AWS Transform MGN（旧 Application Migration Service） |
| 移行の進み具合を 1 か所で | AWS Migration Hub |

数字や条件は AWS「AWS DMS 用語と概念」「AWS DMS のコンポーネント」による

### DMS

#### AWS Database Migration Service（でぃーえむえす / AWS DMS）

- 意味：リレーショナルデータベース・データウェアハウス・NoSQL データベースなどのデータストアを移行するクラウドサービス
- ポイント：ソースとターゲットのデータストアを「エンドポイント」と呼ぶ。同じエンジンどうしも、違うエンジンどうしも移行できる。1 回だけの移行も、変更を続けてレプリケートしてソースとターゲットを同期させることもできる。DMS Fleet Advisor で移行するデータベースを見つけられる
- 例：オンプレミスの Oracle を、Aurora PostgreSQL に移す

#### レプリケーションインスタンス（れぷりけーしょんいんすたんす / Replication instance）

- 意味：1 つ以上のレプリケーションタスクを動かす、マネージドな EC2 インスタンス
- ポイント：移行の特性と容量によって、複数のタスクを動かせる。マルチ AZ にすると、別の AZ にスタンバイを自動で用意し、継続的なレプリケーションの可用性が上がる
- 例：大きなテーブルの移行のため、メモリの多いインスタンスクラスを選ぶ

#### 全ロード（ぜんろーど / Full load）

- 意味：ソースにある既存のデータを、ターゲットにまとめてコピーする移行のタイプ
- ポイント：既存のデータをコピーする間、止めることが許されるときに選ぶ
- 例：週末にシステムを止めて、データを全部コピーする

#### CDC（しーでぃーしー / Change data capture）

- 意味：ソースのデータベースへの変更を捕まえて、ターゲットに続けて反映するしくみ
- ポイント：「全ロード＋CDC」は、変更を捕まえながら全ロードし、終わったら捕まえた変更を反映する（止める時間を短くできる）。「CDC のみ」は、既存のデータを DMS 以外の方法でコピーしたときに使う
- 例：本番を動かしたまま移行し、切り替えの直前まで変更を反映し続ける
- 語の意味：CDC＝Change Data Capture（変更データの捕捉）

#### AWS SCT と DMS Schema Conversion（えすしーてぃー / AWS Schema Conversion Tool, DMS Schema Conversion）

- 意味：データベースエンジンの間で、既存のデータベースのスキーマ（表の定義やコード）を変換するツールと機能
- ポイント：違うエンジンへ移すときに使う。DMS Schema Conversion はソースのスキーマを自動で評価して変換する。AWS SCT はローカルの PC にダウンロードして使う。データそのものは DMS で移す
- 例：Oracle のストアドプロシージャを、PostgreSQL 用に変換する
- 語の意味：SCT＝Schema Conversion Tool

#### 同種データ移行（どうしゅでーたいこう / Homogeneous data migrations）

- 意味：セルフマネージドのデータベースを、同じ種類の RDS に相当するデータベースへ移すのを簡単にする DMS の機能
- ポイント：ネイティブのデータベースのツールを使い、完全に自動で移行する。サーバーレスで、必要なリソースは自動でスケールする
- 例：オンプレミスの PostgreSQL を、Amazon RDS for PostgreSQL に移す

#### DMS Serverless（でぃーえむえすさーばーれす / AWS DMS Serverless）

- 意味：自動のプロビジョニング・スケーリング、組み込みの高可用性、使った分の課金を持つ DMS の機能
- ポイント：容量を見積もってレプリケーションインスタンスを用意する手間がない。エンドポイントの作り方はふつうの DMS と同じ
- 例：移行するデータの量が読めないので、Serverless で始める

### サーバーの移行と管理

#### AWS Transform MGN（えむじーえぬ / AWS Transform MGN, 旧 AWS Application Migration Service）

- 意味：物理・仮想・クラウドのサーバーを、短い停止で AWS に移すのを自動化するサービス
- ポイント：ソースのサーバーをブロックレベルで続けてレプリケートし、AWS で起動できるように変換する。切り替えの停止は、ふつう数分。まず「そのまま移す（リホスト）」をして、あとで作り直すときの最初の一歩になる
- 例：データセンターの 200 台の仮想マシンを、そのまま EC2 に移す
- 語の意味：試験ガイドの対象サービスの一覧では「AWS Application Migration Service」の名前で載っている。その旧ページ（what-is-application-migration-service）は、いまは AWS Transform MGN のページに転送される

#### AWS Migration Hub（まいぐれーしょんはぶ / AWS Migration Hub）

- 意味：既存のサーバーを見つけ、移行を計画し、アプリケーションごとの移行の状態を 1 か所で追えるサービス
- ポイント：サーバーをアプリケーションにまとめて、移行の状態を見られる。移行を始めてからまとめても、先にサーバーを見つけてからまとめてもよい
- 例：100 のアプリの移行がどこまで進んだかを、1 つの画面で確かめる

## 問題演習

- 書式：「#### 問 問題ID」の下に、問・ア〜エ・正解・解説・選択肢ごとの意味・出典を書く。「###」は小分類（クイズの範囲に使う）
- 全問オリジナル問題（AWS は本番の問題を公開していない）。会社名や場面は Claude が作った例。出典には、答えの根拠にした AWS のドキュメントを書いた

### 21-1 オンラインのファイル転送

#### 問 aws-21-o01

- 問：オンプレミスの NFS のファイルサーバーにある 30 TB のファイルを、ネットワーク経由で S3 に移行したい。転送したデータの整合性も確かめたい。最も適したものはどれか。
- ア：S3 Transfer Acceleration を有効にして、手作業でアップロードする
- イ：AWS Transfer Family の SFTP サーバーを作る
- ウ：AWS DataSync
- エ：テープゲートウェイ
- 正解：ウ
- 解説：DataSync は、オンプレミスの NFS・SMB などと S3・EFS・FSx の間で、ファイルやオブジェクトを速く安全に転送する。転送中に必ずデータの整合性チェックを行う。
- アの意味：アップロードを速くする機能で、ファイルサーバーからの移行や整合性の確認のしくみはない。
- イの意味：取引先などが SFTP で送るためのもので、大量のファイルの移行には向かない。
- ウの意味：正しい。
- エの意味：バックアップを仮想テープとして保存するもので、ファイルサーバーの移行ではない。
- 出典：オリジナル問題（根拠：AWS「AWS DataSync とは」（『AWS DataSync は、安全で信頼性が高く、高速なファイル転送サービスであり、ストレージサービスとの間で AWS ファイルまたはオブジェクトデータを迅速かつ簡単に転送できます。』）／AWS「AWS DataSync の仕組み」（『DataSync は転送中に必ずデータの整合性チェックを実行します。』））

#### 問 aws-21-o02
