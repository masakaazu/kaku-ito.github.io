## 13-1 ストレージクラス

### まとめ表

| ストレージクラス | アクセスの目安 | 取り出し | AZ | 最小ストレージ期間 |
| :-: | :-: | :-: | :-: | :-: |
| S3 Standard | 頻繁（月に 2 回以上） | ミリ秒 | 3 以上 | なし |
| S3 Intelligent-Tiering | 分からない・変わる | ミリ秒（アーカイブ階層は復元） | 3 以上 | なし |
| S3 Standard-IA | 月に 1 回 | ミリ秒 | 3 以上 | 30 日 |
| S3 One Zone-IA | 月に 1 回・作り直せる | ミリ秒 | 1 | 30 日 |
| S3 Express One Zone | 最も低いレイテンシー | 1 桁ミリ秒 | 1 | なし |
| S3 Glacier Instant Retrieval | 四半期に 1 回 | ミリ秒 | 3 以上 | 90 日 |
| S3 Glacier Flexible Retrieval | 半年に 1 回 | 数分〜12 時間（復元） | 3 以上 | 90 日 |
| S3 Glacier Deep Archive | 年に 1 回 | 9〜48 時間（復元） | 3 以上 | 180 日 |

すべてのクラスの耐久性は 99.999999999%（イレブンナイン）。数字は AWS「Amazon S3 ストレージクラスの理解と管理」「長期データストレージとしての S3 Glacier ストレージクラスを理解する」の比較表による

### よく使うデータ

#### S3 Standard（すたんだーど / S3 Standard）

- 意味：頻繁にアクセスするデータのための、デフォルトのストレージクラス
- ポイント：アップロードのときにストレージクラスを指定しなければ S3 Standard になる。3 つ以上の AZ に保存され、最小ストレージ期間や取り出し料金はない。アクセスが減ったら、ライフサイクルで安いクラスに移す
- 例：Web サイトの画像や、毎日読むアプリのデータ

#### S3 Intelligent-Tiering（いんてりじぇんとてぃありんぐ / S3 Intelligent-Tiering）

- 意味：アクセスのパターンを監視し、オブジェクトを最も安いアクセス階層に自動で移すストレージクラス
- ポイント：30 日アクセスがないと低頻度アクセス階層、90 日でアーカイブインスタントアクセス階層へ自動で移り、アクセスされると高頻度アクセス階層に戻る。取り出し料金はなく、オブジェクトごとのモニタリングとオートメーションの料金がかかる。128 KB 未満のオブジェクトは監視されず、高頻度アクセス階層に置かれる。オプションのアーカイブアクセス・ディープアーカイブアクセス階層は、使う前に復元が要る
- 例：アクセスの頻度が予測できないデータレイクのファイル

#### S3 Express One Zone（えくすぷれすわんぞーん / S3 Express One Zone）

- 意味：1 つの AZ のディレクトリバケットに保存し、1 桁ミリ秒の一貫したアクセスを出す、高性能のストレージクラス
- ポイント：レイテンシーが最も低いクラスで、S3 Standard よりアクセスが最大 10 倍速く、リクエストのコストが 50% 低い。保存先の AZ を選べるので、コンピューティングと同じ AZ に置ける。1 つの AZ なので、AZ の損失には耐えられない
- 例：機械学習の学習で、同じ AZ の EC2 から大量の小さなファイルを読む

#### ディレクトリバケット（でぃれくとりばけっと / directory bucket）

- 意味：汎用バケットのフラットな構造ではなく、データを階層的にディレクトリにまとめるバケットの種類。S3 Express One Zone で使う
- ポイント：プレフィックスの制限がなく、ディレクトリは水平にスケールする。名前の末尾にゾーンの ID と「--x-s3」が付く。ふつうのバケットは汎用バケット
- 例：bucket-base-name--usw2-az1--x-s3

### アクセスの少ないデータ

#### S3 Standard-IA（すたんだーどあいえー / S3 Standard-Infrequent Access）

- 意味：存続期間が長く、アクセスは少ないが、必要なときはミリ秒で読みたいデータのためのストレージクラス
- ポイント：複数の AZ に保存し、AZ の障害に強い。GB 単位の取り出し料金がかかる。最小ストレージ期間は 30 日、請求の最小サイズは 128 KB。30 日より前に消すと 30 日分の料金がかかる
- 例：月に 1 回ほど読むバックアップ
- 語の意味：IA＝infrequent access（低頻度アクセス）

#### S3 One Zone-IA（わんぞーんあいえー / S3 One Zone-Infrequent Access）

- 意味：Standard-IA と同じ用途だが、1 つの AZ だけに保存して安くしたストレージクラス
- ポイント：AZ が地震や洪水などで物理的に失われると、データは回復できない。作り直せるデータ（ほかのリージョンのレプリカなど）に使う。再作成できない大事なデータは Standard-IA
- 例：CRR で別のリージョンに置いたコピーや、元から作り直せるサムネイル画像

#### S3 Glacier Instant Retrieval（ぐれいしゃーいんすたんとりとりーばる / S3 Glacier Instant Retrieval）

- 意味：ほとんどアクセスしないが、読むときはミリ秒で取り出したい長期のデータのためのストレージクラス
- ポイント：四半期に 1 回くらいのアクセス向け。Standard-IA と同じレイテンシーで読め、保存は安いがアクセスの料金は高い。最小ストレージ期間は 90 日。アーカイブではないので、復元は要らない
- 例：予約のときにだけ開く医療記録、古い画像の保管

#### S3 Glacier Flexible Retrieval（ふれきしぶるりとりーばる / S3 Glacier Flexible Retrieval）

- 意味：年に 1〜2 回ほどアクセスし、すぐには要らないアーカイブのためのストレージクラス
- ポイント：アーカイブされ、リアルタイムでは読めない。まず復元してから読む。取り出しは迅速（1〜5 分）・標準（3〜5 時間）・大容量（5〜12 時間、無料）から選ぶ。最小ストレージ期間は 90 日
- 例：監査のときにだけ取り出すログのアーカイブ

#### S3 Glacier Deep Archive（でぃーぷあーかいぶ / S3 Glacier Deep Archive）

- 意味：年に 1 回未満しかアクセスしないデータの長期のアーカイブのための、最も安いストレージクラス
- ポイント：取り出しは標準（12 時間以内）と大容量（48 時間以内）。迅速取り出しはない。最小ストレージ期間は 180 日。法規制で長く残すアーカイブに向く
- 例：法律で 10 年保存が要る取引記録

#### アーカイブの取り出しオプション（とりだしおぷしょん / archive retrieval options）

- 意味：アーカイブされたオブジェクトを復元するときに選ぶ速さ。迅速（Expedited）・標準（Standard）・大容量（Bulk）
- ポイント：迅速は Flexible Retrieval だけで、緊急の少数のオブジェクト向けの有料のプレミアム機能。指定しなければ標準。大容量が最も安い。迅速を確実に使いたいならプロビジョンドキャパシティーを買う。いつでもミリ秒で読みたいなら、そもそも Glacier Instant Retrieval にする
- 例：急ぎの 1 ファイルだけ迅速取り出しで 5 分以内に復元する

## 13-2 データの管理と保護

### まとめ表

| やりたいこと | 機能 |
| :-: | :-: |
| 古くなったら安いクラスへ移す・消す | S3 ライフサイクル |
| 誤って消した・上書きしたものを戻す | バージョニング |
| バージョンの完全な削除に MFA を求める | MFA 削除 |
| 一定期間、だれにも消させない（WORM） | Object Lock（コンプライアンスモード） |
| 別のバケット・リージョンに自動でコピー | レプリケーション（CRR・SRR） |
| 15 分以内のコピーを SLA で | S3 Replication Time Control |
| 既存のオブジェクトをコピー | S3 バッチレプリケーション |

### ライフサイクルとバージョン

#### S3 ライフサイクル（らいふさいくる / S3 Lifecycle）

- 意味：ルールで、オブジェクトを安いストレージクラスに移したり（移行アクション）、期限切れのオブジェクトを削除したり（失効アクション）するしくみ
- ポイント：作成からの日数などで自動で動く。上から下への一方向（ウォーターフォール）の移行だけができる（例：Standard → Standard-IA → Glacier）。既定では 128 KB 未満のオブジェクトは移行されない。最小ストレージ期間より前に移すとその分の料金がかかる
- 例：ログを 30 日で Standard-IA、1 年で Glacier Flexible Retrieval、7 年で削除

#### 不完全なマルチパートアップロードの削除（ふかんぜんな / AbortIncompleteMultipartUpload）

- 意味：完了も停止もされずに残ったマルチパートアップロードのパートを、指定した日数のあとにライフサイクルで消すアクション
- ポイント：アップロードしたパートは、完了か停止をするまで料金がかかり続ける。ライフサイクルのルールで自動で消すのが勧められている
- 例：開始から 7 日たっても完了しないアップロードを削除する

#### S3 バージョニング（ばーじょにんぐ / S3 Versioning）

- 意味：同じバケットの中に、オブジェクトの複数のバージョンを残す機能
- ポイント：削除すると、本当には消さず削除マーカーを入れるので、前のバージョンから戻せる。上書きしても前のバージョンが残る。既定では無効。一度有効にすると、無効には戻せず停止だけができる。各バージョンはオブジェクト全体として料金がかかる
- 例：誤って上書きした設定ファイルを、前のバージョンから戻す

#### MFA 削除（えむえふえーさくじょ / MFA Delete）

- 意味：バージョニングしているバケットで、バージョンの完全な削除と、バージョニングの状態の変更に MFA を求める設定
- ポイント：認証情報が漏れても、MFA デバイスを持たない人は完全に削除できない。有効にできるのはバケット所有者（ルートアカウント）だけ
- 例：重要なバケットで、認証情報の漏えいに備えて MFA 削除を有効にする

### 消させない・コピーする

#### S3 Object Lock（おぶじぇくとろっく / S3 Object Lock）

- 意味：オブジェクトを一定期間または無期限に削除・上書きできないようにする機能。WORM（書き込みは 1 回、読み取りは何度でも）のモデル
- ポイント：バージョニングが有効なバケットでだけ使える。保持期間にはコンプライアンスモードとガバナンスモードがある。コンプライアンスモードでは、ルートユーザーも含めてだれも消せず、モードも変えられない。ガバナンスモードは、s3:BypassGovernanceRetention の許可を持つ人なら上書き・削除できる
- 例：規制で 5 年間変えてはいけない記録を、コンプライアンスモードで保存する
- 語の意味：WORM＝Write Once Read Many

#### リーガルホールド（りーがるほーるど / legal hold）

- 意味：保持期間と同じ保護を、期限なしで与える Object Lock の設定
- ポイント：明示的に外すまで続く。保持期間とは別に付けられる。訴訟などで、終わりの日が決まっていないあいだ消させないときに使う
- 例：訴訟が終わるまで、関係するメールのアーカイブにリーガルホールドを付ける

#### レプリケーション（CRR・SRR）（れぷりけーしょん / S3 Replication）

- 意味：バケットのあいだでオブジェクトを自動で非同期にコピーする機能。別のリージョンへはクロスリージョンレプリケーション（CRR）、同じリージョンへは同一リージョンレプリケーション（SRR）
- ポイント：レプリケート元とレプリケート先の両方でバージョニングが必要。設定したあとに書かれたオブジェクトがコピーされる（ライブレプリケーション）。既存のオブジェクトは S3 バッチレプリケーションでコピーする。別のアカウントのバケットや、別のストレージクラスへも送れる。CRR はコンプライアンス・レイテンシーの短縮・別のリージョンへのフェイルオーバー、SRR はログの集約や本番とテストのアカウントの同期に使う
- 例：東京のバケットを大阪のバケットへ CRR で複製する
- 語の意味：CRR＝Cross-Region Replication、SRR＝Same-Region Replication

#### S3 Replication Time Control（りぷりけーしょんたいむこんとろーる / S3 RTC）

- 意味：新しいオブジェクトの 99.99% を 15 分以内にレプリケートする、SLA の付いたレプリケーションのオプション
- ポイント：「予測できる時間でコピーしたい」「コンプライアンスで時間の保証が要る」なら S3 RTC。バッチレプリケーションには使えない
- 例：規制で、別のリージョンへのコピーの時間の保証が必要な金融データ
- 語の意味：RTC＝Replication Time Control

#### 強い整合性（つよいせいごうせい / strong read-after-write consistency）

- 意味：オブジェクトの PUT と DELETE のあと、すぐに読むと最新の結果が返る S3 の整合性
- ポイント：すべてのリージョンのバケットで効く。オブジェクトのタグやメタデータ（HEAD）の読み取りも強い整合性。書いた直後に別のサーバーが読んでも、古いデータは返らない
- 例：アップロードの直後に別のサーバーが同じオブジェクトを読んでも、新しい内容が返る

## 13-3 性能と使い方

### まとめ表

| 困りごと | 答え |
| :-: | :-: |
| 1 つのプレフィックスで 503（Slow Down） | プレフィックスを分けてリクエストを分散 |
| 大きなファイルのアップロードが遅い・切れる | マルチパートアップロード |
| 大きなファイルの一部だけ速く読みたい | バイト範囲のフェッチ |
| 遠い国からのアップロードが遅い | S3 Transfer Acceleration |
| 同じオブジェクトが何度も読まれる | CloudFront・ElastiCache でキャッシュ |
| アップロードされたら処理を動かす | イベント通知 |
| ログインなしで一時的に渡す | 署名付き URL |

### 速くする

#### プレフィックスとリクエストレート（ぷれふぃっくす / prefix and request rate）

- 意味：S3 は、パーティショニングされたプレフィックスごとに、毎秒 3,500 以上の PUT/COPY/POST/DELETE と 5,500 以上の GET/HEAD を処理できる
- ポイント：プレフィックスの数に制限はないので、プレフィックスを分けると全体の処理量が増える。急に増えると、S3 が自動でスケールするまで一時的に 503（Slow Down）が返る。連番の名前より、ランダムなプレフィックスのほうがパーティションに分散しやすい
- 例：log-2024-01-01.txt ではなく a1b2/log-2024-01-01.txt のようにする

#### マルチパートアップロード（まるちぱーとあっぷろーど / multipart upload）

- 意味：1 つのオブジェクトをパートに分けて、ばらばらの順でアップロードし、最後に 1 つにまとめる方法
- ポイント：並列でスループットが上がり、失敗したパートだけ送り直せる。100 MB 以上のオブジェクトで勧められている。パート番号は 1〜10,000。完了も停止もしないとパートの料金がかかり続けるので、ライフサイクルで掃除する
- 例：10 GB の動画ファイルを 100 MB ずつ並列でアップロードする

#### バイト範囲のフェッチ（ばいとはんいのふぇっち / byte-range fetches）

- 意味：GetObject の Range ヘッダーで、オブジェクトの一部のバイトだけを取り出すこと
- ポイント：同じオブジェクトの別々の範囲を並列で取れば、全体の取得が速くなる。小さい範囲に分けておけば、中断したときに再試行しやすい。マルチパートで上げたものは、同じパートの大きさで取ると速い
- 例：大きなログファイルの先頭の 1 MB だけ読んで形式を確かめる

#### S3 Transfer Acceleration（とらんすふぁーあくせられーしょん / S3 Transfer Acceleration）

- 意味：CloudFront のエッジロケーションを使い、遠いクライアントと S3 のバケットのあいだのファイル転送を速くするバケットの機能
- ポイント：世界中から 1 つのバケットにアップロードする、大陸をまたいで大量に送るときに向く。バケットで有効にし、専用のエンドポイントを使う。バケット名にピリオドは使えない。追加のデータ転送料金がかかることがある
- 例：海外の支店から東京のバケットへ毎日大きなファイルを送る

### 連携と共有

#### S3 イベント通知（いべんとつうち / S3 Event Notifications）

- 意味：オブジェクトの作成・削除・復元・レプリケーション・ライフサイクルなどのイベントが起きたとき、通知を送る機能
- ポイント：送り先は SNS トピック・SQS キュー・Lambda 関数・EventBridge。少なくとも 1 回は届くように作られ、ふつうは数秒で届く。SQS の FIFO キューには直接送れない
- 例：画像がアップロードされたら Lambda でサムネイルを作る

#### 署名付き URL（しょめいつきゆーあーるえる / presigned URL）

- 意味：バケットポリシーを変えずに、オブジェクトへの時間制限付きのアクセス（ダウンロードやアップロード）を与える URL
- ポイント：作った人の権限で動くので、作る人自身がその操作の許可を持っている必要がある。有効期限まで何度でも使える。IAM ユーザーの認証情報で署名バージョン 4 なら最大 7 日間。AWS のアカウントを持たない人にも渡せる
- 例：購入者だけに、1 時間だけダウンロードできるリンクを渡す

#### 静的ウェブサイトホスティング（せいてきうぇぶさいと / static website hosting）

- 意味：S3 のバケットから、HTML・画像・クライアント側のスクリプトなどの静的なウェブサイトを配信する機能
- ポイント：各ページの内容は静的なコンテンツで、クライアント側のスクリプトは含められる。AWS は CloudFront を使う Amplify ホスティングでの配信を勧めている。SSE-KMS で暗号化したバケットは匿名のユーザーに配信できない
- 例：会社の案内サイトの HTML を S3 に置いて公開する

#### S3 バッチオペレーション（ばっちおぺれーしょん / S3 Batch Operations）

- 意味：マニフェストに並べた大量のオブジェクトに、1 種類の操作（コピー・タグ付け・復元・暗号化の更新など）を一括で行う機能
- ポイント：1 つのジョブで、数十億のオブジェクトを扱える。S3 インベントリのレポートをマニフェストにできる。既存のオブジェクトのレプリケーション（バッチレプリケーション）もこれで行う
- 例：10 億個のオブジェクトに、一括で新しいタグを付ける

#### S3 アクセスポイント（あくせすぽいんと / S3 Access Points）

- 意味：共有のデータセットへのアクセスを簡単にするための、名前付きのネットワークエンドポイント。それぞれに個別のアクセス許可とネットワークの制御を持つ
- ポイント：アプリやチームごとにアクセスポイントを作れば、1 つの大きなバケットポリシーを管理しなくてよい。VPC からだけ使えるように限れる。オブジェクトの操作にだけ使える
- 例：分析チーム用と経理用で、別々のアクセスポイントとポリシーを作る

#### マルチリージョンアクセスポイント（まるちりーじょんあくせすぽいんと / Multi-Region Access Points）

- 意味：複数のリージョンの S3 バケットへの、1 つのグローバルエンドポイント
- ポイント：リクエストは AWS Global Accelerator で AWS のグローバルネットワークを通り、最も近いバケットに自動で送られる。バケット間のデータは CRR で同期する。障害のときはフェイルオーバーコントロールで、数分以内にトラフィックを別のリージョンに移せる
- 例：東京とバージニアのバケットを 1 つのエンドポイントで使い、近いほうから読む
