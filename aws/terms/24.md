## 24-1 S3 のコスト

### まとめ表

| ストレージクラス | 最小ストレージ期間 | 請求の最小サイズ | 取り出し料金 |
| :-: | :-: | :-: | :-: |
| S3 Standard | なし | なし | なし |
| S3 Intelligent-Tiering | なし | なし | なし（モニタリングとオートメーションの料金） |
| S3 Standard-IA・One Zone-IA | 30 日 | 128 KB | GB 単位 |
| S3 Glacier Instant Retrieval | 90 日 | 128 KB | GB 単位 |
| S3 Glacier Flexible Retrieval | 90 日 | — | GB 単位 |
| S3 Glacier Deep Archive | 180 日 | — | GB 単位 |

数字や条件は AWS「Amazon S3 ストレージクラスの理解と管理」による

### 料金の決まり方

#### 最小ストレージ期間（さいしょうすとれーじきかん / Minimum storage duration）

- 意味：一部のストレージクラスで、オブジェクトを置いたとみなして請求される最短の期間
- ポイント：Standard-IA と One Zone-IA は 30 日、Glacier Instant Retrieval と Glacier Flexible Retrieval は 90 日、Glacier Deep Archive は 180 日。期間より前に削除・上書き・別のクラスへの移行をすると、残りの日数分の料金がかかる。すぐ消すデータを安いクラスに入れると、かえって高くなる
- 例：Standard-IA に入れたファイルを 10 日で消すと、30 日分の料金がかかる

#### 請求可能な最小オブジェクトサイズ（さいしょうおぶじぇくとさいず / Minimum billable object size）

- 意味：小さいオブジェクトでも、決まったサイズとして請求される下限。Standard-IA・One Zone-IA・Glacier Instant Retrieval では 128 KB
- ポイント：128 KB より小さいオブジェクトは 128 KB 分の料金になる。小さいファイルが多いと、IA に移しても安くならないことがある。Intelligent-Tiering では 128 KB 未満のオブジェクトは見張られず、自動の階層化の対象にならない
- 例：10 KB のログ 100 万個を Standard-IA に入れると、128 KB × 100 万個分の料金になる

#### 取り出し料金（とりだしりょうきん / Retrieval fee）

- 意味：IA や Glacier のクラスから、データを読み出すときに GB 単位でかかる料金
- ポイント：保存の単価が安い代わりに、読むたびに料金がかかる。だから「めったに読まない」データ向き。Intelligent-Tiering には取り出し料金がない
- 例：月に何度も読むデータを Standard-IA に置くと、取り出し料金で Standard より高くなる

#### S3 Intelligent-Tiering の料金（いんてりじぇんとてぃありんぐ / S3 Intelligent-Tiering）

- 意味：アクセスのパターンを見張り、あまり使われないオブジェクトを安い階層へ自動で動かすストレージクラスの料金のしくみ
- ポイント：オブジェクトごとに少額のモニタリングとオートメーションの月額料金がかかる。取り出し料金はなく、最小ストレージ期間もない。30 日アクセスがないと低頻度アクセス階層、90 日でアーカイブインスタントアクセス階層へ移る。アクセスのパターンが読めない・変わるデータに向く
- 例：どのファイルがいつ読まれるか読めないデータレイクを、Intelligent-Tiering に置く

### コストを下げる設定

#### ライフサイクルの移行と小さいオブジェクト（らいふさいくる / Lifecycle transitions, objects smaller than 128 KB）

- 意味：ライフサイクルのルールでオブジェクトを安いクラスへ移すときの、コストの注意点
- ポイント：移行リクエストはオブジェクトごとに課金される。そのため 2024 年 9 月から、128 KB 未満のオブジェクトはデフォルトではどのクラスにも移行されない。移したいときはオブジェクトサイズのフィルターを付ける。Glacier Flexible Retrieval・Deep Archive に移すと、オブジェクトごとに合計 40 KB のオーバーヘッドの分も払う
- 例：大きな動画だけを、サイズのフィルターで 90 日後に Glacier へ移す

#### 不完全なマルチパートアップロードの中止（ふかんぜんな / AbortIncompleteMultipartUpload）

- 意味：途中で止まったマルチパートアップロードの部品を、ライフサイクルのルールで自動で消す設定
- ポイント：終わっていないアップロードの部品にもストレージの料金がかかる。ストレージのコストを減らすためのベストプラクティスとして勧められている。部品を消しても早期削除の料金はかからない
- 例：開始から 7 日たっても終わらないマルチパートアップロードを中止するルールを付ける

#### リクエスタ支払い（りくえすたしはらい / Requester Pays）

- 意味：リクエストとバケットからのデータのダウンロードの料金を、バケットの所有者ではなく、リクエストした人が払う設定
- ポイント：ふつうはストレージとデータ転送の料金をすべてバケットの所有者が払う。リクエスタ支払いでも、保存の料金は所有者が払う。有効にすると匿名のアクセスはできなくなる。大きなデータセットを共有するが、ダウンロードの費用は負担したくないときに使う
- 例：研究用の地理空間データを公開し、ダウンロードする側に転送料金を払ってもらう

#### S3 Storage Lens（すとれーじれんず / Amazon S3 Storage Lens）

- 意味：組織・アカウント・バケットなどの S3 の使い方のメトリクスを集め、コストの最適化やデータ保護の推奨を示す機能
- ポイント：コストを最適化する機会を見つけるのに使う。毎日のメトリクスのレポートを CSV や Parquet で S3 に出すこともできる
- 例：組織の全アカウントの S3 の使い方をまとめて見て、コストを減らせるバケットを探す

#### アーカイブの取り出しオプション（とりだしおぷしょん / Expedited, Standard, Bulk retrieval）

- 意味：Glacier Flexible Retrieval・Deep Archive などに置いたオブジェクトを復元するときの、速さと料金の選び方。高速・標準・大容量の 3 つ
- ポイント：大容量取り出しが最も安く、大量のデータを安く取り出せる。標準は数時間（Flexible Retrieval はふつう 3〜5 時間、Deep Archive は 12 時間以内）で、何も指定しないときのデフォルト。高速はすばやく取り出せ、プロビジョンドキャパシティで容量を保証できる
- 例：急がない監査用のデータ 5 TB を、大容量取り出しで安く戻す

## 24-2 ブロック・ファイル・バックアップのコスト

### まとめ表

| 手段 | 何を安くするか | 決め手 |
| :-: | :-: | :-: |
| gp2 → gp3 | EBS ボリューム | GiB 単価が 20% 低く、3,000 IOPS・125 MiB/秒が料金に含まれる |
| EBS Snapshots Archive | めったに使わないスナップショット | 90 日以上置くなら最大 75% 減 |
| Data Lifecycle Manager | 古いスナップショット・AMI | 作成・保持・削除を自動化、追加料金なし |
| EFS ライフサイクル管理 | あまり読まないファイル | IA（四半期に数回）・アーカイブ（年に数回）へ移す |

数字や条件は AWS「Amazon EBS 汎用 SSD ボリューム」「Amazon EBS スナップショットのアーカイブ」による

### EBS

#### gp3 ボリューム（じーぴーすりー / General Purpose SSD gp3）

- 意味：最新世代の汎用 SSD で、EBS で最も低コストの SSD ボリューム
- ポイント：GiB あたりの料金が gp2 より 20% 低い。3,000 IOPS と 125 MiB/秒のベースラインが料金に含まれ、バーストは使わない。gp2 は 1 TiB 未満なら 3,000 IOPS までバーストする方式。性能が足りるなら gp2 から gp3 に変えるだけで安くなる
- 例：100 GiB の gp2 のボリュームを gp3 に変え、同じ 3,000 IOPS のまま料金を下げる
- 語の意味：gp＝General Purpose（汎用）

#### EBS Snapshots Archive（すなっぷしょっとあーかいぶ / Amazon EBS Snapshots Archive）

- 意味：めったに使わないスナップショットを、低コストで長く置くためのストレージ階層
- ポイント：90 日以上置く予定で、ほとんど使わないスナップショットなら、スナップショットのストレージのコストを最大 75% 減らせる。アーカイブすると増分のスナップショットがフルのスナップショットに変わる。使うときは標準の階層に復元してから使う
- 例：プロジェクトの終了時に取ったスナップショットを、アーカイブ階層に移す

#### Amazon Data Lifecycle Manager（でーたらいふさいくるまねーじゃー / Amazon Data Lifecycle Manager）

- 意味：EBS のスナップショットと EBS-backed AMI の作成・保持・削除を自動化するサービス
- ポイント：古いバックアップを削除してストレージのコストを減らせる。EventBridge や CloudTrail と組み合わせ、追加料金なしでバックアップの仕組みを作れる。ほかのリージョンやアカウントへのバックアップのポリシーも作れる
- 例：毎日スナップショットを取り、7 世代より古いものを自動で消す

### EFS

#### EFS のライフサイクル管理（らいふさいくるかんり / EFS lifecycle management）

- 意味：ライフサイクルポリシーに従って、ファイルを標準・低頻度アクセス（IA）・アーカイブのストレージクラスの間で自動で動かす機能
- ポイント：IA は四半期に数回、アーカイブは年に数回しか読まないデータ向けにコストが最適化されている。「標準への移行」を設定すると、読まれたファイルを標準に戻せる。ポリシーはファイルシステム全体に効く
- 例：30 日読まれなかったファイルを IA へ、90 日でアーカイブへ移す

## 24-3 データ転送とネットワークのコスト

### まとめ表

| データの流れ | 料金 |
| :-: | :-: |
| インターネット → AWS | かからない |
| AWS → インターネット | かかる |
| 同じリージョンの AZ 間 | かかる（リソースによっては送る側と受ける側の両方） |
| リージョン間 | 転送元のリージョンから出る分にかかる（転送先に入る分はかからない） |
| NAT ゲートウェイ | 使える時間ごと＋処理したデータの GB ごと |
| S3・DynamoDB のゲートウェイエンドポイント | 追加料金なし |

数字や条件は AWS「データ転送料金について」「NAT ゲートウェイの料金」による

### データ転送

#### インターネットとのデータ転送（いんたーねっと / Data transfer in from and out to the internet）

- 意味：インターネットと AWS の間のデータ転送の料金
- ポイント：インターネットから AWS への転送（受信）には料金がかからない。AWS からインターネットへの転送（送信）には料金がかかる。送信を減らすには CloudFront などでキャッシュする
- 例：ユーザーのアップロードは無料、ダウンロードの配信には料金がかかる

#### AZ 間のデータ転送（えーぜっとかん / Data transfer between Availability Zones）

- 意味：同じリージョンの中の、別の AZ どうしのデータ転送の料金
- ポイント：料金がかかり、リソースによっては受信と送信の両方にかかる。高い可用性のための AZ 間の転送は必要なコストだが、大量のデータを AZ 間で往復させる設計は見直す
- 例：AZ a の EC2 が、AZ b の EC2 と毎日大量のデータをやり取りする

#### リージョン間のデータ転送（りーじょんかん / Data transfer between Regions）

- 意味：別の AWS リージョンの間のデータ転送の料金
- ポイント：転送元のリージョンから出るデータに料金がかかり、転送先に入るデータにはかからない。リージョンの境界をまたぐ転送は、よく考えてから決める
- 例：東京からバージニアへのレプリケーションでは、東京から出る分に料金がかかる

### NAT とエンドポイント

#### NAT ゲートウェイの料金（なっとげーとうぇい / NAT gateway pricing）

- 意味：NAT ゲートウェイが使える時間 1 時間ごとと、処理したデータ 1 GB ごとにかかる料金
- ポイント：減らし方は 2 つ。1 つは、大量のトラフィックを送るリソースを NAT ゲートウェイと同じ AZ に置くか、AZ ごとに NAT ゲートウェイを作る（AZ 間の転送をなくす）。もう 1 つは、トラフィックの多くが AWS のサービス宛てなら、VPC エンドポイントを作って NAT を通さない
- 例：プライベートサブネットから S3 への大量のアクセスが、NAT ゲートウェイの処理料金を押し上げている

#### ゲートウェイエンドポイント（げーとうぇいえんどぽいんと / Gateway endpoints）

- 意味：インターネットゲートウェイや NAT デバイスなしで、VPC から S3 と DynamoDB へつなぐ VPC エンドポイント
- ポイント：追加料金なしで使える。ルートテーブルに経路を足して使う。オンプレミス・ほかのリージョンのピア接続した VPC・Transit Gateway からは使えない
- 例：S3 のゲートウェイエンドポイントを作り、NAT ゲートウェイの処理料金をなくす

#### インターフェイスエンドポイント（いんたーふぇいすえんどぽいんと / Interface endpoints）

- 意味：VPC の中にプライベート IP のネットワークインターフェイスを作り、AWS のサービスへプライベートにつなぐ VPC エンドポイント
- ポイント：追加料金がかかる。S3 と DynamoDB はゲートウェイとインターフェイスの両方に対応している。オンプレミスやほかのリージョンから S3 にプライベートにつなぐときは、インターフェイスエンドポイントが必要
- 例：Direct Connect で、オンプレミスから S3 のインターフェイスエンドポイントを使う

#### NAT インスタンス（なっといんすたんす / NAT instance）

- 意味：EC2 インスタンスを NAT として使うもの
- ポイント：NAT AMI のもとの Amazon Linux AMI は、2023 年 12 月 31 日にメンテナンスサポートが終わった。AWS は NAT ゲートウェイへの移行を勧めている。NAT ゲートウェイは可用性と帯域幅に優れ、運用の手間が少ない。NAT ゲートウェイにはスケーリングと管理の機能があり、Well-Architected はスタンドアロンの NAT インスタンスと比べてコストを節約できるとしている
- 例：古い NAT インスタンスを、NAT ゲートウェイに置き換える

### 配信・接続・スロットリング

#### CloudFront によるデータ転送の削減（きゃっしゅ / Reducing data transfer with CloudFront）

- 意味：エッジロケーションでデータをキャッシュし、オリジンの負荷とデータ転送を減らすこと
- ポイント：Well-Architected のコスト最適化の柱では、CDN やキャッシュの層を作ることを、データ転送のコストを減らすサービスの例に挙げている。CloudFront の料金は、使用タイプ・地域・選んだ機能で変わる
- 例：EC2 から直接配っていた画像を CloudFront 経由にして、オリジンからの転送を減らす

#### Direct Connect のコスト（だいれくとこねくと / AWS Direct Connect pricing）

- 意味：Direct Connect で払う料金。ポート時間料金と、データ転送出力の料金
- ポイント：ポート時間料金は、容量と接続のタイプ（専用接続かホスト型接続か）で決まる。プライベートとトランジットの仮想インターフェイスのデータ転送出力の料金は、データ転送を担当するアカウントに付く。インターネット経由で大量のデータを送るより、コスト効率がよく確実とされる
- 例：毎月何十 TB もオンプレミスと AWS の間で送るので、Direct Connect に切り替える

#### API Gateway のスロットリング（すろっとりんぐ / API Gateway throttling）

- 意味：API へのリクエストの量を、トークンバケットのアルゴリズムで制限するしくみ
- ポイント：リージョン・アカウント・API とステージ・メソッド・クライアント（使用量プランと API キー）の単位で制限できる。制限を超えたクライアントは 429 Too Many Requests を受け取る。使用量プランではクライアントごとのレートとクォータを決められる。アカウントの制限は申請で引き上げられる
- 例：無料プランの顧客の API キーに、1 秒 10 リクエスト・1 日 1,000 リクエストの使用量プランを付ける

### 24-1 S3 のコスト

#### 問 aws-24-o01

- 問：数 PB のデータレイクがあり、どのオブジェクトがいつ読まれるかまったく読めない。読み出しのたびにかかる料金も避けたい。最も適したストレージクラスはどれか。
- ア：S3 Standard-IA
- イ：S3 Glacier Instant Retrieval
- ウ：S3 Intelligent-Tiering
- エ：S3 One Zone-IA
- 正解：ウ
- 解説：Intelligent-Tiering は、アクセスのパターンを見張り、あまり使われないオブジェクトを安い階層へ自動で動かす。少額のモニタリングとオートメーションの料金がかかるが、取り出し料金はない。アクセスのパターンが読めないデータに向く。
- アの意味：GB 単位の取り出し料金がかかり、よく読まれるオブジェクトがあると高くなる。
- イの意味：四半期に一度くらいしか読まないデータ向けで、取り出し料金がかかる。
- ウの意味：正しい。
- エの意味：1 つの AZ にしか置かず、取り出し料金もかかる。
