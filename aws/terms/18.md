## 18-1 Site-to-Site VPN と Client VPN

### まとめ表

| 項目 | Site-to-Site VPN | Direct Connect | Client VPN |
| :-: | :-: | :-: | :-: |
| つなぐもの | 拠点のネットワークと VPC | 拠点のネットワークと AWS | 個人の端末と VPC |
| 経路 | インターネット上の IPsec トンネル | 専用の光ファイバー回線 | インターネット上の TLS（OpenVPN） |
| 暗号化 | IPsec で暗号化 | 既定では暗号化しない | TLS で暗号化 |
| 帯域 | トンネルあたり 1.25 Gbps（広帯域幅で 5 Gbps） | 専用接続 1〜400 Gbps | 利用者の数に合わせて伸縮 |
| 用意するもの | 今あるインターネット回線と VPN 機器 | ロケーションまでの回線 | 端末の VPN クライアント |

数字は AWS「AWS Site-to-Site VPN 接続用のトンネルオプション」「専用 Direct Connect 接続」による

### VPN の部品

#### AWS Site-to-Site VPN（さいとつーさいとぶいぴーえぬ / AWS Site-to-Site VPN）

- 意味：オンプレミスのネットワークと VPC の間を、インターネット上の IPsec の暗号化トンネルでつなぐサービス
- ポイント：1 つの VPN 接続には、高可用性のために 2 つのトンネルがあり、それぞれ別の AZ で終わる。AWS 側はターゲットゲートウェイ（仮想プライベートゲートウェイか Transit Gateway）、オンプレミス側はカスタマーゲートウェイ。インターネットを使うので、すぐ作れて安いが、帯域や遅延は回線しだい
- 例：本社のファイアウォールと VPC を VPN でつなぐ
- 語の意味：VPN＝Virtual Private Network（仮想の専用網）、IPsec＝IP Security

#### VPN トンネル（ぶいぴーえぬとんねる / VPN tunnel）

- 意味：お客様のネットワークと AWS の間でデータを送受信する、暗号化されたリンク
- ポイント：各トンネルは固有のパブリック IP を使う。冗長性のため、2 つのトンネルの両方をカスタマーゲートウェイデバイスに設定することが重要。帯域はスタンダードでトンネルあたり最大 1.25 Gbps、広帯域幅トンネルで最大 5 Gbps（Transit Gateway か Cloud WAN にアタッチした VPN だけ）
- 例：トンネル 1 の保守中も、トンネル 2 で通信を続ける

#### 仮想プライベートゲートウェイ（かそうぷらいべーとげーとうぇい / Virtual private gateway, VGW）

- 意味：1 つの VPC にアタッチする、Site-to-Site VPN の AWS 側の VPN エンドポイント
- ポイント：1 つの VPC 専用。Site-to-Site VPN の IPv6 や高速 VPN 接続には対応しない（それらは Transit Gateway を使う）。Direct Connect のプライベート仮想インターフェイスの接続先にもなる。同じ送信先のルートなら、Direct Connect から伝わったルートを VPN のルートより優先する
- 例：VPC に VGW をアタッチし、本社への VPN 接続を作る

#### カスタマーゲートウェイ（かすたまーげーとうぇい / Customer gateway）

- 意味：オンプレミス側の VPN 機器（カスタマーゲートウェイデバイス）の情報を AWS に登録したリソース
- ポイント：デバイスは物理的な機器でもソフトウェアでもよい。VPN 接続を作るときに、デバイスの設定ファイルをダウンロードできる。デバイスそのものが壊れたときに備えるには、2 台目のデバイスと 2 つ目の VPN 接続を用意する
- 例：本社ルーターのパブリック IP と BGP の ASN を登録する

#### 静的ルーティングと動的ルーティング（せいてき・どうてきるーてぃんぐ / Static routing, Dynamic routing）

- 意味：VPN 接続で、オンプレミスのアドレスを手で書くのが静的、BGP で自動に交換するのが動的
- ポイント：VPN 接続を作るときにどちらかを選ぶ。どちらも、サブネットのルートテーブルを更新する（ルート伝達を有効にすると自動で入る）。複数の VPN 接続を使う冗長構成や VPN CloudHub では BGP（動的）を使う。BGP 同士では AS PATH の短いほうが優先される
- 語の意味：BGP＝Border Gateway Protocol（組織のネットワークの間で経路を交換するプロトコル）

#### ルート伝達（るーとでんたつ / Route propagation）

- 意味：VPN や Direct Connect のルートを、VPC のルートテーブルに自動で入れる設定
- ポイント：VPN 接続が UP のとき、静的なら設定したプレフィックスが、動的なら BGP で受けたルートが伝わる。VPC のローカルルートと重なるときは、伝わったルートがより具体的でもローカルルートが優先される
- 例：プライベートサブネットのルートテーブルで、VGW からのルート伝達を有効にする

### VPN の使い方

#### 冗長な VPN 接続（じょうちょうなぶいぴーえぬせつぞく / Redundant VPN connections）

- 意味：2 台目のカスタマーゲートウェイデバイスを足し、同じ仮想プライベートゲートウェイへ 2 つ目の VPN 接続を作る構成
- ポイント：1 つの VPN 接続の 2 つのトンネルは、AWS 側の冗長化。オンプレミスの機器の故障や保守に備えるのがこの構成。両方のデバイスが同じ IP 範囲を BGP で広告し、片方が止まると、もう片方に自動で切り替わる
- 例：本社のルーターを 2 台にし、それぞれから VPN 接続を作る

#### 高速 Site-to-Site VPN 接続（こうそくぶいぴーえぬ / Accelerated Site-to-Site VPN）

- 意味：AWS Global Accelerator を使い、オンプレミスから最も近い AWS のエッジロケーションに通信を入れて、AWS のネットワークで運ぶ VPN 接続
- ポイント：インターネットの経路で起きる中断を避け、性能を安定させる。Transit Gateway にアタッチした VPN 接続だけで使え、仮想プライベートゲートウェイでは使えない。既存の VPN 接続では有効にできず、作り直す
- 例：遠い海外の支店からの VPN が不安定なので、高速 VPN に作り直す

#### VPN CloudHub（ぶいぴーえぬくらうどはぶ / AWS VPN CloudHub）

- 意味：1 つの仮想プライベートゲートウェイに複数の拠点の VPN 接続を集め、拠点どうしも通信できるようにするハブアンドスポークのしくみ
- ポイント：各拠点は一意の BGP の ASN を使い、動的ルーティングの VPN 接続を作る。拠点の間で IP 範囲が重なってはいけない。既存のインターネット回線で、拠点の間の主回線や予備回線をコストを抑えて作れる
- 例：東京・大阪・福岡の支店を、AWS の VGW を中心にお互いにつなぐ

#### AWS Client VPN（くらいあんとぶいぴーえぬ / AWS Client VPN）

- 意味：個人の端末から、OpenVPN ベースのクライアントで AWS とオンプレミスのリソースに安全にアクセスする、マネージドのリモートアクセス VPN
- ポイント：TLS で暗号化する。利用者の数に合わせて自動でスケールする。Active Directory・フェデレーション・証明書で認証できる。拠点と拠点をつなぐ Site-to-Site VPN とは別もの
- 例：在宅勤務の社員が、ノートパソコンからプライベートサブネットのサーバーに入る

#### 分割トンネル（ぶんかつとんねる / Split-tunnel）

- 意味：Client VPN で、エンドポイントのルートに合う通信だけを VPN に通し、ほかはそのまま端末のネットワークに流す設定
- ポイント：既定では、端末からのすべての通信が VPN トンネルを通る（フルトンネル）。分割トンネルにすると、AWS 宛ての通信だけがトンネルを通り、AWS からの送信データが減ってデータ転送のコストが下がる
- 例：VPC（172.31.0.0/16）宛てだけを VPN に通し、Web 会議は自宅の回線から直接出す

## 18-2 Direct Connect

### まとめ表

| 仮想インターフェイス | つながる先 | 使うアドレス | 接続先のゲートウェイ |
| :-: | :-: | :-: | :-: |
| プライベート VIF | VPC | プライベート IP | 仮想プライベートゲートウェイか Direct Connect ゲートウェイ |
| パブリック VIF | S3 などのパブリックなサービス | パブリック IP | なし（AWS のパブリックな範囲） |
| トランジット VIF | Transit Gateway | プライベート IP | Direct Connect ゲートウェイ（Transit Gateway に関連付け） |

数字や条件は AWS「Direct Connect 仮想インターフェイスとホスト仮想インターフェイス」による

### 接続

#### AWS Direct Connect（だいれくとこねくと / AWS Direct Connect）

- 意味：社内のネットワークを、標準のイーサネット光ファイバーケーブルで Direct Connect ロケーションにつなぐ専用線のサービス
- ポイント：インターネットのプロバイダーを通らず、仮想インターフェイスで VPC やパブリックなサービスに直接つながる。帯域と遅延が安定し、大量のデータを送るのに向く。ロケーションまでの物理的な回線を、自分かパートナーが用意する。既定では通信を暗号化しない
- 例：データセンターと AWS の間で、毎日数 TB のデータを安定して送る

#### 専用接続とホスト接続（せんようせつぞく・ほすとせつぞく / Dedicated connection, Hosted connection）

- 意味：AWS から 1 本の物理ポートを借りるのが専用接続、Direct Connect パートナーが用意した回線を借りるのがホスト接続
- ポイント：専用接続の速度は 1・10・100・400 Gbps。ホスト接続は 50 Mbps から 25 Gbps まで細かく選べる（パートナーが作り、利用者が受け入れる）。1 Gbps 未満の小さな接続ならホスト接続
- 例：月に少しだけ使う支社は、200 Mbps のホスト接続にする

#### LAG（らぐ / Link aggregation group）

- 意味：LACP で、1 つの Direct Connect エンドポイントにある複数の接続を束ね、1 つのマネージド接続として扱う論理インターフェイス
- ポイント：帯域を増やすために使う。すべて専用接続で、同じ速度にそろえる。100 Gbps 未満の接続なら 4 つまで、100・400 Gbps なら 2 つまで束ねられる。同じ AWS の機器で終わる接続どうしを束ねるので、ロケーションの障害には別の対策が要る
- 語の意味：Link＝回線、Aggregation＝集約、Group＝グループ。LACP＝Link Aggregation Control Protocol

### 仮想インターフェイス

#### プライベート仮想インターフェイス（ぷらいべーとぶいあいえふ / Private virtual interface）

- 意味：プライベート IP で VPC にアクセスするための仮想インターフェイス
- ポイント：仮想プライベートゲートウェイか、Direct Connect ゲートウェイにつなぐ。S3 などのパブリックなサービスには使わない
- 例：社内からプライベートサブネットの RDS に、専用線でつなぐ

#### パブリック仮想インターフェイス（ぱぶりっくぶいあいえふ / Public virtual interface）

- 意味：パブリック IP で、S3 などの AWS のパブリックなサービスにアクセスするための仮想インターフェイス
- ポイント：インターネットを通らずに、AWS のパブリックな IP の範囲に届く。VPC のプライベートなリソースには届かない。この上で Site-to-Site VPN を張ると、暗号化した専用線になる
- 例：社内のバックアップを、専用線で S3 のパブリックなエンドポイントに送る

#### トランジット仮想インターフェイス（とらんじっとぶいあいえふ / Transit virtual interface）

- 意味：Direct Connect ゲートウェイに関連付けた Transit Gateway にアクセスするための仮想インターフェイス
- ポイント：Transit Gateway の先にある多くの VPC に、1 つの仮想インターフェイスで届く。任意の速度の専用接続かホスト接続で使える
- 例：専用線 1 本で、Transit Gateway につないだ 30 個の VPC に届く

#### Direct Connect ゲートウェイ（だいれくとこねくとげーとうぇい / Direct Connect gateway）

- 意味：仮想インターフェイスと、仮想プライベートゲートウェイや Transit Gateway の間に置く、グローバルに使えるリソース
- ポイント：世界のリージョンの VPC に、1 つの Direct Connect 接続から届く（中国リージョンは除く）。同じ Direct Connect ゲートウェイにつながったゲートウェイどうし（VPC どうし）は、ここを通って通信できない
- 例：東京の Direct Connect ロケーションの接続から、東京とバージニアの VPC に届く

### 回復性と暗号化

#### 最大回復性モデル（さいだいかいふくせい / Maximum resiliency）

- 意味：複数のロケーションの、別々の機器で終わる別々の接続を使う Direct Connect の構成。99.99% の SLA を目指せる
- ポイント：機器・接続・ロケーション全体の障害に耐える。高い回復性モデルは、複数のロケーションへの 2 つの単一の接続で 99.9%。開発とテストのモデルは、1 つのロケーションの別々の機器で、重要でないワークロード向け
- 例：重要な基幹システムは、2 つのロケーションに 2 本ずつ、合計 4 本の専用接続を引く

#### Direct Connect と VPN の組み合わせ（くみあわせ / AWS Direct Connect + Site-to-Site VPN）

- 意味：Direct Connect の専用接続の上に Site-to-Site VPN を張り、IPsec で暗号化したプライベートな接続にする構成
- ポイント：Direct Connect は既定で暗号化しないので、VPC までの通信を IPsec で暗号化したいときに使う。別の使い方として、Direct Connect を主回線にし、インターネットの Site-to-Site VPN を予備回線にもできる。同じ送信先なら、仮想プライベートゲートウェイは Direct Connect のルートを優先する
- 例：普段は専用線、専用線の障害のときだけ VPN で通信する

#### MACsec（まっくせっく / MAC Security）

- 意味：自社のルーターと Direct Connect ロケーションの間の接続を、レイヤー 2 で暗号化する IEEE の標準
- ポイント：データの機密性・整合性・送信元の信頼性を守る。イーサネットのリンク 1 区間のポイントツーポイントの暗号化で、複数の区間にまたがるエンドツーエンドの暗号化ではない。IPsec の VPN（レイヤー 3）とは別もの
- 例：10 Gbps の専用接続で、性能を落とさずに回線の区間を暗号化する

## 18-3 Transit Gateway とハイブリッド DNS

### まとめ表

| 項目 | VPC ピアリング（#17） | Transit Gateway |
| :-: | :-: | :-: |
| 形 | 1 対 1 | ハブアンドスポーク |
| 推移的なルーティング | できない | できる（ハブを経由） |
| つなげるもの | VPC どうし | VPC・VPN・Direct Connect ゲートウェイ・ほかの Transit Gateway |
| 経路の分離 | — | 複数のルートテーブルで分ける |
| 料金 | 作るのは無料。AZ やリージョンをまたぐ転送は有料 | アタッチメントごとの時間と、処理したデータ量 |

数字や条件は AWS「Amazon VPC の AWS Transit Gateway とは」「VPC ピア機能とは」による

### Transit Gateway

#### AWS Transit Gateway（とらんじっとげーとうぇい / AWS Transit Gateway）

- 意味：VPC とオンプレミスのネットワークを相互につなぐ、ネットワークの中継ハブ
- ポイント：たくさんの VPC をピアリングの網目でつなぐ代わりに、ハブに集める。VPC・VPN・Direct Connect ゲートウェイ・ほかの Transit Gateway（ピアリング）などをアタッチできる。AWS RAM でほかのアカウントと共有できる。アタッチメントごとの時間と、処理したデータ量で課金される
- 例：50 個の VPC と本社の VPN を、1 つの Transit Gateway につなぐ

#### Transit Gateway のルートテーブル（るーとてーぶる / Transit gateway route table）

- 意味：Transit Gateway の中で、宛先 IP から次の行き先（アタッチメント）を決める表
- ポイント：各アタッチメントは、ちょうど 1 つのルートテーブルに関連付ける（関連付け）。アタッチメントのルートは、1 つ以上のルートテーブルに伝える（伝達）。ルートテーブルを分けると、開発と本番の VPC を分離できる。ブラックホールルートで通信を捨てられる。VPC 側のサブネットのルートテーブルにも、Transit Gateway へのルートを書く
- 例：本番用と開発用のルートテーブルを作り、どちらにも共有サービスの VPC のルートだけを伝える

#### Transit Gateway の VPC アタッチメント（ぶいぴーしーあたっちめんと / VPC attachment）

- 意味：VPC を Transit Gateway につなぐアタッチメント。AZ ごとにサブネットを 1 つ指定する
- ポイント：指定したサブネットから IP アドレスを 1 つ使う。アタッチメントのない AZ の通信も届くが、高可用性のために複数の AZ を有効にすることが勧められる
- 例：AZ-a と AZ-c に、Transit Gateway 用の小さなサブネットを 1 つずつ作る

#### ECMP（いーしーえむぴー / Equal-cost multi-path routing）

- 意味：同じ宛先への同じ条件の経路が複数あるとき、通信を分けて流すルーティング
- ポイント：Transit Gateway は多くのアタッチメントで ECMP に対応する。VPN アタッチメントでは、Transit Gateway の設定で ECMP を有効にする。複数の VPN 接続にまたがって ECMP を使うと、トンネル 1 本の上限を超える帯域を得られる
- 例：広帯域幅トンネルの VPN 接続 2 つ（トンネル 4 本）で ECMP を使い、20 Gbps にする
- 語の意味：Equal-cost＝同じコストの、Multi-path＝複数の経路

#### Transit Gateway ピアリング（とらんじっとげーとうぇいぴありんぐ / Transit gateway peering attachment）

- 意味：同じリージョンや別のリージョンの Transit Gateway どうしをつなぐアタッチメント
- ポイント：相手の Transit Gateway の所有者が承諾する。通信させるには、ピアリングアタッチメントを指す静的ルートを Transit Gateway のルートテーブルに追加する。リージョン間の通信は AES-256 で暗号化される。一意の ASN を使うことが勧められる
- 例：東京とフランクフルトの Transit Gateway をピアリングし、両方の VPC 群をつなぐ

#### 一元的な発信（いちげんてきなはっしん / Centralized outbound routing to the internet）

- 意味：インターネットゲートウェイのない VPC のインターネット向けの通信を、Transit Gateway で、NAT ゲートウェイとインターネットゲートウェイを持つ 1 つの VPC に集める構成
- ポイント：VPC ごとに NAT ゲートウェイを置かずに、出口を 1 か所にまとめて管理する。VPC ピアリングでは相手の NAT デバイスを使えないが、Transit Gateway なら中継できる
- 例：各部署の VPC はインターネットゲートウェイを持たず、共通の出口 VPC から外に出る

### ハイブリッド DNS

#### インバウンド Resolver エンドポイント（いんばうんどりぞるばーえんどぽいんと / Inbound Resolver endpoint）

- 意味：オンプレミスや別の VPC から、VPC の Route 53 VPC Resolver に DNS の問い合わせを入れるための入口
- ポイント：オンプレミスの DNS サーバーが、プライベートホストゾーンや VPC の名前を解決するときに使う。オンプレミスから VPC の「CIDR＋2」のアドレスへの転送はサポートされず不安定になるので、インバウンドエンドポイントを使う
- 例：社内の DNS サーバーで、aws.example.internal の問い合わせをインバウンドエンドポイントの IP に転送する

#### アウトバウンド Resolver エンドポイントと転送ルール（あうとばうんど / Outbound Resolver endpoint, Forwarding rule）

- 意味：VPC から、オンプレミスや別の VPC の DNS サーバーに問い合わせを転送するための出口と、どのドメインをどこに送るかのルール
- ポイント：アウトバウンドエンドポイントと 1 つ以上のルールを作る。送信元の IP は VPC の中のプライベートなアドレス。ルールを VPC に関連付けると、その VPC の EC2 がオンプレミスの名前を解決できる
- 例：「corp.example.com は社内 DNS（10.10.0.53）へ」というルールを作る

### 18-1 Site-to-Site VPN と Client VPN

#### 問 aws-18-o02

### 18-2 Direct Connect

#### 問 aws-18-o27

- 問：ネットワーク担当のアカウントで Transit Gateway を作った。AWS Organizations のほかのアカウントの VPC も、この Transit Gateway にアタッチさせたい。最も適したものはどれか。
- ア：各アカウントに Transit Gateway を作り、すべてをピアリングでつなぐ
- イ：AWS RAM で、Transit Gateway をほかのアカウントと共有する

- エ：ほかのアカウントの IAM ユーザーに、Transit Gateway の管理者権限を付ける
