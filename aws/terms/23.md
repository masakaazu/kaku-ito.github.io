## 23-1 コストを見る・予測する

### まとめ表

| ツール | 何をするか | 選ぶ決め手 |
| :-: | :-: | :-: |
| Cost Explorer | コストと使用状況をグラフで見て、分析・予測する | 過去 13 か月の傾向、今後 18 か月の予測 |
| コストと使用状況レポート（CUR）・Data Exports | 最も細かい請求データを S3 に出す | Athena・Redshift・Quick で自分で分析 |
| 料金見積りツール | 作る前にコストを見積もる | まだ使っていないサービスの月額 |

数字や条件は AWS「AWS Cost Explorer を使用してコストと使用状況を分析する」「AWS コストと使用状況レポートとは」による

### 見る・分析する

#### AWS Cost Explorer（こすとえくすぷろーらー / AWS Cost Explorer）

- 意味：AWS のコストと使用状況を、グラフやレポートで表示して分析するツール
- ポイント：過去 13 か月までのデータを見られ、今後 18 か月の予測もできる。サービス・アカウント・タグなどでグループ化やフィルタができ、時間単位は日別・月別・時間別から選ぶ。画面で見るのは無料で、API はページ分割されたリクエストごとに 0.01 USD かかる。データは CSV でダウンロードできる
- 例：先月から急に増えたコストを、サービス別のグラフで見て EC2 が原因だとわかる

#### Cost Explorer の予測（よそく / Cost Explorer forecast）

- 意味：過去の使用状況をもとに、選んだ将来の期間に AWS をどれだけ使うかを予測する機能
- ポイント：80% の予測間隔で示す（幅のある予測）。予測に足りるデータがないとき（請求サイクルが 1 回未満のアカウントなど）は予測を出さない。予測をもとに予算やアラームを決められる
- 例：今月末の請求額の予測を見て、予算を超えそうかを確かめる

#### 適切なサイズ設定に関する推奨事項（てきせつなさいず / Rightsizing recommendations）

- 意味：Cost Explorer で、EC2 のインスタンスを小さくする・終了するとコストを減らせる機会を見つける機能
- ポイント：いまは Cost Optimization Hub を使うことが勧められている。#22 の Compute Optimizer は、使用率のメトリクスからサイズを推奨する別のサービス
- 例：ほとんど使われていない EC2 に「終了」、CPU が余っている EC2 に「小さいタイプへ」の推奨が出る
- 語の意味：Rightsizing＝ちょうどよいサイズにすること

#### 予約の概要と有効期限切れアラート（よやくのがいよう / Reservations overview, expiration alerts）

- 意味：予約（RI など）の数・削減額・今月切れる予約の数を見る画面と、予約の有効期限が近づくとメールで知らせるアラート
- ポイント：有効期限切れアラートは、切れる 7 日・30 日・60 日前に受け取れる。どの予約を買うとよいかの推奨（予約の推奨事項）も Cost Explorer で見られる
- 例：3 年の RI が切れる 60 日前にメールを受け、買い直すかを決める

### 出す・見積もる

#### AWS コストと使用状況レポート（CUR / AWS Cost and Usage Report）

- 意味：利用できる中で最も包括的なコストと使用状況のデータを、自分の S3 バケットに出すレポート
- ポイント：製品・使用タイプ・オペレーションの組み合わせごとの行を持つ。1 日に最大 3 回更新され、料金が確定するまで少なくとも 1 日に 1 回更新される。Athena・Redshift・Quick と組み合わせて分析できる。最初のレポートが届くまで最大 24 時間かかることがある
- 例：CUR を S3 に出し、Athena の SQL でプロジェクト別の月額を集計する
- 語の意味：CUR＝Cost and Usage Report

#### AWS Data Exports（でーたえくすぽーと / AWS Data Exports）

- 意味：基本的な SQL で列を選んで、請求とコスト管理のデータをエクスポートするしくみ
- ポイント：標準データエクスポートでは、コストと使用状況レポート 2.0（CUR 2.0）・Cost Optimization Hub の推奨事項・FOCUS などのテーブルを選べる。CUR 2.0 は、細かいコストと使用状況のデータを受け取る、新しく推奨される方法
- 例：CUR 2.0 のエクスポートを作り、必要な列だけを S3 に出す

#### AWS 料金見積りツール（りょうきんみつもりつーる / AWS Pricing Calculator）

- 意味：AWS のサービスを使うときのコストを見積もる、無料のウェブの計画ツール
- ポイント：作る前に構成をモデル化する、サービスの料金を調べる、見積りの計算を確かめる、支出を計画する、などに使う。AWS を使ったことがなくても使える。Cost Explorer の予測は「過去の使用」から、料金見積りツールは「これから使う構成」から計算する
- 例：新しいシステムの EC2・RDS・S3 を入れて、月額と前払いの額を見積もる

## 23-2 予算・異常・推奨

### まとめ表

| しくみ | 何を見張るか | 選ぶ決め手 |
| :-: | :-: | :-: |
| AWS Budgets | 自分で決めたしきい値（コスト・使用量・使用率・カバレッジ） | 予算を超えた・超えそうなら通知・アクション |
| コスト異常検出 | 機械学習で見つけた、ふだんと違う支出 | しきい値を決めずに急な増加を知る |
| Cost Optimization Hub | アカウントとリージョンをまたいだ最適化の推奨 | 削減額で優先順位を付ける |
| Trusted Advisor | ベストプラクティスに照らしたチェック | アイドルなリソース・使われていない EIP など |

数字や条件は AWS「AWS Budgets によるコストの管理」「AWS コスト異常検出による異常な支出の検出」による

### 予算

#### AWS Budgets（ばじぇっと / AWS Budgets）

- 意味：AWS のコストと使用状況を追跡し、しきい値を超えたら通知したり、アクションを実行したりするサービス
- ポイント：実際の支出と、予測の支出の両方で通知できる。通知は E メールと Amazon SNS トピックで送れる。予算の情報は 1 日に最大 3 回（ふつうは 8〜12 時間ごと）更新される。月別・四半期・年別のほか、プロジェクトの期間などのカスタムの期間でも作れる
- 例：月 1,000 USD のコスト予算を作り、予測が 80% を超えたらメールで知らせる

#### 予算のタイプ（よさんのたいぷ / Cost budget, Usage budget）

- 意味：何にしきい値を決めるかの種類。コスト予算は支出の額、使用量予算は 1 つ以上のサービスの使用量
- ポイント：ほかに RI と Savings Plans の「使用率」と「カバレッジ」の予算がある。使用量予算は、特定のサービスの制限の中に収めたいときにも使う
- 例：S3 の保存量に使用量予算を作り、上限に近づいたら通知する

#### 使用率とカバレッジの予算（しようりつ・かばれっじ / Utilization budget, Coverage budget）

- 意味：使用率の予算は、買った RI や Savings Plans がどれだけ使われているかを見張る予算。カバレッジの予算は、使用のうち RI や Savings Plans の対象になっている割合を見張る予算
- ポイント：使用率が下がる＝買った割引が余っている（未使用・使用率の低い RI や Savings Plans を見つける）。カバレッジが下がる＝割引の対象外のオンデマンドの使用が増えている。どちらも「下回ったら」通知する
- 例：Savings Plans の使用率が 80% を下回った日に、SNS で通知を受ける

#### 予算アクション（よさんあくしょん / Budget actions）

- 意味：予算がしきい値を超えたとき、Budgets がユーザーに代わって実行する処理
- ポイント：IAM ポリシーや SCP の適用、アカウント内の特定の EC2・RDS インスタンスを対象にした処理ができる。自動で実行するか、手動で承認してから実行するかを選ぶ。管理アカウントからほかのアカウントに SCP は適用できるが、ほかのアカウントの EC2・RDS インスタンスは対象にできない
- 例：開発アカウントのコストが予測の 90% に達したら、EC2 を新しく作れない Deny の IAM ポリシーを自動で付ける

### 異常と推奨

#### AWS コスト異常検出（こすといじょうけんしゅつ / AWS Cost Anomaly Detection）

- 意味：機械学習のモデルで、ふだんと違う支出のパターンを見つけて知らせる機能
- ポイント：時期による増加や自然な増加を考えて、誤ったアラートを減らす。根本原因をサービス・アカウント・リージョン・使用タイプで調べられる。1 日に約 3 回、割引を計算した後の正味のコストで動く。通知は E メールか SNS で、Slack などにもつなげられる。いつでもオプトアウトできる
- 例：誰かが大きな GPU インスタンスを消し忘れ、翌日に異常のアラートが届く

#### Cost Optimization Hub（こすとおぷてぃまいぜーしょんはぶ / Cost Optimization Hub）

- 意味：アカウントとリージョンをまたいで、コスト最適化の推奨事項をまとめ、優先順位を付ける請求とコスト管理の機能
- ポイント：適切なサイズへの変更、アイドル状態のリソースの削除、Savings Plans や RI の購入などの推奨を集める。RI や Savings Plans などの割引を考えて、推定削減額を出す
- 例：組織全体の推奨を削減額の大きい順に並べ、上から対応する

#### AWS Trusted Advisor（とらすてっどあどばいざー / AWS Trusted Advisor）

- 意味：AWS の環境をベストプラクティスに照らして調べ、コスト削減・可用性とパフォーマンス・セキュリティなどの改善を推奨するサービス
- ポイント：コスト最適化のチェックには、使用率の低い EC2 インスタンス・アイドル状態のロードバランサー・関連付けられていない Elastic IP アドレス・利用頻度の低い EBS ボリューム・アイドル状態の NAT ゲートウェイなどがある。チェックを全部使えるのは Business Support+・Enterprise Support などのプラン。基本サポートでは、サービス制限のすべてのチェックと、セキュリティと障害耐性の一部のチェックだけ
- 例：Trusted Advisor で、どこにも付いていない Elastic IP アドレスを見つけて解放する

#### EC2 インスタンスの休止（きゅうし / Hibernate）

- 意味：インスタンスのメモリ（RAM）の内容を EBS のルートボリュームに保存してから止め、再開すると RAM の内容とプロセスを戻すしくみ
- ポイント：休止して止まっている間、インスタンスの料金はかからない。かかるのは EBS ボリュームの保存の料金（RAM の内容の分も含む）。休止を有効にして起動し、前提を満たしたインスタンスだけが休止できる。起動に時間がかかるアプリを「温めた状態」で止めておける
- 例：夜は休止して料金を止め、朝はメモリの中身ごとすぐに再開する

## 23-3 タグと複数アカウント

### まとめ表

| しくみ | 何をするか | 選ぶ決め手 |
| :-: | :-: | :-: |
| コスト配分タグ | タグのキーごとにコストを分けて見る | アクティブ化が必要 |
| タグポリシー | 組織のタグの付け方をそろえる | 大文字小文字などの表記ゆれを防ぐ |
| Cost Categories | ルールでコストを社内の構造に分ける | アカウントなどの条件で部署・チームにまとめる |
| 一括請求 | 組織のアカウントの請求を 1 つにする | ボリューム割引・RI・Savings Plans を共有 |

数字や条件は AWS「コスト配分タグを使用した AWS コストの整理と追跡」「AWS Organizations の請求の統合」による

### タグ

#### コスト配分タグ（こすとはいぶんたぐ / Cost allocation tags）

- 意味：リソースに付けたタグ（キーと値）を使って、コストを分けて整理・追跡するしくみ
- ポイント：AWS 生成タグとユーザー定義タグの 2 種類がある。どちらも、Cost Explorer やコスト配分レポートで使うには、先にアクティブ化が必要。コスト配分レポートには、タグ付きとタグなしの両方のリソースのコストが出る
- 例：CostCenter タグをアクティブ化し、Cost Explorer で部門別のコストを見る

#### ユーザー定義タグ（ゆーざーていぎたぐ / User-defined tags）

- 意味：自分で定義し、作り、リソースに付けるタグ
- ポイント：タグエディタを使うと、まとめて作って管理できる。タグに秘密の情報を入れない。コスト配分タグの管理画面に入れるのは、組織の管理アカウントと、組織に入っていない単一のアカウントだけ。組織を移ったら、タグをアクティブ化し直す
- 例：Project・Environment・Owner のタグを全リソースに付ける

#### AWS 生成タグ（えーだぶりゅーえすせいせいたぐ / AWS-generated tags）

- 意味：AWS が定義して、サポートしているリソースに付けるコスト配分用のタグ。代表は aws:createdBy（リソースを作った人）
- ポイント：使うには、管理アカウントの所有者が Billing and Cost Management のコンソールで有効にする必要がある。aws:createdBy が入るのは一部のリージョンだけ
- 例：誰が作ったリソースのコストかを、タグを付ける手間なしに見る

#### タグのアクティブ化（あくてぃぶか / Activating cost allocation tags）

- 意味：タグキーを、請求情報とコスト管理のコンソールでコスト配分タグとして有効にすること
- ポイント：リソースにタグを付けてから、キーがアクティブ化の画面に出るまで最大 24 時間、アクティブ化されるまでにも最大 24 時間かかることがある。アクティブ化しないと請求レポートに出ない
- 例：タグを付けた翌日に、コスト配分タグの画面でキーを選んで「アクティブ化」を押す

#### タグポリシー（たぐぽりしー / Tag policies）

- 意味：組織のアカウントのリソースに付けるタグを標準化する、Organizations のポリシー
- ポイント：タグキーや値の大文字と小文字の使い方などをそろえ、一貫したタグの方針を保つ。タグキーと値は大文字と小文字を区別するので、CostCenter と costcenter は別のタグになる
- 例：CostCenter の書き方を組織全体で統一する

### 複数アカウント

#### AWS Cost Categories（こすとかてごり / AWS Cost Categories）

- 意味：ルールを作って、コストを社内の構造に合わせたカテゴリにまとめる、コスト配分のサービス
- ポイント：アカウントなどの請求のディメンションを選んでルールを作り、コストを「チーム」「部署」などに分ける。タグのようなキーと値の組で、すべてのコストの明細に付く。Cost Explorer と Budgets では、追加の請求のディメンションとして使える
- 例：アカウント 1〜3 は Team1、4・5 は Team2、ほかは Team3 というルールを作る

#### 一括請求（いっかつせいきゅう / Consolidated billing）

- 意味：AWS Organizations で、複数のアカウントの請求と支払いを 1 つにまとめる機能
- ポイント：管理アカウントが、すべてのメンバーアカウントの料金を払う。請求書が 1 つになり、料金をまとめて追跡できる。全アカウントの使用量が合算され、ボリューム料金割引・RI の割引・Savings Plans が共有される。追加料金はかからない。メンバーアカウントの請求書は情報のためだけ
- 例：10 個のアカウントの S3 の使用量が合算され、安い単価の段階に早く届く

#### RI と Savings Plans の割引共有（わりびききょうゆう / Reserved Instances and Savings Plans discount sharing）

- 意味：組織の中で、RI と Savings Plans の割引をほかのアカウントの使用にも付けるかどうかの設定
- ポイント：管理アカウントが組織の全アカウントについて制御する。組織全体の共有、グループごとの共有、アカウントごとの有効・無効がある
- 例：独立採算の子会社のアカウントだけ、割引の共有を無効にする

### 23-1 コストを見る・予測する

#### 問 aws-23-o01

- 問：過去 6 か月のコストをサービス別にグラフで見て傾向をつかみ、今後 3 か月の支出も予測したい。最も手間が少ないものはどれか。
- ア：AWS Budgets
- イ：AWS コストと使用状況レポート（CUR）
- ウ：AWS Cost Explorer
- エ：AWS 料金見積りツール
- 正解：ウ
- 解説：Cost Explorer は、コストと使用状況をグラフやレポートで表示・分析するツールで、過去 13 か月までのデータを見て、今後 18 か月の予測もできる。
- アの意味：しきい値を決めて追跡・通知するサービスで、過去の傾向をグラフで分析する道具ではない。
- イの意味：最も細かいデータを S3 に出すもので、グラフにするには Athena などで自分で分析する手間がかかる。
- ウの意味：正しい。
- エの意味：これから作る構成のコストを見積もるもので、過去の実績の分析はしない。
- 出典：オリジナル問題（根拠：AWS「AWS Cost Explorer を使用してコストと使用状況を分析する」（『AWS Cost Explorer は、コストと使用状況を表示および分析できるツールです。』『過去 13 か月までのデータを表示したり、今後 18 か月間に費やす可能性のある金額を予測したり、購入するリザーブドインスタンスのレコメンデーションを取得したりできます。』））

#### 問 aws-23-o02
