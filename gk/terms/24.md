## 24-1 プライバシー

### まとめ表

| 段階 | プライバシーの問題 | 対応 |
| :-: | :-: | :-: |
| データ収集 | 本人が知らないうちに顔や行動が撮られる・集められる | 通知・公表、目的の限定、必要な分だけ集める |
| 推論 | 集めたデータから、本人が明かしていないこと（病気・性的指向など）が推測される | 推論の結果の扱いを決める、センシティブな推論をしない |
| 全体 | あとから対策すると漏れる | プライバシー・バイ・デザイン |

### プライバシー

#### プライバシー・バイ・デザイン（ぷらいばしー・ばい・でざいん / Privacy by Design）

- 意味：システムを作り終えてから対策するのではなく、企画・設計の段階からプライバシー保護を組みこんでおく考え方。カナダ・オンタリオ州の情報・プライバシー・コミッショナーだったアン・カブキアンが提唱した
- ポイント：7つの基本原則がある（事後でなく事前に・初期設定でプライバシー保護・設計に組みこむ・ゼロサムでなくポジティブサム・全期間のセキュリティ・可視性と透明性・利用者の尊重）。AI 事業者ガイドラインも求めている

#### カメラ画像利活用ガイドブック（かめらがぞうりかつようがいどぶっく / Camera Image Utilization Guidebook）

- 意味：経済産業省・総務省などが、店舗や街なかのカメラで撮った画像を事業で使うときに、生活者のプライバシーに配慮するための考え方と取り組みをまとめた手引き
- ポイント：撮影していることや利用の目的を事前に知らせる（告知・掲示）、必要以上に長く保存しない、顔の特徴量などを目的外に使わない、問い合わせの窓口を設ける、など。法的な拘束力はない

#### データ収集段階と推論段階（でーたしゅうしゅうだんかいとすいろんだんかい / collection and inference stages）

- 意味：AI のプライバシーの問題を、データを集めるときの問題と、集めたデータから推論するときの問題に分けて考えること
- ポイント：本人が明かしていない属性（妊娠・病気・性的指向など）を購買履歴などから推測できてしまうのは推論段階の問題。収集が適法でも推論で問題が起きうる

## 24-2 公平性

### まとめ表

| 原因 | 中身 | 例 |
| :-: | :-: | :-: |
| データの偏り | 学習データにある過去の差別や偏りを学ぶ | 過去の採用者が男性中心 → 女性を低く評価 |
| サンプリングバイアス | 集めたデータが母集団を代表していない | 明るい肌の顔ばかりで学習 → 暗い肌の顔で精度が低い |
| 代理変数 | センシティブ属性を消しても、関連する別の変数から推測される | 住所（郵便番号）が人種の代わりになる |

### バイアスの原因

#### アルゴリズムバイアス（あるごりずむばいあす / algorithmic bias）

- 意味：コンピュータのシステムが、ある集団を別の集団より有利に扱うなど、くり返し「不公平な」結果を出してしまう傾向
- 例：Amazon の採用 AI が女性に不利な評価をしたため使われなくなった事例。米国の再犯予測ソフト COMPAS が、黒人の被告人の再犯リスクを高く見積もると批判された事例

#### サンプリングバイアス（さんぷりんぐばいあす / sampling bias）

- 意味：データを集める方法のせいで、集めたデータが対象の集団全体を正しく代表していないこと
- ポイント：学習データに少ない集団では、モデルの精度が低くなりやすい。データの量だけでなく、構成の偏りを確かめる

#### データの偏り（でーたのかたより / data bias）

- 意味：学習データそのものに、社会の過去の差別や不均衡が反映されていること
- ポイント：データが正確でも、過去の判断が偏っていれば、AI はその偏りをそのまま学び、くり返す

#### センシティブ属性（せんしてぃぶぞくせい / sensitive attribute）

- 意味：人種・性別・宗教・障害など、それによって人を不利に扱うことが差別にあたる属性
- ポイント：保護属性ともいう。学習データから取り除くだけでは公平にならない（代理変数があるため）

#### 代理変数（だいりへんすう / proxy variable）

- 意味：センシティブ属性と強く関係していて、その代わりになってしまう別の変数
- 例：郵便番号・名前・出身校などから人種や性別が推測できる。センシティブ属性の列を消しても、代理変数を通じてバイアスが残る

### 公平性の定義

#### 公平性の定義（こうへいせいのていぎ / definitions of fairness）

- 意味：「公平」を数式で表すときの基準。集団ごとの合格率をそろえる（デモグラフィック・パリティ）、集団ごとの誤り率をそろえる（均等化オッズ）、予測の当たり方をそろえる（較正）など、いくつもある
- ポイント：複数の定義を同時に満たすことは一般にできない。COMPAS の論争では、批判側は誤り率のちがいを、開発側は予測の正確さを見ていて、どちらも正しかった。どの定義を使うかは用途に合わせて決める

## 24-3 安全性・セキュリティ・悪用

### まとめ表

| 攻撃 | ねらう段階 | 中身 |
| :-: | :-: | :-: |
| 敵対的攻撃（Adversarial Attack） | 推論 | 入力に小さなノイズを加えて誤認識させる |
| データ汚染（データポイズニング） | 学習 | 学習データに細工したデータを混ぜて、誤りや裏口を仕込む |
| モデル汚染 | 学習・配布 | 配布されるモデル自体に細工する |
| モデル窃取 | 推論 | 大量に問い合わせ、出力からモデルを再現する |
| データ窃取 | 推論 | モデルから学習データ（個人情報など）を引き出す |

### 攻撃

#### 敵対的攻撃（てきたいてきこうげき / Adversarial Attack）

- 意味：人には分からないほど小さく、意図的に作ったノイズを入力に加え、モデルに高い確信度で間違った答えを出させる攻撃。そのような入力を敵対的サンプル（Adversarial Examples）という
- 例：停止標識にシールを貼り、自動運転の画像認識に別の標識と誤認識させる

#### データ汚染（でーたおせん / data poisoning）

- 意味：学習データに、出力の誤りを増やすように作ったデータを混ぜる攻撃
- ポイント：学習データからモデルが作られるので、データを汚すとモデルの動きを変えられる。特定の合図（トリガー）で誤動作するバックドアを仕込むこともある

#### モデル窃取（もでるせっしゅ / model extraction）

- 意味：攻撃者がブラックボックスのモデルに何度も問い合わせ、その出力から、モデルのパラメータや機能を再現する攻撃
- ポイント：API で公開しているモデルがねらわれる。問い合わせの回数の制限や、出力の情報を減らすことで防ぐ

#### データ窃取（でーたせっしゅ / data extraction）

- 意味：モデルへの問い合わせを通じて、学習に使われたデータ（個人情報など）を推測したり引き出したりする攻撃
- ポイント：ある人のデータが学習に使われたかを当てるメンバーシップ推論攻撃や、学習データを復元するモデル反転攻撃がある

#### モデル汚染（もでるおせん / model poisoning）

- 意味：配布される学習済みモデルや、連合学習で集めるモデルの更新に細工をして、モデルそのものを悪くする攻撃
- ポイント：公開モデルをそのまま使うときは、配布元を確かめる

#### セキュリティ・バイ・デザイン（せきゅりてぃ・ばい・でざいん / Security by Design）

- 意味：開発の終わりに対策を足すのではなく、設計・アーキテクチャの段階からセキュリティの要件を組みこむ考え方
- ポイント：AI 事業者ガイドラインも、AI の特性に合わせたセキュリティ対策としてこれを求めている

### 悪用

#### ディープフェイク（でぃーぷふぇいく / deepfake）

- 意味：深層学習（ディープラーニング）と偽物（フェイク）を合わせた造語。AI で作った、実在しない、または改変された人物や出来事を描く精巧な合成の画像・動画・音声
- ポイント：政治家の偽の演説、なりすまし詐欺、本人の同意のない性的な画像などに悪用される。対策は、検出技術・電子透かし・来歴の記録（コンテンツの出どころの証明）・リテラシー教育

#### フェイクニュース（ふぇいくにゅーす / fake news）

- 意味：事実と異なる情報を、ニュースのようにメディアや SNS で広めること
- ポイント：生成 AI で、もっともらしい偽情報を誰でも大量に作れるようになった。ファクトチェック、AI 生成物であることの表示などで対処する

## 24-4 透明性・民主主義・環境・労働・その他の価値

### まとめ表

| 論点 | キーワード |
| :-: | :-: |
| 透明性 | 説明可能性・データの来歴・ブラックボックス |
| 民主主義 | フィルターバブル・エコーチェンバー・フェイクニュース |
| 環境保護 | 気候変動・モデル学習の電力消費 |
| 労働政策 | AI との協働・スキルの喪失・労働力不足 |
| その他 | インクルージョン・軍事利用・死者への敬意・人間の自律性 |

### 透明性

#### 説明可能性（せつめいかのうせい / explainability）

- 意味：AI のシステムが、どのようにその判断（決定）をしたのかを答えられること
- ポイント：深層学習のモデルは中の計算が複雑で、なぜその答えになったかが分かりにくい（ブラックボックス）。融資の審査や医療など、人に大きく影響する判断では特に求められる

#### データの来歴（でーたのらいれき / data provenance）

- 意味：データがどこから来て、どう集められ、どう加工されたかという経歴。その記録
- ポイント：学習データの来歴が分かると、権利の問題・偏り・汚染を確かめられる。生成物の来歴（だれが・どの AI で作ったか）を示す技術もある

### 民主主義

#### フィルターバブル（ふぃるたーばぶる / filter bubble）

- 意味：アルゴリズムが利用者の検索やクリックの履歴を学習し、その人が見たい情報ばかりを見せるようになって、ちがう意見や情報が見えなくなる現象
- ポイント：アルゴリズム（推薦）が原因で、利用者は泡の中にいることに気づきにくい

#### エコーチェンバー（えこーちぇんばー / echo chamber）

- 意味：似た意見を持つ人が集まる SNS などの空間でやりとりがくり返され、自分の意見が肯定され続けることで、それが世の中一般でも正しいと信じこんでしまう現象
- ポイント：フィルターバブルは「アルゴリズムが見せる情報が偏る」、エコーチェンバーは「似た人どうしの集まりで意見が増幅される」。どちらも社会の分断や偏った意見の強まりにつながる

### 環境・労働

#### モデル学習の電力消費（もでるがくしゅうのでんりょくしょうひ / energy consumption of training）

- 意味：大きなモデルの学習に大量の計算資源と電力が必要で、費用がかかり、二酸化炭素の排出にもつながること
- ポイント：Strubell らは2019年に、自然言語処理の大きなモデルの学習による費用と環境への負担を見積もった。効率のよいハードウェアやアルゴリズム、再生可能エネルギーの利用などが対策

#### AI との協働（えーあいとのきょうどう / human-AI collaboration）

- 意味：AI が人の仕事をすべて置きかえるのではなく、人と AI がそれぞれ得意なことを分担して働くこと
- ポイント：AI に頼りすぎると人の技能が失われる（スキルの喪失）おそれもある。学び直し（リスキリング）が大事。人手が足りない分野（労働力不足）を AI が補う面もある

### その他の価値

#### インクルージョン（いんくるーじょん / inclusion）

- 意味：障害・年齢・言語・地域などにかかわらず、だれもが AI の恩恵を受けられ、取り残されないようにすること
- ポイント：AI 事業者ガイドラインの基本理念「多様性・包摂性」と関係する。デジタル格差を広げないことが大事

#### 自律型致死兵器システム（じりつがたちしへいきしすてむ / LAWS: Lethal Autonomous Weapons Systems）

- 意味：AI を使い、人間が介在せずに標的を選んで攻撃を判断する兵器
- ポイント：AI の軍事利用の代表的な論点。人の生死の判断を機械に任せてよいのか、責任はだれにあるのかが国際的に議論されている

#### 死者への敬意（ししゃへのけいい / respect for the dead）

- 意味：亡くなった人の声や姿を AI で再現するときに、本人の意思や遺族の気持ち、故人の尊厳を尊重すること
- ポイント：本人が同意できないので、遺族の同意や使い方の節度が問題になる

#### 人間の自律性（にんげんのじりつせい / human autonomy）

- 意味：人が自分で考え、自分で決めることができること
- ポイント：AI の推薦や操作的なデザインで人の選択が気づかないうちに誘導されると、自律性が損なわれる。AI 事業者ガイドラインも、利用者の選択肢が不本意に制限されることへの注意を求めている

## 問題演習

### 24-1

#### 問 gk-24-o01

- 問：システムを作り終えてから対策するのではなく、企画・設計の段階からプライバシー保護を組みこんでおく考え方はどれか。
- ア：セキュリティ・バイ・デザイン
- イ：プライバシー・バイ・デザイン
- ウ：オプトアウト
- エ：匿名加工
- 正解：イ
- 解説：プライバシー・バイ・デザインは、アン・カブキアンが提唱した、設計の段階からプライバシー保護を組みこむ考え方。7つの基本原則があり、その1つめは「事後ではなく事前に、救済ではなく予防を」。
- アの意味：設計の段階からセキュリティを組みこむ考え方。プライバシーではなくセキュリティ。
- イの意味：正しい。
- ウの意味：本人が求めたら第三者への提供などを止める方式（#20）。
- エの意味：個人を特定できないように加工すること（#20）。
- 出典：オリジナル問題（根拠：ウィキペディア英語版「Privacy by design」（『Proactive not reactive; preventive not remedial』））

#### 問 gk-24-o02

- 問：プライバシー・バイ・デザインの7つの基本原則にふくまれるものはどれか。
- ア：初期設定でプライバシーを保護する（Privacy as the default setting）
- イ：問題が起きてから対応する
- ウ：機能とプライバシーはどちらかしか取れない（ゼロサム）
- エ：利用者には何も知らせない
- 正解：ア
- 解説：7つの基本原則には、事後でなく事前に、初期設定でプライバシーを保護、設計に組みこむ、ゼロサムでなくポジティブサム、全期間のセキュリティ、可視性と透明性、利用者の尊重がある。
- アの意味：正しい。
- イの意味：「事後ではなく事前に」に反する。
- ウの意味：原則は「ゼロサムでなくポジティブサム」（両立させる）。
- エの意味：「可視性と透明性」に反する。
- 出典：オリジナル問題（根拠：ウィキペディア英語版「Privacy by design」（『Privacy as the default setting』））

#### 問 gk-24-o03

- 問：購買の履歴から、本人が明かしていない妊娠や病気を AI が推測してしまう問題は、どの段階のプライバシーの問題か。
- ア：データ収集段階
- イ：データの保存段階
- ウ：推論段階
- エ：データの削除段階
- 正解：ウ
- 解説：データを適法に集めていても、集めたデータから本人が明かしていない属性を推測すると、プライバシーの問題になる。これは推論段階の問題で、収集段階の問題と区別する。
- アの意味：本人が知らないうちにデータを集める問題。
- イの意味：保存の期間や安全管理の問題で、推測の問題ではない。
- ウの意味：正しい。
- エの意味：推測の問題ではない。
- 出典：オリジナル問題（根拠：JDLA「G検定の試験出題範囲（シラバス）G2024#6～」（『データ収集段階と推論段階でプライバシー上の問題が区別できることを理解している』））

#### 問 gk-24-o04

- 問：店舗のカメラの画像を AI で分析するとき、カメラ画像利活用ガイドブックの考え方に沿った対応はどれか。
- ア：撮影していることや利用の目的を、店頭の掲示などで事前に知らせる
- イ：撮影していることを知らせずに、顔の特徴量を無期限に保存する
- ウ：集めた画像を、目的を決めずにほかの会社に渡す
- エ：問い合わせの窓口を設けない
- 正解：ア
- 解説：ガイドブックは、生活者に撮影や利用の目的を事前に知らせる、必要以上に保存しない、目的外に使わない、問い合わせに対応するなど、プライバシーへの配慮を求めている。
- アの意味：正しい。
