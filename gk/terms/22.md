## 22-1 AI 開発の進め方と契約の形

### まとめ表

| 段階（探索的段階型） | やること | 向く契約 |
| :-: | :-: | :-: |
| 1 アセスメント | 少しのデータで、AI で解けそうかを調べる | NDA＋準委任 |
| 2 PoC | 試しにモデルを作り、本格的に開発できるかを確かめる | 準委任（導入検証契約） |
| 3 開発 | 本番で使う学習済みモデルを作る | 準委任（または請負） |
| 4 追加学習 | 運用しながら新しいデータで学習し直す | 準委任など（保守契約） |

### 開発の進め方

#### AI・データの利用に関する契約ガイドライン（えーあい・でーたのりようにかんするけいやくがいどらいん / Contract Guidelines on Utilization of AI and Data）

- 意味：経済産業省が2018年に公表した、AI の開発・利用やデータの取引の契約で考えるべきことと、契約のひな形をまとめたガイドライン。AI 編とデータ編がある
- ポイント：法的な拘束力はなく、当事者が契約を考えるときの参考。AI 開発は「やってみないと分からない」ので、段階に分けて進める「探索的段階型」をすすめている

#### 探索的段階型の開発（たんさくてきだんかいがたのかいはつ / exploratory multi-phase development）

- 意味：AI の開発を、アセスメント → PoC → 開発 → 追加学習の段階に分け、段階ごとに契約を結び、続けるかどうかを判断しながら進める方式
- ポイント：最初にすべてを決めて一括で発注するウォーターフォールの請負契約は、結果が前もって分からない AI 開発には合いにくい。段階ごとに区切ると、うまくいかないときに早く引き返せる

#### PoC（概念実証）（ぴーおーしー / proof of concept）

- 意味：本格的な開発の前に、試しにモデルを作り、目的の精度が出そうか・本当に開発できるかを確かめる段階
- ポイント：結果が出るかどうか分からない検証なので、仕事の完成を約束する請負より、作業そのものを頼む準委任が向く

### 契約の形

#### NDA（秘密保持契約）（えぬでぃーえー / non-disclosure agreement）

- 意味：取引などのときに知った営業秘密や個人情報などの秘密を、第三者に開示しないと約束する契約
- ポイント：アセスメントでユーザーがベンダーにデータを渡す前に結ぶ。秘密の範囲・目的外利用の禁止・返却や消去を決める

#### 請負契約（うけおいけいやく / contract for work）

- 意味：請負人がある仕事を完成することを約束し、注文者がその仕事の結果に対して報酬を払う契約
- ポイント：「完成」が義務。できあがったものが契約の内容に合わなければ、請負人は契約不適合責任を負う。何を作るか（仕様）がはっきりしているときに向く

#### 準委任契約（じゅんいにんけいやく / quasi-mandate contract）

- 意味：法律行為ではない事務（作業）の処理をまかせる契約。委任の規定が準用される
- ポイント：仕事の完成ではなく、専門家として「善良な管理者の注意」（善管注意義務）を尽くして作業すること自体が義務。結果が保証できない AI の開発・PoC に向く。成果に対して報酬を払う「成果完成型」の準委任もある

#### 善管注意義務（ぜんかんちゅういぎむ / duty of care of a prudent manager）

- 意味：委任・準委任を受けた人が、その職業や能力からふつう期待される程度の注意を払って、事務を処理する義務
- ポイント：準委任のベンダーは、目的の精度が出なくても、善管注意義務を尽くしていれば責任を負わない

## 22-2 精度と責任

### まとめ表

| 言葉 | 中身 |
| :-: | :-: |
| 精度保証 | 学習済みモデルの精度（正解率など）を約束すること。前もって保証するのは難しい |
| 契約不適合責任 | 引き渡したものが契約の内容に合わないときの責任（請負・売買）。追完・減額・損害賠償・解除 |
| 保守契約 | 運用中のモデルの監視・再学習・不具合の対応などを約束する契約 |

### 精度と責任

#### 精度保証（せいどほしょう / accuracy guarantee）

- 意味：作ったモデルやサービスが、決まった精度（正解率・再現率など）を出すことを約束すること
- ポイント：AI の性能は学習データや本番のデータに左右され、前もって分からないので、ベンダーが精度を保証するのは難しい。保証しないか、テストデータでの目標値として決めて、達しなかったときの扱いを話し合っておく

#### 契約不適合責任（けいやくふてきごうせきにん / liability for non-conformity）

- 意味：引き渡した目的物が、種類・品質・数量などの点で契約の内容に合わないときに、売主や請負人が負う責任。2020年の民法改正で「瑕疵担保責任」から変わった
- ポイント：買主・注文者は、修理などの追完・代金の減額・損害賠償・解除を求められる。不適合を知ってから1年以内に通知する必要がある（請負）

#### 保守契約（ほしゅけいやく / maintenance contract）

- 意味：システムやモデルを納めたあとの、監視・不具合の対応・再学習などの作業を約束する契約
- ポイント：AI は運用中にデータが変わって精度が落ちる（コンセプトドリフト、#18）ので、追加学習の扱いも決めておく

## 22-3 知的財産とデータの扱い

### まとめ表

| 成果物 | 中身 | 決めておくこと |
| :-: | :-: | :-: |
| 生データ | ユーザーが持っている元のデータ | ベンダーが使ってよい目的・範囲 |
| 学習用データセット | 生データを前処理・アノテーションしたもの | 権利の帰属、ほかの開発への流用 |
| 学習済みモデル | 学習で決まったパラメータとプログラム | 権利の帰属、ほかの顧客への流用、再利用モデル（派生モデル）の扱い |
| ノウハウ | 開発で得た知見 | ベンダーが別の案件で使ってよいか |

### 帰属と利用条件

#### 知的財産の帰属と利用条件（ちてきざいさんのきぞくとりようじょうけん / ownership and terms of use of IP）

- 意味：開発でできた学習済みモデルやデータセットなどの権利を、だれのものにするか（帰属）と、それぞれがどう使ってよいか（利用条件）を契約で決めること
- ポイント：ガイドラインは、権利をどちらに帰属させるかだけで争うより、利用条件（目的・期間・範囲・ほかへの流用・対価）をきめ細かく決めることで、双方の利益を調整することをすすめている

#### 学習済みモデル（がくしゅうずみもでる / trained model）

- 意味：学習用データセットで学習させた結果のパラメータ（重み）と、それを使って推論するプログラムの組み合わせ
- ポイント：プログラムの部分は著作物になりうるが、パラメータ（数値の集まり）が著作物かどうかははっきりしない。だから契約で扱いを決めることが大事。秘密として管理すれば営業秘密にもなりうる（#21）

#### 派生モデル（再利用モデル）（はせいもでる / derived model）

- 意味：ある学習済みモデルに追加学習をしたり、蒸留したりして作った新しいモデル
- ポイント：元のモデルの権利者がどこまで関わるかを契約で決めておく

## 22-4 AI サービス提供契約

### まとめ表

| 項目 | SaaS 型の特殊性 |
| :-: | :-: |
| 契約の形 | 多くの利用者に同じサービスを出すので、個別の交渉ではなく利用規約（約款）で決めることが多い |
| 精度保証 | 利用者ごとのデータに合わせて保証するのは難しい。免責や「現状有姿」での提供が多い |
| 保守 | ベンダーがモデルをいつでも更新できる。出力が変わることもある |
| データ利用権 | 利用者が入力したデータを、ベンダーがサービスの改善やほかの学習に使ってよいか |

### SaaS

#### SaaS（さーす / Software as a Service）

- 意味：必要な機能を、必要な分だけサービスとして使えるようにしたソフトウェアや、その提供の形。インターネット経由で使う
- ポイント：利用者は自分のサーバにインストールしなくてよい。AI の場合、画像認識・音声認識・生成 AI などを API や画面で使う

#### 利用規約（りようきやく / terms of service）

- 意味：サービスの提供者が、多くの利用者との契約の条件として前もって決めて示す文書
- ポイント：利用者が同意すると契約の内容になる。生成物の権利、入力データの扱い、禁止事項、責任の制限などを確かめる

#### データ利用権（でーたりようけん / data usage rights）

- 意味：あるデータを、だれが、どの目的・範囲で使ってよいかという、契約で決める利用の権限
- ポイント：データそのものには所有権がないので（データは物ではない）、「だれのものか」より「だれがどう使えるか」を契約で決める。SaaS では、利用者の入力データをベンダーがモデルの改善に使えるかが論点

## 問題演習

### 22-1

#### 問 gk-22-o01

- 問：民法で、当事者の一方がある仕事を完成することを約束し、相手方がその仕事の結果に対して報酬を払う契約はどれか。
- ア：準委任契約
- イ：請負契約
- ウ：売買契約
- エ：雇用契約
- 正解：イ
- 解説：請負は、当事者の一方がある仕事を完成することを約し、相手方がその仕事の結果に対してその報酬を支払うことを約することによって効力を生ずる。完成が義務。
- アの意味：作業（事務の処理）そのものをまかせる契約。完成は義務ではない。
- イの意味：正しい。
- ウの意味：財産を移し、代金を払う契約。
- エの意味：労働に従事し、報酬を受ける契約。
- 出典：オリジナル問題（根拠：民法 第六百三十二条（『請負は、当事者の一方がある仕事を完成することを約し、相手方がその仕事の結果に対してその報酬を支払うことを約することによって、その効力を生ずる。』））

#### 問 gk-22-o02

- 問：法律行為でない事務の処理（作業）をまかせる契約で、委任の規定が準用されるものはどれか。
- ア：請負契約
- イ：NDA
- ウ：準委任契約
- エ：ライセンス契約
- 正解：ウ
- 解説：民法は、委任の規定を法律行為でない事務の委託について準用する。これが準委任。ソフトウェアや AI の開発の作業をまかせる契約に多い。
- アの意味：仕事の完成を約束する契約。
- イの意味：秘密を守る契約。
- ウの意味：正しい。
- エの意味：権利（特許・著作権など）の利用を許す契約。
- 出典：オリジナル問題（根拠：民法 第六百五十六条（『この節の規定は、法律行為でない事務の委託について準用する。』））

#### 問 gk-22-o03

- 問：準委任契約を受けたベンダーが負う義務として正しいものはどれか。
- ア：善良な管理者の注意をもって事務を処理する義務
- イ：仕事を必ず完成させる義務
- ウ：目的の精度を必ず達成する義務
- エ：何の義務も負わない
- 正解：ア
- 解説：受任者は、委任の本旨に従い、善良な管理者の注意をもって委任事務を処理する義務を負う（善管注意義務）。準委任にも準用される。結果の達成そのものは義務ではない。
- アの意味：正しい。
- イの意味：請負の義務。
- ウの意味：精度保証の特約がない限り義務ではない。
- エの意味：善管注意義務を負う。
- 出典：オリジナル問題（根拠：民法 第六百四十四条（『受任者は、委任の本旨に従い、善良な管理者の注意をもって、委任事務を処理する義務を負う。』））

#### 問 gk-22-o08

- 問：請負と委任（準委任）のちがいとして正しいものはどれか。
- ア：請負は仕事の完成を目的とし、委任は信頼して事務の処理をまかせる
- イ：委任は必ず仕事を完成させなければならない
- ウ：請負は報酬が発生しない
- エ：どちらも同じ契約である
- 正解：ア
- 解説：請負は、ある仕事を完成することを目的とし、そのための手段として労務を供給する点で、雇用や委任と異なる。委任は一般に、他人を信頼して事務の処理を委託する契約と考えられている。
- アの意味：正しい。
- イの意味：それは請負。
- ウの意味：仕事の結果に対して報酬を払う。

#### 問 gk-22-o30

- エの意味：正しい。
- 出典：オリジナル問題（根拠：民法 第五百六十二条第一項（『引き渡された目的物が種類、品質又は数量に関して契約の内容に適合しないものであるときは』））
