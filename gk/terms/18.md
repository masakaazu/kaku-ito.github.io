## 18-1 AI プロジェクトの進め方

### まとめ表

| 段階 | やること | 注意点 |
| :-: | :-: | :-: |
| 企画 | 課題を決める。AI が本当に必要か、ステークホルダーのニーズは何か | AI を使うこと自体を目的にしない |
| PoC（概念実証） | 小さく試して、実現できるかを確かめる | PoC をくり返して先に進まない「PoC 貧乏」に注意 |
| 開発 | データを集め、モデルを作る。アジャイルで少しずつ | 精度は事前に保証できない |
| 運用 | 監視・再学習（MLOps） | データの性質が時間とともに変わる（コンセプトドリフト） |

### プロジェクトの考え方

#### AI のビジネス活用（えーあいのびじねすかつよう / AI in business）

- 意味：AI を使って、業務の効率化（コスト削減）や、新しい商品・サービスの価値づくりを行うこと
- ポイント：まず解きたい課題を決め、AI がその手段として合っているかを考える。業務の流れ（プロセス）ごと見直すことも多い

#### BPR（びーぴーあーる / business process re-engineering）

- 意味：企業の活動をプロセス（業務の流れ）として分析・理解し、作り直して利益を最大にする活動
- ポイント：AI を今の業務にそのまま足すのではなく、AI を前提に業務の流れそのものを作り直す
- 語の意味：re-engineering＝作り直し

#### PoC（概念実証）（ぴーおーしー / proof of concept）

- 意味：新しい考えやアイデアが実現できるかを示すために、簡単で不完全な形で試すこと
- ポイント：本格的な開発の前に、少ないデータや費用で、効果が出そうか・技術的にできるかを確かめる。完全に動く試作品の前の段階

#### CRISP-DM（くりすぷでぃーえむ / cross-industry standard process for data mining）

- 意味：データマイニングの専門家がふつう行う進め方を表した、業界を問わない標準のプロセスモデル
- ポイント：ビジネスの理解 → データの理解 → データの準備 → モデリング → 評価 → 展開 の6段階で、行き来しながら進める。もっとも広く使われる分析のモデル

#### CRISP-ML（くりすぷえむえる / CRISP-ML(Q)）

- 意味：CRISP-DM をもとに、機械学習のアプリケーションの開発に合わせたプロセスモデル。範囲の決定から、展開したモデルの保守までの6段階
- ポイント：最初の段階でビジネスとデータの理解をまとめる（データがあるかどうかが実現の可否を左右するため）。最後の段階に監視と保守が入る。Q は品質保証（quality assurance）

### 開発の進め方

#### ウォーターフォール（うぉーたーふぉーる / waterfall model）

- 意味：開発を、要件定義 → 設計 → 実装 → テストのような順番の段階に分け、前の段階の成果物をもとに次の段階に進む開発モデル
- ポイント：滝のように後戻りしない前提。最初に要件をすべて決められるときに向く。結果が前もってわからない AI 開発には合いにくい

#### アジャイル（あじゃいる / agile software development）

- 意味：短い期間（イテレーション）ごとに、計画・実装・リリースをくり返して、早く価値を届け、学び、合わせていく開発の進め方
- ポイント：やってみないと精度がわからない AI 開発と相性がよい。2001年の「アジャイルソフトウェア開発宣言」の価値観にもとづく

### 人と組織

#### ステークホルダーのニーズ（すてーくほるだーのにーず / stakeholder needs）

- 意味：プロジェクトに利害関係を持つ人（利用者・顧客・経営者・現場の担当者・株主など）が求めること
- ポイント：AI で何を解決したいかをはっきりさせ、関係者の期待（精度・費用・説明のしやすさなど）をすり合わせる

#### データサイエンティスト（でーたさいえんてぃすと / data scientist）

- 意味：統計学・情報科学・アルゴリズムなどを使い、データから新しい役に立つ知見を引き出す、データサイエンスの研究者や実践者
- ポイント：ビジネスの理解・データエンジニアリング・統計とモデリングの力がそろうことが求められる。2010年代後半から世界的に不足している

#### オープン・イノベーション（おーぷんいのべーしょん / open innovation）

- 意味：自社だけでなく、他社・大学・自治体など、ちがう業種や分野の技術・アイデア・データ・知識を組み合わせて、新しいビジネスや研究成果を生むこと
- ポイント：AI に必要なデータ・技術・人材を、1社だけでそろえるのは難しいので、他企業や他業種との連携が大事になる

#### 産学連携（さんがくれんけい / industry-academia collaboration）

- 意味：新しい技術の研究開発や新しい事業づくりのために、大学などの教育・研究機関と民間企業が協力すること
- ポイント：国や自治体（官）を加えると産学官連携。大学の最新の研究と、企業のデータや現場をつなぐ

## 18-2 開発と運用の環境

### まとめ表

| 道具 | 役割 |
| :-: | :-: |
| Python | AI 開発で最もよく使うプログラミング言語。ライブラリが多い |
| Jupyter Notebook | コード・説明・グラフ・結果を1つの文書にまとめ、対話的に試せる |
| Docker | コンテナで、アプリと実行環境をまとめて隔離し、どこでも同じに動かす |
| クラウド | ネットワーク経由で、計算資源（GPU など）をサービスとして使う |
| Web API | 学習したモデルを、HTTP でほかのシステムから呼べるようにする |
| MLOps | 機械学習のモデルを本番で安定して運用し続けるための実践 |

### 開発の道具

#### Python（ぱいそん / Python）

- 意味：主にインタプリタで実行する、高水準の汎用プログラミング言語
- ポイント：文法が読みやすく、NumPy・pandas・scikit-learn・PyTorch・TensorFlow などのライブラリがそろっているので、AI 開発で最もよく使われる

#### Jupyter Notebook（じゅぴたーのーとぶっく / Jupyter Notebook）

- 意味：プログラムのコード・説明の文章・数式・図をふくむ文書（ノートブック）を作り、共有するためのウェブアプリケーション
- ポイント：コードを少しずつ実行して結果やグラフをすぐ見られるので、データの分析やモデルの試行錯誤に向く。結果をそのまま再実行できる形で残せる

#### Docker（どっかー / Docker）

- 意味：コンテナ仮想化を使って、アプリケーションを開発・配置・実行するためのオープンなプラットフォーム
- ポイント：アプリとライブラリなどの実行環境をコンテナにまとめるので、「自分の PC では動くのに本番で動かない」を防げる。仮想マシンより軽い（ホストの OS のカーネルを共有）

#### クラウド（くらうど / cloud computing）

- 意味：インターネットなどのネットワークを通じて、コンピュータの資源（計算・保存・GPU など）をサービスの形で使う利用の形
- ポイント：必要なときに必要なだけ使え、高価な GPU を買わずに大きなモデルを学習できる

#### Web API（うぇぶえーぴーあい / web API）

- 意味：HTTP などのインターネットの技術を使い、ほかのソフトウェアからネットワーク越しに機能を呼び出せるようにするしくみ
- ポイント：学習したモデルを Web API にすると、アプリやほかのシステムから予測を使える。クラウドの AI サービスも Web API で提供されることが多い

### 運用

#### MLOps（えむえるおぷす / machine learning operations）

- 意味：機械学習のモデルを、本番の環境に確実かつ効率よく展開し、保守し続けるための考え方と実践。機械学習（ML）と運用（DevOps）を合わせた言葉
- ポイント：データサイエンティスト・エンジニア・運用担当が協力し、学習 → 展開 → 監視 → 再学習のライフサイクルを自動化・管理する

#### モデルのヘルスモニタリング（もでるのへるすもにたりんぐ / model health monitoring）

- 意味：本番で動いているモデルの予測の精度や、入力データの性質が変わっていないかを見張り続けること
- ポイント：性能が落ちたら再学習する。モデルのバージョンや学習データを記録して管理する（ライフサイクル管理）

#### コンセプトドリフト（こんせぷとどりふと / concept drift）

- 意味：時間がたつにつれてデータ（とくに入力と答えの関係）が変わり、学習したモデルが合わなくなること
- 例：感染症の流行で買い物の傾向が変わり、需要予測が外れるようになる

## 18-3 データの収集と加工

### まとめ表

| 用語 | 中身 |
| :-: | :-: |
| オープンデータセット | だれでも使える公開のデータ（ImageNet・MNIST・COCO など）。利用条件（ライセンス）の確認が必要 |
| コーパス | 自然言語処理のために集めた、大量の文章のデータ |
| アノテーション | データに正解ラベルなどの情報をつける作業 |
| データリーケージ | 予測のときには使えない情報が学習に入りこみ、評価が良すぎる結果になる |
| 正規化・標準化 | 特徴量の値のはんいをそろえる |

### データを集める

#### オープンデータセット（おーぷんでーたせっと / open dataset）

- 意味：だれでも使えるように公開されているデータの集まり
- ポイント：ImageNet・MNIST・COCO などがある。商用利用できるか、出典を書く必要があるかなど、ライセンス（利用条件）を確認する。偏りがないかも確かめる

#### コーパス（こーぱす / corpus）

- 意味：言語の分析のために集めた、大量の言語の資料（文章のデータ）
- ポイント：言語学や自然言語処理で使う。品詞などの情報をつけたものもある

#### アノテーション（あのてーしょん / annotation）

- 意味：データに関連する情報（メタデータ）を注釈としてつけること。機械学習では、画像に写っているものの名前や枠など、正解のラベルをつける作業
- ポイント：教師あり学習に欠かせないが、人手と費用がかかる。基準をそろえないとラベルの質がばらつく。外部に頼むことも多い

### データを加工する

#### データリーケージ（でーたりーけーじ / data leakage）

- 意味：予測のときには手に入らないはずの情報が、モデルの学習に使われてしまうこと。目的変数の漏れ（target leakage）ともいう
- ポイント：テストではとても良い成績が出るのに、本番では役に立たない。テストデータの情報が前処理に混ざる、未来の情報で過去を予測する、なども原因になる
- 例：「解約したか」を予測するのに、「解約の手続きの日」を特徴量に入れてしまう

#### 正規化・標準化（せいきか・ひょうじゅんか / normalization, standardization）

- 意味：特徴量の値のはんいをそろえる前処理（特徴量のスケーリング）。正規化（min-max）は最小を 0・最大を 1 にし、標準化は平均を 0・分散（標準偏差）を 1 にする
- ポイント：身長（cm）と年収（万円）のように単位や大きさがちがう特徴量でも、同じくらいの重さで学習できる。外れ値があるときは標準化のほうが影響を受けにくい
