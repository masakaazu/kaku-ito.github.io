## 01-1 ルーター・スイッチ・セキュリティ機器

### まとめ表

| 機器 | 主な仕事 | 見るもの |
| :-: | :-: | :-: |
| ルーター | 別々のネットワークをつなぎ、最適な経路を選んで送る | 宛先の IP アドレス |
| レイヤ2スイッチ | 同じ LAN の中で、必要なポートにだけ転送する | 宛先の MAC アドレス |
| レイヤ3スイッチ | スイッチの働き＋ルーティング（VLAN の間など） | MAC と IP の両方 |
| ファイアウォール | 状態を追いかけ、許可した通信だけを通す | IP・ポート・プロトコル（5 タプル） |
| NGFW | ファイアウォール＋アプリの識別・IPS・ユーザーの識別など | アプリケーション層まで |
| IPS | 攻撃のパターンを見つけて止める（インライン） | パケットの中身（ルール・シグネチャ） |

### 転送する機器

#### ルーター（るーたー / router）

- 意味：別々のネットワークをつなぎ、パケットの宛先 IP アドレスを見て、最適な経路を選んで送る機器
- ポイント：レイヤ3（ネットワーク層）の機器。家庭用の無線ルーターは、外とつなぐエッジルーターと、利用者に配る働きを1台にまとめたもの。インターネットとの境目に置くものをエッジルーター（ゲートウェイ）と呼ぶ
- 例：本社の LAN とインターネットをつなぐ

#### レイヤ2スイッチ（れいやつーすいっち / Layer 2 switch）

- 意味：同じ LAN の中で、PC・プリンター・サーバーなどをつなぎ、フレームの宛先 MAC アドレスを見て、必要なポートにだけ転送する機器
- ポイント：データリンク層（レイヤ2）で動く。ポートごとに別々に通信できるので、たくさんの機器が同時に通信できる。VLAN で1台を複数の LAN に分けられる（#07）
- 例：フロアの PC をつなぐアクセススイッチ

#### レイヤ3スイッチ（れいやすりーすいっち / Layer 3 switch, multilayer switch）

- 意味：スイッチの働きに加えて、ルーティング（IP での転送）もできるスイッチ
- ポイント：ルーテッドポート（`no switchport` で L3 にした物理ポート）と SVI（`interface vlan` で作る VLAN のインタフェース）に IP アドレスを付けて、VLAN の間をルーティングする。Catalyst 9300 では IP ルーティングは既定で無効なので `ip routing` で有効にする
- 例：VLAN 10 と VLAN 20 の間の通信を SVI で中継する

### 守る機器

#### ファイアウォール（ふぁいあうぉーる / firewall, stateful firewall）

- 意味：ネットワークの境目で、決めたルールに合う通信だけを通す機器
- ポイント：ステートフル（通信の状態を追いかける）で、送信元・宛先の IP アドレス、送信元・宛先のポート番号、プロトコルの 5 つ（5 タプル）でふるい分ける
- 例：社内からの Web は通し、外から始まる通信は止める

#### 次世代ファイアウォール（じせだいふぁいあうぉーる / next-generation firewall, NGFW）

- 意味：ステートフルなファイアウォールの働きに、アプリケーションの識別と制御、IPS、高度な脅威の検知、ユーザーの識別などを加えた機器
- ポイント：ポート番号だけでなく、どのアプリか・誰の通信かまで見て止められる。Gartner の定義に沿って Cisco は、アプリの制御・IPS・マルウェア対策・ユーザーの識別・TLS の復号・脅威インテリジェンスを挙げている
- 例：同じ 443 番でも、許可していないファイル共有アプリだけを止める

#### IPS と IDS（あいぴーえすとあいでぃーえす / intrusion prevention system, intrusion detection system）

- 意味：IDS は通信を見張って攻撃らしいものを見つけ、記録・通知する。IPS はそれに加えて、悪い通信をその場で止めたり変えたりする
- ポイント：IDS は受け身で見張るだけ（検知）。IPS は通信の通り道（インライン）に置いて止める（防止）。ルール（パターン）と照らし合わせて攻撃を見つける。NGFW には IPS が組み込まれている
- 語の意味：Intrusion＝侵入／Prevention＝防止／Detection＝検知／System＝しくみ

## 01-2 無線・端末・PoE

### まとめ表

| 規格 | 呼び名 | 給電側の最大（1ポート） |
| :-: | :-: | :-: |
| IEEE 802.3af | PoE | 15.4 W |
| IEEE 802.3at | PoE+（Type 2） | 30 W |
| IEEE 802.3bt Type 3 | 4PPoE（Cisco UPOE も 60 W） | 60 W |
| IEEE 802.3bt Type 4 | 4PPoE（Cisco UPOE+） | 90 W |

### 無線と管理

#### アクセスポイント（あくせすぽいんと / access point, AP, wireless access point）

- 意味：無線の端末を、有線のネットワークにつなぐ機器
- ポイント：有線の LAN（スイッチ）につないで、無線の利用者の入口になる。AP が複数あると、利用者はつながったまま場所を移れる（ローミング）。中継（リピーター）やブリッジとして使うこともある
- 例：天井につけた AP にノート PC がつながる

#### 無線LANコントローラー（むせんらんこんとろーらー / wireless LAN controller, WLC）

- 意味：たくさんのアクセスポイントをまとめて管理する機器
- ポイント：AP の設定・ソフトの更新・無線の調整などを1か所で行う。集中型ではコントローラーを1か所に置く。コントローラーの働きを AP の中に入れた「コントローラーレス」の形もある。Catalyst 9800 が代表（#10）
- 例：Catalyst 9800 で 200 台の AP を管理する

#### コントローラー（こんとろーらー / controller）

- 意味：ネットワークの機器をまとめて管理・制御するソフトウェアや機器。WLC や、Catalyst Center のような SDN コントローラーがある
- ポイント：1台ずつではなく、まとめて設定や方針を配る（#24）。WLC は AP を、Catalyst Center はスイッチ・ルーター・WLC を扱う
- 例：Catalyst Center、Catalyst 9800

### つながる機器

#### エンドポイント（えんどぽいんと / endpoint）

- 意味：ネットワークの端につながり、利用者が使ったりデータを出し入れしたりする機器
- ポイント：PC・スマートフォン・IP 電話・プリンター・監視カメラ・IoT 機器など。キャンパスのアクセス層には、PC・IP 電話・無線の AP・監視カメラなど多くの種類の機器がつながる
- 例：社員のノート PC

#### サーバー（さーばー / server）

- 意味：ほかの機器（クライアント）からの要求を受けて、サービスやデータを返すコンピューター
- ポイント：Web・メール・ファイル・DNS・DHCP などのサービスを提供する。データセンターではリーフスイッチにつなぐ。今は仮想マシンやコンテナとして動くことも多い（01-5）
- 例：社内の Web サーバー

#### PoE（ぽー / Power over Ethernet）

- 意味：イーサネットの銅線のケーブルで、データと一緒に直流の電気を送るしくみ
- ポイント：電源をとれない天井の AP や IP 電話・カメラにも置ける。電気を送る側（スイッチ）を PSE、受ける側を PD と呼ぶ。スイッチは相手が PoE の機器かを確かめてから給電する。ケーブルは最大 100 m。Catalyst のポートは既定で `power inline auto`（自動で見つけて給電）
- 語の意味：Power＝電気／over＝〜の上で／Ethernet＝イーサネット／PSE＝Power Sourcing Equipment（給電する機器）／PD＝Powered Device（給電される機器）

#### PoE の規格（ぽーのきかく / IEEE 802.3af・802.3at・802.3bt）

- 意味：PoE の電力の大きさを決めた IEEE の規格
- ポイント：802.3af は 1 ポート 15.4 W、802.3at（PoE+）は 30 W、802.3bt は 4 対の線をすべて使い Type 3 で 60 W、Type 4 で 90 W。新しい規格は古い規格の機器にも給電できる。Cisco の UPOE は 60 W、UPOE+ は 90 W
- 例：Wi-Fi 6 の AP に PoE+（30 W）で給電する

## 01-3 キャンパスのトポロジー

### まとめ表

| 層 | 役割 | つながるもの |
| :-: | :-: | :-: |
| アクセス層 | 端末や利用者がネットワークに入る入口 | PC・IP 電話・AP・カメラ |
| ディストリビューション層 | アクセス層をまとめ、サービスへつなぐ | アクセススイッチ・WAN・WLC など |
| コア層 | 大きな LAN で、ディストリビューション層どうしをつなぐ | ディストリビューションスイッチ |

| 構成 | 層 | 向いている所 |
| :-: | :-: | :-: |
| 2 層（コラプストコア） | アクセス＋ディストリビューション（コアの役も兼ねる） | 1 棟の建物など、小さめのサイト |
| 3 層 | アクセス＋ディストリビューション＋コア | 何棟もある大きなキャンパス |

### 3つの層

#### アクセス層（あくせすそう / access layer）

- 意味：利用者が使う機器や端末が、ネットワークにつながる層
- ポイント：有線と無線の両方の入口。いろいろな端末がつながるので、セキュリティ（#23）・PoE・QoS などの機能をここで提供する
- 例：各フロアの配線室のスイッチ

#### ディストリビューション層（でぃすとりびゅーしょんそう / distribution layer）

- 意味：たくさんのアクセス層のスイッチをまとめ（集約）、サービスへの接続を提供する層
- ポイント：アクセススイッチが 2〜3 台より多いと、全部を互いにつなぐのは現実的でないので、ここでまとめる。障害の影響を小さい範囲にとどめる。WAN・インターネットの出口・WLC などをここにつなぐこともある
- 例：建物ごとの集約スイッチ

#### コア層（こあそう / core layer）

- 意味：大きな LAN で、ディストリビューション層どうしをつなぐ層
- ポイント：止まらずに速く運ぶことが仕事で、作りはいちばん単純にする。コアとの接続はレイヤ3だけ。N 個のディストリビューションを互いにつなぐと N×(N−1)/2 本の冗長リンクが要るが、コアを置くと N×2 本ですむ。ディストリビューションが 3 つを超えたらコアを検討する
- 例：キャンパスの中心に置く高速スイッチ

### 構成の型

#### 2層構成（にそうこうせい / two-tier design, collapsed core）

- 意味：アクセス層とディストリビューション層の2つで作り、ディストリビューション層がコア層の役も兼ねる構成
- ポイント：コアをディストリビューションに「つぶして（collapse）」まとめたので、コラプストコアとも呼ぶ。1 棟の建物ならアクセスとディストリビューションだけで足りることが多い
- 例：中規模のオフィスビル

#### 3層構成（さんそうこうせい / three-tier design）

- 意味：アクセス層・ディストリビューション層・コア層の3つで作る構成
- ポイント：何棟もある大きなキャンパスで使う。ディストリビューションが増えても、コアにつなぐだけで広げられる。どの層を使っても、各層が同じ働きをする（モジュール型）
- 例：大学のキャンパス

#### SOHO（そーほー / small office/home office）

- 意味：自宅や数人の小さな事務所のネットワーク
- ポイント：1 台の無線ルーター（ホームゲートウェイ）が、外とつなぐルーターの役と、利用者に配る役（有線のポートと無線）をまとめてこなすことが多い
- 語の意味：Small＝小さい／Office＝事務所／Home＝家

## 01-4 データセンター・WAN・クラウド

### まとめ表

| 構成 | つなぎ方 | 特徴 |
| :-: | :-: | :-: |
| スパイン・リーフ | すべてのリーフがすべてのスパインにつながる。リーフどうし・スパインどうしはつながない | どのリーフからどのリーフへもスパイン1台を通るだけ。横に広げやすい |
| 従来の3層（データセンター） | コア・アグリゲーション・アクセス | 大きな集約スイッチが止まると影響が大きい |

| 提供の形（NIST） | 利用者が管理するもの |
| :-: | :-: |
| IaaS | OS・ストレージ・アプリ（基盤のハードは提供者） |
| PaaS | 自分で作ったアプリ（OS などは提供者） |
| SaaS | ほぼ何もしない（提供者のアプリを使う） |

### データセンターと WAN

#### スパイン・リーフ（すぱいん・りーふ / spine-leaf, spine-and-leaf）

- 意味：データセンターで使う2層の構成。サーバーをつなぐリーフスイッチと、リーフをつなぐ背骨のスパインスイッチでできている
- ポイント：すべてのリーフがすべてのスパインにつながり（フルメッシュ）、リーフどうし・スパインどうしはつながない。スパインが 4 台なら 1 台が壊れても失うのは 25％。横に広げる（スケールアウト）のが得意で、従来の 3 層から移ってきた
- 例：ラックの上のリーフスイッチ（ToR）が、全部のスパインに 100G でつながる

#### WAN（わん / wide area network）

- 意味：離れた場所の LAN どうしをつなぐ広いネットワーク。インターネットは世界最大の WAN
- ポイント：つなぎ方には、専用線・MPLS・ブロードバンド（インターネット）・5G などがある。WAN の出口のルーターはエッジルーターと呼ぶ。SD-WAN は、複数の回線を、ソフトウェアのポリシーで使い分ける
- 例：本社と支社を MPLS とインターネットの 2 本でつなぐ

#### ハブアンドスポーク（はぶあんどすぽーく / hub-and-spoke）

- 意味：中心（ハブ、本社やデータセンター）と各拠点（スポーク）をつなぎ、拠点どうしの通信もハブを通す WAN のつなぎ方
- ポイント：従来の支社のネットワークは、すべての通信を本社のデータセンターに戻して（バックホール）セキュリティを通していた。今は、クラウドへの通信を支社から直接インターネットに出す（ローカルブレイクアウト）形が増えている
- 例：10 の支社が、すべて本社とだけつながる

#### SD-WAN（えすでぃーわん / software-defined WAN）

- 意味：WAN をソフトウェアで定義して、導入・運用・管理をしやすくするやり方
- ポイント：アプリごとのポリシーとオーバーレイを使い、MPLS・ブロードバンド・5G など複数の回線を、回線の状態とアプリに合わせて使い分ける。高い専用線の代わりに安い回線も使える
- 例：会議の映像は品質のよい回線に、ほかはインターネット回線に流す

### オンプレミスとクラウド

#### オンプレミス（おんぷれみす / on-premises）

- 意味：サーバーやネットワークの機器を、自分の会社の建物やデータセンターに置いて、自分で持ち・管理する形
- ポイント：自由に作れるが、機器を買い、置き場所・電源・保守を自分で用意する。クラウドと組み合わせる（ハイブリッド）ことも多い
- 例：本社のサーバールームに置いたファイルサーバー

#### クラウドコンピューティング（くらうどこんぴゅーてぃんぐ / cloud computing）

- 意味：ネットワーク経由で、共有された計算資源（ネットワーク・サーバー・ストレージ・アプリなど）を、必要なときにすぐ使い、すぐ返せるしくみ（NIST SP 800-145）
- ポイント：5 つの特徴＝オンデマンド・セルフサービス、幅広いネットワークからの利用、資源の共有（プール）、すばやい伸び縮み（スケーラビリティ）、使った分を測る（従量）
- 例：必要なときだけ仮想サーバーを 10 台増やす

#### IaaS・PaaS・SaaS（いあーす・ぱーす・さーす / Infrastructure / Platform / Software as a Service）

- 意味：クラウドの提供の形。IaaS＝計算・ストレージ・ネットワークの基盤を借りて OS から自分で入れる。PaaS＝アプリを動かす土台を借り、自分のアプリだけを置く。SaaS＝提供者のアプリをそのまま使う
- ポイント：IaaS → PaaS → SaaS の順に、利用者が管理する範囲が小さくなる。SaaS はブラウザで使う Web メールなど
- 例：IaaS＝仮想サーバーを借りる／SaaS＝Web のメールを使う

#### パブリック・プライベート・ハイブリッド（ぱぶりっく・ぷらいべーと・はいぶりっど / public, private, hybrid cloud）

- 意味：クラウドの置き方。パブリック＝一般の誰でも使える。プライベート＝1つの組織だけが使う。ハイブリッド＝2 つ以上の違う形のクラウドを組み合わせる
- ポイント：NIST はこのほかに、目的を同じくする複数の組織で使うコミュニティクラウドを挙げている。プライベートクラウドは、自社の建物の中にあっても外にあってもよい
- 例：ふだんは社内のプライベートクラウド、混むときだけパブリッククラウドを使う（ハイブリッド）

## 01-5 仮想化

### まとめ表

| 項目 | 仮想マシン（VM） | コンテナ |
| :-: | :-: | :-: |
| 分けるしくみ | ハイパーバイザーがハードを仮想化 | 1 つの OS のカーネルを共有して分ける |
| 中に入るもの | ゲスト OS ＋ アプリ | アプリと必要なライブラリだけ |
| 違う OS | 1 台で Linux と Windows を同時に動かせる | ホストと同じ系統の OS だけ |
| 分離の強さ | 強い | VM より弱い（カーネルを共有するため） |

### サーバーの仮想化

#### 仮想化（かそうか / virtualization）

- 意味：1 台の物理的な機器の上に、ソフトウェアで複数の仮想の機器を作り、それぞれを独立したもののように使うこと
- ポイント：サーバーの仮想化（仮想マシン）、コンテナ、ネットワークの仮想化（VLAN・VRF）などがある。資源をむだなく使える反面、1 台に多くをまとめるので、壊れたときや侵入されたときの影響が大きくなる
- 例：1 台のサーバーで 10 台分の仮想サーバーを動かす

#### ハイパーバイザー（はいぱーばいざー / hypervisor）

- 意味：物理的なハードウェアを仮想化して、その上で複数の仮想マシンを動かすソフトウェア
- ポイント：ベアメタル型（ネイティブ型、Type 1）はハードの上に直接入り、ホスト OS がいらない。ホスト型（Type 2）はふつうの OS（Windows・macOS・Linux）の上で動く。サーバーはベアメタル型、パソコンはホスト型が多い。Catalyst 9800-CL は Type 1 だけに対応し、VirtualBox などの Type 2 には入れられない
- 例：Type 1＝Catalyst 9800-CL を入れるサーバー用のハイパーバイザー／Type 2＝VirtualBox・VMware Fusion

#### 仮想マシン（かそうましん / virtual machine, VM）

- 意味：ハイパーバイザーの上で動く、仮想のコンピューター。自分専用の仮想のハードウェアと、完全なゲスト OS を持つ
- ポイント：仮想マシンどうしはハードウェアのレベルで分けられる。1 台の物理サーバーの上で、Linux と Windows を同時に動かせる
- 例：1 台の物理サーバーに、Web サーバーの VM と DB サーバーの VM を置く

### コンテナと VRF

#### コンテナ（こんてな / container）

- 意味：1 つの OS のカーネルを複数のアプリで共有しながら、アプリどうしを分けて動かすしくみ
- ポイント：ゲスト OS を持たないので軽い。ただしカーネルを共有するので、分離は VM より弱い。Linux のホストでは Linux 用のコンテナだけが動く。Docker などのランタイムで動かす
- 例：同じ Linux サーバーで、Web とキャッシュを別々のコンテナで動かす

#### コンテナイメージ（こんてないめーじ / container image）

- 意味：コンテナを動かすのに必要なファイルをすべてまとめたパッケージ
- ポイント：アプリが使う実行ファイルとライブラリだけを入れ、そのほかの OS の働きはホストのカーネルが提供する。層（レイヤー）を重ねて作り、レジストリ（置き場）に置いて共有する
- 例：Apache のイメージには httpd とそのライブラリ・設定ファイルが入る

#### VRF（ぶいあーるえふ / Virtual Routing and Forwarding）

- 意味：1 台のルーターやレイヤ3スイッチの中に、互いに独立した複数のルーティングテーブルを作る仮想化のしくみ
- ポイント：VRF ごとに別のルーティングテーブルを持つので、別の VRF なら同じ IP アドレスを重ねて使える。L3 のインタフェース（ルーテッドポート・SVI）を VRF に入れ、1 つのインタフェースは 1 つの VRF にしか入れない。Catalyst スイッチなどで使う簡単な形を VRF-lite と呼ぶ
- 例：`vrf definition GUEST` を作り、`vrf forwarding GUEST` を来客用の SVI に入れる
- 語の意味：Virtual＝仮想の／Routing＝経路を決める／Forwarding＝転送
