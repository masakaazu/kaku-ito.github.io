## 21-1 VPN の基本

### まとめ表

| 項目 | サイト間 VPN | リモートアクセス VPN |
| :-: | :-: | :-: |
| つなぐもの | ネットワークとネットワーク（本社と支社） | 1台の端末とネットワーク |
| トンネルを作る機器 | 両側の VPN 機器（ルーター・ファイアウォール） | 端末の VPN クライアントと、会社の VPN 機器 |
| 利用者の操作 | 要らない（いつもつながっている） | 利用者がクライアントで接続する |
| 主な方式 | IPsec（IKEv1／IKEv2） | SSL/TLS VPN、IPsec（IKEv2） |

### VPN とトンネル

#### VPN（ぶいぴーえぬ / Virtual Private Network）

- 意味：インターネットのような共用の網の上に、暗号化したつながりを作り、あたかも専用の網のように使えるようにする仕組み
- ポイント：途中で盗み見されないよう暗号化する。専用線より安く、どこからでもつなげる。CCNA ではサイト間とリモートアクセスの2種類を比べる
- 語の意味：Virtual＝仮想の／Private＝専用の／Network＝網

#### トンネル（とんねる / tunnel）

- 意味：パケットを別のパケットの中に包んで（カプセル化して）運ぶ、仮想の通り道
- ポイント：VPN では、包んだ中身を暗号化してインターネットを通す。外から見えるのは外側のヘッダー（トンネルの両端のアドレス）だけ

#### サイト間 VPN（さいとかんぶいぴーえぬ / site-to-site VPN）

- 意味：本社と支社など、拠点のネットワークどうしをインターネット越しにつなぐ VPN
- ポイント：Cisco の言い方では「ネットワークからネットワークへ」。両側の専用の機器（ルーターやファイアウォール）がトンネルを作り保つので、拠点の PC は VPN を意識しない。IPsec を使う
- 例：本社ルーター R1 と支社ルーター R2 の間の IPsec トンネル

#### リモートアクセス VPN（りもーとあくせすぶいぴーえぬ / remote access VPN）

- 意味：社外にいる1台の端末（ノート PC・スマホ）を、会社のネットワークにつなぐ VPN
- ポイント：Cisco の言い方では「コンピューターからネットワークへ」。端末に VPN クライアント（またはブラウザー）が要る。SSL/TLS VPN か IPsec（IKEv2）を使う。つなぐ前に端末の状態（ポスチャ）を確かめることもできる

#### スプリットトンネル（すぷりっととんねる / split tunneling）

- 意味：リモートアクセス VPN で、会社あての通信だけトンネルに入れ、それ以外はトンネルを通さず直接インターネットへ出すこと
- ポイント：回線の負担は減るが、トンネルの外の通信から端末が攻撃されると、その端末を足がかりに会社の網へ入られるおそれがある。全部をトンネルに入れるのはフルトンネル

#### VPN のトポロジー（ぶいぴーえぬのとぽろじー / hub-and-spoke, point-to-point, full mesh）

- 意味：VPN の拠点どうしをどうつなぐかの形。ハブアンドスポーク（中心の拠点と各拠点）、ポイントツーポイント（2拠点）、フルメッシュ（全拠点どうし）
- ポイント：ハブアンドスポークは設定が少ないが、支社どうしの通信も本社を通る。フルメッシュは直接通れるが、拠点が増えるとトンネルの数がとても増える

## 21-2 IPsec のしくみ

### まとめ表

**IPsec の4つの働き**

| 働き | 意味 |
| :-: | :-: |
| 機密性 | 暗号化して盗み見を防ぐ |
| 完全性 | 途中で書き換えられていないか確かめる |
| 送信元の認証 | 本当にその相手から来たか確かめる |
| リプレイ防止 | 記録して送り直されたパケットを見つけて捨てる |

**ESP と AH**

| 項目 | ESP | AH |
| :-: | :-: | :-: |
| IP のプロトコル番号 | 50 | 51 |
| 暗号化（機密性） | できる | できない |
| 完全性・認証 | できる | できる（外側の IP ヘッダーの一部も守る） |
| NAT | 通せる（NAT-T で UDP 4500 に包む） | 通せない（アドレスの書き換えで検査が合わなくなる） |

### IPsec の部品

#### IPsec（あいぴーせっく / IP Security）

- 意味：IP の層で、パケットに機密性・完全性・送信元の認証・リプレイ防止を与える、開かれた標準の集まり
- ポイント：1つのプロトコルではなく、ESP・AH（データを守る）と IKE（鍵と決まりを話し合う）などの組み合わせ。IP の層で守るので、上のアプリは変えなくてよい
- 語の意味：IP＝インターネットプロトコル／Security＝セキュリティ

#### ESP（いーえすぴー / Encapsulating Security Payload）

- 意味：パケットの中身を暗号化し、完全性・送信元の認証・リプレイ防止も与える IPsec のプロトコル。IP のプロトコル番号 50
- ポイント：暗号化できるのは ESP だけ。RFC 4301 も、たいていのセキュリティの要件は ESP だけで満たせるとしている。外側の IP ヘッダーは検査に入れないので NAT を通せる
- 語の意味：Encapsulating＝包む／Security＝安全の／Payload＝中身

#### AH（えーえいち / Authentication Header）

- 意味：パケットの完全性と送信元の認証、リプレイ防止を与えるが、暗号化はしない IPsec のプロトコル。IP のプロトコル番号 51
- ポイント：外側の IP ヘッダーの送信元・宛先も検査に入れるので、アドレスを書き換える NAT を通ると検査が合わなくなる。暗号化が要るなら ESP
- 語の意味：Authentication＝認証／Header＝ヘッダー

#### SA（えすえー / Security Association）

- 意味：IPsec の2つの相手が決めた、どのプロトコル・どのアルゴリズム・どの鍵でパケットを守るかの取り決め
- ポイント：SA は片方向。行きと帰りで別の SA を持つので、1本のトンネルにふつう2つの IPsec SA がある。また ESP・AH のプロトコルごとに作る

#### IKE（あいく / Internet Key Exchange）

- 意味：IPsec の相手どうしが互いを認証し、使うアルゴリズムを話し合い、鍵を作って SA を作るためのプロトコル。UDP 500（NAT を越えるときは 4500）
- ポイント：IKEv2 では、最初の IKE_SA_INIT（アルゴリズムの話し合いと Diffie-Hellman）と IKE_AUTH（相手の認証と最初の IPsec SA）で始まる。これは IKEv1 のフェーズ1にあたる。追加の SA を作る CREATE_CHILD_SA は IKEv1 のフェーズ2にあたる
- 語の意味：Internet＝インターネット／Key＝鍵／Exchange＝交換

#### Diffie-Hellman（でぃふぃーへるまん / DH）

- 意味：盗み見されるかもしれない通り道の上で、2者が同じ秘密（鍵の素）を作れる公開鍵の方式
- ポイント：IKE の中で、IPsec の鍵を作るために使う。鍵そのものは送らない。Cisco は 2048 ビット以上（グループ 14 以上）か楕円曲線の DH を勧めている

#### 事前共有鍵（じぜんきょうゆうかぎ / pre-shared key, PSK）

- 意味：VPN の両側に同じ秘密の文字列を前もって設定し、相手の認証に使う方法
- ポイント：設定が簡単でサイト間 VPN でよく使う。拠点が多いと鍵の管理が大変なので、証明書（電子署名）で認証する方法もある
- 例：`crypto isakmp key MyKey123 address 203.0.113.2`

#### トランスフォームセット（とらんすふぉーむせっと / transform set）

- 意味：IPsec で使うプロトコルとアルゴリズムの組み合わせ（例 ESP で AES と SHA）
- ポイント：SA を作るとき、両側で同じトランスフォームセットを探して選ぶ。合うものがないとトンネルができない。Cisco は DES・3DES・MD5 を勧めず、AES と SHA を勧める
- 例：`crypto ipsec transform-set TS esp-aes 256 esp-sha-hmac`

### 包み方

#### トンネルモード（とんねるもーど / tunnel mode）

- 意味：元の IP パケット全体（元のヘッダーも含む）を守り、新しい外側の IP ヘッダーを付けて送る IPsec のモード
- ポイント：元の送信元・宛先も隠せる。VPN 機器（セキュリティゲートウェイ）どうしのサイト間 VPN では、原則トンネルモードを使う

#### トランスポートモード（とらんすぽーともーど / transport mode）

- 意味：元の IP ヘッダーはそのまま使い、その後ろの中身（TCP・UDP など上の層）だけを守る IPsec のモード
- ポイント：ふつうはホストどうしの端から端までの保護に使う。GRE で包んだパケットを守るとき（GRE over IPsec）にも使える

#### NAT トラバーサル（なっととらばーさる / NAT traversal, NAT-T）

- 意味：ESP のパケットを UDP で包み、NAT やポート変換をする機器を通れるようにする方法。UDP 4500
- ポイント：ESP にはポート番号がないので、PAT では誰あてか区別できない。UDP に包むとポートで区別できる。IKE と同じポート（4500）を使う

## 21-3 ルーターでの組み方

### まとめ表

| 方式 | どう守る通信を決めるか | ルーティングプロトコル（マルチキャスト） |
| :-: | :-: | :-: |
| クリプトマップ | ACL（crypto ACL）で選んだ通信 | 通せない |
| VTI（IPsec のトンネルインタフェース） | ルーティングでトンネルに入れた通信 | 通せる |
| GRE over IPsec | GRE トンネルに入れた通信を IPsec で守る | 通せる |
| DMVPN | mGRE＋NHRP＋IPsec。支社どうしは必要なときに直接トンネル | 通せる |

### 設定の形

#### クリプトマップ（くりぷとまっぷ / crypto map）

- 意味：守る通信（ACL）・相手（peer）・トランスフォームセットをまとめ、物理インタフェースに付ける IPsec の古くからある設定
- ポイント：ACL に合ったパケットだけが暗号化される（両側で鏡写しの ACL にする）。トンネルインタフェースがないので、ルーティングプロトコルのマルチキャストは通らない
- 例：

```
crypto map VPN 10 ipsec-isakmp
 set peer 203.0.113.2
 set transform-set TS
 match address 120
interface g0/0
 crypto map VPN
```

#### VTI（ぶいてぃーあい / IPsec Virtual Tunnel Interface）

- 意味：IPsec のトンネルの端をインタフェース（Tunnel）として作る方式
- ポイント：インタフェースなので、ルーティングでトンネルに送るだけで暗号化される。ユニキャストもマルチキャストも暗号化して送れるので、OSPF なども通せる。QoS などもかけやすい
- 例：`interface Tunnel1` → `tunnel mode ipsec ipv4` → `tunnel protection ipsec profile P1`

#### GRE（じーあーるいー / Generic Routing Encapsulation）

- 意味：いろいろなパケット（ユニキャスト・マルチキャスト・ブロードキャスト）を IP パケットの中に包んで運ぶトンネルのプロトコル。IP のプロトコル番号 47
- ポイント：GRE 自体には暗号化も認証もない。マルチキャストも運べるので、トンネルの上でルーティングプロトコルが動く
- 語の意味：Generic＝汎用の／Routing＝ルーティングの／Encapsulation＝カプセル化

#### GRE over IPsec（じーあーるいーおーばーあいぴーせっく / GRE over IPsec）

- 意味：GRE で包んだパケットを、さらに IPsec で暗号化して送る方式
- ポイント：GRE は「何でも包めるが守らない」、IPsec は「守るが IP（ユニキャスト）だけ」。組み合わせると、ルーティングプロトコルも守って運べる
- 例：`interface Tunnel100` → `tunnel source …` → `tunnel destination …` → `tunnel protection ipsec profile ipsec_prof`

#### DMVPN（でぃーえむぶいぴーえぬ / Dynamic Multipoint VPN）

- 意味：mGRE（1つのトンネルインタフェースで多くの相手）・NHRP（相手の本当のアドレスを調べる）・IPsec を組み合わせ、多くの拠点の VPN を少ない設定で作る Cisco の方式
- ポイント：ハブ（本社）が NHRP のサーバー。スポーク（支社）は起動時に自分のアドレスを登録し、別のスポークと通信するときはハブに聞いて、直接のトンネルを必要なときに作る。支社のアドレスが変わってもよい
- 語の意味：Dynamic＝動的な／Multipoint＝多地点の

## 21-4 リモートアクセス VPN

### まとめ表

| 方式 | 端末に要るもの | 特徴 |
| :-: | :-: | :-: |
| SSL/TLS VPN（クライアントあり） | VPN クライアント（Cisco AnyConnect など） | TLS で守る。ネットワーク全体に入れる |
| クライアントレス SSL VPN | ブラウザーだけ | Web の画面からアプリを使う |
| IPsec（IKEv2）のリモートアクセス | IKEv2 に対応したクライアント | IPsec で守る |

### 方式と気をつけること

#### SSL/TLS VPN（えすえすえるてぃーえるえすぶいぴーえぬ / SSL/TLS VPN）

- 意味：Web で使う SSL とその後継の TLS で守る VPN。主にリモートアクセスに使う
- ポイント：TLS はたいていのブラウザーに入っているので、つなぎやすい。Cisco のファイアウォールでは、リモートアクセス VPN に SSL か IPsec（IKEv2）を使える。サイト間は IPsec
- 語の意味：SSL＝Secure Sockets Layer／TLS＝Transport Layer Security

#### クライアントレス VPN（くらいあんとれすぶいぴーえぬ / clientless VPN, web VPN）

- 意味：専用のクライアントを入れず、ブラウザーだけで使う SSL VPN
- ポイント：TLS がブラウザーに入っているのでソフトを入れなくてよい。そのため「clientless VPN」「web VPN」とも呼ぶ。使えるのは Web の画面から届くものに限られる

#### VPN クライアント（ぶいぴーえぬくらいあんと / VPN client）

- 意味：端末に入れて、会社の VPN 機器とトンネルを作るソフト
- ポイント：リモートアクセス VPN で使う。Cisco の AnyConnect は SSL と IPsec（IKEv2）の両方に対応する。サイト間 VPN では拠点の機器がトンネルを作るので、PC にクライアントは要らない

#### ポスチャ（ぽすちゃ / posture）

- 意味：端末が、つなぐ前に会社の決めた条件（ウイルス対策が最新か、など）を満たしているかの状態
- ポイント：条件を満たさない端末は、自分のまわりの感染（ワーム・ウイルス）を会社の網へ持ち込むおそれがある。リモートアクセス VPN では、つなぐ前にポスチャを確かめられる

#### リモートアクセスの認証（りもーとあくせすのにんしょう / remote access authentication）

- 意味：リモートアクセス VPN で、つなぐ人や端末を確かめること
- ポイント：Cisco の資料では、VPN の強さは端末側の認証の強さで決まり、遠くからの接続には二要素認証が最低限必要としている。RADIUS などの AAA サーバーとつなぐことが多い（#20）

### 21-1 VPN の基本

#### 問 ccna-21-o01

- 問：本社と3つの支社のネットワークを、インターネット越しにいつもつないでおきたい。各支社の PC には何も入れたくない。最も適した VPN はどれか。
- ア：サイト間 VPN
- イ：リモートアクセス VPN
- ウ：クライアントレス SSL VPN
- エ：スプリットトンネル
- 正解：ア
- 解説：拠点の機器どうしがトンネルを作るサイト間 VPN なら、PC は VPN を意識しない。
- アの意味：正しい。
- イの意味：1台の端末をつなぐ方式。端末ごとにクライアントが要る。
- ウの意味：ブラウザーで1人がつなぐ方式。
- エの意味：リモートアクセス VPN の通信の分け方。VPN の種類ではない。
- 出典：オリジナル問題（根拠：Cisco「What Is a VPN?」（A site-to-site VPN connects the corporate office to branch offices over the Internet … Dedicated equipment is used to establish and maintain a connection. Think of site-to-site access as network to network））

#### 問 ccna-21-o02

- 問：出張中の社員のノート PC を、会社のネットワークにつなぐ VPN はどれか。
- ア：サイト間 VPN
- イ：リモートアクセス VPN
- ウ：GRE だけのトンネル
- エ：DMVPN のスポーク
- 正解：イ
- 解説：1台の端末（エンドポイント）と会社の網をつなぐのがリモートアクセス VPN。Cisco は「コンピューターからネットワークへ」と説明する。
- アの意味：拠点のネットワークどうしをつなぐ。
- イの意味：正しい。
- ウの意味：暗号化がないので VPN として安全ではない。
- エの意味：DMVPN は拠点のルーターどうしの方式。
- 出典：オリジナル問題（根拠：Cisco「What Is a VPN?」（A remote access VPN securely connects a device outside the corporate office … Think of remote access as computer to network））

#### 問 ccna-21-o03

- 問：サイト間 VPN とリモートアクセス VPN の違いとして正しいものはどれか。
- ア：サイト間 VPN は利用者がそのつどクライアントで接続する
- イ：リモートアクセス VPN は拠点のルーターどうしでいつもつないでおく
- ウ：サイト間 VPN は拠点の機器がトンネルを作り、リモートアクセス VPN は端末側のクライアント（かブラウザー）がトンネルを作る
- エ：どちらも暗号化しない
- 正解：ウ
- 解説：サイト間は機器どうし、リモートアクセスは端末と VPN 機器。
- アの意味：リモートアクセスの説明。
- イの意味：サイト間の説明。
- ウの意味：正しい。
- エの意味：どちらも暗号化する。
- 出典：オリジナル問題（根拠：Cisco「How Does a VPN Work?」（A remote-access VPN extends … to a remote device … A site-to-site IPsec VPN lets businesses extend their network resources to branch offices … requires dedicated equipment））

#### 問 ccna-21-o04

- 問：リモートアクセス VPN で、会社あての通信だけをトンネルに入れ、ほかの Web はトンネルを通さず直接インターネットへ出す設定を何と呼ぶか。
- ア：スプリットトンネル
- イ：トンネルモード
- ウ：フルメッシュ
