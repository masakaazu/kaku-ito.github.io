## 17-1 DHCP のしくみ

### まとめ表

| 順番 | メッセージ | 向き | 送り方 |
| :-: | :-: | :-: | :-: |
| 1 | DHCPDISCOVER | クライアント → サーバー | ブロードキャスト（サーバーの場所を知らない） |
| 2 | DHCPOFFER | サーバー → クライアント | Cisco の説明ではユニキャスト |
| 3 | DHCPREQUEST | クライアント → サーバー | ブロードキャスト（ほかのサーバーにも「選ばなかった」と知らせる） |
| 4 | DHCPACK | サーバー → クライアント | Cisco の説明ではユニキャスト |

### 4つのメッセージ

#### DHCP（でぃーえいちしーぴー / Dynamic Host Configuration Protocol）

- 意味：PC などのホストに、IP アドレス・サブネットマスク・デフォルトゲートウェイ・DNS サーバーなどの設定を自動で配るプロトコル。UDP を使い、サーバーはポート 67、クライアントはポート 68
- ポイント：手で1台ずつ設定する手間と、アドレスの重なりを減らす。BOOTP を元にしているので、DHCP のリレーは BOOTP のリレーとしても働く
- 語の意味：Dynamic＝動的な／Host＝ホスト／Configuration＝設定／Protocol＝プロトコル

#### DHCPDISCOVER（でぃすかばー）

- 意味：クライアントが DHCP サーバーを探すために最初に送るメッセージ
- ポイント：クライアントはまだアドレスもサーバーの場所も知らないので、ブロードキャストで送る。ブロードキャストはルーターを越えないので、サーバーが別のサブネットにあるときはリレーエージェントが要る

#### DHCPOFFER（おふぁー）

- 意味：サーバーがクライアントに「このアドレスと設定を使えます」と申し出るメッセージ
- ポイント：まだ確定ではない。サーバーは、クライアントが正式に頼むまでそのアドレスをふつう取っておく。複数のサーバーから届いたら、クライアントはふつう最初に届いたものを選ぶ

#### DHCPREQUEST（りくえすと）

- 意味：クライアントが、申し出られたアドレスを正式に頼むメッセージ
- ポイント：ブロードキャストで送る。DISCOVER を受け取ったほかのサーバーにも「あなたのは選ばなかった」と伝わり、申し出たアドレスを取り戻せる

#### DHCPACK（あっく）

- 意味：サーバーが「そのアドレスを割り当てた」と確定させるメッセージ。これを受け取ってクライアントはアドレスを使い始める
- ポイント：4つの頭文字で DORA（Discover・Offer・Request・Ack）と覚える。割り当てられないときは DHCPNAK が返る

#### リース（りーす / lease）

- 意味：DHCP で配ったアドレスを使ってよい期間
- ポイント：Cisco の DHCP サーバーの初期値は1日。期限が切れる前にクライアントは更新を頼む（RFC 2131 では、リースの半分の時間で更新を始めるのが初期値）
- 例：`lease 7`（7日）、`lease 0 8`（8時間）、`lease infinite`

#### DHCP サーバー（でぃーえいちしーぴーさーばー / DHCP server）

- 意味：アドレスのプールを持ち、クライアントに IP アドレスと設定を貸し出す機器。Cisco のルーターや L3 スイッチもなれる
- ポイント：配る前に ping と gratuitous ARP でそのアドレスが使われていないか確かめ、使われていれば（衝突）プールから外す

#### DHCP クライアント（でぃーえいちしーぴーくらいあんと / DHCP client）

- 意味：DHCP でアドレスと設定をもらう側。PC だけでなく、ルーターのインタフェースもなれる
- ポイント：Cisco のルーターは、同時に DHCP サーバーにもクライアントにもなれる

## 17-2 DHCP の設定（サーバー・リレー・クライアント）

### まとめ表

| 役 | 主なコマンド | 入れる場所 |
| :-: | :-: | :-: |
| サーバー | ip dhcp excluded-address・ip dhcp pool（network・default-router・dns-server・lease） | グローバル |
| リレー | ip helper-address サーバーのアドレス | クライアント側のインタフェース（SVI など） |
| クライアント | ip address dhcp | アドレスをもらうインタフェース |
| 確かめる | show ip dhcp binding・show ip dhcp pool・show ip dhcp conflict | 特権 EXEC |

### サーバーの設定

#### ip dhcp pool（あいぴーでぃーえいちしーぴーぷーる）

- 意味：DHCP で配るアドレスと設定のまとまり（プール）を作り、DHCP プール設定モードに入るコマンド
- ポイント：中で network（配るサブネット）・default-router・dns-server・domain-name・lease を書く。network はネットワークアドレスとマスク（または /長さ）で書く
- 例：`ip dhcp pool VLAN10` → `network 10.1.10.0 255.255.255.0`

#### default-router（でふぉるとるーたー）

- 意味：DHCP プールの中で、クライアントに配るデフォルトゲートウェイのアドレスを決めるコマンド
- ポイント：クライアントと同じサブネットのアドレスにする。最大8個まで、先に書いたものが優先。FHRP を使うなら仮想 IP を書く
- 例：`default-router 10.1.10.1`

#### dns-server（でぃーえぬえすさーばー）

- 意味：DHCP プールの中で、クライアントに配る DNS サーバーのアドレスを決めるコマンド
- ポイント：最大8個まで、優先する順に書く。これがないと、クライアントはアドレスはもらえても名前でサーバーに接続できない
- 例：`dns-server 10.1.99.53 8.8.8.8`

#### ip dhcp excluded-address（あいぴーでぃーえいちしーぴーえくすくるーでっどあどれす）

- 意味：プールの範囲の中で、DHCP で配らないアドレスを決めるグローバル設定コマンド。最初と最後を書けば範囲で指定できる
- ポイント：ゲートウェイ・サーバー・プリンターなど、手で設定するアドレスを外す。プール設定モードではなくグローバル設定モードで入れる。DHCP サーバー自身のインタフェースのアドレスは自動で外れる
- 例：`ip dhcp excluded-address 10.1.10.1 10.1.10.20`

#### show ip dhcp binding（しょーあいぴーでぃーえいちしーぴーばいんでぃんぐ）

- 意味：DHCP サーバーが今貸し出しているアドレスと、相手の MAC（クライアント ID）、リースの期限を表示するコマンド
- ポイント：サーバー側で見るコマンド。プールが足りているかの確認にも使う。アドレスの衝突は show ip dhcp conflict で見る

```
IP address      Client-ID/              Lease expiration        Type
                Hardware address
10.1.10.21      0100.5079.6668.00       Nov 08 2026 10:15 AM    Automatic
```

#### DHCP のアドレス衝突（でぃーえいちしーぴーのあどれすしょうとつ / address conflict）

- 意味：DHCP で配ろうとしたアドレスを、すでに別のホストが使っていること
- ポイント：Cisco の DHCP サーバーは配る前に ping と gratuitous ARP で確かめ、衝突したアドレスはプールから外し、管理者が直すまで配らない。衝突の一覧は show ip dhcp conflict で見る

### リレーとクライアント

#### DHCP リレーエージェント（でぃーえいちしーぴーりれーえーじぇんと / DHCP relay agent）

- 意味：クライアントとサーバーが別のサブネットにあるとき、クライアントのブロードキャストを受け取って、サーバーへユニキャストで送り直すルーター（L3 機器）
- ポイント：ルーターはブロードキャストを転送しないので、リレーがないと別のサブネットの DHCP サーバーに DISCOVER が届かない。Cisco では ip helper-address を入れたインタフェースでリレーが有効になる

#### ip helper-address（あいぴーへるぱーあどれす）

- 意味：インタフェースで受け取った DHCP などの UDP ブロードキャストを、指定したサーバーへユニキャストで転送するインタフェースコマンド
- ポイント：入れるのは「クライアントがいる側」のインタフェース（クライアントの VLAN の SVI など）。サーバー側のインタフェースに入れても働かない。サーバーが何台かあれば、1台ずつ書ける
- 例：`interface vlan 10` → `ip helper-address 10.1.99.10`

#### giaddr（じーあいあどれす / gateway IP address）

- 意味：リレーエージェントが DHCP のメッセージに書き込む、自分のインタフェース（ip helper-address を入れたインタフェース）のアドレス
- ポイント：サーバーは giaddr を見て、どのサブネットのプールから配るかを決め、返事を giaddr のリレーへ送る。だからサーバーには、各 VLAN のサブネットのプールと、giaddr への経路が要る
- 語の意味：gateway＝ゲートウェイ／IP address＝IP アドレス

#### ip address dhcp（あいぴーあどれすでぃーえいちしーぴー）

- 意味：ルーターやスイッチのインタフェースを DHCP クライアントにして、アドレスを DHCP サーバーからもらうインタフェースコマンド
- ポイント：インターネット回線の出口（ISP からアドレスをもらう）でよく使う。手で書く ip address アドレス マスク の代わりに入れる
- 例：`interface g0/1` → `ip address dhcp`

## 17-3 DNS

### まとめ表

| レコード | 中身 | 例（Claudeが作った例） |
| :-: | :-: | :-: |
| A | 名前 → IPv4 アドレス | www.example.com → 192.0.2.10 |
| AAAA | 名前 → IPv6 アドレス | www.example.com → 2001:db8::10 |
| CNAME | 別名 → 本当の名前 | web.example.com → www.example.com |
| MX | ドメイン → メールサーバー | example.com → mail.example.com |
| PTR | IP アドレス → 名前（逆引き） | 10.2.0.192.in-addr.arpa → www.example.com |
| NS | ゾーン → 権威のあるネームサーバー | example.com → ns1.example.com |

### しくみ

#### DNS（でぃーえぬえす / Domain Name System）

- 意味：ホスト名と IP アドレスなどを対応させる、世界中に分かれた階層型のデータベースと、それを引くプロトコル
- ポイント：人は名前で覚え、通信には IP アドレスが要る。その橋渡しをする。DHCP は「自分のアドレスをもらう」、DNS は「相手のアドレスを調べる」と役目が違う
- 語の意味：Domain＝ドメイン（名前の区切り）／Name＝名前／System＝しくみ

#### 名前解決（なまえかいけつ / name resolution）

- 意味：ホスト名から IP アドレスを調べること。PC はリゾルバー（問い合わせる側のプログラム）で、設定された DNS サーバーに問い合わせる
- ポイント：答えはしばらくキャッシュに残るので、同じ名前を何度も問い合わせない。名前を引く順番の問題で「DNS サーバーに届かない」と「名前が間違い」を分けて考える
- 例：PC で `nslookup www.example.com`

#### DNS のポート（でぃーえぬえすのぽーと / port 53）

- 意味：DNS は UDP と TCP の両方のポート 53 を使う
- ポイント：ふつうの問い合わせは UDP 53。大きな応答や、ゾーン転送（サーバーどうしの丸ごとのコピー）は TCP 53。「DNS は UDP だけ」は誤り

#### 権威 DNS サーバー（けんいでぃーえぬえすさーばー / authoritative name server）

- 意味：あるゾーン（ドメインの一部）の情報を元から持っていて、責任を持って答えるネームサーバー
- ポイント：キャッシュから答えるサーバーとは違う。NS レコードで、どのゾーンの権威サーバーがだれかを示す

### レコード

#### A レコード（えーれこーど / A record）

- 意味：ホスト名と IPv4 アドレスの対応を表すレコード
- ポイント：IPv6 は AAAA。名前から IP を調べる「正引き」で使う
- 例：`www.example.com A 192.0.2.10`

#### AAAA レコード（くわっどえーれこーど / AAAA record）

- 意味：ホスト名と IPv6 アドレスの対応を表すレコード（RFC 3596）
- ポイント：IPv6 アドレスは 128 ビットで A（32 ビット）の4倍なので、A を4つ並べた名前
- 例：`www.example.com AAAA 2001:db8::10`

#### CNAME レコード（しーねーむれこーど / canonical name record）

- 意味：別名（エイリアス）が、本当の名前（正規名）のどれにあたるかを表すレコード
- ポイント：アドレスそのものは書かない。引いた側は、続けて正規名の A や AAAA を引く
- 語の意味：Canonical＝正規の／Name＝名前

#### MX レコード（えむえっくすれこーど / mail exchange record）

- 意味：あるドメイン宛てのメールを受け取るメールサーバーを表すレコード。優先度の数も書く
- ポイント：数が小さいほど優先。メールサーバーの名前を書き、そのアドレスは A・AAAA で引く
- 例：`example.com MX 10 mail.example.com`

#### PTR レコード（ぴーてぃーあーるれこーど / pointer record）

- 意味：IP アドレスからホスト名を調べる「逆引き」に使うレコード
- ポイント：A の逆。in-addr.arpa（IPv4）の下に、アドレスを逆順に並べた名前で登録する

### ルーターの DNS の設定

#### ip name-server（あいぴーねーむさーばー）

- 意味：ルーター自身が名前を引くときに問い合わせる DNS サーバーを決めるグローバル設定コマンド。最大6台まで
- ポイント：ルーターが ping や telnet で名前を使うための設定。PC に DNS サーバーを配るのは DHCP プールの dns-server で、別のコマンド
- 例：`ip name-server 10.1.99.53`

#### ip domain lookup（あいぴーどめいんるっくあっぷ）

- 意味：ルーターの DNS による名前解決を有効にするグローバル設定コマンド。初期値は有効
- ポイント：コマンドを打ち間違えると、ルーターはそれをホスト名だと思って DNS で引こうとし、しばらく待たされる。これを避けるために no ip domain lookup を入れることが多い
- 例：`no ip domain lookup`

#### ip domain name（あいぴーどめいんねーむ）

- 意味：ルーターのドメイン名を決めるグローバル設定コマンド。名前だけ（ドメインなし）で引いたときに後ろに付ける
- ポイント：SSH の鍵を作るときにも、ホスト名とドメイン名が要る（#11）。古い書き方は ip domain-name
- 例：`ip domain name example.com`

#### ip host（あいぴーほすと）

- 意味：ホスト名と IP アドレスの対応を、ルーターの中に固定で登録するグローバル設定コマンド
- ポイント：DNS サーバーに問い合わせずに名前が使える。PC の hosts ファイルにあたる
- 例：`ip host R2 10.1.12.2`

### 17-1 DHCP のしくみ

#### 問 ccna-17-o01

- 問：DHCP でアドレスをもらうときのメッセージの順番として正しいものはどれか。
- ア：REQUEST → OFFER → DISCOVER → ACK
- イ：DISCOVER → REQUEST → OFFER → ACK
- ウ：DISCOVER → OFFER → REQUEST → ACK
- エ：OFFER → DISCOVER → ACK → REQUEST
- 正解：ウ
- 解説：クライアントがサーバーを探し（DISCOVER）、サーバーが申し出て（OFFER）、クライアントが正式に頼み（REQUEST）、サーバーが確定する（ACK）。頭文字で DORA。
- アの意味：順番がばらばら。最初はクライアントがサーバーを探す DISCOVER。
- イの意味：申し出（OFFER）の前に頼む（REQUEST）ことはできない。
- ウの意味：正しい。
- エの意味：サーバーから先に申し出ることはない。
- 出典：オリジナル問題（根拠：Cisco DHCP Configuration Guide 15M&T「DHCP Overview」DHCP Server Relay Agent and Client Operation（DHCPDISCOVER … DHCPOFFER … DHCPREQUEST … DHCPACK））

#### 問 ccna-17-o02

- 問：DHCPDISCOVER がブロードキャストで送られる理由として正しいものはどれか。
- ア：クライアントはまだ DHCP サーバーのアドレスを知らないため
- イ：ネットワーク上のすべての PC にアドレスを配るため
- ウ：ブロードキャストのほうがルーターを越えやすいため
- エ：DNS サーバーにも同時に知らせるため
- 正解：ア
- 解説：クライアントはアドレスもサーバーの場所も持っていないので、同じサブネットの全員に向けて送るしかない。
- アの意味：正しい。
- イの意味：アドレスを配るのはサーバー。DISCOVER はクライアントが探すメッセージ。
- ウの意味：逆。ブロードキャストはルーターを越えない。だからリレーが要る。
- エの意味：DNS とは関係ない。
- 出典：オリジナル問題（根拠：Cisco IP Addressing Services Configuration Guide 12.4T「Configuring the Cisco IOS DHCP Relay Agent」（DHCP clients need to use User Datagram Protocol (UDP) broadcasts to send their initial DHCPDISCOVER messages because they don't have information about the network to which they are attached））

#### 問 ccna-17-o03

- 問：クライアントが DHCPREQUEST をブロードキャストで送る理由として正しいものはどれか。
- ア：申し出を出したほかの DHCP サーバーにも、選ばなかったことを伝えるため
- イ：デフォルトゲートウェイの MAC アドレスを調べるため
- ウ：リースを延長するときはブロードキャストしか使えないため
- エ：DNS サーバーに自分の名前を登録するため
- 正解：ア
- 解説：DISCOVER を受け取って申し出たサーバーが何台かあっても、REQUEST がブロードキャストで届くので、選ばれなかったサーバーは申し出たアドレスを取り戻せる。
- アの意味：正しい。
- イの意味：ARP の役目。
- ウの意味：アドレスを持っているクライアントの更新はユニキャストでもできる。
- エの意味：DHCP の REQUEST の目的ではない。
- 出典：オリジナル問題（根拠：Cisco「DHCP Overview」（The formal request for the offered IP address (the DHCPREQUEST message) that is sent by the client is broadcast so that all other DHCP servers that received the DHCPDISCOVER broadcast message from the client can reclaim the IP addresses that they offered to the client））

#### 問 ccna-17-o04

- 問：DHCP が使うトランスポート層のプロトコルとポート番号の組として正しいものはどれか。
- ア：UDP、サーバー 67・クライアント 68
- イ：TCP、サーバー 67・クライアント 68
- ウ：UDP、サーバー 53・クライアント 53
- エ：UDP、サーバー 68・クライアント 67
- 正解：ア
- 解説：DHCP は UDP を使い、クライアントからサーバーへはポート 67、サーバーからクライアントへはポート 68 に送る。
- アの意味：正しい。
- イの意味：DHCP は TCP ではない。
- ウの意味：53 は DNS のポート。
