## 20-1 脅威・脆弱性・エクスプロイト

### まとめ表

| 言葉 | ひとことで | 例 |
| :-: | :-: | :-: |
| 脆弱性 | 弱いところ（穴） | パッチを当てていない OS の不具合 |
| 脅威 | 害を与えうるもの・こと | 攻撃者、マルウェア、停電 |
| エクスプロイト | 穴を突くためのコードや方法 | 不具合を突いてマルウェアを入れるプログラム |
| リスク | 脅威が穴を突いて害が出る見込み | 「この穴が突かれて顧客情報が漏れる見込み」 |
| 対策 | 脅威・穴・攻撃を防ぐ、害を減らす、見つける手段 | パッチ、ACL、MFA、教育 |

### 言葉の関係

#### 脆弱性（ぜいじゃくせい / vulnerability）

- 意味：システムの設計・作り・運用の中にある欠陥や弱さで、悪用されるとセキュリティの決まりを破られてしまうもの
- ポイント：「穴」そのもの。攻撃する人やプログラム（脅威・エクスプロイト）とは別。設計の穴、作り（実装）の穴、運用の穴の3種類がある
- 例：パッチを当てていないソフトの不具合、初期パスワードのままの機器

#### 脅威（きょうい / threat）

- 意味：セキュリティを破って害を与えるおそれ。それを起こしうる人・もの・できごと
- ポイント：攻撃者だけでなく、災害やミスも含む広い言葉。脅威が脆弱性を突くと被害になる
- 例：攻撃者、マルウェア、内部の不正、停電

#### エクスプロイト（えくすぷろいと / exploit）

- 意味：ソフトやシステムの脆弱性を見つけて突くために作られたプログラムやコード
- ポイント：Cisco の説明では、エクスプロイト自体はマルウェアではなく、マルウェアを送り込むための方法。ベンダーがパッチで穴をふさぐと使えなくなる
- 例：OS の不具合を突いて、ランサムウェアを入れるコード

#### リスク（りすく / risk）

- 意味：ある脅威がある脆弱性を突いて、害が出る見込み（起こりやすさと害の大きさ）
- ポイント：脅威・脆弱性・害の3つがそろって初めてリスクになる。対応は「避ける・移す（保険など）・減らす・受け入れる」がある

#### 対策（たいさく / mitigation, countermeasure）

- 意味：脅威・脆弱性・攻撃に対して、防ぐ、害を小さくする、見つけて知らせるための手段や手順
- ポイント：技術（パッチ・ACL・暗号化・MFA）だけでなく、手順（ポリシー）や人（教育）や物理（鍵・入館管理）も対策。1つで全部は防げないので組み合わせる

#### ゼロデイ（ぜろでい / zero-day）

- 意味：ベンダーがまだ知らない（パッチがない）脆弱性を突く攻撃やエクスプロイト
- ポイント：パッチがないので、パッチを当てるだけでは防げない。不審な動きを見つける仕組み（振る舞いの検知など）と組み合わせる

#### CIA の3要素（しーあいえー / Confidentiality, Integrity, Availability）

- 意味：守るべき3つの性質。機密性（許された人だけが見られる）・完全性（勝手に変えられていない）・可用性（使いたいときに使える）
- ポイント：盗み見は機密性、改ざんは完全性、DoS は可用性をこわす。Cisco の説明でも、サイバー攻撃は CIA のどれかを破ろうとするもの
- 語の意味：Confidentiality＝機密性／Integrity＝完全性／Availability＝可用性

## 20-2 ネットワークへの攻撃

### まとめ表

| 攻撃 | 何をする | 主に破られるもの |
| :-: | :-: | :-: |
| DoS・DDoS | 大量の通信などで使えなくする | 可用性 |
| リフレクション・増幅 | 送信元を偽って第三者のサーバーから大きな応答を被害者へ | 可用性 |
| スプーフィング | 送信元のアドレスなどを偽る | 他の攻撃の土台 |
| 中間者攻撃 | 2者の間に入り、盗み見・書き換え | 機密性・完全性 |
| 偵察 | 攻撃の前に相手の情報を集める | （準備） |
| パスワード攻撃 | 辞書や総当たりでパスワードを当てる | 機密性 |

### 使えなくする攻撃

#### DoS 攻撃（どすこうげき / Denial of Service）

- 意味：正規の利用者がシステムを使えないようにする、または動きを遅らせる攻撃
- ポイント：可用性をこわす。大量のパケットを送る（フラッディング）ほか、壊れたパケットで機器を落とす方法もある
- 例：SYN フラッド（偽の送信元から TCP の SYN を大量に送り、相手を返事待ちでいっぱいにする）
- 語の意味：Denial＝拒否／of Service＝サービスの

#### DDoS 攻撃（でぃーどすこうげき / Distributed Denial of Service）

- 意味：たくさんの機器から一斉に DoS をしかける攻撃
- ポイント：乗っ取られた多くの機器（ボットネット・ゾンビ）を使う。送信元が多いので、1つのアドレスを止めるだけでは防げない
- 語の意味：Distributed＝分散した／Denial of Service＝サービス妨害

#### リフレクション・増幅攻撃（りふれくしょん・ぞうふくこうげき / reflection and amplification attack）

- 意味：被害者のアドレスを送信元に偽って、第三者のサーバー（例 オープンな DNS リゾルバー）に小さな問い合わせを送り、大きな応答を被害者に送りつけさせる攻撃
- ポイント：UDP なので送信元を偽りやすい。応答が問い合わせよりずっと大きい（RFC 5358 では DNS で約80倍の例）ので、少しの通信で大量の通信を生む。根本の対策は送信元を偽ったパケットを出さないこと（入口フィルタリング、BCP 38）

### 偽る・割り込む・調べる

#### スプーフィング（すぷーふぃんぐ / spoofing）

- 意味：送信元の IP アドレスや MAC アドレスなどを偽り、ほかの人や機器になりすますこと
- ポイント：DoS・リフレクション・中間者攻撃などの土台になる。対策は、自分のネットワークから出るパケットの送信元が本当に自分の範囲か確かめる入口フィルタリング（RFC 2827）、L2 では DHCP スヌーピングや DAI（#23）

#### 中間者攻撃（ちゅうかんしゃこうげき / man-in-the-middle attack, MITM）

- 意味：通信する2者の間に割り込み、通信を盗み見たり書き換えたりして、片方になりすます攻撃
- ポイント：機密性と完全性をこわす。LAN では ARP のなりすましで割り込む方法がある。暗号化と、相手が本物か確かめる認証（証明書など）で防ぐ

#### 偵察（ていさつ / reconnaissance）

- 意味：攻撃の前に、相手のネットワーク・機器・ソフトの版・人について情報を集めること
- ポイント：Cisco の説明では攻撃の最初の段階。ping での探索やポートスキャン、公開情報の収集などがある。不要なサービスを止め、出す情報を減らすのが対策

#### バッファオーバーフロー（ばっふぁおーばーふろー / buffer overflow）

- 意味：プログラムが書き込みの範囲を確かめないことを突いて、決まった領域より長いデータを書き込み、動きを乗っ取ったり止めたりする攻撃
- ポイント：作り（実装）の脆弱性を突くエクスプロイトの代表。対策はパッチ（修正）

#### パスワード攻撃（ぱすわーどこうげき / password attack）

- 意味：パスワードを当てたり盗んだりして、正規の利用者として入り込む攻撃
- ポイント：辞書攻撃（よく使われる言葉の一覧を順に試す）と総当たり（ブルートフォース、すべての組み合わせを試す）が代表。ほかのサイトで漏れた ID とパスワードをそのまま試すクレデンシャルスタッフィングもある。対策は長いパスワード・失敗回数の制限・MFA

## 20-3 マルウェアと人をねらう攻撃

### まとめ表

| 種類 | 広がり方・特徴 |
| :-: | :-: |
| ウイルス | ほかのファイルやプログラムにくっつき、それが実行されると動く |
| ワーム | 単独で動き、ネットワークを通じて自分で広がる |
| トロイの木馬 | 役に立つソフトに見せかける。自分では増えない |
| ランサムウェア | データを暗号化して使えなくし、お金を要求する |
| フィッシング | 本物に見せかけたメールなどで、情報を入力させる・マルウェアを入れさせる |
| テールゲーティング | 入館を許された人のあとについて入る |

### マルウェア

#### マルウェア（まるうぇあ / malware）

- 意味：害を与える目的で作られたソフトの総称（malicious software の略）
- ポイント：ウイルス・ワーム・トロイの木馬・スパイウェア・ランサムウェアなどを含む広い言葉。エクスプロイトは「穴を突く方法」で、マルウェアは「入れられる害のあるソフト」
- 語の意味：malicious＝悪意のある／software＝ソフト

#### ウイルス（ういるす / virus）

- 意味：ほかのプログラムやファイルに自分のコピーを入れて広がる、害のあるコード
- ポイント：単独では動けない。くっついたプログラム（宿主）が実行されて初めて動く。ここがワームとの違い

#### ワーム（わーむ / worm）

- 意味：単独で動き、ネットワークを通じてほかの機器へ自分のコピーを送り込んで広がるプログラム
- ポイント：宿主のプログラムが要らず、人の操作がなくても広がる。急に広がってネットワークや機器の資源を使い切ることがある

#### トロイの木馬（とろいのもくば / Trojan horse）

- 意味：役に立つソフトに見せかけて、実は隠れた害のある働きをするプログラム
- ポイント：利用者が自分で入れてしまう。ウイルスやワームと違い、自分で増える仕組みはない

#### ランサムウェア（らんさむうぇあ / ransomware）

- 意味：データを暗号化して使えなくし、元に戻すかわりにお金（身代金）を要求するマルウェア
- ポイント：フィッシングのリンクから入ることが多い。対策はバックアップ・パッチ・教育
- 語の意味：ransom＝身代金／ware＝ソフト

### 人をねらう攻撃

#### ソーシャルエンジニアリング（そーしゃるえんじにありんぐ / social engineering）

- 意味：人の心理（信頼・好奇心・あせり）をつき、だまして情報を聞き出したり、危ない操作をさせたりする方法
- ポイント：技術の穴ではなく人をねらう。フィッシング・なりすまし（口実を作る pretexting）・テールゲーティングなどを含む。いちばんの対策は教育（意識向上・訓練）と、決まったポリシー

#### フィッシング（ふぃっしんぐ / phishing）

- 意味：本物の会社や人に見せかけたメールやメッセージで、パスワードなどを入力させたり、マルウェアを入れさせたりする攻撃
- ポイント：多くの人にばらまく。音声の電話で行うものをビッシング（vishing）、SMS で行うものをスミッシング（SMiShing）と呼ぶ。対策はメールのフィルターと教育、盗まれても入られないための MFA

#### スピアフィッシング（すぴあふぃっしんぐ / spear phishing）

- 意味：特定の人や部署にねらいを絞り、その人に合わせた内容で送るフィッシング
- ポイント：調べた情報を使うので本物らしく見え、危険が大きい。経営者など地位の高い人をねらうものはホエーリング（whaling）
- 語の意味：spear＝もり（1匹をねらって突く）

#### テールゲーティング（てーるげーてぃんぐ / tailgating, piggybacking）

- 意味：入館を許された人のあとについて、認証なしで建物や部屋に入ること
- ポイント：物理的なソーシャルエンジニアリング。ピギーバッキングとも呼ぶ。2つの扉の間で1人ずつ確かめるアクセス制御の前室や、教育で防ぐ

## 20-4 セキュリティプログラム

### まとめ表

| 要素 | 目的 | 例 |
| :-: | :-: | :-: |
| 意識向上（awareness） | 全員の注意をセキュリティに向ける | ポスター、ログイン画面の注意、メールでのお知らせ |
| トレーニング | 役割に必要な知識と技能を身につける | 管理者向けの設定の講習、フィッシングの模擬訓練 |
| 物理アクセス制御 | 建物・部屋・機器に入れる人を限る | 入館証のカード、鍵、生体認証、受付の記録、来訪者のエスコート |

### 人と場所を守る

#### セキュリティポリシー（せきゅりてぃぽりしー / security policy）

- 意味：組織が情報をどう管理し、守り、配るかを決めた決まりや手順の全体
- ポイント：パスワードの決まり・MFA を使う場面・来訪者の扱いなどを書いておき、教育と組み合わせる。技術の設定はこの決まりを実現する手段

#### 意識向上（いしきこうじょう / security awareness）

- 意味：全員の注意をセキュリティに向け、危ないことに気づいて正しく動けるようにする活動
- ポイント：NIST では「awareness はトレーニングではない」と区別する。受け手は話を聞く側で、広く全員に届ける
- 例：ポスター、ログイン画面の注意書き、偉い人からの注意喚起メール、イベント

#### トレーニング（とれーにんぐ / security training）

- 意味：仕事に必要なセキュリティの知識と技能を身につけさせる、形の決まった学習
- ポイント：意識向上より学ぶ人が主体。役割ごと（管理者・開発者など）の内容にする（role-based training）。予告なしのフィッシングの模擬訓練など、実際の場面をまねた演習も含む

#### 物理アクセス制御（ぶつりあくせすせいぎょ / physical access control）

- 意味：建物・部屋・機器に入ってよい人を確かめ、出入りを制限し記録すること
- ポイント：ネットワーク機器に直接さわれると、コンソールからパスワードリカバリーなどができてしまう（#11）。鍵・カードリーダー・生体認証の読み取り機・警備員・入退室の記録・来訪者のエスコートなど
- 例：サーバー室はカードと暗証番号で入室し、記録を残す

#### アクセス制御の前室（あくせすせいぎょのぜんしつ / access control vestibule, mantrap）

- 意味：2つの扉が連動していて、間の小部屋で1人ずつ確かめてから奥へ通す仕組み
- ポイント：許された人のあとについて入るテールゲーティング（ピギーバッキング）を防ぐ。マントラップとも呼ばれる

## 20-5 パスワードとその代わり

### まとめ表

**認証の3つの要素**

| 要素 | 例 |
| :-: | :-: |
| 知っているもの（something you know） | パスワード、PIN |
| 持っているもの（something you have） | スマホのアプリ、ハードウェアトークン、スマートカード、証明書と秘密鍵の入った機器 |
| 本人の特徴（something you are） | 指紋、顔、虹彩 |

**NIST SP 800-63B-4 のパスワードの決まり（主なもの）**

| 項目 | 内容 |
| :-: | :-: |
| 長さ | 1要素だけで使うなら 15 文字以上。MFA の一部なら 8 文字以上でよい。64 文字以上まで入れられるようにする |
| 組み合わせの決まり | 「大文字・数字・記号を混ぜる」などの決まりは課さない |
| 定期的な変更 | 求めない。漏れた証拠があれば変えさせる |
| ブロックリスト | よく使われる・漏れたパスワードは使わせない |
| その他 | パスワードマネージャーと貼り付けを使えるようにする、失敗回数を制限する |

### パスワードの管理

#### パスワードの方針（ぱすわーどのほうしん / password policy）

- 意味：パスワードの長さ・使えないもの・変える時期・保管のしかたなどを決めた組織の決まり
- ポイント：NIST SP 800-63B-4 は、記号の混ぜ方などの組み合わせの決まりや定期的な変更を求めない。そのかわり長さ、ブロックリスト（よく使われる・漏れたパスワードを拒む）、失敗回数の制限を求める。機器の初期パスワードは最初に変える
- 例：「Password1」はブロックリストで拒まれる

#### パスワードマネージャー（ぱすわーどまねーじゃー / password manager）

- 意味：長くてばらばらのパスワードを作り、安全に保管して入力してくれるソフト
- ポイント：サービスごとに違うパスワードを使いやすくなり、ほかで漏れたパスワードを試される攻撃（クレデンシャルスタッフィング）に強くなる。NIST は貼り付けや自動入力を許すよう求めている

### パスワードの代わりと組み合わせ

#### 多要素認証（たようそにんしょう / multifactor authentication, MFA）

- 意味：知っているもの・持っているもの・本人の特徴のうち、違う種類の要素を2つ以上使う認証
- ポイント：パスワードを2つ使っても同じ種類なので MFA ではない。パスワードがフィッシングで盗まれても、もう1つの要素がなければ入れない。管理者などの特権アカウントには MFA が求められる
- 例：パスワード＋スマホのアプリに出る数字

#### ワンタイムパスワード（わんたいむぱすわーど / one-time password, OTP）

- 意味：1回だけ使える、その場で作られるパスワード。トークンやスマホのアプリが作る
- ポイント：アプリや機器を「持っているもの」として使う。盗まれても次の回には使えない。NIST では OTP の出力は短くしても6桁まで

#### 証明書（しょうめいしょ / digital certificate, public-key certificate）

- 意味：ある人や機器と、その公開鍵が結びついていることを、認証局（CA）が電子署名で保証したデータ
- ポイント：中身は X.509 の形で、発行した CA・持ち主（subject）・公開鍵・有効期限などが入る。秘密鍵を持っていることを示して認証するので、パスワードを送らずにすむ。秘密鍵を入れた機器やカードは「持っているもの」
- 語の意味：CA＝Certification Authority（認証局）

#### 生体認証（せいたいにんしょう / biometrics）

- 意味：指紋・顔・虹彩など、体や行動の特徴で本人を確かめる方法
- ポイント：「本人の特徴」の要素。パスワードと違い、漏れても取り替えにくい。NIST は生体認証を単独の認証手段とは認めず、持っているもの（機器）と組み合わせた MFA の一部としてだけ使うよう求めている

## 20-6 AAA と 802.1X

### まとめ表

**AAA の3つ**

| A | 問い | 例 |
| :-: | :-: | :-: |
| 認証（Authentication） | あなたはだれ？ | ユーザー名とパスワード、証明書 |
| 認可（Authorization） | 何をしてよい？ | 使えるコマンド、入れる VLAN、ACL |
| アカウンティング（Accounting） | 何をした？ | ログイン・ログアウトの時刻、実行したコマンド、通信量 |

**802.1X の3つの役**

| 役 | だれ | 何をする |
| :-: | :-: | :-: |
| サプリカント | PC などの端末（のソフト） | 自分の ID と資格情報を出す |
| オーセンティケーター | スイッチ・無線 AP | 中継役。認証が済むまでポートを閉じる |
| 認証サーバー | RADIUS サーバー | 本当に確かめ、結果（許可・拒否・VLAN など）を返す |

### AAA の考え方

#### 認証（にんしょう / authentication）

- 意味：相手が名乗ったとおりの本人かどうかを確かめること
- ポイント：「だれ？」。認可・アカウンティングの前に来る。ユーザー名とパスワード、証明書、MFA などで行う

#### 認可（にんか / authorization）

- 意味：認証された相手に、何をしてよいか（使えるコマンド・サービス・ネットワーク）を決めること
- ポイント：「何をしてよい？」。認証が済んでも、何でもできるわけではない。TACACS+ はコマンドごとに認可でき、RADIUS は認証の答えの中に認可の情報（VLAN など）を入れる
- 例：一般の担当は show だけ、管理者は設定もできる

#### アカウンティング（あかうんてぃんぐ / accounting）

- 意味：だれが、いつ、何をしたかを記録し、サーバーへ送ること
- ポイント：「何をした？」。監査（あとから調べる）や課金に使う。記録には利用者・開始と終了の時刻・実行したコマンド・パケット数やバイト数などが入る

#### ローカル認証とサーバー認証（ろーかるにんしょう と さーばーにんしょう / local and server-based AAA）

- 意味：ローカル認証は機器ごとに作ったユーザー（username）で確かめる方法。サーバー認証は TACACS+ や RADIUS のサーバーにユーザーをまとめて確かめる方法
- ポイント：機器が多いとローカルではユーザーの追加・削除が大変で、記録も機器ごとにばらばら。サーバーにまとめると一か所で管理でき、記録も集まる。サーバーが落ちたときに備えて、メソッドリストの最後に local を置く（#11）
- 例：`aaa authentication login default group tacacs+ local`

### ポートで利用者を確かめる

#### 802.1X（はちまるにーてんいちえっくす / IEEE 802.1X port-based authentication）

- 意味：スイッチのポートや無線につないだ端末を、使わせる前に認証する仕組み
- ポイント：認証が済むまで、ポートは EAPOL・CDP・STP などしか通さない（unauthorized）。認証が済むとふつうの通信が通る（authorized）。認証サーバーは RADIUS（Catalyst 9300 では TACACS+ は 802.1X に使えない）。初期では無効
- 例：

```
aaa new-model
aaa authentication dot1x default group radius
dot1x system-auth-control
interface g1/0/2
 switchport mode access
 authentication port-control auto
 dot1x pae authenticator
```

#### サプリカント・オーセンティケーター・認証サーバー（さぷりかんと・おーせんてぃけーたー・にんしょうさーばー / supplicant, authenticator, authentication server）

- 意味：802.1X に出てくる3つの役。サプリカントは認証を受ける端末、オーセンティケーターは間に立つスイッチや AP、認証サーバーは本当に確かめる RADIUS サーバー
- ポイント：スイッチ（オーセンティケーター）は自分で判断せず、端末と認証サーバーの間で EAP のやりとりを中継する。端末とスイッチの間は EAPOL、スイッチとサーバーの間は RADIUS で運ぶ

#### EAP と EAPOL（いーぷ と いーぽる / Extensible Authentication Protocol, EAP over LAN）

- 意味：EAP はいろいろな認証方法（パスワード・証明書など）を載せられる共通の認証の枠組み。EAPOL は EAP を LAN のフレームで運ぶ形
- ポイント：EAP は方法そのものではなく「入れ物」。どの方法を使うかで、パスワード・証明書などが選べる。認証前のポートでも EAPOL は通る
- 語の意味：Extensible＝広げられる／Authentication Protocol＝認証のプロトコル／over LAN＝LAN の上で

### 20-5 パスワードとその代わり

#### 問 ccna-20-o21

- 問：NIST SP 800-63B-4 のパスワードについての決まりとして正しいものはどれか。
- ア：大文字・数字・記号を必ず混ぜさせる
- イ：90日ごとに必ず変えさせる
- ウ：よく使われる・漏れたパスワードの一覧（ブロックリスト）と比べ、当てはまれば拒む
- エ：8文字より長いパスワードは受け付けない
- 正解：ウ
- 解説：NIST は組み合わせの決まりや定期的な変更を求めず、長さ・ブロックリスト・失敗回数の制限を求める。64文字以上まで入れられるようにする。
- アの意味：組み合わせの決まりは課さないとしている。
- イの意味：定期的な変更は求めない（漏れた証拠があれば変えさせる）。
- ウの意味：正しい。
- エの意味：逆。長いパスワードを許すよう求めている。
- 出典：オリジナル問題（根拠：NIST SP 800-63B-4 3.1.1.2（SHALL NOT impose other composition rules／SHALL NOT require subscribers to change passwords periodically／SHALL compare the prospective secret against a blocklist／SHOULD permit a maximum password length of at least 64 characters））

#### 問 ccna-20-o22

- 問：多要素認証（MFA）になっている組み合わせはどれか。
- ア：パスワード＋秘密の質問の答え
- イ：パスワード＋スマホのアプリに出るワンタイムパスワード
- ウ：パスワードを2回入力する
- エ：PIN＋パスワード
- 正解：イ
- 解説：MFA は違う種類の要素（知っているもの・持っているもの・本人の特徴）を2つ以上使う。イは知っているもの＋持っているもの。
- アの意味：どちらも知っているもの。
- イの意味：正しい。
- ウの意味：同じ要素を2回使っているだけ。
- エの意味：どちらも知っているもの。
- 出典：オリジナル問題（根拠：NIST SP 800-53 Rev. 5 IA-2(1)（Multi-factor authentication requires the use of two or more different factors … something you know …, something you have …, or something you are））

#### 問 ccna-20-o23

- 問：指紋や顔で本人を確かめる方法は、認証の3つの要素のどれにあたるか。
- ア：知っているもの
- イ：持っているもの
- ウ：本人の特徴
- エ：どれにもあたらない
- 正解：ウ
- 解説：生体認証は「本人の特徴（something you are）」。NIST は生体認証を持っているもの（機器）と組み合わせた MFA の一部としてだけ使うよう求めている。
- アの意味：パスワードや PIN。
- イの意味：トークン、スマホ、スマートカード。
- ウの意味：正しい。
- エの意味：3つの要素の1つにあたる。
- 出典：オリジナル問題（根拠：NIST SP 800-63B-4 3.2.3（Biometrics SHALL only be used as part of multi-factor authentication with a physical authenticator）・2.2（the biometric match serves as "something you are"））

#### 問 ccna-20-o24

- 問：デジタル証明書の説明として正しいものはどれか。
- ア：持ち主と公開鍵の結びつきを、認証局（CA）が署名して保証したデータ
- イ：持ち主の秘密鍵をそのまま書いて配るデータ
- ウ：パスワードを平文で保存したファイル
- エ：RADIUS サーバーの IP アドレスの一覧
- 正解：ア
- 解説：証明書（X.509）には発行者の CA・持ち主・公開鍵・有効期限などが入り、CA が署名する。認証では秘密鍵を持っていることを示すので、パスワードを送らずにすむ。
- アの意味：正しい。
- イの意味：秘密鍵は配らない。証明書に入るのは公開鍵。
- ウの意味：証明書ではない。
- エの意味：関係ない。
- 出典：オリジナル問題（根拠：RFC 4949「public-key certificate」（A digital certificate that binds a system entity's identifier to a public key value … digitally signed）・「certification authority」／RFC 5280 4.1（issuer・validity・subject・subjectPublicKeyInfo））

#### 問 ccna-20-o25

- 問：フィッシングでパスワードを盗まれても、攻撃者がログインしにくくなる対策として最も効果があるものはどれか。

- ウの意味：むしろ危ない。

### 20-6 AAA と 802.1X

#### 問 ccna-20-o26

- 問：AAA のうち「ログインした管理者が、どのコマンドを使ってよいか」を決めるのはどれか。

- イ：認可

#### 問 ccna-20-o28

- 問：802.1X で、スイッチ（またはアクセスポイント）が受け持つ役はどれか。

#### 問 ccna-20-o29
