## 14-1 OSPF のしくみと設定

### まとめ表

**OSPF の基本の値**

| 項目 | 値 |
| :-: | :-: |
| 種類 | リンクステート型の IGP（1つの組織の中で使う） |
| 運ぶもの | IP に直接のる（プロトコル番号 89） |
| AD | 110 |
| メトリック | コスト（基準の帯域 ÷ インタフェースの帯域、基準の初期値は 100 Mbps） |
| 全 OSPF ルーター宛て | 224.0.0.5 |
| DR・BDR 宛て | 224.0.0.6 |
| CCNA の範囲 | シングルエリア（エリア 0 だけ）の OSPFv2 |

**有効にする2つの書き方**

| 書き方 | 例 | 特徴 |
| :-: | :-: | :-: |
| network コマンド | router ospf 1 → network 10.1.12.0 0.0.0.255 area 0 | ワイルドカードマスクで、当てはまるインタフェースをまとめて有効にする |
| インタフェースのコマンド | interface Gi0/1 → ip ospf 1 area 0 | 1つのインタフェースだけを有効にする |

### しくみ

#### OSPF（おーえすぴーえふ / Open Shortest Path First）

- 意味：ルーターどうしがリンクの状態（LSA）を交換して同じ地図（LSDB）を持ち、それぞれが最短の道を計算するルーティングプロトコル
- ポイント：リンクステート型。AD は 110、メトリックはコスト。RIP（ホップ数）と違い、帯域を見て道を選ぶ。CCNA の出題範囲はシングルエリアの OSPFv2（IPv4 用）
- 例：`O 10.1.30.0/24 [110/3] via 10.1.12.2, 00:05:12, Gi0/1`
- 語の意味：Open＝公開の（標準）／Shortest Path First＝最短の道を先に（SPF の計算）

#### LSA（えるえすえー / Link-State Advertisement）

- 意味：ルーターが「自分のリンクとその状態・コスト」を知らせる情報の単位
- ポイント：エリアの中のすべてのルーターに配られる（フラッディング）。ルーターはこれを集めて LSDB を作る
- 語の意味：Link-State＝リンクの状態／Advertisement＝広告（知らせ）

#### LSDB（えるえすでぃーびー / Link-State Database）

- 意味：集めた LSA をまとめた、ネットワークの地図にあたるデータベース
- ポイント：同じエリアのルーターは同じ LSDB を持つ。隣接（Full）は、相手と LSDB をそろえ終わった状態
- 例：`show ip ospf database`
- 語の意味：Database＝データベース

#### SPF アルゴリズム（えすぴーえふあるごりずむ / Shortest Path First algorithm）

- 意味：LSDB をもとに、自分を根にして各宛先までのコストの合計が最小になる道を計算する方法。ダイクストラ法とも呼ぶ
- ポイント：各ルーターが自分で計算する。計算した結果のうち一番良い道が、ルーティングテーブルに O の経路として入る

#### エリアとバックボーンエリア（えりあとばっくぼーんえりあ / area, backbone area 0）

- 意味：LSA を配る範囲で区切ったルーターのまとまり。エリア 0 はバックボーン（中心）のエリア
- ポイント：CCNA で扱うのは、全部のルーターがエリア 0 にいるシングルエリアの OSPF。ネイバーになるには、向かい合うインタフェースのエリア番号が同じでなければならない

### 設定のコマンド

#### router ospf（るーたーおーえすぴーえふ / router ospf process-id）

- 意味：OSPF のプロセスを作り、ルーター設定モードに入るコマンド。後ろの数字はプロセス ID
- ポイント：プロセス ID はそのルーターの中だけの番号（1〜65535）で、相手と同じでなくてもネイバーになれる。エリア番号とは別物
- 例：`R1(config)# router ospf 1`

#### network area（ねっとわーくえりあ / network ip-address wildcard-mask area area-id）

- 意味：アドレスとワイルドカードマスクに当てはまるインタフェースで OSPF を有効にし、エリアを決めるコマンド
- ポイント：マスクは 0.0.0.255 のようなワイルドカード（0＝見る、1＝見ない）。インタフェースのプライマリのアドレスが当てはまれば有効になり、そのネットワークが広告される。0.0.0.0 にすると1つのアドレスだけに当てはまる
- 例：`network 10.1.12.0 0.0.0.255 area 0`／`network 10.1.12.1 0.0.0.0 area 0`

#### ip ospf area（あいぴーおーえすぴーえふえりあ / ip ospf process-id area area-id）

- 意味：インタフェースの設定モードで、そのインタフェースだけ OSPF を有効にするコマンド
- ポイント：network コマンドと同じ働きを、インタフェースごとに書く。ワイルドカードを計算しなくてよい
- 例：`R1(config-if)# ip ospf 1 area 0`

#### passive-interface（ぱっしぶいんたふぇーす / passive-interface）

- 意味：指定したインタフェースから Hello を送らないようにするコマンド。そのインタフェースのネットワークは広告されるが、ネイバーはできない
- ポイント：PC しかつながっていない LAN 側に使う（不要な Hello を出さない・知らないルーターとネイバーにならない）。ルーターどうしのリンクに付けるとネイバーができなくなる
- 例：`R1(config-router)# passive-interface GigabitEthernet0/2`

#### default-information originate（でふぉるといんふぉめーしょんおりじねーと / default-information originate）

- 意味：自分が持っているデフォルトルートを、OSPF でほかのルーターに配るコマンド
- ポイント：ふつうは自分のテーブルにデフォルトルートがあるときだけ配る（always を付けると無くても配る）。受け取った側では O*E2 0.0.0.0/0 と表示される
- 例：`ip route 0.0.0.0 0.0.0.0 203.0.113.1` ＋ `default-information originate`

#### OSPF のコスト（おーえすぴーえふのこすと / OSPF cost）

- 意味：インタフェースごとの値。初期値は「基準の帯域 ÷ インタフェースの帯域」で、経路のメトリックは出ていくインタフェースのコストの合計
- ポイント：ip ospf cost で直接決めるか、auto-cost reference-bandwidth で基準を変える。基準が初期の 100 Mbps のままだと、100 Mbps 以上はすべて 1
- 例：`ip ospf cost 50`／`auto-cost reference-bandwidth 10000`

## 14-2 ネイバーと隣接

### まとめ表

**ネイバーの状態（show ip ospf neighbor の State）**

| 状態 | 意味 |
| :-: | :-: |
| Down | Hello をまだ受け取っていない |
| Init | 相手の Hello を受け取ったが、その中に自分のルーター ID がない |
| 2-Way | 相手の Hello に自分のルーター ID がある（両方向の確認ができた）。ここで DR・BDR を選ぶ |
| ExStart | DBD の交換の準備。主と従を決める |
| Exchange | DBD（LSDB の目次）を交換する |
| Loading | 足りない LSA を要求して受け取る |
| Full | LSDB がそろった。隣接ができた |

**ネイバーになるために一致が必要なもの**

| 項目 | 確かめるコマンド |
| :-: | :-: |
| エリア番号 | show ip ospf interface |
| サブネットとマスク | show interfaces |
| Hello・Dead の間隔 | show ip ospf interface |
| エリアの種類（stub など） | show ip ospf |
| 認証 | show running-config |
| ルーター ID が違うこと | show ip ospf |
| MTU（合わないと ExStart/Exchange で止まる） | show interfaces |
| ネットワークタイプ（合わないと問題が起きる） | show ip ospf interface |

### Hello とタイマー

#### Hello パケット（はろーぱけっと / hello packet）

- 意味：OSPF のルーターが定期的に送る、ネイバーを見つけて生きていることを知らせるパケット。224.0.0.5 宛てに送る
- ポイント：中にエリア番号・Hello と Dead の間隔・マスク・優先度・DR と BDR・見えているネイバーのルーター ID などが入る。これらの一部が相手と合わないとネイバーにならない
- 例：`ping 224.0.0.5` で、OSPF の Hello の宛先に届くかを確かめられる

#### Hello 間隔（はろーかんかく / hello interval）

- 意味：Hello を送る間隔。イーサネット（broadcast）やポイントツーポイントの初期値は 10 秒
- ポイント：ip ospf hello-interval で変える。同じネットワークのルーターどうしで同じ値でなければならない
- 例：`ip ospf hello-interval 5`

#### Dead 間隔（でっどかんかく / dead interval）

- 意味：この時間 Hello が届かなければ、ネイバーが落ちたとみなす時間。初期値は Hello 間隔の 4 倍（イーサネットなら 40 秒）
- ポイント：ip ospf dead-interval で変える。これも相手と同じ値でなければならない。Hello 間隔だけ変えると、Dead 間隔も 4 倍に合わせて変わる
- 例：`ip ospf dead-interval 20`

#### 224.0.0.5 と 224.0.0.6（にーにーよん・れい・れい・ご / AllSPFRouters, AllDRouters）

- 意味：224.0.0.5 は「全部の OSPF ルーター」宛て、224.0.0.6 は「DR と BDR」宛てのマルチキャストのアドレス
- ポイント：Hello は 224.0.0.5。イーサネットで DROTHER が変化を知らせるときは 224.0.0.6（DR と BDR だけ）に送り、DR が 224.0.0.5 で全員に配る
- 語の意味：AllSPFRouters＝全 SPF ルーター／AllDRouters＝全 DR

### ネイバーの状態

#### ネイバーと隣接（ねいばーとりんせつ / neighbor, adjacency）

- 意味：ネイバー＝Hello を交換して互いを見つけた相手（2-Way まで）。隣接＝さらに LSDB を交換してそろえた相手（Full）
- ポイント：イーサネットでは、DROTHER どうしはネイバーのまま（2-Way）で、隣接になるのは DR と BDR とだけ。ポイントツーポイントでは相手と必ず隣接になる

#### Init 状態（いにっとじょうたい / Init state）

- 意味：相手の Hello は届いたが、その Hello の中に自分のルーター ID がまだ入っていない状態
- ポイント：ここで止まるなら、相手には自分の Hello が届いていない（片方向だけ届いている）。ACL などで片方向が止められていないかを見る

#### 2-Way 状態（つーうぇいじょうたい / 2-Way state）

- 意味：相手の Hello に自分のルーター ID が入っていて、両方向の通信が確認できた状態。この段階の終わりに DR と BDR を選ぶ
- ポイント：イーサネットで DROTHER どうしが 2-Way のままなのは正常。ポイントツーポイントで 2-Way のまま止まるのは問題
- 例：`FULL/DR`・`FULL/BDR`・`2WAY/DROTHER`

#### ExStart と Exchange（えくすすたーととえくすちぇんじ / ExStart, Exchange state）

- 意味：ExStart＝DBD を交換するために主と従を決める状態（ルーター ID が大きいほうが主）。Exchange＝DBD（LSDB の目次）を交換する状態
- ポイント：ここで止まるのはふつうではない。よくある原因は MTU の不一致（大きい DBD が相手に捨てられる）
- 語の意味：DBD＝Database Description（データベースの説明）

#### Loading と Full（ろーでぃんぐとふる / Loading, Full state）

- 意味：Loading＝足りない LSA を要求（LSR）して受け取る（LSU）状態。Full＝LSDB がそろい、隣接ができた状態
- ポイント：Full がふつうの正しい状態。show ip ospf neighbor では FULL/DR・FULL/BDR・FULL/DROTHER・FULL/- のように、相手の役割と一緒に表示される

#### show ip ospf neighbor（しょーあいぴーおーえすぴーえふねいばー / show ip ospf neighbor）

- 意味：OSPF のネイバーの一覧を表示するコマンド。Neighbor ID・Pri・State・Dead Time・Address・Interface が出る
- ポイント：Neighbor ID は相手のルーター ID、Address は相手のインタフェースのアドレス。State の「/」の後ろは相手の役割（DR・BDR・DROTHER）
- 例：

```
Neighbor ID     Pri   State           Dead Time   Address         Interface
2.2.2.2           1   FULL/DR         00:00:35    10.1.1.2        Gi0/0
```

#### MTU の不一致（えむてぃーゆーのふいっち / MTU mismatch）

- 意味：向かい合うインタフェースの MTU（1回に送れる大きさ）が違うこと
- ポイント：OSPF は DBD に自分の MTU を入れる。大きい MTU の側が送った大きな DBD を小さい側が受け取れず、ExStart/Exchange で止まる。Hello は小さいのでネイバー自体は見える
- 例：一方が mtu 1500、もう一方が mtu 1450

## 14-3 ネットワークタイプと DR・BDR

### まとめ表

| 項目 | broadcast（イーサネットの初期値） | point-to-point |
| :-: | :-: | :-: |
| DR・BDR の選出 | する | しない |
| 隣接になる相手 | DR・BDR とだけ | 相手と必ず |
| Hello／Dead の初期値 | 10 秒／40 秒 | 10 秒／40 秒 |
| show ip ospf neighbor の State | FULL/DR・FULL/BDR・2WAY/DROTHER など | FULL/- |
| 変えるコマンド | ip ospf network broadcast | ip ospf network point-to-point |

**DR・BDR の選び方**

| 順番 | 決め方 |
| :-: | :-: |
| ① | インタフェースの優先度（ip ospf priority、初期値 1）が大きいほう |
| ② | 同じなら、ルーター ID が大きいほう |
| ― | 優先度 0 は DR にも BDR にもならない |
| ― | すでに DR がいれば、あとから優先度の大きいルーターが来ても交代しない |

### ネットワークタイプ

#### ブロードキャストネットワーク（ぶろーどきゃすとねっとわーく / broadcast network type）

- 意味：イーサネットのように、1つのセグメントに何台ものルーターがつながれるネットワークのタイプ。イーサネットの初期値
- ポイント：DR と BDR を選び、各ルーターは DR・BDR とだけ隣接になる。全員どうしが隣接になるより、交換する情報が少なくて済む
- 例：`Network Type BROADCAST, Cost: 1`

#### ポイントツーポイントネットワーク（ぽいんとつーぽいんとねっとわーく / point-to-point network type）

- 意味：相手が1台だけのリンクのタイプ。シリアル（HDLC・PPP）の初期値
- ポイント：DR・BDR を選ばず、相手と直接 Full になる。ルーター2台だけをつなぐイーサネットでも、ip ospf network point-to-point にすると選出を省いて早く隣接になれる。両側で同じタイプにそろえる
- 例：`R1(config-if)# ip ospf network point-to-point`

#### ip ospf network（あいぴーおーえすぴーえふねっとわーく / ip ospf network）

- 意味：インタフェースの OSPF のネットワークタイプを、初期値から変えるコマンド
- ポイント：CCNA で使うのは broadcast と point-to-point。向かい合うインタフェースでタイプが合わないと、隣接や経路の計算に問題が起きる
- 例：`ip ospf network point-to-point`

### DR と BDR

#### DR（でぃーあーる / Designated Router）

- 意味：ブロードキャストネットワークで、ほかの全ルーターと隣接になり、LSA の交換をまとめる代表のルーター
- ポイント：ルーター単位ではなく、セグメント（インタフェース）ごとに選ぶ。DR が変わると LSA を作り直すので、いったん決まった DR はなるべく変わらないようにできている
- 語の意味：Designated＝指名された／Router＝ルーター

#### BDR（びーでぃーあーる / Backup Designated Router）

- 意味：DR の予備。DR と同じくほかの全ルーターと隣接になっていて、DR が落ちるとすぐ DR になる
- ポイント：前もって隣接になっているので、DR が落ちても隣接を作り直さずに済む。BDR が DR になったあと、新しい BDR を選ぶ
- 語の意味：Backup＝予備

#### DROTHER（でぃーあーるあざー / DROTHER）

- 意味：DR でも BDR でもないルーター
- ポイント：DROTHER どうしは 2-Way（ネイバー）のままで、Full にならない。これは正常。DR や BDR から見ると、DROTHER は FULL/DROTHER と表示される
- 例：`3.3.3.3  1  2WAY/DROTHER  00:00:33  10.1.1.3  Gi0/0`

#### OSPF の優先度（おーえすぴーえふのゆうせんど / OSPF priority）

- 意味：DR・BDR の選出に使う、インタフェースごとの値。0〜255、初期値は 1
- ポイント：大きいほうが DR になる。同じならルーター ID の大きいほう。0 にすると DR にも BDR にもならない。ポイントツーポイントでは使わない
- 例：`ip ospf priority 100`／`ip ospf priority 0`

#### DR は交代しない（でぃーあーるはこうたいしない / non-preemptive DR election）

- 意味：すでに DR がいるセグメントに、優先度の大きいルーターがあとから加わっても、DR は交代しないこと
- ポイント：優先度を変えても、今の DR はそのまま。意図した DR にするには、今の DR・BDR の OSPF をやり直す（clear ip ospf process など）必要がある。だから本番の問題では「先に起動したルーター」が DR になっている場合がある

## 14-4 ルーター ID

### まとめ表

**ルーター ID の決まり方（上ほど優先）**

| 順番 | 決め方 |
| :-: | :-: |
| ① | router-id コマンドで書いた値 |
| ② | up しているループバックインタフェースの IP アドレスのうち、いちばん大きいもの |
| ③ | up している物理インタフェースの IP アドレスのうち、いちばん大きいもの |

### ルーター ID

#### ルーター ID（るーたーあいでぃー / router ID）

- 意味：OSPF のルーターを見分ける、IPv4 アドレスの形の 32 ビットの値
- ポイント：OSPF の中で一意でなければならない。同じルーター ID のルーターどうしは Hello を無視し合い、隣接にならない。DR・BDR の選出で優先度が同じときの決め手にもなる
- 例：`Routing Process "ospf 1" with ID 1.1.1.1`

#### router-id（るーたーあいでぃーこまんど / router-id command）

- 意味：ルーター ID を手で決めるルーター設定モードのコマンド
- ポイント：インタフェースのアドレスでなくてもよい（1.1.1.1 など）。すでにネイバーがいる OSPF で変えると、次の再起動か clear ip ospf process のあとで使われる
- 例：`R1(config-router)# router-id 1.1.1.1`

#### ループバックインタフェース（るーぷばっくいんたふぇーす / loopback interface）

- 意味：ルーターの中に作る仮想のインタフェース。自分で shutdown しない限り down しない
- ポイント：router-id がないとき、OSPF はループバックのアドレスを物理インタフェースより優先してルーター ID にする（ループバックが何個もあれば、いちばん大きいもの）。落ちないので ID が安定する
- 例：`interface loopback 0` → `ip address 1.1.1.1 255.255.255.255`

#### clear ip ospf process（くりあーあいぴーおーえすぴーえふぷろせす / clear ip ospf process）

- 意味：OSPF のプロセスをやり直すコマンド。ネイバーはいったん切れて作り直される
- ポイント：ルーター ID を変えたときや、DR を選び直したいときに使う。本番の環境で使うと通信が一時的に止まる
- 例：`R1# clear ip ospf process`

### 14-2 ネイバーと隣接

#### 問 ccna-14-o09

- 問：R1 で show ip ospf neighbor を見ると、R2 が INIT のまま進まない。いちばん考えられることはどれか。
- ア：R1 の Hello は R2 に届いているが、R2 の Hello が R1 に届いていない
- イ：R2 の Hello は R1 に届いているが、R1 の Hello が R2 に届いていない（R2 の Hello に R1 のルーター ID がない）

- ウの意味：MTU の不一致は ExStart/Exchange で止まる。
- エの意味：DR の選出は 2-Way の終わりに行う。Init はその前。
- 出典：オリジナル問題（根拠：Cisco「Understand OSPF Neighbor States」Init（the receiving router ID was not included in the hello packet）／「Troubleshoot OSPF Neighbor Problems」Neighbor in Init State）

#### 問 ccna-14-o10

- 問：OSPF のネイバーの状態を、隣接ができるまでの順に並べたものはどれか。

- アの意味：正しい。
- イの意味：Init と 2-Way、ExStart と Exchange が逆。
- ウの意味：最初は Down。Loading は Exchange の後。
- エの意味：2-Way は ExStart の前。
- 出典：オリジナル問題（根拠：Cisco「Understand OSPF Neighbor States」（Down, Attempt, Init, 2-Way, Exstart, Exchange, Loading, Full））
