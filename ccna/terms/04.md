## 04-1 アドレスとマスクの形

### まとめ表

| プレフィックス長 | マスク | 1 つのブロックの大きさ | 使えるホスト |
| :-: | :-: | :-: | :-: |
| /24 | 255.255.255.0 | 256 | 254 |
| /25 | 255.255.255.128 | 128 | 126 |
| /26 | 255.255.255.192 | 64 | 62 |
| /27 | 255.255.255.224 | 32 | 30 |
| /28 | 255.255.255.240 | 16 | 14 |
| /29 | 255.255.255.248 | 8 | 6 |
| /30 | 255.255.255.252 | 4 | 2 |

### 32 ビットの住所

#### IPv4 アドレス（あいぴーぶいふぉーあどれす / IPv4 address）

- 意味：IP のネットワークで機器（インタフェース）を見分ける 32 ビットの番号。8 ビットずつ 4 つに分け、10 進数を点でつないで書く
- ポイント：1 つの区切り（オクテット）は 0〜255。マスクでネットワーク部とホスト部に分かれる（Doc 13788）。ルーターはつながるネットワークの数だけアドレスを持つ
- 例：172.16.81.100

#### オクテット（おくてっと / octet）

- 意味：8 ビットのまとまり。IPv4 アドレスは 4 オクテット
- ポイント：左のビットから 128・64・32・16・8・4・2・1 の重み。全部 1 なら 255、01000001 なら 64＋1＝65（Doc 13788）
- 例：10.1.23.19 ＝ 00001010.00000001.00010111.00010011

#### ネットワーク部とホスト部（ねっとわーくぶとほすとぶ / network portion and host portion）

- 意味：IPv4 アドレスのうち、どのネットワークかを表す前の部分と、そのネットワークの中のどの機器かを表す後ろの部分
- ポイント：マスクのビットが 1 の所がネットワーク部、0 の所がホスト部（Doc 13788）。ルーターで分かれた区間ごとに、ちがうネットワーク部が必要（IOS XE 17 CG）
- 例：10.20.15.1／255.0.0.0 → ネットワーク 10、ホスト 20.15.1

### マスクと書き方

#### サブネットマスク（さぶねっとますく / subnet mask）

- 意味：アドレスのどこまでがネットワーク部かを表す 32 ビットの値。前から 1 が続き、そのあと 0 が続く
- ポイント：アドレスとマスクを論理積（AND）すると、ネットワークのアドレスが出る。10 進で書くと、1 オクテットに入る値は 0・128・192・224・240・248・252・254・255 のどれか
- 例：255.255.240.0 ＝ 11111111.11111111.11110000.00000000

#### プレフィックス長（ぷれふぃっくすちょう / prefix length, CIDR notation）

- 意味：マスクの 1 の数を「/」のあとに書く表し方
- ポイント：CIDR の書き方で、0〜32 の数。172.16.0.0 255.255.0.0 は 172.16.0.0/16（RFC 4632 3.1）。マスクの 10 進とすぐ行き来できるようにする
- 例：255.255.255.224 ＝ /27

#### クラス（くらす / classful addressing, class A・B・C）

- 意味：昔の決め方で、最初のオクテットの値でネットワークの大きさを決めていたもの。A は 1〜127、B は 128〜191、C は 192〜223（D・E は特別用）
- ポイント：既定のマスク（ナチュラルマスク）は A＝255.0.0.0、B＝255.255.0.0、C＝255.255.255.0。今は CIDR になり、クラスという言葉はほとんど使われない（Doc 13788 の注）。RFC 1918 の 3 つのブロックの説明などに名前が残る
- 例：172.16.0.0 は昔の「クラス B」

#### CIDR（さいだー / Classless Inter-Domain Routing）

- 意味：クラスにしばられず、好きな長さのマスク（プレフィックス）でアドレスを割り当て、経路をまとめるやり方
- ポイント：アドレスを無駄なく使い、インターネットの経路表を小さくするために導入された（Doc 13788）。2 の累乗の大きさなら、どんなブロックでも表せる（RFC 4632）
- 語の意味：Classless＝クラスなし／Inter-Domain＝組織と組織の間の／Routing＝経路の選択

## 04-2 特別なアドレス

### まとめ表

| アドレス | 名前 | 使い方 |
| :-: | :-: | :-: |
| ホスト部が全部 0 | ネットワークアドレス | ネットワークそのもの。機器に付けない |
| ホスト部が全部 1 | ブロードキャストアドレス | そのネットワークの全員あて。機器に付けない |
| 127.0.0.0/8 | ループバック | 自分自身。外に出てはいけない |
| 169.254.0.0/16 | リンクローカル | DHCP がないとき（#03） |
| 255.255.255.255 | 限定ブロードキャスト | 自分のネットワークの全員。ルーターは越えない |
| 192.0.2.0/24 など | 文書用（TEST-NET） | 説明や例に使う |

### ネットワークの両端

#### ネットワークアドレス（ねっとわーくあどれす / network address, subnet address）

- 意味：ホスト部のビットをすべて 0 にしたアドレス。ネットワーク（サブネット）そのものを表す
- ポイント：機器には付けられない（ホスト部が全部 0 の値はネットワークアドレスと同じになるから）。ルーティングテーブルに載るのはこのアドレス
- 例：192.168.5.32/27

#### ブロードキャストアドレス（ぶろーどきゃすとあどれす / broadcast address, directed broadcast）

- 意味：ホスト部のビットをすべて 1 にしたアドレス。そのネットワークの全員あて
- ポイント：機器には付けられず、送信元にも使えない（RFC 1122 3.2.1.3 の (d)(e)）。10.255.255.255 あては 10.0.0.0 のネットワークの全員が受け取る（IOS XE 17 CG）。次のネットワークアドレスの 1 つ前
- 例：192.168.5.32/27 → 192.168.5.63

#### 使えるホストの数（つかえるほすとのかず / usable hosts, 2^h − 2）

- 意味：1 つのサブネットで機器に付けられるアドレスの数。ホスト部のビット数を h として 2^h − 2
- ポイント：2 を引くのは、全部 0（ネットワーク）と全部 1（ブロードキャスト）を使えないから。/27 なら h＝5 で 32−2＝30。/31 と /32 は例外（04-3）
- 例：/26 → 2^6 − 2 ＝ 62

### 決まった用途のアドレス

#### ループバックアドレス（るーぷばっくあどれす / loopback address, 127.0.0.0/8）

- 意味：機器が自分自身に送るためのアドレス。127 で始まる
- ポイント：機器の外に出てはいけない（RFC 1122）。ルーターの「interface Loopback0」（論理的なインタフェース）とは別の話なので注意。そちらはふつうのアドレスを /32 で付ける（Doc 13788）
- 例：127.0.0.1

#### 限定ブロードキャスト（げんていぶろーどきゃすと / limited broadcast, 255.255.255.255）

- 意味：全部のビットが 1 のアドレス。同じ物理ネットワークの全員が受け取る
- ポイント：ルーターはこれを外に転送しない。送信元には使えない（RFC 1122）。ネットワークごとのブロードキャスト（例 192.168.1.255）と区別する
- 例：DHCP の DISCOVER の宛先

#### 文書用アドレス（ぶんしょようあどれす / documentation address, TEST-NET）

- 意味：説明書や例に使うために取ってあるアドレス。192.0.2.0/24、198.51.100.0/24、203.0.113.0/24
- ポイント：本物のネットワークで使わないので、例を書くときにぶつからない（RFC 5737）。プライベートアドレスとは別
- 例：203.0.113.10（TEST-NET-3）

## 04-3 サブネットの切り方

### まとめ表

| 手順 | やること | 例：192.168.5.0/24 を 5 つ以上に |
| :-: | :-: | :-: |
| ① | 必要なサブネットの数から借りるビット s を決める（2^s ≥ 数） | 5 つ → s＝3（8 つ） |
| ② | 新しいプレフィックス長 ＝ 元＋s | /24＋3 ＝ /27 |
| ③ | ブロックの大きさ ＝ 256 − マスクの値 | 256 − 224 ＝ 32 |
| ④ | ブロックごとに並べる | .0・.32・.64・.96… |
| ⑤ | 各ブロックの最初＝ネットワーク、最後＝ブロードキャスト | .32〜.63、使えるのは .33〜.62 |

### 分け方

#### サブネット化（さぶねっとか / subnetting）

- 意味：1 つのネットワークを、マスクを長くして小さなネットワーク（サブネット）に分けること
- ポイント：ホスト部の前のほうのビットを借りてサブネットの番号にする。借りるほどサブネットは増え、1 つのサブネットのホストは減る（Doc 13788）
- 例：192.168.5.0/24 → /27 で 8 つ（それぞれ 30 台）

#### サブネットの数（さぶねっとのかず / number of subnets, 2^s）

- 意味：借りたビット数を s として、できるサブネットの数は 2^s
- ポイント：172.16.0.0/16 を /21 にすると s＝5 で 32 個、それぞれ 2^11−2＝2046 台（Doc 13788）。「5 つ必要」なら 2^2＝4 では足りず s＝3
- 例：/24 → /26 は s＝2 で 4 つ

#### ブロックの大きさ（ぶろっくのおおきさ / block size, magic number）

- 意味：マスクが 255 でない最後のオクテットで、256 からその値を引いた数。サブネットはこの間隔で並ぶ
- ポイント：/27（224）なら 32 ごと、/28（240）なら 16 ごと。アドレスがどのブロックに入るかで、ネットワーク・ブロードキャストがすぐ分かる（計算の近道として Claude がまとめた）
- 例：192.168.5.37/27 → 32 ごとなので .32〜.63

#### 論理積（ろんりせき / bitwise AND）

- 意味：アドレスとマスクをビットごとにかけ合わせ、両方 1 の所だけ 1 にする計算。ネットワークアドレスが出る
- ポイント：マスクが 1 の所のビットはそのまま、0 の所は 0 にする（Doc 13788）。2 台の結果が同じなら同じサブネット
- 例：172.16.17.30／255.255.240.0 → 172.16.16.0

### 大きさを変える・特別な長さ

#### VLSM（ぶいえるえすえむ / Variable Length Subnet Mask）

- 意味：サブネットごとにちがう長さのマスクを使い、必要な台数に合わせて切ること
- ポイント：すべて同じマスクだと、小さなサブネットでアドレスが余る。大きいサブネットから順に割り当てると重ならない（Doc 13788）。2 台なら /30、7 台なら /28（/29 は 6 台しかない）
- 語の意味：Variable＝変えられる／Length＝長さ／Subnet Mask＝サブネットマスク

#### サブネットゼロ（さぶねっとぜろ / subnet zero, ip subnet-zero）

- 意味：サブネットの番号のビットが全部 0 のサブネット（例 /27 の .0）
- ポイント：昔は使えない機器があった。Cisco の機器は `ip subnet-zero` で使える。使えばサブネットが 1 つ増える（Doc 13788・IOS XE 17 CG）
- 例：192.168.5.0/27

#### /30 と /31（すらっしゅさんじゅうとさんじゅういち / /30 and /31 point-to-point）

- 意味：2 台だけをつなぐリンク用の短いサブネット。/30 はアドレス 4 つで使えるのは 2 つ、/31 はアドレス 2 つを両方使う
- ポイント：1 対 1 のリンクにブロードキャストもネットワークアドレスもいらないので、/31 ならアドレスを半分にできる（RFC 3021）。Ethernet に /31 を付けると IOS は注意のメッセージを出す（Doc 13788）
- 例：192.168.1.0/31 → .0 と .1 を両端に

#### /32（すらっしゅさんじゅうに / host route, /32）

- 意味：マスク 255.255.255.255。アドレスが 1 つだけのサブネット
- ポイント：リンクには使えない（リンクには 2 つ以上のアドレスが要る）。ほかとつながらないループバックインタフェースに使う（Doc 13788）
- 例：interface Loopback0 → ip address 192.168.2.1 255.255.255.255

## 04-4 プライベートアドレス

### まとめ表（RFC 1918）

| 範囲 | プレフィックス | 昔のクラスでいうと |
| :-: | :-: | :-: |
| 10.0.0.0〜10.255.255.255 | 10/8 | クラス A が 1 つ |
| 172.16.0.0〜172.31.255.255 | 172.16/12 | クラス B が 16 個 |
| 192.168.0.0〜192.168.255.255 | 192.168/16 | クラス C が 256 個 |

### 3 つのブロック

#### プライベートアドレス（ぷらいべーとあどれす / private address, RFC 1918）

- 意味：組織の中だけで使うために取ってあるアドレス。10/8、172.16/12、192.168/16 の 3 つ
- ポイント：IANA や登録機関に頼まずに、どの組織でも使える。組織の中でだけ一意で、インターネットでは意味を持たない（RFC 1918 3）
- 例：家庭や会社の LAN の 192.168.1.0/24

#### 172.16.0.0/12（いちななにーてんいちろくすらっしゅじゅうに / 172.16/12）

- 意味：プライベートアドレスのうち、172.16.0.0〜172.31.255.255 の範囲
- ポイント：/12 なので 2 番目のオクテットは 16〜31。172.15.x.x や 172.32.x.x はプライベートではない。3 つの中で範囲の取り違えがいちばん起きやすい
- 例：172.20.1.1 はプライベート、172.32.0.1 はちがう

#### グローバルアドレス（ぐろーばるあどれす / public address, globally unique address）

- 意味：インターネット全体で一意の、登録機関から割り当てられるアドレス
- ポイント：外とつなぐためのアドレスとして、RFC 1918 のブロックが割り当てられることはない。パブリックなホストは外のパブリックなホストと直接やりとりできる（RFC 1918 3）
- 例：203.0.113.10 ※実際は文書用アドレスで例示

### なぜ必要か

#### プライベートアドレスが必要な理由（ひつようなりゆう / need for private addressing）

- 意味：世界で一意のアドレスがなくなる心配と、インターネットの経路が増えすぎる問題への対策
- ポイント：外と直接つながる必要のない機器にはプライベートアドレスを使えば、一意のアドレスを使わずに済む（RFC 1918 2・3）。たくさんの組織が同じ範囲を重ねて使える
- 例：社内の 1000 台は 10.0.0.0/8、外に出る出口だけグローバル

#### プライベートアドレスと外の通信（そとのつうしん / private hosts and external access）

- 意味：プライベートアドレスの機器は、そのままでは組織の外のホストと IP で通信できない
- ポイント：外のサービスを使うには、中継するゲートウェイ（今はふつう NAT）を通す（RFC 1918 3）。NAT のくわしいしくみは #16
- 例：社内 PC 10.1.1.5 → ルーターの NAT → 外へ

#### 経路のフィルター（けいろのふぃるたー / filtering of private routes）

- 意味：プライベートアドレスの経路やパケットを、組織と組織の間のリンクに流さないこと
- ポイント：プライベートアドレスには世界での意味がないので、その経路を外に広告せず、送信元・宛先がプライベートのパケットも転送しない。ISP のルーターはその経路を捨てるよう設定する（RFC 1918 3）

#### シェアードアドレス（しぇあーどあどれす / shared address space, 100.64.0.0/10）

- 意味：ISP が、キャリアグレード NAT（CGN）と利用者の機器の間で使うために取ってあるアドレス
- ポイント：RFC 1918 のプライベートアドレスとは別のブロック。ISP のネットワークの中だけで使う（RFC 6598）。169.254/16（リンクローカル）もプライベートアドレスではない
- 例：100.64.0.1

## 04-5 IOS での設定と確認

### まとめ表

| コマンド | すること |
| :-: | :-: |
| `ip address 10.1.1.1 255.255.255.0` | インタフェースにアドレスとマスクを付ける |
| `no shutdown` | インタフェースを動かす |
| `ip address … secondary` | 同じインタフェースに 2 つめ以降のアドレスを足す |
| `ip subnet-zero` | サブネットゼロを使えるようにする |
| `show ip interface brief` | インタフェースごとのアドレスと状態の一覧 |

### 付ける

#### ip address コマンド（あいぴーあどれすこまんど / ip address）

- 意味：インタフェースに IPv4 アドレスとマスクを付けるコマンド。`ip address アドレス マスク`
- ポイント：マスクは 10 進（255.255.255.0）で書く。手順は interface → no shutdown → ip address（IOS XE 17 CG）。L3 スイッチでは SVI やルーテッドポートに付ける（#01）
- 例：`interface g0/0/0` → `ip address 192.168.10.1 255.255.255.0`

#### セカンダリアドレス（せかんだりあどれす / secondary IP address）

- 意味：1 つのインタフェースに、2 つめ以降のアドレス（別のサブネット）を足すこと
- ポイント：今のサブネットのアドレスを使い切ったとき、全部の機器のアドレスを変えずに、同じ区間へもう 1 つネットワークを足せる（IOS XE 17 CG）。`secondary` を付けないと、今のアドレスが置き換わる
- 例：`ip address 172.16.32.1 255.255.240.0 secondary`

#### サブネットの重なり（さぶねっとのかさなり / overlapping subnets）

- 意味：ちがうインタフェースに同じネットワーク（重なる範囲）を付けてしまうこと
- ポイント：ルーターがどちらのインタフェースに送ればよいか決められない。IOS は IP ルーティングが有効なとき、同じネットワークを 2 つ以上のインタフェースに付けさせない（IOS XE 17 CG）
- 例：g0/0 と g0/1 にどちらも 172.31.32.0/24 → 拒否される

### 確かめる

#### show ip interface brief（しょーあいぴーいんたふぇーすぶりーふ / show ip interface brief）

- 意味：インタフェースごとに、IP アドレスと状態（Status）・プロトコル（Protocol）を 1 行ずつ表示するコマンド
- ポイント：Status は up・down・administratively down。アドレスの付け忘れ（unassigned）や shutdown のままを見つけるのに使う。マスクは出ないので、マスクを見るなら `show ip interface` や `show running-config`
- 例：`GigabitEthernet0/0/0  192.168.10.1  YES manual up  up`

#### /31 の注意メッセージ（ちゅういめっせーじ / /31 warning on broadcast interface）

- 意味：Ethernet のような、たくさんの機器がつながりうるインタフェースに /31 を付けたときに IOS が出す注意
- ポイント：「% Warning: use /31 mask on non point-to-point interface cautiously」。その区間に必要なアドレスが 2 つだけなら使える（Doc 13788）

- エ：経路を捨てる（フィルターする）。それをルーティングプロトコルのエラーとは扱わない
- 正解：エ
- 解説：プライベートアドレスには世界での意味がないので、組織の間のリンクに経路を流さない。ISP のルーターは捨てるよう設定する。
- アの意味：広告してはいけない。
- イの意味：使ってはいけない。
- ウの意味：そのような決まりはない。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：RFC 1918 3（routing information about private networks shall not be propagated on inter-enterprise links … Internet service providers, are expected to be configured to reject (filter out) routing information about private networks … the rejection shall not be treated as a routing protocol error））

#### 問 ccna-04-o24

- 問：RFC 1918 の 172.16.0.0/12 は、昔のクラスでいうとどれに当たるか。
- ア：クラス A のネットワーク 1 つ
- イ：クラス C のネットワークが 256 個続いたもの
- ウ：クラス B のネットワーク 1 つ
- エ：クラス B のネットワークが 16 個続いたもの
- 正解：エ
- 解説：172.16〜172.31 の 16 個のクラス B。10/8 はクラス A が 1 つ、192.168/16 はクラス C が 256 個。
- アの意味：10/8。
- イの意味：192.168/16。
- ウの意味：172.16.0.0/16 だけなら 1 つだが、/12 は 16 個。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：RFC 1918 3（the first block is nothing but a single class A network number, while the second block is a set of 16 contiguous class B network numbers, and third block is a set of 256 contiguous class C network numbers））

### 04-5 IOS での設定と確認

#### 問 ccna-04-o25

- 問：Cisco IOS のルーターのインタフェースに 192.168.10.1/24 を付けるコマンドとして正しいものはどれか。

#### 問 ccna-04-o26

- 問：あるセグメントのアドレスを使い切ったので、全部の機器のアドレスを変えずに、同じインタフェースへ別のサブネットを足したい。使うものはどれか。

#### 問 ccna-04-o27

- 問：IP ルーティングが有効なルーターで、g0/0 に 172.31.32.1/24 を付けたあと、g0/1 に 172.31.32.2/24 を付けようとした。どうなるか。

#### 問 ccna-04-o28

- 問：次の出力で、g0/0/1 が通信できない理由として最も考えられるものはどれか。

```
Router# show ip interface brief
Interface              IP-Address      OK? Method Status                Protocol
GigabitEthernet0/0/0   192.168.10.1    YES manual up                    up
GigabitEthernet0/0/1   10.1.1.1        YES manual administratively down down
```

#### 問 ccna-04-o29

- 問：ルーターの GigabitEthernet に `ip address 192.168.1.0 255.255.255.254` を入れたところ、注意のメッセージが出た。正しい説明はどれか。
- ア：Ethernet はたくさんの機器がつながりうるので注意を出す。その区間に必要なアドレスが 2 つだけなら使える

#### 問 ccna-04-o30

- 問：`ip subnet-zero` の働きとして正しいものはどれか。
- ア：サブネットの番号のビットが全部 0 のサブネットも使えるようにする
- イ：ホスト部が全部 0 のアドレスを機器に付けられるようにする
