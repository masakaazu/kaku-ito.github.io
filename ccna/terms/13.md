## 13-1 IPv4 のスタティックルート

### まとめ表

**ip route の形**

```
ip route 宛先のネットワーク マスク { ネクストホップ | 出口のインタフェース [ネクストホップ] } [AD]
```

| 種類（出題範囲 3.3） | 宛先とマスク | 例 |
| :-: | :-: | :-: |
| デフォルトルート | 0.0.0.0 0.0.0.0 | ip route 0.0.0.0 0.0.0.0 203.0.113.1 |
| ネットワークルート | ネットワークのアドレスとそのマスク | ip route 10.1.40.0 255.255.255.0 10.1.12.2 |
| ホストルート | 1台のアドレスと 255.255.255.255（/32） | ip route 10.1.40.10 255.255.255.255 10.1.13.3 |
| フローティングスタティック | どれでもよい。最後に AD を付ける | ip route 10.1.40.0 255.255.255.0 10.1.99.2 115 |

**行き先の書き方**

| 書き方 | 例 | 特徴 |
| :-: | :-: | :-: |
| ネクストホップだけ | … 10.1.12.2 | 再帰検索で出口を決める |
| 出口だけ | … Serial0/1/0 | ポイントツーポイント向け。イーサネットでは勧められない |
| 両方（完全指定） | … Gi0/1 10.1.12.2 | 出口がはっきり決まる。Cisco が勧める |

### コマンドと経路の種類

#### スタティックルート（すたてぃっくるーと / static route）

- 意味：管理者が ip route コマンドで手で書いた経路。コードは S、AD の初期値は 1
- ポイント：消すまで残る（no ip route で消す）。道が切れても自動で別の道に変わらない。出口が1つの小さな拠点や、デフォルトルートの設定によく使う
- 例：`ip route 10.1.40.0 255.255.255.0 10.1.12.2`

#### ip route（あいぴーるーと / ip route command）

- 意味：IPv4 のスタティックルートを作るグローバル設定モードのコマンド。宛先・マスク・行き先（ネクストホップか出口）の順に書き、最後に AD などを付けられる
- ポイント：マスクは /24 のような長さではなく 255.255.255.0 の形で書く（IPv6 の ipv6 route は /64 の形）。消すときは頭に no を付ける
- 例：`R1(config)# ip route 10.1.40.0 255.255.255.0 10.1.12.2`

#### ネットワークルート（ねっとわーくるーと / network route）

- 意味：あるネットワーク（サブネット）全体への経路。宛先にネットワークのアドレスとそのマスクを書く
- ポイント：宛先にはホストのアドレスではなく、ネットワークのアドレス（ホスト部が0）を書く
- 例：`ip route 192.168.50.0 255.255.255.0 10.1.12.2`

#### ホストルート（ほすとるーと / host route）

- 意味：1台の機器（1つのアドレス）だけへの経路。マスクは 255.255.255.255（/32）。IPv6 では /128
- ポイント：プレフィックスがいちばん長いので、ほかの経路より必ず優先される（最長一致）。特定のサーバーへの通信だけを別の道に通したいときに使う
- 例：`ip route 10.1.40.10 255.255.255.255 10.1.13.3`

#### デフォルトルート（スタティック）（でふぉるとるーと / static default route）

- 意味：宛先 0.0.0.0、マスク 0.0.0.0 で書くスタティックルート。テーブルのどの経路にも当てはまらない宛先を送る先になる
- ポイント：テーブルでは S* 0.0.0.0/0 と表示され、Gateway of last resort に行き先が出る。IPv6 では ::/0
- 例：`ip route 0.0.0.0 0.0.0.0 203.0.113.1`

### 行き先の書き方

#### ネクストホップ指定（ねくすとほっぷしてい / next-hop static route）

- 意味：行き先に次のルーターの IP アドレスだけを書くスタティックルート。出口はそのアドレスをテーブルで引き直して決める（再帰検索）
- ポイント：ネクストホップへ行く経路がないとテーブルに入らない。逆に、別の経路でネクストホップに届いてしまうと、つながっていなくても入り続ける（13-3 のトラブル）
- 例：`ip route 10.1.40.0 255.255.255.0 10.1.12.2`

#### 出口インタフェース指定（でぐちいんたふぇーすしてい / directly attached static route）

- 意味：行き先に自分の出口のインタフェースだけを書くスタティックルート。宛先は出口の先に直接つながっているものとして扱う
- ポイント：インタフェースが up のときだけテーブルに入る。テーブルでは is directly connected と表示される。シリアルなどポイントツーポイントなら問題ないが、イーサネットでは宛先ごとに ARP を出すことになるので勧められない
- 例：`ip route 10.1.40.0 255.255.255.0 Serial0/1/0`

#### 完全指定のスタティックルート（かんぜんしていのすたてぃっくるーと / fully specified static route）

- 意味：出口のインタフェースとネクストホップの両方を書くスタティックルート
- ポイント：イーサネットのように相手が何台もいる（マルチアクセス）出口で、次のルーターをはっきり決めるために使う。ネクストホップは指定した出口に直接つながっていなければならない。Cisco はイーサネットでは両方を書くことを勧めている
- 例：`ip route 10.1.40.0 255.255.255.0 GigabitEthernet0/1 10.1.12.2`

#### 再帰的なスタティックルート（さいきてきなすたてぃっくるーと / recursive static route）

- 意味：ネクストホップだけを書いたスタティックルートのこと。ネクストホップから出口を引き出す
- ポイント：ネクストホップが直接つながっていなくてもよい。テーブルの経路をたどって、直接つながった出口にたどり着けば有効になる
- 例：`ipv6 route 2001:DB8::/32 2001:DB8:3000::1`

### オプションと確かめ方

#### AD の指定（えーでぃーのしてい / distance）

- 意味：ip route の最後に数字を書いて、そのスタティックルートの AD を変えること。範囲は 1〜255、書かなければ 1
- ポイント：AD を大きくすると、ダイナミックルートに負ける予備の経路（フローティングスタティック）になる。255 にするとテーブルに入らない
- 例：`ip route 10.1.40.0 255.255.255.0 10.1.99.2 115`

#### permanent（ぱーまねんと / permanent）

- 意味：インタフェースが down になっても、そのスタティックルートをテーブルから消さないオプション
- ポイント：ふつうは出口が down になると経路は消える。permanent を付けると消えないので、予備の経路に切り替わらなくなる点に注意
- 例：`ip route 10.1.40.0 255.255.255.0 10.1.12.2 permanent`

#### name（ねーむ / name）

- 意味：スタティックルートに説明の名前を付けるオプション
- ポイント：経路の動きは変わらない。何本もあるときに、running-config で目的を見分けやすくするためのもの
- 例：`ip route 0.0.0.0 0.0.0.0 203.0.113.1 name TO-ISP`

#### show ip route static（しょーあいぴーるーとすたてぃっく / show ip route static）

- 意味：ルーティングテーブルのうち、スタティックルート（S）だけを表示するコマンド
- ポイント：設定しても表示されないなら、ネクストホップに届かない・出口が down・もっと AD の小さい経路がある、のどれかを疑う。設定そのものは show running-config | include ip route で見る
- 例：`S 10.1.40.0/24 [1/0] via 10.1.12.2`

## 13-2 IPv6 のスタティックルート

### まとめ表

| 項目 | IPv4 | IPv6 |
| :-: | :-: | :-: |
| 転送を有効にする | （ルーターは初めから有効） | ipv6 unicast-routing |
| コマンド | ip route 宛先 マスク 行き先 | ipv6 route 宛先/長さ 行き先 |
| デフォルトルート | 0.0.0.0 0.0.0.0 | ::/0 |
| ホストルート | 255.255.255.255（/32） | /128 |
| リンクローカルのネクストホップ | ― | 出口のインタフェースも必ず書く |
| 確かめる | show ip route static | show ipv6 route static |

### IPv6 の設定

#### ipv6 unicast-routing（あいぴーぶいろくゆにきゃすとるーてぃんぐ / ipv6 unicast-routing）

- 意味：ルーターが IPv6 のパケットを転送する（ルーターとして働く）ようにするグローバル設定コマンド
- ポイント：IPv6 のスタティックルートを書く前に必要。インタフェースに IPv6 アドレスを付けただけではルーターとして転送しない
- 例：`R1(config)# ipv6 unicast-routing`

#### ipv6 route（あいぴーぶいろくるーと / ipv6 route command）

- 意味：IPv6 のスタティックルートを作るコマンド。宛先は「プレフィックス/長さ」で書く
- ポイント：行き先の書き方は IPv4 と同じ3通り（ネクストホップだけ・出口だけ・両方）。最後に AD を付けられる
- 例：`ipv6 route 2001:DB8:40::/64 2001:DB8:12::2`

#### IPv6 のデフォルトルート（あいぴーぶいろくのでふぉるとるーと / IPv6 default route, ::/0）

- 意味：宛先 ::/0 のスタティックルート。どの経路にも当てはまらない IPv6 の宛先を送る先
- ポイント：「::/0」は 0.0.0.0/0 の IPv6 版。IPv4 のようにマスクを別に書かない
- 例：`ipv6 route ::/0 2001:DB8:FFFF::1`

#### IPv6 のホストルート（あいぴーぶいろくのほすとるーと / IPv6 host route, /128）

- 意味：1つの IPv6 アドレスだけへの経路。長さは /128
- ポイント：IPv4 の /32 にあたる。最長一致でいちばん優先される
- 例：`ipv6 route 2001:DB8:40::10/128 2001:DB8:13::3`

#### リンクローカルアドレスのネクストホップ（りんくろーかるのねくすとほっぷ / link-local next hop）

- 意味：ネクストホップに相手の fe80:: で始まるリンクローカルアドレスを使うこと
- ポイント：リンクローカルアドレスはどのリンクにも同じ範囲があり、アドレスだけではどのインタフェースの先か決まらない。だから出口のインタフェースを必ず一緒に書く（完全指定）。ネクストホップは隣のルーターでなければならない
- 例：`ipv6 route ::/0 GigabitEthernet0/0 FE80::1`

#### show ipv6 route static（しょーあいぴーぶいろくるーとすたてぃっく / show ipv6 route static）

- 意味：IPv6 のルーティングテーブルのうち、スタティックルートだけを表示するコマンド
- ポイント：IPv6 の表示では、[AD/メトリック] の次の行に via が出る（2行で1つの経路）
- 例：

```
S   2001:DB8:40::/64 [1/0]
     via 2001:DB8:12::2
```

## 13-3 フローティングスタティックとトラブル

### まとめ表

| 現象 | 原因 | 直し方 |
| :-: | :-: | :-: |
| 予備のスタティックがいつまでもテーブルに入らない | AD を 255 にした／本物より小さい AD にした | 本物より大きく 255 より小さい AD にする |
| 本線が切れても予備に切り替わらない | ネクストホップだけの経路が、別の経路（例 10.0.0.0/8）で再帰して生き残る | 出口のインタフェースも書く（完全指定） |
| スタティックがテーブルに入らない | ネクストホップに届く経路がない／出口が down | ネクストホップのアドレスと出口を確かめる |
| 出口だけのデフォルトルートで CPU と ARP 表が増える | イーサネットの出口だけを書いた | ネクストホップも書く |
| 戻りのパケットが届かない | 相手のルーターに戻りの経路がない | 両方向に経路を書く |

### 予備の経路

#### フローティングスタティックルート（ふろーてぃんぐすたてぃっくるーと / floating static route）

- 意味：AD を本物の経路より大きくしたスタティックルート。本物がある間はテーブルに入らず（浮いていて）、本物が消えたときだけ入る予備の経路
- ポイント：守りたい経路の AD より大きく、255 より小さい値にする。EIGRP（内部90）の予備なら 91 以上、OSPF（110）なら 111 以上、スタティック（1）どうしなら 2 以上。外部 EIGRP（170）にも負けたいなら 171 以上
- 例：`ip route 10.1.40.0 255.255.255.0 10.1.99.2 115`

#### AD 255 のスタティックルート（えーでぃーにひゃくごじゅうごのすたてぃっく / static route with distance 255）

- 意味：AD を 255 にしたスタティックルート。255 は「届かない」とみなされ、テーブルに一度も入らない
- ポイント：「いちばん弱い予備」のつもりで 255 にすると、予備として働かない。予備は 254 以下にする
- 例：`ip route 10.1.40.0 255.255.255.0 10.1.99.2 255`（入らない）

#### 本線の経路（ほんせんのけいろ / primary route）

- 意味：ふだん使う経路。フローティングスタティックが守る相手
- ポイント：ダイナミックルートでも、AD 1 のスタティックルートでもよい。本線が消える条件（出口が down・ネクストホップに届かない・ダイナミックで覚えなくなる）を満たしたときだけ予備に切り替わる
- 例：`ip route 10.1.40.0 255.255.255.0 Gi0/1 10.1.12.2`（本線）と `… Gi0/2 10.1.99.2 115`（予備）

### よくあるトラブル

#### 再帰による切り替えの失敗（さいきによるきりかえのしっぱい / recursive lookup keeps the primary route）

- 意味：ネクストホップだけの本線の経路が、本線のリンクが切れても、別の大きな経路（例 10.0.0.0/8）でネクストホップに届いてしまうためにテーブルに残り、予備に切り替わらないこと
- ポイント：スタティックルートは「ネクストホップへの経路がある限り」テーブルに残る。出口のインタフェースも書けば、出口が down になった時点で消えるので予備に切り替わる
- 例：本線 `ip route 172.31.10.0 255.255.255.0 10.10.10.2` が `S 10.0.0.0/8` で再帰して残る

#### イーサネットに出口だけのスタティックルート（いーさねっとにでぐちだけ / static route to a broadcast interface）

- 意味：イーサネットのインタフェースだけを行き先に書いたスタティックルート
- ポイント：その範囲の宛先を全部「直接つながっている」とみなし、宛先ごとに ARP を出す。デフォルトルートでやると ARP の表が大きくなり CPU の負担が増えるので、Cisco は勧めていない。ネクストホップも書く
- 例：`ip route 0.0.0.0 0.0.0.0 GigabitEthernet0/0`（勧められない）

#### 戻りの経路（もどりのけいろ / return route）

- 意味：パケットの返事が戻ってくるための、相手側のルーターの経路
- ポイント：スタティックルートは書いたルーターだけに効く。行きの経路だけ書いて、相手のルーターに戻りの経路がないと ping は失敗する
- 例：R1 に 10.2.0.0/16 への経路、R2 に 10.1.0.0/16 への経路をそれぞれ書く

#### Null0 へのスタティックルート（ぬるぜろへのすたてぃっくるーと / static route to Null0）

- 意味：行き先に Null0（捨てるための仮想インタフェース）を書いたスタティックルート。その宛先のパケットを捨てる
- ポイント：パケットを届けるためではなく、捨てるための経路。集約した経路のループを防ぐのにも使う
- 例：`ipv6 route 2001:DB8:42:1::/64 null0`

### 13-1 IPv4 のスタティックルート

#### 問 ccna-13-o01

- 問：R1 から 192.168.50.0/24 へのパケットを、隣のルーター 10.1.12.2 へ送るスタティックルートとして正しいものはどれか。
- ア：ip route 192.168.50.0 255.255.255.0 10.1.12.2
- イ：ip route 192.168.50.0/24 10.1.12.2
- ウ：ip route 10.1.12.2 255.255.255.0 192.168.50.0
- エ：ip route 192.168.50.0 0.0.0.255 10.1.12.2
- 正解：ア
- 解説：ip route は「宛先 マスク 行き先」の順で、マスクは 255.255.255.0 の形で書く。
- アの意味：正しい。
- イの意味：IPv4 の ip route では /24 の形では書けない（IPv6 の ipv6 route の書き方）。
- ウの意味：宛先とネクストホップが逆。
- エの意味：0.0.0.255 は ACL などで使うワイルドカードマスクで、ip route のマスクではない。
- 出典：オリジナル問題（根拠：Cisco IP Routing: Protocol-Independent Command Reference「ip route」（ip route prefix mask { ip-address | interface-type interface-number [ip-address] }））

#### 問 ccna-13-o02

- 問：インターネットへの出口が ISP（203.0.113.1）だけの支店ルーターで、テーブルにない宛先を全部 ISP へ送りたい。正しい設定はどれか。
- ア：ip route 0.0.0.0 255.255.255.255 203.0.113.1
- イ：ip route 0.0.0.0 0.0.0.0 203.0.113.1
- ウ：ip route 255.255.255.255 255.255.255.255 203.0.113.1
- エ：ip default-network 203.0.113.1
- 正解：イ
- 解説：デフォルトルートは宛先 0.0.0.0・マスク 0.0.0.0（/0）。どの宛先にも当てはまる。
- アの意味：マスク 255.255.255.255 は /32 で、0.0.0.0 という1つのアドレスへのホストルートになる。
- イの意味：正しい。
- ウの意味：255.255.255.255 宛ての1つのアドレスへの経路で、デフォルトルートではない。
- エの意味：ip default-network はネットワークの番号を指定するコマンドで、ネクストホップのアドレスを書くものではない。CCNA でのデフォルトルートの作り方は ip route 0.0.0.0 0.0.0.0。
- 出典：オリジナル問題（根拠：Cisco IP Routing Configuration Guide IOS XE 17.13（Catalyst 9500）「Default Routes and Networks」（specify a static route to the network 0.0.0.0））

#### 問 ccna-13-o03

- 問：サーバー 10.1.40.10 への通信だけを、ほかの 10.1.40.0/24 宛てとは別のルーター 10.1.13.3 へ送りたい。追加する設定はどれか。
