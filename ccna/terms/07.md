## 7-1 VLANとアクセスポート

### まとめ表

**VLAN番号の範囲（Catalyst 9300 の構成ガイド）**

| 範囲 | 名前 | 中身 |
| :-: | :-: | :-: |
| 1 | デフォルトVLAN | 最初から全ポートが入っている。削除できない |
| 2〜1001 | 標準範囲（ノーマル） | 自由に作れる。VLANデータベース（vlan.dat）に保存 |
| 1002〜1005 | 予約 | トークンリング・FDDI用。最初からあり、削除できない |
| 1006〜4094 | 拡張範囲 | VTPバージョン1・2では他のスイッチに伝わらない |

**アクセスポートとトランクポート**

| | アクセスポート | トランクポート |
| :-: | :-: | :-: |
| 入るVLAN | 1つだけ（音声VLANは別に1つ足せる） | 許可した全部のVLAN |
| フレームのタグ | 付けない | 付ける（ネイティブVLANだけ付けない） |
| つなぐ相手 | PC・プリンタ・IP電話 | スイッチ・ルータ・サーバの仮想化ホスト |
| 設定 | `switchport mode access` | `switchport mode trunk` |

### VLANの考え方

#### VLAN（ぶいらん / Virtual LAN）

- 意味：1台（または複数台）のスイッチのポートを、物理的な配線とは関係なく論理的なグループに分けたもの。1つのVLANが1つのブロードキャストドメインになる
- ポイント：違うVLANどうしはスイッチの中で直接は届かず、ルータかレイヤ3スイッチで中継（ルーティング）する必要がある。1つのVLANには1つのIPサブネットを割り当てるのが基本
- 例：`vlan 10` → `name SALES` でVLAN 10を作って名前を付ける
- 語の意味：Virtual＝仮想の／Local＝その場所の／Area＝区域／Network＝網

#### ブロードキャストドメイン（ぶろーどきゃすとどめいん / broadcast domain）

- 意味：ブロードキャスト（宛先MACアドレスがFFFF.FFFF.FFFF）のフレームが届く範囲。ルータやレイヤ3インタフェースで区切られる
- ポイント：スイッチは同じVLANの全ポートにブロードキャストを流す。VLANを分けるとブロードキャストドメインも分かれる。「衝突ドメイン」はスイッチのポートごとに分かれるので、似ているが別もの
- 例：VLANが3つあるスイッチ1台なら、ブロードキャストドメインは3つ

#### 衝突ドメイン（しょうとつどめいん / collision domain）

- 意味：同時に送ると信号がぶつかる（コリジョンが起きる）範囲。ハブにつながった機器全体が1つの衝突ドメインになる
- ポイント：スイッチは1ポートごとに衝突ドメインを分ける。全二重通信ならコリジョンは起きない。ブロードキャストドメインを分けるのはVLANとルータ
- 例：24ポートのスイッチにVLAN 2つ → 衝突ドメイン24、ブロードキャストドメイン2

#### スタティックVLAN（すたてぃっくぶいらん / static VLAN）

- 意味：ポートごとに管理者が手で所属するVLANを決める方式。ポートベースVLANともいう
- ポイント：Catalystの構成ガイドでは「interface-based, or static, VLAN membership」。つないだ機器ではなくポートで決まるので、PCを別のポートにつなぎ替えるとVLANも変わる
- 例：`interface g1/0/5` → `switchport access vlan 10`

#### ダイナミックVLAN（だいなみっくぶいらん / dynamic VLAN）

- 意味：つないだ機器のMACアドレスや認証の結果（IEEE 802.1X）で、VLANを自動で決める方式
- ポイント：PCがどのポートにつながっても同じVLANに入れる。CCNAでは「ポートで決めるスタティック」と対比で問われる
- 語の意味：Dynamic＝動的な

### VLANの番号

#### デフォルトVLAN（でふぉるとぶいらん / default VLAN）

- 意味：スイッチの初期状態で、全ポートが所属しているVLAN。CiscoではVLAN 1
- ポイント：VLAN 1は削除も名前の変更もできない。トランクのネイティブVLANの初期値もVLAN 1。セキュリティのため、使っていないポートはVLAN 1以外の使わないVLANに入れて shutdown しておくのがよいとされる
- 例：`show vlan brief` で、何も設定していないポートは「1 default」の行に並ぶ

#### 標準範囲VLAN（ひょうじゅんはんいぶいらん / normal-range VLAN）

- 意味：VLAN ID 1〜1005のVLAN。作れるのは2〜1001で、1002〜1005はトークンリングとFDDIのために予約されている
- ポイント：設定はフラッシュメモリの vlan.dat（VLANデータベース）に保存される。VTPの対象になるのはこの範囲（VTPバージョン3は拡張範囲も伝える）

#### 拡張範囲VLAN（かくちょうはんいぶいらん / extended-range VLAN）

- 意味：VLAN ID 1006〜4094のVLAN。サービスプロバイダなど、多くのVLANが必要な場面のための範囲
- ポイント：VTPバージョン1・2ではVLANデータベースに入らず、他のスイッチにも伝わらない（その場合はVTPをトランスペアレントにして使う）。VTPのプルーニングの対象にもできない

#### VLANデータベース（ぶいらんでーたべーす / VLAN database）

- 意味：VLAN 1〜1005の設定を保存するファイル。フラッシュメモリの vlan.dat
- ポイント：running-config とは別のファイルなので、`write erase` で設定を消しても vlan.dat は残る。スイッチを初期化するときは vlan.dat も消す
- 例：`delete flash:vlan.dat`

### ポートの種類

#### アクセスポート（あくせすぽーと / access port）

- 意味：1つのVLANだけに所属し、タグを付けずにフレームを送受信するポート。PCなどの端末をつなぐ
- ポイント：`switchport mode access` にすると、相手が何であってもトランクにならない（DTPで交渉しても非トランクのまま）。所属VLANは `switchport access vlan` で決める
- 例：`switchport mode access` → `switchport access vlan 10`

#### トランクポート（とらんくぽーと / trunk port）

- 意味：複数のVLANのフレームを、VLANを区別するタグを付けて1本のリンクで運ぶポート。スイッチどうしやスイッチとルータをつなぐ
- ポイント：初期状態ではVLAN 1〜4094の全部を通す。ネイティブVLANのフレームだけはタグなしで送る。トランクはポイントツーポイント（1対1）のリンク
- 例：`switchport mode trunk`

#### 静的アクセスポートの自動VLAN作成（せいてきあくせすぽーとのじどうさくせい / auto-created VLAN）

- 意味：存在しないVLANを `switchport access vlan` で指定すると、そのVLANが自動で作られるという動き
- ポイント：名前は自動で「VLAN0030」のようになる（VLANの前に0で埋めた番号）。逆にVLANを削除すると、そのVLANにいたポートは使えなく（inactive）なり、別のVLANに入れ直すまで通信できない

### 音声VLAN

#### 音声VLAN（おんせいぶいらん / voice VLAN）

- 意味：IP電話の音声だけを別のVLANで運ぶしくみ。アクセスポート1つで、IP電話の音声（音声VLAN）と、電話の後ろにつないだPCのデータ（アクセスVLAN）を分けて運ぶ
- ポイント：IP電話は音声に802.1Qのタグ（音声VLANの番号とCoS 5）を付け、PCのフレームはタグなしのままアクセスVLANに入る。トランクにしなくてよい。音声VLANを設定するとPortFastが自動で有効になる
- 例：`switchport mode access` → `switchport access vlan 10` → `switchport voice vlan 20`

#### データVLAN（でーたぶいらん / data VLAN）

- 意味：音声VLANと対で使うときの、PCなどの普通のデータが流れるVLAN。設定上はアクセスVLAN
- ポイント：`show interfaces switchport` では「Access Mode VLAN」がデータVLAN、「Voice VLAN」が音声VLAN

#### CoS（こす / Class of Service）

- 意味：802.1Qタグの中の3ビットの優先度（0〜7）。IEEE 802.1pで決められている
- ポイント：Cisco IP電話は音声に初期値でCoS 5を付ける（レイヤ3のIP precedenceも5）。タグのないフレームにはCoSがない。IPヘッダーのDSCPとは別のもの
- 語の意味：Class＝区分／of Service＝サービスの

#### CDP（しーでぃーぴー / Cisco Discovery Protocol）

- 意味：Cisco機器どうしが、隣の機器の名前・型番・ポートなどを知らせ合うCisco独自のプロトコル
- ポイント：音声VLANでは、スイッチがCDPでIP電話に「音声はVLAN 20で送って」と伝える。CDPそのものは小分野08（CDP・LLDP）で詳しく扱う
- 語の意味：Cisco＝シスコ／Discovery＝発見／Protocol＝通信の約束ごと

### VLANの設定と確認のコマンド

#### vlan（ぶいらん / vlan vlan-id）

- 意味：グローバル設定モードでVLANを作る（または既存のVLANを編集する）コマンド。VLAN設定モードに入る
- ポイント：指定できるIDは1〜4094。名前は `name` で付ける。付けないと「VLAN0004」のような名前になる。削除は `no vlan 4`
- 例：`vlan 20` → `name test20`

#### switchport access vlan（すいっちぽーとあくせすぶいらん / switchport access vlan）

- 意味：アクセスポートが所属するVLANを決めるインタフェースのコマンド
- ポイント：ポートがアクセスモードのときに効く。アクセスポートが入れるVLANは1つだけ。`no switchport access vlan` で既定のVLAN（VLAN 1）に戻る
- 例：`switchport access vlan 2`

#### show vlan brief（しょうぶいらんぶりーふ / show vlan brief）

- 意味：VLANの番号・名前・状態と、各VLANに所属するアクセスポートを一覧で見るコマンド
- ポイント：トランクになっているポートは各VLANの行に出てこない。トランクを確かめるのは `show interfaces trunk`
- 例：`show vlan brief`

#### show interfaces switchport（しょういんたふぇーすいずすいっちぽーと / show interfaces switchport）

- 意味：ポートの管理上のモード（Administrative Mode）と実際の動作モード（Operational Mode）、アクセスVLAN、ネイティブVLAN、許可VLAN、音声VLANなどを詳しく見るコマンド
- ポイント：「Administrative Mode: dynamic auto」「Operational Mode: static access」のように、設定と結果が別々に出るので、トランクになっていない原因を探すのに使う
- 例：`show interfaces g1/0/1 switchport`

## 7-2 トランクと802.1Q

### まとめ表

**DTPのモードの組み合わせ（行＝自分、列＝相手）**

| 自分＼相手 | access | dynamic auto | dynamic desirable | trunk |
| :-: | :-: | :-: | :-: | :-: |
| access | アクセス | アクセス | アクセス | ×（不一致） |
| dynamic auto | アクセス | アクセス | トランク | トランク |
| dynamic desirable | アクセス | トランク | トランク | トランク |
| trunk | ×（不一致） | トランク | トランク | トランク |

- 「auto どうし」はどちらも待つだけなのでトランクにならない（CatalystのLayer 2ポートの初期値は dynamic auto）
- 「×」は片方だけがトランクとして動く危ない状態。通信できないVLANが出る
- `switchport nonegotiate` を付けたポートはDTPを送らないので、相手は access か trunk に手で決めておく

**802.1Qタグ（送信元MACアドレスとタイプの間に4バイト入る）**

| フィールド | 長さ | 中身 |
| :-: | :-: | :-: |
| TPID | 16ビット | 0x8100。タグ付きフレームの目印 |
| 優先度（PCP） | 3ビット | IEEE 802.1p の優先度 0〜7（CoS） |
| CFI（DEI） | 1ビット | MACアドレスの形式の目印。新しい規格ではDEI |
| VID | 12ビット | VLAN ID。0〜4095（使うのは1〜4094） |

### タグの付け方

#### IEEE 802.1Q（あいとりぷるいーはちまるにーてんいちきゅー / IEEE 802.1Q）

- 意味：トランクでフレームにVLANの番号を付けるための標準規格。元のフレームの送信元MACアドレスの後ろに4バイトのタグを挿入する
- ポイント：フレームが変わるのでFCSを計算し直す。ネイティブVLANのフレームにはタグを付けない。最大フレーム長は1518から1522バイトになる。いまのCatalystは802.1Qだけに対応しているものが多い
- 例：`switchport trunk encapsulation dot1q`（ISLも使える古い機種で、カプセル化を802.1Qに決めるとき）

#### ISL（あいえすえる / Inter-Switch Link）

- 意味：Cisco独自のトランクの方式。元のフレーム全体を26バイトのヘッダーと4バイトのFCSで包む（カプセル化する）
- ポイント：802.1Qは「タグを中に挿入」、ISLは「外側から丸ごと包む」。ISLはCisco独自で古く、ネイティブVLANの考えもない。新しい機器では802.1Qを使う
- 語の意味：Inter＝間の／Switch＝スイッチ／Link＝接続

#### VLANタグ（ぶいらんたぐ / VLAN tag）

- 意味：フレームがどのVLANのものかを示すためにフレームに付ける情報。802.1Qでは4バイト
- ポイント：アクセスポートから端末へ出るときはタグを外す。端末（PC）は普通タグを意識しない。トランクを通るときだけタグが付く

#### TPID（てぃーぴーあいでぃー / Tag Protocol Identifier）

- 意味：802.1Qタグの先頭16ビット。値は0x8100で、「この後ろにVLANタグがある」ことを示す
- ポイント：普通のフレームならタイプ（IPv4なら0x0800）がある位置に0x8100が入るので、受け取った側はタグ付きだとわかる
- 語の意味：Tag＝札／Protocol＝通信の約束ごと／Identifier＝識別子

#### VID（ぶいあいでぃー / VLAN Identifier）

- 意味：802.1Qタグの中のVLAN番号。12ビットなので0〜4095を表せる
- ポイント：使えるVLANは1〜4094。VID 0は「VLANなしで優先度だけ付けた」フレーム（802.1p のプライオリティタグ）に使われる。2の12乗＝4096を覚えておくと計算問題で迷わない
- 語の意味：VLAN＝仮想LAN／Identifier＝識別子

#### PCP（ぴーしーぴー / Priority Code Point）

- 意味：802.1Qタグの中の3ビットの優先度。0〜7の8段階で、IEEE 802.1pの優先度（CoS）として使う
- ポイント：Cisco の資料では「Priority（user priority）」と書かれている。3ビットなので8段階。VLANの番号（VID）とは別のフィールド
- 語の意味：Priority＝優先度／Code＝符号／Point＝値

### ネイティブVLAN

#### ネイティブVLAN（ねいてぃぶぶいらん / native VLAN）

- 意味：802.1Qトランクで、タグを付けずに送受信するVLAN。初期値はVLAN 1
- ポイント：トランクで受け取ったタグなしのフレームは、ネイティブVLANのものとして扱う。トランクの両端で同じ番号にしないといけない。セキュリティのため、ユーザーが使わないVLAN番号にするのがCiscoの推奨
- 例：`switchport trunk native vlan 999`

#### ネイティブVLANの不一致（ねいてぃぶぶいらんのふいっち / native VLAN mismatch）

- 意味：トランクの両端でネイティブVLANの番号が違う状態
- ポイント：片方のネイティブVLAN（タグなし）のフレームが、相手側では別のVLANのものとして扱われ、VLANどうしがつながってしまう。スパニングツリーのループの原因にもなる（Ciscoの構成ガイド）。トランク自体は上がるので気づきにくい
- 例：SW1が `native vlan 10`、SW2が `native vlan 20` → SW1のVLAN 10のタグなしフレームがSW2ではVLAN 20に入る

#### VLANホッピング（ぶいらんほっぴんぐ / VLAN hopping）

- 意味：攻撃者が、自分が所属していないVLANにフレームを届ける攻撃。二重にタグを付ける方法（ダブルタギング）と、DTPでスイッチとトランクを結ぶ方法がある
- ポイント：ダブルタギングは、攻撃者のアクセスVLANがトランクのネイティブVLANと同じときに成り立つ（Ciscoのベストプラクティス文書）。対策は、ネイティブVLANを使わない番号にする、端末用ポートを `switchport mode access` にしてDTPを止める
- 語の意味：Hopping＝飛び移ること

### トランクの交渉

#### DTP（でぃーてぃーぴー / Dynamic Trunking Protocol）

- 意味：隣のスイッチとトランクにするかどうかを自動で交渉するCisco独自のプロトコル
- ポイント：交渉にはVTPドメイン名が両方で一致している必要がある。DTPに対応しない機器とつなぐときや、端末用のポートでは、DTPを止める（access にするか、trunk ＋ nonegotiate）。交渉の結果は上のまとめ表
- 語の意味：Dynamic＝動的な／Trunking＝トランクにすること／Protocol＝通信の約束ごと

#### dynamic auto（だいなみっくおーと / switchport mode dynamic auto）

- 意味：相手が trunk か dynamic desirable ならトランクになる、受け身のモード。CatalystのLayer 2ポートの初期値
- ポイント：自分からは「トランクにしよう」と言わない。だから auto どうしではトランクにならず、アクセスポートとして動く。本番では「何も設定していないスイッチどうしをつないだらどうなるか」で問われる
- 例：`switchport mode dynamic auto`

#### dynamic desirable（だいなみっくでざいあらぶる / switchport mode dynamic desirable）

- 意味：自分から積極的にトランクにしようとするモード。相手が trunk・desirable・auto のどれでもトランクになる
- ポイント：相手が access なら非トランク。auto との違いは「自分から交渉を持ちかけるかどうか」
- 例：`switchport mode dynamic desirable`

#### switchport mode trunk（すいっちぽーともーどとらんく / switchport mode trunk）

- 意味：相手に関係なく、ポートを常にトランクにするモード。DTPのフレームは送り続ける
- ポイント：相手が auto や desirable ならトランクがそろう。相手が access だと、片方だけがトランクの不一致になる
- 例：`switchport mode trunk`

#### switchport nonegotiate（すいっちぽーとのんねごしえいと / switchport nonegotiate）

- 意味：DTPのフレームを送らないようにするコマンド
- ポイント：ポートが access か trunk のときだけ使える（dynamic のときはエラー）。trunk ＋ nonegotiate にすると、相手も手で trunk にしないとトランクがそろわない。相手が dynamic auto のままだと、相手はDTPを受け取れず非トランクになる
- 例：`switchport mode trunk` → `switchport nonegotiate`

### 通すVLANの制限

#### 許可VLANリスト（きょかぶいらんりすと / allowed VLAN list）

- 意味：トランクで通してよいVLANの一覧。初期値は全部（1〜4094）
- ポイント：`switchport trunk allowed vlan 10,20` は一覧を「10と20だけ」に置き換える。今の一覧に足すときは add、外すときは remove を付ける。add を付け忘れて、それまで通っていたVLANを止めてしまうのが典型的なミス
- 例：`switchport trunk allowed vlan add 30` ／ `switchport trunk allowed vlan remove 2`

#### allowed vlan のキーワード（あらうどぶいらんのきーわーど / add・remove・except・all・none）

- 意味：`switchport trunk allowed vlan` の後ろに付けて、一覧の変え方を決める語
- ポイント：add＝今の一覧に足す、remove＝今の一覧から外す、except＝指定した番号以外を全部、all＝全部（初期値）、none＝空にする。何も付けずに番号だけ書くと置き換え
- 例：`switchport trunk allowed vlan except 100-200`

#### VTP（ぶいてぃーぴー / VLAN Trunking Protocol）

- 意味：VLANの追加・削除・名前の変更を、トランクを通して同じドメインのスイッチに伝えるCisco独自のプロトコル
- ポイント：モードはサーバ・クライアント・トランスペアレント（とオフ）。トランスペアレントは自分のVLANを伝えず、他からの情報も反映しない（中継だけする）。使わないなら「VTPはなくてもよい」と構成ガイドにある。CCNA v1.1 の出題範囲には項目としては入っていない
- 語の意味：VLAN＝仮想LAN／Trunking＝トランク／Protocol＝通信の約束ごと

#### VTPプルーニング（ぶいてぃーぴーぷるーにんぐ / VTP pruning）

- 意味：トランクの先にそのVLANのポートがないとき、ブロードキャストなどをそのトランクに流さないようにするVTPの機能
- ポイント：許可VLANリストは管理者が手で絞る、プルーニングはVTPが自動で絞る。プルーニングできるのはVLAN 2〜1001だけ（VLAN 1と拡張範囲はできない）
- 語の意味：Pruning＝枝を切り落とすこと

### トランクの確認

#### show interfaces trunk（しょういんたふぇーすいずとらんく / show interfaces trunk）

- 意味：トランクになっているポートの、モード・カプセル化・状態・ネイティブVLANと、許可VLAN・実際に通っているVLANを見るコマンド
- ポイント：4つのかたまりで出る。①Mode／Encapsulation／Status／Native vlan、②Vlans allowed on trunk（許可リスト）、③Vlans allowed and active in management domain（許可されてスイッチに存在するVLAN）、④Vlans in spanning tree forwarding state and not pruned（STPで転送中でプルーニングされていないVLAN）。②にあっても③にないVLANは、そのスイッチに作られていない
- 例：`show interfaces trunk`

#### Administrative Mode と Operational Mode（あどみにすとれーてぃぶもーどとおぺれーしょなるもーど / administrative and operational mode）

- 意味：`show interfaces switchport` の行。Administrative Mode＝設定したモード、Operational Mode＝実際に動いているモード
- ポイント：「Administrative Mode: dynamic auto」「Operational Mode: static access」なら、交渉の結果トランクにならずアクセスとして動いている。設定と結果のずれがトラブルの手がかり

## 7-3 VLAN間ルーティング

### まとめ表

**VLAN間ルーティングの3つの方法**

| 方法 | 使う機器 | 設定の中心 | 特徴 |
| :-: | :-: | :-: | :-: |
| VLANごとに物理ポート | ルータ | VLANの数だけルータのポートとケーブル | わかりやすいがポートが足りなくなる |
| ルータオンアスティック | ルータ＋トランク1本 | サブインタフェース＋`encapsulation dot1Q` | ケーブル1本。トランクが混みやすい |
| SVI | レイヤ3スイッチ | `interface vlan 10`＋`ip routing` | スイッチの中で速く中継できる。今の主流 |

### 方式

#### VLAN間ルーティング（ぶいらんかんるーてぃんぐ / inter-VLAN routing）

- 意味：違うVLAN（違うサブネット）の端末どうしの通信を、ルータやレイヤ3スイッチで中継すること
- ポイント：VLANが違うとスイッチだけでは届かない（構成ガイド「Traffic between VLANs must be routed」）。端末のデフォルトゲートウェイは、自分のVLANのルータ側のアドレス（サブインタフェースやSVIのIPアドレス）にする

#### ルータオンアスティック（るーたおんあすてぃっく / router on a stick）

- 意味：ルータの1つの物理ポートをスイッチとトランクでつなぎ、VLANごとのサブインタフェースでVLAN間をルーティングする構成
- ポイント：スイッチ側のポートは trunk、ルータ側は物理ポートの下にサブインタフェースを作る。各サブインタフェースには別のサブネットのIPアドレスを付ける。物理ポートは no shutdown が必要
- 例：`interface g0/0.10` → `encapsulation dot1Q 10` → `ip address 192.168.10.1 255.255.255.0`

#### サブインタフェース（さぶいんたふぇーす / subinterface）

- 意味：1つの物理インタフェースを論理的に分けた仮想のインタフェース。名前は「物理インタフェース名.番号」
- ポイント：`.10` の番号はただの名前で、どのVLANを受け持つかは `encapsulation dot1Q` で決まる（番号とVLANをそろえるのはわかりやすくするため）。サブインタフェースどうしは別のサブネットにする
- 例：`interface g0/0.20`

#### encapsulation dot1Q（えんかぷせれーしょんどっといちきゅー / encapsulation dot1Q）

- 意味：サブインタフェースに、どのVLANのタグ付きフレームを受け持つかを設定するコマンド
- ポイント：ネイティブVLANを受け持つときは `native` を付ける（Ciscoの構成ガイドの制限事項）。付けないとタグなしのフレームを受け取れない。スイッチ側のトランクのネイティブVLANとそろえる
- 例：`encapsulation dot1Q 99 native`

#### SVI（えすぶいあい / Switch Virtual Interface）

- 意味：レイヤ3スイッチの中で、VLANを1つのインタフェースとして扱う仮想インタフェース。IPアドレスを付けてVLAN間ルーティングや管理用に使う
- ポイント：`interface vlan 10` で作る。1つのVLANにSVIは1つ。そのVLANに属してupしているポートがないとSVIは使える状態（up）にならない。VLAN 1のSVIは最初からあり、削除できない
- 例：`interface vlan 10` → `ip address 192.168.10.1 255.255.255.0` → `no shutdown`
- 語の意味：Switch＝スイッチ／Virtual＝仮想の／Interface＝接続口

#### ip routing（あいぴーるーてぃんぐ / ip routing）

- 意味：レイヤ3スイッチでIPのルーティングを有効にするグローバル設定のコマンド
- ポイント：Catalystのレイヤ3スイッチでは、IPルーティングは初期状態で無効。SVIにIPアドレスを付けても、`ip routing` がないとVLAN間で中継しない（管理用のアドレスとしては使える）
- 例：`ip routing`

#### ルーテッドポート（るーてっどぽーと / routed port）

- 意味：レイヤ3スイッチの物理ポートを、VLANに属さないレイヤ3のポートにしたもの。ルータのポートのように直接IPアドレスを付ける
- ポイント：`no switchport` で切り替える。VLANには属さない。SVIは「VLANの代表」、ルーテッドポートは「そのポートだけ」の違い
- 例：`interface g1/0/24` → `no switchport` → `ip address 10.0.0.1 255.255.255.252`

#### レイヤ3スイッチ（れいやすりーすいっち / Layer 3 switch）

- 意味：スイッチの機能に加えて、IPアドレスでのルーティングもできるスイッチ。マルチレイヤスイッチともいう
- ポイント：中継の多くをハードウェアで行うので速い。VLAN間ルーティングはSVIで行う。ルータに比べてWAN向けの機能は少ない

#### デフォルトゲートウェイ（でふぉるとげーとうぇい / default gateway）

- 意味：端末が、自分のサブネットの外に送るときの出口になるルータ（やSVI）のIPアドレス
- ポイント：VLAN間ルーティングでは、VLAN 10の端末のデフォルトゲートウェイ＝VLAN 10を受け持つサブインタフェースかSVIのアドレス。設定ミスでVLAN内は通じるのにVLANの外へ出られない、という形で問われる

### 7-2 トランクと802.1Q

#### 問 ccna-7-o09

- 問：IEEE 802.1Qのタグについて、正しいものはどれか。
- ア：元のフレーム全体を26バイトのヘッダーで包む
- イ：送信元MACアドレスとタイプ／長さのフィールドの間に4バイトを挿入し、FCSを計算し直す
- ウ：VLAN IDは10ビットで、1024個のVLANを区別できる
- エ：ネイティブVLANのフレームにも必ずタグを付ける
- 正解：イ
- 解説：802.1Qは元のフレームの中（送信元MACアドレスの後ろ）に4バイトのタグを入れる。フレームが変わるのでFCSを計算し直す。VLAN IDは12ビット。ネイティブVLANのフレームにはタグを付けない。
- アの意味：これはCisco独自のISLの説明（26バイトのヘッダーと4バイトのFCSで包む）。
- イの意味：正しい。802.1Qは中に挿入する方式。
