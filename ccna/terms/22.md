## 22-1 ACL の基本

### まとめ表

| 書き方 | ワイルドカードマスク | 合うアドレス |
| :-: | :-: | :-: |
| host 10.1.1.2 | 0.0.0.0 | 10.1.1.2 の1台だけ |
| 10.1.1.0 0.0.0.255 | 0.0.0.255 | 10.1.1.0〜10.1.1.255 |
| 172.20.128.64 0.0.0.31 | 0.0.0.31 | 172.20.128.64〜172.20.128.95 |
| 192.168.148.0 0.0.1.255 | 0.0.1.255 | 192.168.148.0〜192.168.149.255 |
| any | 255.255.255.255 | すべてのアドレス |

### 照合のしかた

#### ACL（えーしーえる / Access Control List）

- 意味：パケットを通す（permit）か捨てる（deny）かの条件を、順番に並べたリスト
- ポイント：作っただけでは何もしない。インタフェースや VTY 回線に付けて初めて効く。CCNA ではルーターのインタフェースで通信をしぼる使い方が中心
- 語の意味：Access＝利用・接続／Control＝制御／List＝一覧

#### ACE（えーしーいー / Access Control Entry）

- 意味：ACL の1行1行。permit か deny かと、パケットが満たすべき条件（アドレス・プロトコル・ポートなど）を書く
- ポイント：ACL は ACE を順番に並べたもの。行ごとにシーケンス番号が付く（22-4）
- 例：`10 permit ip any 172.20.128.64 0.0.0.31`
- 語の意味：Access＝利用・接続／Control＝制御／Entry＝項目

#### 上から順の照合（うえからじゅんのしょうごう / first match）

- 意味：パケットを ACL の上の行から1行ずつ比べ、最初に合った行の permit／deny で決める動き
- ポイント：合った時点で比べるのをやめるので、下の行は見ない。だから行の順番がとても大切。Cisco の例では、`permit any` を `deny host 192.168.10.1` より上に書くと、1行目が全部に合ってしまい、その1台を止められない。よく合う行は上に置く
- 例：`access-list 1 deny host 192.168.10.1` のあとに `access-list 1 permit any`（逆にすると止められない）

#### 暗黙の deny（あんもくのでぃない / implicit deny）

- 意味：ACL の最後に、書いていなくても「ほかは全部 deny」がある決まり
- ポイント：どの行にも合わなかったパケットは捨てられる。permit の行が1つもない ACL は全部を止める。ほかを通したいなら最後に `permit any`（拡張なら `permit ip any any`）を自分で書く。IPv6 の ACL も同じ
- 例：`access-list 1 deny host 192.168.10.1` だけを付けると、その1台だけでなく全部が止まる

#### ワイルドカードマスク（わいるどかーどますく / wildcard mask・inverse mask）

- 意味：ACL でアドレスのどのビットを比べるかを決めるマスク。0 のビットは「同じでなければならない」、1 のビットは「何でもよい」
- ポイント：サブネットマスクと 0 と 1 の意味が逆なので、逆マスク（inverse mask）とも呼ぶ。連続した範囲なら「255.255.255.255 − サブネットマスク」で求まる（/24 → 0.0.0.255、/27 → 0.0.0.31）
- 例：`10.1.1.0 0.0.0.255` は 10.1.1.0〜10.1.1.255 に合う

#### any（えにー / any）

- 意味：すべてのアドレスを表すキーワード。`0.0.0.0 255.255.255.255` の省略形
- ポイント：ワイルドカードが全部 1 なので、どのアドレスでも合う
- 例：`access-list 1 permit any`

#### host（ほすと / host）

- 意味：1台のアドレスだけを表すキーワード。ワイルドカード `0.0.0.0` の省略形
- ポイント：`host 10.1.1.2` と `10.1.1.2 0.0.0.0` は同じ意味。標準 ACL でマスクを省いたときも 0.0.0.0 とみなされる
- 例：`access-list 1 deny host 192.168.10.1`

## 22-2 標準と拡張

### まとめ表

| 項目 | 標準 ACL | 拡張 ACL |
| :-: | :-: | :-: |
| 番号 | 1〜99、1300〜1999 | 100〜199、2000〜2699 |
| 比べるもの | 送信元アドレスだけ | プロトコル・送信元・宛先・ポートなど |
| 名前付きで作るとき | ip access-list standard 名前 | ip access-list extended 名前 |
| 置き場所の目安 | 宛先の近く | 送信元の近く |

### 種類と書き方

#### 標準 ACL（ひょうじゅんえーしーえる / standard ACL）

- 意味：送信元の IP アドレスだけで permit／deny を決める ACL。番号は 1〜99 と 1300〜1999
- ポイント：宛先やポートは見られない。だから「この送信元からの、この宛先だけ」は書けない
- 例：`access-list 6 permit 172.20.128.64 0.0.0.31`

#### 拡張 ACL（かくちょうえーしーえる / extended ACL）

- 意味：プロトコル・送信元・宛先・ポート番号などで細かく決める ACL。番号は 100〜199 と 2000〜2699
- ポイント：送信元と宛先の前にプロトコル（ip・tcp・udp・icmp など）を必ず書く。ポートは送信元のあとに書けば送信元ポート、宛先のあとに書けば宛先ポート
- 例：`access-list 101 permit tcp 10.1.1.0 0.0.0.255 host 10.5.5.5 eq www`

#### 番号付き ACL（ばんごうつきえーしーえる / numbered ACL）

- 意味：番号で呼ぶ ACL。グローバル設定の `access-list 番号 …` で1行ずつ作る
- ポイント：この形で足した行は必ず最後に付く。`no access-list 101 deny icmp any any` のように1行だけ消すつもりでも、ACL 101 が丸ごと消える
- 例：`access-list 10 permit 192.168.148.0 0.0.1.255`

#### 名前付き ACL（なまえつきえーしーえる / named ACL）

- 意味：名前で呼ぶ ACL。`ip access-list standard 名前` か `ip access-list extended 名前` で ACL の設定モードに入り、その中で行を書く
- ポイント：番号付きとちがい、行を1つずつ消したり、シーケンス番号を付けて間に入れたりできる。名前の代わりに番号を書いてこのモードに入ると、番号付き ACL も行ごとに直せる
- 例：`ip access-list extended WEB` → `permit tcp any host 10.5.5.5 eq 443`

#### プロトコルの指定（ぷろとこるのしてい / protocol keyword）

- 意味：拡張 ACL の行で、どのプロトコルのパケットに合わせるかを書くところ
- ポイント：`ip` は TCP・UDP・ICMP も含む IP のパケット全部に合う。`tcp` や `udp` と書いたときだけポート番号を書ける
- 例：`permit ip any any`（全部）／`permit icmp any any`（ICMP だけ）

#### ポートの比べ方（ぽーとのくらべかた / port operators）

- 意味：TCP・UDP のポート番号の比べ方。eq（等しい）・gt（より大きい）・lt（より小さい）・neq（等しくない）・range（範囲、両端を含む）
- ポイント：ポートは番号でも名前（www、telnet、domain など）でもよい。range は番号を2つ書く
- 例：`permit tcp any any gt 1023`／`permit udp any any range 16384 32767`
- 語の意味：eq＝equal／gt＝greater than／lt＝less than／neq＝not equal

#### established（えすたぶりっしゅと / established）

- 意味：TCP のヘッダーで ACK か RST のビットが立っているパケットだけに合うキーワード
- ポイント：すでに始まった TCP の通信（中から外へ出た通信の戻り）を通し、外から新しく始める SYN だけのパケットを止めるのに使う。TCP だけで使え、UDP には使えない
- 例：`access-list 102 permit tcp any 172.16.0.0 0.0.255.255 established`

#### IPv6 ACL（あいぴーぶいろくえーしーえる / IPv6 ACL）

- 意味：IPv6 のパケットをしぼる ACL。`ipv6 access-list 名前` で作り、インタフェースに `ipv6 traffic-filter 名前 in|out` で付ける
- ポイント：IPv6 の ACL は名前付きだけで、番号付きは作れない。最後に暗黙の deny があるのは IPv4 と同じ
- 例：`ipv6 access-list V6IN` → `permit icmp any any`

## 22-3 適用と置き場所

### まとめ表

| 付け先 | コマンド | 何をしぼるか |
| :-: | :-: | :-: |
| ルーターのインタフェース（IPv4） | ip access-group 名前か番号 in／out | そのインタフェースを通るパケット |
| ルーターのインタフェース（IPv6） | ipv6 traffic-filter 名前 in／out | そのインタフェースを通る IPv6 パケット |
| VTY 回線（Telnet・SSH） | access-class 番号 in | 機器へのログインの送信元 |

### 付け方

#### ip access-group（あいぴーあくせすぐるーぷ / ip access-group）

- 意味：インタフェース設定モードで、IPv4 の ACL を in か out の向きに付けるコマンド
- ポイント：1つのインタフェースの1つの向きに付けられる ACL は1つだけ。同じ向きに別の ACL を付けると、前のものと入れ替わる
- 例：`interface g0/1` → `ip access-group 106 in`

#### インバウンド（いんばうんど / inbound・in）

- 意味：インタフェースに入ってくるパケットを、受け取った直後（ルーティングの前）に調べる向き
- ポイント：deny ならその場で捨てるので、ルーティングの手間がかからない。permit ならそのまま処理を続ける
- 例：`ip access-group 101 in`

#### アウトバウンド（あうとばうんど / outbound・out）

- 意味：ルーティングで出口に決まったインタフェースから出ていく前に、パケットを調べる向き
- ポイント：向きはルーターから見た出入りで考える。in とちがい、ルーティングが終わってから調べる
- 例：`ip access-group 6 out`

#### 3つの P（みっつのぴー / the three Ps）

- 意味：ACL は「1つのプロトコル・1つの向き・1つのインタフェース」ごとに1つ、という決まり
- ポイント：IPv4 と IPv6 は別の ACL。入りと出をしぼるなら ACL が2つ要る
- 語の意味：per protocol＝プロトコルごと／per direction＝向きごと／per interface＝インタフェースごと

#### ACL の置き場所（えーしーえるのおきばしょ / ACL placement）

- 意味：どのルーターのどのインタフェースに ACL を付けるかの目安
- ポイント：拡張 ACL は送信元のできるだけ近く（いらない通信を早く捨て、帯域をむだにしない）。標準 ACL は宛先を見られないので宛先のできるだけ近く（送信元の近くに置くと、ほかの宛先への通信まで止めてしまう）
- 例：PC から遠いサーバーへの Telnet だけ止めたい → 拡張 ACL を PC 側ルーターの入口に in で付ける

#### access-class（あくせすくらす / access-class）

- 意味：VTY 回線（Telnet・SSH の入口）に ACL を付け、ログインできる送信元をしぼるコマンド
- ポイント：送信元アドレスだけで決めるので、標準 ACL で足りる。インタフェースの `ip access-group` とは付け先がちがう
- 例：`line vty 0 4` → `access-class 10 in`

#### 定義されていない ACL（ていぎされていないえーしーえる / undefined ACL）

- 意味：インタフェースに付けたのに、中身（ACE）をまだ作っていない ACL
- ポイント：Cisco の資料では、定義されていない ACL を付けたインタフェースは ACL がないのと同じ扱いになり、全部のパケットを通す。暗黙の deny で全部止まるわけではない
- 例：`ip access-group 150 in` だけ書いて、ACL 150 を作っていない

## 22-4 編集と確認

### まとめ表

| 確かめたいこと | コマンド |
| :-: | :-: |
| ACL の中身と各行の一致数 | show access-lists／show ip access-lists |
| どのインタフェースにどの向きで付いているか | show ip interface インタフェース名 |
| 設定そのもの（ACL とその付け先） | show running-config |

### 直し方と確かめ方

#### シーケンス番号（しーけんすばんごう / sequence number）

- 意味：ACL の各行に付く番号。何も書かなければ 10、20、30 と 10 ずつ付く
- ポイント：名前付き ACL のモード（番号付きなら `ip access-list extended 101` など）で番号を先頭に書くと、その位置に行を入れられる。番号は 1〜32767
- 例：`ip access-list extended 101` → `5 deny tcp any any eq telnet`（10 の行より前に入る）

#### 行の削除（ぎょうのさくじょ / removing an entry）

- 意味：ACL の中の1行だけを消すこと
- ポイント：ACL の設定モードに入り、`no 20` のようにシーケンス番号で消す（名前付き ACL は1行ずつ消せる）。グローバル設定で `no access-list 101 …` と書くと ACL 101 が丸ごと消えるので注意
- 例：`ip access-list extended 101` → `no 20`

#### ip access-list resequence（あいぴーあくせすりすとりしーくえんす / ip access-list resequence）

- 意味：ACL の各行のシーケンス番号を、始めの番号と増やし幅を決めて付け直すコマンド
- ポイント：行の順番は変わらず、番号だけが付け直される。番号の間が詰まって新しい行を入れられなくなったときに使う
- 例：`ip access-list resequence kmd1 100 15`（100、115、130 … と付け直す）

#### remark（りまーく / remark）

- 意味：ACL に説明（コメント）を書き込むキーワード。パケットの照合には使われない
- ポイント：1行 100 文字まで。説明する行の前か後か、書く位置をそろえる
- 例：`access-list 1 remark Permit only user1 workstation through`

#### log（ろぐ / log）

- 意味：その行に合ったパケットについて、ログのメッセージ（informational）を出させるキーワード
- ポイント：ログはソフトウェアで作るので、たくさん合うと全部は記録されない。数を正確に数える道具には向かない。`log-input` は受け取ったインタフェースも記録する
- 例：`access-list 101 deny ip any any log`

#### show access-lists（しょうあくせすりすつ / show access-lists）

- 意味：作った ACL の中身を表示するコマンド。`show ip access-lists` は IPv4 の ACL だけに絞って表示する
- ポイント：行ごとに「(15 matches)」のような一致数が出るので、どの行にパケットが合っているか確かめられる。どのインタフェースに付いているかはここでは分からない
- 例：`30 permit ip host 10.2.2.2 any (15 matches)`

#### show ip interface（しょうあいぴーいんたふぇーす / show ip interface）

- 意味：インタフェースの IP の設定と状態を表示するコマンド
- ポイント：ACL が付いていれば、どの ACL がどの向き（in／out）に付いているかが出る。「ACL は正しいのに効かない」ときは、付け忘れや向きちがいをこれで確かめる
- 例：`show ip interface g0/1`

### 22-1 ACL の基本

#### 問 ccna-22-o01

- 問：ルーターが ACL でパケットを調べるときの動きとして正しいものはどれか。
- ア：上の行から順に比べ、最初に合った行で決め、そこで比べるのをやめる
- イ：全部の行と比べ、合った行のうち permit が1つでもあれば通す
- ウ：全部の行と比べ、合った行のうち deny が1つでもあれば捨てる
- エ：最も細かく合う行（ワイルドカードの 0 が最も多い行）で決める
- 正解：ア
- 解説：ACL は上から順に1行ずつ比べ、最初に合った行の permit／deny で決める。その後の行は見ないので、行の順番がとても大切。
- アの意味：正しい。
- イの意味：全部と比べることはしない。最初に合った行だけで決まる。
- ウの意味：同じく、全部と比べることはしない。
- エの意味：ルーティングの最長一致（#12）の考え方。ACL では使わない。
- 出典：オリジナル問題（根拠：Cisco「Security Configuration Guide, IOS XE 17.9 (Catalyst 9300)」Configuring IPv4 ACLs（The first match determines whether the device accepts or rejects the packet. Because the device stops testing after the first match, the order of the conditions is critical））

#### 問 ccna-22-o02

- 問：次の ACL をインタフェースに付けた。この ACL の最後の行の後に、書いていなくても入っているものはどれか。
```
access-list 5 deny host 192.168.10.1
access-list 5 permit 10.0.0.0 0.255.255.255
```
- ア：すべてを捨てる deny
- イ：すべてを通す permit
- ウ：送信元が自分のネットワークのものだけ通す permit
- エ：何も入っていない（合わないパケットはそのまま通る）
- 正解：ア
- 解説：どの ACL にも、最後に「残りは全部 deny」が暗黙に入っている。この例では 10.0.0.0/8 以外の送信元は捨てられる。
- アの意味：正しい（暗黙の deny）。
- イの意味：逆。通したいなら自分で permit any を書く必要がある。
- ウの意味：そのような暗黙の行はない。
- エの意味：合わなかったパケットは捨てられる。
- 出典：オリジナル問題（根拠：Cisco「Configure IP Access Lists」Document ID 23602（If no matches are found when the router reaches the end of the list, the traffic is denied … Every ACL has an implicit deny at the end））

#### 問 ccna-22-o03

- 問：ホスト 192.168.10.1 だけを止め、ほかの送信元は通したい。次の標準 ACL を書いたが、192.168.10.1 も通ってしまった。原因はどれか。
```
access-list 1 permit any
access-list 1 deny host 192.168.10.1
```
- ア：1行目がすべてのパケットに合うので、2行目に届かない
- イ：標準 ACL では host キーワードが使えない
- ウ：最後の暗黙の deny が 2行目を打ち消している
- エ：番号 1 は拡張 ACL の番号なので、行が正しく読まれていない
- 正解：ア
- 解説：上から順に比べるので、permit any が先にあると、192.168.10.1 も1行目で通ってしまう。deny host を上に置けばよい。
- アの意味：正しい。
- イの意味：host は標準 ACL でも使える。
- ウの意味：暗黙の deny は、どの行にも合わなかったパケットにだけ働く。
- エの意味：1〜99 は標準 ACL の番号。
- 出典：オリジナル問題（根拠：Cisco「Configure Commonly Used IP ACLs」Document ID 26448（The order of statements is critical … If the order of the entries is reversed …, the first line matches every packet source address））

#### 問 ccna-22-o04

- 問：ACL の `10.1.1.0 0.0.0.255` のワイルドカードマスクの説明として正しいものはどれか。
- ア：0 のビットは同じでなければならず、1 のビットは何でもよい
- イ：1 のビットは同じでなければならず、0 のビットは何でもよい
