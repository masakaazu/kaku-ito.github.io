## 05-1 書き方と構造

### まとめ表

| 書き方の決まり | 例 | 根拠 |
| :-- | :-- | :-- |
| 16 ビットずつ 8 つを 16 進で書き、コロンでつなぐ | 2001:DB8:0:0:8:800:200C:417A | RFC 4291 2.2 |
| 各フィールドの先頭の 0 は省ける（後ろの 0 は省けない） | 0DB8 → DB8、0800 → 800 | RFC 4291 2.2・2.3 |
| 0 が続くフィールドは「::」でまとめられる。1 つのアドレスで 1 回だけ | 2001:DB8::8:800:200C:417A | RFC 4291 2.2 |
| 推奨：小文字、一番長い 0 の並びを ::、同じ長さなら前、0 が 1 つだけなら :: にしない | 2001:db8::1:0:0:1 | RFC 5952 4 |

### 128 ビットの住所

#### IPv6 アドレス（あいぴーぶいしっくすあどれす / IPv6 address）

- 意味：IPv6 でインタフェースを見分ける 128 ビットの番号。16 ビットずつ 8 つに分けて 16 進で書き、コロン（:）でつなぐ
- ポイント：IPv4 の 32 ビットから 128 ビットへ 4 倍になった（IPv6 Basic CG）。アドレスはノード（機器）ではなくインタフェースに付く。1 つのインタフェースが種類のちがう複数のアドレスを持つのがふつう（RFC 4291 2.1）
- 例：2001:DB8:7654:3210:FEDC:BA98:7654:3210

#### フィールド（ふぃーるど / 16-bit field）

- 意味：IPv6 アドレスを 16 ビットずつに分けた 1 つの区切り。16 進で 1〜4 けた
- ポイント：16 進の 1 けたは 4 ビットなので、4 けたで 16 ビット。英字 A〜F は大文字でも小文字でもよい（IPv6 Basic CG）
- 例：2001:DB8:0:0:8:800:200C:417A の 2 つ目のフィールドは DB8（＝0DB8）

#### 先頭の 0 の省略（せんとうのぜろのしょうりゃく / leading zero suppression）

- 意味：各フィールドの左側の 0 を書かなくてよいという決まり
- ポイント：省けるのは左側（先頭）だけ。右側の 0 を消すと別の値になる。0000 は 0 と書く（RFC 4291 2.3、RFC 5952 4.1）
- 例：0800 → 800 は正しい。CD30 → CD3 はまちがい（0CD3 という別の値になる）

#### ダブルコロン（だぶるころん / double colon "::"）

- 意味：0 だけのフィールドが続く所をまとめて「::」と書く省略
- ポイント：1 つのアドレスで 1 回だけ使える。2 回使うと、それぞれ何個の 0 か決められない（RFC 4291 2.2）。先頭や末尾の 0 もまとめられる
- 例：FF01:0:0:0:0:0:0:101 → FF01::101、0:0:0:0:0:0:0:1 → ::1

#### 推奨表記（すいしょうひょうき / RFC 5952 recommended text representation）

- 意味：1 つのアドレスを 1 通りの書き方にそろえるための推奨（RFC 5952）
- ポイント：①先頭の 0 は必ず省く ②:: はできるだけ長く使う ③0 が 1 つだけのフィールドに :: を使わない ④0 の並びが同じ長さなら前の方を :: にする ⑤英字は小文字。ただし読む側はどの書き方も受け付けなければならない（RFC 5952 4）
- 例：2001:db8:0:0:1:0:0:1 → 2001:db8::1:0:0:1。2001:db8:0:1:1:1:1:1 はそのまま

### プレフィックスとヘッダー

#### プレフィックス長（ぷれふぃっくすちょう / prefix length）

- 意味：アドレスの左から何ビットがプレフィックス（ネットワークの部分）かを表す 10 進数。アドレスのあとに「/」をつけて書く
- ポイント：IPv4 の CIDR と同じ書き方。IPv6 ではマスクを 10 進の点区切りでは書かない（RFC 4291 2.3）
- 例：2001:DB8:0:CD30::/60

#### サブネットプレフィックスとインタフェース ID（さぶねっとぷれふぃっくすとインタフェースあいでぃー / subnet prefix and interface ID）

- 意味：ユニキャストアドレスを前と後ろに分けたときの、リンク（サブネット）を表す前の部分と、そのリンクの中のインタフェースを表す後ろの部分
- ポイント：先頭が 2 進 000 以外のユニキャストでは、インタフェース ID は 64 ビット。だからふつうのサブネットは /64（RFC 4291 2.5.1・2.5.4）
- 例：2001:DB8:C18:1:260:3EFF:FE47:1530 → プレフィックス 2001:DB8:C18:1::/64、インタフェース ID 260:3EFF:FE47:1530（IPv6 Basic CG の例）

#### IPv6 ヘッダー（あいぴーぶいしっくすへっだー / IPv6 header）

- 意味：IPv6 パケットの先頭に付く情報。Version・Traffic Class・Flow Label・Payload Length・Next Header・Hop Limit・送信元アドレス・宛先アドレスの 8 つの欄
- ポイント：長さが変わらない形（固定長）で、IPv4 のオプションにあたるものは拡張ヘッダーとして後ろにつなぐ。Cisco は「簡単になったヘッダー」と説明する（RFC 8200 3、IPv6 Basic CG）。図の欄を足すと 40 バイト（Claude が RFC 8200 の図から計算）
- 例：Next Header ＝ 次に続くヘッダーの種類（IPv4 の Protocol 欄と同じ値）

#### ホップリミット（ほっぷりみっと / Hop Limit）

- 意味：IPv6 ヘッダーの 8 ビットの欄。パケットを転送する機器ごとに 1 減らし、0 になったら捨てる
- ポイント：IPv4 の TTL にあたる。RA でホストに使う値を知らせることもできる（RFC 8200 3、RFC 4861 3）
- 例：Hop Limit 1 のパケットは同じリンクの外には出ない（Claude の例）

## 05-2 ユニキャストの種類

### まとめ表

| 種類 | プレフィックス | 届く範囲 | 根拠 |
| :-- | :-- | :-- | :-- |
| グローバルユニキャスト | 2000::/3 | インターネット全体 | RFC 3587、IANA |
| ユニークローカル | FC00::/7（実際は FD00::/8） | 組織の中 | RFC 4193 |
| リンクローカル | FE80::/10 | 同じリンクだけ | RFC 4291 2.5.6 |
| ループバック | ::1/128 | 自分の中だけ | RFC 4291 2.5.3 |
| 未指定 | ::/128 | 宛先にしない | RFC 4291 2.5.2 |
| サイトローカル（廃止） | FEC0::/10 | 使わない | RFC 4291 2.5.7 |

### 外とつながるアドレス

#### ユニキャストアドレス（ゆにきゃすとあどれす / unicast address）

- 意味：1 つのインタフェースを表すアドレス。宛先にすると、そのインタフェースに届く
- ポイント：IPv6 のアドレスはユニキャスト・エニーキャスト・マルチキャストの 3 種類。ブロードキャストはない（RFC 4291 2）
- 例：グローバルユニキャスト、ユニークローカル、リンクローカル

#### グローバルユニキャストアドレス（ぐろーばるゆにきゃすとあどれす / global unicast address, GUA）

- 意味：インターネット全体でただ 1 つになるユニキャストアドレス。IPv4 のグローバルアドレスにあたる
- ポイント：IANA が今割り当てているのは 2000::/3（先頭 3 ビットが 001）。つまり先頭のフィールドが 2〜3 で始まる。形は「グローバルルーティングプレフィックス＋サブネット ID＋インタフェース ID（64）」（RFC 3587 3、IANA）
- 例：2001:DB8:C18:1:260:3EFF:FE47:1530（文書用の値）
- 語の意味：global＝全世界の、unicast＝1 対 1 の送信

#### グローバルルーティングプレフィックス（ぐろーばるるーてぃんぐぷれふぃっくす / global routing prefix）

- 意味：グローバルユニキャストアドレスの先頭の部分。ISP などからサイト（組織）に割り当てられる
- ポイント：RIR と ISP が階層にして配る（RFC 3587 3）。RFC 3587 の例では 001 の後ろの 45 ビット（001 と合わせて 48 ビット＝/48）
- 例：2001:DB8:ACAD::/48 を組織に割り当て（Claude の例）

#### サブネット ID（さぶねっとあいでぃー / subnet ID）

- 意味：グローバルルーティングプレフィックスとインタフェース ID の間にある、組織の中のリンクを表す部分
- ポイント：組織の管理者が自分で決める。/48 を受け取ると、サブネット ID は 64−48＝16 ビットで、/64 のサブネットを 2^16＝65,536 個作れる（RFC 3587 3 の形から Claude が計算）
- 例：2001:DB8:ACAD:0001::/64、2001:DB8:ACAD:0002::/64 …

### 組織とリンクの中だけのアドレス

#### ユニークローカルアドレス（ゆにーくろーかるあどれす / unique local address, ULA）

- 意味：組織の中で使うためのユニキャストアドレス。FC00::/7 の範囲
- ポイント：8 ビット目（L ビット）を 1 にする決まりなので、実際は FD で始まる。後ろの 40 ビットのグローバル ID は乱数で作る。組織の外（BGP など）には広告しない（RFC 4193 3.1・3.2・4.1）。IPv4 のプライベートアドレスに似た使い方
- 例：FD12:3456:789A:1::1/64（Claude の例）

#### グローバル ID（ぐろーばるあいでぃー / Global ID）

- 意味：ユニークローカルアドレスの FD のあとに続く 40 ビット。組織ごとに乱数で作る
- ポイント：順番どおりや覚えやすい値で決めてはいけない。乱数なので、2 つの組織が合併しても重なる見込みはとても小さい（RFC 4193 3.2・4.2）
- 例：FD12:3456:789A::/48 の 12:3456:789A

#### リンクローカルアドレス（りんくろーかるあどれす / link-local address, LLA）

- 意味：1 つのリンク（ルーターで区切られた区間）の中だけで使うユニキャストアドレス。FE80::/10
- ポイント：すべてのインタフェースが必ず 1 つ持つ。ルーターはリンクローカルが送信元・宛先のパケットを別のリンクへ転送しない。近隣探索や自動設定に使う（RFC 4291 2.1・2.5.6）。IOS では 1 つのインタフェースに 1 つだけ（IPv6 Basic CG）
- 例：FE80::260:3EFF:FE47:1530（IPv6 Basic CG の例）

#### サイトローカルアドレス（さいとろーかるあどれす / site-local address）

- 意味：昔、組織の中で使うために決められた FEC0::/10 のアドレス
- ポイント：今は廃止。新しい実装はグローバルユニキャストとして扱う（RFC 4291 2.5.7、IANA）。組織の中ならユニークローカルを使う
- 例：FEC0::1（使わない）

### 特別なアドレス

#### ループバックアドレス（るーぷばっくあどれす / loopback address）

- 意味：自分自身に送るためのアドレス。::1（0:0:0:0:0:0:0:1）
- ポイント：物理インタフェースには付けない。宛先がこのアドレスのパケットは機器の外に出さず、ルーターも転送しない（RFC 4291 2.5.3）。IPv4 の 127.0.0.1 にあたる
- 例：ping ::1

#### 未指定アドレス（みしていあどれす / unspecified address）

- 意味：「アドレスがない」ことを表す ::（すべて 0）
- ポイント：機器には付けない。宛先にもしない。自分のアドレスをまだ持たないホストが送るパケットの送信元に入る（RFC 4291 2.5.2）。DAD の NS の送信元もこれ（RFC 4862 5.4.2）
- 例：送信元 ::、宛先 FF02::1:FF12:3456

#### IPv4 射影アドレス（あいぴーぶいふぉーしゃえいあどれす / IPv4-mapped IPv6 address）

- 意味：下位 32 ビットに IPv4 アドレスを入れ、その前を 0…0:FFFF にした IPv6 アドレス
- ポイント：IPv4 の機器のアドレスを IPv6 アドレスの形で表すためのもの。下位 32 ビットは点区切りの 10 進で書いてよい（RFC 4291 2.2・2.5.5.2、RFC 5952 5）。上位が全部 0 の「IPv4 互換アドレス」は廃止
- 例：::FFFF:129.144.52.38

#### 文書用のプレフィックス（ぶんしょようのぷれふぃっくす / documentation prefix）

- 意味：本や資料の例に使うために取っておかれた 2001:DB8::/32
- ポイント：どの組織にも割り当てない。経路として流さない範囲としてフィルターに入れる（RFC 3849）。Cisco の資料の例もこの範囲
- 例：2001:DB8:0:1::/64

## 05-3 エニーキャストとマルチキャスト

### まとめ表

| アドレス | 意味 | 根拠 |
| :-- | :-- | :-- |
| FF02::1 | 同じリンクの全ノード | RFC 4291 2.7.1 |
| FF02::2 | 同じリンクの全ルーター | RFC 4291 2.7.1 |
| FF02::5・FF02::6 | OSPF のルーター・DR | IANA |
| FF02::9・FF02::A | RIP・EIGRP のルーター | IANA |
| FF02::1:FFxx:xxxx | 要請ノード（下位 24 ビットから作る） | RFC 4291 2.7.1 |
| プレフィックス＋全部 0 | サブネットルーター・エニーキャスト | RFC 4291 2.6.1 |

### 1 対「いちばん近い 1」

#### エニーキャストアドレス（えにーきゃすとあどれす / anycast address）

- 意味：複数のインタフェース（ふつうは別々の機器）に同じアドレスを付け、送ると経路の上で「いちばん近い」1 つに届くアドレス
- ポイント：ユニキャストの範囲から取るので、見た目ではユニキャストと区別できない。付ける機器に「これはエニーキャスト」と設定する（RFC 4291 2.6）。IOS では `ipv6 address … anycast`、show では [ANY] と出る（IOS IPv6 CR、9300 CR）
- 例：ipv6 address 2001:0DB8:1:1:FFFF:FFFF:FFFF:FFFE/64 anycast（IOS IPv6 CR の例）
- 語の意味：any＝どれか 1 つ

#### サブネットルーター・エニーキャストアドレス（さぶねっとるーたーえにーきゃすとあどれす / Subnet-Router anycast address）

- 意味：サブネットプレフィックスのあとのインタフェース ID を全部 0 にしたアドレス。そのサブネットのルーターのどれか 1 台に届く
- ポイント：ルーターはつながっているサブネットについて必ず受け付ける（RFC 4291 2.6.1・2.8）。/127 を使うリンクではこれを止める（RFC 6164 6）
- 例：2001:DB8:1:1::/64 のサブネットルーター・エニーキャスト ＝ 2001:DB8:1:1::

### 1 対グループ

#### マルチキャストアドレス（まるちきゃすとあどれす / multicast address）

- 意味：グループに入っているインタフェース全部に届くアドレス。FF00::/8（先頭 8 ビットが全部 1）
- ポイント：FF の次の 4 ビットがフラグ、その次の 4 ビットがスコープ（届く範囲）。送信元には使えない（RFC 4291 2.7）
- 例：FF02::1、FF05::2

#### スコープ（すこーぷ / scope, scop）

- 意味：マルチキャストアドレスの FF の後ろ 2 けた目にある、届く範囲を表す 4 ビットの値
- ポイント：1＝インタフェースの中、2＝リンク、5＝サイト、8＝組織、E＝グローバル。ルーターはスコープの外へ転送しない（RFC 4291 2.7）
- 例：FF02::101 ＝ 同じリンクの NTP サーバー、FF0E::101 ＝ インターネットの NTP サーバー（RFC 4291 の例）

#### 全ノードマルチキャスト（ぜんのーどまるちきゃすと / all-nodes multicast address）

- 意味：同じリンクのすべての IPv6 ノードを表す FF02::1
- ポイント：ホストも必ず受け付けるアドレス（RFC 4291 2.8）。IPv4 のブロードキャストに近い使い方をする。定期の RA の宛先はここ（RFC 4861 4.2「the all-nodes multicast address」）
- 例：show ipv6 interface の Joined group に FF02::1

#### 全ルーターマルチキャスト（ぜんるーたーまるちきゃすと / all-routers multicast address）

- 意味：同じリンクのすべての IPv6 ルーターを表す FF02::2（サイト全体なら FF05::2）
- ポイント：ルーターだけが受け付ける（RFC 4291 2.7.1・2.8）。RA を送るインタフェースではルーターが必ずこのグループに入る（RFC 4861 6.2.2）。IPv6 Basic CG の出力例でも ipv6 unicast-routing のあとに FF02::2 が並ぶ
- 例：RS の宛先はふつうここ（RFC 4861 4.1「Typically the all-routers multicast address」）

#### 要請ノードマルチキャストアドレス（ようせいのーどまるちきゃすとあどれす / solicited-node multicast address）

- 意味：ユニキャスト（またはエニーキャスト）アドレスの下位 24 ビットを FF02::1:FF00:0/104 の後ろにつけて作るマルチキャストアドレス
- ポイント：ノードは自分の各アドレスについてこのグループに入る。アドレス解決の NS はここへ送るので、リンクの全員ではなく、下位 24 ビットが同じ相手だけが受け取る（RFC 4291 2.7.1、RFC 4861 3）
- 例：2001::A8BB:CCFF:FE00:6700 → FF02::1:FF00:6700（9300 CR の出力例）

#### ブロードキャスト（ぶろーどきゃすと / broadcast）

- 意味：IPv4 で、そのネットワークの全員に届けるしくみ
- ポイント：IPv6 にはブロードキャストアドレスがなく、役目はマルチキャストに置きかわった（RFC 4291 2）。ARP のブロードキャストの代わりは、要請ノードマルチキャストあての NS
- 例：IPv4 の 255.255.255.255 にあたるものは IPv6 にない

## 05-4 インタフェース ID と自動設定

### まとめ表

| 手順（修正 EUI-64） | 例：MAC 0003.a0d6.141e |
| :-- | :-- |
| ① MAC を前 24 ビットと後ろ 24 ビットに分ける | 0003a0 ／ d6141e |
| ② 間に FFFE を入れて 64 ビットにする | 0003:a0ff:fed6:141e |
| ③ 先頭から 7 ビット目（U/L ビット）を反転 | 00 → 02 で 0203:a0ff:fed6:141e |
| ④ プレフィックスの後ろにつける | FE80::203:A0FF:FED6:141E |

### 64 ビットの作り方

#### 修正 EUI-64（しゅうせいいーゆーあいろくじゅうよん / Modified EUI-64）

- 意味：48 ビットの MAC アドレスなどから、64 ビットのインタフェース ID を作る方法
- ポイント：MAC の真ん中に FFFE を入れ、U/L ビットを反転する（RFC 4291 2.5.1・付録 A）。IOS の `ipv6 address 〜/64 eui-64` と、自動でつくるリンクローカルはこれを使う（IPv6 Basic CG）。show では [EUI] と出る（9300 CR）
- 例：MAC 0003.a0d6.141e → FE80::203:A0FF:FED6:141E（9300 CR の show ipv6 neighbors の行。計算は Claude）
- 語の意味：EUI＝Extended Unique Identifier（拡張した、ただ 1 つの識別子）

#### U/L ビット（ゆーえるびっと / universal/local bit, u bit）

- 意味：MAC アドレスの先頭のオクテットの、左から 7 ビット目。もとの MAC では 0＝世界で 1 つ、1＝その場で決めた値
- ポイント：修正 EUI-64 ではこのビットを反転するので、インタフェース ID では 1＝世界で 1 つになる。先頭のオクテットの値でいうと 2 を足すか引く（RFC 4291 2.5.1・付録 A。値での言い方は Claude）
- 例：00 → 02、3C → 3E、02 → 00

#### FFFE（えふえふえふいー / 0xFFFE）

- 意味：修正 EUI-64 で、48 ビットの MAC の前 24 ビットと後ろ 24 ビットの間に入れる 16 ビット
- ポイント：入れる場所は真ん中（会社の番号と製品の番号の間）。末尾につけるのではない（RFC 4291 付録 A）
- 例：0060.3e47.1530 → 0060:3EFF:FE47:1530 → 反転して 260:3EFF:FE47:1530（IPv6 Basic CG のインタフェース ID。もとの MAC は Claude が逆算）

#### 一時アドレス（いちじあどれす / temporary address）

- 意味：インタフェース ID を乱数で作り、時間がたつと取りかえるアドレス
- ポイント：MAC から作るインタフェース ID は変わらないので、同じ機器だと追跡されやすい。一時アドレスはそれを防ぐ（RFC 8981）。RFC 4291 も、プライバシーのための一時的な値をローカルのインタフェース ID の例にあげている
- 例：Windows や macOS の「一時」アドレス（Claude の例）

### 近隣探索

#### 近隣探索（きんりんたんさく / Neighbor Discovery, NDP）

- 意味：同じリンクの機器どうしで、ルーターを見つける・MAC を調べる・アドレスの重なりを調べる・よりよい次の転送先を教える、などを行う ICMPv6 のしくみ
- ポイント：IPv4 の ARP・ICMP ルーター発見・ICMP リダイレクトを合わせたもの。メッセージは RS・RA・NS・NA・Redirect の 5 種類（RFC 4861 3・3.1）
- 例：show ipv6 neighbors で近隣キャッシュ（IPv4 の ARP 表にあたる）を見る

#### ルーター要請（るーたーようせい / Router Solicitation, RS）

- 意味：ホストが「ルーターはいますか、RA をすぐ送って」と求めるメッセージ。ICMPv6 タイプ 133
- ポイント：インタフェースが有効になったときに送る。次の定期の RA を待たずに自動設定できる（RFC 4861 3、SLAAC CG）
- 例：PC の起動直後に RS → ルーターが RA を返す

#### ルーター広告（るーたーこうこく / Router Advertisement, RA）

- 意味：ルーターが自分がいることと、プレフィックスやホップリミットなどを知らせるメッセージ。ICMPv6 タイプ 134
- ポイント：定期的に、また RS への返事として送る。ホストは RA のプレフィックスでアドレスを作り、RA を送ったルーターを既定のルーターの候補にする。DHCPv6 を使うかどうかも RA のフラグで伝える（RFC 4861 3、SLAAC CG）
- 例：ND router advertisements are sent every 200 seconds（IPv6 Basic CG の出力例）

#### 近隣要請と近隣広告（きんりんようせいときんりんこうこく / Neighbor Solicitation and Neighbor Advertisement, NS / NA）

- 意味：相手の MAC を調べる質問（NS、タイプ 135）と、その答え（NA、タイプ 136）
- ポイント：NS は相手のアドレスの要請ノードマルチキャストへ送り、NA はユニキャストで返る。1 往復で両方が相手の MAC を知る。NS は相手がまだ届くかの確認と DAD にも使う（RFC 4861 3）
- 例：FE80::1 の MAC を知りたい → 宛先 FF02::1:FF00:1 へ NS

### 自動でアドレスを付ける

#### SLAAC（すらっく / Stateless Address Autoconfiguration）

- 意味：ホストが RA のプレフィックス（64 ビット）に自分のインタフェース ID（64 ビット）をつけて、サーバーなしで自分のアドレスを作るしくみ
- ポイント：どのホストにどのアドレスを渡したかを誰も覚えていない（ステートレス）。きっちり管理したいときは DHCPv6。両方を同時に使うこともできる（RFC 4862 1、SLAAC CG）。作ったアドレスは DAD で確かめる
- 例：RA のプレフィックス 2001:DB8:1:10::/64 ＋ インタフェース ID → 2001:DB8:1:10:3E5A:B4FF:FE12:3456（Claude の例）
- 語の意味：stateless＝状態（だれに何を渡したか）を持たない、autoconfiguration＝自動設定

#### DAD（だっど / Duplicate Address Detection）

- 意味：アドレスをインタフェースに付ける前に、同じリンクで他の機器が使っていないかを確かめる手順
- ポイント：SLAAC・DHCPv6・手動のどれでも、ユニキャストアドレスに行う（エニーキャストには行わない）。送信元 ::、宛先は調べるアドレスの要請ノードマルチキャストで NS を送る。重なりが見つかったアドレスは使えない（RFC 4862 1・5.4）。IOS では [DUP] と表示（9300 CR）
- 例：ND DAD is enabled, number of DAD attempts: 1（9300 CR の出力例）
- 語の意味：duplicate＝重なった、detection＝見つけること

### アドレスを付けるコマンド

#### ipv6 unicast-routing（あいぴーぶいしっくすゆにきゃすとるーてぃんぐ / ipv6 unicast-routing）

- 意味：機器全体で IPv6 のユニキャストのパケットの転送を有効にするグローバル設定のコマンド
- ポイント：初期状態では IPv6 のアドレスはなく、IPv6 のルーティングも無効。インタフェースにアドレスを付けただけでは、ルーターとしてパケットを転送しない（IPv6 Basic CG）。入れると RA を送り始める（IPv6 Basic CG の出力例「ND router advertisements are sent every 200 seconds」）
- 例：Device(config)# ipv6 unicast-routing

#### ipv6 address（あいぴーぶいしっくすあどれす / ipv6 address ipv6-address/prefix-length）

- 意味：インタフェースに IPv6 アドレスとプレフィックス長を付け、そのインタフェースで IPv6 を使えるようにするコマンド
- ポイント：IPv4 の ip address とちがい、1 つのインタフェースに何個でも付けられる（secondary は要らない）。リンクローカルは自動で 1 つ付く（IPv6 Basic CG、IOS IPv6 CR）
- 例：ipv6 address 2001:DB8:c18:1::3/64（IPv6 Basic CG のデュアルスタックの例）

#### ipv6 address eui-64（あいぴーぶいしっくすあどれすいーゆーあいろくじゅうよん / ipv6 address ipv6-prefix/prefix-length eui-64）

- 意味：前 64 ビットのプレフィックスだけを書き、後ろ 64 ビットをインタフェースの MAC から修正 EUI-64 で作るコマンド
- ポイント：/64 より長いプレフィックス長を書いたときは、プレフィックスのビットが優先される（IOS IPv6 CR）。結果は show ipv6 interface で確かめる
- 例：ipv6 address 2001:DB8:c18:1::/64 eui-64 → 2001:DB8:C18:1:260:3EFF:FE47:1530（IPv6 Basic CG）

#### ipv6 address link-local（あいぴーぶいしっくすあどれすりんくろーかる / ipv6 address ipv6-address link-local）

- 意味：自動で作られるリンクローカルの代わりに、手で決めたリンクローカルを付けるコマンド
- ポイント：リンクローカルは 1 つのインタフェースに 1 つだけ（IPv6 Basic CG）。FE80::1 のように短くすると、隣のルーターのネクストホップを読みやすい（Claude の補足）
- 例：ipv6 address FE80::1 link-local

#### ipv6 enable（あいぴーぶいしっくすいねーぶる / ipv6 enable）

- 意味：グローバルアドレスを付けずに、リンクローカルだけを自動で作って IPv6 を使えるようにするコマンド
- ポイント：初期は無効。アドレスを付けたインタフェースでは、no ipv6 enable を入れても IPv6 は止まらない（IOS IPv6 CR）
- 例：Device(config-if)# ipv6 enable

#### ipv6 address autoconfig（あいぴーぶいしっくすあどれすおーとこんふぃぐ / ipv6 address autoconfig）

- 意味：インタフェースで SLAAC を使い、受け取った RA のプレフィックスから EUI-64 のアドレスを作るコマンド
- ポイント：default を付けると、そのインタフェースで選んだ既定のルーターへの既定ルートも入れる（default は 1 つのインタフェースだけ）（IOS IPv6 CR、SLAAC CG）。ルーターを ISP にホストのようにつなぐときに使う（Claude の補足）
- 例：ipv6 address autoconfig default

#### ipv6 address anycast（あいぴーぶいしっくすあどれすえにーきゃすと / ipv6 address ipv6-prefix/prefix-length anycast）

- 意味：インタフェースにエニーキャストアドレスを付けるコマンド
- ポイント：エニーキャストは見た目で区別できないので、付ける機器で anycast と明示する（RFC 4291 2.6、IOS IPv6 CR）。DAD は行わない（RFC 4862 5.4）
- 例：ipv6 address 2001:0DB8:1:1:FFFF:FFFF:FFFF:FFFE/64 anycast（IOS IPv6 CR）

### 確かめるコマンドと設計

#### show ipv6 interface（しょーあいぴーぶいしっくすいんたーふぇーす / show ipv6 interface）

- 意味：インタフェースの IPv6 の状態、リンクローカル、グローバルアドレス、入っているマルチキャストグループ、ND の設定を表示するコマンド
- ポイント：アドレスの後ろの印：EUI＝EUI-64 で作った、DUP＝DAD で重なりが見つかった、ANY＝エニーキャスト、TEN＝DAD の途中。リンクローカルが重なると「IPv6 is stalled」となり IPv6 の処理が止まる（9300 CR）
- 例：IPv6 is enabled, link-local address is FE80::A8BB:CCFF:FE00:6700（9300 CR）

#### show ipv6 interface brief（しょーあいぴーぶいしっくすいんたーふぇーすぶりーふ / show ipv6 interface brief）

- 意味：インタフェースごとの状態と IPv6 アドレスを 1 覧で短く表示するコマンド
- ポイント：[up/up] のように状態が出て、その下にアドレスが並ぶ。IPv4 の show ip interface brief にあたる（9300 CR）
- 例：Ethernet5 [administratively down/down]（9300 CR の出力例）

#### show ipv6 neighbors（しょーあいぴーぶいしっくすねいばーず / show ipv6 neighbors）

- 意味：近隣探索で調べた、隣の機器の IPv6 アドレスと MAC の対応（ND キャッシュ）を表示するコマンド
- ポイント：IPv4 の show ip arp にあたる。State：INCMP＝NS を送ったが NA が来ていない、REACH＝最近届くのを確かめた、STALE＝しばらく確かめていない（9300 CR）
- 例：FE80::203:A0FF:FED6:141E 0 0003.a0d6.141e REACH Ethernet2（9300 CR）

#### /127（すらっしゅひゃくにじゅうなな / 127-bit prefix）

- 意味：ルーターどうしの 1 対 1 のリンクで使う、アドレスが 2 つだけのプレフィックス
- ポイント：IPv4 の /31 にあたる。ルーターは /127 に対応しなければならず、そのプレフィックスではサブネットルーター・エニーキャストを止める（RFC 6164 6）。ふつうのリンクは /64
- 例：2001:DB8:FFFF::/127 → ::0 と ::1 を両端に付ける（Claude の例）

#### デュアルスタック（でゅあるすたっく / dual stack）

- 意味：1 台の機器やインタフェースで IPv4 と IPv6 を同時に動かすこと。IPv6 へ移るための方法
- ポイント：インタフェースに IPv4 と IPv6 の両方のアドレスを付けると、両方を転送する。DNS が両方のアドレスを返すと、アプリはふつう IPv6 を選ぶ（IPv6 Basic CG）
- 例：ip address 192.168.99.1 255.255.255.0 と ipv6 address 2001:DB8:c18:1::3/64 を同じインタフェースに（IPv6 Basic CG）
- 語の意味：dual＝2 つの、stack＝プロトコルの積み重ね

### 05-1 書き方と構造

#### 問 ccna-05-o01

- 問：`2001:0DB8:0000:0000:0000:0A00:0000:0001` を、できるだけ短く正しく書いたものはどれか。
- ア：2001:DB8::A00:0:1
- イ：2001:DB8::A::1
- ウ：2001:DB8::A:0:1
- エ：2001:DB8:0:A00::1
- 正解：ア
- 解説：0 が 3 つ続く所を :: にし、0A00 は先頭の 0 だけを省いて A00、0000 は 0 と書く。0 が 1 つだけの所は :: にしない。
- アの意味：正しい。0 が 3 つ続く部分を :: にまとめている。
- イの意味：:: を 2 回使っており、それぞれ何個の 0 かが決まらないので書けない。
- ウの意味：A00 の後ろの 0 を消して A にしている。後ろの 0 は省けない（000A という別の値になる）。
- エの意味：正しく戻せるアドレスだが、0 が 1 つの所でなく長い 3 つの所を :: にした方が短い。
- 出典：オリジナル問題（根拠：RFC 4291 2.2（The "::" can only appear once in an address／it is not necessary to write the leading zeros in an individual field）／RFC 4291 2.3（may drop leading zeros, but not trailing zeros, within any 16-bit chunk）／RFC 5952 4.2.1（The use of the symbol "::" MUST be used to its maximum capability））

#### 問 ccna-05-o02

- 問：IPv6 アドレスの書き方として誤っているものはどれか。
- ア：2001:DB8::1::2
- イ：::1
- ウ：FF01::101
- エ：2001:DB8:0:CD30::/60
- 正解：ア
- 解説：:: は 1 つのアドレスで 1 回しか使えない。2 回あると、前と後ろのそれぞれに何個の 0 が入るか決まらない。
- アの意味：誤り。:: が 2 回ある。
- イの意味：ループバックアドレス（0:0:0:0:0:0:0:1）の正しい省略。
- ウの意味：FF01:0:0:0:0:0:0:101 の正しい省略。
- エの意味：60 ビットのプレフィックス 2001:0DB8:0000:CD3 の正しい書き方の 1 つ。
- 出典：オリジナル問題（根拠：RFC 4291 2.2（The "::" can only appear once in an address／FF01::101 a multicast address／::1 the loopback address）／RFC 4291 2.3（2001:0DB8:0:CD30::/60 が legal の例））

#### 問 ccna-05-o03

- 問：RFC 5952 の推奨表記で、`2001:db8:0:0:1:0:0:1` を書いたものはどれか。
- ア：2001:db8::1:0:0:1
- イ：2001:db8:0:0:1::1
- ウ：2001:DB8::1:0:0:1
- エ：2001:db8::1::1
- 正解：ア
- 解説：0 が 2 つ続く所が 2 か所あり、長さが同じ。このときは前の方を :: にする。英字は小文字。
- アの意味：正しい。
- イの意味：戻すと同じアドレスになるが、同じ長さなら前を :: にするという推奨に合わない。
- ウの意味：RFC 5952 は英字を小文字で書くよう求める。
- エの意味：:: が 2 回あり、そもそも書けない。
- 出典：オリジナル問題（根拠：RFC 5952 4.2.3（When the length of the consecutive 16-bit 0 fields are equal … the first sequence of zero bits MUST be shortened. For example, 2001:db8::1:0:0:1 is correct representation）／4.3（MUST be represented in lowercase））

#### 問 ccna-05-o04

- 問：`2001:db8:0:1:1:1:1:1` について、RFC 5952 の推奨にしたがった説明はどれか。
- ア：0 のフィールドが 1 つだけなので :: を使わず、このまま書く
- イ：2001:db8::1:1:1:1:1 と書く
- ウ：先頭の 2001 を 2001:: と書く
- エ：0 を 0000 と書く
- 正解：ア
- 解説：:: は 16 ビットの 0 が 1 つだけの所には使わない。また、0000 は 0 と書く。
- アの意味：正しい。
- イの意味：0 が 1 つだけの所に :: を使っており、推奨に合わない。
- ウの意味：2001 は 0 ではないので省略できない。
- エの意味：先頭の 0 は必ず省き、0000 は 0 と書く。
- 出典：オリジナル問題（根拠：RFC 5952 4.2.2（The symbol "::" MUST NOT be used to shorten just one 16-bit 0 field. For example, the representation 2001:db8:0:1:1:1:1:1 is correct）／4.1（A single 16-bit 0000 field MUST be represented as 0））

#### 問 ccna-05-o05

- 問：インタフェースのアドレスが `2001:DB8:ACAD:1234:5678::9/64` のとき、このインタフェースのサブネットのプレフィックスはどれか。
- ア：2001:DB8:ACAD:1234::/64
- イ：2001:DB8:ACAD::/64
- ウ：2001:DB8:ACAD:1234:5678::/64
- エ：2001:DB8::/64
- 正解：ア
- 解説：/64 は前の 4 つのフィールド（16×4＝64 ビット）。そこまでを残し、後ろを 0 にする。
- アの意味：正しい。前の 4 フィールドが 2001:DB8:ACAD:1234。
- イの意味：/48 までしか残しておらず、4 つ目のフィールド 1234 を落としている。
- ウの意味：5 つ目のフィールド（インタフェース ID の一部）まで残している。/80 にあたる。
- エの意味：/32 までしか残していない。
- 出典：オリジナル問題（根拠：RFC 4291 2.3（the node address 2001:0DB8:0:CD30:123:4567:89AB:CDEF and its subnet number 2001:0DB8:0:CD30::/60）／RFC 4291 2.5.4（n + m = 64））

#### 問 ccna-05-o06

- 問：ISP から /48 のプレフィックスを受け取った組織が、すべてのリンクに /64 を割り当てる。作れる /64 のサブネットの数はどれか。
- ア：65,536
- イ：256
- ウ：16
- エ：2^64
- 正解：ア
- 解説：サブネット ID は 64−48＝16 ビット。2^16＝65,536 個。
- アの意味：正しい。
- イの意味：/56 から /64 を作るとき（8 ビット）の数。
- ウの意味：サブネット ID のビット数そのもの。
- エの意味：1 つの /64 の中のインタフェース ID の数。
- 出典：オリジナル問題（根拠：RFC 3587 3（| 3 | 45 bits | 16 bits | 64 bits |／the subnet ID is an identifier of a subnet within the site）。数は Claude が計算）

### 05-2 ユニキャストの種類

#### 問 ccna-05-o07

- 問：`FE80::260:3EFF:FE47:1530` はどの種類のアドレスか。
- ア：リンクローカルユニキャスト
- イ：ユニークローカルユニキャスト
- ウ：マルチキャスト
- エ：サイトローカルユニキャスト
- 正解：ア

- 出典：オリジナル問題（根拠：RFC 8981 Abstract（generate temporary addresses with randomized interface identifiers … limits the window of time during which eavesdroppers … may trivially perform address-based network-activity correlation）／RFC 4862 5.4（MUST be performed on all unicast addresses））

### 05-5 IOS での設定と確認

#### 問 ccna-05-o25

- 問：ルーターの 2 つのインタフェースに IPv6 アドレスを付けたが、IPv6 のパケットが 2 つの LAN の間を流れない。IPv4 は流れている。まず足りないと考えられる設定はどれか。

- ウ：ipv6 enable
- エ：ipv6 address autoconfig
- 正解：ア

- イの意味：IPv4 のルーティング。IPv4 が流れているので有効になっている。
- ウの意味：アドレスがすでにあるインタフェースでは IPv6 の処理は有効。転送の有無は変わらない。
- エの意味：RA からアドレスを作るコマンドで、転送を有効にするものではない。
- 出典：オリジナル問題（根拠：IPv6 Basic CG（By default, IPv6 addresses are not configured and IPv6 routing is disabled／ipv6 unicast-routing Enables the forwarding of IPv6 unicast datagrams）／IOS IPv6 CR ipv6 enable）

#### 問 ccna-05-o26

- 問：インタフェースに `ipv6 enable` だけを入れたときの状態として正しいものはどれか。
- ア：リンクローカルアドレスだけが自動で付き、IPv6 の処理が有効になる

- ウ：ipv6 unicast-routing も自動で有効になる
- エ：リンクローカルを 2 つ作り、片方を予備にする
- 正解：ア
- 解説：ipv6 enable はグローバルアドレスなしで IPv6 を有効にし、リンクローカルだけを作る。ルーター間のリンクでリンクローカルだけで経路をやりとりするときにも使える（Claude の補足）。

- エの意味：リンクローカルは 1 つのインタフェースに 1 つだけ。

#### 問 ccna-05-o28

- 問：`show ipv6 neighbors` の State 列が INCMP の行が意味するものはどれか。
- ア：要請ノードマルチキャストへ NS を送ったが、まだ NA が返ってきていない
- イ：最近、相手に届くことを確かめた
- ウ：しばらく相手に届くことを確かめていないが、パケットを送るまでは何もしない

- 出典：オリジナル問題（根拠：9300 CR 17.8 show ipv6 neighbors（INCMP (Incomplete)--Address resolution is being performed on the entry. A neighbor solicitation message has been sent to the solicited-node multicast address of the target, but the corresponding neighbor advertisement message has not yet been received／REACH／STALE））

#### 問 ccna-05-o29

- 問：ISP につながるルーターのインタフェースで、RA からアドレスを作り、さらに RA を送ったルーターへの既定ルートも入れたい。入れるコマンドはどれか。

#### 問 ccna-05-o30

- 問：ルーターどうしを 1 対 1 でつなぐリンクに /127 のプレフィックスを使う。RFC 6164 にしたがった説明として正しいものはどれか。
- ア：ルーターは /127 に対応しなければならず、そのプレフィックスではサブネットルーター・エニーキャストを止める
- イ：/127 では両端のアドレスに加えて、ネットワークアドレスとブロードキャストアドレスが要る
- ウ：/127 は IPv4 の /30 にあたり、4 つのアドレスを持つ
- エ：/127 のリンクでは、リンクローカルアドレスは作られない
- 正解：ア
- 解説：/127 はアドレスが 2 つだけで、IPv4 の /31 にあたる。インタフェース ID が全部 0 のアドレスがサブネットルーター・エニーキャストと重なるので、それを止める。
- アの意味：正しい。
- イの意味：IPv6 にブロードキャストアドレスはない。/127 の 2 つは両端に付ける。
- ウの意味：IPv4 の /31 にあたり、アドレスは 2 つ。
- エの意味：リンクローカルはすべてのインタフェースが必ず持つ。
- 出典：オリジナル問題（根拠：RFC 6164 Abstract（Such a practice parallels the use of 31-bit prefixes in IPv4）／6（Routers MUST support the assignment of /127 prefixes on point-to-point inter-router links.
