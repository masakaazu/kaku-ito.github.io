## 19-1 QoS の考え方

### まとめ表

| 項目 | 内容 |
| :-: | :-: |
| QoS の目的 | 回線が混んだとき（輻輳）に、大事な通信を先に・確実に送る |
| 管理する4つ | 帯域・遅延・ジッター・損失 |
| 音声の目安 | 片道遅延 150 ms 未満（ITU G.114）・損失はごくわずか（1% よりずっと小さく）・ジッターは小さく |
| 1台ずつの動き | PHB（パケットを分類し、印を付け、キューに入れ、落とす・制限する） |

### 品質の4つの要素

#### QoS（きゅーおーえす / Quality of Service）

- 意味：回線が混んだとき、通信の種類ごとに扱いを変えて、大事な通信の帯域・遅延・ジッター・損失を守るしくみ
- ポイント：回線を速くするものではない。混んでいないときはほぼ何もしない。「どれを先に送り、どれを待たせ、どれを落とすか」を決める
- 語の意味：Quality＝品質／of Service＝サービスの

#### 帯域（たいいき / bandwidth）

- 意味：回線が一定の時間に運べるデータの量。bps（ビット毎秒）で表す
- ポイント：QoS は帯域を増やさず、限られた帯域を通信の種類ごとに配り分ける（例：音声に優先して、Web に最低保証）

#### 遅延（ちえん / delay, latency）

- 意味：パケットが送り手から受け手に届くまでの時間
- ポイント：光の速さで決まる伝搬遅延と、ルーターやスイッチのキューで待つキューイング遅延が大きな原因。QoS で減らせるのはキューで待つ時間
- 例：音声は片道 150 ms 未満が目安（ITU G.114）

#### ジッター（じったー / jitter）

- 意味：パケットごとの遅延のばらつき
- ポイント：音声や映像は一定の間隔で届かないと途切れる。受け手のジッターバッファーで吸収できるが、そのぶん遅延が増える。遅延そのものとは別の指標

#### パケット損失（ぱけっとそんしつ / packet loss）

- 意味：途中でパケットが落ちて届かないこと。主にキューがあふれて捨てられることで起きる
- ポイント：TCP は送り直すが、音声（UDP）は送り直さないので、そのまま音が欠ける。Cisco の資料では G.729 の音声は損失 1% よりずっと小さくする必要がある

#### 輻輳（ふくそう / congestion）

- 意味：出口のインタフェースに、送れる速さより多くのパケットが集まり、キューに待ちが出ている状態
- ポイント：キューイング・WRED などは、この輻輳のときに効く。例えば 1 Gbps の LAN から 100 Mbps の WAN へ出る所で起きやすい

#### PHB（ぴーえいちびー / Per-Hop Behavior）

- 意味：DiffServ で、ネットワークの1台1台（1ホップごと）が、印（DSCP）に応じてパケットに与える転送の扱い
- ポイント：経路全体で予約するのではなく、各機器が印を見てそれぞれ同じ方針で扱う。代表的な PHB は EF（音声向け）・AF（4クラス×3段の落としやすさ）・Default（ふつう）
- 語の意味：Per-Hop＝1ホップごとの／Behavior＝ふるまい

## 19-2 分類とマーキング

### まとめ表

| 印 | 場所 | ビット数 | 例 |
| :-: | :-: | :-: | :-: |
| CoS（PCP） | 802.1Q タグ（L2） | 3 ビット（0〜7） | 音声 CoS 5 |
| IP Precedence | IPv4 ヘッダーの ToS の上位3ビット（L3） | 3 ビット（0〜7） | 音声 5 |
| DSCP | ToS（IPv6 は Traffic Class）の上位6ビット（L3） | 6 ビット（0〜63） | 音声 EF＝46 |

### 分類と印

#### 分類（ぶんるい / classification）

- 意味：パケットを見て、どの種類の通信か（音声・映像・業務データなど）を見分けること
- ポイント：ACL（アドレスやポート番号）、すでに付いている DSCP・CoS などで見分ける。分類しないと、扱いを変えられない。できるだけ送り手に近い所でする
- 例：`class-map VOICE` → `match dscp ef`

#### マーキング（まーきんぐ / marking）

- 意味：分類したパケットのヘッダーに印（CoS・DSCP など）を書き込むこと
- ポイント：印を付けておけば、後ろの機器は中身を調べ直さず、印だけ見て扱いを決められる。分類（見分ける）とマーキング（書く）は別の動き
- 例：`set dscp ef`

#### CoS（こす / Class of Service, PCP）

- 意味：802.1Q タグの中にある 3 ビットの優先度の欄（0〜7）。IEEE では PCP（Priority Code Point）と呼ぶ
- ポイント：レイヤー2の印なので、タグのあるトランクの上でしか運べない。ルーターを越えると消える。Cisco の IP 電話は音声を CoS 5、データを CoS 0 にする
- 語の意味：Class of Service＝サービスの等級

#### IP Precedence（あいぴーぷれしでんす）

- 意味：IPv4 ヘッダーの ToS バイトの上位 3 ビットを使う、古い優先度の印（0〜7）
- ポイント：DSCP の上位 3 ビットと同じ場所なので、DSCP の CS（Class Selector）の値と互換になる。音声は 5（ビット 101）
- 例：Precedence 5 ＝ ToS の上位3ビットが 101

#### DSCP（でぃーえすしーぴー / Differentiated Services Code Point）

- 意味：IPv4 の ToS バイト（IPv6 の Traffic Class）の上位 6 ビットを使う印。0〜63 の値で PHB を選ぶ
- ポイント：レイヤー3の印なので、ルーターを越えても残る。6 ビットなので IP Precedence（3 ビット）より細かく分けられる。値 0 は Default（ふつうの扱い）
- 語の意味：Differentiated Services＝サービスを分ける（DiffServ）／Code Point＝符号の値

#### EF（いーえふ / Expedited Forwarding, DSCP 46）

- 意味：低遅延・低損失・低ジッターを目指す PHB。推奨値は DSCP 46（ビット 101110）
- ポイント：音声（電話）に使う。キューイングでは優先キュー（LLQ）に入れるのがふつう
- 語の意味：Expedited＝急いだ／Forwarding＝転送

#### AF（えーえふ / Assured Forwarding, AFxy）

- 意味：4つのクラス（x＝1〜4）と、クラスの中の3段階の落としやすさ（y＝1〜3）で表す PHB の組
- ポイント：混んだら、同じクラスの中では y が大きいもの（落としやすさが高い）から捨てる。DSCP の値は 8x＋2y で計算できる（AF11＝10、AF21＝18、AF31＝26、AF41＝34、AF43＝38）
- 例：AF41（映像会議など）＝DSCP 34
- 語の意味：Assured＝保証された／Forwarding＝転送

#### CS（しーえす / Class Selector, CSx）

- 意味：DSCP の下位 3 ビットが 000 の8つの値（CS0〜CS7）。上位3ビットが IP Precedence と同じ並びになり、互換を保つ
- ポイント：CSx の DSCP 値は 8x（CS5＝40、CS3＝24）。CS0＝0 は Default
- 例：CS3＝011000＝24

#### 信頼境界（しんらいきょうかい / trust boundary）

- 意味：ネットワークが、端末や機器の付けた印（CoS・DSCP）を信じ始める境目
- ポイント：PC が自分で高い印を付けると優先キューを横取りできてしまうので、信じない所では印を書き直す。Cisco の IP 電話を CDP で見つけたときだけ信じる「trusted boundary」の機能もある。境界はできるだけ端末に近いアクセススイッチに置く

## 19-3 キューイングと輻輳回避

### まとめ表

| しくみ | 何をするか | 向いているもの |
| :-: | :-: | :-: |
| 優先キュー（LLQ） | いつも先に送る。混んだら決めた量で制限 | 音声（EF） |
| CBWFQ（bandwidth） | クラスごとに最低帯域を保証 | 業務データ・映像 |
| テールドロップ | キューがいっぱいになったら来たものから全部捨てる | 何もしないときの動き |
| WRED | いっぱいになる前に、印の低いものから少しずつ捨てる | TCP の通信 |

### キューイング

#### キューイング（きゅーいんぐ / queuing）

- 意味：出口が混んでいるとき、パケットを種類ごとのキュー（待ち行列）に分けてためておき、決めた順番と割合で送り出すこと
- ポイント：キューは出口（出ていく方向）のしくみ。どのキューから何をどれだけ送るかを決めるのがスケジューリング

#### LLQ（えるえるきゅー / Low Latency Queuing）

- 意味：決めたクラス（ふつうは音声）を厳密な優先キューに入れていつも先に送り、ほかのクラスには最低帯域を保証するキューイング
- ポイント：優先キューは混んだときに priority で決めた量で制限（ポリシング）されるので、音声がほかの通信を飢えさせない。Cisco は音声に LLQ を勧めている
- 例：`class VOICE` → `priority 32`

#### CBWFQ（しーびーだぶりゅーえふきゅー / Class-Based Weighted Fair Queuing）

- 意味：クラスごとにキューを分け、bandwidth で最低帯域を保証するキューイング
- ポイント：保証は「最低」で、空いていれば使った分以上も送れる。厳密な優先はない（優先が要るのは LLQ）
- 例：`class WEB` → `bandwidth 64`

### 輻輳回避

#### テールドロップ（てーるどろっぷ / tail drop）

- 意味：キューがいっぱいになったとき、後から来たパケットを種類に関係なく全部捨てる動き
- ポイント：何も設定しないときの動き。たくさんの TCP の通信が同時に捨てられ、同時に速度を落とし、同時に戻す「TCP グローバル同期」を起こしやすい

#### TCP グローバル同期（てぃーしーぴーぐろーばるどうき / TCP global synchronization）

- 意味：テールドロップで多くの TCP の通信が一斉にパケットを失い、一斉に送る速さを下げ、また一斉に上げることを繰り返す状態
- ポイント：回線が空いたり詰まったりを繰り返し、全体の使用率が下がる。WRED で防ぐ

#### WRED（だぶりゅーれっど / Weighted Random Early Detection）

- 意味：キューがいっぱいになる前から、少しずつランダムにパケットを捨てて、TCP に速度を落とさせる輻輳回避のしくみ。印（DSCP・CoS など）で捨てやすさを変える
- ポイント：RED を Cisco が印の重みつきにしたもの。一度にたくさん捨てないので TCP グローバル同期を防ぐ。UDP の音声には効かない（速度を落とさない）ので、音声は優先キューで守る
- 語の意味：Weighted＝重みつきの／Random＝ランダムな／Early＝早めの／Detection＝検出

## 19-4 ポリシングとシェーピング

### まとめ表

| 項目 | ポリシング | シェーピング |
| :-: | :-: | :-: |
| 超えた分 | 捨てる（または印を下げる） | キューにためて後で送る |
| 遅延 | 増えない | 増える（待つため） |
| 向き | 入りでも出でも使える | 出口だけ |
| 出力の形 | ギザギザ（バーストはそのまま） | なめらか |
| よく使う所 | ISP がお客さんの入りを制限 | お客さんが契約速度に合わせて出す |

### 速度を決まった値に抑える

#### ポリシング（ぽりしんぐ / policing）

- 意味：クラスの通信量を決まった速さ（CIR）までに抑え、超えた分はすぐに捨てるか、印を下げるしくみ
- ポイント：ためないので遅延は増えないが、捨てられた TCP は送り直す。入り（受信）方向にも使える。超えたときの動作（drop・set-dscp-transmit など）を選べる
- 例：`police cir 10000000` → `exceed-action drop`

#### シェーピング（しぇーぴんぐ / shaping）

- 意味：出口の通信量を決まった速さまでに抑えるため、超えた分をキューにためて、少しずつ送り出すしくみ
- ポイント：捨てにくいが、待つぶん遅延とジッターが増える。出口だけで使う。契約した速さ（例 回線は 1 Gbps でも契約は 100 Mbps）に合わせて送り、相手側で捨てられないようにする
- 例：`shape average 100000000`

#### CIR（しーあいあーる / Committed Information Rate）

- 意味：ポリシングやシェーピングで守る、平均の速さ（約束した情報量の速さ）
- ポイント：シェーピングでは、Tc（区切りの時間）ごとに Bc（その間に送ってよい量）を送る。Tc＝Bc÷CIR
- 例：CIR 8 Mbps・Bc 80,000 ビットなら Tc＝10 ms

#### トークンバケツ（とーくんばけつ / token bucket）

- 意味：一定の速さでトークン（送ってよい量の券）がたまるバケツで、パケットを送るにはその大きさ分のトークンが要る、という速さの測り方
- ポイント：トークンが足りないとき、シェーピングは「たまるまで待たせる」、ポリシングは「捨てる・印を下げる」。バケツの大きさが一度に送れる最大のバースト

#### MQC（えむきゅーしー / Modular QoS CLI）

- 意味：QoS を class-map（分類）・policy-map（扱い）・service-policy（インタフェースに付ける）の3段で設定する Cisco の書き方
- ポイント：class-map で「何を」、policy-map で「どうする（set・priority・bandwidth・police・shape）」、service-policy input／output で「どこに、どちら向きに」
- 例：`interface g0/1` → `service-policy output WAN-OUT`
- 語の意味：Modular＝部品を組み合わせる／QoS／CLI＝コマンドライン

### 19-1 QoS の考え方

#### 問 ccna-19-o01

- 問：QoS の説明として正しいものはどれか。
- ア：回線の速さを上げて、すべての通信を速くする
- イ：暗号化して通信を守る
- ウ：回線が混んだとき、通信の種類ごとに扱いを変えて、大事な通信の遅延や損失を守る
- エ：経路を自動で選び直す
- 正解：ウ
- 解説：QoS は帯域を増やさない。混んだときに、どれを先に送り、どれを待たせ、どれを捨てるかを決める。
- アの意味：QoS は帯域そのものは増やさない。
- イの意味：IPsec などの役目。
- ウの意味：正しい。
- エの意味：ルーティングプロトコルの役目。
- 出典：オリジナル問題（根拠：Cisco Quality of Service Configuration Guide IOS XE 17.9（Catalyst 9300）「Configuring QoS」QoS Components（Classification … Marking … Shaping and policing … Queuing is used to prevent traffic congestion））

#### 問 ccna-19-o02

- 問：パケットごとの遅延のばらつきを表す言葉はどれか。
- ア：ジッター
- イ：帯域
- ウ：遅延
- エ：パケット損失
- 正解：ア
- 解説：ジッターは遅延のばらつき。音声や映像は一定の間隔で届かないと途切れる。
- アの意味：正しい。
- イの意味：一定時間に運べる量。
- ウの意味：届くまでの時間そのもの。ばらつきではない。
- エの意味：パケットが届かないこと。
- 出典：オリジナル問題（根拠：Cisco「Quality of Service for Voice over IP」QoS for VoIP Overview（Jitter buffers (used to compensate for varying delay) … Jitter must therefore be minimized））

#### 問 ccna-19-o03

- 問：Cisco の VoIP の QoS の資料が、高品質な音声の目安として挙げる片道の遅延はどれか。
- ア：15 ms 未満
- イ：1500 ms 未満
- ウ：150 ms 未満
- エ：遅延は音声に影響しない
- 正解：ウ
- 解説：ITU G.114 は、音声のような高品質のリアルタイム通信の片道遅延を 150 ms 未満と勧めている。
- アの意味：目安としては厳しすぎる。
- イの意味：会話にならないほど遅い。
- ウの意味：正しい。
- エの意味：遅延が大きいと会話がかみ合わない。
- 出典：オリジナル問題（根拠：Cisco「Quality of Service for Voice over IP」（The ITU G.114 specification recommends less than 150 millisecond (ms) one-way end-to-end delay for high-quality real-time traffic such as voice））

#### 問 ccna-19-o04

- 問：QoS のキューイングで減らせる遅延はどれか。
- ア：光の速さで決まる伝搬遅延
- イ：送り手のアプリケーションの処理時間
- ウ：どの遅延も減らせない
- エ：ルーターやスイッチのキューで待つ時間
- 正解：エ
- 解説：伝搬遅延は距離で決まり変えられない。QoS は大事なパケットを先に送ることで、キューで待つ時間を減らす。
- アの意味：物理的に決まるので QoS では減らせない。
- イの意味：ネットワークの外の話。
- ウの意味：キューで待つ時間は減らせる。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：RFC 3246 1.（The dominant causes of delay in packet networks are fixed propagation delays … and queuing delays in switches and routers））

#### 問 ccna-19-o05

- 問：PHB（Per-Hop Behavior）の説明として正しいものはどれか。
- ア：送り手から受け手まで、経路全体の帯域を前もって予約すること
- イ：1ホップごとに TTL を1減らすこと
- ウ：各機器が、パケットの印（DSCP）に応じて1台ごとに与える転送の扱い
- エ：OSPF のコストの計算方法
- 正解：ウ
- 解説：DiffServ では、各機器が DSCP を見て、それぞれ決めた扱い（EF・AF など）をする。経路全体の予約はしない。
- アの意味：IntServ（RSVP）の考え方。
- イの意味：IP の TTL の動き。QoS とは別。
- ウの意味：正しい。
