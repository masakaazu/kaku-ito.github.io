## 06-1 フレームと MAC アドレス

### まとめ表

| 欄 | 長さ（バイト） | 役目 | 根拠 |
| :-- | :-: | :-- | :-- |
| プリアンブル | 7 | フレームが来ることを知らせる 1・0 のくり返し | tr1904 |
| SFD（SOF） | 1 | フレームの始まり。最後が 1 1 | tr1904 |
| 宛先アドレス | 6 | ユニキャスト・マルチキャスト・ブロードキャスト | tr1904 |
| 送信元アドレス | 6 | いつもユニキャスト | tr1904 |
| タイプ | 2 | 上の層のプロトコル | tr1904 |
| データ | 46〜1500 | 中身。足りなければ埋める | tr1904 |
| FCS | 4 | CRC で傷を調べる | tr1904 |

### フレームの形

#### イーサネットフレーム（いーさねっとふれーむ / Ethernet frame）

- 意味：イーサネットで送るデータの 1 まとまり。プリアンブル・SFD・宛先・送信元・タイプ・データ・FCS の順に並ぶ
- ポイント：スイッチが見るのは主に宛先と送信元の MAC アドレス。データが少ないときは最小の 64 バイトになるよう詰め物を入れる（tr1904）
- 例：宛先 ffff.ffff.ffff・送信元 0011.2233.4401・タイプ IPv4 のフレーム（Claude の例）

#### プリアンブル（ぷりあんぶる / preamble）

- 意味：フレームの先頭にある、1 と 0 をくり返す 7 バイト。受け取る側に「フレームが来る」と知らせる
- ポイント：MAC アドレスより前にある。宛先アドレスの直前の 1 バイトは SFD（tr1904）
- 例：10101010 …（Claude の例）

#### SFD（えすえふでぃー / Start Frame Delimiter）

- 意味：プリアンブルのあと、宛先アドレスの直前にある 1 バイト。最後が 1 が 2 つ続く形で、フレームの始まりを示す
- ポイント：Cisco のハンドブックでは SOF（Start-of-frame delimiter）と書く。受け取りのタイミングを合わせる役目（tr1904）
- 例：10101011（Claude の例）
- 語の意味：start＝始まり、frame＝フレーム、delimiter＝区切り

#### 宛先 MAC アドレス（あてさきまっくあどれす / destination MAC address）

- 意味：フレームを届けたい相手の 6 バイトのアドレス。SFD のすぐ後ろにある
- ポイント：ユニキャスト・マルチキャスト（グループ）・ブロードキャスト（全員）のどれにもなる。スイッチはこれで転送先を決める（tr1904、9300 Sys Mgmt CG）
- 例：0011.2233.4403

#### 送信元 MAC アドレス（そうしんもとまっくあどれす / source MAC address）

- 意味：フレームを送った機器の 6 バイトのアドレス。宛先のすぐ後ろにある
- ポイント：いつもユニキャスト（tr1904）。スイッチはこれでアドレスを学習する（9300 Sys Mgmt CG）。宛先で転送、送信元で学習、と分けて覚える
- 例：0011.2233.4401

#### タイプ（たいぷ / Type, EtherType）

- 意味：送信元アドレスの後ろの 2 バイト。データを受け取る上の層のプロトコルを示す
- ポイント：IEEE 802.3 の形ではここが長さ（Length）になる。TCP/IP のソフトはタイプを使う（tr1904）
- 例：IPv4・IPv6・ARP などを見分ける

#### FCS（えふしーえす / Frame Check Sequence）

- 意味：フレームの最後の 4 バイト。送る側が作った CRC の値が入る
- ポイント：受け取る側がもう一度計算し、途中でフレームが傷ついていないか調べる（tr1904）。ストアアンドフォワードのスイッチは全部受け取ってから CRC を調べる（Nexus 9000 L2 CG）
- 例：CRC の値が合わない → インタフェースの CRC エラーとして数える（#02）
- 語の意味：frame＝フレーム、check＝調べる、sequence＝並び

### MAC アドレスの種類

#### MAC アドレス（まっくあどれす / MAC address）

- 意味：イーサネットのインタフェースを見分ける 48 ビット（6 バイト）のアドレス
- ポイント：前の 3 バイトは IEEE が会社ごとに割り当て、後ろの 3 バイトはその会社が決める（tr1904）。IOS では 4 けたずつ点で区切る H.H.H の形で書く（9300 CR）
- 例：fc58.9a02.7382（9300 CR の例）
- 語の意味：MAC＝Media Access Control（媒体へのアクセスの制御）

#### OUI（おーゆーあい / Organizationally Unique Identifier）

- 意味：IEEE が会社（組織）ごとに割り当てる、MAC アドレスの前の 24 ビット
- ポイント：OUI を持つ会社だけが、その OUI で始まる MAC アドレスを割り当てられる。今は 28・36 ビットの短い割り当て（MA-M・MA-S）もある（RFC 9542 2.1・2.1.2）
- 例：00-00-5E は IANA の OUI（RFC 9542）
- 語の意味：organizationally unique＝組織ごとにただ 1 つの、identifier＝識別子

#### I/G ビット（あいじーびっと / Individual/Group bit, M bit）

- 意味：MAC アドレスの最初のオクテットのいちばん下（最下位）のビット。0 ならユニキャスト、1 ならグループあて（マルチキャストかブロードキャスト）
- ポイント：最初のオクテットが奇数ならグループあて、と読める（Claude の読み方）。その 1 つ上のビットは U/L ビット（#05 の EUI-64 で反転するビット）（RFC 9542 2.1.1）
- 例：01-00-5E-… の 01 は 00000001 → グループあて

#### ブロードキャストアドレス（ぶろーどきゃすとあどれす / broadcast MAC address）

- 意味：同じ LAN（VLAN）の全員あての MAC アドレス。48 ビットすべて 1
- ポイント：スイッチはブロードキャストを受け取ったポート以外の全ポート（同じ VLAN）に流す（Doc 10543）。スイッチの表には CPU 向けの STATIC として ffff.ffff.ffff が載る（9300 CR の例）
- 例：ffff.ffff.ffff（FF-FF-FF-FF-FF-FF）

#### マルチキャスト MAC アドレス（まるちきゃすとまっくあどれす / multicast MAC address）

- 意味：グループあての MAC アドレス。I/G ビットが 1
- ポイント：IPv4 マルチキャストは 01-00-5E に IP アドレスの下位 23 ビットを入れる（RFC 1112）。IPv6 マルチキャストは 33-33 に IPv6 アドレスの下位 32 ビット（RFC 2464）。スイッチの基本動作ではブロードキャストと同じようにフラッディングする（Doc 10543）
- 例：0100.5e00.0005（IPv4 の 224.0.0.5 に対応。Claude が計算）、0180.c200.0000（9300 CR の表の STATIC CPU の行）

## 06-2 MAC アドレステーブル

### まとめ表

| 項目 | 初期値・決まり | 根拠 |
| :-- | :-- | :-- |
| 動的アドレス | 自動で学習、使われないと消える | 9300 Sys Mgmt CG |
| 静的アドレス | 設定なし。入れると消えない・再起動でも残る | 9300 Sys Mgmt CG |
| エージングタイム | 300 秒（10〜1000000 秒、0 で消さない） | 9300 Sys Mgmt CG |
| テーブル | VLAN ごと | 9300 Sys Mgmt CG |
| STP の再構成中 | エージングを forward delay（初期 15 秒）に短縮 | IOS XE 17 STP CG |

### 表の中身

#### MAC アドレステーブル（まっくあどれすてーぶる / MAC address table）

- 意味：スイッチがポートの間でフレームを転送するために使う表。宛先 MAC アドレス・VLAN・ポート・種類（静的か動的か）が並ぶ
- ポイント：どのアドレスも 1 つ以上のポートと結びつく。show mac address-table で見る（9300 Sys Mgmt CG、9300 CR）
- 例：10 0011.2233.4401 DYNAMIC Gi1/0/1（Claude の例）

#### CAM テーブル（きゃむてーぶる / Content Addressable Memory table）

- 意味：スイッチの転送用の表（L2 の転送テーブル）の別の呼び名。高速に引くための CAM というメモリに入っていることから
- ポイント：MAC アドレステーブル、L2 テーブル、CAM テーブルはほぼ同じものを指す（Doc 23563）。いっぱいになると新しいアドレスを学習できない
- 例：show mac address-table notification threshold で CAM の使用率の通知を確かめる（9300 CR）
- 語の意味：content addressable＝中身（値）で引ける、memory＝記憶装置

#### VLAN ごとのテーブル（ぶいらんごとのてーぶる / per-VLAN address table）

- 意味：スイッチが VLAN ごとに別々の論理的な MAC アドレステーブルを持つこと
- ポイント：ある VLAN で知っているアドレスも、別の VLAN では学習するまで知らない（未知）。フラッディングも受け取った VLAN の中だけ（9300 Sys Mgmt CG、Doc 23563）
- 例：VLAN 20 で学習した MAC は、VLAN 10 のフレームの宛先としては未知

### 学習とエージング

#### MAC アドレスの学習（まっくあどれすのがくしゅう / MAC address learning）

- 意味：受け取ったフレームの送信元 MAC アドレスと、受け取ったポートを表に書き込むこと
- ポイント：見るのは送信元。宛先ではない。Host A のフレームがポート 1 から来たら、Host A はポート 1 の先にいると考える（9300 Sys Mgmt CG、Doc 10543）
- 例：Gi1/0/1 で送信元 0011.2233.4401 を受け取る → 0011.2233.4401 は Gi1/0/1

#### 動的アドレス（どうてきあどれす / dynamic address）

- 意味：スイッチが学習した送信元 MAC アドレス。使われないと時間で消える
- ポイント：show mac address-table では Type が DYNAMIC（9300 Sys Mgmt CG、9300 CR）。clear mac address-table dynamic で消せる
- 例：1 fc58.9a02.7382 DYNAMIC Te1/0/1（9300 CR）

#### 静的アドレス（せいてきあどれす / static address）

- 意味：管理者が手で入れたユニキャストの MAC アドレス。時間で消えず、再起動しても残る
- ポイント：エージングの対象外。mac address-table static で入れる（9300 Sys Mgmt CG）。表では Type が STATIC
- 例：mac address-table static c2f3.220a.12f4 vlan 4 interface gigabitethernet 1/0/1（9300 Sys Mgmt CG）

#### エージング（えーじんぐ / aging）

- 意味：使われなくなった動的アドレスを、決まった時間がたったら表から消すこと
- ポイント：機器が外されたり別のポートに移ったりしても、表が古いままにならないようにする（9300 Sys Mgmt CG）。消えたアドレスあてのフレームは次に学習するまでフラッディングになる（Doc 23563）
- 例：PC を別のポートにつなぎかえた → 古い行は消え、新しいポートで学習しなおす

#### エージングタイム（えーじんぐたいむ / aging time）

- 意味：動的アドレスが、使われたり更新されたりしてから表に残る時間
- ポイント：初期値 300 秒。10〜1000000 秒に変えられ、0 はエージングしない。設定は全体だが、VLAN ごとにも指定できる（9300 Sys Mgmt CG）
- 例：mac address-table aging-time 500 vlan 2（9300 Sys Mgmt CG）

#### 加速エージング（かそくえーじんぐ / accelerated aging）

- 意味：スパニングツリーの再構成のときに、動的アドレスのエージングタイムを一時的に短くするしくみ
- ポイント：短くした時間は forward delay の値（#09）。多くの機器の場所が変わりうるので、5 分も待たずに消して学習しなおす。VLAN ごとに行う（IOS XE 17 STP CG）
- 例：初期の forward delay 15 秒（Claude が #09 の初期値から補足）

## 06-3 転送の判断

### まとめ表

| 届いたフレームの宛先 | スイッチの動き | 根拠 |
| :-- | :-- | :-- |
| 表にあり、別のポート | そのポートだけに転送 | 9300 Sys Mgmt CG |
| 表にあり、受け取ったのと同じポート | 捨てる（フィルタリング） | 9300 Sys Mgmt CG |
| 表にない（未知ユニキャスト） | 同じ VLAN の、受け取ったポート以外の全ポートへ（フラッディング） | Doc 23563 |
| ブロードキャスト・マルチキャスト | 同じようにフラッディング | Doc 10543 |

### 3 つの動き

#### 透過ブリッジ（とうかぶりっじ / transparent bridge）

- 意味：送信元アドレスを見て場所を学び、表で転送先を決めるブリッジ。ホストからはいることが見えない（透過）
- ポイント：電源を入れたあと、届くフレームの送信元を見て表を作る。今のスイッチの基本動作はこれと同じ（Doc 10543）
- 例：ホストはスイッチ用の設定をしなくても通信できる

#### 転送（てんそう / forwarding）

- 意味：宛先 MAC アドレスが表にあるとき、そのアドレスに結びついたポートだけにフレームを送ること
- ポイント：ほかのポートには送らないので、関係のない区間の通信が減る（9300 Sys Mgmt CG、Doc 10543）
- 例：宛先 0011.2233.4403 → 表で Gi1/0/2 → Gi1/0/2 だけへ

#### フィルタリング（ふぃるたりんぐ / filtering）

- 意味：宛先が、フレームを受け取ったのと同じポートの先にいるとき、転送せずに捨てること
- ポイント：送り元と宛先が同じポートの先（例：その先にハブや別のスイッチ）にいるので、送り返す必要がない（9300 Sys Mgmt CG）
- 例：Gi1/0/2 から来た、宛先も Gi1/0/2 の先のフレーム → 捨てる

#### フラッディング（ふらっでぃんぐ / flooding）

- 意味：フレームを、同じ VLAN の、受け取ったポート以外のすべての転送中のポートへ送ること
- ポイント：宛先が表にないユニキャスト・ブロードキャスト・マルチキャストで起きる。少しのフラッディングはふつうの動き（Doc 23563、Doc 10543）
- 例：未知のユニキャストは VLAN 10 の他の全ポートへ

#### 未知ユニキャスト（みちゆにきゃすと / unknown unicast）

- 意味：宛先がユニキャストの MAC アドレスなのに、受け取った VLAN の表にその行がないフレーム
- ポイント：フラッディングされる。相手が返事をすれば、その送信元を学習して次からは転送になる（Doc 23563）。ブロードキャストとはちがう（宛先は 1 台）
- 例：電源を入れた直後の通信、エージングで消えたあとの通信

### 転送のやり方

#### ストアアンドフォワード（すとあんどふぉわーど / store-and-forward）

- 意味：フレームを最後まで受け取って CRC を調べてから転送するやり方
- ポイント：傷ついたフレームを先へ送らない。そのぶん遅れは大きい（Nexus 9000 L2 CG）。Catalyst 9300 はいつもこのやり方（9300 Sys Mgmt CG）
- 例：FCS が合わないフレームは捨てる

#### カットスルー（かっとするー / cut-through）

- 意味：宛先の情報を読んだらすぐ、フレームを受け取り終える前に転送を始めるやり方
- ポイント：ストアアンドフォワードより速い。ただし CRC を調べる前に送り始める（Nexus 9000 L2 CG）。Nexus 9000 は初期設定がカットスルー
- 例：遅れを小さくしたいデータセンターのスイッチ（Claude の補足）

## 06-4 フラッディングが続くとき

### まとめ表

| 原因 | なぜ宛先が表にないか | 対策の例 | 根拠 |
| :-- | :-- | :-- | :-- |
| 非対称ルーティング | 行きと帰りの道がちがい、片方の MAC が届かない | ARP のタイムアウトとエージングを近づける | Doc 23563 |
| STP のトポロジー変更 | エージングが短くなり、表が消える | 端末のポートに PortFast | Doc 23563 |
| テーブルのあふれ | 表がいっぱいで学習できない | ポートセキュリティで学習の数を制限 | Doc 23563 |

### 原因

#### 非対称ルーティング（ひたいしょうるーてぃんぐ / asymmetric routing）

- 意味：行きと帰りでパケットの通る道がちがうこと
- ポイント：片方のスイッチには相手の MAC からのフレームが届かないので、そのアドレスを学習できず、フラッディングが続く。Cisco はフラッディングのよくある原因の 1 つとしている（Doc 23563）
- 例：行きはルーター A、帰りはルーター B を通る（HSRP で VLAN ごとに担当を分けた構成など）

#### トポロジー変更通知（とぽろじーへんこうつうち / Topology Change Notification, TCN）

- 意味：スパニングツリーで、ポートが転送の状態になった・外れたことを知らせるしくみ
- ポイント：TCN はエージングタイムを短くして表を作り直させる。ポートが何度も上がり下がりすると TCN が続き、フラッディングがほぼ止まらなくなる。PortFast のポートは TCN を出さない（Doc 23563、#09）
- 例：端末のポートが何度も上がり下がり（フラップ）

#### MAC アドレステーブルのあふれ（まっくあどれすてーぶるのあふれ / forwarding table overflow）

- 意味：MAC アドレステーブルがいっぱいになり、新しいアドレスを学習できなくなること
- ポイント：学習できないアドレスあてのフレームは、空きができるまでフラッディングされる。今のスイッチは表が大きいので、ふつうはまれ（Doc 23563）
- 例：表の多くの行が 1 つのポートを指している → 攻撃を疑う

#### MAC フラッディング攻撃（まっくふらっでぃんぐこうげき / MAC flooding attack）

- 意味：1 台のホストが、送信元 MAC アドレスを次々に変えたフレームを送り、スイッチの表をいっぱいにする攻撃
- ポイント：表があふれると、ほかの通信がフラッディングされ、攻撃者のポートにも流れてくる。学習する MAC の数を制限するポートセキュリティで防ぐ（Doc 23563、#23）
- 例：switchport port-security で 1 ポートあたりの MAC の数を制限（Doc 23563 の注）

## 06-5 IOS での確認と設定

### まとめ表

| コマンド | すること | 根拠 |
| :-- | :-- | :-- |
| show mac address-table | 表を全部見る | 9300 CR |
| show mac address-table address M | 1 つの MAC がどのポートか | 9300 CR |
| show mac address-table count | 行の数 | 9300 CR |
| show mac address-table aging-time | エージングタイム | 9300 CR |
| mac address-table aging-time 秒 | エージングタイムを変える | 9300 Sys Mgmt CG |
| mac address-table static M vlan V interface I | 静的な行を入れる | 9300 Sys Mgmt CG |
| clear mac address-table dynamic | 動的な行を消す | 9300 Sys Mgmt CG |

### 見るコマンド

#### show mac address-table（しょーまっくあどれすてーぶる / show mac address-table）

- 意味：MAC アドレステーブルを表示する特権 EXEC モードのコマンド。Vlan・Mac Address・Type・Ports の列が並ぶ
- ポイント：dynamic・static で種類をしぼり、vlan・interface で範囲をしぼれる。All の VLAN にある STATIC CPU の行は、スイッチ自身が受け取るアドレス（9300 CR）
- 例：show mac address-table dynamic vlan 10

#### show mac address-table address（しょーまっくあどれすてーぶるあどれす / show mac address-table address）

- 意味：指定した 1 つの MAC アドレスの行だけを表示するコマンド
- ポイント：MAC は H.H.H の形で書く。どのポートの先にその機器がいるかを探すのに使う（9300 CR）
- 例：show mac address-table address fc58.9a02.7382 → 1 fc58.9a02.7382 DYNAMIC Te1/0/1（9300 CR）

#### show mac address-table count（しょーまっくあどれすてーぶるかうんと / show mac address-table count）

- 意味：今 MAC アドレステーブルに入っている行の数を表示するコマンド
- ポイント：表があふれていないかを見るのに使える（Claude の補足。表のあふれは Doc 23563）（9300 CR）
- 例：show mac address-table count vlan 10

#### show mac address-table aging-time（しょーまっくあどれすてーぶるえーじんぐたいむ / show mac address-table aging-time）

- 意味：設定されているエージングタイムを表示するコマンド
- ポイント：全体の値（Global Aging Time）と VLAN ごとの値が出る（9300 CR）
- 例：Global Aging Time: 300（9300 CR）

### 変えるコマンド

#### mac address-table aging-time（まっくあどれすてーぶるえーじんぐたいむ / mac address-table aging-time）

- 意味：動的アドレスのエージングタイムを変えるグローバル設定のコマンド
- ポイント：10〜1000000 秒、初期値 300。0 でエージングしない。vlan で VLAN ごとに指定（9300 Sys Mgmt CG）
- 例：mac address-table aging-time 500 vlan 2

#### mac address-table static（まっくあどれすてーぶるすたてぃっく / mac address-table static）

- 意味：MAC アドレス・VLAN・ポートを指定して、静的な行を入れるコマンド
- ポイント：その VLAN でその宛先のフレームは指定したポートへ送られる。ユニキャストは 1 回に 1 ポート。drop を付けると、その MAC が送信元・宛先のフレームを捨てる（9300 Sys Mgmt CG）
- 例：mac address-table static c2f3.220a.12f4 vlan 4 drop

#### clear mac address-table dynamic（くりあまっくあどれすてーぶるだいなみっく / clear mac address-table dynamic）

- 意味：動的に学習した行を消すコマンド。address・interface・vlan で範囲をしぼれる
- ポイント：静的な行は消さない。消したあとは、フレームが来るたびに学習しなおす（それまでは未知ユニキャスト）（9300 Sys Mgmt CG）
- 例：clear mac address-table dynamic interface gigabitethernet1/0/1

#### MAC アドレス学習の停止（まっくあどれすがくしゅうのていし / no mac address-table learning vlan）

- 意味：指定した VLAN で MAC アドレスの学習をやめるコマンド
- ポイント：表の空きを守るために使うが、フラッディングの原因になる。ポートが 3 つ以上の VLAN で止めると、入ってくるフレームがすべてフラッディングされる。勧められるのはポートが 2 つの VLAN だけ（9300 Sys Mgmt CG）
- 例：no mac address-table learning vlan 223

### 06-1 フレームと MAC アドレス

#### 問 ccna-06-o01

- 問：イーサネットフレームの欄を先頭から並べたものとして正しいものはどれか。
- ア：プリアンブル → SFD → 宛先アドレス → 送信元アドレス → タイプ → データ → FCS
- イ：プリアンブル → SFD → 送信元アドレス → 宛先アドレス → タイプ → データ → FCS
- ウ：FCS → プリアンブル → 宛先アドレス → 送信元アドレス → データ → タイプ
- エ：SFD → プリアンブル → 宛先アドレス → 送信元アドレス → データ → FCS → タイプ
- 正解：ア
- 解説：宛先が送信元より前にある。スイッチは先に宛先を読める。FCS は最後。
- アの意味：正しい。
- イの意味：宛先と送信元が逆。IP ヘッダーは送信元が先だが、イーサネットは宛先が先。
- ウの意味：FCS は最後の 4 バイト。
- エの意味：SFD はプリアンブルのあと、タイプは送信元のすぐ後ろ。
- 出典：オリジナル問題（根拠：tr1904 Figure 4-2（Preamble SOF Destination address Source address Type Data FCS）／The byte before the destination address … is a start-of-frame (SOF) delimiter）

#### 問 ccna-06-o02

- 問：イーサネットフレームの FCS の役目として正しいものはどれか。
- ア：送る側が作った CRC の値で、受け取る側がもう一度計算してフレームの傷を調べる
- イ：上の層のプロトコルを示す
- ウ：フレームが来ることを受け取る側に知らせる
- エ：フレームの送り先の機器を示す
- 正解：ア
- 解説：FCS はフレームの最後の 4 バイトの CRC。合わなければフレームが途中で傷ついた。
- アの意味：正しい。
- イの意味：タイプの欄の役目。
- ウの意味：プリアンブルの役目。
- エの意味：宛先 MAC アドレスの役目。
- 出典：オリジナル問題（根拠：tr1904（a 4-byte frame check sequence (FCS) field containing a cyclic redundancy check (CRC) value. The CRC is created by the sending device and is recalculated by the receiving device）／（a type field. This field specifies the upper-layer protocol）／（The preamble tells receiving stations that a frame is coming））

#### 問 ccna-06-o03

- 問：イーサネットのアドレスについて正しいものはどれか。
- ア：送信元アドレスはいつもユニキャストで、宛先アドレスはユニキャスト・マルチキャスト・ブロードキャストのどれにもなる
- イ：送信元アドレスがブロードキャストのフレームで、スイッチは全員の場所を学習する
- ウ：宛先アドレスはいつもユニキャストで、ブロードキャストは送信元に入れる
- エ：送信元も宛先も、いつもマルチキャスト
- 正解：ア
- 解説：送信元は 1 台の機器なのでユニキャスト。だからスイッチは送信元で場所を学習できる。
- アの意味：正しい。
- イの意味：送信元がブロードキャストになることはない。
- ウの意味：ブロードキャストは宛先に入れる。
- エの意味：マルチキャストは宛先のグループあてにだけ使う。
- 出典：オリジナル問題（根拠：tr1904（The source address is always a unicast (single node) address, whereas the destination address may be unicast, multicast (group), or broadcast (all nodes))）

#### 問 ccna-06-o04

- 問：イーサネットのブロードキャストアドレスはどれか。
- ア：ffff.ffff.ffff
- イ：0000.0000.0000
- ウ：0100.5e00.0001
- エ：0180.c200.0000
- 正解：ア
- 解説：48 ビットすべて 1 がブロードキャスト。同じ VLAN の全員に届く。
- アの意味：正しい。
- イの意味：全部 0 はブロードキャストではない。
- ウの意味：01-00-5E で始まる IPv4 マルチキャスト（224.0.0.1 に対応）の MAC。
- エの意味：最初のオクテットが奇数（01）のマルチキャスト MAC。スイッチ自身（CPU）が受け取るアドレスとして表に載る。
- 出典：オリジナル問題（根拠：9300 CR 17.9 show mac address-table（All ffff.ffff.ffff STATIC CPU／All 0180.c200.0000 STATIC CPU）／RFC 1112 6.4（01-00-5E-00-00-00）／RFC 9542 2.1.1）

#### 問 ccna-06-o05

- 問：次の MAC アドレスのうち、グループあて（マルチキャストかブロードキャスト）のものはどれか。
- ア：0100.5e00.0005
- イ：0200.5e00.0005
- ウ：0011.2233.4401
- エ：fc58.9a02.7382
- 正解：ア
- 解説：最初のオクテットの最下位ビット（I/G ビット）が 1 ならグループあて。01＝00000001 で 1。02・00・FC は偶数なので 0。
- アの意味：正しい。IPv4 の 224.0.0.5 に対応するマルチキャスト MAC。
- イの意味：02 は U/L ビットが 1 のユニキャスト（その場で決めた値）。I/G ビットではない。
- ウの意味：00 で始まるユニキャスト。
- エの意味：FC（11111100）は最下位が 0 のユニキャスト。
- 出典：オリジナル問題（根拠：RFC 9542 2.1.1（M bit … If it is zero, the MAC address is unicast. If it is a one, the address is groupcast (multicast or broadcast)／X bit … "universal/local" bit）／RFC 1112 6.4（placing the low-order 23-bits of the IP address into the low-order 23 bits of the Ethernet multicast address 01-00-5E-00-00-00））

#### 問 ccna-06-o06

- 問：MAC アドレスの前の 24 ビットについて正しいものはどれか。
- ア：IEEE が会社（組織）に割り当てる OUI で、後ろの 24 ビットはその会社が決める
- イ：VLAN の番号が入る
- ウ：スイッチのポート番号が入る
- エ：IP アドレスの前半が入る
- 正解：ア
- 解説：MAC アドレスは 6 バイト。前の 3 バイトは IEEE が会社ごとに、後ろの 3 バイトは会社が決める。
- アの意味：正しい。
- イの意味：VLAN 番号は 802.1Q タグ（#07）に入り、MAC アドレスの一部ではない。
- ウの意味：ポート番号は MAC アドレスに入らない。
- エの意味：MAC アドレスは IP アドレスとは別に決まる（対応は ARP で調べる）。
- 出典：オリジナル問題（根拠：tr1904（The first 3 bytes of the addresses are specified by the IEEE on a vendor-dependent basis, and the last 3 bytes are specified by the Ethernet or IEEE 802.3 vendor）／RFC 9542 2.1（MA-L 24））

### 06-2 MAC アドレステーブル

#### 問 ccna-06-o07

- 問：スイッチが MAC アドレスを学習するときに使う情報はどれか。
- ア：受け取ったフレームの送信元 MAC アドレスと、受け取ったポート
- イ：受け取ったフレームの宛先 MAC アドレスと、受け取ったポート
- ウ：送信元 IP アドレスと、出ていくポート
- エ：宛先 MAC アドレスと、転送したポート
- 正解：ア
- 解説：送信元を見れば「その機器はこのポートの先にいる」とわかる。宛先は転送先を決めるときに使う。
- アの意味：正しい。
- イの意味：宛先は、その機器がどこにいるかを教えない。
- ウの意味：L2 スイッチの表は MAC アドレスで作る。
- エの意味：宛先と転送の組み合わせでは場所を学べない。
- 出典：オリジナル問題（根拠：9300 Sys Mgmt CG 17.9 MAC Address Table Creation（learning the source address of packets it receives on each port and adding the address and its associated port number to the address table）／Doc 10543（If … a bridge sees a frame arrive on Line 1 from Host A, the bridge concludes that Host A can be reached through the network connected to Line 1））

#### 問 ccna-06-o08

- 問：Catalyst 9300 で、動的に学習した MAC アドレスが表に残る時間の初期値はどれか。
- ア：300 秒
- イ：15 秒
- ウ：30 秒
- エ：消えない
- 正解：ア
- 解説：エージングタイムの初期値は 300 秒（5 分）。10〜1000000 秒に変えられる。
- アの意味：正しい。
- イの意味：STP の再構成中に短くした値（forward delay の初期値）。
- ウの意味：エージングタイムの初期値ではない。
- エの意味：消えないのは静的アドレス、または 0 を設定したとき。
- 出典：オリジナル問題（根拠：9300 Sys Mgmt CG 17.9 Default MAC Address Table Settings（Aging time 300 seconds）／Changing the Address Aging Time（The range is 10 to 1000000 seconds. The default is 300））

#### 問 ccna-06-o09

- 問：`mac address-table static` で入れた行について正しいものはどれか。
- ア：エージングされず、スイッチを再起動しても消えない
- イ：300 秒使われないと消える
- ウ：clear mac address-table dynamic で消える
- エ：同じ MAC を別のポートで受け取ると、そのポートに自動で書きかわる
- 正解：ア
- 解説：静的アドレスは手で入れたユニキャストのアドレスで、時間でも再起動でも消えない。
- アの意味：正しい。
- イの意味：動的アドレスの動き。
- ウの意味：dynamic は動的な行だけを消す。
- エの意味：自動で書きかわるのは動的な学習の動き。静的な行は設定で決まる。
- 出典：オリジナル問題（根拠：9300 Sys Mgmt CG 17.9（Static address—A manually entered unicast address that does not age and that is not lost when the device resets／Static address entries are never aged or removed from the table／clear mac address-table dynamic Removes all dynamic entries））

#### 問 ccna-06-o10

- 問：スイッチが VLAN 20 で MAC アドレス 0011.2233.4404 を Gi1/0/5 に学習している。VLAN 10 のポートから宛先 0011.2233.4404 のフレームが届いた。正しい動きはどれか。
- ア：VLAN 10 の表には行がないので、VLAN 10 の受け取ったポート以外の全ポートへフラッディングする
- イ：Gi1/0/5 だけに転送する

- アの意味：正しい。
- イの意味：VLAN 20 の行を VLAN 10 のフレームに使うことはない。
- ウの意味：フレームは VLAN 10 のもので、別の VLAN には出さない。
- エの意味：フラッディングの範囲は 1 つの VLAN（ブロードキャストドメイン）。
- 出典：オリジナル問題（根拠：9300 Sys Mgmt CG 17.9 MAC Addresses and VLANs（Each VLAN maintains its own logical address table. A known address in one VLAN is unknown in another until it is learned）／Doc 23563（When there is no entry … in the incoming VLAN, the (unicast) frame will be sent to all forwarding ports within the respective VLAN））

#### 問 ccna-06-o11

- 問：スパニングツリーの再構成が起きたとき、スイッチが動的アドレスについて行うことはどれか。
- ア：エージングタイムを一時的に forward delay の値まで短くし、学習しなおしを早める

- イの意味：そのような動きはない。
- ウの意味：長くすると古い行が残り、届かない時間が延びる。
- エの意味：学習は止めない。学習しなおすために表を早く消す。
- 出典：オリジナル問題（根拠：IOS XE 17 STP CG Accelerated aging（the address-aging time is accelerated so that station addresses can be dropped from the address table and then relearned. The accelerated aging is the same as the forward-delay parameter value／the switch accelerates aging on a per-VLAN basis））

#### 問 ccna-06-o12

- 問：`mac address-table aging-time 0` を設定したときの動きはどれか。
- ア：動的アドレスがエージングで消えなくなる
- イ：動的アドレスがすぐ消え、すべてフラッディングになる
- ウ：MAC アドレスの学習が止まる
- エ：静的アドレスがすべて消える
- 正解：ア
- 解説：0 はエージングをしない設定。範囲は 10〜1000000 秒で、0 だけ特別な意味を持つ。
- アの意味：正しい。
- イの意味：0 を「0 秒で消す」と読みちがえている。
- ウの意味：学習を止めるのは no mac address-table learning vlan。
- エの意味：静的アドレスはエージングの対象外。
- 出典：オリジナル問題（根拠：9300 Sys Mgmt CG 17.9 Changing the Address Aging Time（You can also enter 0, which disables aging. Static address entries are never aged or removed from the table））

### 06-3 転送の判断

#### 問 ccna-06-o13

- 問：スイッチの MAC アドレステーブルが次のとき、Gi1/0/1（VLAN 10）から宛先 0011.2233.4403 のフレームが届いた。スイッチの動きはどれか。

```
Vlan    Mac Address       Type        Ports
----    -----------       --------    -----
  10    0011.2233.4401    DYNAMIC     Gi1/0/1
  10    0011.2233.4402    DYNAMIC     Gi1/0/2
  10    0011.2233.4403    DYNAMIC     Gi1/0/2

```

#### 問 ccna-06-o14

- 問：問 ccna-06-o13 と同じ表のスイッチに、Gi1/0/2 から送信元 0011.2233.4402・宛先 0011.2233.4403 のフレームが届いた。スイッチの動きはどれか。

- アの意味：正しい。

- 出典：オリジナル問題（根拠：9300 Sys Mgmt CG 17.9（If the destination address is on the port that sent the packet, the packet is filtered and not forwarded）／Doc 10543（If the table is mapped between the destination address and any of the ports of the bridge (aside from the one on which the frame was received), the frame is forwarded to the specified port））

#### 問 ccna-06-o15

- 問：宛先 MAC アドレスがスイッチの表にないユニキャストフレームを受け取ったときの動きはどれか。
- ア：同じ VLAN の、受け取ったポート以外のすべての転送中のポートへ送る
- イ：捨てて、送信元にエラーを返す

- 正解：ア

- アの意味：正しい。
- イの意味：スイッチは宛先が未知でも捨てない。エラーも返さない。
- ウの意味：フラッディングは受け取った VLAN の中だけ。
- エの意味：ARP は IP アドレスから MAC を調べるしくみで、スイッチの転送の判断には使わない。
- 出典：オリジナル問題（根拠：Doc 23563（the packet will be flooded out of all forwarding ports in its VLAN (except the port it was received on)／Limited flooding is part of the normal switching process））

#### 問 ccna-06-o16

### 06-4 フラッディングが続くとき

#### 問 ccna-06-o19

- 問：サーバー S1 から S2 へはルーター A、S2 から S1 へはルーター B を通る構成で、片方のスイッチで S2 あてのフレームがずっとフラッディングされている。この原因を表す言葉はどれか。
- ア：非対称ルーティング
- イ：MAC アドレステーブルのあふれ
- ウ：静的アドレスの設定
- エ：カットスルー
- 正解：ア
- 解説：行きと帰りの道がちがうので、片方のスイッチには S2 を送信元とするフレームが届かず、S2 の MAC を学習できない。
- アの意味：正しい。
- イの意味：表がいっぱいで学習できない原因。ここでは S2 のフレームがそもそも届かない。
- ウの意味：静的な行があればフラッディングしない。
- エの意味：送り方のちがいで、フラッディングの原因ではない。
- 出典：オリジナル問題（根拠：Doc 23563 Cause 1: Asymmetric Routing（switch A will not "see" traffic from the S2 MAC address … every time switch A needs to send the packet to the S2 MAC address, the packet will be flooded／Packets follow different paths depending on the direction））

#### 問 ccna-06-o20

- 問：あるポートが何度も上がり下がりしたあと、VLAN の中でフラッディングがほぼ止まらなくなった。最も考えられる理由はどれか。
- ア：スパニングツリーの TCN が何度も出て、エージングタイムが短くなり、表がくり返し消えている
- イ：エージングタイムが長すぎて、表がいっぱいになった
- ウ：ストアアンドフォワードで遅れが大きくなった
- エ：FCS の誤りで、すべてのフレームが捨てられている
- 正解：ア
- 解説：TCN はエージングを短くして表を作り直させる。ポートがフラップすると TCN が続き、フラッディングが続く。端末のポートに PortFast を設定すると TCN を出さない。
- アの意味：正しい。
- イの意味：ポートの上がり下がりとは関係しない。
- ウの意味：遅れはフラッディングの原因ではない。
- エの意味：捨てられているならフラッディングは起きない。
- 出典：オリジナル問題（根拠：Doc 23563 Cause 2（TCN operates by shortening the forwarding table aging time／When the port is flapping, repetitive TCNs and flooding occurs／Ports with the STP portfast feature enabled will not cause TCNs））

#### 問 ccna-06-o21

- 問：1 台のホストが送信元 MAC アドレスを次々に変えたフレームを送り続けている。スイッチで起きることとして正しいものはどれか。
- ア：MAC アドレステーブルがいっぱいになり、新しいアドレスを学習できず、ほかの通信がフラッディングされる
- イ：ホストのポートが自動でルーテッドポートになる
- ウ：表のエージングタイムが自動で 0 になる
- エ：すべてのフレームが FCS の誤りで捨てられる
- 正解：ア
- 解説：表があふれると学習ができず、宛先が表にない通信はフラッディングになる。表を見ると多くの行が同じポートを指す。
- アの意味：正しい。
- イの意味：そのような動きはない。
- ウの意味：エージングタイムは設定で決まり、自動で 0 にはならない。
- エの意味：MAC アドレスを変えても FCS が正しければ捨てられない。
- 出典：オリジナル問題（根拠：Doc 23563 Cause 3: Forwarding Table Overflow（one host starts generating frames each sourced with different MAC address. This will tie up all the forwarding table resources. Once the forwarding tables become saturated, other traffic will be flooded／Most of the MAC addresses will point to the same port））

#### 問 ccna-06-o22

- 問：問 ccna-06-o21 の攻撃を防ぐ方法として Cisco が挙げているものはどれか。
