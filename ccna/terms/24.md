## 24-1 自動化とネットワーク管理

### まとめ表

| 項目 | 手作業の管理 | 自動化した管理 |
| :-: | :-: | :-: |
| 設定のしかた | 1台ずつ CLI で入れる | テンプレートやポリシーから、まとめて配る |
| 間違い | 打ち間違い・機器ごとのばらつきが出やすい | 同じ設定を同じように入れるので、ばらつきが減る |
| 規模が大きくなると | 時間と人手が足りなくなる | 台数が増えても同じ手順で回る |
| 新しい機器の導入 | 箱から出して1台ずつ設定 | ゼロタッチ（PnP）で自動で設定を受け取る |

### 自動化の考え方

#### ネットワーク自動化（ねっとわーくじどうか / network automation）

- 意味：ネットワーク機器の設定・管理・テスト・導入・運用を、人の手作業ではなくソフトウェアで自動で行うこと
- ポイント：ねらいは効率を上げ、人のミスを減らし、運用の費用を下げること。Cisco は、変更の最大 95％ がいまだに手作業で行われ、それが設定ミスやばらつきの原因になると説明している
- 例：100 台のスイッチに同じ NTP サーバーの設定を、コントローラーから一度に入れる

#### 構成のばらつき（こうせいのばらつき / configuration inconsistency, configuration drift）

- 意味：同じ役割の機器なのに、設定が少しずつ違ってしまうこと
- ポイント：手作業での変更が主な原因。自動化では同じテンプレートやポリシーから設定を作るので、機器どうしの設定がそろう（一貫性）
- 例：10 台のうち 1 台だけ SNMP のコミュニティ名が古いまま残っている

#### インテントベースネットワーキング（いんてんとべーすねっとわーきんぐ / intent-based networking, IBN）

- 意味：「何をしたいか」（業務上の意図＝インテント）をポリシーとして決めると、コントローラーがそれを機器ごとの設定に変えて入れ、意図どおりに動いているかを見続ける考え方
- ポイント：管理者は「どう設定するか」ではなく「どうなってほしいか」を決める。Catalyst Center ではポリシーがネットワーク用・機器用の設定に変えられる
- 例：「来客は社内のサーバーにアクセスできない」というポリシーを決めると、各機器に必要な設定が入る

#### ゼロタッチプロビジョニング（ぜろたっちぷろびじょにんぐ / zero-touch provisioning, Plug and Play）

- 意味：箱から出した新しい機器をつなぐだけで、コントローラーから設定やソフトウェアを自動で受け取って使えるようになるしくみ
- ポイント：Cisco では Plug and Play（PnP）と呼ぶ。現地に詳しい人がいなくても機器を入れられる。SD-Access のアンダーレイを自動で作る LAN Automation も PnP の部品を使う
- 例：支社にスイッチを送り、現地の人はケーブルをつなぐだけ

#### 設定のテンプレート（せっていのてんぷれーと / configuration template）

- 意味：機器に入れる設定のひな形。変わる部分（ホスト名・アドレスなど）を変数にしておき、機器ごとの値を入れて設定を作る
- ポイント：同じひな形から作るので、ばらつきが出にくい。Catalyst Center では CLI テンプレートで設定を機器に送れる
- 例：`hostname {{ name }}` の name に機器ごとの名前を入れる

## 24-2 従来型とコントローラー型

### まとめ表

| 項目 | 従来型のネットワーク | コントローラー型のネットワーク |
| :-: | :-: | :-: |
| 設定と管理 | 1台ずつ（box-by-box） | コントローラーからまとめて |
| コントロールプレーン | 各機器がそれぞれ持つ（分散） | コントローラーに集める・まとめて制御する |
| データプレーン | 各機器 | 各機器（ここは変わらない） |
| 全体の見え方 | 機器ごとに見る | ネットワーク全体を1か所で見る |
| 外とのつなぎ方 | CLI・SNMP | ノースバウンド API（REST）とサウスバウンド |

### 3つのプレーン

#### コントロールプレーン（こんとろーるぷれーん / control plane）

- 意味：パケットをどう処理し、どこへ送るかを決める働き。ルーティングプロトコルでの経路の計算、STP、ARP などがここ
- ポイント：RFC 7426 の定義では、機器にパケットの扱い方と送り方を指示するもの。従来型は各機器が自分で持ち、SDN ではここを機器から切り離してまとめて制御する
- 例：OSPF で隣と経路を交換し、ルーティングテーブルを作る

#### データプレーン（でーたぷれーん / data plane, forwarding plane）

- 意味：届いたパケットを、決められたとおりに実際に転送する働き。フォワーディングプレーンとも呼ぶ
- ポイント：コントロールプレーンが作った表（ルーティングテーブル・MAC アドレステーブル）を引いて、1つずつのパケットを送り出す。SDN でもデータプレーンは各機器に残る
- 例：宛先 IP をルーティングテーブルで引いて、出口のインタフェースへ送る

#### マネジメントプレーン（まねじめんとぷれーん / management plane）

- 意味：機器を見張り、設定し、保守するための働き
- ポイント：SSH・SNMP・NETCONF などで機器を管理する通信がここ。SD-Access では Catalyst Center がマネジメントプレーン
- 例：管理者が SSH でログインして設定を変える

### 集中と分散

#### 従来型のネットワーク（じゅうらいがたのねっとわーく / traditional network）

- 意味：各機器が自分のコントロールプレーンを持ち、管理者が1台ずつ設定するネットワーク
- ポイント：機器が多いと手間とミスが増え、全体の状態を1か所で見にくい。各ルーターは自分で経路を計算する（分散したコントロールプレーン）
- 例：50 台のスイッチに 1 台ずつ SSH して VLAN を足す

#### コントローラー型のネットワーク（こんとろーらーがたのねっとわーく / controller-based networking）

- 意味：コントローラー（ソフトウェア）がネットワーク全体を把握し、機器の設定やポリシーをまとめて配るネットワーク
- ポイント：管理者はコントローラーにだけ指示すればよい。全体を1か所で見て、同じポリシーを有線・無線に一貫して入れられる。データの転送はこれまでどおり各機器が行う
- 例：Catalyst Center で、有線と無線に同じポリシーを中央から当てる

#### SDN（えすでぃーえぬ / Software-Defined Networking）

- 意味：コントロールプレーンとデータプレーンの間に抽象化の層を入れて切り離し、ソフトウェア（アプリケーション）からネットワークをプログラムで制御できるようにする考え方
- ポイント：RFC 7426 によると、ねらいはこの分離とプログラムできることで複雑さを減らし、新しい機能を早く入れること。コントローラーが SDN の中心になる
- 語の意味：Software＝ソフトウェア／Defined＝定められた／Networking＝ネットワーク

#### SDN コントローラー（えすでぃーえぬこんとろーらー / SDN controller）

- 意味：SDN で、上のアプリケーションと下のネットワーク機器の間に立ち、ネットワーク全体を制御するソフトウェア
- ポイント：上（アプリ側）にはノースバウンド API、下（機器側）にはサウスバウンドのインタフェースを持つ。Cisco の企業向けキャンパスでは Catalyst Center（旧 DNA Center）がこの役
- 例：Catalyst Center（Cisco の企業キャンパス向け）

## 24-3 API とファブリック

### まとめ表

| 項目 | ノースバウンド API | サウスバウンド API（インタフェース） |
| :-: | :-: | :-: |
| どこの間 | アプリケーション・スクリプト ⇔ コントローラー | コントローラー ⇔ ネットワーク機器 |
| 図での向き | コントローラーの上 | コントローラーの下 |
| 例 | Catalyst Center の Intent API（REST、HTTPS、JSON） | OpenFlow・NETCONF・SNMP・CLI（SSH） |

| SD-Access のプレーン | 使う技術 |
| :-: | :-: |
| マネジメントプレーン | Catalyst Center |
| コントロールプレーン（オーバーレイ） | LISP |
| データプレーン | VXLAN |
| ポリシープレーン | Cisco TrustSec（SGT） |

### API

#### ノースバウンド API（のーすばうんどえーぴーあい / northbound API）

- 意味：コントローラーが上のアプリケーションやスクリプトに向けて出している API
- ポイント：アプリはこれを呼んでコントローラーに仕事を頼み、情報をもらう。Catalyst Center の Intent API はノースバウンドの REST API で、HTTPS の上で GET・POST・PUT・DELETE を使い、JSON でやり取りする
- 例：Python のスクリプトが Catalyst Center に「機器の一覧をちょうだい」と GET を送る
- 語の意味：northbound＝北（上）向きの／API＝Application Programming Interface

#### サウスバウンド API（さうすばうんどえーぴーあい / southbound API, southbound interface）

- 意味：コントローラーがネットワーク機器を制御・設定するために使う、下向きのインタフェース
- ポイント：RFC 7426 はサウスバウンドに制御用（OpenFlow など）と管理用（NETCONF・SNMP など）の両方を含めるべきだとしている。Catalyst Center は機器を見つけて管理するのに CLI（SSH）・SNMP・NETCONF の資格情報を使う
- 例：Catalyst Center が NETCONF（ポート 830）で 9800 に設定を入れる
- 語の意味：southbound＝南（下）向きの

#### Intent API（いんてんとえーぴーあい / Intent API）

- 意味：Catalyst Center がノースバウンドに出している REST API。「何をしたいか」に合わせた形で機能を呼べる
- ポイント：使う前に認証が必要で、ロールベースのアクセス制御（RBAC）に従う。GUI の Platform > Developer Toolkit > APIs で一覧を見られる。ITSM などとつなぐ連携（Integration Flows）は westbound（西向き）と呼ぶ
- 例：GET でサイトの機器の健全性を取る

### ファブリック

#### アンダーレイ（あんだーれい / underlay network）

- 意味：実際のスイッチやルーターと、その間をつなぐ IP の経路でできた物理的なネットワーク
- ポイント：SD-Access では、アンダーレイの全機器がルーティングプロトコルで IP でつながる（レイヤ3のルーテッドアクセス）。利用者の端末やサブネットはアンダーレイに入らず、オーバーレイに入る。LAN Automation では IS-IS で自動で作る
- 例：アクセススイッチまで OSPF か IS-IS でつないだ網

#### オーバーレイ（おーばーれい / overlay network）

- 意味：アンダーレイの上に、カプセル化（トンネル）で作る仮想のネットワーク
- ポイント：1つのアンダーレイの上に、互いに切り離された複数のオーバーレイ（仮想ネットワーク、VN）を作れる。SD-Access では VN ごとに VRF で経路表を分ける
- 例：社員用の VN と来客用の VN を同じ物理網の上に作る

#### ファブリック（ふぁぶりっく / fabric）

- 意味：Cisco の SD-Access の説明では「ファブリックとは、要するにオーバーレイのこと」。アンダーレイの上に、すべての機器を論理的にフルメッシュでつなぐトンネルの網を作ったもの
- ポイント：有線と無線で同じポリシーを中央から決められ、端末は移動しても IP アドレスとポリシーを保てる。ファブリックの機器には役割があり、エッジノード（従来のアクセススイッチにあたる）・コントロールプレーンノード（LISP の対応表を持つ）・ボーダーノード（ファブリックの外とつなぐ）がある
- 例：SD-Access のファブリックサイト

#### VXLAN（ぶいえっくすらん / Virtual Extensible LAN）

- 意味：イーサネットのフレームを丸ごと UDP と IP で包んで運ぶカプセル化（MAC-in-IP）。SD-Access のデータプレーン
- ポイント：セグメントは 24 ビットの VNI で見分けるので、約 1600 万個まで作れる（VLAN の 4094 より多い）。宛先 UDP ポートは 4789。包むと少なくとも 50 バイト増えるので、SD-Access では MTU を大きく（9100）する
- 語の意味：Virtual＝仮想の／Extensible＝拡張できる／LAN＝Local Area Network

#### LISP（りすぷ / Locator/ID Separation Protocol）

- 意味：端末が「誰か」（EID）と「どこにいるか」（RLOC＝つながっているエッジノードのアドレス）を分けて扱い、その対応表を持つプロトコル。SD-Access のコントロールプレーン
- ポイント：エッジノードは宛先の RLOC をコントロールプレーンノードに問い合わせてから送る（必要なときだけ引く方式）。端末が移動しても EID は変わらず、RLOC の対応だけが変わる
- 語の意味：Locator＝場所を示すもの／ID＝識別子／Separation＝分離

#### Catalyst Center（かたりすとせんたー / Cisco Catalyst Center, 旧 Cisco DNA Center）

- 意味：Cisco の企業ネットワーク向けのコントローラー。設計・導入（PnP）・ポリシー・見張り（Assurance）を1か所で行う
- ポイント：SD-Access のマネジメントプレーン。上にノースバウンドの Intent API（REST）を出し、下は CLI・SNMP・NETCONF で機器を扱う。CCNA v1.1 では DNA Center での従来型の機器管理の出題が外れ、AI が加わった
- 例：Catalyst Center から CLI テンプレートで設定を配る

## 24-4 AI と機械学習

### まとめ表

| 項目 | 予測 AI（predictive AI） | 生成 AI（generative AI） |
| :-: | :-: | :-: |
| すること | データのパターンから推論・予測する | 頼まれた内容に合わせて新しい中身（文章・コードなど）を作る |
| ネットワークでの例 | ふだんの状態（ベースライン）から外れた異常を見つける、Wi-Fi の干渉の増加を予測する | 自然な文で質問すると、状態を調べて答える・手順を説明する（Catalyst Center の AI Assistant） |
| 気をつけること | 学習データが足りないと正しく判断できない | もっともらしい誤り（ハルシネーション）を出すことがある。結果を確かめる |

| 学び方 | 学ぶもの | 向いている仕事 |
| :-: | :-: | :-: |
| 教師あり学習 | 正解（ラベル）付きのデータ | 分類・予測 |
| 教師なし学習 | ラベルのないデータの中の隠れたパターン | グループ分け・異常検知 |
| 強化学習 | 試してみて、報酬と罰で学ぶ | 資源の割り当て・ロボット |

### AI の種類

#### 機械学習（きかいがくしゅう / machine learning, ML）

- 意味：人が手順を全部書く代わりに、データからパターンを学ばせて、判断や予測ができるようにする AI の技術
- ポイント：学習（トレーニング）の段階でモデルの中のパラメーターを調整し、推論の段階で新しいデータに使う。Catalyst Center の AI Network Analytics は機械学習でそのネットワークのベースラインを作り、異常や原因を見つける
- 例：過去の接続の記録から、いつもの接続時間の幅を学ぶ

#### 予測 AI（よそくえーあい / predictive AI）

- 意味：データのパターンを見分けて推論し、これから起きることや異常を予測する AI
- ポイント：Cisco の説明では「パターン認識で推論を引き出す」もの。ネットワークでは、固定のしきい値の代わりに学習したベースラインと比べて、問題を早めに知らせる
- 例：Wi-Fi の干渉や、端末の接続の遅れが増えることを前もって予測する

#### 生成 AI（せいせいえーあい / generative AI, GenAI）

- 意味：利用者の頼みに応じて、文章・画像・コードなどの新しい中身を作る AI
- ポイント：大量のデータでパターンを学んだ深層学習のモデル（大規模言語モデル、LLM など）を使う。ネットワークでは、自然な文での質問に答える・手順や設定の案を出す・調べものを手伝うのに使う
- 例：Catalyst Center の AI Assistant に「今日再起動したスイッチを見せて」と聞く

#### AIOps（えーあいおぷす / AI for IT Operations）

- 意味：IT の運用に AI・機械学習・機械推論を使って、作業を簡単にし、自動化すること
- ポイント：Gartner の定義では、ビッグデータと機械学習で、イベントの関連づけ・異常検知・原因の特定を自動化するもの。システムどうしをつなぐには公開された API が要る
- 例：AI が機器の異常を見つけて原因と直し方を示し、ITSM のチケットを自動で開いて閉じる
- 語の意味：AI＝Artificial Intelligence／Ops＝Operations（運用）

#### 機械推論（きかいすいろん / machine reasoning, MR）

- 意味：知識やルールをもとに、論理的な手順で結論（原因など）を導く AI の技術
- ポイント：機械学習がデータからパターンを学ぶのに対し、機械推論は筋道を立てて考える。Catalyst Center は機械推論のエンジンで複雑な原因分析を行う
- 例：「この端末がつながらない」から、認証・DHCP・無線を順に調べて原因をしぼる

### 学び方と使い方

#### 教師あり学習（きょうしありがくしゅう / supervised learning）

- 意味：正解（ラベル）が付いたデータで学ばせる機械学習。最もよく使われる形
- ポイント：出してほしい答えが分かっている仕事に向く（分類・予測）。教師なし学習はラベルなしでパターンを見つける
- 例：「正常」「故障」のラベルを付けた過去のログで学ばせ、新しいログを分類する

#### 教師なし学習（きょうしなしがくしゅう / unsupervised learning）

- 意味：ラベルのないデータから、隠れたパターンやまとまりを見つける機械学習
- ポイント：似たものどうしのグループ分けや、異常検知に向く。正解を用意しなくてよい
- 例：ふだんの通信のまとまりから外れたものを異常として見つける

#### 学習と推論（がくしゅうとすいろん / training and inference）

- 意味：学習はデータでモデルのパラメーターを調整する段階、推論は学習したモデルを本番で使い、新しいデータを判断する段階
- ポイント：学習には大きな計算力とデータが要る。推論はできあがったモデルを使うだけなので、すぐに結果を返せる
- 例：学習＝過去 1 か月のデータでベースラインを作る／推論＝今の値がベースラインから外れたかを判断する

#### ベースライン（べーすらいん / baseline）

- 意味：そのネットワークの「ふだんの状態」。ネットワークの動きを分析して取り出した、正常な振る舞いの幅
- ポイント：AI によるベースラインは、ネットワークや場所ごとに作られ、環境が変わると学び直して変わる。固定のしきい値と違い、そのネットワークに合った判断ができる
- 例：月曜の朝は接続が多いのがふつう、と学んでいるので、それだけでは異常にしない

#### 異常検知（いじょうけんち / anomaly detection）

- 意味：ベースラインから大きく外れた動きを見つけること
- ポイント：Catalyst Center の AI-Driven Anomaly Detection は、害のない小さな異常は無視して通知の雑音（ノイズ）を減らし、本当に影響のある問題を知らせる
- 例：ある場所だけ接続にかかる時間がふだんの幅を大きく超えたので、問題として出す

#### ハルシネーション（はるしねーしょん / hallucination）

- 意味：生成 AI が、もっともらしいが事実と違う答えを作ってしまうこと
- ポイント：減らす方法に RAG（答えを作る前に、社内の新しいデータを探して取り込む）がある。生成 AI の答えは、そのまま信じずに確かめる。学習データのかたより（バイアス）にも注意する
- 例：存在しないコマンドを、本物のように答える
