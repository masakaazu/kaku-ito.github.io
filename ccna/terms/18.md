## 18-1 SNMP

### まとめ表

| 項目 | 内容 |
| :-: | :-: |
| 登場人物 | マネージャー（NMS）・エージェント（機器の中）・MIB（機器の情報の一覧） |
| マネージャー → エージェント | get-request・get-next-request・get-bulk-request（v2c 以降）・set-request。UDP 161 |
| エージェント → マネージャー | trap（確認なし）・inform（確認あり、v2c 以降）。UDP 162 |
| v1・v2c | コミュニティ名（平文の合言葉）で認証。RO（読むだけ）・RW（読み書き） |
| v3 | ユーザー名。noAuthNoPriv・authNoPriv・authPriv（認証＋暗号化） |

### しくみ

#### SNMP（えすえぬえむぴー / Simple Network Management Protocol）

- 意味：ネットワーク機器の状態を集めたり、設定値を変えたり、異変を知らせてもらったりするための管理プロトコル。アプリケーション層で、UDP を使う
- ポイント：インタフェースの使用量のグラフ、CPU の監視、リンクダウンの通知などに使う。syslog は「ログの文章を送る」、SNMP は「決まった項目の値を読み書きする・通知する」
- 語の意味：Simple＝簡単な／Network Management＝ネットワーク管理／Protocol＝プロトコル

#### SNMP マネージャー（えすえぬえむぴーまねーじゃー / SNMP manager, NMS）

- 意味：機器に問い合わせて情報を集め、表示・分析する側。ネットワーク管理システム（NMS）の一部
- ポイント：マネージャーが機器を定期的に問い合わせる（ポーリング）。trap や inform を受け取るのもマネージャー
- 例：Cisco Prime Infrastructure などの管理ソフト

#### SNMP エージェント（えすえぬえむぴーえーじぇんと / SNMP agent）

- 意味：ルーターやスイッチの中で動き、マネージャーの問い合わせに MIB の値で答えたり、値を変えたり、trap を送ったりする側
- ポイント：Cisco の機器では初期値でエージェントは無効。snmp-server community・host・user などを1つ入れると有効になり、UDP 161・162 が開く

#### MIB（みぶ / Management Information Base）

- 意味：エージェントが持つ、管理できる情報（変数）の一覧。インタフェースの数、送受信のバイト数、機器名などが木の形に並ぶ
- ポイント：MIB の各変数は OID（数字を点でつないだ番号）で指す。マネージャーは OID を指定して get や set をする
- 語の意味：Management Information＝管理情報／Base＝データベース

#### OID（おーあいでぃー / Object Identifier）

- 意味：MIB の中の1つの変数を指す、数字を点でつないだ番号。木の根から枝をたどる住所のようなもの
- ポイント：例えば機器名（sysName）は 1.3.6.1.2.1.1.5。名前の決まった木なので、どのメーカーの機器でも同じ番号で同じ情報を指せる
- 例：`1.3.6.1.2.1.1.5.0`（sysName）

### 操作と通知

#### get-request / get-next-request / get-bulk-request（げっとりくえすと）

- 意味：マネージャーがエージェントの MIB の値を読む操作。get は指定した変数、get-next は次の変数、get-bulk は表などをまとめて読む
- ポイント：get-bulk は SNMPv2c 以降だけ。往復の回数を減らせる。答えは response（get-response）で返る

#### set-request（せっとりくえすと）

- 意味：マネージャーがエージェントの MIB の値を書き換える操作
- ポイント：書き換えには RW（読み書き）のコミュニティか、書き込みを許した v3 のユーザーが要る。RO では set できない

#### trap（とらっぷ）

- 意味：エージェントが、何か起きたときに自分からマネージャーへ送る通知。マネージャーは受け取っても返事をしない
- ポイント：送りっぱなしなので、届いたかどうかエージェントにはわからない。リンクのアップ・ダウン、認証の失敗などで送る。UDP 162 宛て
- 例：`snmp-server enable traps` ＋ `snmp-server host 10.1.99.20 version 2c public`

#### inform（いんふぉーむ）

- 意味：エージェントからマネージャーへの通知のうち、マネージャーが受け取ったら返事（response）を返すもの
- ポイント：返事が来なければ送り直すので、trap より届きやすい。その代わり返事が来るまで機器のメモリに残るので、負荷は大きい。SNMPv1 には inform がない

#### SNMP のポート（えすえぬえむぴーのぽーと / UDP 161・162）

- 意味：SNMP は UDP を使い、エージェントは UDP 161 で問い合わせを受け、マネージャーは UDP 162 で trap・inform を受ける
- ポイント：「161＝問い合わせ（get・set）」「162＝通知（trap・inform）」と分けて覚える。snmp-server host で宛先のポートを省略すると 162

### バージョンとセキュリティ

#### コミュニティ名（こみゅにてぃめい / community string）

- 意味：SNMPv1・v2c で使う、合言葉のような文字列。マネージャーとエージェントで同じ文字列が設定されていればアクセスできる
- ポイント：RO（read-only）は読むだけ、RW（read-write）は読み書き。文字列は暗号化されずに流れるので、のぞかれると読まれる。初期値の public・private のままにしない
- 例：`snmp-server community MyRO123 RO`

#### SNMPv2c（えすえぬえむぴーぶいつーしー）

- 意味：SNMPv1 のコミュニティ名のしくみのまま、get-bulk（まとめて読む）と細かいエラーの報告、inform を加えた版
- ポイント：c は community の c。認証はコミュニティ名だけで、暗号化はない。セキュリティが要るなら v3

#### SNMPv3（えすえぬえむぴーぶいすりー）

- 意味：ユーザーごとの認証（パケットが改ざんされていないことと送り手の確認）と暗号化を加えた SNMP
- ポイント：セキュリティのレベルは3つ。noAuthNoPriv（ユーザー名だけ）、authNoPriv（認証あり・暗号化なし）、authPriv（認証あり・暗号化あり）。いちばん安全なのは authPriv
- 例：`snmp-server group ADMIN v3 priv`

#### authPriv（おーすぷらいぶ）

- 意味：SNMPv3 のセキュリティレベルで、認証（HMAC-SHA など）と暗号化（AES など）の両方を使うもの
- ポイント：auth＝認証、priv＝privacy（中身を隠す＝暗号化）。authNoPriv は認証だけで中身は見える。noAuthNoPriv はどちらもない
- 語の意味：auth＝authentication（認証）／Priv＝privacy（秘密を守る＝暗号化）

## 18-2 syslog

### まとめ表

| レベル | キーワード | 意味 |
| :-: | :-: | :-: |
| 0 | emergencies | 機器が使えない |
| 1 | alerts | すぐ対処が要る |
| 2 | critical | 重大な状態 |
| 3 | errors | エラー |
| 4 | warnings | 警告 |
| 5 | notifications | 正常だが大事なこと |
| 6 | informational | 情報 |
| 7 | debugging | デバッグ |

### メッセージ

#### syslog（しすろぐ / system logging）

- 意味：機器のシステムメッセージ（ログ）を、決まった形でコンソールやサーバーに送るしくみ。サーバーへは UDP 514 で送る
- ポイント：ログを1か所の syslog サーバーに集めると、機器が再起動してもログが残り、何台ものログを並べて見られる。時刻をそろえる NTP（#16）とセットで使う

#### 重大度レベル（じゅうだいどれべる / severity level）

- 意味：ログの重大さを 0〜7 の数字で表したもの。0 がいちばん重大（emergencies）、7 がいちばん軽い（debugging）
- ポイント：数字が小さいほど重大。レベルを指定すると「そのレベルと、それより小さい数字（より重大）」が送られる
- 例：`logging trap 4` → 0〜4 を送る

#### ファシリティ（ふぁしりてぃ / facility）

- 意味：ログが何に関するものかを表す分類。Cisco のメッセージでは、%の直後の SYS・LINK・LINEPROTO などがファシリティ。syslog サーバーへ送るときの分類は初期値で local7
- ポイント：レベル（重大さ）とは別の軸。「%LINK-3-UPDOWN」なら LINK がファシリティ、3 がレベル、UPDOWN がニーモニック

#### ログメッセージの形（ろぐめっせーじのかたち / message format）

- 意味：Cisco のログは「連番:時刻: %ファシリティ-レベル-ニーモニック: 説明」の形で出る
- ポイント：連番は service sequence-numbers、時刻は service timestamps を入れたときだけ付く
- 例：`*Nov  7 10:15:03.158: %LINEPROTO-5-UPDOWN: Line protocol on Interface GigabitEthernet0/1, changed state to down`

### 送り先と設定

#### logging console（ろぎんぐこんそーる）

- 意味：コンソールに出すログのレベルを決めるコマンド。初期値は debugging（7 まで全部）
- ポイント：コンソールには初期値でログが出る。多すぎると作業の邪魔になるので、レベルを下げることがある
- 例：`logging console 3`

#### logging monitor と terminal monitor（ろぎんぐもにたー・たーみなるもにたー）

- 意味：logging monitor は Telnet・SSH の画面（vty）に出すログのレベルを決める。terminal monitor は、今の Telnet・SSH の画面にログを出すよう、その場で頼むコマンド
- ポイント：SSH で入ってもログが出ないときは terminal monitor を打つ。セッションごとの設定なので、入り直すたびに要る
- 例：`R1# terminal monitor`

#### logging buffered（ろぎんぐばっふぁーど）

- 意味：機器のメモリの中のバッファーにログをためるコマンド。show logging で見られる
- ポイント：電源を切ったり再起動したりすると消える（フラッシュに保存していなければ）。初期値のサイズは 102400 バイト
- 例：`logging buffered 16384`

#### logging host と logging trap（ろぎんぐほすと・ろぎんぐとらっぷ）

- 意味：logging host は syslog サーバーのアドレスを決める（logging アドレス だけでもよい）。logging trap は syslog サーバーへ送るレベルを決める
- ポイント：syslog サーバーへの初期値のレベルは informational（6 まで）。trap という名前だが SNMP の trap とは別物
- 例：`logging host 10.1.99.30` ＋ `logging trap warnings`

#### service timestamps（さーびすたいむすたんぷす）

- 意味：ログに日付と時刻を付けるコマンド。datetime で日時、uptime で起動してからの時間、msec でミリ秒
- ポイント：何台ものログを比べるには日時が要る。NTP で時刻を合わせておかないと、日時が付いても比べられない
- 例：`service timestamps log datetime msec`

#### logging synchronous（ろぎんぐしんくろなす）

- 意味：コンソールや vty の line で、ログが入力中のコマンドを割り込みで崩さないようにする設定
- ポイント：ログが出たあと、打ちかけのコマンドを新しい行に出し直してくれる。line console 0 や line vty 0 15 の中で入れる
- 例：`line console 0` → `logging synchronous`

## 18-3 TFTP と FTP

### まとめ表

| 項目 | TFTP | FTP |
| :-: | :-: | :-: |
| 運ぶもの | UDP 69 | TCP 21（制御）・20（データ、アクティブ） |
| 認証 | なし | ユーザー名とパスワード |
| ディレクトリの一覧 | できない | できる |
| 確実に届ける方法 | 512 バイトずつ送って1つずつ ACK を待つ | TCP にまかせる |
| 向いているもの | 小さなファイル・機器の起動や設定の保存 | 大きなファイル・いろいろな操作 |

### 2つのプロトコル

#### TFTP（てぃーえふてぃーぴー / Trivial File Transfer Protocol）

- 意味：UDP（ポート 69）でファイルを送る、とても簡単なファイル転送プロトコル
- ポイント：認証がなく、ディレクトリの一覧もできない。ファイルを読む・書くだけ。データは 512 バイトずつ送り、1つずつ ACK を待つ（lock step）ので、UDP でも抜けを直せる。安全な場所でだけ使う
- 語の意味：Trivial＝ささいな・簡単な／File Transfer＝ファイル転送

#### FTP（えふてぃーぴー / File Transfer Protocol）

- 意味：TCP でファイルを送るプロトコル。ユーザー名とパスワードでログインし、一覧・削除・名前の変更などもできる
- ポイント：コマンドを送る制御のコネクション（TCP 21）と、ファイルを運ぶデータのコネクションの2本を使う。パスワードも暗号化されずに流れる
- 例：`copy ftp://user:pass@10.1.99.40/c9300.bin flash:`

#### 制御コネクションとデータコネクション（せいぎょこねくしょん・でーたこねくしょん / control and data connections）

- 意味：FTP で、コマンドと返事をやりとりする接続（制御、サーバーの TCP 21）と、ファイルや一覧の中身を運ぶ接続（データ）
- ポイント：制御のコネクションはつないだまま、ファイルを送るたびにデータのコネクションを作る。データの既定のポートはサーバー側で 20（制御のポートの1つ下）

#### アクティブモードとパッシブモード（あくてぃぶもーど・ぱっしぶもーど / active and passive mode）

- 意味：FTP のデータのコネクションをどちらから張るかの違い。アクティブはサーバーが（ポート 20 から）クライアントへ張る。パッシブ（PASV）はクライアントがサーバーの指定したポートへ張る
- ポイント：アクティブでは外からクライアントへ接続が来るので、ファイアウォールや NAT で止められやすい。パッシブなら接続はいつもクライアントから

### 機器での使い方

#### copy コマンド（こぴーこまんど）

- 意味：ファイルを「元 → 先」の順でコピーする特権 EXEC のコマンド。tftp:・ftp:・scp:・flash: などのファイルシステムを指定できる
- ポイント：設定のバックアップは copy running-config tftp:、OS の入れ替えは copy tftp: flash: など。書く順番は「元」が先。同じ機器の中どうし（flash: から flash:）の同名コピーなど、できない組み合わせもある
- 例：`copy running-config tftp://10.1.99.40/r1-confg`

#### SCP（えすしーぴー / Secure Copy Protocol）

- 意味：SSH の上でファイルをコピーするプロトコル。ユーザー名とパスワード（または鍵）で認証し、中身を暗号化する
- ポイント：TFTP（認証なし）・FTP（暗号化なし）の代わりに、安全にファイルを運ぶときに使う。SSH を設定済みであることが前提（#11）
- 例：`copy scp://admin@10.1.99.40/c9300.bin flash:`

### 18-1 SNMP

#### 問 ccna-18-o01

- 問：SNMP で、ルーターやスイッチの中で動き、MIB の値をマネージャーに答えるものはどれか。
- ア：SNMP マネージャー
- イ：SNMP エージェント
- ウ：syslog サーバー
- エ：TFTP サーバー
- 正解：イ
- 解説：エージェントは機器の中で動き、MIB から値を取り出して答えたり、値を変えたり、trap を送ったりする。
- アの意味：問い合わせて情報を集める側（NMS）。
- イの意味：正しい。
- ウの意味：ログを受け取るサーバー。SNMP の登場人物ではない。
- エの意味：ファイルを置くサーバー。
- 出典：オリジナル問題（根拠：Cisco Network Management Configuration Guide IOS XE 17.9（Catalyst 9300）「Configuring Simple Network Management Protocol」（The SNMP system consists of an SNMP manager, an SNMP agent, and a management information base (MIB) … The agent and MIB reside on the device））

#### 問 ccna-18-o02

- 問：エージェントが、リンクダウンなどが起きたときに自分からマネージャーへ送り、マネージャーは返事をしないメッセージはどれか。
- ア：get-request
- イ：set-request
- ウ：trap
- エ：inform
- 正解：ウ
- 解説：trap はエージェントから送りっぱなしの通知。届いたかどうかエージェントにはわからない。
- アの意味：マネージャーがエージェントの値を読む操作。
- イの意味：マネージャーがエージェントの値を書き換える操作。
- ウの意味：正しい。
- エの意味：マネージャーが返事をする通知。
- 出典：オリジナル問題（根拠：Cisco 17.9「Configuring SNMP」（trap — An unsolicited message sent by an SNMP agent to an SNMP manager when some event has occurred／Traps are unreliable because the receiver does not send an acknowledgment））

#### 問 ccna-18-o03

- 問：trap と比べた inform の特徴として正しいものはどれか。
- ア：マネージャーが返事をするので届いたかがわかり、届かなければ送り直す
- イ：マネージャーからエージェントへ送る
- ウ：SNMPv1 だけで使える
- エ：機器の負荷は trap より小さい
- 正解：ア
- 解説：inform はマネージャーが response を返す。返事がなければ送り直すので届きやすいが、返事が来るまでメモリに残るので負荷は大きい。
- アの意味：正しい。
- イの意味：trap も inform もエージェントからマネージャーへ。
- ウの意味：逆。SNMPv1 には inform がない。
- エの意味：逆。送り直しとメモリの分だけ負荷は大きい。
- 出典：オリジナル問題（根拠：Cisco 17.9「Configuring SNMP」SNMP Notifications（informs are more likely than traps to reach their intended destination … consume more resources／SNMPv1 does not support informs））

#### 問 ccna-18-o04

- 問：SNMP で使うポート番号の組として正しいものはどれか。
- ア：エージェントが問い合わせを受けるのは TCP 161、通知の受け取りは TCP 162
- イ：エージェントが問い合わせを受けるのは UDP 161、マネージャーが trap を受けるのは UDP 162
- ウ：エージェントが問い合わせを受けるのは UDP 162、マネージャーが trap を受けるのは UDP 161
- エ：UDP 514 だけを使う
- 正解：イ
- 解説：SNMP は UDP。get・set などの問い合わせはエージェントの 161、trap・inform はマネージャーの 162 に届く。
- アの意味：SNMP は UDP。
- イの意味：正しい。
- ウの意味：逆。
- エの意味：514 は syslog。

- アの意味：認証も暗号化もない。
- イの意味：認証はあるが暗号化しない。
- ウの意味：正しい。
- エの意味：管理情報の読み書き。ファイルの転送用ではない。
- 出典：オリジナル問題（根拠：Cisco System Management CG 17.9「Working with the Flash File System」（SCP—scp:[[//username [:password]@location]/directory]/filename）・「Secure Copy」）

#### 問 ccna-18-o29

- 問：FTP サーバーにアクティブモードでつないだところ、ログインはできたが一覧やファイルの転送だけ失敗する。原因として最もあてはまるものはどれか。
- ア：制御のコネクション（TCP 21）が止められている
- イ：サーバーからクライアントへのデータのコネクションが、ファイアウォールや NAT で止められている
- ウ：TFTP のポート 69 が開いていない
- エ：SNMP のコミュニティ名が違う
- 正解：イ
- 解説：ログインできたので制御のコネクションは通っている。アクティブモードではサーバーからクライアントへデータのコネクションを張るので、それが止められやすい。パッシブモードにすると直ることが多い。
- アの意味：止められていればログインもできない。
- イの意味：正しい。
- ウの意味：FTP は TFTP のポートを使わない。
- エの意味：SNMP は関係ない。
- 出典：オリジナル問題（根拠：RFC 959 3.2・5.2（control connection と data connection、PASV））

#### 問 ccna-18-o30

- 問：次の用途とプロトコルの組み合わせとして正しいものはどれか。
- ア：機器の CPU 使用率をグラフにする ― syslog
- イ：インタフェースのダウンを文章のログとして集める ― syslog
- ウ：設定ファイルのバックアップ ― SNMP
- エ：時刻をそろえる ― TFTP
- 正解：イ
- 解説：ログの文章を集めるのは syslog。CPU の値の収集は SNMP、ファイルの受け渡しは TFTP・FTP・SCP、時刻は NTP。
- アの意味：値を定期的に集めるのは SNMP。
- イの意味：正しい。
- ウの意味：ファイルを運ぶのは TFTP・FTP・SCP。
- エの意味：時刻は NTP。
- 出典：オリジナル問題（根拠：Cisco 17.9「Configuring SNMP」／Cisco 17.9「Configuring System Message Logs」／RFC 1350）
