## 10-1 電波とチャネル・SSID

### まとめ表

**周波数帯とチャネル**

| 周波数帯 | 重ならないチャネル | 特徴 |
| :-: | :-: | :-: |
| 2.4GHz | 1・6・11 の3つだけ | 遠くまで届くが混みやすい。電子レンジ・Bluetooth とも同じ帯 |
| 5GHz | 20以上（36〜165。一部はDFSが必要） | どれも重ならない。チャネルをつなげて40／80／160MHz にできる |
| 6GHz | さらに多い（Wi-Fi 6E 以降） | 新しい帯。WPA3が前提 |

**サービスセットの呼び方**

| 用語 | 何のことか |
| :-: | :-: |
| BSS | AP1台と、それにつながる端末のまとまり |
| BSSID | BSSを見分けるID（APの無線のMACアドレス） |
| ESS | 同じSSIDを出す複数のAPで作る広いネットワーク（ローミングできる） |
| IBSS | APなしで端末どうしがつながる形（アドホック） |

### 周波数とチャネル

#### 2.4GHz帯（にーてんよんぎがへるつたい / 2.4-GHz band）

- 意味：無線LANが使う周波数帯の1つ。802.11b／g／n／ax が使う。チャネル1〜13（日本は14も）があり、中心の周波数は5MHzずつしか離れていない
- ポイント：1つのチャネルは約22MHz の幅を使うので、となりのチャネルとは重なる。重ならないのは 1・6・11 の3つだけ。電子レンジ・Bluetooth・コードレス電話の電波もこの帯にあり、混みやすい
- 例：チャネル1＝2412MHz、チャネル6＝2437MHz、チャネル11＝2462MHz（25MHzずつ離れている）
- 語の意味：GHz＝ギガヘルツ（1秒に10億回の振動）

#### 5GHz帯（ごぎがへるつたい / 5-GHz band）

- 意味：802.11a／n／ac／ax が使う周波数帯。チャネル36〜165 があり、20MHz幅のチャネルどうしは重ならない
- ポイント：重ならないチャネルが20以上あるので、となりのAPと違うチャネルを選びやすい。2.4GHzより届く距離は短い。52〜144 のチャネルはレーダーと共用なので、DFS（レーダーを見つけたらチャネルを変える）が必要
- 例：UNII-1＝36〜48、UNII-2＝52〜64、UNII-2c＝100〜144、UNII-3＝149〜165
- 語の意味：UNII＝Unlicensed National Information Infrastructure（免許なしで使える帯域の区分）

#### 重ならないチャネル（かさならないちゃねる / nonoverlapping channels）

- 意味：使う周波数の幅がお互いに重ならないチャネルの組み合わせ。2.4GHz では 1・6・11
- ポイント：となりあうAPには重ならないチャネルを割り当てる。1と2のように重なるチャネルを近くで使うと、お互いの電波が雑音になる（隣接チャネル干渉）。Cisco の RRM も「1・6・11 のような重ならないチャネルだけを使う」ように勧めている
- 例：AP1＝ch1、AP2＝ch6、AP3＝ch11、AP4＝ch1（AP1から遠い場所に置く）

#### 同一チャネル干渉（どういつちゃねるかんしょう / co-channel interference, CCI）

- 意味：近くにある複数のAPが同じチャネルを使っているため、電波を出す順番を待ち合い、速度が落ちること
- ポイント：隣接チャネル干渉（少しずれたチャネルの電波が雑音になる）と区別する。同じチャネルは「同じ空気を分け合う」ので、遠くに離して再利用する（チャネルの再利用）
- 例：となりのAPも自分のAPもch6 → 端末が送る順番を待つ時間が増える

#### チャネルボンディング（ちゃねるぼんでぃんぐ / channel bonding）

- 意味：となりあう20MHz のチャネルをつなげて、40MHz・80MHz・160MHz の広いチャネルとして使い、速度を上げるしくみ（802.11n 以降）
- ポイント：広げるほど使えるチャネルの数が減る。2.4GHz は重ならないチャネルが3つしかないので、Cisco は2.4GHz での40MHz を使わない（RRM の DCA も2.4GHz は20MHz だけ）
- 例：5GHz の ch36 と ch40 をつないで 40MHz で使う
- 語の意味：bond＝結びつける

#### IEEE 802.11 の規格（あいとりぷるいー はちまるにーてんいちいち / IEEE 802.11 standards）

- 意味：無線LANの規格の名前。b（2.4GHz、11Mbps）、a（5GHz、54Mbps）、g（2.4GHz、54Mbps）、n（Wi-Fi 4、2.4／5GHz）、ac（Wi-Fi 5、5GHz）、ax（Wi-Fi 6／6E、2.4／5／6GHz）
- ポイント：a と ac は5GHz だけ、b と g は2.4GHz だけ。n と ax は両方。OFDM という変調は a・g から使われている
- 例：802.11ac Wave 2＝最大160MHz幅、4つの空間ストリーム

### 電波の強さ

#### RSSI（あーるえすえすあい / Received Signal Strength Indicator）

- 意味：受け取った電波の強さ。dBm（1mW を0とした対数の単位）のマイナスの値で表し、0に近いほど強い
- ポイント：-67dBm のほうが -80dBm より強い。Cisco は音声の無線LANでは、エリアの端で -67dBm 以上を目安にしている
- 例：-50dBm＝とても強い／-67dBm＝音声も通る目安／-85dBm＝弱い
- 語の意味：Received＝受け取った／Signal＝信号／Strength＝強さ／Indicator＝指標

#### SNR（えすえぬあーる / Signal-to-Noise Ratio）

- 意味：受け取った電波の強さと、周りの雑音（ノイズフロア）の強さの差。dB で表し、大きいほど良い
- ポイント：電波が強くても雑音も強ければ速度は出ない。RSSI -67dBm・ノイズ -92dBm なら SNR は25dB。Cisco は音声で25dB 以上を目安にしている
- 例：信号 -70dBm、ノイズ -95dBm → SNR＝25dB
- 語の意味：Signal＝信号／to＝対／Noise＝雑音／Ratio＝比

### SSIDとサービスセット

#### SSID（えすえすあいでぃー / Service Set Identifier）

- 意味：無線LANのネットワークの名前。最大32文字。APはビーコンでSSIDを知らせ、端末は一覧からSSIDを選んでつなぐ
- ポイント：SSIDは名前にすぎず、隠しても（ブロードキャストしなくても）安全にはならない。1台のAPで複数のSSIDを出せる（WLANごとにSSID）。同じSSIDを出すAPどうしならローミングできる
- 例：社員用「CORP」、来客用「GUEST」を1台のAPから出す
- 語の意味：Service＝サービス／Set＝集まり／Identifier＝識別子

#### BSS（びーえすえす / Basic Service Set）

- 意味：1台のAP（の1つの無線）と、そこにつながっている端末のまとまり。無線LANのいちばん小さい単位
- ポイント：端末はAPを通して通信する（端末どうしが直接話すのではない）。BSSが届く範囲をセル（BSA）と呼ぶ
- 例：会議室のAP1台と、そこにつながるノートPC10台
- 語の意味：Basic＝基本の／Service Set＝サービスの集まり

#### BSSID（びーえすえすあいでぃー / Basic Service Set Identifier）

- 意味：BSSを見分けるID。APの無線インタフェースのMACアドレスを使う
- ポイント：SSIDが同じでも、APが違えばBSSIDは違う。1台のAPが複数のSSIDを出すときは、SSIDごとに別のBSSID（少しずつ違うMAC）を使う
- 例：SSID「CORP」・BSSID 00:3a:7d:12:34:50

#### ESS（いーえすえす / Extended Service Set）

- 意味：同じSSIDを出す複数のAP（複数のBSS）を、有線のネットワーク（ディストリビューションシステム）でつないで作る広いネットワーク
- ポイント：端末は移動しながらAPを乗り換えられる（ローミング）。ローミングのために、となりのAPのセルは10〜15％ほど重ねる。SSID は正しくは ESSID のこと
- 例：建物の全フロアで同じ「CORP」を出す
- 語の意味：Extended＝広げた／Service Set＝サービスの集まり

#### IBSS（あいびーえすえす / Independent Basic Service Set）

- 意味：APを使わず、端末どうしが直接つながる無線LANの形。アドホックモードとも呼ぶ
- ポイント：インフラストラクチャモード（APを使うBSS・ESS）と対になる用語。会社のネットワークでは使わない
- 例：ノートPC2台をAPなしで直接つなぐ
- 語の意味：Independent＝独立した

## 10-2 暗号化と認証

### まとめ表

**セキュリティの方式**

| 方式 | 暗号化 | 認証（パーソナル） | 認証（エンタープライズ） |
| :-: | :-: | :-: | :-: |
| WEP | RC4（破られている） | 固定の鍵 | ― |
| WPA | TKIP | PSK | 802.1X |
| WPA2 | AES-CCMP | PSK | 802.1X |
| WPA3 | AES-CCMP／GCMP（PMF必須） | SAE | 802.1X（192ビットモードあり） |

**パーソナルとエンタープライズ**

| | パーソナル | エンタープライズ |
| :-: | :-: | :-: |
| 何で認証するか | 全員が同じパスフレーズ | 1人ずつのユーザー名・証明書 |
| サーバー | いらない | RADIUSサーバー（ISEなど） |
| 向いている場所 | 家庭・小さな事務所 | 会社 |

### 方式

#### WEP（うぇっぷ / Wired Equivalent Privacy）

- 意味：最初の無線LANの暗号化。RC4 という暗号と、全員で同じ固定の鍵（40ビットか104ビット）を使う
- ポイント：短い時間で鍵が破られるので、今は使ってはいけない。Cisco の新しいAP（Wave 2）は対応していない。WPA・WPA2・WPA3 と並べて「いちばん弱いもの」として出る
- 例：40ビットの鍵＝ASCII 5文字か16進数10文字
- 語の意味：Wired＝有線の／Equivalent＝同じくらいの／Privacy＝秘密を守ること

#### WPA（だぶりゅぴーえー / Wi-Fi Protected Access）

- 意味：WEPの弱さを直すために Wi-Fi Alliance が作った方式。暗号化に TKIP（鍵を通信ごとに変える）を使う
- ポイント：WEPと同じ機械で動くようにした「つなぎ」の方式で、今は使わない。WPA2 が AES、WPA が TKIP と覚える
- 例：AireOS のWLC の画面では「WPA+WPA2」の中に WPA Policy と WPA2 Policy のチェックがある
- 語の意味：Wi-Fi＝無線LANの登録名／Protected＝守られた／Access＝接続

#### WPA2（だぶりゅぴーえーつー / Wi-Fi Protected Access 2）

- 意味：IEEE 802.11i を元にした方式。暗号化に AES-CCMP を使う。認証は PSK（パーソナル）か 802.1X（エンタープライズ）
- ポイント：暗号化は AES で、TKIP は使わない（Cisco の画面でも WPA2 は AES を選ぶ）。Catalyst 9800 で WLAN を作ったときの既定は WPA2・AES・802.1X
- 例：`security wpa wpa2 ciphers aes`（9800 のWLANの設定）
- 語の意味：AES＝Advanced Encryption Standard（今の標準の暗号）／CCMP＝Counter Mode with CBC-MAC Protocol（AESで暗号化と改ざん検知をする方式）

#### WPA3（だぶりゅぴーえーすりー / Wi-Fi Protected Access 3）

- 意味：WPA2の次の方式。パーソナルでは PSK のかわりに SAE を使い、管理フレームの保護（PMF）を必ず使う
- ポイント：パスワードを当てずっぽうで試す攻撃（オフラインの辞書攻撃）に強い。1つの鍵が破られてもほかの通信の鍵は安全（前方秘匿性）。WPA2 と WPA3 を同時に出す「移行モード」もある
- 例：WPA3-Personal＝SAE／WPA3-Enterprise＝802.1X

#### TKIP（てぃーきっぷ / Temporal Key Integrity Protocol）

- 意味：WPAで使う暗号化の方式。WEPと同じRC4を使いながら、パケットごとに鍵を変えて弱さを補った
- ポイント：今は弱いので使わない。PMF（802.11w）は TKIP のWLANでは使えない。「WPA2の暗号化は？」→ TKIPではなく AES
- 例：WPA1 の既定の暗号化は TKIP
- 語の意味：Temporal＝一時的な／Key＝鍵／Integrity＝完全さ（改ざんされていないこと）／Protocol＝決まりごと

### 認証

#### PSK（ぴーえすけー / Pre-Shared Key）

- 意味：APと端末に前もって同じパスフレーズを設定しておき、それで認証する方法。WPA2-Personal ともいう
- ポイント：パスフレーズは ASCII 8〜63文字か16進数64文字。全員が同じ鍵なので、1人が辞めたら全員の鍵を変える必要がある。RADIUSサーバーはいらない
- 例：AireOS の画面で Security > Layer 2 > Authentication Key Management の PSK にチェックし、PSK Format で ASCII を選んで入力
- 語の意味：Pre＝前もって／Shared＝共有した／Key＝鍵

#### 802.1X（はちまるにーてんいちえっくす / IEEE 802.1X）

- 意味：つなぐ前に1人ずつ認証するしくみ。端末（サプリカント）・AP や WLC（オーセンティケータ）・RADIUSサーバー（認証サーバー）の3者で、EAP という方式で認証する
- ポイント：WPA2-Enterprise・WPA3-Enterprise の認証。ユーザーごとに鍵が作られる。WLC は RADIUS のクライアントになる。PSK との違い（全員同じ鍵か、1人ずつか）が狙われる
- 例：WLC → RADIUS（Cisco ISE）にユーザー名とパスワードを確かめる
- 語の意味：EAP＝Extensible Authentication Protocol（いろいろな認証方法を運べる決まりごと）

#### SAE（えすえーいー / Simultaneous Authentication of Equals）

- 意味：WPA3-Personal で使う認証。パスワードそのものを流さず、お互いが同じパスワードを知っていることを確かめ合って、強い鍵を作る
- ポイント：盗み見たデータから家でパスワードを試し続ける攻撃（オフラインの辞書攻撃）に強い。WPA2 の PSK を置きかえるもの
- 例：9800 の WLAN で Security > Layer2 > WPA3 と SAE を選ぶ
- 語の意味：Simultaneous＝同時の／Authentication＝認証／Equals＝対等な者どうし

#### OWE（おーだぶりゅいー / Opportunistic Wireless Encryption）

- 意味：パスワードのないオープンなWLANでも、端末ごとに鍵を作って暗号化するしくみ。Wi-Fi Alliance の名前は Enhanced Open
- ポイント：認証はしない（だれでもつながる）が、通信は暗号化される。カフェや来客用のWLANに向く。SAE（パスワードあり）と区別する
- 例：来客用SSIDを「OWE」にして、盗み見を防ぐ
- 語の意味：Opportunistic＝できるときにする／Wireless＝無線の／Encryption＝暗号化

#### PMF（ぴーえむえふ / Protected Management Frames）

- 意味：切断（ディスアソシエーション）などの管理フレームにも暗号の保護をかけるしくみ。IEEE 802.11w
- ポイント：にせの切断フレームで端末を追い出す攻撃を防ぐ。WPA3 では必ず使う。オープン・WEP・TKIP のWLANでは使えない
- 例：AireOS の画面で Security > Layer 2 > PMF を Required にする
- 語の意味：Protected＝守られた／Management＝管理の／Frames＝フレーム

## 10-3 アーキテクチャとAPのモード

### まとめ表

**無線LANのアーキテクチャ**

| 方式 | 管理するもの | 端末のデータの流れ |
| :-: | :-: | :-: |
| 自律型（Autonomous） | AP 1台ずつ | APから直接有線へ |
| 集中型（Split MAC） | WLC（CAPWAPで管理） | CAPWAPでWLCまで運ぶ |
| FlexConnect | 本社のWLC（WAN越し） | WLANごとに、APから直接（ローカルスイッチング）かWLCへ |
| クラウド型（Meraki） | クラウドのダッシュボード | APから直接（クラウドを通らない） |
| 組み込み型（EWC／Mobility Express） | AP の中のコントローラ | APから直接 |

**APのモード**

| 分類 | モード | すること |
| :-: | :-: | :-: |
| 端末をつなぐ | ローカル（既定） | 全部のデータをCAPWAPでWLCへ運ぶ |
| 端末をつなぐ | FlexConnect | WLANごとに、APから直接出すか、WLCへ運ぶか選ぶ |
| 端末をつなぐ | ブリッジ・Flex+Bridge | メッシュ（無線でAPどうしをつなぐ） |
| 監視専用 | モニター | 端末はつながず、RRMと不正APを見張る |
| 監視専用 | スニファー | 1つのチャネルの全フレームを取り、解析用のPCへ送る |
| 監視専用 | ローグディテクター | 無線を止め、有線側の不正APを見つける（古い） |
| 監視専用 | SE-Connect | スペクトラム解析ソフトに電波の情報を渡す |

### アーキテクチャ

#### 自律型AP（じりつがたえーぴー / autonomous AP）

- 意味：1台ずつ自分で設定を持ち、自分で動くAP。WLCを使わず、AP 1台ずつにログインして設定する
- ポイント：台数が増えると、設定・チャネル・出力の調整を1台ずつやる必要があり大変。端末のデータはAPから直接有線（アクセスまたはトランクのポート）へ出る。軽量AP（lightweight AP）と対になる用語
- 例：小さな事務所で、AP 2台をそれぞれ設定する

#### 軽量AP（けいりょうえーぴー / lightweight AP）

- 意味：自分では設定を持たず、WLC に参加して、設定・ソフトウェア・電波の調整をWLCから受け取るAP。CAPWAP AP とも呼ぶ
- ポイント：WLCを見つけて参加しないと端末をつながない（ローカルモードの場合）。参加の流れ：IPアドレスをもらう → WLCを探す（ディスカバリ） → 参加（ジョイン） → 設定とソフトを受け取る
- 例：AP を電源つきのスイッチにつなぐと、DHCPのオプション43でWLCのアドレスを知って参加する

#### WLC（だぶりゅえるしー / Wireless LAN Controller）

- 意味：たくさんの軽量APをまとめて管理する機器。WLANの設定・認証・ローミング・電波の自動調整（RRM）をまとめて行う
- ポイント：機械（Catalyst 9800-40 など）・仮想マシン（9800-CL）・クラウド・スイッチやAPの中に組み込む形がある。古い機種は AireOS、新しい機種は IOS XE で動く
- 例：Catalyst 9800 のWLCで、100台のAPに同じSSIDを配る
- 語の意味：Wireless＝無線の／LAN＝構内のネットワーク／Controller＝制御する機器

#### スプリットMAC（すぷりっとまっく / split MAC）

- 意味：無線LANの MAC 層の仕事を、AP と WLC で分け合うしくみ。CAPWAP の考え方の中心
- ポイント：時間にきびしい仕事は AP（ビーコンを出す、プローブに応える、フレームの暗号化と復号、電波の監視）。時間にゆるい仕事は WLC（802.11 の認証とアソシエーション、ローミング、802.1X／RADIUS の処理、有線へのブリッジ）。「暗号化はAP」「認証はWLC」がよく狙われる
- 例：端末の認証はWLC が RADIUS に問い合わせ、データの暗号化はAP がする

#### CAPWAP（きゃっぷわっぷ / Control and Provisioning of Wireless Access Points）

- 意味：軽量AP と WLC の間で使う、IETF 標準のトンネルのプロトコル（RFC 5415）。Cisco の LWAPP が元になっている
- ポイント：UDP 5246 が制御（コントロール）、UDP 5247 がデータ。制御は DTLS で必ず暗号化し、データの暗号化は選べる（既定はしない）。APとWLCの間にファイアウォールがあればこの2つのポートを通す。レイヤ3の上で動くので、AP と WLC は別のサブネットでもよい
- 例：AP 10.1.10.20 → WLC 10.1.99.5 の UDP 5246／5247
- 語の意味：Control＝制御／Provisioning＝設定を配ること／Wireless Access Points＝無線のAP

#### FlexConnect（ふれっくすこねくと / FlexConnect）

- 意味：支店のAP を、本社の WLC から WAN越しに管理するしくみ。WLANごとに、端末のデータを WLC に送る（セントラルスイッチング）か、APのLANポートからそのまま出す（ローカルスイッチング）かを選べる
- ポイント：WLCとの接続が切れるとスタンドアロンモードになり、ローカルスイッチングのWLANは使い続けられる（セントラルスイッチングのWLANは止まる）。支店ごとにWLCを置かなくてよい
- 例：支店のPCのデータは支店のスイッチから直接出し、管理（CAPWAPの制御）だけ本社へ送る

#### クラウド型の管理（くらうどがたのかんり / cloud-based management, Meraki）

- 意味：Cisco Meraki のように、APの設定・監視をインターネットの向こうのクラウド（ダッシュボード）で行う方式
- ポイント：クラウドに流れるのは管理のデータ（設定・統計）だけで、端末のデータはクラウドを通らず直接LANやWANへ流れる（アウトオブバンドの管理）。クラウドとの接続が切れても、APは最後の設定で動き続ける
- 例：ブラウザでダッシュボードを開き、全国の店のAPにSSIDを配る

#### 組み込み型コントローラ（くみこみがたこんとろーら / Embedded Wireless Controller, Mobility Express）

- 意味：1台のAPの中でコントローラの機能を動かし、ほかのAPを管理する方式。古い形を Mobility Express、9800 の仕組みのものを EWC と呼ぶ
- ポイント：WLCの機械を買わずに小さな拠点でまとめて管理できる。端末のデータは各APから直接出る
- 例：AP 10台の小さな事務所で、1台のAPがコントローラを兼ねる

### WLCの見つけ方

#### DHCPオプション43（でぃーえいちしーぴーおぷしょんよんじゅうさん / DHCP option 43）

- 意味：DHCPサーバーがAPにIPアドレスを配るときに、WLCのIPアドレスもいっしょに教えるための追加の情報
- ポイント：APとWLCが別のサブネットにあるときによく使う。最大3つのWLCを入れられる。IPv6 では DHCPv6 のオプション52
- 例：`option 43 hex f104.0a01.6305`（f1＝種類、04＝長さ、0a016305＝10.1.99.5）

#### DNSによるWLCの発見（でぃーえぬえすによる はっけん / DNS discovery）

- 意味：APが DNS で「CISCO-CAPWAP-CONTROLLER.（ドメイン名）」を引いて、WLCのIPアドレスを知る方法
- ポイント：DHCPでドメイン名とDNSサーバーを受け取っていることが前提。ほかに、前に参加したWLCのアドレスを覚えておく方法（プライミング）や、同じサブネットへのブロードキャストもある
- 例：DNS に CISCO-CAPWAP-CONTROLLER.example.local → 10.1.99.5 を登録

### APのモード

#### ローカルモード（ろーかるもーど / Local mode）

- 意味：軽量APの既定のモード。すべてのWLANの端末のデータを、CAPWAPでWLCまで運ぶ
- ポイント：WLCにつながっているときだけ電波を出す。端末のデータはWLCから有線へ出るので、APのスイッチポートはアクセスポートでよい。端末にサービスしながら、空き時間にほかのチャネルも見回る
- 例：本社のAPはローカルモードで、WLCは同じ建物のデータセンターにある

#### FlexConnectモード（ふれっくすこねくともーど / FlexConnect mode）

- 意味：APのモードの1つ。WLANごとに、データをWLCへ運ぶか、APから直接出すかを選べる
- ポイント：ローカルスイッチングでVLANを分けるときは、APのスイッチポートをトランクにする。ローカルモードとの違い（全部WLCへ運ぶか、選べるか）が狙われる
- 例：支店のAP をFlexConnectにし、社員用SSIDをVLAN 20、来客用をVLAN 30 に出す

#### モニターモード（もにたーもーど / Monitor mode）

- 意味：端末をつながず、電波の監視だけをするモード。RRM のための測定と、不正なAP（ローグ）や攻撃の検知に使う
- ポイント：端末にサービスしない「監視専用」のモード。すべてのAPの機種が対応している
- 例：電波の様子を常に見るために、10台に1台をモニターモードにする

#### スニファーモード（すにふぁーもーど / Sniffer mode）

- 意味：決めた1つのチャネルの無線のフレームを全部取り込み、CAPWAP で送って、Wireshark などが動くPCに届けるモード
- ポイント：トラブルの調べもの用。モニターモード（自動で監視・検知）との違いは「パケットを取って解析用のPCへ送る」こと
- 例：ch36 のフレームを取り、解析用のPC（10.1.50.9）へ送る

#### ローグディテクターモード（ろーぐでぃてくたーもーど / Rogue Detector mode）

- 意味：無線を止めて、有線のLAN側を見張り、社内の有線につながった不正なAPを見つけるモード
- ポイント：新しいAP（Wave 2・802.11ax）では使えず、なくなる方向。モニターモード（無線の電波を見張る）と区別する
- 例：古いAPをトランクにつなぎ、有線側の不正APを探す

#### SE-Connectモード（えすいーこねくともーど / SE-Connect mode）

- 意味：APを電波の分析器として使い、スペクトラム解析ソフト（Spectrum Expert など）に電波の情報を渡すモード
- ポイント：Wi-Fi 以外の電波（電子レンジ・Bluetooth など）も含めて見るためのもの。CleanAir 対応の機種だけ
- 例：電子レンジの干渉を調べるとき、PCのソフトからAPにつなぐ

#### ブリッジモード（ぶりっじもーど / Bridge mode, mesh）

- 意味：APどうしを無線でつなぐメッシュのためのモード。有線につながったAP（ルートAP）から、無線でほかのAP（メッシュAP）へつなぐ
- ポイント：ケーブルを引けない屋外や倉庫で使う。CAPWAP の通り道（バックホール）が有線ではなく無線になる。Flex+Bridge は FlexConnect とメッシュを合わせたもの
- 例：駐車場の街灯にAPを付け、建物のAPと無線でつなぐ

## 10-4 APとWLCのつなぎ方

### まとめ表

**スイッチのポートの設定**

| つなぐもの | スイッチのポート | 理由 |
| :-: | :-: | :-: |
| ローカルモードのAP | アクセスポート（APの管理VLAN） | 端末のデータはCAPWAPの中なので、VLANは1つでよい |
| FlexConnectのAP | トランク（ネイティブVLAN＝APの管理VLAN） | ローカルスイッチングでWLANごとに別のVLANへ出す |
| WLC（ディストリビューションシステムポート） | トランク | WLANごとのVLAN（ダイナミックインタフェース）と管理VLANを運ぶ。アクセスモードは非対応 |
| WLCのサービスポート | アクセスポート | 802.1Qのタグを扱えない、管理専用のポート |

**WLCのLAG**

| | AireOS のWLC | Catalyst 9800 |
| :-: | :-: | :-: |
| 束ね方 | mode on だけ（LACP・PAgPなし） | on・LACP・PAgP |
| グループの数 | 1つだけ（全ポートが入る） | 複数のポートチャネル |
| 変えたあと | 再起動が必要 | ― |

### スイッチとのつなぎ方

#### アクセスポートにつなぐAP（あくせすぽーとにつなぐえーぴー / AP on an access port）

- 意味：ローカルモードのAPは、APの管理用のVLANだけを持つアクセスポートにつなぐ
- ポイント：端末のデータは全部 CAPWAP のトンネルの中でWLCへ運ばれるので、スイッチは端末のVLANを知らなくてよい。APの起動を早めるため PortFast も設定することが多い
- 例：

```
interface GigabitEthernet1/0/1
 switchport mode access
 switchport access vlan 100
 spanning-tree portfast
```

#### トランクにつなぐAP（とらんくにつなぐえーぴー / AP on a trunk port）

- 意味：FlexConnect のAP（や自律型AP）は、APの管理VLANをネイティブVLANにしたトランクにつなぐ
- ポイント：ローカルスイッチングのWLANの端末を、WLANごとに別のVLANへ出すため。APの管理（CAPWAP）はタグなしのネイティブVLANで流れる
- 例：

```
interface GigabitEthernet1/0/37
 switchport mode trunk
 switchport trunk native vlan 10
 switchport trunk allowed vlan 10,20,30
```

#### ディストリビューションシステムポート（でぃすとりびゅーしょんしすてむぽーと / distribution system port）

- 意味：WLCをスイッチにつなぐ、データ用の物理ポート。端末のデータとAPの管理の通信が通る
- ポイント：スイッチ側はトランクにする（Cisco はアクセスモードをサポートしていない）。WLANごとのVLANをタグつきで運ぶ
- 例：WLCのポート1・2 → スイッチの Gi1/0/47・48（トランク）

#### サービスポート（さーびすぽーと / service port）

- 意味：WLCを管理するためだけの物理ポート（アウトオブバンドの管理）。WLCが起動途中でも使える
- ポイント：802.1Q のタグを扱えないので、スイッチのアクセスポートにつなぐ。APの管理の通信は通らない。端末と同じサブネットにしてはいけない
- 例：サービスポートを管理専用のVLAN 999 のアクセスポートにつなぐ

### LAG

#### LAG（らぐ / Link Aggregation Group）

- 意味：WLCのディストリビューションシステムポートを全部まとめて、1本の論理ポート（ポートチャネル）にすること
- ポイント：AireOS のWLCでは、スイッチ側を `channel-group … mode on` にする。WLCは LACP も PAgP も話さないので、スイッチを active や desirable にするとLAGができない。LAGのグループは1つだけ。有効にしたり変えたりしたら、すぐにWLCを再起動する。1本が切れても残りで動き続ける。Catalyst 9800 は LACP・PAgP にも対応
- 例：

```
interface range GigabitEthernet1/0/47 - 48
 switchport mode trunk
 channel-group 1 mode on
```
- 語の意味：Link＝リンク／Aggregation＝集めること／Group＝グループ

### WLCのインタフェース（AireOS）

#### 管理インタフェース（かんりいんたふぇーす / management interface）

- 意味：WLCのいちばん大事な論理インタフェース。GUIへのアクセス（ブラウザでこのIPを開く）、RADIUSなどとの通信、APとのCAPWAPに使う
- ポイント：最初の設定（スタートアップウィザード）で必ず作る。来客用のWLANを管理インタフェースに割り当ててはいけない
- 例：management 10.1.99.5／VLAN 99

#### ダイナミックインタフェース（だいなみっくいんたふぇーす / dynamic interface）

- 意味：管理者が作る論理インタフェースで、WLANをVLANとサブネットに結びつける。スイッチのSVIに近い（ただしWLCはルーティングしない）
- ポイント：「WLANごとに端末を別のVLANに入れる」ための入れ物。WLANの General タブの Interface でえらぶ。最大512個
- 例：WLAN「CORP」→ ダイナミックインタフェース corp（VLAN 20、10.1.20.0/24）

#### 仮想インタフェース（かそういんたふぇーす / virtual interface）

- 意味：DHCPリレー・Web認証のログインページ・モビリティ管理に使う、WLCの中だけの論理インタフェース
- ポイント：ネットワークで実際に届く必要のないアドレス（192.0.2.1 など）を使う。全WLCで同じ値にする
- 例：virtual 192.0.2.1

## 10-5 WLCのGUI設定

### まとめ表

**AireOS のWLANの作り方（WLANs > Edit のタブ）**

| タブ | 主な項目 |
| :-: | :-: |
| General | Status（有効にする）・SSID・Radio Policy・Interface（VLAN）・Broadcast SSID |
| Security | Layer 2（WPA+WPA2・PSK／802.1X・PMF）・Layer 3（Web認証）・AAA Servers |
| QoS | Platinum／Gold／Silver（既定）／Bronze |
| Advanced | Allow AAA Override・Session Timeout・Client Exclusion・Coverage Hole Detection・P2P Blocking・FlexConnect Local Switching・最大の端末数 |

**QoSのプロファイル（貴金属のポリシー）**

| プロファイル | 用途 | 優先度 |
| :-: | :-: | :-: |
| Platinum | 音声（VoIP） | いちばん高い |
| Gold | ビデオ | 高い |
| Silver | ふつうのデータ（ベストエフォート） | ふつう（既定） |
| Bronze | 来客・バックグラウンド | いちばん低い |

### WLANを作る

#### WLAN（だぶりゅらん / Wireless LAN）

- 意味：WLCの中で作る「1つの無線ネットワークの設定」。WLAN ID・プロファイル名・SSID・セキュリティ・QoS・VLAN をまとめて持つ
- ポイント：作っただけでは無効（Status のチェックを入れて有効にする）。1台のAPが出せるWLANは16個まで。同じSSIDのWLANを複数作るときは、レイヤ2のセキュリティを変える
- 例：AireOS：WLANs > Create New > Go → Type＝WLAN、Profile Name、SSID、ID を入れて Apply
- 語の意味：Wireless＝無線の／LAN＝Local Area Network

#### プロファイル名（ぷろふぁいるめい / profile name）

- 意味：WLCの中でWLANを見分けるための名前。SSID（端末に見える名前）とは別に付ける
- ポイント：プロファイル名はWLCの中で重ならないようにする。SSIDは同じでもよい。最大32文字
- 例：Profile Name「corp-5g」、SSID「CORP」

#### Broadcast SSID（ぶろーどきゃすとえすえすあいでぃー / Broadcast SSID）

- 意味：ビーコンにSSIDを入れて知らせるかどうかの設定。General タブにある
- ポイント：オフにするとSSIDが一覧に出なくなるが、端末がつなぎに来るときのフレームでSSIDは見えるので、セキュリティ対策にはならない
- 例：General タブ → Broadcast SSID のチェックを外す

#### Radio Policy（れでぃおぽりしー / Radio Policy）

- 意味：WLANを出す無線の帯（2.4GHz・5GHz・6GHz）を選ぶ設定
- ポイント：5GHzだけで出すと、2.4GHz の混雑や干渉を避けられる。9800 では WLAN の General タブにある
- 例：Radio Policy＝802.11a only（5GHzだけ）

### セキュリティの設定

#### Layer 2 Security（れいやつーせきゅりてぃ / Layer 2 Security）

- 意味：WLAN の Security タブの中の、無線のつなぎ方そのものの保護の設定。None（オープン）・WPA+WPA2・WPA2+WPA3 などから選び、認証キーの管理（AKM）で PSK か 802.1X を選ぶ
- ポイント：PSK を選んだときは PSK Format（ASCII か Hex）と鍵を入れる。802.1X を選んだときは AAA Servers タブで RADIUS サーバーを選ぶ
- 例：Layer 2 Security＝WPA+WPA2 → WPA2 Policy、AES、Authentication Key Management＝PSK

#### Layer 3 Security（れいやすりーせきゅりてぃ / Layer 3 Security, Web Authentication）

- 意味：つないだあとで、ブラウザのログインページ（Web認証）を出して認証する設定
- ポイント：来客用によく使う。レイヤ2の暗号化とは別のもので、Web認証だけでは無線の通信は暗号化されない
- 例：来客用WLAN：Layer 2＝None、Layer 3＝Web Policy（Authentication）

#### AAA Override（とりぷるえーおーばーらいど / Allow AAA Override）

- 意味：RADIUS サーバーから返ってきた情報（VLAN・QoS・ACL など）で、WLAN の設定を上書きできるようにする設定（Advanced タブ）
- ポイント：同じSSIDでも、ユーザーごとに別のVLANに入れられる。802.1X で使う
- 例：社員はVLAN 20、管理者はVLAN 25 に、RADIUSが振り分ける

#### セッションタイムアウト（せっしょんたいむあうと / Session Timeout）

- 意味：端末に再認証をさせるまでの時間（Advanced タブ）
- ポイント：AireOS の既定は、802.1X のWLANで1800秒（30分）。そのほかのレイヤ2セキュリティでは0（タイムアウトしない）
- 例：Enable Session Timeout にチェック → 1800

### QoSとその他

#### QoSプロファイル（きゅーおーえすぷろふぁいる / QoS profile）

- 意味：WLANごとに選ぶ優先度。Platinum（音声）・Gold（ビデオ）・Silver（ベストエフォート、既定）・Bronze（バックグラウンド）の4つ
- ポイント：WLAN の QoS は、そのWLANの通信の優先度の上限になる。音声の端末のWLANは Platinum にする。来客用は Bronze にすることが多い。9800 では「貴金属（precious metal）のポリシー」と呼び、ポリシープロファイルの QoS で選ぶ
- 例：WLANs > Edit > QoS タブ → Quality of Service＝Platinum (voice)

#### P2Pブロッキング（ぴーつーぴーぶろっきんぐ / Peer-to-Peer Blocking）

- 意味：同じWLANにつながった端末どうしの直接の通信を止める設定（Advanced タブ）
- ポイント：来客用のWLANで、ほかのお客さんのPCに入られないようにする。マルチキャストには効かない
- 例：P2P Blocking Action＝Drop

#### クライアントの除外（くらいあんとのじょがい / Client Exclusion）

- 意味：認証に何度も失敗した端末などを、決めた時間だけつながらないようにする設定（Advanced タブ）
- ポイント：パスワードの総当たりを遅らせる。除外の時間を過ぎると、またつなげる
- 例：Enable Client Exclusion にチェック → Timeout Value 60秒

### Catalyst 9800 の設定のしくみ

#### ポリシープロファイル（ぽりしーぷろふぁいる / policy profile）

- 意味：Catalyst 9800 で、WLAN の端末にかけるルール（VLAN・QoS・ACL・セントラルかローカルか）をまとめたもの
- ポイント：9800 では「WLAN プロファイル（SSIDとセキュリティ）」と「ポリシープロファイル（VLANやQoS）」を分けて作る。AireOS では1つのWLANの画面に全部あった
- 例：Configuration > Tags & Profiles > Policy → VLAN 20、QoS＝Platinum

#### ポリシータグ（ぽりしーたぐ / policy tag）

- 意味：Catalyst 9800 で、WLAN プロファイルとポリシープロファイルを結びつけるもの。APにタグを付けると、そのAPからWLANが出る
- ポイント：タグは3種類：ポリシータグ（WLAN＋ポリシー）、サイトタグ（APの参加の設定＋FlexConnect の設定）、RFタグ（電波の設定）。APには3つのタグを1つずつ付ける
- 例：ポリシータグ「PT-HQ」：WLAN「CORP」→ ポリシー「corp-policy」

#### RRM（あーるあーるえむ / Radio Resource Management）

- 意味：WLC がAPから電波の情報を集めて、チャネル（DCA）と送信の強さ（TPC）を自動で決め、つながりにくい場所（カバレッジホール）を見つけるしくみ
- ポイント：DCA は重ならないチャネルだけを使い、離れたAPには同じチャネルを再利用する。自律型APではこれを1台ずつ手でやる必要がある
- 例：となりのAPと同じチャネルになったら、DCAが自動でチャネルを変える
- 語の意味：Radio＝電波／Resource＝資源／Management＝管理。DCA＝Dynamic Channel Assignment、TPC＝Transmit Power Control
