## 8-1 CDPとLLDP

### まとめ表

**CDPとLLDP（Catalyst 9300 の既定値）**

| | CDP | LLDP |
| :-: | :-: | :-: |
| 作ったところ | Cisco独自 | IEEE 802.1AB（標準） |
| 初期状態 | 有効（全体・全ポート） | 無効（`lldp run` が必要） |
| 送る間隔 | 60秒（`cdp timer`） | 30秒（`lldp timer`） |
| ホールドタイム | 180秒（`cdp holdtime`） | 120秒（`lldp holdtime`） |
| 全体で止める | `no cdp run` | `no lldp run` |
| ポートで止める | `no cdp enable` | `no lldp transmit`・`no lldp receive`（送信と受信が別） |
| 隣を見る | `show cdp neighbors [detail]` | `show lldp neighbors [detail]` |

**show cdp neighbors の列（左から）**

| 列 | 中身 | 誰の情報か |
| :-: | :-: | :-: |
| Device ID | 隣の機器のホスト名 | 隣 |
| Local Intrfce | 隣がつながっている自分のポート | 自分 |
| Holdtme | あと何秒この情報を持つか | （残り時間） |
| Capability | 機器の種類（R＝ルータ、S＝スイッチなど） | 隣 |
| Platform | 隣の機種 | 隣 |
| Port ID | 隣の側のポート | 隣 |

### 隣の機器を知るしくみ

#### CDP（しーでぃーぴー / Cisco Discovery Protocol）

- 意味：Cisco機器どうしが、直接つながった隣の機器の名前・機種・ポート・IPアドレスなどを知らせ合うレイヤ2のプロトコル。Cisco独自
- ポイント：データリンク層で動くので、IPアドレスを設定していなくても、別のネットワーク層プロトコルを使っていても隣がわかる。宛先はマルチキャスト（01-00-0C-CC-CC-CC）、SNAPのタイプは0x2000。Catalystでは最初から有効
- 例：`show cdp neighbors` で隣の一覧を見る
- 語の意味：Cisco＝シスコ社の／Discovery＝発見／Protocol＝通信の決まりごと

#### LLDP（えるえるでぃーぴー / Link Layer Discovery Protocol）

- 意味：IEEE 802.1AB で決められた、隣の機器を知るための標準のレイヤ2プロトコル。他社の機器ともやり取りできる
- ポイント：CDPと同じ目的だが標準規格。Catalyst 9300 では初期状態で無効で、`lldp run` で有効にする。Cisco以外のIP電話やスイッチとつなぐときに使う
- 例：`lldp run` → `show lldp neighbors`
- 語の意味：Link＝リンク（隣とのつながり）／Layer＝層／Discovery＝発見／Protocol＝決まりごと

#### TLV（てぃーえるぶい / Type-Length-Value）

- 意味：「種類・長さ・値」の3つの組で情報を運ぶ書式。CDPやLLDPは、機器名・ポート名・機能・管理アドレスなどをTLVで並べて送る
- ポイント：LLDPの必須のTLVは、ポートの説明・システム名・システムの説明・システムの機能・管理アドレスなど。CDPv2で、ネイティブVLAN・デュプレックス・VTPドメイン名・音声VLANなどのTLVが加わった
- 例：`lldp tlv-select` で送るTLVを選ぶ
- 語の意味：Type＝種類／Length＝長さ／Value＝値

#### CDPv2（しーでぃーぴーばーじょんつー / CDP version 2）

- 意味：CDPの2番目の版。ネイティブVLAN・デュプレックス・VTPドメイン名・音声VLANなどを知らせるTLVが増えた。Catalystは初期状態でv2を送る
- ポイント：隣とネイティブVLANやデュプレックスが食い違うと、CDPv2の情報からログで知らせてくれる。v1しか話さない相手からv1のフレームが来ると、そのポートではv1も送る
- 例：`cdp advertise-v2`（初期状態で有効）

#### LLDP-MED（えるえるでぃーぴーめど / LLDP for Media Endpoint Devices）

- 意味：IP電話などの端末とネットワーク機器の間で使う、LLDPの拡張。使うVLAN・PoEの電力・機器の在庫情報・位置情報などを知らせ合う
- ポイント：ネットワークポリシーTLVで、スイッチが電話に「音声はこのVLAN・このCoSで送って」と伝えられる。Cisco以外のIP電話で音声VLANを使うときの仕組み
- 例：`lldp med-tlv-select network-policy`
- 語の意味：Media＝通話などのメディア／Endpoint＝端末／Device＝機器

### タイマーと設定

#### CDPタイマー（しーでぃーぴーたいまー / CDP timer）

- 意味：CDPの通知を送る間隔。Catalystの初期値は60秒（5〜254秒で変えられる）
- ポイント：LLDPの送る間隔（lldp timer）の初期値は30秒。ホールドタイムと取り違えない
- 例：`cdp timer 20`

#### ホールドタイム（ほーるどたいむ / holdtime）

- 意味：受け取った隣の情報を、新しい通知が来なくても持っておく時間。過ぎると隣の一覧から消える。CDPは180秒、LLDPは120秒が初期値
- ポイント：show cdp neighbors の Holdtme は「あと何秒持つか」の残り時間で、通知を受けるたびに180から数え直す。隣のケーブルを抜いても、最大でホールドタイムの間は一覧に残る
- 例：`cdp holdtime 60`／`lldp holdtime 120`

#### cdp run と cdp enable（しーでぃーぴーらん・いねーぶる / cdp run・cdp enable）

- 意味：`cdp run` は機器全体でCDPを動かすグローバル設定、`cdp enable` はポートごとにCDPを動かすインタフェースの設定。どちらも初期状態で有効
- ポイント：全体を止めるのが `no cdp run`、1つのポートだけ止めるのが `no cdp enable`。「インタフェースで no cdp run」「グローバルで no cdp enable」は書けない組み合わせ
- 例：インターネット側のポートで `no cdp enable`

#### lldp transmit と lldp receive（えるえるでぃーぴーとらんすみっと・れしーぶ / lldp transmit・lldp receive）

- 意味：ポートごとに、LLDPを送るか（transmit）・受け取るか（receive）を決めるインタフェースの設定。全体を動かすのは `lldp run`
- ポイント：CDPはポートで送受信をまとめて止めるが、LLDPは送信と受信を別々に止められる。片方だけ止めると「相手からは見えるが自分は相手を知らない」状態になる
- 例：`no lldp transmit` だけを入れたポートは、隣の情報を受け取るが自分の情報は送らない

#### CDPとLLDPのセキュリティ（せきゅりてぃ / CDP and LLDP security）

- 意味：CDPとLLDPは機器名・機種・ソフトウェアのバージョン・IPアドレスを暗号化せずに送るので、攻撃者がネットワークの下調べに使えてしまう
- ポイント：Ciscoの機器の堅牢化ガイドは「信頼できないネットワークにつながるポートでは止める」としている。社内のスイッチどうしでは障害の切り分けに役立つので有効のままにすることが多い
- 例：外向きのポートで `no cdp enable`・`no lldp transmit`・`no lldp receive`

### 出力の読み方

#### show cdp neighbors（しょーしーでぃーぴーねいばーず / show cdp neighbors）

- 意味：CDPで見つけた隣の機器の一覧を、1台1行で表示するコマンド。Device ID・Local Intrfce・Holdtme・Capability・Platform・Port ID の列が並ぶ
- ポイント：IPアドレスは出ない。IPアドレス・ソフトウェアのバージョン・ネイティブVLAN・デュプレックスまで見るなら detail を付ける
- 例：`show cdp neighbors g1/0/24` のようにポートで絞れる

#### show cdp neighbors detail（でぃてーる / show cdp neighbors detail）

- 意味：隣の機器ごとに、IPアドレス（Entry address）・機種・機能・両側のポート・ホールドタイム・IOSのバージョン・CDPの版・デュプレックス・ネイティブVLAN・VTPドメイン名をくわしく出すコマンド
- ポイント：`show cdp entry *` でも同じくらいの情報が出る。隣の管理用IPアドレスを知って、そこにSSHで入りに行く、という使い方が多い
- 例：Entry address(es): IP address: 10.1.1.2

#### Local Intrfce と Port ID（ろーかるいんたーふぇーす・ぽーとあいでぃー / Local Interface・Port ID）

- 意味：Local Intrfce は「隣がつながっている自分のポート」、Port ID は「隣の機器の側のポート」
- ポイント：本番でいちばん狙われる取り違え。SW1で `Gig 1/0/24 ... Gig 1/0/1` と出たら、SW1のg1/0/24と隣のg1/0/1がつながっている
- 例：LLDPでは列名が Local Intf と Port ID

#### Capability（けいぱびりてぃ / capability code）

- 意味：隣の機器がどんな機能を持つかを示す記号。CDPでは R＝ルータ、T＝トランスペアレントブリッジ、B＝ソースルートブリッジ、S＝スイッチ、H＝ホスト、I＝IGMP、r＝リピータ
- ポイント：レイヤ3スイッチは R と S の両方が出る（R S I など）。LLDPの記号は別で、R＝ルータ、B＝ブリッジ、T＝電話、W＝無線のアクセスポイント、S＝ステーションなど。LLDPの B はスイッチ（ブリッジ）、T は電話
- 例：`R S I` ＝ルーティングもスイッチングもする機器

#### Device ID（でばいすあいでぃー / Device ID）

- 意味：隣の機器を見分ける名前。CDPではホスト名（またはシリアル番号・MACアドレス）、LLDPではシステム名が出る
- ポイント：ドメイン名を設定していると `SW2.example.com` のように付く。LLDPの show lldp neighbors では20文字で切られるので、全部見るなら detail
- 例：`hostname SW2` で隣のDevice IDが変わる

## 8-2 EtherChannelとLACP・PAgP

### まとめ表

**チャネルを作るモードの組み合わせ（○＝束ねられる）**

| 自分＼相手 | active | passive | desirable | auto | on |
| :-: | :-: | :-: | :-: | :-: | :-: |
| active（LACP） | ○ | ○ | × | × | × |
| passive（LACP） | ○ | × | × | × | × |
| desirable（PAgP） | × | × | ○ | ○ | × |
| auto（PAgP） | × | × | ○ | × | × |
| on（交渉なし） | × | × | × | × | ○ |

**LACPとPAgP**

| | LACP | PAgP |
| :-: | :-: | :-: |
| 規格 | IEEE 802.3ad（標準） | Cisco独自 |
| 自分から持ちかける | active | desirable |
| 待つだけ | passive | auto |
| 束ねられる本数 | 16本まで設定・8本が動き、8本は待機 | 8本まで |
| 宛先MAC | 01-80-C2-00-00-02 | 01-00-0C-CC-CC-CC（CDPと同じ） |

### 束ねるしくみ

#### EtherChannel（いーさちゃねる / EtherChannel）

- 意味：複数の物理的なイーサネットのリンクを、1本の論理的なリンクに束ねる技術。帯域が足し算になり、1本切れても残りのリンクで通信を続けられる
- ポイント：STPは束ね全体を1つのポートとして扱うので、ブロックされるリンクが出ない（束ねないと、同じスイッチ間の2本目はSTPでブロックされる）。1つのEtherChannelで動くのは最大8本
- 例：1Gbpsを4本束ねる → 論理的に4Gbpsのリンク1本

#### ポートチャネル（ぽーとちゃねる / port-channel interface）

- 意味：EtherChannelを表す論理インタフェース。`interface port-channel 1` のように番号（1〜128）で呼ぶ
- ポイント：ポートチャネルに入れた設定は、束ねた物理ポート全部に反映される。トランクや許可VLANは、物理ポートではなくポートチャネルで設定するのが基本。show では Po1 と書かれる
- 例：`interface port-channel 1` → `switchport mode trunk`

#### チャネルグループ（ちゃねるぐるーぷ / channel group）

- 意味：どの物理ポートをどのポートチャネルに束ねるかを決めるまとまり。物理ポートで `channel-group 番号 mode モード` と書く
- ポイント：レイヤ2では、channel-group を入れるとその番号のポートチャネルが自動で作られる。チャネルグループの番号とポートチャネルの番号は同じになる。1つのポートは1つのグループにしか入れない
- 例：`interface range g1/0/1 - 2` → `channel-group 1 mode active`

#### LACP（えるえーしーぴー / Link Aggregation Control Protocol）

- 意味：EtherChannelを自動で作るための標準のプロトコル（IEEE 802.3ad）。両側のポートの設定がそろっているかを確かめてから束ねる
- ポイント：他社の機器（サーバのNICのチーミングなど）とも束ねられる。全二重のポートでしか動かない。16本まで入れて8本を使い、残り8本を待機（ホットスタンバイ）にできる
- 例：`channel-group 1 mode active`
- 語の意味：Link＝リンク／Aggregation＝集約／Control＝制御／Protocol＝決まりごと

#### PAgP（ぱぐぴー / Port Aggregation Protocol）

- 意味：EtherChannelを自動で作るためのCisco独自のプロトコル。Cisco機器（とライセンスを受けた機器）の間でだけ使える
- ポイント：モードは desirable（持ちかける）と auto（待つだけ）。LACPと同じグループでは使えず、互いに話も通じない。CDPと同じマルチキャストアドレスを使う
- 例：`channel-group 2 mode desirable`
- 語の意味：Port＝ポート／Aggregation＝集約／Protocol＝決まりごと

#### active と passive（あくてぃぶ・ぱっしぶ / LACP active・passive mode）

- 意味：LACPのモード。active は自分からLACPのパケットを送って交渉を始める、passive は送られてきたら応じるだけ
- ポイント：active＋active と active＋passive は束ねられる。passive＋passive は誰も始めないので束ねられない。CiscoのBest Practicesは両側 active を勧める
- 例：`channel-group 1 mode passive`

#### desirable と auto（でぃざいあらぶる・おーと / PAgP desirable・auto mode）

- 意味：PAgPのモード。desirable は自分から交渉を始める、auto は持ちかけられたら応じるだけ
- ポイント：auto＋auto は束ねられない。DTPのモード（dynamic desirable・dynamic auto）と名前も考え方も似ているが、DTPはトランクの交渉、PAgPはEtherChannelの交渉
- 例：`channel-group 2 mode auto`

#### on モード（おんもーど / on mode）

- 意味：LACPもPAgPも使わず、交渉なしで強制的に束ねるモード
- ポイント：相手も on のときだけ使える。on は交渉のパケットを送らないので、相手が active や desirable でも束ねられない。片方だけ束ねた状態になると、ループやパケットの消失が起こりうる
- 例：`channel-group 3 mode on`

#### サイレントモード（さいれんともーど / PAgP silent mode）

- 意味：PAgPの auto・desirable で、相手からPAgPのパケットが来なくてもポートを使えるようにする動き。non-silent を付けなければサイレントになる
- ポイント：ファイルサーバやパケットアナライザのような、ほとんど何も送らない相手とつなぐときのための設定。相手がPAgPを話すスイッチなら `non-silent` を付ける
- 例：`channel-group 2 mode desirable non-silent`

### LACPのくわしい動き

#### ホットスタンバイ（ほっとすたんばい / hot-standby port）

- 意味：LACPのEtherChannelで、束ねられる上限（8本）を超えたポートや、max-bundle で外したポートが入る待機の状態。使っているリンクが切れると代わりに入る
- ポイント：show etherchannel summary では H の印が付く。PAgPには待機のポートの仕組みはない
- 例：10本を同じグループにすると、8本が P（束ね中）、2本が H（待機）

#### LACPシステムプライオリティ（しすてむぷらいおりてぃ / LACP system priority）

- 意味：LACPでどちらのスイッチが「どのポートを使うか」を決めるかを決める値。初期値32768で、小さいほうが優先。MACアドレスと合わせてシステムIDになる
- ポイント：数字が小さいほど優先されるのは、STPのブリッジプライオリティと同じ考え方。優先されたスイッチのポートプライオリティで、待機にするポートが決まる
- 例：`lacp system-priority 32000`（グローバル設定）

#### LACPポートプライオリティ（ぽーとぷらいおりてぃ / LACP port priority）

- 意味：LACPで、どのポートを束ねてどのポートを待機にするかを決める値。数字が小さいほど優先して束ねられる
- ポイント：8本を超えたとき、ポートプライオリティの数字が小さい8本が束ねられ、残りが待機になる。効くのはシステムプライオリティで優先された側のスイッチの値
- 例：`lacp port-priority 100`（インタフェース設定）

#### lacp rate fast（れいとふぁすと / LACP fast rate）

- 意味：LACPのパケットを受け取る間隔を、通常の30秒から1秒にする設定。タイムアウトはその3倍なので、相手の異常に90秒ではなく3秒で気づける
- ポイント：初期値は normal（束ねたあとは30秒ごと）。両側でそろえるのが基本
- 例：`lacp rate fast`

#### min-links と max-bundle（みんりんくす・まっくすばんどる / min-links・max-bundle）

- 意味：min-links は「最低これだけのポートが束ねられていないとポートチャネルを止める」本数、max-bundle は「束ねるポートの上限」の本数
- ポイント：min-links は帯域が足りないポートチャネルを使わせないための設定。max-bundle で上限を超えたポートは待機（ホットスタンバイ）になる。どちらもLACPの機能
- 例：`port-channel min-links 2`／`lacp max-bundle 3`

## 8-3 EtherChannelの設定と確認

### まとめ表

**束ねるためにそろえる設定（そろわないと suspended など）**

| そろえるもの | 例 |
| :-: | :-: |
| 速度とデュプレックス | 全部 1000Mbps・全二重 |
| モード | 全部アクセス（同じVLAN）か、全部トランク |
| ネイティブVLAN | 全部 99 |
| 許可VLANの範囲 | 全部 10,20,99 |
| レイヤ | 全部レイヤ2か、全部レイヤ3（no switchport） |

**show etherchannel summary の主な印**

| 印 | 意味 |
| :-: | :-: |
| P | 束ねられている（bundled in port-channel） |
| I | 束ねられず単独で動いている（stand-alone） |
| s | 一時停止（suspended）。設定の食い違いなど |
| H | 待機（Hot-standby、LACPだけ） |
| D | ダウン |
| S ／ R | レイヤ2 ／ レイヤ3 のポートチャネル |
| U | 使用中（in use） |

### 設定

#### レイヤ2 EtherChannel（れいやつー / Layer 2 EtherChannel）

- 意味：スイッチポートのまま束ねたEtherChannel。アクセスポートかトランクとして動く
- ポイント：束ねるポートは全部同じVLANのアクセスポートか、全部トランクにする。ネイティブVLANや許可VLANが違うポートは束ねられない
- 例：`interface range g1/0/1 - 2` → `channel-group 1 mode active` → `interface port-channel 1` → `switchport mode trunk`

#### レイヤ3 EtherChannel（れいやすりー / Layer 3 EtherChannel）

- 意味：ルーテッドポートとして束ねたEtherChannel。IPアドレスを持ち、ルーティングに使う
- ポイント：IPアドレスは物理ポートではなく、ポートチャネルのインタフェースに付ける。物理ポートとポートチャネルの両方で `no switchport` にする
- 例：`interface port-channel 10` → `no switchport` → `ip address 10.0.0.1 255.255.255.252`

#### 負荷分散（ふかぶんさん / EtherChannel load balancing）

- 意味：EtherChannelのどのリンクにフレームを送るかを、アドレスなどから計算（ハッシュ）して決める仕組み。Catalyst 9300 の初期値は送信元MAC（src-mac）
- ポイント：パケットごとに順番に振り分けるのではなく、同じアドレスの組み合わせは常に同じリンクを通る。そのため1台どうしの通信は1本分の速さしか出ない。設定は機器全体で1つ（グローバル）で、全部のEtherChannelに効く
- 例：`port-channel load-balance src-dst-ip`／確認は `show etherchannel load-balance`

#### 送信元と宛先の組み合わせ（そうしんもととあてさき / src-dst-ip・src-dst-mac）

- 意味：送信元と宛先のアドレスを両方使って振り分けるリンクを決める方式。A→B、A→C、C→B が別のリンクになりうる
- ポイント：宛先が1台（ルータなど）に集中するなら、宛先だけで決める方式（dst-mac）は全部同じリンクになる。どちらがよいかわからないときは送信元と宛先の両方を使うのが構成ガイドの考え方
- 例：`port-channel load-balance src-dst-mac`

### 確認と切り分け

#### show etherchannel summary（しょーいーさちゃねるさまりー / show etherchannel summary）

- 意味：EtherChannelごとに、ポートチャネルの状態・使っているプロトコル・束ねたポートと各ポートの印を1行で表示するコマンド
- ポイント：`Po1(SU) LACP Gi1/0/1(P) Gi1/0/2(P)` なら、レイヤ2で使用中、LACPで2本とも束ねられている。(SD) ならポートチャネルがダウン、ポートに (s) や (I) があれば束ねられていない
- 例：`show etherchannel summary`

#### suspended（さすぺんでっど / suspended port）

- 意味：EtherChannelに入れたが、設定の食い違い（速度・VLAN・モードなど）や相手からのLACPの応答がないことなどで、一時的に止められたポートの状態。印は s
- ポイント：on モードでも、速度やデュプレックスが合わないポートは suspended になる。設定をそろえれば束ねられる
- 例：Gi1/0/2(s)

#### stand-alone（すたんどあろーん / stand-alone port）

- 意味：EtherChannelには束ねられず、ふつうの1本のポートとして動いている状態。印は I
- ポイント：相手がEtherChannelを設定していないときなどに出る。束ねられていないので、STPで片方がブロックされることがある
- 例：Gi1/0/1(I)

#### 互換性の条件（ごかんせいのじょうけん / port compatibility）

- 意味：EtherChannelで束ねるために、ポートどうしでそろっていなければならない設定。速度・デュプレックス・アクセスかトランクか・アクセスVLAN・ネイティブVLAN・許可VLANの範囲など
- ポイント：STPのパスコストが違うだけなら束ねられる（構成ガイド）。設定を変えるときは、物理ポートを1つずつではなくポートチャネルで変えるとずれない
- 例：1本だけ `switchport trunk allowed vlan 10` だと、そのポートは束ねられない

#### EtherChannelとSTP（いーさちゃねるとすぱにんぐつりー / EtherChannel and STP）

- 意味：STPはEtherChannel全体を1つのポートとして扱う。束ねた中のリンクの1本が切れても、ポートチャネルが動いていればSTPのブロックと転送の状態は変わらない
- ポイント：EtherChannelがないと、同じ2台のスイッチを結ぶ2本のリンクのうち1本はSTPでブロックされる。束ねると両方使える。on モードで片側だけ束ねるとループの原因になる
- 例：show spanning-tree に Po1 が1行で出る
