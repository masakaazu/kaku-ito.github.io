## 11-1 管理アクセスの方法

### まとめ表

**機器にログインする方法**

| 方法 | 通り道 | ポート | 暗号化 |
| :-: | :-: | :-: | :-: |
| コンソール | 専用のケーブル（アウトオブバンド） | ― | ―（直接つなぐ） |
| Telnet | ネットワーク（VTY） | TCP 23 | なし（パスワードも丸見え） |
| SSH | ネットワーク（VTY） | TCP 22 | あり |
| HTTP | ネットワーク（Web画面） | TCP 80 | なし |
| HTTPS | ネットワーク（Web画面） | TCP 443 | あり（TLS） |
| クラウド管理 | インターネット越しのダッシュボード | ― | あり |

### ログインの方法

#### コンソールポート（こんそーるぽーと / console port）

- 意味：機器に直接ケーブルでつないで操作するためのポート。ネットワークの設定がなくても使えるので、最初の設定やネットワークが壊れたときに使う
- ポイント：アウトオブバンド（データの通り道とは別）の管理。設定は `line console 0`。通信の初期値は 9600bps・データ8ビット・ストップ1ビット・パリティなし（9600 8N1）。だれでも物理的にさわれば使えるので、パスワードを付ける
- 例：PCのターミナルソフト（9600bps）→ ロールオーバーケーブルかUSB → コンソールポート

#### VTY（ぶいてぃーわい / Virtual Teletype）

- 意味：Telnet や SSH でネットワーク越しにログインするときに使う、仮想のログイン口（ライン）
- ポイント：同時に何人ログインできるかは VTY の数で決まる（数は機種による。古いルーターは0〜4、Catalyst スイッチは0〜15 が多く、Catalyst 9300 は0〜98 まで作れる）。パスワードやSSHの設定は全部の VTY にそろえて入れる（0〜4 だけ設定して 5〜15 を忘れる、がよくあるミス）
- 例：`line vty 0 15`
- 語の意味：Virtual＝仮想の／Teletype＝テレタイプ端末

#### Telnet（てるねっと / Telnet）

- 意味：ネットワーク越しにコマンドで機器を操作する古いプロトコル。TCP 23
- ポイント：ユーザー名もパスワードもコマンドも、暗号化されずに流れる。盗み見られるので、今は SSH を使う。VTY にパスワードがないと「Password required, but none set」と出てログインできない
- 例：`telnet 10.1.1.1`
- 語の意味：Tele＝遠くの／net＝ネットワーク

#### SSH（えすえすえいち / Secure Shell）

- 意味：ネットワーク越しに機器を操作するときの通信を暗号化するプロトコル。TCP 22。Telnet のかわりに使う
- ポイント：機器にRSAの鍵（キーペア）が必要。CCNA では「SSHv2 を使い、VTY は SSH だけ受け付ける」設定が出る。ユーザー名とパスワードで認証する（local・RADIUS・TACACS+）
- 例：`ssh -l admin 10.1.1.1`
- 語の意味：Secure＝安全な／Shell＝コマンドを受け付ける窓口

#### HTTPとHTTPS（えいちてぃーてぃーぴー と えいちてぃーてぃーぴーえす / HTTP and HTTPS）

- 意味：機器のWebの管理画面（WebUI）を使うためのプロトコル。HTTP は TCP 80、HTTPS は TCP 443
- ポイント：HTTP は暗号化しないので、使うなら HTTPS（`ip http secure-server`）。使わないなら `no ip http server`・`no ip http secure-server` で止める。HTTPS には証明書が必要で、なければ機器が自分で作る（自己署名証明書）
- 例：`ip http secure-server`／`ip http authentication local`
- 語の意味：HyperText Transfer Protocol（Secure）

#### クラウド管理（くらうどかんり / cloud-managed）

- 意味：Cisco Meraki のように、インターネットの向こうのダッシュボードで機器の設定と監視をする方法
- ポイント：機器がクラウドへ暗号化したトンネルを張り、管理のデータだけを送る。利用者のデータはクラウドを通らない。機器にログインして1台ずつ設定する必要がない
- 例：ブラウザで Meraki のダッシュボードを開き、全店のスイッチのVLANを変える

### スイッチに管理用のIPを付ける

#### 管理用のSVI（かんりようのえすぶいあい / management SVI）

- 意味：レイヤ2スイッチに、Telnet・SSH・Web で入るための IP アドレスを付けるVLANインタフェース
- ポイント：レイヤ2スイッチのポートには IP を付けないので、`interface vlan 99` に IP を付ける。そのVLANがどこかのポートで使われていて、インタフェースが up でないと届かない
- 例：

```
interface vlan 99
 ip address 10.1.99.11 255.255.255.0
 no shutdown
```
- 語の意味：SVI＝Switched Virtual Interface（スイッチの中の仮想のインタフェース）

#### ip default-gateway（あいぴーでふぉるとげーとうぇい / ip default-gateway）

- 意味：ルーティングをしていないレイヤ2スイッチが、別のサブネットへパケットを送るときに使うルーター（デフォルトゲートウェイ）を決めるコマンド
- ポイント：これがないと、同じサブネットからは SSH で入れても、ほかのサブネットの管理PCからは入れない（返事を返せない）。ルーティングをしているスイッチ（ip routing）では要らない
- 例：`ip default-gateway 10.1.99.1`

## 11-2 パスワードと特権レベル

### まとめ表

**パスワードの種類**

| コマンド | 守るもの | 設定ファイルでの見え方 |
| :-: | :-: | :-: |
| enable password | 特権EXECモード | そのまま（service password-encryption でタイプ7） |
| enable secret | 特権EXECモード | ハッシュ（今はタイプ9。両方あれば secret が勝つ） |
| line の password ＋ login | コンソール・VTY のログイン | そのまま（タイプ7にできる） |
| username … secret ＋ login local | ユーザーごとのログイン | ハッシュ |

**パスワードのタイプ**

| タイプ | 中身 | 安全さ |
| :-: | :-: | :-: |
| 0 | 平文 | 見ればわかる |
| 7 | 簡単な暗号（ヴィジュネル） | すぐ戻せる。使わない |
| 5 | MD5 のハッシュ | 古い |
| 6 | AES の暗号（戻せる） | 鍵（マスターキー）で守る |
| 8 | PBKDF2（SHA-256）のハッシュ | 強い |
| 9 | scrypt のハッシュ | 強い（Cisco のおすすめ） |

### 特権EXECを守る

#### enable password（いねーぶるぱすわーど / enable password）

- 意味：ユーザーEXECモードから特権EXECモード（enable）に入るときのパスワードを決める古いコマンド
- ポイント：設定ファイルに平文で入る（service password-encryption でもタイプ7 にしかならない）。enable secret があれば、enable password は使われない
- 例：`enable password Cisco123`

#### enable secret（いねーぶるしーくれっと / enable secret）

- 意味：特権EXECモードに入るときのパスワードを、戻せないハッシュにして保存するコマンド
- ポイント：enable password より優先される（両方あれば secret が使われる）。IOS XE（16.10 以降）では、タイプを書かなければ自動でタイプ9 になる。`enable algorithm-type scrypt secret …` でタイプ9 を明示できる
- 例：`enable secret Str0ngPass!` → 設定ファイルには `enable secret 9 $9$…`

#### service password-encryption（さーびすぱすわーどえんくりぷしょん / service password-encryption）

- 意味：設定ファイルの中の平文のパスワード（line の password・enable password・username password など）を、タイプ7 に変えて見えにくくするコマンド
- ポイント：タイプ7 は簡単に元に戻せるので、肩越しにのぞかれるのを防ぐ程度。本当に守るなら secret（ハッシュ）を使う。すでに secret のものには関係ない
- 例：`service password-encryption` → `password 7 0822455D0A16`

#### パスワードのタイプ（ぱすわーどのたいぷ / password types）

- 意味：設定ファイルにパスワードをどう保存しているかを表す番号。0＝平文、7＝弱い暗号、5＝MD5、6＝AES（戻せる）、8＝PBKDF2、9＝scrypt
- ポイント：ログインに使うパスワードは、戻せないハッシュ（8 か 9）にする。Cisco の手引きは「できるだけタイプ9 を使う」としている。タイプ7 は道具ですぐ戻せる
- 例：`username admin privilege 15 algorithm-type scrypt secret Adm1nPass`

### ラインのログイン

#### login（ろぐいん / login）

- 意味：ライン（コンソール・VTY）で、そのラインに設定した password を聞くようにするコマンド
- ポイント：`password` だけでは聞かれない。`login` と `password` の両方が要る。VTY で login があるのに password がないと、Telnet しても「Password required, but none set」で切られる
- 例：

```
line vty 0 4
 password letmein
 login
```

#### login local（ろぐいんろーかる / login local）

- 意味：ラインで、機器に保存したユーザー名とパスワード（username コマンド）で1人ずつ認証するコマンド
- ポイント：line の password は使われなくなる（ユーザー名とパスワードを聞かれる）。SSH では必ずユーザー名が要るので、login local（か AAA）にする。だれがログインしたか記録に残せる
- 例：`username admin secret P@ssw0rd` ＋ `line vty 0 15` → `login local`

#### username（ゆーざーねーむ / username）

- 意味：機器の中にユーザー名とパスワード（と特権レベル）を保存するコマンド。ローカルのユーザーデータベース
- ポイント：`password` で入れるとタイプ0／7、`secret` で入れるとハッシュ。privilege 15 にすると、ログインしてすぐ特権EXECになる
- 例：`username admin privilege 15 secret Adm1nPass`

#### 特権レベル（とっけんれべる / privilege level）

- 意味：使えるコマンドの範囲を0〜15 の16段階で決めるしくみ。初期は 1（ユーザーEXEC）と 15（特権EXEC）の2つだけ
- ポイント：プロンプトが `>` ならレベル1、`#` ならレベル15。コマンドをほかのレベルに移すこともできる（`privilege exec level 5 …`）。`show privilege` で今のレベルがわかる
- 例：`enable 15`／`disable`（レベル1 に戻る）

### そのほかの守り

#### exec-timeout（えぐぜっくたいむあうと / exec-timeout）

- 意味：何も入力しない時間がこれを過ぎたら、ラインのセッションを切るコマンド
- ポイント：初期値は10分。`exec-timeout 0 0` は「切らない」で、席を離れたときに危ない。単位は「分 秒」
- 例：`exec-timeout 5 0`（5分）

#### banner motd（ばなーえむおーてぃーでぃー / banner motd）

- 意味：ログインのときに表示するメッセージを決めるコマンド。「許可のない利用は禁止」と知らせるのに使う
- ポイント：始まりと終わりを同じ文字（区切り文字）で囲む。機器の名前や機種など、攻撃者のヒントになることは書かない。`banner login` はログインのプロンプトの前に出る
- 例：`banner motd # Authorized access only #`
- 語の意味：MOTD＝Message Of The Day（今日のお知らせ）

#### パスワードリカバリー（ぱすわーどりかばりー / password recovery）

- 意味：パスワードを忘れたとき、機器の起動を途中で止めて、新しいパスワードを設定し直す手順
- ポイント：コンソールにさわれる人ならだれでもできるので、機器は鍵のかかる部屋に置く。`no service password-recovery`（スイッチは `system disable password recovery switch all`）で止めると、起動を止めたときに設定ファイルが消える
- 例：起動中に MODE ボタン（スイッチ）や Break キー（ルーター）を押す

## 11-3 SSHの設定

### まとめ表

**SSH を使えるようにする手順**

| 手順 | コマンド | 理由 |
| :-: | :-: | :-: |
| 1 | hostname R1 | 鍵の名前に使う（初期の名前のままだと鍵を作れない） |
| 2 | ip domain name example.com | 鍵の名前に使う |
| 3 | crypto key generate rsa（modulus 2048） | 鍵を作ると SSH が動き出す。SSHv2 は768ビット以上が必要 |
| 4 | ip ssh version 2 | 古い v1 を使わない |
| 5 | username admin secret … | SSH はユーザー名が必要 |
| 6 | line vty 0 15 → login local | ローカルのユーザーで認証 |
| 7 | transport input ssh | Telnet を受け付けない |

### SSHを動かす

#### RSAのキーペア（あーるえすえーのきーぺあ / RSA key pair）

- 意味：SSH の暗号の鍵（公開鍵と秘密鍵の組）。`crypto key generate rsa` で作ると、SSH のサーバーが自動で動き出す
- ポイント：作る前に hostname（初期の Switch・Router 以外）と ip domain name が要る。どちらかがないと「No host name specified」「No domain specified」のエラーになる。鍵を消す（`crypto key zeroize rsa`）と SSH は止まる。長さ（modulus）は Cisco の推奨が1024ビット以上、SSHv2 は768ビット以上が必須
- 例：`crypto key generate rsa modulus 2048`
- 語の意味：RSA＝Rivest・Shamir・Adleman（考えた3人の名前）

#### ip domain name（あいぴーどめいんねーむ / ip domain name）

- 意味：機器のドメイン名を決めるコマンド。RSA の鍵の名前（ホスト名.ドメイン名）に使う
- ポイント：古いIOSでは `ip domain-name`（ハイフンあり）。SSH の手順の中で、hostname とともに忘れやすい
- 例：`ip domain name example.com`

#### ip ssh version 2（あいぴーえすえすえいち ばーじょんつー / ip ssh version 2）

- 意味：SSH のバージョン2 だけを使うようにするコマンド
- ポイント：v1 は弱いので使わない。`show ip ssh` で「SSH Enabled - version 2.0」のように確かめる。v1 と v2 の両方を受け付ける状態は「version 1.99」と表示される
- 例：`ip ssh version 2`

#### transport input（とらんすぽーといんぷっと / transport input）

- 意味：ライン（VTY）に、どのプロトコルでログインしてよいかを決めるコマンド
- ポイント：`transport input ssh` で SSH だけ、`telnet ssh` で両方、`none` でどれも不可。SSH の設定をしても、ここで telnet を許していれば Telnet でも入れてしまう
- 例：`line vty 0 15` → `transport input ssh`

#### access-class（あくせすくらす / access-class）

- 意味：VTY に ACL をかけて、ログインしてよい送信元のIPアドレスを決めるコマンド
- ポイント：インタフェースにかける `ip access-group` ではなく、ラインには `access-class … in` を使う。管理用のネットワークからだけ SSH を許す
- 例：

```
access-list 10 permit 10.1.50.0 0.0.0.255
line vty 0 15
 access-class 10 in
```

#### show ip ssh（しょーあいぴーえすえすえいち / show ip ssh）

- 意味：SSH のサーバーが動いているか、バージョン・タイムアウト・認証の再試行の回数などを表示するコマンド
- ポイント：鍵がないと「SSH Disabled」。`show ssh` は今つながっている SSH のセッションを表示する（別のコマンド）
- 例：`show ip ssh` → `SSH Enabled - version 2.0`、`Authentication timeout: 120 secs; Authentication retries: 3`

#### ip ssh time-out と authentication-retries（あいぴーえすえすえいち たいむあうと / ip ssh time-out, authentication-retries）

- 意味：SSH でログインするときの、交渉の待ち時間と、パスワードを間違えてよい回数を決めるコマンド
- ポイント：ログインしたあとの「何もしないと切れる時間」は exec-timeout（ライン）で、こちらとは別。総当たりを遅らせるには `login block-for` も使える
- 例：`ip ssh time-out 60`／`ip ssh authentication-retries 2`

## 11-4 AAAとTACACS+・RADIUS

### まとめ表

**TACACS+ と RADIUS**

| | TACACS+ | RADIUS |
| :-: | :-: | :-: |
| 作ったところ | Cisco（今は RFC 8907） | IETF 標準（RFC 2865） |
| 運ぶもの | TCP 49 | UDP 1812（認証）・1813（アカウンティング）。古い機器は1645・1646 |
| 暗号化 | パケットの中身全部 | パスワードだけ |
| 認証と認可 | 分けられる | いっしょ |
| コマンドごとの許可 | できる | できない |
| 主な使い道 | 機器の管理者のログイン | 利用者のネットワークへの接続（802.1X・VPN・無線） |

### AAA

#### AAA（とりぷるえー / Authentication, Authorization, Accounting）

- 意味：だれか確かめる（認証）、何をしてよいか決める（認可）、何をしたか記録する（アカウンティング）の3つのしくみ
- ポイント：`aaa new-model` で有効にする。サーバー（TACACS+・RADIUS）にユーザーを集めると、機器ごとにユーザーを作らなくてよい。サーバーが落ちたときのために、ローカルのユーザーも残しておく
- 例：`aaa new-model`
- 語の意味：Authentication＝本人の確認／Authorization＝許可／Accounting＝記録

#### 認証（にんしょう / Authentication）

- 意味：ログインしようとしている人が本人かどうかを、パスワード・証明書などで確かめること
- ポイント：認可（何をしてよいか）・アカウンティング（何をしたか）と区別する。「だれ？」が認証
- 例：ユーザー名 admin とパスワードを TACACS+ サーバーで確かめる

#### 認可（にんか / Authorization）

- 意味：認証が済んだ人に、何をしてよいか（使えるコマンド・特権レベル・VLAN など）を決めること
- ポイント：TACACS+ はコマンドごとに許可・不許可を決められる。「何をしてよい？」が認可
- 例：`aaa authorization commands 15 default group tacacs+ local`

#### アカウンティング（あかうんてぃんぐ / Accounting）

- 意味：だれが、いつ、何をしたか（ログインの時間・入力したコマンドなど）を記録すること
- ポイント：TACACS+ ではコマンドごとに記録できる。あとから「だれが設定を変えたか」を調べるのに使う。「何をした？」がアカウンティング
- 例：`aaa accounting commands 15 default start-stop group tacacs+`

#### メソッドリスト（めそっどりすと / method list）

- 意味：認証にどの方法を、どの順番で使うかを決めたリスト。`aaa authentication login` で作り、ラインに付ける
- ポイント：次の方法へ進むのは、前の方法が「エラー」（サーバーが応えない）のときだけ。パスワードが違って「失敗」したときは、次へ進まずにログインできない。`default` のリストはすべてのラインに使われる
- 例：`aaa authentication login default group tacacs+ local` → サーバーが落ちていればローカルのユーザーで入れる

### サーバーのプロトコル

#### TACACS+（たかくすぷらす / Terminal Access Controller Access-Control System Plus）

- 意味：機器の管理者のログインを、サーバーでまとめて認証・認可・記録するための Cisco 生まれのプロトコル。TCP 49
- ポイント：パケットの中身全部を暗号化する。認証・認可・アカウンティングを別々に扱え、コマンドごとの許可ができるので、機器の管理に向く。Cisco の手引きも、使えるなら RADIUS より TACACS+ をすすめている
- 例：

```
tacacs server TAC1
 address ipv4 10.1.50.5
 key T@cKey
```

#### RADIUS（れいでぃあす / Remote Authentication Dial-In User Service）

- 意味：利用者のネットワークへの接続を、サーバーでまとめて認証するための標準のプロトコル。UDP 1812（認証）・1813（アカウンティング）
- ポイント：パスワードだけを暗号化し、ほかは平文。認証と認可がいっしょ。802.1X（有線・無線）や VPN の利用者の認証でよく使う。Cisco の機器の古い初期値は1645・1646
- 例：

```
radius server RAD1
 address ipv4 10.1.50.6 auth-port 1812 acct-port 1813
 key R@dKey
```
- 語の意味：Remote＝遠くの／Authentication＝認証／Dial-In＝電話で接続してくる／User Service＝利用者へのサービス

#### 共有の鍵（きょうゆうのかぎ / shared secret, key）

- 意味：機器（クライアント）と TACACS+・RADIUS のサーバーの間で、前もって同じにしておく秘密の文字列。通信の暗号化や、相手が本物かの確認に使う
- ポイント：機器とサーバーで1文字でも違うと、認証できない（サーバー側で「鍵が違う」と記録される）。ネットワークには流さない
- 例：機器 `key T@cKey`・サーバー側にも同じ T@cKey を登録

#### 問 ccna-11-o26

- 問：TACACS+ と RADIUS を比べた説明として正しいものはどれか。
- ア：TACACS+ は認証と認可を分けられ、コマンドごとの許可ができる
- イ：TACACS+ はパスワードだけを暗号化し、RADIUS はパケットの中身全部を暗号化する

- エ：RADIUS は Cisco だけの方式である
- 正解：ア
- 解説：TACACS+ は AAA を別々に扱うので、コマンドごとの許可ができ、機器の管理に向く。中身全部を暗号化し、TCP 49 を使う。RADIUS は標準（RFC 2865）で、パスワードだけを暗号化し、UDP を使う。
- アの意味：正しい。
- イの意味：逆。
- ウの意味：逆。RADIUS が UDP、TACACS+ が TCP。
- エの意味：RADIUS は IETF の標準。Cisco から生まれたのは TACACS+。
- 出典：オリジナル問題（根拠：Cisco「TACACS+ and RADIUS Comparison」（Packet Encryption・Authentication and Authorization・Router Management））
