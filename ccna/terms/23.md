## 23-1 DHCP スヌーピング

### まとめ表

| 項目 | 信頼ポート（trusted） | 信頼しないポート（untrusted） |
| :-: | :-: | :-: |
| つなぐもの | 本物の DHCP サーバー・上流のスイッチ | 利用者の端末 |
| 既定 | ― | すべてのポートがこちら |
| サーバーからのメッセージ（OFFER・ACK など） | 通す | 捨てる |
| バインディングテーブル | 作らない | 作る（MAC・IP・リース・VLAN・ポート） |
| 設定 | ip dhcp snooping trust | （何もしない） |

### しくみ

#### DHCP スヌーピング（でぃーえいちしーぴーすぬーぴんぐ / DHCP snooping）

- 意味：スイッチが DHCP のメッセージをのぞき見て、信頼しないポートから来たおかしなメッセージを捨て、正しく配られたアドレスの表（バインディングテーブル）を作るしくみ
- ポイント：信頼しない端末と DHCP サーバーの間のファイアウォールのように働く。既定では無効。全体で有効にし（ip dhcp snooping）、さらに VLAN ごとに有効にする（ip dhcp snooping vlan 10）。どちらかが欠けると働かない
- 例：`ip dhcp snooping` → `ip dhcp snooping vlan 10`
- 語の意味：snoop＝のぞき見る

#### 偽の DHCP サーバー（にせのでぃーえいちしーぴーさーばー / rogue DHCP server）

- 意味：攻撃者などが勝手に置いた DHCP サーバー。うその既定ゲートウェイや DNS を配り、通信を横取りしたり止めたりする
- ポイント：DHCP スヌーピングは、信頼しないポートに来た DHCPOFFER・DHCPACK・DHCPNAK など「サーバーが出すメッセージ」を捨てて防ぐ
- 例：利用者のポートで DHCPOFFER を受けると、DHCP_SNOOPING_UNTRUSTED_PORT のログを出して捨てる

#### 信頼ポート（しんらいぽーと / trusted port）

- 意味：DHCP スヌーピングで、チェックせずに DHCP のメッセージを通すポート。本物の DHCP サーバーや、サーバーのほうへ向かう上流のポートに設定する
- ポイント：既定ではどのポートも信頼されないので、サーバー側のポートを `ip dhcp snooping trust` で信頼にしないと、正しいサーバーの応答まで捨てられて誰もアドレスをもらえない。それ以外のポートは信頼にしない
- 例：`interface fo1/0/10` → `ip dhcp snooping trust`（上流のトランク）

#### 信頼しないポート（しんらいしないぽーと / untrusted port）

- 意味：DHCP スヌーピングでメッセージをチェックするポート。利用者の端末をつなぐポートは、こちらのままにする
- ポイント：ここではサーバーからのメッセージを捨てる。クライアントのメッセージ（DISCOVER・REQUEST）は通し、そのやり取りからバインディングテーブルを作る
- 例：アクセスポート（switchport access vlan 10）は既定のまま

#### バインディングテーブル（ばいんでぃんぐてーぶる / DHCP snooping binding table）

- 意味：信頼しないポートの端末について、MAC アドレス・IP アドレス・リース時間・種類・VLAN・ポートを記録した表
- ポイント：リースが切れたり DHCPRELEASE を受けたりすると消える。信頼ポートの先の端末は載らない。DAI や IP ソースガードがこの表を使って正しい組み合わせか調べる
- 例：`show ip dhcp snooping binding`

#### MAC アドレスの照合（まっくあどれすのしょうごう / MAC address verification）

- 意味：信頼しないポートに来た DHCP のパケットで、イーサネットの送信元 MAC と、DHCP の中のクライアントのハードウェアアドレス（chaddr）が同じか確かめる機能
- ポイント：既定で有効。ちがえば捨てる。1台が MAC を変えながら大量にアドレスを要求する攻撃（DoS）を防ぐ
- 例：`ip dhcp snooping verify mac-address`（既定で有効）

#### オプション 82（おぷしょんはちじゅうに / DHCP option 82, relay agent information）

- 意味：スイッチが DHCP の要求に「どのスイッチのどのポートから来たか」（回線 ID・リモート ID）を書き足す欄
- ポイント：DHCP スヌーピングでは既定で書き足す設定になっている。信頼しないポートに、オプション 82 付きや、中継のアドレス（giaddr）が 0.0.0.0 でない DHCP パケットが来ると捨てる（端末がリレーを装うのを防ぐ）
- 例：`no ip dhcp snooping information option`（書き足すのをやめる）

#### DHCP のレート制限（でぃーえいちしーぴーのれーとせいげん / DHCP snooping rate limit）

- 意味：1つのポートが1秒間に受け取れる DHCP パケットの数を決める設定
- ポイント：既定では制限なし。信頼しないポートでは 100 pps 以下が Cisco の勧め。超えるとポートが err-disabled になり、手で戻すか自動復旧を設定するまで止まる
- 例：`ip dhcp snooping limit rate 10`

## 23-2 DAI と IP ソースガード

### まとめ表

| 機能 | 調べるもの | 使う表 | 守るもの |
| :-: | :-: | :-: | :-: |
| DHCP スヌーピング | DHCP のメッセージ | （表を作る側） | 偽の DHCP サーバー |
| DAI | ARP の要求と応答 | バインディングテーブル（静的なら ARP ACL） | ARP スプーフィング（中間者攻撃） |
| IP ソースガード | ふつうの IP パケットの送信元 | バインディングテーブル（静的な登録） | 隣の IP アドレスのなりすまし |

### ARP を守る

#### ARP スプーフィング（あーぷすぷーふぃんぐ / ARP spoofing, ARP cache poisoning）

- 意味：うその ARP 応答を流して、ほかの機器の ARP キャッシュに「その IP の MAC は自分」と覚えさせる攻撃
- ポイント：ARP は頼まれていない応答（gratuitous ARP）でも受け入れるので成り立つ。だまされた機器は攻撃者に通信を送ってしまい、中間者攻撃になる。同じブロードキャストドメインの中の攻撃
- 例：攻撃者 C が「IA の MAC は MC」とうその応答を流すと、A と B の通信が C を通る

#### DAI（だい / Dynamic ARP Inspection）

- 意味：信頼しないポートに来た ARP の要求と応答を受け止め、IP と MAC の組み合わせがバインディングテーブルと合うか確かめ、合わないものを捨ててログに残す機能
- ポイント：既定ではどの VLAN でも無効で、VLAN ごとに有効にする。DHCP スヌーピングの表を使うので、DHCP スヌーピングも有効にしておく。信頼ポートの ARP は調べずに通す
- 例：`ip arp inspection vlan 10`
- 語の意味：Dynamic＝動的な／ARP＝Address Resolution Protocol／Inspection＝検査

#### DAI の信頼ポート（だいのしんらいぽーと / ip arp inspection trust）

- 意味：DAI で ARP を調べずに通すポート。ふつうはスイッチどうしをつなぐポートにする
- ポイント：既定ではすべて信頼しない。DHCP スヌーピングの trust とは別の設定。端末のポートを信頼にすると、そこからの偽の ARP が素通りになる。逆にスイッチ間を信頼しないままだと、正しい ARP が捨てられて通信が切れることがある
- 例：`interface g1/0/1` → `ip arp inspection trust`

#### ARP ACL（あーぷえーしーえる / ARP access list）

- 意味：固定の IP アドレスの機器（DHCP を使わない機器）について、正しい IP と MAC の組を手で書いておくリスト
- ポイント：DHCP スヌーピングの表に載らない機器のために使う。`ip arp inspection filter` で VLAN に付ける。ARP ACL はバインディングテーブルより先に調べられ、ACL で deny なら表に正しい組があっても捨てる
- 例：`arp access-list SRV` → `permit ip host 10.1.1.10 mac host 0011.2233.4455`

#### ARP の追加チェック（あーぷのついかちぇっく / ip arp inspection validate）

- 意味：DAI に、ARP の中身とヘッダーの食いちがいも調べさせる設定。src-mac・dst-mac・ip から選ぶ
- ポイント：既定では追加のチェックはしない。src-mac は「イーサネットの送信元 MAC」と「ARP の送信者 MAC」、dst-mac は応答の宛先 MAC とターゲット MAC を比べる。ip は 0.0.0.0・255.255.255.255・マルチキャストなどおかしなアドレスを捨てる。コマンドを入れ直すと前の指定は上書きされる
- 例：`ip arp inspection validate src-mac dst-mac ip`

#### ARP のレート制限（あーぷのれーとせいげん / ARP rate limiting）

- 意味：DAI が1秒間に受け取る ARP パケットの数を制限する設定
- ポイント：既定では、信頼しないポートは 15 pps、信頼ポートは制限なし。超えるとポートが err-disabled になる
- 例：`ip arp inspection limit rate 30`

#### IP ソースガード（あいぴーそーすがーど / IP Source Guard, IPSG）

- 意味：信頼しないポートで、バインディングテーブルに載っている送信元 IP（と MAC）のパケットだけを通し、ほかを捨てる機能
- ポイント：DAI は ARP を調べるが、IP ソースガードはふつうの IP パケットを調べる。隣の端末の IP アドレスを勝手に使うなりすましを防ぐ。有効にすると DHCP スヌーピングが許す DHCP 以外の IP は、表に載るまで通らない
- 例：`interface g1/0/5` → `ip verify source`（mac-check を付けると MAC も調べる）

## 23-3 ポートセキュリティ

### まとめ表

| 違反モード | パケット | ログ・SNMP トラップ | 違反カウンター | ポート |
| :-: | :-: | :-: | :-: | :-: |
| protect | 知らない送信元は捨てる | 出さない | 増えない | 動いたまま |
| restrict | 知らない送信元は捨てる | 出す | 増える | 動いたまま |
| shutdown（既定） | すべて止まる | ― | 増える | err-disabled |
| shutdown vlan | その VLAN だけ止まる | ― | 増える | その VLAN だけ err-disabled |

### しくみと設定

#### ポートセキュリティ（ぽーとせきゅりてぃ / port security）

- 意味：ポートにつなげる機器を、MAC アドレスの数や値で制限する機能
- ポイント：既定では無効。アクセスポートかトランクポートに固定してから有効にする（既定の dynamic auto のままでは設定できない）。EtherChannel のポートには使えない
- 例：`switchport mode access` → `switchport port-security`

#### セキュア MAC アドレス（せきゅあまっくあどれす / secure MAC address）

- 意味：ポートセキュリティで「このポートで使ってよい」とされた MAC アドレス。静的（手で書く）・動的（自動で覚える）・スティッキー（覚えて設定に書き込む）の3種類
- ポイント：静的は running-config に入る。動的はアドレス表にだけあり、再起動で消える。スティッキーは running-config に入る（startup-config に保存すれば再起動後も残る）
- 例：`switchport port-security mac-address 0000.0000.0002`

#### スティッキー学習（すてぃっきーがくしゅう / sticky learning）

- 意味：自動で覚えた MAC アドレスを、スティッキーのセキュア MAC アドレスに変えて running-config に書き込む機能
- ポイント：有効にする前に覚えていた動的なアドレスも変わる。保存（copy running-config startup-config）しないと再起動で消える。無効にすると動的なアドレスに戻り、設定から消える
- 例：`switchport port-security mac-address sticky`

#### 最大数（さいだいすう / maximum）

- 意味：1つのポートで使えるセキュア MAC アドレスの数
- ポイント：既定は 1。IP 電話の先に PC をつなぐポート（音声 VLAN あり）は 2 にする（電話が1つ、PC が1つ）。今あるセキュア MAC アドレスより少ない数は設定できない
- 例：`switchport port-security maximum 2`

#### セキュリティ違反（せきゅりてぃいはん / security violation）

- 意味：ポートセキュリティが「違反」と見なすできごと。最大数まで覚えたあとで知らない MAC アドレスの機器が来たとき、または1つのポートで覚えたアドレスが同じ VLAN の別のセキュアポートに現れたとき
- ポイント：違反したときの動きは違反モード（protect・restrict・shutdown・shutdown vlan）で決まる
- 例：最大数 1 のポートで、PC をハブにつなぎ直して2台目を使った

#### protect（ぷろてくと / protect）

- 意味：違反したとき、知らない送信元のパケットだけを捨てる違反モード
- ポイント：ログも SNMP トラップも出さず、違反カウンターも増えないので、違反に気づけない。ポートは動いたまま
- 例：`switchport port-security violation protect`

#### restrict（りすとりくと / restrict）

- 意味：違反したとき、知らない送信元のパケットを捨て、SNMP トラップと syslog を出し、違反カウンターを増やす違反モード
- ポイント：ポートは止めない（許された機器は使い続けられる）。protect との違いは「知らせるかどうか」
- 例：`switchport port-security violation restrict`

#### shutdown（しゃっとだうん / shutdown violation mode）

- 意味：違反したとき、ポートを err-disabled にして止める違反モード。既定のモード
- ポイント：許された機器も含めてポート全体が止まる。shutdown vlan はポートではなく違反した VLAN だけを止める
- 例：`switchport port-security violation shutdown`（書かなくても既定）

#### エージング（えーじんぐ / port security aging）

- 意味：セキュア MAC アドレスを、決めた時間がたったら消す設定。absolute（時間がたったら必ず消す）と inactivity（その時間通信がなければ消す）がある
- ポイント：既定では無効（時間 0）。スティッキーのアドレスには使えない。機器の入れ替えがあるポートで、手で消さずに新しい機器を使えるようにする
- 例：`switchport port-security aging time 120` → `switchport port-security aging type inactivity`

## 23-4 err-disabled と確認

### まとめ表

| 確かめたいこと | コマンド |
| :-: | :-: |
| DHCP スヌーピングの設定・信頼ポート・レート | show ip dhcp snooping |
| 配られたアドレスの記録 | show ip dhcp snooping binding |
| DAI のポートの信頼とレート | show ip arp inspection interfaces |
| ポートセキュリティの最大数・違反数・違反モード | show port-security interface g1/0/1 |

### 止まったポートの戻し方

#### err-disabled（えらーでぃせーぶるど / error-disabled state）

- 意味：スイッチが異常を見つけて、ポートを自動で止めた状態
- ポイント：ポートセキュリティの shutdown、DHCP スヌーピングのレート超え、DAI のレート超えなどで起きる。そのままでは自分では戻らない。原因を取り除いてから、shutdown → no shutdown で手で戻す
- 例：`interface g1/0/1` → `shutdown` → `no shutdown`

#### err-disabled の自動復旧（えらーでぃせーぶるどのじどうふっきゅう / errdisable recovery）

- 意味：err-disabled になったポートを、決めた時間がたったら自動で戻す設定。原因（cause）ごとに有効にする
- ポイント：既定では無効。原因の名前はポートセキュリティなら psecure-violation、DHCP のレート超えなら dhcp-rate-limit
- 例：`errdisable recovery cause psecure-violation`

#### show port-security（しょうぽーとせきゅりてぃ / show port-security）

- 意味：ポートセキュリティの設定と状態を表示するコマンド
- ポイント：インタフェースを指定すると、最大数・今のセキュア MAC アドレスの数・違反の回数・違反モードが分かる。address を付けると覚えたアドレスの一覧
- 例：`show port-security interface g1/0/1`／`show port-security address`

#### show ip dhcp snooping binding（しょうあいぴーでぃーえいちしーぴーすぬーぴんぐばいんでぃんぐ / show ip dhcp snooping binding）

- 意味：DHCP スヌーピングのバインディングテーブル（動的に覚えたもの）を表示するコマンド
- ポイント：MAC・IP・リースの残り秒数・種類（dhcp-snooping）・VLAN・ポートが出る。DAI や IP ソースガードで通信が止まったときは、端末がここに載っているかを確かめる
- 例：`00:A3:D1:44:20:46 10.0.0.3 85556 dhcp-snooping 10 FortyGigabitEthernet1/0/2`

## 23-5 無線 LAN を WPA2 PSK で守る

### まとめ表

| 手順（9800 の GUI） | 選ぶもの |
| :-: | :-: |
| 1 Configuration > Tags & Profiles > WLANs > Add | 新しい WLAN を作る |
| 2 General タブ | Profile Name・SSID・WLAN ID・Status |
| 3 Security > Layer2 タブ | Layer 2 Security Mode＝WPA + WPA2、WPA2 Policy、暗号は AES |
| 4 同じタブの認証キーの管理（AKM） | 802.1X を外し、PSK を選ぶ。PSK の形式（ASCII か Hex）と鍵 |
| 5 Apply to Device | 保存して機器に反映 |

### 設定の中身

#### WPA2 PSK（だぶりゅぴーえーつーぴーえすけー / WPA2 Personal, WPA2-PSK）

- 意味：WPA2 で、利用者が共通の鍵（パスフレーズ）を入れてつなぐ方式。家庭や小さな事務所向け
- ポイント：鍵を知っている人は誰でもつなげ、利用者ごとの区別はできない。会社では利用者ごとに RADIUS で認証する WPA2 Enterprise（802.1X）を使う。CCNA 5.10 では GUI で WPA2 PSK の WLAN を作れることが求められる
- 例：SSID「SHOP」、鍵「Cisco123」をお店の人で共有

#### Layer 2 Security Mode（れいやつーせきゅりてぃもーど / Layer 2 Security Mode）

- 意味：9800 の WLAN の Security > Layer2 タブで、レイヤ2の守り方を選ぶ欄。WPA + WPA2・WPA2 + WPA3・WPA3・Static WEP などがある
- ポイント：WPA2 PSK にするときは WPA + WPA2 を選び、WPA2 Policy にチェックを入れる。同じ SSID の WLAN を複数作るときは、レイヤ2のセキュリティをそれぞれ変える
- 例：Layer 2 Security Mode＝WPA + WPA2 → WPA2 Policy にチェック

#### AES-CCMP（えーいーえすしーしーえむぴー / AES-CCMP）

- 意味：WPA2 が使う暗号化。AES を CCMP という方式で使い、暗号化と改ざんの検出をする
- ポイント：WPA（WPA1）の既定は TKIP、WPA2 の既定は AES。TKIP は古く弱いので、WPA2 では AES を選ぶ。9800 では TKIP は GUI で設定できない
- 例：CLI では `security wpa wpa2 ciphers aes`
- 語の意味：AES＝Advanced Encryption Standard／CCMP＝Counter Mode with CBC-MAC Protocol

#### AKM（えーけーえむ / Authentication Key Management）

- 意味：鍵をどう決めて認証するかの選び方。802.1X・PSK・SAE・FT などから選ぶ
- ポイント：WPA・WPA2 の既定の AKM は 802.1X。WPA2 PSK の WLAN にするときは、802.1X のチェックを外して PSK にチェックを入れる。外し忘れると RADIUS がなくてつながらない
- 例：CLI では `no security wpa akm dot1x` → `security wpa akm psk`

#### 事前共有鍵の形式（じぜんきょうゆうかぎのけいしき / PSK format）

- 意味：WPA2 PSK の鍵の書き方。ASCII（ふつうの文字）か Hex（16進数）を選ぶ
- ポイント：ASCII なら 8〜63 文字、Hex なら 64 けた。この鍵が端末と WLC の間の PMK（ペアワイズマスターキー）になる。ASCII の鍵では % を避ける（つながらない端末がある）
- 例：CLI では `security wpa psk set-key ascii 0 Cisco123`
