## 9-1 ルートブリッジとルートポートの選び方

### まとめ表

**選ぶ順番（どれも「小さいほうが勝ち」）**

| 手順 | 何を選ぶか | 比べるもの |
| :-: | :-: | :-: |
| 1 | ルートブリッジ（ネットワークに1台） | ブリッジID（プライオリティ → MACアドレス） |
| 2 | ルートポート（ルート以外の各スイッチに1つ） | ルートまでのパスコストの合計 → 相手のブリッジID → 相手のポートID |
| 3 | 指定ポート（リンクごとに1つ） | そのリンクからルートまでのパスコスト → ブリッジID → ポートID |
| 4 | 残りのポート | ブロック（RSTPでは代替ポート・バックアップポート） |

**パスコストの既定値**

| 速度 | 短い方式（802.1D、古い機種） | 長い方式（Catalyst 9300 17.9 の既定値） |
| :-: | :-: | :-: |
| 10Mbps | 100 | 2,000,000 |
| 100Mbps | 19 | 200,000 |
| 1Gbps | 4 | 20,000 |
| 10Gbps | 2 | 2,000 |

### ループと STP の考え方

#### スパニングツリープロトコル（すぱにんぐつりーぷろとこる / Spanning Tree Protocol, STP）

- 意味：スイッチをつなぐ経路が二重になっていても、ループができないように一部のポートを止め（ブロックし）、使う経路を木の形（ツリー）に1つに決めるレイヤ2のプロトコル。IEEE 802.1D
- ポイント：経路の予備（冗長）を持ちながら、ループを防ぐのが目的。使っている経路が切れると、止めていたポートを使える状態にする。Catalystでは最初から動いている
- 例：`show spanning-tree vlan 10`
- 語の意味：Spanning＝全体に張りわたす／Tree＝木（枝分かれして輪にならない形）

#### ブロードキャストストーム（ぶろーどきゃすとすとーむ / broadcast storm）

- 意味：ループのあるレイヤ2ネットワークで、ブロードキャストのフレームが止まらずに回り続け、増え続けて帯域を使い切ってしまう状態
- ポイント：イーサネットのフレームにはIPのTTLのような寿命がないので、レイヤ2のループは自然には止まらない。同じフレームが何度も届く、MACアドレステーブルが安定しない（同じMACが別々のポートで学習される）のも、ループで起きる問題
- 例：STPを止めたスイッチ2台を2本でつなぐと起きる

#### BPDU（びーぴーでぃーゆー / Bridge Protocol Data Unit）

- 意味：STPのスイッチどうしが、ルートブリッジのID・ルートまでのコスト・自分のブリッジID・ポートID・タイマーなどを知らせ合うフレーム。初期値では2秒（Hello タイム）ごとに送る
- ポイント：スイッチはBPDUを受け取って使うが、ほかのポートへ中継はしない。「より良い（superior）BPDU」＝ルートのIDが小さい、またはコストが小さいBPDU
- 例：IEEE のBPDUの宛先はマルチキャストの 01-80-C2-00-00-00（スイッチはこの宛先を受け取るが中継しない）
- 語の意味：Bridge＝ブリッジ（スイッチ）／Protocol＝決まりごと／Data＝データ／Unit＝単位

### ルートブリッジ

#### ブリッジID（ぶりっじあいでぃー / bridge ID, BID）

- 意味：スイッチをSTPで見分ける8バイトの値。前の2バイトがプライオリティ（そのうち下12ビットは拡張システムID＝VLAN番号）、後ろの6バイトがMACアドレス
- ポイント：小さいほど強い。まずプライオリティを比べ、同じならMACアドレスを比べる。PVST+ではVLANごとに別のブリッジIDになる
- 例：VLAN 10 の初期値は 32768＋10＝32778

#### ブリッジプライオリティ（ぶりっじぷらいおりてぃ / bridge priority）

- 意味：ブリッジIDの前半で、管理者が決められる値。初期値32768。4096の倍数（0〜61440）でしか設定できない
- ポイント：下12ビットはVLAN番号に使うので、残り4ビットで決める＝4096刻み。小さくするほどルートブリッジになりやすい。「数字が大きい＝優先度が高い」は誤り
- 例：`spanning-tree vlan 10 priority 4096`

#### 拡張システムID（かくちょうしすてむあいでぃー / extended system ID）

- 意味：ブリッジIDのプライオリティの欄の下12ビットに、VLAN番号を入れる仕組み。同じスイッチでもVLANごとに違うブリッジIDになる
- ポイント：show spanning-tree の「Priority 32778 (priority 32768 sys-id-ext 10)」は、設定したプライオリティ32768＋VLAN 10。表示の数字からVLAN番号を引くと、設定した値がわかる
- 例：VLAN 1 → 32769、VLAN 20 → 32788（初期値のとき）

#### ルートブリッジ（るーとぶりっじ / root bridge）

- 意味：スパニングツリーの木の根になるスイッチ。ネットワーク（PVST+ではVLANごと）に1台だけ。ブリッジIDがいちばん小さいスイッチが選ばれる
- ポイント：全部初期値なら、MACアドレスがいちばん小さい（たいてい一番古い）スイッチがルートになる。ルートブリッジのポートは全部が指定ポート。コアやディストリビューションのスイッチをルートにするのがCiscoの推奨
- 例：show spanning-tree で「This bridge is the root」

#### root primary と root secondary（るーとぷらいまり・せかんだり / root primary・root secondary）

- 意味：`spanning-tree vlan 番号 root primary` はそのVLANのルートブリッジになるようにプライオリティを自動で下げるコマンド、`root secondary` はルートが壊れたときの次のルートになるように下げるコマンド
- ポイント：primary はふつう24576に設定する（今のルートより小さくするためにさらに下げることもある）。secondary は28672。プライオリティを直接書く `priority` と違い、その時点の状況を見て値を決めるマクロ
- 例：`spanning-tree vlan 10 root primary`／`spanning-tree vlan 10 root secondary`

### ルートポートと指定ポート

#### パスコスト（ぱすこすと / path cost）

- 意味：ポートの速度から決まる、そのリンクを通る「遠さ」の値。速いリンクほど小さい
- ポイント：ルートまでのパスコストは、ルートから自分までに通る「受け取る側のポート」のコストの合計。Catalyst 9300 の構成ガイドでは長い方式（1Gbps＝20000）が既定値、古い機種は短い方式（1Gbps＝4）。どちらでも比べ方は同じ
- 例：`spanning-tree vlan 10 cost 10`（インタフェース）／`spanning-tree pathcost method long`

#### ルートパスコスト（るーとぱすこすと / root path cost）

- 意味：あるスイッチからルートブリッジまでの、パスコストの合計
- ポイント：ルートブリッジ自身は0。BPDUには送り主のルートパスコストが入っていて、受け取った側は自分の受信ポートのコストを足す
- 例：1Gbps（4）を2回通る → 8（短い方式）

#### ルートポート（るーとぽーと / root port）

- 意味：ルートブリッジ以外の各スイッチで、ルートブリッジへ向かういちばん良い（コストが小さい）ポート。1台に1つだけ
- ポイント：コストが同じなら、相手（送り主）のブリッジIDが小さいほう、それも同じなら相手のポートIDが小さいほうを選ぶ。ルートブリッジにはルートポートがない
- 例：show spanning-tree の Role が Root

#### 指定ポート（していぽーと / designated port）

- 意味：リンク（セグメント）ごとに1つ選ばれる、そのリンクからルートブリッジへ向かうときにいちばん良いポート。フレームを転送する
- ポイント：ルートブリッジのポートは全部が指定ポート。1本のリンクの両端のうち、ルートパスコストが小さいスイッチ側が指定ポートになる（同じならブリッジIDが小さい側）
- 例：show spanning-tree の Role が Desg

#### ポートID（ぽーとあいでぃー / port ID）

- 意味：ポートプライオリティ（初期値128）とポート番号を組み合わせた値。show spanning-tree の Prio.Nbr 列（128.1 など）
- ポイント：ルートポートを決める最後の比べ方は「相手のポートID」。自分のポートIDではない。2台を2本でつないだとき、どちらのポートがルートポートになるかは相手側のポートのプライオリティと番号で決まる
- 例：`spanning-tree port-priority 64`（16の倍数、小さいほど優先）

## 9-2 ポートの役割と状態（Rapid PVST+）

### まとめ表

**ポートの状態：802.1D（STP）と 802.1w（RSTP）**

| 802.1D の状態 | RSTP の状態 | フレームを転送 | MACアドレスを学習 |
| :-: | :-: | :-: | :-: |
| ブロッキング | ディスカーディング | しない | しない |
| リスニング | ディスカーディング | しない | しない |
| ラーニング | ラーニング | しない | する |
| フォワーディング | フォワーディング | する | する |
| ディセーブル | ディスカーディング | しない | しない |

**ポートの役割（RSTP）**

| 役割 | show の表示 | 状態 | 中身 |
| :-: | :-: | :-: | :-: |
| ルートポート | Root | 転送 | ルートへのいちばん良い道 |
| 指定ポート | Desg | 転送 | そのリンクの代表 |
| 代替ポート | Altn | 止める | ルートポートの予備（別のスイッチへの道） |
| バックアップポート | Back | 止める | 指定ポートの予備（同じスイッチの同じリンク） |

### STPの種類

#### PVST+（ぴーぶいえすてぃーぷらす / Per-VLAN Spanning Tree Plus）

- 意味：VLANごとに別々のスパニングツリーを動かす、Cisco独自の拡張を加えたSTP（802.1Dがもと）
- ポイント：VLANごとにルートブリッジを変えられるので、VLAN 10はリンクA、VLAN 20はリンクBのように、止めるリンクをVLANで分けて両方のリンクを使える
- 例：`spanning-tree mode pvst`
- 語の意味：Per＝〜ごとの／VLAN／Spanning Tree／Plus＝拡張

#### Rapid PVST+（らぴっどぴーぶいえすてぃーぷらす / Rapid Per-VLAN Spanning Tree Plus）

- 意味：PVST+ の収束（作り直し）を、IEEE 802.1w（RSTP）の仕組みで速くしたもの。VLANごとにRSTPが動く。Catalyst 9300 の既定のモード
- ポイント：設定はPVST+とほぼ同じ。CCNA v1.1 の出題範囲は「Rapid PVST+ の基本的な動きを読み取る」
- 例：`spanning-tree mode rapid-pvst`／show で「Spanning tree enabled protocol rstp」

#### RSTP（あーるえすてぃーぴー / Rapid Spanning Tree Protocol）

- 意味：IEEE 802.1w で決められた、速く収束するスパニングツリー。802.1D の既定値で最大50秒かかった作り直しを、1秒未満で終えられる
- ポイント：エッジポートはすぐ転送、新しいルートポートはすぐ転送、ポイントツーポイントのリンクでは提案と合意（proposal／agreement）のやり取りで、タイマーを待たずに転送を始める
- 例：RSTPのBPDUはバージョン2

#### MSTP（えむえすてぃーぴー / Multiple Spanning Tree Protocol）

- 意味：IEEE 802.1s。いくつものVLANを1つのスパニングツリー（インスタンス）にまとめて動かす方式。中身はRSTPで速く収束する
- ポイント：VLANが多いとき、VLANの数だけツリーを動かすPVST+より負担が少ない。CCNAでは名前と目的の区別だけ押さえる
- 例：`spanning-tree mode mst`

### 役割と状態

#### 代替ポート（だいたいぽーと / alternate port）

- 意味：RSTPで、今のルートポートとは別の、ルートブリッジへの予備の道になるポート。止めている（ディスカーディング）
- ポイント：ルートポートが切れると、代替ポートがすぐに新しいルートポートになって転送を始める。802.1Dでいうと「ブロックしているポート」の多く
- 例：show spanning-tree で Altn BLK

#### バックアップポート（ばっくあっぷぽーと / backup port）

- 意味：RSTPで、同じスイッチの指定ポートの予備になるポート。同じスイッチの2つのポートが同じリンク（ハブや折り返し）につながっているときだけ出る
- ポイント：代替ポートは「別のスイッチ経由でルートへ」、バックアップポートは「自分の指定ポートの予備」。スイッチどうしを直結しているふつうの構成では出ない
- 例：show spanning-tree で Back BLK

#### ディスカーディング（でぃすかーでぃんぐ / discarding state）

- 意味：RSTPのポートの状態で、フレームを転送せず、MACアドレスも学習しない状態。802.1Dのブロッキング・リスニング・ディセーブルをまとめたもの
- ポイント：RSTPの状態はディスカーディング・ラーニング・フォワーディングの3つ。Ciscoの show では、RSTPでも BLK（blocking）と表示する
- 例：Altn BLK

#### ブロッキング（ぶろっきんぐ / blocking state）

- 意味：802.1Dのポートの状態で、フレームを転送せずMACアドレスも学習しないが、BPDUは受け取る状態
- ポイント：BPDUを受け取り続けるので、ほかの道が切れたことに気づける。ディセーブルはBPDUも受け取らない
- 例：BLK

#### リスニングとラーニング（りすにんぐ・らーにんぐ / listening・learning state）

- 意味：802.1Dでブロッキングから転送に移るまでの途中の状態。リスニングはBPDUのやり取りだけ、ラーニングはMACアドレスの学習を始める（まだ転送しない）
- ポイント：それぞれフォワードディレイ（15秒）ずつ待つので、ブロッキングから転送まで30秒。最大エージ20秒を足すと、802.1Dの作り直しは最大50秒。RSTPではリスニングがない
- 例：LIS／LRN

#### フォワーディング（ふぉわーでぃんぐ / forwarding state）

- 意味：フレームを転送し、MACアドレスも学習する状態。ルートポートと指定ポートはこの状態になる
- ポイント：転送しているのは役割が Root か Desg のポート。Altn と Back は転送しない
- 例：FWD

### タイマーとリンクの種類

#### STPのタイマー（たいまー / hello time・forward delay・max age）

- 意味：Hello タイム（BPDUを送る間隔）2秒、フォワードディレイ（リスニングとラーニングにそれぞれいる時間）15秒、最大エージ（BPDUが届かなくなってから情報を捨てるまで）20秒
- ポイント：タイマーはルートブリッジの値が全体に伝わる。直接変えるより、ネットワークの直径（diameter）から計算させるほうが安全
- 例：show spanning-tree の「Hello Time 2 sec Max Age 20 sec Forward Delay 15 sec」

#### リンクタイプ（りんくたいぷ / link type）

- 意味：RSTPがポートの先を見分ける種類。全二重はポイントツーポイント（P2p）、半二重は共有（Shr）、PortFastのポートはエッジ（Edge）
- ポイント：提案と合意ですぐ転送に移れるのは、ポイントツーポイントのリンクだけ。共有のリンクでは802.1Dと同じくタイマーを待つ
- 例：show spanning-tree の Type 列（P2p／Shr／P2p Edge）

#### 提案と合意（ていあんとごうい / proposal and agreement）

- 意味：RSTPで、ポイントツーポイントのリンクの両端が「私が指定ポートになる」（提案）と「了解、こちらはルートポート」（合意）をBPDUで交わし、すぐに転送を始める仕組み
- ポイント：提案を受けた側は、ループができないように自分のエッジ以外のポートをいったん止めてから合意を返す。これがルートから枝の先へ順に進む
- 例：BPDUのフラグの Proposal と Agreement

## 9-3 PortFastと保護機能

### まとめ表

**4つのガードと PortFast**

| 機能 | どこに付ける | 何が起きたら | どうなる | 戻し方 |
| :-: | :-: | :-: | :-: | :-: |
| PortFast | 端末をつなぐポート | （リンクが上がったら） | すぐ転送（エッジポート） | ― |
| BPDUガード | PortFastのポート | BPDUを受け取った | err-disabled（ポートが止まる） | 手で shutdown→no shutdown など |
| BPDUフィルタ | PortFastのポート | ― | BPDUを送らない（受け取ったらPortFastが外れる） | ― |
| ルートガード | ルートが来てはいけない向きのポート | より良いBPDUを受け取った | root-inconsistent（止まる） | 自動（BPDUが止まれば戻る） |
| ループガード | ルートポート・代替ポート | BPDUが来なくなった | loop-inconsistent（止まる） | 自動（BPDUが来れば戻る） |

### PortFast

#### PortFast（ぽーとふぁすと / PortFast）

- 意味：ポートのリンクが上がったら、リスニングとラーニングを飛ばしてすぐに転送の状態にする機能。RSTPではエッジポートと同じ
- ポイント：PCやサーバ1台をつなぐポートだけで使う。スイッチをつなぐと一時的なループのおそれがある。初期状態では無効。アクセスポートでは `spanning-tree portfast`、トランクでは `spanning-tree portfast trunk` が必要
- 例：`interface g1/0/5` → `spanning-tree portfast`

#### エッジポート（えっじぽーと / edge port）

- 意味：RSTPで、端末だけがつながる「ネットワークの端」のポート。PortFastを設定したポートがエッジポートになる
- ポイント：エッジポートのリンクが上下しても、トポロジーの変化（TC）として扱わないので、MACアドレステーブルを消さずに済む
- 例：show spanning-tree の Type が P2p Edge

#### spanning-tree portfast default（ぽーとふぁすとでふぉると / spanning-tree portfast default）

- 意味：トランクでない全部のポートで、まとめてPortFastを有効にするグローバル設定
- ポイント：トランクには効かない。スイッチどうしをつなぐポートはトランクにしておけば、端末用のポートだけにPortFastが付く。BPDUガードとあわせて使うことが多い
- 例：`spanning-tree portfast default`

### BPDUを守る機能

#### BPDUガード（びーぴーでぃーゆーがーど / BPDU guard）

- 意味：BPDUを受け取ったら、そのポートを err-disabled（エラーで止めた状態）にする機能
- ポイント：PortFastのポートにスイッチが勝手につながれたときに、ループやルートの乗っ取りを防ぐ。グローバルの `spanning-tree portfast bpduguard default` はPortFastのポートに効き、インタフェースの `spanning-tree bpduguard enable` はPortFastでなくても効く。戻すには手で shutdown→no shutdown（または errdisable recovery）
- 例：`%SPANTREE-2-BLOCK_BPDUGUARD` のログのあと err-disabled

#### BPDUフィルタ（びーぴーでぃーゆーふぃるた / BPDU filtering）

- 意味：ポートでBPDUを送らない（設定の仕方によっては受け取りもしない）ようにする機能
- ポイント：グローバル（`spanning-tree portfast bpdufilter default`）はPortFastのポートからBPDUを送らなくなるが、BPDUを受け取るとPortFastもフィルタも外れる。インタフェース（`spanning-tree bpdufilter enable`）は送りも受けもしないので、そのポートのSTPを止めたのと同じになり、ループの危険がある
- 例：BPDUガードとの違い：ガードは「止める」、フィルタは「無視する」

#### err-disabled（えらーでぃせーぶるど / error-disabled state）

- 意味：スイッチが異常を見つけて、ポートを自動で止めた状態。BPDUガード・ポートセキュリティ違反などで起きる
- ポイント：shutdown と同じように通信できない。原因を取り除いてから `shutdown` → `no shutdown` で戻す。`errdisable recovery cause bpduguard` で時間がたったら自動で戻すこともできる
- 例：show interfaces status で err-disabled

#### ルートガード（るーとがーど / root guard）

- 意味：そのポートでより良い（ルートになれる）BPDUを受け取ったら、ポートを root-inconsistent（止めた状態）にして、ルートブリッジが変わるのを防ぐ機能
- ポイント：ルートブリッジが来てはいけない向き（アクセスのスイッチや、お客さんのスイッチにつながる指定ポート）に付ける。より良いBPDUが来なくなれば自動で戻る。BPDUガードと違い err-disabled にはならない
- 例：`spanning-tree guard root`

#### ループガード（るーぷがーど / loop guard）

- 意味：ルートポートや代替ポートでBPDUが届かなくなったとき、指定ポートになって転送を始めてしまわないように、loop-inconsistent（止めた状態）にする機能
- ポイント：片方向だけ通らなくなったリンク（単方向リンク）でBPDUが来なくなり、止めていたポートが転送を始めてループになるのを防ぐ。BPDUがまた来れば自動で戻る。ルートガードと同じポートには付けられない
- 例：`spanning-tree guard loop`／全体は `spanning-tree loopguard default`
