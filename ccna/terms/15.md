## 15-1 FHRP の目的

### まとめ表

| 項目 | 内容 |
| :-: | :-: |
| 困りごと | PC のデフォルトゲートウェイは1つのアドレス。そのルーターが落ちると、PC は外へ出られない |
| FHRP の答え | 何台かのルーターで「仮想のルーター」（仮想 IP と仮想 MAC）を共有し、1台が落ちても別の1台が引き継ぐ |
| PC の設定 | デフォルトゲートウェイに仮想 IP を書くだけ。切り替わっても PC の設定は変えない |
| 主な種類 | HSRP（Cisco 独自）・VRRP（標準）・GLBP（Cisco 独自、負荷分散つき） |

### 目的としくみ

#### FHRP（えふえいちあーるぴー / First Hop Redundancy Protocol）

- 意味：LAN の出口になるルーター（PC から見て最初のホップ＝デフォルトゲートウェイ）を、何台かで冗長にするプロトコルの総称
- ポイント：HSRP・VRRP・GLBP が代表。ルーティングプロトコル（OSPF など）とは別物で、PC とゲートウェイの間の冗長を担う
- 語の意味：First Hop＝最初のホップ（最初に通るルーター）／Redundancy＝冗長／Protocol＝プロトコル

#### デフォルトゲートウェイの単一障害点（でふぉるとげーとうぇいのたんいつしょうがいてん / single point of failure）

- 意味：PC に書けるデフォルトゲートウェイは1つのアドレスなので、そのルーターが落ちると、ほかにルーターがあっても PC は LAN の外へ出られないこと
- ポイント：ルーターを2台置くだけでは解決しない。PC はゲートウェイを自分で切り替えられないので、ルーター側でアドレスを引き継ぐ FHRP が要る

#### 仮想 IP アドレス（かそうあいぴーあどれす / virtual IP address）

- 意味：FHRP のグループで共有する、どのルーターの実際のインタフェースにも付いていない IP アドレス。PC はこれをデフォルトゲートウェイに設定する
- ポイント：各ルーターのインタフェースには、それぞれ別の実際のアドレスも付ける。n 台で HSRP を組むと、IP と MAC は n＋1 組になる（実際の n 組＋仮想の1組）
- 例：R1＝10.1.10.2、R2＝10.1.10.3、仮想 IP＝10.1.10.1（PC のゲートウェイ）

#### 仮想 MAC アドレス（かそうまっくあどれす / virtual MAC address）

- 意味：仮想 IP に対応する MAC アドレス。PC が仮想 IP の ARP を出すと、この MAC が返る
- ポイント：ルーターが切り替わっても仮想 MAC は変わらないので、PC の ARP 表を直す必要がない。プロトコルごとに形が決まっている（HSRPv1＝0000.0c07.acXX、VRRP＝0000.5e00.01XX、GLBP＝0007.b400.XXYY）
- 例：`Active virtual MAC address is 0000.0c07.ac01`

#### 仮想ルーター（かそうるーたー / virtual router）

- 意味：仮想 IP と仮想 MAC で表される、実際には存在しない1台のルーター。グループのルーターが協力してこの1台を演じる
- ポイント：PC から見ると、ゲートウェイは仮想ルーター1台だけ。実際にパケットを転送するのは、その時点でアクティブ（VRRP ではマスター）のルーター

## 15-2 HSRP

### まとめ表

| 項目 | HSRP の値 |
| :-: | :-: |
| 作ったところ | Cisco 独自（RFC 2281 で公開） |
| 役割 | アクティブ（転送する）1台、スタンバイ（待つ）1台、ほかは Listen |
| 優先度 | 1〜255、初期値 100。大きいほうがアクティブ |
| 同点のとき | インタフェースの IP アドレスが大きいほう |
| プリエンプト | 初期値は無効（standby preempt で有効に） |
| Hello／Hold | 3 秒／10 秒 |
| 宛先 | v1：224.0.0.2、v2：224.0.0.102（UDP 1985） |
| 仮想 MAC | v1：0000.0c07.acXX（XX＝グループ番号、16進数） |
| グループ番号 | v1：0〜255 |

### 役割と選び方

#### HSRP（えいちえすあーるぴー / Hot Standby Router Protocol）

- 意味：Cisco の FHRP。グループの中から1台をアクティブに選び、仮想 IP と仮想 MAC で PC のパケットを転送させる。アクティブが落ちるとスタンバイが引き継ぐ
- ポイント：1つのグループで転送するのはアクティブ1台だけ（スタンバイは待つだけ）。両方を使いたいなら、グループを2つ作って VLAN ごとにアクティブを分ける
- 例：`standby 1 ip 10.1.10.1`
- 語の意味：Hot Standby＝すぐ代われる予備

#### アクティブルーター（あくてぃぶるーたー / active router）

- 意味：HSRP のグループで、仮想 IP・仮想 MAC 宛てのパケットを実際に転送しているルーター
- ポイント：優先度がいちばん大きいルーター。同じならインタフェースの IP アドレスが大きいほう。PC からの ARP に仮想 MAC で答えるのもアクティブ
- 例：`State is Active`

#### スタンバイルーター（すたんばいるーたー / standby router）

- 意味：アクティブが落ちたときに引き継ぐ予備のルーター。ふだんは転送しない
- ポイント：アクティブの Hello が Hold 時間（初期値 10 秒）届かなくなるとアクティブになる。そのとき、残りから新しいスタンバイを選ぶ。3台目以降は Listen 状態で待つ
- 例：`Standby router is 10.0.0.2, priority 90`

#### HSRP の優先度（えいちえすあーるぴーのゆうせんど / HSRP priority）

- 意味：アクティブを選ぶための値。1〜255、初期値は 100。大きいほうがアクティブになりやすい
- ポイント：同じなら IP アドレスが大きいほう。ただし、すでにアクティブがいる場合、優先度が大きいルーターが来ても、プリエンプトが有効でないと交代しない
- 例：`standby 1 priority 110`

#### プリエンプト（ぷりえんぷと / preempt）

- 意味：自分の優先度が今のアクティブより大きいとき、アクティブの役を奪い取る（交代させる）設定
- ポイント：HSRP では初期値は無効なので、standby preempt を入れないと、優先度が大きくてもアクティブにならない。直ったルーターをアクティブに戻したいとき（元に戻す設計）に使う。VRRP は初期値で有効
- 例：`standby 1 preempt`／`standby 1 preempt delay minimum 60`

#### standby track（すたんばいとらっく / standby track）

- 意味：別のインタフェース（例：WAN 側）を見張り、それが落ちたら自分の HSRP の優先度を下げる設定。初期値は 10 下げる
- ポイント：LAN 側は生きていても WAN 側が切れたルーターがアクティブのままだと、パケットを外へ出せない。優先度を下げてスタンバイ側（プリエンプト有効）に交代させる
- 例：`standby 1 track GigabitEthernet0/0 20`

### タイマーと状態

#### HSRP の Hello と Hold（はろーとほーるど / hello time, hold time）

- 意味：Hello＝HSRP のルーターが生きていることを知らせる間隔（初期値 3 秒）。Hold＝この時間 Hello が来なければ相手が落ちたとみなす時間（初期値 10 秒）
- ポイント：OSPF の Hello 10・Dead 40 と取り違えないこと。HSRP は 3 と 10
- 例：`Hello time 3 sec, hold time 10 sec`

#### HSRP の状態（えいちえすあーるぴーのじょうたい / HSRP states）

- 意味：Init（まだ動いていない）→ Learn（仮想 IP を知らない）→ Listen（Hello を聞いている）→ Speak（Hello を送って選出に参加）→ Standby → Active
- ポイント：選出に参加するのは Speak から。アクティブ1台とスタンバイ1台が決まると、残りは Listen で待つ
- 例：`State is Active`

#### HSRP のバージョン（えいちえすあーるぴーのばーじょん / HSRPv1, HSRPv2）

- 意味：v1 は初期値で、Hello を 224.0.0.2 に送り、グループ番号は 0〜255。v2 は 224.0.0.102 に送り、IPv6 にも使う
- ポイント：v1 と v2 は同じインタフェースで混ぜられない（相手と同じバージョンにする）。HSRP for IPv6 は v2 が必要
- 例：`standby version 2`

#### HSRP の仮想 MAC（えいちえすあーるぴーのかそうまっく / HSRP virtual MAC 0000.0c07.acXX）

- 意味：HSRPv1 の仮想 MAC は 0000.0c07.acXX で、XX はグループ番号の16進数
- ポイント：グループ 1 なら 0000.0c07.ac01、グループ 10 なら 0000.0c07.ac0a。show standby の Active virtual MAC address で確かめる
- 例：`0000.0c07.ac01`

#### show standby（しょーすたんばい / show standby）

- 意味：HSRP の状態を表示するコマンド。状態・仮想 IP・仮想 MAC・Hello と Hold・プリエンプト・アクティブとスタンバイ・優先度が分かる
- ポイント：show standby brief なら1行ずつ（Interface・Grp・Pri・P・State・Active・Standby・Virtual IP）。P はプリエンプトが有効という印
- 例：

```
Vlan10 - Group 1
  State is Active
  Virtual IP address is 10.1.10.1
  Active virtual MAC address is 0000.0c07.ac01
  Hello time 3 sec, hold time 10 sec
  Preemption enabled
  Active router is local
  Standby router is 10.1.10.3, priority 100
  Priority 110 (configured 110)
```

#### HSRP による負荷分散（えいちえすあーるぴーによるふかぶんさん / MHSRP load sharing）

- 意味：HSRP のグループを2つ以上作り、グループ（VLAN）ごとにアクティブを別のルーターにして、2台とも転送に使うこと
- ポイント：1つのグループでは1台しか転送しないので、この方法で両方を使う。PC のゲートウェイはグループごとに違う仮想 IP になる。直ったときに元の分担に戻すため、プリエンプトを有効にする
- 例：VLAN 10＝R1 がアクティブ、VLAN 20＝R2 がアクティブ

## 15-3 VRRP と GLBP

### まとめ表

| 項目 | HSRP | VRRP | GLBP |
| :-: | :-: | :-: | :-: |
| 作ったところ | Cisco 独自 | 標準（RFC 5798） | Cisco 独自 |
| 転送する役 | アクティブ1台 | マスター1台 | AVF 最大4台（AVG が割り振る） |
| 待つ役 | スタンバイ | バックアップ | ― |
| 1グループで負荷分散 | できない | できない | できる |
| 優先度の初期値 | 100 | 100 | 100 |
| プリエンプトの初期値 | 無効 | 有効 | AVG は無効 |
| 宛先 | 224.0.0.2（v1）・224.0.0.102（v2） | 224.0.0.18 | 224.0.0.102 |
| 仮想 MAC | 0000.0c07.acXX | 0000.5e00.01XX | 0007.b400.XXYY |
| 仮想 IP | インタフェースと別のアドレス | 実アドレスと同じにもできる | インタフェースと別のアドレス |

### VRRP

#### VRRP（ぶいあーるあーるぴー / Virtual Router Redundancy Protocol）

- 意味：IETF の標準の FHRP（RFC 5798 が VRRPv3）。マスターが仮想ルーターのアドレスで転送し、マスターが落ちるとバックアップが引き継ぐ
- ポイント：考え方は HSRP とほぼ同じで、呼び名が「アクティブ→マスター」「スタンバイ→バックアップ」。標準なので、Cisco 以外の機器と組める。プリエンプトは初期値で有効
- 語の意味：Virtual Router＝仮想ルーター／Redundancy＝冗長

#### マスターとバックアップ（ますたーとばっくあっぷ / master, backup）

- 意味：VRRP で、仮想ルーターとして転送するルーターがマスター、マスターが落ちたときに引き継ぐのがバックアップ
- ポイント：HSRP の「アクティブとスタンバイ」にあたる。優先度（初期値 100）が大きいほうがマスター。仮想 IP を自分の実際のアドレスとして持つルーター（アドレスの持ち主）は優先度 255 で、必ずマスターになる

#### VRRP のアドレス（ぶいあーるあーるぴーのあどれす / VRRP addresses）

- 意味：VRRP の広告は 224.0.0.18 宛てに送る（IP プロトコル番号 112）。IPv4 の仮想 MAC は 0000.5e00.01XX（XX は VRID＝グループ番号）
- ポイント：HSRP の 224.0.0.2・0000.0c07.acXX と区別して覚える。MAC の形を見ればどの FHRP かが分かる
- 例：VRID 10 → 0000.5e00.010a

### GLBP

#### GLBP（じーえるびーぴー / Gateway Load Balancing Protocol）

- 意味：Cisco の FHRP。1つの仮想 IP に対して最大4つの仮想 MAC を使い分け、グループの何台ものルーターに転送を分担させる
- ポイント：HSRP・VRRP は1グループで1台しか転送しないが、GLBP は1つのグループ（1つのゲートウェイのアドレス）のまま負荷分散できる。Hello は 3 秒ごとに 224.0.0.102 の UDP 3222 へ
- 語の意味：Gateway＝ゲートウェイ／Load Balancing＝負荷分散

#### AVG（えーぶいじー / Active Virtual Gateway）

- 意味：GLBP のグループで1台だけ選ばれる、まとめ役のルーター。各メンバーに仮想 MAC を割り当て、PC からの ARP に答える
- ポイント：ARP の答えに、PC ごとに違う仮想 MAC を返すことで負荷を分ける。AVG が落ちると別のメンバーが AVG を引き継ぐ
- 語の意味：Active＝動いている／Virtual Gateway＝仮想ゲートウェイ

#### AVF（えーぶいえふ / Active Virtual Forwarder）

- 意味：GLBP で、AVG から割り当てられた仮想 MAC 宛てのパケットを転送するルーター。1グループに最大4台
- ポイント：AVG 自身も AVF になる。ある AVF が落ちると、ほかの AVF がその仮想 MAC も引き受けるので、その MAC を覚えている PC も外へ出られる
- 例：R1＝0007.b400.0101 の AVF、R2＝0007.b400.0102 の AVF

### 15-1 FHRP の目的

#### 問 ccna-15-o01

- 問：FHRP が解決する問題として正しいものはどれか。
- ア：PC のデフォルトゲートウェイのルーターが落ちると、PC が LAN の外へ出られなくなる
- イ：ルーターどうしの経路の交換が遅い
- ウ：スイッチの間でループが起きる
- エ：PC に IP アドレスを自動で配れない
- 正解：ア
- 解説：PC はデフォルトゲートウェイを1つしか持てず、自分で切り替えられない。FHRP は何台かのルーターで仮想のゲートウェイを共有し、1台が落ちても別のルーターが引き継ぐ。
- アの意味：正しい。
- イの意味：OSPF などのルーティングプロトコルの話。
- ウの意味：スパニングツリーが解決する問題。
- エの意味：DHCP が解決する問題。
- 出典：オリジナル問題（根拠：Cisco IP Addressing Services Configuration Guide IOS XE 17.9（Catalyst 9300）「HSRP Overview」（providing first-hop redundancy for IP hosts on an IEEE 802 LAN configured with a default gateway IP address））

#### 問 ccna-15-o02

- 問：R1（10.1.10.2）と R2（10.1.10.3）で HSRP を組み、仮想 IP を 10.1.10.1 にした。PC のデフォルトゲートウェイに設定するアドレスはどれか。
- ア：10.1.10.2
- イ：10.1.10.3
- ウ：10.1.10.1
- エ：10.1.10.2 と 10.1.10.3 の両方
- 正解：ウ
- 解説：PC には仮想 IP を設定する。どちらのルーターがアクティブでも、仮想 IP は同じなので PC の設定を変えなくてよい。
- アの意味：R1 の実アドレス。R1 が落ちると使えなくなる。
- イの意味：R2 の実アドレス。
- ウの意味：正しい。
- エの意味：PC のデフォルトゲートウェイは1つ。
- 出典：オリジナル問題（根拠：Cisco IOS XE 17.9「HSRP Overview」（Instead of configuring hosts … with the IP address of Router A, you configure them with the IP address of the virtual router as their default router））

#### 問 ccna-15-o03

- 問：HSRP でアクティブのルーターが R1 から R2 に切り替わったとき、PC の ARP 表を書き換える必要がない理由はどれか。
- ア：PC が自動で R2 の実 MAC を調べ直すから
- イ：R2 が PC の設定を書き換えるから
- ウ：HSRP は ARP を使わないから
- エ：仮想 IP に対応する仮想 MAC が、切り替わっても同じだから
- 正解：エ
- 解説：新しいアクティブは、同じ仮想 IP と仮想 MAC を引き継ぐ。PC は同じ MAC 宛てに送り続ければよい。
- アの意味：調べ直す必要がない。
- イの意味：ルーターが PC の設定を変えることはない。
- ウの意味：PC は仮想 IP の MAC を ARP で調べる。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：Cisco IOS XE 17.9「HSRP Overview」（the standby router … assumes control of the group MAC address and IP address））

#### 問 ccna-15-o04

- 問：3台のルーターで HSRP のグループを1つ作った。このセグメントで使われる IP アドレスと MAC アドレスは何組か。
- ア：3組
- イ：1組
- ウ：4組
- エ：6組
- 正解：ウ
- 解説：各ルーターの実際の IP と MAC が3組、仮想ルーターの IP と MAC が1組で、合わせて n＋1＝4組。
- アの意味：仮想の1組を数えていない。
- イの意味：仮想の分だけ。
- ウの意味：正しい。
- エの意味：数えすぎ。
- 出典：オリジナル問題（根拠：Cisco IOS XE 17.9「HSRP Overview」（For n routers running HSRP, there are n +1 IP and MAC addresses assigned））

#### 問 ccna-15-o05

- 問：FHRP の種類のうち、IETF の標準のものはどれか。
- ア：HSRP
- イ：VRRP
- ウ：GLBP
- エ：CDP
- 正解：イ
- 解説：VRRP は RFC で決められた標準。HSRP と GLBP は Cisco 独自。
- アの意味：Cisco 独自（RFC 2281 は情報として公開されたもの）。
- イの意味：正しい。
