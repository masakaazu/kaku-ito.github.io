## 22-1 脅威と脆弱性を見つける

### まとめ表

| 見つけたいもの | 使うもの |
| :-: | :-: |
| 不審な通信・認証情報の悪用・マイニング | GuardDuty |
| S3 からのデータの持ち出し | GuardDuty の S3 Protection |
| コンテナや OS の中の不審な動き | GuardDuty の Runtime Monitoring |
| EC2 のマルウェア | GuardDuty の Malware Protection for EC2 |
| ソフトウェアの脆弱性（CVE）・ネットワークの露出 | Amazon Inspector |
| 検出結果の根本原因を調べる | Amazon Detective |

### GuardDuty

#### Amazon GuardDuty（がーどでゅーてぃ / Amazon GuardDuty）

- 意味：CloudTrail の管理イベント・VPC フローログ・DNS ログなどを続けて分析し、脅威インテリジェンスと機械学習で脅威を見つけるサービス
- ポイント：これらのログを自分で有効にしなくても、GuardDuty が独立して取り込む。リージョンごとに有効にする

#### GuardDuty の委任管理者（いにんかんりしゃ / GuardDuty delegated administrator）

- 意味：組織の管理アカウントが指定する、組織全体の GuardDuty を管理するアカウント
- ポイント：メンバーアカウントの有効化を自動にでき、新しいアカウントにも効く。設定はリージョンごと

#### 保護プラン（ほごぷらん / GuardDuty protection plans）

- 意味：基本の検出に足す機能。S3 Protection（S3 のデータイベントで持ち出しなどを検出）・EKS Protection・Runtime Monitoring（エージェントで OS やコンテナの中を見る）・Malware Protection（EBS のスキャン）・RDS Protection・Lambda Protection など
- ポイント：何を見たいかで選ぶ。中の動きは Runtime Monitoring、ファイルのマルウェアは Malware Protection

#### 抑制ルール（よくせいるーる / suppression rule）

- 意味：条件に合う新しい検出結果を自動でアーカイブするルール
- ポイント：脆弱性スキャナーなど、わかっている正当な動きの誤検出を減らす。検出はされ続けるので後から見られる

#### GuardDuty と EventBridge（いべんとぶりっじ / GuardDuty findings in EventBridge）

- 意味：GuardDuty の検出結果は自動で EventBridge にイベントとして送られる
- ポイント：ルールで重要度などを絞り、SNS で通知したり、Lambda や Step Functions で隔離などの対応を自動にしたりする

#### InstanceCredentialExfiltration（いんすたんすくれでんしゃるえくすふぃるとれーしょん / InstanceCredentialExfiltration）

- 意味：EC2 のインスタンスロールの一時的な認証情報が、別のアカウントや AWS の外から使われたことを示す GuardDuty の検出結果
- ポイント：認証情報が盗まれた疑い。ロールのセッションを取り消し、インスタンスを調べる

### 脆弱性と調査

#### Amazon Inspector（いんすぺくたー / Amazon Inspector）

- 意味：EC2・ECR のコンテナイメージ・Lambda のソフトウェアの脆弱性と、意図しないネットワークの露出を続けてスキャンするサービス
- ポイント：新しいパッケージのインストールや新しい CVE の公開で自動で再スキャンする。EC2 は SSM Agent か、エージェントなしで EBS スナップショットを使うハイブリッドモードでスキャンする

#### Amazon Detective（でぃてくてぃぶ / Amazon Detective）

- 意味：ログを自動で集め、機械学習・統計・グラフで、検出結果や不審な動きの根本原因を調べやすくするサービス
- ポイント：GuardDuty は「見つける」、Detective は「調べる」

## 22-2 まとめて見て自動で対応する

### まとめ表

| やりたいこと | 使うもの |
| :-: | :-: |
| 検出結果を 1 か所に集め、標準で点検する | Security Hub（ASFF） |
| 全リージョンの結果を 1 つのリージョンで見る | クロスリージョン集約（ホームリージョン） |
| 組織全体の設定を 1 か所で決める | 中央設定 |
| いろいろなセキュリティのログを長く貯めて分析 | Security Lake（OCSF） |
| 全アカウントの Config の準拠状況 | Config のアグリゲータ |
| 結果に自動で対応する | EventBridge のルール |

### Security Hub

#### AWS Security Hub（せきゅりてぃはぶ / AWS Security Hub CSPM）

- 意味：GuardDuty・Inspector・Macie・Config などの検出結果を集め、セキュリティ標準のコントロールで設定を点検するサービス
- ポイント：標準を有効にするとそのコントロールが自動で有効になる。AWS 基礎セキュリティのベストプラクティス・CIS などがある。Config を有効にしておく必要がある

#### ASFF（えーえすえふえふ / AWS Security Finding Format）

- 意味：Security Hub が検出結果を扱う標準の JSON の形式
- ポイント：自作のツールの結果も ASFF にして BatchImportFindings で取り込める

#### クロスリージョン集約（くろすりーじょんしゅうやく / cross-Region aggregation）

- 意味：リンクしたリージョンの検出結果を、ホームリージョン（旧称は集約リージョン）に集めて見るしくみ
- 例：バージニア北部をホームリージョンに、オレゴンなどをリンクされたリージョンにする

#### 中央設定（ちゅうおうせってい / central configuration）

- 意味：Organizations と統合し、委任管理者から組織のアカウント・OU・リージョンにまたがって Security Hub の有効化・標準・コントロールを設定する機能
- ポイント：アカウントごとに設定して回らなくてよい

### 集める・対応する

#### Amazon Security Lake（せきゅりてぃれいく / Amazon Security Lake）

- 意味：AWS・SaaS・オンプレミスなどのセキュリティのログを、自分のアカウントの S3 のデータレイクに集めるサービス。OCSF の形式と Parquet に変換する
- ポイント：長く貯めて分析するための場所。リアルタイムの点検は Security Hub
- 語の意味：OCSF＝Open Cybersecurity Schema Framework、セキュリティのデータの共通の形

#### Config のアグリゲータ（あぐりげーた / AWS Config aggregator）

- 意味：複数のアカウントとリージョンの Config の設定と準拠のデータを 1 か所に集めるもの
- ポイント：組織全体を指定できる。集めたデータは見るだけで、ルールの評価はそれぞれのアカウントで行う

#### 侵害された認証情報への対応（しんがいされたにんしょうじょうほう / remediating compromised credentials）

- 意味：GuardDuty の IAM の検出結果などで認証情報の悪用が疑われたとき、関係する IAM エンティティと使われた API を特定し、権限を確かめ、正当でなければキーを無効にしてローテーションする
- ポイント：AWS が公開されたキーを見つけると、IAM ユーザーに AWSCompromisedKeyQuarantineV3 を付けて一部の操作を拒否し、AWS Health で知らせる

## 22-3 監査のための記録と証拠

### まとめ表

| やりたいこと | 使うもの |
| :-: | :-: |
| 組織の全アカウントの操作を記録 | 組織の証跡 |
| ログが変えられていないことを示す | ログファイルの整合性の検証 |
| ルートのサインインなどをすぐ知らせる | CloudTrail → CloudWatch Logs のメトリクスフィルター＋アラーム |
| テンプレートと違う設定を見つける | CloudFormation のドリフト検出 |
| 監査の証拠を自動で集める | AWS Audit Manager |
| AWS の SOC・ISO などのレポート | AWS Artifact |

### 記録と証拠

#### 組織の証跡（そしきのしょうせき / organization trail）

- 意味：組織の管理アカウント（または委任管理者）が作る、管理アカウントとすべてのメンバーアカウントのイベントを記録する証跡
- ポイント：メンバーアカウントは止めたり消したりできない。新しいアカウントも自動で入る

#### ログファイルの整合性の検証（せいごうせいのけんしょう / log file integrity validation）

- 意味：CloudTrail が配ったログファイルが、あとで変えられたり消されたりしていないかを確かめる機能。SHA-256 のハッシュと RSA の署名のダイジェストファイルを使う
- ポイント：監査で「ログが改ざんされていない」ことを示すのに使う。さらに守るなら S3 の Object Lock

#### CloudTrail のアラーム（くらうどとれいるのあらーむ / CloudTrail metric filter alarm）

- 意味：証跡を CloudWatch Logs に送り、メトリクスフィルターで特定のイベント（ルートのサインイン・IAM ポリシーの変更など）を数えてアラームにする
- ポイント：EventBridge のルールで CloudTrail のイベントを受けて通知する方法もある

#### ドリフト検出（どりふとけんしゅつ / drift detection）

- 意味：CloudFormation で管理しているリソースが、スタックの外で変えられて、テンプレートと違っていないかを調べる機能
- ポイント：手で開けられたセキュリティグループなどを見つける

#### AWS Audit Manager（おーでぃっとまねーじゃー / AWS Audit Manager）

- 意味：AWS の使い方を続けて監査し、規制や標準のコントロールの証拠を自動で集めて、監査用のレポートにするサービス
- ポイント：「証拠を集める」のが役目。設定の点検は Security Hub や Config

#### AWS Artifact（あーてぃふぁくと / AWS Artifact）

- 意味：AWS の SOC レポート・ISO・PCI などのセキュリティとコンプライアンスの文書を必要なときにダウンロードできるサービス
- ポイント：AWS 側の統制の証明。自分の環境の監査の証拠は Audit Manager

- ア：GuardDuty の Malware Protection for EC2
- イ：Amazon Inspector
- ウ：Amazon Macie
- エ：Amazon Detective
- 正解：ア
- 解説：Malware Protection for EC2 は EBS ボリュームのスナップショットを使ってエージェントなしでスキャンする。マルウェアが見つかればスナップショットを残せる。
- アの意味：正しい。
- イの意味：ソフトの脆弱性を調べるもので、マルウェアは見ない。
- ウの意味：S3 の機密データ。
- エの意味：調査のためのもので、スキャンはしない。
- 出典：オリジナル問題（根拠：AWS「Amazon GuardDuty ユーザーガイド」GuardDuty Malware Protection for EC2（『スナップショットは、マルウェアが検出されて Malware Protection for EC2 の検出結果が生成された場合にのみ保持されます。』））

#### 問 dop-22-o29

- 問：Amazon Inspector は、いつリソースを調べ直すか。
- ア：月に 1 回、手で始めたとき
- イ：アカウントを作ったときだけ
- ウ：新しいパッケージのインストールや新しい CVE の公開などの変化に応じて自動で
- エ：インスタンスを止めている間だけ
- 正解：ウ
- 解説：Inspector は新しい脆弱性につながる変化に応じて自動で再スキャンし、続けて評価する。
- アの意味：自動で続けて調べる。
- イの意味：続けて調べる。
- ウの意味：正しい。
- エの意味：動いているリソースを調べる。
- 出典：オリジナル問題（根拠：AWS「Amazon Inspector ユーザーガイド」Amazon Inspector とは（『Amazon Inspector は、EC2 インスタンスへの新しいパッケージのインストール、パッチのインストール、リソースに影響を与える新しい共通脆弱性識別子 (CVE) が発行された場合など、新しい脆弱性をもたらす可能性のある変更に対応してリソースを自動的に再スキャンすることで、リソースのライフサイクル全体を通じて引き続き環境を評価します。』））

#### 問 dop-22-o30

- 問：Security Hub の結果のうち、重要度 CRITICAL のものだけを自動で SNS に送り、チケットも作りたい。どうするか。
- ア：Security Hub のダッシュボードを毎日見る
- イ：EventBridge のルールで重要度が CRITICAL の結果を選び、SNS と Lambda をターゲットにする
- ウ：Security Hub の標準を無効にする
- エ：結果を CSV で出す
- 正解：イ
- 解説：Security Hub の結果は EventBridge に送られるので、ルールで選んで自動で対応できる。
- アの意味：自動にならない。
- イの意味：正しい。
- ウの意味：点検が止まる。
- エの意味：自動にならない。
- 出典：オリジナル問題（根拠：AWS「AWS Security Hub ユーザーガイド」EventBridge を使用した自動応答と修復（『Amazon EventBridge でルールを作成することで、 AWS Security Hub CSPM の検出結果に自動的に応答できます。』））
