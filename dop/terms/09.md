## 09-1 マネージドノードと接続

### まとめ表

| マネージドノードになる条件 | 中身 |
| :-: | :-: |
| SSM Agent | 多くの AWS の AMI には入っている。オンプレミスは自分で入れる |
| 権限 | インスタンスプロファイル（AmazonSSMManagedInstanceCore）か DHMC。オンプレミスはハイブリッドアクティベーション |
| 通信 | インターネットへの出口（NAT）か、VPC エンドポイント（ssm・ssmmessages・ec2messages） |

### ノードを管理下に置く

#### AWS Systems Manager（しすてむずまねーじゃー / AWS Systems Manager）

- 意味：EC2・オンプレミス・他のクラウドのノードや AWS のリソースを、まとめて見て、操作し、自動化するサービス
- ポイント：Session Manager・Run Command・State Manager・Automation・Patch Manager・Inventory・Parameter Store・OpsCenter などの「ツール」の集まり。ノードを SSH なしで大規模に管理できる

#### SSM Agent（えすえすえむえーじぇんと / SSM Agent）

- 意味：ノードに入れて、Systems Manager からの要求を処理するソフトウェア
- ポイント：Systems Manager のエンドポイントに出ていく通信（HTTPS 443）で動くので、インバウンドのポートは要らない。ssmmessages を使って状態や結果を返す。Amazon Linux など多くの AMI には最初から入っている

#### マネージドノード（まねーじどのーど / managed node）

- 意味：Systems Manager で管理できるように設定したマシン（EC2 インスタンス・オンプレミスのサーバー・VM・エッジデバイス）
- ポイント：EC2 は SSM Agent ＋ 権限（AmazonSSMManagedInstanceCore を含むインスタンスプロファイル）＋ エンドポイントへの経路が要る。フリートマネージャーで一覧が見られない＝この 3 つのどれかが欠けている

#### Default Host Management Configuration（DHMC）（でふぉるとほすとまねじめんと / Default Host Management Configuration）

- 意味：アカウントとリージョンで有効にすると、インスタンスプロファイルを手で作らなくても EC2 インスタンスを Systems Manager で管理できる設定
- ポイント：インスタンスメタデータサービス v2（IMDSv2）が要る。大量のインスタンスにインスタンスプロファイルを付け直す手間をなくす

#### ハイブリッドアクティベーション（はいぶりっどあくてぃべーしょん / hybrid activation）

- 意味：オンプレミスのサーバーや他のクラウドの VM・エッジデバイスに SSM Agent を入れ、アクティベーションのコードと ID で Systems Manager に登録する手順
- ポイント：登録したノードは mi- で始まる ID になる。EC2 と同じように Run Command・Patch Manager などを使える。IAM サービスロールを指定する

#### Systems Manager の VPC エンドポイント（ぶいぴーしーえんどぽいんと / VPC endpoints for Systems Manager）

- 意味：インターネットへの出口がないプライベートサブネットのインスタンスを、AWS PrivateLink で Systems Manager につなぐためのインターフェイスエンドポイント
- ポイント：com.amazonaws.リージョン.ssm・ssmmessages・ec2messages の 3 つが基本。Session Manager のログを S3 や CloudWatch Logs に出すなら s3（ゲートウェイ）や logs、KMS で暗号化するなら kms も要る

### 安全に入る

#### Session Manager（せっしょんまねーじゃー / Session Manager）

- 意味：インバウンドのポートを開けず、踏み台ホストも SSH キーもなしで、ノードにシェルで入れる Systems Manager のツール
- ポイント：アクセスは IAM ポリシーで制御する。ポートフォワーディング（RDS に手元からつなぐなど）もできる。セッションの操作は CloudTrail に記録される
- 例：踏み台サーバーを廃止し、SG のインバウンドの 22 番を閉じる

#### セッションログ（せっしょんろぐ / session logging）

- 意味：Session Manager のセッションでの入出力を、S3 や CloudWatch Logs に記録する設定
- ポイント：監査のためにセッションの中で何をしたかを残す。インスタンスプロファイルに S3・CloudWatch Logs への書き込み権限が要る。KMS でセッションを暗号化できる

## 09-2 実行と構成の自動化

### まとめ表

| ツール | いつ | 何を | 例 |
| :-: | :-: | :-: | :-: |
| Run Command | 今すぐ 1 回 | ノードにコマンド | 全 Web サーバーでログを集める |
| State Manager | 決まった間隔で繰り返し | ノードやリソースを決めた状態に保つ | CloudWatch エージェントを常に入れておく |
| Automation | 必要なとき・イベントで | AWS のリソースを含む手順（ランブック） | AMI を作る、S3 の公開を直す |
| Maintenance Windows | 決めた時間枠 | 止まりうる作業 | 毎週日曜 2 時にパッチ |

### ドキュメントと実行

#### SSM ドキュメント（えすえすえむどきゅめんと / SSM document）

- 意味：Systems Manager がノードやリソースで行う動作を定義した JSON・YAML のドキュメント
- ポイント：Command（Run Command・State Manager 用）・Automation（ランブック）・Session などの種類がある。AWS が用意した AWS- で始まるもの（AWS-RunShellScript・AWS-RunPatchBaseline など）と、自作のものがある。他のアカウントと共有できる

#### Run Command（らんこまんど / Run Command）

- 意味：マネージドノードで、コマンドを安全に、リモートで、一度にたくさん実行する Systems Manager のツール
- ポイント：一度だけの設定変更や管理作業に使う。タグでノードを選び、同時実行数とエラーのしきい値で、少しずつ進めて失敗が増えたら止められる。出力は S3 や CloudWatch Logs に残せる

#### State Manager（すてーとまねーじゃー / State Manager）

- 意味：マネージドノードや他の AWS リソースを、決めた状態に保つことを自動化する設定管理のツール
- ポイント：関連付け（association）で、ドキュメントとターゲットとスケジュールを決める。設定のずれを直し続けたいときに使う（Run Command は 1 回だけ）。新しく起動したインスタンスにも自動でかかる

#### Automation（おーとめーしょん / Automation）

- 意味：EC2・RDS・S3 などの AWS のサービスの、メンテナンス・デプロイ・修復の作業を、ランブック（Automation ドキュメント）で自動化する Systems Manager のツール
- ポイント：AWS が用意したランブック（AWS-RestartEC2Instance・AWS-UpdateLinuxAmi など）と自作のものがある。aws:executeScript で Python・PowerShell も動かせる。EventBridge や Config の自動修復から呼ばれる

#### レート制御（れーとせいぎょ / rate control）

- 意味：同時実行の数（同時に処理するターゲットの数）と、エラーのしきい値（ここまで失敗したら止める）で、フリートへの実行の進み方を決める設定
- ポイント：Run Command と Automation で使う。例 同時実行 10%・エラー 5% → 少しずつ進めて、失敗が続けば止まる

#### 承認ステップ（しょうにんすてっぷ / aws:approve）

- 意味：ランブックの中で、指定した承認者が承認・拒否するまでオートメーションを止めておくアクション
- ポイント：承認者（ユーザー名・ARN）を少なくとも 1 人書く。SNS で承認の依頼を送れる。本番の再起動の前に人の確認を入れる

#### Maintenance Windows（めんてなんすうぃんどう / Maintenance Windows）

- 意味：パッチの適用やソフトの更新など、ノードを止めるかもしれない作業を行う時間枠（スケジュール）を決めるツール
- ポイント：時間枠・ターゲット・タスク（Run Command・Automation・Lambda・Step Functions）を登録する。業務への影響を時間で絞りたいときは Maintenance Windows、状態を保ち続けたいときは State Manager

#### Distributor（でぃすとりびゅーたー / Distributor）

- 意味：ソフトウェアをパッケージにしてマネージドノードに公開・配布する Systems Manager のツール
- ポイント：AmazonCloudWatchAgent など AWS のパッケージや、自作・サードパーティーのパッケージを配る。State Manager と組み合わせて入れ続ける

## 09-3 パッチと可視化

### まとめ表

| 道具 | 役目 |
| :-: | :-: |
| パッチベースライン | どのパッチを承認・拒否するか（自動承認の日数・重要度） |
| パッチポリシー（Quick Setup） | 組織・リージョンをまたいでパッチの設定を配る（推奨） |
| AWS-RunPatchBaseline | Scan（報告だけ）／Install（入れる） |
| インベントリ | ノードのソフト・設定のメタデータを集める |
| Compliance | パッチと State Manager の準拠状況を見る |
| OpsCenter | 運用の問題（OpsItem）を一か所で調べて直す |

### パッチ

#### Patch Manager（ぱっちまねーじゃー / Patch Manager）

- 意味：マネージドノードに、セキュリティ更新などのパッチを当てる作業を自動化する Systems Manager のツール
- ポイント：Scan（足りないパッチを報告するだけ）と Scan and install（足りないパッチを入れる）。中身は AWS-RunPatchBaseline ドキュメント。結果は Compliance で見る

#### パッチベースライン（ぱっちべーすらいん / patch baseline）

- 意味：どのパッチをノードに入れてよいか（承認）・入れないか（拒否）を決めるルール
- ポイント：OS ごとに AWS の事前定義のベースライン（変更できない）がある。細かく決めたいときはカスタムのベースラインを作る。例「重要度が Critical のセキュリティ更新は、公開から 7 日後に自動承認」

#### パッチポリシー（ぱっちぽりしー / patch policy）

- 意味：Quick Setup で作る、パッチの設定（ベースライン・スケジュール・Scan か Install か）を、組織のアカウントとリージョンにまとめてかける設定
- ポイント：パッチの設定のすすめられるやり方。パッチグループはパッチポリシーでは使わない（古いやり方）

#### パッチグループ（ぱっちぐるーぷ / patch group）

- 意味：Patch Group タグでノードをまとめ、パッチベースラインに結び付ける昔からのやり方
- ポイント：パッチポリシーのリリース（2022 年 12 月）より前に使っていたアカウントとリージョンでだけ使える。新しく作るならパッチポリシー

### 見える化と運用

#### インベントリ（いんべんとり / Inventory）

- 意味：マネージドノードから、入っているアプリ・ファイル・ネットワーク設定などのメタデータを集めて見えるようにする Systems Manager のツール
- ポイント：リソースデータの同期で S3 に集め、Athena で複数アカウント・リージョンのデータをまとめて調べられる
- 例：「OpenSSL のこの版が入っているノードはどれか」を一覧にする

#### Compliance（こんぷらいあんす / Compliance）

- 意味：マネージドノードのパッチの準拠状況と、State Manager の関連付けの準拠状況を見る Systems Manager のツール
- ポイント：準拠していないノードを見つける。Config の ssm 関連のルールや Security Hub とも連携する

#### OpsCenter（おぷすせんたー / OpsCenter）

- 意味：AWS リソースの運用の問題（OpsItem）を一か所で見て、調べて、直すための Systems Manager のツール
- ポイント：EventBridge・CloudWatch アラームなどから OpsItem を自動で作れる。関連するリソースやランブックがまとまるので、直すまでの時間を短くできる

#### Quick Setup（くいっくせっとあっぷ / Quick Setup）

- 意味：Systems Manager などのよく使う機能を、ベストプラクティスに沿って組織やアカウントにすばやく設定するツール
- ポイント：DHMC・パッチポリシー・インベントリの収集・CloudWatch エージェントなどを、組織の OU にまとめて設定できる

## 問題演習

### 09-1

#### 問 dop-09-o01

- 問：EC2 インスタンスを起動したが、Systems Manager のフリートマネージャーに表示されない。SSM Agent は入っており、NAT ゲートウェイもある。最も考えられる原因はどれか。
- ア：インスタンスのセキュリティグループで 22 番ポートが閉じている
- イ：インスタンスに AmazonSSMManagedInstanceCore を含むインスタンスプロファイルが付いていない（DHMC も無効）
- ウ：インスタンスにパブリック IP がない
- エ：インスタンスのタグがない
- 正解：イ
- 解説：マネージドノードになるには、SSM Agent・権限・Systems Manager のエンドポイントへの経路が要る。権限はインスタンスプロファイルか DHMC で渡す。
- アの意味：Systems Manager はインバウンドのポートを使わない。
- イの意味：正しい。
- ウの意味：NAT か VPC エンドポイントがあればパブリック IP は要らない。
- エの意味：タグがなくても管理対象にはなる。
- 出典：オリジナル問題（根拠：AWS「AWS Systems Manager ユーザーガイド」Default Host Management Configuration を使用した EC2 インスタンスの自動管理（『このような場合は、IAM インスタンスプロファイルを使用してインスタンスに必要なアクセス許可を付与するか、インスタンスを再作成する必要があります。』））

#### 問 dop-09-o02

- ア：ハイブリッドアクティベーション

- 正解：ウ
- 解説：DHMC を使うと、IAM インスタンスプロファイルを手で作らなくても EC2 インスタンスを管理できる。
- アの意味：オンプレミスなど EC2 以外のマシンを登録する手順。
- イの意味：危険で、すすめられない。
- ウの意味：正しい。
- エの意味：接続の方法で、管理下に置く設定ではない。
- 出典：オリジナル問題（根拠：AWS「AWS Systems Manager ユーザーガイド」Default Host Management Configuration を使用した EC2 インスタンスの自動管理（『デフォルトのホスト管理設定を使用し、AWS Identity and Access Management (IAM) インスタンスプロファイルを手動で作成しなくても EC2 インスタンスを管理できます。』））

- アの意味：正しい。

- 出典：オリジナル問題（根拠：AWS「AWS Systems Manager ユーザーガイド」Systems Manager を利用したハイブリッド環境およびマルチクラウド環境でのノードの管理（『ハイブリッドアクティベーション – SSM Agent を手動でインストールして各マシンをアクティブ化することで、任意の環境から個々のオンプレミスサーバー、エッジデバイス、VM を登録します。』））

#### 問 dop-09-o04

- 問：インターネットへの出口（NAT）がないプライベートサブネットのインスタンスを Systems Manager で管理し、Session Manager で入りたい。最低限必要な VPC エンドポイントはどれか。

- 問：踏み台ホストをなくし、セキュリティグループのインバウンドの 22 番を閉じたまま、運用者がインスタンスにシェルで入れるようにしたい。何を使うか。

#### 問 dop-09-o06

- 問：監査のため、Session Manager のセッションの中で運用者が打ったコマンドと出力を残したい。どうするか。
- ア：セッションログを有効にして、S3 や CloudWatch Logs に出す

- エ：インスタンスの /var/log/secure を見る
- 正解：ア
