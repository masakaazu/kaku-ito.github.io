## 08-1 AWS Organizations の構造

### まとめ表

| 部品 | 役目 |
| :-: | :-: |
| 管理アカウント | 組織を作ったアカウント。請求・ポリシー・アカウント管理。仕事のリソースは置かない |
| メンバーアカウント | ワークロードを動かすアカウント |
| ルート／OU | アカウントを階層でまとめ、ポリシーを付ける単位 |
| 信頼されたアクセス | AWS のサービスが組織全体で動けるようにする |
| 委任管理者 | 管理アカウントの代わりにサービスやポリシーを管理するメンバーアカウント |

### 組織の部品

#### AWS Organizations（おーがないぜーしょんず / AWS Organizations）

- 意味：複数の AWS アカウントを 1 つの組織にまとめ、一元的に管理・統制するサービス
- ポイント：一括請求（請求をまとめる）と、すべての機能（SCP などのポリシー）がある。SCP を使うには「すべての機能」を有効にする

#### 管理アカウント（かんりあかうんと / management account）

- 意味：組織を作ったアカウント。アカウントの作成・招待、ポリシー、一括請求、他のサービスとの統合を行う
- ポイント：SCP は管理アカウントには効かない。だから管理アカウントにはワークロードを置かず、使える人を絞る。日々の管理は委任管理者に任せる

#### 組織単位（OU）（そしきたんい / organizational unit）

- 意味：組織の中でアカウントを論理的にまとめる入れ物。階層にできる
- ポイント：ポリシーは OU に付けると、その下のアカウントに継承される。例 Security・Infrastructure・Workloads（Prod・SDLC）・Sandbox・Suspended・Policy Staging のように分ける
- 語の意味：OU＝Organizational Unit（組織の単位）

#### OrganizationAccountAccessRole（おーがないぜーしょんあかうんとあくせすろーる / OrganizationAccountAccessRole）

- 意味：組織でメンバーアカウントを新しく作ると、そのアカウントに自動で作られる IAM ロール。管理アカウントから引き受けて管理できる
- ポイント：招待で入れた既存のアカウントには自動では作られない（自分で作る）

#### 信頼されたアクセス（しんらいされたあくせす / trusted access）

- 意味：対応する AWS のサービス（Config・CloudTrail・Security Hub・GuardDuty など）が、組織とそのアカウントで代わりに作業できるようにする設定
- ポイント：有効・無効にするのは、できるだけそのサービスのコンソールや API から行う。組織の証跡（CloudTrail）や Config のアグリゲーターは、これでまとめられる

#### 委任管理者（いにんかんりしゃ / delegated administrator）

- 意味：管理アカウントの代わりに、ある AWS サービスや組織のポリシーを管理するように指定したメンバーアカウント
- ポイント：管理アカウントは必要な作業だけに使い、日々の管理はセキュリティ用などのアカウントに任せる。例 GuardDuty・Security Hub の委任管理者を監査アカウントにする

## 08-2 組織のポリシー

### まとめ表

| ポリシー | 対象 | すること |
| :-: | :-: | :-: |
| SCP | 組織内の IAM ユーザー・ロール | できることの上限（ガードレール）。許可は与えない |
| RCP | 組織内のリソース | 組織の外からのアクセスなど、リソース側の上限 |
| タグポリシー | リソースのタグ | タグのキー・値・大文字小文字をそろえる |
| バックアップポリシー | リソース | AWS Backup のプランを組織全体にかける |

### ポリシーの種類

#### サービスコントロールポリシー（SCP）（さーびすこんとろーるぽりしー / service control policy）

- 意味：組織内の IAM ユーザーとロールができることの上限（ガードレール）を決める組織のポリシー
- ポイント：SCP は許可を与えない（IAM ポリシーでの許可が別に要る）。管理アカウント・組織外のプリンシパル・サービスにリンクされたロールには効かない。リソースベースのポリシーには直接効かない
- 例：リージョンを東京と大阪だけに絞る、CloudTrail の停止を拒否する、ルートユーザーの操作を拒否する

#### SCP の評価（えすしーぴーのひょうか / SCP evaluation）

- 意味：あるアカウントで操作が許されるには、ルートからそのアカウントまでの各レベル（ルート・OU・アカウント）のすべてで、SCP が明示的に Allow していなければならないというルール
- ポイント：既定では FullAWSAccess がすべてのレベルに付いている。どこかのレベルで Allow がなければ拒否。Deny はどのレベルでも効く（拒否リストの戦略が一般的）

#### リソースコントロールポリシー（RCP）（りそーすこんとろーるぽりしー / resource control policy）

- 意味：組織のアカウントのリソース（S3・KMS・SQS など）に対して、できることの上限を決める組織のポリシー
- ポイント：組織の外の IAM プリンシパルがメンバーアカウントのリソースにアクセスするのを制限したいときに使う（データ境界）。SCP はプリンシパル側、RCP はリソース側

#### タグポリシー（たぐぽりしー / tag policy）

- 意味：組織のアカウントのリソースに付けるタグを標準化する組織のポリシー
- ポイント：キーの大文字小文字や使える値をそろえる。強制（enforced）にすると、合わないタグの付け方を止められるリソースもある。コスト配分やアクセス制御（ABAC）のためにタグをそろえる

#### バックアップポリシー（ばっくあっぷぽりしー / backup policy）

- 意味：AWS Backup のバックアッププランを、組織のアカウント全体に一元的にかける組織のポリシー
- ポイント：OU に付けると、その下のアカウントのリソースに同じバックアップの規則がかかる

## 08-3 Control Tower と共有のしくみ

### まとめ表

| コントロールの種類 | しくみ | タイミング |
| :-: | :-: | :-: |
| 予防 | SCP・RCP | 操作そのものを止める |
| 検出 | AWS Config ルール | 作られた後に違反を見つける |
| プロアクティブ | CloudFormation フック | 作る前にテンプレートを調べて止める |

### Control Tower

#### AWS Control Tower（こんとろーるたわー / AWS Control Tower）

- 意味：Organizations・Service Catalog・IAM Identity Center などをまとめて動かし、ベストプラクティスに沿ったマルチアカウントの環境（ランディングゾーン）を作り、統制し続けるサービス
- ポイント：ダッシュボードで、アカウント・有効なコントロール・違反しているリソースを見られる。自前で Organizations・Config・CloudTrail・SCP を組むより早い

#### ランディングゾーン（らんでぃんぐぞーん / landing zone）

- 意味：セキュリティとコンプライアンスのベストプラクティスに沿って設計した、複数アカウントの環境
- ポイント：Control Tower は、ログアーカイブアカウント（CloudTrail・Config のログを集める）と監査アカウント（セキュリティチームが使う）を作り、組織の CloudTrail と Config を設定する。サンドボックス OU なども作る

#### コントロール（ガードレール）（こんとろーる / controls）

- 意味：AWS 環境全体に続けて統制をかける高レベルのルール
- ポイント：予防（SCP で止める）・検出（Config ルールで見つける）・プロアクティブ（CloudFormation フックで作る前に止める）の 3 種類。必須・強く推奨・選択的の区分がある。予防コントロールは管理アカウントには効かない（SCP だから）

#### Account Factory（あかうんとふぁくとりー / Account Factory）

- 意味：Control Tower で、決まった設定（ネットワーク・コントロール・ポリシー）を持つアカウントを作成・登録するしくみ
- ポイント：Service Catalog の製品として提供される。新しいアカウントは自動でランディングゾーンの統制に入る

#### Account Factory for Terraform（AFT）（えーえふてぃー / Account Factory for Terraform）

- 意味：Control Tower のアカウントの作成とカスタマイズを、Terraform のパイプライン（GitOps）で行う仕組み
- ポイント：アカウントの依頼を Terraform のファイルで書き、リポジトリにプッシュすると作られる。アカウントごとのカスタマイズも Terraform で書く

#### Customizations for Control Tower（CfCT）（しーえふしーてぃー / Customizations for AWS Control Tower）

- 意味：CloudFormation テンプレートや SCP・RCP で、ランディングゾーンをカスタマイズする仕組み
- ポイント：Control Tower のライフサイクルイベント（新しいアカウントの作成など）と連動して、カスタマイズが自動でかかる

#### ドリフト（Control Tower）（どりふと / drift）

- 意味：Control Tower の外（Organizations のコンソールなど）で、OU やアカウント、SCP を変えて、ランディングゾーンの設定からずれた状態
- ポイント：ドリフトの検出は自動で行われる。例 Control Tower が管理する SCP を手で変えた、アカウントを OU の外に動かした。ランディングゾーンの修復（リセット）などで直す

### 共有とアクセス

#### AWS RAM（らむ / AWS Resource Access Manager）

- 意味：VPC のサブネット・Transit Gateway・Route 53 Resolver のルールなどのリソースを、組織や OU、他のアカウントと安全に共有するサービス
- ポイント：リソースは 1 回作って共有する。組織で有効にすると、組織や OU の単位で共有できる
- 例：ネットワークアカウントの VPC のサブネットを、各ワークロードのアカウントに共有する（共有 VPC）

#### IAM Identity Center（あいでんてぃてぃせんたー / AWS IAM Identity Center）

- 意味：社員などのワークフォースが、複数の AWS アカウントとアプリにサインインできるように、アクセスを一元的に管理するサービス
- ポイント：許可セット（admin・readonly など）を作って、アカウントのユーザー・グループに割り当てる。外部の IdP（Entra ID・Okta）とつなげる。Control Tower のランディングゾーンでも使う

- 問：SCP で s3:* を Allow した。開発者の IAM ロールには何の IAM ポリシーも付いていない。開発者は S3 を使えるか。
