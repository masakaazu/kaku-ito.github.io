## 21-1 ネットワークを守る

### まとめ表

| 層 | 道具 | 特徴 |
| :-: | :-: | :-: |
| インスタンス・ENI | セキュリティグループ | ステートフル、許可だけ |
| サブネット | ネットワーク ACL | ステートレス、許可と拒否、番号の小さい順 |
| VPC の出入り口 | Network Firewall | ステートフルの検査、IPS（Suricata）、ドメインで制限 |
| HTTP(S) | AWS WAF | マネージドルール、レートベースのルール |
| DDoS | Shield Standard・Advanced | Standard は追加料金なし |
| 組織全体 | Firewall Manager | WAF・SG・Network Firewall などを一括で適用 |

### VPC の中

#### セキュリティグループ（せきゅりてぃぐるーぷ / security group）

- 意味：インスタンスなどのネットワークインターフェイスに付ける仮想のファイアウォール
- ポイント：ステートフル（許可した通信の戻りは自動で通る）。許可ルールだけで、拒否ルールは書けない。別のセキュリティグループを送り元に指定できる

#### ネットワーク ACL（ねっとわーくえーしーえる / network ACL）

- 意味：サブネットに付ける、通信を許可・拒否するルールの一覧
- ポイント：ステートレス（戻りの通信も別に許可する。エフェメラルポート 1024〜65535 など）。番号の小さいルールから評価し、最初に一致したものを使う。特定の IP アドレスを拒否するならここ

#### AWS Network Firewall（ねっとわーくふぁいあうぉーる / AWS Network Firewall）

- 意味：VPC の通信を検査するマネージドのファイアウォールと侵入検知・防止（IPS）のサービス。Suricata 互換のルールを使える
- ポイント：ドメイン名でアウトバウンドを絞る・パケットの中身を検査するなど、セキュリティグループや NACL ではできないことをする。専用のサブネットにエンドポイントを置き、ルートテーブルで通す

#### VPC エンドポイントポリシー（えんどぽいんとぽりしー / VPC endpoint policy）

- 意味：VPC エンドポイントに付けて、そのエンドポイントを通して使えるプリンシパル・アクション・リソースを決めるポリシー
- ポイント：IAM ポリシーやバケットポリシーを置き換えない（両方で許可が要る）。バケット側では aws:SourceVpce で「このエンドポイントからだけ」に絞れる

### Web と DDoS

#### AWS WAF（わふ / AWS WAF）

- 意味：CloudFront・ALB・API Gateway・AppSync などへの HTTP(S) のリクエストを、ウェブ ACL のルールで許可・ブロック・カウントするファイアウォール
- ポイント：SQL インジェクションやクロスサイトスクリプティングなど一般的な攻撃は AWS マネージドルールで防ぐ

#### レートベースのルール（れーとべーするーる / rate-based rule）

- 意味：IP アドレスなどごとにリクエストの数を数え、決めた数を超えたら制限する WAF のルール
- 例：ログインのパスに 5 分で 100 回を超える IP アドレスをブロックする

#### AWS Shield（しーるど / AWS Shield Standard・Advanced）

- 意味：DDoS 攻撃からの保護。Standard は追加料金なしですべての利用者に効き、Advanced は検出・緩和の強化、対応チームの支援、攻撃による料金の増加の保護などを足す
- ポイント：大規模な攻撃に専門チームの支援が欲しいなら Advanced

#### AWS Firewall Manager（ふぁいあうぉーるまねーじゃー / AWS Firewall Manager）

- 意味：Organizations の全アカウントに、WAF・Shield Advanced・セキュリティグループ・Network Firewall・DNS Firewall などの保護をまとめて適用するサービス
- ポイント：新しく加わるアカウントやリソースにも自動で適用される

#### aws:SecureTransport（せきゅあとらんすぽーと / aws:SecureTransport）

- 意味：リクエストが TLS（HTTPS）で来たかどうかを表す条件キー
- 例：S3 のバケットポリシーで aws:SecureTransport が false のリクエストを拒否する

## 21-2 証明書

### まとめ表

| やりたいこと | 使うもの |
| :-: | :-: |
| 公開サイトの TLS 証明書を無料で、自動で更新 | ACM のパブリック証明書＋DNS 検証 |
| CloudFront に付ける | us-east-1 で証明書を取る |
| 社内のサービス間の証明書 | AWS Private CA |
| たくさんのサブドメイン | ワイルドカード証明書 |

### 証明書

#### AWS Certificate Manager（ACM）（えーしーえむ / AWS Certificate Manager）

- 意味：パブリックとプライベートの SSL/TLS 証明書の発行・保存・更新を引き受けるサービス。ELB・CloudFront・API Gateway などに付ける
- ポイント：CloudFront で使う証明書は米国東部（バージニア北部、us-east-1）で取る。ELB 用はその ELB と同じリージョン

#### DNS 検証（でぃーえぬえすけんしょう / DNS validation）

- 意味：ACM が示す CNAME レコードを DNS に入れて、ドメインの持ち主であることを示す方法
- ポイント：CNAME を残しておけば、ACM が証明書を自動で更新する。メール検証は更新のたびに対応が要る

#### ワイルドカード証明書（わいるどかーどしょうめいしょ / wildcard certificate）

- 意味：*.example.com のように、1 つの階層のサブドメインをまとめて守る証明書
- ポイント：サブドメインの数に制限がない

#### AWS Private CA（ぷらいべーとしーえー / AWS Private Certificate Authority）

- 意味：自分の組織だけで信頼されるルート CA・下位 CA を作り、社内向けの証明書を発行するサービス
- ポイント：オンプレミスの CA を運用しなくてよい。サービス間の相互 TLS（mTLS）や IAM Roles Anywhere のトラストアンカーに使える。リージョンごとのリソース

## 21-3 暗号化とキーとデータの管理

### まとめ表

| やりたいこと | 使うもの |
| :-: | :-: |
| キーを使える人を決める | キーポリシー（＋IAM ポリシー） |
| 別のアカウントにキーを使わせる | キーポリシーと相手の IAM ポリシーの両方 |
| 大きいデータを暗号化 | エンベロープ暗号化（データキー） |
| 一時的に使わせる | グラント |
| 別のリージョンでも同じキーで復号 | マルチリージョンキー |
| 自分だけが管理する専用の HSM | CloudHSM |
| S3 の KMS の費用を下げる | S3 バケットキー |
| 機密データを見つける | Amazon Macie |

### KMS

#### キーポリシー（きーぽりしー / key policy）

- 意味：KMS キーに付けるリソースベースのポリシー。すべての KMS キーにちょうど 1 つある
- ポイント：キーへのアクセスを決める主な方法。キーポリシーでアカウントを許可していないと、IAM ポリシーだけでは使えない

#### クロスアカウントのキーの利用（くろすあかうんとのきー / cross-account KMS key access）

- 意味：別のアカウントのユーザーやロールに KMS キーを使わせること
- ポイント：キーポリシーで相手のアカウントを許可し、相手のアカウントの IAM ポリシーでも許可する。どちらか一方では足りない

#### エンベロープ暗号化（えんべろーぷあんごうか / envelope encryption）

- 意味：データキーでデータを暗号化し、そのデータキーを KMS キーで暗号化する方法
- ポイント：KMS の Encrypt で直接暗号化できるのは 4 KB まで。大きいデータは GenerateDataKey でデータキーを取って手元で暗号化する

#### キーのローテーション（きーのろーてーしょん / key rotation）

- 意味：カスタマーマネージドキーの自動ローテーションを有効にすると、既定で毎年新しいキーマテリアルを作る。すぐに変えたいならオンデマンドローテーション
- ポイント：キー ID や ARN は変わらず、古いデータもそのまま復号できる

#### マルチリージョンキー（まるちりーじょんきー / multi-Region keys）

- 意味：複数のリージョンにある、同じキーマテリアルとキー ID を持つ KMS キーの組
- ポイント：あるリージョンで暗号化したデータを、別のリージョンでそのまま復号できる。災害対策やグローバルなアプリに使う。キーポリシーなどはそれぞれ管理する

#### グラント（ぐらんと / grant）

- 意味：キーポリシーや IAM ポリシーを変えずに、プリンシパルに KMS キーの使用を許す仕組み。不要になったら取り消す
- ポイント：AWS のサービスが利用者の代わりに一時的に使うことが多い。許可はできるが拒否はできない

#### AWS CloudHSM（くらうどえいちえすえむ / AWS CloudHSM）

- 意味：自分のアカウントの VPC で使う、シングルテナントのハードウェアセキュリティモジュール（HSM）。FIPS 140 のレベル 3 で検証されている
- ポイント：キーを利用者だけが管理する必要があるとき。KMS のカスタムキーストアとしても使える

### データの保存と発見

#### S3 の暗号化（えすすりーのあんごうか / S3 server-side encryption）

- 意味：S3 はすべての新しいオブジェクトを既定で SSE-S3 で暗号化する。SSE-KMS（KMS キー）・DSSE-KMS（2 層）・SSE-C（利用者のキー）も選べる
- ポイント：誰が復号できるかを KMS のキーポリシーで管理し、CloudTrail に使用の記録を残したいなら SSE-KMS

#### S3 バケットキー（ばけっときー / S3 Bucket Keys）

- 意味：SSE-KMS で、バケット単位の短期のキーを使って KMS へのリクエストを減らす機能
- ポイント：KMS のリクエストの費用を最大 99% 下げる

#### S3 パブリックアクセスブロック（ぱぶりっくあくせすぶろっく / S3 Block Public Access）

- 意味：バケットポリシーや ACL による公開を止める設定。組織・アカウント・バケット・アクセスポイントで設定できる
- ポイント：組織やアカウントで有効にすれば、個々のバケットの設定にかかわらず公開を防げる

#### EBS のデフォルトの暗号化（でふぉるとのあんごうか / EBS encryption by default）

- 意味：有効にすると、そのリージョンで新しく作る EBS ボリュームとスナップショットのコピーをすべて暗号化する
- ポイント：リージョンごとの設定。既存のボリュームは変わらない

#### RDS の暗号化（あーるでぃーえすのあんごうか / RDS encryption at rest）

- 意味：DB インスタンスのストレージ・ログ・バックアップ・リードレプリカ・スナップショットを KMS キーで暗号化する
- ポイント：暗号化していない DB インスタンスを後から直接暗号化はできない。スナップショットを暗号化してコピーし、そこから復元する

#### Amazon Macie（めいしー / Amazon Macie）

- 意味：機械学習とパターンで S3 の中の個人情報などの機密データを見つけるサービス。バケットの公開・暗号化の状態も見る
- ポイント：機密データの自動検出は、サンプリングで代表的なオブジェクトを選び、続けて調べる。結果は EventBridge・Security Hub に送れる

## 問題演習

### 21-1

#### 問 dop-21-o01

- 問：ある IP アドレスからの SSH の攻撃を、サブネット全体で止めたい。どうするか。
- ア：セキュリティグループに拒否ルールを書く
- イ：ルートテーブルからその IP アドレスを消す
- ウ：S3 のバケットポリシーで拒否する
- エ：ネットワーク ACL にその IP アドレスの拒否ルールを書く
- 正解：エ
- 解説：ネットワーク ACL は許可と拒否を書け、サブネット単位で効く。セキュリティグループは拒否を書けない。
- アの意味：セキュリティグループには拒否ルールを書けない。
- イの意味：ルートテーブルは送り元の IP アドレスでは止められない。
- ウの意味：S3 だけで、SSH は止められない。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：AWS「Amazon VPC ユーザーガイド」セキュリティグループのルール（『拒否ルールは指定できません。』））

#### 問 dop-21-o02

- 問：ネットワーク ACL でインバウンドの 443 を許可したが、クライアントに応答が返らない。セキュリティグループは問題ない。どうするか。
- ア：ネットワーク ACL のアウトバウンドでエフェメラルポート（1024〜65535）への通信を許可する
- イ：セキュリティグループのアウトバウンドを追加する
- ウ：インバウンドの 443 のルール番号を大きくする
- エ：Network Firewall を入れる
- 正解：ア
- 解説：ネットワーク ACL はステートレスなので、戻りの通信も別に許可する。
- アの意味：正しい。
- イの意味：セキュリティグループはステートフルで、戻りは自動で通る。
- ウの意味：評価の順は関係ない。
- エの意味：必要ない。
- 出典：オリジナル問題（根拠：AWS「Amazon VPC ユーザーガイド」ネットワーク ACL の基本（『NACL は*ステートレス*です。』））

#### 問 dop-21-o03

- 問：ネットワーク ACL のインバウンドに、ルール 100「すべて許可」とルール 200「IP アドレス X を拒否」がある。X からの通信はどうなるか。
- ア：拒否される（拒否が優先）
- イ：許可される（番号の小さいルール 100 に先に一致する）
- ウ：両方に一致して止まる
- エ：セキュリティグループで決まる
- 正解：イ
- 解説：番号の小さいルールから評価し、最初に一致したものを使う。拒否したいならルール 100 より小さい番号にする。
- アの意味：IAM の評価とは違い、順番で決まる。
- イの意味：正しい。
- ウの意味：最初に一致したものだけが使われる。
- エの意味：ネットワーク ACL で許可されたあと、セキュリティグループも通る必要はあるが、ACL の判断は許可。
- 出典：オリジナル問題（根拠：AWS「Amazon VPC ユーザーガイド」ネットワーク ACL の基本（『トラフィックを許可するか拒否するかを決定する際は、最も低い番号のルールから順にルールを評価します』））

#### 問 dop-21-o04

- 問：VPC から外への通信を、許可したドメイン名だけに絞り、さらに IPS のルールで通信を検査したい。何を使うか。
- ア：セキュリティグループ
- イ：ネットワーク ACL
- ウ：AWS Network Firewall
- エ：AWS WAF
- 正解：ウ
- 解説：Network Firewall はステートフルの検査と IPS を行い、ドメイン名での制限もできる。
- アの意味：IP アドレスとポートだけで、ドメイン名や中身は見ない。
- イの意味：IP アドレスとポートだけ。
- ウの意味：正しい。
- エの意味：CloudFront や ALB などに来る HTTP(S) のリクエスト向けで、VPC から外への通信は検査しない。
- 出典：オリジナル問題（根拠：AWS「AWS Network Firewall Developer Guide」What is AWS Network Firewall?（『AWS Network Firewall is a stateful, managed, network firewall and intrusion detection and prevention service for your virtual private cloud (VPC) that you create in Amazon Virtual Private Cloud (Amazon VPC).』））

#### 問 dop-21-o05

- 問：ALB の背後の Web アプリを、SQL インジェクションやクロスサイトスクリプティングから、ルールを自分で書かずに守りたい。どうするか。
- ア：ALB に AWS WAF のウェブ ACL を付け、AWS マネージドルールを入れる
- イ：Shield Standard に頼る
- ウ：セキュリティグループで 443 だけ許可する
- エ：ネットワーク ACL で拒否する
- 正解：ア
- 解説：AWS マネージドルールは一般的な Web の脅威から守るように作られている。
- アの意味：正しい。
- イの意味：DDoS の保護で、アプリの攻撃は見ない。
- ウの意味：ポートを絞るだけで、リクエストの中身は見ない。
- エの意味：IP アドレスとポートだけ。
- 出典：オリジナル問題（根拠：AWS「AWS WAF デベロッパーガイド」AWS の マネージドルール AWS WAF（『AWS マネージドルールは、一般的なウェブ脅威から保護するように設計されています。』））

#### 問 dop-21-o06

- 問：ログインのページに、1 つの IP アドレスから短い時間に大量のリクエストが来る。一定の数を超えた IP アドレスを自動で制限したい。どうするか。
- ア：セキュリティグループで IP アドレスを拒否する
- イ：Shield Advanced に加入する
- ウ：CloudFront のキャッシュを延ばす
- エ：WAF のレートベースのルールを使う
- 正解：エ
