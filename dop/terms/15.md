## 15-1 CloudWatch Logs の基本と保護

### まとめ表

| やりたいこと | 設定 |
| :-: | :-: |
| 古いログを自動で消して費用を下げる | ロググループの保持期間（既定は無期限） |
| 自分の KMS キーで暗号化 | ロググループに KMS キーを関連付け（キーポリシーで logs を許可） |
| メールアドレスなどの個人情報を隠す | データ保護ポリシー（マスキング） |
| あまり見ないログを安く | 低頻度アクセスのログクラス |
| デプロイ中にログを流し見る | Live Tail |

### しくみ

#### ロググループとログストリーム（ろぐぐるーぷ / log group and log stream）

- 意味：ログストリームは同じ送り元（インスタンスやコンテナ）からの一連のログイベント。ロググループは、保持・監視・アクセス制御の設定を共有するログストリームのまとまり
- ポイント：保持期間・暗号化・メトリクスフィルター・サブスクリプションはロググループに設定する

#### 保持期間（ほじきかん / log retention）

- 意味：ロググループのログを残す期間。1 日〜10 年などから選ぶ
- ポイント：既定は無期限で、たまり続けて費用が増える。長く残すなら S3 に流してライフサイクルで管理する

#### CloudWatch エージェントのログ収集（えーじぇんとのろぐしゅうしゅう / CloudWatch agent logs）

- 意味：CloudWatch エージェントの設定の logs セクションに、送るログファイルのパスとロググループを書いて、EC2 やオンプレミスのログを CloudWatch Logs に送る
- ポイント：インスタンスに CloudWatchAgentServerPolicy などの権限が要る。設定は Parameter Store に置いて Run Command や State Manager で配る

### 守る・安くする

#### ログの KMS 暗号化（けーえむえすあんごうか / encrypt log data with AWS KMS）

- 意味：ロググループに KMS キーを関連付けて、ログをカスタマーマネージドキーで暗号化する設定
- ポイント：ログはもともと暗号化されているが、自分のキーで管理したいときに使う。キーポリシーで CloudWatch Logs のサービス（logs.リージョン.amazonaws.com）に権限を与えないと関連付けに失敗する

#### データ保護ポリシー（でーたほごぽりしー / data protection policy）

- 意味：ロググループ（またはアカウント全体）に付けて、取り込んだログの中の機密データ（メールアドレス・カード番号など）を見つけてマスクする設定
- ポイント：Logs Insights やメトリクスフィルターなどの出口でマスクされる。見られるのは logs:Unmask の権限を持つ人だけ

#### ログクラス（ろぐくらす / log classes）

- 意味：リアルタイムの監視や頻繁なアクセス向けの標準と、あまり見ないログ向けで取り込みが安い低頻度アクセスの 2 つ
- ポイント：低頻度アクセスでも Logs Insights で検索できるが、メトリクスフィルターやサブスクリプションなどは標準だけ

#### Live Tail（らいぶている / CloudWatch Logs Live Tail）

- 意味：取り込まれたログをほぼリアルタイムに流して表示・フィルター・強調する機能
- ポイント：デプロイ中や障害の調査で tail -f のように見る。CLI の start-live-tail でも使える

## 15-2 ログからメトリクス・ログを流す

### まとめ表

| やりたいこと | 使うもの |
| :-: | :-: |
| ログの中の ERROR の数でアラーム | メトリクスフィルター |
| ログをリアルタイムに処理・転送 | サブスクリプションフィルター（Kinesis・Firehose・Lambda・OpenSearch） |
| 多くのアカウントのログを中央へ | クロスアカウントのサブスクリプション（送信先） |
| S3 にずっと残す | サブスクリプション → Firehose → S3 |
| 一度だけ S3 に出す | エクスポートタスク |

### メトリクスにする

#### メトリクスフィルター（めとりくすふぃるたー / metric filter）

- 意味：ロググループに入ってくるログを検索して、一致した数や値を CloudWatch のメトリクスにする仕組み
- ポイント：作った後に入ってきたログだけが対象で、過去のログはさかのぼらない。メトリクスにアラームを付けて通知する

#### フィルターパターン（ふぃるたーぱたーん / filter pattern syntax）

- 意味：メトリクスフィルター・サブスクリプションフィルター・Live Tail で使う一致の書き方。文字列・スペース区切り・JSON・正規表現
- 例：{ $.statusCode = 500 }（JSON のログで statusCode が 500）、[ip, user, ..., status=5*, size]（スペース区切り）

### 流す

#### サブスクリプションフィルター（さぶすくりぷしょんふぃるたー / subscription filter）

- 意味：ロググループのログを、条件に合うものだけリアルタイムに Kinesis Data Streams・Firehose・Lambda・OpenSearch Service へ流す仕組み
- ポイント：リアルタイムの処理・別のシステムへの取り込み・継続的なアーカイブはこれ。ロググループあたり 2 つまで

#### クロスアカウントのサブスクリプション（くろすあかうんと / cross-account subscription）

- 意味：受け取る側のアカウントに「送信先（destination）」を作り、送る側のロググループのサブスクリプションフィルターでそこへ流す構成
- ポイント：ログを中央のアカウントに集める定番。ロググループと送信先は同じリージョン（送信先の先の Kinesis などは別リージョンでもよい）。送信先のアクセスポリシーで送る側のアカウントを許可する

#### エクスポートタスク（えくすぽーとたすく / export to Amazon S3）

- 意味：ロググループのある期間のログを、S3 バケットに一度だけ書き出す機能
- ポイント：継続的なアーカイブには向かない（サブスクリプションを使う）。書き出したあとは S3 のライフサイクルで管理

#### Amazon Data Firehose（ふぁいあほーす / Amazon Data Firehose）

- 意味：流れてくるデータを S3・Redshift・OpenSearch・Splunk・HTTP エンドポイントなどへ自動で届けるサービス。Lambda で変換もできる
- ポイント：サーバーもコードも要らない。ログを S3 にためて Athena で調べる構成の入口

#### OpenSearch Service へのストリーミング（おーぷんさーち / streaming to Amazon OpenSearch Service）

- 意味：サブスクリプションで、ロググループのログをほぼリアルタイムに OpenSearch Service に入れる構成
- ポイント：全文検索やダッシュボード（OpenSearch Dashboards）で調べたいとき。量が多いと費用が高くなる

## 15-3 分析と監査のログ

### まとめ表

| 調べたいこと | ログ |
| :-: | :-: |
| 誰がどの API を呼んだか | CloudTrail |
| VPC の通信の許可・拒否 | VPC フローログ |
| ALB へのリクエストの詳細 | ALB のアクセスログ（既定は無効） |
| S3 へのリクエスト | S3 サーバーアクセスログ（ベストエフォート）・CloudTrail のデータイベント |
| CloudWatch Logs のログを集計 | CloudWatch Logs Insights |
| S3 にたまったログを SQL で | Athena |

### 分析

#### CloudWatch Logs Insights（ろぐずいんさいと / CloudWatch Logs Insights）

- 意味：ロググループのログを、専用のクエリ言語（fields・filter・stats・sort・limit など）で対話的に検索・集計する機能
- ポイント：複数のロググループをまとめて調べられる。結果をダッシュボードに置ける
- 例：filter status >= 500 | stats count(*) by ip | sort count(*) desc | limit 10

#### Athena（あてな / Amazon Athena）

- 意味：S3 にあるファイルを、そのまま SQL で検索するサービス
- ポイント：ALB のアクセスログ・CloudTrail・VPC フローログなどのテーブルを作って調べる。パーティションで読む量を減らして費用を下げる

### CloudTrail

#### CloudTrail（くらうどとれいる / AWS CloudTrail）

- 意味：AWS の API の呼び出し（誰が・いつ・どこから・何を）を記録するサービス
- ポイント：イベント履歴で過去 90 日の管理イベントを無料で見られる。それより長く残すには証跡で S3 に送る

#### 証跡（しょうせき / trail）

- 意味：CloudTrail のイベントを S3 バケットに送り続ける設定。CloudWatch Logs にも送れる
- ポイント：マルチリージョンの証跡が推奨（コンソールで作るとマルチリージョン）。組織の証跡なら管理アカウントから全アカウントの記録を集め、メンバーは消せない

#### ログファイルの整合性の検証（せいごうせいのけんしょう / log file integrity validation）

- 意味：CloudTrail がダイジェストファイル（SHA-256 のハッシュと RSA の署名）を作り、配信後にログファイルが変更・削除されていないかを確かめられる機能
- ポイント：監査で「ログが改ざんされていない」ことを示すために有効にする。S3 の Object Lock や MFA 削除と組み合わせる

#### 管理イベントとデータイベント（かんりいべんと / management events and data events）

- 意味：管理イベントはリソースの作成・設定変更などの操作。データイベントは S3 オブジェクトの読み書きや Lambda の呼び出しなど、リソースの中の操作
- ポイント：データイベントは量が多いため、既定では記録されない。GetObject を記録したいなら有効にする

#### CloudTrail Insights（くらうどとれいるいんさいと / CloudTrail Insights）

- 意味：過去の API の呼び出しの量・エラーの率からベースラインを作り、外れた異常な動きを Insights イベントとして記録する機能
- ポイント：急に大量の API が呼ばれた・エラーが急増した、などに気づける

#### CloudTrail Lake（くらうどとれいるれいく / AWS CloudTrail Lake）

- 意味：CloudTrail のイベントをイベントデータストアに集め、SQL で直接検索できる機能。最大 10 年ほど残せる
- ポイント：Athena のテーブルを作らずに CloudTrail のコンソールで SQL を実行できる。ほかのソースのイベントも取り込める

### ネットワークとアクセスのログ

#### VPC フローログ（ふろーろぐ / VPC Flow Logs）

- 意味：VPC のネットワークインターフェイスを通る IP の通信の情報（送信元・宛先・ポート・ACCEPT/REJECT）を記録する機能
- ポイント：送り先は CloudWatch Logs・S3・Firehose。パケットの中身は記録しない。セキュリティグループや NACL で拒否された通信の調査に

#### ALB のアクセスログ（あくせすろぐ / ALB access logs）

- 意味：ALB に来たリクエストの詳細（時刻・クライアント IP・レイテンシー・パス・ステータス）を S3 に保存するログ
- ポイント：既定では無効。S3 のバケットポリシーで ELB からの書き込みを許可する。Athena で調べる

#### S3 サーバーアクセスログ（さーばーあくせすろぐ / S3 server access logs）

- 意味：S3 バケットへのリクエストの詳細を、別のバケットに記録するログ
- ポイント：配信はベストエフォートで、漏れることがある。確実な記録が要るなら CloudTrail のデータイベント

## 問題演習

### 15-1

#### 問 dop-15-o01

- 問：CloudWatch Logs の費用が毎月増え続けている。ロググループの設定は作ったときのまま。最初に見直すべきものはどれか。
- ア：ログストリームの数
- イ：ロググループの保持期間（既定は無期限）
- ウ：メトリクスフィルターの数
- エ：KMS の暗号化
- 正解：イ
- 解説：ログは既定で無期限に保存されるので、たまり続ける。必要な期間に保持期間を設定する。
- アの意味：数は費用の主な原因ではない。
- イの意味：正しい。
- ウの意味：保存の量には影響しない。
- エの意味：保存の量には影響しない。
- 出典：オリジナル問題（根拠：AWS「Amazon CloudWatch Logs ユーザーガイド」ロググループとログストリームの操作（『デフォルトでは、ログデータは CloudWatch Logs に無期限に保存されます。』））

#### 問 dop-15-o02

- 問：規程で、アプリのログを自社が管理する KMS キーで暗号化する必要がある。どうするか。
- ア：S3 のデフォルト暗号化を有効にする
- イ：アプリでログを暗号化してから送る
- ウ：ロググループに KMS のカスタマーマネージドキーを関連付け、キーポリシーで CloudWatch Logs に権限を与える
- エ：何もしなくてよい（既に暗号化されている）
- 正解：ウ
- 解説：ロググループに KMS キーを関連付けると、そのキーで暗号化される。キーポリシーで CloudWatch Logs のサービスに使わせる。
- アの意味：S3 の設定で、CloudWatch Logs には効かない。
- イの意味：検索やメトリクスフィルターが使えなくなる。
- ウの意味：正しい。
- エの意味：暗号化はされているが、自社が管理するキーではない。
- 出典：オリジナル問題（根拠：AWS「Amazon CloudWatch Logs ユーザーガイド」を使用して CloudWatch Logs のログデータを暗号化する AWS Key Management Service（『を使用した暗号化 AWS KMS は、ロググループの作成時または作成後に、KMS キーをロググループに関連付けることで、ロググループレベルで有効になります。』））

#### 問 dop-15-o03

- 問：アプリのログに利用者のメールアドレスが出てしまう。アプリの修正までの間、ログを見る運用者にはマスクして見せたい。何を使うか。
- ア：ロググループのデータ保護ポリシー
- イ：メトリクスフィルター
- ウ：保持期間を 1 日にする
- エ：ロググループを KMS で暗号化する
- 正解：ア
- 解説：データ保護ポリシーは取り込んだログの機密データを見つけてマスクする。マスクを外して見られるのは特別な権限を持つ人だけ。
- アの意味：正しい。
- イの意味：数を数えるもので、隠さない。
- ウの意味：見られる期間が短くなるだけで、見えてしまう。
- エの意味：保存時の暗号化で、権限がある人には平文で見える。
- 出典：オリジナル問題（根拠：AWS「Amazon CloudWatch Logs ユーザーガイド」機密性の高いログデータをマスキングで保護する（『これらのポリシーを使うことで、アカウントのロググループが取り込んだログイベントに表示される機密データを、監査およびマスクできます。』））

#### 問 dop-15-o04

- 問：大量のデバッグログを、事故が起きたときの事後調査のためだけに残している。リアルタイムの監視はしない。取り込みの費用を下げたい。どうするか。

- イ：メトリクスフィルターを外す

- 正解：エ
- 解説：低頻度アクセスのログクラスは取り込みが安く、事後の調査やたまの検索（Logs Insights）に向く。
- アの意味：費用がさらに増える。
- イの意味：取り込みの費用は下がらない。
- ウの意味：取り込みの費用は下がらず、手間も増える。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：AWS「Amazon CloudWatch Logs ユーザーガイド」ログクラス（『低頻度アクセスログクラスは、アクセス頻度の低いログのアドホッククエリや事後フォレンジック分析に最適です。』））

#### 問 dop-15-o05

- 問：新しいバージョンのデプロイ中に、複数のロググループのエラーをその場で流し見て、すぐに異常に気づきたい。何を使うか。

- ウ：CloudWatch Logs Live Tail
- エ：Athena
- 正解：ウ
- 解説：Live Tail は取り込まれたログをほぼリアルタイムに流し、フィルターや強調ができる。
- アの意味：一度だけ S3 に書き出すもので、リアルタイムではない。
- イの意味：API の記録で、アプリのログではない。
- ウの意味：正しい。
- エの意味：S3 のファイルを後から調べるもの。
- 出典：オリジナル問題（根拠：AWS「Amazon CloudWatch Logs ユーザーガイド」CloudWatch Logs Live Tail を使用したトラブルシューティング（『取り込まれたログをほぼリアルタイムで表示、フィルタリング、強調表示できるため、問題をすばやく検出して解決することができます。』））

### 15-2

#### 問 dop-15-o06

- 問：アプリのログに「ERROR」が 5 分間に 10 回以上出たら通知したい。アプリは変えたくない。どうするか。
- ア：メトリクスフィルターで ERROR の数をメトリクスにし、アラームを付ける
- イ：Logs Insights のクエリを毎回手で実行する
- ウ：エクスポートタスクで S3 に出して数える
