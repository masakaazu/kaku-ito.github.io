## 18-1 フリートの設定を入れ替える

### まとめ表

| やりたいこと | 使うもの |
| :-: | :-: |
| 新しい AMI を Auto Scaling グループ全体に順に入れる | 起動テンプレートの新バージョン＋インスタンスの更新 |
| 途中で止めて確かめる | チェックポイント |
| 悪くなったら自動で元に戻す | 自動ロールバック（CloudWatch アラーム） |
| 置き換え中も台数を減らさない | 最小正常率・最大正常率 |
| パッチ済みの AMI を毎月自動で作る | EC2 Image Builder のパイプライン |
| 1 台を調べる・止めずに置く | スタンバイ・プロセスの中断 |

### 入れ替える

#### 起動テンプレートのバージョン（きどうてんぷれーとのばーじょん / launch template versions）

- 意味：起動テンプレートは変更のたびに番号付きのバージョンを作る。どれか 1 つをデフォルトバージョンにする
- ポイント：バージョンを指定せずに起動するとデフォルトバージョンが使われる。Auto Scaling グループは特定の番号・$Default・$Latest のどれかを指す。テンプレートを変えても動いているインスタンスは変わらない

#### インスタンスの更新（いんすたんすのこうしん / instance refresh）

- 意味：Auto Scaling グループのインスタンスを、新しい起動テンプレートや AMI の設定のものに順に置き換える機能
- ポイント：最小正常率・最大正常率で一度に置き換える量を決める。ルートボリュームだけを置き換えて、インスタンスを終了しない戦略もある

#### チェックポイント（ちぇっくぽいんと / checkpoint）

- 意味：インスタンスの更新を、全体の何 % まで進んだら一時停止するかの設定
- 例：20% で止めて新しいインスタンスを確かめ、問題がなければ続ける

#### インスタンスの更新の自動ロールバック（じどうろーるばっく / auto rollback）

- 意味：インスタンスの更新が失敗したり、指定した CloudWatch アラームが ALARM になったりしたら、元の設定のインスタンスに自動で戻す機能
- ポイント：アラームの指定は任意。エラー率やレイテンシーのアラームを付けておくと、悪い変更を自動で戻せる

#### スキップマッチング（すきっぷまっちんぐ / skip matching）

- 意味：インスタンスの更新で、すでに新しい設定になっているインスタンスは置き換えずに飛ばす設定
- ポイント：途中で止まった更新をやり直すときや、一部だけ新しい場合に無駄な置き換えを減らす

#### インスタンスメンテナンスポリシー（めんてなんすぽりしー / instance maintenance policy）

- 意味：インスタンスの更新やヘルスチェックによる置き換えのときに、容量を何 % の範囲に保つかの設定。最小正常率と最大正常率で決める
- ポイント：最小正常率 100%・最大正常率 110% などにすると、先に新しいインスタンスを起動してから古いものを終了するので、容量が下がらない

#### EC2 Image Builder（いめーじびるだー / EC2 Image Builder）

- 意味：AMI やコンテナイメージの作成・テスト・配布を自動にするサービス。レシピ（元のイメージ＋コンポーネント）とパイプラインで動かす
- ポイント：パイプラインは cron 式で定期的に動き、元のイメージやコンポーネントが変わっていなければビルドを飛ばせる。配布先のアカウント・リージョンも決められる

#### AMI のパブリックパラメータ（ぱぶりっくぱらめーた / AMI public parameters）

- 意味：AWS が Parameter Store で公開している、最新の AMI ID を指すパラメータ
- ポイント：起動テンプレートや CloudFormation で使えば、AMI ID を書き換えずにいつも最新の AMI で起動できる
- 例：/aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-arm64

### 止めて調べる

#### スタンバイ（すたんばい / standby）

- 意味：インスタンスを InService から Standby に移し、Auto Scaling グループには残したまま、ロードバランサーの通信から外す状態
- ポイント：調べたり更新したりした後、サービスに戻せる。デタッチはグループから外す

#### プロセスの中断（ぷろせすのちゅうだん / suspend processes）

- 意味：Launch・Terminate・ReplaceUnhealthy・AZRebalance・HealthCheck などの Auto Scaling のプロセスを一時的に止める機能
- ポイント：調査中に異常なインスタンスを置き換えさせないなら ReplaceUnhealthy を止める。起動に何度も失敗すると Auto Scaling が自分でプロセスを止める（管理上の中断）

## 18-2 イベントで設定を変える

### まとめ表

| きっかけ（イベント） | 自動で行うこと |
| :-: | :-: |
| EC2 が起動した | EventBridge → Automation ランブックでソフトを入れる |
| Auto Scaling の起動に失敗 | EventBridge → SNS で通知 |
| パラメータが変わった・期限が近い | EventBridge → Lambda で再読み込み・再作成 |
| Trusted Advisor のチェックが赤 | EventBridge → 修正の Lambda |
| Security Hub の結果をアナリストが選んだ | カスタムアクション → EventBridge |

### イベントで動かす

#### EventBridge から Automation（おーとめーしょん / Automation as an EventBridge target）

- 意味：EventBridge のルールのターゲットに Systems Manager Automation のランブックを指定し、イベントで手順を自動で動かす
- ポイント：ルールには Automation を開始するための IAM ロールが要る。入力トランスフォーマーでインスタンス ID などをランブックの入力に渡す

#### Auto Scaling のイベント（おーとすけーりんぐのいべんと / Auto Scaling events）

- 意味：インスタンスの起動・終了の成功と失敗、ライフサイクルの待機、インスタンスの更新の状態などが EventBridge に届く
- 例：EC2 Instance Launch Unsuccessful で SNS に通知する

#### Parameter Store のイベント（ぱらめーたすとあのいべんと / Parameter Store events）

- 意味：パラメータの作成・更新・削除やパラメータポリシーの状態が EventBridge に届く
- ポイント：アプリの設定の再読み込みや、期限切れのパラメータの再作成を Lambda で自動にできる

#### パラメータポリシー（ぱらめーたぽりしー / parameter policies）

- 意味：高度なパラメータに付ける条件。Expiration（期限で削除）・ExpirationNotification（期限の前に知らせる）・NoChangeNotification（一定期間変わらなければ知らせる）の 3 種類
- ポイント：パスワードを定期的に変えさせたいなら NoChangeNotification。標準のパラメータには付けられない

#### シークレットのローテーション（ろーてーしょん / secret rotation）

- 意味：Secrets Manager で、シークレットとデータベースなどの認証情報を定期的に自動で更新すること。RDS などはマネージドローテーションか Lambda で行う
- ポイント：アプリは毎回 Secrets Manager から取り出すので、変わっても設定を直さなくてよい

#### Trusted Advisor のイベント（とらすてっどあどばいざー / Trusted Advisor check events）

- 意味：Trusted Advisor のチェックの状態が変わったとき（緑から赤など）に EventBridge に届くイベント
- ポイント：イベントは us-east-1 に届く。通知・修正の Lambda などにつなげる

#### Security Hub のカスタムアクション（かすたむあくしょん / custom actions）

- 意味：Security Hub の画面で結果を選んでアクションを実行すると、その結果が EventBridge に送られるしくみ
- ポイント：アナリストが選んだものだけを修正に回す半自動の流れ。全部を自動で処理するなら、結果のイベント（Findings - Imported）をルールで受ける

#### Security Hub の自動化ルール（じどうかるーる / automation rules）

- 意味：条件に合う Security Hub の結果の重要度・ワークフローの状態・メモなどを自動で書き換えるルール
- ポイント：結果を書き換えるだけで、リソースは直さない。管理者アカウントで作る

#### Change Calendar（ちぇんじかれんだー / Change Calendar）

- 意味：変更してよい期間・いけない期間をカレンダーで決め、Automation などの実行を許可したり止めたりする機能
- ポイント：DEFAULT_OPEN のカレンダーはイベントの間 CLOSED になり、実行を止める。繁忙期の変更凍結に使う

## 18-3 望ましくない状態を直す

### まとめ表

| 望ましくない状態 | 直し方 |
| :-: | :-: |
| 設定が規則に合わない（Config で非準拠） | 修復アクション（Automation ランブック）＋再試行 |
| SSH・RDP が全開のセキュリティグループ | AWS-DisablePublicAccessForSecurityGroup |
| ソフトの設定がいつのまにか変わる | State Manager の関連付けで定期的に戻す |
| ハードウェアの故障 | 簡易自動復旧・アラームの復旧アクション |
| 終了されるインスタンスのログ | 終了のライフサイクルフック |

### 直すしくみ

#### Config の修復アクション（しゅうふくあくしょん / remediation action）

- 意味：AWS Config ルールで非準拠になったリソースを、Systems Manager Automation のドキュメントで直す設定。手動と自動がある
- ポイント：自動修復は、直した後もまだ非準拠なら再試行の回数と秒数を決められる。AWS が用意したドキュメントも自作のものも使える

#### AWS-DisablePublicAccessForSecurityGroup（でぃせーぶるぱぶりっくあくせす / AWS-DisablePublicAccessForSecurityGroup）

- 意味：すべての IP アドレスに開いている既定の SSH・RDP のポートを、セキュリティグループから外す AWS 提供のランブック
- ポイント：Config ルール restricted-ssh などの修復アクションに使う

#### 事前定義のランブック（じぜんていぎのらんぶっく / predefined runbooks）

- 意味：AWS・AWS サポート・AWS Config が用意した Automation ランブック。AWS-RestartEC2Instance・AWS-StopEC2Instance・AWS-CreateImage など
- ポイント：まず用意されたものを探し、なければ自作する。AWSSupport- で始まるものはトラブルシューティング向け

#### State Manager の関連付け（かんれんづけ / State Manager association）

- 意味：マネージドノードを決めた状態に保つ設定。スケジュールで繰り返し適用するので、ずれても元に戻る
- 例：CloudWatch エージェントがいつも入って動いているようにする

#### 簡易自動復旧（かんいじどうふっきゅう / simplified automatic recovery）

- 意味：AWS 側のハードウェアの問題でインスタンスが使えなくなったとき、対応するインスタンスを自動で別のホストで復旧する機能
- ポイント：対応するインスタンスでは既定で有効。CloudWatch アラームの復旧アクションでも同じように復旧できる。インスタンスストアを使う種類などは対応しない

#### 終了のライフサイクルフック（しゅうりょうのらいふさいくるふっく / termination lifecycle hook）

- 意味：Auto Scaling がインスタンスを終了する前に待機（Terminating:Wait）させるしくみ
- ポイント：待機の間に EventBridge から Lambda や Run Command を動かし、ログやデータを取り出す。終わったら complete-lifecycle-action で続ける

## 問題演習

### 18-1

#### 問 dop-18-o01

- 問：セキュリティパッチを当てた新しい AMI を、Auto Scaling グループの 40 台に、容量を保ちながら順に入れたい。どうするか。
- ア：古いインスタンスを手で 1 台ずつ終了する
- イ：希望容量を 2 倍にしてから元に戻す
- ウ：スケジュールされたアクションを作る
- エ：起動テンプレートの新しいバージョンを作り、インスタンスの更新を始める
- 正解：エ
- 解説：起動テンプレートを変えても動いているインスタンスは変わらない。インスタンスの更新で順に置き換える。
- アの意味：手作業で、台数の管理も自分でしなければならない。
- イの意味：どのインスタンスが残るかは決まらず、古いものが残ることがある。
- ウの意味：決まった時刻に台数を変えるもので、AMI は入れ替わらない。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：AWS「Amazon EC2 Auto Scaling ユーザーガイド」インスタンスの更新を使用して Auto Scaling グループのインスタンスを更新する（『変更を含む新しい起動テンプレートを作成し、インスタンスの更新を使用して更新をすぐにロールアウトできます。』））

#### 問 dop-18-o02

- 問：インスタンスの更新の途中で 5xx エラーが増えたら、自動で元の AMI のインスタンスに戻したい。どうするか。
- ア：チェックポイントを付ける
- イ：自動ロールバックを有効にし、5xx のアラームを指定する
- ウ：スキップマッチングを有効にする
- エ：新しいインスタンスをスタンバイにする
- 正解：イ
- 解説：自動ロールバックは、更新の失敗や指定したアラームの ALARM で、元の設定に戻す。
- アの意味：止まるだけで、自動では戻らない。
- イの意味：正しい。
- ウの意味：新しいインスタンスを飛ばす設定で、戻す機能ではない。
- エの意味：手作業で、元には戻らない。
- 出典：オリジナル問題（根拠：AWS「Amazon EC2 Auto Scaling ユーザーガイド」手動または自動ロールバックを使用して変更を元に戻す（『自動ロールバック機能を使用すると、エラーが発生したり、指定された Amazon CloudWatch アラームが `ALARM` 状態になったりした場合など、インスタンスの更新が失敗したときに、インスタンスの更新を自動的にロールバックできます。』））

#### 問 dop-18-o03

- 問：インスタンスの更新で、全体の 20% を置き換えたところで止め、運用チームが確かめてから続けたい。何を設定するか。
- ア：チェックポイント
- イ：インスタンスのウォームアップ
- ウ：自動ロールバック
- エ：最大正常率
- 正解：ア
- 解説：チェックポイントは、指定した割合まで置き換えたら一時停止する。
- アの意味：正しい。
- イの意味：新しいインスタンスが落ち着くまで待つ時間で、確認のために止まりはしない。
- ウの意味：失敗したら戻す機能。
- エの意味：置き換え中の容量の上限。
- 出典：オリジナル問題（根拠：AWS「Amazon EC2 Auto Scaling ユーザーガイド」インスタンスの更新にチェックポイントを追加する（『チェックポイントは、インスタンスの更新が一時停止する時点です。』））

#### 問 dop-18-o04

- 問：インスタンスの更新が途中で止まった。やり直すとき、すでに新しい AMI になっているインスタンスまで置き換えたくない。どうするか。
- ア：最小正常率を 100% にする
- イ：チェックポイントを付ける
- ウ：スキップマッチングを有効にして始める
- エ：新しいインスタンスをスタンバイにする
- 正解：ウ
- 解説：スキップマッチングは、すでに新しい設定のインスタンスを飛ばす。
- アの意味：容量の下限で、どれを置き換えるかは変わらない。
- イの意味：止める位置の設定。
- ウの意味：正しい。
- エの意味：手作業で、更新の対象から外す設定ではない。
- 出典：オリジナル問題（根拠：AWS「Amazon EC2 Auto Scaling ユーザーガイド」スキップマッチングでのインスタンスの更新の使用（『スキップマッチングは、既に最新の更新が適用されているインスタンスを無視するように Amazon EC2 Auto Scaling に指示します。』））

#### 問 dop-18-o05

- 問：インスタンスの置き換えのとき、先に新しいインスタンスを起動してから古いものを終了し、容量を下げないようにしたい。何を設定するか。
- ア：ヘルスチェックの猶予期間
- イ：インスタンスメンテナンスポリシーで最小正常率を 100%、最大正常率を 100% より大きくする
- ウ：スケーリングのクールダウン
- エ：スケールインからの保護
- 正解：イ
- 解説：最小正常率と最大正常率の範囲で容量が増減するので、下限を 100% にすると先に起動してから終了する。
- アの意味：起動直後のヘルスチェックの待ち時間。
- イの意味：正しい。
- ウの意味：続けてスケーリングしないための待ち時間。
- エの意味：スケールインで終了しないようにするもので、置き換えの順番は決めない。
- 出典：オリジナル問題（根拠：AWS「Amazon EC2 Auto Scaling ユーザーガイド」インスタンスメンテナンスポリシー（『ポリシーの最小正常率と最大正常率のパラメータを設定すると、Auto Scaling グループはインスタンスを置き換えるときに、最小値と最大値の範囲内でしかキャパシティを増減できません。』））

#### 問 dop-18-o06

- 問：毎月、最新のパッチと社内の監視エージェントを入れた AMI を自動で作り、テストして、3 つのアカウントに配りたい。何を使うか。
- ア：EC2 Image Builder のパイプライン
- イ：各インスタンスで Patch Manager を動かす
