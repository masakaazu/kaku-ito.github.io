## 10-1 instanceof のパターン・マッチング

### まとめ表

| 書き方（o は Object 型） | 結果（JDK 17） | 理由 |
| :-- | :-- | :-- |
| `o instanceof String s` | o が String なら true で、s に入る | 型パターン |
| o が null のとき | false（例外にならない） | null はどの型にも当てはまらない |
| `str instanceof String s`（str は String 型） | expression type String is a subtype of pattern type String | いつも true になるパターンは書けない |
| `str instanceof String`（パターンなし） | OK（true） | 型の比較ならエラーにならない |
| `i instanceof String s`（i は Integer 型） | incompatible types: Integer cannot be converted to String | キャストできない型 |
| `o instanceof int i` | unexpected type | パターンの型は参照型だけ |
| `o instanceof var v` | 'var' is not allowed here | var は書けない |

### instanceof の 2 つの形

#### instanceof 演算子（いんすたんすおぶえんざんし / instanceof operator）

- 意味：左の値が右の型のオブジェクトかどうかを調べ、true か false を返す演算子。右に型を書く「型の比較」と、パターンを書く「パターン・マッチング」の 2 つの形がある
- ポイント：左が null なら必ず false で、例外にはならない。左の型から右の型へキャストできない組み合わせ（Integer と String など）はコンパイルエラー
- 例：`o instanceof String`

#### パターン・マッチング（ぱたーんまっちんぐ / pattern matching for instanceof）

- 意味：`式 instanceof 型 変数名` と書き、型が合えば、その型にキャストした値を新しい変数に入れる書き方。Java 16 で正式になった
- ポイント：調べる・キャストする・変数に入れる、の 3 つが 1 回で済む。前のように `(String) o` と書き直す必要がない。左の型が右の型の部分型（いつも true）だとコンパイルエラー（expression type String is a subtype of pattern type String）
- 例：`if (o instanceof String s) System.out.println(s.length());`

#### 型パターン（かたぱたーん / type pattern）

- 意味：`型 変数名` の形のパターン。値がその型ならマッチし、変数に値が入る
- ポイント：型は参照型だけ（int は unexpected type）。var は使えない。初期化子（= 値）は付けられない。final は付けられる
- 例：`Integer n`・`final String t`

#### パターン変数（ぱたーんへんすう / pattern variable）

- 意味：型パターンで宣言される変数。マッチしたときだけ値が入る
- ポイント：ふつうのローカル変数と同じ扱いで、Java 17 では final ではない（代入できる）。final を付ければ代入できない（cannot assign a value to final variable t）。同じ名前のローカル変数がすでにあると variable s is already defined
- 例：`if (o instanceof String s) { s = s + "!"; }`

## 10-2 パターン変数のスコープ

### まとめ表

| 書き方 | s を使える場所（JDK 17） |
| :-- | :-- |
| `if (o instanceof String s) { … } else { … }` | if の { } の中だけ。else では cannot find symbol |
| `o instanceof String s && s.length() > 3` | && の右側で使える |
| `o instanceof String s \|\| s.length() > 3` | 使えない（cannot find symbol） |
| `if (!(o instanceof String s)) return;` のあと | if 文のあとで使える |
| `if (!(o instanceof String s)) { print(); }` のあと | 使えない（return がないので） |
| `while (!(o instanceof Integer i)) { … }` のあと | while 文のあとで使える |

### フロー・スコープ

#### パターン変数のスコープ（ぱたーんへんすうのすこーぷ / scope of pattern variables）

- 意味：パターン変数が使える範囲。「確実にマッチしている」と分かる場所だけ
- ポイント：if の条件が true のときに入る { } の中では使える。else や、if の外では使えない（流れによる例外は下）。これをフロー・スコープ（flow scoping）と呼ぶ
- 例：`if (o instanceof String s) { s.length(); } else { /* s は使えない */ }`

#### && と ||（あんどあんどとおあおあ / conditional-and and conditional-or）

- 意味：パターン・マッチングを && や || とつなげたときのスコープの決まり
- ポイント：`a && b` の b は「a が true のとき」だけ評価されるので、a のパターン変数を b で使える。`a || b` の b は「a が false のとき」に評価されるので、使えない
- 例：`if (o instanceof String s && s.length() > 3)`

#### ! と早期 return（びっくりとそうきりたーん / negation and early return）

- 意味：`if (!(o instanceof String s)) return;` のように、マッチしないときにメソッドを抜けると、if 文のあとでパターン変数を使える決まり
- ポイント：if の中が正常に終わらない（return・throw など）ときだけ。中で表示するだけなら、あとで s を使うと cannot find symbol
- 例：`if (!(o instanceof String s)) { return; } System.out.println(s.length());`

#### switch のパターン（すいっちのぱたーん / pattern matching for switch）

- 意味：`case String s ->` のように、switch のラベルにパターンを書く書き方
- ポイント：Java 17 ではプレビュー機能で、ふつうにコンパイルすると patterns in switch statements are a preview feature and are disabled by default。正式になったのは Java 21。1Z0-825 の範囲では instanceof のパターンだけを覚える
- 例：（Java 17 では書けない）`case String s -> …`

## 10-3 レコード

### まとめ表

| `record Point(int x, int y) { }` で自動で作られるもの | 中身 |
| :-- | :-- |
| フィールド | `private final int x;`・`private final int y;` |
| アクセサメソッド | `public int x()`・`public int y()`（getX ではない） |
| 正規コンストラクタ | `Point(int x, int y)`（引数なしのコンストラクタはない） |
| equals | 同じレコード型で、全コンポーネントが等しければ true |
| hashCode | equals が true なら同じ値 |
| toString | `Point[x=1, y=2]` の形（JDK 17 の表示） |

### レコードのしくみ

#### レコード（れこーど / record class）

- 意味：`record 名前(コンポーネント) { }` と書く、値をまとめて持つための特別なクラス。Java 16 で正式になった
- ポイント：暗黙に final で、継承できない（cannot inherit from final P）。extends は書けない（親は必ず java.lang.Record）。インタフェースは実装できる。abstract は付けられない。メソッドの中にも書ける（ローカル・レコード）
- 例：`record Point(int x, int y) { }`

#### レコード・コンポーネント（れこーどこんぽーねんと / record component）

- 意味：レコード名のあとのかっこに書く `型 名前` の並び。レコードが持つ値
- ポイント：1 つのコンポーネントから、private final のフィールドと public のアクセサメソッドが作られる。0 個でもよい（`record E() { }` の表示は E[]）
- 例：`(String name, int age)`

#### アクセサメソッド（あくせさめそっど / accessor method）

- 意味：コンポーネントと同じ名前で、その値を返す引数なしのメソッド
- ポイント：名前は `x()` で、getX() ではない（cannot find symbol）。自分で書き直してもよいが、public で、戻り値の型を同じにしなければならない（public がないと invalid accessor method in record P）。書き直しても toString はフィールドの値を使う
- 例：`p.x()`

#### 自動の equals・hashCode・toString（じどうのいこーるず / implicit equals, hashCode, toString）

- 意味：レコードに自動で用意される 3 つのメソッド。すべてのコンポーネントの値から作られる
- ポイント：equals は中身を比べるので `new Point(1, 2).equals(new Point(1, 2))` は true（== は別のオブジェクトなので false）。自分で書けば、それが使われる。toString の正確な形は API では決められていない（JDK 17 では Point[x=1, y=2]）
- 例：`System.out.println(new Person("Ann", 3));` → Person[name=Ann, age=3]

### コンストラクタと制約

#### 正規コンストラクタ（せいきこんすとらくた / canonical constructor）

- 意味：すべてのコンポーネントを、同じ順・同じ型の引数で受け取って初期化するコンストラクタ。書かなければ自動で作られる
- ポイント：レコードにはデフォルトコンストラクタがない（new Point() はエラー）。ふつうの形で書くなら、すべてのフィールドに `this.x = x;` のように代入する
- 例：`P(int x, int y) { this.x = x; this.y = y * 2; }`

#### コンパクト・コンストラクタ（こんぱくとこんすとらくた / compact canonical constructor）

- 意味：引数のかっこを省いて `名前 { … }` と書く、正規コンストラクタの短い形。値のチェックや整えに使う
- ポイント：中の x は引数の x。引数に代入して整えると（`s = s.trim();`）、本体のあとにその値がフィールドに入る。`this.s = …` とフィールドに代入するとエラー（cannot assign a value to final variable s）。return も書けない。同じシグネチャの正規コンストラクタと一緒には書けない
- 例：`Age { if (v < 0) throw new IllegalArgumentException(); }`

#### 正規でないコンストラクタ（せいきでないこんすとらくた / non-canonical constructor）

- 意味：引数の並びが正規コンストラクタとちがうコンストラクタ
- ポイント：最初の文で `this(…)` を使い、ほかのコンストラクタを呼ばなければならない（constructor is not canonical, so its first statement must invoke another constructor）
- 例：`P(int x) { this(x, 0); }`

#### レコードの制約（れこーどのせいやく / restrictions on records）

- 意味：レコードの本体に書けないもの
- ポイント：static でないフィールドは書けない（field declaration must be static）。インスタンス初期化子も書けない（instance initializers not allowed in records）。static フィールド・static メソッド・インスタンスメソッドは書ける。フィールドは final なので、setter は作れない
- 例：`record P(int x) { static int count; int twice() { return x * 2; } }`

#### 浅い不変（あさいふへん / shallow immutability）

- 意味：レコードのフィールドは再代入できないが、フィールドが指すオブジェクト（リストなど）の中身は変えられること
- ポイント：`record R(List<String> list)` で `r.list().add("a")` はできる。中身まで守りたいなら、コンパクト・コンストラクタで `list = List.copyOf(list);` のようにコピーする（#09 の防御的コピー）
- 例：`R[list=[a]]`

### 10-1 instanceof のパターン・マッチング

#### 問 java-10-o01

- 問：main メソッドの中の次のコードを実行した。表示されるものはどれか。

  ```
  Object o = "hello";
  if (o instanceof String s) {
    System.out.println(s.length() + " " + s.toUpperCase());
  }
  ```

- ア：s.length() の行でコンパイルエラーになる（o を String にキャストしていない）
- イ：何も表示されない
- ウ：実行時に ClassCastException がスローされる
- エ：5 HELLO
- 正解：エ
- 解説：o instanceof String s は、o が String なら true になり、String にした値を s に入れる。s は String 型なので、length() や toUpperCase() をそのまま使える。
- アの意味：パターン・マッチングでは、s がすでに String 型なのでキャストは要らない。
- イの意味：o の中身は String なので、条件は true。
- ウの意味：型を調べてから入れるので、ClassCastException は起きない。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：JLS 15.20.2（A side effect of a true result is that pattern variables declared in Pattern will be initialized）／JDK 17 での実行結果）

#### 問 java-10-o02

- 問：main メソッドの中の次のコードを実行した。表示されるものはどれか。

  ```
  Object o = null;
  System.out.println((o instanceof String s) + " " + (null instanceof String) + " " + (o instanceof Object));
  ```

- ア：NullPointerException がスローされる
- イ：false false true
- ウ：false false false
- エ：true true true
- 正解：ウ
- 解説：instanceof の左が null のときは、型の比較でもパターン・マッチングでも結果は false。Object と比べても false で、例外にはならない。
- アの意味：instanceof は null を調べても例外にならない。
- イの意味：null はどんな型とも合わない。Object でも false。
- ウの意味：正しい。
- エの意味：null をすべての型に入れられることと、instanceof の結果を取りちがえている。
- 出典：オリジナル問題（根拠：JLS 15.20.2（If the value of the RelationalExpression is the null reference, then the result is false）／JDK 17 での実行結果）

#### 問 java-10-o03

- 問：main メソッドの中の次のコードをコンパイルした。結果として正しいものはどれか。

  ```
  String str = "a";
  if (str instanceof String s) System.out.println(s);
  ```

- ア：expression type String is a subtype of pattern type String のコンパイルエラーになる
- イ：コンパイルでき、a と表示される
- ウ：コンパイルでき、何も表示されない
- エ：コンパイルでき、実行時に ClassCastException がスローされる
- 正解：ア
- 解説：パターン・マッチングでは、左の式の型がパターンの型と同じか部分型（いつも true になる）だとコンパイルエラーになる。パターンのない `str instanceof String` ならエラーにならず true。
- アの意味：正しい。
- イの意味：型の比較（パターンなし）なら OK だが、パターンを付けるとエラー。
- ウの意味：コンパイルの段階で止まる。
- エの意味：実行時の問題ではない。
- 出典：オリジナル問題（根拠：JLS 15.20.2（If the type of the RelationalExpression is a subtype of the type of the Pattern, then a compile-time error occurs）／JDK 17 でのコンパイル結果）

#### 問 java-10-o04

- 問：main メソッドの中の次のコードをコンパイルした。結果として正しいものはどれか。

  ```
  Integer i = 1;
  if (i instanceof String s) System.out.println(s);
  ```

- ア：コンパイルでき、何も表示されない
- イ：incompatible types: Integer cannot be converted to String のコンパイルエラーになる
- ウ：コンパイルでき、1 と表示される
- エ：実行時に ClassCastException がスローされる
- 正解：イ
- 解説：Integer 型の値が String のオブジェクトであることはありえない（キャストできない組み合わせ）。そういう instanceof はコンパイルの段階でエラーになる。
- アの意味：ありえない組み合わせは false になるのではなく、コンパイルできない。
- イの意味：正しい。
- ウの意味：Integer が自動で String に変わることはない。
- エの意味：コンパイルの段階で止まる。
- 出典：オリジナル問題（根拠：JLS 15.20.2（The RelationalExpression must be compatible with the Pattern, or a compile-time error occurs）・5.5 Casting Contexts／JDK 17 でのコンパイル結果）

#### 問 java-10-o05

- 問：o は Object 型、str は String 型の変数とする。コンパイルできる式はどれか。
- ア：`o instanceof int i`
- イ：`o instanceof var v`
- ウ：`o instanceof Integer i`
- エ：`str instanceof String s`
- 正解：ウ
- 解説：型パターンの型は参照型でなければならず、var は使えない。また、左の型がパターンの型の部分型だとエラー。Object を Integer で調べるのは問題ない。
- アの意味：基本型は書けない（unexpected type）。
- イの意味：'var' is not allowed here になる。
- ウの意味：正しい。
- エの意味：String を String で調べるのはいつも true なので、expression type String is a subtype of pattern type String になる。
- 出典：オリジナル問題（根拠：JLS 14.30.1（The LocalVariableType denotes a reference type (and furthermore is not var)）・15.20.2／JDK 17 でのコンパイル結果）

#### 問 java-10-o06

- 問：main メソッドの中の次のコードを実行した。表示されるものはどれか。

  ```
  Object o = 42;
  if (o instanceof Integer n && n > 40) System.out.println("big " + (n + 1));
  if (o instanceof Number n) System.out.println("num " + n.intValue());
  if (o instanceof String s) System.out.println("str");
  else System.out.println("not str");
  ```

- ア：big 421・num 42・not str の 3 行
- イ：2 つめの if で、n がすでに定義されているというコンパイルエラーになる
- ウ：big 43・num 42・not str の 3 行
- エ：num 42・not str の 2 行
- 正解：ウ
- 解説：42 は Integer に自動ボクシングされている。Integer でマッチし n > 40 なので n + 1 = 43（かっこの中は数の足し算）。Integer は Number の一種なので 2 つめもマッチする。1 つめの n のスコープは 1 つめの if の中だけなので、2 つめで同じ名前を使える。String ではないので not str。
- アの意味：(n + 1) のかっこを見落とし、文字列の連結と考えたまちがい。
- イの意味：パターン変数のスコープはそれぞれの if の中だけで、重ならない。
- ウの意味：正しい。
- エの意味：n > 40 は 42 > 40 で true。
- 出典：オリジナル問題（根拠：JLS 6.3.1.1（A pattern variable introduced by a when true is definitely matched at b）・6.3.2.2／JDK 17 での実行結果）

#### 問 java-10-o07

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  public class Main {
    static String f(Object o) {
      return o instanceof Integer i ? "int " + (i + 1) : "other";
    }
    public static void main(String[] args) {
      System.out.println(f(5) + " / " + f("5"));
    }
  }
  ```

- ア：int 51 / other
- イ：int 6 / int 6
- ウ：? : の中でパターン変数は使えないのでコンパイルエラーになる
- エ：int 6 / other
- 正解：エ
- 解説：条件演算子の 2 番目のオペランドは、条件が true のときだけ評価されるので、i を使える。f(5) は Integer なので int 6、f("5") は文字列なので other。
- アの意味：(i + 1) を文字列の連結と考えたまちがい。
- イの意味："5" は文字列で、Integer ではない。
- ウの意味：条件演算子の true 側ではパターン変数を使える。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：JLS 6.3.1.4（Conditional Operator ? :／A pattern variable introduced by a when true is definitely matched at b）／JDK 17 での実行結果）

#### 問 java-10-o08

- 問：main メソッドの中の次のコードを実行した。表示されるものはどれか。

  ```
  Object o = "x";
  if (o instanceof String s) {
    s = s + "!";
    System.out.println(s);
  }
  System.out.println(o);
  ```

- ア：x! と x! の 2 行
