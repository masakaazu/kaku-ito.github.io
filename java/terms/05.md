## 05-1 算術演算子とインクリメント

### まとめ表

| 式 | 結果（JDK 17） | 理由 |
| :-- | :-- | :-- |
| `7 / 2`・`-7 / 2` | 3・-3 | 整数の割り算は 0 の方向に切り捨て |
| `-7 % 3`・`7 % -3` | -1・1 | 余りの符号は割られる数（左）と同じ |
| `5 / 0` | ArithmeticException | 整数の 0 割りは例外 |
| `5.0 / 0`・`0.0 / 0` | Infinity・NaN | 浮動小数点の 0 割りは例外にならない |
| `x = 5; y = x++ + ++x;` | x は 7、y は 12 | 後置は元の値、前置は増やした値を使う |
| `x = 5; x = x++;` | x は 5 | x++ の値 5 を最後に x に代入し直す |
| `a[i] = i = 2;`（i は 0） | a[0] が 2 | 左の a[i] を先に決める（左から評価） |

### 算術演算子

#### 演算子とオペランド（えんざんしとおぺらんど / operator, operand）

- 意味：演算子は + や == のように計算を表す記号。オペランドは演算子が計算に使う値や変数
- ポイント：オペランドの数で、単項（-x・!b・x++）、二項（a + b）、三項（c ? a : b）に分かれる
- 例：`a + b` の + が演算子、a と b がオペランド

#### 算術演算子（さんじゅつえんざんし / arithmetic operators）

- 意味：+（足す）・−（引く）・*（掛ける）・/（割る）・%（余り）の 5 つ
- ポイント：計算の前にオペランドは数値の昇格を受ける。byte・short・char どうしでも結果は int（#02）。*・/・% は +・− より先に計算する。同じ優先順位なら左から（`10 - 4 - 3` は 3）
- 例：`2 + 3 * 4 - 6 / 2 % 2` → 2 + 12 − 1 = 13

#### 整数の割り算（せいすうのわりざん / integer division）

- 意味：両方が整数のときの /。小数部分を捨てて整数を返す
- ポイント：0 の方向に切り捨てる（JLS 15.17.2：Integer division rounds toward 0）。`-7 / 2` は −3（−4 ではない）。`double d = 10 / 4;` は先に int で 2 を計算してから 2.0 になる。小数がほしければ片方を 4.0 にする
- 例：`10 / 4` → 2、`10 / 4.0` → 2.5

#### 剰余演算子（じょうよえんざんし / remainder operator）

- 意味：% は割り算の余りを返す演算子
- ポイント：(a / b) * b + (a % b) が a になるように決まる。だから余りの符号は左（割られる数）と同じ（JLS 15.17.3）。double にも使える
- 例：`-7 % 3` → −1、`7 % -3` → 1、`7.5 % 2` → 1.5

#### ArithmeticException（ありすめてぃっくえくせぷしょん）

- 意味：整数の計算で、0 で割ったときなどに実行時にスローされる例外
- ポイント：整数の / と % で右が 0 のとき（表示は「/ by zero」）。浮動小数点の割り算では例外にならない（JLS 15.17.2：never throws a run-time exception）。オーバーフローも例外にならない（#02）
- 例：`5 / 0`、`5 % 0`
- 語の意味：Arithmetic（算術の）＋Exception（例外）

#### Infinity と NaN（いんふぃにてぃとなん / Infinity, NaN）

- 意味：浮動小数点の特別な値。Infinity は無限大、NaN は「数ではない」（Not a Number）
- ポイント：`5.0 / 0` は Infinity、`-5.0 / 0` は −Infinity、`0.0 / 0` と `5 % 0.0` は NaN。NaN は自分自身とも等しくない（`Double.NaN == Double.NaN` は false）
- 例：`System.out.println(1.0 / 0);` → Infinity
- 語の意味：NaN＝Not a Number（数ではない）

### インクリメントと評価の順序

#### 後置インクリメント（こうちいんくりめんと / postfix increment）

- 意味：`x++` の形。変数を 1 増やすが、式の値は増やす前の値
- ポイント：`y = x++;` は y に元の値が入り、そのあと x が増える（JLS 15.14.2：The value of the postfix increment expression is the value of the variable before the new value is stored）。`x = x++;` は x が増えたあとで元の値が代入され、結果は変わらない
- 例：x が 5 のとき `System.out.println(x++);` は 5、その後 x は 6

#### 前置インクリメント（ぜんちいんくりめんと / prefix increment）

- 意味：`++x` の形。変数を 1 増やし、式の値は増やしたあとの値
- ポイント：1 つの式に x++ と ++x がまざる問題は、左から 1 つずつ「値」と「x の今の値」を書き出して追う
- 例：x が 5 のとき `x++ + ++x` → 5 + 7 = 12（x は 7）

#### デクリメント（でくりめんと / decrement）

- 意味：`x--`・`--x` で変数を 1 減らす。前置・後置の違いはインクリメントと同じ
- ポイント：final の変数には使えない（cannot assign a value to final variable）。リテラルや式（`5++`・`(a + b)++`）にも使えない。char にも使える（'A' の次は 'B'）
- 例：a が 3 のとき `a-- - --a` → 3 − 1 = 2（a は 1）

#### 評価の順序（ひょうかのじゅんじょ / evaluation order）

- 意味：式の部品を計算する順番。Java では二項演算子の左のオペランドを先に全部計算する
- ポイント：優先順位は「どれとどれを組にするか」で、計算する順番は左から（JLS 15.7.1：The left-hand operand of a binary operator appears to be fully evaluated before any part of the right-hand operand is evaluated）。`a[i] = i = 2;` は a[i] の i を先に決めるので a[0] が 2 になる
- 例：i が 1 のとき `i++ + i++ * 2` → 1 + 2 * 2 = 5

## 05-2 代入と比較

### まとめ表

| 式 | 結果（JDK 17） | 理由 |
| :-- | :-- | :-- |
| `a = b = c = 7;` | 3 つとも 7 | 代入は右から。代入式自体が値を持つ |
| `x += x -= 3;`（x は 10） | x は 17 | 左の x の値 10 を先に覚える |
| `short s = 10; s += 5.7;` | s は 15 | 複合代入は (short) のキャストつき |
| `s = s + 1;`（s は short） | コンパイルエラー | s + 1 は int |
| `0.1 + 0.2 == 0.3` | false | 浮動小数点は 2 進数の近い値 |
| `10 == 10.0`・`'a' == 97` | true・true | 数値の昇格のあと値で比べる |
| `if (x = 1)`（x は int） | コンパイルエラー | 条件は boolean だけ |
| `if (b = true)`（b は boolean） | 通る（いつも true） | 代入式の値 true が条件になる |

### 代入演算子

#### 代入演算子（だいにゅうえんざんし / assignment operator）

- 意味：= は右辺の値を左辺の変数に入れる演算子。代入式そのものも、入れた値を持つ
- ポイント：右から結合するので `a = b = c = 7` は `a = (b = (c = 7))`。代入式が値を持つので、boolean の変数なら `if (b = true)` もコンパイルでき、いつも true（== の書きまちがいのひっかけ）
- 例：`int a, b; a = b = 5;`

#### 複合代入演算子（ふくごうだいにゅうえんざんし / compound assignment operator）

- 意味：+=・−=・*=・/=・%= など、演算と代入をまとめた演算子
- ポイント：`E1 op= E2` は `E1 = (T)((E1) op (E2))` と同じで、左辺の型へのキャストが自動で入る（JLS 15.26.2）。左辺の値は先に覚えておく。`x += x -= 3`（x は 10）は 10 + 7 = 17。右辺は全体がかっこに入る（`x *= 3 + 4` は x * 7）
- 例：`byte b = 10; b *= 30;` → (byte)300 で 44

#### 二項数値昇格（にこうすうちしょうかく / binary numeric promotion）

- 意味：二項演算子の前に、2 つのオペランドを同じ型にそろえるしくみ
- ポイント：どちらかが double なら double、次に float、次に long、それ以外は int（JLS 5.6）。byte + byte も int なので `byte c = a + b;` はコンパイルエラー。ただし a・b が final の定数で、結果が byte の範囲なら定数式として代入できる
- 例：`final byte a = 10, b = 20; byte c = a + b;` → 30

#### char の計算（きゃらのけいさん / arithmetic on char）

- 意味：char は文字コードを表す整数型なので、算術演算子で計算できる
- ポイント：`c + 1` は int になり数が表示される（'A' + 1 → 66）。文字に戻すにはキャスト `(char)(c + 1)`。`c++` や `c += 1` は char のまま（'B'）
- 例：`char c = 'A'; System.out.println(c + 1);` → 66

### 比較演算子

#### 関係演算子（かんけいえんざんし / relational operators）

- 意味：<・>・<=・>= で数の大小を比べ、boolean を返す演算子
- ポイント：数値（char を含む）どうしだけに使える。boolean や String には使えない。instanceof も関係演算子の仲間（#10）
- 例：`'a' < 'b'` → true

#### 等価演算子（とうかえんざんし / equality operators）

- 意味：== と != で、等しいか・等しくないかを比べる演算子
- ポイント：数値は昇格したあと値で比べる（`10 == 10.0` は true）。boolean どうしも比べられる。参照型は同じオブジェクトかどうかを比べる（中身は equals）。int と boolean のように比べられない型どうしはコンパイルエラー
- 例：`1.0f == 1.0` → true

#### 浮動小数点の比較（ふどうしょうすうてんのひかく / comparing floating-point values）

- 意味：double や float の値を == で比べること
- ポイント：0.1 などは 2 進数で正確に表せないので、`0.1 + 0.2 == 0.3` は false。NaN はどれとも等しくなく、自分とも等しくない
- 例：`System.out.println(0.1 + 0.2);` → 0.30000000000000004

#### ラッパーの == （らっぱーのいこーるいこーる / == on wrapper objects）

- 意味：Integer などのラッパーどうしを == で比べると、値ではなくオブジェクトが同じかを比べる
- ポイント：−128〜127 の int をオートボクシングすると、いつも同じオブジェクトになる（JLS 5.1.7）。それ以外は同じになる保証がない（JDK 17 の標準設定では 128 どうしの == は false）。値を比べるなら equals。片方が int なら、もう片方をアンボクシングして値で比べる
- 例：`Integer e = 1000; int f = 1000; e == f` → true（値で比べる）

#### 条件式の型（じょうけんしきのかた / boolean condition）

- 意味：if・while などの条件に書く式。boolean（または Boolean）でなければならない
- ポイント：C 言語と違い、0 や 1 は条件にならない。`if (x = 1)` は int を boolean にできずコンパイルエラー。`boolean b = 1;` もコンパイルエラー
- 例：`if (x == 1)` と書く

## 05-3 論理演算子とビット演算子

### まとめ表

| 演算子 | 意味 | 右側を計算するか |
| :-- | :-- | :-- |
| `&&` | かつ | 左が false なら計算しない（短絡） |
| `\|\|` | または | 左が true なら計算しない（短絡） |
| `&`（boolean） | かつ | 必ず計算する |
| `\|`（boolean） | または | 必ず計算する |
| `^`（boolean） | どちらか一方だけ true | 必ず計算する |
| `!` | 否定 | 単項（boolean だけ） |
| `&`・`\|`・`^`・`~`（整数） | ビットごとの AND・OR・XOR・反転 | ― |

### 論理演算子

#### 条件 AND 演算子（じょうけんあんどえんざんし / conditional-and operator）

- 意味：`&&`。両方が true のときだけ true
- ポイント：左が false なら右を計算しない（JLS 15.23：evaluates its right-hand operand only if the value of its left-hand operand is true）。右に x++ やメソッド呼び出しがあると、実行されないことがある。null チェックに使う：`s != null && s.length() > 0`
- 例：x が 0 のとき `(x > 0) && (++x > 0)` は false で、x は 0 のまま

#### 条件 OR 演算子（じょうけんおあえんざんし / conditional-or operator）

- 意味：`||`。どちらかが true なら true
- ポイント：左が true なら右を計算しない（JLS 15.24）。&& は || より優先順位が高いので、`a || b && c` は `a || (b && c)`。a が true なら b && c 全体が計算されない
- 例：x が 5 のとき `x > 3 || x++ > 0 && x++ > 0` は true で、x は 5 のまま

#### 短絡評価（たんらくひょうか / short-circuit evaluation）

- 意味：左だけで結果が決まったら、右を計算しないこと
- ポイント：&& と || だけが短絡する。& と | は boolean でも両方を必ず計算する。`s != null & s.length() > 0` は s が null だと NullPointerException
- 例：`s == null || s.length() > 0`（s が null でも安全）

#### 論理演算子 & と |（ろんりえんざんしあんどとおあ / boolean logical operators & and |）

- 意味：boolean に使う & は「かつ」、| は「または」。短絡しない
- ポイント：結果は && や || と同じだが、右も必ず計算する。右に ++ があると変数が増える。同じ記号を整数に使うとビット演算子になる
- 例：x が 0 のとき `(x > 0) & (++x > 0)` は false で、x は 1

#### 排他的論理和（はいたてきろんりわ / exclusive or, XOR）

- 意味：`^`。2 つの boolean のうち、ちょうど一方だけが true のとき true
- ポイント：`true ^ true` は false、`true ^ false` は true。べき乗の記号ではない（2 ^ 3 は整数の XOR で 1）
- 例：`false ^ true` → true
- 語の意味：XOR＝eXclusive OR（排他的な または）

#### 論理否定演算子（ろんりひていえんざんし / logical complement operator）

- 意味：`!`。boolean の true と false を反対にする単項演算子
- ポイント：boolean にしか使えない（`!a` で a が int だと bad operand type int for unary operator '!'）。単項演算子は関係演算子より先に計算されるので、`!a > 5` は `(!a) > 5` になる。かっこで `!(a > 5)` と書く
- 例：`!(10 > 5)` → false

### ビット演算子とシフト

#### ビット演算子（びっとえんざんし / bitwise operators）

- 意味：整数を 2 進数で見て、各ビットごとに計算する演算子。&（AND）・|（OR）・^（XOR）・~（反転）
- ポイント：6 は 110、3 は 011 なので 6 & 3 = 2（010）、6 | 3 = 7（111）、6 ^ 3 = 5（101）。~x は −x − 1（~5 は −6）
- 例：`System.out.println(6 & 3);` → 2

#### シフト演算子（しふとえんざんし / shift operators）

- 意味：ビットを左右にずらす演算子。<<（左）・>>（右、符号を保つ）・>>>（右、左を 0 で埋める）
- ポイント：`8 << 2` は 8 × 4 = 32、`-8 >> 1` は −4、`8 >>> 1` は 4。負の数に >>> を使うと大きな正の数になる（`-1 >>> 28` は 15）
- 例：`1 << 3` → 8

## 05-4 優先順位と三項演算子

### まとめ表

| 優先順位（高い順） | 演算子 |
| :-- | :-- |
| 1 後置 | `x++`・`x--` |
| 2 単項 | `++x`・`--x`・`+x`・`-x`・`~`・`!` |
| 3 乗除 | `*`・`/`・`%` |
| 4 加減 | `+`・`-` |
| 5 シフト | `<<`・`>>`・`>>>` |
| 6 関係 | `<`・`>`・`<=`・`>=`・`instanceof` |
| 7 等価 | `==`・`!=` |
| 8〜10 ビット・論理 | `&` → `^` → `\|` |
| 11〜12 条件 | `&&` → `\|\|` |
| 13 三項 | `? :` |
| 14 代入 | `=`・`+=` など |

### 優先順位と結合

#### 優先順位（ゆうせんじゅんい / operator precedence）

- 意味：1 つの式に複数の演算子があるとき、どれを先に組にするかの順番
- ポイント：Java Tutorials の表の順（上の表）。後置・単項 → 乗除 → 加減 → シフト → 関係 → 等価 → & → ^ → | → && → || → 三項 → 代入。迷ったらかっこで書く
- 例：`2 * 3 % 4` は同じ優先順位なので左から → 6 % 4 = 2

#### 結合規則（けつごうきそく / associativity）

- 意味：同じ優先順位の演算子が並んだとき、左右どちらから組にするかの決まり
- ポイント：代入演算子以外の二項演算子は左から、代入演算子は右から（Java Tutorials：All binary operators except for the assignment operators are evaluated from left to right; assignment operators are evaluated right to left）。三項演算子も右から組になる
- 例：`10 - 4 - 3` → (10 − 4) − 3 = 3

### 三項演算子

#### 三項演算子（さんこうえんざんし / conditional operator）

- 意味：`条件 ? 値1 : 値2`。条件が true なら値1、false なら値2 になる式
- ポイント：選ばれなかった側は計算されない（`true ? y++ : y--` は y++ だけ）。式なので単独の文にはできない（`x > 2 ? System.out.println("a") : …;` は not a statement）。入れ子は右から組になる：`a ? "x" : b ? "y" : "z"`
- 例：`String s = x > 5 ? "big" : "small";`

#### 三項演算子の型（さんこうえんざんしのかた / type of a conditional expression）

- 意味：三項演算子の式全体の型。2 つの値の型から決まる
- ポイント：数値どうしは数値の昇格でそろえる（`true ? 1 : 2.0` は 1.0）。char と、char に入る int の定数なら char（`false ? 'a' : 98` は 'b'）。String と int のように合わない型を String の変数に入れるとコンパイルエラー（bad type in conditional expression）
- 例：`System.out.println(true ? 1 : 2.0);` → 1.0

## 問題演習

- 書式：「#### 問 問題ID」の下に、問・（あれば）コード・ア〜エ・正解・解説・選択肢ごとの意味・出典を書く。「###」は小分類（クイズの範囲に使う）

### 05-1 算術演算子とインクリメント

#### 問 java-05-o01

- 問：main メソッドの中の次のコードを実行した。表示されるものはどれか。

  ```
  System.out.println(7 / 2 + " " + -7 / 2 + " " + -7 % 3 + " " + 7 % -3);
  ```

- ア：3 -3 -1 1
- イ：3 -4 2 -2
- ウ：3.5 -3.5 -1 1
- エ：3 -3 1 -1
- 正解：ア
- 解説：整数どうしの / は 0 の方向に切り捨てるので 7 / 2 は 3、−7 / 2 は −3。% の結果の符号は左（割られる数）と同じなので、−7 % 3 は −1、7 % −3 は 1。
- アの意味：正しい。
- イの意味：小さいほうに切り捨てる（床関数）と考えたまちがい。Python などの言語の結果に近い。
- ウの意味：整数どうしの割り算でも小数になると考えたまちがい。
- エの意味：余りの符号を右（割る数）に合わせたまちがい。
- 出典：オリジナル問題（根拠：JLS 15.17.2（Integer division rounds toward 0）・15.17.3（the result of the remainder operation can be negative only if the dividend is negative）／JDK 17 での実行結果）

### 05-3 論理演算子とビット演算子

#### 問 java-05-o17

- 問：main メソッドの中の次のコードを実行した。表示されるものはどれか。

  int x = 0;

  boolean r2 = (x > 0) & (++x > 0);

- イの意味：& で右が先に計算されると考えたまちがい。左の (x > 0) は x が 0 のときに計算され false。
- ウの意味：|| も右を計算すると考えたまちがい。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：JLS 15.23・15.24（evaluates its right-hand operand only if …）・15.22.2（& と | は両方を評価する）／JDK 17 での実行結果）

#### 問 java-05-o18

  ```
  int x = 5;
  boolean r = x > 3 || x++ > 0 && x++ > 0;

  ```

- ア：true 6
- イ：true 7
- ウ：false 7

- 解説：&& は || より優先順位が高いので、式は x > 3 || (x++ > 0 && x++ > 0) と組になる。左の x > 3 が true なので、|| は右（&& 全体）を計算しない。x は 5 のまま。

- イの意味：短絡評価を考えず、x++ を 2 回とも実行したまちがい。
- ウの意味：結果も x の値もまちがい。左が true なので結果は true。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：JLS 15.23・15.24／Java Tutorials Operator Precedence（logical AND は logical OR より上）／JDK 17 での実行結果）

#### 問 java-05-o19

- 問：main メソッドの中の次のコードを実行した。結果として正しいものはどれか。

  ```
  String s = null;

- エの意味：正しい。

### 05-4 優先順位と三項演算子

#### 問 java-05-o23

- 問：main メソッドの中の次のコードを実行した。表示されるものはどれか。

  ```
  System.out.println(2 + 3 * 4 - 6 / 2 % 2);

- イ：13 と 9 の 2 行

- イの意味：10 − (4 − 3) と右から組にしたまちがい。
- ウの意味：% 2 を見落として 6 / 2 = 3 を引いたまちがい（2 + 12 − 3）。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：JLS 15.17（The multiplicative operators have the same precedence and are syntactically left-associative）・15.18／Java Tutorials Operator Precedence／JDK 17 での実行結果）
