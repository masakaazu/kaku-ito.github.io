## 08-1 クラスとインスタンス

### まとめ表

| 変数の種類 | 初期化しないで使うと | 値 |
| :-- | :-- | :-- |
| フィールド（int・long など整数） | 既定値が入る | 0 |
| フィールド（double・float） | 既定値が入る | 0.0 |
| フィールド（boolean） | 既定値が入る | false |
| フィールド（char） | 既定値が入る | '\u0000'（数としては 0） |
| フィールド（String・配列などの参照型） | 既定値が入る | null |
| ローカル変数 | コンパイルエラー | variable x might not have been initialized |

### クラスとインスタンス

#### クラス（くらす / class）

- 意味：オブジェクトの設計図。どんなデータ（フィールド）を持ち、どんな処理（メソッド）ができるかを書いたもの
- ポイント：クラスを書いただけではデータは作られない。new でインスタンスを作ってはじめて、フィールドの入れ物がメモリにできる。1 つのファイルに public でないクラスを複数書ける（public は 1 つまで、#01）
- 例：`class Counter { int count; void inc() { count++; } }`

#### インスタンス（いんすたんす / instance）

- 意味：クラスをもとに new で作った、1 つ 1 つの実体。オブジェクトとも呼ぶ
- ポイント：インスタンスごとにフィールドを別々に持つ。a.inc() で増えるのは a のフィールドだけで、b には影響しない
- 例：`Counter a = new Counter(); Counter b = new Counter();`

#### フィールド（ふぃーるど / field）

- 意味：クラスの中、メソッドの外で宣言した変数。static のないものはインスタンス変数（インスタンスごとに 1 つ）
- ポイント：初期化しなくても既定値が入る（ローカル変数とのちがい）。`オブジェクト.フィールド名` で読み書きする
- 例：`int count;`（new した直後は 0）

#### new 演算子（にゅーえんざんし / class instance creation expression）

- 意味：`new クラス名(引数)` で、インスタンスを作りコンストラクタを実行して、その参照を返す式
- ポイント：new 1 回でオブジェクトが 1 個できる。変数どうしの代入（`A c = a;`）ではオブジェクトは増えない。引数に合うコンストラクタがないとコンパイルエラー
- 例：`A a = new A();`

#### 参照（さんしょう / reference）

- 意味：オブジェクトがある場所を指す値。クラス型の変数に入っているのはオブジェクトそのものではなく参照
- ポイント：`A b = a;` は参照のコピーで、a と b は同じオブジェクトを指す（b.n を変えると a.n も変わる）。== は同じオブジェクトかどうかを比べる。Object の equals も、オーバーライドしなければ == と同じ
- 例：`new A(1) == new A(1)` は false（別のオブジェクト）

### 既定値と null

#### 既定値（きていち / default value）

- 意味：フィールドや配列の要素を作ったときに自動で入る値。数は 0（0.0）、boolean は false、char は '\u0000'、参照型は null
- ポイント：ローカル変数には既定値がない。値を入れる前に使うと variable x might not have been initialized（実行前のコンパイルで止まる）
- 例：`new A().s` は null、`new A().d` は 0.0

#### ローカル変数の初期化（ろーかるへんすうのしょきか / definite assignment）

- 意味：メソッドの中で宣言した変数は、使う前に必ず値を入れなければならない決まり
- ポイント：コンパイラが「どの道を通っても代入されているか」を調べる。if の片方だけで代入していると、そのあとで使うとエラー
- 例：`int x; System.out.println(x);` → variable x might not have been initialized

#### null（ぬる / null reference）

- 意味：参照型の変数が「どのオブジェクトも指していない」ことを表す値
- ポイント：null の変数でフィールドやメソッドを使うと、実行時に NullPointerException。コンパイルはできる。null を表示すると文字列 "null"
- 例：`A a = null; a.n` → NullPointerException（Cannot read field "n" …）

## 08-2 メソッド

### まとめ表

| 書き方 | 結果（JDK 17） | 理由 |
| :-- | :-- | :-- |
| 戻り値の型があるのに、return しない道がある | missing return statement | 最後まで来てしまう道がある |
| void のメソッドで `return 1;` | incompatible types: unexpected return value | void は値を返せない |
| `m(int... a, String s)` | varargs parameter must be the last parameter | 可変長引数は最後に 1 つだけ |
| `m(int a...)` | ',', ')', or '[' expected | ... は型のあと |
| 引数の int を書きかえる | 呼び出し元は変わらない | 値のコピーが渡る |
| 引数のオブジェクトのフィールドを書きかえる | 呼び出し元から見ても変わる | 参照のコピーで同じオブジェクト |

### メソッドの形

#### メソッド（めそっど / method）

- 意味：クラスの中に書く処理のまとまり。`修飾子 戻り値の型 名前(引数の並び) { 本体 }`
- ポイント：戻り値の型は名前の直前に必ず書く（なければ void）。static のないメソッドは、インスタンスを作って `変数.メソッド名()` で呼ぶ
- 例：`int twice(int x) { return x * 2; }`

#### 戻り値と return（もどりちとりたーん / return type and return statement）

- 意味：メソッドが呼び出し元に返す値と、その値を返す文
- ポイント：戻り値の型があるメソッドは、どの道を通っても return 値; で終わらなければならない（missing return statement）。戻り値は使わずに捨ててもよい。`return this;` で自分を返すと、メソッドをつなげて呼べる
- 例：`int f(int x) { if (x > 0) return 1; }` → missing return statement

#### void（ぼいど / void）

- 意味：「値を返さない」ことを表す、戻り値の型の位置に書くキーワード
- ポイント：void のメソッドでも `return;`（値なし）で途中で終われる。`return 1;` は unexpected return value。void のメソッドの呼び出しを変数に代入するとエラー
- 例：`void hello() { System.out.println("hi"); }`

#### 値渡し（あたいわたし / pass by value）

- 意味：メソッドを呼ぶとき、引数の値をコピーして新しい引数の変数に入れるしくみ。Java の引数はすべてこれ
- ポイント：基本型はその値のコピー、参照型は参照のコピーが渡る。参照のコピーなので、フィールドを変えると呼び出し元にも見えるが、引数に別のオブジェクトを代入しても呼び出し元の変数は変わらない。String は変更できないので、s = s + "x" は呼び出し元に影響しない
- 例：`m(x, a)` の中で `x = 10; a.n = 10; a = new A();` → 呼び出し元の x はそのまま、a.n は 10

#### 可変長引数（かへんちょうひきすう / variable arity parameter, varargs）

- 意味：`型... 名前` と書き、0 個以上の引数をまとめて配列として受け取る引数
- ポイント：引数の並びの最後に 1 つだけ。メソッドの中では配列（引数なしなら長さ 0 の配列で、null ではない）。配列をそのまま渡すこともできる
- 例：`static int sum(int... v)` は `sum()`・`sum(1, 2, 3)`・`sum(new int[] {4, 5})` で呼べる

#### シグネチャ（しぐねちゃ / method signature）

- 意味：メソッドを区別するための「名前と引数の型の並び」
- ポイント：戻り値の型・引数の名前・throws は含まない。同じクラスに同じシグネチャのメソッドを 2 つ書くと already defined
- 例：`int f(int x)` と `long f(int y)` は同じシグネチャ f(int)

## 08-3 オーバーロード

### まとめ表

| 呼び出し `m(5)` の候補 | 選ばれるもの（JDK 17） | 段階 |
| :-- | :-- | :-- |
| m(long)・m(Integer)・m(int...) | m(long) | 1：型の拡大だけ |
| m(Integer)・m(int...) | m(Integer) | 2：ボクシングを許す |
| m(Long)・m(int...) | m(int...) | 3：可変長（int は Long にできない） |
| m(Long) だけ | コンパイルエラー | int cannot be converted to Long |
| m(Object)・m(String) に m(null) | m(String) | より具体的な方 |
| m(Integer)・m(String) に m(null) | reference to m is ambiguous | どちらも具体的でない |

### オーバーロードのしくみ

#### オーバーロード（おーばーろーど / overloading）

- 意味：同じ名前で、引数の型・数・順番がちがうメソッド（やコンストラクタ）を複数書くこと
- ポイント：戻り値の型だけ、引数の名前だけがちがうものはオーバーロードにならず、already defined のコンパイルエラー。アクセス修飾子や static のちがいも関係ない。継承で使うオーバーライド（#11）とは別物
- 例：`void print(int x)` と `void print(String s)`

#### オーバーロードの解決（おーばーろーどのかいけつ / overload resolution）

- 意味：呼び出しの引数から、どのメソッドを呼ぶかをコンパイル時に決める手順
- ポイント：3 段階で探し、見つかった段階で止まる。① 型の拡大（int → long → double）だけ ② ボクシング・アンボクシングも許す ③ 可変長引数も許す。だから int の引数は m(long) を m(Integer) より、m(Integer) を m(int...) より優先する。char 'a' は m(double) に 97.0 として渡る
- 例：m(int, int) と m(int...) があれば、m(1, 2) は m(int, int)、m(1, 2, 3) は m(int...)

#### 最も具体的なメソッド（もっともぐたいてきなめそっど / most specific method）

- 意味：同じ段階で候補が複数あるとき選ばれる、引数の型がいちばんせまいメソッド
- ポイント：String は Object の一種なので、m(null) では m(String) が m(Object) より具体的。変数の宣言された型で決まるので、`Object o = "b"; m(o);` は m(Object)
- 例：m(Object) と m(String) に m("a") → String

#### あいまいな呼び出し（あいまいなよびだし / ambiguous method call）

- 意味：候補が複数あって、どれも他より具体的と言えないため、1 つに決められない呼び出し
- ポイント：コンパイルエラー reference to m is ambiguous。m(Integer) と m(String) に m(null)、m(int, long) と m(long, int) に m(1, 2) が典型
- 例：`m((String) null)` のようにキャストすれば決まる

## 08-4 コンストラクタと初期化

### まとめ表

| 書き方 | 結果（JDK 17） | 理由 |
| :-- | :-- | :-- |
| コンストラクタを 1 つも書かない | new A() で作れる | デフォルトコンストラクタが自動で入る |
| `A(int x)` だけ書いて `new A()` | constructor A in class A cannot be applied to given types | 1 つでも書くと自動では入らない |
| `void A() { }` | メソッドとして扱う | 戻り値の型があればコンストラクタではない |
| this(…) を 2 行目に書く | call to this must be first statement in constructor | this(…) は先頭だけ |
| A() → this(1) → this() | recursive constructor invocation | 自分に戻ってくる |
| `A() { }` を 2 つ | constructor A() is already defined | 引数の並びが同じ |
| `final int x;` をどこでも代入しない | variable x not initialized in the default constructor | final フィールドは 1 回必ず代入 |

### コンストラクタ

#### コンストラクタ（こんすとらくた / constructor）

- 意味：new のときに実行され、インスタンスを初期化する特別なメソッドのようなもの。名前はクラス名と同じで、戻り値の型を書かない
- ポイント：戻り値の型（void も）を書くとふつうのメソッドになり、new では実行されない。引数をちがえて複数書ける（オーバーロード）。メンバではないので継承されない
- 例：`class A { int n; A(int n) { this.n = n; } }`

#### デフォルトコンストラクタ（でふぉるとこんすとらくた / default constructor）

- 意味：クラスにコンストラクタを 1 つも書かなかったとき、コンパイラが自動で入れる引数なしのコンストラクタ
- ポイント：コンストラクタを 1 つでも書くと入らない。A(int) だけ書いたクラスで new A() はコンパイルエラー。アクセス修飾子はクラスと同じ（クラスに修飾子がなければパッケージアクセス）
- 例：`public class Point { int x, y; }` には `public Point() { super(); }` が入る

#### this(…)（でぃす / explicit constructor invocation）

- 意味：コンストラクタの中から、同じクラスの別のコンストラクタを呼ぶ書き方
- ポイント：コンストラクタの最初の文でなければならない（call to this must be first statement in constructor）。メソッドの中からは呼べない。呼び出しがぐるっと自分に戻ると recursive constructor invocation
- 例：`A() { this(5); System.out.print("A() "); }` → 先に A(int) の中身が実行される

#### this（でぃす / this）

- 意味：インスタンスメソッドやコンストラクタの中で、今処理しているオブジェクト自身を指す参照
- ポイント：引数やローカル変数とフィールドの名前が同じとき、`this.n` と書けばフィールドを指す。`n = n;` は引数を引数に代入するだけでフィールドは変わらない（0 のまま）。static メソッドの中では使えない（#09）
- 例：`A(int n) { this.n = n; }`

#### シャドウイング（しゃどーいんぐ / shadowing）

- 意味：引数やローカル変数が、同じ名前のフィールドを見えなくすること
- ポイント：シャドウイングされている間、ただの n は引数・ローカル変数を指す。フィールドは this.n で使える。コンパイルエラーにはならない
- 例：フィールド n = 5、メソッドの中で `int n = 1;` なら `n + " " + this.n` は "1 5"

### 初期化の順番

#### インスタンス初期化子（いんすたんすしょきかし / instance initializer）

- 意味：クラスの中にそのまま書いた `{ … }` のブロック。インスタンスを作るたびに実行される
- ポイント：どのコンストラクタで作っても、コンストラクタの本体より先に実行される。複数あれば上から順
- 例：`class A { { System.out.print("init "); } }`

#### 初期化の順番（しょきかのじゅんばん / order of instance initialization）

- 意味：new したとき、フィールドの初期化式とインスタンス初期化子を、ソースに書いた順（上から）に実行し、そのあとコンストラクタの本体を実行する決まり
- ポイント：コンストラクタを上に書いても本体は最後。this(…) があれば、呼ばれた側のコンストラクタの中で初期化子が実行される。`int x = 10;`・`{ x = 30; }`・`A() { x = 20; }` なら最後は 20
- 例：「f1・i1・コンストラクタ・i2・f2」の順に書いても実行は f1 i1 i2 f2 c

#### final フィールド（ふぁいなるふぃーるど / final field）

- 意味：final を付けたフィールド。値を 1 回だけ代入でき、そのあと変えられない
- ポイント：宣言のとき、初期化子、またはすべてのコンストラクタの中のどこかで、必ずちょうど 1 回代入する。どこでも代入しないと variable x not initialized in the default constructor、代入しないコンストラクタがあると variable x might not have been initialized
- 例：`final int x; A() { x = 1; }`

## 08-5 オブジェクトのライフサイクル

### まとめ表

| 操作 | 起きること |
| :-- | :-- |
| `A a = new A();` | オブジェクトが 1 個できて、a がそれを指す |
| `A c = a;` | 参照のコピー。オブジェクトは増えない |
| `a = null;` | a はどこも指さない。c が指していればオブジェクトは残る |
| どの変数からもたどれなくなる | GC の対象になる（すぐ消えるとは限らない） |
| `System.gc();` | GC の実行をすすめるだけ（必ず実行されるとは限らない） |

### ガベージコレクション

#### ガベージコレクション（がべーじこれくしょん / garbage collection, GC）

- 意味：使われなくなったオブジェクトのメモリを、Java の実行環境が自動で解放するしくみ
- ポイント：プログラムでオブジェクトを消す命令（C++ の delete のようなもの）はない。いつ実行されるかは JVM が決める
- 例：メソッドが終わってローカル変数がなくなると、そこからだけ参照されていたオブジェクトは対象になる

#### GC の対象（じーしーのたいしょう / eligible for garbage collection）

- 意味：どの生きている変数からも参照をたどれなくなったオブジェクト
- ポイント：参照する変数が 1 つでも残っていれば対象にならない。null の代入、別のオブジェクトの代入、スコープを出ることで参照がなくなる。「対象になる」と「実際に消される」は別
- 例：`A a = new A(); A b = new A(); A c = a; a = null; b = c;` → 2 個目だけが対象（1 個目は c が指している）

#### System.gc()（しすてむじーしー / System.gc）

- 意味：JVM に「ガベージコレクションをしてほしい」とすすめるメソッド
- ポイント：API の説明は suggests（すすめる）。呼んでもすぐ GC が実行されるとは保証されない。試験では「必ず解放される」という選択肢がまちがい
- 例：`System.gc();`

### 08-1 クラスとインスタンス

#### 問 java-08-o01

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  class A {
    int i; double d; boolean b; String s; char c; long[] arr;
  }
  public class Main {
    public static void main(String[] args) {
      A a = new A();
      System.out.println(a.i + " " + a.d + " " + a.b + " " + a.s + " " + (int) a.c + " " + a.arr);
    }
  }
  ```

- ア：0 0 false null 0 null
- イ：0 0.0 false "" 0 []
- ウ：0 0.0 false null 0 null
- エ：コンパイルエラーになる（フィールドが初期化されていない）
- 正解：ウ
