## 11-1 継承とコンストラクタ

### まとめ表

| 書き方 | 結果（JDK 17） | 理由 |
| :-- | :-- | :-- |
| `class B extends A, Object { }` | '{' expected | extends に書けるクラスは 1 つだけ |
| 親の private フィールドをサブクラスで使う | n has private access in A | private は継承されない |
| 親に引数なしコンストラクタがなく、子が super(…) を書かない | constructor A in class A cannot be applied to given types; | 子のコンストラクタの先頭に super(); が自動で入る |
| 子のコンストラクタで処理のあとに super(1) | call to super must be first statement in constructor | super(…) と this(…) は先頭だけ |
| new C()（C → B → A の順に継承） | A B C の順に表示 | 親のコンストラクタが先に動く |

### 継承のしくみ

#### 継承（けいしょう / inheritance）

- 意味：あるクラスのメンバ（フィールドとメソッド）を引き継いで、新しいクラスを作るしくみ。`class B extends A` と書く
- ポイント：引き継ぐ側をサブクラス、引き継がれる側をスーパークラスと呼ぶ。サブクラスは「スーパークラスの一種（is-a）」になる
- 例：`class Dog extends Animal { }`

#### スーパークラス（すーぱーくらす / superclass）

- 意味：継承のもとになるクラス。親クラスともいう。extends のあとに書いたクラスが直接のスーパークラス
- ポイント：extends を書かないクラスの直接のスーパークラスは Object。Object だけはスーパークラスを持たない
- 例：`class Dog extends Animal` の Animal

#### サブクラス（さぶくらす / subclass）

- 意味：スーパークラスを継承して作ったクラス。子クラスともいう
- ポイント：スーパークラスのメンバに、自分のメンバを足したり、メソッドを書き直したり（オーバーライド）できる
- 例：`class Dog extends Animal` の Dog

#### 単一継承（たんいつけいしょう / single inheritance）

- 意味：クラスが直接継承できるスーパークラスは 1 つだけ、という Java の決まり
- ポイント：`extends A, B` と書くとコンパイルエラー（'{' expected）。複数のインタフェースを implements するのは OK（#12）。A → B → C と何段も継承するのはかまわない
- 例：`class C extends B { }`（B は A を継承していてもよい）

#### Object クラス（おぶじぇくとくらす / class Object）

- 意味：java.lang パッケージにある、すべてのクラスの大もとのクラス
- ポイント：extends を書かないと自動で Object を継承する。toString・equals・hashCode などは Object から引き継いだもの。どのオブジェクトも Object 型の変数に入れられる
- 例：`Object o = new Dog();`

#### 継承されないもの（けいしょうされないもの / members not inherited）

- 意味：サブクラスに引き継がれないもの。private のメンバと、コンストラクタ・初期化子
- ポイント：親の private フィールドはサブクラスのオブジェクトの中に存在するが、サブクラスのコードからは名前で使えない（n has private access in A）。コンストラクタはメンバではないので継承されず、子で使うには super(…) で呼ぶ。別のパッケージのサブクラスには、パッケージアクセス（修飾子なし）のメンバも継承されない
- 例：`private int n;` は子から `n` と書けない

### コンストラクタの連鎖

#### super(…)（すーぱーよびだし / superclass constructor invocation）

- 意味：コンストラクタの先頭で、スーパークラスのコンストラクタを呼ぶ文
- ポイント：コンストラクタの最初の文にしか書けない（call to super must be first statement in constructor）。書かないと、引数なしの super(); が自動で先頭に入る。親に引数なしのコンストラクタがないと、そこでコンパイルエラー
- 例：`B() { super(5); }`

#### this(…)（でぃすよびだし / alternate constructor invocation）

- 意味：コンストラクタの先頭で、同じクラスの別のコンストラクタを呼ぶ文
- ポイント：super(…) と同じく最初の文だけで、super(…) と this(…) を両方は書けない。this(…) で呼んだ先のコンストラクタが super(…) を（自動で）呼ぶ
- 例：`B(int y) { this(); }`

#### 暗黙の super()（あんもくのすーぱー / implicit super()）

- 意味：コンストラクタの先頭に super(…) も this(…) も書かないとき、コンパイラが自動で入れる `super();`
- ポイント：親に引数ありのコンストラクタしかないと「constructor A in class A cannot be applied to given types;」のエラーになる。子のコンストラクタを書かない場合（デフォルトコンストラクタ）も同じエラー
- 例：`B() { System.out.print("B"); }` は `B() { super(); System.out.print("B"); }` と同じ

#### デフォルトコンストラクタ（でふぉるとこんすとらくた / default constructor）

- 意味：クラスにコンストラクタを 1 つも書かなかったときに、コンパイラが自動で作る引数なしのコンストラクタ
- ポイント：中身は `super();` だけ。コンストラクタを 1 つでも書くと作られない。アクセス修飾子はクラスと同じ
- 例：`class B extends A { }` には `B() { super(); }` が自動で作られる

#### コンストラクタの実行順（こんすとらくたのじっこうじゅん / constructor chaining）

- 意味：new でオブジェクトを作ると、super(…) をたどって一番上の Object のコンストラクタから順に実行され、最後に自分のコンストラクタの残りが動く
- ポイント：C → B → A と継承していれば、表示は A → B → C の順。抽象クラスのコンストラクタもサブクラスの new のときに動く
- 例：`new C();` → `A B C`

## 11-2 オーバーライドと隠蔽

### まとめ表

| 子のメソッドの書き方（親は `void m()` など） | 結果（JDK 17） |
| :-- | :-- |
| 親が public、子が修飾子なし | cannot override … attempting to assign weaker access privileges; was public |
| 親が int を返す、子が long を返す | cannot override … return type long is not compatible with int |
| 親が A を返す、子が B（A のサブクラス）を返す | OK（共変戻り値） |
| 親が throws Exception、子が throws なし | OK（検査例外は減らせる） |
| 親がインスタンス、子が static | cannot override … overriding method is static |
| 親が static、子がインスタンス | cannot override … overridden method is static |
| 親が final | cannot override … overridden method is final |
| 引数の型がちがうのに @Override | method does not override or implement a method from a supertype |

### オーバーライドの決まり

#### オーバーライド（おーばーらいど / overriding）

- 意味：スーパークラスのインスタンスメソッドと同じシグネチャ（名前と引数の型の並び）のメソッドをサブクラスに書き、中身を書き直すこと
- ポイント：戻り値は同じ型か、参照型ならそのサブクラス型。アクセスは同じか広く。検査例外は増やせない。static メソッド・final メソッド・private メソッドはオーバーライドできない
- 例：`String sound() { return "wan"; }`（親の sound() を書き直す）

#### オーバーロード（おーばーろーど / overloading）

- 意味：同じ名前で、引数の型や数がちがうメソッドを並べること
- ポイント：オーバーライドとちがい、どれを呼ぶかはコンパイル時に引数の型で決まる。親の m(int) と子の m(long) は別のメソッド（オーバーロード）で、親の型の変数からは m(int) しか見えない
- 例：`void m(int x)` と `void m(long x)`

#### @Override（おーばーらいどあのてーしょん / @Override annotation）

- 意味：「このメソッドはオーバーライドのつもり」とコンパイラに伝えるアノテーション
- ポイント：付けたメソッドが実際にはオーバーライドになっていないと、コンパイルエラー（method does not override or implement a method from a supertype）。付けなくてもオーバーライドはできる
- 例：`@Override public String toString() { … }`

#### 共変戻り値（きょうへんもどりち / covariant return type）

- 意味：オーバーライドするメソッドの戻り値の型を、もとの戻り値の型のサブクラス型にしてよい、という決まり
- ポイント：参照型だけ。int を long にするような基本データ型の変更はできない（return type long is not compatible with int）
- 例：親 `A get()`、子 `B get()`（B は A のサブクラス）

#### アクセスを狭めない決まり（あくせすをせばめないきまり / access of overriding method）

- 意味：オーバーライドするメソッドのアクセス修飾子は、もとのメソッドと同じか、より広くなければならない
- ポイント：広い順に public → protected → 修飾子なし → private。public を修飾子なしにすると attempting to assign weaker access privileges; was public。修飾子なしを public にするのは OK
- 例：親 `void m()`、子 `public void m()` は OK

#### オーバーライドと検査例外（おーばーらいどとけんされいがい / throws of overriding method）

- 意味：オーバーライドするメソッドは、もとのメソッドより多くの検査例外を throws に書けない
- ポイント：減らす・なくす・サブクラスの例外にするのは OK。非検査例外（RuntimeException など）は自由に書ける
- 例：親 `void m() throws Exception`、子 `void m()` は OK

#### super.メソッド（すーぱーめそっど / super.method()）

- 意味：オーバーライドしたメソッドの中などで、スーパークラスのほうのメソッドを呼ぶ書き方
- ポイント：親の処理を生かしたまま、子の処理を足すときに使う。`super.f` と書けば、隠されたフィールドの親のほうも使える
- 例：`void show() { super.show(); System.out.print("B"); }`

### 隠蔽と final メソッド

#### メソッドの隠蔽（めそっどのいんぺい / hiding of static methods）

- 意味：スーパークラスの static メソッドと同じシグネチャの static メソッドをサブクラスに書くこと。オーバーライドではない
- ポイント：どちらが呼ばれるかは変数の型（コンパイル時の型）で決まる。親の型の変数で呼べば親のメソッド。インスタンスメソッドを static で隠すこと、static をインスタンスメソッドでオーバーライドすることは、どちらもコンパイルエラー
- 例：`A a = new B(); a.who();` → A の who()

#### フィールドの隠蔽（ふぃーるどのいんぺい / hiding of fields）

- 意味：スーパークラスと同じ名前のフィールドをサブクラスで宣言すると、親のフィールドが隠されること
- ポイント：フィールドはオーバーライドされず、どちらを使うかは変数の型で決まる（ポリモーフィズムにならない）。型がちがっても、static とインスタンスが混ざっても隠蔽できる。親のほうは super.名前 で使える
- 例：`Animal a = new Dog(); a.name` → Animal の name

#### final メソッド（ふぁいなるめそっど / final method）

- 意味：final を付けて、サブクラスでオーバーライドも隠蔽もできないようにしたメソッド
- ポイント：オーバーライドすると overridden method is final のコンパイルエラー。呼び出すこと・オーバーロードすることはできる。private メソッドと final クラスのメソッドも final のように扱われる
- 例：`final void m() { }`

#### private メソッドとオーバーライド（ぷらいべーとめそっどとおーばーらいど / private methods are not overridden）

- 意味：private メソッドは継承されないので、サブクラスに同じ名前のメソッドを書いても、オーバーライドではなく別のメソッドになる
- ポイント：親のメソッドの中から private メソッドを呼ぶと、オブジェクトが子でも親のメソッドが動く。子のほうに @Override を付けるとコンパイルエラー
- 例：親の call() が private secret() を呼ぶ → new B().call() でも A の secret()

## 11-3 ポリモーフィズムとキャスト

### まとめ表

| 書き方（Dog と Cat は Animal のサブクラス） | 結果（JDK 17） |
| :-- | :-- |
| `Animal a = new Dog();` | OK（アップキャスト。キャスト不要） |
| `Dog d = a;`（a は Animal 型） | incompatible types: Animal cannot be converted to Dog |
| `Dog d = (Dog) a;`（中身が Dog） | OK |
| `Cat c = (Cat) a;`（中身が Dog） | 実行時に ClassCastException |
| `Cat c = (Cat) d;`（d は Dog 型、継承関係なし） | incompatible types: Dog cannot be converted to Cat |
| `a.bark();`（bark は Dog だけにある） | cannot find symbol |
| `a.sound()`（Dog がオーバーライド） | Dog の sound() が動く |
| `a.name`（Dog も name を宣言） | Animal の name（変数の型で決まる） |

### ポリモーフィズム

#### ポリモーフィズム（ぽりもーふぃずむ / polymorphism）

- 意味：同じ型の変数で同じメソッドを呼んでも、中身のオブジェクトの種類によってちがう処理が動くしくみ。多態性・多相性ともいう
- ポイント：スーパークラス型の変数にサブクラスのオブジェクトを入れ、オーバーライドされたメソッドを呼ぶと実現する。フィールドと static メソッドはポリモーフィズムにならない
- 例：`Animal a = new Dog(); a.sound();` → "wan"

#### 動的ディスパッチ（どうてきでぃすぱっち / dynamic method lookup）

- 意味：インスタンスメソッドを呼ぶとき、実行時に中身のオブジェクトのクラスから順にメソッドを探し、オーバーライドされたものを呼ぶしくみ
- ポイント：「どのメソッドを呼べるか」はコンパイル時に変数の型で決まり、「どの中身が動くか」は実行時にオブジェクトのクラスで決まる。親のメソッドの中から呼んだメソッドも、子でオーバーライドされていれば子のものが動く
- 例：親の m() の中の n() → 子の n() が動く

#### 参照型と実際のクラス（さんしょうがたとじっさいのくらす / declared type vs run-time class）

- 意味：変数の型（宣言した型・コンパイル時の型）と、変数が指しているオブジェクトのクラス（実行時のクラス）のちがい
- ポイント：呼べるメソッド・使えるフィールドは変数の型で決まる。Animal 型の変数から Dog だけのメソッドは呼べない（cannot find symbol）。getClass() は実行時のクラスを返す
- 例：`Animal a = new Dog();` → 変数の型は Animal、実際のクラスは Dog

#### コンストラクタからのオーバーライドメソッド呼び出し（こんすとらくたからのよびだし / overridden method called from constructor）

- 意味：親のコンストラクタの中でオーバーライドされるメソッドを呼ぶと、子のメソッドが動くこと
- ポイント：そのとき子のフィールドの初期化はまだなので、int は 0、参照は null のまま見える。Java はオブジェクトを作っている途中でも呼び出し方を変えない
- 例：親のコンストラクタで show() → 子の show() が x = 0 で動く

### キャスト

#### アップキャスト（あっぷきゃすと / upcast）

- 意味：サブクラス型の値をスーパークラス型として扱うこと。JLS では拡大参照変換という
- ポイント：いつでも安全なので、キャスト演算子を書かなくてよく、実行時に例外も起きない
- 例：`Animal a = new Dog();`

#### ダウンキャスト（だうんきゃすと / downcast）

- 意味：スーパークラス型の値をサブクラス型に戻すこと。JLS では縮小参照変換といい、`(Dog) a` のようにキャスト演算子が要る
- ポイント：キャストを書かずに代入すると incompatible types のコンパイルエラー。中身が合わないと実行時に ClassCastException。継承関係のないクラスどうし（Dog と Cat）は、キャストを書いてもコンパイルエラー
- 例：`Dog d = (Dog) a;`

#### ClassCastException（くらすきゃすとえくせぷしょん / ClassCastException）

- 意味：キャストの先の型と、オブジェクトの実際のクラスが合わないときに、実行時にスローされる例外
- ポイント：コンパイルは通るので、コンパイルエラーと区別する。実際のクラスがキャスト先の型か、そのサブクラスならスローされない
- 例：中身が Dog の Animal 変数を `(Cat)` でキャスト

#### instanceof でのたしかめ（いんすたんすおぶでのたしかめ / instanceof check before cast）

- 意味：ダウンキャストの前に instanceof で中身の型をたしかめ、ClassCastException を防ぐ書き方
- ポイント：Java 16 からは `a instanceof Dog d` のパターン・マッチングで、たしかめとキャストを一度に書ける（#10）。サブクラスのオブジェクトは親の型に対しても true
- 例：`if (a instanceof Dog) { Dog d = (Dog) a; }`

## 11-4 abstract と final

### まとめ表

| 書き方 | 結果（JDK 17） |
| :-- | :-- |
| `new Shape()`（Shape は抽象クラス） | Shape is abstract; cannot be instantiated |
| 抽象クラスを継承し、抽象メソッドを書かない普通のクラス | Sq is not abstract and does not override abstract method area() in Shape |
| abstract のないクラスに抽象メソッド | Shape is not abstract and does not override abstract method area() in Shape |
| `abstract double area() { return 0; }` | abstract methods cannot have a body |
| `final abstract class A` | illegal combination of modifiers: abstract and final |
| final クラスを extends | cannot inherit from final A |

### 抽象クラス

#### 抽象クラス（ちゅうしょうくらす / abstract class）

- 意味：abstract を付けた、完成していない（中身のないメソッドを持てる）クラス。new でインスタンスを作れない
- ポイント：コンストラクタ・フィールド・中身のあるメソッドも持てる。変数の型には使えるので、`Shape s = new Sq(3);` のように使う。抽象メソッドが 1 つもなくても abstract にできる
- 例：`abstract class Shape { abstract double area(); }`

#### 抽象メソッド（ちゅうしょうめそっど / abstract method）

- 意味：abstract を付け、中身 { } を書かずに `;` で終えるメソッド。サブクラスで中身を書く（実装する）
- ポイント：抽象メソッドを持てるのは抽象クラス（とインタフェース）だけ。{ } を付けると abstract methods cannot have a body。private・static・final とは一緒に付けられない
- 例：`abstract double area();`

#### 具象クラス（ぐしょうくらす / concrete class）

- 意味：abstract の付いていない、new でインスタンスを作れるクラス
- ポイント：抽象クラスを継承した具象クラスは、引き継いだすべての抽象メソッドを実装しなければならない（not abstract and does not override abstract method）。間に抽象クラスをはさんで、実装を先送りすることはできる
- 例：`class Sq extends Shape { double area() { return s * s; } }`

### final クラス

#### final クラス（ふぁいなるくらす / final class）

- 意味：final を付けて、サブクラスを作れないようにしたクラス
- ポイント：継承しようとすると cannot inherit from final A。abstract とは一緒に付けられない（illegal combination of modifiers: abstract and final）。String は final クラス
- 例：`final class A { }`

#### final の 3 つの使い方（ふぁいなるのつかいかた / uses of final）

- 意味：final は付ける場所によって意味が変わる。クラスなら継承できない、メソッドならオーバーライドできない、変数なら値を変えられない
- ポイント：どれも「これ以上変えさせない」という意味。final メソッドを持つクラスは継承できる。final の変数は #03 で扱った
- 例：`final class`・`final void m()`・`final int N = 1;`

### 11-1 継承とコンストラクタ

#### 問 java-11-o01

- 問：次のプログラムを実行した。表示されるものはどれか。

  ```
  class A {
    A() { System.out.print("A "); }
  }
  class B extends A {
    B() { System.out.print("B "); }
  }
  class C extends B {
    C() { System.out.print("C "); }
  }
  public class Main {
    public static void main(String[] args) {
      new C();
      System.out.println();
    }
  }
  ```

- ア：A B C
- イ：C B A
- ウ：C
- エ：C A B
- 正解：ア
- 解説：B と C のコンストラクタの先頭には、super(); が自動で入る。C のコンストラクタはまず B のコンストラクタを、B はまず A のコンストラクタを呼ぶので、親から順に A → B → C と表示される。
- アの意味：正しい。
- イの意味：子のコンストラクタの本体が先に動くと考えたまちがい。super(); は本体の前に動く。
- ウの意味：親のコンストラクタは書かなくても自動で呼ばれる。
- エの意味：順番に根拠がない。
- 出典：オリジナル問題（根拠：JLS 8.8.7（the constructor body implicitly begins with a superclass constructor invocation "super();", an invocation of the constructor of its direct superclass that takes no arguments）／JDK 17 での実行結果）

#### 問 java-11-o09

- 問：次のプログラムをコンパイルした。結果として正しいものはどれか。

  ```
  class A {
    public void m() { }
  }
  class B extends A {
    void m() { }
  }
  public class Main {
    public static void main(String[] args) { }
  }
  ```

- ア：コンパイルできる（B の m() は A の m() をオーバーライドする）

- イの意味：正しい。
- ウの意味：名前と引数が同じなら別のメソッドにはならない。オーバーライドとして決まりを調べられる。
- エの意味：public のメソッドは、public のままならオーバーライドできる。エラーは B 側。
- 出典：オリジナル問題（根拠：JLS 8.4.8.3（The access modifier of an overriding or hiding method must provide at least as much access as the overridden or hidden method）／JDK 17 でのコンパイル結果）

  ```
    abstract double area();
  }
  class Sq extends Shape { }
  public class Main {
    public static void main(String[] args) { }
  }
  ```

- ア：コンパイルできる（Sq は area() を継承しているので問題ない）
- イ：コンパイルでき、Sq は自動で抽象クラスになる
- ウ：abstract double area() の行で missing method body のコンパイルエラーになる
- エ：class Sq の行で Sq is not abstract and does not override abstract method area() in Shape のコンパイルエラーになる
- 正解：エ
- 解説：abstract のない（具象）クラスは、引き継いだ抽象メソッドをすべて実装しなければならない。直すには、Sq に area() を書くか、Sq にも abstract を付ける。
- アの意味：引き継いだのは中身のない抽象メソッドなので、実装が必要。
- イの意味：自動で abstract になることはない。
- ウの意味：抽象メソッドは中身を書かないのが正しい書き方。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：JLS 8.4.3.1（Every subclass of A that is not abstract (§8.1.1.1) must provide an implementation for m, or a compile-time error occurs）／JDK 17 でのコンパイル結果）

#### 問 java-11-o30

- 問：abstract と final について正しいものはどれか。
- ア：`final abstract class A { }` と書けば、継承もインスタンス化もできないクラスになる
- イ：抽象クラスはコンストラクタを持つことができ、サブクラスを new したときに実行される
- ウ：抽象メソッドに `{ return 0; }` のように中身を書けば、サブクラスでの実装を省ける
- エ：final メソッドを持つクラスは、継承できない
- 正解：イ
- 解説：抽象クラスも、ほかのクラスと同じようにコンストラクタを持てる。new で直接は作れないが、サブクラスを new したときに super(…) によって実行される。
- アの意味：final と abstract は一緒に付けられない（illegal combination of modifiers: abstract and final）。
- イの意味：正しい。
- ウの意味：抽象メソッドに中身を書くと abstract methods cannot have a body のコンパイルエラー。
- エの意味：final メソッドはオーバーライドできないだけで、クラスは継承できる。継承できないのは final クラス。
- 出典：オリジナル問題（根拠：JLS 8.1.1.1（A subclass of an abstract class that is not itself abstract may be instantiated, resulting in the execution of a constructor for the abstract class）・8.1.1.2（It is a compile-time error if a class is declared both final and abstract）・8.4.3.3（A method can be declared final to prevent subclasses from overriding or hiding it）／JDK 17 でのコンパイル結果）
