## 01-1 Java のしくみ

### まとめ表

| ものの名前 | 何か | 作る・動かす道具 | 根拠 |
| :-- | :-- | :-- | :-- |
| ソースファイル（.java） | 人が書く Java のコード | テキストエディタ | javac ドキュメント Description |
| クラスファイル（.class） | JVM の命令（バイトコード）が入ったファイル | javac が作る | javac ドキュメント、JVMS 1.2 |
| JVM | クラスファイルを読み込んで動かす仮想の計算機 | java コマンドが起動する | JVMS 1.2、java ドキュメント |
| JDK | javac や java などの道具一式 | 開発者が入れる | dev.java Getting Started |

### ソースからクラスファイルへ

#### ソースファイル（そーすふぁいる / source file）

- 意味：人が Java の文法で書いたプログラムのファイル。拡張子は .java
- ポイント：javac は拡張子が .java のファイルしか受け付けない。ふつうファイル名は中のクラス名と同じにする（Shape クラスなら Shape.java）（javac ドキュメント）
- 例：`Hello.java`

#### javac（じゃばしー / javac command）

- 意味：ソースファイルを読み、JVM で動くクラスファイルに翻訳する道具（コンパイラ）
- ポイント：文法の誤りや型の誤りはここで見つかる（コンパイルエラー）。コンパイルが通っても、動かしたときに起きる誤り（実行時エラー・例外）は防げない
- 例：`javac Hello.java` → 同じ場所に Hello.class ができる

#### クラスファイル（くらすふぁいる / class file）

- 意味：javac が作るファイル。拡張子は .class。中身は JVM の命令（バイトコード）と記号表など
- ポイント：1 つのソースファイルに 2 つのクラスを書くと、クラスファイルも 2 つできる（クラスごとに 1 つ）。OS ごとに作り直す必要はない（JVMS 1.2）
- 例：`T.java` に class T と class U を書く → T.class と U.class

#### バイトコード（ばいとこーど / bytecode）

- 意味：クラスファイルに入っている、JVM のための命令
- ポイント：CPU が直接読む機械語ではない。JVM が読んで動かすので、同じクラスファイルが Windows でも Linux でも動く（JVMS 1.2）
- 語の意味：byte＝8 ビットの単位、code＝命令の並び

### 動かすしくみ

#### JVM（じぇいぶいえむ / Java Virtual Machine）

- 意味：クラスファイルを読み込んで動かす、ソフトウェアで作られた仮想の計算機
- ポイント：JVM が知っているのはクラスファイルの形式だけで、Java 言語そのものは知らない（JVMS 1.2 The Java Virtual Machine knows nothing of the Java programming language）。「必ずインタプリタで動く」わけではなく、CPU の命令に翻訳して動かしてもよい（JVMS 1.2）
- 語の意味：Java＝言語の名前、Virtual＝仮想の、Machine＝機械

#### java コマンド（じゃばこまんど / java launcher）

- 意味：JVM を起動し、指定したクラスを読み込んで、その main メソッドを呼ぶ道具（ランチャー）
- ポイント：渡すのはファイル名ではなくクラス名（パッケージがあれば完全修飾名）。`.class` を付けると「メインクラスが見つからない」というエラーになる。JDK 11 からは .java ファイルを直接渡す「ソースファイルモード」もある（01-3）
- 例：`java Hello`

#### JDK（じぇいでぃーけー / Java Development Kit）

- 意味：Java の開発に使う道具一式。コンパイラ（javac）や起動の道具（java）が入っている
- ポイント：コンパイルと実行の両方に使う。dev.java は「Java をダウンロードする＝JDK をダウンロードする」と説明している
- 語の意味：Java＝言語の名前、Development＝開発、Kit＝道具一式

#### JRE（じぇいあーるいー / Java Runtime Environment）

- 意味：Java のプログラムを動かすためだけの道具の集まり。JDK の一部
- ポイント：JRE ではコンパイルできない。OpenJDK と Oracle は JRE をもう別に配っていない（dev.java Getting Started）
- 語の意味：Runtime＝実行時、Environment＝環境

## 01-2 main メソッドとコマンドライン引数

### まとめ表

| main の書き方 | java A で起動できるか | 確かめた結果（JDK 17） |
| :-- | :-- | :-- |
| `public static void main(String[] args)` | できる | 標準の形（JLS 12.1.4） |
| `public static void main(String... args)` | できる | 可変長引数の形も可（JLS 12.1.4） |
| `static public void main(String args[])` | できる | 修飾子の順番と [] の位置は自由 |
| `public static final void main(final String[] a)` | できる | final を付けても、引数の名前を変えてもよい |
| `public void main(String[] args)` | できない | コンパイルは通るが、起動時に Main method is not static |
| `static void main(String[] args)` | できない | public がないので Main method not found |
| `public static int main(String[] args)` | できない | 起動時に Main method must return a value of type void |
| `public static void main(String args)` | できない | 引数が配列でないので Main method not found |

### プログラムの入口

#### main メソッド（めいんめそっど / main method）

- 意味：java コマンドが最初に呼ぶメソッド。プログラムの入口
- ポイント：public・static・void で、String の配列を 1 つ受け取る形でなければならない（JLS 12.1.4）。この形でない main もコンパイルは通るが、java で起動したときにエラーになる
- 例：`public static void main(String[] args) { System.out.println("Hello"); }`

#### public（ぱぶりっく / public modifier）

- 意味：どこからでも呼べる、という印（アクセス修飾子）
- ポイント：main から public を外すと、コンパイルは通るが起動時に「Main method not found」になる。アクセス修飾子のくわしい違いは #09 で扱う
- 例：`public static void main(String[] args)`

#### static（すたてぃっく / static modifier）

- 意味：インスタンス（オブジェクト）を作らなくても呼べる、という印
- ポイント：JVM はインスタンスを作らずに main を呼ぶので static が必要。外すと起動時に「Main method is not static」になる（JDK 17 で確認）。static のくわしい話は #09
- 例：`static public void main(String[] args)`（public と static の順番は入れかえてよい）

#### void（ぼいど / void）

- 意味：メソッドが値を返さない、という印
- ポイント：main は値を返さない（java ドキュメント it must not return any value）。int を返す main はコンパイルは通るが、起動時に「Main method must return a value of type void」になる。終了コードを返したいときは System.exit を使う（java ドキュメント Exit Status）
- 例：`System.exit(1);`

#### String[] args（すとりんぐはいれつ / String array parameter）

- 意味：main が受け取る引数。コマンドライン引数が文字列の配列として入る
- ポイント：引数の名前は args でなくてもよい。`String args[]`・`String... args` も同じ意味（JLS 12.1.4）。`String args`（配列でない）は main として認められない
- 例：`public static void main(String... a)`

#### 可変長引数（かへんちょうひきすう / variable arity parameter）

- 意味：`型...` と書いて、同じ型の値をいくつでも受け取れるようにした引数。中身は配列になる
- ポイント：main の `String... args` は `String[] args` と同じように使える（JLS 12.1.4）
- 例：`String... args` の args.length で個数がわかる

#### main のオーバーロード（めいんのおーばーろーど / overloading main）

- 意味：名前が main で、引数の型がちがうメソッドを同じクラスに並べること
- ポイント：コンパイルエラーにはならない。java が入口として呼ぶのは `String[]` を受け取る main だけで、ほかの main はふつうのメソッドとして自分で呼ぶ。オーバーロードのくわしい話は #08
- 例：`main(String[] args)` の中から `main(1)` を呼ぶ

### コマンドライン引数

#### コマンドライン引数（こまんどらいんひきすう / command-line arguments）

- 意味：java コマンドでクラス名のあとに書いた文字列。main の配列に順に入る
- ポイント：クラス名そのものは配列に入らない。`java Test reboot Bob Dot Enzo` なら配列は "reboot"・"Bob"・"Dot"・"Enzo" の 4 つ（JLS 12.1）。数字を書いても String として入る
- 例：`java Hello a b c` → args[0] は "a"、args.length は 3

#### args.length（あーぐすどっとれんぐす / array length）

- 意味：コマンドライン引数の個数
- ポイント：引数なしで起動すると長さ 0 の配列になる（null ではない）。そのとき args[0] を読むと ArrayIndexOutOfBoundsException（実行時エラー）になる。コンパイルは通る
- 例：`java Hello` → args.length は 0

#### 引用符でくくった引数（いんようふでくくったひきすう / quoted argument）

- 意味：空白を含む文字列を 1 つの引数として渡すために、引用符でくくること
- ポイント：くくる・空白で分けるのはシェル（コマンドを受け取るソフト）の決まりで、Java は分けられたあとの文字列を受け取る。Linux の bash で `java Hello "a b" c` と打つと、引数は "a b" と "c" の 2 つになり、引用符は残らない（JDK 17 で確認）
- 例：`java Hello "a b" c` → args.length は 2

## 01-3 コンパイルと実行

### まとめ表

| したいこと | コマンド | 結果 |
| :-- | :-- | :-- |
| コンパイル | `javac Hello.java` | Hello.java と同じ場所に Hello.class |
| 出力先を指定してコンパイル | `javac -d out src/com/example/app/Main.java` | out/com/example/app/Main.class（パッケージどおりの階層ができる） |
| 実行 | `java Hello` | クラス名を書く。`java Hello.class` はエラー |
| パッケージのクラスを実行 | `java -cp out com.example.app.Main` | 完全修飾名で書き、クラスパスはパッケージの根元（out） |
| ソースから直接実行 | `java Hello.java` | メモリの上でコンパイルして実行。クラスファイルは残らない |

### クラスパス

#### クラスパス（くらすぱす / class path）

- 意味：javac や java がクラスファイルを探す場所の一覧。ディレクトリや JAR ファイルを並べる
- ポイント：パッケージのクラスを探すときは、クラスパスに書いた場所の下を「パッケージ名どおりのディレクトリ」でたどる。だからクラスパスにはパッケージの根元（例：out）を書く（javac ドキュメント Arrangement of Source Code）
- 例：`java -cp out com.example.app.Main` → out/com/example/app/Main.class を読む

#### -cp（しーぴー / -cp, -classpath, --class-path）

- 意味：クラスパスを指定するオプション。-classpath・--class-path も同じ
- ポイント：指定すると環境変数 CLASSPATH より優先される。複数の場所は、Windows では「;」、Linux・macOS では「:」で区切る（javac ドキュメント the platform path separator character）
- 例：Linux で `java -cp out:lib/util.jar com.example.app.Main`

#### カレントディレクトリ（かれんとでぃれくとり / current directory）

- 意味：コマンドを打ったときにいるディレクトリ
- ポイント：-cp も環境変数 CLASSPATH もないときは、クラスパスはカレントディレクトリ（.）になる（java ドキュメント the user class path consists of the current directory）。だから `javac Hello.java` のあと同じ場所で `java Hello` が動く
- 例：`java Hello`（-cp を書かない）

#### CLASSPATH（くらすぱす / CLASSPATH environment variable）

- 意味：クラスパスを入れておく OS の環境変数
- ポイント：-cp を書くと無視される。javac ドキュメントは、この環境変数は設定せず -cp で明示することを勧めている
- 例：`export CLASSPATH=out`（Linux）

#### -d（でぃー / -d option）

- 意味：javac が作るクラスファイルの置き場所を指定するオプション
- ポイント：パッケージのクラスなら、指定した場所の下にパッケージ名どおりのディレクトリを自動で作る。-d を付けないと、クラスファイルはソースファイルと同じディレクトリにできる（javac ドキュメント）
- 例：`javac -d out Main.java`（Main が package com.example.app なら out/com/example/app/Main.class）

### 実行のしかた

#### 完全修飾名（かんぜんしゅうしょくめい / fully qualified name）

- 意味：パッケージ名まで付けたクラスの名前
- ポイント：パッケージに入ったクラスを java で動かすときは完全修飾名で書く。`java -cp out Main` では見つからない。out/com/example/app に入って `java Main` としても「wrong name: com/example/app/Main」というエラーになる（JDK 17 で確認）
- 例：`com.example.app.Main`

#### ソースファイルモード（そーすふぁいるもーど / source-file mode）

- 意味：java コマンドに .java ファイルを直接渡して、コンパイルと実行を 1 回で行うしくみ。JDK 11 から（JEP 330）
- ポイント：メモリの上でコンパイルするので、クラスファイルは残らない。動くのはファイルの中で最初に書いたクラス。ほかのソースファイルは探さないので、別ファイルのクラスを使うとコンパイルエラー（java ドキュメント No other source files are found and compiled）。ファイル名とクラス名が合っていなくても動く
- 例：`java Hello.java p q`（p と q は main の引数になる）

#### コンパイルエラー（こんぱいるえらー / compile-time error）

- 意味：javac が見つけて、クラスファイルを作らない誤り
- ポイント：文法の誤り、見つからないクラス、あいまいな名前などで起きる。コンパイルエラーがあるとクラスファイルができないので、そのあと java でも動かせない
- 例：`import java.util;`（パッケージはインポートできない）

#### 実行時エラー（じっこうじえらー / runtime error）

- 意味：コンパイルは通ったが、動かしている途中で起きる誤り。Java では例外として知らされる
- ポイント：配列の範囲外（ArrayIndexOutOfBoundsException）などがある。起動のときの誤り（main が見つからないなど）も、コンパイルのあとで起きる
- 例：引数なしで `java Hello` → args[0] で ArrayIndexOutOfBoundsException

## 01-4 パッケージとソースファイルの決まり

### まとめ表

| ソースファイルの決まり | OK の例 | NG の例 | 根拠 |
| :-- | :-- | :-- | :-- |
| 並び順は package → import → クラス | `package p; import java.util.*; class A {}` | import のあとに package | JLS 7.3 |
| package 宣言は 1 つだけ | `package p;` | `package p; package q;` | JLS 7.3 |
| package の前に書けるのはコメントだけ | `/* メモ */ package p;` | — | JLS 3.2（コメントは空白と同じく捨てられる） |
| public なクラスはファイル名と同じ名前 | T.java に public class T | T.java に public class U | JLS 7.6、javac の制約 |
| public でないクラスはいくつ書いてもよい | T.java に public class T と class U | — | JLS 7.6 |
| トップレベルのクラスに private・protected・static は付けられない | `final class A {}` | `private class A {}` | JLS 7.6 |

### パッケージ

#### パッケージ（ぱっけーじ / package）

- 意味：クラスをまとめて入れる名前の箱。ファイルを置くディレクトリの階層と対応する
- ポイント：同じ名前のクラスも、パッケージがちがえば別のクラスとして区別できる（java.util.Date と java.sql.Date）。パッケージ p.q はディレクトリ p/q（Windows は p\q）に対応する（javac ドキュメント）
- 例：`com.example.app`

#### package 宣言（ぱっけーじせんげん / package declaration）

- 意味：ソースファイルの先頭で、そのファイルのクラスが入るパッケージを決める文
- ポイント：ファイルの最初の宣言でなければならず、1 つのファイルに 1 つだけ（JLS 7.3）。前に書けるのはコメントだけ。import のあとに書くと「class, interface, enum, or record expected」というコンパイルエラーになる（JDK 17 で確認）
- 例：`package com.example.app;`

#### 無名パッケージ（むめいぱっけーじ / unnamed package）

- 意味：package 宣言のないソースファイルのクラスが入るパッケージ
- ポイント：小さなプログラムや学習用の便利さのためにある（JLS 7.4.2）。名前付きパッケージのクラスから、無名パッケージのクラスはインポートできない（JLS 7.5.1 のインポートは名前付きパッケージのメンバーだけ）
- 例：package を書かない Hello.java の Hello クラス

#### サブパッケージ（さぶぱっけーじ / subpackage）

- 意味：あるパッケージの下にある、名前を「.」でつないだパッケージ
- ポイント：java.util と java.util.concurrent は、名前は似ていても別のパッケージ。`import java.util.*;` で java.util.concurrent のクラスは使えるようにならない
- 例：java.util.concurrent は java.util のサブパッケージ

### ソースファイルとクラス

#### コンパイル単位（こんぱいるたんい / compilation unit）

- 意味：1 つのソースファイルのこと。package 宣言・import 宣言・クラスの宣言の 3 つの部分からなり、どれも省ける
- ポイント：並び順は package → import → クラスで決まっている（JLS 7.3）
- 例：`package p;` `import java.util.List;` `public class A { }` の順

#### public クラスとファイル名（ぱぶりっくくらすとふぁいるめい / public class and file name）

- 意味：public なクラスは、クラス名＋.java のファイルに書くという決まり
- ポイント：JLS 7.6 では「ファイルシステムを使う処理系が課してよい制約」とされ、javac はこれを守らせる。Main.java に `public class T` と書くと「class T is public, should be declared in a file named T.java」。1 つのファイルに public なクラスは 1 つまで（JLS 7.6 there must be at most one such class）
- 例：T.java には public class T

#### 1 ファイルに複数のクラス（いちふぁいるにふくすうのくらす / multiple top level classes in one file）

- 意味：1 つのソースファイルに、トップレベルのクラスを 2 つ以上書くこと
- ポイント：public でないクラスなら書いてよい。クラスファイルはクラスごとにでき、main を持つクラスならどれでも java で起動できる
- 例：T.java に public class T と class U → `java U` も動く

#### トップレベルクラス（とっぷれべるくらす / top level class）

- 意味：ほかのクラスの中ではなく、ファイルの直下に書いたクラス
- ポイント：アクセス修飾子は public か、何も書かない（同じパッケージだけ）のどちらか。private・protected・static を付けるとコンパイルエラー（JLS 7.6）。final・abstract は付けられる
- 例：`final class A {}` はOK、`private class A {}` は modifier private not allowed here

## 01-5 インポート

### まとめ表

| 書き方 | 種類 | 使えるようになるもの | 根拠 |
| :-- | :-- | :-- | :-- |
| `import java.util.List;` | 単一型インポート | List という 1 つの型 | JLS 7.5.1 |
| `import java.util.*;` | オンデマンドのインポート | java.util の型すべて（サブパッケージは含まない） | JLS 7.5.2 |
| `import static java.lang.Math.max;` | 単一 static インポート | Math の static メンバー max | JLS 7.5.3 |
| `import static java.lang.Math.*;` | static のオンデマンドのインポート | Math の static メンバーすべて | JLS 7.5.4 |
| （書かない） | 自動のインポート | java.lang の型すべて（String・Math・System など） | JLS 7.3 |

### インポートの種類

#### import 宣言（いんぽーとせんげん / import declaration）

- 意味：ほかのパッケージの型を、パッケージ名を付けずに短い名前で書けるようにする宣言
- ポイント：効くのは書いたそのファイルの中だけ（JLS 7.5）。import しなくても、完全修飾名で書けばどの型でも使える。インポートできるのは型（クラスやインタフェース）と static メンバーで、パッケージそのものはインポートできない（JLS 7.5.1 Example 7.5.1-3）
- 例：`import java.util.ArrayList;`

#### 単一型インポート（たんいつがたいんぽーと / single-type-import declaration）

- 意味：型を 1 つだけ名前を指定してインポートする書き方
- ポイント：同じ短い名前の型を 2 つ単一型インポートするとコンパイルエラー（使っていなくてもエラー）。オンデマンドのインポートと同じ名前がぶつかったときは、単一型インポートのほうが優先される（JLS 7.5.2 Example 7.5.2-1 might be shadowed by a single-type-import declaration）
- 例：`import java.util.Date;`

#### オンデマンドのインポート（おんでまんどのいんぽーと / type-import-on-demand declaration）

- 意味：パッケージ名のあとに `.*` を付けて、そのパッケージの型をまとめて使えるようにする書き方
- ポイント：サブパッケージの型は含まない。2 つのパッケージを `*` でインポートし、両方にある名前（Date など）を使うと「reference to Date is ambiguous」というコンパイルエラーになる。使わなければエラーにならない（JDK 17 で確認）
- 例：`import java.util.*;`

#### static インポート（すたてぃっくいんぽーと / static import）

- 意味：クラスの static なメソッドや定数を、クラス名を付けずに書けるようにする書き方
- ポイント：書き方は `import static`（`static import` の順は文法エラー）。クラス名で終わる `import static java.lang.Math;` はエラーで、最後はメンバー名か `*`。`import java.lang.Math.*;`（static なし）は Math の中の型をインポートする書き方で、max などのメソッドは使えるようにならない
- 例：`import static java.lang.Math.*;` のあと `max(3, abs(-5))`

#### java.lang の自動インポート（じゃばらんぐのじどういんぽーと / implicit import of java.lang）

- 意味：どのソースファイルにも `import java.lang.*;` が書いてあるのと同じ扱いになること
- ポイント：String・Math・System・StringBuilder・Integer などは import なしで使える（JLS 7.3）。ArrayList（java.util）・LocalDate（java.time）などは java.lang ではないので import が必要
- 例：`String s = "x";`（import なし）

### 名前のぶつかり

#### あいまいな参照（あいまいなさんしょう / ambiguous reference）

- 意味：同じ短い名前の型が 2 つ使える状態で、その名前を書いたために、どちらか決まらないこと
- ポイント：`import java.util.*;` と `import java.sql.*;` を書いて Date を使うとコンパイルエラー。どちらかを単一型インポートにするか、完全修飾名で書けば解決する
- 例：`import java.util.Date;` を足すと、Date は java.util.Date に決まる

#### シャドウイング（しゃどういんぐ / shadowing）

- 意味：近いところで宣言した同じ名前が、遠いところの名前を隠すこと
- ポイント：オンデマンドのインポートの型は、単一型インポートや、自分のパッケージにある同じ名前の型に隠される（JLS 7.5.2）。隠された型も完全修飾名なら使える
- 例：`import java.util.*;` があっても、同じファイルの `class Vector {}` が優先される（JLS 7.6 Example 7.6-1）

### 01-1 Java のしくみ

#### 問 java-01-o01

- 問：`javac Hello.java` を実行してコンパイルが成功したとき、新しくできるものはどれか。
- ア：JVM の命令（バイトコード）が入った Hello.class
- イ：OS がそのまま実行できる機械語のファイル
- ウ：クラスファイルをまとめた Hello.jar
- エ：コメントを取り除いた Hello.java
- 正解：ア
- 解説：javac はソースファイルを、JVM で動くクラスファイルに翻訳する。クラスファイルの中身はバイトコード（JVM の命令）。
- アの意味：正しい。-d がなければ Hello.java と同じ場所にできる。
- イの意味：C 言語などのコンパイラが作るもの。Java のクラスファイルは CPU の機械語ではなく、JVM が動かす。
- ウの意味：JAR は jar という別の道具で作る。javac は作らない。
- エの意味：javac はソースファイルを書きかえない。
- 出典：オリジナル問題（根拠：javac ドキュメント Description（compiles them into class files that run on the Java Virtual Machine）／JVMS 1.2（A class file contains Java Virtual Machine instructions (or bytecodes)））

#### 問 java-01-o02

- 問：JVM の説明として正しいものはどれか。
- ア：JVM は .java ファイルを 1 行ずつ読んで実行する
- イ：JVM は必ずインタプリタとして作らなければならない
- ウ：JVM が理解するのはクラスファイルの形式で、Java 言語の文法そのものは知らない
- エ：クラスファイルは、動かす OS ごとに作り直さなければならない
- 正解：ウ
- 解説：JVM はクラスファイルという決まった形式だけを知っている。だから同じクラスファイルが、JVM のあるどの OS でも動く。
- アの意味：ソースを読むのは javac（コンパイラ）。ソースファイルモードでも、java がいったんコンパイルしてから JVM が動かす。
- イの意味：JVMS 1.2 は、命令を CPU の命令に翻訳して動かす作り方も認めている。
- ウの意味：正しい。JVMS 1.2 にそのまま書かれている。
- エの意味：OS や CPU から独立していることが JVM の役目（JVMS 1.2）。
- 出典：オリジナル問題（根拠：JVMS 1.2（The Java Virtual Machine knows nothing of the Java programming language, only of a particular binary format, the class file format／It is not inherently interpreted））

### 01-2 main メソッドとコマンドライン引数

#### 問 java-01-o04

- 問：次の A.java をコンパイルし、`java A` で起動した。main の宣言を次のうちどれにすると、起動に失敗するか。
- ア：`static public void main(String[] args)`
- イ：`public static void main(String... args)`
- ウ：`public void main(String[] args)`
- エ：`public static void main(String args[])`
- 正解：ウ
- 解説：入口の main は public・static・void で、String の配列を受け取る形でなければならない。`public void main` は static がない。コンパイルは通るが、起動時に「Error: Main method is not static in class A」になる。
- アの意味：起動できる。修飾子の public と static は順番を入れかえてよい。
- イの意味：起動できる。可変長引数の形も JLS 12.1.4 が認めている。
- ウの意味：static がない。JVM はインスタンスを作らずに main を呼ぶので、起動できない。
- エの意味：起動できる。配列の [] は変数名のあとに書いてもよい。
- 出典：オリジナル問題（根拠：JLS 12.1.4（The method main must be declared public, static, and void. It must specify a formal parameter whose declared type is array of String）／JDK 17 での起動結果）

#### 問 java-01-o05

- 問：`java A` で起動できる main の宣言はどれか。
- ア：`public static int main(String[] args) { return 0; }`
- イ：`public static void main(String args)`
- ウ：`public static void Main(String[] args)`
- エ：`public static final void main(final String[] a)`
- 正解：エ
- 解説：final を足しても、引数の名前を a に変えても、public・static・void・String 配列の条件は満たしている。
- アの意味：コンパイルは通るが、起動時に「Main method must return a value of type void」になる。
- イの意味：引数が配列でない。起動時に「Main method not found」になる。
- ウの意味：Java は大文字と小文字を区別するので、Main は main ではない。「Main method not found」になる。
- エの意味：正しい。JDK 17 で起動できた。
- 出典：オリジナル問題（根拠：JLS 12.1.4／java ドキュメント Description（it must not return any value, and it must accept a String array as a parameter）／JDK 17 での起動結果）

#### 問 java-01-o06

- 問：次の Hello.java をコンパイルし、`java Hello a b c` で実行した。表示されるものはどれか。

  ```
  public class Hello {
    public static void main(String[] args) {
      System.out.println(args.length + ":" + args[0]);
    }
  }
  ```

- ア：4:Hello
- イ：3:Hello
- ウ：3:a
- エ：4:a
- 正解：ウ
- 解説：クラス名のあとの a・b・c の 3 つが、順に args[0]・args[1]・args[2] に入る。クラス名 Hello は配列に入らない。
- アの意味：C 言語の argv のように、0 番目にプログラム名が入ると考えたまちがい。
- イの意味：個数は合っているが、args[0] は Hello ではなく a。
- ウの意味：正しい。
- エの意味：個数にクラス名を数えている。
- 出典：オリジナル問題（根拠：JLS 12.1（java Test reboot Bob Dot Enzo … passing it an array containing the four strings）／JDK 17 での実行結果）

#### 問 java-01-o07

- 問：問 java-01-o06 と同じ Hello クラスを、Linux の bash で `java Hello "a b" c` と実行した。表示されるものはどれか。
- ア：3:"a
- イ：3:a
- ウ：2:"a b"
- エ：2:a b
- 正解：エ
- 解説：引用符でくくった a b は 1 つの引数になり、引用符はシェルが取り除く。引数は "a b" と "c" の 2 つ。
- アの意味：空白で分けて、引用符も残ると考えたまちがい。
- イの意味：引用符を無視して空白で 3 つに分けたまちがい。
- ウの意味：個数は合っているが、引用符は文字として残らない。
- エの意味：正しい。JDK 17 で 2:a b と表示された。
- 出典：オリジナル問題（根拠：java ドキュメント Synopsis（Arguments following mainclass … are passed as arguments to the main class）／JDK 17 での実行結果）

#### 問 java-01-o08

- 問：問 java-01-o06 と同じ Hello クラスを、引数なしで `java Hello` と実行した。結果として正しいものはどれか。
- ア：コンパイルの時点でエラーになり、Hello.class はできない

- アの意味：javac は引数の個数を知らないので、コンパイルは通る。

- ウの意味：正しい。「Index 0 out of bounds for length 0」と表示された。
- エの意味：args[0] は空文字列ではなく、存在しない。
- 出典：オリジナル問題（根拠：JLS 12.1（passing it a single argument which is an array of strings）／JDK 17 での実行結果）

#### 問 java-01-o09

- 問：次の Over.java をコンパイルし、`java Over` で実行した。結果はどれか。

  ```
  public class Over {
    public static void main(String[] args) {
      System.out.print("A");
  ```

### 01-3 コンパイルと実行

#### 問 java-01-o10

- 問：パッケージのない Hello クラスを Hello.java に書いた。カレントディレクトリでコンパイルして実行するコマンドの組み合わせとして正しいものはどれか。
- ア：`javac Hello` のあと `java Hello.class`
- イ：`javac Hello.java` のあと `java Hello.class`
- ウ：`javac Hello.java` のあと `java Hello`
- エ：`java Hello.java` のあと `javac Hello`
- 正解：ウ
- 解説：javac にはファイル名（拡張子 .java 付き）、java にはクラス名（拡張子なし）を渡す。
- アの意味：`javac Hello` は「Class names, 'Hello', are only accepted if annotation processing is explicitly requested」というエラーになる。また java に .class を付けるのもエラー。
- イの意味：コンパイルはできるが、`java Hello.class` は「Could not find or load main class Hello.class」になる。
- ウの意味：正しい。
- エの意味：`java Hello.java` はソースファイルモードで実行まではできるが、そのあとの `javac Hello` はファイル名の誤り。
- 出典：オリジナル問題（根拠：javac ドキュメント Description（Source files must have a file name extension of .java））／java ドキュメント Synopsis（java [options] mainclass [args ...]）／JDK 17 での実行結果）

#### 問 java-01-o11

- 問：Hello.java をコンパイルしたあと `java Hello.class` と打つと、「Error: Could not find or load main class Hello.class」と表示された。理由として正しいものはどれか。

- ウの意味：クラスパスに書くのはディレクトリや JAR で、何も指定しなければカレントディレクトリが使われている。
- エの意味：正しい。`java Hello` と打てば動く。
- 出典：オリジナル問題（根拠：java ドキュメント Description（the first argument that isn't an option of the java command is the fully qualified name of the class to be called）／JDK 17 での実行結果）

#### 問 java-01-o12

- 問：Hello.java だけがあるディレクトリで `java Hello.java p q` と実行した。説明として正しいものはどれか。

#### 問 java-01-o13

- 問：次の内容の Main.java を `java Main.java` で実行した。表示されるものはどれか。

  ```
  class T {
    public static void main(String[] a) { System.out.println("T"); }
  }
  class Main {
    public static void main(String[] a) { System.out.println("Main"); }
  }
  ```

- ア：Main
- イ：T と Main の両方

- 正解：エ

- ウの意味：main を持つクラスがいくつあってもエラーにはならない。

- 出典：オリジナル問題（根拠：java ドキュメント Using Source-File Mode（The class to be executed is the first top-level class found in the source file）／JDK 17 での実行結果）

#### 問 java-01-o15

- 問：src/com/example/app/Main.java の先頭に `package com.example.app;` と書いてある。`javac -d out src/com/example/app/Main.java` を実行したとき、Main.class ができる場所はどれか。
