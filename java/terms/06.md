## 06-1 if 文

### まとめ表

| 書き方 | 結果（JDK 17） | 理由 |
| :-- | :-- | :-- |
| `if (x > 3) if (x > 10) A; else B;` | else は内側の if に付く | ぶら下がり else は近い if のもの |
| `{ }` なしで 2 行を字下げ | 2 行目は if の外 | 字下げは意味を持たない |
| `if (…) A; B; else C;` | 'else' without 'if' | if の文は A だけ。B のあとに else は置けない |
| `else if` を大きい条件から書かない | 最初に true になった枝だけ | 上から順に調べて 1 つだけ実行 |
| `if (x > 0);` | 空文が if の文になる | 後ろの { } はいつも実行 |
| `if (x = 10)`（x は int） | コンパイルエラー | 条件は boolean か Boolean だけ |

### if と else

#### if 文（いふぶん / if statement）

- 意味：条件が true のときだけ文を実行する文。`if (条件) 文`
- ポイント：条件は boolean か Boolean（アンボクシングされる）でなければコンパイルエラー（JLS 14.9）。実行する文は 1 つで、複数の文はブロック { } にまとめる
- 例：`if (score >= 60) System.out.println("pass");`

#### if-else 文（いふえるすぶん / if-then-else statement）

- 意味：条件が true なら 1 つめの文、false なら else のあとの文を実行する。どちらか一方だけ
- ポイント：if と else の間に置けるのは文 1 つ（またはブロック）だけ。{ } なしで 2 つの文を書くと、else が if とつながらず 'else' without 'if' になる
- 例：`if (x > 0) System.out.println("+"); else System.out.println("-");`

#### else if（えるすいふ / else if chain）

- 意味：else のあとにさらに if を書いて、条件を順に調べる書き方
- ポイント：上から順に調べ、最初に true になった枝だけを実行する。条件の順番をまちがえると、下の枝に届かない（75 点で `x >= 60` を先に書くと、それより下の `x >= 70` は調べない）
- 例：`if (x >= 80) A; else if (x >= 70) B; else C;`

#### ぶら下がり else（ぶらさがりえるす / dangling else）

- 意味：if の中に if があり else が 1 つだけのとき、else がどちらの if に付くかという問題
- ポイント：else は、まだ else を持たないいちばん近い（内側の）if に付く（JLS 14.5）。字下げは関係ない。外側の if に付けたいときは内側の if を { } で囲む
- 例：`if (a) if (b) X; else Y;` の else は `if (b)` のもの

### ブロックと空文

#### ブロック（ぶろっく / block）

- 意味：{ } で囲んだ文のまとまり。if・else・ループの中で 1 つの文として扱われる
- ポイント：{ } がないと、if の対象は直後の 1 文だけ。字下げをそろえても 2 行目は if の外で、いつも実行される。ブロックの中で宣言した変数はブロックの外では使えない（#02 スコープ）
- 例：`if (x > 3) { A(); B(); }`

#### 空文（くうぶん / empty statement）

- 意味：`;` だけの文。何もしない（JLS 14.6：An empty statement does nothing）
- ポイント：`if (x > 0);` は空文が if の文になり、その後ろの { } は if と関係なくいつも実行される。コンパイルエラーにはならない
- 例：`if (x > 0); { System.out.println("block"); }` → x が 0 でも block と表示

#### 条件式の型（じょうけんしきのかた / type of the condition）

- 意味：if・while・for の条件に書く式の型。boolean か Boolean でなければならない
- ポイント：int は条件にできない（`if (x = 10)` は int cannot be converted to boolean）。Boolean の変数はアンボクシングして使える（null なら NullPointerException）
- 例：`Boolean f = Boolean.TRUE; if (f) …` はコンパイルできる

## 06-2 switch 文

### まとめ表

| 書き方 | 結果（JDK 17） | 理由 |
| :-- | :-- | :-- |
| break のない `case 2:` に合う | case 2 以降を全部実行 | フォールスルー |
| `default:` を先頭に置き、どれにも合わない | default から下へ実行 | default の位置は自由。合わないときに入る場所 |
| `switch (longの値)`・`switch (booleanの値)` | コンパイルエラー | セレクタに使える型は決まっている |
| `case y:`（y は final でない変数） | constant expression required | case は定数式か enum 定数 |
| 同じ値の case が 2 つ | duplicate case label | 重複はコンパイルエラー |
| String のセレクタが null | NullPointerException | null はどの case にも合わない |
| `case Color.RED:` | コンパイルエラー（17） | enum の case は定数名だけを書く |

### switch 文のしくみ

#### switch 文（すいっちぶん / switch statement）

- 意味：式の値に合う case ラベルへ処理を移す文
- ポイント：合う case がなく default もなければ何もしない（エラーにならない）。enum のセレクタで定数が足りなくても switch 文ならコンパイルできる
- 例：`switch (k) { case 1: … break; default: … }`

#### セレクタ式（せれくたしき / selector expression）

- 意味：switch のかっこの中の、値で分岐する式
- ポイント：型は char・byte・short・int・Character・Byte・Short・Integer・String・enum のどれか（JLS 14.11）。long・float・double・boolean はコンパイルエラー。ラッパーはアンボクシングされる。値が null なら NullPointerException
- 例：`switch (s)`（s は String）

#### case ラベル（けーすらべる / case label）

- 意味：`case 値:` の形で、セレクタの値と比べる場所の目印
- ポイント：値（case 定数）は定数式か enum の定数名でなければならない（JLS 14.11.1）。final でない変数は constant expression required。final のローカル変数を定数で初期化したものは使える。セレクタの型に代入できる値でなければならない（byte に case 200 は possible lossy conversion）
- 例：`final int Y = 2; … case Y:`

#### default ラベル（でふぉるとらべる / default label）

- 意味：どの case にも合わないときに処理が移る目印
- ポイント：1 つの switch に 1 つまで。どこに置いてもよい。先頭に置いても「合う case がないとき」だけ入る。入ったあとは break までフォールスルーする
- 例：`default: System.out.println("other");`

#### フォールスルー（ふぉーるするー / fall through）

- 意味：コロン（:）形式の switch で、合った case から break まで、下の case の文も続けて実行されること
- ポイント：JLS 14.11.3：execution of statements can "fall through labels"。break を書き忘れると、下の case や default の処理まで実行される。アロー（->）形式では起きない
- 例：k が 2 で case 2・3・default に break がない → two three other

#### break 文（ぶれいくぶん / break statement）

- 意味：switch やループをすぐに抜ける文
- ポイント：switch 文の中の break は switch を抜ける。最後の case の break はなくても動きは同じ（書くのはよい習慣）。switch 式からは break で値を返せない（yield を使う）
- 例：`case 1: System.out.println("one"); break;`

#### 重複した case ラベル（ちょうふくしたけーすらべる / duplicate case label）

- 意味：同じ値の case 定数が 2 つ以上あること
- ポイント：コンパイルエラー（duplicate case label、JLS 14.11.1：No two of the case constants … may have the same value）。'a' と 97 のように書き方がちがっても値が同じなら重複
- 例：`case 1: … case 1: …`

### 型ごとの注意

#### String の switch（すとりんぐのすいっち / switch on String）

- 意味：セレクタが String の switch。case には文字列リテラル（定数式）を書く
- ポイント：比べ方は equals（JLS 14.11.1：unless the value is a String, in which case equality is defined in terms of the equals method）。大文字と小文字は区別する。セレクタが null だと NullPointerException（case null は書けない）
- 例：`switch (s) { case "java": … }` は s が "Java" なら合わない

#### enum の switch（いなむのすいっち / switch on an enum）

- 意味：セレクタが enum 型の switch。case には enum 定数を書く
- ポイント：Java 17 では case に型名を付けない（`case RED:`）。`case Color.RED:` は an enum switch case label must be the unqualified name of an enumeration constant でコンパイルエラー。switch 文なら全部の定数を書かなくてよい
- 例：`switch (c) { case RED: … case GREEN: … }`

#### char の switch（きゃらのすいっち / switch on char）

- 意味：セレクタが char の switch。case には文字リテラルか、char に入る int の定数を書ける
- ポイント：'b' は 98 なので、`case 98:` は c が 'b' のときに合う。'b' と 98 を両方書くと重複
- 例：`char c = 'b'; switch (c) { case 98: … }`

#### switch ブロックのスコープ（すいっちぶろっくのすこーぷ / scope in a switch block）

- 意味：コロン形式の switch では、{ } 全体が 1 つのブロック。case の中で宣言した変数は、それより下の case でも見える
- ポイント：case 1 で `int a = 10;` と宣言すると、case 3 で `a = 30;` と代入して使える（宣言は見えるが、初期化は通っていないので代入が必要）。アロー形式でブロックを使えば、各ブロックで別々に宣言できる
- 例：`case 1: int a = 10; break; case 3: a = 30; …`

## 06-3 アロー形式と switch 式

### まとめ表

| 書き方 | 結果（JDK 17） | 理由 |
| :-- | :-- | :-- |
| `case 1, 7 -> …` | どちらかに合えば実行 | 1 つの case に複数の定数 |
| `->` の右 | その 1 つだけ実行。フォールスルーなし | switch ルール |
| `:` と `->` をまぜる | different case kinds used in the switch | どちらか一方に統一 |
| switch 式に default がない（int） | does not cover all possible input values | 値を必ず返す（網羅性） |
| enum の定数を全部書いた switch 式 | default なしで OK | すべての値を処理している |
| `-> { …; yield 値; }` | ブロックから値を返す | return は使えない |
| switch 文で `case 2 -> "two";` | not a statement | switch 文の -> の右は文になる式だけ |

### アロー形式

#### switch ルール（すいっちるーる / switch rule）

- 意味：`case 定数 -> 式;`・`-> { ブロック }`・`-> throw …;` の形のラベル。アロー形式とも呼ぶ
- ポイント：合ったルールの右側だけを実行し、下へフォールスルーしない。break はいらない。switch 文では右に書ける式は「式文」（メソッド呼び出し・代入・++ など）だけ
- 例：`case 1 -> System.out.println("one");`

#### 複数の case 定数（ふくすうのけーすていすう / multiple case constants）

- 意味：`case 1, 7 ->` のように、1 つの case にカンマで定数を並べる書き方（Java 14〜）
- ポイント：どれか 1 つに合えばその case に入る。コロン形式でも `case 1, 7:` と書ける
- 例：`case SATURDAY, SUNDAY -> "weekend";`

#### ラベルの形の混在（らべるのかたちのこんざい / mixing case kinds）

- 意味：1 つの switch の中に、コロン（:）形式とアロー（->）形式をまぜること
- ポイント：コンパイルエラー（different case kinds used in the switch）。switch ブロックは switch ルールだけか、コロン形式のグループだけのどちらか（JLS 14.11.1 の構文）
- 例：`case 1 -> …; case 2: …` はエラー

#### 式文（しきぶん / expression statement）

- 意味：式のうち、そのまま `;` を付けて文にできるもの。代入・++/--・メソッド呼び出し・new
- ポイント：switch 文のアローの右は式文でなければならない（JLS 14.11.2）。`case 2 -> "two";` は文字列だけで文にならず not a statement。switch 式なら右にどんな式でも書ける
- 例：`case 2 -> count++;` は OK

### switch 式

#### switch 式（すいっちしき / switch expression）

- 意味：値を返す switch（Java 14〜）。`String s = switch (k) { … };` のように式として使う
- ポイント：すべての値を処理しなければならない（網羅性）。終わりに `;` が必要（代入文の一部だから）。空の { } は書けない。値を返さない枝はコンパイルエラー
- 例：`int n = switch (k) { case 1 -> 10; default -> 0; };`

#### yield 文（いーるどぶん / yield statement）

- 意味：switch 式のブロックやコロン形式の中で、switch 式の値を返す文
- ポイント：`-> { …; yield 値; }` の形。ブロックの最後に値だけを書くと not a statement、return は attempt to return out of a switch expression でコンパイルエラー。コロン形式の switch 式は yield までフォールスルーする。yield は文脈キーワードなので、変数名にも使える
- 例：`default -> { System.out.print("calc "); yield "weekday"; }`

#### 網羅性（もうらせい / exhaustiveness）

- 意味：switch 式が、セレクタのありうるすべての値に対して枝を持つこと
- ポイント：int や String のセレクタでは default が必須（JLS 15.28.1：exactly one default label）。enum では全定数を case に書けば default なしでよい。足りないと the switch expression does not cover all possible input values
- 例：Color（RED・GREEN・BLUE）の 3 つを全部書いた switch 式は default 不要

#### switch 式の型（すいっちしきのかた / type of a switch expression）

- 意味：switch 式全体の値の型。代入先があればその型、var などでは結果の式の型から決まる
- ポイント：結果が int と double なら数値の昇格で double（`var r = switch…` で 1 は 1.0 になる）。結果の式どうしで型がそろわないと、代入先によってはコンパイルエラー
- 例：`var r = switch (k) { case 1 -> 1; case 2 -> 2.5; default -> 0; };` → k が 1 なら 1.0

#### switch ルールの throw（すいっちるーるのすろー / switch rule throw statement）

- 意味：`case 値 -> throw 例外;` の形で、その値のとき例外をスローするルール
- ポイント：throw は値を返さないが、switch 式の中に書いてよい（ほかの枝が値を返せばよい）
- 例：`case 2 -> throw new IllegalStateException("no");`

### 06-1 if 文

#### 問 java-06-o01

- 問：main メソッドの中の次のコードを実行した。表示されるものはどれか。

  ```
  int x = 5;
  if (x > 3)
    if (x > 10) System.out.println("A");
  else System.out.println("B");
  System.out.println("C");
  ```

- ア：C だけ
- イ：A と C の 2 行
- ウ：B と C の 2 行
- エ：コンパイルエラーになる
- 正解：ウ
- 解説：else は字下げに関係なく、いちばん近い if（内側の if (x > 10)）に付く。x > 3 は true、x > 10 は false なので else の B が表示され、最後に C。
- アの意味：else が外側の if に付くと考えたまちがい。字下げは意味を持たない。
- イの意味：x > 10 を true と考えたまちがい。
- ウの意味：正しい。
- エの意味：if の中に if を書き、else を 1 つだけ書くのは正しい文法。
- 出典：オリジナル問題（根拠：JLS 14.5（an else clause belongs to the innermost if to which it might possibly belong）・14.9／JDK 17 での実行結果）

#### 問 java-06-o02

- 問：main メソッドの中の次のコードを実行した。表示されるものはどれか。

  ```
  int x = 5;
  if (x > 3)
    System.out.println("A");
    System.out.println("B");
  if (x > 10)
    System.out.println("C");
    System.out.println("D");
  ```

- ア：A、B の 2 行
- イ：A、B、C、D の 4 行
- ウ：A、B、D の 3 行
- エ：A、D の 2 行
- 正解：ウ
- 解説：{ } がないので、if の対象は直後の 1 文だけ。B と D は if の外にあるのでいつも実行される。x > 3 は true で A、x > 10 は false で C は表示されない。
- アの意味：字下げした D も 2 つめの if の中だと考えたまちがい。
- イの意味：x > 10 も true と考えたまちがい。
- ウの意味：正しい。
- エの意味：B が 1 つめの if の中だと考えたうえ、if の外の文を見落としたまちがい。
- 出典：オリジナル問題（根拠：JLS 14.9（if ( Expression ) Statement：対象は 1 つの文）／JDK 17 での実行結果）

#### 問 java-06-o03

- 問：main メソッドの中の次のコードを実行した。表示されるものはどれか。

  ```
  int x = 75;
  if (x >= 60) System.out.println("C");
  else if (x >= 70) System.out.println("B");
  else if (x >= 80) System.out.println("A");
  else System.out.println("F");
  ```

- ア：B
- イ：C
- ウ：C と B の 2 行
- エ：F
- 正解：イ
- 解説：else if は上から順に調べ、最初に true になった枝だけを実行する。75 は最初の x >= 60 で true になるので C だけ。下の x >= 70 は調べない。
- アの意味：いちばん合う（範囲の狭い）条件が選ばれると考えたまちがい。
- イの意味：正しい。
- ウの意味：true になる枝を全部実行すると考えたまちがい。else があるので 1 つだけ。
- エの意味：else の意味を取りちがえたまちがい。
- 出典：オリジナル問題（根拠：JLS 14.9.2（If the value is true, then the first contained Statement … is executed／If the value is false, then the second contained Statement … is executed）／JDK 17 での実行結果）

#### 問 java-06-o04

- 問：main メソッドの中の次のコードをコンパイルした。結果として正しいものはどれか。

  ```
  int x = 1;
  if (x > 0)
    System.out.println("A");
    System.out.println("B");
  else
    System.out.println("C");
  ```

- ア：コンパイルでき、実行すると A と B が表示される
- イ：'else' without 'if' のコンパイルエラーになる
- ウ：コンパイルでき、実行すると A だけが表示される
- エ：コンパイルでき、実行すると B と C が表示される
- 正解：イ
- 解説：if の対象は A の文だけで、B の文は if の外。B のあとに else が来るので、つながる if がなく 'else' without 'if' になる。2 つの文を if の中に入れたいときは { } で囲む。
- アの意味：字下げで if の範囲が決まると考えたまちがい。
- イの意味：正しい。
