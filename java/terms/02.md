## 02-1 基本データ型

### まとめ表

| 型 | 大きさ | 値の範囲 | 初期値（フィールド・配列） |
| :-- | :-- | :-- | :-- |
| byte | 8 ビット（符号あり） | -128 〜 127 | 0 |
| short | 16 ビット（符号あり） | -32768 〜 32767 | 0 |
| int | 32 ビット（符号あり） | -2147483648 〜 2147483647 | 0 |
| long | 64 ビット（符号あり） | 約 -9.2×10^18 〜 約 9.2×10^18 | 0L |
| char | 16 ビット（符号なし） | 0 〜 65535（'\u0000' 〜 '￿'） | '\u0000' |
| float | 32 ビット（IEEE 754） | 小数 | 0.0f |
| double | 64 ビット（IEEE 754） | 小数 | 0.0d |
| boolean | — | true か false | false |
| 参照型（String・配列など） | — | オブジェクトへの参照か null | null |

### 8 つの基本データ型

#### 基本データ型（きほんでーたがた / primitive type）

- 意味：Java の言語に最初から用意されている 8 つの型。byte・short・int・long・char・float・double・boolean
- ポイント：名前はすべて小文字の予約語（JLS 4.2）。値そのものを入れる。String や配列はオブジェクトを指す参照型で、基本データ型ではない
- 例：`int n = 10;` `boolean ok = true;`

#### 整数型（せいすうがた / integral type）

- 意味：整数を表す型。byte（8 ビット）・short（16）・int（32）・long（64）と、文字を表す char（16）
- ポイント：byte・short・int・long は符号あり（2 の補数）、char だけ符号なし（JLS 4.2）。整数の計算のふつうの型は int
- 例：byte の範囲は -128〜127（JLS 4.2.1）

#### 浮動小数点型（ふどうしょうすうてんがた / floating-point type）

- 意味：小数を表す型。float（32 ビット）と double（64 ビット）
- ポイント：IEEE 754 の形式（JLS 4.2）。小数のリテラルは何も付けなければ double。float に入れるには F を付ける
- 例：`double d = 1.5;` `float f = 1.5F;`

#### char（きゃら / char）

- 意味：1 つの文字（UTF-16 の 1 単位）を表す 16 ビットの型。中身は 0〜65535 の数
- ポイント：数として計算できる。char どうしを + すると int の足し算になり、文字はつながらない（'A'+'B' は 131）。負の数は入らない
- 例：`char c = 'A';` `char d = 65;`（どちらも A）

#### boolean（ぶーりあん / boolean）

- 意味：true か false のどちらかだけを持つ型
- ポイント：数とは変換できない。`boolean f = 0;` は「int cannot be converted to boolean」（C 言語とちがう）
- 例：`boolean done = false;`

#### 初期値（しょきち / default value）

- 意味：フィールド（クラスの変数）や配列の要素に、何も代入しなくても最初から入っている値
- ポイント：数は 0、boolean は false、char は '\u0000'、参照型は null（JLS 4.12.5）。ローカル変数には初期値がない
- 例：`new int[2]` の要素は 0、`new String[1]` の要素は null

#### オーバーフロー（おーばーふろー / overflow）

- 意味：計算の結果が型の範囲をこえ、反対の端の値に回りこむこと
- ポイント：エラーにも例外にもならない。int の 2147483647 に 1 を足すと -2147483648。`long y = x + 1;`（x は int）でも、足し算は int で行われてから long に広げられるので回りこむ
- 例：`x + 1L` と書けば long で計算され、2147483648 になる

## 02-2 リテラルと識別子

### まとめ表

| リテラル | 型 | 例 | 注意 |
| :-- | :-- | :-- | :-- |
| 整数（10 進） | int | `100` | 2147483647 をこえるとエラー（integer number too large） |
| 整数＋L | long | `2147483648L` | 小文字 l も可だが 1 と見まちがえやすい |
| 16 進・8 進・2 進 | int | `0x1F`（31）・`017`（15）・`0b101`（5） | 0 で始まると 8 進。`09` はエラー |
| 小数 | double | `1.5`・`1.5D` | float に入れるとエラー |
| 小数＋F | float | `1.5F` | — |
| 文字 | char | `'A'`・`'A'` | 1 文字。シングルクォート |
| 真偽 | boolean | `true`・`false` | 予約語ではなくリテラル |
| null | null 型 | `null` | 参照型にだけ入る |

### 数字の書き方

#### 整数リテラル（せいすうりてらる / integer literal）

- 意味：ソースに直接書いた整数の値
- ポイント：何も付けなければ int。L（または l）を付けると long（JLS 3.10.1）。`long a = 2147483648;` は、右辺が int の範囲をこえるのでコンパイルエラー
- 例：`long a = 2147483648L;`

#### 16 進・8 進・2 進（じゅうろくしん・はっしん・にしん / hexadecimal, octal, binary）

- 意味：0x で始めると 16 進、0 で始めると 8 進、0b で始めると 2 進のリテラル
- ポイント：0x1F は 31、017 は 15、0b101 は 5。8 進では 8 と 9 は使えない（`09` はエラー）。大文字の 0X・0B も同じ
- 例：`int h = 0x1F;`

#### アンダースコア（あんだーすこあ / underscore in numeric literal）

- 意味：数字の間に入れて読みやすくする「_」。値は変わらない
- ポイント：数字と数字の間にだけ書ける。先頭・末尾・0x の直後・小数点の前後・L や F の直前は不可（illegal underscore）。続けて 2 つ（1__0）は OK。先頭の `_100` は数ではなく変数名として読まれる（JLS 3.10.1）
- 例：`int u = 1_000_000;`

#### 浮動小数点リテラル（ふどうしょうすうてんりてらる / floating-point literal）

- 意味：ソースに直接書いた小数の値
- ポイント：何も付けなければ double。F（f）を付けると float、D（d）を付けても double（JLS 3.10.2）。`float f = 1.5;` は「possible lossy conversion from double to float」
- 例：`float f = 1.5F;` `float g = 10;`（整数は float に入る）

#### 文字リテラル（もじりてらる / character literal）

- 意味：シングルクォートでくくった 1 文字。`'A'` のように Unicode の番号でも書ける
- ポイント：ダブルクォートは String。char の変数には 0〜65535 の int の定数も入る（`char b = 65;` は 'A'）
- 例：`char c = 'A';`

### 名前の決まり

#### 識別子（しきべつし / identifier）

- 意味：変数・メソッド・クラスなどに付ける名前
- ポイント：使えるのは文字（日本語も可）・数字・$・_。先頭に数字は不可。予約語・true・false・null は不可。大文字と小文字は区別する（JLS 3.8）。ハイフン（-）は引き算の記号なので使えない
- 例：`int $a, _b, c3, 名前;` はすべて OK

#### 予約語（よやくご / reserved keyword）

- 意味：言語が使うために取ってあり、名前にできない語。int・class・if など
- ポイント：使っていない goto と const も予約語（JLS 3.9）。Java 9 から「_」1 文字も予約語で、`int _ = 3;` はエラー。true・false・null は予約語ではなくリテラルだが、やはり名前にできない
- 例：`int goto = 1;` はコンパイルエラー

#### 文脈キーワード（ぶんみゃくきーわーど / contextual keyword）

- 意味：決まった場所でだけキーワードになり、ほかの場所では名前に使える語。var・record・sealed・permits・yield など
- ポイント：`int var = 3;`・`var var = "var";` は OK。ただしクラスなど型の名前にはできない（`class var {}` は「'var' not allowed here」）（JLS 3.8・3.9）
- 例：`int record = 1;` は OK

## 02-3 変数の宣言・初期化・スコープ

### まとめ表

| 変数の種類 | 書く場所 | 初期値 | スコープ（使える範囲） |
| :-- | :-- | :-- | :-- |
| ローカル変数 | メソッドやブロックの中 | なし（使う前に代入が必要） | 宣言した所からブロックの終わりまで |
| for 文の変数 | for の ( ) の中 | なし | その for 文の中だけ |
| メソッドの引数 | メソッドの ( ) | 呼んだ側が渡した値 | メソッドの中 |
| インスタンス変数 | クラスの中（static なし） | 型の初期値 | クラスの中（#08） |
| クラス変数 | クラスの中（static） | 型の初期値 | クラスの中（#09） |

### 宣言と初期化

#### 変数の宣言（へんすうのせんげん / variable declaration）

- 意味：型と名前を書いて、変数を用意すること
- ポイント：カンマで 1 行に何個でも宣言できる。左の変数を右の初期化で使ってもよい（`int a = 1, b = a + 1;`）。`int a = 1, int b = 2;` のように型を 2 回書くのはエラー
- 例：`int a = 1, b = 2, c;`

#### 初期化（しょきか / initialization）

- 意味：宣言と同時に最初の値を入れること
- ポイント：`int a, b = 3;` で初期化されるのは b だけ。a は値がない
- 例：`int count = 0;`

#### ローカル変数（ろーかるへんすう / local variable）

- 意味：メソッドやブロックの中で宣言した変数
- ポイント：初期値がない。値を入れる前に使うと「variable x might not have been initialized」というコンパイルエラー（JLS 4.12.5）。宣言だけならエラーにならない
- 例：`int x; x = 1; System.out.println(x);` は OK

#### 確実な代入（かくじつなだいにゅう / definite assignment）

- 意味：変数を使う時点で、どの道すじを通っても必ず値が入っていることを、コンパイラが確かめる決まり
- ポイント：if だけで代入すると、条件が false の道すじで値がないのでエラー。if と else の両方で代入すれば OK（JLS 16）
- 例：`int x; if (c) x = 1; else x = 2;` のあとなら x を使える

#### final 変数（ふぁいなるへんすう / final variable）

- 意味：一度だけ値を入れられ、そのあと変えられない変数
- ポイント：宣言と同時に入れなくても、あとで 1 回だけ代入すればよい。2 回目は「cannot assign a value to final variable」や「might already have been assigned」
- 例：`final int a; a = 1;` は OK

### スコープ

#### スコープ（すこーぷ / scope）

- 意味：変数の名前を使える範囲
- ポイント：ブロック（{ }）の中で宣言したローカル変数は、宣言した所からそのブロックの終わりまで（JLS 6.3）。ブロックの外で使うと「cannot find symbol」
- 例：if の { } の中で宣言した y は、if の外では使えない

#### ブロック（ぶろっく / block）

- 意味：{ と } でくくった文のまとまり
- ポイント：ブロックが終わればその中の変数は使えなくなるので、そのあとで同じ名前を宣言し直してよい。2 つの for 文に同じ int i を書けるのもこのため
- 例：`{ int y = 20; } int y = 1;` は OK

#### for 文の変数のスコープ（ふぉーぶんのへんすうのすこーぷ / scope of a for loop variable）

- 意味：for (int i = 0; …) の i が使える範囲
- ポイント：for 文の中（条件・更新・本体）だけ。ループのあとで i を使うと「cannot find symbol」（JLS 6.3）
- 例：ループのあとで回数を使いたいなら、for の前で宣言する

#### 同じ名前の宣言（おなじなまえのせんげん / redeclaration）

- 意味：スコープの中に、同じ名前のローカル変数をもう 1 つ宣言すること
- ポイント：ローカル変数 x のスコープの中（内側のブロックを含む）で x を宣言し直すと「variable x is already defined」（JLS 6.4）。内側のブロックが終わったあとの宣言は OK
- 例：`int x = 10; { int x = 20; }` はコンパイルエラー

#### フィールドの隠蔽（ふぃーるどのいんぺい / shadowing a field）

- 意味：フィールドと同じ名前のローカル変数を宣言すると、その範囲では名前がローカル変数を指すこと
- ポイント：ローカル変数どうしとちがい、エラーにはならない。隠れたフィールドは `クラス名.名前`（static）や `this.名前` で使える（#08）
- 例：`static int x = 5;` のクラスで `int x = 10;` → `x + Main.x` は 15

## 02-4 型変換とラッパークラス

### まとめ表

| 代入 | 書けるか | 理由 |
| :-- | :-- | :-- |
| `long l = i;`（i は int） | そのまま書ける | 広げる変換（拡大変換） |
| `double d = f;`（f は float） | そのまま書ける | 広げる変換 |
| `char c = b;`（b は byte） | エラー | byte の負の数は char に入らない。広げる変換ではない |
| `byte b = i;`（i は int の変数） | エラー | 縮める変換にはキャストが必要 |
| `byte b = 10;`・`final int i = 10; byte b = i;` | 書ける | 範囲内の int の定数は byte・short・char に入る |
| `byte b = (byte) i;` | 書ける | キャストで縮める（はみ出した上位ビットは捨てる） |
| `b += 1;`（b は byte） | 書ける | 複合代入は自動でキャストする |
| `Integer a = 10;`・`int b = a;` | 書ける | ボクシング・アンボクシング |
| `Long f = 10;` | エラー | int を Long にはボクシングできない |

### 基本データ型どうしの変換

#### 拡大変換（かくだいへんかん / widening primitive conversion）

- 意味：小さい型の値を、より大きい型に変えること。代入するだけで自動で行われる
- ポイント：byte → short → int → long → float → double の向きと、char → int の向き（JLS 5.1.2）。byte・short から char、char から short は含まれない。int・long から float などは精度が落ちることがあるが、例外にはならない
- 例：`long l = 10;` `float f = l;`

#### 縮小変換（しゅくしょうへんかん / narrowing primitive conversion）

- 意味：大きい型の値を小さい型に変えること。ふつうはキャストが必要
- ポイント：キャストなしで代入すると「possible lossy conversion」。整数どうしでは上位のビットを捨てるので、(byte) 200 は -56。小数から整数は小数部分を切り捨て（0 の方向へ）で、(int) -3.99 は -3（JLS 5.1.3）
- 例：`byte b = (byte) i;`

#### キャスト（きゃすと / cast）

- 意味：（型）を値の前に書いて、型を変えるように指示すること
- ポイント：縮小変換をしてよいとコンパイラに伝える書き方。値が範囲外なら、エラーではなく変わった値になる。参照型のキャストは #11
- 例：`(int) 3.99` は 3

#### 定数の代入の特別ルール（ていすうのだいにゅうのとくべつるーる / constant narrowing in assignment）

- 意味：int の定数で、値が入る範囲なら、byte・short・char の変数にキャストなしで代入できるという決まり
- ポイント：定数（リテラルや final で初期化した変数）だけ。ふつうの int の変数はだめ。範囲外（`byte c = 128;`）はエラー（JLS 5.2）
- 例：`byte b = 42;` `final int i = 10; byte c = i;`

#### 数値の昇格（すうちのしょうかく / numeric promotion）

- 意味：計算の前に、両辺の型をそろえること
- ポイント：どちらかが double なら double、float なら float、long なら long、それ以外（byte・short・char・int）はすべて int にそろえて計算する（JLS 5.6）。だから byte + 1 の結果は int
- 例：`b = b + 1;`（b は byte）は「possible lossy conversion from int to byte」

#### 複合代入演算子（ふくごうだいにゅうえんざんし / compound assignment operator）

- 意味：+= や -= のように、計算と代入をまとめた演算子
- ポイント：`E1 op= E2` は `E1 = (T)((E1) op (E2))` と同じで、左辺の型へのキャストが自動で入る（JLS 15.26.2）。byte b に `b += 1` は OK。127 に += 1 すると -128 に回りこむ
- 例：`byte b = 10; b += 1;` は 11

### ラッパークラス

#### ラッパークラス（らっぱーくらす / wrapper class）

- 意味：基本データ型の値を包んで、オブジェクトとして扱うためのクラス。Byte・Short・Integer・Long・Character・Float・Double・Boolean
- ポイント：int と char だけ名前が大きくちがう（Integer・Character）。ArrayList などのコレクションには基本データ型を入れられないので、ラッパークラスで入れる（#04）
- 例：`Integer a = 10;`

#### オートボクシング（おーとぼくしんぐ / boxing conversion）

- 意味：基本データ型の値を、対応するラッパークラスのオブジェクトに自動で変えること
- ポイント：変わる先は対応する 1 つのクラスだけ（int → Integer）。int を Long や Double には変えられず、`Long f = 10;` は「int cannot be converted to Long」。ただし範囲内の int の定数は Byte・Short・Character には入る（JLS 5.2）
- 例：`Long f = 10L;` `Short s = 10;`

#### アンボクシング（あんぼくしんぐ / unboxing conversion）

- 意味：ラッパークラスのオブジェクトを、基本データ型の値に自動で戻すこと
- ポイント：中身が null だと NullPointerException（JLS 5.1.8）。アンボクシングのあと拡大変換もできる（`long g = Integer.valueOf(5);` は OK）
- 例：`Integer x = null; int y = x;` → 実行時に NullPointerException

#### parseInt（ぱーすいんと / Integer.parseInt）

- 意味：文字列を int に変える Integer の static メソッド
- ポイント：数として読めない文字列なら NumberFormatException（実行時）。Integer を返すのは Integer.valueOf(String)。double なら Double.parseDouble
- 例：`int d = Integer.parseInt("30");`

## 02-5 var（ローカル変数型推論）

### まとめ表

| 書き方 | 結果 | JDK 17 の表示 |
| :-- | :-- | :-- |
| `var a = 1;` | int になる | — |
| `var a;` | エラー | cannot infer type for local variable a |
| `var a = null;` | エラー | cannot infer type for local variable a |
| `var a = 1, b = 2;` | エラー | 'var' is not allowed in a compound declaration |
| `var a = {1, 2};` | エラー | cannot infer type for local variable a |
| `var a[] = new int[2];` | エラー | 'var' is not allowed as an element type of an array |
| `var f = () -> "hello";` | エラー | cannot infer type for local variable f |
| フィールド・メソッドの引数・戻り値の型に var | エラー | 'var' is not allowed here |
| `for (var i = 0; …)`・`for (var s : args)` | 書ける | — |

### 型推論のしくみ

#### var（ばー / local variable type inference）

- 意味：ローカル変数の型を書くかわりに var と書き、初期化の式から型をコンパイラに決めさせる書き方。Java 10 から
- ポイント：型はコンパイルのときに 1 つに決まり、あとで変わらない（`var a = 1;` の a に 2.5 は入らない）。動的な型ではない。使えるのはローカル変数（for 文・拡張 for 文・try-with-resources を含む）だけ（JLS 14.4）
- 例：`var list = new ArrayList<String>();`（ArrayList<String> になる）

#### 推論される型（すいろんされるかた / inferred type）

- 意味：var の変数に決まる型。初期化の式の型そのもの
- ポイント：`var a = 1;` は int（Integer ではない）、`1L` は long、`1.0` は double、`'x'` は char、`"x"` は String。`var z = 'a' + 1;` は int で 98（JLS 14.4.1）
- 例：`var x = 5 / 2;` は int の 2

#### var を使えない場面（ばーをつかえないばめん / restrictions on var）

- 意味：var が文法上許されない書き方
- ポイント：初期化がない、null だけ、カンマで複数、配列の { } 初期化、[ ] を付ける、自分自身を使う初期化、ラムダ式・メソッド参照はエラー（JLS 14.4・14.4.1）。フィールド・メソッドの引数・戻り値の型にも使えない
- 例：`var x = (String) null;` はキャストで型が決まるので OK

#### 問 java-02-o01

- イ：short

#### 問 java-02-o02

- 問：コンパイルできる宣言はどれか。

- エの意味：正しい。127 は byte の最大値。

#### 問 java-02-o04

#### 問 java-02-o05

- 問：main メソッドの中の次のコードを実行した。表示されるものはどれか。

#### 問 java-02-o06

#### 問 java-02-o19

- 問：main メソッドの中の次のコードをコンパイルした。結果はどれか。

  ```
  int a, b = 3;
  System.out.println(b);
  System.out.println(a);
  ```

- ア：3 と 3 が表示される
- イ：3 と 0 が表示される
- ウ：3 が表示されたあと、実行時エラー
- エ：3 行目の a が初期化されていないので、コンパイルエラー
- 正解：エ
- 解説：`int a, b = 3;` で初期化されるのは b だけ。a には値が入っていない。
- アの意味：= 3 は b だけにかかる。
- イの意味：ローカル変数に 0 は入らない。
- ウの意味：コンパイルの段階で止まるので、何も表示されない。
- エの意味：正しい。「variable a might not have been initialized」。
- 出典：オリジナル問題（根拠：JLS 14.4.2（If a declarator does not have an initializer, then every reference to the variable must be preceded by execution of an assignment to the variable, or a compile-time error occurs）／JDK 17 でのコンパイル結果）

#### 問 java-02-o20

- 問：main メソッドの中に書いたとき、コンパイルできるものはどれか。
- ア：`final int a; a = 1; System.out.println(a);`
- イ：`final int a = 1; a = 2;`
- ウ：`final int a; a = 1; a = 2;`
- エ：`int a = 1, int b = 2;`
- 正解：ア
- 解説：final のローカル変数は、宣言のときに値がなくても、あとで 1 回だけ代入できる。
- アの意味：正しい。1 と表示される。
- イの意味：初期化で値が入っているので、2 回目の代入になる。「cannot assign a value to final variable a」。
- ウの意味：2 回目の代入。「variable a might already have been assigned」。

### 02-4 型変換とラッパークラス

#### 問 java-02-o21

- 問：b は byte、l は long、f は float の変数とする。キャストなしではコンパイルエラーになる代入はどれか。
- ア：`char c = b;`
- イ：`short s = b;`
- ウ：`float g = l;`
- エ：`double d = f;`
- 正解：ア
- 解説：byte は負の数を持てるが、char は持てない。そのため byte から char は拡大変換に入っていない。
- アの意味：正しい（エラーになる）。「possible lossy conversion from byte to char」。
- イの意味：byte → short は拡大変換。
- ウの意味：long → float は拡大変換（精度が落ちることはあるが自動で行われる）。
- エの意味：float → double は拡大変換。
- 出典：オリジナル問題（根拠：JLS 5.1.2（byte to short, int, long, float, or double／long to float or double／float to double）／JDK 17 でのコンパイル結果）

#### 問 java-02-o22

- 問：main メソッドの中に書いたとき、コンパイルできるものはどれか。
- ア：`int i = 10; byte b = i;`
- イ：`final int i = 10; byte b = i;`
- ウ：`byte c = 128;`
- エ：`long l = 10; int i = l;`
- 正解：イ
- 解説：final で定数に初期化した int は「定数式」なので、値が byte の範囲なら、キャストなしで byte に入れられる。
- アの意味：final のない変数は定数ではない。「possible lossy conversion from int to byte」。
- イの意味：正しい。
- ウの意味：定数でも 128 は byte の範囲外。
- エの意味：long から int は縮小変換。`(int) l` と書く。
- 出典：オリジナル問題（根拠：JLS 5.2（if the expression is a constant expression of type byte, short, char, or int: A narrowing primitive conversion may be used if the variable is of type byte, short, or char, and the value of the constant expression is representable）／JDK 17 でのコンパイル結果）

#### 問 java-02-o23

- 問：次の文を実行した。表示されるものはどれか。

  ```
  System.out.println((byte) 200 + " " + (int) 3.99 + " " + (int) -3.99);
  ```

- ア：200 4 -4
- イ：-56 3 -3
- ウ：-56 4 -4
- エ：-56 3 -4
- 正解：イ
- 解説：200 を byte にすると、下位 8 ビットだけが残って -56（200−256）。小数から整数へのキャストは小数部分を捨てる（0 の方向へ丸める）ので、3.99 は 3、-3.99 は -3。
- アの意味：キャストで値が変わらず、四捨五入されると考えたまちがい。
- イの意味：正しい。
- ウの意味：四捨五入ではなく切り捨て。
- エの意味：負の数も 0 の方向へ丸めるので -3（-4 にはならない）。
- 出典：オリジナル問題（根拠：JLS 5.1.3（A narrowing conversion of a signed integer to an integral type T simply discards all but the n lowest order bits／the floating-point value is rounded to an integer value V using the round toward zero rounding policy）／JDK 17 での実行結果）

#### 問 java-02-o24

- 問：main メソッドの中の次のコードを実行した。表示されるものはどれか。

  ```
  byte b = 10;
  b += 1;
  b++;
  System.out.println(b);
  byte c = 127;
  c += 1;
  System.out.println(c);
  ```

- ア：12 と -128
- イ：12 と 128
- ウ：b += 1 の行でコンパイルエラー
- エ：c += 1 の行で実行時に例外
- 正解：ア
- 解説：複合代入（+=）と ++ は、左辺の型 byte へのキャストを自動で行う。127 に 1 を足した 128 は byte に入らず、回りこんで -128。
- アの意味：正しい。
- イの意味：byte に 128 は入らない。
- ウの意味：`b = b + 1;` ならエラーだが、+= は自動でキャストする。
- エの意味：回りこみは例外にならない。
- 出典：オリジナル問題（根拠：JLS 15.26.2（E1 op= E2 is equivalent to E1 = (T) ((E1) op (E2)), where T is the type of E1）／JDK 17 での実行結果）

#### 問 java-02-o25

- 問：コンパイルできる宣言はどれか。
- ア：`Long f = 10;`
- イ：`Integer x = 10L;`
- ウ：`Double h = 1;`
- エ：`long g = Integer.valueOf(5);`
- 正解：エ
- 解説：Integer をアンボクシングして int にし、さらに long へ拡大変換できる。ボクシングでは、基本データ型は対応する 1 つのラッパークラスにしか変わらない。
- アの意味：10 は int で、int は Integer にしかボクシングできない。「int cannot be converted to Long」。
- イの意味：10L は long。「long cannot be converted to Integer」。
- ウの意味：1 は int。「int cannot be converted to Double」。1.0 なら OK。
- エの意味：正しい。5 が入る。
- 出典：オリジナル問題（根拠：JLS 5.2（an unboxing conversion followed by a widening primitive conversion／a boxing conversion）／JLS 5.1.7（From type int to type Integer）／JDK 17 でのコンパイル結果）

#### 問 java-02-o26

- 問：main メソッドの中の次のコードを実行した。結果はどれか。

  ```
  Integer x = null;
  int y = x;
  System.out.println(y);
  ```

- ア：2 行目で NullPointerException が発生する
- イ：0 と表示される
- ウ：null と表示される
- エ：int に null を入れているのでコンパイルエラー
- 正解：ア
- 解説：`int y = x;` は x をアンボクシングする。中身が null なので取り出す値がなく、実行時に NullPointerException になる。
- アの意味：正しい。
- イの意味：null が 0 に変わることはない。
- ウの意味：int は null を持てない。
- エの意味：型の上では Integer から int への代入なので、コンパイルは通る。
- 出典：オリジナル問題（根拠：JLS 5.1.8（If r is null, unboxing conversion throws a NullPointerException）／JDK 17 での実行結果）

### 02-5 var（ローカル変数型推論）

#### 問 java-02-o27

- 問：次の宣言で、a・b・c・d に決まる型の組み合わせはどれか。

  ```
  var a = 1;
  var b = 1L;
  var c = 1.0;
  var d = 'x';
  ```

- ア：Integer・Long・Double・Character
- イ：int・int・float・char
- ウ：int・long・double・char
- エ：long・long・double・String
- 正解：ウ
- 解説：var の型は、初期化の式の型そのもの。1 は int、1L は long、1.0 は double、'x' は char。
- アの意味：var はラッパークラスにボクシングしない（基本データ型のまま）。
- イの意味：L は long、小数の既定は double。
- ウの意味：正しい。
- エの意味：'x' は char のリテラルで、String ではない。
- 出典：オリジナル問題（根拠：JLS 14.4.1（let T be the type of the initializer expression／Example 14.4.1-1 var a = 1; // a has type 'int'）／JLS 3.10）

#### 問 java-02-o28

- 問：main メソッドの中に書いたとき、コンパイルできるものはどれか。
- ア：`var x = (String) null;`
- イ：`var a = null;`
- ウ：`var a = 1, b = 2;`
- エ：`var a = {1, 2};`
- 正解：ア
- 解説：var には、型の決まる初期化が 1 つ必要。キャストした null なら String に決まる。
- アの意味：正しい。x は String 型で、値は null。
- イの意味：null だけでは型が決まらない。「cannot infer type for local variable a」。
- ウの意味：カンマで複数は不可。「'var' is not allowed in a compound declaration」。
- エの意味：配列の { } 初期化は型が決まらない。`var a = new int[] {1, 2};` なら OK。
- 出典：オリジナル問題（根拠：JLS 14.4（It is a compile-time error if the LocalVariableType is var and … More than one VariableDeclarator is listed／The initializer of the VariableDeclarator is an ArrayInitializer）／JLS 14.4.1（It is a compile-time error if T is the null type）／JDK 17 でのコンパイル結果）

#### 問 java-02-o29

- 問：var を使えるのはどこか。
- ア：フィールドの宣言
- イ：for 文の初期化部（`for (var i = 0; i < 3; i++)`）
- ウ：メソッドの引数
- エ：メソッドの戻り値の型
- 正解：イ
- 解説：var はローカル変数のための書き方。for 文・拡張 for 文・try-with-resources の変数もローカル変数なので使える。
- アの意味：「'var' is not allowed here」になった。
- イの意味：正しい。拡張 for 文の `for (var s : args)` も OK。
- ウの意味：同じエラー。
- エの意味：同じエラー。
- 出典：オリジナル問題（根拠：JLS 14.4（A local variable declaration can appear in the following locations: … the header of a basic for statement … the header of an enhanced for statement … the resource specification of a try-with-resources statement）／JDK 17 でのコンパイル結果）

#### 問 java-02-o30

- 問：main メソッドの中の次のコードを実行した。結果はどれか。

  ```
  var a = 1;
  a = 'A';
  System.out.println(a);
  ```

- ア：A と表示される
- イ：var の型が変わるのでコンパイルエラー
- ウ：65 と表示される
- エ：1 と表示される
- 正解：ウ
- 解説：a は int に決まっている。'A' は char で、char から int は拡大変換なので代入でき、65 が入る。型は int のまま。
- アの意味：a の型が char に変わると考えたまちがい。var の型はあとから変わらない。
- イの意味：int に入る値なので代入できる。`a = 2.5;` なら「possible lossy conversion from double to int」でエラー。
- ウの意味：正しい。
- エの意味：2 行目で 65 に変わっている。
- 出典：オリジナル問題（根拠：JLS 14.4.1（The type of the local variable is … T）／JLS 5.1.2（char to int）／JDK 17 での実行結果）
