## 09-1 static フィールド

### まとめ表

| | static フィールド（クラス変数） | インスタンス変数 |
| :-- | :-- | :-- |
| いくつあるか | クラスに 1 つ（インスタンスが 0 個でもある） | インスタンスごとに 1 つ |
| いつできるか | クラスが初期化されたとき | new したとき |
| 書き方 | `クラス名.名前`（`変数.名前` でも同じものを指す） | `変数.名前` |
| ある変数から変えると | 全インスタンスから同じ値が見える | そのインスタンスだけ |

### クラス変数

#### static（すたてぃっく / static modifier）

- 意味：フィールドやメソッドを、インスタンスではなくクラスそのものに結びつける修飾子
- ポイント：static のフィールドとメソッドは、インスタンスを作らなくても `クラス名.名前` で使える。ローカル変数には付けられない（illegal start of expression）。トップレベルクラスにも付けられない
- 例：`static int count;`

#### クラス変数（くらすへんすう / class variable, static field）

- 意味：static を付けたフィールド。クラスに 1 つだけあり、すべてのインスタンスで共有する
- ポイント：どのインスタンスの変数を通して書きかえても、同じ 1 つを変えている。a.s = 5 のあと b.s も C.s も 5。既定値はインスタンス変数と同じ（0・false・null など）
- 例：コンストラクタで `count++` すると、作ったインスタンスの数を数えられる

#### インスタンス変数（いんすたんすへんすう / instance variable）

- 意味：static を付けないフィールド。new のたびに、そのインスタンス用のものが新しくできる
- ポイント：インスタンスがないと使えない。static のメソッドからは、オブジェクトを通さずに使えない（non-static variable … cannot be referenced from a static context）
- 例：`int id;`（オブジェクトごとに別の番号）

#### 定数（ていすう / constant, static final field）

- 意味：`static final` を付けたフィールド。クラスに 1 つで、値を変えられない
- ポイント：宣言か static 初期化子で必ず 1 回代入する。どちらでも代入しないと、JDK 17 では variable X not initialized in the default constructor と表示される。名前は大文字と _ で書く習慣がある
- 例：`static final int MAX = 100;`

## 09-2 static メソッド

### まとめ表

| どこから | 何を | 直接書けるか（JDK 17） |
| :-- | :-- | :-- |
| static メソッド | static のフィールド・メソッド | 書ける |
| static メソッド | インスタンス変数・インスタンスメソッド | non-static … cannot be referenced from a static context |
| static メソッド | this | non-static variable this cannot be referenced from a static context |
| static メソッド | `new A().k` のようにオブジェクトを通す | 書ける |
| インスタンスメソッド | static もインスタンスも | 書ける |

### static コンテキスト

#### クラスメソッド（くらすめそっど / class method, static method）

- 意味：static を付けたメソッド。特定のオブジェクトなしで呼ばれる
- ポイント：`クラス名.メソッド名()` で呼ぶ。同じクラスの中なら名前だけで呼べる。main も static メソッド。ユーティリティ（Math.max など）やファクトリメソッドに使う
- 例：`static int next() { return ++count; }`

#### static コンテキスト（すたてぃっくこんてきすと / static context）

- 意味：static メソッド・static 初期化子・static フィールドの初期化式の中のこと。「今のオブジェクト」がない場所
- ポイント：this と super が使えない。インスタンス変数・インスタンスメソッドを名前だけで使えない。main から同じクラスのインスタンスメソッドを呼ぶなら `new Main().hi()` のようにオブジェクトを作る
- 例：main の中で `hi();`（hi は static なし）→ non-static method hi() cannot be referenced from a static context

#### インスタンスメソッド（いんすたんすめそっど / instance method）

- 意味：static を付けないメソッド。オブジェクトを通して呼び、その中では this が使える
- ポイント：インスタンスメソッドからは static のフィールド・メソッドも名前だけで使える（逆はできない）。`this.s` のように this を通して static フィールドを書いてもよい
- 例：`int sum() { return n + s; }`

#### 参照を通した static の呼び出し（さんしょうをとおしたすたてぃっくのよびだし / static member via reference）

- 意味：`変数.static のメンバー` と書いたときの動き。変数の中身ではなく、変数の宣言された型のクラスのメンバーが使われる
- ポイント：変数が null でも NullPointerException にならない（static はオブジェクトを使わないため）。書けるが、読みにくいのですすめられない
- 例：`C c = null; c.s` は C.s の値

## 09-3 static 初期化子

### まとめ表

| 起きること | 順番 |
| :-- | :-- |
| クラスの初期化（1 回だけ） | static フィールドの初期化式と static 初期化子を上から順に |
| インスタンスの作成（new のたび） | インスタンスの初期化式と初期化子を上から順に → コンストラクタ本体 |
| main のあるクラス | main を実行する前に初期化される |
| ほかのクラス | はじめて new・static メソッドの呼び出し・static フィールドの使用をしたとき |

### クラスの初期化

#### static 初期化子（すたてぃっくしょきかし / static initializer）

- 意味：クラスの中に `static { … }` と書いたブロック。クラスが初期化されるとき 1 回だけ実行される
- ポイント：インスタンスを何個作っても 1 回だけ。インスタンス初期化子（#08）やコンストラクタより先。複数あれば書いた順。中で this やインスタンス変数は使えない
- 例：`static { System.out.print("s1 "); }`

#### クラスの初期化（くらすのしょきか / class initialization）

- 意味：static フィールドの初期化式と static 初期化子を実行して、クラスを使える状態にすること
- ポイント：変数を宣言しただけ（`A a = null;`）では起きない。はじめて new する・static メソッドを呼ぶ・static フィールドを使うなどの直前に 1 回だけ起きる
- 例：`A a = null; print("1 "); A.f();` → 1 A-init f

#### static の初期化の順番（すたてぃっくのしょきかのじゅんばん / order of static initialization）

- 意味：static フィールドの初期化式と static 初期化子を、ソースに書いた順（上から）に実行する決まり
- ポイント：インスタンスの初期化とは別。まずクラスの初期化（1 回）、そのあと new のたびにインスタンスの初期化。`static int x; static { x = 5; } static int y = x * 2;` なら y は 10
- 例：`m s1 s2 i c i c`（static は 1 回、インスタンスの初期化は 2 回）

#### 不正な前方参照（ふせいなぜんぽうさんしょう / illegal forward reference）

- 意味：フィールドの初期化式で、まだ宣言していない（下に書いた）フィールドを名前だけで使うこと
- ポイント：`static int a = b + 1; static int b = 2;` は illegal forward reference。`A.b + 1` のようにクラス名を付けるとコンパイルでき、そのときの b は既定値 0 なので a は 1 になる
- 例：上から順に初期化されることを確かめる問題で出る

## 09-4 アクセス修飾子

### まとめ表

| 修飾子 | 同じクラス | 同じパッケージ | 別パッケージのサブクラス | どこからでも |
| :-- | :-- | :-- | :-- | :-- |
| public | ○ | ○ | ○ | ○ |
| protected | ○ | ○ | ○（継承した自分のメンバーとして） | × |
| なし（パッケージアクセス） | ○ | ○ | × | × |
| private | ○ | × | × | × |

### 4 つのアクセスレベル

#### アクセス修飾子（あくせすしゅうしょくし / access modifier）

- 意味：クラスやメンバーを、どこから使えるかを決める修飾子。public・protected・private の 3 つと、何も付けない場合（パッケージアクセス）で 4 段階
- ポイント：1 つのメンバーに付けられるのは 1 つだけ（public private は illegal combination of modifiers）。ローカル変数には付けられない（illegal start of expression。final は付けられる）
- 例：`private int balance;`

#### public（ぱぶりっく / public）

- 意味：どこからでも使えるアクセスレベル
- ポイント：トップレベルクラスに付けられるのは public か、何も付けないかのどちらか。public クラスはファイル名と同じ名前（#01）
- 例：`public int pub = 1;`

#### protected（ぷろてくてっど / protected）

- 意味：同じパッケージと、別パッケージのサブクラスから使えるアクセスレベル
- ポイント：別パッケージのサブクラスで使えるのは「自分（とサブクラスの型）を通したアクセス」だけ。`pro`・`this.pro`・`b.pro`（b はサブクラス型）は OK、`a.pro`（a は親クラス A の型）は pro has protected access in A。サブクラスでないクラスからは使えない
- 例：`protected int pro = 2;`

#### パッケージアクセス（ぱっけーじあくせす / package access, package-private）

- 意味：アクセス修飾子を何も付けないときのアクセスレベル。同じパッケージの中だけで使える
- ポイント：別パッケージからは、サブクラスでも使えない（def is not public in A; cannot be accessed from outside package）。default という修飾子を書くわけではない
- 例：`int def = 3;`

#### private（ぷらいべーと / private）

- 意味：宣言したクラスの中だけで使えるアクセスレベル
- ポイント：同じファイルの別のクラスからも使えない（n has private access in A）。同じクラスの中なら、別のインスタンスの private フィールド（`o.n`）も使える。トップレベルクラスには付けられない（modifier private not allowed here）
- 例：`private int n;`

#### トップレベルクラスの修飾子（とっぷれべるくらすのしゅうしょくし / top level class modifiers）

- 意味：ファイルの一番外側に書くクラスに付けられるアクセス修飾子
- ポイント：public か、何も付けない（パッケージアクセス）だけ。private・protected は modifier … not allowed here。クラスの中に書くクラス（メンバークラス）には 4 つとも付けられる
- 例：`class Helper { }`（同じパッケージだけで使う）

## 09-5 カプセル化と不変オブジェクト

### まとめ表

| 不変クラスの作り方（Java Tutorials の手順） | ねらい |
| :-- | :-- |
| setter（フィールドを変えるメソッド）を作らない | 外から変えさせない |
| すべてのフィールドを private final にする | 直接の書きかえと再代入を防ぐ |
| クラスを final にする（またはコンストラクタを private にしてファクトリメソッドで作る） | サブクラスに変えさせない |
| 変えられるオブジェクト（配列など）はコピーを保存し、コピーを返す | 外から中身を変えさせない |

### カプセル化

#### カプセル化（かぷせるか / encapsulation）

- 意味：フィールドを private にして隠し、決めたメソッドを通してだけ読み書きさせる設計
- ポイント：メソッドの中で値を確かめられる（マイナスの入金をはじくなど）。Java Tutorials は「意味のある範囲でいちばん制限の強いアクセスレベルを使う。理由がなければ private」とすすめている
- 例：`private int balance; void deposit(int x) { if (x > 0) balance += x; }`

#### getter と setter（げったーとせったー / accessor and mutator methods）

- 意味：private フィールドの値を返すメソッド（getXxx）と、値を設定するメソッド（setXxx）
- ポイント：名前の付け方は習慣で、文法の決まりではない。不変オブジェクトには setter を作らない
- 例：`int getBalance() { return balance; }`

#### private コンストラクタ（ぷらいべーとこんすとらくた / private constructor）

- 意味：private を付けたコンストラクタ。クラスの外から new できなくなる
- ポイント：外からの `new S()` は S() has private access in S。クラスの中の static メソッド（ファクトリメソッド）からは new できる。インスタンスの作り方を決めたいときに使う
- 例：`private S() { } static S create() { return new S(); }`

#### 不変オブジェクト（ふへんおぶじぇくと / immutable object）

- 意味：作ったあと状態（フィールドの値）が変わらないオブジェクト。String が代表例
- ポイント：final のフィールドでも、配列やリストを指していれば中身は変えられる（final は再代入を禁じるだけ）。だからコンストラクタでコピーを保存し、getter でもコピーを返す（防御的コピー）
- 例：`P(int[] d) { data = d.clone(); } int[] get() { return data.clone(); }`

#### final の参照フィールド（ふぁいなるのさんしょうふぃーるど / final reference field）

- 意味：final を付けた参照型のフィールド。別のオブジェクトを代入できない
- ポイント：指しているオブジェクトの中身は変えられる。`list.add("x")` は OK、`list = new ArrayList<>()` は cannot assign a value to final variable list
- 例：`private final List<String> list = new ArrayList<>();`

### 09-1 static フィールド

#### 問 java-09-o01

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  class C {
    static int count;
    int id;
    C() { count++; id = count; }
  }
  public class Main {
    public static void main(String[] args) {
      C c1 = new C();
      C c2 = new C();
      C c3 = new C();
      System.out.println(C.count + " " + c1.id + " " + c3.id + " " + c1.count);
    }
  }
  ```

- ア：3 1 3 1
- イ：1 1 1 1
- ウ：3 3 3 3
- エ：3 1 3 3
- 正解：エ
- 解説：count は static なのでクラスに 1 つだけで、new のたびに同じ count が増えて 3 になる。id はインスタンスごとにあり、作ったときの count（1・2・3）が入る。c1.count は C.count と同じものなので 3。
- アの意味：c1.count を c1 を作ったときの値と考えたまちがい。static フィールドは 1 つなので今の値 3。
- イの意味：count がインスタンスごとにあると考えたまちがい。
- ウの意味：id も共有されると考えたまちがい。id は static でない。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：JLS 8.3.1.1（If a field is declared static, there exists exactly one incarnation of the field, no matter how many instances (possibly zero) of the class may eventually be created）／JDK 17 での実行結果）

#### 問 java-09-o02

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  class C { static int s; int n; }
  public class Main {
    public static void main(String[] args) {
      C a = new C();
      C b = new C();
      a.s = 5;
      a.n = 5;
      System.out.println(b.s + " " + b.n + " " + C.s);
    }
  }
  ```

- ア：0 0 5
- イ：5 5 5
- ウ：5 0 5
- エ：a.s = 5 の行でコンパイルエラーになる
- 正解：ウ
- 解説：s は static なので、a.s・b.s・C.s はどれも同じ 1 つの変数。a を通して 5 にすれば、b.s も C.s も 5。n はインスタンス変数なので、b.n は既定値 0 のまま。
- アの意味：a.s が a 専用の変数だと考えたまちがい。
- イの意味：n も共有されると考えたまちがい。
- ウの意味：正しい。
- エの意味：static フィールドは変数を通しても書ける（すすめられないが、コンパイルできる）。
- 出典：オリジナル問題（根拠：JLS 8.3.1.1／The Java Tutorials「Understanding Class Members」（Every instance of the class shares a class variable, which is in one fixed location in memory）／JDK 17 での実行結果）

#### 問 java-09-o03

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  class C {
    static int count;
    static int next() { return ++count; }
  }
  public class Main {
    public static void main(String[] args) {
      C.next(); C.next();
      C c = new C();
      c.count += 10;
      System.out.println(C.next());
    }
  }
  ```

- ア：3
- イ：11
- ウ：13
- エ：1
- 正解：ウ
- 解説：next() を 2 回呼んで count は 2。c.count += 10 は同じ static の count を 12 にする。最後の next() で 13 になり、それを返す。new してもクラス変数は 0 に戻らない。
- アの意味：c.count がインスタンスごとの別の変数と考えたまちがい。
- イの意味：new C() で count が 0 に戻ると考えたまちがい。
- ウの意味：正しい。
- エの意味：static メソッドの呼び出しのたびに初期化されると考えたまちがい。
- 出典：オリジナル問題（根拠：JLS 8.3.1.1・8.4.3.2（A class method is always invoked without reference to a particular object）／JDK 17 での実行結果）

#### 問 java-09-o04

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  public class Main {
    static int count;
    int n;
    public static void main(String[] args) {
      count++;
      Main m = new Main();
      m.n++;
      System.out.println(count + " " + m.n);
    }
  }
  ```

- ア：1 1
- イ：main の count++ の行でコンパイルエラーになる
- ウ：m.n++ の行でコンパイルエラーになる
- エ：0 1
- 正解：ア
- 解説：main は static メソッドなので、同じクラスの static フィールド count は名前だけで使える。インスタンス変数 n は、オブジェクト m を通せば使える。どちらも既定値 0 から 1 になる。
- アの意味：正しい。
- イの意味：static メソッドから static フィールドは名前だけで使える。
- ウの意味：オブジェクトを通しているので、static メソッドの中でもインスタンス変数を使える。
- エの意味：count++ を見落としたまちがい。
- 出典：オリジナル問題（根拠：The Java Tutorials「Understanding Class Members」（Class methods cannot access instance variables or instance methods directly—they must use an object reference）／JDK 17 での実行結果）

### 09-2 static メソッド

#### 問 java-09-o05

#### 問 java-09-o22

- 問：main メソッドの中に書いたとき、コンパイルできるものはどれか。

- エの意味：public もアクセス修飾子なので書けない。
- 出典：オリジナル問題（根拠：JLS 14.4（LocalVariableDeclaration: {VariableModifier} LocalVariableType VariableDeclaratorList／VariableModifier: Annotation | final）／JDK 17 でのコンパイル結果）

### 09-5 カプセル化と不変オブジェクト

#### 問 java-09-o26

- 問：次のコードを実行した。表示されるものはどれか。

  class Account {

- イの意味：-50 を 50 として足すと考えたまちがい。
- ウの意味：正しい。
- エの意味：クラスの中のメソッドなら private のフィールドの値を返せる。
- 出典：オリジナル問題（根拠：The Java Tutorials「Controlling Access to Members of a Class」（Use private unless you have a good reason not to）／JDK 17 での実行結果）

#### 問 java-09-o27

- 問：次のコードをコンパイルした。結果として正しいものはどれか。

  class S {

#### 問 java-09-o28

- 問：次のコードを実行した。表示されるものはどれか。

  ```
  final class P {
    private final int[] data;
    P(int[] d) { data = d; }
    int[] get() { return data; }
  }
  public class Main {
    public static void main(String[] args) {
      int[] src = {1, 2};
      P p = new P(src);
      src[0] = 9;
      p.get()[1] = 9;
      System.out.println(p.get()[0] + " " + p.get()[1]);
    }
  }
  ```

- ア：1 2
- イ：9 2
- ウ：9 9
- エ：p.get()[1] = 9 の行でコンパイルエラーになる（final の配列は変えられない）
- 正解：ウ
- 解説：コンストラクタは渡された配列の参照をそのまま保存し、get() もその参照を返す。src も get() の戻り値も P の中と同じ配列なので、外から中身を変えられる。final は data に別の配列を代入できないだけで、中身の変更は防がない。
- アの意味：private final にすれば中身も守られると考えたまちがい。コンストラクタで d.clone()、get() で data.clone() を使えば 1 2 になる。
- イの意味：get() の戻り値への書きこみが反映されないと考えたまちがい。
- ウの意味：正しい。
- エの意味：final の配列変数でも、要素への代入はできる。
- 出典：オリジナル問題（根拠：The Java Tutorials「A Strategy for Defining Immutable Objects」（Never store references to external, mutable objects passed to the constructor; if necessary, create copies）／JDK 17 での実行結果）

#### 問 java-09-o29

- 問：不変（イミュータブル）なクラスを作る方法として正しいものはどれか。
- ア：フィールドを public final にすれば、配列のフィールドの中身も変えられなくなる
- イ：クラスに final を付ければ、フィールドもすべて自動で final になる
- ウ：すべてのフィールドを private final にし、フィールドを変えるメソッド（setter）を作らない

- 正解：ウ

#### 問 java-09-o30

- 問：次のクラスをコンパイルした。結果として正しいものはどれか（java.util.* は import 済み）。
