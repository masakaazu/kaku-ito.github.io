## 12-1 インタフェースの基本

### まとめ表

| インタフェースの中に書いたもの | 自動で付く修飾子（JDK 17） | 注意 |
| :-- | :-- | :-- |
| `int N = 10;` | public static final | 値の代入は cannot assign a value to final variable N。初期値なしは = expected |
| `void m();` | public abstract | 実装するクラスで public を付けないと cannot implement … weaker access privileges |
| `default void d() { … }` | public | 中身が必要 |
| `static void s() { … }` | public | インタフェース名.s() で呼ぶ |
| `private void p() { … }` | なし（private） | インタフェースの中だけで使う |
| `protected void m();`・`final void m();` | — | modifier protected（final） not allowed here |

### インタフェースのしくみ

#### インタフェース（いんたふぇーす / interface）

- 意味：クラスが「どんなメソッドを持つか」の約束を決める型。interface で宣言し、クラスが implements で実装する
- ポイント：new でインスタンスを作れない（I is abstract; cannot be instantiated）。変数の型には使えるので、実装したクラスのオブジェクトを入れて使う。インタフェースは暗黙に abstract
- 例：`interface Flyer { String fly(); }`

#### implements（いんぷりめんつ / implements clause）

- 意味：クラスがインタフェースを実装することを宣言するキーワード
- ポイント：コンマで区切って複数のインタフェースを実装できる（クラスの extends は 1 つだけ）。extends と一緒に書くときは `class C extends P implements I` の順
- 例：`class Duck implements Flyer, Swimmer { … }`

#### インタフェースの継承（いんたふぇーすのけいしょう / superinterfaces）

- 意味：インタフェースが extends でほかのインタフェースを継承すること
- ポイント：インタフェースどうしは extends で複数を継承できる。インタフェースはクラスを継承できず、implements も書けない
- 例：`interface AB extends A, B { String ab(); }`

#### 抽象メソッド（インタフェース）（ちゅうしょうめそっど / interface abstract method）

- 意味：インタフェースに中身なしで書いたメソッド。private・default・static のどれも付けなければ、自動で public abstract になる
- ポイント：実装するクラスは public で書かなければならない（修飾子なしだと m() in C cannot implement m() in I / attempting to assign weaker access privileges; was public）。すべて実装しない具象クラスは not abstract and does not override abstract method。中身 { } を書くと interface abstract methods cannot have body
- 例：`void m();`（= `public abstract void m();`）

#### インタフェースの定数（いんたふぇーすのていすう / interface field）

- 意味：インタフェースに書いたフィールド。自動で public static final になる定数
- ポイント：初期値が必須（int N; は = expected）。値は変えられない。I.N のほか、実装したクラス名や、その型の変数からも読める
- 例：`int N = 10;`（= `public static final int N = 10;`）

#### インタフェース型へのキャスト（いんたふぇーすがたへのきゃすと / cast to interface type）

- 意味：オブジェクトをインタフェース型に変換すること
- ポイント：final でないクラスの変数は、そのクラスがインタフェースを実装していなくてもキャストのコンパイルが通る（サブクラスが実装しているかもしれないため）。中身が実装していなければ実行時に ClassCastException。final クラスで実装していなければコンパイルエラー
- 例：`Flyer f = (Flyer) dog;`（Dog は final でない → 実行時に例外）

## 12-2 default・static・private メソッド

### まとめ表

| 種類 | 中身 | 呼び方 | 実装クラスに継承されるか |
| :-- | :-- | :-- | :-- |
| 抽象メソッド | なし | 実装クラスのオブジェクトで | 継承される（実装が必要） |
| default メソッド | あり | 実装クラスのオブジェクトで | 継承される（オーバーライドも可） |
| static メソッド | あり | `インタフェース名.s()` だけ | 継承されない（`C.s()` は cannot find symbol、`x.s()` は illegal static interface method call） |
| private メソッド | あり | 同じインタフェースの中だけ | 継承されない |

### default メソッド

#### default メソッド（でふぉるとめそっど / default method）

- 意味：インタフェースに default を付けて中身を書いた、インスタンスメソッド。実装クラスがオーバーライドしなければ、この中身が使われる
- ポイント：自動で public。中身 { } が必須（ないと missing method body, or declare abstract）。Object の public メソッド（toString・equals・hashCode）と同じものは default にできない（default method toString in interface I overrides a member of java.lang.Object）
- 例：`default String greet() { return "Hello, " + name(); }`

#### default メソッドの衝突（でふぉるとめそっどのしょうとつ / conflicting default methods）

- 意味：2 つのインタフェースから同じシグネチャの default メソッドを受け継ぐと、どちらを使うか決められずコンパイルエラーになること
- ポイント：メッセージは types I and J are incompatible;（class C inherits unrelated defaults for hi() from types I and J）。クラスでそのメソッドをオーバーライドすれば解決する。一方のインタフェースがもう一方を継承していれば、より具体的な（子の）インタフェースのものが使われる
- 例：`class C implements I, J { public String hi() { … } }`

#### インタフェース名.super（いんたふぇーすめいすーぱー / InterfaceName.super.method()）

- 意味：オーバーライドしたメソッドの中から、直接実装しているインタフェースの default メソッドを呼ぶ書き方
- ポイント：インタフェースの default を呼ぶのに `super.hi()` と書くと cannot find symbol（super はスーパークラスを指す）。I.super.hi() と書く
- 例：`return I.super.hi() + J.super.hi();`

#### クラス優先の決まり（くらすゆうせんのきまり / class method wins）

- 意味：スーパークラスから継承した具体的なメソッドと、インタフェースの default メソッドが同じシグネチャなら、クラスのほうが使われるという決まり
- ポイント：このときスーパークラスのメソッドがインタフェースのメソッドを実装する扱いになるので、public でないと hi() in P cannot implement hi() in I（weaker access privileges）のコンパイルエラー
- 例：`class C extends P implements I { }` → P の hi()

### static メソッドと private メソッド

#### static メソッド（インタフェース）（すたてぃっくめそっど / static interface method）

- 意味：インタフェースに static を付けて中身を書いたメソッド。特定のオブジェクトなしで、インタフェース名で呼ぶ
- ポイント：実装クラスには継承されない。C.s() は cannot find symbol、インタフェース型の変数 x で x.s() は illegal static interface method call。クラスの static メソッドは変数経由でも呼べるのと対照的
- 例：`I.s()`

#### private メソッド（インタフェース）（ぷらいべーとめそっど / private interface method）

- 意味：インタフェースの中だけで使う、中身のあるメソッド。Java 9 から書ける。default メソッドどうしの共通処理をまとめるのに使う
- ポイント：実装クラスやほかのクラスからは呼べない（cannot find symbol）。private と default、private と abstract は一緒に付けられない。private static も書ける
- 例：`private void log(String level, String m) { … }`

#### private static メソッド（ぷらいべーとすたてぃっくめそっど / private static interface method）

- 意味：インタフェースの中だけで使う static メソッド。static メソッドの共通処理をまとめるのに使う
- ポイント：static メソッドから private のインスタンスメソッド（static でない private）は呼べない（non-static method p() cannot be referenced from a static context）。private static なら呼べる
- 例：`private static int helper(int x) { return x + 1; }`

#### 修飾子の組み合わせ（しゅうしょくしのくみあわせ / interface method modifiers）

- 意味：インタフェースのメソッドに付けられる修飾子の決まり
- ポイント：使えるアクセス修飾子は public と private だけ。abstract・default・static のうち 2 つは一緒に付けられない（illegal combination of modifiers: static and default）。protected・final は modifier … not allowed here
- 例：`private static`（OK）・`static default`（NG）

## 12-3 シール・クラス

### まとめ表

| 書き方 | 結果（JDK 17） |
| :-- | :-- |
| permits に書いたサブクラスに final・sealed・non-sealed のどれもない | sealed, non-sealed or final modifiers expected |
| permits に書いていないクラスが extends | class is not allowed to extend sealed class: Shape (as it is not listed in its permits clause) |
| sealed のないクラスに permits | invalid permits clause（(class must be sealed)） |
| permits に書いたクラスが extends していない | invalid permits clause（(subclass Circle must extend sealed class)） |
| permits を省略し、同じファイルにサブクラス | OK（同じファイルのサブクラスが許可される） |
| サブクラスが 1 つもない sealed クラス | sealed class must have subclasses |
| sealed final・final non-sealed | illegal combination of modifiers |
| sealed インタフェースを継承するインタフェースに何も付けない | sealed or non-sealed modifiers expected |

### シール・クラスのしくみ

#### シール・クラス（しーるくらす / sealed class）

- 意味：sealed を付け、継承してよい直接のサブクラスを permits で限定したクラス。Java 17 で正式になった
- ポイント：permits にないクラスが継承するとコンパイルエラー。シール・クラス自体は abstract でなければ new できる。final と一緒には付けられない
- 例：`sealed class Shape permits Circle, Square { }`

#### permits（ぱーみっつ / permits clause）

- 意味：シール・クラス（シール・インタフェース）を直接継承してよいクラスを並べる句
- ポイント：sealed がないのに書くと invalid permits clause。書いたクラスは実際にそのクラスを直接継承していなければならない。同じクラスを 2 回書けない。同じファイル（コンパイル単位）にサブクラスを書くなら省略できる。名前のないモジュールでは、許可するクラスは同じパッケージに置く
- 例：`permits Circle, Square, Poly`

#### 許可されたサブクラスの 3 つの修飾子（きょかされたさぶくらすのしゅうしょくし / final, sealed, non-sealed）

- 意味：シール・クラスを直接継承するクラスは、final・sealed・non-sealed のどれか 1 つを必ず付ける、という決まり
- ポイント：final＝ここで止める、sealed＝さらに permits で限定する、non-sealed＝ここから先はだれでも継承できる。付けないと sealed, non-sealed or final modifiers expected。レコードと enum は暗黙に final なので付けなくてよい
- 例：`final class Circle extends Shape { }`

#### non-sealed（のんしーるど / non-sealed modifier）

- 意味：シール・クラスのサブクラスに付けて、そこから下はふつうのクラスと同じく自由に継承できるようにする修飾子
- ポイント：親が sealed でないクラスに付けると non-sealed modifier not allowed here。final と一緒には付けられない。ハイフンの入った唯一のキーワード
- 例：`non-sealed class Square extends Shape { }` → `class Big extends Square { }` は OK

#### シール・インタフェース（しーるいんたふぇーす / sealed interface）

- 意味：sealed を付け、実装・継承してよいクラスとインタフェースを permits で限定したインタフェース
- ポイント：実装するクラスは final・sealed・non-sealed のどれか、継承するインタフェースは sealed か non-sealed（インタフェースに final は付けられない）。レコードは暗黙に final なのでそのまま実装できる
- 例：`sealed interface Expr permits Num, Add { }`

#### シール・クラスとパターン（しーるくらすとぱたーん / sealed hierarchy with instanceof）

- 意味：シール・クラスで種類を限定し、instanceof のパターン・マッチングで種類ごとに処理を分ける書き方
- ポイント：Java 17 では if と instanceof で分ける。switch のパターン（すべての種類を網羅したかコンパイラが調べる）は Java 17 ではプレビューで、Java 21 から正式
- 例：`if (e instanceof Num n) return n.v();`

### 12-1 インタフェースの基本

#### 問 java-12-o01

- 問：次のプログラムを実行した。表示されるものはどれか。

  ```
  interface I {
    int N = 10;
  }
  class C implements I { }
  public class Main {
    public static void main(String[] args) {
      I x = new C();
      System.out.println(I.N + " " + C.N + " " + x.N);
    }
  }
  ```

- ア：C.N の部分でコンパイルエラーになる
- イ：x.N の部分でコンパイルエラーになる
- ウ：10 0 0
- エ：10 10 10
- 正解：エ
- 解説：インタフェースのフィールドは自動で public static final の定数になる。実装したクラス C にも継承されるので、I.N・C.N・x.N のどれでも 10 を読める。
- アの意味：インタフェースの定数は実装クラスに継承されるので、C.N で読める。
- イの意味：static のフィールドは、その型の変数からも読める（すすめられない書き方だが、エラーではない）。
- ウの意味：インスタンスごとの変数ではなく、1 つの定数なので、どこから読んでも 10。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：JLS 9.3（Every field declaration in the body of an interface delaration is implicitly public, static, and final）／JDK 17 での実行結果）

#### 問 java-12-o02

- 問：次のプログラムをコンパイルした。結果として正しいものはどれか。

  ```
  interface I {
    int N = 10;
  }
  public class Main implements I {
    public static void main(String[] args) {
      System.out.println(I.N + " " + Main.N + " " + new Main().N);
      I.N = 20;
    }
  }
  ```

- ア：I.N = 20 の行で cannot assign a value to final variable N のコンパイルエラーになる
- イ：コンパイルでき、10 10 10 と表示される
- ウ：int N = 10 の行で、インタフェースにフィールドは書けないというコンパイルエラーになる
- エ：コンパイルでき、10 10 10 と表示されたあと、I.N = 20 で例外がスローされる
- 正解：ア
- 解説：インタフェースのフィールドは自動で final になるので、あとから値を代入するとコンパイルエラーになる。final と書いていなくても同じ。
- アの意味：正しい。
- イの意味：代入の行があるので、コンパイルの段階で止まる。
- ウの意味：インタフェースには定数としてフィールドを書ける。
- エの意味：final への代入はコンパイル時に見つかる。
- 出典：オリジナル問題（根拠：JLS 9.3（Every field declaration in the body of an interface delaration is implicitly public, static, and final）／JDK 17 でのコンパイル結果）

#### 問 java-12-o03

- 問：次のプログラムをコンパイルした。結果として正しいものはどれか。

  ```
  interface I {
    void m();
  }
  class C implements I {
    void m() { }
  }
  public class Main {
    public static void main(String[] args) { }
  }
  ```

- ア：コンパイルできる（I の m() も C の m() も修飾子なしで同じアクセス）
- イ：class C の行で C is not abstract and does not override abstract method m() in I のコンパイルエラーになる
- ウ：void m(); の行で、abstract を付けていないというコンパイルエラーになる
- エ：C の m() の行で m() in C cannot implement m() in I（attempting to assign weaker access privileges; was public）のコンパイルエラーになる
- 正解：エ
- 解説：インタフェースの抽象メソッドは、何も書かなくても public abstract になる。実装する側を修飾子なし（パッケージアクセス）にするとアクセスを狭めることになるので、コンパイルエラー。public void m() と書く。
- アの意味：インタフェースのメソッドの「修飾子なし」は public の意味で、クラスの「修飾子なし」とはちがう。
- イの意味：同じシグネチャの m() を書いているので、実装しようとはしている。エラーの理由はアクセス。
- ウの意味：インタフェースのメソッドには abstract が自動で付く。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：JLS 9.4（If no access modifier is given, the method is implicitly public）・8.4.8.3（The access modifier of an overriding or hiding method must provide at least as much access as the overridden or hidden method）／JDK 17 でのコンパイル結果）

#### 問 java-12-o04

- 問：次のプログラムを実行した。表示されるものはどれか。

  ```
  interface Flyer { String fly(); }
  interface Swimmer { String swim(); }
  class Duck implements Flyer, Swimmer {
    public String fly() { return "fly"; }
    public String swim() { return "swim"; }
  }
  public class Main {
    public static void main(String[] args) {
      Flyer f = new Duck();
      Swimmer s = (Swimmer) f;
      System.out.println(f.fly() + " " + s.swim() + " " + (f instanceof Swimmer));
    }
  }
  ```

- ア：fly swim false
- イ：Swimmer s = (Swimmer) f の行で incompatible types のコンパイルエラーになる
- ウ：Swimmer s = (Swimmer) f の行で ClassCastException がスローされる
- エ：fly swim true
- 正解：エ
- 解説：Duck は Flyer と Swimmer の両方を実装しているので、Flyer 型の変数の中身（Duck）は Swimmer にもキャストできる。instanceof Swimmer も true。
- アの意味：中身の Duck は Swimmer を実装しているので true。
- イの意味：インタフェースどうしのキャストは、両方を実装したクラスがありうるのでコンパイルが通る。
- ウの意味：中身が Swimmer を実装しているので、キャストは成功する。
- エの意味：正しい。
- 出典：オリジナル問題（根拠：JLS 8.1.5（The optional implements clause in a class declaration specifies the direct superinterface types of the class being declared）・5.1.6.3（If T is an interface type, then R must implement interface T (§8.1.5), or a ClassCastException is thrown）／JDK 17 での実行結果）

#### 問 java-12-o05

- 問：次のプログラムをコンパイルした。結果として正しいものはどれか。

  ```
  interface I { void m(); }
  public class Main {
    public static void main(String[] args) {
      I x = new I();
    }
  }
  ```

- ア：コンパイルでき、実行しても何も起きない
- イ：I x の部分で、インタフェースは変数の型に使えないというコンパイルエラーになる
- ウ：new I() の行で I is abstract; cannot be instantiated のコンパイルエラーになる

- 正解：ウ
