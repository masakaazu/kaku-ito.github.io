## 04-1 配列の宣言と生成

### まとめ表

| 書き方 | 結果 | 理由 |
| :-- | :-- | :-- |
| `int[] a = new int[3];` | {0, 0, 0} | 要素は既定値で埋まる（数は 0、boolean は false、参照は null） |
| `int[] a = {1, 2, 3};` | 長さ 3 | 配列初期化子。宣言と同時のときだけ書ける |
| `a = new int[]{1, 2, 3};` | OK | 宣言のあとで作り直すときは new int[] を付ける |
| `new int[3]{1, 2, 3}` | コンパイルエラー | 長さと初期化子は同時に書けない |
| `int[] a, b[];` | a は int[]、b は int[][] | 変数名のあとの [] はその変数だけに付く |
| `a[3]`（長さ 3） | ArrayIndexOutOfBoundsException | 添字は 0〜length−1 |
| `new int[-1]` | NegativeArraySizeException | 長さが負なのは実行時に分かる |
| `a.length` | 要素数 | フィールドなので () を付けない。String は length() |

### 配列のしくみ

#### 配列（はいれつ / array）

- 意味：同じ型の値を決まった数だけ並べて持つオブジェクト。1 つの変数名と番号で各要素を使う
- ポイント：配列はオブジェクトで、Object 型の変数にも入る（JLS 10）。一度作ると長さは変わらない（JLS 10.2：Once an array object is created, its length never changes）。長さを変えたいときは ArrayList を使う
- 例：`int[] scores = new int[5];`

#### 要素と添字（ようそとそえじ / component, index）

- 意味：配列の中の 1 つ 1 つの変数が要素。要素を指す番号が添字（インデックス）
- ポイント：添字は 0 から始まり、長さ n なら 0〜n−1（JLS 10.4：All arrays are 0-origin）。添字に使えるのは int（byte・short・char は int に広げられる）。long はコンパイルエラー
- 例：`a[0]` は先頭、`a[a.length - 1]` は最後の要素

#### 配列型の宣言（はいれつがたのせんげん / array type declaration）

- 意味：`int[] a;` のように、要素の型のあとに [] を付けて配列の変数を宣言すること。`int a[];` とも書ける
- ポイント：宣言だけでは配列は作られない（JLS 10.2）。`int[] a, b[];` は a が int[]、b が int[][]。`int a, b[];` は a が int、b が int[]。型の後ろの [] は全部の変数に、名前の後ろの [] はその変数だけに付く
- 例：`int a, b[], c[][];` は `int a; int[] b; int[][] c;` と同じ（JLS 例 10.2-2）

#### 参照の代入（さんしょうのだいにゅう / reference assignment）

- 意味：配列の変数が持つのは配列そのものではなく、配列オブジェクトへの参照。`b = a;` は同じ配列を指すようにするだけ
- ポイント：b を通して要素を変えると a からも見える。コピーしたいときは clone や Arrays.copyOf を使う
- 例：`int[] b = a; b[0] = 9;` のあと a[0] も 9

### 配列を作る

#### 配列生成式（はいれつせいせいしき / array creation expression）

- 意味：`new int[3]` のように、new と要素の型と長さを書いて配列を作る式
- ポイント：作った配列の要素は既定値で埋まる。長さは int 以下の整数型（long はコンパイルエラー）。0 も可（空の配列）。多次元では最初の [] に長さが必要で、`new int[][3]` はコンパイルエラー
- 例：`new String[2]` → {null, null}

#### 既定値（きていち / default value）

- 意味：配列の要素やフィールドに、値を入れる前から入っている初めの値
- ポイント：int などの整数は 0、double は 0.0、boolean は false、char は '\u0000'（コード 0）、参照型は null（JLS 4.12.5）。ローカル変数には既定値がない（使う前に代入しないとコンパイルエラー）のと区別する
- 例：`new boolean[1][0]` は false

#### 配列初期化子（はいれつしょきかし / array initializer）

- 意味：`{1, 2, 3}` のように、波かっこの中に要素を並べて配列を作り、値も入れる書き方
- ポイント：長さは並べた数で決まる。最後のカンマは書いてもよい（`{1, 2, 3,}` は長さ 3）。単独で使えるのは宣言と同時のときだけ。`a = {1, 2};` はコンパイルエラー。`var b = {1, 2};` も型が決まらずコンパイルエラー（cannot infer type）
- 例：`int[][] m = {{1, 2}, {3}};`

#### 初期化子つきの配列生成（しょきかしつきのはいれつせいせい / array creation with initializer）

- 意味：`new int[]{1, 2, 3}` のように、new と初期化子をいっしょに書く形。宣言のあとの代入やメソッドの引数にも使える
- ポイント：[] の中に長さを書くとコンパイルエラー（array creation with both dimension expression and initialization is illegal）。`var a = new int[]{1, 2};` は OK
- 例：`a = new int[]{4, 5};`

#### length（れんぐす / length）

- 意味：配列の要素数を表す public final なフィールド（JLS 10.7）
- ポイント：フィールドなので `a.length` と書き、かっこは付けない。`a.length()` や `a.size()` はコンパイルエラー（cannot find symbol）。String は `s.length()`、ArrayList は `list.size()`
- 例：`for (int i = 0; i < a.length; i++)`

### 配列の例外

#### ArrayIndexOutOfBoundsException（あれいいんでっくすあうとおぶばうんずえくせぷしょん）

- 意味：配列の範囲外の添字（負、または length 以上）で要素を使ったときに実行時にスローされる例外
- ポイント：コンパイルは通り、実行時に分かる（JLS 10.4：All array accesses are checked at run time）。表示は「Index 3 out of bounds for length 3」の形。String の範囲外は StringIndexOutOfBoundsException、ArrayList は IndexOutOfBoundsException
- 例：長さ 3 の a に `a[3]`
- 語の意味：Array（配列）＋Index（添字）＋Out Of Bounds（範囲外）＋Exception（例外）

#### NegativeArraySizeException（ねがてぃぶあれいさいずえくせぷしょん）

- 意味：配列生成式の長さが負のときに実行時にスローされる例外
- ポイント：長さが変数ならコンパイルは通る（JLS 15.10.2：If the value of any DimExpr expression is less than zero, then a NegativeArraySizeException is thrown）。長さ 0 は例外にならない
- 例：`int n = -1; int[] a = new int[n];`
- 語の意味：Negative（負の）＋Array Size（配列の大きさ）＋Exception（例外）

## 04-2 多次元配列と配列の操作

### まとめ表

| 書き方 | 結果 | 理由 |
| :-- | :-- | :-- |
| `new int[2][]` | 外側だけ作る。中は null | 内側は後から長さを変えて作れる（非対称な配列） |
| `for (int x : a) x = 0;` | a は変わらない | x は要素のコピー |
| `a.clone()` | 別の配列。中身は同じ値 | 多次元では内側の配列を共有（浅いコピー） |
| `System.out.println(a)` | `[I@1dbd16a6` の形 | 配列は toString をオーバーライドしていない |
| `Arrays.toString(a)` | `[1, 2, 3]` | 中身を並べた文字列 |
| `Arrays.binarySearch(a, key)` | 見つかれば位置、なければ −(挿入位置)−1 | 先に並べ替えておく |
| `a.equals(b)` | 同じ配列のときだけ true | == と同じ。中身は Arrays.equals |

### 多次元配列

#### 多次元配列（たじげんはいれつ / multidimensional array）

- 意味：要素が配列である配列。`int[][]` は「int[] の配列」
- ポイント：`new int[2][3]` は長さ 3 の int[] を 2 つ作る。`m[1][2]` は 2 行目の 3 番目。`m.length` は外側の長さ、`m[0].length` は内側の長さ。`int[] a[]` も int[][]
- 例：`int[][] m = new int[2][3];`

#### 非対称な配列（ひたいしょうなはいれつ / jagged array）

- 意味：内側の配列の長さがそろっていない多次元配列
- ポイント：`new int[2][]` は外側だけ作り、要素は null（JLS 15.10.2：A multidimensional array need not have arrays of the same length at each level）。null のまま `a[0][0]` を使うと NullPointerException
- 例：`int[][] a = {{1, 2, 3}, {4, 5}, {6}};`

#### 拡張 for 文（かくちょうふぉーぶん / enhanced for statement）

- 意味：`for (型 変数 : 配列やリスト)` の形で、先頭から順に全要素を取り出す for 文
- ポイント：ループの変数は要素のコピー。`x = x * 10;` としても配列の中身は変わらない。添字は使えない。多次元配列では外側の要素の型は int[]（`for (int[] row : m)`）
- 例：`for (String s : list) System.out.println(s);`

#### clone（くろーん / clone）

- 意味：配列の複製を作るメソッド。戻り値の型は元と同じ配列型（JLS 10.7）
- ポイント：新しい配列なので `a == a.clone()` は false。1 次元なら要素を変えても元に影響しない（JLS 例 10.7-1）
- 例：`int[] c = a.clone(); c[0] = 9;` のあとも a[0] は元のまま

#### 浅いコピー（あさいこぴー / shallow copy）

- 意味：外側の入れ物だけを新しく作り、中の要素（参照）はそのまま写すコピー
- ポイント：多次元配列の clone は浅いコピー（JLS 10.7：A clone of a multidimensional array is shallow … Subarrays are shared）。`b[0][0] = 9` は a にも見える。`b[1] = new int[]{7}` は b の外側を変えるだけで a は変わらない
- 例：`int[][] b = a.clone(); b[0][0] = 9;` → a[0][0] も 9

#### ArrayStoreException（あれいすとあえくせぷしょん）

- 意味：参照型の配列に、実際の配列の要素型に合わない値を入れたときに実行時にスローされる例外
- ポイント：`Object[] o = new String[2];` はコンパイルできる（String[] は Object[] に代入できる）。しかし `o[0] = 1;` は実行時に ArrayStoreException（JLS 10.5）。コンパイラは変数の型 Object[] しか見ない
- 例：`Object[] o = new String[2]; o[1] = Integer.valueOf(1);`

### Arrays クラス

#### Arrays（あれいず / java.util.Arrays）

- 意味：配列を並べ替える・探す・比べる・文字列にするなどの static メソッドを集めたクラス
- ポイント：java.util なので import が必要。fill（全要素を同じ値にする）、copyOf（長さを変えてコピー。足りない分は既定値）、asList もここにある
- 例：`Arrays.fill(a, 7); int[] b = Arrays.copyOf(a, 6);`

#### Arrays.toString（あれいず・とぅすとりんぐ）

- 意味：配列の中身を `[1, 2, 3]` の形の文字列にする
- ポイント：配列をそのまま `System.out.println(a)` すると Object の toString が使われ、`[I@` のあとにハッシュコードの 16 進数が続く文字列になる（[I は int 配列の型の記号、JLS 例 10.8-1）。char[] だけは println(char[]) があるので文字が並んで表示される
- 例：`Arrays.toString(new int[]{3, 1})` → "[3, 1]"

#### Arrays.sort（あれいず・そーと）

- 意味：配列の要素を小さい順（自然な順序）に並べ替える。配列そのものを書きかえ、戻り値は void
- ポイント：String は文字コード順。数字（0〜9）→ 大文字（A〜Z）→ 小文字（a〜z）の順で、"10" は "9" より前（先頭の '1' が '9' より小さい）
- 例：`{"b", "B", "a", "10", "9"}` → [10, 9, B, a, b]

#### Arrays.binarySearch（あれいず・ばいなりさーち）

- 意味：並べ替え済みの配列から、二分探索で値の位置を探す
- ポイント：見つかれば添字、なければ −(挿入位置)−1 を返す。挿入位置は「その値より大きい最初の要素の添字」。並べ替えていない配列では結果は不定（API：If it is not sorted, the results are undefined）
- 例：`{1, 3, 5, 7}` で 5 → 2、4 → −3、9 → −5、0 → −1

#### Arrays.equals（あれいず・いこーるず）

- 意味：2 つの配列の長さと各要素が同じかを比べる
- ポイント：配列の equals メソッド（`a.equals(b)`）は Object のままで、== と同じく同じ配列かどうかしか見ない。中身を比べるなら Arrays.equals
- 例：`Arrays.equals(new int[]{1}, new int[]{1})` → true

#### Arrays.compare（あれいず・こんぺあ）

- 意味：2 つの配列を辞書順で比べ、前なら負、同じなら 0、後なら正を返す
- ポイント：最初に違う要素どうしを比べる。片方がもう片方の先頭部分と同じなら、長さの差で決まる（短いほうが前）。int[] の場合、違う要素は Integer.compare で比べるので −1・1 になる
- 例：`compare({1,2,3}, {1,2,4})` → −1、`compare({1,2,3}, {1,2})` → 1

#### Arrays.mismatch（あれいず・みすまっち）

- 意味：2 つの配列で、最初に要素が違う位置の添字を返す。全部同じなら −1
- ポイント：片方がもう片方の先頭部分と同じなら、短いほうの長さを返す（API）。compare と組み合わせて出題される
- 例：`mismatch({1,2,3}, {1,2,4})` → 2、`mismatch({1,2,3}, {1,2})` → 2

## 04-3 ArrayList

### まとめ表

| 書き方 | 結果 | 理由 |
| :-- | :-- | :-- |
| `list.add(1, "c")` | 1 番に入れ、後ろをずらす | add(int, E) は挿入。上書きは set |
| `list.set(1, "X")` | 前の値を返す | 戻り値は置きかえる前の要素 |
| `list.remove(1)`（List&lt;Integer&gt;） | 1 番目を消す | int をとる remove(int) が選ばれる |
| `list.remove(Integer.valueOf(10))` | 値 10 を消す | remove(Object) |
| `list.get(list.size())` | IndexOutOfBoundsException | 添字は 0〜size()−1 |
| `List<int>` | コンパイルエラー | 型引数に基本データ型は使えない |
| 拡張 for の中で `list.remove(x)` | ConcurrentModificationException になりうる | 走査中の構造の変更 |

### リストのしくみ

#### コレクション（これくしょん / collection）

- 意味：複数のオブジェクトをまとめて扱う入れ物。java.util の Collection インタフェースが土台
- ポイント：List（順番あり・重複あり）、Set（重複なし）などがある。配列と違い、長さは要素を足すと自動で伸びる
- 例：`Collection<String> c = new ArrayList<>();`

#### List（りすと / List）

- 意味：要素に順番があり、添字で使えるコレクションのインタフェース（java.util.List）
- ポイント：インタフェースなので `new List<>()` はできない。ふつうは `List<String> list = new ArrayList<>();` のように変数を List 型にして ArrayList を入れる。equals は「同じ順に同じ要素」なら実装クラスが違っても true
- 例：`new ArrayList<>(List.of("x")).equals(List.of("x"))` → true

#### ArrayList（あれいりすと / ArrayList）

- 意味：中で配列を使い、大きさを自動で変える List の実装クラス（API：Resizable-array implementation of the List interface）
- ポイント：null も重複も入る。get・set は速い。容量（中の配列の大きさ）は引数なしで 10、`new ArrayList<>(100)` のように指定もできるが、size は 0 のまま。容量と size は別物
- 例：`ArrayList<String> list = new ArrayList<>(100);` → size() は 0

#### ジェネリクス（じぇねりくす / generics）

- 意味：`List<String>` のように、型引数（<> の中の型）で、入れる要素の型を決める仕組み
- ポイント：型引数に基本データ型は書けない（`List<int>` はコンパイルエラー）。ラッパークラス（Integer など）を使う。`List<Object> l = new ArrayList<String>();` もコンパイルエラー（String[] が Object[] に入る配列とは違う）
- 例：`List<Integer> nums = new ArrayList<>();`

#### ダイヤモンド演算子（だいやもんどえんざんし / diamond operator）

- 意味：`new ArrayList<>()` のように、右辺の型引数を省いて <> だけ書く書き方。左辺の型から推論される
- ポイント：`var list = new ArrayList<>();` とすると推論の手がかりがなく ArrayList&lt;Object&gt; になる。どんな型も add できるが、get の戻り値は Object なので `String s = list.get(0);` はコンパイルエラー
- 例：`List<String> list = new ArrayList<>();`

#### オートボクシング（おーとぼくしんぐ / autoboxing）

- 意味：int などの基本データ型の値を、必要なときに Integer などのラッパーに自動で包むこと。逆に取り出すのがアンボクシング
- ポイント：`list.add(10)` は Integer に包んで入れる。List&lt;Integer&gt; の `remove(1)` は remove(int) が選ばれ「添字 1」を消す（ボクシングしない形が優先）。値 1 を消すなら `remove(Integer.valueOf(1))`
- 例：`for (int n : list) sum += n;`（アンボクシング）

### ArrayList のメソッド

#### add（あど / add）

- 意味：要素を足すメソッド。`add(e)` は末尾に、`add(i, e)` は i 番に入れて後ろをずらす
- ポイント：add(i, e) の i は 0〜size()。size() と同じなら末尾に足せる。size() をこえると IndexOutOfBoundsException。add(e) の戻り値は true
- 例：[a, b] に `add(1, "c")` → [a, c, b]

#### get と set（げっととせっと / get, set）

- 意味：get(i) は i 番の要素を返す。set(i, e) は i 番を e に置きかえ、置きかえる前の要素を返す
- ポイント：どちらも i は 0〜size()−1。size() 以上は IndexOutOfBoundsException（set は add と違い、末尾の次には書けない）。容量が大きくても size が 0 なら set(0, …) は例外
- 例：`String old = list.set(1, "X");`

#### remove（りむーぶ / remove）

- 意味：要素を消すメソッド。remove(int) は添字で、remove(Object) は値で消す
- ポイント：remove(int) は消した要素を返し、範囲外なら IndexOutOfBoundsException。remove(Object) は最初に見つかった 1 つを消して true、なければ false を返す（例外にならない）。後ろの要素は前に詰まる
- 例：[10, 20, 30] で `remove(1)` → [10, 30]

#### size・isEmpty・clear（さいず・いずえんぷてぃ・くりあ）

- 意味：size は要素の数、isEmpty は要素が 0 かどうか、clear は全要素を消す
- ポイント：要素数は size()。配列の length や String の length() と取り違えやすい
- 例：`list.clear(); list.isEmpty()` → true

#### contains と indexOf（こんていんずといんでっくすおぶ / contains, indexOf）

- 意味：contains は要素があるか（boolean）、indexOf は最初の位置、lastIndexOf は最後の位置を返す
- ポイント：見つからなければ indexOf は −1。比べ方は equals（API：Objects.equals(o, get(i))）
- 例：[b, a, b] で indexOf("b") → 0、lastIndexOf("b") → 2

#### ConcurrentModificationException（こんかれんともでぃふぃけーしょんえくせぷしょん）

- 意味：拡張 for やイテレータで回している途中で、リスト自体に add・remove をしたときにスローされる例外
- ポイント：ArrayList のイテレータは fail-fast（API）。ただし「必ずスローされる」保証はない（best-effort）。途中で消したいときは removeIf か Iterator の remove を使う
- 例：[a, b, c] を拡張 for で回し、"a" で `list.remove(s)` → 例外
- 語の意味：Concurrent（同時の）＋Modification（変更）＋Exception（例外）

## 04-4 変更できないリストとラムダ式

### まとめ表

| 作り方 | add・remove | set | null |
| :-- | :-- | :-- | :-- |
| `new ArrayList<>()` | できる | できる | 入る |
| `Arrays.asList(配列)` | UnsupportedOperationException | できる（元の配列も変わる） | 入る |
| `List.of(...)` | UnsupportedOperationException | UnsupportedOperationException | NullPointerException |

### 変更できないリスト

#### List.of（りすと・おぶ / List.of）

- 意味：引数の要素を並べた、変更できないリストを作る static メソッド（Java 9〜）
- ポイント：add・remove・set はどれもコンパイルは通るが、実行時に UnsupportedOperationException（API：Unmodifiable Lists）。null を渡すと NullPointerException。要素自体が変更できるオブジェクト（StringBuilder など）なら、その中身は変えられる。List.copyOf も変更できないコピーを作る
- 例：`List<String> l = List.of("a", "b");`

#### Arrays.asList（あれいず・あずりすと）

- 意味：配列をもとにした、大きさが固定のリストを返す（API：Returns a fixed-size list backed by the specified array）
- ポイント：set はできて、元の配列にも反映する（逆も同じ）。add・remove は大きさを変えるので UnsupportedOperationException。変更できる ArrayList が欲しいときは `new ArrayList<>(Arrays.asList(...))`
- 例：`List<String> l = Arrays.asList(arr); l.set(0, "X");` → arr[0] も "X"

#### UnsupportedOperationException（あんさぽーてっどおぺれーしょんえくせぷしょん）

- 意味：そのオブジェクトがサポートしていない操作を呼んだときにスローされる例外
- ポイント：変更できないリストに add などを呼ぶとスローされる。コンパイルエラーではなく実行時の例外（List インタフェースには add があるので、コンパイラは止めない）
- 例：`List.of("a").add("b");`
- 語の意味：Unsupported（サポートされない）＋Operation（操作）＋Exception（例外）

### ラムダ式で操作する

#### ラムダ式（らむだしき / lambda expression）

- 意味：`n -> n % 2 == 0` のように、引数と処理だけを書いて渡す短い関数の書き方
- ポイント：引数 -> 式。引数が 1 つで型を書かないときはかっこを省ける。処理が複数の文なら { } と return を使う。#04 では removeIf・forEach に渡す形を押さえる（詳しくは関数型インタフェースとともに後の分野で扱う）
- 例：`(a, b) -> a + b`

#### removeIf（りむーぶいふ / removeIf）

- 意味：条件（ラムダ式）に合う要素を全部消す Collection のメソッド
- ポイント：走査中に消しても ConcurrentModificationException にならない安全な書き方。戻り値は 1 つでも消したら true
- 例：[1, 2, 3, 4, 5] に `removeIf(n -> n % 2 == 0)` → [1, 3, 5]

#### forEach（ふぉーいーち / forEach）

- 意味：全要素に順に同じ処理（ラムダ式）をするメソッド
- ポイント：戻り値は void。拡張 for 文と同じく順番に処理する。メソッド参照で `list.forEach(System.out::println);` とも書ける
- 例：`list.forEach(n -> System.out.print(n + " "));`
